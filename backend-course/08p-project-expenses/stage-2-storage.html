שיעור 3 — שלב 2: שמירה בקובץ (storage.js)

⏱ ~40 דקות · 🤖 PR1-STORAGE

🎯 בשלב הזה

לכתוב את src/storage.js: טעינה ושמירה של המערך בקובץ JSON — כולל המקרים שבהם הקובץ לא קיים או פגום. הבודק: npm run check PR1-STORAGE.

1. loadExpenses(filePath)

  1. אם הקובץ לא קיים — זו הפעלה ראשונה, לא שגיאה: מחזירים [].
  2. קוראים את הטקסט, ומנסים JSON.parse בתוך try.
  3. אם ה־parse נכשל, או שהתוצאה אינה מערך (Array.isArray) — זורקים expenseError("CORRUPT_FILE", ...).
⚠️ למה לא להחזיר [] גם על קובץ פגום?

כי אז הפקודה הבאה (add) תשמור מערך חדש עם הוצאה אחת — ותדרוס את כל ההיסטוריה של המשתמש. קובץ פגום הוא בדיוק המקרה שבו צריך לעצור ולהודיע. זה עיקרון חשוב: אף פעם לא להשמיד נתונים בשקט.

2. saveExpenses(filePath, expenses)

JSON.stringify(expenses, null, 2) ו־fs.writeFileSync. ההזחה לא חובה למחשב — אבל קובץ קריא עוזר לך לבדוק ידנית מה נשמר (פתח את expenses.json ב־VS Code אחרי כמה פקודות).

3. בדיקה ידנית מה־Terminal

לפני שיש CLI, אפשר לבדוק עם קובץ זמני ב־playground:

playground/try-storage.mjs 
import { addExpense } from "../08p-project-expenses/starter/expenses-cli/src/expenses.js";
import { loadExpenses, saveExpenses } from "../08p-project-expenses/starter/expenses-cli/src/storage.js";

const file = "playground/test-expenses.json";
const updated = addExpense(loadExpenses(file), { date: "2026-10-01", category: "food", amount: "12" });
saveExpenses(file, updated);
console.log(loadExpenses(file));

הרץ פעמיים — בפעם השנייה יהיו שתי הוצאות, עם מזהים 1 ו־2. אחר כך פתח את playground/test-expenses.json, מחק סוגר אחד, ושמור — והרץ שוב: אמורה להיזרק השגיאה CORRUPT_FILE.

💼 בעולם העבודה

קובץ JSON הוא "מסד נתונים" של עניים: אין בו נעילות (שני תהליכים שכותבים יחד ידרסו זה את זה), אין חיפוש מהיר, ואם התוכנית קורסת באמצע כתיבה — הקובץ נשאר פגום. בדיוק בגלל זה קיימים מסדי נתונים — פרק 16. אבל ממשק ה"טען/שמור" שבנית ישרוד: בפרויקט 2 תחליף את המימוש שלו ב־PostgreSQL.
