2. README.md

צור בתיקיית הפרויקט קובץ README.md (Markdown — עיצוב טקסט פשוט: # לכותרת, - לרשימה, הזחה של 4 רווחים לקוד). זה הדבר הראשון שמראיין רואה ב־GitHub. תבנית:

# Expenses CLI

מנהל הוצאות אישי בשורת הפקודה, ב־Node.js — בלי ספריות חיצוניות.

## הפעלה
    node src/cli.js add 2026-10-01 food 54.5 lunch
    node src/cli.js list --month 2026-10
    node src/cli.js summary 2026-10
    node src/cli.js delete 1

## מבנה
- src/expenses.js — לוגיקה טהורה (בדיקות, חישובים, סיכומים)
- src/storage.js — שמירה וטעינה מ־expenses.json
- src/cli.js — פירוש פקודות והדפסה

## החלטות
- מזהים: הגדול הקיים + 1 (לא אורך הרשימה), כדי שלא יחזרו אחרי מחיקה.
- קובץ פגום עוצר את התוכנית במקום לדרוס את הנתונים.
- סכומים מעוגלים ל־2 ספרות בכל סכימה.

## מה הייתי מוסיף
- עריכת הוצאה, תקציב חודשי עם התראה, ייצוא ל־CSV.

הסעיף "החלטות" הוא החשוב ביותר: הוא מראה שחשבת, לא רק כתבת. בפרק 9 נעלה את הפרויקט ל־GitHub, והקובץ הזה יוצג אוטומטית בעמוד שלו.

3. הרחבות (רשות, לפי סדר קושי)

  1. edit <id> --amount 40 — עדכון שדה בהוצאה קיימת (בלי לשנות את המקור — map + spread).
  2. budget <YYYY-MM> <סכום> — שמירת תקציב לחודש, ו־summary מציג כמה נשאר ומזהיר אם חרגת.
  3. import <file.csv> — ייבוא עם דוח שגיאות לכל שורה (יש לך כבר את P08-E17!).
  4. export --month 2026-10 — הדפסת CSV שאפשר לפתוח ב־Excel.

כל הרחבה — קודם הפונקציה הטהורה ב־expenses.js (ובדיקה ידנית שלה), ורק אחר כך הפקודה ב־cli.js.

💼 איך לספר על הפרויקט בראיון

"כתבתי CLI לניהול הוצאות ב־Node בלי ספריות. הפרדתי לוגיקה טהורה מאחסון ומממשק — כך שהלוגיקה נבדקת לבד, ובשלב מאוחר יותר החלפתי את שכבת הממשק ל־API. שתי החלטות שאני אוהב: מזהים שלא חוזרים אחרי מחיקה, וקובץ פגום שעוצר את התוכנית במקום לדרוס נתונים." — שלושה משפטים, וכל אחד פותח שאלה טובה.
