P19-E01 · לקרוא schema 🧠 הבנה רמה 1

💡 רמז 1

@@map, @@id, ?, onDelete.

💡 רמז 2

שדה קשר (עם @relation) קיים רק ב־client.

✅ פתרון
  1. order_items; מפתח משותף (order_id, product_id) — @@id([orderId, productId]).
  2. string | null (בגלל String?). Decimal — אובייקט, לא number.
  3. הזמנה: הפריטים שלה נמחקים איתה (onDelete: Cascade על OrderItem.order). קטגוריה עם מוצרים: שגיאה (ברירת המחדל — RESTRICT), קוד P2003.
  4. customerId הוא העמודה (FK). customer הוא שדה קשר — מאפשר include: { customer: true } ו־where: { customer: { city: "Haifa" } }.
  5. המפתח הראשי (id), ו־(customer_id, created_at) — @@index([customerId, createdAt]), בדיוק ה־index של "ההזמנות שלי" מפרק 18.
⚠️ טעויות נפוצות
  • לחשוב ש־orders Order[] ב־Customer הוא עמודה — אין שום דבר כזה בטבלה customers.

P19-E29 · ‏ORM — מתי כן ומתי SQL? 🧠 הבנה רמה 1

💡 רמז 1

ORM חזק בעבודה "שורה ← אובייקט" ובקשרים. SQL חזק בצבירה, חלונות ופעולות על הרבה שורות.

💡 רמז 2

"לא כל שאילתה מורכבת נוחה לכתיבה (ואז — SQL ישיר)".

✅ פתרון
  1. Prisma — בדיוק בשביל זה: טיפוסים, בלי SQL ידני, בלי injection.
  2. SQL (‏$queryRaw, שיעור 3) — חלונות ו־CTE פשוטים יותר ב־SQL; ב־Prisma אין להם תחביר טבעי.
  3. Prisma — create, ושגיאת unique עם קוד ברור (‏P2002, שיעור 3).
  4. SQL — פקודת UPDATE אחת במסד, במקום לטעון 2 מיליון אובייקטים לזיכרון.
  5. Prisma — include עושה את זה בלי N+1 (שיעור 3).

בפרויקט אמיתי משתמשים בשניהם: ORM לרוב הקוד, SQL לדוחות ולתחזוקה. זו הסיבה שלמדת SQL קודם.

⚠️ טעויות נפוצות
  • "ORM = לא צריך לדעת SQL" — בדיוק הפוך: כש־Prisma איטי, צריך לקרוא את ה־SQL שהוא שלח.

P19-E30 · מה נכנס ל־Git? 🧠 הבנה רמה 1

💡 רמז 1

מה שאפשר לייצר מחדש מפקודה — לא נכנס. מה שמתאר את הפרויקט — נכנס. סודות — אף פעם.

💡 רמז 2

איור 1 בשיעור: מה כתוב מתחת ל־migrations/ ומתחת ל־generated/prisma/?

✅ פתרון
  1. Git — מקור האמת של המודלים.
  2. Git — ה־SQL שירוץ אצל כל חבר צוות, בבדיקות ובייצור, באותו סדר.
  3. ‏.gitignore — נוצר מ־npx prisma generate (כמו node_modules).
  4. Git — איפה הסכמה, איפה ה־migrations, איך מתחברים. בלי סודות: הכתובת מגיעה מ־process.env.
  5. ‏.gitignore — סיסמאות. במקומו נכנס .env.example בלי ערכים אמיתיים.
  6. ‏.gitignore — npm install מייצר.
⚠️ טעויות נפוצות
  • להכניס את generated/ ל־Git "כדי שיעבוד מיד" — ואז הוא לא מתאים לסכמה אחרי שינוי, ו־diff ענק בכל commit.

P19-E31 · שיניתי סכמה, ו־TypeScript לא יודע 🧠 הבנה רמה 2

💡 רמז 1

הטיפוסים של prisma.product מגיעים מ־generated/prisma. מתי הוא נוצר בפעם האחרונה?

💡 רמז 2

✅ פתרון

⚠️ טעויות נפוצות

P19-E32 · ‏new PrismaClient בכל בקשה 🧠 הבנה רמה 2

💡 רמז 1

"יש לו pool של חיבורים בפנים".

💡 רמז 2

מתי ה־pool הזה נסגר?

✅ פתרון

כל בקשה יוצרת client חדש — עם pool חדש וחיבורים חדשים למסד (פתיחת חיבור עולה עשרות מילישניות), ואף אחד לא סוגר אותם ($disconnect). אחרי כמה מאות בקשות המסד מגיע למגבלת החיבורים שלו (ברירת מחדל ב־PostgreSQL: 100), וכל בקשה חדשה — של כל האפליקציה — נכשלת עם too many clients already. הפתרון: client אחד לכל התהליך (src/db.ts מהשיעור), שכל הקוד מייבא.

⚠️ טעויות נפוצות
  • "לתקן" עם await prisma.$disconnect() בסוף כל בקשה — אין דליפה, אבל כל בקשה משלמת על פתיחת חיבור. בדיוק מה ש־pool נועד לחסוך.

P19-E33 · כמה השעה, לפי Prisma? 🧠 הבנה רמה 2

💡 רמז 1

‏21:10+03 = ‏18:10 UTC.

💡 רמז 2

בגרסה הזו, Prisma מפרש את הזמן שהמסד מחזיר כאילו הוא UTC. ב־א׳ המסד מחזיר את השעה בשעון ישראל.

✅ פתרון
  • א: 2026-03-28T21:10:00.000Z — שלוש שעות קדימה (השעה המקומית, עם "Z").
  • ב: 2026-03-28T18:10:00.000Z — נכון.

בדוח לפי UTC עם הגדרה א׳, כל הזמנה שנוצרה ב־31 במרץ אחרי 21:00 שעון ישראל "עוברת" לאפריל. בנתוני הפרק — אף אחת (האחרונה במרץ ב־21:10 ב־28), אבל במבצע של סוף החודש — הרבה. וזה יכול להיות גרוע יותר: כתיבה דרך Prisma וקריאה דרך SQL זזות לכיוון ההפוך. לכן — options: "-c timezone=UTC" בכל חיבור.

⚠️ טעויות נפוצות
  • "לתקן" בקוד עם new Date(d.getTime() - 3 * 3600_000) — בשעון חורף ההפרש שעתיים, והקוד שבור חצי שנה.

P19-E34 · ‏db.ts — client אחד, ב־UTC 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שני ייבואים: PrismaPg מ־@prisma/adapter-pg, ו־PrismaClient מה־client של הפרק.

💡 רמז 2
new PrismaPg({ connectionString: url, options: "-c timezone=UTC" })
✅ פתרון
// P19-E34: db.ts — client אחד, ב־UTC
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "../files/generated/prisma/client.ts";

export function createPrisma(url: string) {
  const adapter = new PrismaPg({ connectionString: url, options: "-c timezone=UTC" });
  return new PrismaClient({ adapter });
}

פונקציה (ולא export const prisma = ... ישירות) — כדי שהבדיקות יוכלו ליצור client מול מסד בדיקה. באפליקציה קוראים לה פעם אחת, ב־server.ts (שיעור 4).

⚠️ טעויות נפוצות
  • לשכוח את options — הכול עובד, והזמנים זזים בשעתיים־שלוש (P19-E33).

P19-E35 · ‏prisma.config.ts לפרויקט אחר 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כמו בשיעור: import "dotenv/config";, defineConfig מ־prisma/config, ו־export default.

💡 רמז 2

ה־seed נכתב בתוך migrations: migrations: { path: "...", seed: "..." }.

✅ פתרון
// P19-E35: prisma.config.ts לפרויקט אחר
import "dotenv/config";
import { defineConfig } from "prisma/config";

export default defineConfig({
  schema: "db/schema.prisma",
  migrations: {

הקובץ הזה הוא מה שה־CLI (npx prisma ...) קורא. האפליקציה עצמה לא משתמשת בו — היא יוצרת client עם createPrisma (P19-E34).

⚠️ טעויות נפוצות

P19-E36 · מודל ראשון: ספקים 🤖 💻 כתיבת קוד 🤖 רמה 1

💡 רמז 1

העתק את מבנה ה־Product מהשיעור, והחלף שדות.

💡 רמז 2

isActive Boolean @default(true) @map("is_active") ו־@@map("suppliers") בסוף המודל.

✅ פתרון
datasource db {
  provider = "postgresql"
}

model Supplier {
  id       Int     @id @default(autoincrement())
  name     String
  email    String
  isActive Boolean @default(true) @map("is_active")

  @@map("suppliers")
}

שם המודל ושמות השדות — כמו בקוד (PascalCase, camelCase); @map/@@map — כמו במסד (snake_case, רבים). כך גם הקוד וגם ה־SQL נראים "טבעיים".

⚠️ טעויות נפוצות
  • לשכוח @@map — הטבלה תיקרא "Supplier", עם אות גדולה ומירכאות בכל שאילתה ב־psql.

P19-E37 · קופונים וכרטיסי מתנה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

עשרוני: Decimal @db.Decimal(5, 2). מספר שלם עם ברירת מחדל: Int @default(1).

💡 רמז 2

אפשר כמה attributes על אותו שדה: maxUses Int @default(1) @map("max_uses").

✅ פתרון
datasource db {
  provider = "postgresql"
}

model Coupon {
  id       Int     @id @default(autoincrement())
  code     String
  percent  Decimal @db.Decimal(5, 2)
  maxUses  Int     @default(1) @map("max_uses")
  isActive Boolean @default(true) @map("is_active")

  @@map("coupons")
}

model GiftCard {
  id         Int     @id @default(autoincrement())
  amount     Decimal @db.Decimal(10, 2)
  holderName String  @map("holder_name")

  @@map("gift_cards")
}

בלי @db.Decimal(5, 2), ‏Decimal הופך ל־DECIMAL(65,30) — עובד, אבל לא מה שהתכוונת, ואין אילוץ על מספר הספרות.

⚠️ טעויות נפוצות
  • Float לאחוזים או לכסף — double precision, עם שגיאות עיגול (פרק 16, ‏numeric מול float).

P19-E38 · שמות כל המוצרים 🤖 💻 כתיבת קוד 🤖 רמה 1

💡 רמז 1

select: { name: true } מחזיר מערך של { name }.

💡 רמז 2

(await prisma.product.findMany({ ... })).map((p) => p.name)

✅ פתרון
// P19-E38: שמות כל המוצרים
import type { PrismaClient } from "../files/generated/prisma/client.ts";

export async function productNames(prisma: PrismaClient): Promise<string[]> {
  const rows = await prisma.product.findMany({ select: { name: true }, orderBy: { name: "asc" } });
  return rows.map((p) => p.name);
}

‏select מביא מהמסד רק את העמודה הזו — ו־TypeScript יודע שלכל איבר יש רק name.

⚠️ טעויות נפוצות
  • למיין ב־JS (.sort()) — עובד, אבל המיון של המסד ושל JS לא תמיד זהים (אותיות גדולות, עברית); ושוב — "תן למסד לעשות את העבודה".

P19-E39 · מ־pg ל־Prisma: מלאי נמוך 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שמות השדות בקוד: isActive, לא is_active. "קטן מ־" — { lt: below }.

💡 רמז 2

מיון לפי שני שדות — מערך: orderBy: [{ stock: "asc" }, { id: "asc" }].

✅ פתרון
// P19-E39: מ־pg ל־Prisma — מלאי נמוך
import type { PrismaClient } from "../files/generated/prisma/client.ts";

export async function lowStock(prisma: PrismaClient, below: number) {
  return prisma.product.findMany({
    where: { isActive: true, stock: { lt: below } },
    select: { id: true, name: true, stock: true },
    orderBy: [{ stock: "asc" }, { id: "asc" }],
  });
}

אותה שאילתה, אבל הערך below נשלח כפרמטר בלי שכתבת $1, והתוצאה מוקלדת.

⚠️ טעויות נפוצות
  • orderBy: { stock: "asc", id: "asc" } (אובייקט אחד עם שני שדות) — Prisma דוחה: כל אובייקט ב־orderBy הוא שדה אחד, והסדר נקבע ע״י המערך.

P19-E41 · מטבלה קיימת למודל 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

לכל עמודה ב־snake_case — שדה ב־camelCase עם @map. ‏numeric(8, 2) ← @db.Decimal(8, 2).

💡 רמז 2

serial PRIMARY KEY ← Int @id @default(autoincrement()).

✅ פתרון
datasource db {
  provider = "postgresql"
}

model Workshop {
  id          Int     @id @default(autoincrement())
  title       String
  seats       Int     @default(12)
  ticketPrice Decimal @map("ticket_price") @db.Decimal(8, 2)
  isOnline    Boolean @default(false) @map("is_online")

כל עמודה ב־SQL היא שורה במודל, וכל אילוץ הוא attribute. ‏NOT NULL הוא ברירת המחדל ב־Prisma — שדה שמותר לו להיות ריק מקבל ? (שיעור 2).

⚠️ טעויות נפוצות
  • ticket_price Decimal (בלי camelCase ו־@map) — עובד, אבל בקוד תכתוב w.ticket_price, שונה משאר השדות.

P19-E42 · ‏"Environment variable not found" 🧠 הבנה רמה 2

💡 רמז 1

.env הוא סתם קובץ טקסט. משתני סביבה מגיעים מהתהליך שהפעיל אותך (הטרמינל), לא מקבצים.

💡 רמז 2

Node 20.6 ומעלה: node --env-file=.env ....

✅ פתרון

ה־CLI ייכשל עם הודעה שאין כתובת למסד (datasource.url ריק). ‏process.env מכיל רק את מה שהתהליך קיבל מהטרמינל; שום דבר לא קורא את .env אם לא ביקשו — זה בדיוק התפקיד של dotenv (הוא קורא את הקובץ וממלא את process.env). עד Prisma 6 ה־CLI עשה את זה לבד; בגרסה 7 — לא. לשרת: import "dotenv/config" בשורה הראשונה של server.ts (כמו בשיעור 4), או node --env-file=.env src/server.ts — בלי תלות בכלל. ובייצור (Docker, ענן) — בלי קובץ: המשתנים מוגדרים בסביבה עצמה (פרק 24).

⚠️ טעויות נפוצות
  • "לתקן" בכתיבת הכתובת ישירות ב־prisma.config.ts — עובד, ומכניס סיסמה ל־Git.

P19-E43 · איזה SQL Prisma ישלח? 🧠 הבנה רמה 2

💡 רמז 1

שמות העמודות במסד — לפי @map (is_active), הטבלה — לפי @@map.

💡 רמז 2

Prisma שולח כל ערך כפרמטר ($1), בדיוק כמו שלמדת לעשות ביד.

✅ פתרון
SELECT id, name, price FROM products
WHERE is_active = true AND price < $1
ORDER BY price ASC;

(Prisma כותב את זה קצת אחרת — עם מירכאות ושם ה־schema, "public"."products"."id" — ראה log: ["query"] בשיעור 3.) "50 OR 1=1" לא יכול להפוך לקוד: הוא נשלח כפרמטר, ומכיוון שהשדה Decimal, Prisma ידחה אותו כערך לא תקין עוד לפני השליחה. עם שרשור ב־pool.query — price < 50 OR 1=1: כל המוצרים, גם הלא פעילים. (ועדיין — ולידציה עם Zod, פרק 15, כדי שהמשתמש יקבל 400 ולא 500.)

⚠️ טעויות נפוצות
  • "עם ORM אין injection בכלל" — יש: $queryRawUnsafe עם שרשור (שיעור 3) פותח אותו מחדש.

P19-E44 · ‏ORM לא מונע מרוץ 🧠 הבנה רמה 2

💡 רמז 1

זה בדיוק "קרא ← חשב ← כתוב" מאיור 1 בשיעור 2 של פרק 18.

💡 רמז 2

Prisma שולח SELECT ואחר כך UPDATE עם מספר קבוע (stock = 0), לא stock - 1.

✅ פתרון

לא נכון. אותו lost update בדיוק: שני ה־findUnique רואים 1, ושני ה־update כותבים 0 — שתי מכירות, מטחנה אחת. ב־Prisma התיקון הוא אותו רעיון — עדכון אטומי עם תנאי:

updateMany({ where: { id: 4, stock: { gte: 1 } }, data: { stock: { decrement: 1 } } })

ובדיקת count (שיעור 3, ותרגיל P19-E21).

⚠️ טעויות נפוצות
  • לעטוף ב־$transaction ולחשוב שזה פותר — ב־Read Committed שני ה־transactions עדיין קוראים 1 (פרק 18).

P19-E45 · ‏snake_case ל־camelCase 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

ביטוי רגולרי: _ שאחריו אות קטנה, ושלפניו תו שאינו _: /(?<=[^_])_([a-z0-9])/g. ‏replace עם פונקציה מקבלת את האות ומחזירה toUpperCase().

💡 רמז 2
Object.fromEntries(Object.entries(row).map(([k, v]) => [toCamel(k), v]))
✅ פתרון
// P19-E45: snake_case ל־camelCase
export function toCamel(name: string): string {
  return name.replace(/(?<=[^_])_([a-z0-9])/g, (_m, ch: string) => ch.toUpperCase());
}

export function camelize(row: Record<string, unknown>): Record<string, unknown> {
  return Object.fromEntries(Object.entries(row).map(([k, v]) => [toCamel(k), v]));
}

P19-E46 · מה יש בכתובת המסד? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

const u = new URL(url); — ‏u.protocol, ‏u.hostname, ‏u.port (מחרוזת, "" אם אין), ‏u.pathname ("/shop"), ‏u.username, ‏u.password.

💡 רמז 2

new URL("לא כתובת") זורק — עטוף ב־try/catch וזרוק את ההודעה שלך.

✅ פתרון
// P19-E46: מה יש בכתובת המסד?
export function describeDbUrl(url: string) {
  let u: URL;
  try {
    u = new URL(url);
  } catch {
    throw new Error("כתובת מסד לא תקינה");
  }
  const database = decodeURIComponent(u.pathname.slice(1));
  if (!["postgresql:", "postgres:"].includes(u.protocol) || database === "" || database.includes("/")) {
    throw new Error("כתובת מסד לא תקינה");
  }
  return {
    host: u.hostname,
    port: u.port === "" ? 5432 : Number(u.port),
    database,
    user: decodeURIComponent(u.username),
    password: u.password === "" ? null : "***",
  };
}

  port: 5432,

  password: null

⚠️ טעויות נפוצות
  • url.split(":") — נשבר על סיסמה עם : או @ (שמקודדים כ־%3A, ‏%40).

P19-E47 · אותה שאילתה — ב־pg וב־Prisma 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

ב־pg — SQL עם $1, ו־rows. ב־Prisma — findMany עם select ו־orderBy של מערך (P19-E39).

💡 רמז 2

שים לב לשמות: ב־pg העמודה is_active; ב־Prisma השדה isActive.

✅ פתרון
// P19-E47: אותה שאילתה — ב־pg וב־Prisma
import type { Pool } from "pg";
import type { PrismaClient } from "../files/generated/prisma/client.ts";

type Row = { id: number; name: string; stock: number };

export async function cheapWithPg(pool: Pool, max: number): Promise<Row[]> {
  const { rows } = await pool.query(
    "SELECT id, name, stock FROM products WHERE is_active AND price < $1 ORDER BY price, id",
    [max],
  );
  return rows;
}

export async function cheapWithPrisma(prisma: PrismaClient, max: number): Promise<Row[]> {
  return prisma.product.findMany({
    where: { isActive: true, price: { lt: max } },
    select: { id: true, name: true, stock: true },
    orderBy: [{ price: "asc" }, { id: "asc" }],
  });
}

בחרתי עמודות שאין בהן numeric בכוונה: ב־pg price היה מגיע כמחרוזת, וב־Prisma כ־Decimal — שתי "צורות" שונות לאותו ערך (שיעור 2).

⚠️ טעויות נפוצות
  • ב־pg בלי id כשובר שוויון — שני מוצרים באותו מחיר עלולים לחזור בסדר שונה מ־Prisma.
