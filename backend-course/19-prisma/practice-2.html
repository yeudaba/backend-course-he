P19-E26 · הספרייה כ־schema של Prisma 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 30 דק׳ידע נדרש: שיעור 2

בשיעור 2 קראת את ה־schema של החנות. עכשיו כותבים schema בעצמך, מקובץ ריק. כתוב ב־Prisma את הספרייה מ־P17-E26, כך שהטבלאות שייווצרו יהיו בדיוק אלה שכתבת שם ב־SQL: אותם שמות טבלאות ועמודות (snake_case), אותם מפתחות, ואותה התנהגות במחיקה.

  • datasource db עם provider = "postgresql" (בלי כתובת — היא ב־config).
  • חמישה מודלים: Author, ‏Book, ‏BookAuthor, ‏Member, ‏Loan. בקוד השדות ב־camelCase (fullName, ‏publishedYear, ‏loanedOn...), ובמסד ב־snake_case (‏@map). הטבלאות: authors, ‏books, ‏book_authors, ‏members, ‏loans (‏@@map).
  • id אוטומטי בכל מודל חוץ מ־BookAuthor, שהמפתח שלו הוא הזוג (@@id).
  • isbn ו־email ייחודיים. ‏publishedYear ו־returnedOn לא חובה. ‏loanedOn — תאריך בלבד (@db.Date), ברירת מחדל: עכשיו.
  • קשרים (@relation) בשני הכיוונים. מחיקת ספר מוחקת את הקישורים שלו ב־BookAuthor (‏onDelete: Cascade). בכל שאר הקשרים — ברירת המחדל, שחוסמת.

הבודק לא צריך מסד כדי לקרוא את הקובץ: הוא מריץ prisma migrate diff --from-empty --to-schema, שהופך את ה־schema ל־SQL. את ה־SQL הוא מריץ על schema זמני, ושם בודק עמודות, מפתחות ומחיקות, כמו ב־P17-E26. רוצה לראות את ה־SQL בעצמך? מתוך 19-prisma/files:

P19-E62 · ‏"migrate diff" בזיכרון 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: פרק 6, פרק 7, שיעור 2

מה Prisma עושה ב־migrate dev: משווה "לפני" ו"אחרי" ומפיק צעדים. בקובץ 19-prisma/starter/P19-E62.ts כתוב וייצא:

export type Column = { table: string; name: string; type: string; nullable: boolean };
export function diffColumns(before: Column[], after: Column[]): { steps: string[]; destructive: boolean }
  • טבלה שקיימת רק ב־after ← CREATE TABLE t; רק ב־before ← DROP TABLE t (בלי צעדים לעמודות שלהן).
  • בטבלה שקיימת בשתיהן: עמודה חדשה ← ADD COLUMN t.c type (ועם NOT NULL בסוף אם nullable: false); עמודה שנעלמה ← DROP COLUMN t.c; טיפוס שהשתנה ← ALTER COLUMN t.c TYPE type; ‏nullable שהשתנה ← ALTER COLUMN t.c SET NOT NULL / ALTER COLUMN t.c DROP NOT NULL (קודם TYPE, אחר כך NOT NULL).
  • סדר: לפי שם הטבלה (א״ב), ובתוך טבלה — לפי שם העמודה.
  • destructive — true אם יש DROP TABLE, ‏DROP COLUMN, שינוי TYPE או SET NOT NULL (שינויים שעלולים לאבד נתונים או להיכשל על נתונים קיימים).
% npm run check P19-E62

🔗 איך זה מתחבר: מערכים, sort ו־localeCompare מפרק 6, ‏Map/Set מפרק 7 — והשיעור: מה migration הוא בעצם, ולמה "שינוי הורס" מקבל אזהרה.

P19-E63 · ‏@db.Date: מ־Date למחרוזת ובחזרה 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 11, פרק 13, שיעור 2

במסד joinedOn הוא date, ב־Prisma הוא Date בחצות UTC, וב־API הוא "2025-11-02". בקובץ 19-prisma/starter/P19-E63.ts כתוב וייצא:

export type ApiCustomer = { id: number; fullName: string; email: string; city: string | null; joinedOn: string };
export function toApiCustomer(c: { id: number; fullName: string; email: string; city: string | null; joinedOn: Date }): ApiCustomer
export function toCustomerData(body: { fullName: string; email: string; city?: string | null; joinedOn: string }): { fullName: string; email: string; city: string | null; joinedOn: Date }
  • toApiCustomer: ‏joinedOn ← "YYYY-MM-DD" לפי UTC (לא לפי השעון של המחשב). שאר השדות כמו שהם.
  • toCustomerData: ‏joinedOn ← Date בחצות UTC; תאריך לא קיים ("2026-02-30") או בפורמט אחר ← throw new Error("תאריך לא תקין"). ‏email — בלי רווחים מסביב, באותיות קטנות. ‏city חסר ← null.
