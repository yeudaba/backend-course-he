P19-E26 · הספרייה כ־schema של Prisma 🤖

✍️ מאפסרמה 3⏱ 30 דק׳ידע נדרש: שיעור 2

בשיעור 2 קראת את ה־schema של החנות. עכשיו כותבים schema בעצמך, מקובץ ריק. כתוב ב־Prisma את הספרייה מ־P17-E26, כך שהטבלאות שייווצרו יהיו בדיוק אלה שכתבת שם ב־SQL: אותם שמות טבלאות ועמודות (snake_case), אותם מפתחות, ואותה התנהגות במחיקה.

  • datasource db עם provider = "postgresql" (בלי כתובת — היא ב־config).
  • חמישה מודלים: Author, ‏Book, ‏BookAuthor, ‏Member, ‏Loan. בקוד השדות ב־camelCase (fullName, ‏publishedYear, ‏loanedOn...), ובמסד ב־snake_case (‏@map). הטבלאות: authors, ‏books, ‏book_authors, ‏members, ‏loans (‏@@map).
  • id אוטומטי בכל מודל חוץ מ־BookAuthor, שהמפתח שלו הוא הזוג (@@id).
  • isbn ו־email ייחודיים. ‏publishedYear ו־returnedOn לא חובה. ‏loanedOn — תאריך בלבד (@db.Date), ברירת מחדל: עכשיו.
  • קשרים (@relation) בשני הכיוונים. מחיקת ספר מוחקת את הקישורים שלו ב־BookAuthor (‏onDelete: Cascade). בכל שאר הקשרים — ברירת המחדל, שחוסמת.

📄 כותבים בקובץ 19-prisma/starter/P19-E26.prisma (יש בו רק הערה), ובודקים:

% npm run check P19-E26

הבודק לא צריך מסד כדי לקרוא את הקובץ: הוא מריץ prisma migrate diff --from-empty --to-schema, שהופך את ה־schema ל־SQL. את ה־SQL הוא מריץ על schema זמני, ושם בודק עמודות, מפתחות ומחיקות, כמו ב־P17-E26. רוצה לראות את ה־SQL בעצמך? מתוך 19-prisma/files:

% npx prisma migrate diff --from-empty --to-schema ../starter/P19-E26.prisma --script

P19-E27 · עמוד מוצרים: רשימה וספירה במקביל 🤖

🔁 חזרהרמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

🔁 חזרה על Promise.all ו־destructuring של מערך (פרקים 7 ו־10) ועל pagination עם OFFSET (‏P16-E14), הפעם ב־Prisma. מסך רשימה צריך שני דברים: המוצרים של העמוד, ו"כמה יש בסך הכול" (בשביל "עמוד 2 מתוך 3"). אלה שתי שאילתות שלא תלויות זו בזו, ולכן שולחים אותן יחד. בקובץ 19-prisma/starter/P19-E27.ts כתוב וייצא:

getProductPage(prisma, { page = 1, pageSize = 5, categoryId } = {}), שמחזירה { items, page, total, pages }:

  • רק מוצרים פעילים. עם categoryId — רק מהקטגוריה הזו.
  • items: ‏{ id, name, price } לפי id, כש־price הוא number. ‏total: כמה מוצרים מתאימים בסך הכול. ‏pages: כמה עמודים (‏Math.ceil). עמוד אחרי הסוף ← items: [], לא שגיאה.
  • findMany ו־count נשלחות במקביל, עם אותו where.
  • page שאינו מספר שלם חיובי ← RangeError("page חייב להיות מספר שלם חיובי"). ‏pageSize שאינו שלם בין 1 ל־50 ← RangeError("pageSize חייב להיות 1–50").

P19-E28 · repository לקטגוריות 🤖

🔁 חזרהרמה 3⏱ 30 דק׳ידע נדרש: שיעור 3

🔁 חזרה על interface, ‏class ... implements ושגיאות משלך עם extends Error (פרק 12), ועל switch (פרק 4). ה־service לא צריך לדעת ש־P2002 הוא "כבר קיים". את התרגום הזה עושה ה־repository. בקובץ 19-prisma/starter/P19-E28.ts כתוב וייצא:

  • type CategorySummary = { id: number; name: string; productCount: number }.
  • interface CategoryRepository עם list(), ‏create(name) ו־rename(id, name). שלושתן מחזירות Promise של CategorySummary (‏list — מערך).
  • class ConflictError ו־class NotFoundError, שתיהן extends Error, עם name שהוא שם המחלקה.
  • class PrismaCategoryRepository implements CategoryRepository, שמקבלת PrismaClient ב־constructor ושומרת אותו בשדה פרטי (#prisma):
    • list() — כל הקטגוריות לפי שם, עם מספר המוצרים בכל אחת (גם לא פעילים).
    • create(name) ו־rename(id, name) — השם אחרי trim. ריק ← RangeError("שם קטגוריה ריק").
    • שגיאת Prisma P2002 (שם קיים) ← ConflictError(קטגוריה בשם ${name} כבר קיימת). ‏P2025 (id לא קיים ב־rename) ← NotFoundError(קטגוריה ${id} לא קיימת). כל שגיאה אחרת — כמו שהיא. הבחירה לפי הקוד — עם switch.

📄 כותבים בקובץ 19-prisma/starter/P19-E28.ts (יש בו רק הערה), ובודקים:

% npm run check P19-E28

P19-E24 · אתגר: repository למוצרים 🤖

רמה 5⏱ 50 דק׳ידע נדרש: כל הפרק

בקובץ 19-prisma/starter/P19-E24.ts מוגדר ה־interface ProductsRepository (מוצר ב־API: { id, name, category, price, stock, isActive } — category הוא שם, price הוא number). ממש PrismaProductsRepository:

  • list({ category, q, inStock, sort, page, limit }) ← { data, total }. sort: "price", "-price", "name" (ברירת מחדל: name); תמיד שובר שוויון לפי id. inStock: true ← רק מלאי > 0.
  • get(id) ← מוצר או undefined.
  • create({ name, category, price, stock }) — הקטגוריה לפי שם; לא קיימת ← AppError("CATEGORY_NOT_FOUND").
  • update(id, changes) — כל שדה לא חובה, כולל category (שם); לא קיים ← undefined.
  • remove(id) ← true/false; מוצר שהוזמן ← AppError("PRODUCT_HAS_ORDERS").
