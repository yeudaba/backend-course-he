P19-E19 · seed שאפשר להריץ שוב 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

upsert לכל דבר שיש לו שדה ייחודי (קטגוריה לפי name, לקוח לפי email).

💡 רמז 2

למוצר אין שדה ייחודי חוץ מ־id. findFirst לפי שם וקטגוריה, ו־create רק אם אין.

✅ פתרון
// P19-E19
import type { PrismaClient } from "../files/generated/prisma/client.ts";

const PRODUCTS = [
  { name: "Cold Brew Bottle 1L", price: 59.9, stock: 20 },
  { name: "Cold Brew Filter Bags", price: 34.9, stock: 100 },
];

export async function seedDemoData(prisma: PrismaClient) {
  const category = await prisma.category.upsert({ where: { name: "cold brew" }, create: { name: "cold brew" }, update: {} });
  for (const p of PRODUCTS) {
    const existing = await prisma.product.findFirst({ where: { name: p.name, categoryId: category.id } });
    if (!existing) await prisma.product.create({ data: { ...p, categoryId: category.id } });
  }
  const customer = await prisma.customer.upsert({
    where: { email: "demo@example.com" },
    create: { email: "demo@example.com", fullName: "Demo User", city: "Tel Aviv", joinedOn: new Date("2026-01-01") },
    update: {},
  });
  return { categoryId: category.id, customerId: customer.id };
}

seed שאפשר להריץ שוב ("idempotent") חוסך המון כאב: אפשר להריץ אותו בכל הפעלה של סביבת פיתוח, בלי "קודם תמחק".

⚠️ טעויות נפוצות
  • create לכל דבר — הרצה שנייה נכשלת על unique (או יוצרת מוצרים כפולים).

P19-E26 · הספרייה כ־schema של Prisma 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

העתק את המבנה מ־files/prisma/schema.prisma: ‏Product/Category הם דוגמה לקשר "רבים לאחד", ו־ProductTag היא בדיוק טבלת קישור כמו BookAuthor. שדה לא חובה: Int?. תאריך עם ברירת מחדל: DateTime @default(now()) @map("loaned_on") @db.Date.

💡 רמז 2

לכל קשר יש שני צדדים. ב־Loan: ‏bookId Int @map("book_id") ו־book Book @relation(fields: [bookId], references: [id]). ב־Book: ‏loans Loan[]. אם תשכח את הצד של המערך, Prisma יגיד בדיוק מה חסר.

✅ פתרון
// P19-E26: הספרייה (P17-E26) כ־schema של Prisma
datasource db {
  provider = "postgresql"
}

model Author {
  id       Int          @id @default(autoincrement())
  fullName String       @map("full_name")
  books    BookAuthor[]

  @@map("authors")
}

model Book {
  id            Int          @id @default(autoincrement())
  title         String
  isbn          String       @unique
  publishedYear Int?         @map("published_year")
  authors       BookAuthor[]
  loans         Loan[]

  @@map("books")
}

model BookAuthor {
  bookId   Int    @map("book_id")
  book     Book   @relation(fields: [bookId], references: [id], onDelete: Cascade)
  authorId Int    @map("author_id")
  author   Author @relation(fields: [authorId], references: [id])

  @@id([bookId, authorId])
  @@map("book_authors")
}

model Member {
  id       Int    @id @default(autoincrement())
  fullName String @map("full_name")
  email    String @unique
  loans    Loan[]

  @@map("members")
}

model Loan {
  id         Int       @id @default(autoincrement())
  bookId     Int       @map("book_id")
  book       Book      @relation(fields: [bookId], references: [id])
  memberId   Int       @map("member_id")
  member     Member    @relation(fields: [memberId], references: [id])
  loanedOn   DateTime  @default(now()) @map("loaned_on") @db.Date
  returnedOn DateTime? @map("returned_on") @db.Date

  @@index([memberId])
  @@map("loans")
}

שלוש שורות ב־schema שוות כאן הרבה SQL: ‏@relation הופך ל־FOREIGN KEY, ‏@unique ל־UNIQUE INDEX, ו־@@id ל־PRIMARY KEY על שתי עמודות. בלי onDelete, Prisma כותב ON DELETE RESTRICT, ולכן היסטוריית ההשאלות מוגנת כמו ב־P17-E26.

השדות books BookAuthor[] ו־loans Loan[] לא יוצרים עמודות. הם קיימים רק ב־Prisma Client, כדי שתוכל לכתוב include: { loans: true }. העמודה עצמה (book_id) נמצאת תמיד בצד ה"רבים".

מה לא עבר מ־P17-E26? ה־CHECK (returned_on >= loaned_on). ב־schema של Prisma אין דרך לכתוב CHECK. בפרויקט אמיתי יוצרים migration עם --create-only, ומוסיפים את ה־CHECK ביד לקובץ ה־SQL (שיעור 2). עוד הבדל: Prisma יוצר SERIAL ולא GENERATED ALWAYS AS IDENTITY.

ה־@@index([memberId]) לא חובה כאן, אבל הוא הרגל טוב. PostgreSQL לא יוצר index על foreign key לבד (‏P18-E16), ו"כל ההשאלות של חבר" היא שאילתה נפוצה.

⚠️ טעויות נפוצות
  • לשכוח @@map("books") — הטבלה נקראת "Book" (באות גדולה ובמירכאות), וכל SQL שכתבת עד עכשיו לא מוצא אותה.
  • onDelete: Cascade גם ב־Loan — מחיקת ספר מוחקת בשקט את ההיסטוריה שלו.
  • DateTime בלי @db.Date — העמודה היא timestamp(3), ו"השאלות של היום" צריכות טווח שעות.
  • id נוסף ב־BookAuthor בלי @@id([bookId, authorId]) — אותו קישור יכול להופיע פעמיים.
