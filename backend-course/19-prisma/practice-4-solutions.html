P19-E71 · ‏refactor — ומה מוכיח שלא שברת 🧠 הבנה רמה 1

💡 רמז 1

refactor = מבנה חדש, אותה התנהגות.

💡 רמז 2

אם משהו נשבר אחרי commit שמשנה שני דברים — איזה מהם אשם?

✅ פתרון
  1. הקוד זז (מה־service ל־repository), אבל מבחוץ — אותם endpoints, אותן תשובות. זה ההגדרה של refactor.
  2. PR2-SERVICE, ‏PR2-API ו־PR2-LIST — הם בודקים התנהגות דרך ה־API/ה־service, לא איפה הקוד יושב. הם רצים עם InMemory (ברירת המחדל של createApp), לכן בלי מסד — ומהר.
  3. צעדים קטנים: אם אחרי ה־refactor הבדיקות ירוקות, יודעים שהמבנה החדש נכון. אחר כך מוסיפים את Prisma, ואם משהו נשבר — זה Prisma. commit אחד עם שניהם — כל כישלון יכול להיות בכל מקום.
⚠️ טעויות נפוצות
  • "refactor" שמשנה גם התנהגות ("ובדרך תיקנתי שהמיון יהיה הפוך") — הבדיקות נכשלות, ולא ברור אם זה באג או שינוי מכוון.

P19-E72 · למה low, medium, high — ולא לפי א״ב? 🧠 הבנה רמה 2

💡 רמז 1

"ב־enum של PostgreSQL הסדר הוא סדר ההגדרה בסכמה".

💡 רמז 2

אילו בדיקות של PR2 ממיינות לפי עדיפות?

✅ פתרון

בסדר low, medium, high: ‏desc ← ‏high, medium, low — מה שהמשתמש מצפה לו. אחרי "סידור" לפי א״ב: ‏desc ← ‏medium, low, high — מיון "עובד" ושגוי. (ושינוי סדר של enum קיים במסד הוא לא שינוי של שורה בסכמה — זה migration לא טריוויאלי.) תדע מ־PR2-LIST / PR2-DB, שבודקים sort=-priority. זו בדיוק הסיבה שיש בדיקה ל־sort, ולא רק ל"יש תוצאות".

⚠️ טעויות נפוצות
  • לפתור במיון ב־JS אחרי השאילתה — שובר את ה־pagination (העמוד הראשון נבחר לפי מיון אחר).

P19-E73 · ‏NULL בסוף — גם ב־desc? 🧠 הבנה רמה 2

💡 רמז 1

ב־PostgreSQL, NULL נחשב "גדול מכל ערך".

💡 רמז 2

"גדול מכולם" ← אחרון בסדר עולה, וראשון בסדר יורד.

✅ פתרון
CREATE TEMP TABLE t (title text, due_date date);
INSERT INTO t VALUES ('a', '2026-12-01'), ('b', '2026-11-20'), ('c', NULL);
SELECT string_agg(title, ', ' ORDER BY due_date ASC) AS asc_default, string_agg(title, ', ' ORDER BY due_date DESC) AS desc_default,
       string_agg(title, ', ' ORDER BY due_date DESC NULLS LAST) AS desc_nulls_last FROM t;
CREATE TABLE
INSERT 0 3
 asc_default | desc_default | desc_nulls_last
-------------+--------------+-----------------
 b, a, c     | c, a, b      | a, b, c
(1 row)

ב־desc בלי הוראה, המשימות בלי תאריך יעד קופצות לראש הרשימה — הפוך ממה שמשתמש מצפה ("הדחופות קודם"). ‏{ dueDate: { sort: "desc", nulls: "last" } } ב־Prisma ← NULLS LAST ב־SQL. ובזיכרון (InMemoryTasksRepository) — חייבים לממש את אותו כלל ביד, אחרת שתי ה־repositories מחזירות סדר שונה.

⚠️ טעויות נפוצות
  • לבדוק מיון רק על נתונים שבכולם יש תאריך — הבאג לא מופיע.

P19-E74 · ‏P2025 ← undefined — ומי מחליט על 404? 🧠 הבנה רמה 2

💡 רמז 1

גם ל־InMemoryTasksRepository יש update. מה הוא מחזיר כשאין משימה?

💡 רמז 2

P19-E22 ("הכול 'לא נמצא'").

✅ פתרון
  1. כי החוזה (TasksRepository) משותף לשני המימושים. ה־service לא יודע — ולא צריך לדעת — ש־P2025 קיים. אם רק מימוש אחד זורק, ה־service צריך לטפל בשני סוגי "לא נמצא".

⚠️ טעויות נפוצות

P19-E75 · ‏Promise.all לרשימה ול־count 🧠 הבנה רמה 2

💡 רמז 1

שתי שאילתות על שני חיבורים מה־pool — כל אחת לבד.

💡 רמז 2

האם ה־count והרשימה רואים את אותו "צילום" של המסד?

✅ פתרון
  1. כמעט חצי — הזמן הוא של האיטית מבין השתיים, לא הסכום.
  2. כל אחת רואה את המסד ברגע שלה (Read Committed), אז ייתכן total גדול באחד מהרשימה (או הפוך). לרשימה במסך זה בסדר — "עמוד 2 מתוך 3" לא צריך להיות מדויק ברמת המילישנייה. אם כן צריך (דוח כספי) — $transaction עם Repeatable Read (פרק 18).
  3. אם ה־where שונה (למשל שכחת את הסינון לפי status באחד) — "מציג 20 מתוך 57" כש־57 הם כל המשימות. בונים את ה־where פעם אחת, במשתנה, ומשתמשים בו בשתיהן.
⚠️ טעויות נפוצות
  • Promise.all בתוך interactive transaction — שתי השאילתות על אותו חיבור, ממילא אחת אחרי השנייה (P18-E39).

💡 רמז 1

GROUP BY מחזיר רק קבוצות שקיימות (P17-E62).

💡 רמז 2

פרק 12: שעון מוזרק. ופרק 13: באיזה אזור זמן "היום"?

✅ פתרון

P19-E77 · ‏toApiOrder — מה־client ל־API 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

[...o.items].sort((a, b) => a.productId - b.productId) — עותק, לא למיין את המקור.

💡 רמז 2

Math.round(Number(i.unitPrice) * 100) * i.quantity לכל פריט, וחלוקה ב־100 בסוף.

✅ פתרון
// P19-E77: toApiOrder — מה־client ל־API
export type ApiOrder = { id: number; customerId: number; status: string; createdAt: string; items: { productId: number; quantity: number; unitPrice: number }[]; total: number };

export function toApiOrder(o: { id: number; customerId: number; status: string; createdAt: Date; items: { productId: number; quantity: number; unitPrice: unknown }[] }): ApiOrder {
  const items = [...o.items]
    .sort((a, b) => a.productId - b.productId)
    .map((i) => ({ productId: i.productId, quantity: i.quantity, unitPrice: Number(i.unitPrice) }));
  const cents = items.reduce((sum, i) => sum + Math.round(i.unitPrice * 100) * i.quantity, 0);
  return { id: o.id, customerId: o.customerId, status: o.status, createdAt: o.createdAt.toISOString(), items, total: cents / 100 };
}

‏unitPrice: unknown בחתימה — כדי שהפונקציה תקבל גם Decimal של Prisma וגם מספר רגיל (בבדיקות). ‏Number(decimal) עובד כי ל־Decimal יש valueOf.

⚠️ טעויות נפוצות
  • להחזיר את unitPrice כמו שהוא — ב־JSON הוא הופך למחרוזת ("89.9"), והלקוח של ה־API מקבל טיפוס אחר ממה שהתיעוד אומר.

P19-E78 · רשימת הזמנות: סינון, מיון, עמודים ו־count 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1
const where = { ...(q.status && { status: q.status }), ...(q.customerId && { customerId: q.customerId }) };
💡 רמז 2
const dir = sort.startsWith("-") ? "desc" : "asc"; orderBy: [{ createdAt: dir }, { id: dir }]
✅ פתרון
// P19-E78: רשימת הזמנות — סינון, מיון, עמודים ו־count
import type { PrismaClient } from "../files/generated/prisma/client.ts";

export type ListQuery = { status?: "pending" | "paid" | "shipped" | "cancelled"; customerId?: number; sort?: "createdAt" | "-createdAt"; page?: number; limit?: number };

export async function listOrders(prisma: PrismaClient, q: ListQuery) {
  const { sort = "-createdAt", page = 1, limit = 5 } = q;
  const where = {
    ...(q.status !== undefined && { status: q.status }),
    ...(q.customerId !== undefined && { customerId: q.customerId }),
  };
  const dir = sort.startsWith("-") ? ("desc" as const) : ("asc" as const);
  const [data, total] = await Promise.all([
    prisma.order.findMany({
      where,
      select: { id: true, customerId: true, status: true },
      orderBy: [{ createdAt: dir }, { id: dir }],
      skip: (page - 1) * limit,
      take: limit,
    }),
    prisma.order.count({ where }),
  ]);
  return { data, meta: { page, limit, total } };
}

‏where נבנה פעם אחת ומשמש את שתי השאילתות (P19-E75). ‏as const — כדי ש־TypeScript ידע ש־dir הוא "asc" | "desc" ולא סתם string.

⚠️ טעויות נפוצות
  • count() בלי where — ‏total של כל ההזמנות, גם כשמסננים.

✅ פתרון
// P19-E79: orderStats עם groupBy
import type { PrismaClient } from "../files/generated/prisma/client.ts";

export async function orderStats(prisma: PrismaClient, customerId?: number) {
  const rows = await prisma.order.groupBy({
    by: ["status"],
    where: customerId === undefined ? {} : { customerId },
    _count: { _all: true },
  });
  const byStatus = { pending: 0, paid: 0, shipped: 0, cancelled: 0 };
  for (const r of rows) byStatus[r.status] = r._count._all;
  const total = Object.values(byStatus).reduce((a, b) => a + b, 0);
  return { total, byStatus };
}

// P19-E80: מחיקת לקוח — לא נמצא, או "יש לו הזמנות"
import { Prisma, type PrismaClient } from "../files/generated/prisma/client.ts";

export class AppError extends Error {
  code: string;
  constructor(code: string, message = code) {
    super(message);
    this.code = code;
  }
}

export async function deleteCustomer(prisma: PrismaClient, id: number): Promise<boolean> {
  try {
    await prisma.customer.delete({ where: { id } });
    return true;
  } catch (err) {
    if (err instanceof Prisma.PrismaClientKnownRequestError) {
      if (err.code === "P2025") return false;
      if (err.code === "P2003") throw new AppError("HAS_ORDERS");

    throw err;
  }
}

// P19-E81: עדכון חלקי של מוצר
import { Prisma, type PrismaClient } from "../files/generated/prisma/client.ts";

export type ApiProduct = { id: number; name: string; price: number; stock: number; isActive: boolean };

export async function updateProduct(prisma: PrismaClient, id: number, changes: Partial<Omit<ApiProduct, "id">>): Promise<ApiProduct | undefined> {
  try {
    const p = await prisma.product.update({
      where: { id },
      data: { name: changes.name, price: changes.price, stock: changes.stock, isActive: changes.isActive },
      select: { id: true, name: true, price: true, stock: true, isActive: true },
    });
    return { ...p, price: Number(p.price) };
  } catch (err) {
    if (err instanceof Prisma.PrismaClientKnownRequestError && err.code === "P2025") return undefined;
    throw err;
  }
}

P19-E82 · חיפוש לקוחות בכמה שדות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

✅ פתרון
// P19-E82: חיפוש לקוחות בכמה שדות
import type { PrismaClient } from "../files/generated/prisma/client.ts";

export async function searchCustomers(prisma: PrismaClient, q: string) {
  const text = q.trim();
  if (text === "") return [];
  const like = { contains: text, mode: "insensitive" as const };
  return prisma.customer.findMany({
    where: { OR: [{ fullName: like }, { email: like }, { city: like }] },
    select: { id: true, fullName: true },
    orderBy: [{ fullName: "asc" }, { id: "asc" }],
  });
}

P19-E83 · ‏repository ללקוחות — בזיכרון 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

private rows = new Map<number, Customer>(); ‏— ו־{ ...c } בכל החזרה.

💡 רמז 2

"id הבא": Math.max(0, ...this.rows.keys()) + 1.

✅ פתרון
// P19-E83: repository ללקוחות — בזיכרון
export type Customer = { id: number; fullName: string; email: string; city: string | null };

export interface CustomersRepository {
  findById(id: number): Promise<Customer | undefined>;
  findByEmail(email: string): Promise<Customer | undefined>;
  insert(data: Omit<Customer, "id">): Promise<Customer>;
  delete(id: number): Promise<boolean>;
}

export class AppError extends Error {
  code: string;
  constructor(code: string, message = code) {
    super(message);
    this.code = code;
  }
}

export class InMemoryCustomersRepository implements CustomersRepository {
  private rows = new Map<number, Customer>();

  constructor(initial: Customer[] = []) {
    for (const c of initial) this.rows.set(c.id, { ...c });
  }

  async findById(id: number) {
    const c = this.rows.get(id);
    return c ? { ...c } : undefined;
  }

  async findByEmail(email: string) {
    const e = email.toLowerCase();
    const c = [...this.rows.values()].find((r) => r.email.toLowerCase() === e);
    return c ? { ...c } : undefined;
  }

  async insert(data: Omit<Customer, "id">) {
    if (await this.findByEmail(data.email)) throw new AppError("EMAIL_TAKEN");
    const c = { id: Math.max(0, ...this.rows.keys()) + 1, ...data };
    this.rows.set(c.id, c);
    return { ...c };
  }

  async delete(id: number) {
    return this.rows.delete(id);
  }
}

מתודות async גם בלי שום המתנה — כי החוזה מבטיח Promise, כמו המימוש של Prisma. כך ה־service לא יודע (ולא צריך לדעת) מי מאחוריו.

⚠️ טעויות נפוצות
  • להחזיר את האובייקט השמור עצמו — הקוד שקרא יכול לשנות את "המסד" בלי update, ובדיקות עוברות בזיכרון ונכשלות עם Prisma.

    super(message);
    this.code = code;
  }
}

const SELECT = { id: true, fullName: true, email: true, city: true } as const;

export class PrismaCustomersRepository {
  private prisma: PrismaClient;
  constructor(prisma: PrismaClient) {
    this.prisma = prisma;
  }

  async findById(id: number): Promise<Customer | undefined> {
    return (await this.prisma.customer.findUnique({ where: { id }, select: SELECT })) ?? undefined;
  }

  async findByEmail(email: string): Promise<Customer | undefined> {
    return (await this.prisma.customer.findFirst({ where: { email: { equals: email, mode: "insensitive" } }, select: SELECT })) ?? undefined;
  }

  async insert(data: Omit<Customer, "id">): Promise<Customer> {
    const today = new Date(new Date().toISOString().slice(0, 10) + "T00:00:00Z");
    try {
      return await this.prisma.customer.create({ data: { ...data, joinedOn: today }, select: SELECT });
    } catch (err) {
      if (known(err, "P2002")) throw new AppError("EMAIL_TAKEN");
      throw err;
    }
  }

  async delete(id: number): Promise<boolean> {
    try {
      await this.prisma.customer.delete({ where: { id } });
      return true;
    } catch (err) {
      if (known(err, "P2025")) return false;
      throw err;
    }
  }
}

שני הבדלים בין המימושים שהבודק מגלה. הראשון: INSERT שנכשל על אימייל תפוס "שורף" מספר במסד (P18-E32), ולכן הלקוח הבא מקבל id 11 ולא 10 — זה תקין, והחוזה לא מבטיח מספרים רציפים. השני: ה־UNIQUE במסד הוא על email כמו שהוא (רגיש לאותיות), ובזיכרון — בלי הבדל. כדי שהשניים יתנהגו אותו דבר, ה־service שומר תמיד אימייל באותיות קטנות (או index ייחודי על lower(email), P18-E12). זו בדיוק הסיבה להריץ את אותו תרחיש על שני המימושים.

⚠️ טעויות נפוצות
  • findUnique({ where: { email } }) — רגיש לאותיות; "Dana@example.com" לא מוצא את דנה, אבל ב־InMemory כן.
  • להחזיר את כל שדות הלקוח (בלי select) — joinedOn "דולף" לחוזה, והשוואה עם InMemory נכשלת.

// P19-E24
import { Prisma, type PrismaClient } from "../files/generated/prisma/client.ts";

export class AppError extends Error {
  code: string;
  constructor(code: string, message = code) {
    super(message);
    this.code = code;
  }
}

export interface Product { id: number; name: string; category: string; price: number; stock: number; isActive: boolean }
export interface ListOptions { category?: string; q?: string; inStock?: boolean; sort?: "price" | "-price" | "name"; page?: number; limit?: number }

export interface ProductsRepository {
  list(options: ListOptions): Promise<{ data: Product[]; total: number }>;
  get(id: number): Promise<Product | undefined>;
  create(data: { name: string; category: string; price: number; stock: number }): Promise<Product>;
  update(id: number, changes: Partial<Omit<Product, "id">>): Promise<Product | undefined>;
  remove(id: number): Promise<boolean>;
}

const withCategory = { category: { select: { name: true } } } as const;
type Row = Prisma.ProductGetPayload<{ include: typeof withCategory }>;

const toProduct = (r: Row): Product => ({
  id: r.id,
  name: r.name,
  category: r.category.name,
  price: Number(r.price),
  stock: r.stock,
  isActive: r.isActive,
});

const code = (err: unknown) => (err instanceof Prisma.PrismaClientKnownRequestError ? err.code : undefined);

export class PrismaProductsRepository implements ProductsRepository {
  prisma: PrismaClient;
  constructor(prisma: PrismaClient) {
    this.prisma = prisma;
  }

  async list({ category, q, inStock, sort = "name", page = 1, limit = 10 }: ListOptions) {
    const where: Prisma.ProductWhereInput = {
      ...(category ? { category: { name: category } } : {}),
      ...(q ? { name: { contains: q, mode: "insensitive" } } : {}),
      ...(inStock ? { stock: { gt: 0 } } : {}),
    };
    const orderBy: Prisma.ProductOrderByWithRelationInput[] = [
      sort === "name" ? { name: "asc" } : { price: sort === "price" ? "asc" : "desc" },
      { id: "asc" },
    ];
    const [rows, total] = await Promise.all([
      this.prisma.product.findMany({ where, orderBy, include: withCategory, skip: (page - 1) * limit, take: limit }),
      this.prisma.product.count({ where }),
    ]);
    return { data: rows.map(toProduct), total };
  }

  async get(id: number) {
    const row = await this.prisma.product.findUnique({ where: { id }, include: withCategory });
    return row ? toProduct(row) : undefined;
  }

  async create({ name, category, price, stock }: { name: string; category: string; price: number; stock: number }) {
    try {
      const row = await this.prisma.product.create({
        data: { name, price, stock, category: { connect: { name: category } } },
        include: withCategory,
      });
      return toProduct(row);
    } catch (err) {
      if (code(err) === "P2025") throw new AppError("CATEGORY_NOT_FOUND");
      throw err;
    }
  }

  async update(id: number, { category, ...rest }: Partial<Omit<Product, "id">>) {
    const exists = await this.prisma.product.findUnique({ where: { id }, select: { id: true } });
    if (!exists) return undefined;
    try {
      const row = await this.prisma.product.update({
        where: { id },
        data: { ...rest, ...(category ? { category: { connect: { name: category } } } : {}) },
        include: withCategory,
      });
      return toProduct(row);
    } catch (err) {
      if (code(err) === "P2025") throw new AppError("CATEGORY_NOT_FOUND");
      throw err;
    }
  }

  async remove(id: number) {
    try {
      await this.prisma.product.delete({ where: { id } });
      return true;
    } catch (err) {
      if (code(err) === "P2025") return false;
      if (code(err) === "P2003") throw new AppError("PRODUCT_HAS_ORDERS");
      throw err;
    }
  }
}

ב־update, P2025 יכול לבוא משני מקומות (המוצר או הקטגוריה) — לכן בודקים קודם שהמוצר קיים. (יש בזה מרוץ קטן: מוצר שנמחק בין הבדיקה לעדכון ידווח כ"קטגוריה לא נמצאה". זה מקרה נדיר, ובשביל להבדיל באמת צריך לבדוק את שניהם באותו transaction.)

// P19-E25
import type { PrismaClient } from "../files/generated/prisma/client.ts";

export async function monthlyReport(prisma: PrismaClient, year: number) {
  return prisma.$queryRaw<{ month: string; orders: number; revenue: number; runningTotal: number }[]>`
    WITH sales AS (
      SELECT EXTRACT(MONTH FROM o.created_at AT TIME ZONE 'UTC')::int AS m,
             COUNT(DISTINCT o.id) AS orders,
             SUM(oi.quantity * oi.unit_price) AS revenue
      FROM orders o
      JOIN order_items oi ON oi.order_id = o.id
      WHERE o.status <> 'cancelled'
        AND o.created_at >= make_timestamptz(${year}::int, 1, 1, 0, 0, 0, 'UTC')
        AND o.created_at <  make_timestamptz(${year}::int + 1, 1, 1, 0, 0, 0, 'UTC')
      GROUP BY 1
    )
    SELECT to_char(make_date(${year}::int, g.m, 1), 'YYYY-MM') AS month,
           COALESCE(s.orders, 0)::int AS orders,
           COALESCE(s.revenue, 0)::float AS revenue,
           (SUM(COALESCE(s.revenue, 0)) OVER (ORDER BY g.m))::float AS "runningTotal"
    FROM generate_series(1, 12) AS g(m)
    LEFT JOIN sales s ON s.m = g.m
    ORDER BY g.m`;
}

שלושה כלים מהפרקים הקודמים בשאילתה אחת: CTE, LEFT JOIN מ"רשימת כל הערכים" (כדי שחודש ריק יופיע עם 0), ופונקציית חלון. ה־${year}::int — פרמטר עם המרה מפורשת, כי PostgreSQL לא תמיד מנחש את הטיפוס של פרמטר.

⚠️ טעויות נפוצות
  • GROUP BY ישר על orders — חודשים בלי מכירות פשוט לא יופיעו, והגרף בדשבורד "יקפוץ" מפברואר לאפריל.

// P19-E88: router שמקבל repository
import express from "express";
import { z } from "zod";

type Customer = { id: number; fullName: string; email: string; city: string | null };
interface CustomersRepository {
  findById(id: number): Promise<Customer | undefined>;
  findByEmail(email: string): Promise<Customer | undefined>;
  insert(data: Omit<Customer, "id">): Promise<Customer>;
  delete(id: number): Promise<boolean>;
}

const CreateCustomer = z.object({
  fullName: z.string().trim().min(1),
  email: z.email().transform((e) => e.toLowerCase()),
  city: z.string().nullable().default(null),
});

const parseId = (raw: string) => {
  const id = Number(raw);
  return Number.isInteger(id) && id > 0 ? id : undefined;
};

export function createApp(repo: CustomersRepository) {
  const app = express();
  app.use(express.json());

  app.get("/customers/:id", async (req, res) => {
    const id = parseId(req.params.id);
    if (id === undefined) return res.status(400).json({ error: "VALIDATION" });
    const c = await repo.findById(id);
    if (!c) return res.status(404).json({ error: "NOT_FOUND" });
    res.json(c);
  });

  app.post("/customers", async (req, res) => {
    const parsed = CreateCustomer.safeParse(req.body);
    if (!parsed.success) return res.status(400).json({ error: "VALIDATION" });
    res.status(201).json(await repo.insert(parsed.data));
  });

  app.delete("/customers/:id", async (req, res) => {
    const id = parseId(req.params.id);
    if (id === undefined) return res.status(400).json({ error: "VALIDATION" });
    if (!(await repo.delete(id))) return res.status(404).json({ error: "NOT_FOUND" });
    res.status(204).end();
  });

  app.use((err: any, _req: express.Request, res: express.Response, _next: express.NextFunction) => {
    if (err?.code === "EMAIL_TAKEN") return res.status(409).json({ error: "EMAIL_TAKEN" });
    res.status(500).json({ error: "INTERNAL" });
  });
  return app;
}
