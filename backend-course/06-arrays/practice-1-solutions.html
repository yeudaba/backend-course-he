P06-E29 · אינדקס, length ו־at 🧠 הבנה רמה 1

💡 רמז 1

האינדקסים הם 0 עד length - 1. אינדקס שלא קיים — undefined, בלי שגיאה.

💡 רמז 2

at עם מספר שלילי סופר מהסוף: -1 הוא האחרון, -4 הוא... כמה איברים יש?

✅ פתרון
const days = ["א", "ב", "ג", "ד"];
console.log(days.length);
console.log(days[days.length - 1]);
console.log(days[days.length]);
console.log(days.at(-1), days.at(-4), days.at(-5));
console.log(days[-1]);
console.log(days[1] + days[2]);

ד
undefined

days[days.length] הוא תמיד undefined — האינדקס האחרון הוא length - 1. הסוגריים המרובעים לא "מבינים" מספר שלילי: days[-1] מחפש תא שהשם שלו "-1", ואין כזה. at נכתבה בדיוק בשביל זה — היא סופרת מהסוף. at(-5) במערך של 4 — מחוץ לטווח, ולכן undefined.

⚠️ טעויות נפוצות
  • לחשוב ש־days[days.length] הוא האחרון — זו טעות "אחד יותר מדי" (off-by-one), הקלאסית ביותר בתכנות.
  • לצפות לשגיאה על אינדקס שלא קיים. JavaScript מחזירה undefined בשקט — ולכן הבאג מתגלה רק מאוחר יותר.

P06-E30 · מה מחזירות push, pop, shift? 🧠 הבנה רמה 1

💡 רמז 1

חזור לטבלה בשיעור: push ו־unshift מחזירות את האורך החדש; pop ו־shift — את האיבר שהוסר.

💡 רמז 2

מערך ריק: אין מה להסיר. האם זו שגיאה?

✅ פתרון
const list = ["a"];
const n1 = list.push("b");
const n2 = list.unshift("z");
console.log(n1, n2, list);
const x = list.pop();
const y = list.shift();
console.log(x, y, list);
const empty = [];
console.log(empty.pop(), empty.shift(), empty.length);
2 3 [ 'z', 'a', 'b' ]
b z [ 'a' ]
undefined undefined 0

push החזירה 2 (האורך אחרי ההוספה), ו־unshift — 3. pop ו־shift החזירו את מה שהוצא. ממערך ריק הן מחזירות undefined — בלי שגיאה, והמערך נשאר ריק.

⚠️ טעויות נפוצות
  • לכתוב const last = list.push("b"); ולחשוב ש־last הוא "b". זה המספר 2.
  • להניח שאחרי pop יש תמיד ערך. בתור ריק מקבלים undefined, ולכן בודקים קודם את length (כמו ב־P06-E07).

P06-E31 · const ומערך — מה מותר? 🧠 הבנה רמה 1

💡 רמז 1

const שומר על המדבקה — אי אפשר להצמיד אותה לקופסה אחרת. מה שבתוך הקופסה — מותר לשנות.

💡 רמז 2

יש רק שורה אחת שמחליפה את הקופסה של משתנה const.

✅ פתרון

רק ג זורקת: TypeError: Assignment to constant variable. — זו הצבה חדשה (=) למשתנה const. כל השאר משנים את התוכן של המערך (א, ב, ד, ו), או מציבים מחדש למשתנה let (ה). הנה הקוד בלי שורה ג:

const cart = ["עט"];
cart.push("מחברת");
cart[0] = "עיפרון";
cart.pop();
let tags = ["a"];
tags = ["b", "c"];
const empty = [];
empty[0] = "ראשון";
console.log(cart, tags, empty);
[ 'עיפרון' ] [ 'b', 'c' ] [ 'ראשון' ]

למה const? כי כמעט אף פעם לא צריך "מערך אחר" באותו שם — צריך לשנות את המערך הקיים. const מבטיח שאף שורה בהמשך לא תחליף אותו בטעות, למשל ב־cart = [] שמנתק את כל מי שעוד מחזיק בעגלה הישנה (על זה — בפרק 7).

⚠️ טעויות נפוצות
  • לחשוב ש־const הופך את המערך ל"קפוא". הוא לא — push עובד.
  • להחליף ל־let רק כדי ש־push "יעבוד". הוא עובד גם עם const.

P06-E32 · includes מול indexOf 🧠 הבנה רמה 2

💡 רמז 1

שתי המתודות משוות עם === — בלי המרות, ועם אותיות גדולות/קטנות.

💡 רמז 2

מה מחזירה indexOf עבור האיבר הראשון? ומה עבור איבר שלא קיים? עכשיו — מה truthy ומה falsy (פרק 3)?

✅ פתרון
const roles = ["viewer", "editor", "admin"];
console.log(roles.includes("Admin"), roles.indexOf("admin"));
console.log(["5", 7].includes(5), ["5", 7].indexOf(7));
if (roles.indexOf("viewer")) {
  console.log("viewer נמצא");
} else {
  console.log("viewer לא נמצא?!");
}
if (roles.indexOf("owner")) {
  console.log("owner נמצא?!");
}
false 2
false 1
viewer לא נמצא?!
owner נמצא?!

השורות עם if הן המלכודת. indexOf("viewer") הוא 0 — falsy, ולכן מודפס "לא נמצא" על איבר שקיים. indexOf("owner") הוא -1 — truthy, ולכן מודפס "נמצא" על איבר שלא קיים. שני באגים הפוכים מאותה סיבה.

לשאלה "האם קיים?" — includes, שמחזירה בוליאני אמיתי. indexOf רק כשצריך את המיקום, ואז בודקים במפורש !== -1.

⚠️ טעויות נפוצות
  • if (list.indexOf(x)) — עובד לכל איבר חוץ מהראשון, ולכן עובר בדיקה ידנית מהירה ונשבר בפרודקשן.
  • לצפות ש־includes(5) ימצא את "5". השוואה היא ===.

P06-E33 · תור או מחסנית? 🧠 הבנה רמה 1

💡 רמז 1

שאל: "מי צריך לצאת קודם — מי שחיכה הכי הרבה, או מי שהגיע אחרון?"

💡 רמז 2

"בטל" מבטל את הפעולה האחרונה. מדפסת מדפיסה את מי ששלח ראשון.

✅ פתרון

s.push(4);

P06-E06 · גישה בטוחה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

arr[arr.length - 1]. למערך ריק זה arr[-1] — undefined, וזה בדיוק מה שצריך.

💡 רמז 2

if (index < 0 || index >= arr.length) return fallback;

✅ פתרון
// P06-E06: גישה בטוחה לאיברים
function lastItem(arr) {
  return arr[arr.length - 1];
}

function firstAndLast(arr) {
  if (arr.length === 0) {
    return [];
  }
  return [arr[0], arr[arr.length - 1]];
}

function safeGet(arr, index, fallback = null) {
  if (index < 0 || index >= arr.length) {
    return fallback;
  }
  return arr[index];
}

console.log(lastItem([1, 2, 3]), firstAndLast(["a", "b", "c"]), safeGet([10, 20], 5, 0));

module.exports = { lastItem, firstAndLast, safeGet };
3 [ 'a', 'c' ] 0
⚠️ טעויות נפוצות
  • safeGet עם arr[index] ?? fallback — נכשל כשהאיבר עצמו null או כשהאינדקס שלילי ובעתיד מישהו ישתמש ב־at.

P06-E07 · תור בבית קפה 🤖 💻 כתיבת קוד 🤖 רמה 2

P06-E26 · range — מערך של מספרים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

מתחילים ממערך ריק const result = [];, ובלולאת for מוסיפים עם push.

💡 רמז 2

guard לפני הלולאה: if (step <= 0) return [];. הלולאה: for (let i = start; i < end; i += step).

✅ פתרון
// P06-E26: range
function range(start, end, step = 1) {
  if (step <= 0) return [];
  const result = [];
  for (let i = start; i < end; i += step) {
    result.push(i);
  }
  return result;
}

console.log(range(1, 5));
console.log(range(0, 10, 3));

module.exports = { range };
[ 1, 2, 3, 4 ]
[ 0, 3, 6, 9 ]

זה הדפוס הבסיסי ביותר לבניית מערך: מערך ריק, לולאה, push, ו־return בסוף. ה־const לא מפריע ל־push: const אומר שהמשתנה תמיד מצביע על אותו מערך, לא שהמערך קפוא.

ב־Python יש range מובנית. ב־JavaScript אין, ולכן כותבים אותה (או Array.from({ length: n }, (_, i) => i), שתפגוש בהמשך).

⚠️ טעויות נפוצות
  • i <= end — ה־end נכנס למערך (range(1, 5) מחזירה 5 מספרים).
  • בלי ה־guard, range(0, 5, 0) לא מסתיימת לעולם.
  • console.log במקום return — הבודק מקבל undefined.

P06-E37 · רמות הרשאה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

roleLevel היא שורה אחת עם indexOf. canAccess משתמשת בה פעמיים.

💡 רמז 2

guard: אם אחת הרמות היא -1 ← false. אחרת: return level >= requiredLevel;

✅ פתרון
06-arrays/starter/P06-E37.js 
const ROLES = ["viewer", "editor", "admin"];

function roleLevel(role) {
  return ROLES.indexOf(role);
}

function canAccess(role, required) {
  const level = roleLevel(role);
  const requiredLevel = roleLevel(required);
  if (level === -1 || requiredLevel === -1) {
    return false;
  }
  return level >= requiredLevel;
}

console.log(canAccess("admin", "editor"), canAccess("viewer", "editor"), canAccess("owner", "viewer"));

module.exports = { roleLevel, canAccess };
true false false

היתרון של מערך על פני שרשרת if: כדי להוסיף תפקיד (למשל "owner" מעל admin) משנים שורה אחת — המערך — וכל הפונקציות ממשיכות לעבוד.

⚠️ טעויות נפוצות
  • בלי ה־guard: canAccess("owner", "viewer") משווה -1 >= 0 — false במקרה. אבל canAccess("viewer", "owner") משווה 0 >= -1 ומחזיר true — כל אחד מקבל גישה לתפקיד שלא קיים.

P06-E38 · בטל ובצע שוב (undo/redo) 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שתי מחסניות: pop מאחת, push לשנייה. איך מרוקנים מערך בלי להציב מערך חדש (הפרמטר הוא עותק של המדבקה, ו־redoStack = [] לא ישנה את המערך של מי שקרא)? לולאה מפרק 4: כל עוד יש בו משהו — pop.

💡 רמז 2
while (redoStack.length > 0) {
  redoStack.pop();
}
✅ פתרון
06-arrays/starter/P06-E38.js 
function doAction(history, redoStack, action) {
  history.push(action);
  while (redoStack.length > 0) {
    redoStack.pop();
  }
}

function undo(history, redoStack) {
  if (history.length === 0) {
    return null;
  }
  const action = history.pop();
  redoStack.push(action);
  return action;
}

function redo(history, redoStack) {
  if (redoStack.length === 0) {
    return null;
  }
  const action = redoStack.pop();
  history.push(action);
  return action;
}

const history = [];
const redoStack = [];
doAction(history, redoStack, "A");
doAction(history, redoStack, "B");
console.log(undo(history, redoStack), history, redoStack);
doAction(history, redoStack, "C");
console.log(redo(history, redoStack), history, redoStack);

module.exports = { doAction, undo, redo };
B [ 'A' ] [ 'B' ]
null [ 'A', 'C' ] []

שתי מחסניות שמעבירות ביניהן איברים — כך בדיוק עובדים Ctrl+Z ו־Ctrl+Y. שים לב ל־doAction: redoStack = [] בתוך הפונקציה היה יוצר מערך חדש מקומי, והמערך של מי שקרא היה נשאר מלא. לכן מרוקנים את המערך עצמו.

⚠️ טעויות נפוצות
  • redoStack = []; בתוך doAction — עובד "בתוך" הפונקציה, אבל המערך המקורי לא מתרוקן. הבודק תופס את זה.
  • shift במקום pop — מבטל את הפעולה הראשונה שבוצעה, לא את האחרונה.

P06-E39 · מחרוזת מול מערך 🧠 הבנה רמה 2

💡 רמז 1

includes במחרוזת מחפשת רצף תווים. במערך — איבר שווה.

💡 רמז 2

מחרוזת היא immutable — אי אפשר לשנות בה תו. ההצבה word[0] = "N" פשוט לא עושה כלום (בלי שגיאה).

✅ פתרון
const word = "node";
const letters = ["n", "o", "d", "e"];
console.log(word[0], letters[0], word.at(-1), letters.at(-1));
console.log(word.includes("od"), letters.includes("od"));
word[0] = "N";
letters[0] = "N";
console.log(word, letters);
const upper = word.toUpperCase();
console.log(word, upper);
n n e e
true false
node [ 'N', 'o', 'd', 'e' ]
node NODE

letters.includes("od") הוא false — אין במערך איבר ששווה ל־"od". וההבדל המרכזי: word[0] = "N" לא שינה את המחרוזת (בשקט!), אבל letters[0] = "N" שינה את המערך.

⚠️ טעויות נפוצות
  • לנסות "לתקן" תו במחרוזת עם s[i] = .... צריך לבנות מחרוזת חדשה (slice, replace, או — מהשיעור הבא — split ו־join).

P06-E40 · while שמרוקן תור 🧠 הבנה רמה 2

💡 רמז 1

כתוב טבלה: בכל סיבוב — מה ב־queue לפני ואחרי, ומה served.

💡 רמז 2

queue.length בתוך ההדפסה נמדד אחרי ה־shift, אבל לפני ה־push.

✅ פתרון
const queue = ["דנה", "עומר", "נועה"];
let served = 0;
while (queue.length > 0) {
  const next = queue.shift();
  served++;
  console.log(`${served}: ${next} (נשארו ${queue.length})`);
  if (next === "עומר") {
    queue.push("עומר שוב");
  }
}
console.log(served, queue);

2: עומר (נשארו 1)
3: נועה (נשארו 1)
4: עומר שוב (נשארו 0)

"עומר שוב" נכנס לסוף התור ומטופל רביעי, ואז התור מתרוקן והלולאה עוצרת. אם היינו מכניסים את next עצמו ("עומר"), הוא היה יוצא שוב, נכנס שוב — לולאה אינסופית. בתור אמיתי (פרק 26) לכן סופרים ניסיונות ומוותרים אחרי כמה.

⚠️ טעויות נפוצות
  • לחשוב שהלולאה רצה 3 פעמים "כי היו 3 אנשים". התנאי נבדק מחדש בכל סיבוב, על המערך כפי שהוא עכשיו.

P06-E41 · פונקציה שמקבלת מערך 🧠 הבנה רמה 2

💡 רמז 1

הפרמטר list הוא מדבקה חדשה — על אותה קופסה ש־items מצביע עליה.

💡 רמז 2

push משנה את הקופסה. list = [...] מזיז רק את המדבקה list לקופסה חדשה.

✅ פתרון
function addOne(n) {
  n = n + 1;
  return n;
}
function addItem(list) {
  list.push("חדש");
  return list.length;
}
function replaceList(list) {
  list = ["אחר"];
  return list.length;
}

let count = 5;
console.log(addOne(count), count);

const items = ["א"];
console.log(addItem(items), items);

addOne לא שינתה את count. addItem כן שינתה את items — דרך push על אותה קופסה. replaceList לא שינתה אותו: היא העבירה את המדבקה המקומית שלה לקופסה אחרת, והקופסה של items נשארה כמו שהייתה.

⚠️ טעויות נפוצות
  • לחשוב ש־list = [...] בתוך פונקציה "מחליף" את המערך של מי שקרא. כדי לשנות את המערך המקורי — משנים את התוכן שלו (push, pop, הצבה לתא).

P06-E42 · ספרות של מספר 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הספרה הימנית: n % 10. המספר בלעדיה: Math.floor(n / 10). חוזרים כל עוד n > 0.

💡 רמז 2

המקרה של 0: הלולאה לא תרוץ אף פעם. guard בהתחלה: if (n === 0) { return [0]; }

✅ פתרון
06-arrays/starter/P06-E42.js 
function digits(n) {
  if (n === 0) {
    return [0];
  }
  const result = [];
  while (n > 0) {
    result.unshift(n % 10);
    n = Math.floor(n / 10);
  }
  return result;
}

console.log(digits(1234), digits(507), digits(0));

module.exports = { digits };
[ 1, 2, 3, 4 ] [ 5, 0, 7 ] [ 0 ]
⚠️ טעויות נפוצות
  • push במקום unshift — מקבלים את הספרות הפוך: [4, 3, 2, 1].
  • n = n / 10 בלי Math.floor — n הופך ל־123.4, 12.34... והלולאה רצה עוד מאות סיבובים עד שהמספר נהיה קטן מאוד (ו־n % 10 כבר לא ספרה).

P06-E43 · לשרת את התור 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

מערך חדש ריק לתוצאה. בכל סיבוב: shift מהתור, push לתוצאה.

💡 רמז 2

while (served.length < count && queue.length > 0) { ... }

✅ פתרון
06-arrays/starter/P06-E43.js 
function serve(queue, count = 1) {
  const served = [];
  while (served.length < count && queue.length > 0) {
    served.push(queue.shift());
  }
  return served;
}

const queue = ["דנה", "עומר", "נועה", "יוסי"];
console.log(serve(queue, 2), serve(queue), serve(queue, 5), serve(queue, 3));

module.exports = { serve };
[ 'דנה', 'עומר' ] [ 'נועה' ] [ 'יוסי' ] []

served.length הוא גם המונה — אין צורך במשתנה i נפרד.

⚠️ טעויות נפוצות
  • for (let i = 0; i < count; i++) בלי לבדוק שהתור לא ריק — כשנגמרים האנשים, shift מחזיר undefined, והתוצאה מתמלאת ב־undefined.
  • for (let i = 0; i < queue.length; i++) עם shift בפנים — האורך קטן בכל סיבוב, ו־i גדל: הלולאה עוצרת באמצע.

P06-E44 · היסטוריית גלישה מוגבלת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שלושה שלבים: נקה (trim), שני guards שמחזירים את history בלי שינוי, ואז push.

💡 רמז 2

האחרון: history.at(-1). הישן ביותר — בהתחלה: if (history.length > max) { history.shift(); }

✅ פתרון
06-arrays/starter/P06-E44.js 
function visit(history, page, max = 5) {
  const clean = page.trim();
  if (clean === "") {
    return history;
  }
  if (history.at(-1) === clean) {
    return history;
  }
  history.push(clean);
  if (history.length > max) {
    history.shift();
  }
  return history;
}

const h = ["/home", "/products"];
console.log(visit(h, "/products"));
console.log(visit(h, " /cart "));
console.log(visit(h, "/home", 3));

module.exports = { visit };
[ '/home', '/products' ]
[ '/home', '/products', '/cart' ]
[ '/products', '/cart', '/home' ]

מספיק if אחד (ולא לולאה) כדי לשמור על המגבלה: בכל קריאה נוסף לכל היותר דף אחד, ולכן לכל היותר צריך למחוק אחד.

⚠️ טעויות נפוצות
  • להשוות את page לפני ה־trim — " /cart " לא שווה ל־"/cart", והרענון נספר כדף חדש.
  • לבדוק history.includes(page) במקום רק את האחרון — אז אי אפשר לחזור לדף הבית אחרי שהיית בו פעם.
