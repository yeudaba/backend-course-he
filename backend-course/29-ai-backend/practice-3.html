P29-E26 · לחלק מסמכים לקטעים, ולמצוא את הרלוונטיים 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 30 דק׳ידע נדרש: שיעור 3

באתגר E25 המודל עונה מתוך מסמכי החנות. כשהמסמכים גדולים, לא שולחים את כולם בכל שאלה: זה יקר, איטי, ומבלבל את המודל. מחלקים אותם לקטעים, ושולחים רק את הקטעים הרלוונטיים (RAG). במערכת אמיתית "רלוונטי" נמדד עם embeddings. כאן נבנה את אותו מבנה עם ניקוד פשוט לפי מילים, מקובץ ריק. כתוב וייצא:

  • chunk(text, maxChars = 500): string[]:
    • פסקאות מופרדות בשורה ריקה (גם אם יש בה רווחים). מורידים רווחים מסביב לכל פסקה, ומדלגים על ריקות.
    • פסקה ארוכה מ־maxChars מתפרקת למשפטים (אחרי ., ‏! או ? ורווח). משפט שעדיין ארוך מדי נחתך כל maxChars תווים.
    • אחר כך אורזים לפי הסדר: מוסיפים חלק לקטע הנוכחי (עם "\n\n" ביניהם) כל עוד האורך הכולל לא עובר את maxChars. אחרת — קטע חדש.
    • maxChars שאינו שלם חיובי ← RangeError.
  • retrieve(chunks, question, k = 3) ← [{ index, score, text }]. "מילה" היא רצף של 3 אותיות או ספרות ומעלה (גם בעברית), בלי תלות באותיות גדולות. ‏score — כמה מילים שונות מהשאלה מופיעות בקטע. רק score > 0, מהגבוה לנמוך, בתיקו לפי index, ולכל היותר k.

P29-E28 · תבנית prompt עם משתנים 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 2⏱ 20 דק׳ידע נדרש: שיעור 3

🔁 חזרה על replace עם regex ופונקציה (‏P13-E26, ‏P25.5-E28), ‏Set (פרק 7) ו־Object.hasOwn. prompts נכתבים כתבניות, וחלק מהערכים מגיעים מהמשתמש. כתוב וייצא renderPrompt(template, vars, untrusted = []):

  • {{name}} (מותרים רווחים בתוך הסוגריים: {{ name }}) מוחלף ב־vars.name. שם: אות או _, ואחריהם אותיות, ספרות או _.
  • ערך לא נקרא שוב כתבנית: אם vars.a הוא "{{b}}", התוצאה מכילה {{b}}. גם $& בתוך ערך נשאר כמו שהוא.
  • משתנה בתבנית שלא קיים ב־vars (כמפתח שלו, לא toString) ← Error עם השם. משתנה ב־vars שלא הופיע בתבנית ← Error עם השם (כנראה טעות הקלדה).
  • שם שנמצא ב־untrusted נעטף: <document name="msg">, שורה חדשה, הערך, שורה חדשה, </document>. ‏</document> בתוך הערך הופך ל־&lt;/document&gt;, כדי שאי אפשר יהיה "לצאת" מהעטיפה (שיעור 3).
