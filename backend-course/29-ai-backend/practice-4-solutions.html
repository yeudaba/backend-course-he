פרק 25 — סודות.

✅ פתרון
  1. לשלוח: מספר הזמנה, סטטוס, תאריכים, שמות המוצרים. לא: כתובת מלאה, טלפון, אימייל, ארבע ספרות כרטיס, הערות פנימיות של צוות. כל מה שנשלח לספק חיצוני — עובר אליו; בדוק מה תנאי השמירה, ואם יש דרישות רגולציה (מידע אישי, GDPR).

  3. במשתנה סביבה בשרת (ANTHROPIC_API_KEY), כמו כל סוד (פרק 25) — אף פעם לא בקוד, ב־Git, או בדפדפן. בדפדפן כל משתמש יכול לפתוח DevTools ולהעתיק. דלף? מבטלים את המפתח בקונסולה ומייצרים חדש — ובודקים בדוח השימוש מה נעשה בו.
⚠️ טעויות נפוצות

P29-E12 · מודל חלופי 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

err instanceof Anthropic.APIError ו־err.status.

💡 רמז 2

למה לא על 429? כי ה־SDK כבר ניסה שוב (E05), ולרוב המגבלה היא על החשבון — לא על המודל. ו־400 ייכשל בכל מודל.

✅ פתרון
// P29-E12
import Anthropic from "@anthropic-ai/sdk";

// ה־SDK כבר מנסה שוב לבד (maxRetries, ברירת מחדל 2) על 408/409/429/5xx. מה שנשאר לנו: מה עושים אחרי שגם זה נכשל.
// עומס או תקלה אצל הספק (5xx, 529 overloaded) ← מודל חלופי. בקשה שגויה (4xx) — אותה בקשה תיכשל גם שם ← זורקים
export async function createWithFallback(
  client: Anthropic,
  params: Anthropic.MessageCreateParamsNonStreaming,
  fallbackModel: string,
): Promise<{ message: Anthropic.Message; usedFallback: boolean }> {
  try {
    return { message: await client.messages.create(params), usedFallback: false };
  } catch (err) {
    const overloaded = err instanceof Anthropic.InternalServerError || (err instanceof Anthropic.APIError && (err.status ?? 0) >= 500);
    if (!overloaded || params.model === fallbackModel) throw err;
    return { message: await client.messages.create({ ...params, model: fallbackModel }), usedFallback: true };
  }
}

(ב־Opus 5.5 יש גם fallbacks בצד השרת — למקרה של סירוב, לא של עומס. שני מנגנונים לשתי בעיות שונות.)

⚠️ טעויות נפוצות
  • fallback בלי לרשום בלוג שהוא קרה — "הכול עובד", ואף אחד לא יודע ש־30% מהבקשות רצות על מודל אחר.

P29-E15 · streaming ללקוח 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

event.type === "content_block_delta" && event.delta.type === "text_delta".

💡 רמז 2

אחרי שהתחלת לכתוב תשובה — אי אפשר להחזיר status 500. השגיאה חייבת לעבור בתוך הזרם.

✅ פתרון
// P29-E15
import type Anthropic from "@anthropic-ai/sdk";

// streaming ללקוח: האירועים של ה־SDK ← Server-Sent Events. רק טקסט יוצא החוצה (לא thinking, לא tool input),
// כל שורת data היא JSON (כך ירידות שורה בטקסט לא שוברות את הפורמט), ובסוף — event: done עם stop_reason
export async function streamToSse(events: AsyncIterable<Anthropic.MessageStreamEvent>, write: (chunk: string) => void): Promise<{ chars: number }> {
  let chars = 0;
  let stopReason: string | null = null;
  try {
    for await (const event of events) {
      if (event.type === "content_block_delta" && event.delta.type === "text_delta") {
        chars += event.delta.text.length;
        write(`data: ${JSON.stringify({ text: event.delta.text })}\n\n`);
      } else if (event.type === "message_delta") {
        stopReason = event.delta.stop_reason ?? stopReason;
      }
    }
  } catch (err) {
    // הזרם כבר התחיל — אי אפשר להחזיר 500. מודיעים בתוך הזרם, והלקוח מציג "משהו השתבש"
    write(`event: error\ndata: ${JSON.stringify({ message: "התשובה נקטעה" })}\n\n`);
    throw err;
  }
  write(`event: done\ndata: ${JSON.stringify({ stop_reason: stopReason })}\n\n`);
  return { chars };
}

ב־Nest: @Sse() מחזיר Observable, או ידנית עם res.setHeader("content-type", "text/event-stream") ו־res.write. ובדפדפן: EventSource, או fetch וקריאה של response.body. (זכור את ה־reverse proxy — nginx צריך proxy_buffering off, אחרת הוא מחזיק את כל התשובה עד הסוף.)

⚠️ טעויות נפוצות
  • לשלוח data: ${text} בלי JSON — ירידת שורה בטקסט מסיימת את האירוע באמצע.

P29-E16 · cache לתשובות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

cache-aside מפרק 26 — אותו דפוס בדיוק.

💡 רמז 2

למה hash ולא השאלה עצמה? מפתח קצר וקבוע, ובלי מידע אישי בשמות מפתחות.

✅ פתרון
// P29-E16
import { createHash } from "node:crypto";
import type Anthropic from "@anthropic-ai/sdk";

export interface KV {
  get(key: string): Promise<string | null>;
  set(key: string, value: string, ttlSeconds: number): Promise<void>;
}

// cache לתשובות (cache-aside, פרק 26) — לשאלות שחוזרות ("מה שעות המשלוח?").
// המפתח: hash של כל מה שמשפיע על התשובה — מודל, system, והשאלה המנורמלת. שומרים רק תשובה שלמה (end_turn)
export function createCachedAsk(client: Anthropic, kv: KV, { model, system, ttlSeconds = 3600 }: { model: string; system: string; ttlSeconds?: number }) {
  const stats = { hits: 0, misses: 0 };
  async function askCached(question: string): Promise<string> {
    const normalized = question.trim().replace(/\s+/g, " ").toLowerCase();
    const key = "ai:" + createHash("sha256").update(JSON.stringify([model, system, normalized])).digest("hex");
    const hit = await kv.get(key);
    if (hit !== null) {
      stats.hits++;
      return hit;
    }
    stats.misses++;
    const response = await client.messages.create({ model, max_tokens: 2048, system, messages: [{ role: "user", content: question.trim() }] });
    const text = response.content.filter((b): b is Anthropic.TextBlock => b.type === "text").map((b) => b.text).join("");
    if (response.stop_reason === "end_turn" && text) await kv.set(key, text, ttlSeconds);
    return text;
  }
  return { ask: askCached, stats };
}

מתי זה עובד? כששאלות באמת חוזרות (FAQ, תיאורי מוצרים) והתשובה לא אישית. "איפה ההזמנה שלי" — אסור ב־cache משותף (פרק 26). וזה שונה מprompt caching של ה־API (שיעור 4): שם ה־API זוכר את תחילת ה־prompt ומוזיל את הקלט; כאן אנחנו לא קוראים בכלל.

⚠️ טעויות נפוצות
  • מפתח בלי המודל או ה־system — מחליפים prompt, והתשובות הישנות ממשיכות לצאת שעה.

P29-E17 · תקציב יומי 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

מפתח ${day}:${userId}, כש־day הוא toISOString().slice(0, 10).

💡 רמז 2

שומרים במיקרו־דולרים — מספרים שלמים (כמו אגורות בפרויקט 3).

✅ פתרון
// P29-E17
// תקציב יומי למשתמש: כל קריאה עולה כסף, ומשתמש אחד (או סקריפט) יכול לשרוף את התקציב של כולם.
// בודקים לפני הקריאה, רושמים אחרי (לפי usage אמיתי), ומתאפסים בחצות UTC
export function createBudget({ dailyUsdPerUser, now = () => Date.now() }: { dailyUsdPerUser: number; now?: () => number }) {
  const spent = new Map<string, number>(); // `${day}:${userId}` ← מיקרו־דולרים (שלמים — בלי שגיאות עיגול)
  const day = () => new Date(now()).toISOString().slice(0, 10);
  const key = (userId: string) => `${day()}:${userId}`;
  const limit = Math.round(dailyUsdPerUser * 1_000_000);
  return {
    check(userId: string): { allowed: boolean; remainingUsd: number } {
      const used = spent.get(key(userId)) ?? 0;
      return { allowed: used < limit, remainingUsd: Math.max(0, limit - used) / 1_000_000 };
    },
    record(userId: string, usd: number) {
      if (!(usd >= 0)) throw new Error("עלות לא תקינה");
      const k = key(userId);
      spent.set(k, (spent.get(k) ?? 0) + Math.round(usd * 1_000_000));
      for (const old of spent.keys()) if (!old.startsWith(day() + ":")) spent.delete(old); // לא שומרים ימים קודמים
    },
  };
}

בשרת עם כמה עותקים — המונה ב־Redis (INCRBY ו־EXPIRE, פרק 26). ובדרך כלל עוד שכבה: מגבלה של כל הארגון בקונסולה של הספק, כרשת ביטחון אחרונה.

⚠️ טעויות נפוצות
  • לבדוק תקציב רק אחרי הקריאה — הכסף כבר הוצא. בודקים לפני, רושמים אחרי.

P29-E18 · קיצור היסטוריה עם כלים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

מהסוף להתחלה, מצטברים עד שעוברים.

💡 רמז 2

Array.isArray(m.content) && m.content.some((b) => b.type === "tool_result").

✅ פתרון
// P29-E18
import type Anthropic from "@anthropic-ai/sdk";

// קיצור היסטוריה לפי תקציב טוקנים: משאירים את הסוף. אסור לחתוך בין tool_use לבין ה־tool_result שלו
// (ה־API דוחה tool_result בלי tool_use לפניו), וההודעה הראשונה חייבת להיות user עם טקסט — לא tool_result
const hasToolResult = (m: Anthropic.MessageParam) => Array.isArray(m.content) && m.content.some((b) => b.type === "tool_result");

export function trimHistory(messages: readonly Anthropic.MessageParam[], maxTokens: number, estimate: (m: Anthropic.MessageParam) => number): Anthropic.MessageParam[] {
  let total = 0;
  let start = messages.length;
  for (let i = messages.length - 1; i >= 0; i--) {
    const cost = estimate(messages[i]);
    if (total + cost > maxTokens) break;
    total += cost;
    start = i;
  }
  // מקדמים את ההתחלה עד הודעת user "נקייה" — כך לא נשאר tool_result יתום ולא assistant ראשון
  while (start < messages.length && (messages[start].role !== "user" || hasToolResult(messages[start]))) start++;
  return messages.slice(start);
}

(להערכת טוקנים מדויקת יש client.messages.countTokens — קריאה ל־API, חינם אבל עם רשת. לחיתוך, הערכה גסה בקוד מספיקה — אבל את היחס בין תווים לטוקנים בעברית כדאי למדוד פעם אחת עם countTokens, ולא לנחש לפי אנגלית.)

⚠️ טעויות נפוצות
  • לחתוך באמצע זוג tool_use/tool_result — ה־API מחזיר 400, והשיחה "נתקעת" אחרי שעה של שימוש.

P29-E23 · cache ועלות — שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

prompt caching הוא התאמה של תחילת הבקשה, בית אחרי בית. מה משתנה בכל בקשה?

💡 רמז 2

איפה cache_control? ובחישוב — באיזה מחיר מחויב הקלט?

✅ פתרון
// P29-E23
import type Anthropic from "@anthropic-ai/sdk";

export const POLICY = "You answer questions about the shop's shipping, returns and warranty policy. ...";

export function buildRequest(policyDocument: string, question: string, now: Date): Anthropic.MessageCreateParamsNonStreaming {
  return {
    model: "claude-opus-5-5",
    max_tokens: 2048,
    system: [
      // תקלה 1: התאריך היה בתוך ה־system ← כל בקשה עם prefix שונה, וה־cache לא נקרא אף פעם.
      // החלק הקבוע ראשון ועם cache_control (תקלה 2: לא היה בכלל), והמשתנה — אחריו
      { type: "text", text: `${POLICY}\n\n<policy>\n${policyDocument}\n</policy>`, cache_control: { type: "ephemeral" } },
    ],
    messages: [{ role: "user", content: `(today is ${now.toISOString().slice(0, 10)})\n\n${question}` }],
  };
}

export function costUsd(usage: Anthropic.Usage, prices = { input: 4, output: 20, cacheWrite: 5, cacheRead: 0.2 }): number {
  // תקלה 3: היה (input + output) * prices.output ← הקלט חויב במחיר הפלט, ו־cache לא נספר בכלל
  return (
    (usage.input_tokens * prices.input +
      usage.output_tokens * prices.output +
      (usage.cache_creation_input_tokens ?? 0) * prices.cacheWrite +
      (usage.cache_read_input_tokens ?? 0) * prices.cacheRead) /
    1_000_000
  );
}

הבדיקה שמוצאת את זה: usage.cache_read_input_tokens בבקשה השנייה. אפס ← משהו ב־prefix משתנה. החשודים הרגילים: תאריך או שעה, מזהה בקשה, JSON עם סדר מפתחות משתנה, או רשימת כלים שמשתנה.

⚠️ טעויות נפוצות
  • "נוסיף cache_control ונראה" — בלי למדוד hit rate. caching שלא פוגע הוא תוספת עלות (כתיבה ל־cache יקרה מקלט רגיל).

P29-E27 · בדיקות ל־redactPII 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

לכל "כולל" בתיאור — בדיקה: אימייל עם +, אימייל עם .co.il, כרטיס עם רווחים, כרטיס עם מקפים, טלפון עם +972. ושתי הופעות באותו טקסט: regex בלי הדגל g מחליף רק את הראשונה.

💡 רמז 2

החצי השני של הבדיקות הוא מה שלא משתנה: assert.equal(redactPII(s), s) על רשימה. גבולות: 13 ספרות (כרטיס) מול 12 (מספר הזמנה). ומספר ארוך מאוד (20 ספרות): אסור שחלק ממנו יוחלף.

✅ פתרון
// P29-E27 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { redactPII } from "./P29-E27.ts";

test("אימיילים — כולל + ודומיין עם כמה חלקים, וכולם (לא רק הראשון)", () => {
  assert.equal(redactPII("כתבו לי ל־dana@example.com"), "כתבו לי ל־[EMAIL]");
  assert.equal(redactPII("dana.levi+shop@mail.co.il"), "[EMAIL]");
  assert.equal(redactPII("a@x.io, b@y.io"), "[EMAIL], [EMAIL]");
});

test("כרטיס אשראי: 13–16 ספרות, עם רווחים או מקפים", () => {
  assert.equal(redactPII("כרטיס 4580123456789012 בבקשה"), "כרטיס [CARD] בבקשה");
  assert.equal(redactPII("4580 1234 5678 9012"), "[CARD]");
  assert.equal(redactPII("4580-1234-5678-9012"), "[CARD]");
  assert.equal(redactPII("1234567890123"), "[CARD]", "13 ספרות");
});

test("טלפון נייד: עם ובלי מקפים, ועם +972", () => {
  assert.equal(redactPII("התקשרו ל־0521234567"), "התקשרו ל־[PHONE]");
  assert.equal(redactPII("052-123-4567"), "[PHONE]");
  assert.equal(redactPII("052 123 4567"), "[PHONE]");
  assert.equal(redactPII("+972-52-123-4567"), "[PHONE]");
  assert.equal(redactPII("+972521234567"), "[PHONE]");
  assert.equal(redactPII("0521234567 ו־0549876543"), "[PHONE] ו־[PHONE]");
});

test("מה שלא מוחלפים", () => {
  for (const s of ["הזמנה מספר 123456789012", "ת.ז. 123456782", "טלפון בבית 03-1234567", "ב־2026 קניתי 3 שקיות", "dana at example dot com", "05212345678901234567"]) {
    assert.equal(redactPII(s), s, s);
  }
});

הבדיקה האחרונה, "מה שלא מוחלף", תופסת שלושה באגים לבד: כרטיס מ־12 ספרות (מספר ההזמנה נמחק), כרטיס בלי \b (חלק מהמספר בן 20 הספרות נמחק), וטלפון שמקבל גם קווי. ב־redaction, החלפה מיותרת היא באג אמיתי: מספר הזמנה שנמחק מהפנייה הופך את התשובה של המודל לחסרת תועלת.

regex הוא הקוד שהכי קל לשבור בשינוי קטן, ואף אחד לא קורא אותו ב־code review. בדיקות עם דוגמאות אמיתיות הן התיעוד היחיד שלו. כשמישהו "מתקן" את הטלפון כדי לתפוס גם קווי, הבדיקה של 03-1234567 מראה לו מה עוד השתנה.

⚠️ טעויות נפוצות
  • רק מקרים שצריכים להתחלף — מימוש שמחליף כל רצף ספרות עובר את כולם.
  • טקסט עם הופעה אחת של כל סוג — באג של דגל g חסר עובר.
  • assert.match(out, /\[EMAIL\]/) — לא בודק ששאר הטקסט נשאר. ‏assert.equal על כל המחרוזת.
