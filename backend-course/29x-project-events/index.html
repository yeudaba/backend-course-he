מה צריך שכבר יהיה מותקן: מהיחידות 25.5, 26.3, 26.5, 28.5 ו־29.5 — MySQL, Kafka, DuckDB ו־SDK של Claude. הקונטיינרים של MySQL ו־Kafka רצים (docker start mysql kafka).

📂 העתקת חומרי הפרק: ב־Finder, העתק את התיקייה 29x-project-events מתוך ~/Desktop/Backend/backend-course אל ~/dev/backend-course (גרירה עם ⌥ Option). אם התיקייה כבר שם מהעתקה קודמת ואתה רוצה לשמור את מה שכתבת — בחר Keep Both / Stop ולא Replace.

🎯 בסוף הפרק תדע
  • לתכנן מערכת נתונים מקצה לקצה: קליטה, תור, עיבוד, אחסון שורתי ועמודתי, ו־API — עם חוזה בין החלקים.
  • נכונות בקנה מידה: at-least-once מ־Kafka, אידמפוטנטיות במסד, ואגרגציות שלא נספרות פעמיים גם אחרי קריסה.
  • OLTP ו־OLAP באותה מערכת: סטטיסטיקה יומית מ־MySQL, ומשפכים מ־Parquet עם DuckDB.
  • פריסה כמו בחברה: image אחד, ארבעה רכיבים ב־Kubernetes, CI — ועוזר AI (רשות) מעל הנתונים.

🤔 מה בונים

פלטפורמה שקולטת אירועי מוצר — "צפה בדף", "הוסיף לעגלה", "קנה" — מכמה לקוחות (tenants), בנפח גבוה, ונותנת להם סטטיסטיקה ומשפכי המרה. זו בדיוק הארכיטקטורה של מוצרי אנליטיקה (וגם של "events pipeline" בתוך כל חברה גדולה), והיא מחברת את כל מה שנוסף לקורס בעקבות המודעה: MySQL, Kafka, נתונים עמודתיים, Kubernetes ו־AI. פרויקט 3 הוכיח שאתה בונה API נכון; פרויקט 4 מוכיח שאתה בונה מערכת — כמה רכיבים, נתונים שזורמים ביניהם, והחלטות על כל קצה.

client ── POST /v1/events ──▶ ingest ──▶ Kafka ──▶ processor ──▶ MySQL
                                                                  │
        query API ◀── DuckDB ◀── lake (Parquet) ◀── export (cron) ┘
            │
   /v1/stats/daily · /v1/funnel · (assistant)
