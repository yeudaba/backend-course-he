P25.7-E26 · חיפוש מוצרים מ־query string 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 25 דק׳ידע נדרש: שיעור 2

GET /products?q=v60&minPrice=50&tags=pour-over. כל מה שמגיע ב־query string הוא מחרוזת, ואת כולו צריך להפוך לפילטר של Mongo, בלי לתת למשתמש לכתוב אופרטורים בעצמו. כתוב מקובץ ריק וייצא:

  • buildProductFilter(query: Record<string, string | undefined>):
    • q ← name: { $regex, $options: "i" }. ‏q אחרי trim, וכל תו מיוחד של regex (. * + ? ^ $ { } ( ) | [ ] \) מקבל \ לפניו.
    • category ← category כמו שהוא.
    • minPrice / maxPrice ← price: { $gte, $lte } כמספרים (רק מה שנשלח). לא מספר סופי, ריק או שלילי ← RangeError. גם minPrice > maxPrice ← RangeError.
    • tags ← tags: { $all: [...] }: מפרידים בפסיק, עושים trim, ומשמיטים ריקים. לא נשאר כלום ← בלי תנאי.
    • inStock: ‏"true" ← stock: { $gt: 0 }, ‏"false" ← stock: 0, ערך אחר ← RangeError. בחר עם switch.
    • ערך ריק ("") — בלי תנאי. מפתחות אחרים (sort, ‏$where) — מתעלמים.
  • searchProducts(db, query) — שמות המוצרים שמתאימים (string[]), ממוינים לפי name.

% npm run check P25.7-E26

P25.7-E27 · בדיקות ל־parseSort 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 2

🔁 חזרה על כתיבת בדיקות (פרק 22): גבולות, טבלת מקרים, ובדיקה ש"מה" ולא "איך". ב־25w-mongodb/starter/P25.7-E27.ts יש parseSort(value, allowed), שהופכת ?sort=-price,name לאובייקט המיון של Mongo:

  • מינוס לפני שדה ← -1 (יורד), בלי ← 1. רווחים סביב כל שדה לא משנים.
  • רק שדות מתוך allowed. שדה אחר, ריק, או שדה שמופיע פעמיים ← RangeError.
  • בסוף תמיד _id: 1, אם הוא לא נבחר כבר, כדי שהסדר יהיה יציב בין עמודים. אם נבחר (-_id), לא נוגעים בו.
  • אין value, או value ריק או רק רווחים ← { _id: 1 }.

כתוב בדיקות ב־P25.7-E27.spec.ts, מקובץ ריק. הבודק מריץ אותן על הקוד התקין, על שני מימושים תקינים אחרים, ועל 10 גרסאות עם באג. את P25.7-E27.ts עצמו לא משנים.
