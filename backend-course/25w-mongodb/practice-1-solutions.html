P25.7-E01 · Mongo או Postgres? 🧠 הבנה רמה 1

💡 רמז 1

שאל: האם הנתונים נקראים כ"אובייקט שלם"? כמה קשרים יש, והאם השאילתות עליהם ידועות מראש? כמה חשובה עקביות בין כמה רשומות?

💡 רמז 2

וזכור ש־Postgres עם jsonb יודע לשמור מבנה גמיש בתוך עמודה אחת.

✅ פתרון
  1. PostgreSQL. כסף: טרנזקציות על כמה טבלאות, מפתחות זרים, ודוחות עם JOIN ו־GROUP BY שלא ידועים מראש.
  2. Mongo מתאים מאוד — כל מוצר הוא מסמך עם מאפיינים משלו. (Postgres עם עמודת jsonb ל־specs — גם עובד.)
  3. שניהם. מסמך אחד שנכתב ונקרא בשלמותו — Mongo טבעי; ב־Postgres — שורה עם jsonb.
  4. לא זה ולא זה במיוחד — "חברים של חברים" הוא שאילתת גרף. Postgres עם recursive CTE מסתדר בהתחלה; בקנה מידה — מסד גרפים. Mongo עם מערך followers שגדל לנצח — המלכודת משיעור 3.
  5. שניהם יעבדו — משימות של משתמש הן מסמכים פשוטים. בחרנו Postgres כדי ללמוד SQL ו־Prisma, וזה בסדר גמור.
⚠️ טעויות נפוצות
  • "Mongo כי הוא מהיר יותר" / "Mongo כי אין schema" — בלי שיקול של דפוסי גישה ועקביות. זה מה שמראיין מחכה לשמוע שלא תגיד.

P25.7-E29 · הזמנה: מסמך אחד או שלוש טבלאות? 🧠 הבנה רמה 1

💡 רמז 1

‏orders + order_items, ו־JOIN.

💡 רמז 2

"בלי schema" — אין ALTER TABLE.

✅ פתרון
  1. Postgres: שורה ב־orders ושתיים ב־order_items. Mongo: מסמך אחד.
  2. Postgres: שאילתה אחת עם JOIN (או שתיים). Mongo: findOne אחד — והכול בפנים.
  3. Postgres: migration (ADD COLUMN gift_wrap boolean NOT NULL DEFAULT false ל־order_items). Mongo: פשוט מתחילים לכתוב את השדה בהזמנות חדשות.
  4. אין להן אותו. הקוד חייב לטפל ב"שדה חסר" (item.giftWrap ?? false) — לנצח, או עד שמריצים עדכון שממלא אותו. ה־migration לא נעלם — הוא עבר לקוד.
⚠️ טעויות נפוצות
  • "ב־Mongo אין migrations" — יש; הם פשוט לא חובה, ולכן נשכחים.

P25.7-E30 · ‏=== על ObjectId, ועוד שלוש השוואות 🧠 הבנה רמה 2

💡 רמז 1

‏includes ו־Set משתמשים בהשוואה של === (בערך).

💡 רמז 2

‏ObjectId יודע להפוך את עצמו ל־JSON.

✅ פתרון
import { ObjectId } from "mongodb";
const a = new ObjectId("6af1a8c0e4b0f1a2b3c4d5e6");
const b = new ObjectId("6af1a8c0e4b0f1a2b3c4d5e6");
console.log(a === b, a.equals(b), String(a) === String(b));
console.log([a].includes(b), new Set([a, b]).size);
console.log(JSON.stringify({ id: a }));

false 2
{"id":"6af1a8c0e4b0f1a2b3c4d5e6"}

‏===, ‏includes ו־Set — כולם משווים הפניות לאובייקט, ולכן "שונים". ‏note.ownerId === user._id תמיד false — אף אחד לא בעלים של שום דבר (או, אם כתבו !== לבדיקת הרשאה — כולם נחסמים). משווים עם .equals(), או ממירים למחרוזת פעם אחת, בגבול של ה־API.

⚠️ טעויות נפוצות
  • "תיקון" עם == — גם הוא משווה הפניות כששני הצדדים אובייקטים.

P25.7-E31 · ‏Date או מחרוזת? 🧠 הבנה רמה 1

💡 רמז 1

ב־BSON, Date ומחרוזת הם טיפוסים שונים — ו־$gte משווה רק בתוך אותו טיפוס.

💡 רמז 2

מיון בין טיפוסים: יש סדר קבוע בין סוגי BSON.

✅ פתרון
  1. לא תחזור — Date לא משתווה למחרוזת. ההזמנה "נעלמת" מכל דוח לפי תאריך.
  2. מסמכים עם מחרוזת ממוינים לפני כל ה־Dates (ב־BSON, String קטן מ־Date) — לא לפי הזמן.
  3. מחרוזת היא לא רגע: "2026-11-01" של איזה אזור זמן? אי אפשר לקבץ לפי יום בישראל (שיעור 4), ולא לחשב "לפני 24 שעות". שומרים Date — רגע ב־UTC (פרק 24).
⚠️ טעויות נפוצות
  • לשמור את מה שהגיע ב־JSON כמו שהוא — JSON לא מכיר Date, אז כל תאריך מה־API מגיע כמחרוזת וצריך המרה לפני insert (E43).

P25.7-E32 · ‏insertOne שינה לי את האובייקט 🧠 הבנה רמה 2

💡 רמז 1

ה־driver מוסיף _id לאובייקט שקיבל, אם אין לו.

💡 רמז 2

11000 — duplicate key.

✅ פתרון
import { MongoClient } from "mongodb";
const client = new MongoClient(process.env.MONGO_URL ?? "mongodb://localhost:27017/?directConnection=true");
const col = client.db("e32").collection("notes");
const template = { text: "hello" };
await col.insertOne(template);
console.log("_id" in template);
try { await col.insertOne(template); } catch (e) { console.log((e as { code?: number }).code); }
await col.insertOne({ ...template, _id: undefined });
console.log(await col.countDocuments());
await client.db("e32").dropDatabase();
await client.close();
true
11000
2

‏insertOne כותב _id לתוך האובייקט שהעברת. ההכנסה השנייה של אותו אובייקט — אותו _id ← ‏11000. בלולאה: הראשון נכנס, וכל השאר נכשלים. מכניסים עותק ({ ...template }, או structuredClone), כמו ב־seed.mjs של היחידה.

⚠️ טעויות נפוצות
  • "לתקן" עם delete template._id אחרי כל insert — עובד, עד שמישהו שוכח שורה אחת.

P25.7-E33 · ‏projection — מה חוזר? 🧠 הבנה רמה 2

💡 רמז 1

‏_id חוזר תמיד, אלא אם כתבת _id: 0.

💡 רמז 2

אסור לערבב "כלול" ו"השמט" — חוץ מ־_id.

✅ פתרון
  1. { _id: "p1", name: "Ethiopia Yirgacheffe" }.
  2. { name: "Ethiopia Yirgacheffe" }.
  3. הכול חוץ מ־reviews ו־specs (כולל _id, ‏tags, ‏ratingCount…).
  4. { specs: { roast: "light" } } — השדה המקונן חוזר בתוך אובייקט, לא כ"roast" שטוח.
  5. שגיאה מהשרת: ‏Cannot do exclusion on field price in inclusion projection.
⚠️ טעויות נפוצות
  • לשלוח מסמך שלם ל־API "ולסנן ב־frontend" — כל השדות (גם passwordHash) עוברים ברשת.

P25.7-E06 · חיפוש מוצרים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

בונים אובייקט filter ומוסיפים לו שדות רק כשהפרמטר הגיע.

💡 רמז 2

{ tags: tag } על שדה שהוא מערך = "המערך מכיל". projection: { name: 1, price: 1 } (_id נכלל אוטומטית).

✅ פתרון
// P25.7-E06
import type { Db } from "mongodb";

// בונים את ה־filter רק מהשדות שהגיעו: undefined לא נכנס, אחרת הוא היה מחפש "שדה שערכו null"
export async function findProducts(db: Db, { category, maxPrice, inStock, tag }: { category?: string; maxPrice?: number; inStock?: boolean; tag?: string } = {}) {
  const filter: Record<string, unknown> = {};
  if (category !== undefined) filter.category = category;
  if (maxPrice !== undefined) filter.price = { $lte: maxPrice };
  if (inStock) filter.stock = { $gt: 0 };
  if (tag !== undefined) filter.tags = tag; // על מערך: "המערך מכיל את הערך"
  return db
    .collection("products")
    .find(filter, { projection: { _id: 1, name: 1, price: 1 } })
    .sort({ price: 1, _id: 1 }) // שובר שוויון — סדר יציב
    .toArray();
}
⚠️ טעויות נפוצות
  • filter.category = category גם כשהוא undefined — ה־driver שולח null, ו־Mongo מחפש מסמכים שבהם השדה null או חסר.
  • מיון בלי שובר שוויון — סדר של מוצרים באותו מחיר לא מובטח.

P25.7-E07 · לקוח חדש, אימייל ייחודי 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

createIndex({ email: 1 }, { unique: true }). ההפרה מגיעה כ־MongoServerError עם code === 11000.

💡 רמז 2

try/catch סביב insertOne: אם 11000 — throw new DuplicateEmailError(...), אחרת throw err.

✅ פתרון
// P25.7-E07
import { MongoServerError, type Db } from "mongodb";

export class DuplicateEmailError extends Error {}

export async function setupCustomers(db: Db) {
  // ה־UNIQUE של Mongo: אינדקס ייחודי. בלעדיו — שני לקוחות עם אותו אימייל יישמרו בשקט
  await db.collection("customers").createIndex({ email: 1 }, { unique: true });
}

export async function createCustomer(db: Db, { name, email, city }: { name: string; email: string; city: string }) {
  try {
    const { insertedId } = await db.collection("customers").insertOne({ name, email: email.trim().toLowerCase(), city, createdAt: new Date() });
    return insertedId; // לא נתנו _id ← Mongo יוצר ObjectId
  } catch (err) {
    if (err instanceof MongoServerError && err.code === 11000) throw new DuplicateEmailError(`האימייל ${email} כבר רשום`);
    throw err;
  }
}
⚠️ טעויות נפוצות
  • לבדוק "האם קיים" עם findOne ואז להכניס — שני רישומים במקביל עוברים את הבדיקה (המרוץ מפרק 18). רק האינדקס הייחודי מבטיח.
  • לבלוע כל שגיאה ולזרוק DuplicateEmailError — גם "המסד נפל" ייראה כמו "האימייל תפוס".

P25.7-E11 · ההזמנות של לקוח 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

projection של "הכול חוץ מ־": { items: 0, customerId: 0 }.

💡 רמז 2

{ status: { $in: status } } — ורק אם המערך הגיע ולא ריק.

✅ פתרון
// P25.7-E11
import type { Db } from "mongodb";

export async function customerOrders(db: Db, customerId: string, { status }: { status?: string[] } = {}) {
  const filter: Record<string, unknown> = { customerId };
  if (status?.length) filter.status = { $in: status };
  return db
    .collection("orders")
    // בלי items — ברשימה מציגים סיכום; הפרטים בדף ההזמנה
    .find(filter, { projection: { items: 0, customerId: 0 } })
    .sort({ createdAt: -1 })
    .toArray();
}
⚠️ טעויות נפוצות
  • לערבב 1 ו־0 באותו projection ({ total: 1, items: 0 }) — Mongo זורק שגיאה (חוץ מ־_id: 0).

import type { Db } from "mongodb";

export async function productCard(db: Db, id: string) {

P25.7-E36 · מוצר חדש — עם Zod לפני insert 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

z.strictObject({ … }) ו־safeParse (פרק 15).

💡 רמז 2

✅ פתרון
// P25.7-E36: מוצר חדש — עם Zod לפני insert
import type { Db } from "mongodb";
import { z } from "zod";

const schema = z.strictObject({
  name: z.string().trim().min(1),
  category: z.enum(["beans", "gear", "merch"]),
  price: z.number().int().positive(),
  stock: z.number().int().min(0).default(0),
  tags: z.array(z.string()).default([]),
});

export async function addProduct(db: Db, input: unknown) {
  const r = schema.safeParse(input);
  if (!r.success) throw new Error("VALIDATION_ERROR");
  const { insertedId } = await db.collection("products").insertOne({ ...r.data, createdAt: new Date() });
  return { id: insertedId.toHexString() };
}
⚠️ טעויות נפוצות
  • insertOne(input) אחרי הבדיקה — נכנס האובייקט המקורי, בלי trim ובלי ברירות מחדל.

P25.7-E37 · ההזמנות האחרונות של לקוח 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

doc.createdAt.toISOString().

✅ פתרון
// P25.7-E37: ההזמנות האחרונות של לקוח
import type { Db } from "mongodb";

type Order = { _id: string; customerId: string; status: string; total: number; createdAt: Date };

export async function lastOrders(db: Db, customerId: string, limit: number) {
  const docs = await db.collection<Order>("orders")
    .find({ customerId }, { projection: { status: 1, total: 1, createdAt: 1 } })
    .sort({ createdAt: -1 })
    .limit(limit)
    .toArray();
  return docs.map((o) => ({ id: o._id, status: o.status, total: o.total, createdAt: o.createdAt.toISOString() }));
}
⚠️ טעויות נפוצות
  • להחזיר את Date כמו שהוא — ‏res.json יהפוך אותו למחרוזת, אבל קוד אחר שקורא לפונקציה מקבל טיפוס אחר ממה שהבטחת.

P25.7-E38 · ממסמך ל־JSON של API 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏value instanceof ObjectId — עם import { ObjectId } from "mongodb".

💡 רמז 2

רקורסיה:

Object.fromEntries(Object.entries(v).map(([k, x]) => [k === "_id" ? "id" : k, toApi(x)]))
✅ פתרון
// P25.7-E38: ממסמך ל־JSON של API
import { ObjectId } from "mongodb";

export function toApi(value: unknown): unknown {
  if (value instanceof ObjectId) return value.toHexString();
  if (value instanceof Date) return value.toISOString();
  if (Array.isArray(value)) return value.map(toApi);
  if (value !== null && typeof value === "object") {
    return Object.fromEntries(Object.entries(value).map(([k, x]) => [k === "_id" ? "id" : k, toApi(x)]));
  }
  return value;
}
⚠️ טעויות נפוצות
  • JSON.parse(JSON.stringify(doc)) — ‏Date ו־ObjectId אכן הופכים למחרוזות, אבל _id נשאר _id, ובדרך עוברים סריאליזציה מלאה של כל המסמך בלי צורך.

P25.7-E39 · ‏jsonb ב־Postgres מול מסמך 🧠 הבנה רמה 2

💡 רמז 1

ב־jsonb רק עמודה אחת גמישה.

💡 רמז 2

מה עוד יש במערכת — הזמנות, תשלומים, קשרים?

✅ פתרון
  1. ב־Postgres רק העמודה הזו גמישה; כל השאר מוגדר, עם טיפוסים ואילוצים. ב־Mongo כל המסמך גמיש — גם price יכול להיות מחרוזת במסמך אחד.
  2. Postgres: ‏price numeric NOT NULL CHECK (price > 0) — המסד אוכף. Mongo: רק אם הוספת $jsonSchema (שיעור 3) או בדיקה בקוד (E36).
  3. כשכל השאר במערכת רלציוני — הזמנות, תשלומים, משתמשים, עם מפתחות זרים וטרנזקציות. jsonb נותן את הגמישות לחלק הקטן שצריך אותה, בלי מסד שני.
⚠️ טעויות נפוצות
  • לבחור Mongo רק בגלל "מאפיינים שונים למוצרים" — jsonb פותר את זה.

P25.7-E40 · ‏Zod — עכשיו הוא ה־schema 🧠 הבנה רמה 2

💡 רמז 1

‏{ "price": "35" }, ‏{ "role": "admin" }.

💡 רמז 2

‏parse מחזיר אובייקט חדש.

✅ פתרון
  1. נשמר מה שהגיע. ‏price: "35" (מחרוזת) — ‏$gte: 30 לא ימצא אותו, ו־$inc עליו ייכשל. ‏role: "admin" בהרשמה — נשמר, ואולי מעניק הרשאות (mass assignment, ‏OWASP — פרק 21).
  2. שדה לא מוכר שנבלע ב־z.object (שמוריד שדות) — בסדר, כל עוד מכניסים את התוצאה. אבל עם passthrough או כשמכניסים את הקלט המקורי — כל שדה נכנס למסד. ‏strict הופך את זה לשגיאה ברורה.
  3. נכנס הקלט המקורי — בלי trim, בלי ברירות מחדל, ועם כל שדה ש־Zod הוריד. מכניסים את מה ש־parse החזיר (E36).
⚠️ טעויות נפוצות

P25.7-E28 · מה מסתתר ב־ObjectId 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

parseInt(id.slice(0, 8), 16) ← שניות. בכיוון השני: seconds.toString(16).padStart(8, "0") + "0".repeat(16). בלי padStart, תאריכים ישנים (לפני 1978) נותנים פחות מ־8 תווים.

💡 רמז 2

day.match(/^(\d{4})-(\d{2})-(\d{2})$/), ואז new Date(Date.UTC(y, m - 1, d)) (החודש מ־0). חצות של מחר: start.getTime() + 24 * 60 * 60 * 1000. ב־UTC אין שעון קיץ, ולכן כל יום הוא בדיוק 24 שעות.

✅ פתרון
// P25.7-E28 — מה מסתתר ב־ObjectId
const OBJECT_ID = /^[0-9a-f]{24}$/i;

export function objectIdDate(id: string): Date {
  if (!OBJECT_ID.test(id)) throw new TypeError(`ObjectId לא תקין: ${id}`);
  const seconds = parseInt(id.slice(0, 8), 16);
  return new Date(seconds * 1000);
}

export function objectIdFromDate(date: Date): string {
  const seconds = Math.floor(date.getTime() / 1000);
  return seconds.toString(16).padStart(8, "0") + "0".repeat(16);
}

export function idRangeForDay(day: string): { $gte: string; $lt: string } {
  const match = day.match(/^(\d{4})-(\d{2})-(\d{2})$/);
  if (!match) throw new TypeError(`תאריך לא תקין: ${day}`);
  const start = new Date(Date.UTC(Number(match[1]), Number(match[2]) - 1, Number(match[3])));
  const end = new Date(start.getTime() + 24 * 60 * 60 * 1000);
  return { $gte: objectIdFromDate(start), $lt: objectIdFromDate(end) };
}

הבודק משווה את התוצאות שלך ל־ObjectId.getTimestamp() ול־ObjectId.createFromTime() של הדרייבר, ומריץ את הטווח על Mongo אמיתי. כדי להשתמש בו בשאילתה, הופכים את המחרוזות ל־ObjectId: { _id: { $gte: new ObjectId(r.$gte), $lt: new ObjectId(r.$lt) } }. השוואה בין ObjectId לפי בתים היא קודם כל השוואה לפי הזמן.

למה זה שימושי? ‏_id תמיד מאונדקס. טווח עליו הוא "כל ההזמנות מאתמול", בלי אינדקס נוסף על createdAt. שני דברים להיזהר מהם: הדיוק הוא שנייה, והזמן נקבע אצל מי שיצר את ה־ObjectId (בדרך כלל הדרייבר, כלומר השעון של השרת שלך). לדוחות מדויקים עדיף שדה createdAt אמיתי.

⚠️ טעויות נפוצות
  • parseInt(id.slice(0, 8)) בלי 16 — ‏6af2d608 נקרא כ־6.
  • לשכוח את * 1000 — ‏new Date מקבל מילישניות, והתאריך יוצא בינואר 1970.
  • new Date("2026-11-10") — עובד (מחרוזת תאריך בלבד נקראת כ־UTC), אבל new Date(2026, 10, 10) הוא חצות לפי השעון המקומי, ובישראל זה 22:00 של היום הקודם ב־UTC.
  • $lte במקום $lt לסוף הטווח — מסמכים מהשנייה הראשונה של מחר נכנסים.

// P25.7-E42: GET /products/:id ב־Express
import { Router } from "express";
import type { Db } from "mongodb";

type Product = { _id: string; name: string; category: string; price: number; stock: number };
const projection = { name: 1, category: 1, price: 1, stock: 1 };
const toDto = (p: Product) => ({ id: p._id, name: p.name, category: p.category, price: p.price, inStock: p.stock > 0 });

export function productsRouter(db: Db) {
  const products = db.collection<Product>("products");
  const router = Router();
  router.get("/products/:id", async (req, res) => {
    const p = await products.findOne({ _id: req.params.id }, { projection });
    if (!p) {
      res.status(404).json({ error: { code: "NOT_FOUND" } });
      return;
    }
    res.json(toDto(p));
  });
  router.get("/products", async (req, res) => {
    const filter = typeof req.query.category === "string" ? { category: req.query.category } : {};
    res.json((await products.find(filter, { projection }).sort({ name: 1 }).toArray()).map(toDto));
  });
  return router;
}
⚠️ טעויות נפוצות
  • find({ category: req.query.category }) בלי לבדוק טיפוס — ‏?category[$ne]=x מחזיר הכול (שיעור 5).

✅ פתרון
// P25.7-E43: seed מקובץ JSON
import type { Db } from "mongodb";

export async function loadSeed(db: Db, jsonText: string) {
  let data: Record<string, Record<string, unknown>[]>;
  try {
    data = JSON.parse(jsonText, (key, value) => {
      if (!key.endsWith("At") || typeof value !== "string") return value;
      const d = new Date(value);
      if (Number.isNaN(d.getTime())) throw new Error(`תאריך לא תקין בשדה ${key}`);
      return d;
    });
  } catch (err) {
    if (err instanceof SyntaxError) throw new Error("JSON לא תקין");
    throw err;
  }
  const counts: Record<string, number> = {};
  for (const [name, docs] of Object.entries(data)) {
    if (docs.length) await db.collection(name).insertMany(docs);
    counts[name] = docs.length;
  }
  return counts;
}

ה־reviver רץ על כל שדה בדרך — גם בתוך מערכים של פריטים — ולכן תופס גם items[0].shippedAt.
