HAVING הוא $match אחרי $group.

✅ פתרון
  1. db.products.find({ category: "gear", stock: { $gt: 0 } }, { projection: { _id: 0, name: 1, price: 1 } }).sort({ price: -1 }).limit(2)

P25.7-E45 · מערך — "מכיל" או "שווה"? 🧠 הבנה רמה 2

💡 רמז 1

ערך יחיד מול שדה מערך = "מכיל". מערך מול מערך = שוויון מדויק.

💡 רמז 2

שוויון מדויק כולל סדר.

✅ פתרון

  2. לא — המערך כולו לא שווה ל־["kettle"].
  3. לא — סדר אחר.
  4. כן — זהה בדיוק.
  5. כן — מכיל את שניהם, בכל סדר.
  6. כן — בדיוק שני איברים.

P25.7-E08 · הוספה למלאי 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

findOneAndUpdate עם $inc — שינוי ושליפה בפקודה אחת.

💡 רמז 2

{ returnDocument: "after" } — אחרת חוזר המסמך לפני העדכון.

✅ פתרון

import type { Db } from "mongodb";

interface Product {
  _id: string;
  name: string;
  price: number;
  stock: number;
  tags: string[];
}

export async function restock(db: Db, productId: string, qty: number) {
  if (!Number.isInteger(qty) || qty <= 0) throw new RangeError("qty חייב להיות מספר שלם חיובי");
  // $inc אטומי בשרת — לא "קרא, חבר, כתוב" (שני מחסנאים במקביל היו דורסים זה את זה)
  const doc = await db.collection<Product>("products").findOneAndUpdate(
    { _id: productId },
    { $inc: { stock: qty } },

P25.7-E09 · תגיות: $addToSet ו־$pull 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

$addToSet מוסיף רק אם הערך לא במערך. $pull מסיר כל מופע.

💡 רמז 2

"המוצר קיים" — matchedCount === 1, לא modifiedCount (תגית שכבר קיימת: התאים, לא השתנה).

✅ פתרון
// P25.7-E09
import type { Db } from "mongodb";

// collection עם טיפוס: TypeScript יודע ש־tags הוא מערך של מחרוזות, ובודק את $addToSet ו־$pull
interface Product {
  _id: string;
  name: string;
  price: number;
  stock: number;
  tags: string[];
}

const norm = (t: string) => t.trim().toLowerCase();

// $addToSet — מוסיף רק אם לא קיים. $push היה מוסיף כפילות
export async function addTag(db: Db, productId: string, tag: string) {
  const r = await db.collection<Product>("products").updateOne({ _id: productId }, { $addToSet: { tags: norm(tag) } });
  return r.matchedCount === 1;
}

export async function removeTag(db: Db, productId: string, tag: string) {
  const r = await db.collection<Product>("products").updateOne({ _id: productId }, { $pull: { tags: norm(tag) } });
  return r.matchedCount === 1;
}
⚠️ טעויות נפוצות
  • $push במקום $addToSet — "organic" פעמיים.
  • modifiedCount כאינדיקציה לקיום — addTag של תגית קיימת יחזיר false.

P25.7-E10 · עמוד של מוצרים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

skip((page - 1) * pageSize).limit(pageSize), ו־countDocuments(filter).

💡 רמז 2

שתי השאילתות לא תלויות זו בזו — Promise.all.

✅ פתרון
// P25.7-E10
import type { Db } from "mongodb";

export async function productsPage(db: Db, { page = 1, pageSize = 3, category }: { page?: number; pageSize?: number; category?: string } = {}) {
  if (!Number.isInteger(page) || page < 1 || !Number.isInteger(pageSize) || pageSize < 1 || pageSize > 50) throw new RangeError("page/pageSize לא תקינים");
  const filter = category === undefined ? {} : { category };
  const col = db.collection("products");
  // שתי שאילתות במקביל: העמוד עצמו, והספירה (באותו filter!)
  const [items, total] = await Promise.all([
    col.find(filter, { projection: { name: 1, price: 1 } }).sort({ name: 1, _id: 1 }).skip((page - 1) * pageSize).limit(pageSize).toArray(),
    col.countDocuments(filter),
  ]);
  return { items, total, totalPages: Math.ceil(total / pageSize) };
}
⚠️ טעויות נפוצות
  • countDocuments() בלי הפילטר — total של כל הקטלוג בעמוד של קטגוריה.
  • estimatedDocumentCount — מהיר, אבל מתעלם מפילטר.

P25.7-E21 · עדכון פרופיל עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

מה קורה ל־email אחרי replaceOne(..., { name: "x" })? ומה קורה עם { role: "admin" }?

💡 רמז 2

והשורה השנייה: האם העדכון כבר קרה כשה־findOne רץ? (שים לב גם ל־as unknown as Customer — מישהו השתיק את TypeScript, והוא צדק.)

✅ פתרון
// P25.7-E21
import type { Db } from "mongodb";

interface Customer {
  _id: string;
  name: string;
  email: string;
  city: string;
  createdAt: Date;
}

const EDITABLE = ["name", "city"] as const;

// PATCH /me: הלקוח מעדכן את הפרופיל שלו
export async function updateProfile(db: Db, customerId: string, body: Record<string, unknown>) {
  // תקלה 2: רק שדות מותרים. אחרת { role: "admin" } או { email } נכנסים כמו שהם (mass assignment)
  const $set: Record<string, string> = {};
  for (const k of EDITABLE) if (typeof body[k] === "string") $set[k] = (body[k] as string).trim();
  if (Object.keys($set).length === 0) throw new RangeError("אין מה לעדכן");
  // תקלה 1: $set ולא replaceOne — replaceOne מחליף את כל המסמך, והאימייל ותאריך ההרשמה נמחקים
  // תקלה 3: await — אחרת מחזירים לפני שהעדכון קרה, ושגיאה הולכת לאיבוד
  const doc = await db.collection<Customer>("customers").findOneAndUpdate({ _id: customerId }, { $set }, { returnDocument: "after" });
  return doc;
}
⚠️ טעויות נפוצות
  • לתקן ל־$set: body — ה־email לא נמחק, אבל עכשיו כל אחד יכול לשנות אותו (ולהוסיף role).

P25.7-E26 · חיפוש מוצרים מ־query string 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

בונים אובייקט ריק, ומוסיפים לו מפתח לכל פרמטר שהגיע: if (query.q) filter.name = {...}. ה־escape: ‏s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&"). ‏$& בתוך מחרוזת ההחלפה הוא "מה שנמצא".

💡 רמז 2

למחיר: אובייקט range נפרד, ורק בסוף if (Object.keys(range).length > 0) filter.price = range. בדיקת מספר: ‏Number("") הוא 0, ולכן בודקים גם value.trim() === "", וגם Number.isFinite(n). ב־searchProducts: ‏find(filter).sort({ name: 1 }).project({ _id: 0, name: 1 }).toArray(), ואז map.

✅ פתרון
// P25.7-E26 — חיפוש מוצרים מ־query string
import type { Db } from "mongodb";

type Query = Record<string, string | undefined>;

const escapeRegex = (s: string) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

function price(value: string, name: string): number {
  const n = Number(value);
  if (value.trim() === "" || !Number.isFinite(n) || n < 0) throw new RangeError(`${name} לא תקין: ${value}`);
  return n;
}

export function buildProductFilter(query: Query): Record<string, unknown> {
  const filter: Record<string, unknown> = {};
  if (query.q) filter.name = { $regex: escapeRegex(query.q.trim()), $options: "i" };
  if (query.category) filter.category = query.category;

  const range: Record<string, number> = {};
  if (query.minPrice !== undefined) range.$gte = price(query.minPrice, "minPrice");
  if (query.maxPrice !== undefined) range.$lte = price(query.maxPrice, "maxPrice");
  if (range.$gte !== undefined && range.$lte !== undefined && range.$gte > range.$lte) throw new RangeError("minPrice גדול מ־maxPrice");
  if (Object.keys(range).length > 0) filter.price = range;

  if (query.tags) {
    const tags = query.tags.split(",").map((t) => t.trim()).filter((t) => t !== "");
    if (tags.length > 0) filter.tags = { $all: tags };
  }

  switch (query.inStock) {
    case undefined:
      break;
    case "true":
      filter.stock = { $gt: 0 };
      break;
    case "false":
      filter.stock = 0;
      break;
    default:
      throw new RangeError(`inStock חייב להיות true או false: ${query.inStock}`);
  }
  return filter;
}

export async function searchProducts(db: Db, query: Query): Promise<string[]> {
  const docs = await db.collection("products").find(buildProductFilter(query)).sort({ name: 1 }).project({ _id: 0, name: 1 }).toArray();
  return docs.map((d) => d.name);
}

הפילטר נבנה רק ממפתחות שאנחנו מכירים, וכל ערך נכנס למקום שקבענו מראש. כך ?category={"$ne":null} מחפש קטגוריה שזה השם שלה, ולא "כל מה שאינו null". זו אותה הגנה כמו ב־P25.7-E20: בלי להעביר את req.query ישר ל־find.

ה־escape חשוב פעמיים. ‏q=. בלי escape מתאים לכל מוצר: נקודה ב־regex היא "כל תו". ‏q=( בלי escape מפיל את השאילתה עם שגיאת regex של Mongo, כלומר 500 על קלט של משתמש. ‏regex עם $options: "i" בלי ^ בהתחלה לא משתמש באינדקס. בחנות של 8 מוצרים זה לא משנה, ובקטלוג גדול עוברים ל־Atlas Search או לאינדקס טקסט (שיעור 4).

⚠️ טעויות נפוצות
  • { price: { $gte: query.minPrice } } — מחרוזת. ב־Mongo "50" ו־50 הם טיפוסים שונים, ואף מוצר לא יתאים.
  • $regex: query.q בלי escape — ‏q=( מחזיר 500.
  • filter.price = { $gte: min, $lte: max } גם כשנשלח רק אחד — ‏$lte: undefined. הדרייבר משמיט שדות undefined, אבל כדאי לא לסמוך על זה.
  • tags: { $in: [...] } — מוצר עם אחת מהתגיות. המשימה: כולן ($all).

// P25.7-E48: תגית sold-out לפי המלאי
import type { Db } from "mongodb";

export async function syncSoldOutTags(db: Db) {
  const products = db.collection("products");
  const a = await products.updateMany({ stock: 0 }, { $addToSet: { tags: "sold-out" } });
  const b = await products.updateMany({ stock: { $gt: 0 } }, { $pull: { tags: "sold-out" } });
  return { tagged: a.modifiedCount, untagged: b.modifiedCount };
}
⚠️ טעויות נפוצות

P25.7-E49 · מחיר חדש — רק אם לא השתנה בינתיים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

ו־matchedCount.

💡 רמז 2

‏expectedPrice === newPrice — ‏matched 1, ‏modified 0. זה "updated" (ממילא זה המחיר).

✅ פתרון
// P25.7-E49: מחיר חדש — רק אם לא השתנה בינתיים
import type { Db } from "mongodb";

export async function updatePrice(db: Db, id: string, expectedPrice: number, newPrice: number) {
  if (!Number.isInteger(newPrice) || newPrice <= 0) throw new RangeError(`מחיר לא תקין: ${newPrice}`);
  const products = db.collection<{ _id: string; price: number }>("products");
  const r = await products.updateOne({ _id: id, price: expectedPrice }, { $set: { price: newPrice } });
  if (r.matchedCount === 1) return "updated" as const;
  return (await products.countDocuments({ _id: id }, { limit: 1 })) ? ("conflict" as const) : ("not_found" as const);
}

זה "optimistic concurrency": לא נועלים כלום, ובודקים בכתיבה שמה שראית עדיין נכון. ב־API — ‏409 על conflict, והממשק מציג "המחיר השתנה ל־X, לעדכן בכל זאת?". (במקום המחיר עצמו אפשר להשתמש במספר גרסה, version, שעולה בכל עדכון.)

⚠️ טעויות נפוצות
  • ‏findOne, השוואה בקוד, ואז updateOne — בין שתי הפקודות מנהל שני מספיק לעדכן.

P25.7-E27 · בדיקות ל־parseSort 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שאלה חשובה: האם assert.deepEqual({ a: 1, b: 1 }, { b: 1, a: 1 }) עובר? כן, כי deepEqual לא בודק את סדר המפתחות. אבל במיון של Mongo הסדר הוא כל העניין: { price: -1, name: 1 } ו־{ name: 1, price: -1 } הם שני מיונים שונים. השווה את Object.entries(...), שהוא מערך, ומערך כן נבדק לפי הסדר.

💡 רמז 2

לכל שורה בתיאור — לפחות בדיקה אחת, ולכל "או" — בדיקה לכל צד: undefined, ‏"" וגם " ". ‏-_id לבד. שדה לא מותר עם מינוס ובלי. ‏"price," (פסיק בסוף) ו־"-" לבד.

✅ פתרון
// P25.7-E27 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { parseSort } from "./P25.7-E27.ts";

const ALLOWED = ["name", "price", "createdAt", "_id"];

// deepEqual לא בודק את סדר המפתחות — ובמיון של Mongo הסדר הוא כל העניין
function sameSort(actual: Record<string, number>, expected: Record<string, number>) {
  assert.deepEqual(Object.entries(actual), Object.entries(expected));
}

test("עולה, יורד, וכמה שדות לפי הסדר", () => {
  sameSort(parseSort("name", ALLOWED), { name: 1, _id: 1 });
  sameSort(parseSort("-price", ALLOWED), { price: -1, _id: 1 });
  sameSort(parseSort("-price,name", ALLOWED), { price: -1, name: 1, _id: 1 });
  sameSort(parseSort("name,-price", ALLOWED), { name: 1, price: -1, _id: 1 });
});

test("רווחים", () => {
  sameSort(parseSort(" -price , name ", ALLOWED), { price: -1, name: 1, _id: 1 });
});

test("_id: לא מוסיפים פעמיים, ולא משנים את הכיוון שנבחר", () => {
  sameSort(parseSort("-_id", ALLOWED), { _id: -1 });
  sameSort(parseSort("_id,name", ALLOWED), { _id: 1, name: 1 });
});

test("בלי value, או value ריק ← { _id: 1 }", () => {
  sameSort(parseSort(undefined, ALLOWED), { _id: 1 });
  sameSort(parseSort("", ALLOWED), { _id: 1 });
  sameSort(parseSort("   ", ALLOWED), { _id: 1 });
});

test("שדה לא מותר, ריק או כפול ← RangeError", () => {
  for (const bad of ["password", "-password", "name,secret", "price,", "-", "name,-name", "price,price"]) {
    assert.throws(() => parseSort(bad, ALLOWED), RangeError, bad);
  }
});

הפונקציה sameSort היא הבדיקה החשובה בתרגיל. בלעדיה, מימוש שמוסיף את _id ראשון ({ _id: 1, price: -1 }) עובר את כל הבדיקות. אבל ב־Mongo המיון הזה הוא "לפי _id", ו־price כבר לא משפיע, כי _id ייחודי.

הטבלה של הקלטים הלא תקינים תופסת כמה באגים יחד: בלי בדיקת allowed (מיון לפי password מאפשר לנחש סיסמאות: "מי לפני מי"), שדה כפול, ופסיק בסוף. ‏" " נפרד מ־"", כי שני מימושים "כמעט נכונים" מטפלים רק באחד מהם.

⚠️ טעויות נפוצות
  • assert.deepEqual על אובייקט המיון — לא תופס סדר מפתחות לא נכון.
  • לבדוק רק את "-price,name" — כל הבאגים במקרי הקצה: _id, ריק, כפול, לא מותר.
  • לבדוק את הודעת השגיאה המדויקת — מימוש תקין עם ניסוח אחר נכשל. מספיק RangeError.

💡 רמז 1

💡 רמז 2

ה־filter של E52.

✅ פתרון
// P25.7-E53: עמוד הבא של הזמנות — keyset
import type { Db, Filter } from "mongodb";

type Order = { _id: string; createdAt: Date; total: number };

export async function ordersPage(db: Db, { limit, after }: { limit: number; after?: string }) {
  let filter: Filter<Order> = {};
  if (after !== undefined) {
    const parts = after.split("|");
    const t = new Date(parts[0]);
    if (parts.length !== 2 || !parts[1] || Number.isNaN(t.getTime())) throw new Error("BAD_CURSOR");
    filter = { $or: [{ createdAt: { $lt: t } }, { createdAt: t, _id: { $lt: parts[1] } }] };
  }
  const docs = await db.collection<Order>("orders")
    .find(filter, { projection: { createdAt: 1, total: 1 } })
    .sort({ createdAt: -1, _id: -1 })
    .limit(limit)
    .toArray();
  const items = docs.map((o) => ({ id: o._id, createdAt: o.createdAt.toISOString(), total: o.total }));
  const last = items.at(-1);
  return { items, next: items.length === limit && last ? `${last.createdAt}|${last.id}` : null };
}
⚠️ טעויות נפוצות
  • cursor שהוא רק התאריך — שתי הזמנות באותה שנייה בגבול העמוד, ואחת נעלמת.

💡 רמז 2

✅ פתרון
// P25.7-E54: PATCH למוצר — רק שדות מותרים
import type { Db } from "mongodb";
import { z } from "zod";

const schema = z.strictObject({
  name: z.string().trim().min(1).optional(),
  price: z.number().int().positive().optional(),
  tags: z.array(z.string()).optional(),
});

export async function patchProduct(db: Db, id: string, body: unknown) {
  const r = schema.safeParse(body);
  if (!r.success || Object.keys(r.data).length === 0) throw new Error("VALIDATION_ERROR");
  const doc = await db.collection<{ _id: string; name: string; price: number; tags: string[] }>("products").findOneAndUpdate(
    { _id: id },
    { $set: r.data },
    { returnDocument: "after", projection: { name: 1, price: 1, tags: 1 } },
  );
  return doc ? { id: doc._id, name: doc.name, price: doc.price, tags: doc.tags } : null;
}
⚠️ טעויות נפוצות
  • $set: body — ‏{ "stock": 9999 } או { "reviews": [] } עוברים.
  • replaceOne עם מה שהגיע — כל שאר השדות נמחקים (‏P25.7-E21).
