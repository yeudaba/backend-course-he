P25.7-E02 · embed או reference? 🧠 הבנה רמה 1

💡 רמז 1

שלוש שאלות: נקרא תמיד ביחד עם ההורה? יש לכמות גבול טבעי? משתנה לבד, או משותף לרבים?

💡 רמז 2

לפעמים התשובה היא "reference — ועותק של שדה או שניים".

✅ פתרון
  1. embed — מעט, שייכות רק ללקוח, נקראות עם הפרופיל.
  2. reference — אין גבול. collection orders עם customerId ואינדקס { customerId: 1, createdAt: -1 }.
  3. reference + עותק — productId, ועותק של name ו־price בזמן הקנייה (שיעור 3, סעיף 3).
  4. reference — collection comments עם postId. מערך מוטמע יעבוד לרוב הפוסטים ויישבר בדיוק בפוסט שכולם קוראים. ואפשר להטמיע את 3 האחרונות לתצוגה מהירה ("subset pattern").
  5. reference + עותק של השם — הקטגוריה היא ישות עם דף משלה. במוצר: categoryId ו־categoryName לתצוגה. שינוי שם של קטגוריה (נדיר) — updateMany.
⚠️ טעויות נפוצות
  • להטמיע הכול "כי ככה Mongo" — ואז לקוח עם 3,000 הזמנות בתוך מסמך אחד.
  • להפריד הכול "כמו בטבלאות" — ואז כל דף צריך חמישה $lookup.

P25.7-E55 · חנות ספרים — לפי השאילתות 🧠 הבנה רמה 2

💡 רמז 1

שאלה לכל אחד: נקרא ביחד? שייך רק להורה? כמה יכולים להיות?

💡 רמז 2

שכפול חלקי: מה מתוך "מחבר" צריך דף הספר?

✅ פתרון
  1. collection authors; בספר — authors: [{ authorId, name }] (שם משוכפל לתצוגה; ביוגרפיה רק בדף המחבר). "כל הספרים של מחבר" — אינדקס על authors.authorId.
  2. collection reviews עם bookId — לא מוגבל, ועימוד. לא בתוך הספר (16MB, וכל קריאה של הספר הייתה מביאה 40,000).
  3. embed בהזמנה — עם עותק של שם ומחיר (שיעור 3, סעיף 3).
  4. embed בעגלה (מסמך עגלה לכל לקוח) — קטן, נקרא ונכתב יחד.
  5. embed בספר: ratingCount, ‏ratingSum — מתעדכנים יחד עם כל ביקורת (‏$inc), ודף הספר לא צריך את הביקורות כדי להציג ממוצע.
⚠️ טעויות נפוצות
  • לתכנן "כמו ב־SQL" — collection לכל ישות ו־$lookup בכל מסך — ולקבל את כל המחיר של Mongo בלי היתרונות.

P25.7-E56 · מערך שגדל לנצח 🧠 הבנה רמה 2

💡 רמז 1

‏findOne של הלקוח — מה הוא מביא?

💡 רמז 2

‏$push עם $slice.

✅ פתרון
  1. ‏~55,000 מזהים — עדיין פחות מ־16MB, אבל ממשיך לגדול בלי גבול. מסמך לקוח אחד שוקל מגה־בייטים.
  2. כל קריאה של הלקוח (התחברות, פרופיל) מביאה את כל המערך; כל עדכון כותב מסמך גדול; אינדקס על המערך (אם יש) עם עשרות אלפי רשומות.
  3. reference בכיוון השני: customerId בכל הזמנה, עם אינדקס { customerId: 1, createdAt: -1 }.
  4. "subset pattern": ‏$push: { recentOrders: { $each: [summary], $slice: -5 } } — מערך שלא עובר 5, עם עותק קטן של כל הזמנה.
⚠️ טעויות נפוצות
  • לפתור עם "נמחק הזמנות ישנות מהמערך מדי פעם" — מנגנון ניקוי שלם, במקום מבנה שלא צריך אותו.

P25.7-E57 · לשכפל את שם הלקוח בהזמנה? 🧠 הבנה רמה 2

💡 רמז 1

שכפול שווה כשהוא "אמת היסטורית", או כשהשדה כמעט לא משתנה.

💡 רמז 2

"שם על החשבונית" מול "איך לפנות ללקוח היום".

✅ פתרון
  1. (א) כל ההזמנות מראות מיד את השם החדש. (ב) ההזמנות הישנות מראות את הישן, אלא אם מעדכנים את כולן (‏updateMany).
  2. תלוי מה זה: בחשבונית — השם שבו נעשתה ההזמנה (בדיוק כמו המחיר). בממשק "צור קשר" — השם העדכני.
  3. (ב) עם השם "בזמן ההזמנה" — זו אמת היסטורית, ורשימת הזמנות היא מסך חם. למסך הלקוח — מהמסמך שלו.
  4. לא — אימייל משמש ליצירת קשר, והוא חייב להיות העדכני. מביאים מהלקוח כשצריך.
⚠️ טעויות נפוצות
  • לשכפל "כל מה שאולי נצטרך" — ואז כל שינוי פרופיל מחייב עדכון של אלפי מסמכים.

P25.7-E58 · ‏$lookup בכל שאילתה 🧠 הבנה רמה 2

💡 רמז 1

‏$lookup הוא שאילתה למסמכים אחרים לכל מסמך (עם אינדקס — מהיר יותר, אבל עדיין).

💡 רמז 2

אם כל מסך צריך join — אולי הנתונים באמת רלציוניים.

✅ פתרון
  1. המבנה תוכנן לפי ישויות, לא לפי שאילתות. מקבלים את החסרונות של Mongo (בלי FK, טרנזקציות פחות טבעיות) בלי היתרון (קריאה של מסמך אחד).
  2. ‏Postgres מתכנן JOINs כבר עשרות שנים (סדר, hash/merge join, סטטיסטיקה). ב־Mongo ‏$lookup הוא בעיקר nested loop לפי אינדקס, ומוגבל יותר בעבודה עם כמה collections.
  3. (א) embed / שכפול חלקי לפי מה שהמסכים צריכים (E55, E57). (ב) אם הנתונים רלציוניים באמת — Postgres. זו תשובה לגיטימית (שיעור 5).
⚠️ טעויות נפוצות
  • להוסיף אינדקסים ל־foreignField ולחשוב שהבעיה נפתרה — היא נעשתה מהירה יותר, לא נכונה יותר.

P25.7-E59 · ‏$jsonSchema או Zod — מי תופס מה? 🧠 הבנה רמה 2

💡 רמז 1

‏Zod רק במסלול שעובר דרכו. ‏$jsonSchema — בכל כתיבה, מכל מקור.

💡 רמז 2

ייחודיות היא לא "צורה" — היא קשר בין מסמכים.

✅ פתרון
  1. שניהם (אם ב־schema כתוב bsonType: ["int", "double"]). Zod קודם — עם הודעה טובה למשתמש.
  2. רק $jsonSchema — הסקריפט עוקף את האפליקציה.
  3. $jsonSchema (‏minimum: 0) — ‏updateOne עובר ולידציה בשרת, וקוד מנהל לא עבר דרך Zod.
  4. רק Zod — ובסקריפט עוקף, אף אחד.
  5. אף אחד מהם — אינדקס ייחודי (‏P25.7-E07).

Zod — הודעות טובות וכללים עסקיים, בגבול של ה־API. ‏$jsonSchema — רשת ביטחון למבנה, לכל מי שכותב. ואינדקסים — לייחודיות.

⚠️ טעויות נפוצות
  • להעתיק את כל כללי Zod ל־$jsonSchema — שני מקומות לתחזק, ושגיאות 121 לא ידידותיות כהודעה למשתמש.

P25.7-E16 · דירוגים עם תקציר 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

הכול ב־updateOne אחד: התנאי "עוד לא דירג" ב־filter, $push ו־$inc ב־update.

💡 רמז 2

"reviews.by": { $ne: by } — "אין במערך דירוג של by".

✅ פתרון
// P25.7-E16
import type { Db } from "mongodb";

interface Review {
  by: string;
  rating: number;
}
interface Product {
  _id: string;
  reviews: Review[];
  ratingCount: number;
  ratingSum: number;
}

export async function addReview(db: Db, productId: string, { by, rating }: { by: string; rating: number }) {
  if (!Number.isInteger(rating) || rating < 1 || rating > 5) throw new RangeError("rating: 1 עד 5");
  // פקודה אחת: התנאי "הלקוח עוד לא דירג", הוספת הדירוג, ועדכון הסיכום — הכול אטומי על המסמך.
  // כך הממוצע (ratingSum / ratingCount) תמיד תואם למערך, גם בשתי בקשות במקביל
  const r = await db.collection<Product>("products").updateOne(
    { _id: productId, "reviews.by": { $ne: by } },
    { $push: { reviews: { by, rating } }, $inc: { ratingCount: 1, ratingSum: rating } }
  );
  return r.modifiedCount === 1;
}

export async function averageRating(db: Db, productId: string) {
  const p = await db.collection<Product>("products").findOne({ _id: productId }, { projection: { ratingCount: 1, ratingSum: 1 } });
  if (!p) return null;
  return p.ratingCount === 0 ? 0 : Math.round((p.ratingSum / p.ratingCount) * 10) / 10;
}
⚠️ טעויות נפוצות
  • לחשב ממוצע מכל המערך בכל קריאה — עובד, ומאט ככל שיש יותר דירוגים.
  • $push בפקודה אחת ו־$inc בשנייה — בין שתיהן, התקציר לא תואם, ושגיאה באמצע משאירה אותו שגוי לתמיד.

P25.7-E18 · schema validation 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

db.createCollection("books", { validator: { $jsonSchema: { … } } }). מספר שלם — bsonType: "int"; כל מספר — ["double", "int"].

💡 רמז 2

additionalProperties: false חוסם גם את _id — צריך properties: { _id: {} }.

✅ פתרון
// P25.7-E18
import type { Db } from "mongodb";

// $jsonSchema: Mongo בודק כל insert ו־update. מסמך לא תקין ← שגיאה 121 (Document failed validation)
export async function createBooksCollection(db: Db) {
  await db.createCollection("books", {
    validator: {
      $jsonSchema: {
        bsonType: "object",
        required: ["title", "price", "stock", "format"],
        additionalProperties: false,
        properties: {
          _id: {},
          title: { bsonType: "string", minLength: 1 },
          price: { bsonType: ["double", "int"], minimum: 0 },
          stock: { bsonType: "int", minimum: 0 },
          format: { enum: ["paperback", "hardcover", "ebook"] },
          tags: { bsonType: "array", items: { bsonType: "string" } },
        },
      },
    },
    validationAction: "error",
  });
}
⚠️ טעויות נפוצות
  • bsonType: "number" ל־stock — מקבל גם 1.5.
  • לשכוח את _id ב־properties כשיש additionalProperties: false — אף מסמך לא נכנס.

P25.7-E60 · הזמנה מהעגלה — עם עותק של המחיר 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏new Map(products.map((p) => [p._id, p])).

💡 רמז 2

איחוד: Map נוספת של productId ← פריט, ומערך לפי סדר ההופעה הראשונה.

✅ פתרון
// P25.7-E60: הזמנה מהעגלה — עם עותק של המחיר
type Product = { _id: string; name: string; price: number; stock: number };
type Item = { productId: string; name: string; price: number; qty: number };

export function buildOrder(products: Product[], cart: { productId: string; qty: number }[], customerId: string, now: Date) {
  if (cart.length === 0) throw new Error("EMPTY_CART");
  const byId = new Map(products.map((p) => [p._id, p]));
  const items = new Map<string, Item>();
  for (const { productId, qty } of cart) {
    if (!Number.isInteger(qty) || qty <= 0) throw new RangeError(`כמות לא תקינה: ${qty}`);
    const p = byId.get(productId);
    if (!p) throw new Error(`UNKNOWN_PRODUCT ${productId}`);
    const existing = items.get(productId);
    if (existing) existing.qty += qty;
    else items.set(productId, { productId, name: p.name, price: p.price, qty });
  }
  const list = [...items.values()];
  return {
    customerId,
    status: "pending" as const,
    createdAt: now,
    items: list,
    total: list.reduce((s, i) => s + i.price * i.qty, 0),
  };
}
⚠️ טעויות נפוצות
  • לשמור רק productId ולחשב את המחיר בזמן התצוגה — אחרי העלאת מחיר, כל ההזמנות הישנות "מתייקרות".

P25.7-E61 · לתקן תקצירי דירוג 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1
find({}, { projection: { reviews: 1, ratingCount: 1, ratingSum: 1 } })

ולולאה.

💡 רמז 2

‏reduce על הדירוגים, ו־updateOne רק כשצריך.

✅ פתרון
// P25.7-E61: לתקן תקצירי דירוג
import type { Db } from "mongodb";

type P = { _id: string; reviews?: { rating: number }[]; ratingCount?: number; ratingSum?: number };

export async function recomputeRatings(db: Db): Promise<string[]> {
  const products = db.collection<P>("products");
  const fixed: string[] = [];
  for (const p of await products.find({}, { projection: { reviews: 1, ratingCount: 1, ratingSum: 1 } }).toArray()) {
    const reviews = p.reviews ?? [];
    const count = reviews.length;
    const sum = reviews.reduce((s, r) => s + r.rating, 0);
    if (p.ratingCount !== count || p.ratingSum !== sum) {
      await products.updateOne({ _id: p._id }, { $set: { ratingCount: count, ratingSum: sum } });
      fixed.push(p._id);
    }
  }
  return fixed.sort();
}

בחנות גדולה — עם aggregation ו־$merge, או בקבוצות; ועדיף להריץ כ־job לילי שמדווח כמה תוקנו (מספר גדול מאפס = באג איפשהו).

⚠️ טעויות נפוצות
  • לעדכן את כל המוצרים תמיד — אי אפשר לדעת אם היו בכלל סטיות.

P25.7-E62 · הוצאת הביקורות ל־collection משלהן 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

find({ reviews: { $exists: true } }).

💡 רמז 2
updateOne({ productId, by }, { $set: { rating } }, { upsert: true })

‏upsertedCount אומר אם נוצר.

✅ פתרון
// P25.7-E62: הוצאת הביקורות ל־collection משלהן
import type { Db } from "mongodb";

type P = { _id: string; reviews?: { by: string; rating: number }[] };

export async function extractReviews(db: Db) {
  const reviews = db.collection("reviews");
  await reviews.createIndex({ productId: 1, by: 1 }, { unique: true });
  const products = db.collection<P>("products");
  let moved = 0;
  for (const p of await products.find({ reviews: { $exists: true } }, { projection: { reviews: 1 } }).toArray()) {
    for (const r of p.reviews ?? []) {
      const res = await reviews.updateOne({ productId: p._id, by: r.by }, { $set: { rating: r.rating } }, { upsert: true });
      moved += res.upsertedCount;
    }
    await products.updateOne({ _id: p._id }, { $unset: { reviews: "" } }); // רק אחרי שכל הביקורות נשמרו
  }
  return { moved };
}

הסדר חשוב: קודם מעתיקים, ורק אז מוחקים מהמקור. קריסה באמצע ← ההרצה הבאה משלימה, בזכות ה־upsert. (זה expand/contract מפרק 25, בתוך מסד אחד.)

⚠️ טעויות נפוצות
  • insertMany בלי ייחודיות — הרצה חוזרת אחרי קריסה מכפילה ביקורות.

P25.7-E63 · ‏$jsonSchema ל־customers 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1
db.createCollection("customers", { validator: { $jsonSchema: { … } } })

כמו בשיעור.

💡 רמז 2
{ bsonType: "array", maxItems: 5, items: { bsonType: "object" } }

ו־{ bsonType: "string", pattern: "…" }.

✅ פתרון
// P25.7-E63: $jsonSchema ל־customers
import type { Db } from "mongodb";

export async function createCustomersCollection(db: Db): Promise<void> {
  await db.createCollection("customers", {
    validator: {
      $jsonSchema: {
        bsonType: "object",
        required: ["name", "email", "createdAt"],
        properties: {
          name: { bsonType: "string", minLength: 1 },
          email: { bsonType: "string", pattern: "^[^@\\s]+@[^@\\s]+$" },

          city: { bsonType: "string" },

        },

P25.7-E64 · עד 5 כתובות — בפקודה אחת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

"פחות מ־5 איברים" = "אין איבר באינדקס 4": ‏{ "addresses.4": { $exists: false } }.

💡 רמז 2

לקוח בלי מערך בכלל — גם מתאים לתנאי, ו־$push יוצר מערך.

✅ פתרון
// P25.7-E64: עד 5 כתובות — בפקודה אחת
import type { Db } from "mongodb";

export async function addAddress(db: Db, customerId: string, address: { label: string; street: string; city: string }) {
  const customers = db.collection<{ _id: string; addresses?: object[] }>("customers");
  const r = await customers.updateOne({ _id: customerId, "addresses.4": { $exists: false } }, { $push: { addresses: address } });
  if (r.modifiedCount === 1) return "added" as const;
  return (await customers.countDocuments({ _id: customerId }, { limit: 1 })) ? ("limit" as const) : ("not_found" as const);
}

‏"addresses.4" — נקודה ומספר פונים לאיבר במערך. התנאי והדחיפה באותו עדכון, ולכן אטומיים יחד — כמו stock: { $gte: 1 } בשיעור 2.

⚠️ טעויות נפוצות
  • { $where: "this.addresses.length < 5" } או $expr עם $size — עובד, אבל איטי ולא משתמש באינדקסים; ‏"addresses.4" פשוט יותר.

P25.7-E65 · ‏$lookup: הזמנות עם שם הלקוח 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1
{ $lookup: { from: "customers", localField: "customerId", foreignField: "_id", as: "customer" } }
💡 רמז 2
{ $unwind: { path: "$customer", preserveNullAndEmptyArrays: true } }

כדי שהזמנה בלי לקוח לא תיעלם. וב־$project: ‏{ $ifNull: ["$customer.name", null] }.

✅ פתרון
// P25.7-E65: $lookup — הזמנות עם שם הלקוח
import type { Db } from "mongodb";

export async function ordersWithCustomer(db: Db, status: string) {
  return (await db.collection("orders").aggregate([
    { $match: { status } },
    { $sort: { createdAt: -1 } },
    { $lookup: { from: "customers", localField: "customerId", foreignField: "_id", as: "customer" } },
    { $unwind: { path: "$customer", preserveNullAndEmptyArrays: true } },
    { $project: { _id: 0, orderId: "$_id", customerName: { $ifNull: ["$customer.name", null] }, total: 1 } },
  ]).toArray()) as { orderId: string; customerName: string | null; total: number }[];
}

‏$lookup הוא LEFT JOIN — ו־$unwind רגיל הופך אותו בשקט ל־INNER (מוחק הזמנות בלי לקוח). ‏preserveNullAndEmptyArrays משאיר אותן.

⚠️ טעויות נפוצות
  • ‏$sort אחרי ה־$lookup — עובד, אבל ה־lookup רץ על הכול לפני שממיינים ומגבילים. ‏$match ו־$sort קודם.

// P25.7-E69: ממסמך לשורות — order ו־order_items
type OrderDoc = { _id: string; customerId: string; status: string; createdAt: Date; items: { productId: string; name: string; price: number; qty: number }[] };

export function toRows(order: OrderDoc) {
  const items = order.items.map((it, i) => ({ order_id: order._id, line: i + 1, product_id: it.productId, quantity: it.qty, unit_price: it.price }));
  return {
    order: {
      id: order._id,
      customer_id: order.customerId,
      status: order.status,
      created_at: order.createdAt.toISOString(),
      total: items.reduce((s, i) => s + i.unit_price * i.quantity, 0),
    },
    items,
  };
}

// P25.7-E70: ביקורת חדשה — Zod, 121 ו־11000
import { MongoServerError, type Db } from "mongodb";
import { z } from "zod";

const schema = z.strictObject({
  productId: z.string().min(1),
  by: z.string().min(1),
  rating: z.number(),
  text: z.string().max(500).optional(),
});

export async function createReview(db: Db, input: unknown) {
  const r = schema.safeParse(input);
  if (!r.success) throw new Error("VALIDATION_ERROR");
  try {
    const { insertedId } = await db.collection("reviews").insertOne({ ...r.data, createdAt: new Date() });
    return { id: insertedId.toHexString() };
  } catch (err) {
    if (err instanceof MongoServerError && err.code === 121) throw new Error("SCHEMA_VIOLATION");
    if (err instanceof MongoServerError && err.code === 11000) throw new Error("ALREADY_REVIEWED");
    throw err;
  }
}
⚠️ טעויות נפוצות
  • לתפוס כל שגיאה כ־"ALREADY_REVIEWED" — ואז מסד שלא זמין נראה למשתמש כמו "כבר דירגת".

💡 רמז 2

✅ פתרון
// P25.7-E71: GET /orders/:id — מסמך אחד, ושם מ־customers
import { Router } from "express";
import type { Db } from "mongodb";

type Order = { _id: string; customerId: string; status: string; createdAt: Date; total: number; items: { productId: string; name: string; price: number; qty: number }[] };

export function ordersRouter(db: Db) {
  const router = Router();
  router.get("/orders/:id", async (req, res) => {
    const o = await db.collection<Order>("orders").findOne({ _id: req.params.id });
    if (!o) {
      res.status(404).json({ error: { code: "NOT_FOUND" } });
      return;
    }
    const c = await db.collection<{ _id: string; name: string }>("customers").findOne({ _id: o.customerId }, { projection: { name: 1 } });
    res.json({
      id: o._id,
      status: o.status,
      createdAt: o.createdAt.toISOString(),
      total: o.total,
      customer: c ? { id: c._id, name: c.name } : null,
      items: o.items.map(({ productId, name, price, qty }) => ({ productId, name, price, qty })),
    });
  });
  return router;
}
⚠️ טעויות נפוצות
  • להחזיר את o כמו שהוא — ‏_id ו־customerId במקום המבנה שהובטח ל־frontend.
