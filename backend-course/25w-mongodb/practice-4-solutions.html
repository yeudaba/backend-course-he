P25.7-E04 · לקרוא explain 🧠 הבנה רמה 1

💡 רמז 1

12 חזרו, 3,800 נבדקו. ו־SORT בתוכנית = מיון בזיכרון.

💡 רמז 2

ESR: שני שדות של שוויון, ואחריהם שדה המיון.

✅ פתרון
  1. האינדקס מצא את 3,800 ההזמנות של c42; את הסינון לפי status ואת המיון Mongo עשה אחר כך — קרא 3,800 מסמכים כדי להחזיר 12, ומיין בזיכרון.
  2. { customerId: 1, status: 1, createdAt: -1 }. שני שדות השוויון קודם (הסדר ביניהם פחות חשוב), ואחריהם שדה המיון — כך הרשומות באינדקס כבר ממוינות בתוך כל צירוף.
  3. אין SORT בתוכנית, ו־totalKeysExamined / totalDocsExamined ≈ 12.
⚠️ טעויות נפוצות
  • { createdAt: -1, customerId: 1 } — שדה המיון ראשון: Mongo עובר על כל ההזמנות לפי זמן ומסנן תוך כדי.

P25.7-E72 · ‏$match — לפני או אחרי? 🧠 הבנה רמה 2

💡 רמז 1

אינדקס עוזר רק לשלב שקורא מה־collection — כלומר לשלב הראשון.

💡 רמז 2

"מוצרים שההכנסה שלהם מעל 1,000".

✅ פתרון
  1. א: מיליון הזמנות ← 3 מיליון מסמכים אחרי unwind, ואז קיבוץ של כולם. ב: ‏100,000 ← ‏300,000.
  2. ב — $match בתחילה עובר ישירות על ה־collection ויכול להשתמש באינדקס (‏IXSCAN). אחרי $unwind/$group המסמכים כבר לא "מה־collection" — אין אינדקס.
  3. כשהתנאי הוא על תוצאה של הקיבוץ: { $match: { revenue: { $gt: 1000 } } } — כמו HAVING ב־SQL.
⚠️ טעויות נפוצות
  • לסמוך על כך שהאופטימייזר "יזיז" את ה־$match לבד — לפעמים כן, אבל לא כשהוא תלוי בשדה שנוצר ב־$group.

P25.7-E73 · ‏$unwind ומערך ריק 🧠 הבנה רמה 2

💡 רמז 1

‏$unwind על מערך ריק — מסמך אחד לכל איבר. כמה איברים?

💡 רמז 2

‏$size.

  • דוח "מוצרים בלי ביקורות" עם $unwind רגיל — תמיד ריק.

P25.7-E74 · ‏ESR — איזה אינדקס? 🧠 הבנה רמה 2

💡 רמז 1

Equality, Sort, Range — בסדר הזה.

💡 רמז 2

אחרי שדה עם טווח, השדות הבאים כבר לא ממוינים "גלובלית".

✅ פתרון
  1. מסנן היטב, אבל createdAt אחרי טווח — ממוין רק בתוך כל ערך של total. ‏SORT בזיכרון.
  2. הנכון (ESR): ‏customerId (שוויון) ← createdAt (מיון, כבר בסדר) ← total (טווח — מסונן בתוך האינדקס, בלי לקרוא מסמכים).
  3. הסדר נכון, אבל עובר על כל ההזמנות לפי זמן כדי למצוא את של c1.
  4. טווח ראשון — סורק את כל ה־total ≥ 100 של כל הלקוחות, ואז ממיין.
⚠️ טעויות נפוצות
  • "השדה הכי סלקטיבי ראשון" — כלל ישן שלא מתחשב במיון.

P25.7-E75 · ‏TTL — מתי זה באמת נמחק? 🧠 הבנה רמה 2

💡 רמז 1

תהליך הרקע רץ בערך פעם בדקה.

💡 רמז 2

TTL עובד רק על Date.

✅ פתרון
  1. כנראה כן — המחיקה לא מיידית (עד דקה ויותר, תחת עומס).
  2. לא נמחק לעולם — TTL מתעלם מערכים שאינם Date.
  3. לא נמחק לעולם.
  4. בדיקה בשאילתה עצמה: findOne({ token, expiresAt: { $gt: new Date() } }). ה־TTL הוא ניקיון, לא אבטחה.
⚠️ טעויות נפוצות
  • לסמוך על TTL כ"תוקף" של טוקן — חלון של דקה שבו טוקן שפג עדיין עובד.

P25.7-E76 · ‏multikey ושני מערכים 🧠 הבנה רמה 3

💡 רמז 1

multikey — רשומה לכל ערך במערך.

💡 רמז 2

4 תגיות × 5 צבעים.

✅ פתרון
  1. 4 — אחת לכל תגית.
  2. זה היה מכפלה קרטזית (4 × 5 = 20 רשומות למסמך, ומתפוצץ). Mongo לא מרשה: "cannot index parallel arrays".
  3. אינדקס על אחד מהם (הסלקטיבי יותר), והשני מסונן על המסמכים שנמצאו. או אינדקס מורכב עם שדה רגיל: { category: 1, tags: 1 }. או, אם צריך באמת — מבנה אחר (variants: [{ tag, color }]).
⚠️ טעויות נפוצות
  • להוסיף אינדקס על כל מערך "כדי שיהיה" — כל עדכון של המערך מעדכן רשומה לכל ערך.

P25.7-E12 · אינדקסים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

ESR: equality קודם, sort אחריו. createIndex(keys, { name }).

💡 רמז 2

TTL: { expiresAt: 1 }, { expireAfterSeconds: 0 } — "0 שניות אחרי הזמן שבשדה".

✅ פתרון
// P25.7-E12
import type { Db } from "mongodb";

export async function createIndexes(db: Db) {
  // ESR: Equality (customerId) ← Sort (createdAt) — מתאים ל"ההזמנות של לקוח, מהחדשה"
  await db.collection("orders").createIndex({ customerId: 1, createdAt: -1 }, { name: "customer_recent" });
  await db.collection("products").createIndex({ category: 1, price: 1 }, { name: "category_price" });
  // TTL: Mongo מוחק לבד מסמכים שה־expiresAt שלהם עבר (תהליך רקע, בערך פעם בדקה)
  await db.collection("sessions").createIndex({ expiresAt: 1 }, { name: "sessions_ttl", expireAfterSeconds: 0 });
}
⚠️ טעויות נפוצות
  • { createdAt: -1, customerId: 1 } — עדיין IXSCAN, אבל על כל ההזמנות.
  • TTL על שדה שהוא מחרוזת — Mongo לא מוחק כלום (רק Date).

P25.7-E14 · מכירות לפי מוצר 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

$match ← $unwind ← $group ← $sort ← $project.

💡 רמז 2

revenue: { $sum: { $multiply: ["$items.price", "$items.qty"] } }, ו־name: { $first: "$items.name" }.

✅ פתרון
// P25.7-E14
import type { Db } from "mongodb";

export async function salesByProduct(db: Db) {
  return db
    .collection("orders")
    .aggregate([
      { $match: { status: { $in: ["paid", "delivered"] } } }, // קודם מסננים — פחות מסמכים לשלבים הבאים
      { $unwind: "$items" }, // מסמך לכל פריט
      { $group: { _id: "$items.productId", name: { $first: "$items.name" }, units: { $sum: "$items.qty" }, revenue: { $sum: { $multiply: ["$items.price", "$items.qty"] } } } },
      { $sort: { revenue: -1, _id: 1 } },
      { $project: { _id: 0, productId: "$_id", name: 1, units: 1, revenue: 1 } },
    ])
    .toArray();
}
⚠️ טעויות נפוצות
  • $match אחרי $group — כבר אין status.
  • $lookup ל־products כדי לקחת מחיר — המחיר של היום, לא של ההזמנה.

P25.7-E15 · הלקוחות המובילים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

קיבוץ לפי customerId, ואז $lookup ל־customers.

💡 רמז 2

$limit לפני ה־$lookup. ותוצאת $lookup היא מערך — $unwind.

✅ פתרון
// P25.7-E15
import type { Db } from "mongodb";

export async function topCustomers(db: Db, n = 3) {
  return db
    .collection("orders")
    .aggregate([
      { $match: { status: { $ne: "cancelled" } } },
      { $group: { _id: "$customerId", spent: { $sum: "$total" }, orders: { $sum: 1 } } },
      { $sort: { spent: -1, _id: 1 } },
      { $limit: n }, // לפני ה־$lookup: מצטרפים רק ל־n לקוחות, לא לכולם
      { $lookup: { from: "customers", localField: "_id", foreignField: "_id", as: "customer" } },
      { $unwind: "$customer" },
      { $project: { _id: 0, customerId: "$_id", name: "$customer.name", spent: 1, orders: 1 } },
    ])
    .toArray();
}
⚠️ טעויות נפוצות
  • $lookup לפני ה־$group — מצרפים את הלקוח לכל הזמנה, ואז מקבצים.
  • name: "$customer.name" בלי $unwind — מקבלים מערך של שם אחד.

P25.7-E22 · aggregation עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

הרץ את ה־pipeline שלב אחרי שלב (מחק את השלבים מהסוף) ותסתכל על המסמכים.

💡 רמז 2

אחרי $group יש רק _id והשדות שהגדרת. ו־{ $sum: 1 } סופר מסמכים, לא יחידות.

✅ פתרון
// P25.7-E22
import type { Db } from "mongodb";

// כמה יחידות נמכרו מכל קטגוריה (הזמנות ששולמו או נמסרו)
export async function unitsByCategory(db: Db) {
  return db
    .collection("orders")
    .aggregate([
      { $match: { status: { $in: ["paid", "delivered"] } } }, // תקלה 1: לסנן לפני ה־$group — אחריו כבר אין status
      { $unwind: "$items" }, // תקלה 2: בלי $unwind, "$items.qty" הוא מערך, ו־$sum של מערך הוא 0
      { $lookup: { from: "products", localField: "items.productId", foreignField: "_id", as: "product" } },
      { $unwind: "$product" },
      { $group: { _id: "$product.category", units: { $sum: "$items.qty" } } }, // תקלה 3: qty, לא 1 (1 סופר שורות)
      { $sort: { units: -1, _id: 1 } },
      { $project: { _id: 0, category: "$_id", units: 1 } },
    ])
    .toArray();
}
⚠️ טעויות נפוצות
  • להוסיף status: { $first: "$status" } ל־$group ולסנן אחריו — מסנן לפי הסטטוס של הזמנה אחת בכל קבוצה.

P25.7-E24 · אתגר: דשבורד בבקשה אחת 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

$facet: { byDay: [...], byStatus: [...], topProducts: [...] } — שלושה pipelines על אותם מסמכים.

💡 רמז 2

$dateToString: { date: "$createdAt", format: "%Y-%m-%d", timezone: "Asia/Jerusalem" }. ו־byStatus — המרה לאובייקט ב־JS אחרי השאילתה.

✅ פתרון
// P25.7-E24
import type { Db } from "mongodb";

// דשבורד של טווח תאריכים — בבקשה אחת: הכנסות לפי יום (בשעון ישראל), ספירה לפי סטטוס, ו־3 המוצרים המובילים
export async function dashboard(db: Db, from: Date, to: Date) {
  const [result] = await db
    .collection("orders")
    .aggregate([
      { $match: { createdAt: { $gte: from, $lt: to } } },
      {
        $facet: {
          byDay: [
            { $match: { status: { $ne: "cancelled" } } },
            // היום לפי ישראל, לא לפי UTC: הזמנה ב־22:10Z ב־1.11 היא 2.11 בישראל (פרק 24)
            { $group: { _id: { $dateToString: { date: "$createdAt", format: "%Y-%m-%d", timezone: "Asia/Jerusalem" } }, revenue: { $sum: "$total" }, orders: { $sum: 1 } } },
            { $sort: { _id: 1 } },
            { $project: { _id: 0, day: "$_id", revenue: 1, orders: 1 } },
          ],
          byStatus: [{ $group: { _id: "$status", n: { $sum: 1 } } }, { $sort: { _id: 1 } }],
          topProducts: [
            { $match: { status: { $ne: "cancelled" } } },
            { $unwind: "$items" },
            { $group: { _id: "$items.productId", units: { $sum: "$items.qty" } } },
            { $sort: { units: -1, _id: 1 } },
            { $limit: 3 },
            { $project: { _id: 0, productId: "$_id", units: 1 } },
          ],
        },
      },
    ])
    .toArray();
  return {
    byDay: result.byDay,
    byStatus: Object.fromEntries(result.byStatus.map((s: { _id: string; n: number }) => [s._id, s.n])),
    topProducts: result.topProducts,
  };
}
⚠️ טעויות נפוצות
  • קיבוץ לפי יום ב־UTC — o6 (21:55Z ב־21.10) נספרת ב־21.10, אבל בישראל זה כבר 22.10.
  • שלוש שאילתות נפרדות — עובד, אבל שלוש סריקות של אותו טווח.

P25.7-E77 · הכנסות לפי יום — בשעון ישראל 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1
{ $dateToString: { format: "%Y-%m-%d", date: "$createdAt", timezone } }
💡 רמז 2

‏$match קודם:

{ status: { $ne: "cancelled" }, createdAt: { $gte: from, $lt: to } }
✅ פתרון
// P25.7-E77: הכנסות לפי יום — בשעון ישראל
import type { Db } from "mongodb";

export async function revenueByDay(db: Db, { timezone, from, to }: { timezone: string; from: Date; to: Date }) {
  return (await db.collection("orders").aggregate([
    { $match: { status: { $ne: "cancelled" }, createdAt: { $gte: from, $lt: to } } },
    { $group: { _id: { $dateToString: { format: "%Y-%m-%d", date: "$createdAt", timezone } }, orders: { $sum: 1 }, revenue: { $sum: "$total" } } },
    { $sort: { _id: 1 } },
    { $project: { _id: 0, day: "$_id", orders: 1, revenue: 1 } },
  ]).toArray()) as { day: string; orders: number; revenue: number }[];
}
⚠️ טעויות נפוצות
  • $dateToString בלי timezone — יום לפי UTC, והזמנה של 00:30 בישראל נספרת ביום הקודם (פרק 24).

P25.7-E78 · הזמנות לפי סטטוס — עם אחוזים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏$group לפי "$status" עם { $sum: 1 }, ואת האחוז — בקוד, אחרי שיש סך הכול.

💡 רמז 2

Math.round((count / total) * 1000) / 10.

✅ פתרון
// P25.7-E78: הזמנות לפי סטטוס — עם אחוזים
import type { Db } from "mongodb";

export async function ordersByStatus(db: Db) {
  const rows = (await db.collection("orders").aggregate([
    { $group: { _id: "$status", count: { $sum: 1 } } },
    { $sort: { count: -1, _id: 1 } },
  ]).toArray()) as { _id: string; count: number }[];
  const total = rows.reduce((s, r) => s + r.count, 0);
  return rows.map((r) => ({ status: r._id, count: r.count, percent: Math.round((r.count / total) * 1000) / 10 }));
}

אפשר גם הכול ב־aggregation (‏$group נוסף עם _id: null ו־$push, או $setWindowFields) — אבל כמה שורות של חשבון בקוד, על 4–5 שורות תוצאה, פשוטות יותר.

⚠️ טעויות נפוצות
  • countDocuments לכל סטטוס בנפרד — שאילתה לכל ערך, ורשימת סטטוסים קבועה בקוד שמתיישנת.

P25.7-E79 · האינדקסים של החנות — ובדיקה ב־explain 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

createIndex על אינדקס שכבר קיים (עם אותן הגדרות) לא עושה כלום.

💡 רמז 2

כמו בשיעור: JSON.stringify(ex.queryPlanner.winningPlan) ו־includes.

✅ פתרון
// P25.7-E79: האינדקסים של החנות — ובדיקה ב־explain
import type { Db } from "mongodb";

export async function ensureShopIndexes(db: Db): Promise<void> {
  await db.collection("orders").createIndex({ customerId: 1, createdAt: -1 });
  await db.collection("orders").createIndex({ status: 1, createdAt: -1 });
  await db.collection("products").createIndex({ category: 1, price: 1 });
  await db.collection("products").createIndex({ tags: 1 });
  await db.collection("customers").createIndex({ email: 1 }, { unique: true });
}

export async function usesIndex(db: Db, filter: object, sort: object) {
  const ex = await db.collection("orders").find(filter).sort(sort as Record<string, 1 | -1>).explain("executionStats");
  const plan = JSON.stringify(ex.queryPlanner.winningPlan);
  return { ixscan: plan.includes("IXSCAN"), inMemorySort: plan.includes('"SORT"') };
}
⚠️ טעויות נפוצות
  • ליצור אינדקסים "ביד" ב־mongosh בפרודקשן ולשכוח אותם בפיתוח — ‏ensureShopIndexes בעלייה (או ב־migration) שומר אותם בקוד.

P25.7-E80 · ‏GROUP BY מפרק 17 מול $group 🧠 הבנה רמה 2

💡 רמז 1

‏HAVING ← $match אחרי $group.

💡 רמז 2

ב׳: הפריטים כבר בתוך ההזמנה. הקטגוריה — לא.

✅ פתרון

א:

[{ $match: { status: { $ne: "cancelled" } } }, { $group: { _id: "$customerId", n: { $sum: 1 }, sum: { $sum: "$total" } } }, { $match: { n: { $gte: 2 } } }]

ב:

[{ $unwind: "$items" }, { $lookup: { from: "products", localField: "items.productId", foreignField: "_id", as: "p" } }, { $unwind: "$p" }, { $group: { _id: "$p.category", revenue: { $sum: { $multiply: ["$items.qty", "$items.price"] } } } }]

מה אין צורך: JOIN בין orders ל־order_items — הפריטים מוטמעים (‏$unwind במקום). ומה כן: הקטגוריה לא שוכפלה לפריט, אז $lookup. אם הדוח הזה חם — שווה לשכפל גם category לפריט (E57).

⚠️ טעויות נפוצות
  • $sum: "$items.qty" בלי $unwind — סכום של מערך בתוך $group הוא 0 (‏P25.7-E22).

P25.7-E81 · ‏EXPLAIN מפרק 18 מול explain 🧠 הבנה רמה 2

💡 רמז 1

‏COLLSCAN, ‏IXSCAN + FETCH, ‏PROJECTION_COVERED, ‏SORT.

💡 רמז 2

‏totalDocsExamined.

✅ פתרון
  • Seq Scan ← COLLSCAN.
  • Index Scan ← IXSCAN ואחריו FETCH (קריאת המסמך).
  • Index Only Scan ← IXSCAN בלי FETCH (‏covered query — ה־projection רק מהאינדקס, בלי _id אם הוא לא באינדקס).
  • Sort ← שלב SORT (מיון בזיכרון).
  • שורות בפועל ← nReturned, ‏totalDocsExamined, ‏totalKeysExamined.

היחס totalDocsExamined / nReturned: בשיעור — 5000 / 10 לפני, 10 / 10 אחרי. יחס קרוב ל־1 = האינדקס מוצא בדיוק את מה שצריך.

⚠️ טעויות נפוצות
  • להסתפק ב"יש IXSCAN" — אינדקס על שדה לא סלקטיבי עדיין יכול לבדוק 400,000 מסמכים כדי להחזיר 10.

P25.7-E82 · אזור זמן מפרק 24 — ב־aggregation 🧠 הבנה רמה 2

💡 רמז 1

‏+02:00 בחורף; בקיץ?

💡 רמז 2

תחילת יום בישראל ב־UTC — ‏P24-E12.

✅ פתרון
  1. ‏+02:00 קבוע — בקיץ ישראל ב־+03:00, וכל הזמנה בין 23:00 ל־00:00 (שעון ישראל) נספרת ביום הקודם. השם — Mongo מחשב לפי החוקים.
  2. from = חצות של אתמול בישראל, to = חצות של היום — כרגעים ב־UTC (‏dayRangeInZone / startOfDayInZone, ‏P24-E12). בחורף: 22:00Z של יום קודם.
  3. "יום" של מי? אזור של החנות היום, של לקוח בחו״ל, של דוח בעוד שנה אחרי שינוי מדיניות — כל אחד צריך חלוקה אחרת. Date אחד, והיום מחושב בשאילתה. (אפשר כ־cache נוסף, לא כמקור.)
⚠️ טעויות נפוצות
  • "נקבץ ב־UTC, זה מספיק קרוב" — עד שמישהו משווה לדוח של הקופה.

P25.7-E83 · התגיות הפופולריות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

{ $unwind: "$tags" }, ואז $group לפי "$tags".

💡 רמז 2

inStock: { $sum: { $cond: [{ $gt: ["$stock", 0] }, 1, 0] } }.

✅ פתרון
// P25.7-E83: התגיות הפופולריות
import type { Db } from "mongodb";

export async function popularTags(db: Db, limit: number) {
  return (await db.collection("products").aggregate([
    { $unwind: "$tags" },
    { $group: { _id: "$tags", products: { $sum: 1 }, inStock: { $sum: { $cond: [{ $gt: ["$stock", 0] }, 1, 0] } } } },
    { $sort: { products: -1, _id: 1 } },
    { $limit: limit },
    { $project: { _id: 0, tag: "$_id", products: 1, inStock: 1 } },
  ]).toArray()) as { tag: string; products: number; inStock: number }[];
}
⚠️ טעויות נפוצות
  • להביא את כל המוצרים ולספור ב־JavaScript — עובד על 8, לא על 800,000.

P25.7-E84 · לקוחות חוזרים — עם השם 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏$match ← ‏$group (‏$max: "$createdAt") ← ‏$match על הספירה ← ‏$lookup.

💡 רמז 2

‏$lookup רק אחרי שנשארו מעט קבוצות — זול יותר. ואת ה־ISO — ב־JS, או $dateToString.

✅ פתרון
// P25.7-E84: לקוחות חוזרים — עם השם
import type { Db } from "mongodb";

export async function repeatCustomers(db: Db, minOrders: number) {
  const rows = await db.collection("orders").aggregate([
    { $match: { status: { $ne: "cancelled" } } },
    { $group: { _id: "$customerId", orders: { $sum: 1 }, spent: { $sum: "$total" }, lastOrderAt: { $max: "$createdAt" } } },
    { $match: { orders: { $gte: minOrders } } },
    { $lookup: { from: "customers", localField: "_id", foreignField: "_id", as: "c" } },
    { $unwind: "$c" },
    { $sort: { spent: -1 } },
  ]).toArray();
  return rows.map((r) => ({ customerId: r._id, name: r.c.name, orders: r.orders, spent: r.spent, lastOrderAt: (r.lastOrderAt as Date).toISOString() }));
}
⚠️ טעויות נפוצות
  • ‏$lookup לפני ה־$group — על כל הזמנה, במקום על כל לקוח.

// P25.7-E85: דוח קטגוריות ל־CSV
import type { Db } from "mongodb";

const cell = (v: unknown) => {
  const s = String(v);
  return /[",\n]/.test(s) ? `"${s.replaceAll('"', '""')}"` : s;
};

export async function categoryCsv(db: Db): Promise<string> {
  const rows = await db.collection("orders").aggregate([
    { $match: { status: { $in: ["delivered", "paid"] } } },
    { $unwind: "$items" },
    { $lookup: { from: "products", localField: "items.productId", foreignField: "_id", as: "p" } },
    { $unwind: "$p" },
    { $group: { _id: "$p.category", units: { $sum: "$items.qty" }, revenue: { $sum: { $multiply: ["$items.price", "$items.qty"] } } } },
    { $sort: { _id: 1 } },
  ]).toArray();
  const lines = ["category,units,revenue", ...rows.map((r) => [r._id, r.units, r.revenue].map(cell).join(","))];
  return lines.join("\n") + "\n";
}
⚠️ טעויות נפוצות
  • row.join(",") בלי escaping — קטגוריה כמו gear, misc מוסיפה עמודה ושוברת את הקובץ באקסל.
