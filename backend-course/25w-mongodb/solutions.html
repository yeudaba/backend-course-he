P25.7-E26 · חיפוש מוצרים מ־query string 🤖 ✍️ מאפס רמה 3

💡 רמז 1

בונים אובייקט ריק, ומוסיפים לו מפתח לכל פרמטר שהגיע: if (query.q) filter.name = {...}. ה־escape: ‏s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&"). ‏$& בתוך מחרוזת ההחלפה הוא "מה שנמצא".

💡 רמז 2

למחיר: אובייקט range נפרד, ורק בסוף if (Object.keys(range).length > 0) filter.price = range. בדיקת מספר: ‏Number("") הוא 0, ולכן בודקים גם value.trim() === "", וגם Number.isFinite(n). ב־searchProducts: ‏find(filter).sort({ name: 1 }).project({ _id: 0, name: 1 }).toArray(), ואז map.

✅ פתרון
// P25.7-E26 — חיפוש מוצרים מ־query string
import type { Db } from "mongodb";

type Query = Record<string, string | undefined>;

const escapeRegex = (s: string) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

function price(value: string, name: string): number {
  const n = Number(value);
  if (value.trim() === "" || !Number.isFinite(n) || n < 0) throw new RangeError(`${name} לא תקין: ${value}`);
  return n;
}

export function buildProductFilter(query: Query): Record<string, unknown> {
  const filter: Record<string, unknown> = {};
  if (query.q) filter.name = { $regex: escapeRegex(query.q.trim()), $options: "i" };
  if (query.category) filter.category = query.category;

  const range: Record<string, number> = {};
  if (query.minPrice !== undefined) range.$gte = price(query.minPrice, "minPrice");
  if (query.maxPrice !== undefined) range.$lte = price(query.maxPrice, "maxPrice");
  if (range.$gte !== undefined && range.$lte !== undefined && range.$gte > range.$lte) throw new RangeError("minPrice גדול מ־maxPrice");
  if (Object.keys(range).length > 0) filter.price = range;

  if (query.tags) {
    const tags = query.tags.split(",").map((t) => t.trim()).filter((t) => t !== "");
    if (tags.length > 0) filter.tags = { $all: tags };
  }

  switch (query.inStock) {
    case undefined:
      break;
    case "true":
      filter.stock = { $gt: 0 };
      break;
    case "false":
      filter.stock = 0;
      break;
    default:
      throw new RangeError(`inStock חייב להיות true או false: ${query.inStock}`);
  }
  return filter;
}

export async function searchProducts(db: Db, query: Query): Promise<string[]> {
  const docs = await db.collection("products").find(buildProductFilter(query)).sort({ name: 1 }).project({ _id: 0, name: 1 }).toArray();
  return docs.map((d) => d.name);
}

הפילטר נבנה רק ממפתחות שאנחנו מכירים, וכל ערך נכנס למקום שקבענו מראש. כך ?category={"$ne":null} מחפש קטגוריה שזה השם שלה, ולא "כל מה שאינו null". זו אותה הגנה כמו ב־P25.7-E20: בלי להעביר את req.query ישר ל־find.

ה־escape חשוב פעמיים. ‏q=. בלי escape מתאים לכל מוצר: נקודה ב־regex היא "כל תו". ‏q=( בלי escape מפיל את השאילתה עם שגיאת regex של Mongo, כלומר 500 על קלט של משתמש. ‏regex עם $options: "i" בלי ^ בהתחלה לא משתמש באינדקס. בחנות של 8 מוצרים זה לא משנה, ובקטלוג גדול עוברים ל־Atlas Search או לאינדקס טקסט (שיעור 4).

⚠️ טעויות נפוצות
  • { price: { $gte: query.minPrice } } — מחרוזת. ב־Mongo "50" ו־50 הם טיפוסים שונים, ואף מוצר לא יתאים.
  • $regex: query.q בלי escape — ‏q=( מחזיר 500.
  • filter.price = { $gte: min, $lte: max } גם כשנשלח רק אחד — ‏$lte: undefined. הדרייבר משמיט שדות undefined, אבל כדאי לא לסמוך על זה.
  • tags: { $in: [...] } — מוצר עם אחת מהתגיות. המשימה: כולן ($all).

P25.7-E27 · בדיקות ל־parseSort 🤖 🔁 חזרה רמה 3

💡 רמז 1

שאלה חשובה: האם assert.deepEqual({ a: 1, b: 1 }, { b: 1, a: 1 }) עובר? כן, כי deepEqual לא בודק את סדר המפתחות. אבל במיון של Mongo הסדר הוא כל העניין: { price: -1, name: 1 } ו־{ name: 1, price: -1 } הם שני מיונים שונים. השווה את Object.entries(...), שהוא מערך, ומערך כן נבדק לפי הסדר.

💡 רמז 2

לכל שורה בתיאור — לפחות בדיקה אחת, ולכל "או" — בדיקה לכל צד: undefined, ‏"" וגם " ". ‏-_id לבד. שדה לא מותר עם מינוס ובלי. ‏"price," (פסיק בסוף) ו־"-" לבד.

✅ פתרון
// P25.7-E27 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { parseSort } from "./P25.7-E27.ts";

const ALLOWED = ["name", "price", "createdAt", "_id"];

// deepEqual לא בודק את סדר המפתחות — ובמיון של Mongo הסדר הוא כל העניין
function sameSort(actual: Record<string, number>, expected: Record<string, number>) {
  assert.deepEqual(Object.entries(actual), Object.entries(expected));
}

test("עולה, יורד, וכמה שדות לפי הסדר", () => {
  sameSort(parseSort("name", ALLOWED), { name: 1, _id: 1 });
  sameSort(parseSort("-price", ALLOWED), { price: -1, _id: 1 });
  sameSort(parseSort("-price,name", ALLOWED), { price: -1, name: 1, _id: 1 });
  sameSort(parseSort("name,-price", ALLOWED), { name: 1, price: -1, _id: 1 });
});

test("רווחים", () => {
  sameSort(parseSort(" -price , name ", ALLOWED), { price: -1, name: 1, _id: 1 });
});

test("_id: לא מוסיפים פעמיים, ולא משנים את הכיוון שנבחר", () => {
  sameSort(parseSort("-_id", ALLOWED), { _id: -1 });
  sameSort(parseSort("_id,name", ALLOWED), { _id: 1, name: 1 });
});

test("בלי value, או value ריק ← { _id: 1 }", () => {
  sameSort(parseSort(undefined, ALLOWED), { _id: 1 });
  sameSort(parseSort("", ALLOWED), { _id: 1 });
  sameSort(parseSort("   ", ALLOWED), { _id: 1 });
});

test("שדה לא מותר, ריק או כפול ← RangeError", () => {
  for (const bad of ["password", "-password", "name,secret", "price,", "-", "name,-name", "price,price"]) {
    assert.throws(() => parseSort(bad, ALLOWED), RangeError, bad);
  }
});

הפונקציה sameSort היא הבדיקה החשובה בתרגיל. בלעדיה, מימוש שמוסיף את _id ראשון ({ _id: 1, price: -1 }) עובר את כל הבדיקות. אבל ב־Mongo המיון הזה הוא "לפי _id", ו־price כבר לא משפיע, כי _id ייחודי.

הטבלה של הקלטים הלא תקינים תופסת כמה באגים יחד: בלי בדיקת allowed (מיון לפי password מאפשר לנחש סיסמאות: "מי לפני מי"), שדה כפול, ופסיק בסוף. ‏" " נפרד מ־"", כי שני מימושים "כמעט נכונים" מטפלים רק באחד מהם.

⚠️ טעויות נפוצות
  • assert.deepEqual על אובייקט המיון — לא תופס סדר מפתחות לא נכון.
  • לבדוק רק את "-price,name" — כל הבאגים במקרי הקצה: _id, ריק, כפול, לא מותר.
  • לבדוק את הודעת השגיאה המדויקת — מימוש תקין עם ניסוח אחר נכשל. מספיק RangeError.

P25.7-E28 · מה מסתתר ב־ObjectId 🤖 🔁 חזרה רמה 2

💡 רמז 1

parseInt(id.slice(0, 8), 16) ← שניות. בכיוון השני: seconds.toString(16).padStart(8, "0") + "0".repeat(16). בלי padStart, תאריכים ישנים (לפני 1978) נותנים פחות מ־8 תווים.

💡 רמז 2

day.match(/^(\d{4})-(\d{2})-(\d{2})$/), ואז new Date(Date.UTC(y, m - 1, d)) (החודש מ־0). חצות של מחר: start.getTime() + 24 * 60 * 60 * 1000. ב־UTC אין שעון קיץ, ולכן כל יום הוא בדיוק 24 שעות.

✅ פתרון
// P25.7-E28 — מה מסתתר ב־ObjectId
const OBJECT_ID = /^[0-9a-f]{24}$/i;

export function objectIdDate(id: string): Date {
  if (!OBJECT_ID.test(id)) throw new TypeError(`ObjectId לא תקין: ${id}`);
  const seconds = parseInt(id.slice(0, 8), 16);
  return new Date(seconds * 1000);
}

export function objectIdFromDate(date: Date): string {
  const seconds = Math.floor(date.getTime() / 1000);
  return seconds.toString(16).padStart(8, "0") + "0".repeat(16);
}

export function idRangeForDay(day: string): { $gte: string; $lt: string } {
  const match = day.match(/^(\d{4})-(\d{2})-(\d{2})$/);
  if (!match) throw new TypeError(`תאריך לא תקין: ${day}`);
  const start = new Date(Date.UTC(Number(match[1]), Number(match[2]) - 1, Number(match[3])));
  const end = new Date(start.getTime() + 24 * 60 * 60 * 1000);
  return { $gte: objectIdFromDate(start), $lt: objectIdFromDate(end) };
}

הבודק משווה את התוצאות שלך ל־ObjectId.getTimestamp() ול־ObjectId.createFromTime() של הדרייבר, ומריץ את הטווח על Mongo אמיתי. כדי להשתמש בו בשאילתה, הופכים את המחרוזות ל־ObjectId: { _id: { $gte: new ObjectId(r.$gte), $lt: new ObjectId(r.$lt) } }. השוואה בין ObjectId לפי בתים היא קודם כל השוואה לפי הזמן.

למה זה שימושי? ‏_id תמיד מאונדקס. טווח עליו הוא "כל ההזמנות מאתמול", בלי אינדקס נוסף על createdAt. שני דברים להיזהר מהם: הדיוק הוא שנייה, והזמן נקבע אצל מי שיצר את ה־ObjectId (בדרך כלל הדרייבר, כלומר השעון של השרת שלך). לדוחות מדויקים עדיף שדה createdAt אמיתי.

⚠️ טעויות נפוצות
  • parseInt(id.slice(0, 8)) בלי 16 — ‏6af2d608 נקרא כ־6.
  • לשכוח את * 1000 — ‏new Date מקבל מילישניות, והתאריך יוצא בינואר 1970.
  • new Date("2026-11-10") — עובד (מחרוזת תאריך בלבד נקראת כ־UTC), אבל new Date(2026, 10, 10) הוא חצות לפי השעון המקומי, ובישראל זה 22:00 של היום הקודם ב־UTC.
  • $lte במקום $lt לסוף הטווח — מסמכים מהשנייה הראשונה של מחר נכנסים.

P25.7-E01 · Mongo או Postgres? רמה 1

💡 רמז 1

שאל: האם הנתונים נקראים כ"אובייקט שלם"? כמה קשרים יש, והאם השאילתות עליהם ידועות מראש? כמה חשובה עקביות בין כמה רשומות?

💡 רמז 2

וזכור ש־Postgres עם jsonb יודע לשמור מבנה גמיש בתוך עמודה אחת.

✅ פתרון
  1. PostgreSQL. כסף: טרנזקציות על כמה טבלאות, מפתחות זרים, ודוחות עם JOIN ו־GROUP BY שלא ידועים מראש.
  2. Mongo מתאים מאוד — כל מוצר הוא מסמך עם מאפיינים משלו. (Postgres עם עמודת jsonb ל־specs — גם עובד.)
  3. שניהם. מסמך אחד שנכתב ונקרא בשלמותו — Mongo טבעי; ב־Postgres — שורה עם jsonb.
  4. לא זה ולא זה במיוחד — "חברים של חברים" הוא שאילתת גרף. Postgres עם recursive CTE מסתדר בהתחלה; בקנה מידה — מסד גרפים. Mongo עם מערך followers שגדל לנצח — המלכודת משיעור 3.
  5. שניהם יעבדו — משימות של משתמש הן מסמכים פשוטים. בחרנו Postgres כדי ללמוד SQL ו־Prisma, וזה בסדר גמור.
⚠️ טעויות נפוצות
  • "Mongo כי הוא מהיר יותר" / "Mongo כי אין schema" — בלי שיקול של דפוסי גישה ועקביות. זה מה שמראיין מחכה לשמוע שלא תגיד.

P25.7-E02 · embed או reference? רמה 1

💡 רמז 1

שלוש שאלות: נקרא תמיד ביחד עם ההורה? יש לכמות גבול טבעי? משתנה לבד, או משותף לרבים?

  2. reference — אין גבול. collection orders עם customerId ואינדקס { customerId: 1, createdAt: -1 }.

  • להטמיע הכול "כי ככה Mongo" — ואז לקוח עם 3,000 הזמנות בתוך מסמך אחד.
  • להפריד הכול "כמו בטבלאות" — ואז כל דף צריך חמישה $lookup.

P25.7-E05 · מ־SQL ל־Mongo רמה 1

💡 רמז 1

לעדכון 2: יש אופרטור שמכפיל ($mul).

💡 רמז 2

HAVING הוא $match אחרי $group.

✅ פתרון
  1. db.products.find({ category: "gear", stock: { $gt: 0 } }, { projection: { _id: 0, name: 1, price: 1 } }).sort({ price: -1 }).limit(2)
  2. db.products.updateMany({ category: "beans" }, { $mul: { price: 1.1 } }) — ושים לב: 62 × 1.1 = 68.2 (Double). מחירים מדויקים — Decimal128, או אגורות במספר שלם.
  3. db.orders.deleteMany({ status: "cancelled", createdAt: { $lt: new Date("2026-10-20T00:00:00+03:00") } }) — Date, לא מחרוזת, ועם אזור זמן.
  4. db.orders.aggregate([{ $group: { _id: "$customerId", n: { $sum: 1 } } }, { $match: { n: { $gte: 3 } } }]) ← c1 (4), c2 (3 — כולל ההזמנה שבוטלה), c3 (3). ל־c4 אין הזמנות, ולכן הוא לא מופיע בכלל (בניגוד ל־LEFT JOIN).
⚠️ טעויות נפוצות
  • updateOne במקום updateMany — רק המסמך הראשון מתעדכן.
  • להשוות createdAt למחרוזת: Date ומחרוזת הם טיפוסים שונים ב־BSON, ו־$lt ביניהם לא מחזיר כלום.

P25.7-E06 · חיפוש מוצרים 🤖 רמה 2

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.7-E06
import type { Db } from "mongodb";

// בונים את ה־filter רק מהשדות שהגיעו: undefined לא נכנס, אחרת הוא היה מחפש "שדה שערכו null"
export async function findProducts(db: Db, { category, maxPrice, inStock, tag }: { category?: string; maxPrice?: number; inStock?: boolean; tag?: string } = {}) {
  const filter: Record<string, unknown> = {};
  if (category !== undefined) filter.category = category;
  if (maxPrice !== undefined) filter.price = { $lte: maxPrice };
  if (inStock) filter.stock = { $gt: 0 };
  if (tag !== undefined) filter.tags = tag; // על מערך: "המערך מכיל את הערך"
  return db
    .collection("products")
    .find(filter, { projection: { _id: 1, name: 1, price: 1 } })
    .sort({ price: 1, _id: 1 }) // שובר שוויון — סדר יציב
    .toArray();
}

  • filter.category = category גם כשהוא undefined — ה־driver שולח null, ו־Mongo מחפש מסמכים שבהם השדה null או חסר.
  • מיון בלי שובר שוויון — סדר של מוצרים באותו מחיר לא מובטח.

P25.7-E08 · הוספה למלאי 🤖 רמה 2

💡 רמז 2

  _id: string;

export async function restock(db: Db, productId: string, qty: number) {

P25.7-E09 · תגיות: $addToSet ו־$pull 🤖 רמה 2

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.7-E09

interface Product {
  _id: string;
  name: string;
  price: number;
  stock: number;

}

const norm = (t: string) => t.trim().toLowerCase();

// $addToSet — מוסיף רק אם לא קיים. $push היה מוסיף כפילות
export async function addTag(db: Db, productId: string, tag: string) {
  const r = await db.collection<Product>("products").updateOne({ _id: productId }, { $addToSet: { tags: norm(tag) } });
  return r.matchedCount === 1;
}

export async function removeTag(db: Db, productId: string, tag: string) {
  const r = await db.collection<Product>("products").updateOne({ _id: productId }, { $pull: { tags: norm(tag) } });
  return r.matchedCount === 1;
}

  • $push במקום $addToSet — "organic" פעמיים.
  • modifiedCount כאינדיקציה לקיום — addTag של תגית קיימת יחזיר false.

P25.7-E10 · עמוד של מוצרים 🤖 רמה 2

💡 רמז 2

✅ פתרון
// P25.7-E10
import type { Db } from "mongodb";

export async function productsPage(db: Db, { page = 1, pageSize = 3, category }: { page?: number; pageSize?: number; category?: string } = {}) {
  if (!Number.isInteger(page) || page < 1 || !Number.isInteger(pageSize) || pageSize < 1 || pageSize > 50) throw new RangeError("page/pageSize לא תקינים");
  const filter = category === undefined ? {} : { category };
  const col = db.collection("products");
  // שתי שאילתות במקביל: העמוד עצמו, והספירה (באותו filter!)
  const [items, total] = await Promise.all([
    col.find(filter, { projection: { name: 1, price: 1 } }).sort({ name: 1, _id: 1 }).skip((page - 1) * pageSize).limit(pageSize).toArray(),
    col.countDocuments(filter),
  ]);
  return { items, total, totalPages: Math.ceil(total / pageSize) };
}

P25.7-E14 · מכירות לפי מוצר 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.7-E14
import type { Db } from "mongodb";

export async function salesByProduct(db: Db) {
  return db
    .collection("orders")
    .aggregate([
      { $match: { status: { $in: ["paid", "delivered"] } } }, // קודם מסננים — פחות מסמכים לשלבים הבאים
      { $unwind: "$items" }, // מסמך לכל פריט
      { $group: { _id: "$items.productId", name: { $first: "$items.name" }, units: { $sum: "$items.qty" }, revenue: { $sum: { $multiply: ["$items.price", "$items.qty"] } } } },
      { $sort: { revenue: -1, _id: 1 } },
      { $project: { _id: 0, productId: "$_id", name: 1, units: 1, revenue: 1 } },
    ])
    .toArray();
}
⚠️ טעויות נפוצות
  • $match אחרי $group — כבר אין status.
  • $lookup ל־products כדי לקחת מחיר — המחיר של היום, לא של ההזמנה.

P25.7-E15 · הלקוחות המובילים 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.7-E15
import type { Db } from "mongodb";

export async function topCustomers(db: Db, n = 3) {
  return db
    .collection("orders")
    .aggregate([
      { $match: { status: { $ne: "cancelled" } } },
      { $group: { _id: "$customerId", spent: { $sum: "$total" }, orders: { $sum: 1 } } },
      { $sort: { spent: -1, _id: 1 } },
      { $limit: n }, // לפני ה־$lookup: מצטרפים רק ל־n לקוחות, לא לכולם
      { $lookup: { from: "customers", localField: "_id", foreignField: "_id", as: "customer" } },
      { $unwind: "$customer" },
      { $project: { _id: 0, customerId: "$_id", name: "$customer.name", spent: 1, orders: 1 } },
    ])
    .toArray();
}
⚠️ טעויות נפוצות
  • $lookup לפני ה־$group — מצרפים את הלקוח לכל הזמנה, ואז מקבצים.
  • name: "$customer.name" בלי $unwind — מקבלים מערך של שם אחד.

P25.7-E16 · דירוגים עם תקציר 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.7-E16
import type { Db } from "mongodb";

interface Review {
  by: string;
  rating: number;
}
interface Product {
  _id: string;
  reviews: Review[];
  ratingCount: number;
  ratingSum: number;
}

export async function addReview(db: Db, productId: string, { by, rating }: { by: string; rating: number }) {
  if (!Number.isInteger(rating) || rating < 1 || rating > 5) throw new RangeError("rating: 1 עד 5");
  // פקודה אחת: התנאי "הלקוח עוד לא דירג", הוספת הדירוג, ועדכון הסיכום — הכול אטומי על המסמך.
  // כך הממוצע (ratingSum / ratingCount) תמיד תואם למערך, גם בשתי בקשות במקביל
  const r = await db.collection<Product>("products").updateOne(
    { _id: productId, "reviews.by": { $ne: by } },
    { $push: { reviews: { by, rating } }, $inc: { ratingCount: 1, ratingSum: rating } }
  );
  return r.modifiedCount === 1;
}

  const p = await db.collection<Product>("products").findOne({ _id: productId }, { projection: { ratingCount: 1, ratingSum: 1 } });
  if (!p) return null;
  return p.ratingCount === 0 ? 0 : Math.round((p.ratingSum / p.ratingCount) * 10) / 10;
}

  • $push בפקודה אחת ו־$inc בשנייה — בין שתיהן, התקציר לא תואם, ושגיאה באמצע משאירה אותו שגוי לתמיד.

P25.7-E17 · הזמנה בטרנזקציה 🤖 רמה 3

💡 רמז 1

client.startSession() ו־session.withTransaction(async () => …). endSession ב־finally.

💡 רמז 2

findOneAndUpdate עם התנאי מ־E13 ו־{ session, returnDocument: "after" } — מחזיר את name ו־price. null ← זורקים, ו־withTransaction מבטל.

✅ פתרון
// P25.7-E17
import type { Db, MongoClient } from "mongodb";

interface Product {
  _id: string;
  name: string;
  price: number;
  stock: number;
}

export class OutOfStockError extends Error {}

// הזמנה = הורדת מלאי בכמה מוצרים + מסמך הזמנה. או הכול, או כלום — טרנזקציה
export async function placeOrder(client: MongoClient, db: Db, customerId: string, cart: { productId: string; qty: number }[]) {
  if (!cart.length) throw new RangeError("עגלה ריקה");
  const session = client.startSession();
  try {
    return await session.withTransaction(async () => {
      const items = [];
      for (const { productId, qty } of cart) {
        // כל פעולה בתוך הטרנזקציה — עם { session }. בלי זה היא רצה מחוץ לטרנזקציה ולא מתבטלת
        const p = await db.collection<Product>("products").findOneAndUpdate(
          { _id: productId, stock: { $gte: qty } },
          { $inc: { stock: -qty } },
          { session, returnDocument: "after", projection: { name: 1, price: 1 } }
        );
        if (!p) throw new OutOfStockError(`אין מספיק ${productId}`); // זריקה ← withTransaction מבטל הכול
        items.push({ productId, name: p.name, price: p.price, qty }); // מחיר מהמסד, לא מהלקוח
      }
      const order = { customerId, status: "pending", createdAt: new Date(), items, total: items.reduce((s, i) => s + i.price * i.qty, 0) };
      const { insertedId } = await db.collection("orders").insertOne(order, { session });
      return { _id: insertedId, ...order };
    });
  } finally {
    await session.endSession();
  }
}
⚠️ טעויות נפוצות
  • לשכוח { session } בפעולה אחת — היא לא מתבטלת.
  • לקחת price מהעגלה — הלקוח קובע מחיר.
  • לתפוס את השגיאה בתוך ה־callback ולהחזיר null — withTransaction חושב שהכול הצליח ועושה commit.

P25.7-E19 · router של פתקים עם ObjectId 🤖 רמה 3

✅ פתרון
// P25.7-E19
import express from "express";
import { ObjectId, type Db } from "mongodb";

export function notesRouter(db: Db) {
  const notes = db.collection("notes");
  const router = express.Router();

  router.post("/", async (req, res) => {
    const text = req.body?.text;
    if (typeof text !== "string" || !text.trim()) return res.status(400).json({ error: "text חובה" });
    const { insertedId } = await notes.insertOne({ text: text.trim(), createdAt: new Date() });
    res.status(201).json({ id: insertedId.toHexString() }); // ללקוח — מחרוזת, לא אובייקט
  });

  router.get("/:id", async (req, res) => {
    // "abc" זה לא ObjectId: new ObjectId("abc") זורק. 400 — לא 500, ולא 404
    if (!ObjectId.isValid(req.params.id) || req.params.id.length !== 24) return res.status(400).json({ error: "מזהה לא תקין" });
    const note = await notes.findOne({ _id: new ObjectId(req.params.id) });
    if (!note) return res.status(404).json({ error: "לא נמצא" });
    res.json({ id: note._id.toHexString(), text: note.text, createdAt: note.createdAt.toISOString() });
  });

  return router;
}
⚠️ טעויות נפוצות
  • findOne({ _id: req.params.id }) — מחפש מחרוזת, ולא מוצא אף פעם.
  • new ObjectId("abc") בלי בדיקה — זורק, ו־Express מחזיר 500.

P25.7-E20 · חיפוש עם שלוש תקלות 🤖 רמה 4

💡 רמז 1

נסה: { category: { $ne: "merch" } }, { q: "(" }, ו־{} על קטלוג של 30 מוצרים.

💡 רמז 2

escaping ל־regex: s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&").

✅ פתרון
// P25.7-E20
import type { Db } from "mongodb";

const escapeRegex = (s: string) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

// חיפוש מוצרים לפי ה־query string: ?q=&category=
export async function searchProducts(db: Db, query: Record<string, unknown>) {
  const filter: Record<string, unknown> = {};
  // תקלה 1: ב־Express, ?category[$ne]=x הופך לאובייקט { $ne: "x" } — NoSQL injection. רק מחרוזות
  for (const k of ["q", "category"]) {
    if (query[k] !== undefined && typeof query[k] !== "string") throw new RangeError(`${k} חייב להיות מחרוזת`);
  }
  if (query.category) filter.category = query.category;
  if (typeof query.q === "string" && query.q.trim()) {
    // תקלה 2: הטקסט של המשתמש הוא טקסט, לא regex: "(" שובר, ו־".*" מחזיר הכול
    filter.name = { $regex: escapeRegex(query.q.trim()), $options: "i" };
  }
  // תקלה 3: בלי limit — "חיפוש ריק" מחזיר את כל הקטלוג
  return db.collection("products").find(filter, { projection: { name: 1, price: 1 } }).sort({ name: 1 }).limit(20).toArray();
}
⚠️ טעויות נפוצות
  • להמיר ל־String(query.category) — "[object Object]" לא מסוכן, אבל מסתיר באג אצל הלקוח. עדיף 400.

P25.7-E21 · עדכון פרופיל עם שלוש תקלות 🤖 רמה 4

💡 רמז 1

מה קורה ל־email אחרי replaceOne(..., { name: "x" })? ומה קורה עם { role: "admin" }?

💡 רמז 2

והשורה השנייה: האם העדכון כבר קרה כשה־findOne רץ? (שים לב גם ל־as unknown as Customer — מישהו השתיק את TypeScript, והוא צדק.)

✅ פתרון
// P25.7-E21
import type { Db } from "mongodb";

interface Customer {
  _id: string;
  name: string;
  email: string;
  city: string;
  createdAt: Date;
}

const EDITABLE = ["name", "city"] as const;

// PATCH /me: הלקוח מעדכן את הפרופיל שלו
export async function updateProfile(db: Db, customerId: string, body: Record<string, unknown>) {
  // תקלה 2: רק שדות מותרים. אחרת { role: "admin" } או { email } נכנסים כמו שהם (mass assignment)
  const $set: Record<string, string> = {};
  for (const k of EDITABLE) if (typeof body[k] === "string") $set[k] = (body[k] as string).trim();
  if (Object.keys($set).length === 0) throw new RangeError("אין מה לעדכן");
  // תקלה 1: $set ולא replaceOne — replaceOne מחליף את כל המסמך, והאימייל ותאריך ההרשמה נמחקים
  // תקלה 3: await — אחרת מחזירים לפני שהעדכון קרה, ושגיאה הולכת לאיבוד
  const doc = await db.collection<Customer>("customers").findOneAndUpdate({ _id: customerId }, { $set }, { returnDocument: "after" });
  return doc;
}
⚠️ טעויות נפוצות
  • לתקן ל־$set: body — ה־email לא נמחק, אבל עכשיו כל אחד יכול לשנות אותו (ולהוסיף role).

P25.7-E22 · aggregation עם שלוש תקלות 🤖 רמה 4

💡 רמז 1

הרץ את ה־pipeline שלב אחרי שלב (מחק את השלבים מהסוף) ותסתכל על המסמכים.

💡 רמז 2

אחרי $group יש רק _id והשדות שהגדרת. ו־{ $sum: 1 } סופר מסמכים, לא יחידות.

✅ פתרון
// P25.7-E22
import type { Db } from "mongodb";

// כמה יחידות נמכרו מכל קטגוריה (הזמנות ששולמו או נמסרו)
export async function unitsByCategory(db: Db) {
  return db
    .collection("orders")
    .aggregate([
      { $match: { status: { $in: ["paid", "delivered"] } } }, // תקלה 1: לסנן לפני ה־$group — אחריו כבר אין status
      { $unwind: "$items" }, // תקלה 2: בלי $unwind, "$items.qty" הוא מערך, ו־$sum של מערך הוא 0
      { $lookup: { from: "products", localField: "items.productId", foreignField: "_id", as: "product" } },
      { $unwind: "$product" },
      { $group: { _id: "$product.category", units: { $sum: "$items.qty" } } }, // תקלה 3: qty, לא 1 (1 סופר שורות)
      { $sort: { units: -1, _id: 1 } },
      { $project: { _id: 0, category: "$_id", units: 1 } },
    ])
    .toArray();
}
⚠️ טעויות נפוצות
  • להוסיף status: { $first: "$status" } ל־$group ולסנן אחריו — מסנן לפי הסטטוס של הזמנה אחת בכל קבוצה.

P25.7-E23 · ביטול הזמנה עם שלוש תקלות 🤖 רמה 4

💡 רמז 1

שני ביטולים של אותה הזמנה במקביל: כמה פעמים חוזר המלאי? ואם עדכון המלאי של הפריט השני נכשל — מה קורה לראשון?

💡 רמז 2

ובלי קשר לכל זה: הזמנה של 1 יחידה, מלאי 5 — כמה במלאי אחרי הביטול?

✅ פתרון
// P25.7-E23
import type { Db, MongoClient } from "mongodb";

interface Order {
  _id: string;
  status: string;
  items: { productId: string; qty: number }[];
}
interface Product {
  _id: string;
  stock: number;
}

// ביטול הזמנה: מחזירים את הכמויות למלאי ומסמנים cancelled — באותה טרנזקציה
export async function cancelOrder(client: MongoClient, db: Db, orderId: string) {
  const session = client.startSession();
  try {
    return await session.withTransaction(async () => {
      // תקלה 1: התנאי על הסטטוס בתוך העדכון — כך שני ביטולים במקביל לא יחזירו מלאי פעמיים
      const order = await db.collection<Order>("orders").findOneAndUpdate(
        { _id: orderId, status: { $in: ["pending", "paid"] } },
        { $set: { status: "cancelled", cancelledAt: new Date() } },
        { session }
      );
      if (!order) return false;
      for (const it of order.items) {
        // תקלה 2: { session } — אחרת ההחזרה למלאי לא חלק מהטרנזקציה
        // תקלה 3: $inc ולא $set: מחזירים את הכמות, לא דורסים את המלאי
        await db.collection<Product>("products").updateOne({ _id: it.productId }, { $inc: { stock: it.qty } }, { session });
      }
      return true;
    });
  } finally {
    await session.endSession();
  }
}
⚠️ טעויות נפוצות
  • להעביר את ה־findOne לתוך הטרנזקציה בלי לשנות אותו — שתי טרנזקציות עדיין יכולות לקרוא "paid" (snapshot). התנאי צריך להיות בעדכון עצמו.

P25.7-E24 · אתגר: דשבורד בבקשה אחת 🤖 רמה 5

💡 רמז 1

$facet: { byDay: [...], byStatus: [...], topProducts: [...] } — שלושה pipelines על אותם מסמכים.

💡 רמז 2

$dateToString: { date: "$createdAt", format: "%Y-%m-%d", timezone: "Asia/Jerusalem" }. ו־byStatus — המרה לאובייקט ב־JS אחרי השאילתה.

✅ פתרון
// P25.7-E24
import type { Db } from "mongodb";

// דשבורד של טווח תאריכים — בבקשה אחת: הכנסות לפי יום (בשעון ישראל), ספירה לפי סטטוס, ו־3 המוצרים המובילים
export async function dashboard(db: Db, from: Date, to: Date) {
  const [result] = await db
    .collection("orders")
    .aggregate([
      { $match: { createdAt: { $gte: from, $lt: to } } },
      {
        $facet: {
          byDay: [
            { $match: { status: { $ne: "cancelled" } } },
            // היום לפי ישראל, לא לפי UTC: הזמנה ב־22:10Z ב־1.11 היא 2.11 בישראל (פרק 24)
            { $group: { _id: { $dateToString: { date: "$createdAt", format: "%Y-%m-%d", timezone: "Asia/Jerusalem" } }, revenue: { $sum: "$total" }, orders: { $sum: 1 } } },
            { $sort: { _id: 1 } },
            { $project: { _id: 0, day: "$_id", revenue: 1, orders: 1 } },
          ],
          byStatus: [{ $group: { _id: "$status", n: { $sum: 1 } } }, { $sort: { _id: 1 } }],
          topProducts: [
            { $match: { status: { $ne: "cancelled" } } },
            { $unwind: "$items" },
            { $group: { _id: "$items.productId", units: { $sum: "$items.qty" } } },
            { $sort: { units: -1, _id: 1 } },
            { $limit: 3 },
            { $project: { _id: 0, productId: "$_id", units: 1 } },
          ],
        },
      },
    ])
    .toArray();
  return {
    byDay: result.byDay,
    byStatus: Object.fromEntries(result.byStatus.map((s: { _id: string; n: number }) => [s._id, s.n])),
    topProducts: result.topProducts,
  };
}
⚠️ טעויות נפוצות
  • קיבוץ לפי יום ב־UTC — o6 (21:55Z ב־21.10) נספרת ב־21.10, אבל בישראל זה כבר 22.10.
  • שלוש שאילתות נפרדות — עובד, אבל שלוש סריקות של אותו טווח.

P25.7-E25 · אתגר: מעבר מ־PostgreSQL 🤖 רמה 5

💡 רמז 1

שאילתה אחת עם json_agg(json_build_object(...) ORDER BY i.id) ו־GROUP BY o.id — הזמנה לשורה, עם הפריטים כמערך.

💡 רמז 2

idempotent: replaceOne({ _id }, doc, { upsert: true }), וכולם ב־bulkWrite אחד.

✅ פתרון
// P25.7-E25
import type { Db } from "mongodb";
import type pg from "pg";

// מעבר מ־PostgreSQL ל־MongoDB: הזמנה + השורות שלה (order_items) ← מסמך אחד עם מערך items.
// אפשר להריץ שוב ושוב (idempotent): upsert לפי ה־id המקורי
export async function migrateOrders(pool: pg.Pool, db: Db) {
  const { rows } = await pool.query(`
    SELECT o.id, o.customer_id, o.status, o.created_at,
           json_agg(json_build_object('productId', i.product_id, 'name', p.name, 'price', i.unit_price, 'qty', i.quantity) ORDER BY i.id) AS items
    FROM orders o
    JOIN order_items i ON i.order_id = o.id
    JOIN products p ON p.id = i.product_id
    GROUP BY o.id
    ORDER BY o.id`);
  if (rows.length === 0) return { migrated: 0 };
  const ops = rows.map((r) => {
    const items = r.items.map((i: { productId: number; name: string; price: string | number; qty: number }) => ({ productId: `p${i.productId}`, name: i.name, price: Number(i.price), qty: i.qty }));
    const doc = {
      customerId: `c${r.customer_id}`,
      status: r.status,
      createdAt: r.created_at, // timestamptz ← Date (pg ממיר לבד) ← BSON Date
      items,
      total: Math.round(items.reduce((s: number, i: { price: number; qty: number }) => s + i.price * i.qty, 0) * 100) / 100,
    };
    return { replaceOne: { filter: { _id: `o${r.id}` }, replacement: doc, upsert: true } } as const;
  });
  // bulkWrite: פקודה אחת לשרת במקום אלף
  await db.collection<{ _id: string }>("orders").bulkWrite(ops, { ordered: false });
  return { migrated: rows.length };
}
⚠️ טעויות נפוצות
  • insertMany — הרצה שנייה נכשלת על _id כפול (או, בלי _id קבוע — כפילויות).
  • numeric מ־pg מגיע כמחרוזת ("60.50") — בלי Number() נשמר מחרוזת, ו־$sum מתעלם ממנה.
  • שאילתה לכל הזמנה בלולאה (N+1, פרק 18).
