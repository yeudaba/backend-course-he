⏱ ~45 דקות

🎯 בשיעור הזה
  • מה זה מסמך, ואיך הזמנה נראית ב־Mongo מול שלוש טבלאות ב־PostgreSQL.
  • database, collection, מסמך — ו־_id.
  • BSON: הטיפוסים ש־JSON לא מכיר, ו־ObjectId.
  • הפעולות הראשונות מ־Node.js: insertOne, find, findOne, projection.
  • "בלי schema" — מה זה אומר באמת.

1. הזמנה אחת, שתי צורות

ב־PostgreSQL (פרק 17) הזמנה היא שורה ב־orders, ועוד שורה ב־order_items לכל פריט, ו־JOIN שמחבר אותן. ב־MongoDB הזמנה היא מסמך אחד — אובייקט, בדיוק כמו ב־JavaScript, שהפריטים הם מערך בתוכו:

המונחים: database (כמו ב־Postgres) מכיל collections (בערך "טבלאות"), ו־collection מכיל מסמכים (בערך "שורות"). אבל שני הבדלים חשובים: מסמך יכול להכיל מערכים ומסמכים מקוננים — ו־collection לא מחייב שכל המסמכים ייראו אותו דבר.

2. מסמך ראשון מ־Node.js

ה־driver הרשמי הוא החבילה mongodb. MongoClient אחד לכל התהליך (הוא מחזיק pool של חיבורים, כמו pg.Pool בפרק 18):

import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGO_URL ?? "mongodb://localhost:27017/?directConnection=true");
const db = client.db("lesson1"); // database שלא קיים — נוצר בכתיבה הראשונה
const products = db.collection("products"); // כנ"ל: collection נוצר לבד

const result = await products.insertOne({ name: "Ethiopia Yirgacheffe", price: 62, tags: ["light", "single-origin"] });
console.log(result.acknowledged, typeof result.insertedId, result.insertedId.constructor.name);

const doc = await products.findOne({ name: "Ethiopia Yirgacheffe" });
console.log(Object.keys(doc!));
console.log(doc!.tags[0], doc!._id.equals(result.insertedId));

await db.dropDatabase();
await client.close();
true object ObjectId
[ '_id', 'name', 'price', 'tags' ]
light true

לא נתנו _id, ולכן ה־driver יצר אחד: ObjectId. לכל מסמך חייב להיות _id ייחודי ב־collection — זה המפתח הראשי, ויש עליו אינדקס תמיד. אפשר לתת _id משלך (מחרוזת, מספר) — בנתוני הדוגמה של היחידה עשינו "p1", "c1", "o1" כדי שיהיה קל לקרוא.

3. BSON ו־ObjectId

Mongo שומר מסמכים ב־BSON — JSON בינארי, עם טיפוסים ש־JSON לא מכיר. שלושה שחשוב להכיר:

  • Date — רגע בזמן (כמו timestamptz, פרק 24). שומרים new Date(), לא מחרוזת: על מחרוזת "2026-11-09" אי אפשר לעשות $gte נכון בין אזורי זמן, ולא לקבץ לפי יום.
  • מספרים — ה־driver שומר מספר שלם כ־Int32 (או Int64 אם גדול), ושבר כ־Double. לכסף מדויק יש Decimal128; ביחידה נשמור מחירים בשקלים שלמים, כמו בחנות הקפה.
  • ObjectId — 12 בתים, שמוצגים כ־24 תווי hex. 4 הבתים הראשונים הם זמן היצירה, ולכן מזהים חדשים "עולים" בערך לפי סדר היצירה:
import { ObjectId } from "mongodb";

const id = new ObjectId("6af1a8c0e4b0f1a2b3c4d5e6");
console.log(id.toHexString().length);
console.log(id.getTimestamp().toISOString()); // מתוך 4 הבתים הראשונים

console.log(ObjectId.isValid("6af1a8c0e4b0f1a2b3c4d5e6"), ObjectId.isValid("abc"));
console.log(id.equals("6af1a8c0e4b0f1a2b3c4d5e6"), id === new ObjectId("6af1a8c0e4b0f1a2b3c4d5e6"));

true false

השורה האחרונה היא מלכודת קלאסית: שני ObjectId הם אובייקטים, ו־=== משווה הפניות. משווים עם .equals(), או משווים מחרוזות (toHexString()). ומזהה שמגיע מ־URL (/notes/:id) הוא מחרוזת — צריך לבדוק שהוא תקין ולהמיר (new ObjectId(id)), אחרת findOne({ _id: "6af1…" }) מחפש מחרוזת ולא מוצא כלום (E19).

4. find, findOne ו־projection

שאילתה ב־Mongo היא אובייקט: "מסמכים שבהם השדות האלה שווים לערכים האלה". find מחזיר cursor — כמו iterator — ו־toArray() אוסף אותו. projection בוחר שדות (כמו הרשימה אחרי SELECT):

import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGO_URL ?? "mongodb://localhost:27017/?directConnection=true");
const products = client.db("lesson1b").collection("products");
await products.insertMany([
  { _id: "p1", name: "Ethiopia Yirgacheffe", category: "beans", price: 62, specs: { roast: "light" } },
  { _id: "p3", name: "House Espresso Blend", category: "beans", price: 48, specs: { roast: "dark" } },
  { _id: "p5", name: "V60 Dripper", category: "gear", price: 89 },
]);

// SELECT name, price FROM products WHERE category = 'beans' ORDER BY price
console.log(await products.find({ category: "beans" }, { projection: { _id: 0, name: 1, price: 1 } }).sort({ price: 1 }).toArray());
// שדה מקונן — בנקודה, ובמרכאות
console.log(await products.findOne({ "specs.roast": "dark" }, { projection: { name: 1 } }));
// שדה שלא קיים במסמך — פשוט לא מתאים
console.log(await products.countDocuments({ "specs.roast": { $exists: true } }));

await client.db("lesson1b").dropDatabase();
await client.close();
[
  { name: 'House Espresso Blend', price: 48 },
  { name: 'Ethiopia Yirgacheffe', price: 62 }
]
{ _id: 'p3', name: 'House Espresso Blend' }

שימו לב ל־V60 Dripper: אין לו specs בכלל — ו־Mongo לא מתלונן. זה ה"בלי schema".

5. "בלי schema" — schema שגרה בקוד

Mongo לא מכריח את כל המסמכים להיראות אותו דבר. זה נוח כשמבנה משתנה (מוצרים עם מאפיינים שונים: לפולים יש "קלייה", למטחנה "חומר"), ומסוכן כשזה קורה בטעות: { prise: 62 } במקום price נשמר בשקט, ו־"62" כמחרוזת לא יימצא ב־price: { $lt: 100 }. ה־schema לא נעלם — הוא עבר לקוד שלך. לכן בפרויקט אמיתי:

  • ולידציה בכניסה — Zod (פרק 15) לפני כל כתיבה, בדיוק כמו עם Postgres.
  • טיפוסים — db.collection<Product>("products"), ו־TypeScript בודק שאילתות ועדכונים (שיעור 5).
  • schema validation בשרת — כללי $jsonSchema שה־Mongo עצמו אוכף (שיעור 3, E18).
💡 mongosh

ה־shell של Mongo: docker exec -it mongo mongosh, ואז use shop, db.products.find({ category: "gear" }), db.orders.countDocuments(). התחביר כמעט זהה ל־driver (בלי await ו־toArray). טוב לבדיקות מהירות; הקוד שלך — ב־Node.
