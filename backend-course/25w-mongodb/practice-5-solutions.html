P25.7-E86 · ‏MongoClient לכל בקשה 🧠 הבנה רמה 1

💡 רמז 1

‏MongoClient הוא pool. כל אחד פותח חיבורים משלו.

💡 רמז 2

‏client.close()?

✅ פתרון
  1. כל בקשה פותחת חיבור חדש (TCP + אימות — עשרות מילישניות), וב־Mongo מספר החיבורים מטפס לאלפים, עד המגבלה. איטי, ובסוף נופל.
  2. אין close() — החיבורים נשארים פתוחים לעד: דליפה. גם אם היה close — עדיין חיבור לכל בקשה.
  3. לקוח אחד בעלייה (‏src/db.ts), שכל הבקשות משתמשות בו; ‏client.close() פעם אחת בכיבוי מסודר, אחרי שהשרת הפסיק לקבל בקשות (פרק 24, E95).
⚠️ טעויות נפוצות
  • "זה עובד בפיתוח" — עם בקשה בכל כמה שניות, הדליפה לא מורגשת.

P25.7-E87 · ‏ObjectId ב־URL: ‏400, ‏404 או 500? 🧠 הבנה רמה 2

💡 רמז 1

‏new ObjectId("abc") זורק.

💡 רמז 2

‏ObjectId.isValid מקבל גם מחרוזת של 12 תווים כלשהם (12 "בתים").

✅ פתרון
  1. 200.
  2. 404.
  3. 400. בקוד נאיבי — new ObjectId זורק ← 500, ובלוג נראה כמו תקלה בשרת.
  4. מזהה hex תקין — אותו ObjectId. ‏200 (ב־API אפשר לנרמל לאותיות קטנות בתשובה).
  5. ‏ObjectId.isValid("123456789012") הוא true (12 תווים = 12 בתים)! והתוצאה ObjectId אחר לגמרי ← 404. לכן בודקים ב־API ‏/^[0-9a-f]{24}$/i (‏P25.7-E19).
⚠️ טעויות נפוצות
  • לסמוך על ObjectId.isValid בלבד.

P25.7-E88 · ‏NoSQL injection — מה מגיע ב־req.body? 🧠 הבנה רמה 2

💡 רמז 1

‏JSON יכול להכיל אובייקט בכל מקום שציפית למחרוזת.

💡 רמז 2

Express (עם הגדרות מסוימות של parser) הופך a[b]=c לאובייקט.

✅ פתרון
  1. כניסה רגילה (נכשלת על סיסמה שגויה).
  2. "סיסמה שאינה null" — מתאים לכל משתמש עם סיסמה: נכנסים לחשבון של דנה בלי סיסמה.
  3. המשתמש הראשון שהאימייל שלו מתחיל ב־a.
  4. תלוי ב־query parser: עם "extended" (‏qs) — { $ne: "x" }; ב־Express 5 ברירת המחדל "simple" — מחרוזת. לא סומכים על זה.

ההגנה: לוודא טיפוס — z.string() לכל שדה שמגיע לשאילתה (E92). הסרת $ חלקית: יש גם אופרטורים בתוך מבנים מקוננים, ושדות עם נקודה; וגם אם לא נשאר אופרטור — אובייקט במקום מחרוזת הוא באג. ובכלל: סיסמאות — רק hash והשוואה בקוד (פרק 21, E98).

⚠️ טעויות נפוצות
  • "יש לי TypeScript, אז email הוא string" — הטיפוס בקוד לא אומר כלום על מה שהגיע ברשת.

P25.7-E89 · פעולה בלי session — בתוך טרנזקציה 🧠 הבנה רמה 2

💡 רמז 1

איזו פעולה לא קיבלה { session }?

💡 רמז 2

בבדיקה "מוצלחת" — שום דבר לא מתבטל.

✅ פתרון
  1. ההזמנה בוטלה (היא עם session). ה־updateOne של p1 רץ מחוץ לטרנזקציה — הוא כבר מחויב: המלאי ירד ב־2, להזמנה שלא קיימת.
  2. products.updateOne(filter, update, { session }) — כל פעולה בתוך הטרנזקציה מקבלת את ה־session.
  3. במסלול המוצלח הכול נכתב, והתוצאה נכונה. הבאג מופיע רק כשמשהו נכשל באמצע — צריך בדיקה שמכשילה בכוונה פריט שני ובודקת שהמלאי של הראשון לא זז (‏P25.7-E17, ‏E93).
⚠️ טעויות נפוצות
  • להעביר את ה־session רק ל־insert "כי זה העיקר" — הטרנזקציה מגינה רק על מה שעבר דרכה.

P25.7-E90 · ‏withTransaction מנסה שוב — ומה עם המייל? 🧠 הבנה רמה 3

💡 רמז 1

‏withTransaction מריץ את כל ה־callback שוב.

💡 רמז 2

מייל הוא "תופעת לוואי" שאי אפשר לבטל.

✅ פתרון
  1. ה־driver עושה abort ומריץ את ה־callback מההתחלה.
  2. אחד לכל ניסיון — שניים, שלושה.
  3. הלקוח קיבל "ההזמנה התקבלה", וההזמנה לא קיימת.
  4. אחרי ש־withTransaction הסתיים בהצלחה. ועוד יותר טוב: רושמים "לשלוח מייל" (outbox) בתוך הטרנזקציה, ותהליך נפרד שולח (פרק 26) — כך גם קריסה מיד אחרי ה־commit לא מפסידה את המייל.
⚠️ טעויות נפוצות
  • קריאות לשירותים חיצוניים (תשלום, מייל, webhook) בתוך טרנזקציה — גם ב־Postgres: מחזיקות נעילות, ולא מתבטלות.

P25.7-E91 · ‏Mongo או Postgres — לכל מקרה 🧠 הבנה רמה 2

💡 רמז 1

כמה קשרים יש, וכמה חשובה שלמות בין ישויות?

💡 רמז 2

jsonb קיים.

✅ פתרון
  1. Postgres — קשרים, טרנזקציות על הרבה רשומות, אילוצים (סכומים שחייבים להתאזן).
  2. שניהם: Mongo טבעי (מסמך למוצר); Postgres עם jsonb למאפיינים — גם מצוין, אם השאר (הזמנות, משתמשים) רלציוני.
  3. Mongo מתאים מאוד: מסמך שנקרא ונכתב בשלמותו, מבנה גמיש. (Postgres יעבוד גם.)
  4. Postgres — הרבה קשרים, ואילוצים כמו "אין שני תורים לאותו חדר באותה שעה" (‏exclusion constraint).
  5. Mongo (או מסד ייעודי לסדרות זמן) — כתיבות רבות של מבנים שונים, בלי קשרים.
⚠️ טעויות נפוצות
  • לענות בראיון "Mongo כי הוא מהיר" — מהירות תלויה במבנה ובאינדקסים, לא במותג.

P25.7-E17 · הזמנה בטרנזקציה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

client.startSession() ו־session.withTransaction(async () => …). endSession ב־finally.

💡 רמז 2

findOneAndUpdate עם התנאי מ־E13 ו־{ session, returnDocument: "after" } — מחזיר את name ו־price. null ← זורקים, ו־withTransaction מבטל.

✅ פתרון
// P25.7-E17
import type { Db, MongoClient } from "mongodb";

interface Product {
  _id: string;
  name: string;
  price: number;
  stock: number;
}

export class OutOfStockError extends Error {}

// הזמנה = הורדת מלאי בכמה מוצרים + מסמך הזמנה. או הכול, או כלום — טרנזקציה
export async function placeOrder(client: MongoClient, db: Db, customerId: string, cart: { productId: string; qty: number }[]) {
  if (!cart.length) throw new RangeError("עגלה ריקה");
  const session = client.startSession();
  try {
    return await session.withTransaction(async () => {
      const items = [];
      for (const { productId, qty } of cart) {
        // כל פעולה בתוך הטרנזקציה — עם { session }. בלי זה היא רצה מחוץ לטרנזקציה ולא מתבטלת
        const p = await db.collection<Product>("products").findOneAndUpdate(
          { _id: productId, stock: { $gte: qty } },
          { $inc: { stock: -qty } },
          { session, returnDocument: "after", projection: { name: 1, price: 1 } }
        );
        if (!p) throw new OutOfStockError(`אין מספיק ${productId}`); // זריקה ← withTransaction מבטל הכול
        items.push({ productId, name: p.name, price: p.price, qty }); // מחיר מהמסד, לא מהלקוח
      }
      const order = { customerId, status: "pending", createdAt: new Date(), items, total: items.reduce((s, i) => s + i.price * i.qty, 0) };
      const { insertedId } = await db.collection("orders").insertOne(order, { session });
      return { _id: insertedId, ...order };
    });
  } finally {
    await session.endSession();
  }
}
⚠️ טעויות נפוצות
  • לשכוח { session } בפעולה אחת — היא לא מתבטלת.
  • לקחת price מהעגלה — הלקוח קובע מחיר.
  • לתפוס את השגיאה בתוך ה־callback ולהחזיר null — withTransaction חושב שהכול הצליח ועושה commit.

P25.7-E19 · router של פתקים עם ObjectId 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

insertedId.toHexString(), ו־new ObjectId(req.params.id) לחיפוש.

💡 רמז 2

ObjectId.isValid("aaaaaaaaaaaa") — true (12 תווים = 12 בתים). בדוק גם אורך 24.

✅ פתרון
// P25.7-E19
import express from "express";
import { ObjectId, type Db } from "mongodb";

export function notesRouter(db: Db) {
  const notes = db.collection("notes");
  const router = express.Router();

  router.post("/", async (req, res) => {
    const text = req.body?.text;
    if (typeof text !== "string" || !text.trim()) return res.status(400).json({ error: "text חובה" });
    const { insertedId } = await notes.insertOne({ text: text.trim(), createdAt: new Date() });
    res.status(201).json({ id: insertedId.toHexString() }); // ללקוח — מחרוזת, לא אובייקט
  });

  router.get("/:id", async (req, res) => {
    // "abc" זה לא ObjectId: new ObjectId("abc") זורק. 400 — לא 500, ולא 404
    if (!ObjectId.isValid(req.params.id) || req.params.id.length !== 24) return res.status(400).json({ error: "מזהה לא תקין" });
    const note = await notes.findOne({ _id: new ObjectId(req.params.id) });
    if (!note) return res.status(404).json({ error: "לא נמצא" });
    res.json({ id: note._id.toHexString(), text: note.text, createdAt: note.createdAt.toISOString() });
  });

  return router;
}
⚠️ טעויות נפוצות
  • findOne({ _id: req.params.id }) — מחפש מחרוזת, ולא מוצא אף פעם.
  • new ObjectId("abc") בלי בדיקה — זורק, ו־Express מחזיר 500.

P25.7-E20 · חיפוש עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

נסה: { category: { $ne: "merch" } }, { q: "(" }, ו־{} על קטלוג של 30 מוצרים.

💡 רמז 2

escaping ל־regex: s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&").

✅ פתרון
// P25.7-E20
import type { Db } from "mongodb";

const escapeRegex = (s: string) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

// חיפוש מוצרים לפי ה־query string: ?q=&category=
export async function searchProducts(db: Db, query: Record<string, unknown>) {
  const filter: Record<string, unknown> = {};
  // תקלה 1: ב־Express, ?category[$ne]=x הופך לאובייקט { $ne: "x" } — NoSQL injection. רק מחרוזות
  for (const k of ["q", "category"]) {
    if (query[k] !== undefined && typeof query[k] !== "string") throw new RangeError(`${k} חייב להיות מחרוזת`);
  }
  if (query.category) filter.category = query.category;
  if (typeof query.q === "string" && query.q.trim()) {
    // תקלה 2: הטקסט של המשתמש הוא טקסט, לא regex: "(" שובר, ו־".*" מחזיר הכול
    filter.name = { $regex: escapeRegex(query.q.trim()), $options: "i" };
  }
  // תקלה 3: בלי limit — "חיפוש ריק" מחזיר את כל הקטלוג
  return db.collection("products").find(filter, { projection: { name: 1, price: 1 } }).sort({ name: 1 }).limit(20).toArray();
}
⚠️ טעויות נפוצות
  • להמיר ל־String(query.category) — "[object Object]" לא מסוכן, אבל מסתיר באג אצל הלקוח. עדיף 400.

P25.7-E23 · ביטול הזמנה עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

שני ביטולים של אותה הזמנה במקביל: כמה פעמים חוזר המלאי? ואם עדכון המלאי של הפריט השני נכשל — מה קורה לראשון?

💡 רמז 2

ובלי קשר לכל זה: הזמנה של 1 יחידה, מלאי 5 — כמה במלאי אחרי הביטול?

✅ פתרון
// P25.7-E23
import type { Db, MongoClient } from "mongodb";

interface Order {
  _id: string;
  status: string;
  items: { productId: string; qty: number }[];
}
interface Product {
  _id: string;
  stock: number;
}

// ביטול הזמנה: מחזירים את הכמויות למלאי ומסמנים cancelled — באותה טרנזקציה
export async function cancelOrder(client: MongoClient, db: Db, orderId: string) {
  const session = client.startSession();
  try {
    return await session.withTransaction(async () => {
      // תקלה 1: התנאי על הסטטוס בתוך העדכון — כך שני ביטולים במקביל לא יחזירו מלאי פעמיים
      const order = await db.collection<Order>("orders").findOneAndUpdate(
        { _id: orderId, status: { $in: ["pending", "paid"] } },
        { $set: { status: "cancelled", cancelledAt: new Date() } },
        { session }
      );
      if (!order) return false;
      for (const it of order.items) {
        // תקלה 2: { session } — אחרת ההחזרה למלאי לא חלק מהטרנזקציה
        // תקלה 3: $inc ולא $set: מחזירים את הכמות, לא דורסים את המלאי
        await db.collection<Product>("products").updateOne({ _id: it.productId }, { $inc: { stock: it.qty } }, { session });
      }
      return true;
    });
  } finally {
    await session.endSession();
  }
}
⚠️ טעויות נפוצות
  • להעביר את ה־findOne לתוך הטרנזקציה בלי לשנות אותו — שתי טרנזקציות עדיין יכולות לקרוא "paid" (snapshot). התנאי צריך להיות בעדכון עצמו.

P25.7-E25 · אתגר: מעבר מ־PostgreSQL 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

שאילתה אחת עם json_agg(json_build_object(...) ORDER BY i.id) ו־GROUP BY o.id — הזמנה לשורה, עם הפריטים כמערך.

💡 רמז 2

idempotent: replaceOne({ _id }, doc, { upsert: true }), וכולם ב־bulkWrite אחד.

✅ פתרון
// P25.7-E25
import type { Db } from "mongodb";
import type pg from "pg";

// מעבר מ־PostgreSQL ל־MongoDB: הזמנה + השורות שלה (order_items) ← מסמך אחד עם מערך items.
// אפשר להריץ שוב ושוב (idempotent): upsert לפי ה־id המקורי
export async function migrateOrders(pool: pg.Pool, db: Db) {
  const { rows } = await pool.query(`
    SELECT o.id, o.customer_id, o.status, o.created_at,
           json_agg(json_build_object('productId', i.product_id, 'name', p.name, 'price', i.unit_price, 'qty', i.quantity) ORDER BY i.id) AS items
    FROM orders o
    JOIN order_items i ON i.order_id = o.id
    JOIN products p ON p.id = i.product_id
    GROUP BY o.id
    ORDER BY o.id`);
  if (rows.length === 0) return { migrated: 0 };
  const ops = rows.map((r) => {
    const items = r.items.map((i: { productId: number; name: string; price: string | number; qty: number }) => ({ productId: `p${i.productId}`, name: i.name, price: Number(i.price), qty: i.qty }));
    const doc = {
      customerId: `c${r.customer_id}`,
      status: r.status,
      createdAt: r.created_at, // timestamptz ← Date (pg ממיר לבד) ← BSON Date
      items,
      total: Math.round(items.reduce((s: number, i: { price: number; qty: number }) => s + i.price * i.qty, 0) * 100) / 100,
    };
    return { replaceOne: { filter: { _id: `o${r.id}` }, replacement: doc, upsert: true } } as const;
  });
  // bulkWrite: פקודה אחת לשרת במקום אלף
  await db.collection<{ _id: string }>("orders").bulkWrite(ops, { ordered: false });
  return { migrated: rows.length };
}
⚠️ טעויות נפוצות
  • insertMany — הרצה שנייה נכשלת על _id כפול (או, בלי _id קבוע — כפילויות).
  • numeric מ־pg מגיע כמחרוזת ("60.50") — בלי Number() נשמר מחרוזת, ו־$sum מתעלם ממנה.
  • שאילתה לכל הזמנה בלולאה (N+1, פרק 18).

P25.7-E92 · ‏login בלי NoSQL injection 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1
z.strictObject({ email: z.string().trim().toLowerCase(), password: z.string().min(1) })
💡 רמז 2

בשאילתה — רק ערך מה־data של zod, שכבר מחרוזת.

✅ פתרון
// P25.7-E92: login בלי NoSQL injection
import type { Db } from "mongodb";
import { z } from "zod";

const schema = z.strictObject({ email: z.string().trim().toLowerCase(), password: z.string().min(1) });

export async function findUserForLogin(db: Db, body: unknown) {
  const r = schema.safeParse(body);
  if (!r.success) throw new Error("VALIDATION_ERROR");
  const u = await db.collection<{ _id: string; email: string; passwordHash: string }>("users")
    .findOne({ email: r.data.email }, { projection: { email: 1, passwordHash: 1 } });
  return u ? { id: u._id, email: u.email, passwordHash: u.passwordHash } : null;
}
⚠️ טעויות נפוצות
  • findOne({ email: body.email }) "כי הסיסמה נבדקת אחר כך" — ‏{ "$ne": "" } מחזיר משתמש כלשהו, ואם בדיקת הסיסמה פגיעה במשהו — נכנסים.

P25.7-E93 · העברת מלאי בין מחסנים — בטרנזקציה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שדה דינמי: { [stock.${productId}]: { $gte: qty } } ו־$inc: { [stock.${productId}]: -qty }.

// P25.7-E93: העברת מלאי בין מחסנים — בטרנזקציה
import type { Db, MongoClient } from "mongodb";

export async function moveStock(client: MongoClient, db: Db, { from, to, productId, qty }: { from: string; to: string; productId: string; qty: number }) {
  if (!Number.isInteger(qty) || qty <= 0) throw new RangeError(`כמות לא תקינה: ${qty}`);
  const warehouses = db.collection<{ _id: string }>("warehouses");
  const field = `stock.${productId}`;
  const session = client.startSession();
  try {
    await session.withTransaction(async () => {
      const out = await warehouses.updateOne({ _id: from, [field]: { $gte: qty } }, { $inc: { [field]: -qty } }, { session });
      if (out.modifiedCount === 0) throw new Error("INSUFFICIENT_STOCK");
      const inn = await warehouses.updateOne({ _id: to }, { $inc: { [field]: qty } }, { session });
      if (inn.matchedCount === 0) throw new Error("NO_SUCH_WAREHOUSE"); // abort — גם ההורדה מתבטלת
    });
  } finally {
    await session.endSession();
  }
}

שני מסמכים — ולכן טרנזקציה. (אם המלאי היה במסמך אחד — ‏stock: { tlv: { p1: 10 } } — עדכון אחד היה אטומי בלי טרנזקציה. זה בדיוק השיקול של שיעור 3.)

⚠️ טעויות נפוצות
  • לשכוח { session } בעדכון השני — "מחסן לא קיים" מבטל את ההורדה, אבל עדכון שרץ בלי session כבר נכתב (E89).

// P25.7-E94: מחירון חדש — ב־bulkWrite אחד
import type { Db } from "mongodb";

export async function applyPriceList(db: Db, list: { productId: string; price: number }[]) {
  for (const { price } of list) if (!Number.isInteger(price) || price <= 0) throw new RangeError(`מחיר לא תקין: ${price}`);
  if (list.length === 0) return { matched: 0, modified: 0, missing: [] };
  const products = db.collection<{ _id: string; price: number }>("products");
  const ids = [...new Set(list.map((l) => l.productId))];
  const found = new Set((await products.find({ _id: { $in: ids } }, { projection: { _id: 1 } }).toArray()).map((p) => p._id));
  const r = await products.bulkWrite(list.map(({ productId, price }) => ({ updateOne: { filter: { _id: productId }, update: { $set: { price } } } })));
  return { matched: r.matchedCount, modified: r.modifiedCount, missing: ids.filter((id) => !found.has(id)).sort() };
}

‏bulkWrite שולח את כל הפעולות בבקשה אחת (או בכמה גדולות). ברירת המחדל ordered: true — עוצר בשגיאה הראשונה; ‏ordered: false — ממשיך ומדווח על כל השגיאות.

⚠️ טעויות נפוצות
  • Promise.all של מאות updateOne — עדיין מאות בקשות, רק במקביל, ומציף את ה־pool.

// P25.7-E98: POST /login — עם bcrypt ובלי injection
import bcrypt from "bcryptjs";
import { Router } from "express";
import type { Db } from "mongodb";
import { z } from "zod";

const schema = z.strictObject({ email: z.string().trim().toLowerCase(), password: z.string() });

export function loginRouter(db: Db) {
  const users = db.collection<{ _id: string; email: string; passwordHash: string }>("users");
  const router = Router();
  router.post("/login", async (req, res) => {
    const r = schema.safeParse(req.body);
    if (!r.success) {
      res.status(400).json({ error: { code: "VALIDATION_ERROR" } });
      return;
    }
    const user = await users.findOne({ email: r.data.email });
    const ok = user !== null && (await bcrypt.compare(r.data.password, user.passwordHash));
    if (!ok) {
      res.status(401).json({ error: { code: "INVALID_CREDENTIALS" } });
      return;
    }
    res.json({ id: user._id, email: user.email });
  });
  return router;
}
⚠️ טעויות נפוצות
  • findOne({ email, passwordHash: hash(password) }) — bcrypt מייצר hash אחר בכל פעם (salt). משווים עם compare.

P25.7-E99 · ‏Idempotency-Key ב־Mongo 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.7-E99: Idempotency-Key ב־Mongo
import { MongoServerError, type Db } from "mongodb";

type Rec = { _id: { userId: string; key: string }; fingerprint: string; status: "pending" | "done"; result?: unknown; createdAt: Date };

export async function runOnce<T>(db: Db, userId: string, key: string, fingerprint: string, fn: () => Promise<T>) {
  const col = db.collection<Rec>("idempotency");
  const _id = { userId, key };
  try {
    await col.insertOne({ _id, fingerprint, status: "pending", createdAt: new Date() });
  } catch (err) {
    if (!(err instanceof MongoServerError && err.code === 11000)) throw err;
    const existing = await col.findOne({ _id });
    if (!existing) throw new Error("IN_PROGRESS"); // נמחק בדיוק עכשיו — הלקוח ינסה שוב
    if (existing.fingerprint !== fingerprint) throw new Error("KEY_REUSED");
    if (existing.status === "pending") throw new Error("IN_PROGRESS");
    return { replayed: true, result: existing.result as T };
  }
  try {
    const result = await fn();
    await col.updateOne({ _id }, { $set: { status: "done", result } });
    return { replayed: false, result };
  } catch (err) {
    await col.deleteOne({ _id, status: "pending" });
    throw err;
  }
}

בדיוק כמו ה־INSERT … ON CONFLICT של פרק 24: ה־_id הייחודי הוא מה שמחליט מי "זכה". ובשונה מ־Postgres — fn והרישום לא באותה טרנזקציה (אם fn כותב ל־Mongo, אפשר לעטוף את שניהם ב־withTransaction). ו־TTL על createdAt — כדי שמפתחות ישנים יימחקו לבד.

⚠️ טעויות נפוצות
  • findOne ואז insertOne — 10 קריאות במקביל לא מוצאות, ו־fn רץ עשר פעמים.

✅ פתרון
// P25.7-E100: עגלה שפגה לבד — TTL
import type { Db } from "mongodb";

const WEEK_MS = 7 * 86_400_000;

export async function ensureCartTtl(db: Db): Promise<void> {
  await db.collection("carts").createIndex({ expiresAt: 1 }, { expireAfterSeconds: 0 });
}

export async function touchCart(db: Db, customerId: string, now: Date): Promise<Date> {
  const expiresAt = new Date(now.getTime() + WEEK_MS);
  await db.collection<{ _id: string }>("carts").updateOne(
    { _id: customerId },
    { $set: { updatedAt: now, expiresAt }, $setOnInsert: { items: [] } },
    { upsert: true },
  );
  return expiresAt;
}

‏"7 ימים" כאן הוא משך (‏7 × 24 שעות) — ולא "אותה שעה על השעון בעוד שבוע" (פרק 24). לתפוגה זה בדיוק מה שרוצים.

⚠️ טעויות נפוצות
  • $set: { items: [] } בכל touch — כל פעולה מרוקנת את העגלה.
