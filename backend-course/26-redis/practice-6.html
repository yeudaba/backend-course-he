P26-E30 · fan-out בין שרתים עם Redis 🤖

ב־E28 המאגר של האירועים האחרונים היה בזיכרון של שרת אחד. לקוח שמתחבר מחדש לשרת אחר — לא מקבל את מה שפספס. בקובץ 26-redis/starter/P26-E120.ts (יש בו רק הערה) כתוב וייצא:

export async function appendEvent(redis: Redis, stream: string, event: string, data: unknown, max?: number): Promise<number>
export async function eventsAfter(redis: Redis, stream: string, lastId: number): Promise<{ id: number; event: string; data: unknown }[]>
  • appendEvent — ‏id עולה ומשותף לכל השרתים מ־INCR sse:<stream>:seq. מוסיף { id, event, data } כ־JSON לסוף list ‏sse:<stream>:log, ומשאיר רק את max (ברירת מחדל 100) האחרונים. מחזיר את ה־id.
  • eventsAfter — כל האירועים במאגר עם id > lastId, ממוינים לפי id.
  • הבודק מוסיף 40 אירועים במקביל משני שרתים — כל ה־ids שונים, ו־eventsAfter(0) מחזיר את כולם, בסדר.

🔗 איך זה מתחבר: ‏INCR, ‏RPUSH ו־LTRIM משיעור 1 — והשיעור: Last-Event-ID גם כשהלקוח עובר שרת.
