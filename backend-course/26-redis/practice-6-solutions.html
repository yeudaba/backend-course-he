P26-E26 · polling, SSE או WebSocket? 🧠 הבנה רמה 1

💡 רמז 1

שתי שאלות: מי מדבר (רק השרת, או גם הלקוח)? וכמה מהר זה צריך להגיע?

💡 רמז 2

SSE — שרת ← לקוח, HTTP רגיל, עם התחברות מחדש ו־Last-Event-ID מובנים. WebSocket — שני הכיוונים, הודעות קטנות ותכופות.

✅ פתרון
  1. SSE — רק השרת מעדכן, ומעט. אפשר גם polling כל 30 שניות, אבל SSE מגיע מיד ולא מעמיס בקשות ריקות. ההתחברות מחדש וה־Last-Event-ID חינם.
  2. WebSocket — שני הצדדים כותבים, הרבה הודעות קטנות. (SSE + POST לכל הודעה עובד גם — פשוט פחות טבעי.)
  3. שום דבר — טעינה רגילה של הדף. אין "זמן אמת" במשהו שמשתנה פעם ביום.
  4. SSE — שרת ← מסכים. ואם יש כמה שרתים — Redis pub/sub מאחור (E30).
  5. WebSocket — שני כיוונים, תדירות גבוהה, וחשוב שלא יהיה overhead של HTTP לכל הודעה.
⚠️ טעויות נפוצות
  • WebSocket לכל דבר "כי הוא זמן אמת" — יותר קוד (התחברות מחדש, heartbeat, אימות) בשביל משהו ש־SSE נותן מובנה.

P26-E106 · מה הדפדפן רואה בזרם הזה? 🧠 הבנה רמה 2

💡 רמז 1

שורה ריקה מסיימת הודעה. שורה שמתחילה בנקודתיים — הערה.

💡 רמז 2

הודעה בלי data — לא מפעילה אירוע. ‏data בכמה שורות — מתחבר עם \n.

✅ פתרון
  1. : connected — הערה, כלום.
  2. retry: 5000 — אין אירוע; הדפדפן יחכה 5 שניות לפני התחברות מחדש.
  3. אירוע status, ‏data {"status":"received"}, ‏lastEventId ‏"1".
  4. אירוע message (אין event), ‏data "שורה ראשונה\nשורה שנייה". ‏lastEventId נשאר "1" (ב־EventSource ה־id האחרון נשמר עד שמגיע חדש).
  5. : ping — heartbeat, כלום.
  6. שום דבר — עדיין. להודעה האחרונה אין שורה ריקה בסוף, אז היא לא הסתיימה. אם החיבור ייפול עכשיו — היא אבדה.

נפל ← אחרי 5 שניות, ‏EventSource מתחבר מחדש עם Last-Event-ID: 1, ושרת טוב (‏E28) שולח שוב את 2.

⚠️ טעויות נפוצות
  • לשכוח את \n\n בסוף כל הודעה בשרת — הדפדפן מחכה, והאירוע מגיע רק עם ההודעה הבאה.

P26-E107 · ‏101, ‏Upgrade ו־token בכתובת 🧠 הבנה רמה 2

💡 רמז 1

‏101 Switching Protocols.

💡 רמז 2

מי עוד רואה את הכתובת המלאה של בקשה?

✅ פתרון
  1. 101 Switching Protocols: מאותו רגע זה לא HTTP — שני הצדדים שולחים frames על אותו חיבור TCP, שנשאר פתוח.
  2. ה־API של WebSocket בדפדפן פשוט לא מאפשר headers. האפשרויות: cookie של session (נשלח לבד), או token קצר־מועד בכתובת.

  4. חיבור פתוח הוא משאב (זיכרון, socket). אם מאמתים אחרי — כל אחד יכול לפתוח אלפי חיבורים ולא לשלוח כלום. ב־upgrade מחזירים 401 והחיבור לא נפתח בכלל (‏E29).
⚠️ טעויות נפוצות
  • לסמוך על from שהלקוח שולח בהודעה — מי ששלח נקבע לפי החיבור (ה־token), לא לפי מה שכתוב.

P26-E108 · כל כמה זמן heartbeat? 🧠 הבנה רמה 2

💡 רמז 1

‏heartbeat צריך להגיע לפני ה־timeout, עם מרווח לעיכובים.

💡 רמז 2

בדיקה כל 30 שניות: "קיבלתי pong מאז ה־ping הקודם?".

✅ פתרון
  1. 90 — החיבור נסגר אחרי 60 שניות, והלקוח מתחבר מחדש כל דקה. ‏59 — עובד על הנייר, אבל עיכוב של שנייה (GC, רשת) וזה נסגר. סביר: 15–30 שניות.
  2. הבדיקה הבאה (עד 30 שניות אחרי t=0) שולחת ping ומסמנת "מחכה". הבדיקה שאחריה, עוד 30 שניות, רואה שלא היה pong ← terminate. כלומר בין 30 ל־60 שניות.

⚠️ טעויות נפוצות
  • heartbeat כל שנייה "ליתר ביטחון" — עם 50,000 לקוחות, 50,000 כתיבות בשנייה בשביל כלום.

💡 רמז 2

✅ פתרון

P26-E110 · ‏fan-out: פעמיים, או אף פעם 🧠 הבנה רמה 2

‏A מנוי לערוץ בעצמו.

💡 רמז 2

✅ פתרון
  1. את האירוע פעמיים: פעם מהשליחה המקומית, ופעם כשההודעה חוזרת מ־Redis ל־A (גם הוא מנוי). לכן ב־E30 לא שולחים מקומית — רק publish.

P26-E27 · הודעת SSE 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כל שדה הוא "name: value\n", וההודעה מסתיימת ב־"\n" נוסף.

💡 רמז 2

text.split(/\r\n|\r|\n/), ולכל שורה — data: ${line}\n.

✅ פתרון
// P26-E27
// הודעה אחת בפורמט של Server-Sent Events: שורות "שדה: ערך", ושורה ריקה בסוף
export function formatEvent({ data, event, id, retry }: { data: unknown; event?: string; id?: string | number; retry?: number }): string {
  let out = "";
  if (id !== undefined) out += `id: ${id}\n`;
  if (event !== undefined) out += `event: ${event}\n`;
  if (retry !== undefined) out += `retry: ${retry}\n`;
  const text = typeof data === "string" ? data : JSON.stringify(data);
  // ירידת שורה בתוך data הייתה מסיימת את השדה — לכן כל שורה מקבלת data: משלה, והדפדפן מחבר אותן עם \n
  for (const line of text.split(/\r\n|\r|\n/)) out += `data: ${line}\n`;
  return out + "\n"; // שורה ריקה = סוף ההודעה
}
⚠️ טעויות נפוצות
  • if (id) במקום id !== undefined — id: 0 נעלם.
  • לשלוח data עם ירידת שורה כמו שהיא — הדפדפן חושב שהשורה השנייה היא שדה לא מוכר, ומשמיט אותה.

P26-E28 · רכזת SSE עם Last-Event-ID 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

res.writeHead(200, {...}) ו־res.flushHeaders() — כדי שהלקוח יקבל את ה־headers מיד, לפני האירוע הראשון. Set<Response> של המחוברים.

💡 רמז 2

req.on("close", () => clients.delete(res)). ו־Number(req.get("last-event-id")) — NaN כשאין header.

✅ פתרון
// P26-E28
// "רכזת" של SSE: כל לקוח מחובר מקבל כל אירוע, עם id עולה — ומי שהתנתק וחזר מקבל את מה שפספס
import type { Request, Response } from "express";

const format = (id: number, event: string, data: unknown) => `id: ${id}\nevent: ${event}\ndata: ${JSON.stringify(data)}\n\n`;

export function eventHub({ bufferSize = 100 }: { bufferSize?: number } = {}) {
  const clients = new Set<Response>();
  const buffer: { id: number; text: string }[] = []; // האירועים האחרונים — בשביל Last-Event-ID
  let lastId = 0;

  function handler(req: Request, res: Response) {
    res.writeHead(200, {
      "Content-Type": "text/event-stream",
      "Cache-Control": "no-cache",
      Connection: "keep-alive",
      "X-Accel-Buffering": "no", // שלא יחזיק את ההודעות ב־proxy (nginx)
    });
    res.flushHeaders();
    // הדפדפן שולח Last-Event-ID לבד כשהוא מתחבר מחדש
    const since = Number(req.get("last-event-id"));
    if (Number.isInteger(since)) for (const e of buffer) if (e.id > since) res.write(e.text);
    clients.add(res);
    req.on("close", () => clients.delete(res)); // אחרת: דליפה, וכתיבה לחיבור סגור
  }

  function publish(event: string, data: unknown) {
    const text = format(++lastId, event, data);
    buffer.push({ id: lastId, text });
    if (buffer.length > bufferSize) buffer.shift();
    for (const res of clients) res.write(text);
    return lastId;
  }

  return { handler, publish, size: () => clients.size };
}
⚠️ טעויות נפוצות
  • לשכוח את req.on("close") — כל רענון של הדף משאיר חיבור "מת" ברשימה. אחרי יום: אלפי res.write לחיבורים סגורים, וזיכרון שרק עולה.
  • לשמור את כל האירועים לנצח בשביל Last-Event-ID — דליפה מסוג אחר. מאגר מוגבל, ומי שפספס יותר מזה — טוען את הדף מחדש.

P26-E29 · חדרי צ'אט ב־WebSocket 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

new WebSocketServer({ noServer: true }), ו־server.on("upgrade", (req, socket, head) => …). שם בודקים את ה־token, ואם תקין — wss.handleUpgrade(req, socket, head, (ws) => …).

לבדוק בעצמך: ב־Node 24 יש WebSocket גלובלי (כמו בדפדפן) — new WebSocket("ws://localhost:3000/chat?token=…").

💡 רמז 2

דחייה לפני ה־upgrade: socket.end("HTTP/1.1 401 Unauthorized\r\nConnection: close\r\n\r\n"). חדרים: Map<string, Set<WebSocket>>, ו־ws.on("close") מוציא מהחדר.

✅ פתרון
// P26-E29
// חדרי צ'אט ב־WebSocket: אימות בזמן ה־upgrade, הצטרפות לחדר, ושידור לחברי החדר בלבד
import type { Server } from "node:http";
import { WebSocketServer, WebSocket } from "ws";

export function createChatServer(server: Server, { verifyToken }: { verifyToken: (token: string) => string | null }) {
  const wss = new WebSocketServer({ noServer: true });
  const rooms = new Map<string, Set<WebSocket>>();
  const send = (ws: WebSocket, msg: object) => ws.readyState === WebSocket.OPEN && ws.send(JSON.stringify(msg));

  // האימות קורה לפני שהחיבור נפתח: בלי token תקין — 401 ו־socket סגור. אחרי upgrade כבר אין status codes
  server.on("upgrade", (req, socket, head) => {
    const url = new URL(req.url ?? "/", "http://x");
    const user = url.pathname === "/chat" ? verifyToken(url.searchParams.get("token") ?? "") : null;
    if (!user) {
      socket.end("HTTP/1.1 401 Unauthorized\r\nConnection: close\r\n\r\n");
      return;
    }
    wss.handleUpgrade(req, socket, head, (ws) => {
      let room: string | null = null;
      const leave = () => { if (room) rooms.get(room)?.delete(ws); room = null; };
      ws.on("message", (raw) => {
        let msg: { type?: string; room?: unknown; text?: unknown };
        try { msg = JSON.parse(String(raw)); } catch { return send(ws, { type: "error", error: "invalid json" }); }
        if (msg.type === "join" && typeof msg.room === "string" && msg.room) {
          leave();
          room = msg.room;
          if (!rooms.has(room)) rooms.set(room, new Set());
          rooms.get(room)!.add(ws);
          return send(ws, { type: "joined", room });
        }
        if (msg.type === "say" && typeof msg.text === "string") {
          if (!room) return send(ws, { type: "error", error: "join a room first" });
          // השולח (user) נקבע בשרת לפי ה־token — לא לפי מה שהלקוח כותב בהודעה
          for (const peer of rooms.get(room) ?? []) send(peer, { type: "message", room, from: user, text: msg.text });
          return;
        }
        send(ws, { type: "error", error: "unknown message" });
      });
      ws.on("close", leave);
    });
  });

  return { close: () => new Promise<void>((resolve) => { for (const ws of wss.clients) ws.terminate(); wss.close(() => resolve()); }) };
}
⚠️ טעויות נפוצות
  • לאמת אחרי שהחיבור נפתח ("שלח token בהודעה הראשונה") — בינתיים כל אחד מחזיק חיבור פתוח בשרת. ואם שוכחים לבדוק בהודעה אחת — פרצה.
  • from: msg.from — כל אחד יכול להתחזות לכל אחד.
  • לזרוק על JSON שבור — חריגה ב־handler של message מפילה את כל התהליך.

P26-E30 · fan-out בין שרתים עם Redis 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

await sub.subscribe(channel) פעם אחת, ו־sub.on("message", (ch, message) => …) שמפיץ ל־Set של מאזינים.

💡 רמז 2

"פעם אחת": אל תקרא למאזינים המקומיים ישירות ב־publish — ההודעה חוזרת מ־Redis גם לשרת ששלח.

✅ פתרון
// P26-E30
// כמה שרתים, לקוחות מחוברים לכל אחד: אירוע שקרה בשרת אחד צריך להגיע ללקוחות של כולם — דרך Redis pub/sub
import type { Redis } from "ioredis";

export async function createRelay({ pub, sub, channel }: { pub: Redis; sub: Redis; channel: string }) {
  const listeners = new Set<(data: unknown) => void>();
  // מנוי אחד לשרת, לא אחד לכל לקוח. החיבור sub נפרד: חיבור במצב SUBSCRIBE לא מריץ פקודות אחרות
  await sub.subscribe(channel);
  const onMessage = (ch: string, message: string) => {
    if (ch !== channel) return; // אותו חיבור יכול להיות מנוי לערוצים אחרים
    const data = JSON.parse(message);
    for (const l of listeners) l(data);
  };
  sub.on("message", onMessage);

  return {
    // לא שולחים ישירות למאזינים המקומיים: ההודעה תחזור מ־Redis גם לשרת הזה — אחרת כל אחד יקבל פעמיים
    publish: async (data: unknown) => { await pub.publish(channel, JSON.stringify(data)); },
    subscribe(listener: (data: unknown) => void) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    async close() {
      sub.off("message", onMessage);
      await sub.unsubscribe(channel);
    },
  };
}
⚠️ טעויות נפוצות
  • publish שגם שולח מקומית וגם ל־Redis — הלקוחות של השרת השולח מקבלים כל הודעה פעמיים.
  • subscribe ב־Redis לכל לקוח SSE — אלף לקוחות = אלף מנויים, ואלף קריאות ל־JSON.parse לכל הודעה.
  • pub/sub לא שומר כלום: שרת שהיה למטה ברגע ה־publish — פספס. לכן ל־SSE יש Last-Event-ID, ולדברים שאסור לפספס — תור (BullMQ, שיעור 4) או Redis Streams.

P26-E111 · לפרק זרם SSE 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

// P26-E111: לפרק זרם SSE
type Event = { event: string; data: string; id?: string };

export function parseSSE(text: string): Event[] {
  const out: Event[] = [];
  let data: string[] = [];
  let event = "";
  let id: string | undefined;
  const lines = text.split(/\r\n|\r|\n/);
  lines.pop(); // מה שאחרי ירידת השורה האחרונה — שורה שעוד לא הסתיימה (או ריק)
  for (const line of lines) {
    if (line === "") {
      if (data.length) out.push({ event: event || "message", data: data.join("\n"), ...(id !== undefined ? { id } : {}) });
      data = [];
      event = "";
      id = undefined;
      continue;
    }
    if (line.startsWith(":")) continue;
    const i = line.indexOf(":");
    const field = i === -1 ? line : line.slice(0, i);
    let value = i === -1 ? "" : line.slice(i + 1);
    if (value.startsWith(" ")) value = value.slice(1);
    if (field === "data") data.push(value);
    else if (field === "event") event = value;
    else if (field === "id") id = value;
  }
  return out;
}

‏lines.pop(): האיבר האחרון של split הוא מה שבא אחרי ירידת השורה האחרונה — ריק, או שורה שעוד לא הגיעה עד סופה. בלי ה־pop, טקסט שמסתיים ב־data: x\n (שורה אחת, בלי שורה ריקה) היה נראה כמו הודעה גמורה. זה בדיוק מה שהדפדפן עושה: הודעה שלא הסתיימה לא נמסרת.

⚠️ טעויות נפוצות
  • value.trim() — מוחק רווחים שהם חלק מה־data (‏data: x הוא " x").
  • line.split(":") — ‏data: {"a":1} נחתך בנקודתיים שבתוך ה־JSON.

// P26-E113: heartbeat ל־WebSocket — ping, pong, terminate
import type { WebSocket, WebSocketServer } from "ws";

export function attachHeartbeat(wss: WebSocketServer, intervalMs: number) {
  const alive = new WeakMap<WebSocket, boolean>();
  wss.on("connection", (ws) => {
    alive.set(ws, true);
    ws.on("pong", () => alive.set(ws, true));
  });
  const timer = setInterval(() => {
    for (const ws of wss.clients) {
      if (!alive.get(ws)) {
        ws.terminate();
        continue;
      }
      alive.set(ws, false);
      ws.ping();
    }
  }, intervalMs);
  return () => clearInterval(timer);
}

‏terminate() ולא close(): ‏close שולח frame של סגירה ומחכה לתשובה — מלקוח מת היא לא תגיע. ‏terminate הורס את ה־socket מיד, ו־ws.on("close") של השרת נקרא (כדי לנקות חדרים, מנויים וכו׳).

// P26-E114: SSE של הזמנה — רק לבעלים
import type { EventEmitter } from "node:events";
import type express from "express";

type Deps = { authenticate(req: express.Request): number | null; ownerOf(orderId: number): Promise<number | null>; bus: EventEmitter };

export function orderEvents({ authenticate, ownerOf, bus }: Deps): express.RequestHandler {
  return async (req, res) => {
    const userId = authenticate(req);
    if (userId === null) return void res.status(401).json({ error: "נדרשת התחברות" });
    const orderId = Number(req.params.id);
    const owner = Number.isInteger(orderId) ? await ownerOf(orderId) : null;
    if (owner === null || owner !== userId) return void res.status(404).json({ error: "הזמנה לא נמצאה" });

    res.writeHead(200, { "Content-Type": "text/event-stream", "Cache-Control": "no-cache" });
    res.write(": connected\n\n");
    const listener = (e: { orderId: number; status: string }) => {
      if (e.orderId === orderId) res.write(`event: status\ndata: ${JSON.stringify(e)}\n\n`);
    };
    bus.on("status", listener);
    req.on("close", () => bus.off("status", listener));

// P26-E118: SSE בשני שרתים — POST ב־A, אירוע ב־B
import express from "express";
import type { Redis } from "ioredis";

export async function createLiveApp({ pub, sub, channel }: { pub: Redis; sub: Redis; channel: string }) {
  const clients = new Set<express.Response>();
  await sub.subscribe(channel);
  const onMessage = (ch: string, msg: string) => {
    if (ch !== channel) return;
    for (const c of clients) c.write(`data: ${msg}\n\n`);
  };
  sub.on("message", onMessage);

  const app = express();
  app.use(express.json());
  app.get("/events", (req, res) => {
    res.writeHead(200, { "Content-Type": "text/event-stream", "Cache-Control": "no-cache" });
    res.write(": connected\n\n");
    clients.add(res);
    req.on("close", () => clients.delete(res));
  });
  app.post("/events", async (req, res) => {
    await pub.publish(channel, JSON.stringify(req.body));
    res.status(202).end();
  });

  return {
    app,
    async close() {
      sub.off("message", onMessage);
      await sub.unsubscribe(channel);
    },
  };
}

const schema = z.discriminatedUnion("type", [
  z.strictObject({ type: z.literal("join"), room: z.string().regex(/^[a-z0-9-]{1,30}$/) }),
  z.strictObject({ type: z.literal("say"), text: z.string().trim().min(1).max(500) }),

// P26-E120: Last-Event-ID בין שרתים — מאגר ב־Redis
import type { Redis } from "ioredis";

export async function appendEvent(redis: Redis, stream: string, event: string, data: unknown, max = 100) {
  const id = await redis.incr(`sse:${stream}:seq`);
  const log = `sse:${stream}:log`;
  await redis.multi().rpush(log, JSON.stringify({ id, event, data })).ltrim(log, -max, -1).exec();
  return id;
}

export async function eventsAfter(redis: Redis, stream: string, lastId: number) {
  const all = (await redis.lrange(`sse:${stream}:log`, 0, -1)).map((x) => JSON.parse(x) as { id: number; event: string; data: unknown });
  return all.filter((e) => e.id > lastId).sort((a, b) => a.id - b.id);
}

id מ־INCR ולא מונה בזיכרון — כך Last-Event-ID: 42 אומר אותו דבר בכל שרת. (ל־Redis יש גם מבנה שנבנה בדיוק לזה — Streams, ‏XADD/XRANGE — עם ids עולים וחיתוך מובנים. כאן בנינו אותו משני הכלים שכבר מכירים.)

⚠️ טעויות נפוצות
  • LTRIM key 0 max-1 — משאיר את הראשונים (הישנים), ומוחק כל אירוע חדש.
  • לסמוך על הסדר ב־list בלי מיון — במקביל, ה־id וסדר ה־RPUSH לא תמיד אותו דבר.
