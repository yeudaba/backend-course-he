P26-E71 · ‏backoff: מתי כל ניסיון?

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: שיעור 4

עבודה עם attempts: 5 ו־backoff: { type: "exponential", delay: 1000 }. הניסיון הראשון יוצא ב־t=0, וכל ניסיון נכשל מיד.

  1. מתי יוצא כל אחד מהניסיונות 2–5? (BullMQ מחכה delay × 2^(n−1) לפני הניסיון החוזר ה־n.)
  2. מתי העבודה עוברת ל־failed?
  3. אותו דבר עם type: "fixed".
  4. שרת המייל למטה 10 דקות. אילו מההגדרות "מחזיקה מעמד", ואיזה ערך attempts היה מספיק עם exponential של שנייה?

P26-E72 · ‏worker קרס — איפה בדיוק?

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: שיעור 4

ה־worker של מייל האישור עושה שלושה צעדים: (א) לוקח עבודה מהתור, (ב) שולח את המייל, (ג) מסמן "הושלם". לכל רגע קריסה — מה יקרה ללקוח?

  1. קריסה בין (א) ל־(ב).
  2. קריסה בין (ב) ל־(ג).
  3. עכשיו "משפרים": מסמנים הושלם לפני השליחה — (א), (ג), (ב). קריסה בין (ג) ל־(ב)?

איזה מהם at-least-once ואיזה at-most-once, ולמה תורים כמעט תמיד בוחרים את הראשון?

P26-E73 · איזה ‏jobId?

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 4

לכל עבודה — איזה jobId (או בלי), כך שלחיצה כפולה / קריאה כפולה לא תיצור עבודה כפולה, אבל עבודה לגיטימית שנייה כן תיווצר:

  1. מייל אישור להזמנה.
  2. הקטנת תמונה שהמשתמש העלה (כל העלאה — קובץ חדש).
  3. דוח מכירות יומי.
  4. "הזכר לי לשלם" — לכל היותר תזכורת אחת ביום למשתמש.
  5. webhook ללקוח על כל שינוי סטטוס של הזמנה.

P26-E76 · לוח זמנים של backoff 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: שיעור 4

חימום. בקובץ 26-redis/starter/P26-E76.ts (יש בו רק הערה) כתוב וייצא:

export function backoffDelays(attempts: number, delay: number, type: "fixed" | "exponential"): number[]
export function giveUpAfter(attempts: number, delay: number, type: "fixed" | "exponential"): number
  • backoffDelays ← ההמתנה (ms) לפני כל ניסיון חוזר — attempts − 1 מספרים. ‏fixed — תמיד delay. ‏exponential — ‏delay × 2^(n−1) לניסיון החוזר ה־n.
  • giveUpAfter ← סכום ההמתנות: אחרי כמה ms (מהניסיון הראשון) יוצא הניסיון האחרון.
  • attempts שאינו שלם חיובי, או delay שלילי ← RangeError.

דוגמה: backoffDelays(5, 1000, "exponential") ← [1000, 2000, 4000, 8000], ו־giveUpAfter ← ‏15000 (‏E71).

P26-E79 · תור פשוט מ־list 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 4

לפני BullMQ: תור הוא list. בקובץ 26-redis/starter/P26-E79.ts (יש בו רק הערה) כתוב וייצא:

export async function enqueue(redis: Redis, queue: string, job: unknown): Promise<number>
export async function drain(redis: Redis, queue: string, handler: (job: any) => Promise<void>): Promise<{ done: number; failed: number }>

  • שני drain במקביל (שני workers) — כל עבודה מטופלת פעם אחת.

P26-E83 · ‏outbox relay: מ־PostgreSQL לתור 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: פרק 18, שיעור 4

בקובץ 26-redis/starter/P26-E83.ts (יש בו רק הערה) כתוב וייצא:

export async function relayOutbox(db: pg.Client, queue: Queue, limit?: number): Promise<number>
  • הטבלה outbox: ‏id serial, ‏kind text, ‏payload jsonb, ‏sent_at timestamptz.
  • קוראת עד limit (ברירת מחדל 100) שורות שעוד לא נשלחו, לפי id. לכל שורה: queue.add(kind, payload, { jobId: "outbox-" + id }), ואז מסמנת sent_at = now() לשורה הזו.

  • אם ה־relay קרס אחרי ה־add ולפני הסימון — הריצה הבאה מוסיפה שוב, אבל בתור עדיין יש עבודה אחת.

P26-E85 · ‏timeout בתוך worker 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: פרק 10, שיעור 4

שרת SMTP לפעמים "נתקע" — לא עונה ולא נכשל. העבודה נשארת active לנצח. בקובץ 26-redis/starter/P26-E85.ts (יש בו רק הערה) כתוב וייצא:

export function startWorkerWithTimeout(connection: ConnectionOptions, prefix: string, queueName: string, handler: (data: any) => Promise<unknown>, timeoutMs: number): Worker
  • Worker לתור queueName שקורא ל־handler(job.data) ומחזיר את התוצאה שלו.

🔗 איך זה מתחבר: ‏Promise.race ו־setTimeout/clearTimeout מפרק 10 — והשיעור: כישלון = ניסיון חוזר.
