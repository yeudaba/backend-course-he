פרק 26 — Redis: מטמון, מצב משותף ותורים

⏱ 4 מפגשים

🧰 לפני שמתחילים — פרק 26

מה צריך שכבר יהיה מותקן: Node.js 24, Docker Desktop, ופרויקט 3 (חנות הקפה) בשלב 4 — כל בודקי PR3 עוברים.

מה מתקינים / מריצים עכשיו:

  • Redis 8 בקונטיינר (פעם אחת; אחר כך docker start redis): 
    docker run -d --name redis -p 6379:6379 redis:8-alpine
  • בדיקה: docker exec -it redis redis-cli ping ← PONG.
  • ב־~/dev/backend-course/.env — שורה COURSE_REDIS_URL=redis://localhost:6379 (הבודקים משתמשים בה; זו גם ברירת המחדל). הבודקים כותבים רק מפתחות עם קידומת chk: ומוחקים אותם בסוף.
  • תוסף VS Code (לא חובה): Redis for VS Code — לראות מפתחות וערכים בזמן שהקוד רץ. אותו דבר בטרמינל: docker exec -it redis redis-cli.

📂 העתקת חומרי הפרק: ב־Finder, העתק את התיקייה 26-redis מתוך ~/Desktop/Backend/backend-course אל ~/dev/backend-course (גרירה עם ⌥ Option). אם התיקייה כבר שם מהעתקה קודמת ואתה רוצה לשמור את מה שכתבת — בחר Keep Both / Stop ולא Replace.

✔ בדיקה: cd ~/dev/backend-course && npm install && npm run check P26-E06 ← הבודק מתחבר ל־Redis ונכשל על קובץ ההתחלה. npm install מוסיף את ioredis ו־bullmq; אם הבודק כותב ECONNREFUSED 127.0.0.1:6379 — הקונטיינר לא רץ.

🎯 בסוף הפרק תדע
  • להבין מה Redis טוב בו ומה לא: זיכרון, מבני נתונים, TTL, ופקודות אטומיות — ומתי PostgreSQL מספיק.
  • cache-aside: מפתחות, TTL, ביטול עם גרסה, stampede — ולמדוד את ההבדל בעצמך.
  • מצב משותף לכמה שרתים: הגבלת קצב, מנעולים, pub/sub ו־Lua.
  • תורים עם BullMQ: עבודות ברקע, ניסיונות חוזרים, עיכוב, at-least-once וצרכן idempotent.
  • פרויקט 3, שלב 5: cache לקטלוג, מייל אישור בתור, וביטול אוטומטי של הזמנות שלא שולמו.

🤔 למה צריך את זה?

חנות הקפה עובדת. עכשיו שלוש בעיות של "מערכת אמיתית": דף הקטלוג נקרא אלף פעמים על כל פעם שהוא משתנה — ובכל פעם הולך למסד; מייל האישור נשלח בתוך הבקשה של התשלום — ואם שרת המייל איטי, הלקוח מחכה (ואם הוא נופל — התשלום "נכשל"?); והזמנה שלא שולמה מחזיקה מלאי לנצח. ועוד אחת שנשארה מפרק 24: הגבלת הקצב סופרת בזיכרון של תהליך אחד — עם שלושה שרתים היא לא עובדת. לכל אלה יש כלי אחד שמופיע כמעט בכל מודעת דרושים: Redis.
