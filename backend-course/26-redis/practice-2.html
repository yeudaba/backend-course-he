P26-E07 · cache-aside 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 2

בקובץ P26-E07.ts: createCacheAside(redis) ← { get(key, ttl, load), stats, invalidate(key) }. get: יש ב־Redis ← מחזיר (stats.hits++); אין ← load(), שומר עם TTL, מחזיר (stats.misses++). שגיאה מ־load ← עולה, ולא נשמר כלום. null/undefined ← לא נשמרים.

P26-E50 · מפתח cache יציב 🤖

P26-E51 · ‏cache-aside עם TTL אקראי 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 2

כדי שמפתחות שנוצרו יחד לא יפוגו יחד (stampede), מוסיפים "רעש" ל־TTL. בקובץ 26-redis/starter/P26-E51.ts (יש בו רק הערה) כתוב וייצא:

  • cache-aside רגיל: יש ← מחזירים (בלי load); אין ← load(), שומרים כ־JSON, ומחזירים.
  • ה־TTL בפועל: ttl + Math.floor(random() * ttl * 0.2) — בין ttl ל־20% יותר.
  • load זרק ← השגיאה עולה, ושום דבר לא נשמר.

P26-E32 · לקרוא את INFO של Redis 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 2⏱ 20 דק׳ידע נדרש: שיעור 2

🔁 חזרה על split עם regex, ‏indexOf/slice (‏P14-E26), ‏Object.entries/fromEntries (‏P07-E26) ו־?./??. כדי לדעת אם ה־cache עובד, מסתכלים על INFO: כמה פגיעות (keyspace_hits) וכמה החטאות (keyspace_misses). ‏redis.info() מחזיר טקסט: מקטעים שמתחילים ב־# Server, ובכל שורה key:value, עם \r\n בסוף. כתוב וייצא:

  • parseInfo(text) ← { server: { redis_version: "8.2.1", ... }, stats: { ... }, ... }. שם המקטע באותיות קטנות. הערך — הכול אחרי הנקודתיים הראשונות, כמחרוזת. שורות ריקות מדלגים.
  • parseKeyspace(info) — מתוך info.keyspace: ‏"db0" : "keys=1204,expires=980,..." ← { db0: { keys: 1204, expires: 980, ... } }, כמספרים. בלי מקטע keyspace (מסד ריק) ← {}.
  • hitRatio(info) ← hits / (hits + misses), מעוגל לשלוש ספרות אחרי הנקודה. אין נתונים (שניהם 0, או אין מקטע stats) ← null.

🔗 איך זה מתחבר: פירוק טקסט עם split ו־Object.fromEntries מפרקים 2 ו־7 — והשיעור: איך יודעים אם ה־cache באמת עובד (hits מול misses).
