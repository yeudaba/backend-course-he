שיעור 1 — Redis: מבני נתונים בזיכרון

⏱ ~45 דקות

🎯 בשיעור הזה
  • מה זה Redis, ובמה הוא שונה מ־PostgreSQL.
  • פקודות ראשונות ב־redis-cli: מחרוזות, מונים, TTL.
  • חמשת מבני הנתונים — ולאיזו בעיה כל אחד.
  • Redis מ־Node.js עם ioredis: קידומת מפתחות, MULTI, ומה עושים כש־Redis לא זמין.

1. מסד נתונים שחי בזיכרון

Redis הוא שרת שמחזיק מפתח ← ערך, הכול ב־RAM. אין טבלאות, אין SQL, אין JOIN. מה שיש: פעולות מהירות מאוד (מיקרו־שניות בתוך השרת), מבני נתונים מוכנים, תוקף (TTL) לכל מפתח, ופקודות אטומיות — Redis מריץ פקודה אחת בכל רגע, כך ש־INCR משני שרתים במקביל אף פעם לא "מאבד" ספירה.

PostgreSQLRedis
איפה הנתוניםדיסק (עם cache בזיכרון)זיכרון (עם גיבוי לדיסק — אם הוגדר)

טוב ל־הזמנות, משתמשים, כסף, מלאיcache, מונים, הגבלות קצב, מנעולים, תורים, סשנים

הכלל שילווה את כל הפרק: Redis לא מקור האמת. כל מה שבו אפשר לבנות מחדש או לאבד בלי נזק אמיתי. ההזמנה, המלאי והתשלום — ב־PostgreSQL, כמו בפרויקט 3. (Redis יכול לשמור לדיסק — RDB ו־AOF — ושירותים מנוהלים עושים את זה. אבל המערכת צריכה לשרוד גם Redis ריק.)

2. redis-cli

מהקונטיינר שהרצת בהתקנה: docker exec -it redis redis-cli.

127.0.0.1:6379> SET greeting shalom
OK
127.0.0.1:6379> GET greeting
"shalom"
127.0.0.1:6379> INCR visits
(integer) 1
127.0.0.1:6379> INCR visits
(integer) 2
127.0.0.1:6379> GET visits
"2"
127.0.0.1:6379> SET code 4821 EX 300
OK
127.0.0.1:6379> TTL code
(integer) 300
127.0.0.1:6379> TTL greeting
(integer) -1
127.0.0.1:6379> GET nothing
(nil)
127.0.0.1:6379> DEL greeting visits code
(integer) 3
  • INCR על מפתח שלא קיים — מתחיל מ־0. ו־GET visits מחזיר "2", מחרוזת: ב־Redis כל ערך הוא מחרוזת; "מספר" הוא מחרוזת ש־INCR יודע לקרוא.
  • EX 300 — המפתח נמחק לבד אחרי 5 דקות (קוד אימות, סשן). TTL מחזיר −1 כשאין תוקף, −2 כשאין מפתח.
  • שמות מפתחות — מוסכמה: חלקים עם נקודתיים, shop:cache:products:…, views:2026-11-08.

ואותו דבר מ־Node.js, עם ioredis — כל פקודה היא פונקציה עם אותו שם:

import { Redis } from "ioredis";
const redis = new Redis(process.env.REDIS_URL ?? "redis://localhost:6379", { keyPrefix: "lesson26:" });

await redis.hset("user:7", { name: "דנה", city: "חיפה" });
await redis.hincrby("user:7", "orders", 1);
console.log(await redis.hgetall("user:7"));

await redis.zadd("bestsellers", 12, "latte", 30, "espresso", 7, "mocha");
await redis.zincrby("bestsellers", 25, "latte");
console.log(await redis.zrevrange("bestsellers", 0, 2, "WITHSCORES"));

for (const p of ["latte", "mocha", "latte", "cookie"]) {
  await redis.lrem("recent:7", 0, p);
  await redis.lpush("recent:7", p);
}
await redis.ltrim("recent:7", 0, 2);
console.log(await redis.lrange("recent:7", 0, -1));

await redis.del("user:7", "bestsellers", "recent:7");
await redis.quit();
{ name: 'דנה', city: 'חיפה', orders: '1' }
[ 'latte', '37', 'espresso', '30', 'mocha', '7' ]
[ 'cookie', 'latte', 'mocha' ]

שים לב: hgetall מחזיר את orders כמחרוזת, וגם הניקודים ב־WITHSCORES. ו"צפית לאחרונה" בשלוש פקודות: מוחקים אם כבר שם, דוחפים לראש, וחותכים ל־3 — latte שנצפה שוב עלה לראש, בלי כפילות.

4. ioredis: שלושה דברים שכדאי לדעת

keyPrefix. בדוגמה, "user:7" נשמר בפועל כ־lesson26:user:7. כמה אפליקציות (או סביבות — dev, test) על אותו Redis לא דורכות זו על זו. הבודקים של הפרק משתמשים בזה: כל ריצה מקבלת קידומת משלה, ומוחקת רק אותה בסוף. בפרויקט 3: REDIS_PREFIX=shop.

MULTI / pipeline. כמה פקודות בהלוך־חזור אחד:

const results = await redis.multi()
  .hincrby(`views:${day}`, productId, 1)
  .zincrby(`top:${day}`, 1, productId)
  .expire(`views:${day}`, 7 * 86400)
  .exec(); // [[null, 3], [null, "3"], [null, 1]] — [שגיאה, תוצאה] לכל פקודה

MULTI מריץ את כולן ברצף, בלי שפקודה של לקוח אחר תיכנס באמצע. אבל זה לא טרנזקציה כמו ב־SQL: אין rollback, ואי אפשר להחליט באמצע לפי ערך שנקרא (לזה — Lua, בשיעור 3).

מה קורה כש־Redis לא זמין. ioredis מנסה להתחבר מחדש לבד, ופקודות ממתינות בתור (עד 20 ניסיונות לפקודה, ברירת מחדל). לכן קוד שמשתמש ב־Redis כאופטימיזציה צריך להחליט: ליפול, או להמשיך בלי. ב־cache של הפרויקט — ממשיכים בלי (המסד עונה, רק לאט יותר); בתור של BullMQ — אין "בלי".

⚠️ פקודות שאסור בפרודקשן

KEYS * סורק את כל המפתחות — ומאחר ש־Redis עושה דבר אחד בכל רגע, בזמן הסריקה כל השרתים שלך מחכים. עם מיליון מפתחות — שניות. בקוד: SCAN (בחלקים), או — עדיף — לתכנן כך שלא צריך לחפש מפתחות (שיעור 2). ו־FLUSHALL מוחק הכול, גם של אפליקציות אחרות.

💡 Redis, Valkey, ומה מנוהל

ב־2024 שינה Redis את הרישיון, ונוצר fork בקוד פתוח בשם Valkey (שספקי ענן גדולים עברו אליו). ב־2025 Redis 8 חזר לרישיון קוד פתוח (AGPL). מבחינת הקוד שלך — אותן פקודות, ו־ioredis ו־BullMQ עובדים מול שניהם. בענן: Upstash (יש תוכנית חינמית, נכון לנובמבר 2026), ElastiCache, Redis Cloud, או Key Value של Render.
