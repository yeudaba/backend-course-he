שיעור 3 — union, literal types ו־narrowing

⏱ ~40 דקות

🎯 בשיעור הזה
  • union — "אחד מכמה טיפוסים".
  • literal types — רשימה סגורה של ערכים מותרים.
  • narrowing — איך TypeScript "מבין" את הטיפוס אחרי בדיקה.
  • discriminated unions ו־never — לא לשכוח אף מקרה.

1. Union: A | B

function format(id: string | number): string {
  return id.toUpperCase();
}
snippet.ts(2,13): error TS2339: Property 'toUpperCase' does not exist on type 'string | number'.
  Property 'toUpperCase' does not exist on type 'number'.

id יכול להיות מספר — ולמספר אין toUpperCase. TypeScript מרשה רק מה שבטוח לכל האפשרויות. כדי להשתמש במשהו ספציפי — בודקים קודם:

2. Narrowing — צמצום בבדיקה

function format(id: string | number): string {
  if (typeof id === "number") {
    return `#${id.toFixed(0)}`;
  }
  return id.toUpperCase();
}
console.log(format(42), format("ab-7"));
#42 AB-7

בתוך ה־if, TypeScript יודע ש־id הוא number; אחרי ה־return, מה שנשאר הוא רק string. אותן בדיקות שכתבת בפרק 3 — עכשיו הן גם מלמדות את הבודק.

3. Literal types — רשימה סגורה

type OrderStatus = "pending" | "paid" | "shipped" | "cancelled";

let orderStatus: OrderStatus = "pending";
orderStatus = "paid";
orderStatus = "deliverd";
snippet.ts(5,1): error TS2322: Type '"deliverd"' is not assignable to type 'OrderStatus'.

שגיאת כתיב בסטטוס — באג שיכול לחיות שנים בקוד JavaScript — נתפסת מיד. ובעורך, הקלדת orderStatus = " מציעה את ארבעת הערכים. (ב־SQL נראה את המקבילה: CHECK או enum בעמודה, פרק 17.)

4. Discriminated unions

אמצעי תשלום: לכרטיס יש 4 ספרות אחרונות, ל־PayPal — אימייל, להעברה — מספר אסמכתא. אובייקט אחד עם כל השדות האופציונליים היה מבולגן. במקום:

type Payment =
  | { method: "card"; last4: string }
  | { method: "paypal"; email: string }
  | { method: "transfer"; reference: string };

function describe(p: Payment): string {
  switch (p.method) {
    case "card":
      return `כרטיס שמסתיים ב־${p.last4}`;
    case "paypal":
      return `PayPal (${p.email})`;
    case "transfer":
      return `העברה ${p.reference}`;
  }
}
console.log(describe({ method: "card", last4: "4242" }));
כרטיס שמסתיים ב־4242

השדה המשותף method "מבחין" בין האפשרויות. בתוך case "card", TypeScript יודע שיש last4 ואין email.

never — לוודא שלא שכחנו מקרה

type Payment =
  | { method: "card"; last4: string }
  | { method: "paypal"; email: string }
  | { method: "bit"; phone: string };

function fee(p: Payment): number {
  switch (p.method) {
    case "card":
      return 1.5;
    case "paypal":
      return 2.9;
    default: {
      const unhandled: never = p;
      throw new Error(`אמצעי תשלום לא נתמך: ${JSON.stringify(unhandled)}`);
    }
  }
}
snippet.ts(13,13): error TS2322: Type '{ method: "bit"; phone: string; }' is not assignable to type 'never'.

מישהו הוסיף "bit" לטיפוס — ו־TypeScript מראה בדיוק איפה הקוד לא מטפל בו. never = "טיפוס שאין לו אף ערך"; אם הגענו לשם עם ערך — שכחנו מקרה. דפוס חזק מאוד בקוד עסקי.
