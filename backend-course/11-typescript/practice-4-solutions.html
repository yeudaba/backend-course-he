P11-E05 · any, unknown או as? 🧠 הבנה רמה 1

💡 רמז 1

any — כמעט אף פעם. unknown — מבחוץ. as — כשאתה באמת יודע.

💡 רמז 2

גם "קובץ שלי" יכול להשתנות.

✅ פתרון
  1. unknown + validation — זה המקום המסוכן ביותר.
  2. unknown + type guard (עדיף), או as Config אם הקובץ קטן ובשליטה מלאה — עם הבנה שאין כאן הגנה.
  3. לכתוב type לפי התיעוד ו־as במקום אחד (בפונקציית עטיפה), כדי שכל השאר יהיה מוקלד.
  4. לא any. התלונה כמעט תמיד מצביעה על באג אמיתי — קרא אותה.
⚠️ טעויות נפוצות
  • as על קלט מהמשתמש — "מבטיח" משהו שאין לך שליטה עליו.

P11-E69 · אותו קוד — עם any ועם unknown 🧠 הבנה רמה 2

💡 רמז 1

💡 רמז 2

P11-E71 · type guard שמשקר 🧠 הבנה רמה 2

💡 רמז 1

value is Product הוא הבטחה של מי שכתב את הפונקציה. TypeScript לא בודק שהגוף באמת מוודא הכול.

💡 רמז 2

מה בודקים לגבי price?

✅ פתרון
type Product = { name: string; price: number };

function isProduct(value: unknown): value is Product {
  return typeof value === "object" && value !== null && "name" in value;
}

const raw: unknown = JSON.parse('[{"name":"עט","price":5},{"name":"דף"}]');
if (Array.isArray(raw)) {
  for (const item of raw.filter(isProduct)) {
    console.log(item.name, item.price * 2);
  }
}
עט 10
דף NaN

"דף" עבר את הבדיקה בלי מחיר, ו־undefined * 2 נתן NaN. ה־guard בודק רק name — וגם לא את הטיפוס שלו. type guard הוא כמו as שעטוף בפונקציה: אם הבדיקה לא שלמה, TypeScript "מאמין" לשקר. לכן כותבים בו בדיקה לכל שדה (כמו בשיעור), ובפרק 15 נותנים לספרייה (Zod) לכתוב אותה.

⚠️ טעויות נפוצות

P11-E72 · מה הטיפוס של err ב־catch? 🧠 הבנה רמה 2

💡 רמז 1

ב־JavaScript אפשר לזרוק כל דבר: throw "טקסט", ‏throw 42. מה TypeScript יכול להניח על err?

💡 רמז 2

תחת --strict, המשתנה של catch הוא unknown.

✅ פתרון
function risky(): number {
  if (Math.random() > 2) return 1;
  throw new RangeError("מחוץ לטווח");
}

try {
  risky();
} catch (err) {
  console.log(err.message);
  if (err instanceof Error) {
    console.log(err.message);
  }
  if (typeof err === "string") {
    console.log(err.toUpperCase());
  }
}
snippet.ts(9,15): error TS18046: 'err' is of type 'unknown'.

רק השורה הראשונה ב־catch נכשלת. err הוא unknown — בדיוק כמו JSON.parse בקוד בטוח — ולכן צריך narrowing: instanceof Error (פרק 8) או typeof. זה גם הבסיס ל־P11-E76.

⚠️ טעויות נפוצות
  • catch (err: any) — "פותר" את השגיאה, ומחזיר את הבעיה: err.message של throw "טקסט" הוא undefined.

P11-E73 · מתי as בסדר? 🧠 הבנה רמה 1

💡 רמז 1

שאל: האם אני באמת יודע יותר מבודק הטיפוסים — או שאני רק מקווה?

💡 רמז 2

סעיף 5 הוא as const — לא "תאמין לי", אלא "תסיק את הטיפוס הכי מדויק".

✅ פתרון
  1. לא. נתונים מהעולם — unknown ובדיקה (type guard, ובפרק 15 — Zod).
  2. סביר. אתה יודע על ה־HTML משהו ש־TypeScript לא יודע. ועדיין, אם מישהו ימחק את ה־input — תקבל null בזמן ריצה; בדיקה instanceof HTMLInputElement בטוחה יותר.
  3. תלוי. קובץ שאתה כתבת ונמצא בפרויקט — סיכון קטן. אבל קובץ הגדרות של שרת ישתנה בידי אנשים — עדיף לבדוק (P11-E77).
  4. לא בשום מקרה. "as כפול" הוא הודאה שהטיפוסים לא מתאימים. מתקנים את הסיבה.
  5. כן. as const לא מבטיח שקר — הוא מבקש מ־TypeScript להסיק readonly ["pending", "paid"] במקום string[].
⚠️ טעויות נפוצות
  • "as זה כמו המרה". לא — as לא משנה את הערך בזמן ריצה; הוא רק משנה את מה ש־TypeScript חושב.

P11-E12 · מספר מתוך unknown 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

if (typeof value === "number") return Number.isFinite(value) ? value : null;

💡 רמז 2

למחרוזת: trim, בדיקת ריק, Number(...), Number.isFinite.

✅ פתרון
// P11-E12
export function toNumber(value: unknown): number | null {
  if (typeof value === "number") {
    return Number.isFinite(value) ? value : null;
  }
  if (typeof value === "string") {
    const text = value.trim();
    if (text === "") {
      return null;
    }
    const n = Number(text);
    return Number.isFinite(n) ? n : null;
  }
  return null;
}

console.log(toNumber(" 12.5 "), toNumber(""), toNumber(true), toNumber(Infinity));
12.5 null null null

זה סוג הפונקציה שתכתוב בגבול של כל שרת: מה שנכנס הוא unknown, מה שיוצא — טיפוס בטוח.

⚠️ טעויות נפוצות
  • Number(value) ישר על unknown — Number(true) הוא 1, Number(null) הוא 0.

P11-E18 · type guard למשתמשים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

const data: unknown = JSON.parse(json) בתוך try.

💡 רמז 2

roles: Array.isArray(value.roles) && value.roles.every((r) => typeof r === "string").

✅ פתרון
// P11-E18
export type User = { id: number; email: string; roles: string[] };

export function isUser(value: unknown): value is User {
  return (
    typeof value === "object" &&
    value !== null &&
    "id" in value &&
    typeof value.id === "number" &&
    "email" in value &&
    typeof value.email === "string" &&
    "roles" in value &&
    Array.isArray(value.roles) &&
    value.roles.every((r: unknown) => typeof r === "string")
  );
}

export function parseUsers(json: string): { users: User[]; invalid: number } {
  let data: unknown;
  try {
    data = JSON.parse(json);
  } catch {
    throw new Error("הקלט אינו מערך JSON");
  }
  if (!Array.isArray(data)) {
    throw new Error("הקלט אינו מערך JSON");
  }
  const users = data.filter(isUser);
  return { users, invalid: data.length - users.length };
}

console.log(JSON.stringify(parseUsers('[{"id":1,"email":"a@b.c","roles":["admin"]},{"id":"2"}]')));
{"users":[{"id":1,"email":"a@b.c","roles":["admin"]}],"invalid":1}
⚠️ טעויות נפוצות
  • JSON.parse(json) as User[] — "עובר" בבדיקת טיפוסים, ומשתמש לא תקין זולג פנימה.

P11-E19 · Map מוקלד 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

עותק של Map: new Map(inv).

💡 רמז 2

inv.get(code) מחזיר number | undefined — TypeScript יכריח אותך לטפל ב־undefined.

✅ פתרון
// P11-E19
export type Result<T> = { ok: true; value: T } | { ok: false; error: string };
export type Inventory = Map<string, number>;

export function restock(inv: Inventory, code: string, qty: number): Inventory {
  const next = new Map(inv);
  next.set(code, (next.get(code) ?? 0) + qty);
  return next;
}

export function reserve(inv: Inventory, code: string, qty: number): Result<Inventory> {
  const current = inv.get(code);
  if (current === undefined) {
    return { ok: false, error: "מוצר לא קיים" };
  }
  if (current < qty) {
    return { ok: false, error: "אין מספיק במלאי" };
  }
  const next = new Map(inv);
  next.set(code, current - qty);
  return { ok: true, value: next };
}

export function lowStock(inv: Inventory, threshold: number): string[] {
  return [...inv].filter(([, qty]) => qty < threshold).map(([code]) => code).sort();
}

const inv = new Map([["A", 5], ["B", 1]]);
const r = reserve(inv, "A", 2);
console.log(r.ok && r.value.get("A"), inv.get("A"), lowStock(inv, 3));
3 5 [ 'B' ]
⚠️ טעויות נפוצות
  • inv.get(code) - qty — שגיאת טיפוסים (undefined), ובצדק: מוצר לא קיים היה נותן NaN.

P11-E23 · as שמסתיר באג 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 2

✅ פתרון
// P11-E23: validation במקום as
export type Settings = { theme: "light" | "dark"; pageSize: number };

export function loadSettings(json: string): Settings {
  const data: unknown = JSON.parse(json);
  if (typeof data !== "object" || data === null || Array.isArray(data)) {
    throw new Error("הגדרה לא תקינה: root");
  }

  let theme: Settings["theme"] = "light";
  if ("theme" in data) {
    if (data.theme !== "light" && data.theme !== "dark") {
      throw new Error("הגדרה לא תקינה: theme");
    }
    theme = data.theme;
  }

  let pageSize = 20;
  if ("pageSize" in data) {
    const p = data.pageSize;
    if (typeof p !== "number" || !Number.isInteger(p) || p < 1 || p > 100) {
      throw new Error("הגדרה לא תקינה: pageSize");
    }
    pageSize = p;
  }

  return { theme, pageSize };
}

console.log(loadSettings('{"theme":"dark"}'));
try {
  loadSettings('{"pageSize":"20"}');
} catch (err) {
  console.log((err as Error).message);
}
{ theme: 'dark', pageSize: 20 }
הגדרה לא תקינה: pageSize

P11-E74 · מערך של מחרוזות? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

ב־tagsOf: if (isStringArray(value)) return value.map((t) => t.toLowerCase()); — בתוך ה־if, ‏value הוא string[].

✅ פתרון
// P11-E74: מערך של מחרוזות?
export function isStringArray(value: unknown): value is string[] {
  return Array.isArray(value) && value.every((x) => typeof x === "string");
}

export function tagsOf(value: unknown): string[] {
  if (isStringArray(value)) return value.map((t) => t.toLowerCase());
  return [];
}

P11-E75 · משימה מ־JSON 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

let data: unknown; try { data = JSON.parse(json); } catch { return null; } — ואז שרשרת בדיקות כמו ב־isProduct מהשיעור.

💡 רמז 2

ל־priority: "priority" in data → אם כן, data.priority === "low" || data.priority === "high". בסוף: const todo: Todo = { title: data.title, done: data.done }; if (...) todo.priority = data.priority;

✅ פתרון
// P11-E75: משימה מ־JSON
export type Todo = { title: string; done: boolean; priority?: "low" | "high" };

export function parseTodo(json: string): Todo | null {
  let data: unknown;
  try {
    data = JSON.parse(json);
  } catch {
    return null;
  }
  if (typeof data !== "object" || data === null || Array.isArray(data)) return null;
  if (!("title" in data) || typeof data.title !== "string" || data.title.trim() === "") return null;
  if (!("done" in data) || typeof data.done !== "boolean") return null;
  const todo: Todo = { title: data.title, done: data.done };
  if ("priority" in data) {
    if (data.priority !== "low" && data.priority !== "high") return null;
    todo.priority = data.priority;
  }
  return todo;
}

console.log(parseTodo('{"title": "לקנות חלב", "done": false, "extra": 1}'));
console.log(parseTodo('{"title": "x", "done": true, "priority": "high"}'));
console.log(parseTodo('{"title": "x", "done": "no"}'), parseTodo("{oops"), parseTodo("[]"));
{ title: 'לקנות חלב', done: false }
{ title: 'x', done: true, priority: 'high' }
null null null

שים לב איך TypeScript "לומד" לאורך הבדיקות: אחרי typeof data.title !== "string" עם return, בשורות הבאות data.title הוא string. ואחרי הבדיקה של priority — הוא "low" | "high", ולכן ההשמה ל־todo.priority מותרת בלי as.

⚠️ טעויות נפוצות
  • להחזיר את data עצמו — שדות נוספים מה־JSON (כמו extra) עוברים הלאה.
  • לשכוח Array.isArray — מערך הוא "object".

P11-E76 · הודעה מכל שגיאה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

✅ פתרון
// P11-E76: הודעה מכל שגיאה
export function errorMessage(err: unknown): string {
  if (err instanceof Error) return err.message;
  if (typeof err === "string" && err !== "") return err;
  if (typeof err === "object" && err !== null && "message" in err && typeof err.message === "string") {
    return err.message;
  }
  return "שגיאה לא ידועה";
}

  }

  • (err as Error).message — עובד רק אם באמת נזרק Error.

P11-E77 · הגדרות שרת — עם הודעת שגיאה מדויקת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

כמו P11-E75, אבל במקום return null — throw עם שם השדה. כך מי שכתב קובץ הגדרות שבור יודע בדיוק מה לתקן.

💡 רמז 2

✅ פתרון
// P11-E77: הגדרות שרת — עם הודעת שגיאה מדויקת
export type Config = { host: string; port: number; debug: boolean };

export function parseConfig(raw: unknown): Config {
  if (typeof raw !== "object" || raw === null || Array.isArray(raw)) {
    throw new Error("ההגדרות חייבות להיות אובייקט");
  }
  if (!("host" in raw) || typeof raw.host !== "string" || raw.host.trim() === "") {

💡 רמז 1

💡 רמז 2

on<T extends AppEvent["type"]>(type: T, handler: (e: Extract<AppEvent, { type: T }>) => void). בפנים, שומרים ב־Map של type ← מערך פונקציות; כדי לשמור אותן במבנה אחיד, אפשר לעטוף: (e: AppEvent) => handler(e as Extract<...>) — as מוצדק כאן כי ה־emit מפעיל רק לפי type.

✅ פתרון
// P11-E24: event bus מוקלד
export type AppEvent =
  | { type: "order.created"; orderId: number; total: number }
  | { type: "order.paid"; orderId: number; amount: number }
  | { type: "user.signedUp"; userId: number; email: string };

type EventOf<T extends AppEvent["type"]> = Extract<AppEvent, { type: T }>;

export function createBus() {
  const handlers = new Map<AppEvent["type"], ((e: AppEvent) => void)[]>();
  const log: AppEvent[] = [];

  function on<T extends AppEvent["type"]>(type: T, handler: (e: EventOf<T>) => void): void {
    const list = handlers.get(type) ?? [];
    list.push((e) => handler(e as EventOf<T>));
    handlers.set(type, list);
  }

  function emit(event: AppEvent): void {
    log.push(event);
    for (const handler of handlers.get(event.type) ?? []) {
      handler(event);
    }
  }

  function history(): AppEvent[] {
    return [...log];
  }

  return { on, emit, history };
}

💡 רמז 1

✅ פתרון
// P11-E25: mini validation library
export type Result<T> = { ok: true; value: T } | { ok: false; error: string };
export type Validator<T> = (value: unknown, path?: string) => Result<T>;

const fail = (path: string | undefined, msg: string): { ok: false; error: string } => ({
  ok: false,
  error: path ? `${path}: ${msg}` : msg,
});

export function string(opts: { min?: number; max?: number } = {}): Validator<string> {
  return (value, path) => {
    if (typeof value !== "string") return fail(path, "חייב להיות מחרוזת");
    if (opts.min !== undefined && value.length < opts.min) return fail(path, `לפחות ${opts.min} תווים`);
    if (opts.max !== undefined && value.length > opts.max) return fail(path, `לכל היותר ${opts.max} תווים`);
    return { ok: true, value };
  };
}

export function number(opts: { min?: number; max?: number; integer?: boolean } = {}): Validator<number> {
  return (value, path) => {
    if (typeof value !== "number" || !Number.isFinite(value)) return fail(path, "חייב להיות מספר");
    if (opts.integer && !Number.isInteger(value)) return fail(path, "חייב להיות מספר שלם");
    if (opts.min !== undefined && value < opts.min) return fail(path, `לפחות ${opts.min}`);
    if (opts.max !== undefined && value > opts.max) return fail(path, `לכל היותר ${opts.max}`);
    return { ok: true, value };
  };
}

export function boolean(): Validator<boolean> {
  return (value, path) => (typeof value === "boolean" ? { ok: true, value } : fail(path, "חייב להיות true או false"));
}

export function optional<T>(v: Validator<T>): Validator<T | undefined> {
  return (value, path) => (value === undefined ? { ok: true, value: undefined } : v(value, path));
}

export function array<T>(v: Validator<T>): Validator<T[]> {
  return (value, path) => {
    if (!Array.isArray(value)) return fail(path, "חייב להיות מערך");
    const out: T[] = [];
    for (let i = 0; i < value.length; i++) {
      const r = v(value[i], `${path ?? ""}[${i}]`);
      if (!r.ok) return r;
      out.push(r.value);
    }
    return { ok: true, value: out };
  };
}

export function object<S extends Record<string, Validator<unknown>>>(
  shape: S
): Validator<{ [K in keyof S]: S[K] extends Validator<infer T> ? T : never }> {
  return (value, path) => {
    if (typeof value !== "object" || value === null || Array.isArray(value)) return fail(path, "חייב להיות אובייקט");
    const input = value as Record<string, unknown>;
    const out: Record<string, unknown> = {};
    for (const key of Object.keys(shape)) {
      const r = shape[key](input[key], path ? `${path}.${key}` : key);
      if (!r.ok) return r;
      if (r.value !== undefined) out[key] = r.value;
    }
    return { ok: true, value: out as { [K in keyof S]: S[K] extends Validator<infer T> ? T : never } };
  };
}

✅ פתרון
// P11-E28: שליפת משתמשים
export type User = { id: number; name: string };

export async function findUsers(
  ids: number[],
  getUser: (id: number) => Promise<User | undefined>
): Promise<{ found: User[]; missing: number[] }> {
  const unique = [...new Set(ids)];
  const results = await Promise.all(unique.map(getUser));
  const found: User[] = [];
  const missing: number[] = [];
  unique.forEach((id, i) => {
    const user = results[i];
    if (user) {
      found.push(user);
    } else {
      missing.push(id);
    }
  });
  return { found, missing };
}

const db = new Map<number, User>([
  [1, { id: 1, name: "דנה" }],
  [3, { id: 3, name: "עומר" }],
]);

new Set(ids) מסיר כפילויות ושומר על הסדר של ההופעה הראשונה, ו־[...set] מחזיר אותו למערך. זה חוסך בקשה כפולה למסד, ובמערכת אמיתית — גם שורה כפולה בתשובה.

unique.map(getUser) מעביר את הפונקציה עצמה ל־map. זה בטוח כאן, כי getUser מקבלת פרמטר אחד. (map שולחת גם אינדקס ומערך, ופונקציה עם פרמטר שני אופציונלי הייתה מקבלת אותם בטעות. ב־parseInt זה מפורסם: ["10", "10"].map(parseInt) נותן [10, NaN].)

ה־await בשורת ההדפסה עובד בלי async function מסביב, כי קובץ .ts שיש בו export רץ כ־ES Module, ושם מותר top-level await.

  • for (const id of ids) { const u = await getUser(id); ... } — אחד אחרי השני. הבודק מודד, ונכשל.
  • results.filter((u) => u !== undefined) בשביל found — עובד, אבל אז צריך לעבור שוב כדי למצוא את missing, ובגרסאות TypeScript ישנות הטיפוס נשאר (User | undefined)[].
