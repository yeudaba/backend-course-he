P11-E65 · Result או throw?

🧠 הבנהרמה 2⏱ 15 דק׳ידע נדרש: פרק 8, שיעור 3

שתי גרסאות של אותה פונקציה:

// א — עם throw (פרק 8)
function parseAgeA(text: string): number {
  const n = Number(text);
  if (!Number.isInteger(n) || n < 0) throw new RangeError(`"${text}" אינו גיל`);
  return n;
}

// ב — עם discriminated union (P11-E17)
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
function parseAgeB(text: string): Result<number> {
  const n = Number(text);
  if (!Number.isInteger(n) || n < 0) return { ok: false, error: `"${text}" אינו גיל` };
  return { ok: true, value: n };
}
  1. מי שקורא ל־parseAgeA שכח try/catch. מה קורה? והאם TypeScript מזהיר?
  2. מי שקורא ל־parseAgeB כתב parseAgeB(t).value + 1. מה קורה?
  3. לכל מצב — איזו גרסה מתאימה יותר, ולמה: (א) קלט של משתמש בטופס, שבו "לא תקין" זה מצב רגיל. (ב) קובץ הגדרות של השרת, שאם הוא שבור — אין טעם להמשיך.

🔗 איך זה מתחבר: פרק 8: throw עוצר את הזרימה ומטפס עד catch. השיעור: union עם שדה מבחין (ok) הופך את הכישלון לחלק מהטיפוס — ו־TypeScript מכריח לבדוק.
