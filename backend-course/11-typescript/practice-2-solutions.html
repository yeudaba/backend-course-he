P11-E45 · readonly — כמה עמוק? 🧠 הבנה רמה 2

💡 רמז 1

💡 רמז 2

אחרי order.coupon = "VIP", האם TypeScript "זוכר" שיש ערך? (נסה — התשובה אולי תפתיע.)

✅ פתרון
type Order = {
  readonly id: number;
  readonly items: string[];
  coupon?: string;
};

const order: Order = { id: 1, items: ["עט"] };
order.id = 2;
order.items = ["מחק"];
order.items.push("מחק");
order.coupon = "VIP";
const code = order.coupon.toUpperCase();
snippet.ts(8,7): error TS2540: Cannot assign to 'id' because it is a read-only property.
snippet.ts(9,7): error TS2540: Cannot assign to 'items' because it is a read-only property.

שתי שגיאות: השמה ל־id ול־items. אבל push עובר: readonly הוא "רדוד" — השדה מצביע תמיד לאותו מערך, אבל את המערך עצמו מותר לשנות. (למערך שאסור לשנות יש טיפוס נפרד: readonly string[].) והשורה האחרונה עוברת כי TypeScript ראה את ההשמה שורה אחת קודם — הוא עוקב אחרי הקוד, לא רק אחרי ההגדרה.

⚠️ טעויות נפוצות

P11-E46 · שדה מיותר — למה פה כן ושם לא? 🧠 הבנה רמה 2

💡 רמז 1

TypeScript בודק "שדה מיותר" רק כשכותבים את האובייקט ישירות במקום שבו הוא מושם (object literal) — כי שם זו כנראה שגיאת כתיב.

💡 רמז 2

משתנה שכבר קיים בודקים לפי השאלה "יש לו את כל מה ש־Point צריך?" — ולא "אין לו כלום חוץ מזה?".

✅ פתרון
type Point = { x: number; y: number };

const a: Point = { x: 1, y: 2, label: "A" };

const withLabel = { x: 1, y: 2, label: "B" };
const b: Point = withLabel;

function show(p: Point): string {
  return `(${p.x}, ${p.y})`;
}
show(withLabel);
show({ x: 3, y: 4, z: 5 });
snippet.ts(3,32): error TS2353: Object literal may only specify known properties, and 'label' does not exist in type 'Point'.
snippet.ts(12,20): error TS2353: Object literal may only specify known properties, and 'z' does not exist in type 'Point'.

השגיאות רק באובייקטים שנכתבו במקום. משתנה עם שדות נוספים מתאים ל־Point — יש לו x ו־y, וזה כל מה ש־show צריכה. TypeScript בודק צורה ("structural typing"): מתאים כל מה שיש לו את השדות הנדרשים.

⚠️ טעויות נפוצות
  • לחשוב שהטיפוס מבטיח שאין שדות נוספים בזמן ריצה. בדיוק בגלל זה toPublic ב־P11-E26 בונה אובייקט חדש — ולא סומך על הטיפוס שיסתיר את passwordHash.

P11-E47 · callback שמחזיר טיפוס לא נכון 🧠 הבנה רמה 2

💡 רמז 1

fn: (item: Item) => number — הטיפוס של i מוסק מכאן, וגם מה שה־callback חייב להחזיר.

💡 רמז 2

callback שמקבל פחות פרמטרים — בסדר (מתעלם מהשאר). יותר פרמטרים ממה שהטיפוס מבטיח — שגיאה.

✅ פתרון
type Item = { price: number; qty?: number };

function applyAll(items: Item[], fn: (item: Item) => number): number[] {
  return items.map(fn);
}

const items: Item[] = [{ price: 10 }, { price: 5, qty: 3 }];
applyAll(items, (i) => i.price * (i.qty ?? 1));
applyAll(items, (i) => i.price.toFixed(2));
applyAll(items, (i) => i.qty * 2);
applyAll(items, () => 0);
applyAll(items, (i, index) => index);
snippet.ts(9,24): error TS2322: Type 'string' is not assignable to type 'number'.
snippet.ts(10,24): error TS18048: 'i.qty' is possibly 'undefined'.
snippet.ts(12,17): error TS2345: Argument of type '(i: any, index: any) => any' is not assignable to parameter of type '(item: Item) => number'.
  Target signature provides too few arguments. Expected 2 or more, but got 1.
snippet.ts(12,18): error TS7006: Parameter 'i' implicitly has an 'any' type.
snippet.ts(12,21): error TS7006: Parameter 'index' implicitly has an 'any' type.
  1. הראשונה תקינה.
  2. toFixed מחזיר מחרוזת — וה־callback חייב להחזיר מספר.
  3. i.qty אופציונלי — יכול להיות undefined.
  4. () => 0 תקין: מותר להתעלם מהפרמטר.
  5. ה־callback מבקש פרמטר שני, אבל לפי הטיפוס אף אחד לא מבטיח לתת אותו.
⚠️ טעויות נפוצות
  • לכתוב (i: any) => ... כדי "להשתיק" — מאבדים בדיוק את הבדיקה שתפסה את השגיאות כאן.

P11-E48 · מה נותן await? 🧠 הבנה רמה 2

💡 רמז 1

טבלת השיעור: פונקציה אסינכרונית מחזירה Promise<טיפוס>, ו־await "פותח" את ה־Promise.

💡 רמז 2

?. על משהו שיכול להיות null נותן undefined — מה הטיפוס של התוצאה?

✅ פתרון
type User = { id: number; name: string };

async function findUser(id: number): Promise<User | null> {
  return id === 1 ? { id: 1, name: "דנה" } : null;
}

async function main() {
  const p = findUser(1);
  console.log(p.name);
  const user = await findUser(1);
  console.log(user.name);
  console.log(user?.name ?? "אין משתמש");
  const id: number = (await findUser(2))?.id;
}
snippet.ts(9,17): error TS2339: Property 'name' does not exist on type 'Promise<User | null>'.
snippet.ts(11,15): error TS18047: 'user' is possibly 'null'.
snippet.ts(13,9): error TS2322: Type 'number | undefined' is not assignable to type 'number'.
  Type 'undefined' is not assignable to type 'number'.

שלוש שגיאות, שלושה באגים אמיתיים: גישה ל־Promise כאילו הוא משתמש (שכחת await), גישה למשתמש שאולי לא נמצא, ו־?.id שיכול להיות undefined נכנס למשתנה שהובטח לו מספר. ה־| null בחתימה הוא מה שמכריח את כל מי שקורא ל־findUser להחליט מה עושים כשאין משתמש.

⚠️ טעויות נפוצות
  • להסיר את | null מהחתימה "כדי שיהיה נוח". הפונקציה עדיין תחזיר null — רק שעכשיו אף אחד לא יבדוק.

P11-E49 · type או interface? 🧠 הבנה רמה 1

💡 רמז 1

💡 רמז 2

סעיף 3 בשיעור: מה type יכול להיות ש־interface לא?

✅ פתרון
type Customer = {
  id: number;
  name: string;
};
type VipCustomer = Customer & {
  discountPercent: number;
};

type OrderStatus = "pending" | "paid";

snippet.ts(13,7): error TS2322: Type '{ id: number; name: string; }' is not assignable to type 'VipCustomer'.
  Property 'discountPercent' is missing in type '{ id: number; name: string; }' but required in type '{ discountPercent: number; }'.
  1. Customer & { discountPercent: number } — עובד כמו extends. (השגיאה בפלט מוכיחה ש־VipCustomer באמת דורש את השדה הנוסף; ו־vip מתאים גם ל־Customer.)

  3. לא באג — שניהם עובדים. הכלל בקורס: type כברירת מחדל, interface לצורה של "מחלקה" (פרק 12). בצוות — הולכים לפי מה שכבר מקובל בקוד.
⚠️ טעויות נפוצות
  • לבזבז זמן ב־code review על type מול interface כשאין הבדל בהתנהגות.

  readonly id: number;
  name: string;
  price: number;
  tags: string[];
  stock?: number;
};

  return { id, name, price, tags: [] };

  return (p.stock ?? 0) > 0;

P11-E13 · עגלה מוקלדת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

readonly CartItem[] אוסר push — וזה בדיוק הרעיון.

💡 רמז 2

addItem: cart.some(...) ? cart.map((it) => it.sku === item.sku ? { ...it, qty: it.qty + item.qty } : it) : [...cart, item].

✅ פתרון
// P11-E13
export type CartItem = { sku: string; name: string; price: number; qty: number };

export function cartTotal(cart: readonly CartItem[]): number {
  return Math.round(cart.reduce((s, it) => s + it.price * it.qty, 0) * 100) / 100;
}

export function addItem(cart: readonly CartItem[], item: CartItem): CartItem[] {
  if (cart.some((it) => it.sku === item.sku)) {
    return cart.map((it) => (it.sku === item.sku ? { ...it, qty: it.qty + item.qty } : it));
  }
  return [...cart, item];
}

export function removeSku(cart: readonly CartItem[], sku: string): CartItem[] {
  return cart.filter((it) => it.sku !== sku);
}

const cart = addItem(addItem([], { sku: "A", name: "עט", price: 2.5, qty: 2 }), { sku: "A", name: "עט", price: 2.5, qty: 1 });
console.log(cart, cartTotal(cart));
[ { sku: 'A', name: 'עט', price: 2.5, qty: 3 } ] 7.5
⚠️ טעויות נפוצות

P11-E14 · groupBy גנרי 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P11-E14
export function groupBy<T>(items: T[], keyFn: (item: T) => string): Record<string, T[]> {
  const result: Record<string, T[]> = {};
  for (const item of items) {
    const key = keyFn(item);
    (result[key] ??= []).push(item);
  }
  return result;
}

export function indexBy<T, K>(items: T[], keyFn: (item: T) => K): Map<K, T> {
  return new Map(items.map((item) => [keyFn(item), item]));
}

export function sumBy<T>(items: T[], fn: (item: T) => number): number {
  return items.reduce((s, item) => s + fn(item), 0);
}

const orders = [{ id: 1, status: "paid", total: 10 }, { id: 2, status: "new", total: 5 }, { id: 3, status: "paid", total: 7 }];
console.log(Object.keys(groupBy(orders, (o) => o.status)), indexBy(orders, (o) => o.id).get(2)?.total, sumBy(orders, (o) => o.total));
[ 'paid', 'new' ] 5 22

(result[key] ??= [] — "אם עוד אין, צור מערך ריק" — קיצור שימושי.)

⚠️ טעויות נפוצות

P11-E21 · find יכול להחזיר undefined 🤖 💻 כתיבת קוד 🤖 רמה 4

✅ פתרון
// P11-E21: מתוקן
export type CatalogItem = { sku: string; price: number };

export function priceOf(catalog: CatalogItem[], sku: string): number | null {
  return catalog.find((c) => c.sku === sku)?.price ?? null;
}

export function cartPrice(catalog: CatalogItem[], skus: string[]): number {
  let total = 0;
  for (const sku of skus) {
    const price = priceOf(catalog, sku);
    if (price === null) {
      throw new Error(`מוצר לא קיים: ${sku}`);
    }
    total += price;
  }
  return total;
}

console.log(cartPrice([{ sku: "A", price: 10 }], ["A", "A"]));
20

P11-E26 · טיפוסים מטיפוסים: Omit, ‏Pick, ‏Partial, ‏Record 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הטיפוסים הם שורה אחת כל אחד: export type PublicUser = Omit<User, "passwordHash">;. ב־UserPatch עוטפים: Partial<Pick<...>>. ‏User["role"] הוא הטיפוס של השדה role, כלומר "admin" | "member".

💡 רמז 2

toPublic: const { passwordHash, ...rest } = u; return rest;. ‏applyPatch: { ...u, ...patch }. ‏countRoles: מתחילים מ־{ admin: 0, member: 0 } ומגדילים בלולאה.

✅ פתרון
// P11-E26: טיפוסים מטיפוסים
export type User = {
  id: number;
  name: string;
  email: string;
  passwordHash: string;
  role: "admin" | "member";
};

export type PublicUser = Omit<User, "passwordHash">;
export type UserPatch = Partial<Pick<User, "name" | "email">>;
export type RoleCounts = Record<User["role"], number>;

export function toPublic(u: User): PublicUser {
  const { passwordHash, ...rest } = u;
  return rest;
}

export function applyPatch(u: User, patch: UserPatch): User {
  return { ...u, ...patch };
}

export function countRoles(users: User[]): RoleCounts {
  const counts: RoleCounts = { admin: 0, member: 0 };
  for (const u of users) {
    counts[u.role]++;
  }
  return counts;
}

const dana: User = { id: 1, name: "דנה", email: "dana@x.com", passwordHash: "h1", role: "admin" };
console.log(toPublic(dana));
console.log(applyPatch(dana, { name: "דנה כ." }).name);
console.log(countRoles([dana]));
{ id: 1, name: 'דנה', email: 'dana@x.com', role: 'admin' }
דנה כ.
{ admin: 1, member: 0 }

כל ארבעת הטיפוסים החדשים נגזרים מ־User. אם מחר יתווסף ל־User שדה phone, הוא יופיע אוטומטית ב־PublicUser. ואם יתווסף role שלישי, countRoles תפסיק להתקמפל עד שתוסיף אותו ל־{ admin: 0, member: 0 }. בדיוק את זה רוצים: TypeScript מזכיר לך את המקום ששכחת.

ב־toPublic, ה־destructuring עם ...rest (פרק 7) "מוציא" את passwordHash ואוסף את כל השאר לאובייקט חדש. ובפרק 20 תראה את אותם טיפוסים ב־NestJS: ‏PartialType ו־OmitType ל־DTOs.

⚠️ טעויות נפוצות

// P11-E56: אינדקס לפי מזהה
export type Product = { id: number; name: string; price: number };

export function indexById(products: Product[]): Map<number, Product> {
  const index = new Map<number, Product>();
  for (const p of products) {
    if (index.has(p.id)) throw new Error(`מזהה כפול: ${p.id}`);
    index.set(p.id, p);
  }
  return index;
}

export function missingIds(ids: number[], index: Map<number, Product>): number[] {
  const missing = new Set<number>();
  for (const id of ids) {
    if (!index.has(id)) missing.add(id);
  }
  return [...missing];
}

export function orderTotal(lines: { id: number; qty: number }[], index: Map<number, Product>): number {
  let total = 0;
  for (const line of lines) {
    const p = index.get(line.id);
    if (!p) throw new Error(`אין מוצר ${line.id}`);
    total += p.price * line.qty;
  }
  return total;
}

  { id: 1, name: "עט", price: 5 },
