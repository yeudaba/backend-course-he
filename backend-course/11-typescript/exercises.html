P11-E26 · טיפוסים מטיפוסים: Omit, ‏Pick, ‏Partial, ‏Record 🤖

✍️ מאפסרמה 2⏱ 15 דק׳ידע נדרש: שיעור 2

לעיתים קרובות צריך טיפוס שהוא "כמעט" טיפוס קיים: משתמש בלי הסיסמה, או עדכון שבו כל השדות אופציונליים. אפשר להעתיק את השדות ידנית, אבל אז כל שינוי ב־User מחייב לעדכן כמה מקומות. ב־TypeScript יש utility types שבונים טיפוס חדש מטיפוס קיים:

כותביםמקבלים
Omit<User, "passwordHash">כל השדות של User, חוץ מ־passwordHash
Pick<User, "name" | "email">רק name ו־email
Partial<T>כל השדות של T, כאופציונליים
Record<"a" | "b", number>{ a: number; b: number }

כתוב קובץ שמייצא (export):

  • type User — id (מספר), name, email, passwordHash (מחרוזות), role ("admin" או "member").
  • type PublicUser — User בלי passwordHash (מה שמותר לשלוח ללקוח). השתמש ב־Omit.
  • type UserPatch — עדכון: רק name ו־email, ושניהם אופציונליים. השתמש ב־Partial וב־Pick.
  • type RoleCounts — מספר לכל role. השתמש ב־Record וב־User["role"].
  • toPublic(u: User): PublicUser — עותק בלי passwordHash.
  • applyPatch(u: User, patch: UserPatch): User — עותק מעודכן.
  • countRoles(users: User[]): RoleCounts — כמה מכל role (גם 0).

הבודק מריץ את הפונקציות, וגם בודק את הטיפוסים: למשל ש־{ role: "admin" } לא מתקבל כ־UserPatch.

P11-E27 · משך זמן: מטקסט למספר ובחזרה 🤖

🔁 חזרהרמה 3⏱ 15 דק׳ידע נדרש: שיעור 3

🔁 חזרה על split, ‏endsWith, ‏slice ו־Number.isInteger (פרקים 2 ו־6), על לולאה עם return מוקדם (פרקים 4–5), ועל Math.floor ו־% (פרק 2) — עם טיפוסים. כתוב וייצא שתי פונקציות:

  • parseDuration(text: string): number | null — מחזירה דקות. הטקסט הוא מילים מופרדות ברווחים (אחד או יותר). כל מילה היא מספר שלם ואחריו h (שעות) או m (דקות). אם יש מילה לא תקינה, או שאין אף מילה — null.
  • formatDuration(minutes: number): string — הכיוון ההפוך: 90 ← "1h 30m", ‏120 ← "2h", ‏45 ← "45m", ‏0 ← "0m".
parseDuration("1h 30m");  // 90
parseDuration(" 2h ");    // 120
parseDuration("15m 1h");  // 75 — הסדר לא משנה
parseDuration("1.5h");    // null — רק מספרים שלמים
parseDuration("abc");     // null
parseDuration("");        // null

הבודק בודק גם את הטיפוסים: מי שקורא ל־parseDuration חייב לבדוק null לפני שהוא משתמש בתוצאה כמספר.

P11-E03 · מה הטיפוס כאן?

רמה 1⏱ 10 דק׳ידע נדרש: שיעור 3

לכל הערה (A–E) — מה הטיפוס של value באותה נקודה, לפי TypeScript?

function show(value: string | number | null | string[]) {
  // A
  if (value === null) {
    return "ריק";
  }
  // B
  if (Array.isArray(value)) {
    // C
    return value.join(",");
  }
  if (typeof value === "number") {
    // D
    return value.toFixed(2);
  }
  // E
  return value.trim();
}

P11-E25 · אתגר: mini-Zod 🤖

רמה 5⏱ 40 דק׳ידע נדרש: כל הפרק

בנה ספריית validation זעירה. בקובץ 11-typescript/starter/P11-E25.ts (הטיפוס Result ו־Validator<T> = (value: unknown, path?: string) => Result<T> מוגדרים) השלם:

  • string({ min?, max? }), number({ min?, max?, integer? }), boolean() — כל אחת מחזירה Validator.
  • optional(v) — undefined מותר.
  • array(v) — מערך שכל איבריו עוברים את v.
  • object(shape) — shape הוא אובייקט שם ← validator; מחזיר Result של אובייקט חדש רק עם השדות שב־shape.

הודעות שגיאה כוללות נתיב: "items[1].qty: חייב להיות מספר שלם". רשימת ההודעות המדויקות — בקובץ.
