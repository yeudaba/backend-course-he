P11-E23 · as שמסתיר באג 🤖

בקובץ 11-typescript/starter/P11-E23.ts, loadSettings(json) משתמשת ב־JSON.parse(json) as Settings. כשמגיע קובץ ישן עם "pageSize": "20" (מחרוזת) או בלי theme — הקוד ממשיך עם ערכים שגויים. החלף את ה־as בבדיקה אמיתית: שדות חסרים ← ברירות מחדל (theme: "light", pageSize: 20); שדה קיים מהסוג הלא נכון או מחוץ לטווח (pageSize 1–100, theme רק "light"/"dark") ← זריקת Error(הגדרה לא תקינה: ${field}).

P11-E28 · שליפת משתמשים: נמצאו וחסרים 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 15 דק׳ידע נדרש: שיעור 4

🔁 חזרה על Promise.all (פרק 10) ועל Set (פרק 7), עם טיפוסים. כתוב קובץ שמייצא:

  • type User = { id: number; name: string }.
  • async function findUsers(ids: number[], getUser: (id: number) => Promise<User | undefined>): Promise<{ found: User[]; missing: number[] }>

הפונקציה מבקשת את כל המשתמשים במקביל. ‏getUser מחזירה undefined כשאין משתמש כזה. מחזירים את מי שנמצא ב־found ואת ה־ids שלא נמצאו ב־missing. שניהם לפי הסדר שב־ids. id שמופיע כמה פעמים — מבקשים ומחזירים פעם אחת.

// במסד: 1 → דנה, 3 → עומר
await findUsers([3, 2, 1, 3], getUser);
// { found: [{ id: 3, name: "עומר" }, { id: 1, name: "דנה" }], missing: [2] }

% node 11-typescript/starter/P11-E28.ts
% npm run check P11-E28

P11-E25 · אתגר: mini-Zod 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 40 דק׳ידע נדרש: כל הפרק

בנה ספריית validation זעירה. בקובץ 11-typescript/starter/P11-E25.ts (הטיפוס Result ו־Validator<T> = (value: unknown, path?: string) => Result<T> מוגדרים) השלם:

  • string({ min?, max? }), number({ min?, max?, integer? }), boolean() — כל אחת מחזירה Validator.
  • optional(v) — undefined מותר.
  • array(v) — מערך שכל איבריו עוברים את v.
  • object(shape) — shape הוא אובייקט שם ← validator; מחזיר Result של אובייקט חדש רק עם השדות שב־shape.

הודעות שגיאה כוללות נתיב: "items[1].qty: חייב להיות מספר שלם". רשימת ההודעות המדויקות — בקובץ.
