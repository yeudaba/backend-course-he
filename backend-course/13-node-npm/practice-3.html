P13-E62 · required ו־optional 🤖

💻 כתיבת קוד 🤖🔥 חימוםרמה 2⏱ 10 דק׳ידע נדרש: שיעור 3

P13-E63 · בודק לקובץ .env 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 3

טעויות בקובץ .env שקטות: Node פשוט קורא משהו אחר ממה שהתכוונת. כתוב וייצא lintEnv(text) שמחזירה מערך אזהרות (מחרוזות), לפי סדר השורות — בכל שורה לכל היותר אזהרה אחת, לפי סדר הבדיקות:

  • שורות ריקות והערות (# אחרי רווחים) — תקינות.
  • אין = ← "שורה N: חסר =".
  • שם (מה שלפני ה־= הראשון, אחרי trim) שאינו UPPER_SNAKE_CASE (/^[A-Z][A-Z0-9_]*$/) ← "שורה N: שם לא תקין: <name>".
  • השם כבר הופיע ← "שורה N: KEY מוגדר שוב (קודם בשורה M)".
  • ערך (אחרי trim) שמתחיל במירכאה ולא נגמר באותה מירכאה ← "שורה N: מירכאות לא סגורות".
  • ערך בלי מירכאות שיש בו רווח ← "שורה N: ערך עם רווחים בלי מירכאות".

מספרי השורות מתחילים ב־1.

lintEnv('PORT=8080\nport=9\nAPP_NAME=Dana Shop\nPORT=1\nTITLE="Hi\n');
// ["שורה 2: שם לא תקין: port", "שורה 3: ערך עם רווחים בלי מירכאות",
//  "שורה 4: PORT מוגדר שוב (קודם בשורה 1)", "שורה 5: מירכאות לא סגורות"]

P13-E64 · מה חסר לי ב־.env? 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 15 דק׳ידע נדרש: שיעור 3

אחרי git pull, חבר הוסיף משתנה חדש ל־.env.example — ואצלך השרת לא עולה. כתוב וייצא envDiff(exampleText, envText) שמחזירה { missing, empty, extra }:

  • missing — מפתחות שב־example ואין אותם ב־.env.
  • empty — מפתחות שב־example, קיימים ב־.env אבל עם ערך ריק.
  • extra — מפתחות שב־.env ואין ב־example (אולי כבר לא בשימוש — או שחסר תיעוד).
  • כל רשימה לפי סדר ההופעה בקובץ שלה, בלי כפילויות. הערות ושורות ריקות — מדלגים. ערך במירכאות ריקות ("") — נחשב ריק.

P13-E65 · config מקונן וקפוא לגמרי 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

P13-E66 · config כמודול: מתי הוא רץ?

🧠 הבנהרמה 2⏱ 15 דק׳ידע נדרש: פרק 8, שיעור 3

function required(name) {
  const value = process.env[name];
  if (value === undefined || value.trim() === "") throw new Error(`חסר משתנה סביבה: ${name}`);

}

P13-E69 · הפניות בין משתנים ב־.env 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 2, פרק 8, שיעור 3

כלים רבים מאפשרים ב־.env להפנות למשתנה אחר: DATABASE_URL=postgres://${DB_USER}@${DB_HOST}/shop. כתוב וייצא expand(vars):

  • vars — אובייקט של מחרוזות (כמו שיוצא מ־parseDotenv, P13-E10). מחזירה אובייקט חדש שבו כל ${NAME} בכל ערך מוחלף בערך של NAME.
  • הפניה לערך שגם בו יש הפניות — מותרת (מרחיבים עד הסוף).
  • שם שלא קיים ב־vars ← throw new Error(משתנה לא מוגדר: ${NAME} (ב־${KEY})).
  • מעגל (A=${B}, ‏B=${A}) ← throw new Error(הפניה מעגלית: ${KEY}) — כש־KEY הוא המפתח שבו התגלה המעגל.
  • שם חוקי: אותיות, ספרות ו־_ (/\$\{(\w+)\}/g). $NAME בלי סוגריים — לא מוחלף.
expand({ DB_USER: "dana", DB_HOST: "localhost", DATABASE_URL: "postgres://${DB_USER}@${DB_HOST}/shop" });
// { DB_USER: "dana", DB_HOST: "localhost", DATABASE_URL: "postgres://dana@localhost/shop" }

במקום לכתוב required/envInt לכל משתנה — מתארים את כולם בסכמה אחת. כתוב וייצא parseEnv(env, schema):

  • schema — אובייקט: שם משתנה ← { type, default?, values? }. ‏type אחד מ: "string", ‏"int", ‏"bool", ‏"enum" (עם values).
  • לכל משתנה: ערך חסר/ריק ← default אם יש; אם אין default ← בעיה "<NAME>: חסר".
  • המרות: int — רק ספרות (אפשר - בהתחלה); bool — true/false/1/0 (בלי תלות באותיות); enum — אחד מ־values. לא תקין ← "<NAME>: לא תקין".
  • התוצאה — אובייקט עם המפתחות ב־camelCase: ‏DATABASE_URL ← databaseUrl, ‏PORT ← port.
  • בעיות — כולן יחד: throw new Error("הגדרות לא תקינות:\n" + בעיות.join("\n")), לפי סדר הסכמה.
  • type לא מוכר בסכמה — זו טעות של המתכנת: throw new Error(סוג לא מוכר: ${type}) מיד.

P13-E71 · הסתרת סודות בכל עומק 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 15 דק׳ידע נדרש: פרק 5, פרק 7, שיעור 3

הקופסה "⚠️ לא להדפיס סודות" בשיעור. כתוב וייצא redact(value) שמחזירה עותק עמוק שבו כל ערך של מפתח "רגיש" מוחלף ב־"***":

  • מפתח רגיש — שמכיל (בלי תלות באותיות) אחת מהמילים: password, secret, token, key.
  • עובדת על אובייקטים ומערכים בכל עומק (רקורסיה). ערכים אחרים — כמו שהם. אם ערך של מפתח רגיש הוא אובייקט — גם הוא כולו "***".
  • ב־URL עם סיסמה (scheme://user:pass@host...) בכל ערך מסוג מחרוזת — מחליפים רק את הסיסמה: postgres://dana:***@localhost/shop.
  • אסור לשנות את המקור.
