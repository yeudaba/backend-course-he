P28-E05 · ביקורת על מסמך תכנון 🧠 הבנה רמה 1

💡 רמז 1

מה קורה כשיש 5 שרתים, ו־Map בכל אחד?

💡 רמז 2

ומה קורה ל־Apple כשהיא חוזרת מתקלה, ואלף שרתים "מנסים שוב מיד"?

✅ פתרון
  1. שליחה בתוך הבקשה — הלקוח מחכה לספק חיצוני. ← תור ו־worker (פרק 26).
  2. ניסיון חוזר מיד, 10 פעמים — מכה את הספק בדיוק כשהוא חלש, וחוסם את הבקשה. ← backoff אקספוננציאלי עם jitter (E12), מספר ניסיונות סביר, ו־circuit breaker (E15).
  3. Map בזיכרון — עם 5 שרתים, כל אחד יודע רק על עצמו; ואחרי restart — שוכח הכול. ← ייחודיות במסד (UNIQUE) או ב־Redis (SET NX, פרק 26).
  4. Date.now() כמזהה — שתי התראות באותה מילישנייה, או בשני שרתים = אותו מזהה. ← UUID, מזהה מהמסד, או Snowflake (E24).
  5. "נוסיף שרתים" — לפני שיודעים מה צוואר הבקבוק. אם הבעיה היא ההמתנה לספק, עוד שרתים רק יכפילו את ההמתנה. ← למדוד; ועם תור — מגדילים workers, לא API.
  6. (בונוס) אין התייחסות לטוקן שפג (משתמש מחק את האפליקציה) — ספקי push מחזירים שגיאה שצריך לטפל בה ולמחוק את הטוקן, לא "לנסות שוב".
⚠️ טעויות נפוצות
  • ביקורת בלי הצעה ("זה לא יעבוד"). בצוות, ובראיון, מה שעוזר הוא "הבעיה היא X, והייתי עושה Y כי Z".

P28-E83 · ‏fan-out בכתיבה או בקריאה? 🧠 הבנה רמה 1

💡 רמז 1

שאל: כמה כתיבות לפידים יוצר פוסט אחד? וכמה עולה לפתוח פיד?

💡 רמז 2

אם יש מעט מפרסמים — אפשר פשוט לקרוא מהם.

✅ פתרון
  1. on write: 30 כתיבות להודעה, וקריאה מיידית. (בפועל — כל קבוצה היא "פיד" אחד משותף, וזה עוד יותר פשוט.)
  2. on read, או פשוט טבלה אחת עם אינדקס על זמן: 200 עובדים, כולם רואים הכול — "הפוסטים האחרונים", ‏LIMIT 50. אין צורך בפיד לכל אחד.
  3. היברידי — בדיוק המקרה מהשיעור.
  4. on read: עשרה מפרסמים בלבד — קוראים את הפוסטים האחרונים של הספקים שהלקוח עוקב אחריהם (שאילתה אחת עם IN), עם cache. fan-out on write היה יוצר עד 100,000 כתיבות לכל פרסום, בשביל כלום.
⚠️ טעויות נפוצות
  • "פיד = fan-out on write" — זו אופטימיזציה לקריאות רבות ממקורות רבים, לא ברירת מחדל.

P28-E84 · פיד מוגבל ל־500 🧠 הבנה רמה 1

💡 רמז 1

‏500 מזהים × 8 בתים × 10 מיליון.

💡 רמז 2

"גיבוי במסד" מהשיעור.

✅ פתרון
  1. ‏500 × 8 × 10⁷ = ‏40GB — כבר הרבה ב־Redis. "הכול" הוא פי מאות. ואף אחד לא גולל לפוסט מלפני חצי שנה.
  2. "אין עוד" — או fan-out on read איטי מהמסד, לאלה שבאמת מגיעים לשם (מעטים).
  3. בונים מחדש: fan-out on read מהמסד (הפוסטים האחרונים של מי שהוא עוקב), ושומרים ב־Redis. פתיחה ראשונה איטית יותר — פעם אחת.
  4. רק המזהה: הפוסט נשמר פעם אחת (ב־cache נפרד ובמסד). עריכה או מחיקה של פוסט לא דורשת לעדכן מיליון פידים — ופיד של 500 מזהים קטן פי מאות.
⚠️ טעויות נפוצות
  • לשמור את הפוסט המלא בכל פיד — עריכה של פוסט של סלבריטי היא מיליון כתיבות.

P28-E86 · ביקורת: הסעיף שחסר 🧠 הבנה רמה 1

💡 רמז 1

מה אם Redis נופל? מה אם ה־worker נופל באמצע? מה אם מייל נשלח פעמיים?

💡 רמז 2

מדד "לפני ואחרי": זמן התשובה של ההרשמה, כמה מיילים נכשלו, כמה זמן בתור.

✅ פתרון

סיכונים: (1) Redis למטה ← ההרשמה לא יכולה להכניס job. החלטה: ההרשמה מצליחה, ונרשמת שורת outbox במסד שמישהו יעביר לתור אחר כך (או: נכשלים בגלוי). (2) worker נופל באמצע ← BullMQ מחזיר את ה־job; מייל עלול לצאת פעמיים — jobId קבוע לכל מייל, ורישום "נשלח". (3) הספק חוסם בגלל קצב ← הגבלת קצב ב־worker. (4) חזרה אחורה: feature flag ‏EMAIL_VIA_QUEUE — כבוי ← הקוד הישן.

איך נדע: p95 של POST /register לפני ואחרי (צפי: מ־1.2s ל־150ms); אחוז מיילים שנכשלו סופית; זמן מהכנסה לתור עד שליחה (p95 מתחת לדקה); גודל התור — התראה אם עולה מעל 1,000.

⚠️ טעויות נפוצות
  • "נבדוק שזה עובד" בלי מספר יעד — אין דרך להגיד "זה לא עבד" ולחזור אחורה.

P28-E19 · פיד היברידי 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

Maps: עוקבים, נעקבים, פיד לכל משתמש, פוסטים לכל מחבר.

💡 רמז 2

כפילות: פוסט של מי שהפך לסלבריטי אחרי שפרסם — כבר בפיד, וגם נמשך. Map לפי id.

✅ פתרון
// P28-E19
// פיד: fan-out on write (כל פוסט נכתב לפיד של כל עוקב) — קריאה מהירה; אבל לסלבריטי עם מיליון עוקבים זה מיליון כתיבות.
// היברידי: לסלבריטאים — fan-out on read (מושכים את הפוסטים שלהם בזמן הקריאה וממזגים)
export interface Post {
  id: number;
  author: string;
  at: number;
}

export function createFeed({ celebrityThreshold = 1000, timelineCap = 500 }: { celebrityThreshold?: number; timelineCap?: number } = {}) {
  const followers = new Map<string, Set<string>>();
  const following = new Map<string, Set<string>>();
  const timelines = new Map<string, Post[]>(); // החדש ראשון
  const postsBy = new Map<string, Post[]>(); // החדש ראשון
  const stats = { timelineWrites: 0 };
  let nextId = 1;

  const set = (m: Map<string, Set<string>>, k: string) => m.get(k) ?? m.set(k, new Set()).get(k)!;
  const isCelebrity = (u: string) => (followers.get(u)?.size ?? 0) >= celebrityThreshold;
  const newestFirst = (a: Post, b: Post) => b.at - a.at || b.id - a.id;

  return {
    stats,
    follow(user: string, target: string) {
      set(followers, target).add(user);
      set(following, user).add(target);
    },
    post(author: string, at: number): Post {
      const p = { id: nextId++, author, at };
      (postsBy.get(author) ?? postsBy.set(author, []).get(author)!).unshift(p);
      if (!isCelebrity(author)) {
        for (const f of followers.get(author) ?? []) {
          const tl = timelines.get(f) ?? timelines.set(f, []).get(f)!;
          tl.unshift(p);
          if (tl.length > timelineCap) tl.length = timelineCap;
          stats.timelineWrites++;
        }
      }
      return p;
    },
    timeline(user: string, limit = 20): Post[] {
      // Map לפי id: פוסט של מי שהפך לסלבריטי אחרי שפרסם — כבר בפיד, וגם נמשך עכשיו. לא להציג פעמיים
      const merged = new Map((timelines.get(user) ?? []).map((p) => [p.id, p]));
      for (const t of following.get(user) ?? []) {
        if (isCelebrity(t)) for (const p of (postsBy.get(t) ?? []).slice(0, limit)) merged.set(p.id, p);
      }
      return [...merged.values()].sort(newestFirst).slice(0, limit);
    },
  };
}
⚠️ טעויות נפוצות
  • fan-out on read לכולם — כל פתיחה של האפליקציה = שאילתה על מאות חשבונות, ממוזגת. איטי בדיוק בפעולה הנפוצה.

P28-E88 · כמה כתיבות לפידים? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

לולאה אחת שצוברת שני סכומים.

💡 רמז 2

‏Math.round(((pushAll - hybrid) / pushAll) * 100).

✅ פתרון
// P28-E88: כמה כתיבות לפידים?
type User = { id: string; followers: number; postsPerDay: number };

export function fanoutCost(users: User[], threshold: number) {
  let pushAll = 0;
  let hybrid = 0;
  const celebrities: string[] = [];
  for (const u of users) {
    const writes = u.followers * u.postsPerDay;
    pushAll += writes;
    if (u.followers >= threshold) celebrities.push(u.id);
    else hybrid += writes;
  }
  const saved = pushAll === 0 ? 0 : Math.round(((pushAll - hybrid) / pushAll) * 100);
  return { pushAll, hybrid, celebrities, saved };
}
⚠️ טעויות נפוצות
  • ‏> במקום >= — מי שבדיוק בסף לא נחשב סלבריטי.

P28-E89 · מיזוג פידים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏const pos = lists.map(() => 0). בכל סיבוב: עוברים על הרשימות, ומוצאים את i שהאיבר lists[i][pos[i]] שלו הכי "חדש".

💡 רמז 2

‏Set של מזהים שכבר נלקחו; אם האיבר שנבחר כבר שם — רק מקדמים את המצביע.

✅ פתרון
// P28-E89: מיזוג פידים
type Post = { id: number; at: number };

const newer = (a: Post, b: Post) => a.at > b.at || (a.at === b.at && a.id > b.id);

export function mergeFeeds(lists: Post[][], limit: number): Post[] {
  const pos = lists.map(() => 0);
  const seen = new Set<number>();
  const out: Post[] = [];
  while (out.length < limit) {
    let best = -1;
    for (let i = 0; i < lists.length; i++) {
      const head = lists[i][pos[i]];
      if (head && (best === -1 || newer(head, lists[best][pos[best]]))) best = i;
    }
    if (best === -1) break;
    const post = lists[best][pos[best]++];
    if (seen.has(post.id)) continue;
    seen.add(post.id);
    out.push(post);
  }
  return out;
}

‏O(limit × k) עבור k רשימות — לא תלוי באורך הרשימות. עם מאות רשימות כדאי ערימה (MinHeap מפרק 27).

⚠️ טעויות נפוצות
  • ‏lists.flat().sort() — נכון, אבל ממיין מיליוני פוסטים בשביל 20.
  • לבדוק כפילות לפני שבוחרים — האיבר הכפול נשאר בראש הרשימה ותוקע את הלולאה.

P28-E90 · פיד עם תקרה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏Map<string, number[]>. הוספה: unshift, ואם length > cap — ‏pop.

💡 רמז 2

‏before: ‏const i = list.indexOf(before); ‏-1 ← ‏[]; אחרת list.slice(i + 1, i + 1 + limit).

✅ פתרון
// P28-E90: פיד עם תקרה
export class FeedStore {
  private feeds = new Map<string, number[]>();
  private cap: number;

  constructor(cap = 500) {
    this.cap = cap;
  }

  add(userId: string, postId: number): void {
    let list = this.feeds.get(userId);
    if (!list) {
      list = [];
      this.feeds.set(userId, list);
    }
    if (list.includes(postId)) return;
    list.unshift(postId);
    if (list.length > this.cap) list.pop();
  }

  read(userId: string, limit = 20, before?: number): number[] {
    const list = this.feeds.get(userId) ?? [];
    let start = 0;
    if (before !== undefined) {
      const i = list.indexOf(before);
      if (i === -1) return [];
      start = i + 1;
    }
    return list.slice(start, start + limit);
  }

  size(userId: string): number {
    return this.feeds.get(userId)?.length ?? 0;
  }
}

‏includes ו־unshift הם O(cap) — עם תקרה של 500 זה זניח. ב־Redis זה LPUSH ואז LTRIM feed:<user> 0 499.

⚠️ טעויות נפוצות
  • להחזיר את המערך הפנימי מ־read — מי שקורא יכול לשנות את הפיד. ‏slice מחזיר עותק.

P28-E91 · בודק מסמך תכנון 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

עוברים על השורות, ושומרים "הסעיף הנוכחי": כותרת חדשה ← מוצאים לאיזה סעיף היא שייכת (או אף אחד), ומתחילים לספור שורות תוכן.

💡 רמז 2

‏Map מסעיף למספר שורות התוכן שלו. בסוף: לא ב־Map ← missing; ‏0 ← empty.

✅ פתרון
// P28-E91: בודק מסמך תכנון
export const REQUIRED = ["הקשר", "מטרות", "אומדנים", "פתרון", "חלופות", "סיכונים", "איך נדע"];

export function checkDesignDoc(markdown: string) {
  const content = new Map<string, number>();
  let current: string | null = null;
  for (const line of markdown.split("\n")) {
    if (line.startsWith("## ")) {
      const title = line.slice(3).trim();
      current = REQUIRED.find((s) => title.startsWith(s)) ?? null;
      if (current !== null && !content.has(current)) content.set(current, 0);
      continue;
    }
    if (current !== null && line.trim() !== "") content.set(current, (content.get(current) ?? 0) + 1);
  }
  const missing = REQUIRED.filter((s) => !content.has(s));
  const empty = REQUIRED.filter((s) => content.get(s) === 0);
  return { ok: missing.length === 0 && empty.length === 0, missing, empty };
}
⚠️ טעויות נפוצות
  • ‏line.startsWith("#") — תופס גם ###, ואז תת־כותרת "סוגרת" את הסעיף.
  • ‏title === s — ‏"מטרות ולא־מטרות" לא נחשב.

P28-E92 · חיבורים למסד: האם נכנסים? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏destructuring עם ברירות מחדל: const { workers = 0, poolPerWorker = 0, reserved = 3 } = p.

💡 רמז 2
Math.max(0, Math.floor((available - workers * poolPerWorker) / instances))
✅ פתרון
// P28-E92: חיבורים למסד — האם נכנסים?
export function poolBudget(p: { instances: number; poolPerInstance: number; workers?: number; poolPerWorker?: number; maxConnections: number; reserved?: number }) {
  const { instances, poolPerInstance, workers = 0, poolPerWorker = 0, maxConnections, reserved = 3 } = p;
  const total = instances * poolPerInstance + workers * poolPerWorker;
  const available = maxConnections - reserved;
  return {
    total,
    available,
    ok: total <= available,
    maxPoolPerInstance: Math.max(0, Math.floor((available - workers * poolPerWorker) / instances)),
  };
}

ב־Render, ב־RDS הקטן וב־Supabase החינמי max_connections הוא לפעמים 20–100. "עוד 5 עותקים" בשיא יכול להפיל את המסד בלי שום עומס של שאילתות.

⚠️ טעויות נפוצות

// P28-E93: מלאי בחלקים
export function splitStock(total: number, parts: number): number[] {
  if (!Number.isInteger(parts) || parts <= 0) throw new RangeError("parts חייב להיות שלם חיובי");
  if (!Number.isInteger(total) || total < 0) throw new RangeError("total חייב להיות שלם אי־שלילי");
  const base = Math.floor(total / parts);
  const extra = total % parts;
  return Array.from({ length: parts }, (_, i) => base + (i < extra ? 1 : 0));
}

export function takeOne(shards: number[], start: number): number {
  const n = shards.length;
  for (let k = 0; k < n; k++) {
    const i = (start + k) % n;
    if (shards[i] > 0) {
      shards[i]--;
      return i;
    }
  }
  return -1;
}

// P28-E94: ADR בקובץ
const STATUSES = ["proposed", "accepted", "superseded", "rejected"];

export function adrMarkdown(r: { number: number; title: string; status: string; date: string; context: string; decision: string; consequences: string[] }): string {
  if (!STATUSES.includes(r.status)) throw new Error(`סטטוס לא מוכר: ${r.status}`);
  if (!/^\d{4}-\d{2}-\d{2}$/.test(r.date)) throw new Error(`תאריך לא תקין: ${r.date}`);
  if (!r.title.trim() || !r.decision.trim()) throw new Error("חסרים כותרת או החלטה");
  if (r.consequences.length === 0) throw new Error("צריך לפחות השלכה אחת");
  const lines = [
    `# ADR-${String(r.number).padStart(4, "0")}: ${r.title.trim()}`,
    "",
    `- סטטוס: ${r.status}`,
    `- תאריך: ${r.date}`,
    "",
    "## הקשר",
    r.context,
    "",
    "## החלטה",
    r.decision,
    "",
    "## השלכות",
    ...r.consequences.map((c) => `- ${c}`),
    "",
  ];
  return lines.join("\n");
}

✅ פתרון
// P28-E102: מיזוג פידים — מתוקן
export type Post = { id: number; createdAt: string; shop: string };

export function mergeFeeds(lists: Post[][], limit: number): Post[] {
  const all = lists.flat().sort((a, b) => b.createdAt.localeCompare(a.createdAt) || b.id - a.id);
  const seen = new Set<number>();
  const out: Post[] = [];
  for (const p of all) {
    if (seen.has(p.id)) continue;
    seen.add(p.id);
    out.push(p);
    if (out.length === limit) break;
  }
  return out;
}
  1. מיון עולה. ‏a.createdAt.localeCompare(b.createdAt) מסדר מהישן לחדש. בפיד רוצים הפוך: b לפני a. ‏id שובר תיקו, כדי שהסדר לא יקפוץ בין טעינות.
  2. בלי סינון כפילויות. פוסט משותף נמצא ברשימה של כל חנות. ‏Set של ids.
  3. ‏slice(0, limit + 1) החזיר פוסט אחד יותר. וחשוב: מסננים כפילויות לפני שחותכים ל־limit, אחרת עמוד עם כפילות יוצא קצר.

(בקנה מידה, במקום לחבר הכול ולמיין, ממזגים את הרשימות הממוינות עם תור עדיפויות ועוצרים אחרי limit: O(limit · log k). הרעיון זהה.)

⚠️ טעויות נפוצות
  • לסנן כפילויות אחרי ה־slice. העמוד מקבל פחות מ־limit פוסטים.
  • למיין את אחת הרשימות במקום (lists[0].sort(...)). ‏sort משנה את המערך, והרשימה של החנות משתנה. ‏flat() יוצר מערך חדש, ולכן למיין אחריו בטוח.
  • להשוות תאריכים עם - בין מחרוזות. ‏"2026-…" - "2026-…" הוא NaN, והמיון לא עושה כלום.

✅ פתרון
// P28-E98: API של פיד ב־Express
import express from "express";

type Post = { id: number; author: string; text: string; at: number };

export function feedApp(opts: { celebrityThreshold: number; now: () => number }) {
  const followers = new Map<string, Set<string>>();
  const following = new Map<string, Set<string>>();
  const feeds = new Map<string, number[]>();
  const posts = new Map<number, Post>();
  const byAuthor = new Map<string, number[]>();
  let nextId = 1;
  let feedWrites = 0;

  const setOf = (m: Map<string, Set<string>>, k: string) => {
    if (!m.has(k)) m.set(k, new Set());
    return m.get(k)!;
  };
  const isCelebrity = (u: string) => (followers.get(u)?.size ?? 0) >= opts.celebrityThreshold;

  const app = express();
  app.use(express.json());

  app.post("/follow", (req, res) => {
    const { follower, followee } = req.body ?? {};
    if (typeof follower !== "string" || typeof followee !== "string" || !follower || !followee || follower === followee) {
      return res.status(400).json({ error: "follower ו־followee שונים" });
    }
    setOf(followers, followee).add(follower);
    setOf(following, follower).add(followee);
    res.status(204).end();
  });

  app.post("/posts", (req, res) => {
    const { author, text } = req.body ?? {};
    if (typeof author !== "string" || !author || typeof text !== "string" || !text.trim()) {
      return res.status(400).json({ error: "author ו־text חובה" });
    }
    const post: Post = { id: nextId++, author, text, at: opts.now() };
    posts.set(post.id, post);
    if (!byAuthor.has(author)) byAuthor.set(author, []);
    byAuthor.get(author)!.push(post.id);
    if (!isCelebrity(author)) {
      for (const f of followers.get(author) ?? []) {
        if (!feeds.has(f)) feeds.set(f, []);
        feeds.get(f)!.push(post.id);
        feedWrites++;
      }
    }
    res.status(201).json(post);
  });

  app.get("/feed/:user", (req, res) => {
    const user = req.params.user;
    const limit = Math.min(Math.max(Number(req.query.limit) || 20, 1), 100);
    const found = new Map<number, Post>();
    for (const id of feeds.get(user) ?? []) found.set(id, posts.get(id)!);
    for (const f of following.get(user) ?? []) {
      if (!isCelebrity(f)) continue;
      for (const id of byAuthor.get(f) ?? []) found.set(id, posts.get(id)!);
    }
    const items = [...found.values()].sort((a, b) => b.at - a.at || b.id - a.id).slice(0, limit);
    res.json({ items });
  });

  app.get("/stats", (req, res) => res.json({ feedWrites }));
  return app;
}
⚠️ טעויות נפוצות

// P28-E99: fan-out בתור, בחבילות
export function fanoutJobs(postId: number, followers: string[], batchSize = 1000) {
  if (!Number.isInteger(batchSize) || batchSize <= 0) throw new RangeError("batchSize חייב להיות שלם חיובי");
  const unique = [...new Set(followers)];
  const jobs: { name: string; data: { postId: number; followers: string[] }; opts: { jobId: string } }[] = [];
  for (let i = 0; i < unique.length; i += batchSize) {
    jobs.push({
      name: "fanout",
      data: { postId, followers: unique.slice(i, i + batchSize) },
      opts: { jobId: `fanout:${postId}:${i / batchSize}` },
    });
  }
  return jobs;
}

  • ‏jobId שהוא רק מספר ("42") — ‏BullMQ לא מרשה jobId שהוא מספר שלם; לכן הקידומת fanout:.

// P28-E100: עמדנו ביעדים?
export function verdict(results: { ms: number; status: number }[], targets: { p99Ms: number; maxErrorRate: number }) {
  const count = results.length;
  if (count === 0) return { count: 0, p50: 0, p99: 0, errorRate: 0, pass: false, reasons: ["no results"] };
  const sorted = results.map((r) => r.ms).sort((a, b) => a - b);
  const pct = (n: number) => sorted[Math.ceil((n / 100) * count) - 1];
  const p50 = pct(50);
  const p99 = pct(99);
  const errorRate = results.filter((r) => r.status >= 500).length / count;
  const asPct = (x: number) => Number((x * 100).toFixed(2));
  const reasons: string[] = [];
  if (p99 > targets.p99Ms) reasons.push(`p99 ${p99}ms > ${targets.p99Ms}ms`);
  if (errorRate > targets.maxErrorRate) reasons.push(`errors ${asPct(errorRate)}% > ${asPct(targets.maxErrorRate)}%`);
  return { count, p50, p99, errorRate, pass: reasons.length === 0, reasons };
}
