⏱ 3–4 מפגשים

🧰 לפני שמתחילים — פרק 28

מה צריך שכבר יהיה מותקן: Node.js 24. אין התקנות חדשות — כל התרגילים רצים בזיכרון, עם שעון ו־random מוזרקים.

📂 העתקת חומרי הפרק: ב־Finder, העתק את התיקייה 28-system-design מתוך ~/Desktop/Backend/backend-course אל ~/dev/backend-course (גרירה עם ⌥ Option). אם התיקייה כבר שם מהעתקה קודמת ואתה רוצה לשמור את מה שכתבת — בחר Keep Both / Stop ולא Replace.

✔ בדיקה: cd ~/dev/backend-course && npm run check P28-E06 ← הבודק רץ ונכשל על קובץ ההתחלה.

פרק חובה. יחידה 28.5 ופרויקט 4 נשענים עליו. ראיונות ל־Junior כוללים לפעמים שאלת תכנון "קלה" (קיצור קישורים, פיד, מערכת הזמנות); הפרק מכין אותך אליה, ומסביר את המושגים שתשמע בצוות מהיום הראשון.

🎯 בסוף הפרק תדע
  • לנהל שאלת תכנון: דרישות, אומדנים, API, מודל נתונים, תרשים, ומה קורה בעומס.
  • להכיר את אבני הבניין — load balancer, replicas, cache, תור, CDN — ומתי כל אחת פותרת בעיה.
  • לטפל בכשלים: timeouts, retry עם jitter, circuit breaker, health checks.
  • נתונים בקנה מידה: עימוד עם cursor, sharding ו־consistent hashing, מזהים מבוזרים, batching, Bloom filter.
  • לתכנן שתי מערכות מלאות — קיצור קישורים ופיד — ולכתוב מסמך תכנון לחנות הקפה פי 100.

🤔 למה צריך את זה?

עד עכשיו בנית שרת אחד, מסד אחד, Redis אחד — וזה בדיוק מה שרוב המערכות בעולם צריכות. אבל בצוות תשמע "נוסיף replica", "זה צריך ללכת לתור", "ה־breaker נפתח", ובראיון עלול להגיע "איך היית מתכנן קיצור קישורים?". תכנון מערכת ברמת Junior הוא לא לצייר את טוויטר — זה לדעת לשאול את השאלות הנכונות, לחשב מסדר גודל, ולהסביר מה כל קופסה בתרשים פותרת ומה היא עולה. ורוב הקופסות כבר מוכרות לך מהקורס.
