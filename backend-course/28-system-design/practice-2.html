P28-E12 · retry נכון 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 20 דק׳ידע נדרש: שיעור 2

בקובץ P28-E12.ts: retry(fn, { retries, baseMs, maxMs, random, sleep }). קורא ל־fn(attempt); נכשל ← מחכה Math.floor(random() × min(maxMs, baseMs × 2^attempt)) ("full jitter") ומנסה שוב, עד retries ניסיונות חוזרים. לא מחכים אחרי האחרון, וזורקים את השגיאה המקורית. HttpError עם status 4xx (חוץ מ־429) — לא מנסים שוב בכלל.

P28-E15 · circuit breaker 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 30 דק׳ידע נדרש: שיעור 2

בקובץ P28-E15.ts: createBreaker(call, { failureThreshold = 5, openMs = 30000, now }) ← { state, exec() }. closed: exec קורא ל־call; failureThreshold כישלונות (הצלחה מאפסת) ← open. ב־open: נכשל מיד עם "circuit open", בלי לקרוא. אחרי openMs ← half-open: בקשת ניסיון אחת עוברת (בזמן שהיא רצה — השאר נדחים); הצליחה ← closed, נכשלה ← open מחדש, לעוד openMs שלם.

P28-E28 · hedged request: בקשה שנייה אם הראשונה מתעכבת 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 2

🔁 חזרה על new Promise עם resolve/reject, ‏setTimeout/clearTimeout ו־then עם שתי פונקציות (פרק 10), ‏closures (פרק 5) ו־generics (פרק 11). ב־p99 (שיעור 1) אחת ממאה בקשות איטית בלי סיבה: GC, דיסק עמוס, שכן רועש. "hedged request" (מהמאמר של Google, ‏The Tail at Scale) עוזר: אם אין תשובה תוך זמן קצר, שולחים את אותה בקשה שוב, ולוקחים את מי שעונה ראשון. כתוב וייצא hedged<T>(fn: (attempt: number) => Promise<T>, delayMs: number): Promise<T>:

  • מתחילה fn(1). אם אחרי delayMs עוד אין תשובה, מתחילה גם fn(2). התשובה המוצלחת הראשונה מנצחת.
  • אם fn(1) נכשלה לפני ש־fn(2) התחילה, ‏fn(2) מתחילה מיד, בלי לחכות ל־delayMs.
  • שתיהן נכשלו ← reject עם השגיאה של האחרונה שנכשלה. לכל היותר שתי קריאות ל־fn.
  • תשובה שמגיעה אחרי שכבר הוחלט (הצלחה מאוחרת, או כישלון מאוחר) — לא משנה כלום.
