P28-E02 · חישוב על גב מעטפה 🧠 הבנה רמה 1

💡 רמז 1

יום ≈ 100,000 שניות (86,400 — אבל לגב מעטפה, 10⁵).

💡 רמז 2

62⁶ ≈ 57 מיליארד, 62⁷ ≈ 3.5 טריליון.

✅ פתרון
  1. 10⁸ / 10⁵ = כ־1,000 בשנייה בממוצע, כ־3,000 בשיא. כתיבות: 10⁶ / 10⁵ = כ־10 בשנייה.
  2. 10⁶ × 500 בתים = 500MB ביום ← × 365 × 5 ≈ כ־1TB.
  3. 10⁶ × 365 × 5 ≈ 1.8 מיליארד קודים. 6 תווים (57 מיליארד) מספיקים פי 30; 7 נותנים מרווח ענק, וקוד אקראי כמעט לא מתנגש.
  4. 3,000 קריאות בשנייה ו־10 כתיבות: זו מערכת קריאה. cache (רוב הקליקים על מעט קישורים חמים) ו־replicas פותרים; מסד אחד מחזיק את הכתיבות בקלות. 1TB — שרת PostgreSQL אחד, בלי sharding. זו המסקנה החשובה: החישוב אומר לך ממה לא צריך לפחד.

(E07 עושה את אותו חישוב בקוד.)

⚠️ טעויות נפוצות
  • לחשב רק ממוצע — שרת שעומד בממוצע נופל בשיא. ולשכוח שגיבוי ו־replicas מכפילים את האחסון.

P28-E30 · ראיון שקפץ לשלב 5 🧠 הבנה רמה 1

💡 רמז 1

הטבלה בשיעור: דרישות ← אומדנים ← API ← נתונים ← תרשים.

💡 רמז 2

כמה התראות ביום? אם זה 50,000 — כמה זה בשנייה?

✅ פתרון

P28-E31 · איפה הולך הזמן? 🧠 הבנה רמה 1

💡 רמז 1

הלוך־חזור לארה״ב מאירופה — לפחות כמו מישראל לארה״ב, כ־150ms.

💡 רמז 2

10,000 × 100 ננו־שניות = 1 מילישנייה.

✅ פתרון
  1. Redis: 3 × 0.5 = 1.5ms. שאילתות: 2 × 1 = 2ms. לולאה: כ־1ms. תשלומים: כ־150ms. סך הכול כ־155ms.
  2. הקריאה לחו״ל — כ־97% מהזמן.
  3. הכי משתלם: לא לחכות לתשלומים בתוך הבקשה (תור, או לקרוא להם רק בשלב התשלום), או לבחור region קרוב. "שיפור" חסר ערך: לשכתב את הלולאה — חוסך מילישנייה מתוך 155.
⚠️ טעויות נפוצות
  • לבצע אופטימיזציה לקוד בזיכרון לפני שמדדת — רשת ודיסק הם כמעט תמיד הסיבה.

P28-E32 · פי כמה השיא? 🧠 הבנה רמה 1

💡 רמז 1

הממוצע מחלק את כל היום שווה ב־86,400 שניות. מה קורה אם כל הפעילות היא בשעתיים?

💡 רמז 2

אזורי זמן שונים "מורחים" את העומס.

✅ פתרון
  1. 3–10: כל הדיווחים בבוקר ובסוף היום, ובלילה כמעט אפס.
  2. יותר מ־10 — לפעמים פי מאות: רוב הבקשות של היום בדקות הראשונות.
  3. פחות מ־3: משתמשים בכל אזורי הזמן, העומס מתפזר.
  4. יום רגיל — 3–5 (ערב). בלאק פריידיי — הממוצע עצמו גדל, והשיא יכול להגיע לפי 10–20 מיום רגיל.

מערכת שתוכננה לממוצע של (2) מחזיקה אולי עשירית מהשיא — ונופלת בדיוק ברגע שבו יש לה הכי הרבה כסף להרוויח.

⚠️ טעויות נפוצות
  • להשתמש ב"פי 3" לכל מערכת. המספר תלוי בהתנהגות המשתמשים — ושואלים עליו בשלב הדרישות.

P28-E07 · אומדן בקוד 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

בקשות ביום = משתמשים × בקשות למשתמש. כתיבות ביום = בקשות × writeRatio.

💡 רמז 2

שים לב לסדר: מעגלים רק בסוף — peakRps מהממוצע לפני עיגול.

✅ פתרון
// P28-E07
// "חישוב על גב מעטפה": מסדרי גודל, לא דיוק. יום = 86,400 שניות ≈ 100,000
export interface Inputs {
  dailyActiveUsers: number;
  requestsPerUserPerDay: number;
  writeRatio: number; // חלק הבקשות שכותבות (0..1)
  bytesPerWrite: number;
  peakFactor: number; // השיא פי כמה מהממוצע
  retentionDays: number;
}

export function estimate(i: Inputs) {
  const perDay = i.dailyActiveUsers * i.requestsPerUserPerDay;
  const avgRps = perDay / 86_400;
  const writesPerDay = perDay * i.writeRatio;
  const storageBytes = writesPerDay * i.bytesPerWrite * i.retentionDays;
  return {
    avgRps: Math.round(avgRps),
    peakRps: Math.round(avgRps * i.peakFactor),
    writesPerSecond: Math.round(writesPerDay / 86_400),
    storageGB: Math.round(storageBytes / 1e9),
  };
}
⚠️ טעויות נפוצות
  • לעגל את הממוצע ואז להכפיל בשיא — טעות קטנה שהבודק תופס, וטעות גדולה כשהממוצע הוא 0.4.

P28-E33 · מיליון ביום — כמה בשנייה? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

עיגול לספרה אחת: Math.round(x * 10) / 10.

💡 רמז 2

‏Number.isFinite(n) מחזיר false גם ל־NaN וגם ל־Infinity.

✅ פתרון
// P28-E33: מיליון ביום — כמה בשנייה?
const DAY = 86_400;

function check(n: number) {
  if (!Number.isFinite(n) || n < 0) throw new RangeError(`מספר לא תקין: ${n}`);
}

export function perSecond(perDay: number): number {
  check(perDay);
  return Math.round((perDay / DAY) * 10) / 10;
}

export function perDayFrom(perSecond: number): number {
  check(perSecond);
  return Math.round(perSecond * DAY);
}

שני המספרים שכדאי לזכור מכאן: מיליון ביום ≈ 12 בשנייה, ו־100 מיליון ביום ≈ 1,157 בשנייה.

⚠️ טעויות נפוצות
  • לחלק ב־3,600 או ב־1,440 — יחידות שעה ודקה.
  • ‏toFixed(1) מחזיר מחרוזת, לא מספר.

P28-E34 · בתים בשפה של בני אדם 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

מערך יחידות, ולולאה: כל עוד value >= 1000 ויש עוד יחידה — מחלקים ב־1,000 ומתקדמים.

💡 רמז 2

‏String(Math.round(v * 10) / 10) כבר מוריד את ה־.0.

✅ פתרון
// P28-E34: בתים בשפה של בני אדם
const UNITS = ["B", "KB", "MB", "GB", "TB", "PB"];

export function formatBytes(bytes: number): string {
  if (!Number.isFinite(bytes) || bytes < 0) throw new RangeError(`גודל לא תקין: ${bytes}`);
  let value = bytes;
  let i = 0;
  while (value >= 1000 && i < UNITS.length - 1) {
    value /= 1000;
    i++;
  }
  return `${Math.round(value * 10) / 10}${UNITS[i]}`;
}
⚠️ טעויות נפוצות
  • לחלק ב־1,024 — זה KiB ו־MiB. באומדנים משתמשים בעשרוני, וזה גם מה שספקי ענן מחייבים עליו ברוב המקרים.
  • לולאה בלי i < UNITS.length - 1 ← ‏undefined בסוף המחרוזת.

P28-E35 · תקציב latency של בקשה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

חשב קודם מערך של עלויות: steps.map((s) => s.ms * (s.count ?? 1)).

💡 רמז 2

היקר: לולאה ששומרת אינדקס, עם > ולא >= — כדי שבתיקו יישאר הראשון.

✅ פתרון
// P28-E35: תקציב latency של בקשה
type Step = { name: string; ms: number; count?: number };

export function latencyBudget(steps: Step[]) {
  const costs = steps.map((s) => s.ms * (s.count ?? 1));
  const total = costs.reduce((a, b) => a + b, 0);
  if (total === 0) return { totalMs: 0, slowest: null, slowestShare: 0 };
  let best = 0;
  for (let i = 1; i < costs.length; i++) if (costs[i] > costs[best]) best = i;
  return {
    totalMs: Math.round(total * 100) / 100,
    slowest: steps[best].name,
    slowestShare: Math.round((costs[best] / total) * 100),
  };
}
⚠️ טעויות נפוצות
  • להשוות לפי ms בלי count — 200 קריאות ל־Redis (‏N+1) "נראות" זולות.
  • לחלק ב־0 כשאין צעדים ← NaN.

P28-E36 · כמה שרתים צריך? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏Math.ceil(peakRps / (rpsPerServer * (1 - headroom))).

💡 רמז 2

‏Math.max(2, ...). ובדיקות הקלט — לפני החישוב.

✅ פתרון
// P28-E36: כמה שרתים צריך?
export function serversNeeded(peakRps: number, rpsPerServer: number, headroom = 0.3): number {
  if (!(rpsPerServer > 0)) throw new RangeError("rpsPerServer חייב להיות חיובי");
  if (!(peakRps >= 0)) throw new RangeError("peakRps לא תקין");
  if (!(headroom >= 0 && headroom < 1)) throw new RangeError("headroom חייב להיות בין 0 ל־1 (לא כולל)");
  return Math.max(2, Math.ceil(peakRps / (rpsPerServer * (1 - headroom))));
}

‏!(x > 0) ולא x <= 0: כך גם NaN נתפס (כל השוואה עם NaN היא false).

⚠️ טעויות נפוצות
  • ‏Math.round במקום Math.ceil — 4.2 שרתים הם 5, לא 4.
  • לשכוח את המינימום 2 — האומדן אמר "שרת אחד מספיק", והשרת היחיד עושה restart.

P28-E37 · לקרוא רשימת דרישות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏text.split("\n").forEach((raw, i) => ...) — ‏i + 1 הוא מספר השורה.

💡 רמז 2

‏/^(nf|f):(.*)$/i על השורה אחרי trim. שים לב לסדר: nf קודם, כי f לבד לא יתאים ל־NF: בכל מקרה — אבל כך הקוד ברור.

✅ פתרון
// P28-E37: לקרוא רשימת דרישות
export function parseRequirements(text: string) {
  const functional: string[] = [];
  const nonFunctional: string[] = [];
  text.split("\n").forEach((raw, i) => {
    const line = raw.trim();
    if (line === "" || line.startsWith("#")) return;
    const m = line.match(/^(nf|f):(.*)$/i);
    if (!m) throw new Error(`שורה ${i + 1}: חסרה קידומת F: או NF:`);
    const body = m[2].trim();
    if (!body) throw new Error(`שורה ${i + 1}: דרישה ריקה`);
    (m[1].toLowerCase() === "f" ? functional : nonFunctional).push(body);
  });
  return { functional, nonFunctional };
}
⚠️ טעויות נפוצות
  • לסנן שורות ריקות לפני הלולאה — מספרי השורות בהודעות השגיאה זזים.
  • ‏line.startsWith("F:") — לא תופס f:, ולא שורה עם רווח לפני הקידומת.

P28-E38 · אחסון שגדל כל חודש 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

משתנה rate שמתחיל ב־writesPerDay ומוכפל בסוף כל איטרציה, ומשתנה total בבתים.

💡 רמז 2

‏out.push(Math.round((total / 1e9) * 100) / 100).

✅ פתרון
// P28-E38: אחסון שגדל כל חודש
export function monthlyStorage(writesPerDay: number, bytesPerWrite: number, monthlyGrowth: number, months: number): number[] {
  const out: number[] = [];
  let rate = writesPerDay;
  let total = 0;
  for (let m = 0; m < months; m++) {
    total += rate * 30 * bytesPerWrite;
    out.push(Math.round((total / 1e9) * 100) / 100);
    rate *= 1 + monthlyGrowth;
  }
  return out;
}

עם צמיחה של 10% בחודש, אחרי שנה הקצב הוא פי 2.85 מההתחלה. זה מה שהופך "1TB ב־5 שנים" ל־"1TB בשנה וחצי".

⚠️ טעויות נפוצות
  • לעגל את total בכל חודש — טעויות קטנות מצטברות.
  • להכפיל את הקצב לפני החודש הראשון — החודש הראשון כבר "גדל".

P28-E39 · יחס קריאה לכתיבה מתוך לוג 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏m.toUpperCase() פעם אחת, ואז if/else if.

💡 רמז 2

סדר הבדיקות בסוף: קודם writes === 0, ורק אז לחלק.

✅ פתרון
// P28-E39: יחס קריאה לכתיבה מתוך לוג
export function readWriteRatio(methods: string[]) {
  let reads = 0;
  let writes = 0;
  for (const raw of methods) {
    const m = raw.toUpperCase();
    if (m === "OPTIONS") continue;
    if (m === "GET" || m === "HEAD") reads++;
    else writes++;
  }
  const ratio = writes === 0 ? (reads === 0 ? 0 : Infinity) : Math.round((reads / writes) * 10) / 10;
  return { reads, writes, ratio };
}
⚠️ טעויות נפוצות
  • לספור OPTIONS (preflight של CORS, פרק 15.5) כקריאה — באתר עם הרבה fetch מהדפדפן הוא מנפח את המספר.

// P28-E101: אומדן גב־המעטפה — מתוקן
const round1 = (x: number) => Math.round(x * 10) / 10;

export function estimate({ dau, actionsPerUser, peakFactor, bytesPerAction, retentionDays }: { dau: number; actionsPerUser: number; peakFactor: number; bytesPerAction: number; retentionDays: number }) {
  const perDay = dau * actionsPerUser;
  const avg = perDay / 86_400;
  return {
    avgRps: round1(avg),
    peakRps: round1(avg * peakFactor),
    storageGB: round1((perDay * bytesPerAction * retentionDays) / 1e9),
  };
}

// P28-E43: GET /estimate עם Zod
import express from "express";
import { z } from "zod";

const Query = z.object({
  users: z.coerce.number().int().positive(),
  perUser: z.coerce.number().int().positive(),
  peak: z.coerce.number().min(1).max(100).default(3),
});

const round1 = (n: number) => Math.round(n * 10) / 10;

export function estimateApp() {
  const app = express();
  app.get("/estimate", (req, res) => {
    const r = Query.safeParse(req.query);
    if (!r.success) {
      const fields = [...new Set(r.error.issues.map((i) => String(i.path[0])))].sort();
      return res.status(400).json({ error: "invalid query", fields });
    }
    const avg = (r.data.users * r.data.perUser) / 86_400;
    res.json({ avgRps: round1(avg), peakRps: round1(avg * r.data.peak) });
  });
  return app;
}
⚠️ טעויות נפוצות
  • ‏z.number() בלי coerce — כל בקשה נכשלת, כי "1000" הוא מחרוזת.
  • ‏z.coerce.number() על פרמטר חסר נותן NaN (Number(undefined)) — ו־.int() תופס אותו. בלי .int()/.positive() היית מחזיר null ב־JSON.

// P28-E44: שיא מתוך לוגים של JSON
export function trafficFromLogs(lines: string[]) {
  const perMinute = new Map<number, number>();
  let skipped = 0;
  let total = 0;
  let min = Infinity;
  let max = -Infinity;
  for (const line of lines) {
    let ms = NaN;
    try {
      const rec = JSON.parse(line);
      if (typeof rec?.time === "string") ms = Date.parse(rec.time);
    } catch {
      // לא JSON
    }
    if (Number.isNaN(ms)) {
      skipped++;
      continue;
    }
    const minute = Math.floor(ms / 60_000);
    perMinute.set(minute, (perMinute.get(minute) ?? 0) + 1);
    total++;
    min = Math.min(min, minute);
    max = Math.max(max, minute);
  }
  if (total === 0) return { total: 0, skipped, minutes: 0, avgPerMinute: 0, peakPerMinute: 0, peakFactor: 0 };
  const minutes = max - min + 1;
  const avg = total / minutes;
  const peak = Math.max(...perMinute.values());
  return { total, skipped, minutes, avgPerMinute: Math.round(avg * 10) / 10, peakPerMinute: peak, peakFactor: Math.round((peak / avg) * 10) / 10 };
}
⚠️ טעויות נפוצות
  • ‏minutes = perMinute.size — מתעלם מדקות שקטות, והממוצע יוצא גבוה מדי.
  • להניח שהשורות ממוינות — לוגים ממכמה עותקים מתערבבים.

💡 רמז 1

💡 רמז 2

מעגל: Set של "בתהליך" — אם נכנסים לשם שכבר בתהליך, זה מעגל. ל־critical שמור לכל צעד גם את התלות שבחרת (‏via), ובסוף לך אחורה מהצעד האחרון.

✅ פתרון
// P28-E45: Promise.all — כמה זמן באמת?
type Step = { name: string; ms: number; after?: string[] };

export function pageTime(steps: Step[]) {
  const byName = new Map(steps.map((s) => [s.name, s]));
  const done = new Map<string, number>();
  const via = new Map<string, string | null>();
  const visiting = new Set<string>();

  function finish(name: string): number {
    const known = done.get(name);
    if (known !== undefined) return known;
    const step = byName.get(name);
    if (!step) throw new Error(`תלות לא מוכרת: ${name}`);
    if (visiting.has(name)) throw new Error(`מעגל תלויות דרך ${name}`);
    visiting.add(name);
    let start = 0;
    let from: string | null = null;
    for (const dep of step.after ?? []) {
      const t = finish(dep);
      if (t > start) {
        start = t;
        from = dep;
      }
    }
    visiting.delete(name);
    done.set(name, start + step.ms);
    via.set(name, from);
    return start + step.ms;
  }

  let parallel = 0;
  let last: string | null = null;
  for (const s of steps) {
    const t = finish(s.name);
    if (last === null || t > parallel) {
      parallel = t;
      last = s.name;
    }
  }
  const critical: string[] = [];
  for (let cur = last; cur !== null; cur = via.get(cur) ?? null) critical.unshift(cur);
  return { sequential: steps.reduce((a, s) => a + s.ms, 0), parallel, critical };
}

זה מסביר למה דף "עם 12 קריאות" יכול להיות מהיר: אם רובן לא תלויות זו בזו, הזמן הוא השרשרת הארוכה, לא הסכום. וזה מסביר גם למה await בתוך לולאה הופך את הכול לסכום.

⚠️ טעויות נפוצות
  • ‏parallel = Math.max(...ms) — מתעלם מתלויות: הזמנות מחכות למשתמש.
  • בלי Map של תוצאות — כל צעד מחושב שוב ושוב, ובגרף עמוק זה מתפוצץ.
  • ‏if (t >= start) — בתיקו נבחרת התלות האחרונה ולא הראשונה.
