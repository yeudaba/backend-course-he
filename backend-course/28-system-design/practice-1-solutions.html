P28-E02 · חישוב על גב מעטפה 🧠 הבנה רמה 1

💡 רמז 1

יום ≈ 100,000 שניות (86,400 — אבל לגב מעטפה, 10⁵).

💡 רמז 2

62⁶ ≈ 57 מיליארד, 62⁷ ≈ 3.5 טריליון.

✅ פתרון
  1. 10⁸ / 10⁵ = כ־1,000 בשנייה בממוצע, כ־3,000 בשיא. כתיבות: 10⁶ / 10⁵ = כ־10 בשנייה.
  2. 10⁶ × 500 בתים = 500MB ביום ← × 365 × 5 ≈ כ־1TB.
  3. 10⁶ × 365 × 5 ≈ 1.8 מיליארד קודים. 6 תווים (57 מיליארד) מספיקים פי 30; 7 נותנים מרווח ענק, וקוד אקראי כמעט לא מתנגש.
  4. 3,000 קריאות בשנייה ו־10 כתיבות: זו מערכת קריאה. cache (רוב הקליקים על מעט קישורים חמים) ו־replicas פותרים; מסד אחד מחזיק את הכתיבות בקלות. 1TB — שרת PostgreSQL אחד, בלי sharding. זו המסקנה החשובה: החישוב אומר לך ממה לא צריך לפחד.

(E07 עושה את אותו חישוב בקוד.)

⚠️ טעויות נפוצות
  • לחשב רק ממוצע — שרת שעומד בממוצע נופל בשיא. ולשכוח שגיבוי ו־replicas מכפילים את האחסון.

P28-E07 · אומדן בקוד 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

בקשות ביום = משתמשים × בקשות למשתמש. כתיבות ביום = בקשות × writeRatio.

💡 רמז 2

שים לב לסדר: מעגלים רק בסוף — peakRps מהממוצע לפני עיגול.

✅ פתרון
// P28-E07
// "חישוב על גב מעטפה": מסדרי גודל, לא דיוק. יום = 86,400 שניות ≈ 100,000
export interface Inputs {
  dailyActiveUsers: number;
  requestsPerUserPerDay: number;
  writeRatio: number; // חלק הבקשות שכותבות (0..1)
  bytesPerWrite: number;
  peakFactor: number; // השיא פי כמה מהממוצע
  retentionDays: number;
}

export function estimate(i: Inputs) {
  const perDay = i.dailyActiveUsers * i.requestsPerUserPerDay;
  const avgRps = perDay / 86_400;
  const writesPerDay = perDay * i.writeRatio;
  const storageBytes = writesPerDay * i.bytesPerWrite * i.retentionDays;
  return {
    avgRps: Math.round(avgRps),
    peakRps: Math.round(avgRps * i.peakFactor),
    writesPerSecond: Math.round(writesPerDay / 86_400),
    storageGB: Math.round(storageBytes / 1e9),
  };
}
⚠️ טעויות נפוצות
  • לעגל את הממוצע ואז להכפיל בשיא — טעות קטנה שהבודק תופס, וטעות גדולה כשהממוצע הוא 0.4.
