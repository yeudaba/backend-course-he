P28-E56 · מונה, אקראי או hash? 🧠 הבנה רמה 1

💡 רמז 1

מה החיסרון של כל שיטה — והאם הוא משנה כאן?

💡 רמז 2

"צפוי" הוא בעיה רק כשמישהו מבחוץ יכול לנחש.

✅ פתרון
  1. מונה + base62: הכי פשוט, הכי קצר, אף פעם לא מתנגש. הצפיות לא משנה — הכול מאחורי התחברות.
  2. אקראי: מונה מסגיר את הכמות (‏/4c92 היום, ‏/4d10 מחר). אקראי עם UNIQUE וניסיון חוזר.
  3. hash של ה־URL (מנורמל — E65), עם טיפול בהתנגשויות. ושאלה למוצר: אם שני אנשים חולקים קוד, הם חולקים גם סטטיסטיקות.
  4. אקראי: כל שרת מייצר לבד. (או מונה שכל שרת לוקח ממנו "חבילות" של 1,000 — עוד רכיב לתחזק.)
⚠️ טעויות נפוצות
  • לבחור hash "כי הוא לא מתנגש" — 7 תווים מתוך sha256 מתנגשים בדיוק כמו 7 תווים אקראיים.

P28-E57 · ‏301, ‏302 או 307? 🧠 הבנה רמה 1

💡 רמז 1

301 נשמר אצל הדפדפן. אחרי זה הוא לא שואל אותך.

💡 רמז 2

307 מבטיח שה־method לא משתנה; 302 — בפועל דפדפנים הופכים POST ל־GET.

✅ פתרון
  1. עם 302 כל קליק עובר דרכם: אפשר לספור, לשנות יעד, ולחסום. זה המוצר.
  2. 301 (ואולי Cache-Control ארוך) — זו בדיוק הבקשה. כדאי להגיד ללקוח שהוא מוותר על סטטיסטיקות ועל אפשרות לשנות.
  3. 302 — הדפדפן עלול לשלוח GET ליעד והנתונים של הטופס הולכים לאיבוד; 307 שומר על POST ועל הגוף.
  4. כמעט כלום: דפדפנים ששמרו את ה־301 לא יחזרו לשאול. אפשר לחסום רק משתמשים חדשים, ולדווח לרשימות חסימה. לכן ברירת מחדל 302.
⚠️ טעויות נפוצות
  • "301 עדיף ל־SEO" — נכון לדף שעבר כתובת באתר שלך, לא לקישור מקוצר שאתה רוצה לשלוט בו.

P28-E58 · כמה תווים מספיקים? 🧠 הבנה רמה 1

💡 רמז 1

הסיכוי = קודים תפוסים ÷ קודים אפשריים.

💡 רמז 2

אם הסיכוי להצליח הוא p, מספר הניסיונות הממוצע הוא 1/p.

✅ פתרון
  1. ‏10⁸ / 9.2 × 10⁸ ≈ 0.11 — אחד מתשעה ניסיונות מתנגש.
  2. הסיכוי להצליח ≈ 0.89 ← בערך 1.12 ניסיונות. עדיין סביר, אבל עם 5 ניסיונות מקסימום כבר יש סיכוי קטן לכישלון, והוא גדל מהר.
  3. כשהסיכוי מתקרב לאחוזים (E62 עושה את החישוב). הקודים הקיימים נשארים כמו שהם — העמודה היא text, והחיפוש לפי מחרוזת; רק קודים חדשים ארוכים יותר. אם יש בדיקה של אורך הקוד (ב־validation או ב־regex של ה־route) — לעדכן.
⚠️ טעויות נפוצות
  • לחשוב שצריך "migration של כל הקודים" — אין סיבה לגעת בקישורים קיימים.

P28-E59 · ‏"בדקתי שהקוד פנוי" 🧠 הבנה רמה 1

💡 רמז 1

בין ה־SELECT ל־INSERT עוברות מילישניות — ומישהו אחר יכול להכניס בדיוק את אותו קוד.

💡 רמז 2

"המסד הוא שמבטיח, לא 'בדקתי קודם'" — מהשיעור.

✅ פתרון
  1. שני שרתים מגרילים את אותו קוד (נדיר, אבל ב־10 בשנייה לאורך שנים זה קורה), שניהם בודקים — פנוי — ושניהם מכניסים.
  2. שתי שורות עם אותו קוד: ה־redirect מחזיר אחת מהן, לפעמים את זו ולפעמים את זו. קישור של מישהו אחד מפנה לאתר של מישהו אחר.
  3. code כ־PRIMARY KEY; ‏INSERT ישר. נכשל על ייחודיות (קוד 23505) ← קוד חדש וניסיון נוסף. שאילתה אחת במקום שתיים ברוב המקרים, והמסד מבטיח שאין כפילות.
⚠️ טעויות נפוצות
  • "הסיכוי זניח" — זניח בבקשה אחת, לא במיליארד. ואותו דפוס במלאי הוא באג של כל יום.

P28-E60 · קליקים: מה מאבדים? 🧠 הבנה רמה 1

💡 רמז 1

‏180,000 בדקה מול מספר הקישורים.

💡 רמז 2

"קרא ואז אפס" הן שתי פעולות. ב־Redis יש GETDEL.

✅ פתרון
  1. ישיר: 180,000 עדכונים בדקה, על אותן 50 שורות — נעילות. באצווה: לכל היותר 50 עדכונים בדקה (אחד לכל קישור שהיו לו קליקים).
  2. עד דקה של קליקים — מחיר סביר, וכדאי להגיד אותו בקול.
  3. הקליקים ייספרו פעמיים. מונעים: GETDEL (קריאה ואיפוס באותה פעולה) לפני העדכון — ואז נפילה מאבדת במקום לכפול; או מפתח לכל דקה (clicks:abc:202603011004) שה־job מעבד פעם אחת ומסמן.
  4. "בזמן אמת" = המספר במסד ועוד מה שב־Redis עכשיו. ה־endpoint של הסטטיסטיקות יכול לחבר את שניהם.
⚠️ טעויות נפוצות
  • לשכוח שאיבוד וכפילות הם בחירה: אפשר לבחור מה מהשניים, לא להימנע משניהם בלי עוד עבודה.

P28-E61 · מה חוסמים? 🧠 הבנה רמה 1

💡 רמז 1

חשוב על מי שלוחץ, לא רק על מי שיוצר.

💡 רמז 2

קישור לעצמך יכול ליצור לולאה.

✅ פתרון
  1. לחסום: רק http/https. ‏javascript: רץ בהקשר של מי שלוחץ.
  2. לחסום (או לפחות לפתור לסוף): קישור לקישור מסתיר את היעד האמיתי, ושרשרת שמפנה לעצמה היא לולאה.

⚠️ טעויות נפוצות

P28-E06 · base62 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כמו להמיר לבסיס 2: שארית החלוקה ב־62 היא הספרה האחרונה; מחלקים (שלם) וממשיכים.

💡 רמז 2

decode: n = n * 62 + ALPHABET.indexOf(ch), משמאל לימין.

✅ פתרון
// P28-E06
// base62: ספרות 0-9, a-z, A-Z. כמו בסיס 10 או 16 — רק עם 62 "ספרות". 7 תווים = 62⁷ ≈ 3.5 טריליון קודים
const ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";

export function encode(n: number): string {
  if (!Number.isSafeInteger(n) || n < 0) throw new Error("רק מספר שלם אי־שלילי");
  if (n === 0) return "0";
  let out = "";
  while (n > 0) {
    out = ALPHABET[n % 62] + out;
    n = Math.floor(n / 62);
  }
  return out;
}

export function decode(code: string): number {
  if (!/^[0-9a-zA-Z]+$/.test(code)) throw new Error("קוד לא תקין");
  let n = 0;
  for (const ch of code) n = n * 62 + ALPHABET.indexOf(ch);
  if (!Number.isSafeInteger(n)) throw new Error("קוד ארוך מדי");
  return n;
}
⚠️ טעויות נפוצות
  • לשכוח את 0 — הלולאה לא רצה, ומתקבלת מחרוזת ריקה (E20).

P28-E10 · קוד אקראי והתנגשויות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

לולאת ניסיונות, ובתוכה לולאה שבונה את הקוד.

💡 רמז 2

random מוזרק — כך הבודק קובע מה יוגרל.

✅ פתרון
// P28-E10
// קוד קצר אקראי: אין צורך במונה משותף בין שרתים. התנגשות — נדירה, אבל קורית: בודקים ומנסים שוב
const ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";

export async function generateCode(
  exists: (code: string) => Promise<boolean>,
  { length = 7, maxAttempts = 5, random = Math.random }: { length?: number; maxAttempts?: number; random?: () => number } = {},
): Promise<string> {
  for (let attempt = 0; attempt < maxAttempts; attempt++) {
    let code = "";
    for (let i = 0; i < length; i++) code += ALPHABET[Math.floor(random() * 62)];
    if (!(await exists(code))) return code;
  }
  throw new Error(`לא נמצא קוד פנוי אחרי ${maxAttempts} ניסיונות`);
}

"בודקים ואז מכניסים" — יש פה מרוץ: שני שרתים מגרילים אותו קוד, שניהם רואים "פנוי". הסיכוי זעום, אבל הפתרון הנכון זהה לפרויקט 3: UNIQUE במסד, ו־INSERT שנכשל ← קוד חדש. כך עושה E17 (insert מחזיר false).

⚠️ טעויות נפוצות
  • לולאה בלי גבול — אם ה־store תמיד אומר "תפוס" (באג, או מסד מלא בקודים קצרים), השרת נתקע.

P28-E17 · שירות קיצור קישורים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

new URL(url) זורק על כתובת לא חוקית; .protocol כולל את הנקודתיים: "https:".

💡 רמז 2

תפוגה: expiresAt = now() + ttlSeconds * 1000, ו־now() >= expiresAt ← 410.

✅ פתרון
// P28-E17
// שירות קיצור קישורים — הלוגיקה, מעל store שאפשר להחליף (Map בבדיקות, PostgreSQL + Redis בפרודקשן)
export interface Link {
  code: string;
  url: string;
  createdAt: number;
  expiresAt: number | null;
  clicks: number;
}

export interface Store {
  get(code: string): Promise<Link | undefined>;
  insert(link: Link): Promise<boolean>; // false אם הקוד תפוס
  incrementClicks(code: string): Promise<void>;
}

export function memoryStore(): Store & { links: Map<string, Link> } {
  const links = new Map<string, Link>();
  return {
    links,
    get: async (code) => links.get(code),
    insert: async (link) => (links.has(link.code) ? false : (links.set(link.code, { ...link }), true)),
    incrementClicks: async (code) => {
      const l = links.get(code);
      if (l) l.clicks++;
    },
  };
}

const RESERVED = new Set(["api", "admin", "health", "login"]);

export function createShortener(store: Store, { newCode, now = () => Date.now() }: { newCode: () => string; now?: () => number }) {
  return {
    async create({ url, alias, ttlSeconds }: { url: string; alias?: string; ttlSeconds?: number }): Promise<Link> {
      let parsed: URL;
      try {
        parsed = new URL(url);
      } catch {
        throw new Error("כתובת לא תקינה");
      }
      if (parsed.protocol !== "https:" && parsed.protocol !== "http:") throw new Error("רק http/https"); // לא javascript: ולא data:
      if (alias !== undefined && (!/^[a-zA-Z0-9-]{3,30}$/.test(alias) || RESERVED.has(alias.toLowerCase()))) throw new Error("alias לא תקין");
      const base = { url: parsed.toString(), createdAt: now(), expiresAt: ttlSeconds ? now() + ttlSeconds * 1000 : null, clicks: 0 };
      if (alias !== undefined) {
        if (!(await store.insert({ ...base, code: alias }))) throw new Error("alias תפוס");
        return { ...base, code: alias };
      }
      for (let i = 0; i < 5; i++) {
        const code = newCode();
        if (await store.insert({ ...base, code })) return { ...base, code };
      }
      throw new Error("לא נמצא קוד פנוי");
    },
    // מה ה־redirect מחזיר: 302 (לא 301 — דפדפן שומר 301 לתמיד, ואז לא סופרים קליקים ואי אפשר לשנות יעד)
    async resolve(code: string): Promise<{ status: 302; location: string } | { status: 404 } | { status: 410 }> {
      const link = await store.get(code);
      if (!link) return { status: 404 };
      if (link.expiresAt !== null && now() >= link.expiresAt) return { status: 410 };
      await store.incrementClicks(code);
      return { status: 302, location: link.url };
    },
  };
}

מכאן לשירות אמיתי — הכול כבר בקורס: Nest controller עם @Redirect, store ב־PostgreSQL (code כ־PRIMARY KEY), cache של code ← url ב־Redis (רוב הקליקים על מעט קישורים), והקליקים — INCR ב־Redis או תור, שנכתבים למסד באצוות. הגבלת קצב על create. אולי פרויקט קטן לתיק העבודות?

⚠️ טעויות נפוצות
  • לקבל כל מחרוזת כ־URL — javascript: בקישור "קצר" שמופץ ברשת הוא מתקפה מוכנה.

P28-E20 · base62 עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

n / 62 ב־JavaScript — מה הוא מחזיר ל־63?

💡 רמז 2

out += ch מוסיף לסוף. איזו ספרה מחושבת ראשונה?

✅ פתרון
// P28-E20
const ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";

export function encode(n: number): string {
  if (!Number.isSafeInteger(n) || n < 0) throw new Error("רק מספר שלם אי־שלילי");
  if (n === 0) return "0"; // תקלה 1: בלי זה, 0 ← "" (הלולאה לא רצה), וקוד ריק לא מתפענח
  let out = "";
  while (n > 0) {
    out = ALPHABET[n % 62] + out; // תקלה 2: היה out += … ← הספרות יוצאות הפוך (הקטנה ראשונה)
    n = Math.floor(n / 62); // תקלה 3: היה n / 62 ← שבר, והלולאה ממשיכה עם 0.0something עד שמתקבל אפס
  }
  return out;
}

export function decode(code: string): number {
  if (!/^[0-9a-zA-Z]+$/.test(code)) throw new Error("קוד לא תקין");
  let n = 0;
  for (const ch of code) n = n * 62 + ALPHABET.indexOf(ch);
  return n;
}
⚠️ טעויות נפוצות
  • "לתקן" עם .split("").reverse().join("") בסוף — עובד, אבל הקוד הנכון פשוט יותר.

P28-E62 · איזה אורך קוד? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

לולאה: מתחילים מ־1 ומגדילים כל עוד הסיכוי גדול מדי.

💡 רמז 2

‏Math.min(1, existing / 62 ** length).

✅ פתרון
// P28-E62: איזה אורך קוד?
export function collisionChance(existing: number, length: number): number {
  return Math.min(1, existing / 62 ** length);
}

export function codeLengthFor(totalLinks: number, maxChance: number): number {
  if (!(maxChance > 0 && maxChance <= 1)) throw new RangeError("maxChance חייב להיות בין 0 ל־1");
  let length = 1;
  while (collisionChance(totalLinks, length) > maxChance) length++;
  return length;
}

שני מיליארד קישורים, ולכל היותר אחד לאלף מתנגש ← 7 תווים. אותו מספר שהגענו אליו בשיעור.

⚠️ טעויות נפוצות
  • להתחיל מ־0: ‏62 ** 0 = 1, וקוד ריק "מתאים" כשאין קישורים.

P28-E63 · קוד מתוך hash של ה־URL 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏createHash("sha256").update(url).digest() מחזיר Buffer.

💡 רמז 2

base62 — כמו ב־E06:

do { s = ALPHABET[n % 62] + s; n = Math.floor(n / 62); } while (n > 0)

ואז padStart(length, "0").

✅ פתרון
// P28-E63: קוד מתוך hash של ה־URL
import { createHash } from "node:crypto";

const ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";

function base62(n: number): string {
  let s = "";
  do {
    s = ALPHABET[n % 62] + s;
    n = Math.floor(n / 62);
  } while (n > 0);
  return s;
}

export function hashCode(url: string, length = 7): string {
  const n = createHash("sha256").update(url).digest().readUIntBE(0, 6);
  return base62(n % 62 ** length).padStart(length, "0");
}

export function codeFor(url: string, taken: Set<string>, length = 7): string {
  for (let i = 0; i < 5; i++) {
    const code = hashCode(i === 0 ? url : `${url}#${i}`, length);
    if (!taken.has(code)) return code;
  }
  throw new Error(`לא נמצא קוד פנוי ל־${url} אחרי 5 ניסיונות`);
}

ה־#1 שמוסיפים לא משנה את היעד — הוא רק "מלח" שנותן hash אחר.

⚠️ טעויות נפוצות
  • לקרוא 8 בתים — מספר גדול מ־Number.MAX_SAFE_INTEGER, והשארית יוצאת לא מדויקת.
  • בלי padStart — חלק מהקודים קצרים מ־7.

P28-E64 · מונה קליקים שנשפך באצווה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

— ואז new Map() ו־total = 0.

✅ פתרון
// P28-E64: מונה קליקים שנשפך באצווה
export class ClickBuffer {
  private counts = new Map<string, number>();
  private total = 0;
  private maxPending: number;

  constructor(maxPending = 10_000) {
    this.maxPending = maxPending;
  }

  click(code: string): boolean {
    this.counts.set(code, (this.counts.get(code) ?? 0) + 1);
    this.total++;
    return this.total >= this.maxPending;
  }

  pending(): number {
    return this.total;
  }

  flush(): [string, number][] {
    const out = [...this.counts].sort((a, b) => b[1] - a[1] || (a[0] < b[0] ? -1 : a[0] > b[0] ? 1 : 0));
    this.counts = new Map();
    this.total = 0;
    return out;
  }
}

‏constructor(private maxPending = 10_000) לא עובד כאן — הבודק מריץ TypeScript ב"הסרת טיפוסים" בלבד, ו־parameter properties דורשים המרה.

⚠️ טעויות נפוצות

  • ‏localeCompare מתחשב בשפה; לסדר "אלפביתי" פשוט של קודים — </>.

💡 רמז 2

// P28-E65: לנרמל URL לפני hash
export function normalizeUrl(raw: string): string {
  const url = new URL(raw.trim());
  if (url.protocol !== "http:" && url.protocol !== "https:") throw new Error(`פרוטוקול לא נתמך: ${url.protocol}`);
  url.hash = "";
  const pairs: [string, string][] = [];
  for (const [name, value] of url.searchParams) {
    if (name.startsWith("utm_") || name === "fbclid") continue;
    pairs.push([name, value]);
  }
  pairs.sort((a, b) => (a[0] < b[0] ? -1 : a[0] > b[0] ? 1 : 0));
  url.search = new URLSearchParams(pairs).toString();
  return url.href;
}

‏sort של JavaScript יציב — שני tag= נשארים בסדר המקורי, וזה חשוב: לפעמים הסדר שלהם הוא חלק מהמשמעות.

⚠️ טעויות נפוצות
  • להוריד גם את הנתיב או לשנות אותיות בו — /About ו־/about הם דפים שונים בהרבה שרתים.
  • ‏url.searchParams.sort() קיים ועושה בדיוק את המיון — מותר, אבל אז זכור לסנן לפני.

P28-E69 · ‏redirect עם cache ו־X-Cache 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

פונקציה פנימית async function lookup(code) שמחזירה { link, hit }; ‏try/catch נפרד סביב cache.get וסביב cache.set.

💡 רמז 2

בבדיקה מ־fetch צריך redirect: "manual" כדי לראות את ה־302 — הבודק כבר עושה את זה.

✅ פתרון
// P28-E69: redirect עם cache ו־X-Cache
import express from "express";

export type Link = { url: string; expiresAt: number | null };
export type Store = { get(code: string): Promise<Link | null> };
export type Cache = {
  get(key: string): Promise<string | null>;
  set(key: string, value: string, ttlSeconds: number): Promise<void>;
};

export function redirectApp(deps: { store: Store; cache: Cache; now: () => number }) {
  const { store, cache, now } = deps;

  async function lookup(code: string): Promise<{ link: Link | null; hit: boolean }> {
    const key = `link:${code}`;
    try {
      const cached = await cache.get(key);
      if (cached !== null) return { link: JSON.parse(cached), hit: true };
    } catch {
      // cache למטה ← כמו miss
    }
    const link = await store.get(code);
    if (link) {
      try {
        await cache.set(key, JSON.stringify(link), 3600);
      } catch {
        // לא נורא — בפעם הבאה ננסה שוב
      }
    }
    return { link, hit: false };
  }

  const app = express();
  app.get("/:code", async (req, res) => {
    const { link, hit } = await lookup(req.params.code);
    res.set("X-Cache", hit ? "HIT" : "MISS");
    if (!link) return res.status(404).json({ error: "not found" });
    if (link.expiresAt !== null && link.expiresAt <= now()) return res.status(410).json({ error: "expired" });
    res.redirect(302, link.url);
  });
  return app;
}
⚠️ טעויות נפוצות
  • לשמור ב־cache גם "לא קיים" בלי TTL קצר — קוד שנוצר אחר כך יחזיר 404 שעה (אם שומרים — עם TTL של שניות).
  • לבדוק תפוגה רק כשהקישור הגיע מהמסד — ה־cache מחזיק אותו עוד שעה אחרי שפג.

P28-E70 · ‏UPDATE אחד לכל האצווה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏Map לאיחוד (שומר סדר הכנסה), ואז [...map].map(([code, n], i) => ...): לזוג ה־i הפרמטרים הם $${2 * i + 1} ו־$${2 * i + 2}.

💡 רמז 2

‏values.push(code, n) בתוך אותה לולאה, ו־join(", ") לחלקים.

✅ פתרון
// P28-E70: UPDATE אחד לכל האצווה
export function clicksUpdate(entries: [string, number][]) {
  const merged = new Map<string, number>();
  for (const [code, n] of entries) {
    if (!Number.isInteger(n) || n <= 0) throw new RangeError(`מספר קליקים לא תקין ל־${code}: ${n}`);
    merged.set(code, (merged.get(code) ?? 0) + n);
  }
  if (merged.size === 0) return null;
  const values: (string | number)[] = [];
  const rows = [...merged].map(([code, n], i) => {
    values.push(code, n);
    return `($${2 * i + 1}, $${2 * i + 2}::bigint)`;
  });
  return {
    text: `UPDATE links SET clicks = links.clicks + v.n FROM (VALUES ${rows.join(", ")}) AS v(code, n) WHERE links.code = v.code`,
    values,
  };
}

‏::bigint בשורה הראשונה מספיק לתת ל־PostgreSQL טיפוס לעמודה של VALUES — אבל לשים אותו בכל שורה פשוט וברור יותר.

⚠️ טעויות נפוצות
  • `('${code}', ${n})` — ‏SQL injection דרך alias שהמשתמש בחר.
  • קוד כפול בלי איחוד — באותו UPDATE ... FROM, שורה שמתאימה לשתי שורות של v מתעדכנת רק פעם אחת, וקליקים הולכים לאיבוד.

✅ פתרון
// P28-E71: רשימת חסימה לפי מתחם
const clean = (d: string) => d.trim().toLowerCase().replace(/\.$/, "");

export function createBlocklist(domains: string[]) {
  const blocked = new Set(domains.map(clean));
  return (url: string): boolean => {
    let host: string;
    try {
      host = clean(new URL(url).hostname);
    } catch {
      return true;
    }
    const parts = host.split(".");
    for (let i = 0; i < parts.length; i++) {
      if (blocked.has(parts.slice(i).join("."))) return true;
    }
    return false;
  };
}
⚠️ טעויות נפוצות
  • ‏host.endsWith("evil.com") — חוסם גם את notevil.com.
  • ‏url.includes("evil.com") — חוסם את https://ok.com/?ref=evil.com, ולא חוסם EVIL.com.
