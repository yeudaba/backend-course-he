P09-E37 · בודק הודעות commit 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 15 דק׳ידע נדרש: שיעור 1

כתוב checkMessage(msg) שמחזירה מערך של הבעיות בהודעת commit (מערך ריק — הודעה טובה), בסדר הזה:

  1. "הודעה ריקה" — ריקה או רק רווחים (ואז מחזירים רק את הבעיה הזו).
  2. "לא אומרת מה השתנה" — אם כל ההודעה (אחרי trim, בלי תלות באותיות) היא אחת מ: fix, ‏update, ‏changes, ‏wip, ‏stuff, ‏asdf.
  3. "ארוכה מ־50 תווים"
  4. "מתחילה באות קטנה" — התו הראשון הוא אות אנגלית קטנה (a–z).
  5. "נגמרת בנקודה"
checkMessage("Add monthly summary command"); // []
checkMessage("fixed the bug.");               // ["מתחילה באות קטנה", "נגמרת בנקודה"]
checkMessage("WIP");                          // ["לא אומרת מה השתנה"]

P09-E39 · לפרק את git status בקוד

const status = "A  README.md\n M app.js\n?? notes.txt\n";
const lines = status.split("\n").filter((l) => l !== "");
console.log(lines.length);

P09-E27 · ניתוח של git log 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 2⏱ 15 דק׳ידע נדרש: שיעור 1

🔁 חזרה על indexOf ו־slice (פרק 2), על split, ‏filter ו־map (פרק 6), ועל ספירה באובייקט (פרק 7). כלים כמו GitHub ו־release notes קוראים את ההיסטוריה של המאגר. כאן תכתוב גרסה קטנה של זה. כתוב שתי פונקציות:

  • parseLog(text) — text הוא הפלט של git log --oneline. מחזירה מערך של { hash, message }: ה־hash הוא מה שלפני הרווח הראשון, וההודעה היא כל מה שאחריו. שורות ריקות לא נכללות.
  • countTypes(commits) — סופרת commits לפי סוג, כמו במוסכמה feat: ... / fix: .... הסוג הוא מה שלפני ה־: הראשון, באותיות קטנות, רק אם אין בו רווח. אחרת (אין נקודתיים, או שיש רווח לפניהן) — "other".
const log = `a1b2c3d feat: add login
9f8e7d6 fix: wrong total
5a4b3c2 Update README
1122334 feat: add logout
`;
const commits = parseLog(log);
commits[2];            // { hash: "5a4b3c2", message: "Update README" }
countTypes(commits);   // { feat: 2, fix: 1, other: 1 }

📄 כותבים בקובץ 09-git/starter/P09-E27.js (יש בו רק הערה). בסוף הקובץ: module.exports = { parseLog, countTypes };

% node 09-git/starter/P09-E27.js
% npm run check P09-E27

🔗 איך זה מתחבר: indexOf, ‏slice ו־split מפרקים 2 ו־6, וספירה באובייקט מפרק 7 — על הפלט של git log --oneline מהשיעור. ההודעות בסגנון feat: / fix: הן מוסכמה נפוצה (Conventional Commits).

P09-E42 · לפרק את git status --porcelain 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: פרק 6, פרק 7, שיעור 1

כתוב parseStatus(text) שמקבלת את הפלט של git status --porcelain ומחזירה אובייקט עם שלושה מערכים של שמות קבצים, לפי הסדר:

  • untracked — שורות שמתחילות ב־??.
  • staged — התו הראשון אינו רווח ואינו ?.
  • modified — התו השני אינו רווח ואינו ?.

קובץ יכול להיות גם staged וגם modified ("MM"). שם הקובץ מתחיל בתו הרביעי. שורות ריקות — מדלגים.

parseStatus("A  README.md\n M app.js\nMM cart.js\n?? notes.txt\n");
// { staged: ["README.md", "cart.js"], modified: ["app.js", "cart.js"], untracked: ["notes.txt"] }

📄 כותבים בקובץ 09-git/starter/P09-E42.js (יש בו רק הערה). בסוף הקובץ: module.exports = { parseStatus };

% node 09-git/starter/P09-E42.js
% npm run check P09-E42

🔗 איך זה מתחבר: הפורמט של git status --short מהשיעור, עם split, ‏slice ו־for...of מפרק 6, ואובייקט של מערכים מפרק 7 (כמו P07-E55). חיתוך לפי מיקום — הלקח של P09-E39.

P09-E43 · מי עשה הכי הרבה commits? 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 15 דק׳ידע נדרש: פרק 2, פרק 7, שיעור 1

הפקודה git log --format="%an|%s" מדפיסה לכל commit את שם הכותב ואת ההודעה, מופרדים ב־|. כתוב shortlog(text) שמחזירה מערך שורות — לכל כותב: מספר ה־commits שלו, מיושר לימין ברוחב 4, שני רווחים, והשם. מהגבוה לנמוך; בתיקו — לפי השם (localeCompare).

shortlog("Dana|Add login\nOmer|Fix total\nDana|Add logout\nNoa|Update README\nDana|Add tests\n");
// ["   3  Dana", "   1  Noa", "   1  Omer"]

(הודעה יכולה להכיל | — השם הוא רק מה שלפני ה־| הראשון.)

📄 כותבים בקובץ 09-git/starter/P09-E43.js (יש בו רק הערה). בסוף הקובץ: module.exports = { shortlog };

% node 09-git/starter/P09-E43.js
% npm run check P09-E43

🔗 איך זה מתחבר: Map לספירה מפרק 7, ‏sort עם שובר שוויון מפרק 6 (P07-E66), ו־padStart מפרק 2. Git עצמו עושה את זה עם git shortlog -sn.
