P09-E26 · מאגר ראשון — כסקריפט 🤖

✍️ מאפסרמה 2⏱ 15 דק׳ידע נדרש: שיעור 2

עד עכשיו הקלדת פקודות Git אחת אחת. הפעם תכתוב אותן בקובץ: סקריפט הוא פשוט רשימה של פקודות, אחת בכל שורה, בדיוק כמו שהיית מקליד ב־Terminal. bash script.sh מריץ אותן לפי הסדר. היתרון: הבודק יכול להריץ את הסקריפט בתיקייה ריקה, ולבדוק את המאגר שנוצר.

כתוב סקריפט שיוצר מאגר חדש בתיקייה הנוכחית, ובו שלושה commits:

  1. Add README — הקובץ README.md עם השורה # Notes.
  2. Add notes — הקובץ notes.txt עם השורה first note, והקובץ .gitignore עם השורה *.log. לפני ה־commit צור גם app.log עם השורה debug. הוא נשאר בתיקייה, אבל לא נכנס למאגר.
  3. Add second note — השורה second note נוספת לסוף notes.txt.

בסוף, git status צריך להיות נקי. ליצירת קובץ עם שורה: echo "..." > file. להוספת שורה בסוף: >> (ראה P09-E06).

📄 כותבים בקובץ 09-git/starter/P09-E26.sh (יש בו רק הערה). כדי לנסות בעצמך, מריצים בתיקייה ריקה. הבודק עושה את אותו דבר בתיקייה זמנית:

% bash ../../09-git/starter/P09-E26.sh

P09-E27 · ניתוח של git log 🤖

🔁 חזרהרמה 2⏱ 15 דק׳ידע נדרש: שיעור 1

🔁 חזרה על indexOf ו־slice (פרק 2), על split, ‏filter ו־map (פרק 6), ועל ספירה באובייקט (פרק 7). כלים כמו GitHub ו־release notes קוראים את ההיסטוריה של המאגר. כאן תכתוב גרסה קטנה של זה. כתוב שתי פונקציות:

  • parseLog(text) — text הוא הפלט של git log --oneline. מחזירה מערך של { hash, message }: ה־hash הוא מה שלפני הרווח הראשון, וההודעה היא כל מה שאחריו. שורות ריקות לא נכללות.
  • countTypes(commits) — סופרת commits לפי סוג, כמו במוסכמה feat: ... / fix: .... הסוג הוא מה שלפני ה־: הראשון, באותיות קטנות, רק אם אין בו רווח. אחרת (אין נקודתיים, או שיש רווח לפניהן) — "other".
const log = `a1b2c3d feat: add login
9f8e7d6 fix: wrong total
5a4b3c2 Update README
1122334 feat: add logout
`;
const commits = parseLog(log);
commits[2];            // { hash: "5a4b3c2", message: "Update README" }
countTypes(commits);   // { feat: 2, fix: 1, other: 1 }

📄 כותבים בקובץ 09-git/starter/P09-E27.js (יש בו רק הערה). בסוף הקובץ: module.exports = { parseLog, countTypes };

% node 09-git/starter/P09-E27.js
% npm run check P09-E27

P09-E28 · .gitignore קטן משלך 🤖

🔁 חזרהרמה 3⏱ 20 דק׳ידע נדרש: שיעור 2

🔁 חזרה על startsWith, ‏endsWith, ‏includes ו־trim (פרק 2), ועל split, ‏filter ו־some (פרק 6). איך Git מחליט אם קובץ מוסתר? כתוב גרסה פשוטה: isIgnored(filePath, gitignore). ‏filePath הוא נתיב יחסי ("src/app.log"), ו־gitignore הוא כל התוכן של הקובץ, כמחרוזת אחת.

  • שורות ריקות ושורות שמתחילות ב־# (הערות) לא נחשבות. רווחים בקצוות של שורה לא נחשבים.
  • name/ — תיקייה: הנתיב מתחיל ב־name/ או מכיל /name/.
  • *.ext — הנתיב נגמר ב־.ext.
  • כל שורה אחרת — שם מדויק: הנתיב שווה לשם, או נגמר ב־/ ואחריו השם.

מחזירה true אם לפחות כלל אחד מתאים.

const gitignore = `
# תלויות
node_modules/
*.log
.env
`;
isIgnored("node_modules/lodash/index.js", gitignore); // true
isIgnored("src/app.log", gitignore);                  // true
isIgnored("config/.env", gitignore);                  // true
isIgnored(".env.example", gitignore);                 // false
isIgnored("src/index.js", gitignore);                 // false

📄 כותבים בקובץ 09-git/starter/P09-E28.js (יש בו רק הערה). בסוף הקובץ: module.exports = { isIgnored };

% node 09-git/starter/P09-E28.js
% npm run check P09-E28

סמלץ צוות של שניים על expenses-cli: שני clones (~/dev/dev-a, ~/dev/dev-b). שניהם משנים את אותה שורה בהודעת ה־HELP ב־cli.js (כל אחד אחרת), עושים commit. A דוחף ראשון. B מנסה לדחוף ונדחה. השלם את התהליך מצד B עד שהשינויים של שניהם ב־GitHub, ושני ה־clones מסונכרנים. תעד כל פקודה וכל הודעה.

P09-E25 · אתגר: git bisect

רמה 5⏱ 30 דק׳ידע נדרש: כל הפרק

כשבאג נכנס "מתישהו" ויש מאות commits, git bisect מוצא את ה־commit האשם בחיפוש בינארי. בנה בעצמך מאגר playground/bisect-lab עם 12 commits, שבכל אחד שינוי קטן ב־calc.js (פונקציה total(items)), ובאחד מהם (נגיד השביעי) — באג. אחר כך כתוב סקריפט בדיקה קטן check.js שיוצא עם קוד 0 כשהתוצאה נכונה ו־1 כשלא, והרץ:

% git bisect start
% git bisect bad HEAD
% git bisect good <hash-of-first-commit>
% git bisect run node check.js

כמה צעדים לקח ל־Git? כמה היו לוקחים עם 1,000 commits?

🏁 מבחן מעבר

  • ליצור מאגר לפרויקט 1, עם .gitignore נכון ולפחות 3 commits עם הודעות ברורות — ולהעלות ל־GitHub עם README.
  • להסביר את שלושת האזורים ומה כל אחת מהפקודות add, commit, restore מזיזה ביניהם.
  • ליצור ענף, לעבוד עליו, לפתוח Pull Request ולמזג.
  • לפתור התנגשות בתרגיל conflict בלי לאבד אף אחד מהשינויים.
  • לדעת מה לעשות אם סוד נדחף ל־GitHub (ולמה מחיקה מה־commit הבא לא מספיקה).
  • לענות נכון על 80% מ־P09-E01–E19 ולפתור לפחות תרחיש תקלה אחד (E20–E23).
