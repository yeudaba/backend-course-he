P09-E03 · גרף של ענפים 🧠 הבנה רמה 1

💡 רמז 1

C נוצר על fix, D על main — שניהם "ילדים" של B.

💡 רמז 2

fast-forward אפשרי רק אם ב־main לא קרה כלום מאז הפיצול.

✅ פתרון
A ── B ── D ── M   ← main, HEAD
       \     /
        C ──     ← fix

לא fast-forward: שני הענפים התקדמו מ־B, ולכן נוצר merge commit (M) עם שני "הורים" — D ו־C. HEAD על main, ב־M. הענף fix עדיין מצביע על C (אפשר למחוק אותו).

⚠️ טעויות נפוצות
  • לחשוב שה־merge "מעביר" את C להיות אחרי D — זה מה ש־rebase עושה, לא merge.

P09-E04 · לקרוא התנגשות 🧠 הבנה רמה 1

💡 רמז 1

HEAD = הענף שאתה נמצא בו.

💡 רמז 2

אחרי העריכה: add ואז commit.

✅ פתרון

(1) למעלה (עד =======) — מ־main; למטה — מ־feature/discount. (2) Current ← return withVat(price);. Incoming ← return withVat(price) - 10;. (3) מוחקים את שורות הסימון (VS Code עושה את זה בכפתורים), מוודאים שהקוד רץ, ואז git add <file> ו־git commit.

ומה נכון? תלוי: אם ההנחה היא התכונה החדשה — Incoming. זו החלטה עסקית, לא טכנית.

⚠️ טעויות נפוצות
  • להשאיר את ======= בקובץ — הקוד לא ירוץ, וה־commit יכיל זבל.

P09-E55 · מה יש בתיקייה אחרי switch? 🧠 הבנה רמה 2

💡 רמז 1

switch מחליף את הקבצים שבמעקב לגרסה של הענף. קובץ untracked — Git לא נוגע בו.

💡 רמז 2

draft.txt לא ב־commit של אף ענף.

✅ פתרון
% ls
app.js  draft.txt
% cat app.js
main
% git switch feature/report
% ls
app.js  draft.txt  report.js

ב־main: ‏report.js "נעלם" (הוא קיים רק בענף), ו־app.js חזר ל־main. ‏draft.txt נשאר בשני הענפים — untracked "נוסע" איתך. שום דבר לא נמחק: הכול שמור ב־commits, ו־switch רק מציג גרסה אחרת.

⚠️ טעויות נפוצות
  • להיבהל ש"report.js נמחק" אחרי git switch main — הוא בענף שלו.

P09-E56 · fast-forward או merge commit? 🧠 הבנה רמה 2

💡 רמז 1

fast-forward אפשרי רק כש־main לא זז מאז שהענף נוצר.

💡 רמז 2

התנגשות — רק כששני הצדדים שינו את אותן שורות (או שורות צמודות).

✅ פתרון
  1. fast-forward — main פשוט זז קדימה. אין merge commit, אין התנגשות.
  2. merge commit (שני הקווים התקדמו). אין התנגשות — קבצים שונים.
  3. merge commit — עם התנגשות, שאותה פותרים ידנית.
  4. merge commit, בלי התנגשות: Git ממזג שינויים באותו קובץ אם הם באזורים שונים (P09-E68).
⚠️ טעויות נפוצות
  • לחשוב ש"אותו קובץ" = התנגשות. התנגשות היא ברמת שורות.

P09-E57 · לאיזה כיוון ממזגים? 🧠 הבנה רמה 1

💡 רמז 1

git merge X = "הבא את X לתוך הענף שאני נמצא בו".

💡 רמז 2

אם main התקדם מאז שפתחת את הענף — מה עדיף: לגלות התנגשויות אצלך, או ב־PR?

✅ פתרון
  1. feature/cart — הוא מקבל את מה שחדש ב־main. ‏main לא משתנה.
  2. אם יש התנגשויות — פותרים אותן בענף שלך, ובודקים שהקוד עובד, לפני שמישהו סוקר. ה־PR יהיה נקי.
  3. git switch main ואז git merge feature/cart.
⚠️ טעויות נפוצות
  • להריץ git merge feature/cart כשאתה בתוך feature/cart — "Already up to date", ולא קרה כלום.

P09-E58 · commit -am וקובץ חדש 🧠 הבנה רמה 2

💡 רמז 1

הטבלה בשיעור: -a מוסיף רק קבצים שכבר במעקב.

💡 רמז 2

האם utils.js במעקב?

✅ פתרון
% git commit -am "Update app and add utils"
[main 9501247] Update app and add utils
 1 file changed, 1 insertion(+)
% git status --short
?? utils.js

"1 file changed" — רק app.js. ‏utils.js נשאר untracked, וההודעה של ה־commit משקרת. מי שיעשה clone יקבל קוד שמנסה לייבא קובץ שלא קיים. לכן: git status לפני (ואחרי) כל commit.

⚠️ טעויות נפוצות
  • להשתמש תמיד ב־-am "כי זה מהיר" — קבצים חדשים לא נכנסים.

P09-E10 · ענף ומיזוג 💻 כתיבת קוד רמה 2

💡 רמז 1

switch -c ← commits ← switch main ← ls ← merge ← branch -d.

💡 רמז 2

אחרי המעבר ל־main, ls לא יראה את goodbye.js — Git החליף את הקבצים בתיקייה.

✅ פתרון
% git switch -c feature/goodbye
% echo 'console.log("bye");' > goodbye.js
% git add goodbye.js && git commit -m "Add goodbye script"
% echo 'console.log("see you");' >> goodbye.js
% git commit -am "Add second goodbye line"
% git switch main
% ls
README.md	hello.js
% git merge feature/goodbye
Updating c3e1a20..7d02b55
Fast-forward
 goodbye.js | 2 ++
 1 file changed, 2 insertions(+)
 create mode 100644 goodbye.js
% git branch -d feature/goodbye
% git log --oneline --graph

Fast-forward — כי ב־main לא קרה כלום בזמן שעבדת על הענף.

⚠️ טעויות נפוצות
  • git merge main בזמן שאתה ב־main — "Already up to date". ממזגים את הענף לתוך הנוכחי.

P09-E16 · merge commit 💻 כתיבת קוד רמה 3

💡 רמז 1

שני הענפים התקדמו — לא fast-forward.

💡 רמז 2

Git יפתח את VS Code עם הודעת merge מוכנה. שמור וסגור את הלשונית.

✅ פתרון
% git switch -c feature/a
% echo a > a.txt && git add a.txt && git commit -m "Add a"
% git switch main
% echo b > b.txt && git add b.txt && git commit -m "Add b"
% git merge feature/a
Merge made by the 'ort' strategy.
 a.txt | 1 +
% git log --oneline --graph
*   5e1f0aa (HEAD -> main) Merge branch 'feature/a'
|\
| * 81c3d2e (feature/a) Add a
* | 47b9e10 Add b
|/
* 7d02b55 Add second goodbye line

נוצר merge commit עם שני הורים. אין התנגשות, כי שני הענפים שינו קבצים שונים — Git משלב לבד.

⚠️ טעויות נפוצות
  • להיבהל מהעורך שנפתח — זו רק הודעת ה־merge.

P09-E22 · Git לא מסכים לעבור ענף 💻 כתיבת קוד רמה 4

💡 רמז 1

Git מסרב כי השינוי שלך היה נדרס בגרסה של main.

💡 רמז 2

stash ← switch ← (עבודה ב־main) ← switch בחזרה ← stash pop.

✅ פתרון
% git switch feature/english
% (עריכה של greeting.js)
% git switch main
error: Your local changes to the following files would be overwritten by checkout:
	greeting.js
Please commit your changes or stash them before you switch branches.
Aborting
% git stash
Saved working directory and index state WIP on feature/english: ...
% git switch main
% git switch feature/english
% git stash pop

stash — כשהשינוי באמצע ולא מוכן ל־commit ("רגע, צריך לבדוק משהו ב־main"). commit — כשהשינוי הוא יחידה הגיונית; תמיד בטוח יותר, כי stash קל לשכוח.

⚠️ טעויות נפוצות
  • git switch -f ("force") — דורס את השינויים. בדיוק מה ש־Git ניסה למנוע.

P09-E61 · התנגשות — בסקריפט 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

בסקריפט אין VS Code: "פתרון" = לכתוב את התוכן הנכון לקובץ עם echo ... > (זה דורס גם את סימני ההתנגשות).

💡 רמז 2

אחרי ה־echo: git add greeting.txt ו־git commit --no-edit (ההודעה המוכנה: Merge branch 'feature/hebrew').

✅ פתרון
09-git/starter/P09-E61.sh 
git init
echo "Hello" > greeting.txt
git add greeting.txt
git commit -m "Add greeting"

git switch -c feature/hebrew
echo "שלום" > greeting.txt
git commit -am "Translate greeting"

git switch main
echo "Hello!" > greeting.txt
git commit -am "Make greeting louder"

git merge feature/hebrew
echo "Hello! / שלום" > greeting.txt
git add greeting.txt
git commit --no-edit

ה־git merge "נכשל" (מדפיס CONFLICT), והסקריפט פשוט ממשיך לשורה הבאה — בדיוק כמו שאתה ממשיך לעבוד אחרי ההודעה. ‏git add אומר ל־Git "פתרתי את הקובץ הזה".

⚠️ טעויות נפוצות
  • git commit -m "..." לפני git add — ‏Git מסרב: Committing is not possible because you have unmerged files.

P09-E62 · לפתור התנגשויות בקוד 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

מעבר על השורות עם "מצב": "out" (מחוץ להתנגשות), "ours" (אחרי <<<<<<<), "theirs" (אחרי =======). שני מערכים זמניים לשני הצדדים.

💡 רמז 2

בשורת >>>>>>>: מוסיפים לתוצאה את הצד/הצדדים לפי choice, ומאפסים את המערכים הזמניים.

✅ פתרון
09-git/starter/P09-E62.js 
function resolve(text, choice) {
  const out = [];
  let state = "out";
  let ours = [];
  let theirs = [];
  for (const line of text.split("\n")) {
    if (line.startsWith("<<<<<<<")) {
      state = "ours";
    } else if (line === "=======" && state === "ours") {
      state = "theirs";
    } else if (line.startsWith(">>>>>>>") && state === "theirs") {
      if (choice === "ours" || choice === "both") {
        out.push(...ours);
      }
      if (choice === "theirs" || choice === "both") {
        out.push(...theirs);
      }
      ours = [];
      theirs = [];
      state = "out";
    } else if (state === "ours") {
      ours.push(line);
    } else if (state === "theirs") {
      theirs.push(line);
    } else {
      out.push(line);
    }
  }
  return out.join("\n");
}

const text = ["<<<<<<< HEAD", "a", "=======", "b", ">>>>>>> x", "end"].join("\n");
console.log(resolve(text, "both"));

module.exports = { resolve };
a
b
end

"מכונת מצבים" קטנה: המשתנה state זוכר באיזה חלק של הקובץ אנחנו. זה בדיוק מה שהכפתורים Accept Current / Incoming / Both של VS Code עושים — אבל זכור: פתרון אמיתי הוא החלטה, ולפעמים אף אחת משלוש האפשרויות לא נכונה.

⚠️ טעויות נפוצות
  • out.push(ours) בלי ... — נכנס מערך כאיבר אחד.

P09-E63 · התנגשות שנפתרה — ו־JSON שבור 🧠 הבנה רמה 2

💡 רמז 1

מה צריך להיות בין שני שדות באובייקט JSON?

💡 רמז 2

השורה "test": "node --test" הייתה האחרונה בצד שלה — ולכן בלי פסיק.

✅ פתרון
const resolved = `{
  "scripts": {
    "start": "node index.js",
    "test": "node --test"
    "lint": "eslint ."
  }
}`;
try {
  const pkg = JSON.parse(resolved);
  console.log(Object.keys(pkg.scripts));
} catch (err) {
  console.log(err.name);
  console.log(err.message);
}
SyntaxError
Expected ',' or '}' after property value in JSON at position 77 (line 5 column 5)

חסר פסיק אחרי "node --test" — SyntaxError, וההודעה מצביעה על המיקום שבו ה־parser התבלבל. אם לא בודקים — npm ייכשל לכל הצוות אחרי ה־merge. התיקון: פסיק אחד, ואז npm test כדי לוודא.

⚠️ טעויות נפוצות
  • להניח ש"Git סיים את ה־merge" = "הקוד תקין". Git רק מחבר טקסט.

P09-E64 · merge נקי, קוד שבור 🧠 הבנה רמה 2

💡 רמז 1

האם שני הענפים שינו את אותן שורות?

💡 רמז 2

ב־receipt.js יש const { calcTotal } = require("./cart"); — אבל cart.js כבר לא מייצא שם כזה (P08-E38).

✅ פתרון
  1. לא — קבצים שונים, ו־Git מיזג בשקט.
  2. calcTotal הוא undefined (destructuring של ייצוא שלא קיים), והקריאה זורקת TypeError: calcTotal is not a function.
  3. בדיקות אוטומטיות שרצות אחרי ה־merge (או על ה־PR, פרק 25); ‏ESLint ב־ESM (ייבוא של שם שלא קיים נכשל כבר בטעינה, P08-E32); ו־git merge main לתוך הענף של עומר לפני ה־PR (P09-E57) + הרצה.
⚠️ טעויות נפוצות
  • "אין התנגשות = אין בעיה". התנגשות סמנטית לא מסומנת אף פעם.

P09-E65 · ענף הוא הפניה 🧠 הבנה רמה 2

💡 רמז 1

commit חדש בענף = אובייקט חדש שה־parent שלו הוא הקצה הקודם, והחץ של הענף זז אליו.

💡 רמז 2

ה־parent של c3 הוא c2 — מה ש־main מצביע עליו.

✅ פתרון
const c1 = { message: "Add app", parent: null };
const c2 = { message: "Add README", parent: c1 };
const branches = { main: c2 };
branches["feature/x"] = branches.main;
const c3 = { message: "Add x", parent: branches["feature/x"] };
branches["feature/x"] = c3;
console.log(branches.main.message, branches["feature/x"].message);
console.log(branches["feature/x"].parent === branches.main);
delete branches["feature/x"];
console.log(Object.keys(branches), c3.message);
Add README Add x
true
[ 'main' ] Add x

main נשאר על "Add README"; feature/x זז ל־"Add x", שההורה שלו הוא בדיוק הקצה של main — לכן merge יהיה fast-forward: מספיק להזיז את החץ של main. אחרי delete — המפתח נעלם, אבל c3 עדיין קיים. (זו הסיבה ש־git branch -d מסרב למחוק ענף שלא מוזג — בלי חץ, קשה למצוא את ה־commit שוב. -D מוחק בכל זאת.)

⚠️ טעויות נפוצות
  • לחשוב שיצירת ענף "מעתיקה את הפרויקט". היא יוצרת קובץ קטן עם hash אחד.

P09-E66 · שם ענף מכותרת משימה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

קידומת: title.trim().toLowerCase().startsWith("fix:"). ניקוי: לולאה על התווים — תו "טוב" נשאר, אחר הופך לרווח.

💡 רמז 2

ואז split(" ").filter((w) => w !== "").join("-"), ‏slice(0, 30), ולולאה קטנה (או while) שמורידה - מהסוף.

function branchName(title) {
  let text = title.trim().toLowerCase();
  let prefix = "feature/";
  if (text.startsWith("fix:")) {
    prefix = "fix/";
    text = text.slice(4);
  }
  let clean = "";
  for (const ch of text) {
    const ok = (ch >= "a" && ch <= "z") || (ch >= "0" && ch <= "9");
    clean += ok ? ch : " ";
  }
  let slug = clean.split(" ").filter((w) => w !== "").join("-").slice(0, 30);
  while (slug.endsWith("-")) {
    slug = slug.slice(0, -1);
  }
  return prefix + slug;
}

console.log(branchName("Add monthly summary command"), branchName("FIX: crash when file is empty!"));

function parseBranches(text) {
  let current = null;
  const others = [];
  for (const line of text.split("\n")) {
    if (line.trim() === "") {
      continue;
    }
    const name = line.slice(2).trim();
    if (line.startsWith("* ")) {
      current = name;
    } else {
      others.push(name);
    }
  }
  others.sort((a, b) => a.localeCompare(b));
  return { current, others };
}

console.log(parseBranches("  feature/summary\n* main\n  fix/typo\n"));

module.exports = { parseBranches };
{ current: 'main', others: [ 'feature/summary', 'fix/typo' ] }

Git מזהה ששני הצדדים שינו "אזורים" (hunks, השורות עם @@ בשיעור 2) שלא נוגעים זה בזה, ומחיל את שניהם. אילו השינויים היו בשורות צמודות (למשל 1 ו־2) — הייתה התנגשות, גם אם הן שונות.
