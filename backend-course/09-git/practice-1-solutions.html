P09-E01 · איפה השינוי? 🧠 הבנה רמה 1

💡 רמז 2

סעיף 5: add מכניס לאזור ההכנה את הקובץ כפי שהיה ברגע ה־add.

✅ פתרון
  1. תיקיית עבודה (לא במעקב) ← git add notes.md.
  2. תיקיית עבודה ← git add app.js.
  3. אזור ההכנה ← git commit.
  4. המאגר ← (לשרת: git push, בשיעור 4).
  5. app.js יופיע פעמיים: תחת "Changes to be committed" (הגרסה מרגע ה־add) וגם תחת "Changes not staged" (השינוי החדש). commit עכשיו יכלול רק את הגרסה הראשונה — צריך git add שוב.
⚠️ טעויות נפוצות
  • לחשוב ש־add "מסמן קובץ" לתמיד — הוא מצלם את מצבו באותו רגע.

P09-E06 · מאגר ראשון 💻 כתיבת קוד רמה 2

💡 רמז 1

אחרי כל שינוי: git status ← git add ← git commit -m.

💡 רמז 2

אם נוצר commit עם הודעה גרועה, ועוד לא דחפת: git commit --amend -m "הודעה חדשה" מתקן את האחרון.

✅ פתרון
% mkdir -p playground/git-first && cd playground/git-first
% git init
% echo 'console.log("hello");' > hello.js
% git add hello.js && git commit -m "Add hello script"
% echo "# Git practice" > README.md
% git add README.md && git commit -m "Add README"
% echo 'console.log("from git");' >> hello.js
% git commit -am "Print a second line"
% git log --oneline
c3e1a20 (HEAD -> main) Print a second line
9b7f114 Add README
4f2a9c1 Add hello script
% git status
On branch main
nothing to commit, working tree clean

(ה־hashes אצלך יהיו שונים. >> מוסיף לסוף קובץ, > דורס. && בין פקודות — "רק אם הראשונה הצליחה".)

⚠️ טעויות נפוצות
  • git commit -am על קובץ חדש — הוא לא נכלל, כי -a חל רק על קבצים שכבר במעקב.

P09-E13 · שני commits מבלגן אחד 💻 כתיבת קוד רמה 3

💡 רמז 1

אזור ההכנה: git add README.md לבד ← commit; ואז git add math.js ← commit.

💡 רמז 2

לפני כל commit: git diff --staged כדי לראות שבאזור ההכנה רק מה שצריך.

✅ פתרון
% git status --short
 M README.md
?? math.js
% git add README.md
% git diff --staged
(רק התיקון ב־README)
% git commit -m "Fix typo in README"
% git add math.js
% git commit -m "Add math helpers"
% git log --stat -2
... Add math helpers
 math.js | 4 ++++
... Fix typo in README
 README.md | 2 +-

(אפשר אפילו לפצל שינויים בתוך אותו קובץ: git add -p — אבל זה מצב אינטראקטיבי; ב־VS Code אפשר לבחור שורות בתצוגת ה־diff ולבחור "Stage Selected Ranges".)

⚠️ טעויות נפוצות
  • git commit -am — מכניס את כל הקבצים במעקב, כלומר מבטל את הפיצול.

P09-E27 · ניתוח של git log 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

text.split("\n").filter((line) => line.trim() !== "").map(...). בתוך ה־map: const i = line.indexOf(" ");, ואז line.slice(0, i) ו־line.slice(i + 1).

(split(" ") לא מתאים כאן, כי בהודעה עצמה יש רווחים.)

💡 רמז 2

ב־countTypes: פונקציית עזר typeOf(message) עם indexOf(":"), ואחר כך הדפוס של ספירה מפרק 7: counts[type] = (counts[type] ?? 0) + 1;.

✅ פתרון
// P09-E27: ניתוח של git log
function parseLog(text) {
  return text
    .split("\n")
    .filter((line) => line.trim() !== "")
    .map((line) => {
      const i = line.indexOf(" ");
      return { hash: line.slice(0, i), message: line.slice(i + 1) };
    });
}

function typeOf(message) {
  const i = message.indexOf(":");
  if (i <= 0) return "other";
  const type = message.slice(0, i);
  return type.includes(" ") ? "other" : type.toLowerCase();
}

function countTypes(commits) {
  const counts = {};
  for (const { message } of commits) {
    const type = typeOf(message);
    counts[type] = (counts[type] ?? 0) + 1;
  }
  return counts;
}

const log = `a1b2c3d feat: add login
9f8e7d6 fix: wrong total
5a4b3c2 Update README
1122334 feat: add logout
`;
const commits = parseLog(log);
console.log(commits[2]);
console.log(countTypes(commits));

module.exports = { parseLog, countTypes };
{ hash: '5a4b3c2', message: 'Update README' }
{ feat: 2, fix: 1, other: 1 }

הפלט של git log נגמר בשורה ריקה (אחרי ה־\n האחרון), ולכן ה־filter לפני ה־map חשוב. בלעדיו מתקבל אובייקט עם hash: "".

הבדיקה i <= 0 מכסה שני מקרים: אין נקודתיים בכלל (-1), או שההודעה מתחילה בנקודתיים (0, סוג ריק). ב־for (const { message } of commits) יש destructuring של אובייקט בתוך הלולאה: לוקחים מכל commit רק את השדה שצריך.

⚠️ טעויות נפוצות
  • line.split(" ") ואז [hash, message] — ההודעה נחתכת אחרי המילה הראשונה ("feat:").
  • counts[type]++ בלי ערך התחלתי — undefined + 1 הוא NaN.
  • לשכוח את בדיקת הרווח — "Merge branch 'x': conflicts" נספר כסוג "merge branch 'x'".
