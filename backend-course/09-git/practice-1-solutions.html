💡 רמז 2

סעיף 5: add מכניס לאזור ההכנה את הקובץ כפי שהיה ברגע ה־add.

✅ פתרון

P09-E29 · באיזה אזור כל קובץ? 🧠 הבנה רמה 1

💡 רמז 1

עקוב אחרי כל קובץ לבד: מתי נוצר, מתי נכנס לאזור ההכנה, ומתי השתנה אחרי זה.

💡 רמז 2

app.js כבר ב־commit — והשורה השנייה נוספה אחריו, בלי add.

✅ פתרון
% git status --short
A  README.md
 M app.js
?? notes.txt
% git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	new file:   README.md

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   app.js

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	notes.txt

README.md — staged (A = added). app.js — modified, לא staged (ה־M בעמודה השנייה). notes.txt — untracked (??). commit עכשיו יכניס רק את README.md: commit מצלם את אזור ההכנה, לא את התיקייה.

⚠️ טעויות נפוצות
  • לחשוב ש־commit לוקח "את כל מה שהשתנה". הוא לוקח רק את מה שב־staging.

P09-E30 · add ואז שינוי נוסף 🧠 הבנה רמה 2

💡 רמז 1

git add מכניס לאזור ההכנה את הקובץ במצבו באותו רגע — כמו צילום.

💡 רמז 2

השינוי ל־v2 קרה אחרי הצילום.

✅ פתרון
% git show HEAD:notes.txt
v1
% cat notes.txt
v2
% git status --short
 M notes.txt

ה־commit מכיל v1 — מה שהיה באזור ההכנה. הקובץ בתיקייה הוא v2, ו־Git מסמן אותו כ־modified. (git show HEAD:notes.txt מציג קובץ כפי שהוא ב־commit האחרון.) זה מה שמאפשר "לבחור" מה נכנס — וזו גם מלכודת: תמיד git status (או git diff --staged, שיעור 2) לפני commit.

⚠️ טעויות נפוצות
  • להריץ git add פעם אחת בתחילת העבודה, ולחשוב שכל השינויים שאחריו "בפנים".

P09-E31 · hash, HEAD ו־main 🧠 הבנה רמה 1

💡 רמז 1

ה־hash נגזר מכל מה שב־commit — כולל מי עשה ומתי.

💡 רמז 2

main הוא שם של ענף (שיעור 3). HEAD = "איפה אני עכשיו".

✅ פתרון
  1. תחילת ה־hash של ה־commit — המזהה הייחודי שלו (המלא ארוך יותר; 7 תווים מספיקים כדי לזהות).
  2. ה־hash מחושב מהתוכן, מההודעה, מהשם והאימייל, מהשעה, ומה־hash של ה־commit הקודם. שעה אחרת או שם אחר ← hash אחר. (ולכן "שינוי היסטוריה" משנה את כל ה־hashes שאחריו.)
  3. HEAD — המקום שבו אתה נמצא עכשיו; הוא מצביע על הענף main, שמצביע על ה־commit הזה.
  4. מהחדש לישן — האחרון למעלה.
⚠️ טעויות נפוצות
  • להעתיק hash ממדריך ולהריץ איתו פקודה — אצלך הוא לא קיים.

P09-E06 · מאגר ראשון 💻 כתיבת קוד רמה 2

💡 רמז 1

אחרי כל שינוי: git status ← git add ← git commit -m.

💡 רמז 2

אם נוצר commit עם הודעה גרועה, ועוד לא דחפת: git commit --amend -m "הודעה חדשה" מתקן את האחרון.

✅ פתרון
% mkdir -p playground/git-first && cd playground/git-first
% git init
% echo 'console.log("hello");' > hello.js
% git add hello.js && git commit -m "Add hello script"
% echo "# Git practice" > README.md
% git add README.md && git commit -m "Add README"
% echo 'console.log("from git");' >> hello.js
% git commit -am "Print a second line"
% git log --oneline
c3e1a20 (HEAD -> main) Print a second line
9b7f114 Add README
4f2a9c1 Add hello script
% git status
On branch main
nothing to commit, working tree clean

(ה־hashes אצלך יהיו שונים. >> מוסיף לסוף קובץ, > דורס. && בין פקודות — "רק אם הראשונה הצליחה".)

⚠️ טעויות נפוצות
  • git commit -am על קובץ חדש — הוא לא נכלל, כי -a חל רק על קבצים שכבר במעקב.

P09-E13 · שני commits מבלגן אחד 💻 כתיבת קוד רמה 3

💡 רמז 2

לפני כל commit: git diff --staged כדי לראות שבאזור ההכנה רק מה שצריך.

P09-E37 · בודק הודעות commit 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

guard להודעה ריקה, ואז ארבעה if נפרדים עם push (כמו P07-E56). הרשימה של המילים — מערך עם includes.

💡 רמז 2

אות קטנה: first >= "a" && first <= "z" (השוואת מחרוזות, פרק 3).

✅ פתרון
09-git/starter/P09-E37.js 
const VAGUE = ["fix", "update", "changes", "wip", "stuff", "asdf"];

function checkMessage(msg) {
  const text = msg.trim();
  if (text === "") {
    return ["הודעה ריקה"];
  }
  const problems = [];
  if (VAGUE.includes(text.toLowerCase())) {
    problems.push("לא אומרת מה השתנה");
  }
  if (text.length > 50) {
    problems.push("ארוכה מ־50 תווים");
  }
  if (text[0] >= "a" && text[0] <= "z") {
    problems.push("מתחילה באות קטנה");
  }
  if (text.endsWith(".")) {
    problems.push("נגמרת בנקודה");
  }
  return problems;
}

console.log(checkMessage("fixed the bug."), checkMessage("WIP"));

module.exports = { checkMessage };
[ 'מתחילה באות קטנה', 'נגמרת בנקודה' ] [ 'לא אומרת מה השתנה' ]

בודק כזה רץ באמת בחברות — כ־"commit hook" שעוצר commit עם הודעה רעה, או בבדיקות של Pull Request (פרק 25).

⚠️ טעויות נפוצות
  • לבדוק את האורך לפני trim — רווחים בסוף נספרים.

P09-E39 · לפרק את git status בקוד 🧠 הבנה רמה 2

💡 רמז 1

השורה האחרונה בטקסט ריקה (ה־\n בסוף), וה־filter זורק אותה.

💡 רמז 2

" M app.js".split(" ") — הרווח הראשון בא לפני ה־M.

✅ פתרון
const status = "A  README.md\n M app.js\n?? notes.txt\n";
const lines = status.split("\n").filter((l) => l !== "");
console.log(lines.length);
console.log(lines.map((l) => l.slice(3)));
console.log(lines.filter((l) => l.startsWith("??")).length);
console.log(lines.map((l) => l.split(" ")));
3
[ 'README.md', 'app.js', 'notes.txt' ]
1
[
  [ 'A', '', 'README.md' ],
  [ '', 'M', 'app.js' ],
  [ '??', 'notes.txt' ]
]

slice(3) נותן את שמות הקבצים בדיוק. אבל split(" ") מחזיר תוצאות שונות לכל שורה: ב־"A README.md" יש שני רווחים (מחרוזת ריקה באמצע), וב־" M app.js" — מחרוזת ריקה בהתחלה. כשיש פורמט עם עמודות ברוחב קבוע — חותכים לפי מיקום, לא לפי רווחים. (פלט לבני אדם עלול להשתנות בין גרסאות; לכן לסקריפטים יש git status --porcelain — פורמט שמובטח שלא ישתנה.)

⚠️ טעויות נפוצות
  • split(" ")[1] כ"שם הקובץ" — עובד לחלק מהשורות בלבד.

P09-E40 · הודעת commit כמו שם של פונקציה 🧠 הבנה רמה 1

💡 רמז 1

שני המקרים מתחילים בפועל באנגלית. ההבדל באות הראשונה ובמה שבא אחרי.

💡 רמז 2

commit מתאר שינוי בקוד; פונקציה מתארת פעולה שהקוד עושה בכל קריאה.

✅ פתרון
הודעת commitשם פונקציה
1Add shipping cost by weightcalculateShipping(weightKg)
2Fix crash on empty expenses file— (תיקון הוא שינוי, לא פעולה; הפונקציה המתוקנת שומרת על שמה, למשל loadExpenses)
3Remove legacy-import command— (מחיקה)

דומה: פועל בציווי בהתחלה, ובלי מילים כמו "stuff". שונה: commit מתאר מה השתנה בפרויקט (Add / Fix / Remove), ולכן יש הודעות שאין להן פונקציה מקבילה.

⚠️ טעויות נפוצות
  • הודעה בזמן עבר (Added, ‏Fixed) — לא שגיאה, אבל המוסכמה ברוב הפרויקטים היא ציווי.

P09-E41 · תיקייה ריקה 🧠 הבנה רמה 2

💡 רמז 1

מה Git שומר ב־commit — קבצים, או גם תיקיות?

💡 רמז 2

.gitkeep הוא לא שם מיוחד ל־Git. הוא פשוט קובץ ריק עם שם שמסביר למה הוא שם.

✅ פתרון
% git status
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)
% touch logs/.gitkeep
% git status --short
?? logs/

תיקייה ריקה "לא קיימת" מבחינת Git. אחרי שיש בה קובץ — היא מופיעה (?? logs/ — Git מקצר תיקייה חדשה לשורה אחת). מוסכמה נפוצה: קובץ ריק בשם .gitkeep בתיקיות שחייבות להיות במאגר (למשל logs/ שהקוד כותב אליה).

⚠️ טעויות נפוצות
  • לשלוח לחבר מאגר "עם תיקיית uploads" ריקה — אצלו היא לא תהיה, והקוד יקרוס ב־ENOENT.

P09-E27 · ניתוח של git log 🤖 💻 כתיבת קוד 🤖 רמה 2

// P09-E27: ניתוח של git log
function parseLog(text) {
  return text
    .split("\n")
    .filter((line) => line.trim() !== "")
    .map((line) => {
      const i = line.indexOf(" ");
      return { hash: line.slice(0, i), message: line.slice(i + 1) };
    });
}

function typeOf(message) {
  const i = message.indexOf(":");
  if (i <= 0) return "other";
  const type = message.slice(0, i);
  return type.includes(" ") ? "other" : type.toLowerCase();
}

function countTypes(commits) {
  const counts = {};
  for (const { message } of commits) {
    const type = typeOf(message);
    counts[type] = (counts[type] ?? 0) + 1;
  }
  return counts;
}

const log = `a1b2c3d feat: add login
9f8e7d6 fix: wrong total
5a4b3c2 Update README
1122334 feat: add logout
`;
const commits = parseLog(log);
console.log(commits[2]);
console.log(countTypes(commits));

module.exports = { parseLog, countTypes };
{ hash: '5a4b3c2', message: 'Update README' }
{ feat: 2, fix: 1, other: 1 }

הפלט של git log נגמר בשורה ריקה (אחרי ה־\n האחרון), ולכן ה־filter לפני ה־map חשוב. בלעדיו מתקבל אובייקט עם hash: "".

הבדיקה i <= 0 מכסה שני מקרים: אין נקודתיים בכלל (-1), או שההודעה מתחילה בנקודתיים (0, סוג ריק). ב־for (const { message } of commits) יש destructuring של אובייקט בתוך הלולאה: לוקחים מכל commit רק את השדה שצריך.

⚠️ טעויות נפוצות
  • line.split(" ") ואז [hash, message] — ההודעה נחתכת אחרי המילה הראשונה ("feat:").
  • counts[type]++ בלי ערך התחלתי — undefined + 1 הוא NaN.
  • לשכוח את בדיקת הרווח — "Merge branch 'x': conflicts" נספר כסוג "merge branch 'x'".

function parseStatus(text) {
  const result = { staged: [], modified: [], untracked: [] };
  for (const line of text.split("\n")) {
    if (line === "") {
      continue;
    }
    const file = line.slice(3);
    if (line.startsWith("??")) {
      result.untracked.push(file);
      continue;
    }
    if (line[0] !== " ") {
      result.staged.push(file);
    }
    if (line[1] !== " ") {
      result.modified.push(file);
    }
  }
  return result;
}

console.log(parseStatus("A  README.md\n M app.js\nMM cart.js\n?? notes.txt\n"));

  modified: [ 'app.js', 'cart.js' ],
  untracked: [ 'notes.txt' ]
}

function shortlog(text) {
  const counts = new Map();
  for (const line of text.split("\n")) {
    if (line.trim() === "") {
      continue;
    }
    const name = line.slice(0, line.indexOf("|"));
    counts.set(name, (counts.get(name) ?? 0) + 1);
  }
  return [...counts]
    .sort((a, b) => b[1] - a[1] || a[0].localeCompare(b[0]))
    .map(([name, n]) => `${String(n).padStart(4)}  ${name}`);
}

console.log(shortlog("Dana|Add login\nOmer|Fix total\nDana|Add logout\nNoa|Update README\nDana|Add tests\n"));

module.exports = { shortlog };
[ '   3  Dana', '   1  Noa', '   1  Omer' ]
