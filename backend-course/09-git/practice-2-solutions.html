P09-E15 · איזה ביטול? 🧠 הבנה רמה 3

💡 רמז 1

שיעור 2, טבלת הביטולים.

💡 רמז 2

"דחפתי" ← לא משכתבים היסטוריה.

✅ פתרון
  1. git restore cli.js — השינויים של השעה נמחקים לתמיד. (אם יש בהם משהו שווה — קודם git stash, או העתק לקובץ אחר.)
  2. git restore --staged debug.log — יוצא מאזור ההכנה, נשאר בדיסק. ואז להוסיף *.log ל־.gitignore.
  3. git revert <hash> — commit חדש שמבטל; בטוח אחרי push.
  4. git add file ← git commit --amend --no-edit.
  5. git status, git log --oneline, git diff — פקודות שרק מסתכלות, תמיד בטוחות.
⚠️ טעויות נפוצות
  • להשתמש ב־git reset --hard כי "ראיתי באינטרנט" — מוחק גם שינויים שרצית לשמור.

P09-E21 · "Git מחק לי את הקוד!" 🧠 הבנה רמה 4

💡 רמז 1

כל מה שנכנס ל־commit (או ל־stash) — Git זוכר.

💡 רמז 2

מה שמעולם לא נכנס ל־commit ונדרס — Git לא ראה אותו.

✅ פתרון
  1. לא אבד — הוא בענף feature/x. git switch feature/x.
  2. אבד. השינויים לא היו ב־Git אף פעם. (אולי בהיסטוריה המקומית של VS Code: לחיצה ימנית על הקובץ ← "Open Timeline".) לקח: commit לעתים קרובות, גם בענף פרטי.
  3. לא אבד — git stash list, ו־git stash pop.
  4. לא אבד — ה־commit המקורי עדיין בהיסטוריה; אפשר git revert על ה־revert, או לראות אותו עם git show.
⚠️ טעויות נפוצות
  • להריץ עוד פקודות "מצילות" מהאינטרנט בפאניקה — עלול להחמיר. קודם git status ו־git log.

P09-E44 · diff מול diff --staged 🧠 הבנה רמה 2

💡 רמז 1

git diff — התיקייה מול אזור ההכנה. git diff --staged — אזור ההכנה מול ה־commit האחרון.

💡 רמז 2

שינוי המע״מ כבר באזור ההכנה; שינוי המשלוח — רק בתיקייה.

✅ פתרון
% git diff
diff --git a/prices.js b/prices.js
index 987622f..5bf5592 100644
--- a/prices.js
+++ b/prices.js
@@ -1,2 +1,2 @@
 const VAT = 0.18;
-const SHIPPING = 25;
+const SHIPPING = 30;
% git diff --staged
diff --git a/prices.js b/prices.js
index cbe25dd..987622f 100644
--- a/prices.js
+++ b/prices.js
@@ -1,2 +1,2 @@
-const VAT = 0.17;
+const VAT = 0.18;
 const SHIPPING = 25;

commit עכשיו יכניס רק את המע״מ — מה ש־--staged מראה. שים לב שב־git diff השורה של המע״מ היא כבר "הקשר" (בלי סימן): מבחינתו, 0.18 הוא נקודת ההתחלה.

⚠️ טעויות נפוצות
  • להריץ רק git diff לפני commit, לראות "רק המשלוח", ולהיות בטוח שזה מה שנכנס — בדיוק ההפך.

P09-E45 · מה אבד ומה לא? 🧠 הבנה רמה 2

💡 רמז 1

שאל לכל אחד: האם השינוי היה אי פעם ב־commit?

💡 רמז 2

רק אחת מהן מוחקת משהו לתמיד.

✅ פתרון
  1. נמחק לתמיד. השינוי לא נשמר אף פעם ב־Git — אין ממה לשחזר. (אולי ב־Undo של העורך, אם הקובץ עוד פתוח.)
  2. שום דבר לא אבד. הקובץ רק יוצא מאזור ההכנה; השינויים נשארים בתיקייה.
  3. שום דבר לא אבד. נוצר commit חדש שעושה את ההפך; ה־commit המקורי נשאר בהיסטוריה (ואפשר אפילו לבטל את הביטול).
  4. שום דבר לא אבד — ה־commit האחרון מוחלף בגרסה שכוללת גם את הקובץ (עם hash חדש). לכן לא עושים --amend ל־commit שכבר נדחף.
⚠️ טעויות נפוצות
  • להריץ git restore . "כדי לנקות" — כל העבודה שלא נשמרה נמחקת.

P09-E46 · מה .gitignore יתפוס? 🧠 הבנה רמה 2

💡 רמז 1

תבנית בלי / באמצע תופסת בכל עומק: *.log תופס גם logs/server.log.

💡 רמז 2

.env תופס רק קובץ ששמו בדיוק .env. ו־dist/ — כל תיקייה בשם dist, גם עמוק.

✅ פתרון
% git status --short -uall
?? .env.example
?? .gitignore
?? app.js

(-uall מציג כל קובץ בנפרד, במקום לקצר תיקיות.) config/.env נתפס (שם זהה, בתיקייה אחרת), .env.example — לא, וזה טוב: הוא נכנס למאגר כדי להראות אילו משתנים צריך, בלי ערכים (P09-E54). src/dist/notes.md נתפס — אם התכוונת רק ל־dist שבשורש, כותבים /dist/.

⚠️ טעויות נפוצות
  • לשכוח ש־.gitignore עצמו מופיע — הוא צריך להיכנס ל־commit.

P09-E14 · מי הכניס את הבאג? 💻 כתיבת קוד רמה 3

💡 רמז 1

git log --oneline -- discount.js ו־git show.

💡 רמז 2

percent מגיע כמספר שלם (20), לא כשבר (0.2).

✅ פתרון
% git log --oneline -- discount.js
c1a703d Add discount
% git show c1a703d
+function discount(p, percent) {
+  return p - p * percent;
+}
discount.js 
function discount(p, percent) {
  return p - (p * percent) / 100;
}
module.exports = { discount };
% git commit -am "Fix discount to use percent, not fraction"

revert היה מוחק את כל התכונה (הפונקציה כולה). כאן התכונה רצויה וצריך רק תיקון — commit קדימה. revert מתאים כשרוצים לבטל שינוי שלם (למשל תכונה שגרמה לתקלה בייצור).

⚠️ טעויות נפוצות
  • "לתקן" את ה־commit הישן עצמו — אי אפשר בלי לשכתב היסטוריה; ובמאגר משותף אסור.

P09-E20 · node_modules נכנס למאגר 💻 כתיבת קוד רמה 4

💡 רמז 1

git rm --cached — "תפסיק לעקוב", הקובץ נשאר. לתיקייה: -r.

💡 רמז 2

הסוד ב־.env כבר נמצא ב־commit "stuff" בהיסטוריה.

✅ פתרון
% git add . && git commit -m "stuff"
% git rm -r --cached node_modules .env .DS_Store
rm '.DS_Store'
rm '.env'
rm 'node_modules/left-pad/index.js'
% printf "node_modules/\n.env\n.DS_Store\n" > .gitignore
% git add .gitignore
% git commit -m "Stop tracking dependencies, secrets and OS files"
% ls -a
(הקבצים עדיין בדיסק)

ה־.env: הסיסמה שבתוכו נמצאת ב־commit "stuff" בהיסטוריה. אם המאגר נדחף (או יידחף) — יש להחליף את הסיסמה אצל המסד (rotate). אם עוד לא דחפת, אפשר גם לבטל את ה־commit לפני ה־push — אבל החלפת הסיסמה היא הדרך הבטוחה.

⚠️ טעויות נפוצות
  • git rm בלי --cached — מוחק גם מהדיסק.

P09-E26 · מאגר ראשון — כסקריפט 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הסקריפט נראה כמו הפתרון של P09-E06: git init, ואחר כך שלוש פעמים "יוצרים או משנים קבצים ← git add ← git commit -m".

💡 רמז 2

ב־commit השני, git add . מוסיף את כל מה שלא מוסתר. app.log לא ייכנס, כי .gitignore כבר קיים באותו רגע. ב־commit השלישי מספיק git commit -am, כי notes.txt כבר במעקב.

✅ פתרון
# P09-E26: מאגר ראשון — כסקריפט
git init

echo "# Notes" > README.md
git add README.md
git commit -m "Add README"

echo "first note" > notes.txt
echo "*.log" > .gitignore
echo "debug" > app.log
git add .
git commit -m "Add notes"

echo "second note" >> notes.txt
git commit -am "Add second note"

אחרי הרצה בתיקייה ריקה:

% git log --oneline
33fb3a3 Add second note
f5b061d Add notes
a49e5f3 Add README
% git status
On branch main
nothing to commit, working tree clean

(ה־hashes אצלך יהיו שונים.) app.log נמצא בתיקייה (ls יראה אותו), אבל git status לא מזכיר אותו בכלל — זו בדיוק המטרה של .gitignore. הסדר בסקריפט חשוב: .gitignore נוצר לפני git add .. אילו היה נוצר אחריו, app.log כבר היה ב־staging, ונכנס ל־commit.

סקריפט כזה הוא גם תיעוד: אפשר לשחזר איתו את המאגר מאפס בכל רגע. בפרק 23 תכתוב סקריפטים ארוכים יותר, עם תנאים ועם בדיקת שגיאות.

⚠️ טעויות נפוצות
  • echo "second note" > notes.txt (חץ אחד) — דורס את הקובץ, ו־first note נמחק.
  • git commit -am "Add notes" ב־commit השני — -a לא מוסיף קבצים חדשים, ולכן ה־commit נכשל ("nothing added to commit").
  • להריץ את הסקריפט פעמיים באותה תיקייה — בפעם השנייה יש כבר commits, והמאגר נראה אחרת. לכל ניסיון — תיקייה חדשה.

P09-E47 · revert ל־commit עם באג 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

HEAD~1 = "ה־commit שלפני האחרון" — כאן, ה־commit עם הטעות.

💡 רמז 2

ב־commit השני, git commit -am מספיק — הקובץ כבר במעקב.

✅ פתרון
09-git/starter/P09-E47.sh 
git init
echo "0.17" > vat.txt
git add vat.txt
git commit -m "Add VAT"

echo "0.71" > vat.txt
git commit -am "Change VAT to 0.71"

echo "# Shop" > README.md
git add README.md
git commit -m "Add README"

git revert --no-edit HEAD~1
% git log --oneline
5e2c9a1 (HEAD -> main) Revert "Change VAT to 0.71"
b81f0d4 Add README
3c7a2e9 Change VAT to 0.71
a19d6f2 Add VAT

ה־commit עם הטעות נשאר בהיסטוריה, ואחריו commit שעושה את ההפך. ה־README — שנוצר אחרי הטעות — לא נגע. זה היתרון של revert: מבטלים שינוי אחד באמצע, בלי לגעת במה שאחריו.

⚠️ טעויות נפוצות
  • git revert HEAD — מבטל את ה־README במקום את הטעות.

P09-E48 · שכחתי קובץ ב־commit 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

אחרי ה־commit הראשון: git add utils.js, ואז git commit --amend --no-edit.

💡 רמז 2

ב־echo של app.js יש מירכאות כפולות — עטוף במירכאות בודדות (P09-E34). ו־{} ו־; בתוך מירכאות לא מפריעים.

✅ פתרון
09-git/starter/P09-E48.sh 
git init
echo 'require("./utils")' > app.js
echo "module.exports = {};" > utils.js
git add app.js
git commit -m "Add app"

git add utils.js
git commit --amend --no-edit

--amend לא "מוסיף" ל־commit — הוא יוצר commit חדש במקומו (hash אחר). כל עוד לא דחפת (שיעור 4) — זה בסדר; אחרי — כבר לא.

⚠️ טעויות נפוצות
  • commit שני בשם Add utils — עובד, אבל ההיסטוריה מכילה commit "שבור" (app.js בלי utils).

P09-E49 · להוציא מהמעקב בלי למחוק 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

הקופסה ⚠️ בשיעור: git rm --cached file — מסיר מהמעקב ומשאיר בדיסק.

💡 רמז 2

ליצירת .gitignore עם שתי שורות: echo ואז echo ... >>, או printf "*.log\n.env\n" > .gitignore.

✅ פתרון
09-git/starter/P09-E49.sh 
git init
echo "console.log(1)" > app.js
echo "trace" > debug.log
echo "API_KEY=123" > .env
git add .
git commit -m "Initial commit"

printf "*.log\n.env\n" > .gitignore
git rm --cached debug.log .env
git add .gitignore
git commit -m "Stop tracking log and env"

אחרי git rm --cached הקבצים נראים ב־status כ"נמחקו" (מהמעקב) — וה־commit רושם את זה. מכאן .gitignore דואג שלא ייכנסו שוב. אבל: .env עדיין נמצא ב־commit הראשון. אם המאגר נדחף — הסוד דלף (שיעור 4).

⚠️ טעויות נפוצות
  • git rm debug.log בלי --cached — הקובץ נמחק גם מהדיסק.
  • להוסיף ל־.gitignore בלי rm --cached — הקבצים כבר במעקב, ו־.gitignore לא משפיע עליהם.

P09-E50 · "אתמול זה עבד" 🧠 הבנה רמה 2

💡 רמז 1

הבאג חייב להיות באחד מהשינויים שבין "עבד" ל"לא עבד". איך רואים אותם?

💡 רמז 2

git diff — מה שלא נשמר. git log -p / git show — מה שכל commit שינה. git stash (שיעור 3) — לבדוק בלי השינויים שלא נשמרו.

✅ פתרון
  1. שחזר: מריצים את הבודק — נכשל. (מתעדים את ההודעה.)
  2. בודד: git diff מראה מה לא נשמר; git stash → מריצים שוב: אם עובר — הבאג בשינויים שלא נשמרו (git stash pop להחזיר). אם עדיין נכשל — git log -p על שלושת ה־commits, או בדיקה של כל commit (git switch --detach <hash>, ואחר כך git switch main) — ובמאות commits: git bisect (P09-E25).
  3. השערה: מתוך השורות ששונו — "השינוי של <= ב־commit השני גורם ל...".
  4. תקן: commit חדש עם שינוי אחד (או git revert אם ה־commit כולו שגוי).
  5. הוכח: הבודק עובר; git diff --staged לפני ה־commit — רק התיקון נכנס.
⚠️ טעויות נפוצות
  • לחפש את הבאג בכל הקוד, כשאפשר לצמצם ל"מה שהשתנה מאז שעבד".

P09-E51 · לספור שורות ב־diff 🧠 הבנה רמה 2

💡 רמז 1

אילו שורות מתחילות ב־+? (כולן — לא רק שורות הקוד.)

💡 רמז 2

P09-E28 · .gitignore קטן משלך 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני שלבים. קודם הופכים את הטקסט לרשימת כללים: split("\n") ← map(trim) ← filter (בלי ריקות ובלי #). אחר כך: rules.some((rule) => matches(filePath, rule)).

💡 רמז 2

matches היא פונקציה עם שלושה if ו־return בכל אחד: rule.endsWith("/"), ‏rule.startsWith("*."), ובסוף המקרה של שם מדויק. בכלל של תיקייה, rule כבר נגמר ב־/, ולכן הבדיקה היא filePath.startsWith(rule) || filePath.includes("/" + rule).

✅ פתרון
// P09-E28: .gitignore קטן משלך
function matches(filePath, rule) {
  if (rule.endsWith("/")) {
    return filePath.startsWith(rule) || filePath.includes("/" + rule);
  }
  if (rule.startsWith("*.")) {
    return filePath.endsWith(rule.slice(1));
  }
  return filePath === rule || filePath.endsWith("/" + rule);
}

function isIgnored(filePath, gitignore) {
  const rules = gitignore
    .split("\n")
    .map((line) => line.trim())
    .filter((line) => line !== "" && !line.startsWith("#"));
  return rules.some((rule) => matches(filePath, rule));
}

הפירוק לשתי פונקציות שומר על כל אחת פשוטה. isIgnored מטפלת בטקסט (שורות, הערות, רווחים), ו־matches מטפלת בכלל אחד מול נתיב אחד. ה־some עוצר בכלל הראשון שמתאים, ולא ממשיך לבדוק את השאר.

rule.slice(1) מוריד את ה־* ומשאיר .log. בלי הנקודה, catalog היה נחשב "נגמר ב־log". וב־.env הבדיקה מדויקת: .env.example לא מוסתר, וזה מה שרוצים — את קובץ הדוגמה כן מכניסים למאגר (פרק 13).

ל־Git האמיתי יש עוד כללים (! לביטול, **, נתיב שמתחיל ב־/), אבל הבסיס הוא אותו בסיס.

⚠️ טעויות נפוצות
  • filePath.includes(rule) לכל הכללים — .env מוסתר גם ב־.env.example, ו־node_modules/ גם ב־my_node_modules/.
  • לשכוח trim — שורה כמו "*.log " (עם רווח בסוף) לא מתאימה לאף קובץ.
  • לא לסנן שורות ריקות — כלל ריק נופל למקרה של "שם מדויק", ו־filePath.endsWith("/") מחזירה true לכל נתיב שנגמר ב־/. עדיף לסנן במפורש.

function diffStat(diff) {
  const stat = { files: 0, added: 0, removed: 0 };
  for (const line of diff.split("\n")) {
    if (line.startsWith("diff --git ")) {
      stat.files++;
    } else if (line.startsWith("+++") || line.startsWith("---")) {
      continue;
    } else if (line.startsWith("+")) {
      stat.added++;
    } else if (line.startsWith("-")) {
      stat.removed++;
    }
  }
  return stat;
}

function toExample(envText, keep = []) {
  const out = [];
  for (const line of envText.split("\n")) {
    const trimmed = line.trim();
    if (trimmed === "" || trimmed.startsWith("#")) {
      out.push(line);
      continue;
    }
    const eq = line.indexOf("=");
    if (eq === -1) {
      continue;
    }
    const key = line.slice(0, eq).trim();
    out.push(keep.includes(key) ? `${key}=${line.slice(eq + 1)}` : `${key}=`);
  }
  return out.join("\n");
}
