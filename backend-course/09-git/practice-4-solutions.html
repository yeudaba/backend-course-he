P09-E05 · Git, GitHub, ומה איפה 🧠 הבנה רמה 1

💡 רמז 1

Git הוא כלי מקומי; GitHub הוא רק עוד עותק.

💡 רמז 2

push שולח commits, לא "קבצים בתיקייה".

✅ פתרון
  1. ✘ — commit הוא מקומי לגמרי. רק push/pull/clone צריכים רשת.
  2. ✘ — push שולח commits שעוד אין בשרת. שינויים שלא נכנסו ל־commit, וקבצים ב־.gitignore, לא נשלחים.
  3. ✘ — clone מוריד את כל ההיסטוריה.
  4. ✘ — הסיסמה עדיין בהיסטוריה, בכל commit ישן. צריך לבטל אותה אצל הספק (rotate).
  5. ✔ (מבחינה טכנית: pull = fetch + merge.)
⚠️ טעויות נפוצות
  • להתבלבל בין "Git" ל־"GitHub" — בראיון זו שאלה קלאסית.

P09-E69 · ahead by 1 commit 🧠 הבנה רמה 1

💡 רמז 1

origin/main הוא "מה שידוע לי על main בשרת" — עותק מקומי של המצביע שם.

💡 רמז 2

commit שמור רק אצלך עד push.

✅ פתרון
  1. המצביע של הענף main ב־remote בשם origin (GitHub), כפי שהיה ב־push/pull האחרון.
  2. לא — הוא רק אצלך. ‏"ahead by 1" = יש לך commit אחד שאין בשרת.
  3. ה־commit האחרון (וכל שינוי שלא נשמר). כל מה שנדחף — בטוח.
  4. "clean" = אין שינויים שלא נכנסו ל־commit. זה לא אומר שה־commits נדחפו. לכן בסוף יום עבודה: commit וגם push.
⚠️ טעויות נפוצות
  • לחשוב ש־commit "שומר בענן". ‏commit — מקומי; ‏push — לענן.

P09-E70 · push נדחה 🧠 הבנה רמה 2

💡 רמז 1

קרא את שורות ה־hint — הן אומרות בדיוק מה לעשות.

💡 רמז 2

git pull = להוריד את ה־commits החדשים ולמזג אותם לענף שלך (שיעור 3).

✅ פתרון
  1. בשרת יש commit שאין אצלך. אילו Git היה מקבל את ה־push, ה־commit של החבר היה נדרס.
  2. git pull ← (בודקים שהקוד עובד) ← git push.
  3. ה־pull ממזג — ואם שניכם שיניתם את אותן שורות, תהיה התנגשות. פותרים בדיוק כמו בשיעור 3 (‏add + commit), ואז push.
  4. --force "מנצח" — ומוחק מהשרת את העבודה של החבר (השיעור 2: פקודות מסוכנות).
⚠️ טעויות נפוצות
  • לחפש באינטרנט את ההודעה ולהעתיק את התשובה הראשונה עם --force.

P09-E71 · מה מקבלים ב־clone? 🧠 הבנה רמה 1

💡 רמז 1

clone = עותק מלא של המאגר (התיקייה .git) + הקבצים של הענף הראשי.

💡 רמז 2

מה שב־.gitignore לא נכנס למאגר מלכתחילה — אז גם לא יוצא ממנו.

✅ פתרון
  1. לא נכון — מקבלים את כל ההיסטוריה (ולכן סוד שנדחף פעם — נמצא אצל כל מי שעושה clone).
  2. נכון.
  3. לא נכון — clone כבר מגדיר origin שמצביע על הכתובת שממנה שכפלת.
  4. לא (אם הוא ב־.gitignore, כמו שצריך). צריך ליצור אותו לבד — מתוך .env.example (P09-E52).
  5. לא (אם הוא ב־.gitignore) — מריצים npm install (פרק 13).
⚠️ טעויות נפוצות
  • לשלוח לחבר את .env במייל "כי ה־clone לא עובד". ‏.env.example + ערכים בערוץ מאובטח.

P09-E72 · תיאור של Pull Request 🧠 הבנה רמה 2

💡 רמז 1

חזור לשלב 4 בזרימת העבודה בשיעור: מה, למה, ואיך בודקים.

💡 רמז 2

הסוקר לא היה איתך כשכתבת. מה הוא צריך כדי להבין ולבדוק תוך 5 דקות?

✅ פתרון

3 ← 2 ← 1. ב־3 יש מה, למה ואיך בודקים — כולל מקרה קצה. ב־2 "עובד" לא אומר איך בדקת. ‏1 — כמעט כלום. אפשר לשפר את 3 עם: קישור למשימה (issue), ומה לא נבדק או ידוע כחסר (למשל "עוד אין בדיקה אוטומטית"). PR קטן עם תיאור כזה נסקר מהר; PR ענק בלי תיאור — שוכב שבוע.

⚠️ טעויות נפוצות
  • PR שמכיל גם את edit וגם "סידרתי את כל הקוד" — קשה לסקור, וקשה לבטל רק חלק.

P09-E73 · מחקתי את הסוד — זה מספיק? 🧠 הבנה רמה 2

💡 רמז 1

git log -p מציג את כל השינויים בכל ה־commits — גם שורות שנמחקו.

💡 רמז 2

המפתח מופיע פעמיים: כשורה שנוספה (ב־commit הראשון), וכשורה שנמחקה (בשני).

✅ פתרון
% git log -p | grep "sk_live"
-const API_KEY = "sk_live_51Hx9QzA";
+const API_KEY = "sk_live_51Hx9QzA";

המפתח עדיין בהיסטוריה — כל מי שעשה clone יכול למצוא אותו בשנייה (ובוטים עושים את זה אוטומטית). ה־commit השני תיקן את הקוד, לא את הדליפה. לכן הצעד הראשון הוא תמיד לבטל את המפתח אצל הספק (rotate) — ראה הסדר בשיעור.

⚠️ טעויות נפוצות
  • git revert ל־commit עם הסוד — יוצר commit שלישי, וה־commit עם הסוד עדיין שם.

P09-E11 · פרויקט 1 ב־GitHub 💻 כתיבת קוד רמה 2

💡 רמז 1

אם כבר עשית commit אחד גדול — זה בסדר. מעכשיו, כל שיפור — commit נפרד.

💡 רמז 2

שגיאת "remote origin already exists"? git remote -v מראה לאן הוא מצביע; git remote set-url origin <url> מתקן.

✅ פתרון

ראה הפקודות בשיעור 4. בדיקה מהירה מה־Terminal: git remote -v מציג את כתובת GitHub; git status אומר Your branch is up to date with 'origin/main'.

🎉 זה הפריט הראשון בתיק העבודות שלך. העתק את הקישור למקום בטוח — הוא ייכנס לקורות החיים בפרק 30.

⚠️ טעויות נפוצות
  • יצירת המאגר ב־GitHub עם README — ואז push נדחה ("rejected... fetch first"). הפתרון: git pull origin main --allow-unrelated-histories, לפתור אם צריך, ו־push. או למחוק את המאגר בגיטהאב וליצור מחדש בלי README.

P09-E12 · שני מחשבים 💻 כתיבת קוד רמה 2

P09-E76 · סורק סודות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

לולאה עם אינדקס. לכלל 3: const eq = line.indexOf("="); — המילה: line.slice(0, eq).trim().split(" ").at(-1).toUpperCase().

💡 רמז 2

ניקוי הערך: trim, הורדת ; בסוף, ואז הורדת " ו־' מהקצוות (replaceAll מפרק 2 מספיק כאן).

✅ פתרון
09-git/starter/P09-E76.js 
const WORDS = ["PASSWORD", "SECRET", "TOKEN", "API_KEY"];

function findSecrets(text) {
  const found = [];
  const lines = text.split("\n");
  for (let i = 0; i < lines.length; i++) {
    const line = lines[i];
    if (line.includes("sk_live_")) {
      found.push({ line: i + 1, kind: "stripe" });
      continue;
    }
    if (line.includes("PRIVATE KEY-----")) {
      found.push({ line: i + 1, kind: "private-key" });
      continue;
    }
    const eq = line.indexOf("=");
    if (eq === -1) {
      continue;
    }
    const name = line.slice(0, eq).trim().split(" ").at(-1).toUpperCase();
    let value = line.slice(eq + 1).trim();
    if (value.endsWith(";")) {
      value = value.slice(0, -1);
    }
    value = value.replaceAll('"', "").replaceAll("'", "").trim();
    if (WORDS.some((w) => name.includes(w)) && value !== "" && !value.startsWith("process.env")) {
      found.push({ line: i + 1, kind: "assignment" });
    }
  }
  return found;
}

console.log(findSecrets('const stripe = "sk_live_51Hx9QzA";\nconst apiKey = process.env.API_KEY;'));

module.exports = { findSecrets };
[ { line: 1, kind: 'stripe' } ]

שים לב לשורה 5 בדוגמה: const token = getToken(); מסומנת — "false positive". סורקים אמיתיים (כמו GitHub secret scanning) מחפשים בעיקר תבניות של מפתחות אמיתיים (כמו sk_live_), כי כללים על שמות משתנים מרעישים. ובכל זאת — עדיף אזעקת שווא אחת מאשר מפתח בענן.

⚠️ טעויות נפוצות
  • לבדוק name.includes("KEY") — כל const keyboard = ... הופך ל"סוד".

P09-E78 · סקירת קוד ל־PR 🧠 הבנה רמה 2

💡 רמז 1

קרא כל שורה עם +: האם היא משנה משהו שלא שלה? האם היא משווה בבטחה?

💡 רמז 2

שורת ה־- הראשונה היא רמז: מישהו הוריד את [...].

✅ פתרון
  1. שורה 3 (products.sort): "הסרת את [...products] — עכשיו topProducts ממיינת את המערך של מי שקרא לה (באג השרת מקופסת 💼 של פרק 6). מציע להחזיר את העותק."

P09-E24 · אתגר: שני מפתחים, התנגשות דרך GitHub 💻 כתיבת קוד רמה 5

ייתכן ש־Git ישאל איך לבצע pull כשיש היסטוריות נפרדות. git config --global pull.rebase false (merge — כמו שלמדנו) פותר את השאלה.

hint: have locally. ...

Fast-forward

זה התרגיל הכי קרוב לחיים האמיתיים בפרק. הלקח: pull לעתים קרובות — ככל שהענפים נפרדים יותר זמן, ההתנגשויות גדולות יותר. ובצוות: מי שדוחף שני — הוא שפותר.

  • git push --force מצד B — דורס את העבודה של A ב־GitHub. בחברה זה ייתפס כאסון קטן.

P09-E80 · זרימת PR מקצה לקצה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

מחיקה: git branch -d feature/usage — אחרי git switch main והמיזוג (אחרת Git יסרב: הענף לא מוזג).

✅ פתרון
09-git/starter/P09-E80.sh 
git init --bare server.git
git clone server.git app
cd app
echo "# App" > README.md
git add README.md
git commit -m "Add README"
git push -u origin main

git switch -c feature/usage
echo "Run: node index.js" >> README.md
git commit -am "Add usage to README"
git push -u origin feature/usage

git switch main
git merge --no-ff --no-edit feature/usage
git push
git branch -d feature/usage
% git -C server.git log --oneline --graph --all
*   a7d2e51 (HEAD -> main) Merge branch 'feature/usage'
|\
| * 3f9c0b8 (feature/usage) Add usage to README
|/
* 0e41d2c Add README

(ה־hashes אצלך יהיו שונים.) הענף feature/usage עדיין קיים בשרת — ב־GitHub יש כפתור "Delete branch" אחרי המיזוג (או git push origin --delete feature/usage). ה־merge commit משאיר בהיסטוריה סימן ברור: "כאן נכנסה התכונה הזו" — ואפשר לבטל את כולה עם revert אחד.

⚠️ טעויות נפוצות
  • git merge בלי --no-ff — fast-forward, ובהיסטוריה לא רואים שהיה כאן PR.
