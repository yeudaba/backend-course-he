P09-E05 · Git, GitHub, ומה איפה 🧠 הבנה רמה 1

💡 רמז 1

Git הוא כלי מקומי; GitHub הוא רק עוד עותק.

💡 רמז 2

push שולח commits, לא "קבצים בתיקייה".

✅ פתרון
  1. ✘ — commit הוא מקומי לגמרי. רק push/pull/clone צריכים רשת.
  2. ✘ — push שולח commits שעוד אין בשרת. שינויים שלא נכנסו ל־commit, וקבצים ב־.gitignore, לא נשלחים.
  3. ✘ — clone מוריד את כל ההיסטוריה.
  4. ✘ — הסיסמה עדיין בהיסטוריה, בכל commit ישן. צריך לבטל אותה אצל הספק (rotate).
  5. ✔ (מבחינה טכנית: pull = fetch + merge.)
⚠️ טעויות נפוצות
  • להתבלבל בין "Git" ל־"GitHub" — בראיון זו שאלה קלאסית.

P09-E11 · פרויקט 1 ב־GitHub 💻 כתיבת קוד רמה 2

💡 רמז 1

אם כבר עשית commit אחד גדול — זה בסדר. מעכשיו, כל שיפור — commit נפרד.

💡 רמז 2

שגיאת "remote origin already exists"? git remote -v מראה לאן הוא מצביע; git remote set-url origin <url> מתקן.

✅ פתרון

ראה הפקודות בשיעור 4. בדיקה מהירה מה־Terminal: git remote -v מציג את כתובת GitHub; git status אומר Your branch is up to date with 'origin/main'.

🎉 זה הפריט הראשון בתיק העבודות שלך. העתק את הקישור למקום בטוח — הוא ייכנס לקורות החיים בפרק 30.

⚠️ טעויות נפוצות
  • יצירת המאגר ב־GitHub עם README — ואז push נדחה ("rejected... fetch first"). הפתרון: git pull origin main --allow-unrelated-histories, לפתור אם צריך, ו־push. או למחוק את המאגר בגיטהאב וליצור מחדש בלי README.

P09-E12 · שני מחשבים 💻 כתיבת קוד רמה 2

💡 רמז 1

שתי התיקיות הן שני עותקים עצמאיים; הם "נפגשים" רק דרך GitHub.

💡 רמז 2

לפני pull, העותק המקורי לא יודע על ה־commit החדש.

✅ פתרון
% cd ~/dev && git clone https://github.com/YOUR-USER/expenses-cli.git expenses-laptop
% cd expenses-laptop
% echo "Built in a Backend course." >> README.md
% git commit -am "Mention the course in README"
% git push
% cd ~/dev/expenses-cli
% git log --oneline -1
(ה־commit הקודם — החדש עוד לא כאן)
% git pull
Updating ...
Fast-forward
 README.md | 1 +
% git log --oneline -1
... Mention the course in README

זה בדיוק מה שקורה בצוות: כל אחד עם עותק, GitHub באמצע, ו־pull בתחילת היום.

⚠️ טעויות נפוצות
  • לשכוח git pull, לשנות, ולנסות push — יידחה ("Updates were rejected"). פתרון: pull, ואז push.

P09-E18 · Pull Request ראשון 💻 כתיבת קוד רמה 3

💡 רמז 1

שיעור 4, סעיף 4.

💡 רמז 2

תבנית תיאור: ## מה / ## למה / ## איך לבדוק — עם פקודות לדוגמה.

✅ פתרון
% git switch -c feature/edit-command
(עבודה: פונקציה updateExpense ב־expenses.js, ואז case "edit" ב־cli.js)
% git commit -am "Add updateExpense to expenses logic"
% git commit -am "Add edit command to CLI"
% git push -u origin feature/edit-command
(ב־GitHub: Compare & pull request ← תיאור ← Create ← Merge)
% git switch main
% git pull
% git branch -d feature/edit-command

תיאור לדוגמה: "מה: פקודת edit <id> --amount X --category Y. למה: אי אפשר היה לתקן טעות בלי מחיקה והוספה מחדש. איך לבדוק: add, ואז edit 1 --amount 40, ואז list."

⚠️ טעויות נפוצות
  • PR ענק עם 15 קבצים ו"שיפורים" לא קשורים — קשה לסקור. PR אחד = שינוי אחד.

P09-E23 · מפתח API ב־commit 💻 כתיבת קוד רמה 4

💡 רמז 1

הצעד הראשון אינו טכני ב־Git.

💡 רמז 2

.env.example מכיל את שמות המשתנים בלי ערכים — כדי שמי שעושה clone יידע מה להגדיר.

✅ פתרון
  1. לבטל את המפתח אצל הספק ולהנפיק חדש. מעכשיו הדליפה לא מסוכנת.
  2. להוציא מהקוד:
config.js 
module.exports = { port: 3000, apiKey: process.env.API_KEY };
.env.example 
API_KEY=
% printf ".env\n" >> .gitignore
% git add config.js .env.example .gitignore
% git commit -m "Read API key from environment"
% API_KEY=new-key-here node app.js
listening on 3000
  1. לדווח לצוות/אבטחה.
  2. (אופציונלי, אחרי ש־1 בוצע) ניקוי ההיסטוריה בכלים ייעודיים.

API_KEY=... node app.js — מגדיר משתנה סביבה רק לפקודה הזו. בפרק 13 נשתמש ב־.env.

⚠️ טעויות נפוצות
  • להתחיל מ"ניקוי היסטוריה" — בינתיים המפתח עדיין עובד אצל כל מי שכבר העתיק אותו.

P09-E24 · אתגר: שני מפתחים, התנגשות דרך GitHub 💻 כתיבת קוד רמה 5

💡 רמז 1

B: push נדחה ← pull ← conflict ← פתרון ← commit ← push. ואז A: pull.

💡 רמז 2

ייתכן ש־Git ישאל איך לבצע pull כשיש היסטוריות נפרדות. git config --global pull.rebase false (merge — כמו שלמדנו) פותר את השאלה.

✅ פתרון
% cd ~/dev/dev-b && git push
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/YOUR-USER/expenses-cli.git'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. ...
% git pull
CONFLICT (content): Merge conflict in src/cli.js
Automatic merge failed; fix conflicts and then commit the result.
% (פתרון ב־VS Code — שילוב שני הניסוחים, מחיקת הסימונים)
% git add src/cli.js && git commit --no-edit
% git push
% cd ~/dev/dev-a && git pull
Fast-forward
% git log --oneline --graph -5

זה התרגיל הכי קרוב לחיים האמיתיים בפרק. הלקח: pull לעתים קרובות — ככל שהענפים נפרדים יותר זמן, ההתנגשויות גדולות יותר. ובצוות: מי שדוחף שני — הוא שפותר.

⚠️ טעויות נפוצות
  • git push --force מצד B — דורס את העבודה של A ב־GitHub. בחברה זה ייתפס כאסון קטן.

P09-E25 · אתגר: git bisect 💻 כתיבת קוד רמה 5

💡 רמז 1

check.js: const { total } = require("./calc"); process.exit(total([{ price: 10, qty: 2 }]) === 20 ? 0 : 1);

💡 רמז 2

אחרי שנמצא: git bisect reset מחזיר אותך ל־HEAD.

✅ פתרון
% git bisect run node check.js
running 'node' 'check.js'
Bisecting: 2 revisions left to test after this (roughly 2 steps)
...
a7c3f01 is the first bad commit
commit a7c3f01...
    Change total to use reduce
% git bisect reset

עם 12 commits — כ־4 צעדים (log₂12 ≈ 3.6). עם 1,000 — כ־10. זו אותה חשיבה כמו חיפוש בינארי במערך ממוין (פרק 27): כל בדיקה חותכת את מרחב החיפוש בחצי. ושים לב ש־check.js הוא בעצם בדיקה אוטומטית — עוד הוכחה כמה הן שוות (פרק 22).

⚠️ טעויות נפוצות
  • לשכוח git bisect reset — נשארים "תקועים" על commit ישן (detached HEAD).
