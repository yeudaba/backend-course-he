P09-E01 · איפה השינוי? רמה 1

💡 רמז 1

חזור לאיור שלושת האזורים בשיעור 1.

💡 רמז 2

סעיף 5: add מכניס לאזור ההכנה את הקובץ כפי שהיה ברגע ה־add.

✅ פתרון
  1. תיקיית עבודה (לא במעקב) ← git add notes.md.
  2. תיקיית עבודה ← git add app.js.
  3. אזור ההכנה ← git commit.
  4. המאגר ← (לשרת: git push, בשיעור 4).
  5. app.js יופיע פעמיים: תחת "Changes to be committed" (הגרסה מרגע ה־add) וגם תחת "Changes not staged" (השינוי החדש). commit עכשיו יכלול רק את הגרסה הראשונה — צריך git add שוב.
⚠️ טעויות נפוצות
  • לחשוב ש־add "מסמן קובץ" לתמיד — הוא מצלם את מצבו באותו רגע.

P09-E03 · גרף של ענפים רמה 1

💡 רמז 1

C נוצר על fix, D על main — שניהם "ילדים" של B.

💡 רמז 2

fast-forward אפשרי רק אם ב־main לא קרה כלום מאז הפיצול.

✅ פתרון
A ── B ── D ── M   ← main, HEAD
       \     /
        C ──     ← fix

לא fast-forward: שני הענפים התקדמו מ־B, ולכן נוצר merge commit (M) עם שני "הורים" — D ו־C. HEAD על main, ב־M. הענף fix עדיין מצביע על C (אפשר למחוק אותו).

⚠️ טעויות נפוצות
  • לחשוב שה־merge "מעביר" את C להיות אחרי D — זה מה ש־rebase עושה, לא merge.

P09-E04 · לקרוא התנגשות רמה 1

💡 רמז 1

HEAD = הענף שאתה נמצא בו.

💡 רמז 2

אחרי העריכה: add ואז commit.

✅ פתרון

(1) למעלה (עד =======) — מ־main; למטה — מ־feature/discount. (2) Current ← return withVat(price);. Incoming ← return withVat(price) - 10;. (3) מוחקים את שורות הסימון (VS Code עושה את זה בכפתורים), מוודאים שהקוד רץ, ואז git add <file> ו־git commit.

ומה נכון? תלוי: אם ההנחה היא התכונה החדשה — Incoming. זו החלטה עסקית, לא טכנית.

⚠️ טעויות נפוצות
  • להשאיר את ======= בקובץ — הקוד לא ירוץ, וה־commit יכיל זבל.

P09-E05 · Git, GitHub, ומה איפה רמה 1

💡 רמז 1

Git הוא כלי מקומי; GitHub הוא רק עוד עותק.

💡 רמז 2

push שולח commits, לא "קבצים בתיקייה".

✅ פתרון
  1. ✘ — commit הוא מקומי לגמרי. רק push/pull/clone צריכים רשת.
  2. ✘ — push שולח commits שעוד אין בשרת. שינויים שלא נכנסו ל־commit, וקבצים ב־.gitignore, לא נשלחים.
  3. ✘ — clone מוריד את כל ההיסטוריה.
  4. ✘ — הסיסמה עדיין בהיסטוריה, בכל commit ישן. צריך לבטל אותה אצל הספק (rotate).
  5. ✔ (מבחינה טכנית: pull = fetch + merge.)
⚠️ טעויות נפוצות
  • להתבלבל בין "Git" ל־"GitHub" — בראיון זו שאלה קלאסית.

P09-E06 · מאגר ראשון רמה 2

💡 רמז 1

אחרי כל שינוי: git status ← git add ← git commit -m.

💡 רמז 2

אם נוצר commit עם הודעה גרועה, ועוד לא דחפת: git commit --amend -m "הודעה חדשה" מתקן את האחרון.

✅ פתרון
% mkdir -p playground/git-first && cd playground/git-first
% git init
% echo 'console.log("hello");' > hello.js
% git add hello.js && git commit -m "Add hello script"
% echo "# Git practice" > README.md
% git add README.md && git commit -m "Add README"
% echo 'console.log("from git");' >> hello.js
% git commit -am "Print a second line"
% git log --oneline
c3e1a20 (HEAD -> main) Print a second line
9b7f114 Add README
4f2a9c1 Add hello script
% git status
On branch main
nothing to commit, working tree clean

(ה־hashes אצלך יהיו שונים. >> מוסיף לסוף קובץ, > דורס. && בין פקודות — "רק אם הראשונה הצליחה".)

⚠️ טעויות נפוצות
  • git commit -am על קובץ חדש — הוא לא נכלל, כי -a חל רק על קבצים שכבר במעקב.

P09-E09 · .gitignore לתיקייה מבולגנת רמה 2

P09-E10 · ענף ומיזוג רמה 2

💡 רמז 1

switch -c ← commits ← switch main ← ls ← merge ← branch -d.

💡 רמז 2

אחרי המעבר ל־main, ls לא יראה את goodbye.js — Git החליף את הקבצים בתיקייה.

✅ פתרון
% git switch -c feature/goodbye
% echo 'console.log("bye");' > goodbye.js
% git add goodbye.js && git commit -m "Add goodbye script"
% echo 'console.log("see you");' >> goodbye.js
% git commit -am "Add second goodbye line"
% git switch main
% ls
README.md	hello.js
% git merge feature/goodbye
Updating c3e1a20..7d02b55
Fast-forward
 goodbye.js | 2 ++
 1 file changed, 2 insertions(+)
 create mode 100644 goodbye.js
% git branch -d feature/goodbye
% git log --oneline --graph

Fast-forward — כי ב־main לא קרה כלום בזמן שעבדת על הענף.

⚠️ טעויות נפוצות
  • git merge main בזמן שאתה ב־main — "Already up to date". ממזגים את הענף לתוך הנוכחי.

💡 רמז 2

שגיאת "remote origin already exists"? git remote -v מראה לאן הוא מצביע; git remote set-url origin <url> מתקן.

🎉 זה הפריט הראשון בתיק העבודות שלך. העתק את הקישור למקום בטוח — הוא ייכנס לקורות החיים בפרק 30.

P09-E14 · מי הכניס את הבאג? רמה 3

💡 רמז 1

git log --oneline -- discount.js ו־git show.

💡 רמז 2

percent מגיע כמספר שלם (20), לא כשבר (0.2).

✅ פתרון
% git log --oneline -- discount.js
c1a703d Add discount
% git show c1a703d
+function discount(p, percent) {
+  return p - p * percent;
+}
discount.js 
function discount(p, percent) {
  return p - (p * percent) / 100;
}
module.exports = { discount };

revert היה מוחק את כל התכונה (הפונקציה כולה). כאן התכונה רצויה וצריך רק תיקון — commit קדימה. revert מתאים כשרוצים לבטל שינוי שלם (למשל תכונה שגרמה לתקלה בייצור).

⚠️ טעויות נפוצות
  • "לתקן" את ה־commit הישן עצמו — אי אפשר בלי לשכתב היסטוריה; ובמאגר משותף אסור.

P09-E15 · איזה ביטול? רמה 3

💡 רמז 1

שיעור 2, טבלת הביטולים.

💡 רמז 2

"דחפתי" ← לא משכתבים היסטוריה.

✅ פתרון
  1. git restore cli.js — השינויים של השעה נמחקים לתמיד. (אם יש בהם משהו שווה — קודם git stash, או העתק לקובץ אחר.)
  2. git restore --staged debug.log — יוצא מאזור ההכנה, נשאר בדיסק. ואז להוסיף *.log ל־.gitignore.
  3. git revert <hash> — commit חדש שמבטל; בטוח אחרי push.
  4. git add file ← git commit --amend --no-edit.
  5. git status, git log --oneline, git diff — פקודות שרק מסתכלות, תמיד בטוחות.
⚠️ טעויות נפוצות
  • להשתמש ב־git reset --hard כי "ראיתי באינטרנט" — מוחק גם שינויים שרצית לשמור.

P09-E20 · node_modules נכנס למאגר רמה 4

💡 רמז 1

git rm --cached — "תפסיק לעקוב", הקובץ נשאר. לתיקייה: -r.

💡 רמז 2

הסוד ב־.env כבר נמצא ב־commit "stuff" בהיסטוריה.

✅ פתרון
% git add . && git commit -m "stuff"
% git rm -r --cached node_modules .env .DS_Store
rm '.DS_Store'
rm '.env'
rm 'node_modules/left-pad/index.js'
% printf "node_modules/\n.env\n.DS_Store\n" > .gitignore

% git commit -m "Stop tracking dependencies, secrets and OS files"
% ls -a
(הקבצים עדיין בדיסק)

ה־.env: הסיסמה שבתוכו נמצאת ב־commit "stuff" בהיסטוריה. אם המאגר נדחף (או יידחף) — יש להחליף את הסיסמה אצל המסד (rotate). אם עוד לא דחפת, אפשר גם לבטל את ה־commit לפני ה־push — אבל החלפת הסיסמה היא הדרך הבטוחה.

⚠️ טעויות נפוצות

P09-E21 · "Git מחק לי את הקוד!" רמה 4

💡 רמז 1

כל מה שנכנס ל־commit (או ל־stash) — Git זוכר.

💡 רמז 2

מה שמעולם לא נכנס ל־commit ונדרס — Git לא ראה אותו.

✅ פתרון
  1. לא אבד — הוא בענף feature/x. git switch feature/x.
  2. אבד. השינויים לא היו ב־Git אף פעם. (אולי בהיסטוריה המקומית של VS Code: לחיצה ימנית על הקובץ ← "Open Timeline".) לקח: commit לעתים קרובות, גם בענף פרטי.
  3. לא אבד — git stash list, ו־git stash pop.
  4. לא אבד — ה־commit המקורי עדיין בהיסטוריה; אפשר git revert על ה־revert, או לראות אותו עם git show.
⚠️ טעויות נפוצות
  • להריץ עוד פקודות "מצילות" מהאינטרנט בפאניקה — עלול להחמיר. קודם git status ו־git log.

P09-E22 · Git לא מסכים לעבור ענף רמה 4

💡 רמז 1

Git מסרב כי השינוי שלך היה נדרס בגרסה של main.

💡 רמז 2

stash ← switch ← (עבודה ב־main) ← switch בחזרה ← stash pop.

✅ פתרון
% git switch feature/english
% (עריכה של greeting.js)
% git switch main
error: Your local changes to the following files would be overwritten by checkout:
	greeting.js
Please commit your changes or stash them before you switch branches.
Aborting
% git stash
Saved working directory and index state WIP on feature/english: ...
% git switch main
% git switch feature/english
% git stash pop

stash — כשהשינוי באמצע ולא מוכן ל־commit ("רגע, צריך לבדוק משהו ב־main"). commit — כשהשינוי הוא יחידה הגיונית; תמיד בטוח יותר, כי stash קל לשכוח.

⚠️ טעויות נפוצות
  • git switch -f ("force") — דורס את השינויים. בדיוק מה ש־Git ניסה למנוע.

P09-E24 · אתגר: שני מפתחים, התנגשות דרך GitHub רמה 5

💡 רמז 1

B: push נדחה ← pull ← conflict ← פתרון ← commit ← push. ואז A: pull.

💡 רמז 2

ייתכן ש־Git ישאל איך לבצע pull כשיש היסטוריות נפרדות. git config --global pull.rebase false (merge — כמו שלמדנו) פותר את השאלה.

✅ פתרון
% cd ~/dev/dev-b && git push
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/YOUR-USER/expenses-cli.git'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. ...
% git pull
CONFLICT (content): Merge conflict in src/cli.js
Automatic merge failed; fix conflicts and then commit the result.
% (פתרון ב־VS Code — שילוב שני הניסוחים, מחיקת הסימונים)
% git add src/cli.js && git commit --no-edit
% git push
% cd ~/dev/dev-a && git pull
Fast-forward
% git log --oneline --graph -5

זה התרגיל הכי קרוב לחיים האמיתיים בפרק. הלקח: pull לעתים קרובות — ככל שהענפים נפרדים יותר זמן, ההתנגשויות גדולות יותר. ובצוות: מי שדוחף שני — הוא שפותר.

⚠️ טעויות נפוצות
  • git push --force מצד B — דורס את העבודה של A ב־GitHub. בחברה זה ייתפס כאסון קטן.

P09-E25 · אתגר: git bisect רמה 5

✅ פתרון

running 'node' 'check.js'
Bisecting: 2 revisions left to test after this (roughly 2 steps)
...

עם 12 commits — כ־4 צעדים (log₂12 ≈ 3.6). עם 1,000 — כ־10. זו אותה חשיבה כמו חיפוש בינארי במערך ממוין (פרק 27): כל בדיקה חותכת את מרחב החיפוש בחצי. ושים לב ש־check.js הוא בעצם בדיקה אוטומטית — עוד הוכחה כמה הן שוות (פרק 22).
