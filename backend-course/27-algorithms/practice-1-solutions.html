P27-E01 · מה הסיבוכיות? 🧠 הבנה רמה 1

💡 רמז 1

ספור כמה פעמים כל שורה רצה כש־n גדל פי 10. פונקציות מובנות הן לא "חינם": findIndex, includes ו־shift הן לולאות.

💡 רמז 2

מה shift() עושה לשאר האיברים במערך?

✅ פתרון
  • א — O(n). מעבר אחד.
  • ב — O(n²). לולאה בתוך לולאה על אותו מערך. 10,000 משתמשים = 100 מיליון השוואות.
  • ג — O(n²), למרות שיש "רק" שורה אחת. findIndex הוא לולאה, בתוך filter. התיקון: Set של emails שכבר ראינו (E06, E21).
  • ד — O(n + m). בניית ה־Map — n; כל get — O(1) בממוצע. זה בדיוק מה ש־JOIN עם hash עושה במסד, ומה ש־DataLoader עושה מול בעיית N+1 (פרק 19).
  • ה — O(n log n) בגלל המיון. (אפשר חציון ב־O(n) בממוצע עם quickselect — כמעט אף פעם לא שווה את זה.)
  • ו — O(n²) לפי ההגדרה. shift מזיז את כל השאר מקום אחד שמאלה: O(n) כל פעם. בפועל V8 מקצר את ההתחלה של מערכים קטנים בלי להעתיק, אז על 10,000 איברים זה מהיר — אבל מדדתי ריקון של 100,000 מספרים: 768ms, ו־100,000 מערכים קטנים: 8.2 שניות. לתור גדול — אינדקס שרץ קדימה (כמו ב־BFS, E15).
⚠️ טעויות נפוצות
  • לספור "כמה לולאות כתובות בקוד" במקום כמה עבודה נעשית: arr.includes בתוך for הוא לולאה כפולה.

P27-E06 · כפילויות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

"ראיתי כבר?" — Set.

💡 רמז 2

hasDuplicates בשורה אחת: מה הגודל של Set שנבנה מהמערך?

✅ פתרון
// P27-E06
// Set: "ראיתי כבר?" ב־O(1). מעבר אחד על המערך ← O(n) זמן, O(n) זיכרון
export function firstDuplicate<T>(items: readonly T[]): T | undefined {
  const seen = new Set<T>();
  for (const item of items) {
    if (seen.has(item)) return item;
    seen.add(item);
  }
  return undefined;
}

export function hasDuplicates<T>(items: readonly T[]): boolean {
  return new Set(items).size !== items.length;
}
⚠️ טעויות נפוצות
  • items.indexOf(x) !== i בתוך לולאה — נכון, ו־O(n²): על 50,000 ערכים כשנייה, על מיליון — שעות.

P27-E07 · שני מוצרים לכרטיס מתנה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הגרסה הנאיבית: לכל זוג — O(n²). השאלה הנכונה לכל מחיר: "האם ההשלמה שלו (target − price) כבר הופיעה?"

💡 רמז 2

Map מערך ← אינדקס. שמור רק את ההופעה הראשונה של כל מחיר.

✅ פתרון
// P27-E07
// Map של "ערך ← אינדקס" למה שכבר ראינו: לכל מחיר בודקים אם ההשלמה שלו כבר הופיעה. O(n)
export function twoSum(prices: readonly number[], target: number): [number, number] | null {
  const seenAt = new Map<number, number>();
  for (let j = 0; j < prices.length; j++) {
    const i = seenAt.get(target - prices[j]);
    if (i !== undefined) return [i, j];
    if (!seenAt.has(prices[j])) seenAt.set(prices[j], j); // הראשון — כדי שהזוג יהיה הכי מוקדם
  }
  return null;
}

זו כנראה שאלת הראיון הנפוצה בעולם ("Two Sum"). הדפוס שמאחוריה — "Map של מה שכבר ראיתי, ובדיקה מול השלמה" — חוזר בעשרות שאלות.

⚠️ טעויות נפוצות
  • להכניס את המחיר ל־Map לפני הבדיקה — ואז 50 עם target 100 "מוצא" את עצמו.

P27-E33 · כפילויות לפי email — O(n) 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏Set של emails מנורמלים.

💡 רמז 2

‏filter עם has/add — O(n).

✅ פתרון
// P27-E33: כפילויות לפי email — O(n)
export function dedupeByEmail<T extends { email: string }>(users: T[]): T[] {
  const seen = new Set<string>();
  return users.filter((u) => {
    const key = u.email.trim().toLowerCase();
    if (seen.has(key)) return false;
    seen.add(key);
    return true;
  });
}

זה המדידה מתחילת השיעור, כפונקציה: findIndex בתוך filter היה O(n²) — דקה שלמה במקום מילישניות.

⚠️ טעויות נפוצות
  • ‏users.filter((u, i) => users.findIndex(…) === i) — נכון, ו־O(n²).

P27-E34 · לחבר הזמנות למשתמשים — O(n + m) 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏new Map(users.map((u) => [u.id, u])) — פעם אחת.

💡 רמז 2

‏{ ...o, user: byId.get(o.userId) ?? null }.

✅ פתרון
// P27-E34: לחבר הזמנות למשתמשים — O(n + m)
export function attachUsers<U extends { id: number }, O extends { userId: number }>(users: U[], orders: O[]) {
  const byId = new Map(users.map((u) => [u.id, u]));
  return orders.map((o) => ({ ...o, user: byId.get(o.userId) ?? null }));
}

זה JOIN בזיכרון — בדיוק "hash join" ש־PostgreSQL עושה: בונה טבלת hash מהצד הקטן, ועובר על הגדול. ‏users.find בתוך map היה nested loop: ‏O(n·m).

⚠️ טעויות נפוצות
  • לבנות את ה־Map בתוך ה־map — חזרה ל־O(n·m).

// P27-E35: מה חסר?
export function missing<T>(expected: T[], actual: T[]): T[] {
  const have = new Set(actual);

}

P27-E36 · ‏multiset: מספיק מכל דבר? 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

ספירה: Map של פריט ← כמה יש.

💡 רמז 2

לכל פריט בהזמנה — מורידים 1; ירד מתחת ל־0 ← false.

✅ פתרון
// P27-E36: multiset — מספיק מכל דבר?
export function canFulfill(order: string[], stock: string[]): boolean {
  const left = new Map<string, number>();
  for (const s of stock) left.set(s, (left.get(s) ?? 0) + 1);
  for (const o of order) {
    const n = left.get(o) ?? 0;
    if (n === 0) return false;
    left.set(o, n - 1);
  }
  return true;
}

דפוס "הספירה" משיעור 2, מוקדם: זו גם שאלת "אנגרמה" ("האם אפשר לבנות את המילה מהאותיות"), וגם בדיקת מלאי לעגלה.

⚠️ טעויות נפוצות
  • ‏Set — מתעלם מכמויות: שני latte מול אחד עוברים.
  • ‏stock.splice(stock.indexOf(o), 1) — נכון, ו־O(n·m).

P27-E37 · חיתוך של שתי רשימות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏Set של b, ו־Set של מה שכבר הוצאת.

💡 רמז 2

אפשר גם: new Set(b), ואז delete אחרי שמוציאים — כך כפילות ב־a לא תעבור.

✅ פתרון
// P27-E37: חיתוך של שתי רשימות
export function intersection<T>(a: T[], b: T[]): T[] {
  const inB = new Set(b);
  const out: T[] = [];
  for (const x of a) {
    if (inB.delete(x)) out.push(x); // delete מחזיר true אם היה — ומונע כפילות
  }
  return out;
}

‏delete שמחזיר boolean הוא טריק קטן: "היה שם?" ו"שלא יספר שוב" בפעולה אחת.

⚠️ טעויות נפוצות
  • a.filter((x) => b.includes(x)) — ‏O(n·m), וגם מחזיר כפילויות.

P27-E38 · תור בלי shift 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 2

דחיסה — O(n), אבל רק אחרי n פעולות: בממוצע O(1).

✅ פתרון
// P27-E38: תור בלי shift
export class FastQueue<T> {
  #items: T[] = [];
  #head = 0;

  push(x: T) {
    this.#items.push(x);
  }
  shift(): T | undefined {
    if (this.#head >= this.#items.length) return undefined;
    const x = this.#items[this.#head];
    this.#items[this.#head++] = undefined as T; // לא להחזיק הפניה
    if (this.#head * 2 >= this.#items.length) {
      this.#items = this.#items.slice(this.#head);
      this.#head = 0;
    }
    return x;
  }
  peek(): T | undefined {
    return this.#head < this.#items.length ? this.#items[this.#head] : undefined;
  }
  get size() {
    return this.#items.length - this.#head;
  }
}

"O(1) בממוצע" (amortized): לפעמים פעולה יקרה, אבל היא קורית רק אחרי הרבה זולות. ‏push של מערך עובד בדיוק כך (מכפיל את הקיבולת מדי פעם).

⚠️ טעויות נפוצות
  • לא לדחוס לעולם — תור שעבר בו מיליון עבודות מחזיק מיליון תאים ריקים.
  • לדחוס בכל shift — חזרה ל־O(n).

P27-E27 · מיזוג רשימות ממוינות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שני אינדקסים, i ו־j. ‏while (i < a.length && j < b.length): אם a[i] <= b[j] ← out.push(a[i++]), אחרת מ־b. כשאחת נגמרת, מעתיקים את מה שנשאר בשנייה (שתי לולאות קצרות, או slice).

💡 רמז 2

mergeAll: ‏while (round.length > 1). בכל סיבוב, לולאה עם k += 2 שממזגת את round[k] עם round[k + 1]. אם נשארה רשימה בודדת בסוף (מספר אי־זוגי), היא עוברת לסיבוב הבא כמו שהיא.

✅ פתרון
// P27-E27 — מיזוג רשימות ממוינות
export function mergeSorted(a: number[], b: number[]): number[] {
  const out: number[] = [];
  let i = 0;
  let j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) out.push(a[i++]);
    else out.push(b[j++]);
  }
  while (i < a.length) out.push(a[i++]);
  while (j < b.length) out.push(b[j++]);
  return out;
}

export function mergeAll(lists: number[][]): number[] {
  if (lists.length === 0) return [];
  let round = lists;
  while (round.length > 1) {
    const next: number[][] = [];
    for (let k = 0; k < round.length; k += 2) {
      next.push(k + 1 < round.length ? mergeSorted(round[k], round[k + 1]) : round[k]);
    }
    round = next;
  }
  return round[0];
}

‏mergeSorted נוגע בכל איבר פעם אחת: O(n + m). ‏mergeAll בזוגות: בכל סיבוב כל האיברים עוברים מיזוג אחד, ויש log k סיבובים. סך הכול O(n log k), כש־k הוא מספר הרשימות. אילו היית ממזג אחת־אחת לתוך תוצאה שגדלה, הרשימה הראשונה הייתה מועתקת k פעמים: O(n·k).

‏a[i] <= b[j] ולא <: בשוויון לוקחים קודם מ־a. כך המיזוג יציב: ערכים שווים שומרים על הסדר המקורי שלהם. כשממזגים אובייקטים לפי זמן, זה ההבדל בין "האירועים מאותה שנייה לפי סדר השרתים" לבין סדר מקרי. זה גם הצעד שבלב merge sort, ו־ORDER BY ... LIMIT על טבלה מחולקת (partitioned) עושה בדיוק את זה.

⚠️ טעויות נפוצות
  • [...a, ...b].sort() — בלי פונקציית השוואה 10 בא לפני 2. וגם עם פונקציה, זה O(n log n).
  • לשכוח להעתיק את השארית — כל מה שנשאר ברשימה הארוכה נעלם.
  • a.shift() במקום אינדקס — ‏shift הוא O(n), ומשנה את הקלט של מי שקרא לפונקציה.
  • לולאת for עם k += 2 שניגשת ל־round[k + 1] בלי לבדוק — ‏undefined נכנס למיזוג.

// P27-E42: Express — "שם המשתמש פנוי?" ב־O(1)
import express from "express";

const norm = (s: string) => s.trim().toLowerCase();

export function usernamesApp(usernames: string[]) {
  const taken = new Set(usernames.map(norm));
  const app = express();
  app.use(express.json());
  app.get("/available", (req, res) => {
    const name = typeof req.query.name === "string" ? norm(req.query.name) : "";
    if (!name) return res.status(400).json({ error: "חסר name" });
    res.json({ available: !taken.has(name) });
  });
  app.post("/usernames", (req, res) => {
    const name = typeof req.body?.name === "string" ? norm(req.body.name) : "";
    if (!name) return res.status(400).json({ error: "חסר name" });
    if (taken.has(name)) return res.status(409).json({ error: "תפוס" });
    taken.add(name);
    res.status(201).json({ name });
  });
  return app;
}

ה־Set נבנה פעם אחת — O(n) — וכל בקשה אחר כך O(1). זה ה"זמן מול זיכרון" של השיעור: כמה MB של זיכרון קבוע, תמורת בקשות שלא תלויות במספר המשתמשים. (בעולם האמיתי — מצב משותף בין שרתים הוא במסד או ב־Redis, לא ב־Set של תהליך אחד.)

⚠️ טעויות נפוצות
  • לבנות את ה־Set בתוך ה־route — O(n) לכל בקשה, בדיוק כמו קודם.
