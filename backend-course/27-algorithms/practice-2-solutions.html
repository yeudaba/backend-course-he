P27-E02 · איזה מבנה נתונים? 🧠 הבנה רמה 1

💡 רמז 1

שאל: מה הפעולה שחוזרת הכי הרבה? חיפוש לפי ערך? הוספה בסוף והוצאה מהסוף? מההתחלה? טווח?

💡 רמז 2

heap — "תור עדיפויות": הוספה והוצאת המינימום ב־O(log n).

✅ פתרון
  1. Set — has ב־O(1). (במסד: אינדקס UNIQUE, שעושה גם את האכיפה.)
  2. מחסנית — האחרון שנכנס הוא הראשון שמבטלים.
  3. תור (FIFO). בשרת אמיתי — תור חיצוני, כמו BullMQ (פרק 26).
  4. מערך ממוין + חיפוש בינארי — שני חיפושים, O(log n) לשאילתה (E10). במסד: אינדקס B-tree על created_at — אותו רעיון בדיוק.
  5. Map (מפתח ← מונה). ובין כמה שרתים — HINCRBY ב־Redis.
  6. heap. ב־JavaScript אין מובנה; בראיון אומרים "priority queue / heap" ומסבירים, ולרוב לא נדרש לממש. עם מעט משימות — מערך וחיפוש מקסימום מספיק לגמרי.
⚠️ טעויות נפוצות
  • מערך לכל דבר: emails.includes(x) עובד מצוין עם 100 משתמשים — ומפיל שרת עם מיליון.

P27-E46 · למה החלון הנע הוא O(n)? 🧠 הבנה רמה 2

💡 רמז 1

‏left אף פעם לא חוזר אחורה.

💡 רמז 2

"כל איבר נכנס פעם אחת ויוצא פעם אחת".

✅ פתרון
  1. לכל היותר n — הוא רק עולה, ולא עובר את right.
  2. O(n): ‏right עובר n פעמים, ו־left עובר לכל היותר n פעמים בסך הכול — יחד 2n. "כל איבר נכנס לחלון פעם אחת ויוצא פעם אחת."
  3. O(n²) — לכל right, סריקה מההתחלה.
  4. אותו רעיון: מוציאים מה שיצא מהחלון (בצד השמאלי), וסופרים את מה שנשאר. ה־sorted set עושה את ה"left++" בפקודה אחת.
⚠️ טעויות נפוצות
  • "יש while בתוך for, אז O(n²)" — צריך לשאול כמה פעמים הפנימית רצה בסך הכול, לא בכל סיבוב.

P27-E48 · ‏LRU — מי יוצא? 🧠 הבנה רמה 1

💡 רמז 1

‏get "מרענן" — מעביר לסוף.

💡 רמז 2

‏get על מפתח שלא קיים לא משנה כלום.

✅ פתרון
  1. set a → ‏[a]; ‏set b → ‏[a, b]; ‏set c → ‏[a, b, c].
  2. get a → ‏[b, c, a].
  3. set d → ‏b יוצא → ‏[c, a, d].
  4. get b → לא קיים (miss), אין שינוי.
  5. set e → ‏c יוצא → ‏[a, d, e].
  6. set c → ‏a יוצא → ‏[d, e, c].
  7. get d → ‏[e, c, d].

ב־FIFO, ‏get a לא היה מציל את a: ‏set d היה מוציא את a (הראשון שנכנס). LRU מתאים יותר לcache, כי מה שנקרא לאחרונה כנראה ייקרא שוב.

⚠️ טעויות נפוצות
  • לשכוח ש־set של מפתח קיים גם הוא "שימוש" — מעביר לסוף, ולא מגדיל את הגודל.

P27-E08 · אנגרמות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

צריך מפתח שזהה לכל המילים בקבוצה. מה משותף ל־"listen" ול־"silent"?

💡 רמז 2

האותיות ממוינות: [...w.toLowerCase()].sort().join(""). ו־Map שומר את סדר ההכנסה.

✅ פתרון
// P27-E08
// מפתח קנוני לכל קבוצה: האותיות ממוינות. Map שומר את סדר ההוספה — כלומר סדר ההופעה הראשונה
export function groupAnagrams(words: readonly string[]): string[][] {
  const groups = new Map<string, string[]>();
  for (const word of words) {
    const key = [...word.toLowerCase()].sort().join("");
    const group = groups.get(key);
    if (group) group.push(word);
    else groups.set(key, [word]);
  }
  return [...groups.values()];
}

הדפוס: "מפתח קנוני" — מנרמלים כל פריט לצורה אחת, ומקבצים לפיה. אותו רעיון כמו email.trim().toLowerCase() (E21), או כמו GROUP BY lower(email) במסד.

⚠️ טעויות נפוצות
  • להשוות כל מילה לכל מילה ("האם הן אנגרמות?") — O(n²).

P27-E11 · שיא עומס בחלון זמן 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שני מצביעים: right מתקדם אחד־אחד; left מתקדם כל עוד החלון ארוך מדי.

💡 רמז 2

למה זה O(n) ולא O(n²), אם יש while בתוך for? כמה פעמים בסך הכול left יכול לזוז?

✅ פתרון
// P27-E11
// חלון נע עם שני מצביעים: right מתקדם, left "מדביק" כשהחלון ארוך מדי. כל אינדקס נכנס ויוצא פעם אחת ← O(n)
export function peakInWindow(timestamps: readonly number[], windowMs: number): { count: number; start: number } {
  let best = { count: 0, start: timestamps[0] ?? 0 };
  let left = 0;
  for (let right = 0; right < timestamps.length; right++) {
    while (timestamps[right] - timestamps[left] >= windowMs) left++;
    const count = right - left + 1;
    if (count > best.count) best = { count, start: timestamps[left] };
  }
  return best;
}

"שני מצביעים" / "חלון נע" — אותו רעיון כמו הגבלת קצב עם חלון נע (פרקים 24, 26), וכמו "הרצף הארוך ביותר בלי תו חוזר" — שאלת ראיון קלאסית.

⚠️ טעויות נפוצות
  • לכל בקשה — לספור מחדש את כל הבקשות בחלון שלה: O(n × k).

P27-E14 · הכי נמכרים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני שלבים: ספירה (Map), ואז מיון של הזוגות.

💡 רמז 2

פונקציית השוואה עם שני קריטריונים: b.count - a.count || ….

✅ פתרון
// P27-E14
// ספירה ב־Map ← O(n); מיון של הערכים השונים ← O(m log m). (עם heap בגודל k: O(m log k) — לרוב לא שווה את המורכבות)
export function topK(items: readonly string[], k: number): { item: string; count: number }[] {
  const counts = new Map<string, number>();
  for (const item of items) counts.set(item, (counts.get(item) ?? 0) + 1);
  return [...counts]
    .map(([item, count]) => ({ item, count }))
    .sort((a, b) => b.count - a.count || (a.item < b.item ? -1 : a.item > b.item ? 1 : 0))
    .slice(0, k);
}
⚠️ טעויות נפוצות
  • a.item.localeCompare(b.item) — תלוי בשפה של המחשב; כאן השוואה פשוטה מספיקה ויציבה.

P27-E16 · LRU cache 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

Map ב־JavaScript שומר סדר הכנסה. הראשון ב־map.keys() הוא הוותיק.

💡 רמז 2

"לרענן" מפתח = delete ואז set — עובר לסוף.

✅ פתרון
// P27-E16
// Map ב־JavaScript שומר סדר הכנסה: הראשון = הכי פחות בשימוש. "שימוש" = מוחקים ומכניסים מחדש (לסוף). הכול O(1)
export class LRUCache<K, V> {
  private readonly map = new Map<K, V>();
  private readonly capacity: number;

  // (בלי "constructor(private capacity)": Node מריץ TypeScript בלי קומפילציה, וזה תחביר שאינו JavaScript)
  constructor(capacity: number) {
    this.capacity = capacity;
    if (!Number.isInteger(capacity) || capacity < 1) throw new Error("capacity חייב להיות שלם חיובי");
  }

  get size() {
    return this.map.size;
  }

  get(key: K): V | undefined {
    if (!this.map.has(key)) return undefined;
    const value = this.map.get(key)!;
    this.map.delete(key);
    this.map.set(key, value);
    return value;
  }

  set(key: K, value: V): void {
    this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.capacity) this.map.delete(this.map.keys().next().value!);
  }

  keys(): K[] {
    return [...this.map.keys()]; // מהישן לחדש
  }
}

בשפות אחרות הפתרון הקלאסי הוא hash map + רשימה מקושרת כפולה; ב־JavaScript, Map כבר עושה את שניהם. בראיון כדאי להגיד את זה במפורש — ולהיות מוכן לממש את הרשימה אם יבקשו. ובעולם: maxmemory-policy allkeys-lru של Redis, וה־cache של כל דפדפן.

⚠️ טעויות נפוצות
  • לשמור "זמן שימוש אחרון" ולחפש מינימום כשמתמלא — O(n) לכל הוצאה.

// P27-E21
export interface Customer {
  id: number;
  name: string;
  email: string;
}

export function dedupeCustomers(list: readonly Customer[]): Customer[] {
  const seen = new Set<string>(); // תקלה 1: היה result.some(...) בתוך הלולאה ← O(n²): 50,000 לקוחות = מיליארד השוואות
  const result: Customer[] = [];

P27-E26 · הראשון שמופיע פעם אחת 🤖 💻 כתיבת קוד 🤖 רמה 1

💡 רמז 1

שני מעברים. בראשון סופרים כל ערך ב־Map. בשני עוברים שוב על המערך (לא על ה־Map), ומחזירים את הראשון שהספירה שלו היא 1.

💡 רמז 2

counts.set(item, (counts.get(item) ?? 0) + 1). ‏?? ולא ||: כאן זה לא משנה (ספירה לא יכולה להיות 0), אבל זה הרגל טוב.

✅ פתרון
// P27-E26 — הראשון שמופיע פעם אחת בלבד
export function firstUnique<T>(items: T[]): T | undefined {
  const counts = new Map<T, number>();
  for (const item of items) counts.set(item, (counts.get(item) ?? 0) + 1);
  for (const item of items) if (counts.get(item) === 1) return item;
  return undefined;
}

שני מעברים של O(n) הם עדיין O(n). זה הדפוס הבסיסי של שיעור 2: "לספור קודם, להחליט אחר כך". הוא חוזר ב־anagrams (‏E08) וב־top-K (‏E14).

המעבר השני הוא על המערך, כי שם הסדר. אגב, גם Map שומר על סדר ההכנסה (פרק 7), כך שמעבר על ה־Map היה עובד גם הוא. אבל בראיון כדאי להגיד את זה במפורש, ולא לסמוך על זה בשקט.

⚠️ טעויות נפוצות
  • indexOf / filter בתוך לולאה — נכון, ו־O(n²). על 100,000 ערכים זה כמה שניות.
  • Set של "ראיתי" — יודע רק אם הערך הופיע, לא כמה פעמים. ‏3 שמופיע שלוש פעמים נראה כמו 3 שמופיע פעמיים.

P27-E49 · הרצף הארוך ביותר בלי חזרה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏Map של ערך ← המקום האחרון שבו ראינו אותו.

💡 רמז 2

ערך שכבר ראינו בתוך החלון (‏last >= left) ← left = last + 1.

✅ פתרון
// P27-E49: הרצף הארוך ביותר בלי חזרה
export function longestUnique<T>(items: T[]) {
  const lastAt = new Map<T, number>();
  let left = 0;
  let best = { length: 0, start: 0 };
  for (let right = 0; right < items.length; right++) {
    const last = lastAt.get(items[right]);
    if (last !== undefined && last >= left) left = last + 1;
    lastAt.set(items[right], right);
    if (right - left + 1 > best.length) best = { length: right - left + 1, start: left };
  }
  return best;
}

‏left קופץ קדימה ישר אל אחרי ההופעה הקודמת — עדיין O(n), כי הוא רק עולה.

⚠️ טעויות נפוצות
  • ‏left = last + 1 בלי לבדוק last >= left — ערך שראינו לפני החלון מחזיר את left אחורה.

P27-E50 · כמה תת־מערכים מסתכמים ל־k? 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

סכום־קידומת: prefix אחרי כל איבר. תת־מערך שמסתיים כאן מסתכם ל־k אם קודם היה prefix − k.

💡 רמז 2

דפוס "ההשלמה" עם ספירה: Map של prefix ← כמה פעמים ראינו אותו, שמתחילה ב־{0: 1}.

✅ פתרון
// P27-E50: כמה תת־מערכים מסתכמים ל־k?
export function countSubarraysWithSum(nums: number[], k: number): number {
  const seen = new Map<number, number>([[0, 1]]);
  let prefix = 0;
  let count = 0;
  for (const x of nums) {
    prefix += x;
    count += seen.get(prefix - k) ?? 0;
    seen.set(prefix, (seen.get(prefix) ?? 0) + 1);
  }
  return count;
}

שני דפוסים יחד: סכומי־קידומת הופכים "סכום של קטע" להפרש בין שני מספרים, ו"ההשלמה" מוצאת את ההפרש ב־O(1). ‏{0: 1} בהתחלה — כדי שקטע שמתחיל באינדקס 0 ייספר.

⚠️ טעויות נפוצות
  • חלון נע — עם שליליים, הרחבת החלון יכולה להקטין את הסכום, והכלל "גדול מדי ← לכווץ" לא תקף.
  • לשכוח את {0: 1} — מפספסים כל קטע שמתחיל בהתחלה.

P27-E54 · הגבלת קצב בחלון נע — זיכרון קבוע לכל לקוח 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P27-E54: הגבלת קצב בחלון נע — זיכרון קבוע לכל לקוח
export function createSlidingLimiter({ limit, windowMs }: { limit: number; windowMs: number }) {
  const log = new Map<string, number[]>();
  const prune = (clientId: string, now: number) => {
    const times = log.get(clientId);
    if (!times) return [];
    while (times.length && times[0] <= now - windowMs) times.shift();
    if (times.length === 0) log.delete(clientId);
    return times;
  };
  return {
    hit(clientId: string, now: number) {
      const times = prune(clientId, now);
      if (times.length >= limit) return false;
      if (times.length === 0) log.set(clientId, times);
      times.push(now);
      return true;
    },
    tracked(clientId: string) {
      return log.get(clientId)?.length ?? 0;
    },
  };
}

‏shift על מערך של לכל היותר limit איברים — O(limit), כלומר קבוע. זה הבדל חשוב מ־E38: הסיבוכיות של פעולה תלויה בגודל של מה שהיא עובדת עליו. ולקוחות שנעלמו נמחקים — אחרת ה־Map גדל לנצח.

⚠️ טעויות נפוצות
  • לרשום גם בקשות שנדחו — לקוח שמנסה כל שנייה לא משתחרר לעולם (פרק 26, ‏E68 שם).

P27-E55 · ‏LRU עם TTL 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏Map<string, { value, expiresAt }> — וה־delete/set מעבירים לסוף כמו בשיעור.

💡 רמז 2

‏size: לעבור מההתחלה (הכי ישנים) ולמחוק פגים — אבל זהירות: "ישן בשימוש" לא תמיד "יפוג ראשון" (‏get מזיז). לכן size עובר על כולם.

✅ פתרון
// P27-E55: LRU עם TTL
export function createTtlLru<V>(capacity: number, ttlMs: number, now: () => number = Date.now) {
  const map = new Map<string, { value: V; expiresAt: number }>();
  return {
    get(key: string): V | undefined {
      const e = map.get(key);
      if (!e) return undefined;
      map.delete(key);
      if (now() >= e.expiresAt) return undefined;
      map.set(key, e);
      return e.value;
    },
    set(key: string, value: V) {
      map.delete(key);
      map.set(key, { value, expiresAt: now() + ttlMs });
      while (map.size > capacity) {
        map.delete(map.keys().next().value as string);
      }
    },
    size() {
      for (const [k, e] of map) if (now() >= e.expiresAt) map.delete(k);
      return map.size;
    },
  };
}

‏get ו־set הם O(1). ‏size הוא O(n) — ובסדר: זה מדד, לא פעולה חמה. ‏Redis עושה בדיוק את השילוב הזה: פקיעה "עצלה" כשניגשים, ודגימה מדי פעם — לא סריקה של הכול.

⚠️ טעויות נפוצות
  • להחזיר ערך שפג ב־get כי "הוא עוד ב־Map" — ה־TTL לא קיים.
  • ‏get שמעביר לסוף לפני בדיקת התוקף — ערך פג "מתחדש".

P27-E56 · מה השתנה? ‏diff של שני אובייקטים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏for (const k in before) — ובדיקה k in after.

💡 רמז 2

‏Object.hasOwn(after, k) מדויק יותר מ־in (לא כולל prototype).

✅ פתרון
// P27-E56: מה השתנה? diff של שני אובייקטים
export function diffObjects(before: Record<string, unknown>, after: Record<string, unknown>) {
  const added: string[] = [];
  const removed: string[] = [];
  const changed: { key: string; from: unknown; to: unknown }[] = [];
  for (const k of Object.keys(before)) {
    if (!Object.hasOwn(after, k)) removed.push(k);
    else if (JSON.stringify(before[k]) !== JSON.stringify(after[k])) changed.push({ key: k, from: before[k], to: after[k] });
  }
  for (const k of Object.keys(after)) if (!Object.hasOwn(before, k)) added.push(k);
  const byKey = (a: string, b: string) => (a < b ? -1 : a > b ? 1 : 0);
  return { added: added.sort(byKey), removed: removed.sort(byKey), changed: changed.sort((a, b) => byKey(a.key, b.key)) };
}

‏hasOwn הוא O(1) — אובייקט הוא בעצמו מבנה hash. ‏Object.keys(after).includes(k) בתוך הלולאה היה O(n²) — ועם מוצר עם מאות שדות, כבר מורגש.

⚠️ טעויות נפוצות
  • before[k] !== after[k] — מערכים ואובייקטים תמיד "שונים".
  • ‏after[k] === undefined כבדיקת "נמחק" — שדה שקיים עם undefined נחשב נמחק.
