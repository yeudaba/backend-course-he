1. אותו קוד, פי 4,000

"האם ה־email כבר נרשם?" — שתי גרסאות, שתיהן נכונות:

const seen: string[] = [];
for (const e of emails) { if (seen.includes(e)) …; seen.push(e); }   // מערך

const seen = new Set<string>();
for (const e of emails) { if (seen.has(e)) …; seen.add(e); }          // Set

ב־Set: פי 2 נתונים ← פי 2 זמן. במערך: פי 2 נתונים ← פי 4 זמן (ובפועל אפילו יותר — מעבר לגודל מסוים, הזיכרון של המעבד כבר לא מכיל את המערך, וכל השוואה איטית יותר). דקה שלמה ל־80,000 משתמשים. עם 10 משתמשים בבדיקות המקומיות — שתי הגרסאות מיידיות. לכן הבאג הזה מגיע לפרודקשן.

2. Big-O

Big-O עונה על שאלה אחת: כשהקלט גדל, איך העבודה גדלה? לא סופרים מילישניות ולא מחשבים מדויק — רק את הצורה:

סימוןn פי 10 ← הזמןדוגמה
O(1)אותו דברmap.get, set.has, arr[i], arr.push
O(log n)+ צעד אחד בערךחיפוש בינארי, אינדקס B-tree במסד
O(n)פי 10לולאה אחת, includes, filter, map
O(n log n)קצת יותר מפי 10sort
O(n²)פי 100לולאה בתוך לולאה על אותם נתונים
O(2ⁿ)לא יסתייםלבדוק כל תת־קבוצה; רקורסיה שמחשבת אותו דבר שוב ושוב (E24)

ואיך מחשבים? סופרים כמה פעמים השורה הפנימית רצה:

let ops = 0;
const linear = (n: number) => { for (let i = 0; i < n; i++) ops++; };
const quadratic = (n: number) => { for (let i = 0; i < n; i++) for (let j = 0; j < n; j++) ops++; };
const binary = (n: number) => { let lo = 0, hi = n; while (lo < hi) { ops++; const mid = (lo + hi) >> 1; if (mid < n - 1) lo = mid + 1; else hi = mid; } };

for (const n of [10, 100, 1000, 10000]) {
  const row = [linear, quadratic, binary].map((f) => { ops = 0; f(n); return ops; });
  console.log(`n=${n}`.padEnd(8), row.map((x) => String(x).padStart(10)).join(""));
}
n=10             10       100         3
n=100           100     10000         7
n=1000         1000   1000000        10
n=10000       10000 100000000        13

שלושה כללים שמספיקים כמעט תמיד:

  • רצף ← הכי גדול. לולאה ואחריה מיון: O(n) + O(n log n) = O(n log n).
  • קינון ← כפל. לולאה על n, ובתוכה includes על n: O(n²). על n משתמשים ו־m הזמנות: O(n·m).
  • קבועים לא משנים. שתי לולאות נפרדות — עדיין O(n). אבל בעולם האמיתי, "פי 2" כן משנה כשמדובר בשאילתה למסד בכל איטרציה.

ובראיון מוסיפים זיכרון: הגרסה עם Set היא O(n) זמן וגם O(n) זיכרון נוסף. זו כמעט תמיד עסקה טובה — אבל צריך להגיד אותה.

בשרת, ה־n הגדול הוא לרוב לא מערך בזיכרון — הוא המסד. "שאילתה בתוך לולאה" (N+1, פרק 19) היא O(n) שאילתות, כל אחת מילישנייה או יותר — הרבה יותר גרוע מ־O(n²) בזיכרון על n קטן. ו־Seq Scan על טבלה של מיליון שורות הוא O(n) לכל בקשה, כשאינדקס הוא O(log n) (פרק 18). אותה חשיבה, יחידות אחרות.
