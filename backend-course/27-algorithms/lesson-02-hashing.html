שיעור 2 — Map, Set וחלון נע

⏱ ~45 דקות

🎯 בשיעור הזה
  • ארבעה דפוסים עם Map ו־Set: "ראיתי כבר", "ההשלמה", ספירה, ומפתח קנוני.
  • שני מצביעים וחלון נע: O(n) במקום O(n²).
  • Map כמבנה עם סדר: LRU cache בעשר שורות.

1. למה Map ו־Set מהירים

Set לא מחפש. הוא מחשב מהמפתח מספר (hash), והמספר אומר באיזה "תא" בזיכרון לחפש. לכן has לוקח אותו זמן עם 10 איברים ועם מיליון — O(1) בממוצע. ("בממוצע" — כי שני מפתחות יכולים לקבל אותו תא, ואז בודקים את שניהם. במנועים מודרניים זה כמעט לא מורגש.) המחיר: זיכרון נוסף, ואין סדר לפי ערך — רק לפי הכנסה.

אותו רעיון כמו אינדקס hash במסד, ו־GET key ב־Redis. ברוב שאלות הראיון, השאלה הראשונה שכדאי לשאול את עצמך: "מה אני מחפש שוב ושוב — ואפשר לשים את זה ב־Map?"

2. ארבעה דפוסים

// 1. "ראיתי כבר?" — Set
const seen = new Set<string>();
const firstRepeat = ["dana", "yossi", "noa", "yossi", "dana"].find((u) => (seen.has(u) ? true : (seen.add(u), false)));
console.log("ראשון שחוזר:", firstRepeat);

// 2. "ההשלמה" — Map של ערך ← אינדקס (Two Sum)
const prices = [89, 119, 30, 70, 24];
const at = new Map<number, number>();
for (let j = 0; j < prices.length; j++) {
  const i = at.get(100 - prices[j]);
  if (i !== undefined) { console.log("זוג ל־100:", [i, j]); break; }
  at.set(prices[j], j);
}

// 3. ספירה — Map של ערך ← כמה
const counts = new Map<string, number>();
for (const item of ["latte", "mocha", "latte", "tea", "latte"]) counts.set(item, (counts.get(item) ?? 0) + 1);
console.log("ספירה:", Object.fromEntries(counts));

// 4. מפתח קנוני — מקבצים לפי צורה מנורמלת
const groups = new Map<string, string[]>();
for (const email of ["Dana@x.com", "yossi@x.com", " dana@X.com"]) {
  const key = email.trim().toLowerCase();
  groups.set(key, [...(groups.get(key) ?? []), email]);
}
console.log("קבוצות:", [...groups.values()]);
ראשון שחוזר: yossi
זוג ל־100: [ 2, 3 ]
ספירה: { latte: 3, mocha: 1, tea: 1 }
קבוצות: [ [ 'Dana@x.com', ' dana@X.com' ], [ 'yossi@x.com' ] ]
  • "ראיתי כבר" — כפילויות, "הראשון שחוזר", מעגל ברשימה (E06, E21).
  • "ההשלמה" — לכל איבר שואלים: "האם מה שחסר לי כבר הופיע?" במקום לולאה פנימית שמחפשת אותו (E07). שים לב לסדר: קודם בודקים, אחר כך מוסיפים — אחרת 50 מוצא את עצמו.
  • ספירה — "הכי נפוץ", "הכי נמכרים", "האם שתי מחרוזות הן אנגרמות" (E14).
  • מפתח קנוני — מנרמלים, ואז מקבצים או משווים (E08). זה בדיוק GROUP BY lower(email), או אינדקס UNIQUE על lower(email) במסד.

3. שני מצביעים וחלון נע

"הכי הרבה בקשות בדקה אחת", "הרצף הארוך ביותר בלי תו חוזר", "תת־מערך עם סכום X". הגרסה הנאיבית: לכל נקודת התחלה — לולאה שסופרת קדימה. O(n²). הגרסה הטובה: שני אינדקסים, left ו־right, ששניהם רק מתקדמים:

P27-E11.ts 
let left = 0;
for (let right = 0; right < timestamps.length; right++) {
  while (timestamps[right] - timestamps[left] >= windowMs) left++;   // החלון ארוך מדי ← מכווצים משמאל
  const count = right - left + 1;                                    // מה שבין left ל־right — בתוך החלון
  …
}

יש while בתוך for — ובכל זאת O(n): left מתקדם לכל היותר n פעמים בסך הכול, לא n פעמים לכל right. כשמסבירים סיבוכיות בראיון, זה בדיוק סוג הנימוק שמראיינים מחפשים: "כל איבר נכנס לחלון פעם אחת ויוצא פעם אחת".

נשמע מוכר? זה ה־sliding window של הגבלת קצב (פרק 24) וה־sorted set עם ZREMRANGEBYSCORE (פרק 26): להוציא מה שיצא מהחלון, ולספור מה שנשאר.

4. Map עם סדר: LRU

LRU (Least Recently Used) — cache מוגבל בגודל, שכשהוא מתמלא מוציא את מי שהכי מזמן לא נגעו בו. שאלה אהובה בראיונות Backend, כי היא משלבת מבנה נתונים עם בעיה אמיתית. ב־JavaScript הטריק הוא ש־Map זוכר סדר הכנסה:

const lru = new Map<string, number>();
const touch = (k: string, v: number) => { lru.delete(k); lru.set(k, v); if (lru.size > 3) lru.delete(lru.keys().next().value!); };

touch("a", 1); touch("b", 2); touch("c", 3);
touch("a", 1);           // a "נגע" ← עובר לסוף
touch("d", 4);           // מלא ← יוצא הוותיק: b
console.log([...lru.keys()]);
[ 'c', 'a', 'd' ]

הפתרון ה"קלאסי" בשפות אחרות הוא hash map + רשימה מקושרת כפולה. בראיון אפשר להגיד: "ב־JavaScript, Map שומר סדר — אז delete ו־set מעבירים לסוף ב־O(1). אם תרצה, אממש עם רשימה מקושרת". זה מראה שאתה מכיר גם את השפה וגם את הרעיון. (E16 — עם get, size ובדיקת קלט.)

⚠️ מתי Map לא מתאים
  • צריך סדר לפי ערך ("הכי זול", "בין 20 ל־35") — Map לא עוזר. מיון + חיפוש בינארי (שיעור 3), או במסד: אינדקס B-tree.
  • מפתח שהוא אובייקט — Map משווה לפי זהות: map.get({ id: 1 }) לא ימצא אובייקט אחר עם אותו id. משתמשים במפתח פרימיטיבי (id, או מחרוזת קנונית).
