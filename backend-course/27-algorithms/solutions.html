P27-E26 · הראשון שמופיע פעם אחת 🤖 🔥 חימום רמה 1

💡 רמז 1

שני מעברים. בראשון סופרים כל ערך ב־Map. בשני עוברים שוב על המערך (לא על ה־Map), ומחזירים את הראשון שהספירה שלו היא 1.

💡 רמז 2

counts.set(item, (counts.get(item) ?? 0) + 1). ‏?? ולא ||: כאן זה לא משנה (ספירה לא יכולה להיות 0), אבל זה הרגל טוב.

✅ פתרון
// P27-E26 — הראשון שמופיע פעם אחת בלבד
export function firstUnique<T>(items: T[]): T | undefined {
  const counts = new Map<T, number>();
  for (const item of items) counts.set(item, (counts.get(item) ?? 0) + 1);
  for (const item of items) if (counts.get(item) === 1) return item;
  return undefined;
}

שני מעברים של O(n) הם עדיין O(n). זה הדפוס הבסיסי של שיעור 2: "לספור קודם, להחליט אחר כך". הוא חוזר ב־anagrams (‏E08) וב־top-K (‏E14).

המעבר השני הוא על המערך, כי שם הסדר. אגב, גם Map שומר על סדר ההכנסה (פרק 7), כך שמעבר על ה־Map היה עובד גם הוא. אבל בראיון כדאי להגיד את זה במפורש, ולא לסמוך על זה בשקט.

⚠️ טעויות נפוצות
  • indexOf / filter בתוך לולאה — נכון, ו־O(n²). על 100,000 ערכים זה כמה שניות.
  • Set של "ראיתי" — יודע רק אם הערך הופיע, לא כמה פעמים. ‏3 שמופיע שלוש פעמים נראה כמו 3 שמופיע פעמיים.
  • if (!result) בבדיקה — ‏0 ו־"" הם תשובות תקינות.

P27-E27 · מיזוג רשימות ממוינות 🤖 🔁 חזרה רמה 2

💡 רמז 1

שני אינדקסים, i ו־j. ‏while (i < a.length && j < b.length): אם a[i] <= b[j] ← out.push(a[i++]), אחרת מ־b. כשאחת נגמרת, מעתיקים את מה שנשאר בשנייה (שתי לולאות קצרות, או slice).

💡 רמז 2

mergeAll: ‏while (round.length > 1). בכל סיבוב, לולאה עם k += 2 שממזגת את round[k] עם round[k + 1]. אם נשארה רשימה בודדת בסוף (מספר אי־זוגי), היא עוברת לסיבוב הבא כמו שהיא.

✅ פתרון
// P27-E27 — מיזוג רשימות ממוינות
export function mergeSorted(a: number[], b: number[]): number[] {
  const out: number[] = [];
  let i = 0;
  let j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) out.push(a[i++]);
    else out.push(b[j++]);
  }
  while (i < a.length) out.push(a[i++]);
  while (j < b.length) out.push(b[j++]);
  return out;
}

export function mergeAll(lists: number[][]): number[] {
  if (lists.length === 0) return [];
  let round = lists;
  while (round.length > 1) {
    const next: number[][] = [];
    for (let k = 0; k < round.length; k += 2) {
      next.push(k + 1 < round.length ? mergeSorted(round[k], round[k + 1]) : round[k]);
    }
    round = next;
  }
  return round[0];
}

‏mergeSorted נוגע בכל איבר פעם אחת: O(n + m). ‏mergeAll בזוגות: בכל סיבוב כל האיברים עוברים מיזוג אחד, ויש log k סיבובים. סך הכול O(n log k), כש־k הוא מספר הרשימות. אילו היית ממזג אחת־אחת לתוך תוצאה שגדלה, הרשימה הראשונה הייתה מועתקת k פעמים: O(n·k).

‏a[i] <= b[j] ולא <: בשוויון לוקחים קודם מ־a. כך המיזוג יציב: ערכים שווים שומרים על הסדר המקורי שלהם. כשממזגים אובייקטים לפי זמן, זה ההבדל בין "האירועים מאותה שנייה לפי סדר השרתים" לבין סדר מקרי. זה גם הצעד שבלב merge sort, ו־ORDER BY ... LIMIT על טבלה מחולקת (partitioned) עושה בדיוק את זה.

⚠️ טעויות נפוצות
  • [...a, ...b].sort() — בלי פונקציית השוואה 10 בא לפני 2. וגם עם פונקציה, זה O(n log n).
  • לשכוח להעתיק את השארית — כל מה שנשאר ברשימה הארוכה נעלם.
  • a.shift() במקום אינדקס — ‏shift הוא O(n), ומשנה את הקלט של מי שקרא לפונקציה.
  • לולאת for עם k += 2 שניגשת ל־round[k + 1] בלי לבדוק — ‏undefined נכנס למיזוג.

P27-E28 · דחיסת רצפים 🤖 🔁 חזרה רמה 2

💡 רמז 1

compress: אינדקס i, ובתוך הלולאה j שרץ קדימה כל עוד text[j] === text[i]. האורך הוא j - i, ואחר כך i = j. הלולאה הפנימית לא הופכת את זה ל־O(n²): ‏i קופץ ישר ל־j, ולכן כל תו נבדק פעם אחת.

💡 רמז 2

decompress: ‏code.matchAll(/(\D)(\d*)/g) — כל התאמה היא תו שאינו ספרה, ואחריו אפס ספרות או יותר. ‏for (const [, ch, count] of ...), ואז ch.repeat(count === "" ? 1 : Number(count)). ספרה בהתחלה לא תיתפס ב־regex בכלל, ולכן בודקים אותה לפני.

✅ פתרון
// P27-E28 — דחיסת רצפים (run-length encoding)
export function compress(text: string): string {
  if (/\d/.test(text)) throw new TypeError("אי אפשר לדחוס טקסט עם ספרות — לא יהיה אפשר לפתוח אותו");
  let out = "";
  let i = 0;
  while (i < text.length) {
    let j = i;
    while (j < text.length && text[j] === text[i]) j++;
    const run = j - i;
    out += run === 1 ? text[i] : `${text[i]}${run}`;
    i = j;
  }
  return out;
}

export function decompress(code: string): string {
  if (/\d/.test(code[0] ?? "")) throw new SyntaxError("קוד לא יכול להתחיל בספרה");
  let out = "";
  for (const [, ch, count] of code.matchAll(/(\D)(\d*)/g)) {
    if (count.startsWith("0")) throw new SyntaxError(`מספר לא תקין אחרי ${ch}: ${count}`);
    out += ch.repeat(count === "" ? 1 : Number(count));
  }
  return out;
}

const samples = ["aaabccdddd", "abc", "", "zzzzzzzzzzzz"];
for (const s of samples) {
  const c = compress(s);
  console.log(JSON.stringify(s), "→", JSON.stringify(c), "→", decompress(c) === s ? "✓" : "✗");
}
"aaabccdddd" → "a3bc2d4" → ✓
"abc" → "abc" → ✓
"" → "" → ✓
"zzzzzzzzzzzz" → "z12" → ✓

הנקודה העדינה היא \d* ולא \d: ‏z12 הוא z פעמיים־עשרה, ולא z, ‏1, ‏2. ולכן גם האיסור על ספרות בטקסט: ב־"a1" הדחיסה הייתה "a1", והפתיחה הייתה מחזירה "a". פורמט שאי אפשר לפענח בחזרה הוא באג, גם אם כל צד נראה תקין לבד.

על ביצועים: ‏out += ... בלולאה נשמע כמו O(n²), כי מחרוזות לא משתנות. בפועל V8 מחזיק "חבל" (rope) של חתיכות, ומחבר אותן פעם אחת בסוף. 200,000 תווים לוקחים כמה מילישניות. בראיון כדאי להזכיר שבשפות אחרות (Java) משתמשים ב־StringBuilder, וב־JavaScript אפשר מערך ו־join.

⚠️ טעויות נפוצות
  • /(\D)(\d)/g — רק ספרה אחת: ‏z12 נפתח ל־z ואחר כך 2.
  • להשוות כל תו לתו הקודם ולשכוח את הרצף האחרון אחרי הלולאה — ‏"aab" הופך ל־"a2".
  • Number("") הוא 0 — תו בלי מספר נעלם בפתיחה.
  • לכתוב 1 גם לרצף של תו אחד — עובד, אבל "abc" "נדחס" ל־"a1b1c1", כפול מהמקור.

P27-E01 · מה הסיבוכיות? רמה 1

💡 רמז 1

ספור כמה פעמים כל שורה רצה כש־n גדל פי 10. פונקציות מובנות הן לא "חינם": findIndex, includes ו־shift הן לולאות.

💡 רמז 2

מה shift() עושה לשאר האיברים במערך?

✅ פתרון
  • א — O(n). מעבר אחד.
  • ב — O(n²). לולאה בתוך לולאה על אותו מערך. 10,000 משתמשים = 100 מיליון השוואות.
  • ג — O(n²), למרות שיש "רק" שורה אחת. findIndex הוא לולאה, בתוך filter. התיקון: Set של emails שכבר ראינו (E06, E21).
  • ד — O(n + m). בניית ה־Map — n; כל get — O(1) בממוצע. זה בדיוק מה ש־JOIN עם hash עושה במסד, ומה ש־DataLoader עושה מול בעיית N+1 (פרק 19).
  • ה — O(n log n) בגלל המיון. (אפשר חציון ב־O(n) בממוצע עם quickselect — כמעט אף פעם לא שווה את זה.)
  • ו — O(n²) לפי ההגדרה. shift מזיז את כל השאר מקום אחד שמאלה: O(n) כל פעם. בפועל V8 מקצר את ההתחלה של מערכים קטנים בלי להעתיק, אז על 10,000 איברים זה מהיר — אבל מדדתי ריקון של 100,000 מספרים: 768ms, ו־100,000 מערכים קטנים: 8.2 שניות. לתור גדול — אינדקס שרץ קדימה (כמו ב־BFS, E15).
⚠️ טעויות נפוצות
  • לספור "כמה לולאות כתובות בקוד" במקום כמה עבודה נעשית: arr.includes בתוך for הוא לולאה כפולה.

P27-E02 · איזה מבנה נתונים? רמה 1

💡 רמז 1

שאל: מה הפעולה שחוזרת הכי הרבה? חיפוש לפי ערך? הוספה בסוף והוצאה מהסוף? מההתחלה? טווח?

💡 רמז 2

heap — "תור עדיפויות": הוספה והוצאת המינימום ב־O(log n).

✅ פתרון
  1. Set — has ב־O(1). (במסד: אינדקס UNIQUE, שעושה גם את האכיפה.)
  2. מחסנית — האחרון שנכנס הוא הראשון שמבטלים.
  3. תור (FIFO). בשרת אמיתי — תור חיצוני, כמו BullMQ (פרק 26).
  4. מערך ממוין + חיפוש בינארי — שני חיפושים, O(log n) לשאילתה (E10). במסד: אינדקס B-tree על created_at — אותו רעיון בדיוק.
  5. Map (מפתח ← מונה). ובין כמה שרתים — HINCRBY ב־Redis.
  6. heap. ב־JavaScript אין מובנה; בראיון אומרים "priority queue / heap" ומסבירים, ולרוב לא נדרש לממש. עם מעט משימות — מערך וחיפוש מקסימום מספיק לגמרי.
⚠️ טעויות נפוצות
  • מערך לכל דבר: emails.includes(x) עובד מצוין עם 100 משתמשים — ומפיל שרת עם מיליון.

P27-E03 · לפני שכותבים קוד רמה 1

💡 רמז 1

מה הקלט בדיוק? כמה מוצרים? מה עושים בתיקו? כמה "נמכרים ביותר"?

💡 רמז 2

הפתרון הראשון לא צריך להיות חכם — הוא צריך להיות נכון ולהיאמר בקול.

✅ פתרון
  1. שאלות: מה הקלט — מערך של מכירות (productId לכל יחידה) או של הזמנות עם כמויות? כמה להחזיר (k)? בתיקו — מה הסדר? מה הסדר גודל — אלף מכירות או מיליארד (נכנס לזיכרון)? ומה מחזירים — מזהים, או גם ספירה?

זה E14 — עכשיו אפשר לכתוב.

⚠️ טעויות נפוצות

P27-E04 · חמש שאלות Backend רמה 1

💡 רמז 1

מבנה טוב לתשובה: הגדרה במשפט ← למה זה חשוב ← דוגמה מהקוד שלי ← המחיר או ה־trade-off.

💡 רמז 2

כל התשובות נמצאות בפרקים 14, 18, 21, 24 ובפרויקט 3. שיעור 5 מסכם.

✅ פתרון
  1. PUT מחליף את כל המשאב; PATCH משנה חלק. idempotent = לשלוח פעמיים זה כמו פעם אחת — PUT, DELETE ו־GET כן, POST לא. לכן ב־POST של הזמנה ותשלום אני דורש Idempotency-Key (פרק 24, פרויקט 3), ולעגלה השתמשתי ב־PUT /cart/items/:id — "הכמות היא 2", לא "תוסיף 1".
  2. כשיש שאילתה חוזרת שמסננת או ממיינת לפי עמודה בטבלה גדולה — ו־EXPLAIN ANALYZE מראה Seq Scan. המחיר: כל INSERT/UPDATE מעדכן גם את האינדקס, ומקום בדיסק. לא מוסיפים "ליתר ביטחון" (פרק 18).
  3. session — מזהה שהשרת שומר; קל לבטל. JWT — חתום, השרת לא שומר כלום; מהיר ומתאים לכמה שרתים, אבל אי אפשר "לבטל" טוקן לפני שפג. לכן: access token קצר (15 דק׳) ו־refresh token שנשמר במסד ואפשר לבטל (פרק 21).
  4. אצלי: UPDATE products SET stock = stock − 1 WHERE id = … AND stock >= 1, בתוך טרנזקציה, ובודקים כמה שורות עודכנו — המסד מסדר את שתי הבקשות, ורק אחת מצליחה. ועוד CHECK (stock >= 0) כרשת ביטחון. וידאתי בבדיקה עם 20 בקשות במקביל: גרסה נאיבית (SELECT ואז UPDATE) מכרה 12 יחידות מתוך 3.
  5. למדוד לפני שמנחשים: request ID בלוגים ← כמה זמן כל שלב; EXPLAIN ANALYZE לשאילתות; לחפש N+1. ואז, לפי הממצא: אינדקס, לתקן N+1, עימוד, ורק אחר כך cache (פרקים 18, 24, 26).
⚠️ טעויות נפוצות
  • תשובה של הגדרה בלבד ("idempotent זה שאפשר לחזור על זה"). מה שמבדיל ג׳וניור טוב: "ואצלי בפרויקט עשיתי את זה כך, כי…".

P27-E06 · כפילויות 🤖 רמה 2

💡 רמז 1

"ראיתי כבר?" — Set.

💡 רמז 2

hasDuplicates בשורה אחת: מה הגודל של Set שנבנה מהמערך?

✅ פתרון
// P27-E06
// Set: "ראיתי כבר?" ב־O(1). מעבר אחד על המערך ← O(n) זמן, O(n) זיכרון
export function firstDuplicate<T>(items: readonly T[]): T | undefined {
  const seen = new Set<T>();
  for (const item of items) {
    if (seen.has(item)) return item;
    seen.add(item);
  }
  return undefined;
}

export function hasDuplicates<T>(items: readonly T[]): boolean {
  return new Set(items).size !== items.length;
}
⚠️ טעויות נפוצות
  • items.indexOf(x) !== i בתוך לולאה — נכון, ו־O(n²): על 50,000 ערכים כשנייה, על מיליון — שעות.

P27-E07 · שני מוצרים לכרטיס מתנה 🤖 רמה 2

💡 רמז 1

הגרסה הנאיבית: לכל זוג — O(n²). השאלה הנכונה לכל מחיר: "האם ההשלמה שלו (target − price) כבר הופיעה?"

💡 רמז 2

Map מערך ← אינדקס. שמור רק את ההופעה הראשונה של כל מחיר.

✅ פתרון
// P27-E07
// Map של "ערך ← אינדקס" למה שכבר ראינו: לכל מחיר בודקים אם ההשלמה שלו כבר הופיעה. O(n)
export function twoSum(prices: readonly number[], target: number): [number, number] | null {
  const seenAt = new Map<number, number>();
  for (let j = 0; j < prices.length; j++) {
    const i = seenAt.get(target - prices[j]);
    if (i !== undefined) return [i, j];
    if (!seenAt.has(prices[j])) seenAt.set(prices[j], j); // הראשון — כדי שהזוג יהיה הכי מוקדם
  }
  return null;
}

זו כנראה שאלת הראיון הנפוצה בעולם ("Two Sum"). הדפוס שמאחוריה — "Map של מה שכבר ראיתי, ובדיקה מול השלמה" — חוזר בעשרות שאלות.

⚠️ טעויות נפוצות
  • להכניס את המחיר ל־Map לפני הבדיקה — ואז 50 עם target 100 "מוצא" את עצמו.

P27-E08 · אנגרמות 🤖 רמה 2

💡 רמז 1

צריך מפתח שזהה לכל המילים בקבוצה. מה משותף ל־"listen" ול־"silent"?

💡 רמז 2

האותיות ממוינות: [...w.toLowerCase()].sort().join(""). ו־Map שומר את סדר ההכנסה.

✅ פתרון
// P27-E08
// מפתח קנוני לכל קבוצה: האותיות ממוינות. Map שומר את סדר ההוספה — כלומר סדר ההופעה הראשונה
export function groupAnagrams(words: readonly string[]): string[][] {
  const groups = new Map<string, string[]>();
  for (const word of words) {
    const key = [...word.toLowerCase()].sort().join("");
    const group = groups.get(key);
    if (group) group.push(word);
    else groups.set(key, [word]);
  }
  return [...groups.values()];
}

הדפוס: "מפתח קנוני" — מנרמלים כל פריט לצורה אחת, ומקבצים לפיה. אותו רעיון כמו email.trim().toLowerCase() (E21), או כמו GROUP BY lower(email) במסד.

⚠️ טעויות נפוצות
  • להשוות כל מילה לכל מילה ("האם הן אנגרמות?") — O(n²).

P27-E09 · סוגריים מאוזנים 🤖 רמה 2

💡 רמז 1

מחסנית: פותח ← push. סוגר ← הפותח האחרון חייב להיות מאותו סוג.

💡 רמז 2

שמור במחסנית את האינדקס של הפותח, לא את התו — כך יודעים איפה הבעיה.

✅ פתרון
// P27-E09
// מחסנית: כל פותח נדחף; כל סוגר חייב להתאים לפותח האחרון. מחסנית לא ריקה בסוף ← משהו לא נסגר
const PAIRS: Record<string, string> = { ")": "(", "]": "[", "}": "{" };

export function checkBrackets(text: string): { ok: true } | { ok: false; index: number } {
  const stack: number[] = []; // אינדקסים של הפותחים — כדי לדעת איפה הבעיה
  for (let i = 0; i < text.length; i++) {
    const ch = text[i];
    if (ch === "(" || ch === "[" || ch === "{") stack.push(i);
    else if (ch in PAIRS) {
      if (stack.length === 0 || text[stack[stack.length - 1]] !== PAIRS[ch]) return { ok: false, index: i };
      stack.pop();
    }
  }
  return stack.length === 0 ? { ok: true } : { ok: false, index: stack[0] };
}

זה מה שעושה כל parser — של JSON, של TypeScript, של SQL — כשהוא מדווח "Unexpected token at position 11".

⚠️ טעויות נפוצות
  • לספור פותחים וסוגרים ("שווים ← מאוזן") — ([)] עובר את הספירה.

P27-E10 · חיפוש בינארי 🤖 רמה 2

💡 רמז 1

טווח [lo, hi) שהתשובה בתוכו. mid קטן מ־x ← התשובה מימין: lo = mid + 1. אחרת ← mid עצמו מועמד: hi = mid.

💡 רמז 2

ערכים שלמים: "עד to כולל" = "לפני הראשון שהוא >= to + 1".

✅ פתרון
// P27-E10
// חיפוש בינארי: הטווח [lo, hi) תמיד מכיל את התשובה, וחוצים אותו בכל צעד ← O(log n)
export function lowerBound(sorted: readonly number[], x: number): number {
  let lo = 0;
  let hi = sorted.length; // התשובה יכולה להיות length: "כולם קטנים מ־x"
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (sorted[mid] < x) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}

// כמה ערכים ב־[from, to] — שני חיפושים בינאריים
export function countInRange(sorted: readonly number[], from: number, to: number): number {
  if (from > to) return 0;
  return lowerBound(sorted, to + 1) - lowerBound(sorted, from);
}

זה בדיוק מה שאינדקס B-tree עושה ב־PostgreSQL ל־WHERE price BETWEEN 20 AND 35: יורד לנקודת ההתחלה ב־O(log n), וקורא ברצף עד הסוף.

⚠️ טעויות נפוצות
  • להחזיר "נמצא / לא נמצא" במקום מיקום. lower bound שימושי בהרבה: הוא גם "איפה להכניס" וגם "מאיפה לקרוא".

P27-E11 · שיא עומס בחלון זמן 🤖 רמה 2

💡 רמז 1

שני מצביעים: right מתקדם אחד־אחד; left מתקדם כל עוד החלון ארוך מדי.

💡 רמז 2

למה זה O(n) ולא O(n²), אם יש while בתוך for? כמה פעמים בסך הכול left יכול לזוז?

✅ פתרון
// P27-E11
// חלון נע עם שני מצביעים: right מתקדם, left "מדביק" כשהחלון ארוך מדי. כל אינדקס נכנס ויוצא פעם אחת ← O(n)
export function peakInWindow(timestamps: readonly number[], windowMs: number): { count: number; start: number } {
  let best = { count: 0, start: timestamps[0] ?? 0 };
  let left = 0;
  for (let right = 0; right < timestamps.length; right++) {
    while (timestamps[right] - timestamps[left] >= windowMs) left++;
    const count = right - left + 1;
    if (count > best.count) best = { count, start: timestamps[left] };
  }
  return best;
}

"שני מצביעים" / "חלון נע" — אותו רעיון כמו הגבלת קצב עם חלון נע (פרקים 24, 26), וכמו "הרצף הארוך ביותר בלי תו חוזר" — שאלת ראיון קלאסית.

⚠️ טעויות נפוצות
  • לכל בקשה — לספור מחדש את כל הבקשות בחלון שלה: O(n × k).

P27-E13 · איחוד מרווחים 🤖 רמה 3

💡 רמז 1

אחרי מיון לפי התחלה — רק המרווח האחרון בתוצאה יכול לחפוף לבא בתור.

💡 רמז 2

[...intervals].sort(...) — עותק. וגם כל זוג בתוצאה — מערך חדש, לא המערך מהקלט (אחרת "הארכה" שלו משנה את הקלט).

✅ פתרון
// P27-E13
// ממיינים לפי התחלה (עותק!), ואז מעבר אחד: חופף לאחרון ← מאריכים אותו; אחרת ← מרווח חדש. O(n log n)
export function mergeIntervals(intervals: readonly (readonly [number, number])[]): [number, number][] {
  const sorted = [...intervals].sort((a, b) => a[0] - b[0]);
  const merged: [number, number][] = [];
  for (const [start, end] of sorted) {
    const last = merged[merged.length - 1];
    if (last && start <= last[1]) last[1] = Math.max(last[1], end);
    else merged.push([start, end]);
  }
  return merged;
}
⚠️ טעויות נפוצות
  • last[1] = end במקום Math.max(last[1], end) — מרווח שמוכל בקודם "מקצר" אותו.

P27-E14 · הכי נמכרים 🤖 רמה 3

💡 רמז 1

שני שלבים: ספירה (Map), ואז מיון של הזוגות.

💡 רמז 2

פונקציית השוואה עם שני קריטריונים: b.count - a.count || ….

✅ פתרון
// P27-E14
// ספירה ב־Map ← O(n); מיון של הערכים השונים ← O(m log m). (עם heap בגודל k: O(m log k) — לרוב לא שווה את המורכבות)
export function topK(items: readonly string[], k: number): { item: string; count: number }[] {
  const counts = new Map<string, number>();
  for (const item of items) counts.set(item, (counts.get(item) ?? 0) + 1);
  return [...counts]
    .map(([item, count]) => ({ item, count }))
    .sort((a, b) => b.count - a.count || (a.item < b.item ? -1 : a.item > b.item ? 1 : 0))
    .slice(0, k);
}
⚠️ טעויות נפוצות
  • a.item.localeCompare(b.item) — תלוי בשפה של המחשב; כאן השוואה פשוטה מספיקה ויציבה.

P27-E15 · הדרך הקצרה במחסן 🤖 רמה 3

💡 רמז 1

BFS: תור, ומרחק לכל תא. התא הראשון שיוצא מהתור הוא תמיד הקרוב ביותר שעוד לא טופל.

💡 רמז 2

מסמנים "ביקרתי" כשמכניסים לתור — אחרת אותו תא נכנס כמה פעמים. ובמקום queue.shift() (שעל תור גדול נהיה איטי — שיעור 3) — אינדקס head שרץ קדימה.

✅ פתרון
// P27-E15
// BFS: מתקדמים "בגלים" — כל התאים במרחק 1, אחר כך 2... הפעם הראשונה שמגיעים ל־E היא הקצרה ביותר
export function shortestPath(grid: readonly string[]): number {
  const h = grid.length;
  const w = grid[0]?.length ?? 0;
  let start: [number, number] | null = null;
  for (let y = 0; y < h; y++) {
    const x = grid[y].indexOf("S");
    if (x !== -1) start = [x, y];
  }
  if (!start) return -1;
  const dist = new Map<number, number>([[start[1] * w + start[0], 0]]); // מסמנים כשנכנסים לתור, לא כשיוצאים
  const queue: [number, number][] = [start];
  for (let head = 0; head < queue.length; head++) { // אינדקס במקום shift(): לא מזיזים כלום, גם כשהתור ענק
    const [x, y] = queue[head];
    const d = dist.get(y * w + x)!;
    if (grid[y][x] === "E") return d;
    for (const [dx, dy] of [[1, 0], [-1, 0], [0, 1], [0, -1]]) {
      const nx = x + dx;
      const ny = y + dy;
      if (nx < 0 || ny < 0 || nx >= w || ny >= h || grid[ny][nx] === "#" || dist.has(ny * w + nx)) continue;
      dist.set(ny * w + nx, d + 1);
      queue.push([nx, ny]);
    }
  }
  return -1;
}

"גרף" בראיון זה לרוב בדיוק זה: רשת, או "משתמשים וחברים", או "תלויות". BFS ← הקצר ביותר כשכל צעד עולה אותו דבר. DFS ← "האם יש דרך", או לעבור על הכול.

⚠️ טעויות נפוצות
  • DFS (מחסנית / רקורסיה) לדרך הקצרה — מוצא דרך, לא בהכרח את הקצרה (E22).

P27-E16 · LRU cache 🤖 רמה 3

💡 רמז 1

Map ב־JavaScript שומר סדר הכנסה. הראשון ב־map.keys() הוא הוותיק.

💡 רמז 2

"לרענן" מפתח = delete ואז set — עובר לסוף.

✅ פתרון
// P27-E16
// Map ב־JavaScript שומר סדר הכנסה: הראשון = הכי פחות בשימוש. "שימוש" = מוחקים ומכניסים מחדש (לסוף). הכול O(1)
export class LRUCache<K, V> {
  private readonly map = new Map<K, V>();
  private readonly capacity: number;

  // (בלי "constructor(private capacity)": Node מריץ TypeScript בלי קומפילציה, וזה תחביר שאינו JavaScript)
  constructor(capacity: number) {
    this.capacity = capacity;
    if (!Number.isInteger(capacity) || capacity < 1) throw new Error("capacity חייב להיות שלם חיובי");
  }

  get size() {
    return this.map.size;
  }

  get(key: K): V | undefined {
    if (!this.map.has(key)) return undefined;
    const value = this.map.get(key)!;
    this.map.delete(key);
    this.map.set(key, value);
    return value;
  }

  set(key: K, value: V): void {
    this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.capacity) this.map.delete(this.map.keys().next().value!);
  }

  keys(): K[] {
    return [...this.map.keys()]; // מהישן לחדש
  }
}

בשפות אחרות הפתרון הקלאסי הוא hash map + רשימה מקושרת כפולה; ב־JavaScript, Map כבר עושה את שניהם. בראיון כדאי להגיד את זה במפורש — ולהיות מוכן לממש את הרשימה אם יבקשו. ובעולם: maxmemory-policy allkeys-lru של Redis, וה־cache של כל דפדפן.

⚠️ טעויות נפוצות
  • לשמור "זמן שימוש אחרון" ולחפש מינימום כשמתמלא — O(n) לכל הוצאה.

P27-E17 · סדר הרצה של migrations 🤖 רמה 3

💡 רמז 1

לכל שם: כמה תלויות עוד לא "שוחררו". מתחילים ממי שיש לו 0.

💡 רמז 2

כשמוציאים שם — מורידים 1 לכל מי שתלוי בו; מי שהגיע ל־0 — מוכן. נגמר התור ועוד יש שמות? מעגל.

✅ פתרון
// P27-E17
// מיון טופולוגי (Kahn): מתחילים ממי שאין לו תלויות, ו"משחררים" את מי שחיכה לו.
// נשארו צמתים שלא שוחררו ← יש מעגל. בכל שלב — האלפביתי הראשון, כדי שהסדר יהיה קבוע
export function buildOrder(deps: Readonly<Record<string, readonly string[]>>): string[] {
  const names = new Set<string>(Object.keys(deps));
  for (const list of Object.values(deps)) for (const d of list) names.add(d);
  const waitingFor = new Map<string, number>();
  const dependents = new Map<string, string[]>();
  for (const name of names) {
    waitingFor.set(name, 0);
    dependents.set(name, []);
  }
  for (const [name, list] of Object.entries(deps)) {
    for (const d of new Set(list)) {
      waitingFor.set(name, waitingFor.get(name)! + 1);
      dependents.get(d)!.push(name);
    }
  }
  const ready = [...names].filter((n) => waitingFor.get(n) === 0).sort();
  const order: string[] = [];
  while (ready.length) {
    const next = ready.shift()!;
    order.push(next);
    for (const dep of dependents.get(next)!) {
      const left = waitingFor.get(dep)! - 1;
      waitingFor.set(dep, left);
      if (left === 0) {
        ready.push(dep);
        ready.sort();
      }
    }
  }
  if (order.length !== names.size) {
    const stuck = [...names].filter((n) => !order.includes(n)).sort();
    throw new Error(`יש מעגל בתלויות: ${stuck.join(", ")}`);
  }
  return order;
}

מיון טופולוגי מופיע בכל מקום ב־Backend: סדר migrations, סדר בנייה של חבילות ב־monorepo, depends_on ב־Docker Compose, ו־Nest — שבונה את ה־providers לפי סדר התלויות (וזורק על תלות מעגלית, כמו שראינו בפרק 26).

⚠️ טעויות נפוצות
  • DFS בלי זיהוי מעגל — רקורסיה אינסופית, Maximum call stack size exceeded.

P27-E18 · הלקוח המוביל בכל עיר 🤖 רמה 3

💡 רמז 1

שני שלבים: סכום לכל לקוח (GROUP BY), ואז "הראשון בכל עיר".

💡 רמז 2

ROW_NUMBER() OVER (PARTITION BY city ORDER BY paid_total DESC, id) — ואז WHERE rn = 1 בשאילתה החיצונית (פרק 17).

✅ פתרון
-- P27-E18
-- הלקוח המוביל בכל עיר (סכום ההזמנות ששולמו); בתיקו — ה־id הקטן. ROW_NUMBER ממספר בתוך כל עיר
WITH totals AS (
  SELECT c.id, c.name, c.city, SUM(o.total) AS paid_total
  FROM customers c
  JOIN orders o ON o.customer_id = c.id AND o.status = 'paid'
  GROUP BY c.id
),
ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY city ORDER BY paid_total DESC, id) AS rn
  FROM totals
)
SELECT city, name, paid_total
FROM ranked
WHERE rn = 1

✅ פתרון
// P27-E19
// sweep line: כל סשן = שני אירועים (+1 בהתחלה, −1 בסוף). ממיינים לפי זמן — וסוף לפני התחלה באותו רגע
// (end לא כולל: סשן שנגמר ב־10 וסשן שמתחיל ב־10 לא חופפים). O(n log n)
export function peakConcurrency(sessions: readonly { start: number; end: number }[]): { peak: number; at: number | null } {
  const events: [number, number][] = [];
  for (const s of sessions) {
    if (s.end <= s.start) continue;
    events.push([s.start, 1], [s.end, -1]);
  }
  events.sort((a, b) => a[0] - b[0] || a[1] - b[1]);
  let current = 0;
  let best = { peak: 0, at: null as number | null };
  for (const [time, delta] of events) {
    current += delta;
    if (current > best.peak) best = { peak: current, at: time };
  }
  return best;
}

"sweep line" — אותה שאלה כמו "כמה חדרי ישיבות צריך", "כמה חיבורים פתוחים למסד בשיא", ו"כמה שרתים צריך כדי לעמוד בעומס".

⚠️ טעויות נפוצות
  • לבדוק כל זוג סשנים — O(n²), וגם לא נותן את השיא (שלושה שחופפים בזוגות לא בהכרח חופפים יחד).

💡 רמז 2

// P27-E20
export function lowerBound(sorted: readonly number[], x: number): number {
  let lo = 0;
  let hi = sorted.length; // תקלה 1: היה length − 1 ← "כולם קטנים" החזיר את האינדקס האחרון במקום length
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (sorted[mid] < x) lo = mid + 1; // תקלה 2: היה <= ← זה upper bound (הראשון שגדול מ־x), לא הראשון שגדול או שווה
    else hi = mid;
  }
  return lo;
}

export function countInRange(sorted: readonly number[], from: number, to: number): number {
  if (from > to) return 0;
  return lowerBound(sorted, to + 1) - lowerBound(sorted, from); // תקלה 3: היה lowerBound(to) ← ערכים ששווים ל־to לא נספרו
}

חיפוש בינארי הוא האלגוריתם עם הכי הרבה באגים ביחס לאורך שלו. ההרגל שמציל: להגדיר במילים מה הטווח [lo, hi) מכיל, ולבדוק שלוש דוגמאות: x קטן מכולם, גדול מכולם, ושווה לכמה.

⚠️ טעויות נפוצות
  • lo = mid (בלי +1) — לולאה אינסופית כש־hi = lo + 1.

// P27-E22
export function shortestPath(grid: readonly string[]): number {
  const h = grid.length;
  const w = grid[0]?.length ?? 0;
  let start: [number, number] | null = null;
  for (let y = 0; y < h; y++) {
    const x = grid[y].indexOf("S");
    if (x !== -1) start = [x, y];
  }
  if (!start) return -1;
  const dist = new Map<string, number>([[`${start[0]},${start[1]}`, 0]]);
  const queue: [number, number][] = [start];
  while (queue.length) {
    const [x, y] = queue.shift()!; // תקלה 2: היה pop() ← מחסנית = DFS, שמוצא מסלול — לא בהכרח הקצר
    const d = dist.get(`${x},${y}`)!;
    if (grid[y][x] === "E") return d;
    for (const [dx, dy] of [[1, 0], [-1, 0], [0, 1], [0, -1]]) {
      const nx = x + dx;
      const ny = y + dy;
      // תקלה 1: היה nx <= w ו־ny <= h ← grid[y][w] הוא undefined, "לא קיר" — והמסלול יצא מחוץ למפה
      if (nx < 0 || ny < 0 || nx >= w || ny >= h || grid[ny][nx] === "#" || dist.has(`${nx},${ny}`)) continue;
      dist.set(`${nx},${ny}`, d + 1);
      queue.push([nx, ny]);
    }
  }
  return -1; // תקלה 3: היה return 0 ← "אין דרך" נראה כמו "כבר שם"
}

(כאן נשאר shift() — ברור יותר לקריאה. ב־BFS על רשת התור נשאר קטן (רק ה"חזית"), אז גם על 400×400 מדדתי שזה מהיר; בתור שמגיע למאות אלפים — אינדקס, כמו ב־E15.)

⚠️ טעויות נפוצות
  • "תיקון" עם ?. כדי שלא ייזרק Cannot read properties of undefined — מסתיר את הבאג במקום לתקן אותו. השגיאה הייתה הרמז.

P27-E24 · אתגר: עודף (DP) 🤖 רמה 5

💡 רמז 1

"חמדני" (תמיד המטבע הגדול) נכשל: [1, 3, 4] ו־6. במקום זה: התשובה לכל סכום a נבנית מהתשובות ל־a − c.

💡 רמז 2

מערך best[0..amount], מ־0 למעלה. ב־countWays — הלולאה החיצונית על המטבעות, כדי לא לספור סדרים שונים.

✅ פתרון
// P27-E24
// תכנון דינמי (DP): התשובה לסכום a נבנית מהתשובות לסכומים קטנים יותר — כל אחד מחושב פעם אחת. O(amount × coins)
export function minCoins(coins: readonly number[], amount: number): number {
  const best = new Array<number>(amount + 1).fill(Infinity);
  best[0] = 0;
  for (let a = 1; a <= amount; a++) {
    for (const c of coins) {
      if (c <= a && best[a - c] + 1 < best[a]) best[a] = best[a - c] + 1;
    }
  }
  return best[amount] === Infinity ? -1 : best[amount];
}

// כמה צירופים (בלי חשיבות לסדר): הלולאה החיצונית על המטבעות — כך 1+2 ו־2+1 נספרים פעם אחת
export function countWays(coins: readonly number[], amount: number): number {
  const ways = new Array<number>(amount + 1).fill(0);
  ways[0] = 1;
  for (const c of coins) {
    for (let a = c; a <= amount; a++) ways[a] += ways[a - c];
  }
  return ways[amount];
}

תכנון דינמי (Dynamic Programming) = רקורסיה + "לא לחשב אותו דבר פעמיים". הסימן בראיון: השאלה "כמה דרכים" או "מה המינימום", והתשובה לבעיה גדולה בנויה מתשובות לבעיות קטנות שחוזרות. רקורסיה נאיבית ל־minCoins(…, 9999) לא תסתיים עד סוף הקורס.

⚠️ טעויות נפוצות
  • ב־countWays, לולאה חיצונית על הסכומים ופנימית על המטבעות — סופרת סדרים (1+2 ו־2+1 בנפרד).

P27-E25 · אתגר: השלמה אוטומטית 🤖 רמה 5

💡 רמז 1

הנאיבי — לסנן את כל המונחים בכל הקלדה — O(n) לכל אות. Trie: עץ שבו כל צומת הוא אות, והמסלול מהשורש הוא prefix.

💡 רמז 2

גם עם Trie, איסוף כל תת־העץ של "a" הוא רוב העץ. הטריק: כל צומת שומר את ה־10 המובילים שמתחתיו, ו־add מעדכן אותם לאורך המסלול.

✅ פתרון
// P27-E25
// Trie: עץ של אותיות. כל צומת שומר גם את ה־k הכי פופולריים מתחתיו — כך suggest לא סורק את כל תת־העץ.
// add מעדכן את הרשימות לאורך המסלול: O(L × k). suggest: O(L) — הליכה לצומת, והרשימה מוכנה
interface Node {
  children: Map<string, Node>;
  top: string[]; // עד MAX מונחים, ממוינים
}

const MAX = 10;

export function createAutocomplete() {
  const root: Node = { children: new Map(), top: [] };
  const weights = new Map<string, number>(); // מונח (lowercase) ← משקל מצטבר
  const display = new Map<string, string>(); // מונח (lowercase) ← הכתיב הראשון שנוסף
  const better = (a: string, b: string) => weights.get(b)! - weights.get(a)! || (a < b ? -1 : a > b ? 1 : 0);

  return {
    add(term: string, weight = 1) {
      const key = term.trim().toLowerCase();
      if (!key) return;
      weights.set(key, (weights.get(key) ?? 0) + weight);
      if (!display.has(key)) display.set(key, term.trim());
      let node = root;
      const path = [root];
      for (const ch of key) {
        let next = node.children.get(ch);
        if (!next) {
          next = { children: new Map(), top: [] };
          node.children.set(ch, next);
        }
        node = next;
        path.push(node);
      }
      for (const n of path) {
        if (!n.top.includes(key)) n.top.push(key);
        n.top.sort(better);
        if (n.top.length > MAX) n.top.length = MAX;
      }
    },
    suggest(prefix: string, k = 5): string[] {
      let node: Node | undefined = root;
      for (const ch of prefix.trim().toLowerCase()) {
        node = node.children.get(ch);
        if (!node) return [];
      }
      return node.top.slice(0, Math.min(k, MAX)).map((key) => display.get(key)!);
    },
    get size() {
      return weights.size;
    },
  };
}

פשרה קלאסית: עבודה בכתיבה (add מעדכן L צמתים) כדי שהקריאה תהיה מיידית — כי קוראים הרבה יותר משכותבים. אותו רעיון כמו אינדקס במסד, cache (פרק 26), ו"denormalization". בפרודקשן: PostgreSQL עם pg_trgm, או Elasticsearch / Meilisearch.

⚠️ טעויות נפוצות
  • לשמור ב־top רשימה בלי לבדוק כפילות — אותו מונח מופיע פעמיים אחרי add שני.
