P27-E03 · לפני שכותבים קוד 🧠 הבנה רמה 1

💡 רמז 1

מה הקלט בדיוק? כמה מוצרים? מה עושים בתיקו? כמה "נמכרים ביותר"?

💡 רמז 2

הפתרון הראשון לא צריך להיות חכם — הוא צריך להיות נכון ולהיאמר בקול.

✅ פתרון
  1. שאלות: מה הקלט — מערך של מכירות (productId לכל יחידה) או של הזמנות עם כמויות? כמה להחזיר (k)? בתיקו — מה הסדר? מה הסדר גודל — אלף מכירות או מיליארד (נכנס לזיכרון)? ומה מחזירים — מזהים, או גם ספירה?
  2. דוגמאות: ["latte","mocha","latte"], k=1 ← [{latte, 2}]. מקרה קצה: מערך ריק ← []; k גדול ממספר המוצרים ← כולם.
  3. פתרון ראשון: ספירה ב־Map, מיון לפי ספירה, slice(0, k). O(n + m log m) — n מכירות, m מוצרים שונים.
  4. שיפור: heap בגודל k ← O(n + m log k) — שווה רק כש־m ענק ו־k קטן. ואם "מיליארד מכירות": זה לא בעיה של JavaScript — GROUP BY … ORDER BY count DESC LIMIT k במסד, או מונים מצטברים (sorted set ב־Redis, פרק 26).

זה E14 — עכשיו אפשר לכתוב.

⚠️ טעויות נפוצות
  • לקפוץ ישר לקוד. המראיין שומע שקט, ואז רואה פתרון לשאלה אחרת ממה שהוא התכוון.

P27-E70 · מ־brute force לשיפור 🧠 הבנה רמה 2

💡 רמז 1

"שאלה שחוזרת" ← Map. "טווחים" ← מיון. "בכמה דרכים" ← DP.

💡 רמז 2

ב־2: מה צריך לזכור תוך כדי מעבר אחד?

✅ פתרון
  1. כל זוג: O(n²) ← Set של שניות: O(n).
  2. כל זוג (קנייה לפני מכירה): O(n²) ← מעבר אחד שזוכר את המינימום עד כה: O(n).
  3. לכל טווח — מעבר על כל ההזמנות: O(q·n) ← מיון פעם אחת ו־lowerBound לכל טווח: O(n log n + q log n).
  4. רקורסיה: O(2ⁿ) ← DP (פיבונאצ'י): O(n).
  5. לכל אינדקס — מכפלה של כל השאר: O(n²) ← מכפלות קידומת וסיומת: O(n).
⚠️ טעויות נפוצות
  • לדלג על ה־brute force בקול — המראיין רוצה לראות שאתה יודע שיש פתרון עובד לפני האופטימלי.

P27-E73 · ‏NOT IN ו־NULL — הכול נעלם 🧠 הבנה רמה 2

💡 רמז 1

‏x NOT IN (1, 2, NULL) = ‏x <> 1 AND x <> 2 AND x <> NULL.

💡 רמז 2

‏x <> NULL הוא NULL — אף פעם לא TRUE.

✅ פתרון
SELECT COUNT(*) FROM employees WHERE id NOT IN (SELECT manager_id FROM employees);
SELECT COUNT(*) FROM employees WHERE id NOT IN (SELECT manager_id FROM employees WHERE manager_id IS NOT NULL);
SELECT COUNT(*) FROM employees e WHERE NOT EXISTS (SELECT 1 FROM employees x WHERE x.manager_id = e.id);

בתת־השאילתה יש NULL (מי שאין לו מנהל). ‏NOT IN עם NULL ברשימה לא יכול להיות TRUE לאף שורה — אפס. ‏NOT EXISTS לא נופל במלכודת הזו, ולכן זו הגרסה הבטוחה (ו־PostgreSQL גם מבצע אותה ביעילות, כ־anti join).

⚠️ טעויות נפוצות

P27-E18 · הלקוח המוביל בכל עיר 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני שלבים: סכום לכל לקוח (GROUP BY), ואז "הראשון בכל עיר".

💡 רמז 2

ROW_NUMBER() OVER (PARTITION BY city ORDER BY paid_total DESC, id) — ואז WHERE rn = 1 בשאילתה החיצונית (פרק 17).

✅ פתרון
-- P27-E18
-- הלקוח המוביל בכל עיר (סכום ההזמנות ששולמו); בתיקו — ה־id הקטן. ROW_NUMBER ממספר בתוך כל עיר
WITH totals AS (
  SELECT c.id, c.name, c.city, SUM(o.total) AS paid_total
  FROM customers c
  JOIN orders o ON o.customer_id = c.id AND o.status = 'paid'
  GROUP BY c.id
),
ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY city ORDER BY paid_total DESC, id) AS rn
  FROM totals
)
SELECT city, name, paid_total
FROM ranked
WHERE rn = 1
ORDER BY city;
   city   |    name     | paid_total
----------+-------------+------------
 Haifa    | Dana Levi   |     288.00
 Tel Aviv | Noa Mizrahi |     678.90
(2 rows)

"Top-N לכל קבוצה" — שאלת ה־SQL הנפוצה בראיונות. ב־PostgreSQL יש גם קיצור: SELECT DISTINCT ON (city) … ORDER BY city, paid_total DESC, id. וגם: בחיפה יש תיקו (288 מול 288) — ORDER BY paid_total DESC לבד היה מחזיר אחד מהם "במקרה".

⚠️ טעויות נפוצות
  • MAX(paid_total) לפי עיר — נותן את הסכום, לא את מי. ואז JOIN חזרה מחזיר שתי שורות בתיקו.

P27-E23 · שאילתה עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

מה NULL <> 'paid'? (פרק 16.) ומה השאילתה באמת שואלת: "יש לו הזמנה שלא שולמה", או "אין לו הזמנה ששולמה"?

💡 רמז 2

NOT EXISTS (SELECT 1 FROM orders … AND status = 'paid').

✅ פתרון
-- P27-E23
-- לקוחות בלי אף הזמנה ששולמה — כולל מי שלא הזמין בכלל
SELECT c.id, c.name
FROM customers c
WHERE NOT EXISTS (
  SELECT 1 FROM orders o WHERE o.customer_id = c.id AND o.status = 'paid'
)
ORDER BY c.id;
 id |    name
----+------------
  3 | Dana L.
  5 | Avi Peretz
  7 | Avi P.
  8 | Omer Biton
(4 rows)

שלוש תקלות: (1) WHERE o.status <> 'paid' על LEFT JOIN — לקוח בלי הזמנות מקבל NULL, ו־NULL <> 'paid' הוא לא TRUE ← נעלם; (2) השאלה הלא נכונה — "יש הזמנה לא משולמת" (דנה: הזמנה שבוטלה) במקום "אין משולמת"; (3) לקוח עם שתי הזמנות לא משולמות היה מופיע פעמיים. NOT EXISTS פותר את שלושתן.

⚠️ טעויות נפוצות
  • NOT IN (SELECT customer_id FROM orders WHERE …) — עובד כאן, אבל אם תת־השאילתה מחזירה NULL אחד, NOT IN מחזיר אפס שורות. NOT EXISTS בטוח.

P27-E74 · הרווח המקסימלי — מעבר אחד 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

מעבר אחד, שזוכר את המחיר הנמוך ביותר עד כה (ואת היום שלו).

💡 רמז 2

לכל יום: "אם הייתי מוכר היום — כמה הרווחתי?" ‏prices[i] - minPrice.

✅ פתרון
// P27-E74: הרווח המקסימלי — מעבר אחד
export function maxProfit(prices: number[]) {
  let best: { profit: number; buy: number; sell: number } | null = null;
  let minAt = 0;
  for (let i = 1; i < prices.length; i++) {
    const profit = prices[i] - prices[minAt];
    if (profit > 0 && (!best || profit > best.profit)) best = { profit, buy: minAt, sell: i };
    if (prices[i] < prices[minAt]) minAt = i;
  }
  return best;
}

"מה אני צריך לזכור?" — רק את המינימום עד עכשיו. זו השאלה שהופכת O(n²) ל־O(n) גם ב־E75 ובחלון נע. ‏< (לא <=) בעדכון המינימום — כדי שבשוויון תישאר הקנייה המוקדמת.

⚠️ טעויות נפוצות
  • מינימום ומקסימום של כל המערך — המקסימום יכול לבוא לפני המינימום.

P27-E75 · מכפלה חוץ מעצמי — בלי חילוק 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

מכפלה של כל מה שלפניי × מכפלה של כל מה שאחריי.

💡 רמז 2

מעבר משמאל שממלא "לפני", ומעבר מימין שמכפיל ב"אחרי" — עם משתנה אחד.

✅ פתרון
// P27-E75: מכפלה חוץ מעצמי — בלי חילוק
export function productExceptSelf(nums: number[]): number[] {
  const out = new Array<number>(nums.length);
  let left = 1;
  for (let i = 0; i < nums.length; i++) {
    out[i] = left;
    left *= nums[i];
  }
  let right = 1;
  for (let i = nums.length - 1; i >= 0; i--) {
    out[i] *= right;
    right *= nums[i];
  }
  return out;
}

שני מעברים — O(n), וזיכרון נוסף O(1) מלבד התוצאה. אותו רעיון של "סכומי קידומת" (‏E50), עם כפל.

⚠️ טעויות נפוצות
  • מכפלה כוללת וחילוק — 0 במערך שובר את זה, ו־‏-0 מוסיף הפתעות.

P27-E76 · פלינדרום במשפט — שני מצביעים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏while (i < j): מקדמים את i כל עוד הוא לא אות/ספרה; אותו דבר ל־j מהסוף.

💡 רמז 2

‏s[i].toLowerCase() !== s[j].toLowerCase() ← ‏false.

✅ פתרון
// P27-E76: פלינדרום במשפט — שני מצביעים
const ok = (ch: string) => /[\p{L}\p{N}]/u.test(ch);

export function isPalindromeSentence(s: string): boolean {
  let i = 0;
  let j = s.length - 1;
  while (i < j) {
    if (!ok(s[i])) i++;
    else if (!ok(s[j])) j--;
    else {
      if (s[i].toLowerCase() !== s[j].toLowerCase()) return false;
      i++;
      j--;
    }
  }
  return true;
}

‏O(n) זמן ו־O(1) זיכרון. הגרסה "נקה, הפוך, השווה" היא גם O(n) — אבל עם שני עותקים של המחרוזת. בראיון שואלים בדיוק את זה: "אפשר בלי זיכרון נוסף?"

⚠️ טעויות נפוצות
  • /\w/ — עברית לא נחשבת אות, ו"אבא" לא פלינדרום.

הטבלה פעמיים: FROM employees e JOIN employees m ON m.id = e.manager_id.

-- P27-E77: מרוויחים יותר מהמנהל — self join
SELECT e.name AS employee, e.salary, m.name AS manager, m.salary AS manager_salary

P27-E78 · סכום מצטבר לכל לקוח — window function 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1
SUM(total) OVER (PARTITION BY customer_id ORDER BY created_on, id)
💡 רמז 2

ה־WHERE על הסטטוס רץ לפני ה־window — אז הסכום רק של ששולמו.

✅ פתרון
-- P27-E78: סכום מצטבר לכל לקוח — window function
SELECT customer_id, id, created_on, total,
       SUM(total) OVER (PARTITION BY customer_id ORDER BY created_on, id) AS running_total
FROM orders
WHERE status = 'paid'
ORDER BY customer_id, created_on, id;

‏O(n log n) במסד (מיון לפי partition), בשאילתה אחת — לעומת שאילתה מתואמת (SELECT SUM … WHERE o2.created_on <= o.created_on) שהיא O(n²). ה־id ב־ORDER BY של ה־window חשוב: שתי הזמנות באותו יום בלי שובר שוויון — ושתיהן מקבלות את אותו סכום.

⚠️ טעויות נפוצות
  • ORDER BY created_on בלבד בתוך ה־OVER — ההזמנות של אותו יום מקבלות את הסכום של סוף היום (ה־frame כולל את כל ה"שווים").

P27-E28 · דחיסת רצפים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

compress: אינדקס i, ובתוך הלולאה j שרץ קדימה כל עוד text[j] === text[i]. האורך הוא j - i, ואחר כך i = j. הלולאה הפנימית לא הופכת את זה ל־O(n²): ‏i קופץ ישר ל־j, ולכן כל תו נבדק פעם אחת.

💡 רמז 2

decompress: ‏code.matchAll(/(\D)(\d*)/g) — כל התאמה היא תו שאינו ספרה, ואחריו אפס ספרות או יותר. ‏for (const [, ch, count] of ...), ואז ch.repeat(count === "" ? 1 : Number(count)). ספרה בהתחלה לא תיתפס ב־regex בכלל, ולכן בודקים אותה לפני.

✅ פתרון
// P27-E28 — דחיסת רצפים (run-length encoding)
export function compress(text: string): string {
  if (/\d/.test(text)) throw new TypeError("אי אפשר לדחוס טקסט עם ספרות — לא יהיה אפשר לפתוח אותו");
  let out = "";
  let i = 0;
  while (i < text.length) {
    let j = i;
    while (j < text.length && text[j] === text[i]) j++;
    const run = j - i;
    out += run === 1 ? text[i] : `${text[i]}${run}`;
    i = j;
  }
  return out;
}

export function decompress(code: string): string {
  if (/\d/.test(code[0] ?? "")) throw new SyntaxError("קוד לא יכול להתחיל בספרה");
  let out = "";
  for (const [, ch, count] of code.matchAll(/(\D)(\d*)/g)) {
    if (count.startsWith("0")) throw new SyntaxError(`מספר לא תקין אחרי ${ch}: ${count}`);
    out += ch.repeat(count === "" ? 1 : Number(count));
  }
  return out;
}

const samples = ["aaabccdddd", "abc", "", "zzzzzzzzzzzz"];
for (const s of samples) {
  const c = compress(s);
  console.log(JSON.stringify(s), "→", JSON.stringify(c), "→", decompress(c) === s ? "✓" : "✗");
}
"aaabccdddd" → "a3bc2d4" → ✓
"abc" → "abc" → ✓
"" → "" → ✓
"zzzzzzzzzzzz" → "z12" → ✓

הנקודה העדינה היא \d* ולא \d: ‏z12 הוא z פעמיים־עשרה, ולא z, ‏1, ‏2. ולכן גם האיסור על ספרות בטקסט: ב־"a1" הדחיסה הייתה "a1", והפתיחה הייתה מחזירה "a". פורמט שאי אפשר לפענח בחזרה הוא באג, גם אם כל צד נראה תקין לבד.

על ביצועים: ‏out += ... בלולאה נשמע כמו O(n²), כי מחרוזות לא משתנות. בפועל V8 מחזיק "חבל" (rope) של חתיכות, ומחבר אותן פעם אחת בסוף. 200,000 תווים לוקחים כמה מילישניות. בראיון כדאי להזכיר שבשפות אחרות (Java) משתמשים ב־StringBuilder, וב־JavaScript אפשר מערך ו־join.

⚠️ טעויות נפוצות
  • /(\D)(\d)/g — רק ספרה אחת: ‏z12 נפתח ל־z ואחר כך 2.
  • להשוות כל תו לתו הקודם ולשכוח את הרצף האחרון אחרי הלולאה — ‏"aab" הופך ל־"a2".
  • Number("") הוא 0 — תו בלי מספר נעלם בפתיחה.
  • לכתוב 1 גם לרצף של תו אחד — עובד, אבל "abc" "נדחס" ל־"a1b1c1", כפול מהמקור.

// P27-E82: crossCheck — הפתרון המהיר מול הפשוט
export function findCounterexample<I, O>(fast: (input: I) => O, slow: (input: I) => O, generate: (rnd: () => number) => I, runs: number, seed = 1) {
  let s = seed >>> 0;
  const rnd = () => {
    s = (s * 1664525 + 1013904223) >>> 0;
    return s / 2 ** 32;
  };
  for (let r = 0; r < runs; r++) {
    const input = generate(rnd);
    const a = fast(structuredClone(input));
    const b = slow(structuredClone(input));
    if (JSON.stringify(a) !== JSON.stringify(b)) return { input, fast: a, slow: b };
  }
  return null;
}

זו הבדיקה שמצאה את רוב הבאגים בפתרונות של הפרק — "פלוס־מינוס אחד" בחיפוש בינארי, שוויון בחלון. מקרי קצה שלא חשבת עליהם, קלטים קטנים ואקראיים מוצאים לבד. (בשם המקצועי: property-based testing; ספרייה מוכרת — fast-check.)

⚠️ טעויות נפוצות

✅ פתרון
// P27-E83: groupBy עם generics
export function groupBy<T, K>(items: T[], keyOf: (item: T) => K): Map<K, T[]> {
  const out = new Map<K, T[]>();
  for (const item of items) {
    const k = keyOf(item);
    const list = out.get(k);
    if (list) list.push(item);
    else out.set(k, [item]);
  }
  return out;
}

export function countBy<T, K>(items: T[], keyOf: (item: T) => K): Map<K, number> {
  const out = new Map<K, number>();
  for (const item of items) {
    const k = keyOf(item);
    out.set(k, (out.get(k) ?? 0) + 1);
  }
  return out;
}

‏K מוסק מהפונקציה שהעברת — לכן Map עם המפתחות המדויקים. (מ־Node 21 יש גם Map.groupBy מובנה, שעושה בדיוק את זה.)

⚠️ טעויות נפוצות
  • להחזיר Record<string, T[]> — מפתחות מספריים הופכים למחרוזות, וסדר מספרי משתנה.
