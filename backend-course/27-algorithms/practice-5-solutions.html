💡 רמז 2

כל התשובות נמצאות בפרקים 14, 18, 21, 24 ובפרויקט 3. שיעור 5 מסכם.

✅ פתרון
  1. PUT מחליף את כל המשאב; PATCH משנה חלק. idempotent = לשלוח פעמיים זה כמו פעם אחת — PUT, DELETE ו־GET כן, POST לא. לכן ב־POST של הזמנה ותשלום אני דורש Idempotency-Key (פרק 24, פרויקט 3), ולעגלה השתמשתי ב־PUT /cart/items/:id — "הכמות היא 2", לא "תוסיף 1".
  2. כשיש שאילתה חוזרת שמסננת או ממיינת לפי עמודה בטבלה גדולה — ו־EXPLAIN ANALYZE מראה Seq Scan. המחיר: כל INSERT/UPDATE מעדכן גם את האינדקס, ומקום בדיסק. לא מוסיפים "ליתר ביטחון" (פרק 18).
  3. session — מזהה שהשרת שומר; קל לבטל. JWT — חתום, השרת לא שומר כלום; מהיר ומתאים לכמה שרתים, אבל אי אפשר "לבטל" טוקן לפני שפג. לכן: access token קצר (15 דק׳) ו־refresh token שנשמר במסד ואפשר לבטל (פרק 21).
  4. אצלי: UPDATE products SET stock = stock − 1 WHERE id = … AND stock >= 1, בתוך טרנזקציה, ובודקים כמה שורות עודכנו — המסד מסדר את שתי הבקשות, ורק אחת מצליחה. ועוד CHECK (stock >= 0) כרשת ביטחון. וידאתי בבדיקה עם 20 בקשות במקביל: גרסה נאיבית (SELECT ואז UPDATE) מכרה 12 יחידות מתוך 3.
  5. למדוד לפני שמנחשים: request ID בלוגים ← כמה זמן כל שלב; EXPLAIN ANALYZE לשאילתות; לחפש N+1. ואז, לפי הממצא: אינדקס, לתקן N+1, עימוד, ורק אחר כך cache (פרקים 18, 24, 26).

P27-E89 · סיסמאות עם scrypt ו־salt 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏randomBytes(16), ‏scryptSync(password, salt, 64), ‏.toString("hex").

💡 רמז 2

‏timingSafeEqual זורק כשהאורכים שונים — לבדוק אורך קודם.

✅ פתרון
// P27-E89: סיסמאות עם scrypt ו־salt
import { randomBytes, scryptSync, timingSafeEqual } from "node:crypto";

export function hashPassword(password: string): string {
  const salt = randomBytes(16);
  const hash = scryptSync(password, salt, 64);
  return `scrypt$${salt.toString("hex")}$${hash.toString("hex")}`;
}

export function verifyPassword(password: string, stored: string): boolean {
  const [kind, saltHex, hashHex] = stored.split("$");
  if (kind !== "scrypt" || !/^[0-9a-f]{32}$/.test(saltHex ?? "") || !/^[0-9a-f]{128}$/.test(hashHex ?? "")) return false;
  const expected = Buffer.from(hashHex, "hex");
  const actual = scryptSync(password, Buffer.from(saltHex, "hex"), 64);
  return actual.length === expected.length && timingSafeEqual(actual, expected);
}

ארבעת החלקים של התשובה בראיון יוצאים מהקוד: hash איטי בכוונה (scrypt/bcrypt/argon2) — כי ניחוש של מיליארד סיסמאות צריך להיות יקר; salt — כי שתי סיסמאות זהות לא ייראו זהות (ואין rainbow tables); השוואה בזמן קבוע; ואף פעם לא הצפנה הפיכה.

⚠️ טעויות נפוצות
  • ‏sha256(password) — מהיר מדי: GPU מנסה מיליארדים בשנייה.
  • actual.toString("hex") === hashHex — עובד, אבל ההשוואה עוצרת בתו הראשון שונה (timing).

P27-E90 · ‏ETag ו־304 ב־Express 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏const body = JSON.stringify(getProducts()), ‏createHash("sha1").update(body).digest("hex").

💡 רמז 2

‏res.status(304).end(), ואחרת res.type("json").send(body).

✅ פתרון
// P27-E90: ETag ו־304 ב־Express
import { createHash } from "node:crypto";
import express from "express";

export function catalogApp(getProducts: () => unknown) {
  const app = express();
  app.set("etag", false);
  app.get("/products", (req, res) => {
    const body = JSON.stringify(getProducts());
    const etag = `"${createHash("sha1").update(body).digest("hex")}"`;
    res.set({ ETag: etag, "Cache-Control": "no-cache" });
    if (req.headers["if-none-match"] === etag) return res.status(304).end();
    res.type("json").send(body);
  });
  return app;
}

304 חוסך את הגוף (רוחב פס, ופענוח בדפדפן), אבל לא את החישוב בשרת — עדיין בנינו את התשובה כדי לחשב hash. לכן משלבים: ‏ETag לרשת, ‏Redis (פרק 26) לחישוב. (Express מחשב ETag "חלש" לבד — כאן כיבינו כדי לבנות בעצמנו ולראות את המנגנון.)

⚠️ טעויות נפוצות
  • ETag בלי מירכאות — לפי התקן הוא חייב אותן, ודפדפנים/proxies עלולים לא לשלוח אותו בחזרה.
  • להחזיר 304 עם גוף.

P27-E91 · ‏cursor לעימוד: לקודד, לפענח, להמשיך 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏Buffer.from(JSON.stringify(c)).toString("base64url").

💡 רמז 2

"אחרי" ב־desc: הפריט הראשון שהוא (createdAt, ‏id) קטן ממש מה־cursor. ‏lowerBound עם פונקציית השוואה.

✅ פתרון
// P27-E91: cursor לעימוד — לקודד, לפענח, להמשיך
type Cursor = { createdAt: string; id: number };

export function encodeCursor(c: Cursor): string {
  return Buffer.from(JSON.stringify({ createdAt: c.createdAt, id: c.id })).toString("base64url");
}

export function decodeCursor(s: string): Cursor | null {
  if (!/^[A-Za-z0-9_-]+$/.test(s)) return null;
  try {
    const v = JSON.parse(Buffer.from(s, "base64url").toString("utf8"));
    if (typeof v?.createdAt !== "string" || !Number.isInteger(v?.id)) return null;
    return { createdAt: v.createdAt, id: v.id };
  } catch {
    return null;
  }
}

// האם a "אחרי" b בסדר יורד (createdAt, id)
const after = (a: Cursor, b: Cursor) => a.createdAt < b.createdAt || (a.createdAt === b.createdAt && a.id < b.id);

export function pageAfter<T extends Cursor>(sortedDesc: T[], cursor: string | null, limit: number) {
  let start = 0;
  const c = cursor === null ? null : decodeCursor(cursor);
  if (c) {
    let lo = 0;
    let hi = sortedDesc.length;
    while (lo < hi) {
      const mid = (lo + hi) >>> 1;
      if (after(sortedDesc[mid], c)) hi = mid;
      else lo = mid + 1;
    }
    start = lo;
  }
  const items = sortedDesc.slice(start, start + limit);
  const more = start + limit < sortedDesc.length;
  const last = items.at(-1);
  return { items, nextCursor: more && last ? encodeCursor(last) : null };
}

במסד זה:

WHERE (created_at, id) < ($1, $2) ORDER BY created_at DESC, id DESC LIMIT 20

— האינדקס עושה את "החיפוש הבינארי". ה־cursor אטום ללקוח (base64), כך שאפשר לשנות אותו בעתיד בלי לשבור לקוחות. ו־id בתוכו — כי שני פריטים באותה מילישנייה לא יכולים להיעלם בין עמודים.

⚠️ טעויות נפוצות
  • cursor רק עם createdAt — פריטים עם אותו זמן נעלמים או מוכפלים בין עמודים.
  • findIndex במקום חיפוש בינארי — O(n) לכל עמוד, בדיוק מה ש־keyset בא לחסוך.

// P27-E92: בוחר קוד סטטוס
type S = { authenticated: boolean; exists: boolean; owned: boolean; allowed: boolean; valid: boolean; conflict: boolean; rateLimited: boolean; created?: boolean };

export function chooseStatus(s: S): number {
  if (s.rateLimited) return 429; // לא מבזבזים עבודה (גם לא בדיקת טוקן) על מי שחרג
  if (!s.authenticated) return 401;
  if (!s.exists || !s.owned) return 404; // לא מגלים שקיים משאב של מישהו אחר
  if (!s.allowed) return 403;
  if (!s.valid) return 422;
  if (s.conflict) return 409;
  return s.created ? 201 : 200;
}

P27-E93 · ‏Idempotency-Key בזיכרון 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏Map<key, { hash, promise, at }> — שומרים את ה־Promise עצמו, כך שגם "בזמן ריצה" וגם "אחרי" מקבלים אותו.

💡 רמז 2

‏promise.catch(() => map.delete(key)) — כישלון מוחק.

✅ פתרון
// P27-E93: Idempotency-Key בזיכרון
import { createHash } from "node:crypto";

type Entry = { hash: string; promise: Promise<unknown>; at: number };

export function createIdempotency(ttlMs: number, now: () => number = Date.now) {
  const entries = new Map<string, Entry>();
  return {
    async run<T>(key: string, body: unknown, fn: () => Promise<T>) {
      const hash = createHash("sha256").update(JSON.stringify(body)).digest("hex");
      const e = entries.get(key);
      if (e && now() - e.at < ttlMs) {
        if (e.hash !== hash) throw new Error("KEY_REUSED");
        return { status: "replayed" as const, result: (await e.promise) as T };
      }
      const promise = fn();
      entries.set(key, { hash, promise, at: now() });
      promise.catch(() => {
        if (entries.get(key)?.promise === promise) entries.delete(key);
      });
      return { status: "fresh" as const, result: await promise };
    },
  };
}

שמירת ה־Promise (ולא רק התוצאה) פותרת את שני המקרים יחד: "כבר הסתיים" ו"עוד רץ". בפרודקשן זה במסד (‏UNIQUE על המפתח) או ב־Redis — כי שני השרתים צריכים לראות את אותו key; הלוגיקה זהה.

⚠️ טעויות נפוצות
  • לשמור רק אחרי ש־fn הסתיים — שתי בקשות במקביל מריצות פעמיים (התשלום הכפול שה־key נועד למנוע).

    if (Array.isArray(v)) {
      if (v.length === 0) throw new Error("מערך ריק ב־IN");
      text += v.map((x) => (params.push(x), `$${params.length}`)).join(", ");
    } else {
      params.push(v);
      text += `$${params.length}`;
    }
    text += strings[i + 1];
  });
  return { text, values: params };
}

זה בדיוק מה ש־$queryRaw של Prisma ו־tagged template בשם sql של ספריות כמו postgres.js עושים: התבנית נראית כמו שרשור, אבל הערכים נשלחים בנפרד מהטקסט, והמסד לא יכול לפרש אותם כ־SQL. (שמות טבלאות ועמודות לא יכולים להיות פרמטרים — אותם בודקים מול רשימה מותרת.)

⚠️ טעויות נפוצות
  • "לבצע escape למירכאות" — יש תמיד עוד מקרה (backslash, קידוד, מספרים בלי מירכאות). פרמטרים פותרים את כל המחלקה.

✅ פתרון
// P27-E95: heap — k הגדולים מתוך זרם
export class MinHeap {
  #a: number[] = [];

  get size() {
    return this.#a.length;
  }
  peek() {
    return this.#a[0];
  }
  push(x: number) {
    const a = this.#a;
    a.push(x);
    let i = a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (a[p] <= a[i]) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  pop() {
    const a = this.#a;
    if (a.length === 0) return undefined;
    const top = a[0];
    const last = a.pop()!;
    if (a.length) {
      a[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1;
        const r = l + 1;
        let m = i;
        if (l < a.length && a[l] < a[m]) m = l;
        if (r < a.length && a[r] < a[m]) m = r;
        if (m === i) break;
        [a[m], a[i]] = [a[i], a[m]];
        i = m;
      }
    }
    return top;
  }
}

export function topK(values: Iterable<number>, k: number): number[] {
  if (k <= 0) return [];
  const heap = new MinHeap();
  for (const x of values) {
    if (heap.size < k) heap.push(x);
    else if (x > heap.peek()!) {
      heap.pop();
      heap.push(x);
    }
  }
  const out: number[] = [];
  while (heap.size) out.push(heap.pop()!);
  return out.reverse();
}

‏O(n log k) עם k=10 הוא כמעט O(n), וזיכרון O(k) — אפשר להריץ על זרם שלא נכנס לזיכרון (שורות מקובץ, הודעות מ־Kafka). מיון מלא היה O(n log n) וזיכרון O(n). וזה "תור העדיפויות" של E57.

⚠️ טעויות נפוצות
  • max-heap של כל הערכים ו־k פעמים pop — נכון, אבל O(n) זיכרון.
  • ‏(i - 1) / 2 בלי עיגול — אינדקס שבור.

export function indexUsage(index: string[], query: { equals: string[]; range?: string; orderBy?: string }) {
  const eq = new Set(query.equals);
  let i = 0;
  while (i < index.length && eq.has(index[i])) i++;
  let columns = i;
  const next = index[i];
  if (next !== undefined && next === query.range) columns++;
  const sortFromIndex = query.orderBy !== undefined && next === query.orderBy;
  return { usable: columns > 0, columns, sortFromIndex };
}

// P27-E101: smoke test אחרי deploy
type Check = { path: string; status: number; contains?: string };

async function runCheck(baseUrl: string, c: Check, timeoutMs: number): Promise<string | null> {
  try {
    const res = await fetch(baseUrl + c.path, { signal: AbortSignal.timeout(timeoutMs) });
    const body = await res.text();
    if (res.status !== c.status) return `status ${res.status}`;
    if (c.contains !== undefined && !body.includes(c.contains)) return "missing text";
    return null;
  } catch (err) {
    return (err as Error).name === "TimeoutError" ? "timeout" : "network";
  }
}

export async function smokeTest(baseUrl: string, checks: Check[], timeoutMs: number) {
  const reasons = await Promise.all(checks.map((c) => runCheck(baseUrl, c, timeoutMs)));
  const failures = checks.flatMap((c, i) => (reasons[i] ? [{ path: c.path, reason: reasons[i]! }] : []));
  return { ok: failures.length === 0, failures };
}

בדיקת עשן לא מחליפה בדיקות — היא עונה על שאלה אחת: "הגרסה שעלתה עכשיו, בסביבה האמיתית, עונה?" (‏health, דף ראשי, endpoint אחד שנוגע במסד). נכשלה ← rollback אוטומטי, לפני שלקוח שם לב.

// P27-E102: p50, p95, p99 — לא ממוצע
export function percentiles(latencies: number[], ps: number[]) {
  for (const p of ps) if (!(p > 0 && p <= 100)) throw new RangeError(`p לא תקין: ${p}`);
  const sorted = Float64Array.from(latencies).sort();
  const n = sorted.length;
  const out: Record<string, number | null> = {};
  for (const p of ps) out[`p${p}`] = n === 0 ? null : sorted[Math.ceil((p / 100) * n) - 1];
  return out;
}

למה לא ממוצע: 99 בקשות של 20ms ובקשה אחת של 5 שניות — ממוצע 70ms ("בסדר"), ‏p99 — 5 שניות. ואחד מכל מאה לקוחות מחכה 5 שניות. ‏p95/p99 הם מה שמשתמשים מרגישים, ועליהם שמים התראות.
