P24-E06 · logger של JSON 🤖

רמה 2⏱ 20 דק׳ידע נדרש: שיעור 1

בקובץ 24-production/starter/P24-E06.ts כתוב createLogger({ level, sink, clock, base }):

  • מחזיר אובייקט עם debug, info, warn, error — כל אחת (msg, fields?).
  • כל קריאה ← קריאה אחת ל־sink עם מחרוזת JSON בשורה אחת: { ...base, ...fields, time, level, msg }. time — clock().toISOString().
  • שדות בשם time/level/msg ב־fields לא דורסים את האמיתיים.
  • רמה: ברירת מחדל info. מתחת לרמה — לא נכתב.
  • child(fields) ← logger חדש עם אותן הגדרות, ו־base מורחב.
  • ברירות מחדל: sink ← process.stdout.write(line + "\n"), clock ← new Date().

P24-E12 · חצות בישראל — באיזו שעה ב־UTC? 🤖

רמה 2⏱ 25 דק׳ידע נדרש: שיעור 2

הכיוון ההפוך: מתאריך ושעה מקומיים לרגע. בקובץ P24-E12.ts:

  • offsetMinutes(instant, tz) — ההפרש בדקות בין השעון באזור ל־UTC באותו רגע (ישראל: 120 בחורף, 180 בקיץ; ניו יורק בקיץ: −240).
  • zonedTimeToUtc(date, time, tz) — ("2026-11-05", "09:00", "Asia/Jerusalem") ← 2026-11-05T07:00:00.000Z. שעה שלא קיימת (קפיצה לשעון קיץ) ← קדימה, כמו השעון (02:30 ← 03:30). שעה כפולה (חזרה לחורף) ← המופע הראשון.
  • startOfDayInZone(date, tz) ו־dayRangeInZone(date, tz) ← { start, end }, כש־end הוא תחילת היום הבא (ביום מעבר — 23 או 25 שעות).

P24-E14 · מאגר של Idempotency-Key 🤖

רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P24-E14.ts כתוב את IdempotencyStore (בזיכרון) — new IdempotencyStore({ ttlMs, now }):

  • begin(scope, key, fingerprint) ← {kind:"new"} (נשמר "בטיפול") · {kind:"in_progress"} · {kind:"replay", response} · {kind:"mismatch"} (אותו מפתח, טביעה אחרת — גם בזמן טיפול).
  • complete(scope, key, response) — בלי begin ← Error("אין בקשה כזו בטיפול").
  • release(scope, key) — מוחק רק אם עדיין בטיפול.
  • תוקף: רשומה בת ttlMs ומעלה — כאילו לא קיימת. sweep() מוחק אותן ומחזיר כמה; size — getter.
  • ("a:b", "c") ו־("a", "b:c") — שתי רשומות שונות.

(שדות פרטיים עם #, לא constructor(private x) — Node מריץ TypeScript בלי קומפילציה, ו־parameter properties לא נתמכות.)

P24-E15 · middleware של Idempotency-Key 🤖

רמה 3⏱ 30 דק׳ידע נדרש: שיעור 3

בקובץ P24-E15.ts כתוב idempotency({ store, scope }) ל־Express. ה־store הוא בדיוק הממשק של E14 (הבודק מביא אחד משלו).

  • רק ל־POST עם header Idempotency-Key. אחרת — next() בלי לגעת במאגר.
  • מפתח לא תקין (/^[A-Za-z0-9_-]{8,100}$/) ← 400.
  • טביעה: sha256 של [method, path, body]. scope — ברירת מחדל x-user-id או "anonymous".
  • mismatch ← 422 · in_progress ← 409 · replay ← אותו status ו־body, עם Idempotent-Replayed: true.
  • new: עוטפים את res.json. תשובה < 500 ← complete. 5xx ← release. בקשה שנגמרת בלי res.json (חריגה, חיבור שנסגר) ← release.

P24-E17 · Token Bucket 🤖

רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

  • מתחיל מלא. מתמלא ברציפות (גם חלקי אסימון) — עד capacity, לא מעבר.

  • X-Request-Id כמו ב־E08, ושורת לוג JSON לכל בקשה דרך logSink: time (מה־clock), level לפי status, msg: "request", requestId, userId (אם יש), method, path בלי query, status, durationMs.

  • GET /health ← 200 תמיד. GET /ready ← 200, או 503 DRAINING כש־app.locals.draining.

  • GET /orders ← ההזמנות של המשתמש.
  • POST /orders { item, quantity } (item לא ריק, מקוצץ; quantity שלם 1–100; אחרת 400 VALIDATION_ERROR) ← 201 + Location, { id, userId, item, quantity, createdAt }.
    • Idempotency-Key חובה (400 IDEMPOTENCY_KEY_REQUIRED); replay עם Idempotent-Replayed; גוף אחר ← 422 IDEMPOTENCY_KEY_REUSED; בקשה לא תקינה לא "תופסת" את המפתח.
    • הגבלת קצב לכל משתמש: rateLimitPerMinute ב־60 שניות ← 429 TOO_MANY_REQUESTS עם Retry-After.

P24-E25 · אתגר: מתי התזכורת הבאה? 🤖

רמה 5⏱ 60 דק׳ידע נדרש: שיעור 2

בקובץ P24-E25.ts: nextRun({ hour, minute, days }, after, tz) ← הרגע הבא (אחרי after, לא כולל) שבו השעון באזור מראה hour:minute, ביום מותר (days: 0 = ראשון … 6 = שבת; בלי — כל יום). ו־upcoming(schedule, after, tz, count) ← מערך של הריצות הבאות.

  • "היום" ו"יום בשבוע" — לפי האזור, לא לפי UTC.
  • שעה שלא קיימת ← קדימה (02:30 ב־27.3 בישראל ← 03:30). שעה כפולה ← פעם אחת, במופע הראשון.
  • hour 0–23, minute 0–59, שלמים; days לא ריק, 0–6 ← אחרת RangeError.
