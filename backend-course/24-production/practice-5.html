P24-E97 · ‏logger של JSON בשביל Nest 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 20, שיעור 5

כמו AppLogger של הפרויקט — כך גם ההודעות של Nest עצמו יוצאות כ־JSON. בקובץ 24-production/starter/P24-E97.ts (יש בו רק הערה) כתוב וייצא class JsonLogger:

  • constructor({ sink, now, level }) — ‏sink(line), ‏now() מחזיר Date, ‏level מינימלי (‏debug/info/warn/error).
  • המתודות ש־Nest קורא להן: log(message, context?) ← info · warn(message, context?) ← warn · debug ו־verbose ← debug · fatal(message, context?) ← error · error(message, stack?, context?) ← error.
  • כל קריאה מעל הרמה ← sink עם שורת JSON: { time, level, msg, context?, stack? }. ‏context ו־stack — רק אם הם מחרוזות לא ריקות.
  • message שהוא Error ← ‏msg = ההודעה שלו, ו־stack שלו (אם לא הגיע stack בנפרד). מחרוזת ← כמו שהיא. כל דבר אחר ← JSON.stringify.

הבודק מחבר אותו ל־Nest: Logger.overrideLogger(new JsonLogger(...)), ואז new Logger("Tasks").log("hi") אמור להגיע אליך.

P24-E108 · ‏exception filter עם requestId 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 20, שיעור 5

בפרויקט, ב־500 הלקוח מקבל {"error":{"code":"INTERNAL",...}} — אבל בלי requestId בגוף (רק ב־header). בקובץ 24-production/starter/P24-E108.ts (יש בו רק הערה) כתוב וייצא class RequestIdErrorFilter (בלי decorators):

  • constructor(log) — ‏log(level, msg, fields), ‏level הוא "warn" או "error".
  • catch(exception, host) — ‏res = host.switchToHttp().getResponse(), ‏requestId = res.getHeader("X-Request-Id") ?? null (ה־middleware כבר קבע אותו).
  • HttpException ← אותו status, ‏{ error: { code, message: exception.message, requestId } }. ‏code: ‏400 BAD_REQUEST, ‏401 UNAUTHORIZED, ‏403 FORBIDDEN, ‏404 NOT_FOUND, ‏429 TOO_MANY_REQUESTS, אחרת ERROR. ‏log("warn", "http error", { status, requestId }) — רק ל־4xx.
  • כל דבר אחר ← 500, עם code: "INTERNAL" ו־message: "שגיאה פנימית" (ו־requestId), ו־log("error", "unhandled", { requestId, message }) — ההודעה של השגיאה רק בלוג.
