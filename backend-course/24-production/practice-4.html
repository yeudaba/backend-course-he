P24-E17 · Token Bucket 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

בקובץ P24-E17.ts כתוב new TokenBucket({ capacity, refillPerSecond, now }) עם take(cost = 1) ← { allowed, remaining, retryAfterSeconds }:

  • מתחיל מלא. מתמלא ברציפות (גם חלקי אסימון) — עד capacity, לא מעבר.
  • יש מספיק ← מוריד, allowed: true, retryAfterSeconds: 0. remaining — מעוגל למטה.
  • אין ← לא מוריד כלום, ו־retryAfterSeconds = הזמן עד שיהיה מספיק, מעוגל למעלה.
  • cost > capacity, או capacity/קצב לא חיוביים ← RangeError.

export function createFixedWindow(opts: { limit: number; windowMs: number; now: () => number }): {
  hit(key: string): { allowed: boolean; remaining: number; resetSeconds: number };

  sweep(): number;
}

P24-E32 · בדיקות ל־Retry-After 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 4

P24-E87 · הגבלה ל־login: לפי IP ולפי חשבון 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: פרק 21, שיעור 4

הגרסה של E77 (ג). בקובץ 24-production/starter/P24-E87.ts (יש בו רק הערה) כתוב וייצא:

type Rule = { limit: number; windowMs: number };
export function createLoginLimiter(opts: { now: () => number; perIp?: Rule; perEmail?: Rule }): {
  check(ip: string, email: string): { allowed: true } | { allowed: false; reason: "ip" | "email"; retryAfterSeconds: number };
  fail(email: string): void;
  succeed(email: string): void;
}
  • ברירות מחדל: perIp — ‏20 ב־60 שניות; ‏perEmail — ‏5 ב־15 דקות.
  • check רץ לפני בדיקת הסיסמה. בודקים קודם את ה־IP: אם יש כבר limit ניסיונות בחלון ← נדחה (reason: "ip"). אחר כך את החשבון: אם יש limit כישלונות בחלון ← נדחה ("email"). אם עבר — הניסיון נספר ל־IP. ניסיון שנדחה לא נספר.
  • fail(email) — רושם כישלון לחשבון. ‏succeed(email) — מאפס את הכישלונות שלו.
