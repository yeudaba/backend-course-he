P24-E89 · למה request-id נרשם ראשון? 🧠 הבנה רמה 2

‏express.json() שנכשל קורא ל־next(err) — ומדלג על כל ה־middlewares הרגילים שאחריו.

💡 רמז 2

שורת ה־request נכתבת ב־res.on("finish") — אבל רק אם ה־middleware שמאזין הספיק לרוץ.

✅ פתרון

💡 רמז 1

💡 רמז 2

מה אם ה־schema מתעלם בשקט משדה לא מוכר?

✅ פתרון

P24-E92 · ‏release אחרי DUE_DATE_IN_PAST 🧠 הבנה רמה 2

💡 רמז 1

‏release מוחק את המפתח רק אם הוא עדיין "בטיפול".

💡 רמז 2

קריסה = אף שורת קוד לא רצה, גם לא catch.

✅ פתרון
  1. המפתח שוחרר. הבקשה המתוקנת (תוכן אחר!) עם אותו מפתח — מתבצעת: 201. זה מה שה־frontend של הפרויקט עושה: המפתח נמחק רק אחרי הצלחה.
  2. הבקשה המתוקנת מקבלת 422 IDEMPOTENCY_KEY_REUSED (תוכן אחר). ה־frontend צריך לייצר מפתח חדש אחרי כל 4xx. גם זה עובד — אבל צריך לזכור.
  3. שוחרר ← הניסיון השני מתבצע. בדיוק בשביל זה המנגנון קיים.
  4. הרשומה נשארה "בטיפול" ← 409 IDEMPOTENCY_IN_PROGRESS, עד שהיא פגה (IDEMPOTENCY_TTL_HOURS, 24 שעות). זה החיסרון של TTL אחד לכל המצבים — ויש מערכות שנותנות ל"בטיפול" תוקף קצר בהרבה.
⚠️ טעויות נפוצות
  • לחשוב ש־release בתוך catch מכסה את כל המקרים — קריסה, SIGKILL ו־OOM לא עוברים דרך catch.

P24-E93 · ‏onModuleDestroy מול onApplicationShutdown 🧠 הבנה רמה 2

💡 רמז 1

הסדר של Nest: ‏onModuleDestroy ← סגירת שרת ה־HTTP ← onApplicationShutdown.

💡 רמז 2

בבדיקה, מתי נקרא app.close() ביחס לבקשות?

✅ פתרון
  1. עם onModuleDestroy — הלקוח קיבל 500: המסד נסגר כשהבקשה עוד הייתה צריכה אותו. עם onApplicationShutdown — 200, והמסד נסגר אחרי שהשרת סיים.
  2. בבדיקות, app.close() נקרא ב־afterAll, כשאין בקשות באמצע. הבאג מופיע רק כשיש תעבורה בזמן כיבוי — כלומר בכל deploy בפרודקשן.
  3. כל משאב שבקשות משתמשות בו: חיבור ל־Redis (פרק 26), לקוח של תור הודעות, ה־exporter של OpenTelemetry (שולח את מה שנשאר — שיעור 6). ו"השעון" של משימות רקע — לעצור אותן לפני, ולא לתת להן להתחיל עבודה חדשה.
⚠️ טעויות נפוצות
  • להעתיק onModuleDestroy ממדריך — רוב המדריכים כותבים אותו, ורובם לא בדקו כיבוי עם תעבורה.

P24-E94 · ‏x-request-id מחזיר null בדפדפן 🧠 הבנה רמה 2

💡 רמז 1

שני כיוונים: ה־headers שהדפדפן שולח (‏preflight, ‏Access-Control-Allow-Headers) וה־headers ש־JavaScript קורא מהתשובה (‏Access-Control-Expose-Headers).

💡 רמז 2

בלי allowedHeaders, ספריית cors (שמאחורי enableCors) מחזירה ב־preflight את מה שהדפדפן ביקש.

✅ פתרון
  1. הדפדפן מקבל את ה־header, אבל חושף ל־JavaScript של אתר אחר רק headers "בטוחים" (כמו Content-Type) — אלא אם השרת שלח Access-Control-Expose-Headers. בפרויקט — exposedHeaders עם שלושה: ‏X-Request-Id, ‏Retry-After ו־Idempotent-Replayed.
  2. header לא סטנדרטי גורם ל־preflight (‏OPTIONS עם Access-Control-Request-Headers שמפרט אותו). בלי allowedHeaders, ‏cors פשוט מחזיר את הרשימה שהתבקשה — לכן בפלט של השיעור ראינו ב־Access-Control-Allow-Headers את authorization,content-type,idempotency-key.
  3. ה־preflight נכשל (‏idempotency-key לא ברשימה), והדפדפן לא שולח את ה־POST בכלל. בקונסול: שגיאת CORS; בשרת — רק OPTIONS בלוג. מי שמגדיר allowedHeaders צריך לזכור להוסיף כל header חדש.
⚠️ טעויות נפוצות
  • origin: "*" "כדי שיעבוד" — זה לא קשור לבעיה, ופותח את ה־API לכל אתר (יחידה 15.5).

export function requestLogEntry(input: { method: string; originalUrl: string; status: number; durationMs: number; requestId: string; userId?: number }) {
  const path = input.originalUrl.split("?")[0];
  const { status } = input;

      path,

P24-E97 · ‏logger של JSON בשביל Nest 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏Nest קורא error(message, stack, context) — שלושה פרמטרים — וכל השאר עם שניים.

💡 רמז 2

מתודה פרטית אחת #write(level, message, context, stack), וכל המתודות הציבוריות קוראות לה.

✅ פתרון
// P24-E97: logger של JSON בשביל Nest
type Level = "debug" | "info" | "warn" | "error";
const ORDER: Record<Level, number> = { debug: 10, info: 20, warn: 30, error: 40 };

export class JsonLogger {
  #sink: (line: string) => void;
  #now: () => Date;
  #level: Level;

  constructor({ sink, now, level }: { sink: (line: string) => void; now: () => Date; level: Level }) {
    this.#sink = sink;
    this.#now = now;
    this.#level = level;
  }

  #write(level: Level, message: unknown, context?: unknown, stack?: unknown) {
    if (ORDER[level] < ORDER[this.#level]) return;
    const err = message instanceof Error ? message : undefined;
    const msg = err ? err.message : typeof message === "string" ? message : JSON.stringify(message);
    const st = typeof stack === "string" && stack ? stack : err?.stack;
    this.#sink(JSON.stringify({
      time: this.#now().toISOString(),
      level,
      msg,
      ...(typeof context === "string" && context ? { context } : {}),
      ...(st ? { stack: st } : {}),
    }));
  }

  log(message: unknown, context?: string) { this.#write("info", message, context); }
  warn(message: unknown, context?: string) { this.#write("warn", message, context); }
  debug(message: unknown, context?: string) { this.#write("debug", message, context); }
  verbose(message: unknown, context?: string) { this.#write("debug", message, context); }
  fatal(message: unknown, context?: string) { this.#write("error", message, context); }
  error(message: unknown, stack?: string, context?: string) { this.#write("error", message, context, stack); }
}

‏context הוא השם שהעברת ל־new Logger("Tasks") — כאן הוא הופך לשדה, ואפשר לסנן לפיו ("כל ההודעות של RoutesResolver").

⚠️ טעויות נפוצות
  • error(message, context) — עם שני פרמטרים, כמו האחרות. ‏Nest מעביר את ה־stack במקום השני, וה־stack נכתב כ־context.

P24-E99 · ‏reserve עם P2002 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1
for (let attempt = 0; attempt < 2; attempt++) { try { ...; return { kind: "new" } } catch (err) { if (code !== "P2002") throw err } ... }
💡 רמז 2

‏"פג תוקף":

row.createdAt.getTime() <= now.getTime() - ttlHours * 3_600_000
✅ פתרון
// P24-E99: reserve עם P2002
export type Row = { id: number; fingerprint: string; status: number | null; body: unknown; createdAt: Date };
export type Db = {
  create(data: { userId: number; key: string; fingerprint: string; createdAt: Date }): Promise<void>;
  findUnique(userId: number, key: string): Promise<Row | null>;
  deleteById(id: number): Promise<void>;
};
export type Reservation = { kind: "new" } | { kind: "in_progress" } | { kind: "mismatch" } | { kind: "replay"; status: number; body: unknown };

const isUniqueViolation = (err: unknown) => typeof err === "object" && err !== null && (err as { code?: unknown }).code === "P2002";

export async function reserve(db: Db, userId: number, key: string, fingerprint: string, now: Date, ttlHours: number): Promise<Reservation> {
  for (let attempt = 0; attempt < 2; attempt++) {
    try {
      await db.create({ userId, key, fingerprint, createdAt: now }); // האילוץ במסד מחליט מי "זוכה"
      return { kind: "new" };
    } catch (err) {
      if (!isUniqueViolation(err)) throw err; // תקלה אמיתית — לא "מישהו תפס"
    }
    const row = await db.findUnique(userId, key);
    if (!row) continue; // נמחק בין ה־create ל־find — עוד סיבוב
    if (row.createdAt.getTime() <= now.getTime() - ttlHours * 3_600_000) {
      await db.deleteById(row.id); // פג תוקף — כאילו לא קיים
      continue;
    }
    if (row.fingerprint !== fingerprint) return { kind: "mismatch" };
    if (row.status === null) return { kind: "in_progress" };
    return { kind: "replay", status: row.status, body: row.body };
  }
  return { kind: "in_progress" };
}

למה לכל היותר 2? כי כל סיבוב "נכשל" רק אם מישהו אחר שינה את השורה באמצע. אחרי שניים — הנחה סבירה שיש מרוץ פעיל, ו־409 אומר ללקוח לנסות שוב בעוד רגע.

⚠️ טעויות נפוצות
  • catch {} בלי לבדוק את הקוד — המסד לא זמין, וכל בקשה מקבלת "in_progress".
  • לולאה בלי גבול — שני תהליכים שמוחקים ויוצרים זה לזה יכולים להסתובב לנצח.

💡 רמז 2

✅ פתרון
// P24-E100: guard של הגבלת קצב ב־Nest
import { HttpException, type CanActivate, type ExecutionContext } from "@nestjs/common";

const WINDOW_MS = 60_000;

export class LoginRateLimitGuard implements CanActivate {
  #hits = new Map<string, number[]>();
  #limit: number;
  #clock: { now(): Date };

  constructor(limitPerMinute: number, clock: { now(): Date }) {
    this.#limit = limitPerMinute;
    this.#clock = clock;
  }

  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest<{ ip?: string }>();
    const res = context.switchToHttp().getResponse<{ setHeader(name: string, value: string): void }>();
    const now = this.#clock.now().getTime();
    const key = String(req.ip);
    const recent = (this.#hits.get(key) ?? []).filter((t) => t > now - WINDOW_MS);
    const blocked = recent.length >= this.#limit;
    if (!blocked) recent.push(now); // בקשה חסומה לא נספרת
    this.#hits.set(key, recent);
    const reset = String(Math.ceil((recent[0] + WINDOW_MS - now) / 1000));
    res.setHeader("RateLimit-Limit", String(this.#limit));
    res.setHeader("RateLimit-Remaining", String(this.#limit - recent.length));
    res.setHeader("RateLimit-Reset", reset);
    if (blocked) {
      res.setHeader("Retry-After", reset);
      throw new HttpException({ error: { code: "TOO_MANY_REQUESTS", message: `יותר מדי ניסיונות. נסה שוב בעוד ${reset} שניות` } }, 429);
    }
    return true;
  }
}

// P24-E101: request() של הדף — עם קוד לתמיכה
type Options = { method?: string; body?: string; headers?: Record<string, string> };

export function createApiClient({ fetchFn, base, getToken }: { fetchFn: typeof fetch; base: string; getToken: () => string | null }) {
  return async (path: string, options: Options = {}) => {
    const token = getToken();
    const headers = {
      ...(options.body ? { "Content-Type": "application/json" } : {}),
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...options.headers,
    };
    const res = await fetchFn(base + path, { ...options, headers });
    if (res.status === 204) return undefined;
    const data = (await res.json().catch(() => ({}))) as { error?: { message?: string } };
    if (!res.ok) {
      const message = data.error?.message ?? `HTTP ${res.status}`;
      throw new Error(res.status >= 500 ? `${message} · קוד לתמיכה: ${res.headers.get("x-request-id")}` : message);
    }
    return data;
  };
}

‏"קוד לתמיכה" רק ב־5xx: ב־4xx ההודעה מספיקה ("תאריך היעד עבר"), וזו בעיה שהמשתמש מתקן בעצמו. ב־5xx — זה הקוד שהתמיכה מחפשת בלוגים (E02).

⚠️ טעויות נפוצות

// P24-E102: מפתח אחד לטופס
export function createFormSubmitter<T>({ send, newKey }: { send: (body: unknown, key: string) => Promise<T>; newKey: () => string }) {
  let key: string | null = null;
  let pending: Promise<T> | null = null;
  return {
    submit(body: unknown): Promise<T> {
      if (pending) return pending; // לחיצה כפולה — אותה שליחה
      key ??= newKey();
      const k = key;
      pending = (async () => {
        try {
          const result = await send(body, k);
          key = null; // הצליח — הפעולה הבאה תקבל מפתח חדש
          return result;
        } finally {
          pending = null;
        }
      })();
      return pending;
    },
    currentKey: () => key,
  };
}

// P24-E106: בדיקת עשן ל־Idempotency-Key
export async function idempotencySmoke(base: string, token: string, key: string) {
  const post = async (body: unknown) => {
    const res = await fetch(`${base}/tasks`, {
      method: "POST",
      headers: { Authorization: `Bearer ${token}`, "Content-Type": "application/json", "Idempotency-Key": key },
      body: JSON.stringify(body),
    });
    const json = (await res.json().catch(() => null)) as { id?: unknown } | null;
    return { status: res.status, headers: res.headers, json };
  };
  const a = await post({ title: "smoke" });
  const b = await post({ title: "smoke" });
  const c = await post({ title: "smoke-2" });
  const replayed = b.headers.get("idempotent-replayed") === "true";
  const sameId = a.json?.id !== undefined && a.json.id === b.json?.id;
  const ok = a.status === 201 && b.status === 201 && replayed && sameId && c.status === 422;
  return { first: a.status, second: b.status, replayed, sameId, reused: c.status, ok };
}

// P24-E107: משימות באיחור — לפי האזור של כל משתמש
import type { Pool } from "pg";

export async function overdueByUser(pool: Pool, now: Date) {
  const { rows } = await pool.query(
    `SELECT u.id AS "userId",
            COUNT(t.id) FILTER (
              WHERE t.status <> 'done'
                AND t.due_date < ($1::timestamptz AT TIME ZONE u.time_zone)::date
            )::int AS overdue
       FROM users u
       LEFT JOIN tasks t ON t.owner_id = u.id
      GROUP BY u.id
      ORDER BY u.id`,
    [now],
  );
  return rows as { userId: number; overdue: number }[];
}

// P24-E108: exception filter עם requestId
import { HttpException, type ArgumentsHost, type ExceptionFilter } from "@nestjs/common";
import type { Response } from "express";

type Log = (level: "warn" | "error", msg: string, fields: Record<string, unknown>) => void;
const CODES: Record<number, string> = { 400: "BAD_REQUEST", 401: "UNAUTHORIZED", 403: "FORBIDDEN", 404: "NOT_FOUND", 429: "TOO_MANY_REQUESTS" };

export class RequestIdErrorFilter implements ExceptionFilter {
  #log: Log;
  constructor(log: Log) {
    this.#log = log;
  }

  catch(exception: unknown, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse<Response>();
    const requestId = res.getHeader("X-Request-Id") ?? null;
    if (exception instanceof HttpException) {
      const status = exception.getStatus();
      if (status < 500) this.#log("warn", "http error", { status, requestId });
      res.status(status).json({ error: { code: CODES[status] ?? "ERROR", message: exception.message, requestId } });
      return;
    }
    this.#log("error", "unhandled", { requestId, message: exception instanceof Error ? exception.message : String(exception) });
    res.status(500).json({ error: { code: "INTERNAL", message: "שגיאה פנימית", requestId } });
  }
}
