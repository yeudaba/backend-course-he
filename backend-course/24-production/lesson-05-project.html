2. לוגים

src/common/request-id.middleware.ts 
export function requestIdMiddleware(logger: AppLogger) {
  return (req: Request, res: Response, next: NextFunction) => {
    const incoming = req.get("x-request-id");
    const requestId = incoming && VALID_ID.test(incoming) ? incoming : randomUUID();
    res.setHeader("X-Request-Id", requestId);
    const started = performance.now();
    const context = { requestId } as { requestId: string; userId?: number };

    res.on("finish", () => {
      const status = res.statusCode;
      const path = req.originalUrl.split("?")[0];
      // healthcheck של Docker מגיע כל 5 שניות — בהצלחה הוא רק רעש, אז debug
      const level = status >= 500 ? "error" : status >= 400 ? "warn" : path === "/health" ? "debug" : "info";
      const userId = (req as Request & { user?: { id: number } }).user?.id;
      requestContext.run({ ...context, ...(userId ? { userId } : {}) }, () =>
        logger.write(level, "request", { method: req.method, path, status, durationMs: Math.round(performance.now() - started) }),
      );
    });

    requestContext.run(context, next);
  };
}
  • configureApp רושם אותו ראשון (app.use) — לפני ה־body parser, כדי שגם JSON שבור יקבל requestId.
  • JwtAuthGuard, אחרי שאימת את הטוקן: currentRequest().userId = req.user.id — ומאותו רגע כל שורת לוג בבקשה כוללת אותו.
  • main.ts: NestFactory.create(AppModule, { bufferLogs: true }) ו־app.useLogger(app.get(AppLogger)) — גם ההודעות של Nest עצמו יוצאות כ־JSON.
  • בבדיקות — LOG_SINK מוחלף במערך, וה־JSON נבדק ישירות.

3. אזור זמן

ב־schema: timeZone String @default("UTC") @map("time_zone"). ב־zod של הרשמה: timeZone: z.string().refine(isValidTimeZone).default("UTC"), ו־PATCH /auth/me עם z.strictObject({ timeZone }) — רק השדה הזה. ב־TasksService, במקום "היום של השרת":

private async todayFor(ownerId: number) {
  const user = await this.users.findById(ownerId);
  return localDate(this.now(), user?.timeZone ?? "UTC");
}

לכן TasksModule מייבא את AuthModule (שמייצא את USERS_REPOSITORY), והבנאי של TasksService מקבל עוד פרמטר. הבדיקות משלב ה׳ צריכות עדכון קטן — וזה בדיוק מה שהן אמורות לעשות: לשבור כשמשהו משתנה.

4. Idempotency-Key

prisma/migrations/…_production_features/migration.sql 
ALTER TABLE "users" ADD COLUMN     "time_zone" TEXT NOT NULL DEFAULT 'UTC';

CREATE TABLE "idempotency_keys" (
    "id" SERIAL NOT NULL,
    "user_id" INTEGER NOT NULL,
    "key" TEXT NOT NULL,
    "fingerprint" TEXT NOT NULL,
    "status" INTEGER,
    "body" JSONB,
    "created_at" TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT "idempotency_keys_pkey" PRIMARY KEY ("id")
);
CREATE UNIQUE INDEX "idempotency_keys_user_id_key_key" ON "idempotency_keys"("user_id", "key");

(נוצר עם npx prisma migrate dev --name production_features, מקוצר.) status ריק = "בטיפול". ה־UNIQUE על (user_id, key) הוא מה שמבטיח שרק בקשה אחת "זוכה" — PrismaIdempotencyRepository.reserve מנסה create, ועל P2002 קורא את השורה הקיימת: טביעה אחרת ← mismatch; status ריק ← in_progress; אחרת ← replay. מפתח שפג תוקפו — נמחק ומנסים שוב.

src/tasks/tasks.controller.ts 
@Post()
@ApiHeader({ name: "Idempotency-Key", required: false, description: "אותו מפתח שוב ← אותה תשובה, בלי משימה כפולה" })
async create(
  @CurrentUser() user: AuthUser,
  @Body(new ZodValidationPipe(createTaskSchema)) body: CreateTaskInput,
  @Res({ passthrough: true }) res: Response,
  @Headers("idempotency-key") key?: string,
) {
  const create = () => this.tasks.create(user.id, body);
  const { replayed, body: task } = key === undefined ? { replayed: false, body: await create() } : await this.idempotency.run(user.id, key, body, create);
  if (replayed) res.setHeader("Idempotent-Replayed", "true");
  res.location(`/tasks/${task.id}`);
  return task;
}

הטביעה מחושבת מה־body אחרי ה־ZodValidationPipe — כלומר אחרי trim וברירות מחדל. {"title":" חלב "} ו־{"title":"חלב"} הן אותה בקשה. ו־IdempotencyService.run: הצלחה ← complete(201, task); שגיאה (למשל DUE_DATE_IN_PAST) ← release, והלקוח יכול לתקן ולשלוח עם אותו מפתח.

⚠️ CORS

הדף ב־5500 שולח header חדש (Idempotency-Key) — הדפדפן שואל קודם ב־preflight, ו־enableCors מאשר (פלט אמיתי: Access-Control-Allow-Headers: authorization,content-type,idempotency-key). והכיוון ההפוך: כדי ש־JavaScript יוכל לקרוא X-Request-Id ו־Retry-After מהתשובה, צריך exposedHeaders — בלעדיו res.headers.get("x-request-id") מחזיר null.

5. הגבלת קצב וכיבוי

AuthRateLimitGuard — חלון נע של 60 שניות לכל req.ip, @UseGuards על register ו־login (ולא על refresh: שם כבר צריך טוקן תקף). TRUST_PROXY ב־env — מספר ה־proxies שלפני השרת; בלי — X-Forwarded-For לא נחשב. ו־PrismaService סוגר את המסד ב־onApplicationShutdown. בפועל (פלט אמיתי): docker compose stop api הסתיים ב־0.24 שניות — Node קיבל SIGTERM וסגר יפה, ולא חיכה 10 שניות ל־SIGKILL.
