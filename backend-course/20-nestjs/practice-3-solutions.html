💡 רמז 2

✅ פתרון

(א) Nest ניסה ליצור את OrdersService; הרשימה בסוגריים היא הפרמטרים של ה־constructor, וה־? מסמן את זה שלא נמצא — הראשון (index [0]), מסוג UsersService. הוא חיפש אותו בהקשר של OrdersModule.

P20-E04 · מי רץ ומתי 🧠 הבנה רמה 1

💡 רמז 1

האיור בשיעור 3: middleware ← guards ← interceptors (לפני) ← pipes ← handler ← interceptors (אחרי). שגיאה — ישר ל־filters.

💡 רמז 2

חלק ה"אחרי" של interceptor עם tap רץ רק כשה־handler הצליח.

✅ פתרון
  1. middleware ← guard (מאשר) ← interceptor (לפני) ← ParseIntPipe ← handler ← interceptor (אחרי) ← תשובה. ה־filter לא רץ.
  2. middleware ← guard זורק UnauthorizedException ← filter ← 401. interceptor, pipe ו־handler לא רצים.
  3. middleware ← guard ← interceptor (לפני) ← ParseIntPipe זורק 400 ← filter. ה־handler לא רץ, וגם ה־tap של ה־interceptor לא (אין ערך מוצלח).
  4. הכול עד ה־handler ← הוא זורק ← filter ← 404.

למה זה חשוב: guard הוא המקום לבדיקת הרשאה — כי שום קוד שלך (ואפילו לא ולידציה) לא רץ לפני שהוא אישר.

⚠️ טעויות נפוצות
  • לשים בדיקת הרשאה בתוך ה־handler — היא רצה מאוחר מדי, אחרי pipes שיכולים לגשת למסד.
  • לחשוב ש־middleware רץ אחרי guards — הפוך.

P20-E11 · שעון כ־provider 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

getUTCHours(), לא getHours() — אחרת התוצאה תלויה באזור הזמן של המחשב.

💡 רמז 2

אם לא כתבת @Inject(CLOCK): Clock הוא interface, ו־Nest לא יודע מה להזריק.

✅ פתרון
// P20-E11
import { Controller, Get, Inject, Injectable, Module } from "@nestjs/common";

export const CLOCK = "CLOCK";
export interface Clock {
  now(): Date;
}

@Injectable()
export class GreetingService {
  constructor(@Inject(CLOCK) private readonly clock: Clock) {}

  greeting(): string {
    const hour = this.clock.now().getUTCHours();
    if (hour >= 5 && hour < 12) return "בוקר טוב";
    if (hour >= 12 && hour < 17) return "צהריים טובים";
    if (hour >= 17 && hour < 21) return "ערב טוב";
    return "לילה טוב";
  }
}

@Controller("greeting")
export class GreetingController {
  constructor(private readonly greetings: GreetingService) {}

  @Get()
  get() {
    return { greeting: this.greetings.greeting() };
  }
}

@Module({
  controllers: [GreetingController],
  providers: [GreetingService, { provide: CLOCK, useValue: { now: () => new Date() } }],
})
export class GreetingModule {}

זה אותו רעיון כמו now ב־createApp({ now }) של פרויקט 2 — רק ש־Nest מנהל את ההחלפה. קוד שתלוי בזמן אף פעם לא קורא ל־new Date() ישירות: בבדיקה אי אפשר לקבוע מה השעה.

⚠️ טעויות נפוצות
  • hour <= 12 במקום < 12 ← 12:00 יוצא "בוקר טוב".
  • לקרוא ל־now() פעם אחת ב־constructor ← השעה "קפואה" מרגע עליית השרת.

P20-E12 · מבנה שגיאות אחיד 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

exception.getResponse() מחזיר את מה שהועבר ל־constructor של ה־exception — מחרוזת או אובייקט.

💡 רמז 2

ב־exceptionFactory מקבלים ValidationError[]: e.property הוא שם השדה, e.constraints — אובייקט של הודעות.

✅ פתרון
// P20-E12
import {
  ArgumentsHost, BadRequestException, Body, Catch, Controller, ExceptionFilter, Get, HttpException,
  Module, NotFoundException, Param, ParseIntPipe, Post, ValidationPipe, type ValidationError,
} from "@nestjs/common";
import { IsString, Length } from "class-validator";
import type { Response } from "express";

const CODES: Record<number, string> = { 400: "BAD_REQUEST", 401: "UNAUTHORIZED", 403: "FORBIDDEN", 404: "NOT_FOUND", 409: "CONFLICT" };

@Catch(HttpException)
export class ApiExceptionFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse<Response>();
    const status = exception.getStatus();
    const body = exception.getResponse();
    // אם מי שזרק כבר נתן code (למשל ה־exceptionFactory למטה) — משתמשים בו
    if (typeof body === "object" && body !== null && "code" in body) {
      res.status(status).json({ error: body });
      return;
    }
    res.status(status).json({ error: { code: CODES[status] ?? "ERROR", message: exception.message } });
  }
}

export function validationPipe() {
  return new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
    transform: true,
    exceptionFactory: (errors: ValidationError[]) =>
      new BadRequestException({
        code: "VALIDATION_ERROR",
        message: "קלט לא תקין",
        details: errors.map((e) => ({ field: e.property, messages: Object.values(e.constraints ?? {}) })),
      }),
  });
}

export class CreateItemDto {
  @IsString()
  @Length(1, 50)
  name: string;
}

@Controller("items")
export class ItemsController {
  private readonly items: { id: number; name: string }[] = [];

  @Post()
  create(@Body() dto: CreateItemDto) {
    const item = { id: this.items.length + 1, name: dto.name };
    this.items.push(item);
    return item;
  }

  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    const item = this.items.find((i) => i.id === id);
    if (!item) throw new NotFoundException(`פריט ${id} לא נמצא`);
    return item;
  }
}

@Module({ controllers: [ItemsController] })
export class ItemsModule {}

ה־404 של "כתובת לא קיימת" הוא גם NotFoundException שהמסגרת זורקת — ולכן גם הוא עובר דרך ה־filter, בלי שום קוד נוסף. וה־exceptionFactory הוא המקום היחיד שבו ההודעות של class-validator הופכות ל־details — כך הלקוח (הדף מיחידה 15.5) יכול להציג שגיאה ליד כל שדה.

⚠️ טעויות נפוצות
  • לשכוח res.status(status) ← כל השגיאות יוצאות 200 (תראה את זה ב־E22).
  • לעטוף פעמיים: { error: { error: {...} } } כשה־exception כבר מכיל code.
  • @Catch() בלי פרמטר תופס גם שגיאות שאינן HTTP — ואז getStatus לא קיים. כאן ביקשנו רק HttpException.

P20-E13 · modules שמדברים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

זה E03, בכתיבה.

💡 רמז 2

שני שינויים מעבר לקוד החדש: exports: [UsersService] ב־UsersModule, ו־imports: [UsersModule] ב־OrdersModule (ובנוסף OrdersModule ב־imports של AppModule).

✅ פתרון
// P20-E13
import { Body, Controller, Get, Injectable, Module, NotFoundException, Param, ParseIntPipe, Post } from "@nestjs/common";

export interface User {
  id: number;
  name: string;
}

@Injectable()
export class UsersService {
  private readonly users: User[] = [
    { id: 1, name: "Dana" },
    { id: 2, name: "Yossi" },
  ];

  findById(id: number): User {
    const user = this.users.find((u) => u.id === id);
    if (!user) throw new NotFoundException(`משתמש ${id} לא נמצא`);
    return user;
  }
}

@Controller("users")
export class UsersController {
  constructor(private readonly users: UsersService) {}

  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    return this.users.findById(id);
  }
}

@Module({ controllers: [UsersController], providers: [UsersService], exports: [UsersService] })
export class UsersModule {}

export interface Order {
  id: number;
  item: string;
  user: User;
}

@Injectable()
export class OrdersService {
  private readonly orders: Order[] = [];

  constructor(private readonly users: UsersService) {}

  create(userId: number, item: string): Order {
    const user = this.users.findById(userId); // 404 אם אין משתמש כזה
    const order = { id: this.orders.length + 1, item, user };
    this.orders.push(order);
    return order;
  }
}

@Controller("orders")
export class OrdersController {
  constructor(private readonly orders: OrdersService) {}

  @Post()
  create(@Body() body: { userId: number; item: string }) {
    return this.orders.create(body.userId, body.item);
  }
}

@Module({ imports: [UsersModule], controllers: [OrdersController], providers: [OrdersService] })
export class OrdersModule {}

@Module({ imports: [UsersModule, OrdersModule] })
export class AppModule {}

ב־AppModule יש מופע אחד של UsersService — גם ה־UsersController וגם OrdersService מקבלים אותו. module שמיובא פעמיים (פעם ב־AppModule ופעם ב־OrdersModule) נוצר פעם אחת. בפרויקט אמיתי זה ההבדל בין חיבור אחד למסד לבין עשרה.

⚠️ טעויות נפוצות
  • להוסיף את UsersService ל־providers של OrdersModule — "עובד", אבל עם עותק נפרד של המשתמשים.
  • לשכוח את OrdersModule ב־imports של AppModule ← POST /orders מחזיר 404.

P20-E14 · guard של מפתח API 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

הקוד בשיעור 3 כמעט מוכן. מה שנשאר: לרשום ב־module, ולהחליט איפה לשים @UseGuards.

💡 רמז 2

@UseGuards(ApiKeyGuard) על המתודה secret בלבד — לא על כל ה־controller.

✅ פתרון
// P20-E14
import {
  CanActivate, Controller, ExecutionContext, ForbiddenException, Get, Inject, Injectable, Module,
  UnauthorizedException, UseGuards,
} from "@nestjs/common";
import type { Request } from "express";

export const API_KEYS = "API_KEYS";

@Injectable()
export class ApiKeyGuard implements CanActivate {
  constructor(@Inject(API_KEYS) private readonly keys: Set<string>) {}

  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest<Request>();
    const key = req.get("x-api-key");
    if (!key) throw new UnauthorizedException("חסר X-Api-Key");
    if (!this.keys.has(key)) throw new ForbiddenException("מפתח לא מוכר");
    return true;
  }
}

@Controller()
export class SecretController {
  @Get("public")
  public() {
    return { ok: true };
  }

  @Get("secret")
  @UseGuards(ApiKeyGuard)
  secret() {
    return { secret: 42 };
  }
}

@Module({
  controllers: [SecretController],
  providers: [ApiKeyGuard, { provide: API_KEYS, useValue: new Set(["dev-key"]) }],
})
export class SecretModule {}

למה המפתחות ב־provider ולא const KEYS = new Set([...]) בקובץ? כי ככה הבדיקה מחליפה אותם, ובפרודקשן הם יגיעו מ־CONFIG (E17) — מה־env, לא מהקוד. ולמה 401 מול 403: 401 — "לא אמרת מי אתה"; 403 — "אמרת, ואין לך הרשאה". תראה את זה שוב בפרק 21 עם JWT.

⚠️ טעויות נפוצות
  • return false במקום לזרוק ← Nest מחזיר 403 עם הודעה כללית, ואי אפשר להבדיל בין "חסר" ל"שגוי".
  • req.headers["X-Api-Key"] — ב־Node שמות headers באותיות קטנות. req.get() לא תלוי באותיות.

P20-E15 · interceptor של זמנים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

intercept(context, next): מה שלפני next.handle() רץ לפני ה־handler. next.handle() מחזיר Observable, ו־.pipe(tap(() => ...)) רץ אחרי.

💡 רמז 2

context.switchToHttp().getResponse() ← res.setHeader(...). ה־status כבר קבוע ב־res.statusCode.

✅ פתרון
// P20-E15
import { CallHandler, Controller, ExecutionContext, Get, Inject, Injectable, Module, NestInterceptor } from "@nestjs/common";
import { APP_INTERCEPTOR } from "@nestjs/core";
import type { Request, Response } from "express";
import { Observable, tap } from "rxjs";

export const LOGGER = "LOGGER";
export interface Logger {
  log(line: string): void;
}

@Injectable()
export class TimingInterceptor implements NestInterceptor {
  constructor(@Inject(LOGGER) private readonly logger: Logger) {}

  intercept(context: ExecutionContext, next: CallHandler): Observable<unknown> {
    const start = Date.now();
    const http = context.switchToHttp();
    const req = http.getRequest<Request>();
    const res = http.getResponse<Response>();
    return next.handle().pipe(
      tap(() => {
        // רץ אחרי ה־handler, לפני ש־Nest שולח את התשובה — לכן עוד אפשר להוסיף header
        const ms = Date.now() - start;
        res.setHeader("X-Response-Time", `${ms}ms`);
        this.logger.log(`${req.method} ${req.originalUrl} ${res.statusCode} ${ms}ms`);
      }),
    );
  }
}

@Controller()
export class PingController {
  @Get("ping")
  ping() {
    return { pong: true };
  }

  @Get("slow")
  async slow() {
    await new Promise((resolve) => setTimeout(resolve, 60));
    return { done: true };
  }
}

@Module({
  controllers: [PingController],
  providers: [
    { provide: LOGGER, useValue: console },
    { provide: APP_INTERCEPTOR, useClass: TimingInterceptor },
  ],
})
export class PingModule {}

למה APP_INTERCEPTOR ולא app.useGlobalInterceptors(new TimingInterceptor(...)) ב־main.ts? כי ב־main.ts אין DI — היית צריך ליצור את ה־logger ידנית. דרך ה־module, Nest מזריק את LOGGER, והבדיקה יכולה להחליף אותו. ולמה אפשר עוד לשים header ב־tap? Nest שולח את התשובה רק אחרי שכל ה־interceptors סיימו.

⚠️ טעויות נפוצות
  • למדוד ב־tap בלי לשמור start לפני next.handle() ← תמיד 0ms.
  • req.url מול req.originalUrl: כאן זה אותו דבר, אבל עם routers מקוננים רק originalUrl מלא.

P20-E17 · הגדרות עם useFactory 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

{ provide: CONFIG, useFactory: (env) => loadConfig(env), inject: [ENV] } — inject אומר ל־Nest מה להעביר לפונקציה.

💡 רמז 2

Zod 4: .default() מקבל ערך מהפלט. אז ל־DEBUG: z.enum(["true","false"]).transform(v => v === "true").default(false).

✅ פתרון
// P20-E17
import { Controller, Get, Inject, Module } from "@nestjs/common";
import { z } from "zod";

export const ENV = "ENV";
export const CONFIG = "CONFIG";

export const configSchema = z.object({
  APP_NAME: z.string().min(1),
  PORT: z.coerce.number().int().min(1).max(65535).default(3000),
  DEBUG: z.enum(["true", "false"]).transform((v) => v === "true").default(false),
});
export type Config = z.infer<typeof configSchema>;

export function loadConfig(env: Record<string, string | undefined>): Config {
  const result = configSchema.safeParse(env);
  if (!result.success) {
    const problems = result.error.issues.map((i) => `${i.path.join(".")}: ${i.message}`).join("; ");
    throw new Error(`הגדרות לא תקינות — ${problems}`);
  }
  return result.data;
}

@Controller("info")
export class InfoController {
  constructor(@Inject(CONFIG) private readonly config: Config) {}

  @Get()
  info() {
    return { name: this.config.APP_NAME, port: this.config.PORT, debug: this.config.DEBUG };
  }
}

@Module({
  controllers: [InfoController],
  providers: [
    { provide: ENV, useValue: process.env },
    { provide: CONFIG, useFactory: (env: Record<string, string | undefined>) => loadConfig(env), inject: [ENV] },
  ],
})
export class ConfigModule {}

למה זה חשוב: שרת עם PORT=abc לא אמור לעלות "בערך" ולהיכשל אחרי שעה בבקשה הראשונה. הוא צריך ליפול מיד, עם הודעה שאומרת מה חסר. בדוק בעצמך: loadConfig({ PORT: "abc" }) זורק עם APP_NAME: Invalid input: expected string, received undefined ו־PORT: Invalid input: expected number, received NaN. ו־ENV כ־token — כדי שהבדיקה לא תצטרך לגעת ב־process.env האמיתי.

⚠️ טעויות נפוצות
  • z.coerce.boolean() ל־DEBUG ← "false" הופך ל־true (כי Boolean("false") הוא true — מחרוזת לא ריקה).
  • z.number() בלי coerce ← כל ערך מה־env נכשל, כי ב־env הכול מחרוזת.

P20-E18 · repository דרך token 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

זה ה־TASKS_REPOSITORY של פרויקט 2, בקטן.

💡 רמז 2

ה־service מכיר רק את ה־interface. אם כתבת בו new InMemoryNotesRepository() — הבדיקה לא תוכל להחליף.

✅ פתרון
// P20-E18
import { Body, Controller, Get, Inject, Injectable, Module, Post } from "@nestjs/common";
import { IsString, Length } from "class-validator";

export interface Note {
  id: number;
  text: string;
}

export interface NotesRepository {
  list(): Promise<Note[]>;
  add(text: string): Promise<Note>;
}

export const NOTES_REPOSITORY = "NOTES_REPOSITORY";

export class InMemoryNotesRepository implements NotesRepository {
  private readonly notes: Note[] = [];

  async list() {
    return this.notes;
  }

  async add(text: string) {
    const note = { id: this.notes.length + 1, text };
    this.notes.push(note);
    return note;
  }
}

export class CreateNoteDto {
  @IsString()
  @Length(1, 500)
  text: string;
}

@Injectable()
export class NotesService {
  constructor(@Inject(NOTES_REPOSITORY) private readonly repo: NotesRepository) {}

  list() {
    return this.repo.list();
  }

  add(text: string) {
    return this.repo.add(text.trim());
  }
}

@Controller("notes")
export class NotesController {
  constructor(private readonly notes: NotesService) {}

  @Get()
  list() {
    return this.notes.list();
  }

  @Post()
  add(@Body() dto: CreateNoteDto) {
    return this.notes.add(dto.text);
  }
}

@Module({
  controllers: [NotesController],
  providers: [NotesService, { provide: NOTES_REPOSITORY, useClass: InMemoryNotesRepository }],
})
export class NotesModule {}

זו הסיבה שבגללה עשינו את כל זה: מחר PrismaNotesRepository נכנס ב־useClass, וה־service, ה־controller והבדיקות לא משתנים. בפרויקט 2 בדיוק ככה הבודק מריץ את ה־API שלך בלי מסד.

⚠️ טעויות נפוצות
  • constructor(private readonly repo: NotesRepository) בלי @Inject ← Nest לא יודע מה להזריק (interface נמחק — E05).
  • לנקות רווחים ב־controller ← ה־fake יקבל טקסט עם רווחים. כללים עסקיים — ב־service.

import {
  ArgumentsHost, Catch, Controller, ExceptionFilter, Get, HttpException, Injectable, Module,
  NotFoundException, Param, ParseIntPipe,
} from "@nestjs/common";
import { APP_FILTER } from "@nestjs/core";
import type { Response } from "express";

@Catch(HttpException) // ← תקלה 3: היה @Catch(NotFoundException), אז ה־400 של ParseIntPipe יצא במבנה של Nest
export class ApiExceptionFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse<Response>();
    const status = exception.getStatus();
    const code = status === 404 ? "NOT_FOUND" : status === 400 ? "BAD_REQUEST" : "ERROR";
    res.status(status).json({ error: { code, message: exception.message } }); // ← תקלה 2: בלי status — 200
  }
}

export class OrdersService {

    { id: 1, item: "Espresso cup" },

    return order;
  }
}

✅ פתרון
// P20-E25
import {
  CanActivate, Controller, ExecutionContext, Get, HttpException, HttpStatus, Inject, Injectable, Module, UseGuards,
} from "@nestjs/common";
import type { Request, Response } from "express";

export const CLOCK = "CLOCK";
export const RATE_LIMIT = "RATE_LIMIT";
export interface Clock {
  now(): Date;
}
export interface RateLimitOptions {
  limit: number; // כמה בקשות מותר בחלון
  windowMs: number; // אורך החלון
}

@Injectable()
export class RateLimitGuard implements CanActivate {
  // לכל לקוח: מתי התחיל החלון שלו, וכמה בקשות היו בו
  private readonly windows = new Map<string, { start: number; count: number }>();

  constructor(
    @Inject(RATE_LIMIT) private readonly options: RateLimitOptions,
    @Inject(CLOCK) private readonly clock: Clock,
  ) {}

  canActivate(context: ExecutionContext): boolean {
    const http = context.switchToHttp();
    const req = http.getRequest<Request>();
    const res = http.getResponse<Response>();
    const key = req.get("x-client-id") ?? req.ip ?? "unknown";
    const now = this.clock.now().getTime();

    let w = this.windows.get(key);
    if (!w || now >= w.start + this.options.windowMs) {
      w = { start: now, count: 0 };
      this.windows.set(key, w);
    }
    if (w.count >= this.options.limit) {
      const seconds = Math.ceil((w.start + this.options.windowMs - now) / 1000);
      res.setHeader("Retry-After", String(seconds)); // לפני ה־throw: ה־header נשאר על ה־response
      throw new HttpException({ error: { code: "RATE_LIMITED", message: "יותר מדי בקשות — נסה שוב מאוחר יותר" } }, HttpStatus.TOO_MANY_REQUESTS);
    }
    w.count++;
    res.setHeader("X-RateLimit-Remaining", String(this.options.limit - w.count));
    return true;
  }
}

@Controller("data")
@UseGuards(RateLimitGuard)
export class DataController {
  @Get()
  get() {
    return { data: [1, 2, 3] };
  }
}

@Module({
  controllers: [DataController],
  providers: [
    RateLimitGuard,
    { provide: RATE_LIMIT, useValue: { limit: 5, windowMs: 60_000 } },
    { provide: CLOCK, useValue: { now: () => new Date() } },
  ],
})
export class DataModule {}

זה אלגוריתם "חלון קבוע" — הפשוט מכולם, עם חיסרון ידוע: 3 בקשות ב־10:00:09.9 ועוד 3 ב־10:00:10.0 ← 6 בשנייה אחת. בפרק 24 נכיר "חלון נע" ו־token bucket, ובפרק 26 נשמור את המונים ב־Redis — כי כשיש שני שרתים, Map בזיכרון של כל אחד לא מספיק.

⚠️ טעויות נפוצות
  • Math.round במקום Math.ceil ← Retry-After: 0 כשנשארה חצי שנייה, והלקוח מנסה מיד שוב.
  • מונה אחד לכל השרת ← לקוח אחד חוסם את כולם.
  • להשתמש ב־Date.now() במקום ב־CLOCK ← הבדיקה לא יכולה "להזיז את הזמן".

// P20-E28: סיכום לקוח — שני repositories במקביל
import { Controller, Get, Inject, Injectable, Module, NotFoundException, Param, ParseIntPipe } from "@nestjs/common";

export interface Customer {
  id: number;
  fullName: string;
}

export interface Order {
  id: number;
  customerId: number;
  total: number;
  status: "paid" | "cancelled";
}

export interface CustomersRepository {
  findById(id: number): Promise<Customer | null>;
}

export interface OrdersRepository {
  findByCustomer(customerId: number): Promise<Order[]>;
}

export const CUSTOMERS_REPOSITORY = "CUSTOMERS_REPOSITORY";
export const ORDERS_REPOSITORY = "ORDERS_REPOSITORY";

export class InMemoryCustomersRepository implements CustomersRepository {
  private readonly customers: Customer[] = [{ id: 1, fullName: "Dana Levi" }];

  async findById(id: number) {
    return this.customers.find((c) => c.id === id) ?? null;
  }
}

export class InMemoryOrdersRepository implements OrdersRepository {
  private readonly orders: Order[] = [
    { id: 1, customerId: 1, total: 120.5, status: "paid" },
    { id: 2, customerId: 1, total: 80, status: "cancelled" },
  ];

  async findByCustomer(customerId: number) {
    return this.orders.filter((o) => o.customerId === customerId);
  }
}

@Injectable()
export class SummaryService {
  constructor(
    @Inject(CUSTOMERS_REPOSITORY) private readonly customers: CustomersRepository,
    @Inject(ORDERS_REPOSITORY) private readonly orders: OrdersRepository,
  ) {}

  async summary(customerId: number) {
    const [customer, orders] = await Promise.all([this.customers.findById(customerId), this.orders.findByCustomer(customerId)]);
    if (!customer) throw new NotFoundException(`לקוח ${customerId} לא נמצא`);
    const paid = orders.filter((o) => o.status === "paid");
    const agorot = paid.reduce((sum, o) => sum + Math.round(o.total * 100), 0);
    return { customer, orders: paid.length, total: agorot / 100 };
  }
}

@Controller("customers")
export class SummaryController {
  constructor(private readonly service: SummaryService) {}

  @Get(":id/summary")
  summary(@Param("id", ParseIntPipe) id: number) {
    return this.service.summary(id);
  }
}

@Module({
  controllers: [SummaryController],
  providers: [
    SummaryService,
    { provide: CUSTOMERS_REPOSITORY, useClass: InMemoryCustomersRepository },
    { provide: ORDERS_REPOSITORY, useClass: InMemoryOrdersRepository },
  ],
})
export class SummaryModule {}

את ההזמנות מביאים במקביל ללקוח, גם אם בסוף יתברר שהלקוח לא קיים. זו בחירה: במקרה הנפוץ (הלקוח קיים) חוסכים זמן, ובמקרה הנדיר שולחים שאילתה מיותרת אחת.
