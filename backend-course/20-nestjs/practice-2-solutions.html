P20-E02 · לקרוא controller 🧠 הבנה רמה 1

💡 רמז 1

Nest רושם את ה־routes ב־Express לפי סדר המתודות במחלקה — ו־Express בודק לפי הסדר.

💡 רמז 2

"featured" מתאים לתבנית :id. מה ParseIntPipe יעשה איתו?

✅ פתרון

כל התשובות נבדקו בהרצה אמיתית:

  1. 200 {"route":"one","id":7} — id הוא מספר (ParseIntPipe).
  2. 400 {"message":"Validation failed (numeric string is expected)","error":"Bad Request","statusCode":400} — הבקשה נתפסה ב־:id, שרשום קודם, ו־ParseIntPipe נכשל על "featured".
  3. 201 — ברירת המחדל של @Post().
  4. 204 בלי גוף.
  5. 404 {"message":"Cannot PUT /products/3","error":"Not Found","statusCode":404}.

התיקון ל־(2): להזיז את @Get("featured") מעל @Get(":id"). אותו כלל כמו ב־Express (P15-E01): כתובות קבועות לפני כתובות עם פרמטרים. בפרויקט 2 זה @Get("stats") לפני :id.

⚠️ טעויות נפוצות
  • לחשוב ש־Nest "חכם" ובוחר את ה־route המדויק יותר — הוא לא. הסדר קובע.
  • לצפות ל־200 ב־POST — ב־Nest זה 201.

P20-E45 · איזה status בלי לבקש? 🧠 הבנה רמה 1

💡 רמז 1

"@Post() — 201 אוטומטית". ומה לשאר?

💡 רמז 2

204 = "No Content" — לפי HTTP אסור לו גוף.

✅ פתרון

הרצה אמיתית (Nest 12):

POST       201 {"created":true}
GET        200 {"id":1}
PUT        200 {"put":true}
DELETE     200 {"deleted":true}
DELETE 204 204 (גוף ריק)

רק POST מקבל 201 לבד. DELETE מחזיר 200 עם גוף — אם רוצים 204 (כמו בפרויקט 2), צריך @HttpCode(204), ואז מה שהמתודה מחזירה נזרק. אז ב־DELETE עם 204 — לא להחזיר כלום.

⚠️ טעויות נפוצות
  • להחזיר ב־204 "הודעת הצלחה" — הלקוח לא יקבל אותה, ובדיקה שמצפה לגוף תיכשל.

P20-E46 · ‏whitelist, ‏forbidNonWhitelisted ו־transform 🧠 הבנה רמה 2

💡 רמז 1

בלי pipe — אף אחד לא מסתכל על ה־decorators. הם רק metadata.

💡 רמז 2

transform ממיר גם params לפי הטיפוס שכתבת (number). מה זה Number("abc")?

✅ פתרון

הרצה אמיתית:

== בלי pipe
POST extra      201 {"dto":{"name":"a","price":5,"extra":1}}
POST price str  201 {"dto":{"name":"a","price":"10"}}
GET abc         200 {"id":"abc","type":"string"}
== whitelist
POST extra      201 {"dto":{"name":"a","price":5}}
POST price str  400 {"message":["price must not be less than 0.01","price must be a number conforming to the specified constraints"],...}
GET abc         200 {"id":"abc","type":"string"}
== whitelist + forbidNonWhitelisted + transform
POST extra      400 {"message":["property extra should not exist"],...}
POST price str  400 (אותן שתי הודעות)
GET abc         200 {"id":null,"type":"number"}
  • בלי pipe — שום ולידציה: price: "10" (מחרוזת) נכנס, וגם extra.
  • whitelist — מוחק בשקט שדות שאין להם decorator.
  • forbidNonWhitelisted — במקום למחוק, 400. ו־transform הפך את "abc" ל־NaN (שמגיע ב־JSON כ־null) — בלי שגיאה! לכן ל־id משתמשים ב־ParseIntPipe, ולא סומכים על transform.

ו־"10" בגוף — גם עם transform — לא הופך למספר (ב־body אין המרה אוטומטית; ב־query צריך @Type(() => Number)).

⚠️ טעויות נפוצות
  • לשכוח את useGlobalPipes ב־main.ts — כל ה־DTOs "קיימים", ושום דבר לא נבדק. הבדיקות של הקורס מפעילות את ה־pipe בעצמן, אז זה לא ייתפס בהן — רק ב־main.ts שלך.

P20-E47 · ‏PATCH עם null 🧠 הבנה רמה 2

💡 רמז 1

PartialType מוסיף @IsOptional() לכל שדה.

💡 רמז 2

@IsOptional() מדלג על הבדיקות כשהערך undefined — או null.

✅ פתרון

הרצה אמיתית: שתיהן 200 — {"dto":{}} ו־{"dto":{"price":null}}. ‏{} הוא בסדר (לא מעדכנים כלום). אבל null עובר את הוולידציה ומגיע ל־service: אם הוא עושה Object.assign(product, dto) — המחיר נמחק; אם המסד דורש NOT NULL — 500. תיקון: לא לתת ל־null לעבור — @ValidateIf((o, v) => v !== undefined) על השדה (בודק תמיד, חוץ מכשהשדה חסר), או בדיקה ב־service, או Zod (.optional() בלי .nullable() — P20-E52).

⚠️ טעויות נפוצות
  • לסמוך על הטיפוס price?: number — TypeScript לא רואה את ה־JSON שהגיע.

P20-E48 · איזה exception? 🧠 הבנה רמה 1

💡 רמז 1

הטבלה ב"Exceptions" בשיעור.

💡 רמז 2

401 — "מי אתה?"; 403 — "אני יודע מי אתה, ואסור לך".

✅ פתרון
  1. BadRequestException — 400 (ה־ValidationPipe זורק לבד).
  2. UnauthorizedException — 401.
  3. ForbiddenException — 403. (או 404 — "לא מגלים שקיים" — פרק 21.)
  4. ConflictException — 409.
  5. UnprocessableEntityException — 422, או 409 (INSUFFICIENT_FUNDS, כמו P18-E41). העיקר: לא 400 (הבקשה תקינה) ולא 500.
  6. NotFoundException — 404.
  7. כלום — לא לתפוס. Error רגיל ← 500 "Internal server error", וההודעה רק בלוג. (או 503 מ־filter, אם רוצים שהלקוח ינסה שוב.)
⚠️ טעויות נפוצות
  • לזרוק BadRequestException לכל דבר "לא בסדר" — הלקוח לא יכול להבדיל בין "שלחת שטויות" לבין "אין לך כסף".

P20-E49 · ‏@Query() מול @Query("page") 🧠 הבנה רמה 2

💡 רמז 1

ל־@Query("page") אין DTO — רק הטיפוס number. מה transform עושה עם טיפוס פרימיטיבי (P20-E46)?

💡 רמז 2

מה יקרה ב־a עם ?page=abc? וב־b?

✅ פתרון
  • a: ‏page הוא 2 (מספר — transform המיר לפי הטיפוס), ‏q הוא "mug". אבל אין ולידציה: ?page=abc ← NaN, ו־?page=-5 ← ‏-5, בלי שגיאה. וגם limit לא נקרא בכלל.
  • b: ‏query הוא מופע של ListProductsQuery עם page: 2, limit: 5, q: "mug" — אחרי בדיקה. ‏?page=abc ← 400 עם הודעה. ברירות מחדל — בשדות של ה־class.

פרמטר בודד בלי כללים (?q=) — @Query("q") מספיק. כל דבר עם כללים (מספרים, טווחים, רשימה סגורה) — DTO, כמו ב־P20-E10.

⚠️ טעויות נפוצות
  • @Query("page", ParseIntPipe) כשהפרמטר לא חובה — בלי page ב־URL, ‏ParseIntPipe מחזיר 400 (צריך new DefaultValuePipe(1) לפניו).

P20-E08 · DTO וולידציה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

העתק את ה־DTO מהשיעור — ובדוק כל decorator מול הדרישה.

💡 רמז 2

ה־service מקבל dto: CreateProductDto, ובונה אובייקט חדש (לא שומר את ה־dto עצמו).

✅ פתרון
// P20-E08
import { Body, Controller, Get, Injectable, Module, Post } from "@nestjs/common";
import { IsBoolean, IsInt, IsNumber, IsOptional, IsString, Length, Max, Min } from "class-validator";

export class CreateProductDto {
  @IsString()
  @Length(2, 80)
  name: string;

  @IsNumber({ maxDecimalPlaces: 2 })
  @Min(0.01)
  @Max(100_000)
  price: number;

  @IsInt()
  @Min(0)
  stock: number;

  @IsOptional()
  @IsBoolean()
  isActive?: boolean;
}

export interface Product extends CreateProductDto {
  id: number;
  isActive: boolean;
}

@Injectable()
export class ProductsService {
  private readonly products: Product[] = [];
  private nextId = 1;

  list(): Product[] {
    return this.products;
  }

  create(dto: CreateProductDto): Product {
    const product: Product = { id: this.nextId++, name: dto.name, price: dto.price, stock: dto.stock, isActive: dto.isActive ?? true };
    this.products.push(product);
    return product;
  }
}

@Controller("products")
export class ProductsController {
  constructor(private readonly products: ProductsService) {}

  @Get()
  list() {
    return this.products.list();
  }

  @Post()
  create(@Body() dto: CreateProductDto) {
    return this.products.create(dto);
  }
}

@Module({ controllers: [ProductsController], providers: [ProductsService] })
export class ProductsModule {}

ה־DTO הוא גם הטיפוס של dto וגם הסכמה של הבדיקה. כמו z.infer ב־Zod, רק הפוך: שם כותבים סכמה ומקבלים טיפוס, כאן כותבים class ומקבלים בדיקה.

למה לבנות אובייקט חדש ב־create? whitelist כבר מחק שדות זרים, אבל המופע הוא עדיין CreateProductDto — ומה שנשמר צריך להיות הטיפוס Product, עם id וברירות מחדל.

⚠️ טעויות נפוצות
  • @IsNumber() על stock ← 2.5 עובר. ל"שלם" — @IsInt().
  • @IsBoolean() בלי @IsOptional() ← שדה אופציונלי הופך לחובה.
  • לוותר על @IsString() כי "יש כבר @Length": על "name": 12345 ההודעה תהיה name must be longer than or equal to 2 and shorter than or equal to 80 characters — על אורך, לא על סוג. מבלבל. כותבים את שניהם.

P20-E09 · PATCH ו־DELETE 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

export class UpdateProductDto extends PartialType(CreateProductDto) {} — מ־@nestjs/swagger.

💡 רמז 2

ב־update וב־remove קרא קודם ל־findOne — הוא כבר זורק 404.

✅ פתרון
// P20-E09
import { Body, Controller, Delete, Get, HttpCode, Injectable, Module, NotFoundException, Param, ParseIntPipe, Patch, Post } from "@nestjs/common";
import { PartialType } from "@nestjs/swagger";
import { IsInt, IsNumber, IsString, Length, Min } from "class-validator";

export class CreateProductDto {
  @IsString()
  @Length(2, 80)
  name: string;

  @IsNumber({ maxDecimalPlaces: 2 })
  @Min(0.01)
  price: number;

  @IsInt()
  @Min(0)
  stock: number;
}

export class UpdateProductDto extends PartialType(CreateProductDto) {}

export interface Product extends CreateProductDto {
  id: number;
}

@Injectable()
export class ProductsService {
  private readonly products: Product[] = [];
  private nextId = 1;

  create(dto: CreateProductDto): Product {
    const product = { id: this.nextId++, ...dto };
    this.products.push(product);
    return product;
  }

  findOne(id: number): Product {
    const product = this.products.find((p) => p.id === id);
    if (!product) throw new NotFoundException(`מוצר ${id} לא נמצא`);
    return product;
  }

  update(id: number, dto: UpdateProductDto): Product {
    const product = this.findOne(id);
    Object.assign(product, dto);
    return product;
  }

  remove(id: number): void {
    this.findOne(id);
    this.products.splice(this.products.findIndex((p) => p.id === id), 1);
  }
}

@Controller("products")
export class ProductsController {
  constructor(private readonly products: ProductsService) {}

  @Post()
  create(@Body() dto: CreateProductDto) {
    return this.products.create(dto);
  }

  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    return this.products.findOne(id);
  }

  @Patch(":id")
  update(@Param("id", ParseIntPipe) id: number, @Body() dto: UpdateProductDto) {
    return this.products.update(id, dto);
  }

  @Delete(":id")
  @HttpCode(204)
  remove(@Param("id", ParseIntPipe) id: number) {
    this.products.remove(id);
  }
}

@Module({ controllers: [ProductsController], providers: [ProductsService] })
export class ProductsModule {}

PartialType יוצר מחלקה חדשה עם אותם שדות ואותם decorators, ומוסיף לכל אחד @IsOptional(). לכן { "stock": -1 } עדיין נכשל, ו־{ "color": "red" } נכשל על whitelist. למה מ־@nestjs/swagger ולא מ־@nestjs/mapped-types? שתיהן עובדות; הגרסה של swagger מעבירה גם את התיעוד (שיעור 4).

⚠️ טעויות נפוצות
  • לשכוח את @HttpCode(204) ← 200 עם גוף ריק.
  • Object.assign(product, dto) כש־dto מכיל id? כאן אי אפשר — whitelist מוחק שדות שאין ב־DTO. זה בדיוק למה whitelist חשוב.

P20-E10 · pagination עם Query DTO 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

query מגיע כמחרוזת. @Type(() => Number) מ־class-transformer ממיר לפני הבדיקה (עם transform: true).

💡 רמז 2

ברירת מחדל: page: number = 1; — מאתחלים את השדה במחלקה.

✅ פתרון
// P20-E10
import { Controller, Get, Injectable, Module, Query } from "@nestjs/common";
import { Type } from "class-transformer";
import { IsInt, IsOptional, IsString, Max, Min } from "class-validator";

export class ListProductsQuery {
  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  page: number = 1;

  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  @Max(50)
  limit: number = 10;

  @IsOptional()
  @IsString()
  q?: string;
}

export interface Product {
  id: number;
  name: string;
}

@Injectable()
export class ProductsService {
  private readonly products: Product[] = Array.from({ length: 25 }, (_, i) => ({ id: i + 1, name: `Product ${i + 1}` }));

  list({ page, limit, q }: ListProductsQuery) {
    const filtered = q ? this.products.filter((p) => p.name.toLowerCase().includes(q.toLowerCase())) : this.products;
    const data = filtered.slice((page - 1) * limit, page * limit);
    return { data, meta: { page, limit, total: filtered.length, pages: Math.ceil(filtered.length / limit) } };
  }
}

@Controller("products")
export class ProductsController {
  constructor(private readonly products: ProductsService) {}

  @Get()
  list(@Query() query: ListProductsQuery) {
    return this.products.list(query);
  }
}

@Module({ controllers: [ProductsController], providers: [ProductsService] })
export class ProductsModule {}

הסדר של ה־decorators לא משנה לבדיקה, אבל קל לקרוא אותו מלמעלה: אופציונלי ← המרה ← שלם ← טווח. ומה עם ?q=product 2? 7 תוצאות: Product 2 ו־20–25.

⚠️ טעויות נפוצות
  • בלי @Type ← כל ?page=2 נכשל ב־"page must be an integer number" (תראה את זה שוב ב־E21).
  • לחשב pages עם Math.floor ← 25/10 נותן 2 ומאבדים את הדף האחרון.

P20-E16 · pipe משלך 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

transform(value, metadata): מה שמחזירים — זה מה שה־handler מקבל.

💡 רמז 2

Number(" 7") הוא 7 ו־Number("") הוא 0. בדיקה עם regex (/^\d+$/) פשוטה יותר.

✅ פתרון
// P20-E16
import { ArgumentMetadata, BadRequestException, Controller, Get, Injectable, Module, Param, PipeTransform } from "@nestjs/common";

@Injectable()
export class ParsePositiveIntPipe implements PipeTransform<string, number> {
  transform(value: string, metadata: ArgumentMetadata): number {
    if (!/^\d+$/.test(value) || Number(value) < 1) {
      throw new BadRequestException(`${metadata.data ?? "הערך"} חייב להיות מספר שלם חיובי`);
    }
    return Number(value);
  }
}

@Controller("items")
export class ItemsController {
  @Get(":id")
  findOne(@Param("id", ParsePositiveIntPipe) id: number) {
    return { id, type: typeof id };
  }
}

@Module({ controllers: [ItemsController] })
export class ItemsModule {}

הבודק בודק את ה־pipe גם לבד — new ParsePositiveIntPipe().transform("7", ...). זה היתרון של pipe כמחלקה: יחידה קטנה שאפשר לבדוק בלי שרת. ושם הפרמטר מ־metadata.data הופך את אותו pipe לשימושי גם ל־@Param("orderId", ...).

⚠️ טעויות נפוצות
  • parseInt("7x") ← 7. parseInt סלחני מדי לקלט מהמשתמש.
  • לשכוח את ParsePositiveIntPipe ב־@Param ← type יוצא "string".

P20-E21 · ולידציה שמכשילה 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

(1) ו־(2): מה class-transformer ו־whitelist "רואים" בזמן ריצה? לא את הטיפוסים של TypeScript.

💡 רמז 2

(3): Nest יודע לתרגם ל־status רק HttpException. כל דבר אחר שנזרק — 500.

✅ פתרון
// P20-E21: מתוקן
import { Body, Controller, Get, Module, NotFoundException, Param, ParseIntPipe, Post, Query } from "@nestjs/common";
import { Type } from "class-transformer";
import { IsInt, IsOptional, IsString, Length, Max, Min } from "class-validator";

export class ListReportsQuery {
  @IsOptional()
  @Type(() => Number) // ← תקלה 1: בלי זה "2" נשאר מחרוזת ו־@IsInt נכשל
  @IsInt()
  @Min(1)
  page: number = 1;

  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  @Max(20)
  limit: number = 5;
}

export class CreateReportDto {
  @IsString()
  @Length(1, 100)
  title: string;

  @IsOptional() // ← תקלה 2: שדה בלי decorators "לא קיים" מבחינת whitelist
  @IsString()
  @Length(0, 1000)
  note?: string;
}

interface Report {
  id: number;
  title: string;
  note: string | null;
}

@Controller("reports")
export class ReportsController {
  private readonly reports: Report[] = [];

  @Get()
  list(@Query() query: ListReportsQuery) {
    const start = (query.page - 1) * query.limit;
    return { page: query.page, limit: query.limit, data: this.reports.slice(start, start + query.limit) };
  }

  @Post()
  create(@Body() dto: CreateReportDto) {
    const report = { id: this.reports.length + 1, title: dto.title, note: dto.note ?? null };
    this.reports.push(report);
    return report;
  }

  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    const report = this.reports.find((r) => r.id === id);
    if (!report) throw new NotFoundException(`דוח ${id} לא נמצא`); // ← תקלה 3: throw "..." הופך ל־500
    return report;
  }
}

@Module({ controllers: [ReportsController] })
export class ReportsModule {}

כל שלוש התקלות הן אותו רעיון: בזמן ריצה יש רק מה שכתבת ב־decorators. page: number לא ממיר (צריך @Type); note?: string בלי decorator לא קיים מבחינת whitelist; ו־throw "..." הוא לא exception של Nest. ההודעות בתרגיל הן אמיתיות. ולמה "3" נכשל גם ב־@Min וגם ב־@Max? כי שתי הבדיקות דורשות קודם כול מספר — ומחרוזת נכשלת בכל אחת מהן.

💡 רמז 1

סדר הכתיבה: imports ← interface Bookmark ← class CreateBookmarkDto עם decorators ← @Injectable() class BookmarksService (המערך ו־nextId כשדות פרטיים) ← @Controller("bookmarks") ← @Module({ controllers, providers }). מה מייבאים? כל decorator שהשתמשת בו: @nestjs/common לחלק של HTTP, ו־class-validator ל־DTO.

💡 רמז 2

// P20-E26: מודול סימניות — מקובץ ריק
import { Body, Controller, Delete, Get, HttpCode, Injectable, Module, NotFoundException, Param, ParseIntPipe, Post, Query } from "@nestjs/common";
import { ArrayMaxSize, IsArray, IsOptional, IsString, IsUrl, Length } from "class-validator";

export interface Bookmark {
  id: number;
  url: string;
  title: string;
  tags: string[];
}

export class CreateBookmarkDto {
  @IsUrl()
  url: string;

  @IsString()
  @Length(1, 100)
  title: string;

  @IsOptional()
  @IsArray()
  @ArrayMaxSize(5)
  @IsString({ each: true })
  tags?: string[];
}

@Injectable()
export class BookmarksService {
  private readonly bookmarks: Bookmark[] = [];
  private nextId = 1;

  list(tag?: string): Bookmark[] {
    return tag === undefined ? this.bookmarks : this.bookmarks.filter((b) => b.tags.includes(tag));
  }

  get(id: number): Bookmark {
    const bookmark = this.bookmarks.find((b) => b.id === id);
    if (!bookmark) throw new NotFoundException(`סימנייה ${id} לא נמצאה`);
    return bookmark;
  }

  create(dto: CreateBookmarkDto): Bookmark {
    const bookmark = { id: this.nextId++, url: dto.url, title: dto.title.trim(), tags: dto.tags ?? [] };
    this.bookmarks.push(bookmark);
    return bookmark;
  }

  remove(id: number): void {
    const bookmark = this.get(id);
    this.bookmarks.splice(this.bookmarks.indexOf(bookmark), 1);
  }
}

@Controller("bookmarks")
export class BookmarksController {
  constructor(private readonly bookmarks: BookmarksService) {}

  @Get()
  list(@Query("tag") tag?: string) {
    return this.bookmarks.list(tag);
  }

  @Get(":id")
  get(@Param("id", ParseIntPipe) id: number) {
    return this.bookmarks.get(id);
  }

  @Post()
  create(@Body() dto: CreateBookmarkDto) {
    return this.bookmarks.create(dto);
  }

  @Delete(":id")
  @HttpCode(204)
  remove(@Param("id", ParseIntPipe) id: number) {
    this.bookmarks.remove(id);
  }
}

@Module({ controllers: [BookmarksController], providers: [BookmarksService] })
export class BookmarksModule {}

שים לב איך כל שכבה עושה דבר אחד. ה־DTO והוולידציה דוחים קלט רע לפני שהוא מגיע לקוד. ה־service מחזיק את הנתונים ומחליט מה "לא נמצא". ה־controller רק מתרגם בין HTTP לבין קריאה ל־service. ‏remove משתמשת ב־get, ולכן ה־404 נכתב פעם אחת.

ה־NotFoundException נזרק מה־service, ו־Nest הופך אותו ל־404 עם { statusCode, message, error }. ה־controller לא צריך if.

ParseIntPipe הופך את "2" מה־URL למספר 2, ומחזיר 400 על "abc". בלעדיו b.id === id משווה מספר למחרוזת, וכל סימנייה "לא נמצאת".

⚠️ טעויות נפוצות
  • לשכוח את ה־controller או את ה־service ב־@Module — ‏404 לכל כתובת, או Nest can't resolve dependencies (‏P20-E03).
  • @Param("id") id: number בלי ParseIntPipe — הטיפוס אומר number, אבל בזמן ריצה זו מחרוזת.
  • @IsString() tags בלי { each: true } — מערך תמיד נכשל, כי מערך אינו מחרוזת.
  • בלי @HttpCode(204) על ה־DELETE — ‏Nest מחזיר 200 כברירת מחדל.

import { Body, ConflictException, Controller, Injectable, Module, Post } from "@nestjs/common";
import { IsEmail, IsOptional, IsString, Length, Matches, MinLength } from "class-validator";

export class SignupDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(8)
  @Matches(/\d/, { message: "password חייב לכלול ספרה" })
  password: string;

  @IsOptional()
  @IsString()
  @Length(2, 40)
  displayName?: string;
}

type User = { id: number; email: string; displayName: string | null; password: string };

@Injectable()
export class UsersService {
  private users: User[] = [];

  signup(dto: SignupDto) {
    const email = dto.email.toLowerCase();
    if (this.users.some((u) => u.email === email)) throw new ConflictException("האימייל כבר רשום");
    const user: User = { id: this.users.length + 1, email, displayName: dto.displayName ?? null, password: dto.password };
    this.users.push(user);
    const { password, ...pub } = user;
    return pub;
  }
}

@Controller("signup")
export class SignupController {
  constructor(private readonly users: UsersService) {}
  @Post()
  signup(@Body() dto: SignupDto) {
    return this.users.signup(dto);
  }
}

@Module({ controllers: [SignupController], providers: [UsersService] })
export class SignupModule {}

⚠️ טעויות נפוצות

// P20-E51: אירועים — Query DTO עם תאריכים ורשימה סגורה
import { BadRequestException, Controller, Get, Module, Query } from "@nestjs/common";
import { Type } from "class-transformer";
import { IsDateString, IsIn, IsInt, IsOptional, Max, Min } from "class-validator";

const EVENTS = [
  { id: 1, title: "Latte Art", city: "tel-aviv", date: "2026-12-01" },
  { id: 2, title: "Cupping", city: "haifa", date: "2026-11-20" },
  { id: 3, title: "Roasting 101", city: "tel-aviv", date: "2027-01-15" },
  { id: 4, title: "Espresso Lab", city: "jerusalem", date: "2026-12-10" },
  { id: 5, title: "Pour Over", city: "haifa", date: "2027-02-02" },
];

export class EventsQuery {
  @IsOptional()
  @IsIn(["tel-aviv", "haifa", "jerusalem"])
  city?: string;

  @IsOptional()
  @IsDateString()
  from?: string;

  @IsOptional()
  @IsDateString()
  to?: string;

  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  @Max(20)
  limit = 10;
}

@Controller("events")
export class EventsController {
  @Get()
  list(@Query() q: EventsQuery) {
    if (q.from && q.to && q.from > q.to) throw new BadRequestException("from חייב להיות לפני to");
    return EVENTS.filter((e) => (!q.city || e.city === q.city) && (!q.from || e.date >= q.from) && (!q.to || e.date <= q.to))
      .sort((a, b) => a.date.localeCompare(b.date))
      .slice(0, q.limit);
  }
}

@Module({ controllers: [EventsController] })
export class EventsModule {}

⚠️ טעויות נפוצות

P20-E27 · slug: ‏regex בפונקציה וב־pipe 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

// P20-E27: slug — regex בפונקציה וב־pipe
import { BadRequestException, Controller, Get, Injectable, Module, Param, type PipeTransform, Query } from "@nestjs/common";

const SLUG = /^[a-z0-9]+(?:-[a-z0-9]+)*$/;

export function slugify(title: string): string {
  return title
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, "-")
    .replace(/^-+|-+$/g, "");
}

@Injectable()
export class SlugPipe implements PipeTransform<string, string> {
  transform(value: string): string {
    if (typeof value !== "string" || value.length > 60 || !SLUG.test(value)) {
      throw new BadRequestException(`slug לא תקין: ${value}`);
    }
    return value;
  }
}

@Controller("slugs")
export class SlugsController {
  @Get("preview")
  preview(@Query("title") title = "") {
    return { slug: slugify(title) };
  }

  @Get(":slug")
  show(@Param("slug", SlugPipe) slug: string) {
    return { slug };
  }
}

@Module({ controllers: [SlugsController] })
export class SlugsModule {}

שני ה־regex משלימים זה את זה: slugify מייצרת slug מכל טקסט, ו־SlugPipe בודק שמה שהגיע מבחוץ הוא slug. כל מה ש־slugify מייצרת עובר את ה־pipe (חוץ ממחרוזת ריקה). הבודק מנסה גם "hello--world" ו־"-hello", שה־pipe צריך לדחות.

pipe הוא מחלקה עם מתודה אחת, transform, שמקבלת ערך ומחזירה ערך (או זורקת). ‏implements PipeTransform הוא החוזה, כמו ב־interface מפרק 12. ‏Nest מפעיל את ה־pipe לפני ה־handler, ולכן הקוד ב־show כבר יודע שה־slug תקין.

הסדר של ה־routes חשוב: Nest בודק אותם לפי הסדר במחלקה. אילו :slug היה ראשון, ‏/slugs/preview היה מגיע אליו עם slug = "preview".

⚠️ טעויות נפוצות
  • .replace(/[^a-z0-9]/g, "-") בלי + — ‏"a & b" הופך ל־"a---b".
  • /^[a-z0-9-]+$/ — מקבל "--", ‏"-a" ו־"a--b".
  • .toLowerCase() אחרי ה־replace — האותיות הגדולות כבר הפכו למקפים.
  • לזרוק Error רגיל מה־pipe — הלקוח מקבל 500 במקום 400.

// P20-E55: הזמנה עם פריטים — DTO מקונן
import { BadRequestException, Body, Controller, Module, Post } from "@nestjs/common";
import { Type } from "class-transformer";
import { ArrayMaxSize, ArrayMinSize, IsArray, IsEmail, IsInt, IsNumber, Matches, Max, Min, ValidateNested } from "class-validator";

export class OrderItemDto {
  @Matches(/^[A-Z]{3}-\d{3}$/)
  sku: string;

  @IsInt()
  @Min(1)
  @Max(99)
  qty: number;

  @IsNumber({ maxDecimalPlaces: 2 })
  @Min(0.01)
  price: number;
}

export class CreateOrderDto {
  @IsEmail()
  customerEmail: string;

  @IsArray()
  @ArrayMinSize(1)
  @ArrayMaxSize(20)
  @ValidateNested({ each: true })
  @Type(() => OrderItemDto)
  items: OrderItemDto[];
}

@Controller("orders")
export class OrdersController {
  private nextId = 1;

  @Post()
  create(@Body() dto: CreateOrderDto) {
    const seen = new Set<string>();
    for (const i of dto.items) {
      if (seen.has(i.sku)) throw new BadRequestException(`sku כפול: ${i.sku}`);
      seen.add(i.sku);
    }
    const cents = dto.items.reduce((sum, i) => sum + Math.round(i.price * 100) * i.qty, 0);
    const items = dto.items.map((i) => ({ sku: i.sku, qty: i.qty, price: i.price }));
    return { id: this.nextId++, customerEmail: dto.customerEmail, items, total: cents / 100 };
  }
}

@Module({ controllers: [OrdersController] })
export class OrdersModule {}

‏@ValidateNested + @Type הם הזוג שהופך "מערך של אובייקטים" ל"מערך של DTOs שנבדקים". שגיאה בפריט מגיעה עם נתיב: "items.1.qty must not be greater than 99".

⚠️ טעויות נפוצות
  • @IsArray() לבד — הפריטים עצמם לא נבדקים בכלל, ו־{ qty: -5 } עובר.

  const id = i + 1;
  const special: Record<number, string> = { 7: "Nest Tips", 21: "More Nest" };
  return { id, title: special[id] ?? `Article ${id}` };
});

export class ListArticlesQuery {
  @IsOptional() @Type(() => Number) @IsInt() @Min(1)
  page = 1;

  @IsOptional() @Type(() => Number) @IsInt() @Min(1) @Max(20)
  limit = 5;

  @IsOptional() @IsString()
  q?: string;
}

@Controller("articles")
export class ArticlesController {
  @Get()
  list(@Query() { page, limit, q }: ListArticlesQuery) {
    const all = q ? ARTICLES.filter((a) => a.title.toLowerCase().includes(q.toLowerCase())) : ARTICLES;
    const total = all.length;
    const pages = Math.ceil(total / limit);
    const link = (p: number) => "/articles?" + new URLSearchParams({ ...(q ? { q } : {}), page: String(p), limit: String(limit) });
    return {
      data: all.slice((page - 1) * limit, page * limit),
      meta: { page, limit, total, pages },
      links: { self: link(page), next: page < pages ? link(page + 1) : null, prev: page > 1 ? link(page - 1) : null },
    };
  }
}

@Module({ controllers: [ArticlesController] })
export class ArticlesModule {}
