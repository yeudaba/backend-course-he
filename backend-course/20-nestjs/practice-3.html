P20-E03 · לקרוא שגיאת DI

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 3

הקוד:

@Injectable() export class UsersService {}
@Injectable() export class OrdersService { constructor(private readonly users: UsersService) {} }

@Module({ providers: [UsersService] })  export class UsersModule {}
@Module({ providers: [OrdersService] }) export class OrdersModule {}

ב־NestFactory.create(OrdersModule) מתקבלת השגיאה (פלט אמיתי, השורה הראשונה):

Nest can't resolve dependencies of the OrdersService (?). Please make sure that the argument UsersService at index [0] is available in the OrdersModule module.

(א) מה אומר כל חלק בהודעה: OrdersService, (?), index [0], OrdersModule? (ב) תקן — שני שינויים. (ג) למה לא כדאי לתקן ב־providers: [OrdersService, UsersService] בתוך OrdersModule?

  1. בקשה תקינה עם מפתח נכון.

P20-E11 · שעון כ־provider 🤖

P20-E12 · מבנה שגיאות אחיד 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ 20-nestjs/starter/P20-E12.ts השלם שני דברים, כך שכל שגיאת HTTP תחזור במבנה של פרויקט 2: { "error": { "code", "message", "details"? } }.

  1. ApiExceptionFilter: code לפי status — 400 BAD_REQUEST, 401 UNAUTHORIZED, 403 FORBIDDEN, 404 NOT_FOUND, 409 CONFLICT, אחר ERROR. message — exception.message. אבל אם מי שזרק כבר שם אובייקט עם code — מחזירים אותו כמו שהוא.
  2. validationPipe(): עם exceptionFactory שזורק BadRequestException עם { code: "VALIDATION_ERROR", message: "קלט לא תקין", details: [{ field, messages }] }.

דוגמאות: GET /items/5 ← 404 {"error":{"code":"NOT_FOUND","message":"פריט 5 לא נמצא"}}; GET /nothing ← 404 עם "Cannot GET /nothing".

P20-E25 · אתגר: הגבלת קצב 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 45 דק׳ידע נדרש: שיעור 3

בקובץ 20-nestjs/starter/P20-E25.ts כתוב RateLimitGuard ("חלון קבוע") והפעל אותו על DataController:

  • האופציות מ־token RATE_LIMIT ({ limit, windowMs }), והזמן מ־CLOCK.
  • מזהה לקוח: header X-Client-Id, ואם אין — req.ip. לכל לקוח מונה משלו.
  • החלון מתחיל בבקשה הראשונה של הלקוח ונמשך windowMs. בכל בקשה מאושרת: header X-RateLimit-Remaining.
  • מעבר למכסה ← 429 { error: { code: "RATE_LIMITED", message } }, עם header Retry-After — שניות עד סוף החלון, מעוגל למעלה.

דוגמה (limit 3, חלון 10 שניות): 3 בקשות ב־10:00:00 ← remaining 2, 1, 0. בקשה ב־10:00:02.5 ← 429, Retry-After: 8. ב־10:00:10 ← חלון חדש.

P20-E28 · סיכום לקוח משני repositories 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

🔁 חזרה על Promise.all (פרק 10), ‏reduce ואגורות (פרקים 2, 6) ו־interface (פרק 12), בתוך DI של Nest. בקובץ 20-nestjs/starter/P20-E28.ts כתוב וייצא:

  • interface Customer { id; fullName }, ‏interface Order { id; customerId; total; status: "paid" | "cancelled" }.
  • interface CustomersRepository { findById(id): Promise<Customer | null> } ו־interface OrdersRepository { findByCustomer(customerId): Promise<Order[]> }, עם שני tokens: CUSTOMERS_REPOSITORY ו־ORDERS_REPOSITORY (מחרוזות).
  • מימוש בזיכרון לכל אחד: לקוח { id: 1, fullName: "Dana Levi" }, ושתי הזמנות שלו: { id: 1, total: 120.5, status: "paid" } ו־{ id: 2, total: 80, status: "cancelled" }.
  • SummaryService שמקבל את שני ה־repositories דרך ה־tokens. ‏GET /customers/:id/summary ← { customer, orders, total }: מספר ההזמנות ששולמו וסכומן. את הלקוח ואת ההזמנות מביאים במקביל. הסכום מדויק (באגורות). לקוח לא קיים ← 404 לקוח ${id} לא נמצא.
  • SummaryModule שמחבר הכול.

הבודק מחליף את שני ה־repositories במזויפים שכל קריאה אליהם לוקחת 80ms, ומודד.
