פרק 20 — NestJS

⏱ 5 מפגשים

🧰 לפני שמתחילים — פרק 20

מה צריך שכבר יהיה מותקן: Node.js 24+, VS Code, פרויקט 2 בשלב ב׳ (Prisma).

מה מתקינים עכשיו:

  • חבילות NestJS לתרגילים — כבר רשומות ב־package.json של תיקיית הקורס: npm install.
  • Nest CLI — לא מתקינים גלובלית; מריצים עם npx @nestjs/cli@12 כשיוצרים פרויקט (שיעור 1 ו־4). דורש Node 24 — ב־Node ישן יותר ה־CLI נכשל עם ERR_REQUIRE_CYCLE_MODULE.

📂 העתקת חומרי הפרק: ב־Finder, העתק את התיקייה 20-nestjs מתוך ~/Desktop/Backend/backend-course אל ~/dev/backend-course (גרירה עם ⌥ Option). אם התיקייה כבר שם מהעתקה קודמת ואתה רוצה לשמור את מה שכתבת — בחר Keep Both / Stop ולא Replace.

איך עובדים בתרגילים: Nest משתמש ב־decorators (@Controller(), @Get()...), ו־Node לא יודע להריץ אותם ישירות מקובץ .ts כמו בפרקים הקודמים. לכן הבודק מקמפל כל קובץ תרגיל עם tsc לתיקייה 20-nestjs/.build ומריץ משם — אתה רק כותב ומריץ npm run check P20-E06. (בפרויקט — npm run start:dev של Nest עושה את הקומפילציה.)

✔ בדיקה: npm run check P20-E06 צריך להיכשל על הקוד שלך — לא על "Cannot find module '@nestjs/common'".

🎯 בסוף הפרק תדע
  • להבין את הארכיטקטורה של Nest: modules, controllers, providers ו־dependency injection.
  • לכתוב controllers עם DTOs, ולידציה (class-validator) ו־pipes.
  • להשתמש ב־custom providers ו־injection tokens — ולהחליף תלויות בבדיקות.
  • guards, interceptors ו־exception filters: היכן כל אחד רץ, ולמה.
  • תיעוד API אוטומטי עם Swagger, ומעבר של פרויקט 2 ל־Nest.

🤔 למה צריך את זה?

ב־Express בנית בעצמך את המבנה: שכבות, הזרקת תלויות ידנית ב־createApp, middleware לבדיקת קלט, error handler. בפרויקט עם 5 מפתחים ו־30 מודולים, כל אחד יבנה את זה אחרת. NestJS נותן מבנה קבוע: איפה כל דבר גר, איך תלויות מוזרקות, איך בודקים קלט ואיך מטפלים בשגיאות. הוא הפך לסטנדרט בהרבה חברות שעובדות עם Node ו־TypeScript, והוא מופיע בחלק גדול ממשרות ה־Backend. החדשות הטובות: כל מה שלמדת ב־Express — עדיין שם, מתחת.
