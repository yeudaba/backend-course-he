P20-E01 · מ־Express ל־Nest 🧠 הבנה רמה 1

💡 רמז 1

חזור לטבלה בשיעור 1 ולשיעור 2 (טבלת ה־decorators).

💡 רמז 2

חלק מהדברים Nest עושה לבד — למשל 201 ל־POST.

✅ פתרון
  1. @Get(":id") על מתודה בתוך מחלקה עם @Controller("tasks") — ב־controller.
  2. @Param("id"), @Query("page"), @Body() — פרמטרים של מתודת ה־controller.
  3. מחזירים את האובייקט (return task). POST מחזיר 201 כברירת מחדל; לשינוי — @HttpCode().
  4. providers ב־module + constructor ב־service/controller. Nest יוצר ומעביר. החלפה בבדיקה: overrideProvider.
  5. pipe: ValidationPipe + DTO (או pipe משלך עם Zod, כמו בפרויקט 2).
  6. exception filter (@Catch()), נרשם ב־main.ts או עם APP_FILTER ב־module.
  7. NestFactory.create(AppModule) ואז app.listen(3000) — ב־main.ts.

המסקנה: אותם רעיונות בדיוק. Nest רק קובע לכל אחד מקום קבוע.

⚠️ טעויות נפוצות
  • לחשוב שב־Nest כותבים res.json() כמו ב־Express — אפשר (@Res()), אבל אז Nest מפסיק לטפל בתשובה בשבילך. כמעט תמיד פשוט מחזירים ערך.

P20-E05 · למה צריך build 🧠 הבנה רמה 1

💡 רמז 1

Node "מוחק" טיפוסים. decorator הוא לא טיפוס — הוא קוד שרץ.

💡 רמז 2

אחרי קומפילציה, מה נשאר מ־UsersService ומה נשאר מ־TasksRepository?

✅ פתרון

(א) מצב ה־strip-types של Node רק מוחק תחביר של טיפוסים. decorators (בגרסה ש־Nest משתמש בה, experimentalDecorators) הם קוד שצריך לתרגם לקריאות פונקציה — ואת זה רק קומפיילר (tsc, או ה־CLI של Nest שמפעיל אותו) עושה. לכן ב־Nest יש תמיד build: npm run start:dev מקמפל ל־dist/ ומריץ משם, והבודק מקמפל ל־.build/.

(ב) עם emitDecoratorMetadata הקומפיילר שומר, לכל מחלקה שיש עליה decorator, את רשימת הטיפוסים של פרמטרי ה־constructor (design:paramtypes → [UsersService]). Nest קורא את הרשימה, ומחפש provider לכל אחד. בלי decorator על המחלקה — אין רשימה. זה התפקיד האמיתי של @Injectable() (ותראה מה קורה בלעדיו ב־E20).

(ג) UsersService הוא class — הוא קיים בזמן ריצה, ואפשר לשמור הפניה אליו. interface נמחק לגמרי בקומפילציה; ב־metadata נשאר רק Object. לכן נותנים לו שם — token — ומבקשים לפי השם: @Inject(TASKS_REPOSITORY).

⚠️ טעויות נפוצות
  • לחשוב ש־@Injectable() "רושם" את ה־service — לא. הרישום הוא ב־providers של ה־module. ה־decorator רק גורם לקומפיילר לשמור את הטיפוסים.

P20-E29 · מי נוצר קודם, וכמה פעמים? 🧠 הבנה רמה 2

💡 רמז 1

כדי ליצור controller, Nest צריך קודם את מה שה־constructor שלו מבקש.

💡 רמז 2

provider רגיל ב־Nest הוא singleton — מופע אחד לכל האפליקציה.

✅ פתרון

בעלייה: CounterService פעם אחת, ואז AController ו־BController (קודם התלויות, אחר כך מי שתלוי בהן). אחרי הבקשות: הבקשה השלישית ל־/a מחזירה { "a": 3 }, והשנייה ל־/b — { "b": 5 }: שני ה־controllers מקבלים אותו מופע, עם מונה אחד משותף. ‏CounterService נוצר פעם אחת — לא לכל בקשה ולא לכל controller.

זה בדיוק מה שעשית ב־createApp של פרויקט 2: new אחד לכל דבר, והעברה לכל מי שצריך. ומכאן גם הסכנה: state בתוך service משותף לכל המשתמשים (P20-E23).

⚠️ טעויות נפוצות
  • לחשוב ש"כל בקשה מקבלת service חדש" (כמו ב־PHP, למשל) — ולשמור בו מידע של משתמש אחד.

P20-E30 · מה ה־handler מחזיר — ומה הלקוח מקבל? 🧠 הבנה רמה 2

💡 רמז 1

"מה שהמתודה מחזירה הופך ל־JSON עם 200". ו־Promise? Nest מחכה.

💡 רמז 2

שגיאה שאינה HttpException — 500, "בלי פרטים".

✅ פתרון
  • obj — 200, ‏{"ok":true} (JSON).
  • text — 200, ‏שלום כטקסט (מחרוזת לא עוברת JSON.stringify).
  • none — 200 עם גוף ריק.
  • later — 200, ‏[1,2,3] אחרי 50ms; Nest מחכה ל־Promise.
  • nf — 404, עם message: "מוצר 7 לא נמצא", ‏error: "Not Found" ו־statusCode: 404.
  • boom — 500, ‏{"statusCode":500,"message":"Internal server error"}. ההודעה המקורית (עם הסיסמה!) לא נשלחת ללקוח — רק ללוג. ב־Express של פרק 15 היית צריך לכתוב את זה בעצמך ב־errorHandler.
⚠️ טעויות נפוצות
  • return res.json(...) עם @Res() "כמו ב־Express" — עכשיו Nest לא שולח בעצמו, ו־interceptors ו־filters לא רואים את התשובה (שיעור 3).

P20-E31 · ‏private readonly בפרמטר — מה זה עושה? 🧠 הבנה רמה 2

💡 רמז 1

"מחיקת טיפוסים" = מוחקים את מה שאחרי : ומשאירים את השאר. מה נשאר מ־private readonly products: ProductsService?

💡 רמז 2

בגרסה הקצרה יש קוד JavaScript "נסתר": this.products = products.

✅ פתרון
  1. מקבלת פרמטר products, ויוצרת שדה private readonly באותו שם עם הערך שלו — קיצור ל־3 השורות של הגרסה הארוכה.
  2. כדי להריץ את הגרסה הקצרה צריך להוסיף קוד (this.products = products) — ומחיקת טיפוסים רק מוחקת. לכן Node מסרב (זו השגיאה שראינו בפועל, ב־Node 24, כשניסינו להריץ קובץ כזה בלי build). בגרסה הארוכה מחיקת : ProductsService ו־private readonly משאירה JavaScript תקין. זו אותה סיבה שבגללה Nest צריך tsc (P20-E05): decorators ו־parameter properties הם קוד, לא רק טיפוסים.
⚠️ טעויות נפוצות
  • לכתוב constructor(products: ProductsService) {} בלי private — אין שדה, ו־this.products הוא undefined בכל מתודה.

P20-E32 · ‏nest generate resource — ומה לבדוק אחריו 🧠 הבנה רמה 1

💡 רמז 1

"נוצרים module, controller, service ו־DTOs — ו־ProductsModule נרשם אוטומטית ב־AppModule".

💡 רמז 2

+"abc" ב־JavaScript הוא...?

✅ פתרון
  1. ‏products.module.ts, ‏products.controller.ts, ‏products.service.ts, ‏dto/create-product.dto.ts, ‏dto/update-product.dto.ts, ‏entities/product.entity.ts — ו־app.module.ts מקבל imports: [ProductsModule].
  2. ‏+id ממיר מחרוזת למספר. ‏+"abc" הוא NaN — ה־service מקבל NaN, לא מוצא כלום, ובמקרה הטוב מחזיר 404 (במקרה הרע — שגיאה מהמסד ו־500). 400 היה נכון.
  3. @Param("id", ParseIntPipe) id: number במקום +id; למלא את ה־DTOs (הם ריקים); ולמחוק מה שלא צריך (entities כשיש Prisma). הקוד שנוצר הוא שלד, לא קוד מוכן.
⚠️ טעויות נפוצות
  • להשאיר את ה־DTOs הריקים — עם whitelist, כל השדות נמחקים מהגוף בשקט (P20-E46).

P20-E06 · שלום Nest 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

@Controller("hello") על המחלקה, @Get() על המתודה, @Query("name") name?: string בפרמטר.

💡 רמז 2

controller שלא מופיע ב־controllers: [...] של module — לא קיים מבחינת Nest (404).

✅ פתרון
// P20-E06
import { Controller, Get, Module, Query } from "@nestjs/common";

@Controller("hello")
export class HelloController {
  @Get()
  hello(@Query("name") name?: string) {
    return { message: `שלום ${name ? name : "אורח"}` };
  }
}

@Module({ controllers: [HelloController] })
export class HelloModule {}

שים לב כמה מעט קוד: אין res.json — מחזירים אובייקט, ו־Nest הופך אותו ל־JSON עם 200.

⚠️ טעויות נפוצות
  • לשכוח את controllers: [HelloController] ← 404 על הכול.
  • @Query() name (בלי שם) ← מקבלים את כל אובייקט ה־query, לא את המחרוזת.

P20-E07 · קריאת מוצרים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

ה־controller מקבל את ה־service ב־constructor: constructor(private readonly products: ProductsService) {}.

💡 רמז 2

throw new NotFoundException("...") מתוך ה־service. @Param("id", ParseIntPipe) id: number.

✅ פתרון
// P20-E07
import { Controller, Get, Injectable, Module, NotFoundException, Param, ParseIntPipe } from "@nestjs/common";

export interface Product {
  id: number;
  name: string;
  price: number;
}

@Injectable()
export class ProductsService {
  private readonly products: Product[] = [
    { id: 1, name: "Espresso cup", price: 24.9 },
    { id: 2, name: "Hand grinder", price: 189 },
    { id: 3, name: "Milk jug", price: 59.5 },
  ];

  list(): Product[] {
    return this.products;
  }

  findOne(id: number): Product {
    const product = this.products.find((p) => p.id === id);
    if (!product) throw new NotFoundException(`מוצר ${id} לא נמצא`);
    return product;
  }
}

@Controller("products")
export class ProductsController {
  constructor(private readonly products: ProductsService) {}

  @Get()
  list() {
    return this.products.list();
  }

  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    return this.products.findOne(id);
  }
}

@Module({ controllers: [ProductsController], providers: [ProductsService] })
export class ProductsModule {}

ה־404 נזרק מה־service, לא מה־controller: כל מי שקורא ל־findOne (גם controller אחר, גם job) יקבל את אותה התנהגות. ה־controller נשאר דק — בדיוק כמו בפרויקט 2.

⚠️ טעויות נפוצות
  • בלי ParseIntPipe: id הוא "2", ו־p.id === "2" אף פעם לא נכון ← 404 על הכול. (טיפוס number בפרמטר לא ממיר כלום — זה רק TypeScript.)
  • להחזיר undefined במקום לזרוק ← 200 עם גוף ריק.

P20-E34 · מונה ביקורים ב־service 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

@Get("peek") בנוסף ל־@Get().

💡 רמז 2

המונה הוא שדה במחלקה (private count = 0) — לא משתנה גלובלי בקובץ.

✅ פתרון
// P20-E34: מונה ביקורים ב־service
import { Controller, Get, Injectable, Module } from "@nestjs/common";

@Injectable()
export class VisitsService {
  private count = 0;
  hit() {
    return ++this.count;
  }
  peek() {
    return this.count;
  }
}

@Controller("visits")
export class VisitsController {
  constructor(private readonly visits: VisitsService) {}

  @Get()
  hit() {
    return { visits: this.visits.hit() };
  }

  @Get("peek")
  peek() {
    return { visits: this.visits.peek() };
  }
}

@Module({ controllers: [VisitsController], providers: [VisitsService] })
export class VisitsModule {}

המונה שייך למופע של ה־service, ולכל אפליקציה — מופע משלה. משתנה ברמת הקובץ היה משותף לכל האפליקציות באותו תהליך (P20-E23).

⚠️ טעויות נפוצות
  • let count = 0 מחוץ למחלקה — עובד עם שרת אחד, ונכשל בבדיקות.

P20-E35 · ברכות בכמה שפות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

@Param("lang") lang: string — בלי pipe, זה כבר מחרוזת.

💡 רמז 2

throw new NotFoundException(שפה ${lang} לא נתמכת) — מתוך ה־service.

✅ פתרון
// P20-E35: ברכות בכמה שפות
import { Controller, Get, Injectable, Module, NotFoundException, Param } from "@nestjs/common";

@Injectable()
export class GreetingsService {
  private texts: Record<string, string> = { he: "שלום", en: "Hello", ar: "مرحبا" };

  greet(lang: string) {
    if (!Object.hasOwn(this.texts, lang)) throw new NotFoundException(`שפה ${lang} לא נתמכת`);
    return { lang, text: this.texts[lang] };
  }

  languages() {
    return Object.keys(this.texts).sort();
  }
}

@Controller("hello")
export class HelloController {
  constructor(private readonly greetings: GreetingsService) {}
  @Get(":lang")
  greet(@Param("lang") lang: string) {
    return this.greetings.greet(lang);
  }
}

@Controller("languages")
export class LanguagesController {
  constructor(private readonly greetings: GreetingsService) {}
  @Get()
  list() {
    return this.greetings.languages();
  }
}

@Module({ controllers: [HelloController, LanguagesController], providers: [GreetingsService] })
export class GreetingsModule {}

הלוגיקה והשגיאה — ב־service; ה־controllers רק מתרגמים HTTP לקריאה. כך גם controller שלישי (למשל ל־WebSocket) ישתמש באותו קוד.

⚠️ טעויות נפוצות
  • if (!this.texts[lang]) — ‏GET /hello/constructor מוצא את Object.prototype.constructor (פונקציה!) ומחזיר 200. ‏Object.hasOwn (או Map, פרק 7) בודק רק מפתחות שבאמת הוספת. הבודק שולח בדיוק את זה.

P20-E36 · ‏AppModule שמייבא שני modules 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1
@Module({ imports: [HealthModule, CatalogModule] }) export class AppModule {}
💡 רמז 2

סדר בקובץ: מחלקה צריכה להיות מוגדרת לפני שמשתמשים בה ב־decorator — ה־modules הקטנים קודם, AppModule בסוף.

✅ פתרון
// P20-E36: AppModule שמייבא שני modules
import { Controller, Get, Injectable, Module, NotFoundException, Param, ParseIntPipe } from "@nestjs/common";

@Controller("health")
export class HealthController {
  @Get()
  check() {
    return { status: "ok" };
  }
}

@Module({ controllers: [HealthController] })
export class HealthModule {}

@Injectable()
export class CatalogService {
  private items = [
    { id: 1, name: "Mug" },
    { id: 2, name: "Kettle" },
    { id: 3, name: "Filters" },
  ];
  findOne(id: number) {
    const item = this.items.find((i) => i.id === id);
    if (!item) throw new NotFoundException(`פריט ${id} לא נמצא`);
    return item;
  }
}

@Controller("catalog")
export class CatalogController {
  constructor(private readonly catalog: CatalogService) {}
  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    return this.catalog.findOne(id);
  }
}

@Module({ controllers: [CatalogController], providers: [CatalogService] })
export class CatalogModule {}

@Module({ imports: [HealthModule, CatalogModule] })
export class AppModule {}

האפליקציה היא עץ של modules. כל module עומד בפני עצמו — הבודק מעלה כל אחד לבד, ואת AppModule שמחבר.

⚠️ טעויות נפוצות
  • לרשום את CatalogController גם ב־AppModule — הוא נרשם פעמיים, ו־CatalogService לא זמין ב־AppModule (שגיאת DI).

P20-E38 · מחיר עם מע״מ 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

באגורות:

const cents = Math.round(price * 100); const vatCents = Math.round(cents * 0.18);
💡 רמז 2

בסוף — חלוקה ב־100: vat: vatCents / 100, total: (cents + vatCents) / 100.

✅ פתרון
// P20-E38: מחיר עם מע״מ
import { Controller, Get, Injectable, Module, NotFoundException, Param, ParseIntPipe } from "@nestjs/common";

@Injectable()
export class PricesService {
  private products = [
    { id: 1, price: 89.9 },
    { id: 2, price: 19.9 },
    { id: 3, price: 0.1 },
  ];
  private readonly vatRate = 0.18;

  withVat(id: number) {
    const p = this.products.find((x) => x.id === id);
    if (!p) throw new NotFoundException(`מוצר ${id} לא נמצא`);
    const cents = Math.round(p.price * 100);
    const vatCents = Math.round(cents * this.vatRate);
    return { id, price: p.price, vat: vatCents / 100, total: (cents + vatCents) / 100 };
  }
}

@Controller("prices")
export class PricesController {
  constructor(private readonly prices: PricesService) {}
  @Get(":id")
  get(@Param("id", ParseIntPipe) id: number) {
    return this.prices.withVat(id);
  }
}

P20-E42 · ‏DI container קטן משלך 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שתי מפות: registry (token ← { deps, factory }) ו־instances (token ← המופע שנוצר).

💡 רמז 2

למעגלים — מחסנית של מה ש"בבנייה" עכשיו (building: string[]). אם token כבר בה — יש מעגל:

[...building.slice(building.indexOf(token)), token].join(" -> ")
✅ פתרון
// P20-E42: DI container קטן משלך
type Entry = { deps: string[]; factory: (...args: any[]) => unknown };

export class Container {
  private registry = new Map<string, Entry>();
  private instances = new Map<string, unknown>();
  private building: string[] = [];

  register(token: string, deps: string[], factory: (...args: any[]) => unknown): void {
    this.registry.set(token, { deps, factory });
  }

  get<T>(token: string): T {
    if (this.instances.has(token)) return this.instances.get(token) as T;
    const entry = this.registry.get(token);
    if (!entry) throw new Error(`Cannot resolve ${token}`);
    if (this.building.includes(token)) {
      const cycle = [...this.building.slice(this.building.indexOf(token)), token];
      throw new Error(`Circular dependency: ${cycle.join(" -> ")}`);
    }
    this.building.push(token);
    try {
      const args = entry.deps.map((dep) => {
        if (!this.registry.has(dep)) throw new Error(`Cannot resolve ${token}: missing ${dep}`);
        return this.get(dep);
      });
      const instance = entry.factory(...args);
      this.instances.set(token, instance);
      return instance as T;
    } finally {
      this.building.pop();
    }
  }
}

זה כל הרעיון: רשימה של "מה כל דבר צריך", ובנייה מהעלים לשורש, פעם אחת לכל דבר. Nest עושה את זה עם ה־metadata של TypeScript (emitDecoratorMetadata) במקום deps שכתבת ביד — ומוסיף modules, ‏scopes ו־hooks. ושגיאת ה"missing" שלך היא בדיוק "Nest can't resolve dependencies" מ־P20-E03.

⚠️ טעויות נפוצות
  • בלי מחסנית — מעגל הופך לרקורסיה אינסופית ו־Maximum call stack size exceeded.
  • לשמור את המופע לפני שה־factory סיים — מופע חלקי "דולף" לאחרים.

P20-E43 · ‏decorators משלך: @Route ו־routesOf 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

decorator של מתודה (‏experimentalDecorators) מקבל (target, propertyKey, descriptor), כש־target הוא ה־prototype. ה־class הוא target.constructor.

💡 רמז 2

decorators של מתודות רצים לפני ה־decorator של ה־class (המחלקה "נגמרת" אחרונה). לכן בונים את השורות רק ב־routesOf, ולא ב־Prefix.

✅ פתרון
// P20-E43: decorators משלך — @Route ו־routesOf
type RouteInfo = { method: string; path: string; handler: string };

const prefixes = new Map<Function, string>();
const routes = new Map<Function, RouteInfo[]>();

export function Prefix(path: string): ClassDecorator {
  return (target) => {
    prefixes.set(target, path);
  };
}

export function Route(method: "GET" | "POST" | "DELETE", path = ""): MethodDecorator {
  return (target, propertyKey) => {
    const cls = target.constructor;
    if (!routes.has(cls)) routes.set(cls, []);
    routes.get(cls)!.push({ method, path, handler: String(propertyKey) });
  };
}

export function routesOf(cls: Function): string[] {
  const prefix = prefixes.get(cls) ?? "";
  return (routes.get(cls) ?? []).map((r) => {
    const full = "/" + [prefix, r.path].filter((p) => p !== "").join("/");
    return `${r.method} ${full} -> ${r.handler}`;
  });
}

Nest עושה בדיוק את זה, עם Reflect.defineMetadata במקום Map שלך — ובעלייה עובר על כל ה־controllers ב־modules ובונה מה־metadata את ה־router של Express. ה־decorator עצמו לא "עושה" כלום בזמן בקשה; הוא רק משאיר מידע.

⚠️ טעויות נפוצות
  • prefixes.set(target.name, ...) לפי שם — שתי מחלקות בשם ProductsController (בשני modules) דורסות זו את זו.

P20-E44 · ‏service אסינכרוני — 404 ו־500 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

@Query("ids") ids: string — ואז ids.split(",").map(Number).

💡 רמז 2

לדלג על חסרים:

Promise.all(list.map((id) => this.findOne(id).catch((e) => (e instanceof NotFoundException ? null : Promise.reject(e)))))

ואז filter.

✅ פתרון
// P20-E44: service אסינכרוני — 404 ו־500
import { Controller, Get, Injectable, Module, NotFoundException, Param, ParseIntPipe, Query } from "@nestjs/common";

const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

@Injectable()
export class UsersService {
  private users = [
    { id: 1, name: "Dana" },
    { id: 2, name: "Yossi" },
  ];

  async findOne(id: number) {
    await sleep(20);
    if (id === 13) throw new Error("db timeout");
    const user = this.users.find((u) => u.id === id);
    if (!user) throw new NotFoundException(`משתמש ${id} לא נמצא`);
    return user;
  }

  async findMany(ids: number[]) {
    const found = await Promise.all(
      ids.map((id) => this.findOne(id).catch((e) => (e instanceof NotFoundException ? null : Promise.reject(e)))),
    );
    return found.filter((u) => u !== null);
  }
}

@Controller("users")
export class UsersController {
  constructor(private readonly users: UsersService) {}

  @Get()
  many(@Query("ids") ids = "") {
    return this.users.findMany(ids.split(",").filter((s) => s !== "").map(Number));
  }

  @Get(":id")
  one(@Param("id", ParseIntPipe) id: number) {
    return this.users.findOne(id);
  }
}

@Module({ controllers: [UsersController], providers: [UsersService] })
export class UsersModule {}

ה־catch הופך רק "לא נמצא" ל־null; תקלה אמיתית (db timeout) ממשיכה הלאה ← 500. ובזכות Promise.all — כל הקריאות רצות יחד (פרק 10).

⚠️ טעויות נפוצות
  • for ... of עם await — 10 מזהים לוקחים 200ms.
  • .catch(() => null) לכל שגיאה — תקלה במסד נראית כמו "המשתמש לא קיים".
