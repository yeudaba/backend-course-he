2. שלוש אבני בניין

src/products/products.service.ts 
import { Injectable, NotFoundException } from "@nestjs/common";

@Injectable()
export class ProductsService {
  private items = [{ id: 1, name: "Ceramic Mug", price: 39 }];

  findOne(id: number) {
    const product = this.items.find((p) => p.id === id);
    if (!product) throw new NotFoundException(`מוצר ${id} לא נמצא`);
    return product;
  }
}
src/products/products.controller.ts 
import { Controller, Get, Param, ParseIntPipe } from "@nestjs/common";
import { ProductsService } from "./products.service";

@Controller("products")
export class ProductsController {
  constructor(private readonly products: ProductsService) {}

  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    return this.products.findOne(id);
  }
}
src/products/products.module.ts 
import { Module } from "@nestjs/common";
import { ProductsController } from "./products.controller";
import { ProductsService } from "./products.service";

@Module({
  controllers: [ProductsController],
  providers: [ProductsService],
})
export class ProductsModule {}
  • Controller — routes. @Controller("products") + @Get(":id") = GET /products/:id. מה שהמתודה מחזירה הופך ל־JSON עם 200 (או 201 ל־POST). throw new NotFoundException(...) ← 404.
  • Provider — כל מה שמסומן @Injectable() ורשום ב־providers. כאן: הלוגיקה.
  • Module — קובץ שאומר ל־Nest "בתחום הזה יש את ה־controllers וה־providers האלה". האפליקציה היא module ראשי (AppModule) שמייבא את כל השאר.

שים לב: ה־imports בלי .ts בסוף. פרויקט Nest מתקמפל עם tsc (CommonJS), לא רץ ישירות כמו בפרקים הקודמים.

3. Dependency injection

constructor(private readonly products: ProductsService) — שני דברים בשורה אחת: (1) Nest רואה שה־controller צריך ProductsService ומזריק אותו; (2) private readonly בפרמטר יוצר שדה במחלקה (קיצור של TypeScript — "parameter property"). בקוד של Nest תראה את זה בכל מקום.

4. decorators — ולמה צריך build

@Controller("products") הוא פונקציה שרצה על ה־class ומצמידה לה מידע ("זה controller, בכתובת products"). Nest קורא את המידע בעלייה ובונה את ה־routes. ואיך Nest יודע ש־constructor צריך ProductsService? TypeScript, עם emitDecoratorMetadata, שומר את טיפוסי הפרמטרים בקוד ה־JavaScript שהוא מייצר.

שני הדברים — decorators בסגנון הזה ו־parameter properties — הם לא "רק טיפוסים": הם דורשים קוד JavaScript נוסף. לכן Node לא יכול "למחוק טיפוסים ולהריץ" (כמו בפרקים 11–19), ופרויקט Nest מתקמפל עם tsc ל־dist/. ה־CLI עושה את זה בשבילך (npm run start:dev).

5. פרויקט חדש

% cd ~/dev
% npx @nestjs/cli@12 new nest-playground --package-manager npm --strict
% cd nest-playground
% npm run start:dev

(דורש Node 24.) נוצר פרויקט עם src/main.ts (מפעיל), app.module.ts, controller ו־service לדוגמה, בדיקות (Jest) ו־tsconfig.json עם experimentalDecorators ו־emitDecoratorMetadata. פתח http://localhost:3000 — "Hello World!". ו־resource שלם בפקודה אחת:

% npx nest generate resource products --no-spec

(בוחרים REST API.) נוצרים module, controller, service ו־DTOs — ו־ProductsModule נרשם אוטומטית ב־AppModule. נוח, אבל כדאי לכתוב את הראשונים ביד כדי להבין מה נוצר.
