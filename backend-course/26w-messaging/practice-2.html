P26.5-E06 · topic exchange 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 20 דק׳ידע נדרש: שיעור 2

ב־26w-messaging/starter/P26.5-E06.ts:

  • setupTopology(ch, { exchange, emailQueue, analyticsQueue }) — topic exchange ושני תורים, כולם durable. emailQueue מקבל רק created ו־shipped; analyticsQueue — כל אירוע הזמנה.
  • publishOrderEvent(ch, exchange, event) — routing key order.<type>.<country באותיות קטנות>, גוף JSON, persistent, ו־messageId = event.id.

(השמות מגיעים כפרמטרים — הבודק נותן שמות ייחודיים לכל בדיקה, ומוחק אותם בסוף. בכל תרגילי RabbitMQ: COURSE_RABBIT_URL.)

P26.5-E07 · worker עם dead letter 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 25 דק׳ידע נדרש: שיעור 2

ב־P26.5-E07.ts:

  • setupWorkQueue(ch, { queue, deadLetterExchange, deadLetterQueue }) — exchange מסוג fanout ל־dead letters, התור שלו, ותור העבודה עם deadLetterExchange.
  • startWorker(ch, queue, handler, { prefetch }) — לכל הודעה: JSON ← handler ← ack. נכשל (גם JSON פגום) ← nack בלי requeue, כדי שתגיע ל־dead letter. ולא יותר מ־prefetch הודעות בטיפול בבת אחת.

P26.5-E18 · retry עם השהיה ב־RabbitMQ 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 30 דק׳ידע נדרש: שיעור 2

RabbitMQ לא יודע "תחזיר את ההודעה בעוד 5 שניות". הטריק: תור המתנה עם TTL. ב־P26.5-E18.ts:

  • setupRetry(ch, { queue, retryQueue, deadQueue }, delayMs) — nack ב־queue ← retryQueue; שם ההודעה מחכה delayMs ← חזרה ל־queue. ו־deadQueue.
  • startRetryingWorker(ch, names, handler, { maxAttempts }) — הצלחה ← ack. כישלון ← nack (לניסיון נוסף), ואחרי maxAttempts ניסיונות ← עותק ל־deadQueue עם headers x-attempts ו־x-error, ו־ack למקור.
