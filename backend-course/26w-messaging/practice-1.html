P26.5-E33 · ‏ack לפני או אחרי — לכל נקודת נפילה 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 1

בקובץ 26w-messaging/starter/P26.5-E33.ts (יש בו רק הערה) כתוב וייצא:

export function crashOutcomes(order: ("ack" | "handle")[]): { minHandled: number; maxHandled: number; guarantee: "at-most-once" | "at-least-once" | "exactly-once" }
  • order — סדר שני הצעדים של consumer (בדיוק "ack" ו־"handle", כל אחד פעם אחת; אחרת RangeError).
  • בודקים כל נקודת נפילה אפשרית: לפני הצעד הראשון, בין הצעדים, אחרי השני — וגם "לא נפל". נפל לפני ה־ack ← ההודעה נמסרת שוב, וה־consumer הבא עובר את שני הצעדים בלי ליפול.
  • לכל תרחיש סופרים כמה פעמים handle רץ בסך הכול. ‏minHandled/maxHandled — על כל התרחישים.
  • guarantee: ‏min 0 ← at-most-once; ‏max יותר מ־1 ← at-least-once; אחרת exactly-once.

P26.5-E34 · תור בזיכרון: ‏ack, ‏nack ונפילה 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 1

המודל של תור, בלי broker. בקובץ 26w-messaging/starter/P26.5-E34.ts (יש בו רק הערה) כתוב וייצא class MemoryQueue<T>:

  • push(msg) — לסוף התור. ‏size() — כמה ממתינות (לא כולל unacked).
  • receive(consumer) ← ‏{ tag, msg } מראש התור (ה־tag מספר עולה מ־1), או null. ההודעה עוברת ל־"unacked" של ה־consumer.
  • ack(tag) — נמחקת. ‏nack(tag, requeue) — ‏requeue ← חוזרת לראש התור; אחרת — נמחקת. tag לא מוכר (או שכבר טופל) ← Error.
  • crash(consumer) — כל ה־unacked שלו חוזרות לראש התור, בסדר שבו הוא קיבל אותן. מחזירה כמה.
  • unacked(consumer) — כמה מחזיק.

P26.5-E35 · ‏log בזיכרון: ‏partitions, ‏offsets ו־groups 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 1

המודל של log. בקובץ 26w-messaging/starter/P26.5-E35.ts (יש בו רק הערה) כתוב וייצא class MemoryLog:

  • constructor(partitions). ‏append(key, value) ← ‏{ partition, offset }. ה־partition: ‏hash(key) % partitions, כש־hash הוא סכום קודי התווים (charCodeAt) של ה־key. ה־offset — מספר רץ בתוך ה־partition, מ־0.
  • read(group, partition, max) ← עד max הודעות ({ offset, key, value }) החל מה־offset שה־group עשה לו commit (אין ← 0). קריאה לא מזיזה כלום.
  • commit(group, partition, nextOffset) — "הבא שאקרא". ‏lag(group) ← סכום על כל ה־partitions של (סוף ה־partition − committed).

  • התוצאות לפי סדר השירותים. כשל של אחד לא מפיל את האחרים, והפונקציה עצמה לא זורקת.
  • הזמן הכולל ≈ האיטי ביותר (עד timeoutMs), לא סכום.

🔗 איך זה מתחבר: ‏Promise.allSettled, ‏Promise.race ו־timeout מפרק 10 — והשיעור: מה broker חוסך.
