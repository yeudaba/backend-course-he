P07-E04 · destructuring 🧠 הבנה רמה 1

P07-E57 · עותק של מערך אובייקטים 🧠 הבנה רמה 2

💡 רמז 1

[...cart] יוצר מערך חדש, אבל האיברים שלו הם אותם חצים לאותם אובייקטים.

💡 רמז 2

push על copy — משנה רק את copy. copy[0].qty — משנה אובייקט ששני המערכים מצביעים עליו.

✅ פתרון
const cart = [{ name: "עט", qty: 1 }];
const copy = [...cart];
copy.push({ name: "תיק", qty: 1 });
copy[0].qty = 5;
console.log(cart.length, cart[0].qty);

const deep = structuredClone(cart);
deep[0].qty = 100;
console.log(cart[0].qty, deep[0].qty);

const updated = cart.map((item) => ({ ...item, qty: item.qty + 1 }));
console.log(cart[0].qty, updated[0].qty, updated[0] === cart[0]);
1 5
5 100
5 6 false

הקופסה של המערך שוכפלה, אבל העט לא: cart[0] ו־copy[0] הם אותו אובייקט, ולכן cart[0].qty הוא 5. structuredClone שכפל הכול. וה־map האחרון הוא הדרך המקובלת לעדכן "בלי לגעת": מערך חדש ואובייקטים חדשים.

⚠️ טעויות נפוצות
  • לחשוב ש־[...arr] מגן על האובייקטים שבפנים. הוא מגן רק על המערך עצמו (הוספה, הסרה, מיון).

P07-E58 · שוויון של אובייקטים 🧠 הבנה רמה 1

💡 רמז 2

P07-E59 · destructuring — מה נכנס לכל משתנה? 🧠 הבנה רמה 2

💡 רמז 1

total: amount — "קח את השדה total, ושים אותו במשתנה amount".

💡 רמז 2

ברירת מחדל ב־destructuring נכנסת רק כשהערך הוא undefined — לא כשהוא null.

✅ פתרון
const order = { id: 7, total: 320, customer: { name: "עומר" }, coupon: null };
const { id, total: amount, discount = 0, coupon = "אין" } = order;
console.log(id, amount, discount, coupon);

const { customer: { name } } = order;

let y = 2;

console.log(x, y);
7 320 0 null
עומר
א ב ג
2 1

coupon הוא null — ברירת המחדל "אין" לא נכנסת (בדיוק כמו ברירת מחדל של פרמטר, P05-E51). discount לא קיים בכלל (undefined) — ולכן כן מקבל 0. במערך, second קיבל undefined ולכן "ב". ולא נוצר משתנה total — רק amount.

⚠️ טעויות נפוצות
  • לסמוך על ברירת מחדל ב־destructuring כדי "לתפוס" null מהמסד. ל־null צריך ??.

P07-E60 · מה שורד את JSON? 🧠 הבנה רמה 2

💡 רמז 1

JSON יודע רק: מחרוזות, מספרים, true/false, null, מערכים ואובייקטים.

💡 רמז 2

שדה עם undefined או פונקציה — נעלם. בתוך מערך אי אפשר "להעלים" תא (המיקומים היו זזים) — אז הוא הופך ל־null. ו־NaN?

✅ פתרון
const event = {
  name: "כנס",
  date: new Date("2026-11-11T09:00:00Z"),
  price: NaN,
  note: undefined,
  tags: ["node", undefined],
  greet() {
    return "שלום";
  },
};
const text = JSON.stringify(event);
console.log(text);
const back = JSON.parse(text);
console.log(typeof back.date, back.note, "note" in back, back.greet);
{"name":"כנס","date":"2026-11-11T09:00:00.000Z","price":null,"tags":["node",null]}
string undefined false undefined

התאריך הפך למחרוזת, ואחרי parse הוא נשאר מחרוזת. NaN הפך ל־null. note ו־greet נעלמו לגמרי, וה־undefined במערך הפך ל־null. לכן שרת שמקבל JSON תמיד ממיר תאריכים בחזרה ובודק שדות — מה שנשלח הוא לא בדיוק מה שהיה.

⚠️ טעויות נפוצות
  • JSON.parse(JSON.stringify(obj)) כ"עותק עמוק" — מאבד תאריכים, פונקציות ו־undefined. בשביל זה יש structuredClone.

P07-E11 · עדכון בלי לשנות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

{ ...product, price: newPrice }

💡 רמז 2

without: const copy = { ...obj }; delete copy[key]; return copy;. withTag: { ...product, tags: [...product.tags, tag] }.

✅ פתרון
// P07-E11: עדכונים בלי לשנות את המקור
const withPrice = (product, newPrice) => ({ ...product, price: newPrice });

function without(obj, key) {
  const copy = { ...obj };
  delete copy[key];
  return copy;
}

const withTag = (product, tag) => ({ ...product, tags: [...product.tags, tag] });

const p = { name: "עט", price: 5, tags: ["משרד"] };
console.log(withPrice(p, 4), without(p, "tags"), withTag(p, "כחול"), p);

module.exports = { withPrice, without, withTag };
{ name: 'עט', price: 4, tags: [ 'משרד' ] } { name: 'עט', price: 5 } { name: 'עט', price: 5, tags: [ 'משרד', 'כחול' ] } { name: 'עט', price: 5, tags: [ 'משרד' ] }

(דרך נוספת ל־without: const { [key]: _, ...rest } = obj; return rest; — destructuring עם "שאר השדות".)

⚠️ טעויות נפוצות
  • withTag עם copy.tags.push(tag) — העותק הרדוד חולק את המערך עם המקור!

P07-E12 · query string 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

Object.entries(params).filter(...).map(([k, v]) => ${k}=${v}).join("&")

💡 רמז 2

parse: הסר ? אם יש, split("&"), ולכל זוג const [key, value] = pair.split("=").

✅ פתרון
// P07-E12: אובייקט ⇄ query string
function toQueryString(params) {
  return Object.entries(params)
    .filter(([, value]) => value !== null && value !== undefined)
    .map(([key, value]) => `${key}=${value}`)
    .join("&");
}

function parseQueryString(text) {
  const clean = text.startsWith("?") ? text.slice(1) : text;
  const result = {};
  if (clean === "") {
    return result;
  }
  for (const pair of clean.split("&")) {
    const [key, value = ""] = pair.split("=");
    result[key] = value;
  }
  return result;
}

console.log(toQueryString({ page: 2, sort: "price", q: null }));
console.log(parseQueryString("?page=2&sort=price"));

module.exports = { toQueryString, parseQueryString };
page=2&sort=price
{ page: '2', sort: 'price' }

בעולם האמיתי יש URLSearchParams מובנה, שגם מטפל בתווים מיוחדים ובעברית (קידוד %D7%A9...). נשתמש בו בפרק 14. וכאן רואים שוב: פרמטרים מה־URL הם תמיד מחרוזות.

⚠️ טעויות נפוצות
  • "".split("&") הוא [""] — בלי guard יווצר שדה בשם "".

P07-E16 · מיזוג הגדרות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

{ ...defaults, ...userSettings, notifications: { ...defaults.notifications, ...userSettings.notifications } }

💡 רמז 2

undefined: לפני המיזוג, סנן את userSettings — Object.fromEntries(Object.entries(userSettings).filter(([, v]) => v !== undefined)).

✅ פתרון
// P07-E16: מיזוג הגדרות עם רמה פנימית
function defined(obj = {}) {
  return Object.fromEntries(Object.entries(obj).filter(([, v]) => v !== undefined));
}

function mergeSettings(defaults, userSettings = {}) {
  const user = defined(userSettings);
  return {
    ...defaults,
    ...user,
    notifications: { ...defaults.notifications, ...defined(user.notifications) },
  };
}

const defaults = { theme: "light", language: "he", notifications: { email: true, sms: false } };
console.log(mergeSettings(defaults, { theme: "dark", language: undefined, notifications: { sms: true } }));

module.exports = { mergeSettings };
{
  theme: 'dark',
  language: 'he',
  notifications: { email: true, sms: true }
}

Object.fromEntries — ההפך של Object.entries: מערך זוגות ← אובייקט.

⚠️ טעויות נפוצות
  • { ...defaults, ...userSettings } בלבד — notifications של המשתמש מחליף לגמרי, ו־email נעלם.

P07-E17 · מה השתנה? (יומן שינויים) 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

כל המפתחות משני האובייקטים: new Set([...Object.keys(before), ...Object.keys(after)]).

💡 רמז 2

לכל מפתח: אם before[key] !== after[key] — שינוי.

✅ פתרון
// P07-E17: השוואת שני אובייקטים
function diff(before, after) {
  const keys = [...new Set([...Object.keys(before), ...Object.keys(after)])].sort();
  return keys
    .filter((key) => before[key] !== after[key])
    .map((key) => ({ key, from: before[key], to: after[key] }));
}

console.log(diff({ name: "עט", price: 5, color: "כחול" }, { name: "עט", price: 4, size: "M" }));

module.exports = { diff };
[
  { key: 'color', from: 'כחול', to: undefined },
  { key: 'price', from: 5, to: 4 },
  { key: 'size', from: undefined, to: 'M' }
]
⚠️ טעויות נפוצות
  • לעבור רק על המפתחות של before — שדות חדשים לא יופיעו.

P07-E22 · מפתחות ו־JSON 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

שדה ששמו במשתנה; סדר הזוגות ב־Object.entries; ו־=== בין אובייקטים.

💡 רמז 2

sameContent: השוואה של JSON.stringify של שניהם (עובד כשסדר השדות זהה).

✅ פתרון
// P07-E22: מתוקן
function getField(obj, fieldName) {
  return obj[fieldName];
}

function toLines(obj) {
  return Object.entries(obj).map(([key, value]) => `${key}: ${value}`);
}

function sameContent(a, b) {
  return JSON.stringify(a) === JSON.stringify(b);
}

console.log(getField({ city: "חיפה" }, "city"), toLines({ a: 1 }), sameContent({ x: [1] }, { x: [1] }));

module.exports = { getField, toLines, sameContent };
חיפה [ 'a: 1' ] true

(1) obj.fieldName מחפש שדה בשם "fieldName". (2) ([value, key]) — הסדר הפוך; הזוג הוא תמיד [key, value]. (3) a === b בודק אם זה אותו אובייקט. ההשוואה דרך JSON היא טריק — היא נכשלת אם סדר השדות שונה ({a, b} מול {b, a}). בבדיקות אוטומטיות יש לזה כלי מסודר: assert.deepEqual — בדיוק מה שהבודק שלך משתמש בו.

⚠️ טעויות נפוצות
  • לתקן את (3) ל־a == b — אותה בעיה.

P07-E26 · mapValues עם Object.fromEntries 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שלושה שלבים: Object.entries(obj) ← .map(...) ← Object.fromEntries(...).

💡 רמז 2

ב־map מקבלים זוג ומחזירים זוג: ([key, value]) => [key, fn(value)].

✅ פתרון
// P07-E26: mapValues
function mapValues(obj, fn) {
  return Object.fromEntries(Object.entries(obj).map(([key, value]) => [key, fn(value)]));
}

const prices = { keyboard: 100, mouse: 50 };
console.log(mapValues(prices, (p) => p * 2));
console.log(prices);

module.exports = { mapValues };
{ keyboard: 200, mouse: 100 }
{ keyboard: 100, mouse: 50 }

ה־map מקבל כל זוג ומפרק אותו מיד בפרמטר: ([key, value]). זה destructuring של מערך, כמו ב־for (const [item, qty] of Object.entries(stock)) משיעור 3. הוא מחזיר זוג חדש, ו־fromEntries מרכיב ממנו אובייקט חדש. בשום שלב לא נגענו ב־obj, ולכן הוא לא השתנה.

את אותו דפוס אפשר להפעיל גם עם filter באמצע. למשל, כך מסירים שדות ריקים מ־query string: Object.fromEntries(Object.entries(q).filter(([, v]) => v !== "")).

⚠️ טעויות נפוצות
  • .map((pair) => fn(pair)) — fn מקבלת את כל הזוג (["keyboard", 100]), ולא את הערך.
  • .map(([k, v]) => ({ [k]: fn(v) })) — יוצא מערך של אובייקטים קטנים, ו־fromEntries לא יודעת מה לעשות איתם.
  • for (const k in obj) obj[k] = fn(obj[k]) — עובד, אבל משנה את המקור.

P07-E61 · pick — רק השדות שביקשו 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

אובייקט ריק, ולולאה על keys. שם השדה במשתנה — סוגריים מרובעים, גם בקריאה וגם בכתיבה.

💡 רמז 2
for (const key of keys) {
  if (obj[key] !== undefined) {
    result[key] = obj[key];
  }
}
✅ פתרון
07-objects/starter/P07-E61.js 
function pick(obj, keys) {
  const result = {};
  for (const key of keys) {
    if (obj[key] !== undefined) {
      result[key] = obj[key];
    }
  }
  return result;
}

const user = { id: 1, name: "דנה", passwordHash: "x9f...", email: "d@m.com" };
console.log(pick(user, ["id", "name", "email"]), pick(user, ["id", "phone"]));

module.exports = { pick };
{ id: 1, name: 'דנה', email: 'd@m.com' } { id: 1 }

זה בדיוק מה ששרת עושה לפני שהוא שולח משתמש ללקוח: רשימה מותרת של שדות (allowlist). עדיף על "למחוק את הסודיים" — אם מחר יתווסף שדה סודי חדש, הוא לא ידלוף.

⚠️ טעויות נפוצות
  • result.key = obj.key — שדה אחד בשם "key".
  • delete על obj — משנה את המשתמש המקורי.

💡 רמז 1

function countBy(list, keyFn) {
  const counts = {};
  for (const item of list) {
    const key = keyFn(item);
    counts[key] = (counts[key] ?? 0) + 1;
  }
  return counts;
}

function topKeys(counts, n) {
  return Object.entries(counts)
    .sort((a, b) => b[1] - a[1] || a[0].localeCompare(b[0]))
    .slice(0, n)
    .map(([key]) => key);
}

const orders = [{ city: "חיפה" }, { city: "אילת" }, { city: "חיפה" }, { city: "באר שבע" }];

P07-E67 · מ־snake_case ל־camelCase 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

toCamel: split("_"). החלק הראשון — כמו שהוא; כל השאר — אות ראשונה גדולה. ה־callback של map מקבל גם אינדקס.

✅ פתרון
07-objects/starter/P07-E67.js 
function toCamel(key) {
  return key
    .split("_")
    .map((part, i) => (i === 0 ? part : part[0].toUpperCase() + part.slice(1)))
    .join("");
}

function camelizeKeys(row) {
  const result = {};
  for (const [key, value] of Object.entries(row)) {
    result[toCamel(key)] = value;
  }
  return result;
}

function camelizeRows(rows) {
  return rows.map(camelizeKeys);
}

console.log(camelizeKeys({ id: 7, first_name: "דנה", last_login_at: null }));

module.exports = { toCamel, camelizeKeys, camelizeRows };
{ id: 7, firstName: 'דנה', lastLoginAt: null }

rows.map(camelizeKeys) — מעבירים את הפונקציה עצמה. כאן זה בטוח: camelizeKeys משתמשת רק בפרמטר הראשון (בניגוד ל־parseInt ב־P06-E65).

⚠️ טעויות נפוצות
  • part[0].toUpperCase() על חלק ריק ("a__b") — undefined.toUpperCase(). בנתונים מהמסד זה לא קורה, אבל כדאי לדעת איפה זה נשבר.
