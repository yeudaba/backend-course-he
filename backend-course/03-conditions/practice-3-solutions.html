P03-E61 · truthy או falsy? 🧠 הבנה רמה 1

💡 רמז 1

יש רק שישה ערכים falsy: false, 0, "", null, undefined, NaN. כל השאר — truthy.

💡 רמז 2

מחרוזת שיש בה משהו — גם רווח, גם "0", גם "false" — היא truthy.

✅ פתרון
console.log(Boolean("0"), Boolean(0), Boolean(" "), Boolean(""), Boolean(null));
console.log(Boolean(NaN), Boolean("false"), Boolean(-1), Boolean(undefined), Boolean(0.0));
true false true false false
false true true false false

Boolean(x) מחזיר בדיוק את מה ש־if (x) "רואה". הכי מבלבלים: "0" ו־"false" (טקסט עם תוכן ← truthy), ו־" " (רווח הוא תוכן).

⚠️ טעויות נפוצות
  • -1 falsy — לא. רק אפס הוא falsy מבין המספרים (ו־NaN).

P03-E62 · ?? או ||? 🧠 הבנה רמה 2

💡 רמז 1

?? מחליף רק null ו־undefined. || מחליף כל ערך falsy.

💡 רמז 2

שורה 2: "" אינו null — אז ?? משאיר אותו.

✅ פתרון
const a = 0;
const b = "";
const c = null;
const d = undefined;
const e = "שלום";
console.log(a ?? 5, a || 5);
console.log(b ?? "ברירת מחדל", b || "ברירת מחדל");
console.log(c ?? 5, c || 5);
console.log(d ?? 5, d || 5);
console.log(e ?? "x", e || "x");
0 5

5 5
5 5
שלום שלום

(בשורה 2 הערך הראשון הוא מחרוזת ריקה — לכן נראה רק רווח לפני "ברירת מחדל".)

  1. פריטים בעמוד: שני הכלים עובדים כאן, אבל ?? עדיף כברירת מחדל כללית — ואת 0 דוחים בבדיקה נפרדת ("חייב להיות לפחות 1").
  2. אחוז הנחה: ?? — אחרת הנחה של 0 תהפוך לברירת המחדל.
  3. כינוי: || — כאן ריק באמת אומר "אין", ורוצים להחליף גם אותו.
⚠️ טעויות נפוצות
  • להשתמש ב־|| תמיד "כי זה עובד". זה עובד — עד שמישהו שולח 0.

P03-E16 · ברירות מחדל לחיפוש 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

בחר לכל אחד ?? או || לפי השאלה: האם 0 / "" הם ערכים חוקיים?

💡 רמז 2

ל־limit צריך תנאי נוסף מעבר לברירת מחדל: (limit < 1 || limit > 100) ? 20 : limit.

✅ פתרון
03-conditions/starter/P03-E16.js 
const pageParam = undefined;
const limitParam = 0;
const sortParam = "";
const minPriceParam = 0;

const page = pageParam ?? 1;
const rawLimit = limitParam ?? 20;

P03-E21 · הרשאה פרוצה 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

role === "admin" || "owner" — מה הצד הימני של ה־||, לבדו?

💡 רמז 2

!age < 18 — ! מחושב לפני <. מה זה !17?

✅ פתרון

באג 1: "viewer" === "admin" || "owner" ← false || "owner" ← "owner" (truthy). כל תפקיד עובר.

באג 2: ! מחושב לפני <: !17 < 18 ← false < 18 ← (false מומר ל־0) 0 < 18 ← true. כלומר isAdult יוצא true לכל גיל שאינו 0.

const role = "viewer";
const age = 17;

const isAllowedRole = role === "admin" || role === "owner";
const isAdult = age >= 18;

console.log("מותר לצפות?", isAllowedRole && isAdult);
מותר לצפות? false

"מעל 18" בדרישה — האם 18 עצמו מותר? בעבודה אמיתית זו שאלה למנהל המוצר. כאן בחרנו >= 18 (גיל בגירות). שאלות כאלה על גבולות הן חלק מהעבודה.

⚠️ טעויות נפוצות
  • לתקן ל־!(age < 18) — תקין, אבל age >= 18 קריא יותר.

P03-E22 · כשאפס הוא ערך 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

|| מחליף כל ערך falsy, כולל 0.

💡 רמז 2

במלאי: מה יקרה אם stock יהיה undefined (המלאי לא נטען)? מה יודפס?

✅ פתרון
const savedShippingFee = 0;
const savedClubDiscount = 0;
const stock = 0;

const clubDiscount = savedClubDiscount ?? 5;

  console.log("מלאי: לא ידוע");
} else if (stock === 0) {
  console.log("מלאי: אזל");
} else {
  console.log("מלאי:", stock);

על המלאי: הפלט יצא נכון "במקרה" — כי ה־else if תפס את 0. אבל אם stock יהיה undefined, הקוד המקורי לא ידפיס כלום (אף תנאי לא מתקיים ואין else). הקוד המתוקן מטפל בשלושת המצבים במפורש.

P03-E26 · שעות פתיחה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

איזה תנאי בודקים קודם? אם שבת — לא משנה מה השעה. "בשעות הפתיחה" הם שני תנאים שחייבים להתקיים יחד.

💡 רמז 2

hour >= 8 && hour < 20. ל"שעה" מול "6 שעות" — ternary על 20 - hour.

✅ פתרון
03-conditions/starter/P03-E26.js 
const hour = 14;
const isSaturday = false;

if (isSaturday) {
  console.log("שבת — סגור");
} else if (hour >= 8 && hour < 20) {
  const left = 20 - hour;
  const leftText = left === 1 ? "שעה" : `${left} שעות`;
  console.log(`${hour}:00 — פתוח (נסגר בעוד ${leftText})`);
} else {
  console.log(`${hour}:00 — סגור`);
}
14:00 — פתוח (נסגר בעוד 6 שעות)

הסדר חשוב: שבת קודם. אם בודקים קודם את השעה, ב־14:00 בשבת יודפס "פתוח". זה אותו עיקרון כמו בבדיקת הזמנה (E24): התנאי שגובר על כל השאר — ראשון.

hour < 20 ולא <= 20: ב־20:00 החנות כבר סגורה. גבולות של טווח הם המקום הקלאסי לטעות "אחד מדי" (off-by-one).

⚠️ טעויות נפוצות
  • hour >= 8 || hour < 20 — כל מספר מקיים לפחות אחד מהשניים, ולכן החנות "פתוחה" גם ב־3 בלילה.
  • (נסגר בעוד ${20 - hour} שעות) בלי מקרה מיוחד — ב־19:00 יודפס "1 שעות".

P03-E66 · שני באגים קלאסיים 🧠 הבנה רמה 2

💡 רמז 1

א: "guest" === "admin" הוא false. ואז false || "owner" — מה זה, ואיך if רואה אותו?

💡 רמז 2

ב: !age קודם. !30 הוא false. ו־false > 18?

✅ פתרון
const role = "guest";
const age = 30;
if (role === "admin" || "owner") {
  console.log("א: גישה למערכת הניהול");
}
if (!age > 18) {
  console.log("ב: קטין");
} else {
  console.log("ב: לא קטין");
}
if (!(age > 18)) {
  console.log("ג: עד גיל 18");
}
א: גישה למערכת הניהול
ב: לא קטין
  • א: false || "owner" ← "owner" — מחרוזת עם תוכן, truthy. אורח קיבל גישה! תיקון: role === "admin" || role === "owner".
  • ב: !30 ← false ← 0 > 18 ← false — אז "לא קטין". נכון במקרה. עם age = 0? !0 ← true ← 1 > 18 ← false. אף פעם לא "קטין".

⚠️ טעויות נפוצות
  • לראות ש"ב" הדפיס תשובה נכונה ולהסיק שהקוד תקין. בודקים כמה ערכים, לא אחד.

P03-E67 · ?? ו־Number 🧠 הבנה רמה 2

💡 רמז 1

אחרי Number(...) כבר אין null או undefined — יש מספר (או NaN). אז ?? אחרי ההמרה כמעט אף פעם לא עושה כלום.

console.log(Number(null) ?? 10);

0

1
NaN

⚠️ טעויות נפוצות
  • Number(pageParam) ?? 1 — כש־pageParam חסר, יוצא NaN, ו־?? לא מחליף NaN.

P03-E68 · "0" עובר, 0 לא 🧠 הבנה רמה 2

💡 רמז 1

"0" הוא מחרוזת עם תו אחד — truthy. 0 המספר — falsy.

💡 רמז 2

ג: שני התנאים חייבים להתקיים. האם 0 גדול מ־0?

✅ פתרון
const qtyInput = "0";
if (qtyInput) {
  console.log("א: הוזן משהו");
}
const qty = Number(qtyInput);
if (qty) {
  console.log("ב: יש כמות");
} else {
  console.log("ב: אין כמות");
}
if (qtyInput.trim() !== "" && qty > 0) {
  console.log("ג: כמות חיובית");
}
א: הוזן משהו
ב: אין כמות

"הוזן משהו" שואל על הטקסט; "כמות חיובית" שואל על המספר. if (x) עונה על אחת מהן — תלוי מה הסוג של x באותו רגע — וזה בדיוק מה שמבלבל. השוואה מפורשת (!== "", > 0) אומרת לקורא איזו שאלה נשאלה.

⚠️ טעויות נפוצות
  • לחשוב ש־if (qtyInput) ידחה "0". הוא לא — הוא דוחה רק טקסט ריק לגמרי.

P03-E27 · מספר טלפון לתצוגה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

מתודות שכבר פגשת בפרק 2: trim, replaceAll, slice, startsWith, ו־length.

💡 רמז 2

phoneInput.trim().replaceAll("-", "").replaceAll(" ", ""). "3 הראשונות" — slice(0, 3); "4 האחרונות" — slice(-4).

✅ פתרון
03-conditions/starter/P03-E27.js 
const phoneInput = " 054-123 4567 ";

const digits = phoneInput.trim().replaceAll("-", "").replaceAll(" ", "");

if (digits.length !== 10 || !digits.startsWith("05")) {
  console.log(`מספר לא תקין: ${phoneInput.trim()}`);
} else {
  const prefix = digits.slice(0, 3);
  console.log(`נקי: ${digits}`);
  console.log(`לתצוגה: ${prefix}-${digits.slice(3)}`);
  console.log(`מוסתר: ${prefix}-***${digits.slice(-4)}`);
}
נקי: 0541234567
לתצוגה: 054-1234567
מוסתר: 054-***4567

למה מנקים לפני שבודקים: את האורך בודקים על מה שנשאר אחרי הניקוי. " 054-123 4567 " הוא 14 תווים, אבל 10 ספרות. כך עובדים גם בשרת אמיתי: קודם מנרמלים, אחר כך בודקים, ושומרים במסד את הגרסה הנקייה.

בדיקה מלאה הייתה גם מוודאת שכל התווים הם ספרות. את זה עושים עם ביטוי רגולרי (regex), שנלמד בפרק 13.

⚠️ טעויות נפוצות
  • replace("-", "") — מחליף רק את המקף הראשון.
  • digits.length !== 10 && !digits.startsWith("05") — מספר של 9 ספרות שמתחיל ב־05 יעבור. כל אחד מהשניים לבד כבר הופך את המספר ללא תקין, ולכן ||.

P03-E69 · שם תצוגה עם ברירת מחדל 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

קודם הפוך null למחרוזת ריקה: const nickname = (nicknameInput ?? "").trim();.

💡 רמז 2

if (nickname !== "") { ... } else { ... } — ובענף של השם הפרטי: name[0].toUpperCase() + name.slice(1).

✅ פתרון
03-conditions/starter/P03-E69.js 
const firstName = " dana ";
const nicknameInput = null;
const nickname = (nicknameInput ?? "").trim();
let displayName;
if (nickname !== "") {
  displayName = nickname;
} else {
  const name = firstName.trim();
  displayName = name[0].toUpperCase() + name.slice(1);
}
console.log(`שלום, ${displayName}!`);
שלום, Dana!
⚠️ טעויות נפוצות
  • nicknameInput.trim() ישירות — TypeError: Cannot read properties of null (reading 'trim').
  • nicknameInput ?? firstName — מטפל ב־null, אבל כינוי של רווחים בלבד "עובר".

P03-E70 · משלוח היום? 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שלושה משתנים: isSameDay (ביטוי עם שני &&), isFree (ביטוי עם ||), fee.

💡 רמז 2

let fee = 15 + Math.max(0, distanceKm - 10) * 2; ואז if (isFree) { fee = 0; }.

✅ פתרון
03-conditions/starter/P03-E70.js 
const orderHour = 11;
const isWeekday = true;
const distanceKm = 18;
const total = 120;
const isClubMember = false;
const isSameDay = isWeekday && orderHour < 14 && distanceKm <= 30;
const isFree = total >= 300 || isClubMember;
let fee = 15 + Math.max(0, distanceKm - 10) * 2;
if (isFree) {
  fee = 0;
}
console.log(`משלוח היום? ${isSameDay}`);
console.log(`דמי משלוח: ${fee.toFixed(2)} ₪`);
משלוח היום? true
דמי משלוח: 31.00 ₪
⚠️ טעויות נפוצות
  • orderHour <= 14 — הזמנה ב־14:00 "לפני 14:00"? לא.
  • לכתוב את דמי המשלוח עם if למרחקים קטנים — Math.max כבר מטפל בזה.
