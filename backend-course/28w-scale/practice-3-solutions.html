P28.5-E10 · פירוק NDJSON בזרם 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

StringDecoder שומר בתים של תו שלא נגמר עד ה־chunk הבא. chunk.toString() — לא.

💡 רמז 2

buffer של טקסט: מוסיפים, מפצלים ב־\n, והחלק האחרון חוזר ל־buffer. ב־flush — מה שנשאר.

✅ פתרון
// P28.5-E10: Transform שמפרק NDJSON לאובייקטים — גם כש־chunk נחתך באמצע שורה, ובאמצע תו
import { Transform, type TransformCallback } from "node:stream";
import { StringDecoder } from "node:string_decoder";

export function ndjsonParser(): Transform {
  const decoder = new StringDecoder("utf8"); // מחזיק בתים של תו שנחתך עד שה־chunk הבא משלים אותו
  let buffer = "";
  let lineNo = 0;
  function pushLine(this: Transform, line: string): Error | null {
    lineNo++;
    if (line.trim() === "") return null;
    try {
      this.push(JSON.parse(line));
      return null;
    } catch {
      return new Error(`שורה ${lineNo}: JSON לא תקין`);
    }
  }
  return new Transform({
    readableObjectMode: true,
    transform(chunk: Buffer, _enc, cb: TransformCallback) {
      buffer += decoder.write(chunk);
      const lines = buffer.split("\n");
      buffer = lines.pop()!; // השורה האחרונה אולי עוד לא הסתיימה
      for (const l of lines) {
        const err = pushLine.call(this, l.replace(/\r$/, ""));
        if (err) return cb(err);
      }
      cb();
    },
    flush(cb: TransformCallback) {
      buffer += decoder.end();
      cb(pushLine.call(this, buffer.replace(/\r$/, "")) ?? undefined); // שורה אחרונה בלי \n
    },
  });
}
⚠️ טעויות נפוצות
  • chunk.toString().split("\n") לכל chunk — עובד בבדיקה עם קובץ קטן (chunk אחד), ונשבר בפרודקשן על קובץ של 1GB: שורות חתוכות, ו־� במקום אותיות (E20).

// P28.5-E11: אגרגציה על קובץ ענק — שורה אחרי שורה, בזיכרון קבוע
import { createInterface } from "node:readline";
import type { Readable } from "node:stream";

export interface DayTotals {
  orders: number;
  revenueCents: number;
}

const dayFmt = new Intl.DateTimeFormat("en-CA", { timeZone: "Asia/Jerusalem", year: "numeric", month: "2-digit", day: "2-digit" });
export const israelDay = (iso: string) => dayFmt.format(new Date(iso)); // "2026-10-31"

export async function dailyRevenue(input: Readable): Promise<Record<string, DayTotals>> {
  const totals: Record<string, DayTotals> = {};
  const lines = createInterface({ input, crlfDelay: Infinity });
  for await (const line of lines) {
    if (!line.trim()) continue;
    const o = JSON.parse(line) as { createdAt: string; quantity: number; priceCents: number; status?: string };
    if (o.status === "cancelled") continue;
    const day = israelDay(o.createdAt);
    const t = (totals[day] ??= { orders: 0, revenueCents: 0 });
    t.orders++;
    t.revenueCents += o.quantity * o.priceCents;
  }
  return totals;
}

הזיכרון כאן קבוע: שורה אחת בכל רגע, ומפה של ~30 ימים. אותו קוד יעבוד על 300 אלף שורות ועל 300 מיליון. ההפך — (await fs.readFile(f, "utf8")).split("\n") — טוען את כל הקובץ לזיכרון (ומחרוזת ב־V8 מוגבלת בכל מקרה לכחצי מיליארד תווים).

// P28.5-E12: הכנסה של הרבה שורות — מעט round trips, עם unnest
import type { Pool } from "pg";

export interface PageView {
  id: string;
  userId: number;
  path: string;
  at: string;
}

export async function bulkInsertViews(pool: Pool, rows: PageView[], { batchSize = 5000 } = {}): Promise<number> {
  let inserted = 0;
  for (let i = 0; i < rows.length; i += batchSize) {
    const b = rows.slice(i, i + batchSize);
    // ארבעה מערכים — ארבעה פרמטרים, לא 4 × 5000 (ל־PostgreSQL יש תקרה של 65,535 פרמטרים בשאילתה)
    const res = await pool.query(
      `INSERT INTO page_views (id, user_id, path, viewed_at)
       SELECT * FROM unnest($1::text[], $2::int[], $3::text[], $4::timestamptz[])
       ON CONFLICT (id) DO NOTHING`,
      [b.map((r) => r.id), b.map((r) => r.userId), b.map((r) => r.path), b.map((r) => r.at)],
    );
    inserted += res.rowCount ?? 0;
  }
  return inserted;
}

למה לא VALUES ($1,$2,$3,$4), ($5,…)? אפשר — אבל 5,000 שורות × 4 = 20,000 פרמטרים, ו־PostgreSQL מגביל ל־65,535 בשאילתה. עם unnest — תמיד 4. ולמיליוני שורות: COPY … FROM STDIN (החבילה pg-copy-streams), המהיר מכולם.

P28.5-E19 · reservoir sampling 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

k הראשונים נכנסים. הפריט ה־n (n > k): מגרילים j בין 0 ל־n−1; אם j < k — מחליף את sample[j].

💡 רמז 2

for await (const x of items) עובד גם על iterable רגיל.

✅ פתרון
// P28.5-E19: reservoir sampling — דגימה אחידה מזרם שלא יודעים את אורכו
export async function reservoirSample<T>(items: Iterable<T> | AsyncIterable<T>, k: number, random: () => number = Math.random): Promise<T[]> {
  if (!Number.isInteger(k) || k < 1) throw new Error("k חייב להיות שלם חיובי");
  const sample: T[] = [];
  let seen = 0;
  for await (const item of items) {
    seen++;
    if (sample.length < k) sample.push(item);
    else {
      const j = Math.floor(random() * seen); // 0..seen-1
      if (j < k) sample[j] = item; // הסיכוי של הפריט ה־n להיכנס: k/n
    }
  }
  return sample;
}

💡 רמז 1

קובץ קטן מגיע כ־chunk אחד. קובץ גדול — בחתיכות של 64KB, שלא מתחשבות בשורות או בתווים.

💡 רמז 2

onEvent(…) בלי await — כמה רצים במקביל?

✅ פתרון
// P28.5-E20: ייבוא אירועים מ־NDJSON — אחרי התיקון
import { createInterface } from "node:readline";
import type { Readable } from "node:stream";

export async function importEvents(input: Readable, onEvent: (e: any) => Promise<void>): Promise<number> {
  let count = 0;
  // תיקון 1+2: readline מחבר שורות שנחתכו בין chunks (וגם תו עברי שנחתך), ומחזיר גם שורה אחרונה בלי \n
  for await (const line of createInterface({ input, crlfDelay: Infinity })) {
    if (!line.trim()) continue;
    await onEvent(JSON.parse(line)); // תיקון 3: מחכים — backpressure, ושגיאה עולה למעלה
    count++;
  }
  return count;
}

P28.5-E26 · הנפוצים ביותר בזרם, בזיכרון קבוע 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שדה #counters = new Map<T, { count: number; error: number }>(). ב־add, שלושת המקרים לפי הסדר עם return אחרי כל אחד. ‏counter.count++ על האובייקט שב־Map מעדכן אותו במקום, בלי set נוסף.

💡 רמז 2

מציאת המינימום: לולאת for (const [key, c] of this.#counters) עם min ו־minItem. זה O(k) לכל החלפה. עם k של עשרות זה זניח, ובגרסאות מהירות מחזיקים את המונים ברשימה ממוינת. אחר כך delete(minItem) ו־set(item, { count: min + 1, error: min }).

✅ פתרון
// P28.5-E26 — הנפוצים ביותר בזרם, בזיכרון קבוע (Space-Saving)
export type Counted<T> = { item: T; count: number; error: number };

export class TopK<T> {
  #k: number;
  #counters = new Map<T, { count: number; error: number }>();
  #seen = 0;

  constructor(k: number) {
    if (!Number.isInteger(k) || k < 1) throw new RangeError("k חייב להיות מספר שלם חיובי");
    this.#k = k;
  }

  add(item: T): void {
    this.#seen++;
    const counter = this.#counters.get(item);
    if (counter) {
      counter.count++;
      return;
    }
    if (this.#counters.size < this.#k) {
      this.#counters.set(item, { count: 1, error: 0 });
      return;
    }
    // מחליפים את המונה הקטן ביותר: החדש "יורש" את הספירה שלו (וזו גם הטעות האפשרית)
    let minItem: T | undefined;
    let min = Infinity;
    for (const [key, c] of this.#counters) {
      if (c.count < min) {
        min = c.count;
        minItem = key;
      }
    }
    this.#counters.delete(minItem as T);
    this.#counters.set(item, { count: min + 1, error: min });
  }

  get seen(): number {
    return this.#seen;
  }

  top(n = this.#k): Counted<T>[] {
    return [...this.#counters]
      .map(([item, c]) => ({ item, count: c.count, error: c.error }))
      .sort((a, b) => b.count - a.count || String(a.item).localeCompare(String(b.item)))
      .slice(0, n);
  }
}

// זרם של 100,000 בקשות: 3 נתיבים "חמים" ו־5,000 נתיבים שמופיעים מעט
let seed = 1;
const rand = () => ((seed = (seed * 1103515245 + 12345) % 2 ** 31) / 2 ** 31);
const topk = new TopK<string>(20);
const truth = new Map<string, number>();
for (let i = 0; i < 100_000; i++) {
  const r = rand();
  const path = r < 0.2 ? "/products" : r < 0.3 ? "/cart" : r < 0.35 ? "/checkout" : `/products/${Math.floor(rand() * 5000)}`;
  topk.add(path);
  truth.set(path, (truth.get(path) ?? 0) + 1);
}
for (const { item, count, error } of topk.top(4)) {
  console.log(item.padEnd(16), String(count).padStart(6), `(אמיתי: ${truth.get(item)}, טעות עד ${error})`);
}

שלושת הנתיבים החמים נספרו בדיוק, או כמעט: ב־/checkout הטעות האפשרית היא 6, מתוך 5,550. השורה הרביעית היא השיעור: ‏/products/1237 הופיע 31 פעמים, אבל המונה שלו הוא 3,759, כי הוא "ירש" מונה של פריט אחר. ה־error (‏3,758) אומר את זה במפורש: ייתכן שהוא הופיע רק count - error = פעם אחת. לכן מציגים רק פריטים עם count - error גבוה, או לפחות מראים את הטעות.

למה זה עובד? סכום כל המונים תמיד שווה ל־N (כל add מוסיף 1 בדיוק). לכן המונה הקטן ביותר הוא לכל היותר N/k. פריט שהופיע יותר מ־N/k פעמים לא יכול להימחק לצמיתות: בכל פעם שהוא חוזר, הוא מקבל מונה גדול מהמינימום. זה גם המבנה של "trending" ב־Redis ‏(TOPK ב־RedisBloom) ובמנועי סטרימינג.

⚠️ טעויות נפוצות
  • החדש מקבל count: 1 במקום min + 1 — הוא יימחק מיד בפעם הבאה, ופריט חם שנכנס מאוחר לא "יטפס" לעולם.
  • לשכוח את error — אי אפשר להבדיל בין 3,759 אמיתיים ל־3,759 שעברו בירושה.
  • לשמור Map של הכול "רק לבדיקה" — זה בדיוק מה שהאלגוריתם חוסך.
  • top() שממיין את ה־Map עצמו — ‏Map לא ממוין; יוצרים מערך חדש.
