P28.5-E24 · אתגר: API אנליטיקה תחת עומס 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 60 דק׳ידע נדרש: שיעור 5

ב־P28.5-E24.ts: createAnalyticsServer({ parquetPath, cacheTtlMs, cacheSize, now }) מחזירה http.Server (הבודק קורא ל־listen):

  • GET /revenue?from=YYYY-MM-DD&to=YYYY-MM-DD ← { from, to, days: [{ day, orders, revenue }], total: { orders, revenue } } — ימים בשעון ישראל, כולל שני הקצוות; revenue בשקלים (2 ספרות). תאריך לא תקין, from אחרי to, או טווח של יותר מ־92 ימים ← 400.
  • GET /top-products?day=…&limit=… ← [{ product, units, revenue }], מההכנסה הגבוהה; limit 1–20, ברירת מחדל 5.
  • cache: LRU של cacheSize תשובות ל־cacheTtlMs, עם header X-Cache: HIT/MISS. ה־now מוזרק — הבודק מזיז אותו.
  • תחת עומס (300 בקשות, 10 במקביל) — p95 מתחת ל־50ms.

P28.5-E25 · אתגר: data lake מצטבר 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 60 דק׳ידע נדרש: שיעור 5

הזמנות ב־PostgreSQL (files/lake.sql) משתנות כל הזמן — מתבטלות, מתעדכנות. ב־P28.5-E25.ts:

  • syncOrders({ pool, conn, lakeDir, pageSize }) — מעתיקה ל־lakeDir רק שורות ששונו מאז הסנכרון הקודם, לקובץ חדש part-00001.parquet, part-00002.parquet… (append-only — לא נוגעים בקבצים קיימים). ה"עד איפה הגעתי" (watermark) נשמר ב־lakeDir/_state.json, ונכתב רק אחרי שהקובץ קיים. אין שינויים ← אין קובץ, { exported: 0, file: null }.
  • lakeReport(conn, lakeDir) — הזמנות והכנסה לכל יום (שעון ישראל, לפי created_at), לפי הגרסה האחרונה של כל הזמנה, בלי מבוטלות — זהה למה ש־PostgreSQL אומר.
