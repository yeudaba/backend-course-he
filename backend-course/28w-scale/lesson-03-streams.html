שיעור 3 — נתונים גדולים בזרם

⏱ ~40 דקות

🎯 בשיעור הזה
  • למה "לקרוא הכול לזיכרון" נשבר — ומה זה זיכרון קבוע.
  • streams: chunks, pipeline, ו־backpressure.
  • NDJSON, ושני הבאגים הקלאסיים של chunks.
  • לכתוב הרבה שורות למסד — ולדגום מזרם.

1. זיכרון קבוע

export של הזמנות, לוג של יום, קובץ של לקוח — 5GB. await fs.readFile(file, "utf8") ינסה לטעון את כולו לזיכרון: התהליך יקרוס (ומחרוזת ב־V8 מוגבלת לכחצי מיליארד תווים בכל מקרה). הדרך הנכונה: stream — הקובץ מגיע ב־chunks של 64KB, מעבדים כל אחד וממשיכים. הזיכרון תלוי בגודל ה־chunk ובמה ששומרים (סכומים, מונים) — לא בגודל הקובץ. אותו קוד עובד על 5MB ועל 5TB.

2. pipeline ו־backpressure

stream שקורא מהר (דיסק) וכותב לאט (מסד) — מה קורה לנתונים שבאמצע? בלי מנגנון, הם מצטברים בזיכרון עד קריסה. backpressure: כשהצרכן לא עומד בקצב, היצרן עוצר. pipeline מחבר streams עם backpressure וטיפול בשגיאות מובנים:

import { createReadStream, createWriteStream } from "node:fs";
import { createGzip } from "node:zlib";
import { pipeline } from "node:stream/promises";

// קורא, דוחס וכותב — בזיכרון קבוע, ושגיאה בכל שלב סוגרת את כולם
await pipeline(createReadStream("orders.ndjson"), createGzip(), createWriteStream("orders.ndjson.gz"));

וב־for await על stream, backpressure מגיע בחינם — אם מחכים: הלולאה לא מבקשת chunk חדש לפני שה־await בתוכה הסתיים. onEvent(e) בלי await מבטל את זה: הקריאה רצה במלוא המהירות, ואלפי INSERT יוצאים במקביל (E20).

3. NDJSON

JSON רגיל — מערך אחד גדול — חייב להיקרא כולו לפני שאפשר לפרש אותו. NDJSON (או JSON Lines): אובייקט בכל שורה. אפשר לקרוא שורה, לפרש, ולהמשיך; אפשר להוסיף לסוף הקובץ; אפשר לפצל אותו בכל שורה. זה הפורמט של exports מ־BigQuery, של לוגים מובנים (פרק 24), ושל הרבה APIs של streaming. הדרך הקלה לקרוא אותו בזרם:

import { createReadStream } from "node:fs";
import { createInterface } from "node:readline";

for await (const line of createInterface({ input: createReadStream("orders.ndjson"), crlfDelay: Infinity })) {
  if (!line) continue;
  const order = JSON.parse(line);
  // … אגרגציה בזיכרון קבוע (E11)
}

4. לכתוב הרבה, ולדגום

הצד השני — לכתוב מיליון שורות למסד. INSERT לכל שורה = מיליון round trips; גם ב־1ms כל אחד, זה רבע שעה. במקום: batch — אלפי שורות בשאילתה אחת עם unnest של מערכים (E12), או COPY — הפקודה של PostgreSQL לטעינה מרוכזת, המהירה מכולן. ו־ON CONFLICT DO NOTHING הופך את הטעינה לאידמפוטנטית: אפשר להריץ שוב קובץ שנכשל באמצע.

ולפעמים לא צריך את כל הנתונים: "1,000 שורות אקראיות מהלוג, לבדיקה" — reservoir sampling בוחר k פריטים אחידים מזרם באורך לא ידוע, במעבר אחד ובזיכרון של k (E19).
