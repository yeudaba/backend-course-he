P28.5-E28 · דוח של בדיקת עומס 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 2⏱ 20 דק׳ידע נדרש: פרק 2, פרק 6, שיעור 1

  • report(results): string — טבלת טקסט. שורת כותרת: name, ‏req/s, ‏p50 ms, ‏p99 ms, ועמודה חמישית בלי כותרת. אחריה שורה לכל תוצאה, מהמהיר (req/s הגבוה) לאיטי:

P28.5-E40 · ‏middleware של histogram ו־GET /slo 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 30 דק׳ידע נדרש: פרק 15, שיעור 1

בקובץ 28w-scale/starter/P28.5-E40.ts (יש בו רק הערה) כתוב וייצא:

export function sloMetrics(opts: { buckets: number[]; latencyMs: number; target: number; now?: () => number }): { middleware: express.RequestHandler; router: express.Router }
  • middleware — מודד כל בקשה (מ־now() בתחילתה ועד אירוע "finish"; ברירת מחדל performance.now) ומוסיף 1 לדלי הראשון ש־ms <= bucket; גדול מכולם ← דלי "+Inf". סופר גם 5xx.
  • router — ‏GET /slo ← ‏{ total, errors, buckets, good, ok }: ‏buckets — מערך מונים באורך buckets.length + 1 (האחרון ‏+Inf). ‏good — בקשות בלי 5xx ובדלי שהגבול שלו <= latencyMs (‏latencyMs חייב להיות אחד הגבולות — אחרת שגיאה ביצירה). ‏ok — ‏good / total >= target (אין בקשות ← true). הבקשה ל־/slo עצמה לא נספרת.

🔗 איך זה מתחבר: ‏middleware ו־Router מפרק 15, ו־histogram מפרק 24 — והשיעור: לבדוק SLO מתוך דליים, בלי לשמור כל מדידה.
