P28.5-E03 · מי חוסם את ה־event loop? 🧠 הבנה רמה 1

💡 רמז 1

ה־event loop הוא thread אחד. timer יכול לרוץ רק כשה־JavaScript הנוכחי מסתיים.

💡 רמז 2

pbkdf2 עם callback רץ ב־thread pool של libuv — לא ב־thread של JavaScript.

✅ פתרון
import { pbkdf2, pbkdf2Sync } from "node:crypto";

// מתזמנים timer של 10ms, ומיד מתחילים עבודה. השאלה: ה־timer רץ בזמן העבודה, או רק אחריה?
function measure(label: string, work: (done: () => void) => void) {
  return new Promise<void>((resolve) => {
    let timerAt = 0;
    let doneAt = 0;
    const report = () => {
      if (!timerAt || !doneAt) return;
      console.log(`${label.padEnd(16)} ${timerAt < doneAt ? "timer fired while the work was running" : "timer waited until the work finished"}`);
      resolve();
    };
    setTimeout(() => ((timerAt = performance.now()), report()), 10);
    work(() => ((doneAt = performance.now()), report()));
  });
}

await measure("pbkdf2Sync", (done) => {
  pbkdf2Sync("pw", "salt", 1_000_000, 32, "sha256");
  done();
});
await measure("pbkdf2 (async)", (done) => pbkdf2("pw", "salt", 1_000_000, 32, "sha256", () => done()));
await measure("busy loop", (done) => {
  let x = 0;
  for (let i = 0; i < 300_000_000; i++) x += i;
  done();
});
pbkdf2Sync       timer waited until the work finished
pbkdf2 (async)   timer fired while the work was running
busy loop        timer waited until the work finished

pbkdf2Sync ולולאת החישוב תופסים את ה־thread היחיד של JavaScript — שום timer, שום בקשת HTTP ושום health check לא ייענו עד שיסתיימו. ב־API עם 100 משתמשים, התחברות אחת "מקפיאה" את כולם. pbkdf2 האסינכרוני עושה בדיוק את אותה עבודה — ב־thread אחר. עבודת CPU של JavaScript עצמו (הלולאה) — מעבירים ל־worker thread (E13).

P28.5-E13 · worker threads 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

new Worker(WORKER_CODE, { eval: true }), worker.postMessage([from, to]), worker.on("message", …).

💡 רמז 2

תור משותף של טווחים: כל worker שמסיים — מקבל את הבא. Promise לכל worker שמסתיים כשהתור ריק.

✅ פתרון
// P28.5-E13: עבודת CPU ב־worker threads — כדי שה־event loop ימשיך לענות
import { Worker } from "node:worker_threads";

// הקוד שרץ בכל worker (מוכן): מקבל [from, to] ומחזיר כמה ראשוניים יש בטווח
export const WORKER_CODE = `
const { parentPort } = require("node:worker_threads");
parentPort.on("message", ([from, to]) => {
  let count = 0;
  for (let n = Math.max(2, from); n < to; n++) {
    let prime = true;
    for (let d = 2; d * d <= n; d++) if (n % d === 0) { prime = false; break; }
    if (prime) count++;
  }
  parentPort.postMessage(count);
});`;

export async function countPrimesParallel(limit: number, { threads = 4, chunks = 16 } = {}): Promise<number> {
  const size = Math.ceil(limit / chunks);
  const ranges: [number, number][] = Array.from({ length: chunks }, (_, i) => [i * size, Math.min(limit, (i + 1) * size)]);
  let next = 0;
  let total = 0;
  const workers = Array.from({ length: Math.min(threads, ranges.length) }, () => new Worker(WORKER_CODE, { eval: true }));
  try {
    // כל worker לוקח את הטווח הבא כשהוא מסיים — כך אף אחד לא יושב בטל
    await Promise.all(
      workers.map(
        (w) =>
          new Promise<void>((resolve, reject) => {
            const giveNext = () => {
              if (next >= ranges.length) return resolve();
              w.postMessage(ranges[next++]);
            };
            w.on("message", (count: number) => {
              total += count;
              giveNext();
            });
            w.on("error", reject);
            giveNext();
          }),
      ),
    );
  } finally {
    await Promise.all(workers.map((w) => w.terminate()));
  }
  return total;
}

worker threads הם לא "async": כל worker הוא thread נוסף עם V8 משלו (כ־10MB זיכרון, ועשרות ms לעלות). לכן — pool קבוע, לא worker לכל בקשה (בפרודקשן: piscina). ולעבודה ש־Node כבר מריץ ב־thread pool (crypto, zlib, fs) — מספיקה הגרסה האסינכרונית (E03, E23).

✅ פתרון
// P28.5-E14: מוניטור ל־event loop — מתריע כשמשהו חוסם
import { monitorEventLoopDelay } from "node:perf_hooks";

export interface LagReport {
  p99Ms: number;
  maxMs: number;
}

export function startLagMonitor({ thresholdMs, intervalMs = 1000, onLag }: { thresholdMs: number; intervalMs?: number; onLag: (r: LagReport) => void }): () => void {
  const h = monitorEventLoopDelay({ resolution: 10 });
  h.enable();
  const timer = setInterval(() => {
    const report = { p99Ms: Math.round(h.percentile(99) / 1e6), maxMs: Math.round(h.max / 1e6) }; // ננו־שניות ← מילי
    h.reset(); // כל חלון נמדד בנפרד
    if (report.maxMs >= thresholdMs) onLag(report);
  }, intervalMs);
  timer.unref(); // מוניטור לא אמור להשאיר את התהליך חי
  return () => {
    clearInterval(timer);
    h.disable();
  };
}

בפרודקשן מייצאים את זה כמדד (nodejs_eventloop_lag_seconds ב־prom-client) ומתריעים עליו: p99 lag של 200ms אומר שכל בקשה בשרת הזה מחכה עד 200ms — לפני שהקוד שלה בכלל התחיל.

✅ פתרון
// P28.5-E23: שרת שה־event loop שלו פנוי — אחרי התיקון
import http from "node:http";
import { pbkdf2 } from "node:crypto";
import { gzip } from "node:zlib";
import { promisify } from "node:util";
import { setTimeout as sleep } from "node:timers/promises";

const pbkdf2Async = promisify(pbkdf2);
const gzipAsync = promisify(gzip);
const SALT = "coffee-salt";
const EXPORT = Buffer.from(JSON.stringify(Array.from({ length: 200_000 }, (_, i) => ({ id: i, name: `order-${i}`, total: i % 997 }))));

export function createServer(): http.Server {
  return http.createServer(async (req, res) => {
    try {
      if (req.url === "/health") return void res.end("ok");
      if (req.url === "/login") {
        // תיקון 1: pbkdf2 האסינכרוני רץ ב־thread pool של libuv, לא על ה־event loop
        const hash = await pbkdf2Async("secret-password", SALT, 200_000, 32, "sha256");
        return void res.end(hash.toString("hex").slice(0, 8));
      }
      if (req.url === "/export") {
        const body = await gzipAsync(EXPORT); // תיקון 2: גם gzip — ב־thread pool
        res.setHeader("content-encoding", "gzip");
        return void res.end(body);
      }
      if (req.url === "/slow") {
        await sleep(300); // תיקון 3: המתנה שלא חוסמת (במקום while על Date.now)
        return void res.end("done");
      }
      res.statusCode = 404;
      res.end();
    } catch {
      res.statusCode = 500;
      res.end();
    }
  });
}

איך מוצאים את זה בפרודקשן: מוניטור lag (E14) מראה שה־event loop נחסם; ואז node --cpu-prof (או clinic flame) — פרופיל שמראה באיזו פונקציה ה־CPU בילה. pbkdf2Sync בראש ה־flame graph — וזהו.
