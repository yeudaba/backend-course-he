P28.5-E03 · מי חוסם את ה־event loop? 🧠 הבנה רמה 1

💡 רמז 1

ה־event loop הוא thread אחד. timer יכול לרוץ רק כשה־JavaScript הנוכחי מסתיים.

💡 רמז 2

pbkdf2 עם callback רץ ב־thread pool של libuv — לא ב־thread של JavaScript.

✅ פתרון
import { pbkdf2, pbkdf2Sync } from "node:crypto";

// מתזמנים timer של 10ms, ומיד מתחילים עבודה. השאלה: ה־timer רץ בזמן העבודה, או רק אחריה?
function measure(label: string, work: (done: () => void) => void) {
  return new Promise<void>((resolve) => {
    let timerAt = 0;
    let doneAt = 0;
    const report = () => {
      if (!timerAt || !doneAt) return;
      console.log(`${label.padEnd(16)} ${timerAt < doneAt ? "timer fired while the work was running" : "timer waited until the work finished"}`);
      resolve();
    };
    setTimeout(() => ((timerAt = performance.now()), report()), 10);
    work(() => ((doneAt = performance.now()), report()));
  });
}

await measure("pbkdf2Sync", (done) => {
  pbkdf2Sync("pw", "salt", 1_000_000, 32, "sha256");
  done();
});
await measure("pbkdf2 (async)", (done) => pbkdf2("pw", "salt", 1_000_000, 32, "sha256", () => done()));
await measure("busy loop", (done) => {
  let x = 0;
  for (let i = 0; i < 300_000_000; i++) x += i;
  done();
});
pbkdf2Sync       timer waited until the work finished
pbkdf2 (async)   timer fired while the work was running
busy loop        timer waited until the work finished

pbkdf2Sync ולולאת החישוב תופסים את ה־thread היחיד של JavaScript — שום timer, שום בקשת HTTP ושום health check לא ייענו עד שיסתיימו. ב־API עם 100 משתמשים, התחברות אחת "מקפיאה" את כולם. pbkdf2 האסינכרוני עושה בדיוק את אותה עבודה — ב־thread אחר. עבודת CPU של JavaScript עצמו (הלולאה) — מעבירים ל־worker thread (E13).

P28.5-E42 · חוסם או לא? 🧠 הבנה רמה 1

💡 רמז 1

חסימה = הקוד שלך רץ על ה־thread הראשי ולא משחרר אותו. "לוקח זמן" ≠ "חוסם".

💡 רמז 2

שאל גם: כמה זמן, וכמה פעמים בשנייה?

✅ פתרון
  1. חוסם, אבל לא בעיה: פעם אחת, לפני שיש בקשות.
  2. חוסם ובעיה: עשרות ms לכל העלאה, וכל השרת מחכה.
  3. לא חוסם (thread pool). אבל 40MB בזיכרון לכל בקשה — עדיף stream (שיעור 3).
  4. חוסם, זניח: מיקרו־שניות.
  5. חוסם ובעיה: מאות ms עד שניות של CPU, ומחרוזת ענקית בזיכרון. ‏stream של NDJSON, או עימוד.
  6. לא חוסם: ה־await מחכה; השרת משרת אחרים. (400ms זו בעיה אחרת — אינדקס.)
  7. חוסם, זניח.
⚠️ טעויות נפוצות
  • "async = לא חוסם" — async function שמריצה לולאה של שנייה חוסמת שנייה. ה־await רק משחרר כשמחכים למשהו חיצוני.

P28.5-E45 · ‏regex שמפיל שרת 🧠 הבנה רמה 1

💡 רמז 1

💡 רמז 2

כשההתאמה מצליחה, המנוע עוצר מיד. רק כישלון מכריח לנסות את כל החלוקות.

✅ פתרון

P28.5-E13 · worker threads 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

new Worker(WORKER_CODE, { eval: true }), worker.postMessage([from, to]), worker.on("message", …).

💡 רמז 2

תור משותף של טווחים: כל worker שמסיים — מקבל את הבא. Promise לכל worker שמסתיים כשהתור ריק.

✅ פתרון
// P28.5-E13: עבודת CPU ב־worker threads — כדי שה־event loop ימשיך לענות
import { Worker } from "node:worker_threads";

// הקוד שרץ בכל worker (מוכן): מקבל [from, to] ומחזיר כמה ראשוניים יש בטווח
export const WORKER_CODE = `
const { parentPort } = require("node:worker_threads");
parentPort.on("message", ([from, to]) => {
  let count = 0;
  for (let n = Math.max(2, from); n < to; n++) {
    let prime = true;
    for (let d = 2; d * d <= n; d++) if (n % d === 0) { prime = false; break; }
    if (prime) count++;
  }
  parentPort.postMessage(count);
});`;

export async function countPrimesParallel(limit: number, { threads = 4, chunks = 16 } = {}): Promise<number> {
  const size = Math.ceil(limit / chunks);
  const ranges: [number, number][] = Array.from({ length: chunks }, (_, i) => [i * size, Math.min(limit, (i + 1) * size)]);
  let next = 0;
  let total = 0;
  const workers = Array.from({ length: Math.min(threads, ranges.length) }, () => new Worker(WORKER_CODE, { eval: true }));
  try {
    // כל worker לוקח את הטווח הבא כשהוא מסיים — כך אף אחד לא יושב בטל
    await Promise.all(
      workers.map(
        (w) =>
          new Promise<void>((resolve, reject) => {
            const giveNext = () => {
              if (next >= ranges.length) return resolve();
              w.postMessage(ranges[next++]);
            };
            w.on("message", (count: number) => {
              total += count;
              giveNext();
            });
            w.on("error", reject);
            giveNext();
          }),
      ),
    );
  } finally {
    await Promise.all(workers.map((w) => w.terminate()));
  }
  return total;
}

worker threads הם לא "async": כל worker הוא thread נוסף עם V8 משלו (כ־10MB זיכרון, ועשרות ms לעלות). לכן — pool קבוע, לא worker לכל בקשה (בפרודקשן: piscina). ולעבודה ש־Node כבר מריץ ב־thread pool (crypto, zlib, fs) — מספיקה הגרסה האסינכרונית (E03, E23).

💡 רמז 1

💡 רמז 2

timer.unref().

✅ פתרון
// P28.5-E14: מוניטור ל־event loop — מתריע כשמשהו חוסם
import { monitorEventLoopDelay } from "node:perf_hooks";

export interface LagReport {
  p99Ms: number;
  maxMs: number;
}

export function startLagMonitor({ thresholdMs, intervalMs = 1000, onLag }: { thresholdMs: number; intervalMs?: number; onLag: (r: LagReport) => void }): () => void {
  const h = monitorEventLoopDelay({ resolution: 10 });
  h.enable();
  const timer = setInterval(() => {
    const report = { p99Ms: Math.round(h.percentile(99) / 1e6), maxMs: Math.round(h.max / 1e6) }; // ננו־שניות ← מילי
    h.reset(); // כל חלון נמדד בנפרד
    if (report.maxMs >= thresholdMs) onLag(report);
  }, intervalMs);
  timer.unref(); // מוניטור לא אמור להשאיר את התהליך חי
  return () => {
    clearInterval(timer);
    h.disable();
  };
}

בפרודקשן מייצאים את זה כמדד (nodejs_eventloop_lag_seconds ב־prom-client) ומתריעים עליו: p99 lag של 200ms אומר שכל בקשה בשרת הזה מחכה עד 200ms — לפני שהקוד שלה בכלל התחיל.

✅ פתרון
// P28.5-E23: שרת שה־event loop שלו פנוי — אחרי התיקון
import http from "node:http";
import { pbkdf2 } from "node:crypto";
import { gzip } from "node:zlib";
import { promisify } from "node:util";
import { setTimeout as sleep } from "node:timers/promises";

const pbkdf2Async = promisify(pbkdf2);
const gzipAsync = promisify(gzip);
const SALT = "coffee-salt";
const EXPORT = Buffer.from(JSON.stringify(Array.from({ length: 200_000 }, (_, i) => ({ id: i, name: `order-${i}`, total: i % 997 }))));

export function createServer(): http.Server {
  return http.createServer(async (req, res) => {
    try {
      if (req.url === "/health") return void res.end("ok");
      if (req.url === "/login") {
        // תיקון 1: pbkdf2 האסינכרוני רץ ב־thread pool של libuv, לא על ה־event loop
        const hash = await pbkdf2Async("secret-password", SALT, 200_000, 32, "sha256");
        return void res.end(hash.toString("hex").slice(0, 8));
      }
      if (req.url === "/export") {
        const body = await gzipAsync(EXPORT); // תיקון 2: גם gzip — ב־thread pool
        res.setHeader("content-encoding", "gzip");
        return void res.end(body);
      }
      if (req.url === "/slow") {
        await sleep(300); // תיקון 3: המתנה שלא חוסמת (במקום while על Date.now)
        return void res.end("done");
      }
      res.statusCode = 404;
      res.end();
    } catch {
      res.statusCode = 500;
      res.end();
    }
  });
}

איך מוצאים את זה בפרודקשן: מוניטור lag (E14) מראה שה־event loop נחסם; ואז node --cpu-prof (או clinic flame) — פרופיל שמראה באיזו פונקציה ה־CPU בילה. pbkdf2Sync בראש ה־flame graph — וזהו.

💡 רמז 2

✅ פתרון
// P28.5-E47: לעבד מערך גדול בלי לחסום
const pause = () => new Promise<void>((resolve) => setImmediate(resolve));

export async function mapInChunks<T, R>(items: T[], fn: (item: T, index: number) => R, chunkSize = 1000): Promise<R[]> {
  if (!Number.isInteger(chunkSize) || chunkSize <= 0) throw new RangeError("chunkSize חייב להיות שלם חיובי");
  const out: R[] = [];
  for (let i = 0; i < items.length; i++) {
    out.push(fn(items[i], i));
    if ((i + 1) % chunkSize === 0) await pause();
  }
  return out;
}

‏setImmediate ולא await Promise.resolve(): ‏microtask רץ לפני שה־event loop ממשיך לבקשות אחרות — כלומר הוא לא משחרר כלום. ‏setImmediate נותן ל־I/O ול־timers לרוץ.

⚠️ טעויות נפוצות
  • ‏await null בין חתיכות — נראה כמו הפסקה, אבל זה microtask: השרת עדיין חסום.
  • הזמן הכולל ארוך קצת יותר — זה המחיר. העבודה לא נהיית קלה יותר; היא רק מפסיקה לחסום.

P28.5-E48 · מי הכי רחב ב־flame graph? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שני Maps: ‏self ו־total. לכל דגימה: ‏new Set(stack) ל־total, ו־stack.at(-1) ל־self.

💡 רמז 2

אחוז: Math.round((n / samples.length) * 1000) / 10.

✅ פתרון
// P28.5-E48: מי הכי רחב ב־flame graph?
export function hotFunctions(samples: string[][], top = 5) {
  const self = new Map<string, number>();
  const total = new Map<string, number>();
  for (const stack of samples) {
    for (const name of new Set(stack)) total.set(name, (total.get(name) ?? 0) + 1);
    const leaf = stack.at(-1);
    if (leaf !== undefined) self.set(leaf, (self.get(leaf) ?? 0) + 1);
  }
  const pct = (n: number) => Math.round((n / samples.length) * 1000) / 10;
  return [...total.keys()]
    .map((name) => ({ name, self: pct(self.get(name) ?? 0), total: pct(total.get(name)!) }))
    .sort((a, b) => b.self - a.self || b.total - a.total || (a.name < b.name ? -1 : a.name > b.name ? 1 : 0))
    .slice(0, top);
}

‏total גבוה ו־self נמוך (כמו handleRequest) — פונקציה שקוראת לדבר היקר. ‏self גבוה — היא עצמה היקרה. בדרך כלל מחפשים את השנייה.

⚠️ טעויות נפוצות
  • לספור פונקציה רקורסיבית כמה פעמים באותה דגימה — ה־total עובר 100%.

P28.5-E49 · ‏semaphore: לכל היותר N בבת אחת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

מונה running ומערך queue של פונקציות "התחל אותי".

💡 רמז 2

‏run:

if (running >= max) await new Promise<void>((r) => queue.push(r))

running++;

try { return await fn() } finally { running--; queue.shift()?.() }
✅ פתרון
// P28.5-E49: semaphore — לכל היותר N בבת אחת
export function createSemaphore(max: number, maxQueue = Infinity) {
  if (!Number.isInteger(max) || max <= 0) throw new RangeError("max חייב להיות שלם חיובי");
  let running = 0;
  const queue: (() => void)[] = [];

  async function run<T>(fn: () => Promise<T>): Promise<T> {
    if (running >= max) {
      if (queue.length >= maxQueue) throw new Error("busy: התור מלא");
      await new Promise<void>((resolve) => queue.push(resolve));
    }
    running++;
    try {
      return await fn();
    } finally {
      running--;
      queue.shift()?.();
    }
  }

  return { run, active: () => running, waiting: () => queue.length };
}

הסדר חשוב: ‏running++ קורה רק אחרי שהגיע התור — וה־finally מעיר את הבא רק אחרי running--. כך המונה לא עובר את max.

⚠️ טעויות נפוצות
  • לשחרר בתוך then ולא ב־finally — ‏fn שנכשלת לא משחררת, ואחרי max כישלונות הכול תקוע לנצח.

export function buildSearch(q: string): RegExp {

// P28.5-E51: JSON ענק בחתיכות
export function* jsonArrayChunks(items: unknown[], perChunk = 500): Generator<string> {
  if (items.length === 0) {
    yield "[]";
    return;
  }
  for (let i = 0; i < items.length; i += perChunk) {
    const body = items.slice(i, i + perChunk).map((x) => JSON.stringify(x) ?? "null").join(",");
    const last = i + perChunk >= items.length;
    yield (i === 0 ? "[" : ",") + body + (last ? "]" : "");
  }
}

// P28.5-E56: load shedding לפי event loop lag
import type { Request, Response, NextFunction } from "express";

export function shedLoad(opts: { getLagMs: () => number; maxLagMs: number; exempt?: string[] }) {
  const { getLagMs, maxLagMs, exempt = ["/health", "/ready"] } = opts;
  return (req: Request, res: Response, next: NextFunction) => {
    const lag = getLagMs();
    res.set("X-Lag-Ms", String(Math.round(lag)));
    if (exempt.includes(req.path) || lag <= maxLagMs) return next();
    res.set("Retry-After", "2").status(503).json({ error: "overloaded" });
  };
}

בפרודקשן getLagMs מגיע מ־monitorEventLoopDelay (‏E14), למשל p99 של השנייה האחרונה. ו־503 עם Retry-After אומר ל־load balancer ולקוחות טובים "נסה שרת אחר / עוד רגע".

⚠️ טעויות נפוצות

const derive = (password: string, salt: string) =>
  new Promise<string>((resolve, reject) => {
    pbkdf2(password, salt, 100_000, 32, "sha256", (err, key) => (err ? reject(err) : resolve(key.toString("hex"))));
  });

export async function deriveAll(passwords: string[], salt: string, limit = 2): Promise<string[]> {
  const out: string[] = new Array(passwords.length);
  let next = 0;
  async function worker() {
    while (next < passwords.length) {
      const i = next++;
      out[i] = await derive(passwords[i], salt);
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, passwords.length) }, worker));
  return out;
}
