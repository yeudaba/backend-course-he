יחידה 28.5 — ביצועים ונתונים בקנה מידה

⏱ 4 מפגשים

🧰 לפני שמתחילים — יחידה 28.5

מה צריך שכבר יהיה מותקן: PostgreSQL מפרק 16. בלי קונטיינרים חדשים.

מה מתקינים עכשיו:

  • npm install בתיקיית הקורס — מוסיף את @duckdb/node-api: DuckDB, מנוע SQL אנליטי (עמודתי) שרץ בתוך תהליך ה־Node, בלי שרת — וקורא Parquet, CSV ו־JSON ישירות. (חבילה עם רכיב native; npm מוריד את הגרסה המתאימה ל־Mac/Windows/Linux אוטומטית.)
  • לא חובה — npx autocannon (בדיקת עומס מהטרמינל) ו־clinic (פרופיילינג). בתרגילים לא צריך אותם.

📂 העתקת חומרי הפרק: ב־Finder, העתק את התיקייה 28w-scale מתוך ~/Desktop/Backend/backend-course אל ~/dev/backend-course (גרירה עם ⌥ Option). אם התיקייה כבר שם מהעתקה קודמת ואתה רוצה לשמור את מה שכתבת — בחר Keep Both / Stop ולא Replace.

✔ בדיקה: cd ~/dev/backend-course && npm install && npm run check P28.5-E15 ← הבודק טוען 60,000 הזמנות מ־files/orders.parquet ל־DuckDB, ונכשל על הקובץ הריק שלך.

🎯 בסוף הפרק תדע
  • למדוד נכון: percentiles במקום ממוצע, histograms שמתאחדים, בדיקת עומס, וחוק Little לתכנון קיבולת.
  • Node.js תחת עומס: מה חוסם את ה־event loop, thread pool מול worker threads, ומוניטור lag.
  • נתונים גדולים בזרם: streams, NDJSON, backpressure, הכנסה מרוכזת ודגימה.
  • OLTP מול OLAP: אחסון עמודתי, Parquet ו־DuckDB, partitions, ועלות שאילתה במחסני נתונים (BigQuery, Snowflake, Databricks).
  • לחבר הכול: data lake מצטבר מ־PostgreSQL, ו־API אנליטי שעומד ב־SLO.

🤔 למה צריך את זה?

"נפחי נתונים גדולים ותעבורה גבוהה" — כך מסתיימות הרבה מודעות דרושים, והן מתכוונות לשני דברים. הראשון: שרת שמקבל אלפי בקשות בשנייה, ושבו בקשה אחת שחוסמת את ה־event loop עוצרת את כולם; שם לא שואלים "זה עובד?" אלא "מה ה־p99, ומה יקרה בשיא?". השני: טבלאות של מיליארדי שורות, שאילתות אנליטיות שסורקות אותן, ו־BigQuery, Snowflake או Databricks שמחייבים לפי כל בית שנסרק. בפרק 28 תכננת מערכות על הלוח; ביחידה הזו תמדוד, תמצא צווארי בקבוק, ותעבוד עם נתונים בצורה שבה עובדים איתם בקנה מידה — עמודות, partitions, streams — עם DuckDB שרץ אצלך בתוך Node.
