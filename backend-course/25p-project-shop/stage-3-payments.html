שיעור 4 — שלב 3: Idempotency, תשלום, ביטול ומשלוח

⏱ ~240 דקות · 🤖 PR3-PAY

🎯 בשלב הזה
  • מכונת מצבים להזמנה.
  • תשלום מדומה — כולל כישלון — עם Idempotency-Key.
  • ביטול שמחזיר מלאי (פעם אחת!), ומשלוח.

1. מכונת המצבים

שים את הטבלה הזו במקום אחד, כפונקציה טהורה (nextStatus(current, action)) — היא הדבר הכי קל לבדוק ב־unit test בפרויקט. ובמסד — מעבר מותנה: UPDATE orders SET status = 'cancelled' WHERE id = $1 AND status IN ('pending_payment', 'paid'). שני ביטולים במקביל: רק אחד מקבל count = 1 — ורק הוא מחזיר מלאי. בלי זה, ביטול כפול מחזיר את המלאי פעמיים (הבודק מנסה 5 במקביל).

2. תשלום מדומה

POST /orders/:id/pay עם { cardNumber } ו־Idempotency-Key (חיוב כפול גרוע מהזמנה כפולה). הספק המדומה עובד עם מספרי הכרטיסים "לבדיקות" שמקובלים בתעשייה:

כרטיסתוצאה
4242 4242 4242 4242 (וכל כרטיס תקין אחר)מצליח ← 200, status: "paid", paidAt
4000 0000 0000 0002נדחה ← 402 PAYMENT_DECLINED, ההזמנה נשארת pending_payment
4000 0000 0000 9995אין כיסוי ← 402 PAYMENT_DECLINED
לא עובר Luhn (ספרת ביקורת)400 — לא מגיע בכלל לספק
  • רווחים ומקפים במספר — מותרים ("4242 4242 4242 4242").
  • הספק מאחורי ממשק (PaymentGateway, provider ב־Nest): מחר מחליפים בספק אמיתי בלי לגעת בהזמנות.
  • מספר כרטיס מלא — לא נשמר, לא ב־log ולא בתשובה. 4 ספרות אחרונות מספיקות ("ויזה שמסתיימת ב־4242"). זה גם מה ש־PCI DSS, התקן של חברות האשראי, דורש בפועל.
  • כל ניסיון (גם נדחה) — שורה בטבלת payments: מה ניסו, מתי, והתוצאה.

מהפתרון לדוגמה (פלטים אמיתיים, מקוצרים):

% curl -s -X POST localhost:3000/orders/1/pay -H "Authorization: Bearer $T" -H 'Idempotency-Key: pay-dana-0001' \
  -H 'content-type: application/json' -d '{"cardNumber":"4000 0000 0000 0002"}'
{"error":{"code":"PAYMENT_DECLINED","message":"התשלום נדחה","details":[{"reason":"declined"}]}}
% curl -s -X POST localhost:3000/orders/1/pay … -H 'Idempotency-Key: pay-dana-0002' -d '{"cardNumber":"4242424242424242"}'
{"id":1,"userId":2,"status":"paid","totalCents":49800,…,"paidAt":"2026-11-08T07:00:01.561Z",…}
% curl -s -X POST localhost:3000/orders/1/cancel -H "Authorization: Bearer $T"
{"id":1,"userId":2,"status":"cancelled","totalCents":49800,…}

שים לב למפתח: ניסיון שני = מפתח חדש. אותו מפתח היה מחזיר שוב את ה־402 — "אותה בקשה, אותה תשובה". והביטול של הזמנה ששולמה מחזיר גם את הכסף (ב־refund של הספק המדומה, ושורה refunded ב־payments).

3. לבדוק

% npm run check PR3-PAY -- --dir ~/dev/coffee-shop

PR3-PAY: Idempotency-Key חובה; Luhn ← 400; שני סוגי דחייה ← 402 וההזמנה ממתינה; הצלחה; תשלום כפול ← 409; מספר הכרטיס לא בתשובה; 4 בקשות במקביל עם אותו מפתח; הזמנה של אחר ← 404; ביטול מחזיר מלאי, ביטול כפול לא מחזיר פעמיים; משלוח רק למנהל ורק אחרי תשלום; אחרי משלוח — אין ביטול; ו־5 ביטולים במקביל.
