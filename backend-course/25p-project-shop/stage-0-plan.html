2. החוזה

הבודק לא קורא את הקוד שלך — הוא מדבר עם השרת. לכן החוזה מדויק: נתיבים, status codes ו־code של שגיאות. איך תממש — שלך לגמרי.

שגיאות — תמיד { "error": { "code", "message", "details"? } }. כסף — priceCents, totalCents: מספרים שלמים, באגורות.

הזמנה: { id, status, totalCents, createdAt, paidAt, …, items: [{ productId, name, priceCents, quantity }] }. ההגדרות שהבודק מעביר לשרת (משתני סביבה): PORT, DATABASE_URL, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD, BCRYPT_ROUNDS, CORS_ORIGINS, NODE_ENV=test. השרת צריך להאזין ל־PORT, ולהבטיח בעלייה שיש מנהל עם ADMIN_EMAIL ו־ADMIN_PASSWORD.

4. החלטות לפני הקוד

כתוב קובץ DECISIONS.md (או טיוטה של סעיף "החלטות טכניות" ב־README) ותן תשובה לכל אחת — לפני שאתה כותב קוד:

  4. אילו מעברים מותרים בין המצבים של הזמנה? (צייר.)
  5. איפה נשמר ה־Idempotency-Key, ומה מבטיח שרק בקשה אחת "זוכה"?
  6. מה נשמר מהתשלום — ומה אסור לשמור?
