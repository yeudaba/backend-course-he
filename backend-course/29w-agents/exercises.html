P29.5-E26 · שומר לולאה לסוכן 🤖

✍️ מאפסרמה 3⏱ 25 דק׳ידע נדרש: שיעור 1

סוכן שנתקע עושה את אותו דבר שוב ושוב: מחפש הזמנות, לא מוצא, ומחפש שוב עם אותו קלט. כל סיבוב עולה כסף. ‏max_turns (שיעור 1) עוצר בסוף, אבל מאוחר מדי. כתוב מקובץ ריק "שומר" שנבדק לפני כל קריאה לכלי, וייצא:

  • stableKey(value): string — כמו JSON.stringify, אבל המפתחות של כל אובייקט ממוינים, בכל עומק. כך { status, email } ו־{ email, status } נותנים אותו מפתח. במערכים הסדר נשמר. ‏stableKey({ b: 1, a: 2 }) ← {"a":2,"b":1}.
  • class LoopGuard עם constructor({ maxSteps, maxRepeats, maxCostUsd }):
    • check(tool, input, costUsd) — קודם סופרת: עוד צעד, עוד עלות, ועוד הופעה של הקריאה (שם הכלי + stableKey(input)). אחר כך בודקת, לפי הסדר: צעדים מעל maxSteps ← reason: "steps". עלות מעל maxCostUsd ← "cost". אותה קריאה יותר מ־maxRepeats פעמים ← "repeat". מחזירה { ok: true }, או { ok: false, reason, message }.
    • getters: ‏steps, ו־costUsd מעוגל ל־4 ספרות אחרי הנקודה.
    • כל השדות פרטיים.

P29.5-E27 · בודק קלט של כלי לפי JSON Schema 🤖

🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 2

🔁 חזרה על union עם שדה מבחין ו־switch (פרק 11), ‏typeof/Array.isArray (פרק 7), ‏flatMap (פרק 6) ורקורסיה (פרק 27). כלי MCP מגדיר inputSchema ב־JSON Schema (שיעור 2), והמודל לא תמיד שולח קלט תקין. Zod עושה את זה בשבילך (‏E07), אבל כדאי לראות שזה פחות קסם ממה שנראה. כתוב וייצא:

  • type Schema — union של: { type: "string"; enum? }, ‏{ type: "number" | "integer"; minimum?; maximum? } (גבולות כוללים), ‏{ type: "boolean" }, ‏{ type: "array"; items }, ‏{ type: "object"; properties; required? }.
  • validate(schema, value, path = "input"): string[] — כל השגיאות, כל אחת בפורמט "נתיב: הסבר". נתיבים: input.items[1].qty.
    • מספר: NaN ו־Infinity לא תקינים. ‏integer — רק שלם.
    • אובייקט: null ומערך הם לא אובייקט. שדה מ־required שחסר ← שגיאה עם הנתיב שלו. שדה שלא מופיע ב־properties ← שגיאה (המודל המציא שדה).
    • אם הטיפוס עצמו לא נכון, מספיקה שגיאה אחת לנתיב הזה.

P29.5-E28 · trace כעץ טקסט 🤖

🔁 חזרהרמה 2⏱ 20 דק׳ידע נדרש: שיעור 5

🔁 חזרה על Map של רשימות (קיבוץ, פרק 7), ‏sort עם שני קריטריונים, רקורסיה, ו־padEnd/padStart (פרק 2). trace של סוכן (שיעור 5) הוא רשימה שטוחה של spans, שכל אחד מצביע על ההורה שלו. כדי להבין מה קרה, מציגים אותה כעץ. כתוב וייצא:

  • type Span = { id: string; parentId: string | null; name: string; start: number; end: number } (זמנים במילישניות).
  • renderTrace(spans): string — שורה לכל span. השם עם הזחה של שני רווחים לכל רמה, מרופד ל־32 תווים (padEnd), ואחריו המשך (end - start ו־ms) מרופד ל־8 תווים (padStart). השורות מופרדות ב־"\n".
  • מתחת לכל span — הילדים שלו, לפי start, ובתיקו לפי name. גם השורשים באותו סדר.
  • span שה־parentId שלו לא נמצא ברשימה (ה־trace נחתך) מוצג כשורש, ולא נעלם. בלי spans ← "".
