P29.5-E03 · MCP: מי מדבר עם מי 🧠 הבנה רמה 1

💡 רמז 1

שלושה תפקידים: host (האפליקציה), client (חיבור אחד לשרת, בתוך ה־host), server (חושף tools, resources ו־prompts).

✅ פתרון
  1. לא. השרת חושף כלים ונתונים; המודל רץ אצל ה־host (שקורא ל־API של Claude). השרת לא יודע איזה מודל משתמש בו.
  2. נכון — זו כל הנקודה: כותבים את הכלים פעם אחת, וכל host שמדבר MCP משתמש בהם.
  3. נכון. stdio — השרת הוא תהליך־ילד של ה־host (כלים מקומיים: קבצים, git). Streamable HTTP — שרת מרוחק, עם אימות (OAuth). הכלים עצמם זהים; בבדיקות שלנו — transport בזיכרון.
  4. לא. השם, התיאור וה־schema הם בדיוק מה שנשלח למודל ב־tools — לפיהם הוא מחליט מתי ואיך לקרוא (E09, E21). תיאור גרוע = שימוש גרוע.
  5. לא. שרת MCP הוא קוד שרץ אצלך עם ההרשאות שלך — ותיאורי הכלים שלו נכנסים להקשר של המודל (אפשר להחביא בהם הוראות). מתקינים כמו כל תלות: ממקור מוכר, עם גרסה קבועה, ומעט ככל האפשר.
  6. נכון. המודל עושה מה שמבקשים ממנו — כולל מה שמשתמש זדוני ביקש. השרת מקבל את זהות המשתמש מה־host (לא מהמודל), ובודק כל קריאה (E08).

import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { InMemoryTransport } from "@modelcontextprotocol/sdk/inMemory.js";
import { z } from "zod";

const server = new McpServer({ name: "coffee", version: "1.0.0" });
server.registerTool(
  "check_stock",
  { description: "How many units of a product are in stock", inputSchema: { productId: z.number().int().positive() } },
  async ({ productId }) => {
    const stock: Record<number, number> = { 1: 12, 3: 4 };
    if (!(productId in stock)) return { content: [{ type: "text", text: `no product ${productId}` }], isError: true };
    return { content: [{ type: "text", text: `${stock[productId]} units` }] };
  },
);

const [serverSide, clientSide] = InMemoryTransport.createLinkedPair();
await server.connect(serverSide);
const client = new Client({ name: "demo-agent", version: "1.0.0" });
await client.connect(clientSide);

const { tools } = await client.listTools();
console.log(tools[0].name, "|", tools[0].description, "|", JSON.stringify(tools[0].inputSchema.properties), tools[0].inputSchema.required);
for (const args of [{ productId: 3 }, { productId: 99 }, { productId: "3" }]) {
  const r = await client.callTool({ name: "check_stock", arguments: args });
  console.log(JSON.stringify(args), "→", r.isError ? "ERROR:" : "", (r.content as { text: string }[])[0].text);
}
await client.close();

ה־schema של zod הפך ל־JSON Schema — זה מה שהמודל רואה (E09 מעביר אותו כמו שהוא ל־tools של Claude). קלט לא תקין לא מגיע לקוד שלך: ה־SDK בודק ומחזיר שגיאה עם isError. ושגיאה "עסקית" (מוצר שלא קיים) — אתה מחזיר isError: true בעצמך. בשני המקרים: תשובה, לא exception — כך המודל יכול לתקן ולנסות שוב.

✅ פתרון
// P29.5-E08: שרת MCP — הכלים של החנות, לכל סוכן שמדבר MCP
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";
import type { Store } from "../files/store.ts";

const text = (t: string) => ({ content: [{ type: "text" as const, text: t }] });
const error = (t: string) => ({ ...text(t), isError: true });

// customerId מגיע מהשרת (מי מחובר), לא מהמודל — המודל לא יכול לבקש הזמנה של לקוח אחר
export function createCoffeeMcpServer(store: Store, customerId: number): McpServer {
  const server = new McpServer({ name: "coffee-shop", version: "1.0.0" });

  server.registerTool(
    "search_products",
    {
      description: "Search the coffee shop catalog by name. Returns id, name, price in ILS and whether it is in stock.",
      inputSchema: { query: z.string().min(2).max(50) },
      annotations: { readOnlyHint: true },
    },
    async ({ query }) => {
      const q = query.toLowerCase();
      const found = store.products
        .filter((p) => p.name.toLowerCase().includes(q))
        .map((p) => ({ id: p.id, name: p.name, price: p.priceCents / 100, inStock: p.stock > 0 }));
      return text(JSON.stringify(found));
    },
  );

  server.registerTool(
    "get_order",
    {
      description: "Get one of the signed-in customer's orders by order id: status, total in ILS and items.",
      inputSchema: { orderId: z.number().int().positive() },
      annotations: { readOnlyHint: true },
    },
    async ({ orderId }) => {
      const o = store.orders.get(orderId);
      // הזמנה של לקוח אחר — בדיוק כמו "לא קיימת": לא מגלים שהיא קיימת
      if (!o || o.customerId !== customerId) return error(`הזמנה ${orderId} לא נמצאה`);
      return text(JSON.stringify({ id: o.id, status: o.status, total: o.totalCents / 100, items: o.items }));
    },
  );

  server.registerTool(
    "list_my_orders",
    {
      description: "List the signed-in customer's orders (id, status, total in ILS), newest first.",
      inputSchema: {},
      annotations: { readOnlyHint: true },
    },
    async () => {
      const mine = [...store.orders.values()].filter((o) => o.customerId === customerId).sort((a, b) => b.id - a.id);
      return text(JSON.stringify(mine.map((o) => ({ id: o.id, status: o.status, total: o.totalCents / 100 }))));
    },
  );
  return server;
}

להריץ את השרת הזה ב־Claude Code או בכל host אחר — מוסיפים בסוף await server.connect(new StdioServerTransport()) (מ־@modelcontextprotocol/sdk/server/stdio.js), ומגדירים את הפקודה בהגדרות ה־MCP של ה־host. ושימו לב ל־annotations: readOnlyHint אומר ל־host שהכלי לא משנה כלום — host יכול להחליט לא לבקש עליו אישור.

// P29.5-E09: גשר בין MCP ל־Messages API — הכלים של שרת MCP, כלים של Claude
import type Anthropic from "@anthropic-ai/sdk";
import type { Client } from "@modelcontextprotocol/sdk/client/index.js";

export async function mcpToolsForClaude(mcp: Client, { prefix = "" } = {}): Promise<Anthropic.Tool[]> {
  const out: Anthropic.Tool[] = [];
  let cursor: string | undefined;
  do {
    const page = await mcp.listTools(cursor ? { cursor } : {}); // שרת יכול להחזיר רשימה בעמודים
    for (const t of page.tools) {
      const { $schema, ...schema } = t.inputSchema as Record<string, unknown>;
      out.push({ name: prefix + t.name, description: t.description ?? "", input_schema: schema as Anthropic.Tool.InputSchema });
    }
    cursor = page.nextCursor;
  } while (cursor);
  return out;
}

export async function callMcpTool(mcp: Client, call: Anthropic.ToolUseBlock, { prefix = "" } = {}): Promise<Anthropic.ToolResultBlockParam> {
  const name = call.name.startsWith(prefix) ? call.name.slice(prefix.length) : call.name;
  try {
    const res = await mcp.callTool({ name, arguments: call.input as Record<string, unknown> });
    const content = (res.content as { type: string; text?: string }[])
      .map((c) => (c.type === "text" ? c.text : `[${c.type}]`))
      .join("\n");
    return { type: "tool_result", tool_use_id: call.id, content, ...(res.isError ? { is_error: true } : {}) };
  } catch (err) {
    // שרת שנפל / timeout — עדיין tool_result, כדי שהשיחה תישאר תקינה
    return { type: "tool_result", tool_use_id: call.id, content: `שרת ה־MCP נכשל: ${(err as Error).message}`, is_error: true };
  }
}

(ה־Messages API יודע גם להתחבר לשרתי MCP מרוחקים בעצמו — "MCP connector", עם mcp_servers ו־mcp_toolset. הגשר כאן נחוץ כשהשרת מקומי, או כשאתה רוצה לשלוט בכל קריאה: אישורים, הרשאות, logging.)

// P29.5-E21: שרת MCP של הזמנות — אחרי התיקון
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";
import type { Store } from "../files/store.ts";

const text = (t: string) => ({ content: [{ type: "text" as const, text: t }] });
const error = (t: string) => ({ ...text(t), isError: true });

export function createOrdersMcpServer(store: Store, customerId: number): McpServer {
  const server = new McpServer({ name: "orders", version: "1.0.0" });
  server.registerTool(
    "get_order",
    { description: "Get one of the signed-in customer's orders by id: status, total in ILS, items.", inputSchema: { orderId: z.number().int().positive() } },
    async ({ orderId }) => {
      const o = store.orders.get(orderId);
      if (!o || o.customerId !== customerId) return error(`הזמנה ${orderId} לא נמצאה`); // תיקון 1: רק הזמנות של הלקוח המחובר
      return text(JSON.stringify({ id: o.id, status: o.status, total: o.totalCents / 100 }));
    },
  );
  server.registerTool(
    "cancel_order",
    {
      // תיקון 2: בלי תיאור המודל מנחש מתי להשתמש בכלי, ומה הוא עושה
      description: "Cancel one of the signed-in customer's orders. Only orders that were not shipped yet (status placed or paid) can be cancelled.",
      inputSchema: { orderId: z.number().int().positive() },
      annotations: { destructiveHint: true },
    },
    async ({ orderId }) => {
      const o = store.orders.get(orderId);
      if (!o || o.customerId !== customerId) return error(`הזמנה ${orderId} לא נמצאה`);
      if (o.status !== "placed" && o.status !== "paid") return error(`אי אפשר לבטל הזמנה בסטטוס ${o.status}`); // תיקון 3
      o.status = "cancelled";
      return text(`הזמנה ${orderId} בוטלה`);
    },
  );
  return server;
}

P29.5-E27 · בודק קלט של כלי לפי JSON Schema 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

switch (schema.type). בכל case, ‏TypeScript יודע איזה חלק של ה־union זה: ב־case "array" יש schema.items, וב־case "object" יש schema.properties. מערך: value.flatMap((item, i) => validate(schema.items, item, ${path}[${i}])).

💡 רמז 2

אובייקט: קודם for (const key of schema.required ?? []) ← חסרים. אחר כך for (const key of Object.keys(obj)): אין properties[key] ← "שדה לא מוכר", ואחרת errors.push(...validate(sub, obj[key], ${path}.${key})). ‏case "number": case "integer": { ... } — שני case עם אותו קוד, וסוגריים בגלל ה־const.

✅ פתרון
// P29.5-E27 — בודק קלט של כלי לפי JSON Schema (חלק קטן)
export type Schema =
  | { type: "string"; enum?: string[] }
  | { type: "number" | "integer"; minimum?: number; maximum?: number }
  | { type: "boolean" }
  | { type: "array"; items: Schema }
  | { type: "object"; properties: Record<string, Schema>; required?: string[] };

export function validate(schema: Schema, value: unknown, path = "input"): string[] {
  switch (schema.type) {
    case "string":
      if (typeof value !== "string") return [`${path}: צריך להיות string`];
      if (schema.enum && !schema.enum.includes(value)) return [`${path}: חייב להיות אחד מ־${schema.enum.join(", ")}`];
      return [];
    case "number":
    case "integer": {
      if (typeof value !== "number" || !Number.isFinite(value)) return [`${path}: צריך להיות number`];
      if (schema.type === "integer" && !Number.isInteger(value)) return [`${path}: צריך להיות מספר שלם`];
      if (schema.minimum !== undefined && value < schema.minimum) return [`${path}: לפחות ${schema.minimum}`];
      if (schema.maximum !== undefined && value > schema.maximum) return [`${path}: לכל היותר ${schema.maximum}`];
      return [];
    }
    case "boolean":
      return typeof value === "boolean" ? [] : [`${path}: צריך להיות boolean`];
    case "array":
      if (!Array.isArray(value)) return [`${path}: צריך להיות array`];
      return value.flatMap((item, i) => validate(schema.items, item, `${path}[${i}]`));
    case "object": {
      if (value === null || typeof value !== "object" || Array.isArray(value)) return [`${path}: צריך להיות object`];
      const obj = value as Record<string, unknown>;
      const errors: string[] = [];
      for (const key of schema.required ?? []) if (!(key in obj)) errors.push(`${path}.${key}: חסר`);
      for (const key of Object.keys(obj)) {
        const sub = schema.properties[key];
        if (!sub) errors.push(`${path}.${key}: שדה לא מוכר`);
        else errors.push(...validate(sub, obj[key], `${path}.${key}`));
      }
      return errors;
    }
  }
}

שש שגיאות בבת אחת, כל אחת עם נתיב מדויק. זה מה שמחזירים למודל ב־tool_result עם is_error: true. מודל שמקבל "input.items[1].productId: צריך להיות number" מתקן בניסיון הבא. מודל שמקבל "invalid input" מנחש.

הרקורסיה היא העיקר: validate של אובייקט קוראת ל־validate על כל שדה, וזו של מערך על כל איבר. כך מבנה בכל עומק עובד עם אותן חמש שורות. זה גם ה־"discriminated union" של פרק 11 במיטבו: ‏switch על type, ו־TypeScript מוודא שלא שכחת אף מקרה (אם תוסיף "null" ל־union ולא תטפל בו, ‏tsc יתלונן שהפונקציה לא מחזירה ערך).

⚠️ טעויות נפוצות
  • typeof value === "object" בלבד — ‏null ומערכים עוברים כאובייקט.
  • לעצור בשגיאה הראשונה — המודל מתקן שגיאה אחת בכל סיבוב, וכל סיבוב עולה כסף.
  • להתעלם משדות לא מוכרים — המודל שולח discount: 100, והקוד שלך מתעלם ממנו בשקט, או גרוע מזה, מעביר אותו הלאה.
  • typeof value === "number" בלי Number.isFinite — ‏NaN עובר.
