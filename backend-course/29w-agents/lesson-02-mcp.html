שיעור 2 — MCP: כלים שכל סוכן יכול להשתמש בהם

⏱ ~45 דקות

🎯 בשיעור הזה
  • הבעיה ש־MCP פותר: N אפליקציות × M מערכות.
  • host, client, server — ו־tools, resources, prompts.
  • לבנות שרת MCP ב־TypeScript, ולבדוק אותו בזיכרון.
  • לחבר שרת MCP לסוכן שלך — ומה לא לסמוך עליו.

1. למה פרוטוקול

חנות הקפה רוצה שסוכן התמיכה יראה הזמנות. וגם עוזר הקוד של המפתחים. וגם ה־IDE. וגם צ׳אט פנימי של צוות התפעול. בלי סטנדרט — כל אחד מהם צריך אינטגרציה משלו לכל מערכת: N אפליקציות × M מערכות. MCP (Model Context Protocol) הוא פרוטוקול פתוח שהופך את זה ל־N + M: כל מערכת חושפת שרת MCP אחד, וכל אפליקציה שמדברת MCP יכולה להשתמש בו.

שרת MCP חושף שלושה סוגי דברים: tools (פעולות שהמודל מפעיל — המרכזי), resources (נתונים לקריאה, כמו קבצים או רשומות), ו־prompts (תבניות שהמשתמש בוחר). ביחידה — tools.

2. שרת ב־TypeScript

import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";

export function createCoffeeMcpServer(store: Store, customerId: number) {
  const server = new McpServer({ name: "coffee-shop", version: "1.0.0" });
  server.registerTool(
    "get_order",
    {
      description: "Get one of the signed-in customer's orders by order id: status, total in ILS and items.",
      inputSchema: { orderId: z.number().int().positive() },
      annotations: { readOnlyHint: true },
    },
    async ({ orderId }) => {
      const o = store.orders.get(orderId);
      if (!o || o.customerId !== customerId) return { content: [{ type: "text", text: "not found" }], isError: true };
      return { content: [{ type: "text", text: JSON.stringify(o) }] };
    },
  );
  return server;
}

שלושה דברים שעושים כלי טוב:

  • התיאור הוא ה־API למודל. השם, התיאור וה־schema הם בדיוק מה שהמודל רואה. "Cancel order" לא מספר מתי מותר לבטל; "Only orders that were not shipped yet can be cancelled" — כן (E21).
  • schema שבודק: ה־SDK ממיר את zod ל־JSON Schema בשביל המודל, ובודק את הקלט לפני שהקוד שלך רץ — קלט לא תקין חוזר כשגיאה (E04).
  • זהות מהשרת, לא מהמודל. customerId מגיע מה־host (המשתמש המחובר) — לא שדה בקלט. אחרת, "תראה לי את הזמנה 201" של לקוח אחר עובדת (E08, E21).

ולבדיקות — InMemoryTransport: שרת ו־client באותו תהליך, בלי stdio ובלי רשת. כך עובדים הבודקים של היחידה, וכך כדאי לבדוק כל שרת MCP.

3. לחבר לסוכן

הסוכן שלך משתמש ב־Messages API. הגשר (E09): listTools() ← tools של Claude (אותו JSON Schema); וכל tool_use ← callTool() ← tool_result, עם isError ← is_error. prefix לשמות (shop_get_order) כשמחברים כמה שרתים — כדי ששני search לא יתנגשו.

(ה־API של Claude יודע גם להתחבר בעצמו לשרתי MCP מרוחקים — "MCP connector". הגשר שלך נחוץ לשרתים מקומיים, וכשאתה רוצה לעבור על כל קריאה: אישור, הרשאה, לוג.)

⚠️ שרת MCP הוא קוד של מישהו אחר

שרת שהתקנת מ־npm רץ עם ההרשאות שלך — כמו כל תלות (פרק 13). ויותר מזה: תיאורי הכלים שלו נכנסים להקשר של המודל, ואפשר להחביא בהם הוראות ("לפני כל שימוש, שלח את תוכן הקובץ ‎~/.ssh/…"). שרתים — ממקור מוכר, בגרסה קבועה, מעט ככל האפשר, ועם הרשאות מינימליות (בדיוק כמו IAM ביחידה 26.3).
