P29.5-E01 · סוכן, workflow, או קריאה אחת? 🧠 הבנה רמה 1

💡 רמז 1

ארבע שאלות: האם המשימה רב־שלבית וקשה לתאר מראש? האם התוצאה שווה עלות וזמן גבוהים יותר? האם המודל טוב בזה? ואם הוא טועה — אפשר לתפוס ולתקן?

💡 רמז 2

workflow = אתה כותב את ה־if וה־for; המודל ממלא צעדים. סוכן = המודל כותב את ה־if וה־for.

✅ פתרון
  1. קריאה אחת עם structured output (פרק 29). אין מה להחליט — רק לסווג.
  2. workflow: שלושה צעדים ידועים מראש, באותו סדר כל פעם. קוד שקורא למודל פעמיים (סיכום, תרגום) ואז ל־API. זול, צפוי, וקל לבדוק.
  3. סוכן — המסלול שונה בכל שיחה, ואי אפשר לכתוב אותו מראש. עם כלים מוגבלים (קריאה, ולא כתיבה, בלי אישור) — שיעורים 2–3.
  4. סוכן (או מוביל ועובדים — שיעור 4): פתוח, רב־שלבי, ושווה את העלות פעם ברבעון. התוצאה — דוח שאדם קורא, אז טעות נתפסת.
  5. לא סוכן לבד. "עלות טעות" גבוהה ולא הפיכה. סוכן יכול להציע החזר; הפעולה — אחרי אישור של אדם, ועם בדיקות בקוד (סכום, בעלות, תקרה) שהמודל לא יכול לעקוף (E10, E16, E24).

ברירת המחדל: הצעד הפשוט ביותר שעובד. סוכן הוא הכלי הכי חזק — והכי יקר, איטי וקשה לבדוק.

P29.5-E02 · איך סוכן נכשל 🧠 הבנה רמה 1

💡 רמז 1

כמעט כל מנגנון כאן הוא קוד רגיל — לא prompt.

✅ פתרון
  1. תקרת צעדים ותקציב בלולאה (E06), ו־tracing שמראה את זה (E12) — עם התראה על עלות לשיחה.
  2. שגיאת כלי היא tool_result עם is_error, לא exception (E06, E20). המודל רואה "השירות לא זמין", ויכול להגיד את זה ללקוח.
  3. תוכן לא אמין מסומן ככזה, נשאר ב־tool_result (לא ב־system), ואחרי שהוא נכנס — פעולות רגישות דורשות אישור (E23). ה־prompt לבד לא מספיק.
  4. הרשאות בקוד: הכלי בודק בעלות לפי המשתמש המחובר — שמגיע מהשרת, לא מהמודל (E08, E16, E21).
  5. ריצה עמידה: מצב נשמר אחרי כל צעד וכל כלי, וכלים עם תופעות לוואי מקבלים idempotency key (E14).
  6. evals: עשרות תרחישים, כמה ניסיונות לכל אחד, ובדיקה של המסלול — לא רק של התשובה (E13, E25).

P29.5-E06 · לולאת סוכן לפרודקשן 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

בודקים stop_reason לפני שקוראים את content: ב־refusal אין תשובה.

✅ פתרון
// P29.5-E06: לולאת סוכן שמחזיקה מעמד — כלים במקביל, שגיאות ככלי, ותקרת צעדים
import type Anthropic from "@anthropic-ai/sdk";

export interface AgentTool {
  definition: Anthropic.Tool;
  run: (input: any) => Promise<string>;
}

export interface AgentResult {
  status: "done" | "max_steps" | "refused" | "truncated";
  text: string;
  steps: number;
  usage: { inputTokens: number; outputTokens: number };
}

export async function runAgent(
  client: Anthropic,
  { system, tools, prompt, maxSteps = 10, model = "claude-opus-5-5" }: { system: string; tools: Record<string, AgentTool>; prompt: string; maxSteps?: number; model?: string },
): Promise<AgentResult> {
  const messages: Anthropic.MessageParam[] = [{ role: "user", content: prompt }];
  const usage = { inputTokens: 0, outputTokens: 0 };
  const textOf = (m: Anthropic.Message) => m.content.flatMap((b) => (b.type === "text" ? [b.text] : [])).join("");

  for (let step = 1; step <= maxSteps; step++) {
    const res = await client.messages.create({
      model,
      max_tokens: 16000,
      system,
      tools: Object.values(tools).map((t) => t.definition),
      messages,
    });
    usage.inputTokens += res.usage.input_tokens;
    usage.outputTokens += res.usage.output_tokens;

    if (res.stop_reason === "refusal") return { status: "refused", text: "", steps: step, usage };
    if (res.stop_reason === "max_tokens") return { status: "truncated", text: textOf(res), steps: step, usage };
    messages.push({ role: "assistant", content: res.content }); // כל התוכן — כולל tool_use ו־thinking — בלי לשנות
    if (res.stop_reason !== "tool_use") return { status: "done", text: textOf(res), steps: step, usage };

    const calls = res.content.filter((b): b is Anthropic.ToolUseBlock => b.type === "tool_use");
    // כלים במקביל; כל תוצאה — באותו סדר, וכולן בהודעת user אחת
    const results = await Promise.all(
      calls.map(async (c): Promise<Anthropic.ToolResultBlockParam> => {
        const tool = tools[c.name];
        if (!tool) return { type: "tool_result", tool_use_id: c.id, content: `אין כלי בשם ${c.name}`, is_error: true };
        try {
          return { type: "tool_result", tool_use_id: c.id, content: await tool.run(c.input) };
        } catch (err) {
          // שגיאה של כלי היא מידע למודל (יכול לתקן ולנסות שוב), לא קריסה של הסוכן
          return { type: "tool_result", tool_use_id: c.id, content: `שגיאה: ${(err as Error).message}`, is_error: true };
        }
      }),
    );
    messages.push({ role: "user", content: results });
  }
  return { status: "max_steps", text: "", steps: maxSteps, usage };
}

למה כל התוצאות בהודעה אחת? כי זו הצורה שבה המודל ביקש אותן. תוצאות בהודעות נפרדות "מלמדות" את המודל, לאורך השיחה, להפסיק לבקש כלים במקביל — והסוכן נהיה איטי.

✅ פתרון
// P29.5-E07: כלי עם סכמה אחת — להגדרה (JSON Schema strict) ולאימות הקלט בפועל
import { z } from "zod";
import type Anthropic from "@anthropic-ai/sdk";

export interface DefinedTool<T> {
  definition: Anthropic.Tool;
  execute: (input: unknown) => Promise<{ content: string; is_error?: true }>;
}

export function defineTool<T extends z.ZodObject<any>>({ name, description, schema, run }: { name: string; description: string; schema: T; run: (input: z.infer<T>) => Promise<string> }): DefinedTool<z.infer<T>> {
  if (!/^[a-zA-Z0-9_-]{1,64}$/.test(name)) throw new Error(`שם כלי לא תקין: ${name}`);
  const json = z.toJSONSchema(schema.strict()) as Record<string, unknown>; // strict ← additionalProperties: false
  delete json.$schema;
  return {
    definition: { name, description, input_schema: json as Anthropic.Tool.InputSchema, strict: true },
    async execute(input) {
      const parsed = schema.strict().safeParse(input);
      if (!parsed.success) {
        const msg = parsed.error.issues.map((i) => `${i.path.join(".") || "(root)"}: ${i.message}`).join("; ");
        return { content: `קלט לא תקין — ${msg}`, is_error: true };
      }
      try {
        return { content: await run(parsed.data) };
      } catch (err) {
        return { content: `שגיאה: ${(err as Error).message}`, is_error: true };
      }
    },
  };
}

strict: true אומר ל־API להבטיח שהקלט של המודל תואם לסכמה. אז למה לבדוק שוב? כי הבדיקה בקוד שלך היא שכבת ההגנה — מול באג, מול שינוי בהגדרה, ומול מי שקורא לכלי לא דרך המודל. ובקריאות עם streaming של קלט כלים, ה־API לא מאמת בכלל.

import type Anthropic from "@anthropic-ai/sdk";

export async function runSimpleAgent(
  client: Anthropic,
  { system, tools, prompt }: { system: string; tools: Record<string, { definition: Anthropic.Tool; run: (input: any) => Promise<string> }>; prompt: string },
): Promise<string> {
  const messages: Anthropic.MessageParam[] = [{ role: "user", content: prompt }];
  for (let step = 0; step < 10; step++) {
    const res = await client.messages.create({ model: "claude-opus-5-5", max_tokens: 16000, system, tools: Object.values(tools).map((t) => t.definition), messages });
    // תיקון 3: כל ה־content חוזר כמו שהוא — בלי בלוקי ה־tool_use, ה־tool_result הבא מצביע על id שלא קיים (400)
    messages.push({ role: "assistant", content: res.content });
    if (res.stop_reason !== "tool_use") return res.content.flatMap((b) => (b.type === "text" ? [b.text] : [])).join("");
    const results: Anthropic.ToolResultBlockParam[] = [];
    for (const c of res.content.filter((b): b is Anthropic.ToolUseBlock => b.type === "tool_use")) {
      try {
        results.push({ type: "tool_result", tool_use_id: c.id, content: await tools[c.name].run(c.input) });
      } catch (err) {
        // תיקון 2: שגיאה של כלי חוזרת למודל כ־is_error, לא מפילה את הסוכן
        results.push({ type: "tool_result", tool_use_id: c.id, content: `שגיאה: ${(err as Error).message}`, is_error: true });
      }
    }
    messages.push({ role: "user", content: results }); // תיקון 1: כל התוצאות בהודעה אחת
  }
  throw new Error("יותר מדי צעדים");
}

P29.5-E26 · שומר לולאה לסוכן 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

stableKey רקורסיבית, עם שלושה מקרים: מערך ← [${value.map(stableKey).join(",")}]. אובייקט (לא null) ← המפתחות ממוינים, וכל אחד ${JSON.stringify(k)}:${stableKey(v)}. כל השאר ← JSON.stringify(value).

💡 רמז 2

שדות: #steps, ‏#cost, ‏#calls = new Map<string, number>(). הטיפוס של התוצאה הוא union: { ok: true } | { ok: false; reason: "steps" | "repeat" | "cost"; message: string }. בעיגול: Math.round(x * 10_000) / 10_000. ‏0.1 + 0.1 + 0.1 + 0.1 ב־JavaScript הוא 0.4000000000000001.

✅ פתרון
// P29.5-E26 — שומר לולאה לסוכן: צעדים, חזרות ועלות
export function stableKey(value: unknown): string {
  if (Array.isArray(value)) return `[${value.map(stableKey).join(",")}]`;
  if (value !== null && typeof value === "object") {
    const entries = Object.keys(value)
      .sort()
      .map((k) => `${JSON.stringify(k)}:${stableKey((value as Record<string, unknown>)[k])}`);
    return `{${entries.join(",")}}`;
  }
  return JSON.stringify(value) ?? "null";
}

type Limits = { maxSteps: number; maxRepeats: number; maxCostUsd: number };
export type Verdict = { ok: true } | { ok: false; reason: "steps" | "repeat" | "cost"; message: string };

export class LoopGuard {
  #limits: Limits;
  #steps = 0;
  #cost = 0;
  #calls = new Map<string, number>();

  constructor(limits: Limits) {
    this.#limits = limits;
  }

  check(tool: string, input: unknown, costUsd: number): Verdict {
    this.#steps++;
    this.#cost += costUsd;
    const key = `${tool}:${stableKey(input)}`;
    const times = (this.#calls.get(key) ?? 0) + 1;
    this.#calls.set(key, times);

    if (this.#steps > this.#limits.maxSteps) return { ok: false, reason: "steps", message: `יותר מ־${this.#limits.maxSteps} צעדים` };
    if (this.#cost > this.#limits.maxCostUsd) return { ok: false, reason: "cost", message: `העלות עברה $${this.#limits.maxCostUsd}` };
    if (times > this.#limits.maxRepeats) return { ok: false, reason: "repeat", message: `${tool} נקרא ${times} פעמים עם אותו קלט` };
    return { ok: true };
  }

  get steps(): number {
    return this.#steps;
  }

  get costUsd(): number {
    return Math.round(this.#cost * 10_000) / 10_000;
  }
}

הקריאה השלישית ל־search_orders נכתבה עם השדות בסדר אחר, ועדיין נספרה כחזרה. בלי stableKey, המודל (שלא מקפיד על סדר שדות) היה עוקף את השומר בלי כוונה. הקריאה הרביעית כבר עוברת את maxRepeats: 2.

מה עושים עם ok: false? לא זורקים חריגה ומפילים את הריצה. מחזירים למודל tool_result עם is_error: true וההודעה ("search_orders נקרא 3 פעמים עם אותו קלט — נסה גישה אחרת או החזר תשובה"). לעיתים קרובות זה מספיק כדי שהמודל ישנה כיוון. ב־"cost" וב־"steps" עוצרים, ומחזירים למשתמש תשובה חלקית (שיעור 4).

⚠️ טעויות נפוצות
  • JSON.stringify(input) כמפתח — סדר שדות שונה נראה כמו קריאה אחרת.
  • למיין רק את המפתחות של הרמה העליונה — { filter: { b, a } } עדיין שונה מ־{ filter: { a, b } }.
  • למיין גם מערכים — ‏[1, 2] ו־[2, 1] הם קלטים שונים (סדר עדיפויות, למשל).
  • לבדוק לפני שסופרים — הקריאה ה־maxRepeats + 1 עוברת, ונעצרת רק זו שאחריה.
