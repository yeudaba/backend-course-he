P15.5-E13 · טבלת HTML מנתונים 🤖

✍️ מאפסרמה 3⏱ 20 דק׳ידע נדרש: שיעור 1

דף ניהול מציג כמעט תמיד טבלה: מוצרים, הזמנות, משתמשים. כתוב פונקציה אחת שבונה טבלה לכל רשימה. כתוב וייצא renderTable(columns, rows), שמחזירה מחרוזת HTML:

  • columns — מערך של { key, label, numeric? }. ‏rows — מערך של אובייקטים.
  • המבנה, בשורה אחת ובלי רווחים בין התגיות: <table><thead><tr><th>label</th>...</tr></thead><tbody><tr><td>...</td>...</tr>...</tbody></table>.
  • בכל שורה, תא לכל עמודה לפי הסדר של columns: הערך row[key]. ערך null או undefined ← — (קו מפריד ארוך).
  • עמודה עם numeric: true ← <td class="num"> (ב־CSS היא תיושר לשמאל, כמו מספרים).
  • כל טקסט — גם הכותרות — מקודד כמו ב־P15.5-E06 (& < > " '). את הקידוד כותבים שוב, בתוך הקובץ הזה.
  • אין שורות ← <p class="empty">אין נתונים להצגה</p> במקום הטבלה.

P15.5-E14 · debounce לשדה חיפוש 🤖

🔁 חזרהרמה 3⏱ 15 דק׳ידע נדרש: שיעור 3

🔁 חזרה על closures (P05-E26) ועל setTimeout (פרק 10). בשדה חיפוש, אם שולחים fetch על כל הקשה, המילה cors שולחת 4 בקשות לשרת. הפתרון המקובל הוא debounce: מחכים שהמשתמש יפסיק להקליד, ורק אז שולחים בקשה אחת. כתוב וייצא debounce(fn, ms):

  • מחזירה פונקציה חדשה. כל קריאה אליה מבטלת את הטיימר הקודם ומתחילה חדש.
  • fn רצה רק אחרי ms מילישניות בלי קריאה נוספת — פעם אחת, עם הארגומנטים של הקריאה האחרונה.
  • לפונקציה המוחזרת יש מתודה cancel(), שמבטלת קריאה שממתינה (למשל כשהמשתמש עוזב את הדף).
  • כל debounce עם טיימר משלו: שני שדות חיפוש לא מפריעים זה לזה.
const search = debounce((q) => fetch(`/products?q=${q}`), 300);
input.addEventListener("input", () => search(input.value));

% node 15w-web-bridge/starter/P15.5-E14.mjs
% npm run check P15.5-E14

P15.5-E08 · לקוח API 🤖

רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ 15w-web-bridge/starter/P15.5-E08.mjs השלם createApiClient(baseUrl) — כל הקריאות ל־tasks-api במקום אחד (המחלקה ApiError כתובה):

  • listTasks(params = {}) ← GET /tasks עם query; פרמטרים ריקים ("", undefined, null) לא נשלחים. מחזירה את { data, meta }.
  • createTask(body) ← POST; updateTask(id, changes) ← PATCH; deleteTask(id) ← DELETE (מחזירה undefined).

P15.5-E09 · CORS בלי ספרייה 🤖

רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

כדי להבין מה cors() עושה — כתוב אותו. בקובץ 15w-web-bridge/starter/P15.5-E09.ts השלם corsMiddleware(origins):

  • אם ה־header Origin של הבקשה ברשימה ← Access-Control-Allow-Origin: <אותו origin>. תמיד (גם אם לא ברשימה) ← Vary: Origin.
  • בקשת OPTIONS (preflight) ← עונים מיד 204. אם ה־origin מורשה, מוסיפים גם Access-Control-Allow-Methods: GET,POST,PUT,PATCH,DELETE, Access-Control-Allow-Headers = מה שהדפדפן ביקש ב־Access-Control-Request-Headers (או Content-Type אם לא ביקש), ו־Access-Control-Max-Age: 600.
  • כל בקשה אחרת ← next() — גם מ־origin לא מורשה (הדפדפן הוא שיחסום את הקריאה).

P15.5-E12 · אתגר: CORS לייצור 🤖

רמה 5⏱ 35 דק׳ידע נדרש: כל היחידה

בקובץ 15w-web-bridge/starter/P15.5-E12.ts השלם createCors({ allow, credentials = false, maxAge = 600 }) — middleware כמו E09, עם דרישות של ייצור:

  • allow: origins מדויקים, וגם תבנית עם * לתת־דומיין אחד: "https://*.preview.example.com" מתיר את https://pr-42.preview.example.com, אבל לא את https://a.b.preview.example.com, לא את http://pr-42.preview.example.com, ולא את https://preview.example.com.evil.io. תת־דומיין: אותיות קטנות, ספרות ומקפים.
  • מורשה ← Access-Control-Allow-Origin: <origin> (לעולם לא *); עם credentials ← גם Access-Control-Allow-Credentials: true. תמיד Vary: Origin.
  • preflight (OPTIONS עם Access-Control-Request-Method) ממורשה ← 204 עם methods (GET,POST,PUT,PATCH,DELETE), headers (מה שביקשו), Access-Control-Max-Age. preflight מלא מורשה ← 403 { error: { code: "CORS_ORIGIN_NOT_ALLOWED", message } } — עדיף לדבג מ־204 ריק.
  • בלי Origin (curl, שרת) ← next() בלי שום header. בקשה רגילה מלא־מורשה ← next() בלי ACAO.
