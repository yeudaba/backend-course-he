P15.5-E09 · CORS בלי ספרייה 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

כדי להבין מה cors() עושה — כתוב אותו. בקובץ 15w-web-bridge/starter/P15.5-E09.ts השלם corsMiddleware(origins):

  • אם ה־header Origin של הבקשה ברשימה ← Access-Control-Allow-Origin: <אותו origin>. תמיד (גם אם לא ברשימה) ← Vary: Origin.
  • בקשת OPTIONS (preflight) ← עונים מיד 204. אם ה־origin מורשה, מוסיפים גם Access-Control-Allow-Methods: GET,POST,PUT,PATCH,DELETE, Access-Control-Allow-Headers = מה שהדפדפן ביקש ב־Access-Control-Request-Headers (או Content-Type אם לא ביקש), ו־Access-Control-Max-Age: 600.
  • כל בקשה אחרת ← next() — גם מ־origin לא מורשה (הדפדפן הוא שיחסום את הקריאה).

P15.5-E59 · סדר הדברים ב־submit אסינכרוני

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 10, שיעור 3

הקוד מדמה את ה־handler של הטופס (עם fetch מזויף שלוקח 50ms) ושתי לחיצות. מה יודפס, ובאיזה סדר?

const fakeFetch = (title) => new Promise((resolve) => setTimeout(() => resolve({ id: title.length, title }), 50));
const button = { disabled: false };

async function onSubmit(title) {
  console.log("submit:", title, "disabled?", button.disabled);
  if (button.disabled) return console.log("נחסם:", title);
  button.disabled = true;
  try {
    const task = await fakeFetch(title);
    console.log("נוצרה:", task.title);
  } finally {
    button.disabled = false;
  }
}

onSubmit("חלב");
onSubmit("לחם");
console.log("סוף הקוד הסינכרוני");
setTimeout(() => onSubmit("ביצים"), 100);

🔗 איך זה מתחבר: async/await, ‏setTimeout וסדר הריצה מפרק 10, ו־try/finally מפרק 8. השיעור: handler של submit — ו־P15.5-E55.

P15.5-E60 · השרת ביצע — הדפדפן חסם

🧠 הבנהרמה 3⏱ 10 דק׳ידע נדרש: פרק 15, שיעור 3

שרת Express עם cors({ origin: ["http://localhost:5500"] }). הקוד שולח בקשת GET "כמו דפדפן" — עם header ‏Origin — פעם ממקור מותר ופעם ממקור זר. מה יודפס?

import express from "express";
import cors from "cors";

const log = [];
const app = express();
app.use(cors({ origin: ["http://localhost:5500"] }));
app.get("/me", (req, res) => {
  log.push(`השרת הריץ את /me עבור ${req.get("origin")}`);
  res.json({ name: "דנה", balance: 1200 });
});

const server = app.listen(0);
await new Promise((r) => server.once("listening", r));
for (const origin of ["http://localhost:5500", "https://evil.example"]) {
  const res = await fetch(`http://localhost:${server.address().port}/me`, { headers: { Origin: origin } });
  console.log(origin, res.status, res.headers.get("access-control-allow-origin"), await res.text());
}
console.log(log.join("\n"));
server.close();

🔗 איך זה מתחבר: Express ו־middleware מפרק 15, headers מפרק 14. השיעור: "CORS נאכף בדפדפן, לא בשרת" — ו"CORS הוא לא אבטחה של השרת".

P15.5-E14 · debounce לשדה חיפוש 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 15 דק׳ידע נדרש: שיעור 3

🔁 חזרה על closures (P05-E26) ועל setTimeout (פרק 10). בשדה חיפוש, אם שולחים fetch על כל הקשה, המילה cors שולחת 4 בקשות לשרת. הפתרון המקובל הוא debounce: מחכים שהמשתמש יפסיק להקליד, ורק אז שולחים בקשה אחת. כתוב וייצא debounce(fn, ms):

  • מחזירה פונקציה חדשה. כל קריאה אליה מבטלת את הטיימר הקודם ומתחילה חדש.
  • fn רצה רק אחרי ms מילישניות בלי קריאה נוספת — פעם אחת, עם הארגומנטים של הקריאה האחרונה.
  • לפונקציה המוחזרת יש מתודה cancel(), שמבטלת קריאה שממתינה (למשל כשהמשתמש עוזב את הדף).
  • כל debounce עם טיימר משלו: שני שדות חיפוש לא מפריעים זה לזה.
const search = debounce((q) => fetch(`/products?q=${q}`), 300);
input.addEventListener("input", () => search(input.value));
