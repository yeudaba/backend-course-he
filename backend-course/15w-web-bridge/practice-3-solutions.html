P15.5-E03 · אותו origin? preflight? 🧠 הבנה רמה 1

💡 רמז 1

origin = פרוטוקול + host + port. כל הבדל — origin אחר.

💡 רמז 2

"פשוטה" = GET/HEAD/POST, בלי headers מיוחדים, ו־Content-Type רק מסוגי טפסים.

✅ פתרון
  1. אותו origin — אין CORS בכלל.
  2. origin אחר (port). בקשה פשוטה ← בלי preflight, אבל התשובה תיחסם בלי Access-Control-Allow-Origin.
  3. origin אחר! 127.0.0.1 ו־localhost הם אותו מחשב, אבל שמות שונים.
  4. אחר; preflight — application/json הופך אותה ל"לא פשוטה".
  5. אחר; preflight — DELETE.
  6. אחר (פרוטוקול).
  7. אחר; preflight — header Authorization.
⚠️ טעויות נפוצות
  • לחשוב ש־localhost ו־127.0.0.1 "זה אותו דבר" — לדפדפן לא. זו סיבה נפוצה ל"זה עבד אתמול".

P15.5-E51 · querySelector שמחזיר null 🧠 הבנה רמה 2

💡 רמז 1

querySelector מחזיר null כשאין התאמה ברגע הקריאה.

💡 רמז 2

סקריפט רגיל ב־head רץ לפני שה־body נקרא. ‏type="module" נדחה (deferred) עד שהדף נטען.

✅ פתרון
  1. שגיאה — newTask ≠ new-task.
  2. שגיאה — הסקריפט רץ כשהטופס עוד לא קיים בעץ.
  3. אין שגיאה — מודול רץ אחרי שכל ה־HTML נקרא.
  4. שגיאה — "new-task" מחפש תגית בשם new-task (P15.5-E35: בלי # — תגית).
  5. שגיאה אם הקוד רץ בהתחלה — הטופס עוד לא שם. פותרים עם האזנה על הורה קבוע (event delegation, P15.5-E59) או מחברים אחרי שיוצרים.
⚠️ טעויות נפוצות
  • "לתקן" עם ?. (querySelector(...)?.addEventListener) — השגיאה נעלמת, וגם הכפתור לא עובד, בלי שום הודעה.

P15.5-E52 · textContent או innerHTML? 🧠 הבנה רמה 1

💡 רמז 1

textContent = "זה טקסט". ‏innerHTML = "זה HTML — פרש אותו".

💡 רמז 2

onerror רץ כשהתמונה נכשלת בטעינה — ו־src=x בטוח ייכשל.

✅ פתרון
  1. הטקסט כמו שהוא, עם הסוגריים. בטוח.
  2. תמונה שבורה ו"קניות" — והקוד רץ (XSS).
  3. אותו דבר, בתוך strong — הקוד רץ.
  4. הטקסט כמו שהוא, מודגש. בטוח — כל עוד לא שוכחים את escapeHtml באף מקום.
  5. הטקסט כמו שהוא, מודגש. בטוח, בלי לחשוב על קידוד.

5 היא הדרך שהשיעור ממליץ עליה: createElement + textContent. אפשרות 4 עובדת, אבל כל שכחה אחת היא פרצה — ולכן הבודקים בשיעור 4 אוסרים innerHTML עם נתונים.

⚠️ טעויות נפוצות
  • "השם הגיע מהשרת שלנו, אז הוא בטוח" — השרת שמר את מה שמשתמש אחר הקליד.

P15.5-E53 · בלי preventDefault 🧠 הבנה רמה 1

💡 רמז 1

ברירת המחדל של טופס היא "שלח את השדות לכתובת ב־action וטען דף חדש" (P15.5-E25). כשאין action — לאותו דף.

💡 רמז 2

ה־handler הוא async: ה־await fetch משחרר את הדפדפן להמשיך — והוא ממשיך לטעון את הדף מחדש.

✅ פתרון
  1. מריץ את ה־handler עד ה־await הראשון, ואז מבצע את ברירת המחדל: שולח את הטופס (GET לאותה כתובת, עם השדות ב־query) וטוען את הדף מחדש.
  2. לפעמים כן ולפעמים לא — תלוי אם הבקשה יצאה לפני שהדף הוחלף. גם אם יצאה, התשובה כבר לא תגיע לקוד (הדף שלו נעלם).
  3. הדף "מהבהב", הטופס מתרוקן, והמשימה לא מופיעה (או מופיעה רק אחרי רענון). בכתובת מופיע ?title=...&priority=.... ה־Network מתנקה בטעינה החדשה.
  4. אין שום שגיאה בקונסול, ולפעמים זה "עובד" — כי הבקשה הספיקה לצאת.
⚠️ טעויות נפוצות
  • לשים את preventDefault() אחרי ה־await — מאוחר מדי: הדפדפן כבר החליט.

P15.5-E54 · לקרוא שגיאת CORS 🧠 הבנה רמה 2

💡 רמז 1

origin הוא פרוטוקול + host + פורט — כטקסט (P14-E35).

💡 רמז 2

preflight נשלח לפני POST עם JSON, ‏PATCH או DELETE (שיעור 3, Preflight).

✅ פתרון
  1. הדף: http://127.0.0.1:5500. היעד: http://localhost:3000/tasks.
  2. בקשה "לא פשוטה" — POST עם Content-Type: application/json, או PATCH/DELETE. הדפדפן שאל קודם ב־OPTIONS.
  3. 127.0.0.1 ו־localhost הם origins שונים, גם אם זה אותו מחשב. השרת התיר רק את http://localhost:5500.
  4. fetch זורק TypeError: Failed to fetch — אין status בכלל, הקוד לא רואה את התשובה (בניגוד ל־404, שמגיע כתשובה).
  5. לפתוח את הדף מ־http://localhost:5500; או להוסיף את http://127.0.0.1:5500 לרשימה (דרך CORS_ORIGINS, שיעור 4).
⚠️ טעויות נפוצות
  • לחפש את התקלה בקוד ה־route — הבקשה האמיתית בכלל לא נשלחה; ה־preflight נחסם.

P15.5-E55 · שתי לחיצות, שתי משימות 🧠 הבנה רמה 2

💡 רמז 1

כל לחיצה היא אירוע submit נפרד, וכל אחד מריץ את ה־handler מההתחלה.

💡 רמז 2

כפתור עם disabled = true לא שולח את הטופס.

✅ פתרון
  1. שתי בקשות, שתי משימות זהות.
  2. preventDefault מונע רק את ברירת המחדל של הדפדפן (טעינת דף) — לא את הריצה של ה־handler שלך.
  3. בתחילת ה־handler: button.disabled = true;, ואת כל השאר בתוך try { ... } finally { button.disabled = false; } — כך הכפתור חוזר גם אם הבקשה נכשלה. (P15.5-E61 כותב את זה כפונקציה.)
  4. כי לקוח אחר (אפליקציה, סקריפט, רשת שמנסה שוב) יכול לשלוח פעמיים. POST אינו idempotent — מפתח idempotency (P15-E25) מאפשר לשרת לזהות "זו אותה בקשה".
⚠️ טעויות נפוצות
  • לנעול את הכפתור ולשחרר אותו רק כשהבקשה הצליחה — אחרי שגיאה הכפתור נשאר נעול, והמשתמש תקוע.

P15.5-E06 · קידוד HTML 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

& קודם — אחרת < הופך ל־&lt; ואז ל־&amp;lt;.

💡 רמז 2

replaceAll חמש פעמים, או replace(/[&<>"']/g, (ch) => map[ch]).

✅ פתרון
// P15.5-E06
const ENTITIES = { "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" };

export function escapeHtml(value) {
  if (value === null || value === undefined) return "";
  return String(value).replace(/[&<>"']/g, (ch) => ENTITIES[ch]);
}

export function renderTaskItem(task) {
  return `<li class="task ${escapeHtml(task.priority)}">${escapeHtml(task.title)}</li>`;
}

console.log(renderTaskItem({ title: '<img src=x onerror="alert(1)">', priority: "high" }));
console.log(renderTaskItem({ title: "Tom & Jerry", priority: 'x" onclick="alert(1)' }));

השורה השנייה מראה למה מקודדים גם ערכים בתוך תכונות: בלי &quot;, ה־priority היה "סוגר" את ה־class ומוסיף onclick.

⚠️ טעויות נפוצות
  • לקודד רק < ו־> — מירכאות בתוך תכונה עדיין מאפשרות הזרקה.

P15.5-E08 · לקוח API 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

פונקציה פנימית אחת request(method, path, body), וכל המתודות קוראות לה.

💡 רמז 2

גוף שגיאה לא JSON: await res.json().catch(() => null).

✅ פתרון
// P15.5-E08
export class ApiError extends Error {
  constructor(status, code, message, details = []) {
    super(message);
    this.name = "ApiError";
    this.status = status;
    this.code = code;
    this.details = details;
  }
}

export function createApiClient(baseUrl) {
  async function request(method, path, body) {
    const res = await fetch(baseUrl + path, {
      method,
      headers: body === undefined ? {} : { "Content-Type": "application/json" },
      body: body === undefined ? undefined : JSON.stringify(body),
    });
    if (res.status === 204) return undefined;
    const data = await res.json().catch(() => null);
    if (!res.ok) {
      const e = data?.error;
      throw new ApiError(res.status, e?.code ?? "UNKNOWN", e?.message ?? `HTTP ${res.status}`, e?.details ?? []);
    }
    return data;
  }

  return {
    listTasks(params = {}) {
      const sp = new URLSearchParams();
      for (const [k, v] of Object.entries(params)) if (v !== "" && v !== undefined && v !== null) sp.append(k, String(v));
      const qs = sp.toString();
      return request("GET", `/tasks${qs ? `?${qs}` : ""}`);
    },
    createTask: (body) => request("POST", "/tasks", body),
    updateTask: (id, changes) => request("PATCH", `/tasks/${id}`, changes),
    deleteTask: (id) => request("DELETE", `/tasks/${id}`),
  };
}

בדף: const api = createApiClient("http://localhost:3000"), ואז try { await api.createTask(...) } catch (err) { if (err instanceof ApiError) showError(err.message) }. כל הידע על HTTP במקום אחד; שאר הקוד מדבר במונחים של "משימות". זה דפוס שתמצא בכל Frontend רציני — וגם ב־Backend, כשאתה קורא לשירות אחר.

⚠️ טעויות נפוצות
  • לקרוא res.json() על 204 — זורק, כי אין גוף.

P15.5-E09 · CORS בלי ספרייה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

res.vary("Origin") או res.append("Vary", "Origin").

💡 רמז 2

למה Vary? כי התשובה שונה לפי origin — cache (פרק 26) חייב לדעת לא להגיש תשובה של origin אחד לאחר.

✅ פתרון
// P15.5-E09
import type { Request, Response, NextFunction } from "express";

export function corsMiddleware(origins: string[]) {
  const allowed = new Set(origins);
  return (req: Request, res: Response, next: NextFunction) => {
    const origin = req.get("origin");
    const ok = origin !== undefined && allowed.has(origin);
    res.vary("Origin");
    if (ok) res.set("Access-Control-Allow-Origin", origin);

    if (req.method === "OPTIONS") {
      if (ok) {
        res.set({
          "Access-Control-Allow-Methods": "GET,POST,PUT,PATCH,DELETE",
          "Access-Control-Allow-Headers": req.get("access-control-request-headers") ?? "Content-Type",
          "Access-Control-Max-Age": "600",
        });
      }
      res.sendStatus(204);
      return;
    }
    next();
  };
}

Max-Age אומר לדפדפן "אל תשאל שוב 10 דקות" — בלי זה, כל PATCH הוא שתי בקשות.

⚠️ טעויות נפוצות
  • להחזיר 403 לבקשה רגילה מ־origin לא מורשה — שובר לקוחות שאינם דפדפן (שרתים, אפליקציות), שבכלל לא שולחים Origin או ש־CORS לא רלוונטי להם.

export function renderComments(comments) {
  const items = comments.map((c) => `<li><b>${escapeHtml(c.author || "אנונימי")}</b>: ${escapeHtml(c.text)}</li>`);

export async function postComment(baseUrl, text) {
  const res = await fetch(`${baseUrl}/comments`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ text }),

P15.5-E56 · רשימת משימות ב־DOM 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

const items = tasks.map((t) => { const li = doc.createElement("li"); ...; return li; }); ואז ul.replaceChildren(...items).

💡 רמז 2

li.classList.toggle("done", t.done) — מוסיף אם true, מוריד אם false.

✅ פתרון
// P15.5-E56: רשימת משימות ב־DOM
export function renderTasks(doc, ul, tasks) {
  if (tasks.length === 0) {
    const li = doc.createElement("li");
    li.classList.add("empty");
    li.textContent = "אין משימות";
    ul.replaceChildren(li);
    return;
  }
  ul.replaceChildren(
    ...tasks.map((t) => {
      const li = doc.createElement("li");
      li.textContent = t.title;
      li.dataset.id = t.id;
      li.classList.toggle("done", t.done);
      return li;
    }),
  );
}

בדפדפן: renderTasks(document, document.querySelector("#tasks"), data). העברת doc כפרמטר (במקום להשתמש ב־document הגלובלי) היא אותה הזרקת תלות כמו בפרק 12 — וזה מה שמאפשר לבדוק את הפונקציה ב־Node, בלי דפדפן. ‏replaceChildren מנקה ומוסיף בפעולה אחת — הרשימה תמיד משקפת בדיוק את tasks.

⚠️ טעויות נפוצות
  • ul.append(...) בלי לנקות — כל טעינה מוסיפה עוד עותק של הרשימה.
  • li.className = t.done ? "done" : "" — עובד, אבל מוחק classes אחרים שאולי יש ל־li.

P15.5-E57 · מונה עם כפתורים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

פונקציה פנימית render() שמעדכנת את הטקסט ואת שני ה־disabled — קוראים לה בהתחלה ואחרי כל שינוי.

💡 רמז 2

המונה הוא משתנה בתוך bindCounter (closure, פרק 5) — לא ה־textContent. אל תקרא מספרים מהדף.

✅ פתרון
// P15.5-E57: מונה עם כפתורים
export function bindCounter(doc, { max = 10 } = {}) {
  const dec = doc.querySelector("#dec");
  const inc = doc.querySelector("#inc");
  const out = doc.querySelector("#count");
  let value = 0;

  function render() {
    out.textContent = String(value);
    dec.disabled = value === 0;
    inc.disabled = value === max;
  }

  inc.addEventListener("click", () => {
    if (value < max) value++;
    render();
  });
  dec.addEventListener("click", () => {
    if (value > 0) value--;
    render();
  });
  render();
  return () => value;
}

"המצב בקוד, הדף רק מציג אותו": המונה הוא משתנה, ו־render() מסנכרן את הדף לפיו. הבדיקה if (value < max) מגינה גם אם מישהו "מבטל" את ה־disabled דרך DevTools. זה הרעיון שספריות כמו React בנויות עליו.

⚠️ טעויות נפוצות
  • Number(out.textContent) + 1 — המצב "חי" בתוך הדף, ופתאום הוא "NaN" אחרי שמישהו שינה טקסט.
  • לעדכן את ה־disabled רק בלחיצות — בהתחלה #dec לא נעול.

P15.5-E59 · סדר הדברים ב־submit אסינכרוני 🧠 הבנה רמה 2

P15.5-E60 · השרת ביצע — הדפדפן חסם 🧠 הבנה רמה 3

💡 רמז 1

P15.5-E14 · debounce לשדה חיפוש 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

משתנה אחד let timer מחוץ לפונקציה המוחזרת, אבל בתוך debounce. זה ה־closure: הוא "זוכר" את הטיימר בין קריאה לקריאה. בכל קריאה: clearTimeout(timer) ואז timer = setTimeout(...).

💡 רמז 2

ארגומנטים: function debounced(...args) { ... setTimeout(() => fn(...args), ms) }. מתודה על פונקציה: debounced.cancel = () => clearTimeout(timer); — פונקציה היא גם אובייקט.

✅ פתרון
// P15.5-E14: debounce לשדה חיפוש
export function debounce(fn, ms) {
  let timer = null;
  function debounced(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      fn(...args);
    }, ms);
  }
  debounced.cancel = () => {
    clearTimeout(timer);
    timer = null;
  };
  return debounced;
}

// המשתמש מקליד "c", "co", "cor", "cors" — 30ms בין הקשות. החיפוש רץ פעם אחת, 100ms אחרי ההקשה האחרונה
const search = debounce((q) => console.log("מחפשים:", q), 100);
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
for (const q of ["c", "co", "cor", "cors"]) {
  search(q);
  await sleep(30);
}
await sleep(150);
search("x");
search.cancel();
await sleep(150);
console.log("סוף");
מחפשים: cors
סוף

ה־closure הוא timer: כל קריאה ל־debounce יוצרת משתנה חדש, וכל פונקציה מוחזרת רואה רק את שלה. זה אותו מנגנון כמו המונה ב־P05-E26. שם הזיכרון היה מספר, וכאן הוא טיימר.

clearTimeout(null) לא עושה כלום, ולכן אין צורך לבדוק אם יש טיימר לפני שמבטלים.

בהדגמה, ארבע הקשות במרווח 30ms. כל אחת "מאפסת את השעון", ורק 100ms אחרי ההקשה האחרונה החיפוש רץ — פעם אחת, עם "cors". הקריאה עם "x" בוטלה עם cancel, ולכן לא הודפסה.

⚠️ טעויות נפוצות
  • let timer מחוץ ל־debounce (ברמת הקובץ) — כל השדות חולקים טיימר אחד, ושדה אחד מבטל את החיפוש של השני.
  • לשמור את הארגומנטים של הקריאה הראשונה — מחפשים "c" במקום "cors".
  • להפעיל את fn מיד ולחסום קריאות בהמשך — זה throttle, לא debounce.

P15.5-E15 · טעינת לוח בקרה במקביל 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

Promise.all נכשל כולו אם בקשה אחת נכשלה, ולכן כאן משתמשים ב־Promise.allSettled: לכל בקשה מקבלים { status: "fulfilled", value } או { status: "rejected", reason }. ‏const [me, tasks, stats] = await Promise.allSettled([...]).

💡 רמז 2

if (me.status === "rejected") throw me.reason;. לשתי האחרות — פונקציית עזר valueOf(result, name) שמחזירה result.value, או מוסיפה ל־errors ומחזירה null.

✅ פתרון
// P15.5-E15: טעינת לוח בקרה במקביל
export async function loadDashboard(getJson) {
  const [me, tasks, stats] = await Promise.allSettled([getJson("/me"), getJson("/tasks"), getJson("/stats")]);
  if (me.status === "rejected") {
    throw me.reason;
  }
  const errors = [];
  const valueOf = (result, name) => {
    if (result.status === "fulfilled") {
      return result.value;
    }
    errors.push(`${name}: ${result.reason.message}`);
    return null;
  };
  return { me: me.value, tasks: valueOf(tasks, "tasks"), stats: valueOf(stats, "stats"), errors };
}

const data = { "/me": { name: "דנה" }, "/tasks": [{ id: 1, title: "ללמוד CORS" }] };
const getJson = async (path) => {
  await new Promise((resolve) => setTimeout(resolve, 50));
  if (!(path in data)) throw new Error("503 Service Unavailable");
  return data[path];
};

const start = Date.now();
const dashboard = await loadDashboard(getJson);
console.log(dashboard);
console.log(Date.now() - start < 100 ? "במקביל" : "אחד אחרי השני");

במקביל

שלוש בקשות של 50ms לקחו פחות מ־100ms, כי הן יצאו יחד. אחת אחרי השנייה זה היה לוקח 150ms.

ההחלטה מה "חובה" ומה "רשות" היא החלטה של הדף, לא של הרשת. בלי /me אי אפשר להציג כלום, ולכן זורקים, ומי שקרא ל־loadDashboard יעביר לדף ההתחברות. בלי סטטיסטיקה עדיין אפשר לעבוד, ולכן מציגים את הדף עם הודעה קטנה.

throw me.reason זורק את השגיאה המקורית ולא שגיאה חדשה. כך נשמרים ה־status וכל השדות ש־ApiError (P15.5-E08) הוסיפה.

⚠️ טעויות נפוצות
  • await getJson("/me"), אחר כך await getJson("/tasks")... — עובד, אבל לאט פי שלושה. הבודק מודד.
  • Promise.all — תקלה ב־/stats מפילה את כל הדף.
  • throw new Error("לא מחובר") במקום throw me.reason — מאבדים את סוג השגיאה ואת ההודעה מהשרת.

P15.5-E61 · כפתור שננעל בזמן שליחה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

return async (...args) => { if (button.disabled) return; const label = button.textContent; button.disabled = true; ... }

💡 רמז 2

try { return await fn(...args); } finally { ... } — ה־finally רץ גם אחרי return וגם אחרי throw.

✅ פתרון
// P15.5-E61: כפתור שננעל בזמן שליחה
export function withLock(button, fn) {
  return async (...args) => {
    if (button.disabled) return undefined;
    const label = button.textContent;
    button.disabled = true;
    button.textContent = "שולח...";
    try {
      return await fn(...args);
    } finally {
      button.disabled = false;
      button.textContent = label;
    }
  };
}

  await new Promise((r) => setTimeout(r, 30));
  if (title === "") throw new Error("כותרת ריקה");
  return { id: 1, title };
});

שימו לב ל־return await בתוך try: בלי ה־await, הפונקציה הייתה מחזירה את ה־Promise מיד — וה־finally היה משחרר את הכפתור לפני שהשליחה הסתיימה. זה הבדל קטן בכתיבה, וגדול בהתנהגות.

⚠️ טעויות נפוצות
  • return fn(...args) (בלי await) בתוך ה־try — הנעילה משתחררת מיד.
  • לשחזר את הטקסט ל"הוספה" קבוע — כפתור אחר ("שמירה") יחזור עם טקסט שגוי.
