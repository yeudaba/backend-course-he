P15.5-E33 · מי מנצח? 🧠 הבנה רמה 2

💡 רמז 1

סופרים לפי סדר: כמה #id, אחר כך כמה .class, אחר כך כמה תגיות. משווים משמאל לימין.

💡 רמז 2

.card h2 = class אחד + תגית אחת. .title = class אחד. מי מפורט יותר?

✅ פתרון
  1. כחול — class מנצח תגית.
  2. אדום — id אחד מנצח כל מספר של classes.
  3. סגול — שוויון (class אחד מול class אחד), והאחרון בקובץ מנצח.
  4. כתום — .card h2 (class + תגית) מפורט יותר מ־.title (class), גם אם הוא מוקדם יותר.
  5. חום — .card .big (שני classes) מול h2.title (class + תגית): בעמודת ה־classes 2 מול 1.

ב־P15.5-E44 תכתוב את החישוב הזה כפונקציה. ובפועל: כש"הצבע לא משתנה", DevTools ← Styles מראה את הכלל שניצח, והמפסידים מחוקים בקו.

⚠️ טעויות נפוצות
  • לחשוב ש"האחרון תמיד מנצח" — רק בשוויון.

P15.5-E34 · padding או margin? 🧠 הבנה רמה 1

💡 רמז 1

padding — בתוך המסגרת: חלק מהקופסה, עם הרקע שלה, ולחיץ. margin — מחוץ למסגרת: שקוף, לא שייך לאלמנט.

💡 רמז 2

margin נספר בשני הצדדים, וכך גם padding ו־border.

✅ פתרון
  1. padding.
  2. margin (או gap על ההורה, אם הוא flex).
  3. padding — השטח הלחיץ הוא הקופסה עצמה; margin לא לחיץ.
  4. padding — הרקע ממלא גם את ה־padding.
  5. margin (למשל margin-top על הרשימה).

בלי border-box: התוכן 300, ועוד 16×2 padding, 2×2 border ← הקופסה 336px, ועם ה־margin היא תופסת 356px. עם border-box: הקופסה 300px בדיוק (התוכן מצטמצם ל־264), ועם ה־margin — 320px.

⚠️ טעויות נפוצות
  • להגדיל כפתור עם margin — הוא נראה רחוק יותר מהשכנים, אבל קשה ללחוץ עליו בדיוק כמו קודם.

P15.5-E35 · מה כל selector בוחר? 🧠 הבנה רמה 2

💡 רמז 1

בלי רווח (li.done) — אותו אלמנט, שני תנאים. עם רווח (li .done) — .done בתוך li.

💡 רמז 2

"בתוך" כולל כל עומק — לא רק ילד ישיר.

✅ פתרון
  1. שלושת ה־li.
  2. "לקנות חלב", ה־span "✓", ו"פסקה".
  3. רק "לקנות חלב".
  4. רק ה־span "✓" — הוא .done בתוך .task. ("לקנות חלב" עצמו הוא .task.done, לא בתוך .task.)
  5. שלושת ה־li.
  6. שני ה־li עם task.
  7. רק ה־span.

רווח אחד משנה הכול: li.done מול li .done. ובשיעור 3, document.querySelectorAll מקבל בדיוק את אותם selectors.

⚠️ טעויות נפוצות
  • לכתוב .task .done כשהכוונה "משימה שבוצעה" — זה .task.done.

P15.5-E36 · flexbox מימין לשמאל 🧠 הבנה רמה 2

💡 רמז 1

ב־RTL, "התחלה" (start) היא ימין.

💡 רמז 2

flex: 1 — "קח את כל המקום שנשאר". אם ילד אחד לוקח הכול, ל־space-between אין מה לפזר.

✅ פתרון
  1. צ'קבוקס בקצה הימני, כפתור בקצה השמאלי, הכותרת באמצע (הרווח מתחלק שווה בין שלושתם). כולם ממורכזים לגובה.
  2. הכותרת מתמתחת על כל הרווח: צ'קבוקס מימין, מיד אחריו הכותרת (שתופסת את כל האמצע), והכפתור בקצה השמאלי. זה הסידור שרוצים ברשימת משימות.
  3. שלושתם צמודים לימין, אחד אחרי השני; משמאל — מקום ריק.
  4. הם נערמים אחד מתחת לשני (צ'קבוקס, כותרת, כפתור). עכשיו justify-content פועל לגובה, ו־align-items לרוחב.
  5. הכול מתהפך: הצ'קבוקס בקצה השמאלי, הכפתור בימני — בלי לשנות שורה ב־CSS.
⚠️ טעויות נפוצות
  • לכתוב float: right או margin-left: auto "כדי שיהיה בצד ימין" — שוברים את התמיכה האוטומטית ב־RTL.

P15.5-E44 · לחשב specificity 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

regex עם matchAll: ‏/#[\w-]+/g ל־ids, ‏/\.[\w-]+|\[[^\]]+\]|:[\w-]+/g ל־classes. לתגיות: מורידים את כל אלה ובודקים מה נשאר בתחילת כל חלק.

💡 רמז 2

תגית: selector.split(/\s+/), ולכל חלק — /^[a-z][\w-]*/i.

✅ פתרון
// P15.5-E44: לחשב specificity
export function specificity(selector) {
  const ids = (selector.match(/#[\w-]+/g) ?? []).length;
  const classes = (selector.match(/\.[\w-]+|\[[^\]]+\]|:[\w-]+/g) ?? []).length;
  const tags = selector
    .trim()
    .split(/\s+/)
    .filter((part) => /^[a-z][\w-]*/i.test(part)).length;
  return [ids, classes, tags];
}

function compare(a, b) {
  for (let i = 0; i < 3; i++) if (a[i] !== b[i]) return a[i] - b[i];
  return 0;
}

export function winner(element, rules) {
  let best;
  for (const rule of rules) {
    if (!best || compare(specificity(rule.selector), specificity(best.selector)) >= 0) best = rule;
  }
  return best?.value;
}

for (const s of ["#main .card h2:hover", "ul li.done", ".card .title", "h2", "*", "input[type=email]"]) {
  console.log(s.padEnd(22), specificity(s));
}

ההשוואה היא "לקסיקוגרפית": ‏[1, 0, 0] מנצח [0, 10, 0] — אין מספר classes שמשתווה ל־id. ‏>= 0 בלולאה הוא שגורם לאחרון לנצח בשוויון. (הדפדפן מחשב בדיוק את זה, ועוד: ‏!important ו־style="" על האלמנט גוברים על הכול.)

⚠️ טעויות נפוצות
  • לחבר את שלושת המספרים (ids*100 + classes*10 + tags) — 11 classes "מנצחים" id אחד.
  • > 0 בהשוואה — בשוויון ינצח הראשון, לא האחרון.

P15.5-E45 · למה ה־CSS לא נטען? 🧠 הבנה רמה 2

💡 רמז 1

href="style.css" (בלי /) הוא יחסי לתיקייה של הדף — כמו new URL("style.css", base).

💡 רמז 2

שרת הקבצים (serve-web.mjs) קובע את ה־Content-Type לפי הסיומת.

✅ פתרון
  1. כתובת יחסית: new URL("style.css", "http://localhost:5500/tasks/index.html") ← /tasks/style.css. תיקון: href="/style.css" (מהשורש), או להעביר את הקובץ.
  2. השרת שולח סוג שגוי, והדפדפן מסרב להשתמש בקובץ (הגנה). תיקון בשרת: .css ← text/css (כמו במפה types של serve-web.mjs).
  3. cache: הדפדפן משתמש בעותק ששמר. ⌘⇧R עוקף אותו; בפיתוח — DevTools ← Network ← Disable cache. בייצור פותרים עם שם קובץ שמשתנה בכל גרסה (style.a1b2.css).
  4. הדפדפן לא הגיע לשורה: <link> לא ב־head, טעות כתיב (rel="stylesheets"), או שהקובץ שאתה עורך הוא לא הקובץ שהדפדפן פתח.
⚠️ טעויות נפוצות
  • להתחיל לשנות CSS "כי הוא לא עובד", לפני שבודקים ב־Network שהקובץ בכלל נטען.

P15.5-E48 · hex ל־rgb ובחזרה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

נרמל קודם: אם 3 ספרות — הכפל כל אחת. אחר כך parseInt(h.slice(0, 2), 16) וכו׳.

💡 רמז 2

const two = (n) => n.toString(16).padStart(2, "0");

✅ פתרון
// P15.5-E48: hex ל־rgb ובחזרה
export function hexToRgb(hex) {
  if (typeof hex !== "string" || !/^#([0-9a-f]{3}){1,2}$/i.test(hex)) throw new Error(`צבע לא תקין: ${hex}`);
  let h = hex.slice(1);
  if (h.length === 3) h = [...h].map((c) => c + c).join("");
  return { r: parseInt(h.slice(0, 2), 16), g: parseInt(h.slice(2, 4), 16), b: parseInt(h.slice(4, 6), 16) };
}

export function rgbToHex({ r, g, b }) {
  const two = (n) => {
    if (!Number.isInteger(n) || n < 0 || n > 255) throw new Error("ערך rgb לא תקין");
    return n.toString(16).padStart(2, "0");
  };
  return `#${two(r)}${two(g)}${two(b)}`;
}

for (const bad of ["#abcd", "red"]) {
  try {
    hexToRgb(bad);
  } catch (err) {
    console.log(err.message);
  }
}

P15.5-E49 · יחס ניגודיות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

const [R, G, B] = [r, g, b].map((c) => { const s = c / 255; return s <= 0.03928 ? ... : ...; });

💡 רמז 2

עיגול ל־2 ספרות: Math.round(x * 100) / 100. ‏Math.max ו־Math.min בוחרים מי בהיר.

✅ פתרון
// P15.5-E49: יחס ניגודיות
function rgb(hex) {
  let h = hex.slice(1);
  if (h.length === 3) h = [...h].map((c) => c + c).join("");
  return [0, 2, 4].map((i) => parseInt(h.slice(i, i + 2), 16));
}

export function luminance(hex) {
  const [R, G, B] = rgb(hex).map((c) => {
    const s = c / 255;
    return s <= 0.03928 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * R + 0.7152 * G + 0.0722 * B;
}

export function contrast(hex1, hex2) {
  const a = luminance(hex1);
  const b = luminance(hex2);
  const ratio = (Math.max(a, b) + 0.05) / (Math.min(a, b) + 0.05);
  return Math.round(ratio * 100) / 100;
}

export function readable(fg, bg) {
  return contrast(fg, bg) >= 4.5;
}

for (const [fg, bg] of [["#000", "#fff"], ["#8c959f", "#ffffff"], ["#0969da", "#ffffff"], ["#82071e", "#ffebe9"], ["#fff", "#fff"]]) {
  console.log(fg, bg, contrast(fg, bg), readable(fg, bg));
}

P15.5-E50 · לכווץ CSS 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שרשרת של replace: הערות (/\/\*[\s\S]*?\*\//g), רווחים (/\s+/g), ואז רווח סביב התווים המיוחדים: /\s*([{}:;,])\s*/g ← "$1".

💡 רמז 2

הסדר חשוב: הערות לפני רווחים (אחרת הערה על כמה שורות נשארת "מכווצת" באמצע). ו־*? (לא חמדן) — אחרת שתי הערות מוחקות את כל מה שביניהן.

✅ פתרון
// P15.5-E50: לכווץ CSS
export function minifyCss(css) {
  return css
    .replace(/\/\*[\s\S]*?\*\//g, "")
    .replace(/\s+/g, " ")
    .replace(/\s*([{}:;,])\s*/g, "$1")
    .replace(/;}/g, "}")
    .trim();
}

const css = `/* כפתורים */
button,
.btn {
  padding: 8px 16px;
  border: none;   /* בלי מסגרת */
}

.card h2 { margin-top: 0; }
button:hover { background: #0550ae; }
`;
console.log(minifyCss(css));
console.log(css.length, "←", minifyCss(css).length, "תווים");
button,.btn{padding:8px 16px;border:none}.card h2{margin-top:0}button:hover{background:#0550ae}
153 ← 95 תווים

שימו לב: הרווח בתוך .card h2 ובתוך 8px 16px נשאר — הוא חלק מהמשמעות (צאצא; שני ערכים). רק רווח סביב תווים מפרידים מיותר. כלים אמיתיים (esbuild, lightningcss) עושים גם יותר — מקצרים צבעים (#ffffff ← #fff) ומאחדים כללים.

⚠️ טעויות נפוצות
  • למחוק את כל הרווחים — .card h2 הופך ל־.cardh2, ו־8px 16px ל־8px16px.
  • /\/\*.*\*\// בלי [\s\S] ובלי ? — לא תופס הערה על כמה שורות, ומוחק בין שתי הערות באותה שורה.
