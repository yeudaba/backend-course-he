P18-E04 · index או לא?

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 3

טבלת orders עם 10 מיליון שורות. לכל שאילתה — האם index יעזור, ואיזה?

  1. WHERE customer_id = $1 ORDER BY created_at DESC LIMIT 20
  2. WHERE status = 'shipped' (95% מההזמנות)
  3. WHERE lower(coupon_code) = $1
  4. WHERE note LIKE '%gift%'
  5. WHERE created_at >= now() - interval '1 day'
  6. טבלת countries עם 200 שורות, WHERE code = 'IL'

P18-E11 · index להזמנות של לקוח 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: שיעור 3

מסך "ההזמנות שלי" מריץ: SELECT id, total, created_at FROM big_orders WHERE customer_id = $1 ORDER BY created_at DESC LIMIT 10. בקובץ 18-consistency/starter/P18-E11.sql צור index אחד, כך שהשאילתה לא תסרוק את הטבלה וגם לא תצטרך למיין.

P18-E12 · בעלים ייחודי 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: שיעור 3

בקובץ 18-consistency/starter/P18-E12.sql: דאג שלא יהיו שני חשבונות לאותו בעלים, בלי תלות באותיות (Dana ו־dana — אותו אדם). (אילוץ UNIQUE רגיל על owner לא יספיק.)

P18-E15 · index חלקי 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 15 דק׳ידע נדרש: שיעור 3

מסך המחסן מריץ כל כמה שניות: SELECT id, total FROM big_orders WHERE status IN ('paid', 'pending') ORDER BY created_at LIMIT 50. בקובץ 18-consistency/starter/P18-E15.sql צור index חלקי שמכיל רק את ההזמנות הפתוחות, ושהשאילתה תשתמש בו בלי למיין.

P18-E16 · index ל־foreign keys 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 10 דק׳ידע נדרש: שיעור 3

"ההעברות של חשבון X" (יוצאות ונכנסות) מריצה WHERE from_id = $1 ו־WHERE to_id = $1. וגם מחיקת חשבון צריכה לבדוק שאין העברות שמצביעות עליו. בקובץ 18-consistency/starter/P18-E16.sql הוסף את ה־indexes החסרים.

P18-E22 · ה־index שלא בשימוש 🤖

💻 כתיבת קוד 🤖רמה 4⏱ 15 דק׳ידע נדרש: שיעור 3

בקובץ 18-consistency/starter/P18-E22.sql יש index על created_at, ושאילתה של "הזמנות מ־1 ביוני 2025" (לפי שעון ישראל). השאילתה מחזירה את התוצאה הנכונה — אבל סורקת את כל הטבלה. תקן את השאילתה (לא את ה־index) כך שתשתמש בו ותחזיר אותן שורות.
