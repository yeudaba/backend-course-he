P18-E01 · מה נשמר? 🧠 הבנה רמה 1

💡 רמז 1

ב־ב' אין BEGIN — כל פקודה עומדת לבד. ומה קורה ב־UPDATE שלא מוצא שורה?

💡 רמז 2

ב־ג', ל־Dana יש 1000.

✅ פתרון
  1. Dana 1000, Noa 0 — הכול בוטל.
  2. Dana 900, Noa 0 — באג: הפקודה השנייה לא נכשלה, היא פשוט עדכנה 0 שורות (UPDATE 0). 100 ש״ח נעלמו. transaction לא היה עוזר כאן — צריך לבדוק rowCount ולזרוק (ואז ה־ROLLBACK יבטל את הראשונה).
  3. Dana 1000, Noa 0 — העדכון הראשון הפר את ה־CHECK, ה־transaction בוטל, ו־COMMIT הפך ל־ROLLBACK.
⚠️ טעויות נפוצות
  • לחשוב ש"0 שורות עודכנו" זו שגיאה — מבחינת המסד זו הצלחה.

P18-E29 · אחרי השגיאה — שום דבר לא עובר 🧠 הבנה רמה 2

💡 רמז 1

ל־Yossi (2) יש 250. מה ה־CHECK על balance?

💡 רמז 2

אחרי שגיאה, ה־transaction "מת": כל פקודה נדחית עד סוף הבלוק — וגם ה־COMMIT לא באמת שומר.

✅ פתרון
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance - 999 WHERE id = 2;
SELECT balance FROM accounts WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 3;
COMMIT;
SELECT id, balance FROM accounts WHERE id IN (1, 3) ORDER BY id;
BEGIN
UPDATE 1
ERROR:  new row for relation "accounts" violates check constraint "accounts_balance_check"
DETAIL:  Failing row contains (2, Yossi, -749.00).
ERROR:  current transaction is aborted, commands ignored until end of transaction block
ERROR:  current transaction is aborted, commands ignored until end of transaction block
ROLLBACK
 id | balance
----+---------
  1 | 1000.00
  3 |    0.00
(2 rows)

אחרי השגיאה המסד לא מוכן לעשות כלום בתוך ה־transaction — גם לא SELECT — עד שהוא נסגר. ה־COMMIT מחזיר ROLLBACK: גם העדכון הראשון של Dana בוטל. בקוד: אם לא תבדוק שגיאות, אתה עלול לחשוב ש"ה־COMMIT עבר" — ולכן ב־Node כל שגיאה זורקת, וה־catch עושה ROLLBACK.

⚠️ טעויות נפוצות
  • להמשיך "לתקן" בתוך אותו transaction אחרי שגיאה (עוד UPDATE, עוד SELECT) — כל פקודה תיכשל באותה הודעה. צריך ROLLBACK ולהתחיל מחדש.

P18-E30 · ‏ACID — איזו אות? 🧠 הבנה רמה 1

💡 רמז 1

A — הכול או כלום. C — האילוצים מתקיימים. I — לא רואים חצאי עבודה של אחרים. D — מה ש־commit שורד.

💡 רמז 2

בסעיף 5, איזו תכונה חסרה?

✅ פתרון
  1. A — שתי הפקודות יחד או אף אחת.
  2. D — PostgreSQL כותב ליומן (WAL) בדיסק לפני שהוא מחזיר הצלחה ל־COMMIT.
  3. I — שינויים שלא נעשה להם commit לא נראים לחיבורים אחרים.
  4. C — ה־CHECK מבטיח שאחרי כל commit החוקים מתקיימים.
  5. חסר D — "נשמר" אצלה זה "נשמר בזיכרון". (זה בדיוק ההבדל בין Redis בתצורה מסוימת למסד יחסי — יחידה 26.)
⚠️ טעויות נפוצות
  • לבלבל C של ACID עם "עקביות" במערכות מבוזרות (CAP) — כאן היא רק "האילוצים שלך מתקיימים".

P18-E31 · מה השעה בתוך transaction? 🧠 הבנה רמה 2

💡 רמז 1

now() מחזיר את הזמן שבו ה־transaction התחיל. ‏clock_timestamp() — את הזמן ברגע הזה.

💡 רמז 2

כמה ערכים שונים של created_at יש בשתי השורות?

✅ פתרון
BEGIN;
SELECT pg_sleep(0.2);
SELECT now() = transaction_timestamp() AS now_is_start, clock_timestamp() > now() AS clock_moved;
INSERT INTO transfers (from_id, to_id, amount) VALUES (1, 3, 10);
SELECT pg_sleep(0.2);
INSERT INTO transfers (from_id, to_id, amount) VALUES (4, 3, 20);
SELECT COUNT(*) AS transfers, COUNT(DISTINCT created_at) AS different_times FROM transfers;
COMMIT;
BEGIN
 pg_sleep
----------

(1 row)

 now_is_start | clock_moved
--------------+-------------
 t            | t
(1 row)

INSERT 0 1
 pg_sleep
----------

(1 row)

INSERT 0 1
 transfers | different_times
-----------+-----------------
         2 |               1
(1 row)

COMMIT

בתוך transaction, now() "קפוא" — לכל השורות שנכתבו בו אותה שעה. זה מכוון: כל מה שקרה ב־transaction קרה "ברגע אחד" (גם זה חלק מ־A). אבל זה מפתיע אם ממיינים לפי created_at: שתי השורות שוות, וצריך שובר שוויון (id) — שיעור 4.

⚠️ טעויות נפוצות
  • להשתמש ב־now() כדי למדוד כמה זמן לקח משהו בתוך transaction — תמיד 0. למדידה: clock_timestamp().

P18-E32 · מה ROLLBACK לא מבטל 🧠 הבנה רמה 2

💡 רמז 1

מונה ה־IDENTITY מתקדם גם כשה־INSERT מתבטל — כדי ששני transactions במקביל לא יקבלו אותו מספר.

💡 רמז 2

ROLLBACK מבטל שינויים במסד. האימייל כבר יצא מהשרת.

✅ פתרון
BEGIN;
INSERT INTO transfers (from_id, to_id, amount) VALUES (1, 3, 50) RETURNING id;
ROLLBACK;
INSERT INTO transfers (from_id, to_id, amount) VALUES (1, 3, 50) RETURNING id;
BEGIN
 id
----
  1
(1 row)

INSERT 0 1
ROLLBACK
 id
----
  2
(1 row)

INSERT 0 1

(1) המספר 1 "נשרף" — ה־ROLLBACK לא מחזיר אותו. מספרים מ־IDENTITY הם ייחודיים, לא רציפים (אל תשתמש בהם כ"מספר חשבונית" שחייב להיות רציף). (2) אם ה־COMMIT נכשל — הלקוח קיבל אימייל על העברה שלא קרתה. כל מה שיוצא מהמסד (אימייל, קריאה ל־API של תשלומים, קובץ) לא מתבטל ב־ROLLBACK. שולחים אחרי COMMIT מוצלח (ואם השליחה נכשלת — מנסים שוב; ההעברה כבר אמיתית). וגם: שליחה בתוך transaction פתוח מחזיקה נעילות כל זמן השליחה (שיעור 2).

⚠️ טעויות נפוצות
  • "נשלח את האימייל לפני, כדי שהלקוח יקבל מהר" — מהיר, ולפעמים שקרי.

P18-E33 · ‏BEGIN כרשת ביטחון ב־psql 🧠 הבנה רמה 1

💡 רמז 1

ה־DELETE מדווח כמה שורות נמחקו — זה הרגע לעצור.

💡 רמז 2

בתוך ה־transaction אתה רואה את השינויים שלך. אחרי ROLLBACK — הם לא היו.

✅ פתרון
INSERT INTO transfers (from_id, to_id, amount) VALUES (1, 3, 10), (4, 2, 20), (4, 3, 30);
BEGIN;
DELETE FROM transfers;
SELECT COUNT(*) AS left_after_delete FROM transfers;
ROLLBACK;
SELECT COUNT(*) AS left_in_the_end FROM transfers;
INSERT 0 3
BEGIN
DELETE 3
 left_after_delete
-------------------
                 0
(1 row)

ROLLBACK
 left_in_the_end
-----------------
               3
(1 row)

DELETE 3 כשציפית ל־1 — סימן לעצור. ROLLBACK, וכאילו לא קרה. הרגל של אנשי DBA: כל UPDATE/DELETE ידני על מסד אמיתי — בתוך BEGIN, עם SELECT לבדיקה, ורק אז COMMIT.

⚠️ טעויות נפוצות
  • לשכוח לסגור (בלי COMMIT ובלי ROLLBACK) ולהשאיר את ה־psql פתוח — השורות נעולות, ושאר המערכת מחכה (שיעור 2).

P18-E07 · transfer מ־Node 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הדפוס מהשיעור: pool.connect(), try/catch/finally.

💡 רמז 2

INSERT ... RETURNING id, ו־rows[0].id.

✅ פתרון
// P18-E07
import type { Pool } from "pg";

export async function transfer(pool: Pool, fromId: number, toId: number, amount: number): Promise<number> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [amount, fromId]);
    await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    const { rows } = await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3) RETURNING id", [fromId, toId, amount]);
    await client.query("COMMIT");
    return rows[0].id;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}
⚠️ טעויות נפוצות
  • return לפני COMMIT — ה־finally משחרר חיבור עם transaction פתוח, והבקשה הבאה שתקבל אותו תמשיך בתוך ה־transaction הזה.

P18-E08 · פרמטרים, לא שרשור 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

pool.query("... WHERE owner = $1", [owner])

💡 רמז 2

בחיפוש: התו % שהמשתמש הקליד הוא "כל רצף" ב־LIKE. צריך לנטרל אותו: text.replace(/[\\%_]/g, "\\$&"), ואז ILIKE '%' || $1 || '%'.

✅ פתרון
// P18-E08
import type { Pool } from "pg";

export async function findByOwner(pool: Pool, owner: string) {
  const { rows } = await pool.query("SELECT id, owner, balance FROM accounts WHERE owner = $1 ORDER BY id", [owner]);
  return rows;
}

export async function searchOwners(pool: Pool, text: string) {
  const escaped = text.replace(/[\\%_]/g, "\\$&"); // % ו־_ שהמשתמש הקליד — כתווים רגילים
  const { rows } = await pool.query("SELECT id, owner, balance FROM accounts WHERE owner ILIKE '%' || $1 || '%' ORDER BY id", [escaped]);
  return rows;
}

הפרמטר מגן מ־injection — אבל לא מ־"wildcard injection": בלי ה־escape, חיפוש של % היה מחזיר הכול (ועל טבלה גדולה — סריקה יקרה שכל משתמש יכול להפעיל).

⚠️ טעויות נפוצות
  • ... LIKE '%${text}%' — SQL injection קלאסית.

P18-E20 · transaction שלא באמת 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

על איזה חיבור רץ כל pool.query?

💡 רמז 2

מה קורה לחיבור ול־transaction כשנזרקת שגיאה?

✅ פתרון
// P18-E20: מתוקן — חיבור אחד, ROLLBACK בשגיאה, release תמיד
import type { Pool } from "pg";

export async function transfer(pool: Pool, fromId: number, toId: number, amount: number) {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [amount, fromId]);
    await client.query("COMMIT");
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

(1) pool.query("BEGIN") פותח transaction על חיבור אקראי — הפקודות הבאות רצות על חיבורים אחרים, כל אחת ב־autocommit. (2) אין ROLLBACK. (3) החיבור שהוחזק לא שוחרר בשגיאה — אחרי כמה כישלונות ה־pool ריק.

⚠️ טעויות נפוצות
  • לתקן רק את ה־release — הכסף עדיין "נוצר" בכל כישלון.

P18-E26 · withTransaction — עוזר שכותבים פעם אחת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

ה־import: import type { Pool, PoolClient } from "pg";. גוף withTransaction הוא בדיוק הדפוס מ־P18-E07. ההבדל היחיד: במקום שלוש שאילתות באמצע, ‏const result = await fn(client);.

💡 רמז 2

transferAll מחזירה את מה ש־withTransaction מחזירה: return withTransaction(pool, async (client) => { ...; return amount; });. בתוך ה־callback, כל throw מגיע ל־catch של withTransaction, ומשם ל־ROLLBACK. ‏יעד לא קיים: ‏rowCount === 0 אחרי ה־UPDATE שלו. ‏balance מגיע מ־pg כמחרוזת (‏numeric), ולכן Number(...).

✅ פתרון
// P18-E26: withTransaction — עוזר שכותבים פעם אחת
import type { Pool, PoolClient } from "pg";

export async function withTransaction<T>(pool: Pool, fn: (client: PoolClient) => Promise<T>): Promise<T> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const result = await fn(client);
    await client.query("COMMIT");
    return result;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

export async function transferAll(pool: Pool, fromId: number, toId: number): Promise<number> {
  return withTransaction(pool, async (client) => {
    const { rows } = await client.query("SELECT balance FROM accounts WHERE id = $1 FOR UPDATE", [fromId]);
    if (rows.length === 0) throw new Error(`חשבון לא קיים: ${fromId}`);
    const amount = Number(rows[0].balance);
    if (amount === 0) throw new Error("אין מה להעביר");
    await client.query("UPDATE accounts SET balance = 0 WHERE id = $1", [fromId]);
    const to = await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    if (to.rowCount === 0) throw new Error(`חשבון לא קיים: ${toId}`);
    await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3)", [fromId, toId, amount]);
    return amount;
  });
}

עכשיו transferAll מכילה רק את מה שמיוחד לה. אין בה BEGIN, ‏ROLLBACK או release, ולכן גם אין איפה לשכוח אותם. כל פונקציה עתידית שצריכה transaction תקבל את אותה התנהגות נכונה בחינם. זה בדיוק מה ש־Prisma נותן ב־$transaction(async (tx) => ...) (פרק 19).

ה־<T> (generic, פרק 11) מעביר את הטיפוס של מה ש־fn מחזירה הלאה. ‏withTransaction(pool, async () => 5) היא Promise<number>, ו־TypeScript יודע את זה בלי שתכתוב.

שגיאה ב"יעד לא קיים" מגיעה אחרי שכבר איפסנו את המקור. בלי transaction הכסף היה נעלם. כאן ה־ROLLBACK מחזיר הכול.

⚠️ טעויות נפוצות
  • ב־catch לבלוע את השגיאה (return null) — מי שקרא חושב שהכול הצליח.
  • client.release() בסוף ה־try ולא ב־finally — כל שגיאה משאירה חיבור תפוס, ואחרי כמה שגיאות ה־pool נתקע.
  • fn(client) בלי await — ‏COMMIT רץ לפני שהשאילתות של fn הסתיימו, ושגיאה שלהן כבר לא תגיע ל־catch.
  • לקרוא ל־pool.query בתוך fn במקום ל־client.query — השאילתה רצה בחיבור אחר, מחוץ ל־transaction.

P18-E34 · סגירת חשבון ב־transaction 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1
INSERT INTO transfers (from_id, to_id, amount) SELECT 2, 1, balance FROM accounts WHERE id = 2;
💡 רמז 2

להוספה ל־Dana: balance + (SELECT balance FROM accounts WHERE id = 2) — לפני האיפוס.

✅ פתרון
BEGIN;
INSERT INTO transfers (from_id, to_id, amount)
  SELECT 2, 1, balance FROM accounts WHERE id = 2;
UPDATE accounts SET balance = balance + (SELECT balance FROM accounts WHERE id = 2) WHERE id = 1;
UPDATE accounts SET balance = 0 WHERE id = 2;
COMMIT;
BEGIN
INSERT 0 1
UPDATE 1
UPDATE 1
COMMIT

שלוש פקודות שחייבות לקרות יחד: בלי transaction, נפילה אחרי השנייה משאירה ל־Dana את הכסף ול־Yossi עדיין את היתרה — כסף שנוצר. ‏(INSERT ... SELECT — מכניס את התוצאה של שאילתה; כאן שורה אחת.) ואם במקביל מישהו מפקיד ל־Yossi? בין הקריאה של היתרה לאיפוס יכול להיכנס כסף שיימחק — את זה פותרים בשיעור 2 עם FOR UPDATE.

⚠️ טעויות נפוצות
  • לכתוב 250 ביד — נכון היום, ושגוי מחר.
  • לאפס לפני ההוספה ל־Dana — היא מקבלת 0.

P18-E35 · פתיחת חשבון עם הפקדה ראשונה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

התבנית מהשיעור: connect, ואז:

try { BEGIN ... COMMIT } catch { ROLLBACK; throw } finally { release }
💡 רמז 2
const { rows } = await client.query("INSERT INTO accounts (owner, balance) VALUES ($1, 0) RETURNING id", [owner]);
✅ פתרון
// P18-E35: פתיחת חשבון עם הפקדה ראשונה
import type { Pool } from "pg";

export async function openAccount(pool: Pool, owner: string, fromId: number, deposit: number): Promise<number> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const { rows } = await client.query("INSERT INTO accounts (owner, balance) VALUES ($1, 0) RETURNING id", [owner]);
    const id: number = rows[0].id;
    await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [deposit, fromId]);
    await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [deposit, id]);
    await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3)", [fromId, id, deposit]);
    await client.query("COMMIT");
    return id;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

ה־INSERT של החשבון הוא חלק מה־transaction — ולכן גם הוא מתבטל אם ההפקדה נכשלת. בלי זה היו נשארים "חשבונות רפאים" עם יתרה 0 מכל ניסיון שנכשל. (ה־id שנשרף לא חוזר — P18-E32.)

⚠️ טעויות נפוצות
  • ליצור את החשבון עם pool.query לפני ה־transaction — הוא נשמר מיד, גם כשההפקדה נכשלת.
  • return id לפני ה־COMMIT — ה־finally משחרר את החיבור באמצע transaction פתוח.

לולאת for ... of עם await בתוך transaction אחד — כל הפקודות על אותו client.

💡 רמז 2
const r = await client.query("UPDATE ... WHERE id = $2", [amount, toId]); if (r.rowCount === 0) throw new Error(...)
✅ פתרון
// P18-E36: תשלום משכורות — הכול או כלום
import type { Pool } from "pg";

export async function payMany(pool: Pool, fromId: number, payments: { toId: number; amount: number }[]): Promise<number[]> {
  if (payments.length === 0) return [];
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const ids: number[] = [];
    for (const { toId, amount } of payments) {
      await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [amount, fromId]);
      const to = await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
      if (to.rowCount === 0) throw new Error(`חשבון לא קיים: ${toId}`);
      const { rows } = await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3) RETURNING id", [fromId, toId, amount]);
      ids.push(rows[0].id);
    }
    await client.query("COMMIT");
    return ids;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

transaction יכול להכיל כמה פקודות שרוצים — גם לולאה. הכול נשמר ב־COMMIT אחד, או מתבטל. (ואם יש 10,000 תשלומים? transaction ארוך מחזיק נעילות — בשיעור 2 נראה למה זה יקר, ובשיעור 4 איך שולחים הרבה שורות בפקודה אחת.)

⚠️ טעויות נפוצות
  • להתעלם מ־rowCount — UPDATE של חשבון שלא קיים "מצליח" עם 0 שורות, והכסף יורד מ־Avi לשום מקום (עד ש־FK של transfers עוצר — אם יש).
  • payments.map(async ...) במקום לולאה — כל הפקודות נשלחות "ביחד", וקשה לדעת מה נכשל ומתי (P18-E39).

P18-E37 · ה־COMMIT עבר, התשובה לא הגיעה 🧠 הבנה רמה 2

💡 רמז 1

מבחינת השרת, הבקשה השנייה היא בקשה חדשה לגמרי.

💡 רמז 2

מפתח שהלקוח מייצר פעם אחת לכל "כוונה" (UUID), ונשלח בכל ניסיון חוזר — ועמודה עם UNIQUE.

✅ פתרון
  1. שתיים. ה־transaction הראשון הצליח (D — הוא נשמר), והשני הוא transaction חדש ותקין. transaction לא יודע ששתי בקשות הן "אותה כוונה".
  2. GET רק קורא — לשלוח אותו פעמיים זה כמו פעם אחת. POST יוצר משהו — כל שליחה יוצרת עוד.
  3. Idempotency key: הלקוח מייצר מזהה (crypto.randomUUID()) לכל העברה ושולח אותו בכותרת Idempotency-Key בכל ניסיון. בשרת: עמודה idempotency_key text NOT NULL UNIQUE בטבלת ההעברות, והרישום שלה בתוך אותו transaction. בניסיון השני — 23505, ה־transaction מתבטל (הכסף לא זז שוב), והשרת מחזיר את התוצאה של הראשונה. זה בדיוק מה ש־shop_orders.idempotency_key באתגר P18-E24 עושה, ומה ש־Stripe דורש בכל תשלום.
⚠️ טעויות נפוצות
  • "לבדוק אם הייתה העברה זהה בדקה האחרונה" — שתי העברות לגיטימיות של 300 לאותו אדם נחסמות, ושתי בקשות במקביל עדיין עוברות.

P18-E38 · ‏transaction בלי await 🧠 הבנה רמה 3

💡 רמז 1

בלי await, client.query(...) מחזיר Promise — והקוד ממשיך מיד לשורה הבאה.

💡 רמז 2

Promise שנדחה ואף אחד לא מחכה לו — "unhandled rejection". ב־Node 15 ומעלה זה מפיל את התהליך.

✅ פתרון
  1. "ok" — מיד, עוד לפני שהמסד ענה. ה־catch לא רץ, כי שום await לא "קיבל" את השגיאה. ‏pg שולח את הפקודות בתור על אותו חיבור, ולכן הן כן מגיעות לפי הסדר: ה־UPDATE נכשל, ה־transaction "מת" (P18-E29), וה־COMMIT הופך ל־ROLLBACK. הכסף לא זז — אבל הלקוח קיבל "ok".
  2. הוא נדחה בלי שאף אחד מחכה לו: unhandledRejection — ו־Node מפיל את כל השרת (כל הבקשות של כל המשתמשים).
  3. החיבור חוזר ל־pool באמצע עבודה. בקשה אחרת יכולה לקבל אותו ולשלוח פקודות שייכנסו לתוך ה־transaction הזה (או ייכשלו בגללו). באג שמופיע רק בעומס, ואי אפשר לשחזר.

ESLint עם הכלל @typescript-eslint/no-floating-promises (פרק 8) תופס בדיוק את זה.

⚠️ טעויות נפוצות
  • "זה עבד בבדיקה" — במקרה המוצלח הכול נראה תקין, כי הפקודות רצות בסדר הנכון.

P18-E39 · ‏Promise.all בתוך transaction 🧠 הבנה רמה 2

💡 רמז 1

חיבור אחד = פקודה אחת בכל רגע. ‏pg מכניס את השאר לתור.

💡 רמז 2

האם UPDATE של שורה שלא קיימת נכשל?

✅ פתרון
  1. לא. ל־transaction יש חיבור אחד, והוא מריץ פקודה אחת בכל פעם — pg פשוט שם את השלוש בתור. אותה מהירות, קוד פחות ברור.
  2. UPDATE של id 99 לא נכשל — הוא מעדכן 0 שורות. Avi מאבד 100 ש״ח שלא הגיעו לאף אחד, וה־COMMIT שומר את זה. (בלולאה עם await היית יכול לבדוק rowCount אחרי כל פקודה ולעצור — P18-E36.)
  3. כשהעבודה היא כמה שאילתות בלתי תלויות, שאין ביניהן "הכול או כלום" — למשל דשבורד עם שלוש שאילתות קריאה — עם pool.query, שמשתמש בכמה חיבורים מה־pool.
⚠️ טעויות נפוצות
  • להעביר את ה־Promise.all ל־pool.query כדי "שיהיה מקביל באמת" — עכשיו כל פקודה בחיבור אחר, מחוץ ל־transaction (P18-E20).

💡 רמז 2

החזרה: new Map([...cents].map(([k, v]) => [k, v / 100])).

✅ פתרון
// P18-E40: פנקס בזיכרון — הכול או כלום
export type Op = { from: string; to: string; amount: number };

export function applyAll(balances: Map<string, number>, ops: Op[]): Map<string, number> {
  const cents = new Map([...balances].map(([k, v]) => [k, Math.round(v * 100)] as [string, number]));
  for (const { from, to, amount } of ops) {
    for (const name of [from, to]) if (!cents.has(name)) throw new Error(`חשבון לא קיים: ${name}`);
    if (!(amount > 0)) throw new Error("סכום לא חוקי");
    const a = Math.round(amount * 100);
    if (cents.get(from)! < a) throw new Error(`אין מספיק כסף: ${from}`);
    cents.set(from, cents.get(from)! - a);
    cents.set(to, cents.get(to)! + a);
  }
  return new Map([...cents].map(([k, v]) => [k, v / 100] as [string, number]));
}

כל השינויים על עותק, והמקור לא משתנה אף פעם — מחזירים Map חדש. ‏throw באמצע "זורק" את העותק, וזה ה־ROLLBACK. כך עובדים גם reducers ב־frontend, ו־"immutable updates" בכלל.

⚠️ טעויות נפוצות
  • לעדכן את balances ישירות ולבדוק "בסוף" — כשהפעולה השלישית נכשלת, השתיים הראשונות כבר בוצעו על המקור.
  • new Map(balances) כעותק — נכון כאן (המספרים לא משותפים), אבל שים לב: אם הערכים היו אובייקטים, זה עותק רדוד.

P18-E41 · ‏route של העברה: Zod, transaction ו־status 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

ב־catch: קודם ROLLBACK, ואז:

✅ פתרון
// P18-E41: route של העברה — Zod, transaction ו־status
import type { Pool } from "pg";
import { z } from "zod";

const TransferBody = z.object({
  fromId: z.number().int().positive(),
  toId: z.number().int().positive(),
  amount: z.number().positive().multipleOf(0.01),
});

class HttpFail extends Error {
  status: number;
  code: string;
  constructor(status: number, code: string) {
    super(code);
    this.status = status;
    this.code = code;
  }
}

export async function handleTransfer(pool: Pool, body: unknown): Promise<{ status: number; body: unknown }> {
  const parsed = TransferBody.safeParse(body);
  if (!parsed.success) return { status: 400, body: { error: "VALIDATION" } };
  const { fromId, toId, amount } = parsed.data;
  if (fromId === toId) return { status: 400, body: { error: "SAME_ACCOUNT" } };

  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const from = await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [amount, fromId]);
    if (from.rowCount === 0) throw new HttpFail(404, "ACCOUNT_NOT_FOUND");
    const to = await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    if (to.rowCount === 0) throw new HttpFail(404, "ACCOUNT_NOT_FOUND");
    const { rows } = await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3) RETURNING id", [fromId, toId, amount]);
    await client.query("COMMIT");
    return { status: 201, body: { id: rows[0].id } };
  } catch (err: any) {
    await client.query("ROLLBACK");
    if (err instanceof HttpFail) return { status: err.status, body: { error: err.code } };
    if (err.code === "23514") return { status: 409, body: { error: "INSUFFICIENT_FUNDS" } };
    throw err;
  } finally {
    client.release();
  }
}

ה־route עצמו ב־Express הוא שתי שורות:

. הפרדה כזו (לוגיקה בלי req/res) היא מה שמאפשר לבדוק אותה ישירות — פרק 22.

⚠️ טעויות נפוצות
  • לבדוק "יש מספיק כסף?" עם SELECT לפני ה־UPDATE — מרוץ (שיעור 2). ה־CHECK כבר עושה את זה, אטומית.
  • return מתוך ה־catch בלי ROLLBACK — החיבור חוזר ל־pool עם transaction פתוח ש"מת".

P18-E42 · ייבוא העברות מ־CSV 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

csv.split(/\r?\n/), ואז לולאה עם האינדקס (n = i + 1). מספר שלם חיובי: Number.isInteger(x) && x > 0.

💡 רמז 2

שמור לכל שורה מפוענחת גם את n — כדי שאפשר יהיה לדווח עליה גם בשגיאה מהמסד.

✅ פתרון
// P18-E42: ייבוא העברות מ־CSV
import type { Pool } from "pg";

type Row = { n: number; from: number; to: number; amount: number };

function parse(csv: string): Row[] {
  const rows: Row[] = [];
  csv.split(/\r?\n/).forEach((line, i) => {
    const n = i + 1;
    if (n === 1 || line.trim() === "") return;
    const parts = line.split(",").map((s) => s.trim());
    const [from, to, amount] = parts.map(Number);
    const ok = parts.length === 3 && parts.every((p) => p !== "") && Number.isInteger(from) && from > 0 && Number.isInteger(to) && to > 0 && amount > 0;
    if (!ok) throw new Error(`שורה ${n}: לא תקינה`);
    rows.push({ n, from, to, amount });
  });
  return rows;
}

export async function importTransfers(pool: Pool, csv: string): Promise<number> {
  const rows = parse(csv);
  const client = await pool.connect();
  let current = 0;
  try {
    await client.query("BEGIN");
    for (const r of rows) {
      current = r.n;
      await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [r.amount, r.from]);
      await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [r.amount, r.to]);
      await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3)", [r.from, r.to, r.amount]);
    }
    await client.query("COMMIT");
    return rows.length;
  } catch (err: any) {
    await client.query("ROLLBACK");
    throw new Error(`שורה ${current}: ${err.message}`);
  } finally {
    client.release();
  }
}
