P18-E01 · מה נשמר? 🧠 הבנה רמה 1

💡 רמז 1

ב־ב' אין BEGIN — כל פקודה עומדת לבד. ומה קורה ב־UPDATE שלא מוצא שורה?

💡 רמז 2

ב־ג', ל־Dana יש 1000.

✅ פתרון
  1. Dana 1000, Noa 0 — הכול בוטל.
  2. Dana 900, Noa 0 — באג: הפקודה השנייה לא נכשלה, היא פשוט עדכנה 0 שורות (UPDATE 0). 100 ש״ח נעלמו. transaction לא היה עוזר כאן — צריך לבדוק rowCount ולזרוק (ואז ה־ROLLBACK יבטל את הראשונה).
  3. Dana 1000, Noa 0 — העדכון הראשון הפר את ה־CHECK, ה־transaction בוטל, ו־COMMIT הפך ל־ROLLBACK.
⚠️ טעויות נפוצות
  • לחשוב ש"0 שורות עודכנו" זו שגיאה — מבחינת המסד זו הצלחה.

P18-E07 · transfer מ־Node 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הדפוס מהשיעור: pool.connect(), try/catch/finally.

💡 רמז 2

INSERT ... RETURNING id, ו־rows[0].id.

✅ פתרון
// P18-E07
import type { Pool } from "pg";

export async function transfer(pool: Pool, fromId: number, toId: number, amount: number): Promise<number> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [amount, fromId]);
    await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    const { rows } = await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3) RETURNING id", [fromId, toId, amount]);
    await client.query("COMMIT");
    return rows[0].id;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}
⚠️ טעויות נפוצות
  • return לפני COMMIT — ה־finally משחרר חיבור עם transaction פתוח, והבקשה הבאה שתקבל אותו תמשיך בתוך ה־transaction הזה.

P18-E08 · פרמטרים, לא שרשור 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

pool.query("... WHERE owner = $1", [owner])

💡 רמז 2

בחיפוש: התו % שהמשתמש הקליד הוא "כל רצף" ב־LIKE. צריך לנטרל אותו: text.replace(/[\\%_]/g, "\\$&"), ואז ILIKE '%' || $1 || '%'.

✅ פתרון
// P18-E08
import type { Pool } from "pg";

export async function findByOwner(pool: Pool, owner: string) {
  const { rows } = await pool.query("SELECT id, owner, balance FROM accounts WHERE owner = $1 ORDER BY id", [owner]);
  return rows;
}

export async function searchOwners(pool: Pool, text: string) {
  const escaped = text.replace(/[\\%_]/g, "\\$&"); // % ו־_ שהמשתמש הקליד — כתווים רגילים
  const { rows } = await pool.query("SELECT id, owner, balance FROM accounts WHERE owner ILIKE '%' || $1 || '%' ORDER BY id", [escaped]);
  return rows;
}

הפרמטר מגן מ־injection — אבל לא מ־"wildcard injection": בלי ה־escape, חיפוש של % היה מחזיר הכול (ועל טבלה גדולה — סריקה יקרה שכל משתמש יכול להפעיל).

⚠️ טעויות נפוצות
  • ... LIKE '%${text}%' — SQL injection קלאסית.

P18-E20 · transaction שלא באמת 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

על איזה חיבור רץ כל pool.query?

💡 רמז 2

מה קורה לחיבור ול־transaction כשנזרקת שגיאה?

✅ פתרון
// P18-E20: מתוקן — חיבור אחד, ROLLBACK בשגיאה, release תמיד
import type { Pool } from "pg";

export async function transfer(pool: Pool, fromId: number, toId: number, amount: number) {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [amount, fromId]);
    await client.query("COMMIT");
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

(1) pool.query("BEGIN") פותח transaction על חיבור אקראי — הפקודות הבאות רצות על חיבורים אחרים, כל אחת ב־autocommit. (2) אין ROLLBACK. (3) החיבור שהוחזק לא שוחרר בשגיאה — אחרי כמה כישלונות ה־pool ריק.

⚠️ טעויות נפוצות
  • לתקן רק את ה־release — הכסף עדיין "נוצר" בכל כישלון.

P18-E26 · withTransaction — עוזר שכותבים פעם אחת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

ה־import: import type { Pool, PoolClient } from "pg";. גוף withTransaction הוא בדיוק הדפוס מ־P18-E07. ההבדל היחיד: במקום שלוש שאילתות באמצע, ‏const result = await fn(client);.

💡 רמז 2

transferAll מחזירה את מה ש־withTransaction מחזירה: return withTransaction(pool, async (client) => { ...; return amount; });. בתוך ה־callback, כל throw מגיע ל־catch של withTransaction, ומשם ל־ROLLBACK. ‏יעד לא קיים: ‏rowCount === 0 אחרי ה־UPDATE שלו. ‏balance מגיע מ־pg כמחרוזת (‏numeric), ולכן Number(...).

✅ פתרון
// P18-E26: withTransaction — עוזר שכותבים פעם אחת
import type { Pool, PoolClient } from "pg";

export async function withTransaction<T>(pool: Pool, fn: (client: PoolClient) => Promise<T>): Promise<T> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const result = await fn(client);
    await client.query("COMMIT");
    return result;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

export async function transferAll(pool: Pool, fromId: number, toId: number): Promise<number> {
  return withTransaction(pool, async (client) => {
    const { rows } = await client.query("SELECT balance FROM accounts WHERE id = $1 FOR UPDATE", [fromId]);
    if (rows.length === 0) throw new Error(`חשבון לא קיים: ${fromId}`);
    const amount = Number(rows[0].balance);
    if (amount === 0) throw new Error("אין מה להעביר");
    await client.query("UPDATE accounts SET balance = 0 WHERE id = $1", [fromId]);
    const to = await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    if (to.rowCount === 0) throw new Error(`חשבון לא קיים: ${toId}`);
    await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3)", [fromId, toId, amount]);
    return amount;
  });
}

עכשיו transferAll מכילה רק את מה שמיוחד לה. אין בה BEGIN, ‏ROLLBACK או release, ולכן גם אין איפה לשכוח אותם. כל פונקציה עתידית שצריכה transaction תקבל את אותה התנהגות נכונה בחינם. זה בדיוק מה ש־Prisma נותן ב־$transaction(async (tx) => ...) (פרק 19).

ה־<T> (generic, פרק 11) מעביר את הטיפוס של מה ש־fn מחזירה הלאה. ‏withTransaction(pool, async () => 5) היא Promise<number>, ו־TypeScript יודע את זה בלי שתכתוב.

שגיאה ב"יעד לא קיים" מגיעה אחרי שכבר איפסנו את המקור. בלי transaction הכסף היה נעלם. כאן ה־ROLLBACK מחזיר הכול.

⚠️ טעויות נפוצות
  • ב־catch לבלוע את השגיאה (return null) — מי שקרא חושב שהכול הצליח.
  • client.release() בסוף ה־try ולא ב־finally — כל שגיאה משאירה חיבור תפוס, ואחרי כמה שגיאות ה־pool נתקע.
  • fn(client) בלי await — ‏COMMIT רץ לפני שהשאילתות של fn הסתיימו, ושגיאה שלהן כבר לא תגיע ל־catch.
  • לקרוא ל־pool.query בתוך fn במקום ל־client.query — השאילתה רצה בחיבור אחר, מחוץ ל־transaction.
