P18-E26 · withTransaction — עוזר שכותבים פעם אחת 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 25 דק׳ידע נדרש: שיעור 1

ב־P18-E07 וב־P18-E13 כתבת שוב ושוב את אותו שלד: connect, ‏BEGIN, ‏COMMIT, ‏ROLLBACK ב־catch, ו־release ב־finally. מה שמשתנה הוא רק הקוד שבאמצע. כותבים את השלד פעם אחת, כפונקציה שמקבלת את האמצע כפרמטר. הקובץ ריק. כתוב וייצא:

  • withTransaction<T>(pool: Pool, fn: (client: PoolClient) => Promise<T>): Promise<T> — לוקחת חיבור, ‏BEGIN, מריצה את fn(client), ‏COMMIT, ומחזירה את מה ש־fn החזירה. אם fn זרקה — ‏ROLLBACK, ואותה שגיאה נזרקת הלאה. החיבור משתחרר תמיד.
  • transferAll(pool, fromId, toId): Promise<number> — מעבירה את כל היתרה מחשבון לחשבון, ומחזירה את הסכום (מספר). כתוב אותה עם withTransaction: נעילת החשבון שממנו מעבירים (FOR UPDATE), איפוס שלו, הוספה לשני, ורישום ב־transfers.
    • חשבון מקור לא קיים ← Error(חשבון לא קיים: ${fromId}). חשבון יעד לא קיים ← Error(חשבון לא קיים: ${toId}), וכלום לא משתנה.
    • יתרה 0 ← Error("אין מה להעביר").

הטבלאות — accounts ו־transfers מ־files/bank.sql, כמו בשאר הפרק.

P18-E38 · ‏transaction בלי await

🧠 הבנהרמה 3⏱ 10 דק׳ידע נדרש: פרק 10, שיעור 1

מישהו שכח await:

export async function transfer(pool: Pool, fromId: number, toId: number, amount: number) {
  const client = await pool.connect();
  try {
    client.query("BEGIN");
    client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2", [amount, fromId]);
    client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2", [amount, toId]);
    client.query("COMMIT");
    return "ok";
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}
  1. מה transfer מחזירה כשאין ל־fromId מספיק כסף? האם ה־catch רץ?
  2. מה קורה ל־Promise של ה־UPDATE שנכשל? (פרק 10)
  3. ה־release רץ לפני שהפקודות סיימו לרוץ. למה זה מסוכן במיוחד?

🔗 איך זה מתחבר: Promise ו־await מפרק 10 — try/catch תופס רק שגיאות של Promise שמחכים לו. והשיעור: ה־ROLLBACK תלוי בזה שה־catch באמת רץ.

P18-E41 · ‏route של העברה: Zod, transaction ו־status 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 30 דק׳ידע נדרש: פרק 14, פרק 15, שיעור 1

הלוגיקה של POST /transfers, בלי Express (כדי לבדוק אותה ישירות). בקובץ 18-consistency/starter/P18-E41.ts כתוב וייצא:

export async function handleTransfer(pool: Pool, body: unknown): Promise<{ status: number; body: unknown }>
  • Zod: ‏fromId, ‏toId — מספרים שלמים חיוביים; ‏amount — חיובי, עד 2 ספרות אחרי הנקודה (.multipleOf(0.01)). לא תקין ← { status: 400, body: { error: "VALIDATION" } }. אותו חשבון בשני הצדדים ← 400 ו־"SAME_ACCOUNT".
  • transaction: הורדה, הוספה, רישום ב־transfers עם RETURNING id. ‏UPDATE שעדכן 0 שורות (חשבון חסר) ← ROLLBACK ו־{ status: 404, body: { error: "ACCOUNT_NOT_FOUND" } }. ‏CHECK על היתרה (23514) ← ROLLBACK ו־409 עם "INSUFFICIENT_FUNDS".
  • הצלחה ← { status: 201, body: { id } }. כל שגיאה אחרת — ROLLBACK ו־throw (ה־error middleware יחזיר 500).
