P18-E02 · ציר זמן 🧠 הבנה רמה 1

💡 רמז 1

שני ה־SELECT־ים לפני שני ה־UPDATE־ים.

💡 רמז 2

ה־UPDATE כותב מספר קבוע (50), לא balance - 200.

✅ פתרון
  1. A קורא 250, B קורא 250, A כותב 50, B כותב 50. היתרה 50 — אבל יצאו 400 ש״ח. הבנק הפסיד 200.
  2. לא. אף כתיבה לא שלילית (שתיהן כותבות 50). ה־CHECK תופס רק ערכים לא חוקיים, לא חישוב שגוי.
  3. לא, ב־Read Committed: שני ה־SELECT־ים רואים 250 (אף אחד עוד לא עשה commit), והכתיבות פשוט ממתינות אחת לשנייה. מה שכן מציל: UPDATE accounts SET balance = balance - 200 WHERE id = 2 AND balance >= 200 ובדיקת rowCount, או SELECT ... FOR UPDATE בתוך transaction.
⚠️ טעויות נפוצות
  • "זה לא יקרה, הבקשות לא מגיעות באותה מילישנייה" — לחיצה כפולה על כפתור, ו־retry אוטומטי של אפליקציה, שולחים בדיוק כך.

P18-E03 · איזה כלי? 🧠 הבנה רמה 1

💡 רמז 1

מה הכי פשוט שעובד? עדכון אטומי ואילוצים — קודם.

💡 רמז 2

4 הוא חוק על כמה שורות יחד — אף שורה בודדת לא "שגויה".

✅ פתרון
  1. עדכון אטומי עם תנאי (WHERE stock >= $qty) + CHECK כרשת ביטחון.
  2. UNIQUE על האימייל. אל תבדוק "האם קיים" ואז תכניס — המסד יתפוס, ואת השגיאה (23505) מתרגמים ל־409.
  3. FOR UPDATE על שני החשבונות (לפי סדר id), ואז כל הבדיקות בקוד, ואז העדכונים — הכול ב־transaction אחד.
  4. Serializable + ניסיון חוזר: כל ביטול לבד חוקי; רק השילוב שבור. (חלופה: לנעול את כל שורות המשמרת עם FOR UPDATE לפני הבדיקה.)
  5. עדכון אטומי: SET views = views + 1. (בהיקפים ענקיים — צוברים בזיכרון/Redis ומעדכנים בקבוצות, פרק 26.)
⚠️ טעויות נפוצות
  • להשתמש ב־Serializable "בכל מקום ליתר ביטחון" — כל transaction צריך מנגנון ניסיון חוזר, והביצועים יורדים.

P18-E10 · buy בלי מרוץ 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

עדכון אטומי (E09) עם פרמטרים. rowCount === 0 — לא נמכר.

💡 רמז 2

אבל למה 0? כדי להבדיל בין "אין מוצר" ל"אין מלאי" — שאילתה נוספת, רק במקרה של כישלון.

✅ פתרון
// P18-E10
import type { Pool } from "pg";

export class AppError extends Error {
  code: string;
  constructor(code: string, message = code) {
    super(message);
    this.code = code;
  }
}

export async function buy(pool: Pool, productId: number, qty: number): Promise<number> {
  const { rows } = await pool.query(
    "UPDATE inventory SET stock = stock - $2 WHERE product_id = $1 AND stock >= $2 RETURNING stock",
    [productId, qty]
  );
  if (rows.length > 0) return rows[0].stock;
  const exists = await pool.query("SELECT 1 FROM inventory WHERE product_id = $1", [productId]);
  throw new AppError(exists.rowCount === 0 ? "PRODUCT_NOT_FOUND" : "OUT_OF_STOCK");
}

במקרה הנפוץ (יש מלאי) — שאילתה אחת. השאילתה השנייה רק כדי לתת הודעת שגיאה מדויקת.

⚠️ טעויות נפוצות
  • לבדוק קודם אם המוצר קיים ויש מלאי, ואז לעדכן — חזרנו לבאג של E02.

P18-E13 · העברה עם נעילה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

SELECT id, balance FROM accounts WHERE id = ANY($1) ORDER BY id FOR UPDATE — שורה אחת, נעילה מסודרת.

💡 רמז 2

balance מגיע מ־pg כמחרוזת (numeric) — Number(...) להשוואה.

✅ פתרון
// P18-E13
import type { Pool } from "pg";

export class AppError extends Error {
  code: string;
  constructor(code: string, message = code) {
    super(message);
    this.code = code;
  }
}

export async function transferSafe(pool: Pool, fromId: number, toId: number, amount: number) {
  if (fromId === toId) throw new AppError("SAME_ACCOUNT");
  if (!(amount > 0)) throw new AppError("INVALID_AMOUNT");

  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    // נעילה לפי סדר id — שתי העברות הפוכות לא יחכו זו לזו במעגל
    const { rows } = await client.query("SELECT id, balance FROM accounts WHERE id = ANY($1) ORDER BY id FOR UPDATE", [[fromId, toId]]);
    const from = rows.find((r) => r.id === fromId);
    const to = rows.find((r) => r.id === toId);
    if (!from || !to) throw new AppError("ACCOUNT_NOT_FOUND");
    if (Number(from.balance) < amount) throw new AppError("INSUFFICIENT_FUNDS");

    const a = await client.query("UPDATE accounts SET balance = balance - $1 WHERE id = $2 RETURNING balance", [amount, fromId]);
    const b = await client.query("UPDATE accounts SET balance = balance + $1 WHERE id = $2 RETURNING balance", [amount, toId]);
    const t = await client.query("INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3) RETURNING id", [fromId, toId, amount]);
    await client.query("COMMIT");
    return { transferId: t.rows[0].id, fromBalance: Number(a.rows[0].balance), toBalance: Number(b.rows[0].balance) };
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}
⚠️ טעויות נפוצות
  • לנעול fromId ואז toId — זה בדיוק התרחיש של deadlock מהשיעור.

P18-E14 · הזמנת מקומות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

אין עמודת "מקומות פנויים" לעדכן אטומית — צריך לספור. ספירה במקביל = מרוץ. מה אפשר לנעול?

💡 רמז 2

SELECT capacity FROM events WHERE id = $1 FOR UPDATE — כל ההרשמות לאותו אירוע עוברות בתור. ו־ALREADY_BOOKED: ה־UNIQUE על (event_id, user_id), עם קוד השגיאה 23505.

✅ פתרון
// P18-E14
import type { Pool } from "pg";

export class AppError extends Error {
  code: string;
  constructor(code: string, message = code) {
    super(message);
    this.code = code;
  }
}

export async function bookSeat(pool: Pool, eventId: number, userId: number): Promise<number> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const event = await client.query("SELECT capacity FROM events WHERE id = $1 FOR UPDATE", [eventId]);
    if (event.rowCount === 0) throw new AppError("EVENT_NOT_FOUND");
    const { rows } = await client.query("SELECT COUNT(*)::int AS taken FROM bookings WHERE event_id = $1", [eventId]);
    const capacity = event.rows[0].capacity;
    try {
      await client.query("INSERT INTO bookings (event_id, user_id) VALUES ($1, $2)", [eventId, userId]);
    } catch (err) {
      if ((err as { code?: string }).code === "23505") throw new AppError("ALREADY_BOOKED");
      throw err;
    }
    if (rows[0].taken >= capacity) throw new AppError("SOLD_OUT");
    await client.query("COMMIT");
    return capacity - rows[0].taken - 1;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

שים לב לסדר: קודם ה־INSERT (כדי ש"כבר רשום" ינצח את "מלא" — משתמש רשום שמנסה שוב צריך לשמוע "אתה כבר רשום"), ואז בדיקת המקום — ואם מלא, ה־ROLLBACK מבטל את ה־INSERT. הנעילה על שורת האירוע היא מה שהופך את "סופרים ← בודקים ← מכניסים" לבטוח.

⚠️ טעויות נפוצות
  • לנעול את bookings עם FOR UPDATE — נועל רק שורות קיימות; את ההרשמה ה"חדשה" של המשתמש הבא אי אפשר לנעול מראש.

P18-E19 · ניסיון חוזר ב־Serializable 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

לולאת for (let attempt = 0; ; attempt++) סביב try/catch שלם (כמו P14-E19).

💡 רמז 2

COMMIT יכול להיכשל ב־40001 — לכן הוא בתוך ה־try.

✅ פתרון
// P18-E19
import type { Pool, PoolClient } from "pg";

const RETRYABLE = new Set(["40001", "40P01"]);
const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

export async function withSerializableRetry<T>(pool: Pool, work: (client: PoolClient) => Promise<T>, { retries = 5 } = {}): Promise<T> {
  const client = await pool.connect();
  try {
    for (let attempt = 0; ; attempt++) {
      try {
        await client.query("BEGIN ISOLATION LEVEL SERIALIZABLE");
        const result = await work(client);
        await client.query("COMMIT");
        return result;
      } catch (err) {
        await client.query("ROLLBACK");
        const code = (err as { code?: string }).code;
        if (!code || !RETRYABLE.has(code) || attempt >= retries) throw err;
        await sleep(5 + Math.random() * 20);
      }
    }
  } finally {
    client.release();
  }
}

ההמתנה האקראית ("jitter") חשובה: בלי, כל המתנגשים מנסים שוב באותה מילישנייה — ומתנגשים שוב.

⚠️ טעויות נפוצות
  • לנסות שוב רק את הפקודה שנכשלה — ב־40001 כל ה־transaction פסול; צריך להתחיל מה־SELECT הראשון.
