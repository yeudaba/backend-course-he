P08-E81 · regex: מה יודפס? 🧠 הבנה רמה 2

💡 רמז 1

בלי ^ ו־$, מספיק שהתבנית תופיע איפשהו. והדגל i — מה הוא משנה?

💡 רמז 2

group תמיד מחרוזת. match בלי התאמה מחזיר null. ו־replace בלי g מחליף רק את הראשון.

  • "1234" הוא לא "בדיוק 3 ספרות", אבל כן מכיל 3 ספרות ברצף.
  • בלי i, ‏[a-z] לא מתאים ל־H.
  • m[1] הוא המחרוזת "0042", עם האפסים. Number הופך אותה ל־42.
  • עם g: כל ההתאמות. \d+ לוקח כמה שיותר ספרות ברצף, ולכן "22" ו־"333" נשארים שלמים.

  • לחשוב ש־test בודק את כל הטקסט. הוא בודק רק אם התבנית מופיעה. "כל הטקסט" = ^...$.
  • לחשוב ש־m[1] הוא מספר.

P08-E82 · שלושה בודקים, שלושה באגים 🧠 הבנה רמה 2

💡 רמז 1

הראשון: מה עם 8 ספרות? השני: מה המשמעות של . ב־regex?

💡 רמז 2

השלישי: regex עם g זוכר איפה עצר. נסה לקרוא ל־HAS_UPPER.test("Abc") פעמיים ברצף.

✅ פתרון

false false true true
  1. מיקוד: בלי ^ ו־$, גם 8 ספרות (או "abc1234567") עוברות, כי יש בהן 7 ספרות ברצף. תיקון: /^\d{7}$/.
  2. מחיר: . הוא "כל תו", ולכן "12x50" עובר. תיקון: \..
  3. סיסמה: עם g, הקריאה השנייה מתחילה לחפש מאיפה שהראשונה עצרה (lastIndex), לא מוצאת, ומחזירה false. משתמש עם סיסמה תקינה יקבל "חסרה אות גדולה" בכל ניסיון שני. תיקון: בלי g.
⚠️ טעויות נפוצות
  • לבדוק כל בודק פעם אחת בלבד, עם קלט תקין אחד. הבאג השלישי מופיע רק בקריאה השנייה, והשניים הראשונים רק בקלט לא תקין. תמיד בודקים גם קלט שצריך להידחות.

P08-E87 · groups: מה יש בכל מקום? 🧠 הבנה רמה 2

💡 רמז 1

group עם שם הוא עדיין group עם מספר. ו־(?:...) לא מקבל מספר בכלל.

  • שורה 2: (?:\.(\d+))? מקבץ "נקודה וספרות" כחלק אופציונלי, בלי לתפוס אותו. ב־"v3" החלק הזה לא הופיע, ולכן ה־group שבתוכו undefined. לא מחרוזת ריקה, ולא null.

⚠️ טעויות נפוצות
  • לחשוב ש־group עם שם לא נכנס למערך. הוא נכנס, במקום לפי סדר הסוגריים הפותחים.
  • לבדוק if (m[2] === "") כדי לדעת אם חלק אופציונלי חסר. הוא undefined, ולכן בודקים m[2] === undefined או משתמשים ב־??.

P08-E88 · g, ‏matchAll, ו־null 🧠 הבנה רמה 2

💡 רמז 1

בלי g: התאמה אחת, עם פרטים (index, input, groups). עם g: רק המחרוזות שהתאימו.

💡 רמז 2

match בלי אף התאמה מחזיר null גם עם g. ו־matchAll?

  • בלי g, ‏match עוצר בהתאמה הראשונה ומחזיר אותה עם פרטים: index: 6 הוא המקום שבו היא התחילה.
  • עם g מקבלים את כל ההתאמות, אבל בלי index ובלי groups.
  • ב־matchAll כל איבר הוא התאמה מלאה עם groups: [0] הוא "120 ₪", ו־[1] הוא ה־group, "120". יש רק אחת, כי רק אחרי 120 בא ₪.
  • השורה שהייתה נופלת: .match(/\d+/g).length. בלי התאמות, match מחזיר null, ו־null.length הוא TypeError. ‏?? [] הופך את null למערך ריק. ‏matchAll בלי התאמות לא מחזיר null: מפזרים אותו ומקבלים [].
⚠️ טעויות נפוצות
  • לצפות ל־[] מ־match(/.../g) כשאין התאמות. מקבלים null.
  • לחפש groups בתוצאה של match עם g. הם לא שם. בשביל groups של כל ההתאמות יש matchAll.

P08-E90 · escaping, עברית, ומתי לא 🧠 הבנה רמה 2

💡 רמז 1

ב־"c++", מה המשמעות של + ב־regex? ומה המשמעות של + שבא מיד אחרי +?

💡 רמז 2

\w הוא רק [A-Za-z0-9_]. ו־\b נשען על \w, גם עם u.

  • new RegExp("c++") הוא "c, פעם או יותר, פעם או יותר". ‏++ הוא לא תבנית חוקית, ולכן הבנייה זורקת SyntaxError, עוד לפני ה־test. אחרי escaping התבנית היא c\+\+, כלומר הטקסט "c++" עצמו.
  • \w מכיר רק אותיות לטיניות בלי סימנים. ב־"Ünïcödé" רק n, c ו־d הן כאלה, ולכן הן נחתכות לחתיכות. העברית לא מופיעה בכלל.

  • \b הוא גבול בין \w ללא־\w. סביב "שלום" אין אף תו \w, אז אין גבול, ולכן false גם כשהטקסט הוא בדיוק "שלום".

⚠️ טעויות נפוצות
  • לחשוב ש־new RegExp עם טקסט של משתמש "רק לא ימצא". הוא יכול לזרוק, ולהפיל את הבקשה.
  • לבנות בדיקת שם בעברית עם \w או \b.

P08-E83 · בודקי קלט לטופס 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כל אחת: return /^...$/.test(text);. התחל מ־^ ו־$, ומלא באמצע.

P08-E84 · לפרק שורת לוג 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

regex אחד עם group לכל חלק, מופרדים ברווח אחד. ל־method: ‏(GET|POST|PUT|PATCH|DELETE). ל־path: (\/\S*).

💡 רמז 2

אם match החזיר null — מחזירים null. אחרת: const [, time, method, path, status, ms] = m; ו־Number על השניים.

✅ פתרון
08-modules-errors/starter/P08-E84.js 
const LOG_LINE = /^(\S+) (GET|POST|PUT|PATCH|DELETE) (\/\S*) (\d{3}) (\d+)ms$/;

function parseLogLine(line) {
  const m = line.match(LOG_LINE);
  if (m === null) {
    return null;
  }
  const [, time, method, path, status, ms] = m;
  return { time, method, path, status: Number(status), ms: Number(ms) };
}

⚠️ טעויות נפוצות
  • .* במקום \S+: . מתאים גם לרווח, ושורה עם רווח כפול "עוברת" עם חלקים מוזזים.
  • לשכוח Number: status === 200 נכשל, כי הוא "200".
  • split(" ") במקום regex: עובד על השורה התקינה, אבל לא דוחה שורות שבורות.

P08-E85 · camelCase ו־snake_case 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

replace עם g, ובמקום טקסט — פונקציה שמקבלת את ההתאמה (ואת ה־groups).

💡 רמז 2
name.replace(/_([a-z])/g, (all, letter) => letter.toUpperCase());
✅ פתרון
08-modules-errors/starter/P08-E85.js 
function snakeToCamel(name) {
  return name.replace(/_([a-z])/g, (all, letter) => letter.toUpperCase());
}

function camelToSnake(name) {
  return name.replace(/[A-Z]/g, (letter) => "_" + letter.toLowerCase());
}

console.log(snakeToCamel("created_at_utc"), camelToSnake("orderItemsCount"), snakeToCamel("id"));
console.log(camelToSnake(snakeToCamel("user_id")));

module.exports = { snakeToCamel, camelToSnake };

הפונקציה שמועברת ל־replace מקבלת קודם את ההתאמה המלאה ("_a"), ואחריה את ה־groups ("a"). ב־camelToSnake אין groups, ולכן הפרמטר היחיד הוא האות שהתאימה. ההמרה הלוך־חזור מחזירה את המקור, וזו בדיקה טובה לשתיהן. את ההמרה הזו עושה Prisma בשבילך בפרק 19 (@map).

⚠️ טעויות נפוצות
  • לשכוח g: רק ה־_ הראשון מוחלף ("createdAt_utc").
  • replace("_", "") עם מחרוזת: מוחק את הקו, אבל לא מגדיל את האות שאחריו.

const LINE = /^([A-Z_][A-Z0-9_]*)\s*=\s*(.*)$/;
const QUOTED = /^"(.*)"$/;

function parseEnv(text) {
  const env = {};
  const lines = text.split(/\r?\n/);
  for (let i = 0; i < lines.length; i++) {
    const line = lines[i].trim();
    if (line === "" || line.startsWith("#")) {
      continue;
    }
    const m = line.match(LINE);
    if (m === null) {
      throw new Error(`שורה ${i + 1}: לא בפורמט KEY=VALUE: "${lines[i]}"`);
    }
    const [, key, raw] = m;
    const quoted = raw.match(QUOTED);
    env[key] = quoted === null ? raw : quoted[1];
  }
  return env;
}

ה־trim קורה פעם אחת על כל השורה, ולכן ה־.* בסוף כבר לא כולל רווחים בסוף, ו־\s* סביב ה־= מטפל באמצע. המירכאות נבדקות אחרי ה־trim, כך ש־"My App " שומר את הרווחים שבתוך המירכאות. בהודעת השגיאה, lines[i] ולא line: מראים למשתמש את השורה כמו שהיא בקובץ שלו. ‏for עם אינדקס, ולא for...of, בשביל מספר השורה.

⚠️ טעויות נפוצות
  • split("\n"): בקובץ שנשמר ב־Windows כל ערך נגמר ב־\r בלתי נראה, ו־PORT הוא "3000\r".
  • line.split("="): ערך עם = (כמו ב־URL) נחתך.
  • מספר שורה שמתחיל מ־0, או שנספר רק על שורות שלא דילגת עליהן.
  • ^(\w+) במקום ^([A-Z_][A-Z0-9_]*): גם port ו־1ABC עוברים.

💡 רמז 1

אותו regex כמו ב־E84: /^(\S+) (GET|POST|PUT|PATCH|DELETE) (\/\S*) (\d{3}) (\d+)ms$/. לכל שורה: ריקה ← continue. ‏match החזיר null ← skipped++.

💡 רמז 2

שמור את slowest כ־null בהתחלה, ועדכן רק כש־slowest === null || ms > slowest.ms. ‏> ולא >=, כדי שבתיקו הראשונה תישאר. ו־ms כמספר: "9" > "10" כשהם מחרוזות.

const LOG_LINE = /^(\S+) (GET|POST|PUT|PATCH|DELETE) (\/\S*) (\d{3}) (\d+)ms$/;

export function summarizeLog(text) {
  const summary = { total: 0, skipped: 0, byStatus: {}, slowest: null };
  for (const line of text.split(/\r?\n/)) {
    if (line.trim() === "") {
      continue;
    }
    const m = line.match(LOG_LINE);
    if (m === null) {
      summary.skipped++;
      continue;
    }
    const [, , , path, status, msText] = m;
    const ms = Number(msText);
    summary.total++;
    summary.byStatus[status] = (summary.byStatus[status] ?? 0) + 1;
    if (summary.slowest === null || ms > summary.slowest.ms) {
      summary.slowest = { path, ms };
    }
  }
  return summary;
}

console.log(summarizeLog("2026-11-19T08:30:00Z GET /tasks 200 13ms\nserver started\n2026-11-19T08:30:02Z GET /tasks/9 404 40ms"));

‏status נשאר מחרוזת, כי הוא מפתח באובייקט, ומפתחות של אובייקט הם תמיד מחרוזות. ‏ms הופך למספר, כי משווים אותו. ב־destructuring, כל פסיק ריק מדלג על איבר: על ההתאמה המלאה, על הזמן ועל ה־method. ואם תרצה את parseLogLine מ־E84 במקום regex משלך, זה בדיוק המקום ל־import.

⚠️ טעויות נפוצות
  • >= בהשוואה: בתיקו נשארת האחרונה ולא הראשונה.
  • להשוות msText כמחרוזת: "9" > "10" הוא true.
  • לספור שורה ריקה (למשל אחרי ירידת השורה האחרונה בקובץ) כ־skipped.
  • slowest: {} בהתחלה במקום null: בלי שורות תקינות מקבלים {}.
