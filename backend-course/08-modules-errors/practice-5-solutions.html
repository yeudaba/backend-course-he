P08-E81 · regex: מה יודפס? 🧠 הבנה רמה 2

💡 רמז 1

בלי ^ ו־$, מספיק שהתבנית תופיע איפשהו. והדגל i — מה הוא משנה?

💡 רמז 2

group תמיד מחרוזת. match בלי התאמה מחזיר null. ו־replace בלי g מחליף רק את הראשון.

✅ פתרון
console.log(/^\d{3}$/.test("1234"), /\d{3}/.test("1234"));
console.log(/^[a-z]+$/i.test("Hello"), /^[a-z]+$/.test("Hello"));

const m = "order-0042".match(/^order-(\d+)$/);
console.log(m[1], Number(m[1]));

console.log("a1b22c333".match(/\d+/g));
console.log("abc".match(/\d/));
console.log("2026-11-19".replace(/-/, "/"), "2026-11-19".replace(/-/g, "/"));

true false
0042 42
[ '1', '22', '333' ]
null
2026/11-19 2026/11/19
  • "1234" הוא לא "בדיוק 3 ספרות", אבל כן מכיל 3 ספרות ברצף.
  • בלי i, ‏[a-z] לא מתאים ל־H.
  • m[1] הוא המחרוזת "0042", עם האפסים. Number הופך אותה ל־42.
  • עם g: כל ההתאמות. \d+ לוקח כמה שיותר ספרות ברצף, ולכן "22" ו־"333" נשארים שלמים.
  • בלי התאמה: null, לא מערך ריק.
⚠️ טעויות נפוצות
  • לחשוב ש־test בודק את כל הטקסט. הוא בודק רק אם התבנית מופיעה. "כל הטקסט" = ^...$.
  • לחשוב ש־m[1] הוא מספר.

P08-E82 · שלושה בודקים, שלושה באגים 🧠 הבנה רמה 2

💡 רמז 1

הראשון: מה עם 8 ספרות? השני: מה המשמעות של . ב־regex?

💡 רמז 2

השלישי: regex עם g זוכר איפה עצר. נסה לקרוא ל־HAS_UPPER.test("Abc") פעמיים ברצף.

✅ פתרון
const POSTAL = /\d{7}/;
const PRICE = /^\d+.\d{2}$/;
const HAS_UPPER = /[A-Z]/g;
console.log(POSTAL.test("12345678"), PRICE.test("12x50"), HAS_UPPER.test("Abc"), HAS_UPPER.test("Abc"));

const POSTAL_OK = /^\d{7}$/;
const PRICE_OK = /^\d+\.\d{2}$/;
const HAS_UPPER_OK = /[A-Z]/;
console.log(POSTAL_OK.test("12345678"), PRICE_OK.test("12x50"), HAS_UPPER_OK.test("Abc"), HAS_UPPER_OK.test("Abc"));
true true true false
false false true true
  1. מיקוד: בלי ^ ו־$, גם 8 ספרות (או "abc1234567") עוברות, כי יש בהן 7 ספרות ברצף. תיקון: /^\d{7}$/.
  2. מחיר: . הוא "כל תו", ולכן "12x50" עובר. תיקון: \..
  3. סיסמה: עם g, הקריאה השנייה מתחילה לחפש מאיפה שהראשונה עצרה (lastIndex), לא מוצאת, ומחזירה false. משתמש עם סיסמה תקינה יקבל "חסרה אות גדולה" בכל ניסיון שני. תיקון: בלי g.
⚠️ טעויות נפוצות
  • לבדוק כל בודק פעם אחת בלבד, עם קלט תקין אחד. הבאג השלישי מופיע רק בקריאה השנייה, והשניים הראשונים רק בקלט לא תקין. תמיד בודקים גם קלט שצריך להידחות.

P08-E83 · בודקי קלט לטופס 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כל אחת: return /^...$/.test(text);. התחל מ־^ ו־$, ומלא באמצע.

💡 רמז 2

שם משתמש: תו ראשון [a-z], ואחריו [a-z0-9_] בין 2 ל־15 פעמים: {2,15}.

✅ פתרון
08-modules-errors/starter/P08-E83.js 
function isMobile(text) {
  return /^05\d-?\d{7}$/.test(text);
}

function isPostalCode(text) {
  return /^\d{7}$/.test(text);
}

function isUsername(text) {
  return /^[a-z][a-z0-9_]{2,15}$/.test(text);
}

console.log(isMobile("052-1234567"), isMobile("052-123456"), isPostalCode("6100000"), isUsername("dana_2026"), isUsername("2dana"));

module.exports = { isMobile, isPostalCode, isUsername };
true false true true false

בשם המשתמש, התו הראשון כבר "תפס" מקום אחד, ולכן אחריו {2,15} ולא {3,16}: סך הכול 3 עד 16. בכל השלושה, ^ ו־$ הם מה שהופך "מכיל" ל"הוא".

⚠️ טעויות נפוצות
  • {3,16} אחרי התו הראשון: שם של 17 תווים עובר.
  • \w במקום [a-z0-9_]: \w כולל גם אותיות גדולות.
  • לבנות regex עם g ולשמור אותו במשתנה: test יחזיר תוצאות מתחלפות.

P08-E84 · לפרק שורת לוג 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

regex אחד עם group לכל חלק, מופרדים ברווח אחד. ל־method: ‏(GET|POST|PUT|PATCH|DELETE). ל־path: (\/\S*).

💡 רמז 2

אם match החזיר null — מחזירים null. אחרת: const [, time, method, path, status, ms] = m; ו־Number על השניים.

✅ פתרון
08-modules-errors/starter/P08-E84.js 
const LOG_LINE = /^(\S+) (GET|POST|PUT|PATCH|DELETE) (\/\S*) (\d{3}) (\d+)ms$/;

function parseLogLine(line) {
  const m = line.match(LOG_LINE);
  if (m === null) {
    return null;
  }
  const [, time, method, path, status, ms] = m;
  return { time, method, path, status: Number(status), ms: Number(ms) };
}

console.log(parseLogLine("2026-11-19T08:30:00Z GET /tasks/42 200 13ms"));
console.log(parseLogLine("2026-11-19T08:30:01Z DELETE /tasks/7 404 2ms"));
console.log(parseLogLine("server started"));
console.log(parseLogLine("2026-11-19T08:30:00Z GET  /tasks 200 13ms"));

module.exports = { parseLogLine };

ה־regex נשמר בקבוע מחוץ לפונקציה: הוא נבנה פעם אחת, ויש לו שם שמסביר מה הוא. בלי g, אז אין בעיית lastIndex. \S (כל תו שאינו רווח) מתאים לזמן ולנתיב בלי לפרט את כל הפורמט שלהם.

⚠️ טעויות נפוצות
  • .* במקום \S+: . מתאים גם לרווח, ושורה עם רווח כפול "עוברת" עם חלקים מוזזים.
  • לשכוח Number: status === 200 נכשל, כי הוא "200".
  • split(" ") במקום regex: עובד על השורה התקינה, אבל לא דוחה שורות שבורות.

P08-E85 · camelCase ו־snake_case 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

replace עם g, ובמקום טקסט — פונקציה שמקבלת את ההתאמה (ואת ה־groups).

💡 רמז 2
name.replace(/_([a-z])/g, (all, letter) => letter.toUpperCase());
✅ פתרון
08-modules-errors/starter/P08-E85.js 
function snakeToCamel(name) {
  return name.replace(/_([a-z])/g, (all, letter) => letter.toUpperCase());
}

function camelToSnake(name) {
  return name.replace(/[A-Z]/g, (letter) => "_" + letter.toLowerCase());
}

console.log(snakeToCamel("created_at_utc"), camelToSnake("orderItemsCount"), snakeToCamel("id"));
console.log(camelToSnake(snakeToCamel("user_id")));

module.exports = { snakeToCamel, camelToSnake };
createdAtUtc order_items_count id
user_id

הפונקציה שמועברת ל־replace מקבלת קודם את ההתאמה המלאה ("_a"), ואחריה את ה־groups ("a"). ב־camelToSnake אין groups, ולכן הפרמטר היחיד הוא האות שהתאימה. ההמרה הלוך־חזור מחזירה את המקור, וזו בדיקה טובה לשתיהן. את ההמרה הזו עושה Prisma בשבילך בפרק 19 (@map).

⚠️ טעויות נפוצות
  • לשכוח g: רק ה־_ הראשון מוחלף ("createdAt_utc").
  • replace("_", "") עם מחרוזת: מוחק את הקו, אבל לא מגדיל את האות שאחריו.

P08-E86 · מחיר מטקסט, באגורות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני groups: שקלים (\d{1,3}(?:,\d{3})+|\d+), ואגורות אופציונליות (?:\.(\d{1,2}))?. לפני: ^₪?\s*. ואת הרווחים מסביב — trim().

💡 רמז 2

group שלא השתתף בהתאמה הוא undefined. האגורות: (m[2] ?? "").padEnd(2, "0") ← "5" הופך ל־"50". השקלים: m[1].replace(/,/g, "").

✅ פתרון
08-modules-errors/starter/P08-E86.js 
const PRICE = /^₪?\s*(\d{1,3}(?:,\d{3})+|\d+)(?:\.(\d{1,2}))?$/;

function parsePrice(text) {
  const m = text.trim().match(PRICE);
  if (m === null) {
    throw new Error(`מחיר לא תקין: "${text}"`);
  }
  const shekels = Number(m[1].replace(/,/g, ""));
  const agorot = Number((m[2] ?? "").padEnd(2, "0"));
  return shekels * 100 + agorot;
}

for (const input of ["12", "12.5", " ₪ 1,234.50 ", "0.99", "12,50", "12.345", "-5"]) {
  try {
    console.log(input, "←", parsePrice(input));
  } catch (err) {
    console.log(`✘ ${err.message}`);
  }
}

module.exports = { parsePrice };

12.5 ← 1250

0.99 ← 99
✘ מחיר לא תקין: "12,50"
✘ מחיר לא תקין: "12.345"
✘ מחיר לא תקין: "-5"

שני דברים לא מובנים מאליהם: (?:,\d{3})+ מקבץ "פסיק ושלוש ספרות" בלי ליצור group, כדי שהאגורות יישארו ב־m[2]. ו־"12.5" הוא 12 שקלים ו־50 אגורות, לא 5. לכן padEnd מימין, ולא padStart.

⚠️ טעויות נפוצות
  • Math.round(Number(text) * 100): עובד על "12.5", אבל לא דוחה "12.345", ולא מבין "1,234" (מחזיר NaN).
  • padStart לאגורות: "12.5" הופך ל־1205.
  • (,\d{3})* עם סוגריים רגילים: האגורות זזות ל־m[3].
