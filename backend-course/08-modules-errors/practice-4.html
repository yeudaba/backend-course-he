P08-E24 · אתגר: חשבון בנק עם שגיאות מסודרות 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 35 דק׳ידע נדרש: כל הפרק

בקובץ 08-modules-errors/starter/P08-E24.js בנה "מודול בנק" קטן. חשבון הוא { id, owner, balance }. אף פונקציה לא משנה את הקלט — כולן מחזירות חשבונות חדשים.

  • bankError(code, message) — Error עם שדה code.
  • deposit(account, amount) — סכום חייב להיות מספר חיובי, אחרת INVALID_AMOUNT / "סכום לא תקין".
  • withdraw(account, amount) — כמו deposit, ואם אין מספיק: INSUFFICIENT_FUNDS / "אין מספיק יתרה".
  • transfer(from, to, amount) — מחזירה [newFrom, newTo]. העברה לאותו חשבון (id זהה) ← SAME_ACCOUNT / "לא ניתן להעביר לאותו חשבון". הכול או כלום.
  • safeTransfer(from, to, amount) — כמו transfer, אבל לא זורקת: מחזירה { ok: true, from, to } או { ok: false, code, message, from, to } (עם החשבונות המקוריים).

🔗 איך זה מתחבר: עדכון בלי לשנות את הקלט עם spread (פרק 7), guard clauses (פרק 5), ושגיאות עם שדה code מהשיעור 2. "הכול או כלום" ב־transfer: בודקים הכול לפני שיוצרים חשבונות חדשים — ואז אין מה "לבטל" אם משהו נכשל. ובקובץ אחד שמייצא רק את הממשק (שיעור 1).

P08-E80 · לצמצם את הקלט 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 20 דק׳ידע נדרש: פרק 4, פרק 6, שיעור 4

שלב 2 בשיטה: "הקלט הכי קטן שעדיין שובר". כתוב shrink(input, fails): מקבלת מערך שגורם לכישלון (fails(input) הוא true), ומחזירה מערך מינימלי שעדיין נכשל:

  • מנסים להסיר כל איבר, אחד אחד (מההתחלה). אם בלעדיו fails עדיין true — מסירים אותו לתמיד וממשיכים.
  • חוזרים על כל המעבר כל עוד באותו מעבר הוסר לפחות איבר אחד.
  • אסור לשנות את input.
// "נכשל" כשיש במערך גם 0 וגם מספר שלילי
const fails = (arr) => arr.includes(0) && arr.some((n) => n < 0);
shrink([5, 0, 8, -3, 2, 0, 7], fails); // [-3, 0]
