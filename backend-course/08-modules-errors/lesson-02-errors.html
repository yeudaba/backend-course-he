שיעור 2 — throw, try/catch ו־finally

⏱ ~35 דקות

🎯 בשיעור הזה
  • throw — לעצור ולדווח "משהו לא בסדר".
  • try / catch / finally — לתפוס שגיאה ולהמשיך בשליטה.
  • אובייקט השגיאה: name, message, stack ושדות משלך.
  • מתי return null ומתי throw.

1. throw

בפרק 5 החזרנו הודעת שגיאה או null. הבעיה: מי שקורא לפונקציה חייב לזכור לבדוק. אם הוא שוכח — הקוד ממשיך עם ערך שגוי. throw עוצר מיד, ואי אפשר "לשכוח" אותו:

function parseQuantity(input) {
  const qty = Number(input);
  if (!Number.isInteger(qty) || qty < 1) {
    throw new Error(`כמות לא תקינה: "${input}"`);
  }
  return qty;
}

console.log(parseQuantity("3"));
console.log(parseQuantity("abc"));
console.log("השורה הזו לא תרוץ");

הפלט: 3, ואז Node קורס עם הודעה שמתחילה ב־Error: כמות לא תקינה: "abc" ו־stack trace. throw new Error(...) יוצר אובייקט שגיאה עם הודעה, ו"זורק" אותו למעלה — לפונקציה שקראה, ולזו שקראה לה, עד שמישהו תופס אותו. אם אף אחד לא תופס — התוכנית נעצרת.

2. try / catch

function parseQuantity(input) {
  const qty = Number(input);
  if (!Number.isInteger(qty) || qty < 1) {
    throw new Error(`כמות לא תקינה: "${input}"`);
  }
  return qty;
}

for (const input of ["3", "abc", "0", "7"]) {
  try {
    const qty = parseQuantity(input);
    console.log(`✔ הוזמנו ${qty}`);
  } catch (err) {
    console.log(`✘ ${err.message}`);
  }
}
console.log("סיימנו — התוכנית לא קרסה");
✔ הוזמנו 3
✘ כמות לא תקינה: "abc"
✘ כמות לא תקינה: "0"
✔ הוזמנו 7
סיימנו — התוכנית לא קרסה

כל קלט נבדק בתוך try משלו. כשנזרקת שגיאה, ה־catch מדפיס אותה — והלולאה ממשיכה לקלט הבא. בלי try/catch, הקלט השני היה עוצר את כל התוכנית.

3. finally

function processPayment(amount) {
  console.log("פותח חיבור לחברת האשראי");
  try {
    if (amount <= 0) {
      throw new Error("סכום לא חוקי");
    }
    console.log(`חויב ${amount}`);
    return "ok";
  } catch (err) {
    console.log(`נכשל: ${err.message}`);
    return "failed";
  } finally {
    console.log("סוגר חיבור");
  }
}
console.log(processPayment(50));
console.log(processPayment(-1));
פותח חיבור לחברת האשראי
חויב 50
סוגר חיבור
ok
פותח חיבור לחברת האשראי
נכשל: סכום לא חוקי
סוגר חיבור
failed

finally רץ תמיד — אחרי הצלחה, אחרי שגיאה, ואפילו אחרי return. מקום לניקוי: סגירת קבצים, שחרור חיבור למסד נתונים.

4. אובייקט השגיאה

try {
  const user = null;
  console.log(user.name);
} catch (err) {
  console.log(err.name);
  console.log(err.message);
  console.log(err instanceof TypeError);
}

const notFound = new Error("ההזמנה לא נמצאה");
notFound.status = 404;
notFound.orderId = 77;
try {
  throw notFound;
} catch (err) {
  console.log(`${err.status}: ${err.message} (#${err.orderId})`);
}
TypeError
Cannot read properties of null (reading 'name')
true
404: ההזמנה לא נמצאה (#77)

גם שגיאות של JavaScript עצמה (TypeError, SyntaxError מ־JSON.parse) נתפסות כך. ואפשר להוסיף שדות משלך לשגיאה — למשל status, שבפרק 15 השרת ישתמש בו כדי להחזיר "404" במקום "500". (בפרק 12 נלמד ליצור סוגי שגיאות משלך עם class NotFoundError extends Error.)

5. null או throw?

מצבמה עדיףדוגמה
"לא נמצא" הוא תוצאה רגילה וצפויהreturn null (או undefined)findUserByEmail — אולי פשוט אין משתמש כזה
משהו לא אמור לקרות, או שאי אפשר להמשיךthrowקלט לא חוקי, חיבור למסד נכשל, מצב בלתי אפשרי
⚠️ לא לבלוע שגיאות

try { ... } catch (err) { } — catch ריק — הוא אחד הדברים המסוכנים בקוד: השגיאה נעלמת בשקט, והבאג יתגלה הרבה יותר מאוחר במקום אחר. אם תופסים — עושים משהו: מדווחים, מחזירים תשובה מסודרת, או זורקים שוב (throw err;).

💼 בעולם העבודה

בכל שרת יש "error handler" מרכזי: כל שגיאה שלא נתפסה מגיעה אליו, נרשמת ביומן (log) עם ה־stack, והלקוח מקבל תשובה מסודרת בלי פרטים פנימיים. תבנה אחד כזה בפרק 15.
