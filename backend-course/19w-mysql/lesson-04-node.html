1. mysql2

ה־driver הנפוץ ל־MySQL ב־Node.js, עם API של Promises. כמו pg מפרק 16 — עם שני הבדלים בולטים: פרמטרים הם ? (לא $1), ותוצאה היא זוג [rows, fields]:

import mysql from "mysql2/promise";

const pool = mysql.createPool({
  uri: process.env.DATABASE_URL,      // mysql://user:pass@host:3306/shop
  connectionLimit: 10,                // כמה חיבורים לכל היותר (כמו max ב־pg.Pool)
  timezone: "Z",                      // DATETIME ← Date ב־UTC, לא באזור הזמן של התהליך
});

const [rows] = await pool.execute("SELECT id, name, price FROM products WHERE category = ? AND stock > ?", ["beans", 0]);
const [res] = await pool.execute("INSERT INTO customers (name, email, city) VALUES (?, ?, ?)", ["Dana", "dana@x.com", "Haifa"]);
res.insertId;        // ה־id החדש — במקום RETURNING

execute — prepared statement: השאילתה והערכים נשלחים בנפרד, והשרת לא מפרש ערך כ־SQL. query — מחליף את ה־? בצד הלקוח (עם escaping נכון), וגמיש יותר: WHERE id IN (?) עם מערך, ו־VALUES ? עם מערך של מערכים להכנסה מרובה. שניהם בטוחים מ־SQL injection; מה שלא בטוח — לשרשר מחרוזות.

2. מה חוזר

E05 מריץ את זה ומראה בדיוק — הנקודות החשובות:

ב־MySQLב־JavaScript (ברירת מחדל)למה
DECIMAL(10,2)מחרוזת "89.90"כדי לא לאבד דיוק. a.price + b.price הוא שרשור (E21)
BOOLEAN1 / 0זה TINYINT
JSONאובייקטmysql2 מפענח
DATETIMEDate לפי אזור הזמן של התהליךלכן timezone: "Z", או dateStrings: true
BIGINTnumber (או מחרוזת, עם supportBigNumbers)מעל 2⁵³ number מאבד דיוק

הדרך הנקייה: להמיר במקום אחד — פונקציה שהופכת שורה לטיפוס של האפליקציה (priceCents, isActive) — ולא לפזר Number(…) בכל הקוד (E10).

ומה עם UPDATE? שני מספרים: affectedRows — כמה שורות התאימו ל־WHERE; changedRows — כמה באמת השתנו. "סמן כנשלח" על הזמנה שכבר נשלחה: affected 1, changed 0. לבדיקת "הצלחתי?" — כמעט תמיד affectedRows (E13, E21).

3. טרנזקציה עם pool

P19.5-E09.ts 
const conn = await pool.getConnection();
try {
  await conn.beginTransaction();
  const [rows] = await conn.query("SELECT id, price, stock FROM products WHERE id IN (?) ORDER BY id FOR UPDATE", [ids]);
  // … בדיקות, INSERT להזמנה ולפריטים, UPDATE למלאי …
  await conn.commit();
} catch (err) {
  await conn.rollback();
  throw err;
} finally {
  conn.release(); // בלי זה, אחרי connectionLimit טרנזקציות — כל השרת מחכה לחיבור שלא יחזור
}

4. Prisma מול MySQL

Prisma (פרק 19) תומך ב־MySQL: provider = "mysql" ב־datasource, adapter של MySQL, ו־migrations שנוצרות ב־SQL של MySQL. רוב הקוד — findMany, create, $transaction — לא משתנה. מה כן:

  • טיפוסים: String הוא VARCHAR(191) כברירת מחדל — לטקסט ארוך @db.Text, לאורך אחר @db.VarChar(255).
  • חיפוש לא רגיש לרישיות: mode: "insensitive" לא נתמך — וגם לא צריך: הקולציה כבר כזו.
  • migrations: DDL ב־MySQL לא בטרנזקציה (שיעור 5) — migration שנכשל באמצע משאיר חצי. migrations קטנים.
  • Raw SQL ($queryRaw) — בתחביר של MySQL: בלי ||, בלי RETURNING.

וההבדלים של שיעורים 1–3 — קולציה, REPEATABLE READ, deadlocks — חלים גם דרך Prisma: ה־ORM לא מסתיר את המסד.
