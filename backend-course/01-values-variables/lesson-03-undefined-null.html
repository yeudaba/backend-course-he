שיעור 3 — undefined, null, ומה עם var

⏱ ~20 דקות

🎯 בשיעור הזה
  • מה זה undefined, מה זה null, ומה ההבדל.
  • מה זה var, ולמה לא נשתמש בו.

1. undefined — "עוד לא קיבל ערך"

עם let אפשר ליצור משתנה בלי לתת לו ערך מיד. מה יש בקופסה בינתיים? undefined:

let discount;
console.log(discount);
console.log(typeof discount);
discount = 10;
console.log(discount);
undefined
undefined
10

undefined הוא ערך בפני עצמו (וגם שם הסוג שלו). בדרך כלל JavaScript שמה אותו, כשמשהו עוד לא קיבל ערך. בפרקים הבאים נפגוש אותו הרבה: פונקציה שלא החזירה כלום, שדה שלא קיים באובייקט — כולם undefined.

2. null — "ריק בכוונה"

null הוא ערך שאנחנו שמים כדי לומר: "בדקתי, ואין כאן כלום". למשל: למשתמש יש שדה טלפון, והוא בחר לא למסור טלפון.

const phone = null;
console.log("טלפון:", phone);
טלפון: null
⚡ חשוב גם במסלול המהיר — מוזרות ידועה 
console.log(typeof null);
object

typeof null מחזיר "object" — זו טעות היסטורית מ־1995 שאי אפשר לתקן בלי לשבור את האינטרנט. אל תנסה להבין אותה; רק תזכור אותה. (נפגוש object בפרק 7.)

💡 למה זה חשוב ב־Backend?

במסד נתונים (פרק 16) יש ערך בשם NULL — בדיוק "ריק בכוונה". כשמשתמש לא מילא שדה לא חובה, שומרים NULL. וכשהקוד שלך מקבל undefined במקום שציפית לערך — זה כמעט תמיד באג: שגיאת כתיב בשם, או נתון שלא הגיע.

3. var — הדרך הישנה

בקוד ישן ובמדריכים ישנים באינטרנט תראה var price = 10;. זו הדרך שהייתה לפני 2015, לפני ש־let ו־const נוספו לשפה. ל־var יש התנהגויות מבלבלות — למשל, מותר להכריז עליו פעמיים, ומותר להשתמש בו לפני השורה שיוצרת אותו (ומקבלים undefined במקום שגיאה):

console.log(oldStyle);
var oldStyle = 5;
var oldStyle = 6;
console.log(oldStyle);
undefined
6

עם let, שתי השורות האלה היו נותנות שגיאה ברורה — וזה טוב: עדיף שגיאה מיד מאשר באג שקט. בקורס הזה לא נשתמש ב־var. אם תראה אותו בקוד של מישהו אחר — קרא אותו כמו let, ובדרך כלל אפשר להחליף.

💼 בעולם העבודה

שאלת ראיון קלאסית: "מה ההבדל בין null ל־undefined?" תשובה טובה: "undefined — עוד לא הוגדר ערך, בדרך כלל ברירת המחדל של השפה. null — הוגדר במפורש שאין ערך. ב־API אני מחזיר null לשדה ריק, כדי שהלקוח יבדיל בין 'אין' לבין 'שכחו לשלוח'."
