P10-E03 · error-first 🧠 הבנה רמה 1

💡 רמז 1

סדר הפרמטרים.

💡 רמז 2

מה קורה אם יש שגיאה — האם הקוד עוצר?

✅ פתרון
  1. הפרמטרים הפוכים: הראשון הוא err.
  2. JSON.parse רץ לפני בדיקת השגיאה — אם הקריאה נכשלה, text הוא undefined וה־parse זורק.
  3. אחרי "שגיאה" אין return — הקוד ממשיך ל־data.total.
  4. JSON.parse של קובץ פגום זורק בתוך ה־callback — שגיאה שלא נתפסת ומפילה את התוכנית.
fs.readFile("data.json", "utf8", (err, text) => {
  if (err) {
    console.log("שגיאה:", err.message);
    return;
  }
  try {
    console.log(JSON.parse(text).total);
  } catch {
    console.log("JSON לא תקין");
  }
});
⚠️ טעויות נפוצות
  • לשכוח את ה־return — הבאג הכי נפוץ עם callbacks.

P10-E07 · callback בסגנון Node 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

בתוך ה־callback של readFile: אם יש err — return callback(err).

💡 רמז 2

JSON.parse בתוך try/catch. היזהר לא לקרוא ל־callback בתוך ה־try (אם הוא עצמו יזרוק — ייקרא שוב מה־catch).

✅ פתרון
// P10-E07: callback בסגנון error-first
const fs = require("node:fs");

function readJson(file, callback) {
  fs.readFile(file, "utf8", (err, text) => {
    if (err) {
      callback(err);
      return;
    }
    let data;
    try {
      data = JSON.parse(text);
    } catch (parseError) {
      callback(parseError);
      return;
    }
    callback(null, data);
  });
}

readJson("/no/such.json", (err) => console.log(err.code));

module.exports = { readJson };
ENOENT
⚠️ טעויות נפוצות
  • try { callback(null, JSON.parse(text)) } catch (e) { callback(e) } — אם ה־callback של מי שקרא זורק, הוא יקרא פעמיים.

✅ פתרון
// P10-E08
function legacyGetPrice(code, callback) {
  const prices = { "KB-101": 199, "MS-201": 89 };
  setTimeout(() => {
    if (code in prices) {
      callback(null, prices[code]);
    } else {
      callback(new Error(`אין מחיר ל־${code}`));
    }
  }, 5);
}

function getPrice(code) {
  return new Promise((resolve, reject) => {
    legacyGetPrice(code, (err, price) => {
      if (err) {
        reject(err);
      } else {
        resolve(price);
      }
    });
  });
}

getPrice("KB-101").then((p) => console.log(p));

module.exports = { legacyGetPrice, getPrice };
199

(ל־Node יש עוזר מובנה: require("node:util").promisify(legacyGetPrice) — עושה בדיוק את זה לכל פונקציה error-first.)

⚠️ טעויות נפוצות
  • return price מתוך ה־callback — חוזר ל־legacyGetPrice, לא אליך.

P10-E20 · callback שנקרא פעמיים 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

חסר return אחרי טיפול בשגיאה; ה־parse לא בתוך try.

💡 רמז 2

מבנה נכון: אם err ← cb(err) ו־return; try parse; catch ← cb(e) ו־return; cb(null, data).

✅ פתרון
// P10-E20: מתוקן
const fs = require("node:fs");

function loadSettings(file, cb) {
  fs.readFile(file, "utf8", (err, text) => {
    if (err) {
      cb(err);
      return;
    }
    let settings;
    try {
      settings = JSON.parse(text);
    } catch (parseErr) {
      cb(parseErr);
      return;
    }
    cb(null, { theme: "light", ...settings });
  });
}

module.exports = { loadSettings };
⚠️ טעויות נפוצות
  • להוסיף try/catch סביב fs.readFile — לא תופס שום דבר אסינכרוני.

P10-E26 · חיבור אסינכרוני עם callback 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כל הקוד של הפונקציה נכנס לתוך setTimeout(() => { ... }, 10). כך גם השגיאה וגם התוצאה מגיעות אחרי ההמתנה.

💡 רמז 2

בתוך ה־setTimeout: if (typeof a !== "number" || typeof b !== "number") { callback(new TypeError(...)); return; }, ואחריו callback(null, a + b);.

✅ פתרון
// P10-E26: חיבור אסינכרוני עם callback
function addLater(a, b, callback) {
  setTimeout(() => {
    if (typeof a !== "number" || typeof b !== "number") {
      callback(new TypeError("a ו־b חייבים להיות מספרים"));
      return;
    }
    callback(null, a + b);
  }, 10);
}

addLater(2, 3, (err, sum) => console.log(err, sum));
addLater(2, "3", (err) => console.log(err.message));
console.log("קודם אני");

module.exports = { addLater };
קודם אני
null 5
a ו־b חייבים להיות מספרים

"קודם אני" מודפס ראשון, כי שתי הקריאות ל־addLater רק רושמות טיימר וחוזרות מיד (שיעור 1). ה־callbacks רצים אחר כך, מתוך ה־event loop.

למה גם השגיאה מחכה? כי פונקציה שלפעמים קוראת ל־callback מיד ולפעמים אחר כך מבלבלת את מי שמשתמש בה: הקוד שאחרי הקריאה רץ פעם לפני ה־callback ופעם אחריו. הכלל ב־Node: callback תמיד אסינכרוני.

⚠️ טעויות נפוצות
  • בדיקת הטיפוסים לפני ה־setTimeout, עם callback(err) מיד — השגיאה מגיעה בסנכרון. הבודק תופס את זה.
  • לשכוח return אחרי ה־callback של השגיאה — ה־callback נקרא פעמיים, פעם עם שגיאה ופעם עם "23".
  • return a + b מתוך ה־setTimeout — הערך הולך לאיבוד. מי שקרא ל־addLater כבר לא מחכה.
