P10-E05 · all, allSettled, race 🧠 הבנה רמה 1

💡 רמז 1

all שומר את הסדר במערך, לא את סדר הסיום.

💡 רמז 2

const ok = (ms, v) => new Promise((r) => setTimeout(() => r(v), ms));

const show = (p) => p.then((v) => JSON.stringify(v), (e) => `נכשל: ${e.message}`);

console.log(await show(Promise.all([ok(30, "a"), ok(10, "b")])));
console.log(await show(Promise.all([ok(30, "a"), fail(10, "x")])));
console.log(await show(Promise.allSettled([ok(30, "a"), fail(10, "x")]).then((r) => r.map((s) => s.status))));

P10-E75 · async מחזירה תמיד Promise 🧠 הבנה רמה 1

💡 רמז 1

הטבלה בשיעור: async function תמיד מחזירה Promise. return 5 ← Promise שמצליח עם 5.

💡 רמז 2

ו־throw בתוך async? Promise שנכשל — לא זריקה רגילה.

✅ פתרון
async function five() {
  return 5;
}
async function nothing() {}
async function boom() {
  throw new Error("בום");
}

console.log(five());
console.log(nothing() instanceof Promise);
five().then((v) => console.log("then:", v));
boom().catch((e) => console.log("catch:", e.message));
console.log("סוף");
Promise { 5 }
true
סוף
then: 5
catch: בום

Promise { 5 } — Node מדפיס Promise שכבר הצליח עם הערך שבתוכו, אבל זה עדיין Promise: כדי להשתמש ב־5 צריך then או await. גם boom() לא זרקה בשורה שבה קראו לה — היא החזירה Promise שנכשל, וה־catch שלו תפס.

⚠️ טעויות נפוצות
  • const n = five(); n + 1 — מקבלים "[object Promise]1", לא 6.

P10-E76 · שתי פונקציות async משתלבות 🧠 הבנה רמה 2

💡 רמז 1

כל await עוצר רק את הפונקציה שלו. עד ה־await הראשון — הכול רץ מיד.

💡 רמז 2

חשב זמנים: א מדפיס ב־30 ו־60; ב מדפיס ב־20 ו־40.

✅ פתרון
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

async function worker(name, ms) {
  console.log(name, "התחיל");
  await sleep(ms);
  console.log(name, "באמצע");
  await sleep(ms);
  console.log(name, "סיים");
}

worker("א", 30);
worker("ב", 20);
console.log("שתיהן נקראו");
א התחיל
ב התחיל
שתיהן נקראו
ב באמצע
א באמצע
ב סיים
א סיים

שתי הפונקציות "חיות" בו־זמנית ומתחלפות. זה בדיוק מה שקורה בשרת: כל בקשה היא פונקציית async, וכשאחת מחכה למסד — אחרת ממשיכה. ‏await נראה כמו "עצירה", אבל הוא עוצר רק את הפונקציה, לא את המלצר.

⚠️ טעויות נפוצות
  • לחשוב ש־ב מתחיל רק אחרי שא סיים, כי "יש await".

P10-E77 · רצף או מקביל? 🧠 הבנה רמה 1

💡 רמז 1

שאל גם: מה קורה אם ב' יקרה למרות שא' נכשל?

💡 רמז 2

סעיף 5: לא "הכול יחד" ולא "אחד־אחד" — ראה את האתגר P10-E24.

✅ פתרון
  1. Promise.all. שלושתם צריכים רק את המזהה, שכבר יש. ‏300ms ← 100ms.
  2. רצף. אסור ליצור טוקן לפני שידוע שהסיסמה נכונה.
  3. רצף. האימייל תלוי בהצלחת החיוב — לא שולחים "התקבלה" על הזמנה שנכשלה.
  4. Promise.all (או allSettled, אם רוצים להציג דוח חלקי כשאחד נופל).
  5. לא זה ולא זה: 500 בבת אחת יפילו את השרת, ואחד־אחד ייקח נצח. מגבלת מקביליות — 5 בכל רגע (P10-E24).

P10-E78 · return או return await? 🧠 הבנה רמה 2

💡 רמז 1

return fail() מחזיר את ה־Promise כמו שהוא — בלי לחכות לו בתוך ה־try. מתי הוא נכשל?

💡 רמז 2

עם await, הכישלון "קורה" בתוך ה־try — וה־catch רואה אותו.

✅ פתרון
const fail = async () => {
  throw new Error("נכשל");
};

async function withoutAwait() {
  try {
    return fail();
  } catch {
    return "נתפס בפנים";
  }
}

async function withAwait() {
  try {
    return await fail();
  } catch {
    return "נתפס בפנים";
  }
}

withoutAwait().then(console.log, (e) => console.log("ברח החוצה:", e.message));
withAwait().then(console.log, (e) => console.log("ברח החוצה:", e.message));
נתפס בפנים
ברח החוצה: נכשל

ה־try תופס רק מה שנזרק בזמן שהוא פתוח. בלי await הפונקציה יוצאת מה־try עם Promise שעוד לא נכשל, והכישלון מגיע למי שקרא. הכלל: בתוך try — תמיד return await. (הסדר בפלט: הכישלון שיוצא החוצה עובר עוד "קפיצה" בתור, ולכן מגיע שני.)

⚠️ טעויות נפוצות
  • להסיר את ה־await כי "הוא מיותר ב־return". מחוץ ל־try — נכון; בתוכו — זה משנה את ההתנהגות.

P10-E79 · לקרוא תוצאה של allSettled 🧠 הבנה רמה 1

💡 רמז 1

הטבלה בשיעור: כל איבר הוא { status: "fulfilled", value } או { status: "rejected", reason }.

💡 רמז 2

הסדר במערך הוא סדר ה־Promises שהעברת — לא סדר הסיום.

✅ פתרון
const ok = (ms, v) => new Promise((r) => setTimeout(() => r(v), ms));
const fail = (ms, m) => new Promise((_, rej) => setTimeout(() => rej(new Error(m)), ms));

const results = await Promise.allSettled([ok(20, "משתמש"), fail(10, "אין חיבור"), ok(5, 3)]);
console.log(results.map((r) => r.status));
console.log(results.filter((r) => r.status === "fulfilled").map((r) => r.value));
console.log(results.filter((r) => r.status === "rejected").map((r) => r.reason.message));
[ 'fulfilled', 'rejected', 'fulfilled' ]
[ 'משתמש', 3 ]
[ 'אין חיבור' ]

allSettled לא נכשל לעולם — הוא מחזיר דוח על כל אחד, באותו סדר. השגיאה נמצאת ב־reason (לא ב־error ולא ב־value). זה הבסיס ללוח המחוונים ב־P10-E17.

⚠️ טעויות נפוצות
  • r.value על איבר שנכשל — undefined, בלי שום שגיאה שתזהיר.

P10-E11 · אותו דבר עם await 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

בתוך async, throw ← Promise שנכשל.

✅ פתרון
// P10-E11
const users = [{ id: 1, name: "דנה" }, { id: 2, name: "עומר" }];
const orders = [{ userId: 1 }, { userId: 1 }, { userId: 2 }];
const wait = (v) => new Promise((r) => setTimeout(() => r(v), 5));
const findUser = (id) => wait(users.find((u) => u.id === id) ?? null);
const findOrders = (userId) => wait(orders.filter((o) => o.userId === userId));

async function orderCountText(userId) {
  const user = await findUser(userId);
  if (user === null) {
    throw new Error("משתמש לא נמצא");
  }
  const list = await findOrders(user.id);
  return `${user.name}: ${list.length} הזמנות`;
}

orderCountText(2).then(console.log);

module.exports = { orderCountText };
עומר: 1 הזמנות
⚠️ טעויות נפוצות

P10-E15 · timeout 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

Promise.race בין ה־promise לבין promise של טיימר שעושה reject.

💡 רמז 2

שמור את ה־id של setTimeout, ו־.finally(() => clearTimeout(id)) על ה־race.

✅ פתרון
// P10-E15
function withTimeout(promise, ms) {
  let timer;
  const timeout = new Promise((_, reject) => {
    timer = setTimeout(() => {
      const err = new Error(`timeout after ${ms}ms`);
      err.code = "TIMEOUT";
      reject(err);
    }, ms);
  });
  return Promise.race([promise, timeout]).finally(() => clearTimeout(timer));
}

const slow = new Promise((r) => setTimeout(() => r("done"), 200));
withTimeout(slow, 20).catch((e) => console.log(e.code, e.message));

module.exports = { withTimeout };
TIMEOUT timeout after 20ms

(שים לב: ה־Promise האיטי ממשיך לרוץ ברקע — timeout לא "מבטל" אותו. ביטול אמיתי דורש AbortController, שנפגוש עם fetch בפרק 14.)

⚠️ טעויות נפוצות
  • בלי clearTimeout — התוכנית מחכה לטיימר של 30 שניות גם אחרי שהכול נגמר.

P10-E16 · retry עם המתנה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שיעור 4, סעיף 4.

💡 רמז 2

return await fn(i) בתוך try.

✅ פתרון
// P10-E16
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

async function retryAsync(fn, { attempts = 3, baseDelay = 10, log = () => {} } = {}) {
  for (let i = 1; i <= attempts; i++) {
    try {
      return await fn(i);
    } catch (err) {
      if (i === attempts) {
        throw err;
      }
      log(`attempt ${i} failed: ${err.message}`);
      await sleep(baseDelay * 2 ** (i - 1));
    }
  }
}

retryAsync(async (n) => {
  if (n < 2) throw new Error("busy");
  return "ok";
}, { log: console.log }).then(console.log);

module.exports = { retryAsync };
attempt 1 failed: busy
ok
⚠️ טעויות נפוצות
  • return fn(i) בלי await — השגיאה בורחת מה־try, ואין ניסיון חוזר.

P10-E17 · לוח מחוונים עם כשלים חלקיים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

const names = Object.keys(sources); const results = await Promise.allSettled(names.map((n) => sources[n]()));

💡 רמז 2

results[i] שייך ל־names[i].

✅ פתרון
// P10-E17
async function loadDashboard(sources) {
  const names = Object.keys(sources);
  const results = await Promise.allSettled(names.map((name) => sources[name]()));
  const data = {};
  const errors = {};
  results.forEach((result, i) => {
    if (result.status === "fulfilled") {
      data[names[i]] = result.value;
    } else {
      errors[names[i]] = result.reason?.message ?? String(result.reason);
    }
  });
  return { data, errors };
}

loadDashboard({
  user: async () => ({ name: "דנה" }),
  weather: async () => {
    throw new Error("השירות לא זמין");
  },
  cart: async () => 3,
}).then(console.log);

module.exports = { loadDashboard };
{
  data: { user: { name: 'דנה' }, cart: 3 },
  errors: { weather: 'השירות לא זמין' }
}
⚠️ טעויות נפוצות
  • Promise.all — כישלון של מזג האוויר מפיל את כל הדף.

P10-E18 · אחד אחרי השני 🤖 💻 כתיבת קוד 🤖 רמה 3

// P10-E18
async function processInOrder(items, fn) {

processInOrder([1, 2, 3], async (n) => {

P10-E19 · המהיר שהצליח 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 2

כשכולן נכשלות, Promise.any זורק AggregateError — תפוס והחלף בהודעה שלך.

✅ פתרון
// P10-E19
async function fastestSuccess(fns) {
  try {
    return await Promise.any(fns.map((fn) => fn()));
  } catch {
    throw new Error("כל המקורות נכשלו");
  }
}

const after = (ms, v, fail = false) => () =>
  new Promise((res, rej) => setTimeout(() => (fail ? rej(new Error(v)) : res(v)), ms));
fastestSuccess([after(5, "x", true), after(20, "slow"), after(10, "fast")]).then(console.log);

module.exports = { fastestSuccess };
fast

השווה ל־race: race היה מחזיר את הכישלון של 5ms.

⚠️ טעויות נפוצות
  • להשתמש ב־race — מחזיר את הראשון שהסתיים, גם אם נכשל.

P10-E22 · forEach ו־async 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

forEach מתעלם מערך ההחזרה — הוא לא מחכה.

💡 רמז 2

const stocks = await Promise.all(codes.map(getStock)); return stocks.reduce(...)

✅ פתרון
// P10-E22: מתוקן
async function totalStock(codes, getStock) {
  const stocks = await Promise.all(codes.map((code) => getStock(code)));
  return stocks.reduce((sum, n) => sum + n, 0);
}

const fake = (code) => new Promise((r) => setTimeout(() => r(code.length), 10));
totalStock(["a", "bb", "ccc"], fake).then(console.log);

module.exports = { totalStock };
6

במקור: codes.forEach(async (c) => { total += await getStock(c); }); return total; — ה־return קרה מיד, כש־total עדיין 0. ה־callbacks עדכנו אותו אחר כך — מאוחר מדי.

⚠️ טעויות נפוצות
  • for...of עם await — נכון, אבל ברצף (איטי יותר). התרגיל ביקש במקביל.

P10-E23 · דף איטי 🤖 💻 כתיבת קוד 🤖 רמה 4

async function getProfilePage(userId, api) {

P10-E80 · await בלולאה מול map 🧠 הבנה רמה 2

💡 רמז 1

הלולאה: שלוש המתנות של 40ms, אחת אחרי השנייה.

💡 רמז 2

map עם async מחזיר מערך של Promises — גם הוא מתחיל את כולן יחד.

✅ פתרון
const sleep = (ms, v) => new Promise((r) => setTimeout(() => r(v), ms));
const price = (id) => sleep(40, id * 10);
const ids = [1, 2, 3];
const round = (t) => Math.round((Date.now() - t) / 40) * 40;

let t = Date.now();
let sum = 0;
for (const id of ids) {
  sum += await price(id);
}
console.log("for:", sum, round(t));

t = Date.now();
const prices = await Promise.all(ids.map((id) => price(id)));
console.log("map:", prices.reduce((s, p) => s + p, 0), round(t));

t = Date.now();
const all = await Promise.all(ids.map(async (id) => (await price(id)) + 1));
console.log("async map:", all, round(t));
for: 60 120
map: 60 40
async map: [ 11, 21, 31 ] 40

(הזמנים עוגלו לכפולות של 40, כדי שהפלט יהיה יציב.) אותה תוצאה, פי שלושה מהר. ולמה for עם await עדיין קיים? כשיש תלות בין הסיבובים, או כשחייבים "אחד בכל פעם" (P10-E18) — שם הוא בדיוק הכלי הנכון.

⚠️ טעויות נפוצות
  • ids.map(async ...) בלי Promise.all — מערך של Promises, לא של מספרים (P10-E71).

P10-E81 · try/catch רגיל ופונקציית async 🧠 הבנה רמה 2

💡 רמז 1

האם הקריאה ל־boom() בלי await זורקת? (P10-E75.)

💡 רמז 2

עם await — ה־Promise שנכשל זורק בתוך main, ושם יש try פתוח.

✅ פתרון
async function boom() {
  throw new Error("בום");
}

try {
  const p = boom();
  console.log("לא נזרק כאן");
  p.catch((e) => console.log("ה־catch של ה־Promise:", e.message));
} catch (err) {
  console.log("try/catch רגיל:", err.message);
}

async function main() {
  try {
    await boom();
  } catch (err) {
    console.log("try/catch עם await:", err.message);
  }
}
main();
לא נזרק כאן
ה־catch של ה־Promise: בום
try/catch עם await: בום

ה־catch הרגיל לא רץ אף פעם. בלי ה־p.catch — ה־Promise שנכשל לא היה נתפס בכלל, ו־Node היה קורס (unhandled rejection). שתי דרכים נכונות: .catch על ה־Promise, או await בתוך try.

⚠️ טעויות נפוצות
  • לעטוף קריאה לפונקציית async ב־try/catch בלי await, ולהרגיש "מוגן".

P10-E82 · מפירמידה לארבע שורות 🧠 הבנה רמה 3

💡 רמז 1

כל שלב הוא שורה: const config = await readConfigP(); וכן הלאה.

💡 רמז 2

"בכל מקרה" — finally (פרק 8). ולגבי מקביל: מי תלוי במי?

✅ פתרון
async function report() {
  try {
    const config = await readConfigP();
    const user = await readUserP(config.userId);
    const orders = await readOrdersP(user.id);
    await sendReportP(orders);
    console.log("done");
  } catch (err) {
    handle(err);
  } finally {
    console.log("סיימנו");
  }
}
  1. ארבע שורות, ו־catch אחד לכל השלבים — כולל שגיאה שנזרקת בקוד שלנו (למשל config.userId על undefined).
  2. מקום אחד: finally. בגרסת ה־callbacks היו צריכים חמישה.
  3. לא כמו שהקוד כתוב: כל שלב צריך את התוצאה של הקודם (config ← user ← orders). אילו readOrdersP הייתה מקבלת את config.userId ישירות — אפשר היה להביא את המשתמש וההזמנות יחד: await Promise.all([readUserP(id), readOrdersP(id)]).
⚠️ טעויות נפוצות
  • לשים try/catch נפרד סביב כל שורה — חוזרים לפירמידה, רק בלי ההזחה.
  • לשכוח את await לפני sendReportP — "done" מודפס לפני שהדוח נשלח, וכישלון שלו לא נתפס.

P10-E24 · אתגר: מגבלת מקביליות 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

"עובדים": צור limit פונקציות async שכל אחת לוקחת את האינדקס הבא מתוך מונה משותף בלולאה, עד שנגמרים הפריטים.

💡 רמז 2

let next = 0; const worker = async () => { while (next < items.length) { const i = next++; results[i] = await fn(items[i], i); } }; await Promise.all(Array.from({ length: limit }, worker)); — זה בטוח כי JavaScript לא קוטעת קוד סינכרוני (event loop!).

✅ פתרון
// P10-E24: מקביליות מוגבלת
async function mapLimit(items, limit, fn) {
  const results = new Array(items.length);
  let next = 0;
  async function worker() {
    while (next < items.length) {
      const i = next++;
      results[i] = await fn(items[i], i);
    }
  }
  const workers = Array.from({ length: Math.min(limit, items.length) }, () => worker());
  await Promise.all(workers);
  return results;
}

let active = 0;
let maxActive = 0;
mapLimit([1, 2, 3, 4, 5, 6], 2, async (n) => {
  active++;
  maxActive = Math.max(maxActive, active);
  await new Promise((r) => setTimeout(r, 10));
  active--;
  return n * n;
}).then((r) => console.log(r, "max in parallel:", maxActive));

module.exports = { mapLimit };
[ 1, 4, 9, 16, 25, 36 ] max in parallel: 2

next++ בטוח בלי נעילה כי שום worker לא קוטע אחר באמצע שורה — רק ב־await. זה אחד המקומות שבהם הבנת ה־event loop נותנת יתרון אמיתי.

⚠️ טעויות נפוצות
  • חלוקה ל"מנות" של limit ו־Promise.all על כל מנה — עובד, אבל איטי: כל מנה מחכה לאיטי שבה.

P10-E25 · אתגר: cache אסינכרוני 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

Map של key ← { promise, expires }. שומרים את ה־Promise עצמו (לא את התוצאה) — כך בקשות מקבילות משתפות אותו.

💡 רמז 2

על כישלון: promise.catch(() => cache.delete(key)). את expires קובעים ברגע השמירה.

✅ פתרון
// P10-E25: cache עם שיתוף בקשות בטיסה
function memoizeAsync(fn, ttlMs) {
  const cache = new Map();
  return function (key) {
    const hit = cache.get(key);
    if (hit && hit.expires > Date.now()) {
      return hit.promise;
    }
    const promise = fn(key);
    cache.set(key, { promise, expires: Date.now() + ttlMs });
    promise.catch(() => cache.delete(key));
    return promise;
  };
}

let calls = 0;
const slowDouble = async (n) => {
  calls++;
  await new Promise((r) => setTimeout(r, 10));
  return n * 2;
};
const cached = memoizeAsync(slowDouble, 1000);
Promise.all([cached(5), cached(5), cached(5)]).then((r) => console.log(r, "calls:", calls));

module.exports = { memoizeAsync };
[ 10, 10, 10 ] calls: 1

זה בדיוק "cache stampede protection" — כשאלף משתמשים מבקשים את אותו דבר באותה שנייה, השרת עושה עבודה אחת. נחזור לזה עם Redis בפרק 26.

⚠️ טעויות נפוצות
  • לשמור את התוצאה רק אחרי ש־fn סיימה — בקשות מקבילות כולן מפספסות את ה־cache וקוראות ל־fn.

P10-E27 · סכום הזמנה במקביל 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שלושה שלבים: items.map(({ sku }) => getPrice(sku)) (מערך של Promises) ← await Promise.all(...) (מערך של מחירים, באותו סדר) ← reduce.

💡 רמז 2

ב־reduce הפרמטר השלישי הוא האינדקס: prices.reduce((sum, price, i) => sum + price * items[i].qty, 0).

✅ פתרון
// P10-E27: סכום הזמנה במקביל
async function orderTotal(items, getPrice) {
  const prices = await Promise.all(items.map(({ sku }) => getPrice(sku)));
  return prices.reduce((sum, price, i) => sum + price * items[i].qty, 0);
}

const catalog = { A: 10, B: 25 };
const getPrice = (sku) => new Promise((resolve) => setTimeout(() => resolve(catalog[sku]), 50));

const start = Date.now();
orderTotal([{ sku: "A", qty: 3 }, { sku: "B", qty: 2 }], getPrice).then((total) => {
  console.log(total, Date.now() - start < 90 ? "במקביל" : "אחד אחרי השני");
});

module.exports = { orderTotal };
80 במקביל

Promise.all שומר על הסדר: המחיר במקום i שייך לפריט במקום i, גם אם התשובות הגיעו בסדר אחר. בזכות זה אפשר לחבר בין prices[i] ל־items[i].qty.

והשגיאה? אם Promise אחד נכשל, Promise.all נכשל איתו, ו־await זורק אותה הלאה. לא צריך try/catch — מי שקרא ל־orderTotal יחליט מה לעשות. (כשרוצים תוצאות חלקיות, משתמשים ב־Promise.allSettled, כמו ב־P10-E17.)

⚠️ טעויות נפוצות
  • for (const item of items) { total += (await getPrice(item.sku)) * item.qty; } — עובד, אבל אחד אחרי השני: 250ms במקום 50. הבודק תופס את זה.
  • items.map(async ...) ואז reduce בלי await Promise.all — מחברים Promises ולא מספרים, ויוצא "0[object Promise]...".
  • try { ... } catch { return 0; } — שגיאה בשליפת מחיר הופכת להזמנה בחינם.

P10-E28 · כל העמודים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

כמה עמודים יהיו? לא יודעים מראש — רק מתי לעצור. זה while. משתנים: all = [], ‏page = 1, ‏count = 0.

💡 רמז 2

while (page !== null) { if (count === maxPages) throw ...; const { items, next } = await getPage(page); all.push(...items); page = next; count++; }.

✅ פתרון
// P10-E28: כל העמודים
async function fetchAll(getPage, maxPages = 100) {
  const all = [];
  let page = 1;
  let count = 0;
  while (page !== null) {
    if (count === maxPages) {
      throw new Error("יותר מדי עמודים");
    }
    const { items, next } = await getPage(page);
    all.push(...items);
    page = next;
    count++;
  }
  return all;
}

const pages = {
  1: { items: ["a", "b"], next: 2 },
  2: { items: ["c"], next: 3 },
  3: { items: [], next: null },
};
const getPage = async (n) => {
  console.log(`מביא עמוד ${n}`);
  return pages[n];
};

fetchAll(getPage).then((all) => console.log(all));

module.exports = { fetchAll };

כאן await בתוך לולאה הוא הכרחי, בניגוד ל־P10-E27: את מספר העמוד הבא יודעים רק אחרי שהתשובה הנוכחית הגיעה, ולכן אי אפשר לבקש את כל העמודים במקביל.

all.push(...items) פורש את הפריטים אחד אחד לתוך המערך. all.push(items) (בלי שלוש הנקודות) היה מכניס מערך שלם כפריט אחד. ובדיקת maxPages קורית לפני הבקשה, כך שלעולם לא יוצאות יותר מ־maxPages בקשות. זה אותו "guard נגד לולאה אינסופית" כמו ב־P04-E25.

⚠️ טעויות נפוצות
  • all.push(items) — יוצא [["a", "b"], ["c"], []].
  • while (next) בלי await — getPage(page) מחזירה Promise, ול־Promise אין שדה next.
  • לבדוק את maxPages אחרי הבקשה — יוצאת בקשה אחת יותר מהמותר.
