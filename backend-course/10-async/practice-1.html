💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 1

כתוב ticker(times, ms, onTick, onDone): קוראת ל־onTick(1), ‏onTick(2), ... עד onTick(times), עם המתנה של ms לפני כל אחת, ואחרי האחרונה — ל־onDone(). את הטיימר הבא רושמים רק אחרי שהקודם רץ (טיימר בתוך טיימר). עם times = 0 — רק onDone(), אחרי ms.

P10-E37 · מתי כולם סיימו? 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 1

כתוב afterAll(delays, done): רושמת טיימר לכל מספר במערך delays. כשהטיימר האחרון רץ — קוראת ל־done(order), כש־order הוא מערך של ה־delays לפי הסדר שבו הטיימרים רצו בפועל. עם מערך ריק — done([]) אחרי טיימר של 0.

P10-E38 · עבודה כבדה בחתיכות 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 1

לולאה ארוכה חוסמת את השרת. פתרון ותיק: לחלק אותה לחתיכות, ולתת ל־event loop "לנשום" בין חתיכה לחתיכה. כתוב inChunks(items, size, work, done):

  • קוראת ל־work(item) לכל פריט, לפי הסדר, size פריטים בכל חתיכה.
  • כל חתיכה — בטיימר של 0 משלה (גם הראשונה). כך טיימרים אחרים יכולים לרוץ בין החתיכות.
  • אחרי הפריט האחרון — done(). עם מערך ריק — done() בטיימר של 0.
inChunks([1, 2, 3, 4, 5], 2, (n) => console.log("עבודה", n), () => console.log("סוף"));
setTimeout(() => console.log("בקשה אחרת"), 0);
// עבודה 1, עבודה 2, בקשה אחרת, עבודה 3, עבודה 4, עבודה 5, סוף

P10-E41 · try/catch סביב טיימר

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 8, שיעור 1

בלי להריץ — מה יודפס, ובאיזה סדר? ושאלה נוספת: אילו ה־callback היה עושה throw new Error("בום") במקום console.log — האם ה־catch היה תופס?

try {
  setTimeout(() => console.log("בתוך הטיימר"), 0);
  console.log("סוף ה־try");

  console.log("catch:", err.message);
} finally {

}

🔗 איך זה מתחבר: פרק 8: try/catch/finally תופס שגיאות של קוד שרץ בתוכו. השיעור: ה־callback של הטיימר לא רץ בתוכו — הוא רץ הרבה אחר כך, מתוך ה־event loop.

P10-E43 · סדר הטיימרים — בלי להריץ אותם 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: פרק 6, פרק 7, שיעור 1

כתוב timerOrder(timers) — פונקציה רגילה (בלי טיימרים אמיתיים) שמנבאת באיזה סדר ירוצו טיימרים. timers הוא מערך של { label, ms } לפי סדר הרישום; מחזירים את ה־labels לפי סדר הריצה: לפי ms מהקטן לגדול, ובאותו ms — לפי סדר הרישום. אסור לשנות את המערך שקיבלת.

  { label: "C", ms: 50 },
  { label: "D", ms: 0 },
]); // ["B", "D", "C", "A"]

P10-E44 · מנבא ה־event loop 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 20 דק׳ידע נדרש: פרק 3, פרק 6, שיעור 1

הפעם תכתוב "מנבא" לשאלות כמו P10-E02. predictOrder(steps) מקבלת מערך של שלבים לפי הסדר שבו הם מופיעים בקוד, ומחזירה את ה־labels לפי סדר ההדפסה. כל שלב הוא אחד מאלה:

  • { kind: "sync", label } — console.log רגיל.
  • { kind: "promise", label } — Promise.resolve().then(...).
  • { kind: "timeout", label, ms } — setTimeout(..., ms).

הכלל מהשיעור: כל ה־sync לפי הסדר ← כל ה־promise לפי הסדר ← ה־timeout לפי ms (ובשוויון — לפי הסדר). סוג לא מוכר ← throw new Error("סוג לא מוכר: ...") עם הסוג.

predictOrder([
  { kind: "sync", label: "1" },
  { kind: "timeout", label: "timeout", ms: 0 },
  { kind: "promise", label: "promise" },
  { kind: "sync", label: "2" },
]); // ["1", "2", "promise", "timeout"]

📄 כותבים בקובץ 10-async/starter/P10-E44.js (יש בו רק הערה). בסוף הקובץ: module.exports = { predictOrder };

% node 10-async/starter/P10-E44.js
% npm run check P10-E44

P10-E45 · מונה עצלן 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: פרק 5, פרק 7, שיעור 1

כתוב lazyCounter(ms) שמחזירה אובייקט עם שתי מתודות:

  • add(n) — לא מוסיפה מיד: רושמת טיימר של ms, ורק בו המונה גדל ב־n.
  • get() — מחזירה את הערך הנוכחי של המונה (מיד).

c.add(2);
console.log(c.get());                          // 0 — עוד לא עברו 20ms
setTimeout(() => console.log(c.get()), 40);    // 7
