שיעור 2 — IAM, ה־SDK ו־S3

⏱ ~50 דקות

🎯 בשיעור הזה
  • IAM: user, role ו־policy — ואיך AWS מחליט אם מותר.
  • איך הקוד שלך מקבל credentials — בלי מפתח בקובץ.
  • AWS SDK v3 מ־Node.js, מול LocalStack.
  • S3: אובייקטים, מפתחות, pagination — וכתובות חתומות להעלאה ישירה.

1. IAM: מי, מה, על מה

כל קריאה ל־AWS — מהקונסולה, מה־CLI או מה־SDK — חתומה בזהות, ו־IAM מחליט אם היא מותרת. שלושה מושגים:

  • User — אדם (או, בעבר, שירות) עם סיסמה ו/או Access Key קבוע.
  • Role — זהות בלי סוד קבוע. שירות "לובש" אותה (assume) ומקבל credentials זמניים שפגים תוך שעה ומתחדשים לבד. pod ב־EKS, Lambda, מכונת EC2 — כולם עובדים עם roles.
  • Policy — מסמך JSON שאומר מה מותר: Effect, Action, Resource, ולפעמים Condition.
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::coffee-uploads/uploads/*"
    }
  ]
}

Resource הוא ARN — המזהה הייחודי של משאב. ל־S3: arn:aws:s3:::bucket הוא ה־bucket עצמו, ו־arn:aws:s3:::bucket/key אובייקט בתוכו. ההבדל הזה הוא הסיבה הנפוצה ביותר ל־"AccessDenied, אבל נתתי הרשאה" (E21).

ואיך מחליטים? לכל קריאה, AWS אוסף את כל ה־statements שמתאימים לפעולה ולמשאב:

least privilege: כל שירות מקבל רק את הפעולות, על המשאבים, שהוא צריך. s3:* על * "עובד" — עד שמישהו מוצא באג ב־worker ומוחק את כל הקבצים של כל הלקוחות (E08).

2. מאיפה הקוד מקבל credentials

ה־SDK מחפש credentials בשרשרת קבועה, ולוקח את הראשון שמוצא: משתני סביבה (AWS_ACCESS_KEY_ID…) ← קובץ ~/.aws/credentials של המפתח ← הזהות של הסביבה: ה־role של ה־pod ב־EKS (IRSA / Pod Identity), של ה־Lambda, של מכונת ה־EC2. לכן אותו קוד בדיוק:

import { S3Client } from "@aws-sdk/client-s3";
const s3 = new S3Client({ region: "eu-central-1" }); // בלי מפתחות בקוד

רץ על המחשב שלך עם הפרופיל שלך, וב־EKS עם ה־role של השירות — בלי סוד בשום קובץ. מפתח קבוע ב־.env של שרת הוא ריח רע: הוא לא פג, ודולף מגיבויים ומלוגים.

3. ה־SDK מול LocalStack

AWS SDK v3 בנוי מחבילה לכל שירות (@aws-sdk/client-s3, -sqs…), ותמיד באותו דפוס: client.send(new XxxCommand({…})). LocalStack מדבר באותו API, אז ההבדל היחיד הוא endpoint — ושני דגלים:

import { S3Client, CreateBucketCommand, PutObjectCommand, GetObjectCommand, HeadObjectCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({
  region: "us-east-1",
  endpoint: process.env.AWS_ENDPOINT_URL ?? "http://localhost:4566", // LocalStack. ב־AWS — בלי השורה הזו
  credentials: { accessKeyId: "test", secretAccessKey: "test" },     // LocalStack מקבל כל ערך
  forcePathStyle: true,                                              // localhost:4566/bucket/key במקום bucket.s3.amazonaws.com
});

const Bucket = `lesson-${Date.now()}`;
await s3.send(new CreateBucketCommand({ Bucket }));
await s3.send(new PutObjectCommand({ Bucket, Key: "products/7.json", Body: JSON.stringify({ name: "קפה" }), ContentType: "application/json" }));

const head = await s3.send(new HeadObjectCommand({ Bucket, Key: "products/7.json" }));
console.log("size:", head.ContentLength, "type:", head.ContentType);
const obj = await s3.send(new GetObjectCommand({ Bucket, Key: "products/7.json" }));
console.log(JSON.parse(await obj.Body!.transformToString()));

try {
  await s3.send(new GetObjectCommand({ Bucket, Key: "nope.json" }));
} catch (err: any) {
  console.log("error:", err.name, err.$metadata.httpStatusCode);
}
size: 17 type: application/json
{ name: 'קפה' }
error: NoSuchKey 404

שלוש נקודות מהפלט: size הוא 17, למרות שב־JSON יש 14 תווים — "קפה" הם 3 תווים אבל 6 בתים ב־UTF-8, ו־S3 סופר בתים. Body הוא stream — transformToString() קורא אותו (E22). ושגיאה היא אובייקט עם name (NoSuchKey) ו־status — מבדילים בין "אין כזה" לבין כל תקלה אחרת (E06).

ועוד שלושה דברים על S3 שכדאי לדעת: אין תיקיות — products/7.json הוא מפתח אחד עם לוכסן (E03); אין עדכון חלקי — כותבים אובייקט שלם; ו־ListObjectsV2 מחזיר עד 1000 בכל קריאה — מי שלא ממשיך עם ContinuationToken רואה רק חלק (E19).

4. כתובת חתומה: הלקוח מעלה ישירות

"משתמש מעלה קבלה ב־PDF": הדרך הנאיבית — הקובץ עובר דרך ה־API, ומשם ל־S3. כל העלאה תופסת זיכרון וחיבור בשרת שלך. הדרך המקובלת:

החתימה נעשית עם ה־credentials של השרת, מקומית — אין קריאה ל־AWS. לכן גם ההרשאה של הכתובת היא של השרת: אם ל־role שלו אין s3:PutObject על uploads/*, הכתובת תיכשל (ומכאן עוד סיבה ל־least privilege: כתובת שדלפה לא יכולה יותר ממה שהשרת יכול).
