P26.3-E12 · סודות כקבצים: *_FILE 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 20 דק׳ידע נדרש: שיעור 3

Kubernetes יכול לתת Secret כ־env, או כקובץ (volume) — עדיף, כי env דולף ל־/proc, לדוחות קריסה ולילדים של התהליך. המוסכמה (של Docker ושל הרבה images רשמיים): אם X_FILE מוגדר — קוראים את X מהקובץ. ב־P26.3-E12.ts: loadConfig(env, readFile) ל־DATABASE_URL, JWT_SECRET, REDIS_URL (חובה) ו־PORT (ברירת מחדל 3000):

  • X_FILE ← תוכן הקובץ, בלי ה־newline שבסוף. קובץ שלא נקרא או ריק ← שגיאה עם X_FILE.
  • X ו־X_FILE שניהם ← שגיאה. מחרוזת ריקה = חסר.
  • חסרות כמה ← שגיאה אחת שמונה את כולן.

P26.3-E14 · כמויות של Kubernetes 🤖

ב־P26.3-E14.ts: parseCpu(q) ← millicores ("250m" ← 250, "0.5" ← 500, 2 ← 2000; פחות ממילי־ליבה או פורמט לא מוכר ← שגיאה); parseMemory(q) ← בתים, כש־Ki/Mi/Gi/Ti הם חזקות של 1024 ו־k/M/G/T של 1000; ו־formatMemory(bytes) ← היחידה הבינארית הגדולה ביותר שמחלקת בדיוק.

P26.3-E17 · rolling update בצעדים 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

ב־P26.3-E17.ts:

  • rolloutBounds(replicas, maxSurge, maxUnavailable) ← { maxPods, minAvailable }. כל אחד — מספר או אחוז ("25%"); אחוז של surge מעוגל למעלה, של unavailable למטה (כמו Kubernetes). שניהם 0 (אחרי עיגול) ← שגיאה.
  • simulateRollout(…) ← { maxPods, minAvailable, steps }, כש־steps הוא רשימת { old, new } מ־{replicas, 0} עד {0, replicas}. בכל צעד: קודם מורידים כמה שיותר ישנים בלי לרדת מתחת ל־minAvailable (סופרים ישנים + חדשים שכבר היו בתחילת הצעד), ואז מוסיפים כמה שיותר חדשים בלי לעבור את maxPods. החדשים מוכנים בסוף הצעד.

P26.3-E26 · label selector של Kubernetes 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 3⏱ 30 דק׳ידע נדרש: שיעור 3

Service יודע לאילו Pods לשלוח תעבורה לפי selector (שיעור 3), ו־kubectl get pods -l 'env in (prod,staging),!canary' מסנן באותה שפה. כתוב מקובץ ריק וייצא matches(labels: Record<string, string>, selector: string): boolean, לפי הכללים של Kubernetes:

  • הדרישות מופרדות בפסיק, וכולן צריכות להתקיים. פסיק בתוך סוגריים לא מפריד בין דרישות.
  • key=value או key==value — ה־label קיים ושווה. ‏key!=value — לא שווה, או שאין label כזה בכלל.
  • key in (a, b) — קיים, והערך ברשימה. ‏key notin (a, b) — לא ברשימה, או שאין label כזה.
  • key — קיים (כל ערך). ‏!key — לא קיים.
  • רווחים סביב אופרטורים וערכים מותרים. שם: אותיות, ספרות, _ . - / (‏app.kubernetes.io/name). ערך: אותיות, ספרות, _ . -, ו־key= עם ערך ריק מותר. ‏selector ריק מתאים לכל Pod.
  • כל דבר אחר (app in prod, ‏!app=web, פסיק בסוף, ערך ריק בתוך סוגריים) ← SyntaxError.

P26.3-E28 · סיכום של kubectl get pods 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 2⏱ 20 דק׳ידע נדרש: שיעור 3

🔁 חזרה על פירוק טבלת טקסט לפי הכותרת (‏P23-E28), ‏destructuring של מערכים (פרק 6), ספירה לאובייקט (פרק 7) ומיון עם שני קריטריונים. כשמשהו לא עובד ב־cluster, הפקודה הראשונה היא kubectl get pods. כתוב וייצא:

  • type Pod = { name: string; ready: number; total: number; status: string; restarts: number; age: string }.
  • parsePods(text): Pod[]. העמודות מופרדות בשני רווחים או יותר, ואת המיקום שלהן מוצאים לפי הכותרת: -o wide מוסיף עמודות. ‏READY כמו 1/2 ← ready: 1, total: 2. ‏RESTARTS כמו 14 (63s ago) ← 14.
  • podSummary(pods) ← { byStatus, notReady, restarting }:
    • byStatus — כמה Pods בכל סטטוס: { Running: 4, CrashLoopBackOff: 1, Completed: 1 }.
    • notReady — שמות ה־Pods עם ready < total, חוץ מ־Completed (‏Job שסיים, ולכן 0/1 זה תקין).
    • restarting — Pods עם 3 הפעלות מחדש או יותר, כ־"name (14)", מהגבוה לנמוך, ובתיקו לפי שם.

🔗 איך זה מתחבר: פירוק טבלת טקסט (‏P23-E28) ו־destructuring מפרק 6 — והשיעור: הפקודה הראשונה כשמשהו לא עובד ב־cluster.

P26.3-E67 · כיבוי מסודר שמתאים ל־Kubernetes 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: פרק 24, שיעור 3

התיקון של E64, בקוד. בקובץ 26c-cloud/starter/P26.3-E67.ts (יש בו רק הערה) כתוב וייצא:

export function createGracefulShutdown(opts: { server: http.Server; drainMs: number; closeResources: () => Promise<void> }): { isReady(): boolean; shutdown(): Promise<void> }
  • isReady() — ‏true עד שמתחילים לכבות. (ה־route של /ready יחזיר 503 כשהוא false.)
  • shutdown(): (1) מיד — isReady() ← ‏false. (2) מחכים drainMs — ובזמן הזה השרת ממשיך לקבל בקשות. (3) ‏server.close() — ומחכים שהבקשות שבאמצע יסתיימו. (4) ‏closeResources().
  • קריאה שנייה ל־shutdown() מחזירה את אותו Promise, ולא מתחילה כיבוי שני.
