P26.3-E04 · מה Kubernetes יעשה? 🧠 הבנה רמה 1

💡 רמז 1

readiness ← "לשלוח אליי תנועה?"; liveness ← "להרוג ולהפעיל מחדש?".

💡 רמז 2

ה־Deployment כל הזמן משווה בין מה שכתוב (desired) למה שקיים (actual).

✅ פתרון
  1. ה־ReplicaSet רואה 2 במקום 3, ויוצר pod חדש תוך שניות. זה הרעיון של desired state: לא אומרים "תפעיל", אומרים "צריכים להיות 3".
  2. שום pod לא מופעל מחדש (liveness תקין). כולם יוצאים מה־endpoints של ה־Service (readiness נכשל) — הבקשות נכשלות מהר ב־Ingress במקום להיתקע, וכשהמסד חוזר, הם חוזרים לבד. אם liveness היה בודק את המסד — Kubernetes היה מפעיל מחדש את כל ה־pods בלולאה, בלי שזה עוזר בכלום (פרק 25).
  3. אחרי failureThreshold כישלונות של liveness — הקונטיינר מופעל מחדש (RESTARTS עולה ב־kubectl get pods).
  4. OOMKilled — הקונטיינר נהרג ומופעל מחדש. (חריגה מ־limit של CPU לא הורגת — היא מאטה: throttling.)
  5. ה־pods החדשים ב־CrashLoopBackOff, אף אחד לא Ready — וה־rolling update נעצר: הישנים לא מוסרים מעבר ל־maxUnavailable. האתר ממשיך לעבוד על הגרסה הישנה. kubectl rollout undo (או revert ב־Git, עם Argo CD — שיעור 4).
  6. ה־scheduler יוצר שני pods חדשים על nodes אחרים (אם יש מקום — אחרת הם Pending, E18). ו־PodDisruptionBudget מגן מכיבוי מתוכנן של nodes, לא מתקלה (E11).

P26.3-E58 · לאיזה pod תגיע הבקשה? 🧠 הבנה רמה 2

💡 רמז 1

‏selector הוא "כל ה־labels האלה קיימים ושווים" — labels נוספים לא מפריעים.

💡 רמז 2

Service לא יודע מה זה Deployment.

✅ פתרון

P26.3-E59 · ‏Pending, ‏OOMKilled או סתם איטי? 🧠 הבנה רמה 2

💡 רמז 1

‏scheduler סופר requests, לא שימוש בפועל.

💡 רמז 2

מעל limit של memory ← הורגים. מעל CPU ← מאטים (ואין limit ל־CPU כאן).

✅ פתרון
  1. בכל node נכנסים 2 (‏2×750m = 1.5 CPU; שלישי היה 2.25). סה״כ 4 רצים ו־2 ב־Pending. ב־Events: 0/2 nodes are available: 2 Insufficient cpu. (Cluster Autoscaler היה מוסיף node.)
  2. מעל ה־limit ← ‏OOMKilled, והקונטיינר מופעל מחדש (‏RESTARTS עולה).
  3. אין limit ל־CPU, אז הוא יכול לקחת CPU פנוי ב־node. אם אין — מתחלקים לפי requests, והוא פשוט איטי. לא נהרג.
  4. ה־scheduler "מאמין" ל־100m ודוחס יותר pods ל־node. בעומס כולם מתחרים על אותו CPU, וה־HPA מחשב אחוזים לא נכונים (אחוז מ־100m).
⚠️ טעויות נפוצות
  • "Pending = הקונטיינר קורס" — Pending הוא עוד לפני שהוא התחיל: אין לו node.

P26.3-E60 · ‏rolling update עם אחוזים 🧠 הבנה רמה 2

💡 רמז 1

surge מעוגל למעלה, unavailable למטה.

💡 רמז 2

pod חדש נספר רק כשהוא Ready.

✅ פתרון
  1. 25% מ־10 = 2.5. ‏surge ← 3, כלומר עד 13 pods. ‏unavailable ← 2, כלומר לפחות 8 Ready.
  2. Kubernetes מוריד 2 ישנים ומעלה 3+2=5 חדשים (עד 13 בסך הכול), והחדשים לא נהיים Ready — ה־rollout נתקע. נשארים 8 ישנים Ready ו־5 חדשים קורסים. הלקוחות מקבלים שירות מ־8 במקום 10 — אולי איטי יותר, לא מושבת.
  3. מעלים חדש אחד, הוא לא Ready, ולא מורידים אף ישן. 10 ישנים ו־1 חדש קורס — הלקוחות לא מרגישים כלום.
  4. kubectl rollout undo (או, ב־GitOps, ‏git revert בשיעור 4). ולמה זה קרה בכלל — kubectl logs --previous של pod חדש.
⚠️ טעויות נפוצות
  • "rollout תקוע = הכול למטה" — זה בדיוק ה־readiness מגן: התקלה נעצרת אחרי כמה pods.

P26.3-E61 · לקרוא את kubectl get pods 🧠 הבנה רמה 1

💡 רמז 1

‏describe — Events. ‏logs --previous — הקונטיינר שקרס.

💡 רמז 2

Running אבל 0/1 = הקונטיינר רץ, ה־readiness נכשל.

✅ פתרון
  1. CrashLoopBackOff — התהליך עולה ונופל. ‏kubectl logs … --previous: בדרך כלל משתנה סביבה חסר, או קריסה בעלייה.
  2. Running ‏0/1 — readiness נכשל (מסד לא זמין? נתיב /ready שגוי? פורט שגוי?). ‏describe ← Events של probe, ואז logs.
  3. Pending — אין node עם מספיק requests, או volume/selector. ‏describe ← ‏Insufficient cpu וכו׳ (‏E59).
  4. ImagePullBackOff — שם או tag לא קיים, או אין הרשאה ל־registry. ‏describe ← ההודעה המדויקת.
  5. 1/1 אבל 14 restarts ב־3 ימים — OOMKilled או liveness שנכשל מדי פעם. ‏describe ← ‏Last State: Terminated, Reason: OOMKilled.
⚠️ טעויות נפוצות
  • למחוק pods "כדי שיעלו מחדש" — ה־Deployment יוצר אותם עם אותה בעיה. קודם מבינים.

P26.3-E12 · סודות כקבצים: *_FILE 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

readFile מוזרק — בבדיקה הוא אובייקט בזיכרון, באפליקציה (p) => fs.readFileSync(p, "utf8").

💡 רמז 2

"בלי ה־newline שבסוף" — רק שורה אחת אחרונה. trim() היה מוחק גם רווח שהוא חלק מהסיסמה.

✅ פתרון
// P26.3-E12: הגדרות מ־env, עם המוסכמה *_FILE לסודות (Kubernetes Secret שמורכב כקובץ)
export interface AppConfig {
  databaseUrl: string;
  jwtSecret: string;
  redisUrl: string;
  port: number;
}

type ReadFile = (path: string) => string;

const REQUIRED = { databaseUrl: "DATABASE_URL", jwtSecret: "JWT_SECRET", redisUrl: "REDIS_URL" } as const;

export function readSetting(env: Record<string, string | undefined>, name: string, readFile: ReadFile): string | undefined {
  const direct = env[name];
  const file = env[`${name}_FILE`];
  if (direct !== undefined && file !== undefined) throw new Error(`${name} ו־${name}_FILE מוגדרים שניהם — בחר אחד`);
  if (file !== undefined) {
    let text: string;
    try {
      text = readFile(file);
    } catch {
      throw new Error(`${name}_FILE: אי אפשר לקרוא את ${file}`);
    }
    const value = text.replace(/\r?\n$/, "");
    if (!value) throw new Error(`${name}_FILE: הקובץ ${file} ריק`);
    return value;
  }
  return direct === "" ? undefined : direct;
}

export function loadConfig(env: Record<string, string | undefined>, readFile: ReadFile): AppConfig {
  const missing: string[] = [];
  const out: Record<string, string> = {};
  for (const [key, name] of Object.entries(REQUIRED)) {
    const v = readSetting(env, name, readFile);
    if (v === undefined) missing.push(name);
    else out[key] = v;
  }
  if (missing.length) throw new Error(`חסרות הגדרות: ${missing.join(", ")}`);
  const port = Number(env.PORT ?? "3000");
  if (!Number.isInteger(port) || port < 1 || port > 65535) throw new Error(`PORT לא תקין: ${env.PORT}`);
  return { databaseUrl: out.databaseUrl, jwtSecret: out.jwtSecret, redisUrl: out.redisUrl, port };
}
⚠️ טעויות נפוצות
  • value.trim() — סיסמה שמסתיימת ברווח (נדיר, אבל קורה) נשברת בשקט.

P26.3-E14 · כמויות של Kubernetes 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

"512M" הוא 512,000,000 — כמעט 25MB פחות מ־"512Mi". טעות נפוצה ב־limits.

💡 רמז 2

regex אחד: /^(\d+(?:\.\d+)?)(Ki|Mi|…)?$/.

✅ פתרון
// P26.3-E14: כמויות של Kubernetes — CPU ו־memory
const BINARY: Record<string, number> = { Ki: 2 ** 10, Mi: 2 ** 20, Gi: 2 ** 30, Ti: 2 ** 40 };
const DECIMAL: Record<string, number> = { k: 1e3, M: 1e6, G: 1e9, T: 1e12 };

// מחזיר millicores: "250m" ← 250, "1" ← 1000, "0.5" ← 500
export function parseCpu(q: string | number): number {
  const s = String(q).trim();
  const m = /^(\d+(?:\.\d+)?)(m?)$/.exec(s);
  if (!m) throw new Error(`CPU לא תקין: ${q}`);
  const n = Number(m[1]);
  const milli = m[2] ? n : n * 1000;
  if (!Number.isInteger(milli)) throw new Error(`CPU לא תקין (פחות ממילי־ליבה): ${q}`);
  return milli;
}

// מחזיר בתים: "512Mi" ← 536870912, "1G" ← 1e9
export function parseMemory(q: string | number): number {
  const s = String(q).trim();
  const m = /^(\d+(?:\.\d+)?)(Ki|Mi|Gi|Ti|k|M|G|T)?$/.exec(s);
  if (!m) throw new Error(`memory לא תקין: ${q}`);
  const unit = m[2] ? (BINARY[m[2]] ?? DECIMAL[m[2]]) : 1;
  return Math.round(Number(m[1]) * unit);
}

export function formatMemory(bytes: number): string {
  for (const u of ["Gi", "Mi", "Ki"]) if (bytes >= BINARY[u] && bytes % BINARY[u] === 0) return `${bytes / BINARY[u]}${u}`;
  return String(bytes);
}
⚠️ טעויות נפוצות
  • "250M" כ־CPU — זה לא "250 מילי", זה 250 מיליון ליבות (ו־Kubernetes דוחה). m קטנה.

P26.3-E17 · rolling update בצעדים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

4 עותקים, surge 1, unavailable 0: 4/0 4/1 3/2 2/3 1/4 0/4.

💡 רמז 2

להסיר: min(old, old + new - minAvailable). להוסיף: min(replicas - new, maxPods - old - new).

✅ פתרון
// P26.3-E17: rolling update — כמה pods מותר, ואיך ה־rollout מתקדם
export type Amount = number | `${number}%`;

function resolve(amount: Amount, replicas: number, round: (n: number) => number, name: string): number {
  if (typeof amount === "number") {
    if (!Number.isInteger(amount) || amount < 0) throw new Error(`${name} לא תקין: ${amount}`);
    return amount;
  }
  const m = /^(\d+)%$/.exec(amount);
  if (!m) throw new Error(`${name} לא תקין: ${amount}`);
  return round((replicas * Number(m[1])) / 100);
}

export function rolloutBounds(replicas: number, maxSurge: Amount, maxUnavailable: Amount) {
  if (!Number.isInteger(replicas) || replicas < 1) throw new Error("replicas חייב להיות לפחות 1");
  const surge = resolve(maxSurge, replicas, Math.ceil, "maxSurge"); // Kubernetes: surge מעגל למעלה
  const unavailable = resolve(maxUnavailable, replicas, Math.floor, "maxUnavailable"); // unavailable — למטה
  if (surge === 0 && unavailable === 0) throw new Error("maxSurge ו־maxUnavailable לא יכולים להיות שניהם 0 — ה־rollout לא יתקדם");
  return { maxPods: replicas + surge, minAvailable: replicas - unavailable };
}

export interface Snapshot {
  old: number;
  new: number;
}

// מודל פשוט: pods חדשים שנוצרו בצעד מוכנים (ready) בסוף הצעד
export function simulateRollout(replicas: number, maxSurge: Amount, maxUnavailable: Amount) {
  const { maxPods, minAvailable } = rolloutBounds(replicas, maxSurge, maxUnavailable);
  let oldPods = replicas;
  let newPods = 0;
  const steps: Snapshot[] = [{ old: oldPods, new: newPods }];
  while (oldPods > 0 || newPods < replicas) {
    const remove = Math.max(0, Math.min(oldPods, oldPods + newPods - minAvailable));
    oldPods -= remove;
    const add = Math.max(0, Math.min(replicas - newPods, maxPods - oldPods - newPods));
    newPods += add;
    if (remove === 0 && add === 0) throw new Error("ה־rollout תקוע");
    steps.push({ old: oldPods, new: newPods });
  }
  return { maxPods, minAvailable, steps };
}

הבחירה בפועל: maxUnavailable: 0 + maxSurge: 1 — אף פעם לא פחות קיבולת, אבל איטי ודורש מקום ל־pod נוסף. 25%/25% (ברירת המחדל של Kubernetes) — מהר יותר. maxSurge: 0 — כשאין מקום פנוי ב־cluster.

  cpu: string;
  memory: string;
}
export interface PodSpec {
  name: string;
  cpu: string;
  memory: string;
}

// מוכנות (מ־E14)
export const parseCpu = (q: string) => (q.endsWith("m") ? Number(q.slice(0, -1)) : Number(q) * 1000);
const UNITS: Record<string, number> = { Ki: 2 ** 10, Mi: 2 ** 20, Gi: 2 ** 30, k: 1e3, M: 1e6, G: 1e9 };
export const parseMemory = (q: string) => {
  const m = /^(\d+(?:\.\d+)?)(Ki|Mi|Gi|k|M|G)?$/.exec(q)!;
  return Math.round(Number(m[1]) * (m[2] ? UNITS[m[2]] : 1));
};

export function schedule(nodes: NodeSpec[], pods: PodSpec[]) {
  const free = new Map(nodes.map((n) => [n.name, { cpu: parseCpu(n.cpu), memory: parseMemory(n.memory) }]));
  const order = pods
    .map((p) => ({ name: p.name, cpu: parseCpu(p.cpu), memory: parseMemory(p.memory) }))
    .sort((a, b) => b.cpu - a.cpu || b.memory - a.memory || a.name.localeCompare(b.name)); // הגדולים קודם
  const placements: Record<string, string> = {};
  const pending: string[] = [];
  for (const pod of order) {
    const node = nodes.find((n) => {
      const f = free.get(n.name)!;
      return f.cpu >= pod.cpu && f.memory >= pod.memory;
    });
    if (!node) {
      pending.push(pod.name);
      continue;
    }
    const f = free.get(node.name)!;
    f.cpu -= pod.cpu;
    f.memory -= pod.memory;
    placements[pod.name] = node.name;
  }
  return { placements, pending, free: Object.fromEntries(free) };
}

✅ פתרון
// P26.3-E26 — label selector של Kubernetes
export type Requirement =
  | { key: string; op: "=" | "!="; value: string }
  | { key: string; op: "in" | "notin"; values: string[] }
  | { key: string; op: "exists" | "!exists" };

const EQUALITY = /^([\w./-]+)\s*(==|=|!=)\s*([\w.-]*)$/;
const SET = /^([\w./-]+)\s+(in|notin)\s*\(([^()]*)\)$/;
const EXISTS = /^(!?)\s*([\w./-]+)$/;
const VALUE = /^[\w.-]+$/;

export function parseSelector(selector: string): Requirement[] {
  if (selector.trim() === "") return [];
  // פסיק מפריד בין דרישות — אבל לא פסיק בתוך סוגריים
  return selector.split(/,(?![^()]*\))/).map((raw) => {
    const part = raw.trim();
    let m = part.match(EQUALITY);
    if (m) return { key: m[1], op: m[2] === "!=" ? "!=" : "=", value: m[3] };
    m = part.match(SET);
    if (m) {
      const values = m[3].split(",").map((v) => v.trim());
      if (values.some((v) => !VALUE.test(v))) throw new SyntaxError(`ערך לא תקין ב־"${part}"`);
      return { key: m[1], op: m[2] as "in" | "notin", values };
    }
    m = part.match(EXISTS);
    if (m) return { key: m[2], op: m[1] ? "!exists" : "exists" };
    throw new SyntaxError(`דרישה לא תקינה: "${part}"`);
  });
}

export function matches(labels: Record<string, string>, selector: string): boolean {
  return parseSelector(selector).every((r) => {
    const has = Object.hasOwn(labels, r.key);
    const value = labels[r.key];
    switch (r.op) {
      case "=":
        return has && value === r.value;
      case "!=":
        return !has || value !== r.value;
      case "in":
        return has && r.values.includes(value);
      case "notin":
        return !has || !r.values.includes(value);
      case "exists":
        return has;
      case "!exists":
        return !has;
    }
  });
}

// P26.3-E28 — סיכום של kubectl get pods
export type Pod = { name: string; ready: number; total: number; status: string; restarts: number; age: string };

export function parsePods(text: string): Pod[] {
  const [header, ...rows] = text.trim().split("\n");
  const cols = header.trim().split(/\s{2,}/);
  const at = (name: string) => {
    const i = cols.indexOf(name);
    if (i === -1) throw new Error(`חסרה עמודה ${name}`);
    return i;
  };
  const [NAME, READY, STATUS, RESTARTS, AGE] = ["NAME", "READY", "STATUS", "RESTARTS", "AGE"].map(at);
  return rows
    .filter((row) => row.trim() !== "")
    .map((row) => {
      const cells = row.trim().split(/\s{2,}/);
      const [ready, total] = cells[READY].split("/").map(Number);
      return {
        name: cells[NAME],
        ready,
        total,
        status: cells[STATUS],
        restarts: parseInt(cells[RESTARTS], 10),
        age: cells[AGE],
      };
    });
}

export function podSummary(pods: Pod[]) {
  const byStatus: Record<string, number> = {};
  for (const pod of pods) byStatus[pod.status] = (byStatus[pod.status] ?? 0) + 1;
  const notReady = pods.filter((p) => p.ready < p.total && p.status !== "Completed").map((p) => p.name);
  const restarting = pods
    .filter((p) => p.restarts >= 3)
    .sort((a, b) => b.restarts - a.restarts || a.name.localeCompare(b.name))
    .map((p) => `${p.name} (${p.restarts})`);
  return { byStatus, notReady, restarting };
}

אותו image כמו ה־API, פקודה אחרת — אין צורך ב־image נפרד לדוח. ‏timeZone חשוב בישראל: בלעדיו 0 2 * * * הוא 02:00 UTC — 04:00 או 05:00 אצלנו, תלוי בשעון קיץ (פרק 24).

P26.3-E67 · כיבוי מסודר שמתאים ל־Kubernetes 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏await new Promise((r) => setTimeout(r, drainMs)), ואחר כך await new Promise((r) => server.close(() => r())).

💡 רמז 2

לשמור את ה־Promise הראשון במשתנה: let running: Promise<void> | null = null.

✅ פתרון
// P26.3-E67: כיבוי מסודר שמתאים ל־Kubernetes
import type http from "node:http";

type Opts = { server: http.Server; drainMs: number; closeResources: () => Promise<void> };

export function createGracefulShutdown({ server, drainMs, closeResources }: Opts) {
  let ready = true;
  let running: Promise<void> | null = null;
  async function run() {
    ready = false; // /ready ← 503: Kubernetes מפסיק לשלוח אלינו
    await new Promise((r) => setTimeout(r, drainMs)); // בינתיים ממשיכים לענות לבקשות שעוד מגיעות
    await new Promise<void>((r) => server.close(() => r())); // לא מקבלים חדשות, ומחכים לאלה שבאמצע
    await closeResources(); // המסד, Redis — אחרונים
  }
  return {
    isReady: () => ready,
    shutdown() {
      running ??= run();
      return running;
    },
  };
}

בשימוש: process.on("SIGTERM", () => void shutdown()), ו־/ready מחזיר isReady() ? 200 : 503. ה־drainMs הוא הזמן שלוקח לעדכון ה־endpoints להגיע לכל מקום — כמה שניות. עם preStop של sleep 5 ב־YAML מקבלים אותו אפקט בלי קוד.

⚠️ טעויות נפוצות
  • server.close() מיד ואחר כך לחכות — בדיוק הבאג של E64.
  • closeResources() לפני ש־server.close הסתיים — הבקשה האחרונה נופלת על "pool closed".
