P26.3-E01 · איזה שירות של AWS? 🧠 הבנה רמה 1

💡 רמז 1

חלק מהשירותים הם "גרסה מנוהלת" של משהו שכבר הכרת בקורס: PostgreSQL, Redis, תור, Docker.

💡 רמז 2

לשורה 1 יש שתי תשובות טובות: ECS (פשוט יותר) או EKS (Kubernetes — שיעור 3).

✅ פתרון
  1. EKS (Kubernetes מנוהל — מה שהמודעה ביקשה) או ECS (מנגנון של AWS עצמה, פשוט יותר). בשניהם: עם Fargate לא מנהלים שרתים; או על EC2 — מכונות שלך. ה־image יושב ב־ECR (registry של AWS) או ב־GHCR.
  2. RDS for PostgreSQL או Aurora (PostgreSQL או MySQL — יחידה 25.5). Multi-AZ = עותק ממתין באזור אחר.
  3. ElastiCache (Redis/Valkey) — אותו פרוטוקול, אותו ioredis מפרק 26.
  4. S3 — object storage: מפתח ← קובץ, בלי שרת קבצים ובלי דיסק שמתמלא (שיעור 2).
  5. CloudFront — CDN מול ה־bucket.
  6. SQS (יחידה 26.5). ל־BullMQ שכבר יש — אפשר להישאר עם Redis.
  7. Secrets Manager (או SSM Parameter Store) — ומשם ל־Kubernetes Secret (שיעור 3).
  8. CloudWatch — לוגים, מדדים, alarms. (הרבה חברות שולחות לכלי אחר — Datadog, Grafana — אבל CloudWatch קיים תמיד.)
  9. Lambda + EventBridge Scheduler — משלמים על 20 שניות ביום, לא על שרת שמחכה. (או CronJob ב־Kubernetes, אם כבר יש cluster.)
  10. IAM — users, roles, policies (שיעור 2).
⚠️ טעויות נפוצות
  • "S3 כדיסק של השרת" — אין שם תיקיות אמיתיות ואין "לפתוח קובץ ולכתוב באמצע". קוראים ושומרים אובייקט שלם.
  • EC2 לכל דבר — אפשר, אבל אז אתה מנהל עדכוני מערכת הפעלה, גיבויים ו־failover בעצמך.

P26.3-E29 · ‏region, ‏AZ ו־Multi-AZ 🧠 הבנה רמה 1

💡 רמז 1

AZ = מרכז נתונים נפרד, עם חשמל ורשת משלו. region = אזור שלם.

💡 רמז 2

"הנתונים לא יוצאים מה־region אלא אם ביקשת".

✅ פתרון
  1. ה־API ממשיך עם שני עותקים (ה־load balancer מפסיק לשלוח לשרוף), ו־Kubernetes מעלה שלישי ב־AZ אחר. ה־RDS נפל יחד עם ה־AZ — האתר למטה עד שחוזרים מגיבוי. Multi-AZ = עותק standby ב־AZ אחר, ו־failover אוטומטי של דקה־שתיים.
  2. מחיר, שירותים שעוד לא קיימים ב־region החדש, וניסיון של הצוות; ‏latency מישראל לפרנקפורט הוא עשרות מילישניות — מורגש רק במערכות רגישות. מה יכול לחייב: רגולציה של שמירת מידע בארץ (בנקים, בריאות, ממשלה).
  3. מגן מתקלה בשרת או ב־AZ (S3 שומר עותקים בכמה AZs). לא מגן מטעות (מישהו מחק — ‏versioning עוזר), ולא מאסון ב־region כולו או מנעילת החשבון — לשם צריך עותק ב־region או בחשבון אחר.
⚠️ טעויות נפוצות
  • "AZ = region" — ה־region הוא העיר, ה־AZs הם כמה מרכזי נתונים בה.

P26.3-E30 · ‏EC2, קונטיינרים או Lambda? 🧠 הבנה רמה 1

💡 רמז 1

Lambda — לכל אירוע, קצר, ומשלמים לפי מילי־שנייה.

💡 רמז 2

מה קורה ל־Lambda שצריך לחכות לעבודות, או להחזיק חיבור?

✅ פתרון
  1. קונטיינרים — אותו image, עותקים, rolling update.
  2. Lambda — מזדמן וקצר; ‏EC2 היה דולק 24 שעות בשביל 10 שניות של עבודה ביום.
  3. קונטיינרים — תהליך שרץ ומחכה. ב־Lambda משלמים על כל שנייה של המתנה, ויש הגבלת זמן לריצה.
  4. Lambda — האירוע של S3 מפעיל אותה; אין עבודה — אין חשבון.
  5. EC2 — רק מכונה מלאה נותנת שליטה במערכת ההפעלה.
  6. קונטיינרים — Lambda לא מחזיקה חיבור פתוח שעה (יש לה גבול זמן, וכל חיבור הוא הרצה).
⚠️ טעויות נפוצות
  • "Lambda תמיד הכי זול" — בעומס קבוע, שעת מכונה זולה בהרבה ממיליון הרצות (‏E36).

P26.3-E32 · מה משתנה בקוד כשעוברים ל־AWS? 🧠 הבנה רמה 2

💡 רמז 1

שלושה עותקים, וכל אחד יכול למות ולהיווצר מחדש על מכונה אחרת.

💡 רמז 2

"12-factor": הגדרות מ־env, לוגים ל־stdout, בלי מצב בדיסק.

✅ פתרון
  1. כלום — רק ערך אחר (‏RDS, עם TLS).
  2. קוד — הדיסק של pod זמני ולא משותף. קובץ שהועלה לעותק A לא קיים ב־B, ונעלם כשה־pod מוחלף. ‏S3 (שיעור 2).
  3. קוד (קטן) — לכתוב ל־stdout. הפלטפורמה אוספת (CloudWatch).
  4. קוד — כל עותק עם sessions משלו. Redis (פרק 26) או JWT.
  5. הגדרות + build — סוד לא נכנס ל־image. ‏Secret של Kubernetes / Secrets Manager, נטען כ־env או כקובץ (E12).
  6. כלום — ועכשיו יש להם תפקיד: readiness ו־liveness (שיעור 3).
⚠️ טעויות נפוצות
  • "נשים volume משותף לכל ה־pods" — אפשרי (EFS), אבל יקר ואיטי, ופותר בעיה ש־S3 פותר טוב יותר.

P26.3-E33 · ‏Infrastructure as Code ו"חשבון שנשרף" 🧠 הבנה רמה 1

‏review, היסטוריה, שחזור.

💡 רמז 2

Git זוכר הכול (פרק 9).

P26.3-E34 · ‏AZ, ‏region ופיזור עותקים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏/^([a-z]{2}(?:-[a-z]+)+-\d+)[a-z]$/.

💡 רמז 2

סבב: העותק ה־i הולך ל־azs[i % azs.length]. נפילה: total - spread[az] >= minHealthy לכל az.

✅ פתרון
// P26.3-E34: AZ, region ופיזור עותקים
export function regionOf(az: string): string | null {
  const m = /^([a-z]{2}(?:-[a-z]+)+-\d+)[a-z]$/.exec(az);
  return m ? m[1] : null;
}

export function spreadAcrossAzs(replicas: number, azs: string[]): Record<string, number> {
  if (azs.length === 0) throw new RangeError("צריך לפחות AZ אחד");
  const out: Record<string, number> = Object.fromEntries(azs.map((az) => [az, 0]));
  for (let i = 0; i < replicas; i++) out[azs[i % azs.length]]++;
  return out;
}

export function survivesAzLoss(spread: Record<string, number>, minHealthy: number): boolean {
  const total = Object.values(spread).reduce((s, n) => s + n, 0);
  return Object.values(spread).every((n) => total - n >= minHealthy);
}

שלושה עותקים באותו AZ הם עותק אחד מבחינת שריפה. Kubernetes עושה את הפיזור הזה עם topologySpreadConstraints, ו־survivesAzLoss היא השאלה שה־PDB (‏E11) צריך לענות עליה גם בתחזוקה.

⚠️ טעויות נפוצות
  • לבדוק רק את ה־AZ עם הכי הרבה עותקים — נכון כאן, אבל קל לטעות בכיוון (המינימום ולא המקסימום).

P26.3-E35 · כמה תשיעיות? 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏-Math.log10(1 - a) — ‏0.999 ← 3.

💡 רמז 2

שברים עשרוניים: 1 - 0.999 הוא 0.0010000000000000009. לכן Math.floor(x + 1e-9).

✅ פתרון
// P26.3-E35: כמה תשיעיות?
export function availability(single: number, copies: number) {
  return 1 - (1 - single) ** copies;
}

export function nines(a: number) {
  if (a >= 1) return Infinity;
  return Math.floor(-Math.log10(1 - a) + 1e-9);
}

export function downtimeMinutesPerYear(a: number) {
  return Math.round((1 - a) * 365 * 24 * 60);
}

שני עותקים של 99% נותנים 99.99% — אם הם באמת עצמאיים. שניהם באותו AZ, או תלויים באותו מסד, הם לא עצמאיים, והחישוב משקר. לכן Multi-AZ, ולכן readiness שמוציא עותק בלי מסד.

⚠️ טעויות נפוצות
  • Math.floor(-Math.log10(1 - 0.999)) — יוצא 2 בגלל שגיאת עיגול.

P26.3-E36 · ‏EC2 או Lambda — מה יותר זול? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏Math.round(x * 100) / 100.

💡 רמז 2

‏512MB הם חצי GB. ‏200ms הן 0.2 שנייה.

✅ פתרון
// P26.3-E36: EC2 או Lambda — מה יותר זול?
const cents = (x: number) => Math.round(x * 100) / 100;

export function ec2Monthly(hourlyUsd: number, instances: number, hours = 730) {
  return cents(hourlyUsd * instances * hours);
}

export function lambdaMonthly({ requests, avgMs, memoryMb, perMillionRequests = 0.2, perGbSecond = 0.0000166667 }: { requests: number; avgMs: number; memoryMb: number; perMillionRequests?: number; perGbSecond?: number }) {
  const requestCost = (requests / 1_000_000) * perMillionRequests;
  const gbSeconds = requests * (avgMs / 1000) * (memoryMb / 1024);
  return cents(requestCost + gbSeconds * perGbSecond);
}

export function cheaper(ec2: number, lambda: number): "ec2" | "lambda" | "same" {
  return ec2 < lambda ? "ec2" : lambda < ec2 ? "lambda" : "same";
}

webhook של 6,000 קריאות בחודש: Lambda עולה פחות מסנט, ושתי מכונות קטנות עשרות דולרים. ‏API עם 100 בקשות בשנייה כל החודש: ההפך. "Lambda או שרת" היא שאלה של צורת העומס.

⚠️ טעויות נפוצות
  • לשכוח את memoryMb / 1024 — המחיר הוא ל־GB־שנייה, לא לשנייה.

P26.3-E37 · ‏handler של Lambda מאחורי API Gateway 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏Buffer.from(body, "base64").toString("utf8").

💡 רמז 2

פונקציית עזר:

const json = (statusCode, data) => ({ statusCode, headers: …, body: JSON.stringify(data) });
✅ פתרון
// P26.3-E37: handler של Lambda מאחורי API Gateway
type Event = { httpMethod: string; path: string; body: string | null; isBase64Encoded?: boolean };

const json = (statusCode: number, data: unknown) => ({ statusCode, headers: { "Content-Type": "application/json" }, body: JSON.stringify(data) });
const isInt = (x: unknown, min: number, max: number) => Number.isInteger(x) && (x as number) >= min && (x as number) <= max;

export async function handler(event: Event) {
  if (event.httpMethod === "GET" && event.path === "/health") return json(200, { ok: true });
  if (event.httpMethod === "POST" && event.path === "/orders") {
    const raw = event.body && event.isBase64Encoded ? Buffer.from(event.body, "base64").toString("utf8") : event.body;
    let data: { productId?: unknown; qty?: unknown };
    try {
      data = JSON.parse(raw ?? "");
    } catch {
      return json(400, { error: "JSON לא תקין" });
    }
    if (!data || typeof data !== "object") return json(400, { error: "גוף לא תקין" });
    if (!isInt(data.productId, 1, Number.MAX_SAFE_INTEGER)) return json(400, { error: "productId לא תקין" });
    if (!isInt(data.qty, 1, 10)) return json(400, { error: "qty בין 1 ל־10" });
    return json(202, { accepted: true, productId: data.productId, qty: data.qty });
  }
  return json(404, { error: "not found" });
}

זה מה ש־Express עושה בשבילך מתחת לפני השטח: לפרק את הבקשה, ולבנות תשובה. יש ספריות שעוטפות אפליקציית Express שלמה ב־Lambda — אבל כדאי לראות פעם אחת את החוזה הגולמי.

⚠️ טעויות נפוצות
  • להחזיר body כאובייקט — API Gateway מצפה למחרוזת.
  • JSON.parse(null) מחזיר null בלי לזרוק — ואז data.productId נופל.

P26.3-E38 · תחזית חשבון והתראות תקציב 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏reduce לסכום, ו־sum / dailyCosts.length לממוצע.

💡 רמז 2

לולאה על הימים עם סכום מצטבר; לכל סף — findIndex על מערך הסכומים המצטברים.

✅ פתרון
// P26.3-E38: תחזית חשבון והתראות תקציב
const cents = (x: number) => Math.round(x * 100) / 100;

export function forecastMonth(dailyCosts: number[], daysInMonth: number) {
  if (dailyCosts.length === 0) return 0;
  const spent = dailyCosts.reduce((s, x) => s + x, 0);
  const avg = spent / dailyCosts.length;
  return cents(spent + avg * (daysInMonth - dailyCosts.length));
}

export function budgetAlerts(dailyCosts: number[], budget: number, thresholds = [0.5, 0.8, 1]) {
  const cumulative: number[] = [];
  let sum = 0;
  for (const c of dailyCosts) cumulative.push((sum += c));
  const out: { threshold: number; day: number }[] = [];
  for (const threshold of thresholds) {
    const i = cumulative.findIndex((x) => x >= threshold * budget - 1e-9);
    if (i !== -1) out.push({ threshold, day: i + 1 });
  }
  return out;
}

ב־AWS Budgets יש את שני הסוגים: התראה על בפועל ("עברת 80%") ועל תחזית ("בקצב הזה תעבור את התקציב"). התחזית מתריעה מוקדם יותר — מפתח שדלף ביום 3 מקפיץ את הממוצע מיד.

⚠️ טעויות נפוצות
  • > במקום >= — מי שהוציא בדיוק 50% לא מקבל התראה.

P26.3-E39 · ‏terraform plan קטן 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏new Map(actual.map((r) => [${r.type}.${r.name}, r])).

💡 רמז 2

כל המפתחות של שני ה־props: new Set([...Object.keys(a), ...Object.keys(b)]).

✅ פתרון
// P26.3-E39: terraform plan קטן
type Resource = { type: string; name: string; props: Record<string, unknown> };

const id = (r: Resource) => `${r.type}.${r.name}`;

export function plan(desired: Resource[], actual: Resource[]) {
  const have = new Map(actual.map((r) => [id(r), r]));
  const want = new Map(desired.map((r) => [id(r), r]));
  const create: string[] = [];
  const update: { id: string; changes: string[] }[] = [];
  let unchanged = 0;
  for (const [k, d] of want) {
    const a = have.get(k);
    if (!a) {
      create.push(k);
      continue;
    }
    const keys = new Set([...Object.keys(d.props), ...Object.keys(a.props)]);
    const changes = [...keys].filter((p) => JSON.stringify(d.props[p]) !== JSON.stringify(a.props[p])).sort();
    if (changes.length) update.push({ id: k, changes });
    else unchanged++;
  }
  const del = [...have.keys()].filter((k) => !want.has(k));
  return { create: create.sort(), update: update.sort((x, y) => (x.id < y.id ? -1 : 1)), delete: del.sort(), unchanged };
}

זה לב של Terraform, CloudFormation, ‏kubectl apply ו־Argo CD (שיעור 4): להשוות בין "רצוי" ל"מצוי". ההבדל ביניהם הוא מה משווים ואיך מבצעים — אבל ה־plan שמראים ב־review הוא בדיוק הרשימה הזו. ושורה ב־delete של מסד היא הרגע לעצור ולקרוא שוב.

⚠️ טעויות נפוצות

P26.3-E40 · לפרק כתובת של image (גם ECR) 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

קודם מורידים את ה־digest (indexOf("@")), אחר כך ה־registry, ורק אז מחפשים tag ב־lastIndexOf(":") של מה שנשאר.

💡 רמז 2
/^(\d{12})\.dkr\.ecr\.([a-z0-9-]+)\.amazonaws\.com$/
✅ פתרון
// P26.3-E40: לפרק כתובת של image (גם ECR)
export function parseImageRef(ref: string) {
  let rest = ref;
  let digest: string | null = null;
  const at = rest.indexOf("@");
  if (at !== -1) {
    digest = rest.slice(at + 1);
    rest = rest.slice(0, at);
  }
  let registry = "docker.io";
  const slash = rest.indexOf("/");
  const first = slash === -1 ? "" : rest.slice(0, slash);
  if (first && (first.includes(".") || first.includes(":") || first === "localhost")) {
    registry = first;
    rest = rest.slice(slash + 1);
  } else if (slash === -1) {
    rest = `library/${rest}`;
  }
  let tag: string | null = null;
  const colon = rest.lastIndexOf(":");
  if (colon > rest.lastIndexOf("/")) {
    tag = rest.slice(colon + 1);
    rest = rest.slice(0, colon);
  }
  return { registry, repository: rest, tag, digest };
}

export function ecrInfo(ref: string) {
  const m = /^(\d{12})\.dkr\.ecr\.([a-z0-9-]+)\.amazonaws\.com$/.exec(parseImageRef(ref).registry);
  return m ? { account: m[1], region: m[2] } : null;
}

‏ECR (‏Elastic Container Registry) הוא ה־registry של AWS. ה־image נשאר אותו image — רק הכתובת משתנה, ובתוכה החשבון וה־region. ב־EKS משיכה מ־ECR באותו חשבון לא צריכה סיסמה: ה־role של ה־nodes מקבל הרשאה ב־IAM.

⚠️ טעויות נפוצות
  • ref.split(":") — ‏localhost:5000/app:1 מתפרק לשלושה.
  • להניח tag latest כשאין — ‏null מאפשר לקוד אחר להחליט (ו"בלי tag" הוא בדיוק מה שהבודקים של E09 דוחים).

💡 רמז 2

✅ פתרון
// P26.3-E41: סורק סודות לפני commit
const RULES: { kind: string; re: RegExp }[] = [
  { kind: "aws-access-key", re: /\b((?:AKIA|ASIA)[0-9A-Z]{16})\b/g },
  { kind: "aws-secret-key", re: /aws_secret_access_key\s*[=:]\s*["']?([A-Za-z0-9/+=]{40})(?![A-Za-z0-9/+=])/gi },
  { kind: "github-token", re: /\b(ghp_[A-Za-z0-9]{36})\b/g },
];

export function findSecrets(text: string) {
  const out: { line: number; kind: string; preview: string }[] = [];
  text.split(/\r?\n/).forEach((lineText, i) => {
    const found: { at: number; kind: string; secret: string }[] = [];
    for (const { kind, re } of RULES) {
      for (const m of lineText.matchAll(re)) found.push({ at: m.index! + m[0].indexOf(m[1]), kind, secret: m[1] });
    }
    found.sort((a, b) => a.at - b.at);
    for (const f of found) out.push({ line: i + 1, kind: f.kind, preview: `${f.secret.slice(0, 4)}…` });
  });
  return out;
}

‏preview בלי הסוד המלא — כי הפלט של סורק כזה מגיע ללוג של ה־CI, ולוג הוא בדיוק המקום שממנו סודות דולפים. כלים אמיתיים (gitleaks, ה־secret scanning של GitHub) עובדים כך, עם מאות כללים.

⚠️ טעויות נפוצות
  • להדפיס את השורה כולה "כדי שיהיה קל למצוא" — הסוד עכשיו גם בלוג.

✅ פתרון

P26.3-E45 · מ־compose.yaml לתוכנית AWS 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏depends_on יכול להיות רשימה ([db]) או מפה ({ db: { condition: … } }). רק במפה יש condition.

💡 רמז 2

קודם אוספים Set של שירותים שמישהו מחכה לסיום שלהם, ורק אז עוברים על השירותים.

✅ פתרון
// P26.3-E45: מ־compose.yaml לתוכנית AWS
import YAML from "yaml";

type Target = "RDS" | "ElastiCache" | "EKS Job" | "EKS Deployment";
type Service = { image?: string; depends_on?: string[] | Record<string, { condition?: string }> };

export function awsPlanFromCompose(yamlText: string) {
  const services: Record<string, Service> = YAML.parse(yamlText)?.services ?? {};
  const runOnce = new Set<string>();
  for (const s of Object.values(services)) {
    const deps = s.depends_on;
    if (deps && !Array.isArray(deps)) {
      for (const [name, d] of Object.entries(deps)) if (d?.condition === "service_completed_successfully") runOnce.add(name);
    }
  }
  return Object.entries(services)
    .map(([service, s]): { service: string; target: Target } => {
      const image = s.image ?? "";
      if (/^(postgres|mysql)\b/.test(image)) return { service, target: "RDS" };
      if (/^(redis|valkey)\b/.test(image)) return { service, target: "ElastiCache" };
      if (runOnce.has(service)) return { service, target: "EKS Job" };
      return { service, target: "EKS Deployment" };
    })
    .sort((a, b) => (a.service < b.service ? -1 : 1));
}

‏service_completed_successfully הוא הרמז הכי טוב שיש ב־compose ל"זה Job": מישהו מחכה שהוא יסתיים, לא שהוא יהיה בריא. זה בדיוק ה־migrate של חנות הקפה, ו־E24 הופך אותו ל־Job של Kubernetes.

⚠️ טעויות נפוצות
  • image.includes("redis") — ‏bitnami/redis-exporter הוא לא Redis.

P26.3-E46 · דוח עלויות ב־SQL 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

הסכום הכולל באותה שאילתה: SUM(SUM(usd)) OVER () — סכום של הסכומים, על כל השורות של התוצאה.

✅ פתרון
-- P26.3-E46: דוח עלויות ב־SQL
SELECT service,
       SUM(usd) AS total,
       ROUND(100 * SUM(usd) / SUM(SUM(usd)) OVER (), 1) AS share
FROM costs
WHERE day >= '2026-11-01' AND day < '2026-12-01'
GROUP BY service
ORDER BY total DESC, service;

‏SUM(SUM(usd)) OVER () נראה מוזר, אבל הוא בדיוק "הסכום הכולל, בכל שורה": ה־SUM הפנימי הוא של ה־GROUP BY, והחיצוני — window על כל התוצאה. בלי זה צריך תת־שאילתה.

⚠️ טעויות נפוצות
  • day <= '2026-11-30' — עובד ל־date, אבל נשבר ברגע שהעמודה תהיה timestamptz (פרק 24).
  • 100 * SUM(usd) / (SELECT SUM(usd) FROM costs) — בלי הסינון של החודש בתת־השאילתה, האחוזים של כל החודשים.

💡 רמז 2

‏sleep ו־random כפרמטרים — כדי שהבודק לא יחכה באמת, ויידע בדיוק אילו המתנות ביקשת.

✅ פתרון
// P26.3-E47: retry ל־ThrottlingException
type Opts = { retries?: number; baseMs?: number; sleep?: (ms: number) => Promise<void>; random?: () => number };

const RETRYABLE = new Set(["ThrottlingException", "SlowDown", "RequestLimitExceeded"]);

function retryable(err: unknown) {
  const e = err as { name?: string; $metadata?: { httpStatusCode?: number } };
  return RETRYABLE.has(e?.name ?? "") || (e?.$metadata?.httpStatusCode ?? 0) >= 500;
}

export async function withAwsRetry<T>(fn: () => Promise<T>, opts: Opts = {}): Promise<T> {
  const { retries = 3, baseMs = 100, sleep = (ms) => new Promise((r) => setTimeout(r, ms)), random = Math.random } = opts;
  for (let attempt = 0; ; attempt++) {
    try {
      return await fn();
    } catch (err) {
      if (!retryable(err) || attempt >= retries) throw err;
      await sleep(Math.floor(random() * baseMs * 2 ** attempt));
    }
  }
}

למה אקראי? אם מאה workers נחסמו באותו רגע וכולם מחכים בדיוק 100ms — הם חוזרים יחד, ונחסמים שוב יחד. "full jitter" מפזר אותם. (ה־SDK של AWS עושה retry כזה לבד, עם 3 ניסיונות. כדאי לדעת מה הוא עושה — ומתי להגדיל.)

⚠️ טעויות נפוצות
  • לנסות שוב על כל שגיאה — ‏AccessDenied לא יעבור בניסיון הרביעי, רק ייקח יותר זמן להיכשל.
