🧰 לפני שמתחילים — יחידה 26.3

מה צריך שכבר יהיה מותקן: Docker Desktop (פרק 23), ופרק 25 — ה־CI וה־deploy של פרויקט 2.

מה מתקינים / מריצים עכשיו:

  • LocalStack — אמולטור של AWS שרץ בקונטיינר: S3, SQS ו־IAM על המחשב שלך, בלי חשבון ובלי כרטיס אשראי (פעם אחת; אחר כך docker start localstack): 
    docker run -d --name localstack -p 4566:4566 -e SERVICES=s3,sqs,iam,sts localstack/localstack:4.14.0
    הגרסה קבועה בכוונה: מגרסאות 2026 ואילך LocalStack דורש חשבון ו־auth token גם לשימוש החינמי. 4.14 עובדת בלי, ומספיקה לכל היחידה.
  • בדיקה: curl http://localhost:4566/_localstack/health ← "s3": "available" (או "running").
  • ב־~/dev/backend-course/.env: COURSE_AWS_ENDPOINT=http://localhost:4566.
  • npm install בתיקיית הקורס — מוסיף את @aws-sdk/client-s3, @aws-sdk/client-sqs, @aws-sdk/s3-request-presigner ו־yaml.
  • תוסף VS Code: Kubernetes — השלמה ובדיקה של manifests בזמן הכתיבה (מגיע עם תוסף YAML של Red Hat).
  • לא חובה — cluster אמיתי על המחשב: kind (Kubernetes בתוך Docker), kubectl ו־helm. ב־Mac: brew install kind kubectl helm; ב־Windows: winget install Kubernetes.kind Kubernetes.kubectl Helm.Helm. הבודקים של היחידה לא צריכים cluster — הם קוראים את ה־YAML ובודקים אותו — אבל לראות pod עולה ונופל זה שווה את רבע השעה.

📂 העתקת חומרי הפרק: ב־Finder, העתק את התיקייה 26c-cloud מתוך ~/Desktop/Backend/backend-course אל ~/dev/backend-course (גרירה עם ⌥ Option). אם התיקייה כבר שם מהעתקה קודמת ואתה רוצה לשמור את מה שכתבת — בחר Keep Both / Stop ולא Replace.

✔ בדיקה: cd ~/dev/backend-course && npm install && npm run check P26.3-E06 ← הבודק יוצר bucket ב־LocalStack ונכשל על הקובץ הריק. ECONNREFUSED 127.0.0.1:4566 — הקונטיינר לא רץ.

🎯 בסוף הפרק תדע
  • להכיר את המפה של AWS: מה רץ איפה (EKS/ECS, RDS, ElastiCache, S3, SQS, CloudFront) — ומה מקביל למה שכבר בנית.
  • IAM: users, roles ו־policies, least privilege, וסדר ההחלטה Allow/Deny — ולכתוב policy שעוברת בדיקה.
  • S3 מ־Node.js עם AWS SDK v3: JSON, pagination, וכתובות חתומות להעלאה ישירה — מול LocalStack.
  • Kubernetes: Pod, Deployment, Service, ConfigMap, Secret, Ingress, Job, HPA — probes, resources ו־rolling update.
  • Helm ו־GitOps עם Argo CD, ו־CI ב־Jenkins: הדרך של image מ־commit ועד cluster.

🤔 למה צריך את זה?

בפרק 25 העלית את פרויקט 2 ל־Render: לוחצים, והשרת רץ. ככה עובדים הרבה סטארטאפים בהתחלה. אבל כשמודעת דרושים כותבת "AWS, Kubernetes (EKS), Jenkins, Argo CD" — היא מתארת חברה עם עשרות שירותים, מאות pods ותנועה גבוהה, שבה הפלטפורמה לא "קסם" אלא קוד: YAML ב־Git, pipelines, והרשאות מדויקות. ג׳וניור Backend לא מקים את ה־cluster לבד — אבל הוא כותב את ה־Deployment של השירות שלו, מבין למה ה־pod לא Ready, מבקש הרשאת IAM מדויקת, ומעדכן גרסה דרך pull request ל־repo התצורה. את כל זה נעשה כאן — עם AWS אמיתי־למחצה (LocalStack) ובודקים שקוראים את ה־manifests כמו ש־Kubernetes קורא.

🏁 מבחן מעבר

  • לבחור שירות AWS לכל רכיב של המערכת, ולהסביר role מול access key.
  • לכתוב IAM policy מצומצמת, ולהסביר למה Deny מפורש מנצח.
  • לעבוד עם S3 מ־Node.js: JSON, pagination, וכתובת חתומה להעלאה.
  • לכתוב Deployment, Service, ConfigMap, Ingress ו־HPA — ולהסביר readiness מול liveness ו־requests מול limits.
  • להסביר את הדרך של שינוי מ־commit, דרך Jenkins ו־repo התצורה, עד rolling update ב־Argo CD.
