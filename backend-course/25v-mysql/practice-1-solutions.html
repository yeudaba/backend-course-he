P25.5-E01 · מילון PostgreSQL ← MySQL 🧠 הבנה רמה 1

💡 רמז 1

רוב השפה זהה: SELECT, JOIN, GROUP BY, CTE, window functions (מ־8.0), CHECK (נאכף מ־8.0.16).

💡 רמז 2

שלושה מהם "קיימים, אבל עושים משהו אחר".

✅ פתרון
  1. INT UNSIGNED AUTO_INCREMENT PRIMARY KEY.
  2. אין RETURNING. ה־driver מחזיר insertId (mysql2), או SELECT LAST_INSERT_ID() באותו חיבור.
  3. INSERT … AS new ON DUPLICATE KEY UPDATE col = new.col — על כל מפתח ייחודי בטבלה, לא על אחד שבוחרים (E08).
  4. מלכודת: || ב־MySQL הוא OR לוגי — 'a' || 'b' מחזיר 0. חיבור מחרוזות: CONCAT('a', 'b').
  5. אין ILIKE. אבל ברירת המחדל (utf8mb4_0900_ai_ci) כבר לא רגישה לרישיות ולסימנים — LIKE מספיק. לרגישות: COLLATE utf8mb4_bin.
  6. BOOLEAN הוא TINYINT(1) (חוזר כ־0/1); JSON (בינארי, דומה ל־jsonb); DATETIME(3) בלי אזור זמן — שומרים UTC בעצמך, או TIMESTAMP (ממיר לפי אזור הזמן של החיבור, טווח עד 2038).
  7. אין. ROW_NUMBER() OVER (PARTITION BY …) בתת־שאילתה (E07, E20).
  8. אין. LEFT JOIN … UNION … RIGHT JOIN.
  9. ? (mysql2: execute(sql, [a, b])).
⚠️ טעויות נפוצות
  • להעתיק שאילתה מ־PostgreSQL ולהאמין לה כי "לא הייתה שגיאה". || לא זורק — הוא מחזיר 0 בשקט.

P25.5-E02 · קולציה: מה שווה למה? 🧠 הבנה רמה 1

💡 רמז 1

ai = accent-insensitive, ci = case-insensitive. וקולציות 0900 הן NO PAD — רווח בסוף נחשב.

💡 רמז 2

השוואה בין שתי מחרוזות מילוליות משתמשת בקולציה של החיבור, לא של טבלה.

✅ פתרון
  1. 0 — הרווח בסוף נחשב (NO PAD).
  2. 1 — Café ו־cafe שווים: בלי רישיות ובלי ניקוד.
  3. Duplicate entry 'DANA@x.com' — ה־UNIQUE משתמש באותה קולציה. ל־email זה בדיוק מה שרוצים (ב־PostgreSQL היינו צריכים lower(email)).
  4. מדדתי: ב־mysql2 החיבור הוא utf8mb4_unicode_ci ← 1; ב־mysql CLI בקונטיינר הוא latin1_swedish_ci ← 0. אותה שאילתה, תשובות שונות — לכן משווים מול עמודות, וקובעים charset בחיבור במפורש.
  5. בעיה: abc ו־ABC שווים — מפתח "כמעט נכון" עובר. לעמודות כאלה: VARBINARY או COLLATE utf8mb4_bin (ועדיף לשמור hash ולא את המפתח).
⚠️ טעויות נפוצות
  • להניח שההתנהגות זהה ל־PostgreSQL (שם ההשוואה רגישה לרישיות ולניקוד) — ולגלות כפילויות "דנה"/"DANA" רק בפרודקשן.

P25.5-E04 · DATETIME או TIMESTAMP? 🧠 הבנה רמה 1

💡 רמז 1

TIMESTAMP נשמר ב־UTC ומומר לפי time_zone של החיבור; טווח 1970–2038.

💡 רמז 2

DATETIME נשמר כמו שהוא — "שעון על הקיר", בלי אזור זמן.

✅ פתרון
  1. DATETIME(3) שבו האפליקציה תמיד כותבת UTC (ומתעדים את זה). TIMESTAMP אפשרי, אבל ההמרה לפי החיבור היא מקור לבאגים כשחיבורים מוגדרים שונה — והטווח נגמר ב־2038.
  2. DATE — אין שעה, ו־TIMESTAMP לא מגיע לפני 1970 (E23).
  3. DATETIME — TIMESTAMP לא מגיע ל־2040.
  4. DATE — יום מקומי, לא רגע (פרק 24: "רגע" מול "תאריך").
⚠️ טעויות נפוצות
  • לערבב: חלק מהקוד כותב UTC וחלק שעון ישראל, לאותה עמודה. החלטה אחת, בתיעוד, ובדיקה.

P25.5-E29 · למה המפתח הזר לא נוצר? 🧠 הבנה רמה 2

💡 רמז 1

‏INT ו־INT UNSIGNED — אותו גודל, טווחים שונים.

💡 רמז 2

האם יש UNSIGNED ב־PostgreSQL?

✅ פתרון
CREATE TABLE authors (id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY, name VARCHAR(100) NOT NULL);
CREATE TABLE books (
  id INT AUTO_INCREMENT PRIMARY KEY,
  author_id INT NOT NULL,
  FOREIGN KEY (author_id) REFERENCES authors (id)
);
CREATE TABLE books (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  author_id INT UNSIGNED NOT NULL,
  FOREIGN KEY (author_id) REFERENCES authors (id)
);
SELECT 'ok' AS created;
ERROR 3780 (HY000): Referencing column 'author_id' and referenced column 'id' in foreign key constraint 'books_ibfk_1' are incompatible.
+---------+
| created |
+---------+
| ok      |
+---------+
  1. המפתח הזר והעמודה שהוא מצביע עליה חייבים להיות בדיוק אותו טיפוס — כולל UNSIGNED. ‏INT מול INT UNSIGNED — לא תואמים.
  2. author_id INT UNSIGNED (ובדרך כלל גם ה־id של books — לעקביות).
  3. ב־PostgreSQL אין UNSIGNED — יש integer אחד, אז אין במה לטעות. (ומגבלה של "לא שלילי" עושים שם עם CHECK.)
⚠️ טעויות נפוצות
  • "לתקן" עם SET FOREIGN_KEY_CHECKS = 0 — הטבלה נוצרת, והמסד לא שומר על שום קשר.

P25.5-E30 · ‏utf8mb3 בטבלה ישנה 🧠 הבנה רמה 2

💡 רמז 1

‏information_schema.COLUMNS — יש בו CHARACTER_SET_NAME לכל עמודה.

💡 רמז 2

utf8mb4 = עד 4 בתים לתו. ‏255 × 4 = ?

✅ פתרון
  1. הטבלה (או העמודה) ב־utf8 הישן = utf8mb3: ‏🔥 הוא 4 בתים ונדחה (‏Incorrect string value).
  2. שאילתה אחת:
SELECT TABLE_NAME, COLUMN_NAME, CHARACTER_SET_NAME
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = DATABASE() AND CHARACTER_SET_NAME = 'utf8mb3';
  1. ALTER TABLE reviews CONVERT TO CHARACTER SET utf8mb4 (עם הקולציה הרצויה; בונה את הטבלה מחדש — בטבלה גדולה זה זמן, ונועל). גם החיבור: אם ה־driver מתחבר ב־utf8mb3, התו נפגם בדרך — ב־mysql2 ברירת המחדל היא utf8mb4.
  2. באינדקסים ישנים (‏InnoDB עם row format ישן) — מגבלה של 767 בתים למפתח. ‏VARCHAR(255) ב־utf8mb4 = עד 1020 בתים. ב־8.x עם DYNAMIC ‏(ברירת מחדל) המגבלה 3072, ובדרך כלל זה עובר.
⚠️ טעויות נפוצות
  • לשנות רק את ה־database (ALTER DATABASE … CHARACTER SET utf8mb4) — זה משפיע רק על טבלאות חדשות.

P25.5-E31 · השוואות שקטות — נבא 🧠 הבנה רמה 2

💡 רמז 1

הקולציה של MySQL 8 היא NO PAD — רווח בסוף הוא תו.

💡 רמז 2

‏<=> הוא "שווה, גם ל־NULL".

✅ פתרון
SELECT 'abc' = 'abc ' AS trailing_space,
       'Ä' = 'a' AS umlaut,
       'Ö' = 'o' COLLATE utf8mb4_bin AS umlaut_bin,
       1 = '1abc' AS num_vs_text,
       NULL = NULL AS null_eq,
       NULL <=> NULL AS null_safe;
+----------------+--------+------------+-------------+---------+-----------+
| trailing_space | umlaut | umlaut_bin | num_vs_text | null_eq | null_safe |
+----------------+--------+------------+-------------+---------+-----------+
|              0 |      1 |          0 |           1 |    NULL |         1 |
+----------------+--------+------------+-------------+---------+-----------+
  • trailing_space — ב־utf8mb4_0900_ai_ci (‏NO PAD) רווח בסוף נחשב. (בקולציות הישנות, ‏PAD SPACE — הוא לא היה נחשב.)
  • umlaut — ‏ai = accent-insensitive: ‏Ä שווה ל־a. ‏umlaut_bin — בקולציה בינארית, לא.
  • num_vs_text — ‏'1abc' מומר למספר 1 (עם warning) — ההשוואה "מצליחה". זו שהייתי רוצה כשגיאה: ב־PostgreSQL היא שגיאה.
  • null_eq — NULL (לא ידוע), כמו ב־PostgreSQL. ‏<=> הוא המקבילה של IS NOT DISTINCT FROM.
⚠️ טעויות נפוצות
  • להשוות מזהה שמגיע מ־URL (מחרוזת) לעמודה מספרית ולסמוך על זה — '7abc' מוצא את רשומה 7.

P25.5-E06 · טבלה ב־MySQL 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הטיפוס של מפתח זר חייב להיות זהה בדיוק לעמודה שהוא מצביע עליה — כולל UNSIGNED.

💡 רמז 2

DEFAULT CHARSET=utf8mb4 בסוף ה־CREATE TABLE.

✅ פתרון
-- P25.5-E06
-- טבלת ביקורות ב־MySQL: מפתח AUTO_INCREMENT, utf8mb4 (אמוג׳י!), CHECK שנאכף (מ־8.0.16), מפתחות זרים,
-- ייחודיות "ביקורת אחת למוצר ללקוח", ואינדקס לשאילתה הנפוצה (הביקורות של מוצר, מהחדשה)
CREATE TABLE reviews (
  id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  product_id  INT UNSIGNED NOT NULL,
  customer_id INT UNSIGNED NOT NULL,
  rating      TINYINT UNSIGNED NOT NULL,
  body        TEXT NOT NULL,
  created_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  CONSTRAINT fk_reviews_product FOREIGN KEY (product_id) REFERENCES products (id),
  CONSTRAINT fk_reviews_customer FOREIGN KEY (customer_id) REFERENCES customers (id),
  CONSTRAINT chk_reviews_rating CHECK (rating BETWEEN 1 AND 5),
  UNIQUE KEY uq_reviews_product_customer (product_id, customer_id),
  KEY idx_reviews_product_created (product_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
⚠️ טעויות נפוצות
  • product_id INT כש־products.id הוא INT UNSIGNED ← Referencing column and referenced column are incompatible.

P25.5-E23 · טבלה — שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

utf8 ב־MySQL הוא utf8mb3 — עד 3 בתים לתו. ☕ נכנס (3 בתים); 🔥 לא (4).

💡 רמז 2

FLOAT לכסף? TIMESTAMP לתאריך לידה?

✅ פתרון
-- P25.5-E23
-- תקלה 1: CHARSET utf8 ב־MySQL הוא utf8mb3 — 3 בתים לתו, ואמוג׳י (4 בתים) נכשל ← utf8mb4
-- תקלה 2: FLOAT לכסף ← 89.90 נשמר כ־89.9000015…; DECIMAL(10,2) מדויק
-- תקלה 3: TIMESTAMP לתאריך לידה ← טווח 1970–2038 בלבד; תאריך בלי שעה — DATE
CREATE TABLE members (
  id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name       VARCHAR(100) NOT NULL,
  bio        TEXT NOT NULL,
  balance    DECIMAL(10, 2) NOT NULL DEFAULT 0,
  birth_date DATE NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
⚠️ טעויות נפוצות
  • לשנות רק את הטבלה ל־utf8mb4 ולשכוח את החיבור — ב־mysql2 הוא utf8mb4 כברירת מחדל, אבל בכלים ישנים צריך charset=utf8mb4 גם שם.

P25.5-E32 · טבלת קודי הנחה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

קולציה לעמודה אחת: code VARCHAR(20) COLLATE utf8mb4_0900_bin NOT NULL.

💡 רמז 2

‏product_id חייב להיות INT UNSIGNED — כמו products.id (E29).

✅ פתרון
-- P25.5-E32: טבלת קודי הנחה
CREATE TABLE promo_codes (
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  code        VARCHAR(20) COLLATE utf8mb4_0900_bin NOT NULL,
  percent     TINYINT UNSIGNED NOT NULL,
  uses_left   INT UNSIGNED NOT NULL DEFAULT 1,
  valid_until DATE NULL,
  product_id  INT UNSIGNED NULL,
  UNIQUE KEY uq_promo_codes_code (code),
  CONSTRAINT chk_promo_percent CHECK (percent BETWEEN 1 AND 90),
  CONSTRAINT fk_promo_product FOREIGN KEY (product_id) REFERENCES products (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

‏UNSIGNED על uses_left עושה את עבודת ה־"לא שלילי": במצב STRICT, ‏-1 נדחה עם "Out of range". וה־UNIQUE "יורש" את הקולציה של העמודה — לכן הוא רגיש לרישיות.

⚠️ טעויות נפוצות
  • להשאיר את code בקולציה של הטבלה — ואז save10 נדחה כ"כפול" של SAVE10 (והקוד של לקוח אחר "תפוס").

P25.5-E33 · מחיר עם מע״מ, וקרטונים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

ב־MySQL ‏/ מחזיר עשרוני גם בין שלמים. חילוק שלם — DIV; שארית — MOD (או %).

💡 רמז 2

ROUND(price * 1.18, 2). ‏price הוא DECIMAL, אז החישוב מדויק.

✅ פתרון
-- P25.5-E33: מחיר עם מע״מ, וקרטונים
SELECT name, price, ROUND(price * 1.18, 2) AS price_with_vat,
       stock DIV 6 AS full_boxes, stock MOD 6 AS loose
FROM products
WHERE category = 'beans'
ORDER BY price DESC;
+--------------------+-------+----------------+------------+-------+
| name               | price | price_with_vat | full_boxes | loose |
+--------------------+-------+----------------+------------+-------+
| Ethiopia Beans 1kg | 89.90 |         106.08 |          6 |     4 |
| Colombia Beans 1kg | 84.90 |         100.18 |          0 |     0 |
| Brazil Beans 250g  | 29.90 |          35.28 |         20 |     0 |
+--------------------+-------+----------------+------------+-------+
⚠️ טעויות נפוצות
  • FLOOR(stock / 6) — עובד, אבל DIV אומר בדיוק מה שהתכוונת. ו־stock / 6 לבד מחזיר 6.6667.

P25.5-E34 · שורת משלוח — CONCAT ו־GROUP_CONCAT 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏|| הוא OR ב־MySQL (שיעור 1). שרשור: CONCAT(a, b, c).

💡 רמז 2

‏GROUP_CONCAT(expr ORDER BY … SEPARATOR ', ') — המקבילה של string_agg.

✅ פתרון
-- P25.5-E34: שורת משלוח
SELECT o.id,
       CONCAT('#', o.id, ' · ', c.name, ' · ', c.city) AS line,
       GROUP_CONCAT(CONCAT(oi.quantity, '× ', p.name) ORDER BY p.name SEPARATOR ', ') AS items
FROM orders o
JOIN customers c ON c.id = o.customer_id
JOIN order_items oi ON oi.order_id = o.id
JOIN products p ON p.id = oi.product_id
WHERE o.status IN ('paid', 'shipped')
GROUP BY o.id
ORDER BY o.id;
+----+-------------------------------+------------------------------------------+
| id | line                          | items                                    |
+----+-------------------------------+------------------------------------------+
|  1 | #1 · Dana Levi · Haifa        | 1× Ethiopia Beans 1kg, 1× Hand Grinder   |
|  2 | #2 · Yossi Cohen · Tel Aviv   | 1× Electric Grinder Pro                  |
|  4 | #4 · Noa Mizrahi · Tel Aviv   | 2× French Press 1L                       |
|  5 | #5 · Avi Peretz · Jerusalem   | 1× French Press 1L                       |
+----+-------------------------------+------------------------------------------+

‏c.name ו־c.city לא ב־GROUP BY, ובכל זאת אין error 1055: ‏MySQL מבין ש־o.id (מפתח ראשי) קובע את o.customer_id, ו־c.id = o.customer_id קובע את כל השורה של הלקוח.

⚠️ טעויות נפוצות
  • '#' || o.id — מחזיר 0 או 1 (OR לוגי), בלי שגיאה.
  • ‏GROUP_CONCAT חותך בשקט ב־1024 תווים (‏group_concat_max_len) — בדוחות עם הרבה פריטים, להגדיל.

P25.5-E35 · קוד קופון — בדיוק או בערך? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏code = 'save10' כביטוי ב־SELECT מחזיר 1 או 0.

💡 רמז 2

code = 'save10' COLLATE utf8mb4_0900_bin — בינארי, ו־NO PAD (רווח בסוף נחשב).

✅ פתרון
-- P25.5-E35: קוד קופון — בדיוק או בערך?
SELECT code, discount,
       code = 'save10' AS ci_match,
       code = 'save10' COLLATE utf8mb4_0900_bin AS exact_match
FROM coupons
ORDER BY id;
+--------+----------+----------+-------------+
| code   | discount | ci_match | exact_match |
+--------+----------+----------+-------------+
| SAVE10 |       10 |        1 |           0 |
| save10 |       15 |        1 |           1 |
| Save10 |       20 |        1 |           0 |
| SAVE20 |       20 |        0 |           0 |
| Café   |        5 |        0 |           0 |
| CAFE   |        7 |        0 |           0 |
+--------+----------+----------+-------------+

באפליקציה, קוד קופון שהמשתמש מקליד — כדאי דווקא לא רגיש לרישיות (נוח). אבל אז גם ה־UNIQUE צריך להיות לא רגיש, כדי שלא יהיו שני קודים שמתנגשים. טוקנים, מזהים אקראיים ו־hashes — תמיד בינארי.

ולמה utf8mb4_0900_bin ולא utf8mb4_bin הוותיק? הוותיק הוא PAD SPACE: בו 'save10 ' (עם רווח בסוף) "שווה" ל־'save10'. הבודק מוסיף קופון כזה.

⚠️ טעויות נפוצות
  • BINARY code = 'save10' — עובד, אבל מיושן (deprecated מ־8.0.27). ‏COLLATE ברור יותר.

P25.5-E36 · ‏DATETIME מול TIMESTAMP — בפועל 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

SET time_zone = '+02:00'; — משפיע על החיבור הנוכחי בלבד.

💡 רמז 2

‏TIMESTAMP ממיר מאזור החיבור ל־UTC בכתיבה, ובחזרה בקריאה. ‏DATETIME — שומר את מה שכתבת, כמו שהוא.

✅ פתרון
-- P25.5-E36: DATETIME מול TIMESTAMP
SET time_zone = '+00:00';
INSERT INTO events (name, at_datetime, at_timestamp) VALUES ('launch', '2026-11-04 22:30:00', '2026-11-04 22:30:00');
SET time_zone = '+02:00';
INSERT INTO events (name, at_datetime, at_timestamp) VALUES ('israel', '2026-11-05 00:30:00', '2026-11-05 00:30:00');
SET time_zone = '+00:00';
SELECT name, at_datetime, at_timestamp FROM events ORDER BY id;
+--------+---------------------+---------------------+
| name   | at_datetime         | at_timestamp        |

P25.5-E28 · שאילתה מ־PostgreSQL ל־MySQL 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הטריק: regex אחד עם שלוש חלופות, ו־replace עם פונקציה. החלופה של המחרוזת באה ראשונה: ‏/'(?:[^']|'')*'|"([^"]+)"|\$(\d+)/g. ה־regex סורק משמאל לימין, וכשהוא פוגש ' הוא "בולע" את כל המחרוזת. כך $1 שבתוכה לא נתפס בנפרד.

💡 רמז 2

הפונקציה מקבלת (match, name, n) — קבוצה 1 וקבוצה 2. אם name !== undefined ← backticks. אם n !== undefined ← out.push(params[Number(n) - 1]) ומחזירים "?". אחרת זו מחרוזת ← return match.

✅ פתרון
// P25.5-E28 — שאילתה מ־PostgreSQL ל־MySQL: placeholders ושמות
export function pgToMysql(sql: string, params: unknown[]): { sql: string; params: unknown[] } {
  const out: unknown[] = [];
  // מחרוזת '...' (עם '' בפנים) — כמו שהיא; "שם" ← `שם`; $n ← ?
  const converted = sql.replace(/'(?:[^']|'')*'|"([^"]+)"|\$(\d+)/g, (match, name, n) => {
    if (name !== undefined) return `\`${name}\``;
    if (n !== undefined) {
      const i = Number(n);
      if (i < 1 || i > params.length) throw new RangeError(`$${n} — אין פרמטר כזה (יש ${params.length})`);
      out.push(params[i - 1]);
      return "?";
    }
    return match;
  });
  return { sql: converted, params: out };
}

  pgToMysql("SELECT $3", [1, 2]);
} catch (err) {

ב־PostgreSQL ‏$2 הוא "הפרמטר השני", בכל מקום שהוא מופיע. ב־MySQL כל ? הוא "הפרמטר הבא". לכן ההמרה צריכה לבנות מערך חדש לפי סדר ההופעה, ו־$2 שמופיע פעמיים נכנס פעמיים.

הסדר של החלופות ב־regex הוא מה שעושה את העבודה. ה־regex לא "יודע" שהוא בתוך מחרוזת. הוא פשוט פוגש קודם את הגרש הפותח, ומתאים את כל המחרוזת כחתיכה אחת. זה אותו רעיון כמו ה־TOKENS ב־_ts.mjs של הבודקים, שמוריד הערות בלי לגעת במחרוזות.

ההמרה הזו מכסה את ההבדלים התחביריים בלבד. ‏ILIKE, ‏RETURNING ו־::int צריכים שינוי ידני (שיעור 1).

⚠️ טעויות נפוצות
  • sql.replace(/\$\d+/g, "?") ושמירת params כמו שהם — ‏$2 ... $1 מחליף בין הערכים, ו־$2 כפול חסר.
  • בלי חלופה למחרוזות — 'cost: $1' הופך ל־'cost: ?', נוסף פרמטר מיותר, ו־MySQL נכשל (או, גרוע יותר, מקבל ערך במקום הלא נכון).
  • /\$(\d)/ — ‏$10 נקרא כ־$1 ואחריו 0.
  • להחליף " גם בתוך מחרוזות — הטקסט 'say "hi"' שנשמר במסד משתנה.

// P25.5-E42: יכנס לעמודה? תווים, בתים ו־utf8mb3
export function mysqlLength(value: string) {
  return { chars: [...value].length, bytes: Buffer.byteLength(value, "utf8") };
}

export function columnProblems(value: string, { maxChars, charset }: { maxChars: number; charset: "utf8mb3" | "utf8mb4" }): string[] {
  const problems: string[] = [];
  if (mysqlLength(value).chars > maxChars) problems.push("too-long");
  if (charset === "utf8mb3" && [...value].some((c) => c.codePointAt(0)! > 0xffff)) problems.push("needs-utf8mb4");
  return problems;
}
