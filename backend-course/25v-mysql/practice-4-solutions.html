P25.5-E05 · מה mysql2 מחזיר? 🧠 הבנה רמה 1

💡 רמז 1

DECIMAL יכול להיות מדויק יותר מ־number של JavaScript — אז mysql2 לא ממיר אותו.

💡 רמז 2

affectedRows — שורות שהתאימו; changedRows — שורות שהערך בהן השתנה.

✅ פתרון
import mysql from "mysql2/promise";

const admin = await mysql.createConnection(process.env.MYSQL_URL ?? "mysql://root:course@localhost:3306");
await admin.query("CREATE DATABASE IF NOT EXISTS e05_demo");
const conn = await mysql.createConnection({ uri: process.env.MYSQL_URL ?? "mysql://root:course@localhost:3306", database: "e05_demo" });
await conn.query("CREATE TABLE IF NOT EXISTS t (id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(10))");
await conn.query("TRUNCATE t");

const [rows] = await conn.query<any[]>("SELECT CAST(89.90 AS DECIMAL(10,2)) AS price, TRUE AS flag, CAST('{\"a\":1}' AS JSON) AS doc, COUNT(*) AS n, CAST('2026-03-01 10:00:00' AS DATETIME) AS at FROM DUAL");
for (const [k, v] of Object.entries(rows[0])) console.log(k, typeof v, v instanceof Date ? "Date" : JSON.stringify(v));
const [ins] = await conn.query<any>("INSERT INTO t (name) VALUES ('a'), ('b')");
console.log("insert:", ins.insertId, ins.affectedRows);
const [upd] = await conn.query<any>("UPDATE t SET name = 'a' WHERE id IN (1, 2)");

await conn.end();
await admin.query("DROP DATABASE e05_demo");
await admin.end();

n number 1

insert: 1 2
update: 2 1
  • DECIMAL ← מחרוזת. סכום של מחרוזות הוא שרשור (E21). או decimalNumbers: true בחיבור (מאבד דיוק מעל 15 ספרות), או המרה במקום אחד (E10).
  • TRUE ← 1: אין boolean ב־MySQL.
  • COUNT(*) ← number (BIGINT קטן). JSON ← אובייקט.
  • DATETIME ← Date — ומפורש לפי אזור הזמן של התהליך (בשרת שמוגדר לישראל — שעתיים הפרש). dateStrings: true או timezone: "Z" בחיבור — החלטה אחת לכל האפליקציה.
  • insertId — ה־id של השורה הראשונה ב־INSERT מרובה. changedRows = 1 — רק שורה 2 השתנתה ('b' ← 'a'); affectedRows = 2.
⚠️ טעויות נפוצות
  • insertId של INSERT עם כמה שורות כ"ה־id של האחרונה" — הוא של הראשונה; השאר עוקבים (ברוב ההגדרות), אבל עדיף לא להסתמך.

P25.5-E70 · ‏execute או query? 🧠 הבנה רמה 2

💡 רמז 1

‏execute = prepared statement: ה־SQL נשלח פעם אחת, והערכים בנפרד. ‏query = mysql2 מרכיב את הטקסט המלא בצד שלך (עם escaping).

💡 רמז 2

ב־prepared statement כל ? הוא ערך אחד בדיוק.

✅ פתרון
  1. execute — השרת מפרסר פעם אחת (mysql2 שומר את ה־statement לחיבור), והערך לעולם לא מתפרש כ־SQL.
  2. query — רק הוא פורש מערך ל־1, 2, 3. ב־execute צריך לבנות ?, ?, ? בעצמך (E76).
  3. query עם multipleStatements: true בחיבור (וזהירות: זה גם פותח את הדלת להזרקה של כמה פקודות — רק לחיבור של ה־migrations).
  4. query — ‏VALUES ? עם מערך של מערכים הוא תכונה של ה־escaping בצד הלקוח.
  5. אף אחד מהם לא עוזר — שם טבלה לא יכול להיות פרמטר. רשימה סגורה (if (!["a", "b"].includes(table)) throw), או mysql.escapeId(table). לעולם לא קלט ישיר (E82).
⚠️ טעויות נפוצות
  • "execute תמיד בטוח יותר" — שניהם בטוחים מהזרקה דרך ערכים אם משתמשים ב־?. ההזרקה מגיעה משרשור.

P25.5-E71 · ‏affectedRows מול changedRows 🧠 הבנה רמה 2

💡 רמז 1

‏affected = כמה שורות התאימו ל־WHERE (כשה־driver מבקש "found rows", כמו mysql2). ‏changed = כמה באמת השתנו.

💡 רמז 2

להזמנה 2 כבר יש shipped.

✅ פתרון
import mysql from "mysql2/promise";
const url = process.env.MYSQL_URL ?? "mysql://root:course@localhost:3306";
const c = await mysql.createConnection({ uri: url, multipleStatements: true });
await c.query("CREATE DATABASE IF NOT EXISTS e71; USE e71; CREATE TABLE IF NOT EXISTS orders (id INT PRIMARY KEY, status VARCHAR(20)); REPLACE INTO orders VALUES (1, 'paid'), (2, 'shipped')");
for (const id of [1, 2, 3]) {
  const [r] = await c.query("UPDATE orders SET status = 'shipped' WHERE id = ?", [id]);
  console.log(id, "affected:", r.affectedRows, "changed:", r.changedRows);
}
await c.query("DROP DATABASE e71");
await c.end();
1 affected: 1 changed: 1
2 affected: 1 changed: 0
3 affected: 0 changed: 0

1 — נמצאה ושונתה. 2 — נמצאה, לא שונתה (כבר shipped). 3 — לא נמצאה. עם changedRows === 1 בתור "הצליח", שליחה חוזרת של "סמן כנשלח" מחזירה כישלון — למרות שהמצב בדיוק מה שהלקוח רצה. ל"האם קיים" — ‏affectedRows; ל"האם שיניתי" — ‏changedRows (E77).

⚠️ טעויות נפוצות
  • להעביר קוד מ־driver אחר (או עם הגדרה אחרת של flags) ולהניח שאותו מספר אומר אותו דבר — ב־MySQL זה תלוי בהגדרת החיבור.

P25.5-E73 · ‏pool בלי release 🧠 הבנה רמה 2

💡 רמז 1

מה קורה ל־conn כש־OutOfStock נזרק?

💡 רמז 2

‏connectionLimit — ברירת מחדל 10.

✅ פתרון
  1. כל פעם שהמלאי חסר — throw לפני ה־release. החיבור לא חוזר ל־pool. אחרי 10 כאלה (‏connectionLimit) אין חיבורים פנויים, ו־getConnection מחכה לנצח (ברירת מחדל: אין timeout בתור).
  2. מלאי חסר הוא מקרה נדיר — צריך 10 כאלה מאז ה־restart האחרון.
  3. ‏try (… commit) ‏catch (rollback ו־throw) ‏finally (release) — שיעור 4, איור 1.
  4. טרנזקציה פתוחה עם FOR UPDATE: השורה של המוצר נעולה. כל מי שינסה לקנות אותו מוצר יחכה ל־lock wait timeout (‏50 שניות) — גם מחיבורים אחרים, גם אחרי restart של חלק מהשרתים.
⚠️ טעויות נפוצות
  • להגדיל את connectionLimit ל־100 — זה רק דוחה את התקיעה, ותופס חיבורים של המסד.

P25.5-E74 · ‏timezone: "Z" או dateStrings? 🧠 הבנה רמה 2

💡 רמז 1

בלי הגדרה, mysql2 מפרש DATETIME כשעון מקומי של התהליך.

💡 רמז 2

‏dateStrings אפשר להגדיר גם רק לטיפוסים מסוימים: dateStrings: ["DATE"].

✅ פתרון
  1. Date של 2026-11-04T20:30:00.000Z — שעתיים "אחורה": ה־22:30 פורש כשעון ישראל.
  2. Date של 2026-11-04T22:30:00.000Z — נכון.
  3. המחרוזת "2026-11-04 22:30:00.000" — בלי פרשנות; האפליקציה אחראית.

DATE: בלי הגדרה — ‏Date של חצות מקומי (‏2026-11-04T22:00:00.000Z — "4 בנובמבר" ב־UTC!). עם "Z" — חצות UTC (עובד, עד שמישהו מציג אותו באזור אחר). עם dateStrings — "2026-11-05": בדיוק תאריך מקומי (פרק 24), בלי רגע. לכן: timezone: "Z" ו־dateStrings: ["DATE"].

⚠️ טעויות נפוצות
  • לבדוק רק במחשב שבו התהליך ב־UTC (CI, Docker) — ואז הבאג מופיע רק אצל מפתח שמריץ מקומית, או להפך.

P25.5-E09 · הזמנה בטרנזקציה עם mysql2 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

const conn = await pool.getConnection(); beginTransaction / commit / rollback; finally { conn.release() }.

💡 רמז 2

אין RETURNING: const [res] = await conn.execute(…) ואז res.insertId. ו־INSERT מרובה: conn.query("… VALUES ?", [rows]).

✅ פתרון
// P25.5-E09
import type { Pool } from "mysql2/promise";

export class OutOfStock extends Error {}

// הזמנה בטרנזקציה ב־mysql2: חיבור אחד מה־pool לכל הטרנזקציה (getConnection), ו־release בכל מקרה.
// execute = prepared statement עם ? — אף פעם לא שרשור מחרוזות. ואין RETURNING: את ה־id נותן insertId
export async function insertOrder(pool: Pool, order: { customerId: number; items: { productId: number; quantity: number }[] }) {
  const conn = await pool.getConnection();
  try {
    await conn.beginTransaction();
    const ids = order.items.map((i) => i.productId).sort((a, b) => a - b); // נועלים תמיד באותו סדר — פחות deadlocks
    const [rows] = await conn.query<any[]>("SELECT id, price, stock FROM products WHERE id IN (?) ORDER BY id FOR UPDATE", [ids]);
    const byId = new Map(rows.map((r) => [r.id, r]));
    let totalCents = 0;
    for (const item of order.items) {
      const p = byId.get(item.productId);
      if (!p || p.stock < item.quantity) throw new OutOfStock(`אין מספיק מלאי למוצר ${item.productId}`);
      totalCents += Math.round(Number(p.price) * 100) * item.quantity;
    }
    const [res] = await conn.execute<any>("INSERT INTO orders (customer_id, status, total) VALUES (?, 'pending_payment', ?)", [order.customerId, (totalCents / 100).toFixed(2)]);
    const orderId: number = res.insertId;
    await conn.query("INSERT INTO order_items (order_id, product_id, quantity, unit_price) VALUES ?", [
      order.items.map((i) => [orderId, i.productId, i.quantity, byId.get(i.productId).price]),
    ]);
    for (const item of order.items) {
      await conn.execute("UPDATE products SET stock = stock - ? WHERE id = ?", [item.quantity, item.productId]);
    }
    await conn.commit();
    return { orderId, totalCents };
  } catch (err) {
    await conn.rollback();
    throw err;
  } finally {
    conn.release();
  }
}
⚠️ טעויות נפוצות
  • pool.query("START TRANSACTION") ואז pool.query(…) — כל קריאה ל־pool יכולה לקבל חיבור אחר. טרנזקציה חיה על חיבור אחד.

P25.5-E10 · טיפוסים מ־mysql2 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

Math.round(Number("89.90") * 100) — round, כי 89.9 × 100 = 8990.000000000001.

💡 רמז 2

E05 מראה בדיוק מה חוזר.

✅ פתרון
// P25.5-E10
import type { Connection } from "mysql2/promise";

export interface Product {
  id: number;
  name: string;
  priceCents: number;
  isActive: boolean;
  attributes: Record<string, unknown> | null;
}

// mysql2 בברירת מחדל: DECIMAL ← מחרוזת ("89.90" — כדי לא לאבד דיוק), BOOLEAN (TINYINT(1)) ← 0/1,
// JSON ← אובייקט מפוענח. ממירים פעם אחת, במקום אחד, לטיפוסים של האפליקציה
export function toProduct(row: { id: number; name: string; price: string | number; is_active: number | boolean; attributes: unknown }): Product {
  const priceCents = Math.round(Number(row.price) * 100); // 89.9 * 100 = 8990.000000000001 — לכן round
  return {
    id: row.id,
    name: row.name,
    priceCents,
    isActive: row.is_active === 1 || row.is_active === true,
    attributes: typeof row.attributes === "string" ? JSON.parse(row.attributes) : ((row.attributes as Record<string, unknown> | null) ?? null),
  };
}

export async function listProducts(conn: Connection, category: string): Promise<Product[]> {
  const [rows] = await conn.execute<any[]>("SELECT id, name, price, is_active, attributes FROM products WHERE category = ? ORDER BY id", [category]);
  return rows.map(toProduct);
}
⚠️ טעויות נפוצות
  • להפעיל decimalNumbers: true "וזהו" — מעל 15 ספרות משמעותיות מאבדים דיוק בשקט. לכסף — אגורות כמספר שלם, או מחרוזת עד הרגע האחרון.

💡 רמז 2

✅ פתרון
// P25.5-E21
import type { Connection } from "mysql2/promise";

export async function dailyReport(conn: Connection, day: string) {
  const [rows] = await conn.execute<any[]>(
    "SELECT total FROM orders WHERE status IN ('paid', 'shipped') AND created_at >= ? AND created_at < ? + INTERVAL 1 DAY",
    [day, day],
  );
  // תקלה 1: היה rows.reduce((s, r) => s + r.total, 0) ← total הוא מחרוזת ("89.90"), והתוצאה "089.90119.00"
  const cents = rows.reduce((s, r) => s + Math.round(Number(r.total) * 100), 0);
  return { day, orders: rows.length, totalCents: cents };
}

export async function markShipped(conn: Connection, orderId: number): Promise<boolean> {
  const [res] = await conn.execute<any>("UPDATE orders SET status = 'shipped' WHERE id = ? AND status IN ('paid', 'shipped')", [orderId]);
  // תקלה 2: היה changedRows === 1 ← הזמנה שכבר shipped (ערך זהה) החזירה false, כאילו לא קיימת או לא שולמה.
  // affectedRows — כמה שורות התאימו ל־WHERE (ב־mysql2 ברירת המחדל: CLIENT_FOUND_ROWS)
  return res.affectedRows === 1;
}

// תקלה 3: היה new Date(day) ← "2026-03-01" כ־Date ב־UTC, ו־mysql2 שולח אותו לפי אזור הזמן של התהליך —
// בשרת בישראל השאילתה התחילה ב־"2026-03-01 02:00". מחרוזת 'YYYY-MM-DD' עוברת כמו שהיא
export const dayParam = (day: string) => {
  if (!/^\d{4}-\d{2}-\d{2}$/.test(day)) throw new Error("תאריך בפורמט YYYY-MM-DD");
  return day;
};
⚠️ טעויות נפוצות
  • לתקן את הסכום עם parseFloat ולחבר שברים — אחרי אלף הזמנות מגיעים לאגורה חסרה. אגורות כמספר שלם.

P25.5-E75 · לקוח חדש — insertId ואימייל תפוס 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.5-E75: לקוח חדש — insertId ואימייל תפוס
import type { Pool, ResultSetHeader } from "mysql2/promise";

export async function createCustomer(pool: Pool, input: { name: string; email: string; city: string }) {
  const row = { name: input.name.trim(), email: input.email.trim().toLowerCase(), city: input.city.trim() };
  try {
    const [res] = await pool.execute<ResultSetHeader>("INSERT INTO customers (name, email, city) VALUES (?, ?, ?)", [row.name, row.email, row.city]);
    return { id: res.insertId, ...row };
  } catch (err) {
    if ((err as { errno?: number }).errno === 1062) throw new Error("EMAIL_TAKEN");
    throw err;
  }
}
⚠️ טעויות נפוצות
  • לבדוק אם האימייל קיים ב־SELECT לפני ה־INSERT — מרוץ (פרק 18), ושתי פקודות במקום אחת. ה־UNIQUE הוא הבדיקה.

P25.5-E76 · מוצרים לפי רשימת ids 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

‏pool.query(sql, [ids]) — מערך בתוך מערך: ה־? אחד מקבל את כל הרשימה.

💡 רמז 2

new Map(rows.map((r) => [r.id, r])), ואז [...new Set(ids)] לפי הסדר.

✅ פתרון
// P25.5-E76: מוצרים לפי רשימת ids
import type { Pool, RowDataPacket } from "mysql2/promise";

export async function productsByIds(pool: Pool, ids: number[]) {
  const unique = [...new Set(ids)];
  if (unique.length === 0) return [];
  const [rows] = await pool.query<RowDataPacket[]>("SELECT id, name, price FROM products WHERE id IN (?)", [unique]);
  const byId = new Map(rows.map((r) => [Number(r.id), r]));
  return unique
    .filter((id) => byId.has(id))
    .map((id) => {
      const r = byId.get(id)!;
      return { id, name: String(r.name), priceCents: Math.round(Number(r.price) * 100) };
    });
}

‏IN (?) עם מערך עובד רק עם query (E70). והסדר: SQL לא מבטיח שום סדר בלי ORDER BY — לכן מסדרים בקוד.

⚠️ טעויות נפוצות
  • לולאה של שאילתה לכל id — N+1 (פרק 18).

P25.5-E77 · ‏"סמן כנשלח" — שלוש תשובות שונות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1
UPDATE orders SET status = 'shipped' WHERE id = ? AND status IN ('paid', 'shipped')
💡 רמז 2

‏changedRows ← 1: נשלחה עכשיו. ‏affectedRows 1 ו־changed 0: כבר. ‏affected 0: ‏SELECT קטן.

✅ פתרון
// P25.5-E77: "סמן כנשלח" — שלוש תשובות שונות
import type { Pool, ResultSetHeader, RowDataPacket } from "mysql2/promise";

export async function markShipped(pool: Pool, orderId: number) {
  const [res] = await pool.execute<ResultSetHeader>(
    "UPDATE orders SET status = 'shipped' WHERE id = ? AND status IN ('paid', 'shipped')",
    [orderId],
  );
  if (res.changedRows === 1) return "shipped" as const;
  if (res.affectedRows === 1) return "already" as const;
  const [rows] = await pool.execute<RowDataPacket[]>("SELECT 1 FROM orders WHERE id = ?", [orderId]);
  return rows.length ? ("invalid_status" as const) : ("not_found" as const);
}

ב־API: ‏shipped ו־already ← 200 (idempotent, פרק 24), ‏invalid_status ← 409, ‏not_found ← 404.

⚠️ טעויות נפוצות
  • SELECT של הסטטוס ואז UPDATE — מרוץ: ההזמנה בוטלה בין שתי הפקודות, ונשלחה הזמנה מבוטלת.

// P25.5-E78: הרבה לקוחות ב־INSERT אחד
import type { Pool, ResultSetHeader } from "mysql2/promise";

export async function createCustomers(pool: Pool, list: { name: string; email: string; city: string }[]) {
  if (list.length === 0) return [];
  const [res] = await pool.query<ResultSetHeader>(
    "INSERT INTO customers (name, email, city) VALUES ?",

}

P25.5-E79 · הזמנה עם הפריטים — בשאילתה אחת 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25.5-E79: הזמנה עם הפריטים — בשאילתה אחת
import type { Pool, RowDataPacket } from "mysql2/promise";

const cents = (v: unknown) => Math.round(Number(v) * 100);

export async function orderWithItems(pool: Pool, orderId: number) {
  const [rows] = await pool.query<RowDataPacket[]>(
    `SELECT o.id, o.status, o.total,
            DATE_FORMAT(o.created_at, '%Y-%m-%dT%H:%i:%s.%fZ') AS created_at,
            JSON_ARRAYAGG(JSON_OBJECT('productId', oi.product_id, 'name', p.name, 'quantity', oi.quantity, 'unitPrice', oi.unit_price)) AS items
       FROM orders o
       JOIN order_items oi ON oi.order_id = o.id
       JOIN products p ON p.id = oi.product_id
      WHERE o.id = ?
      GROUP BY o.id`,
    [orderId],
  );
  if (rows.length === 0) return null;
  const r = rows[0];
  const items = (r.items as { productId: number; name: string; quantity: number; unitPrice: number | string }[])
    .map((i) => ({ productId: Number(i.productId), name: i.name, quantity: Number(i.quantity), unitPriceCents: cents(i.unitPrice) }))
    .sort((a, b) => a.productId - b.productId);
  return {
    id: Number(r.id),
    status: String(r.status),
    totalCents: cents(r.total),
    createdAt: String(r.created_at).replace(/(\.\d{3})\d{3}Z$/, "$1Z"),
    items,
  };
}

‏DATE_FORMAT בצד ה־SQL עוקף את כל ההמרות של ה־driver: מה שבעמודה (‏UTC) יוצא כמחרוזת, עם Z. ו־JSON_ARRAYAGG חוסך שאילתה שנייה לפריטים. (הזמנה בלי פריטים לא תחזור ב־JOIN רגיל — בחנות שלנו אין כאלה.)

⚠️ טעויות נפוצות
  • new Date(r.created_at).toISOString() עם ברירות המחדל של mysql2 — ב־TZ=Asia/Jerusalem יוצא 07:00Z במקום 09:00Z (E74).

P25.5-E80 · ‏pg מול mysql2 — מה משתנה בקוד? 🧠 הבנה רמה 2

💡 רמז 1

‏$2 לפני $1 בשאילתה — ומה עם ??

💡 רמז 2

מה query של mysql2 מחזיר — אובייקט, או זוג?

✅ פתרון
  • pool.connect() ← pool.getConnection(). ‏"BEGIN"/"COMMIT"/"ROLLBACK" ← conn.beginTransaction(), ‏commit(), ‏rollback() (או אותן מחרוזות, גם עובד).
  • $1 ← ?. המלכודת: ‏? לפי סדר ההופעה. ב־UPDATE, ‏$2 מופיע לפני $1 — אז המערך הוא [qty, id], לא [id, qty]. (‏P25.5-E28 עושה את זה אוטומטית.)
  • { rows } ← const [rows] = await conn.query(…). ‏rowCount ← ‏affectedRows של ה־ResultSetHeader.
  • RETURNING id ← אין; insertId.
  • וגם: ‏stock חוזר כמספר (INT), אבל אם היה DECIMAL — מחרוזת בשניהם (‏pg מחזיר numeric כמחרוזת גם).
⚠️ טעויות נפוצות
  • להחליף רק $n ל־? בעזרת regex, בלי לסדר מחדש את הפרמטרים — העדכון רץ על מוצר עם id = הכמות.

P25.5-E81 · ‏Prisma: מ־postgresql ל־mysql 🧠 הבנה רמה 2

💡 רמז 1

‏String ב־MySQL — ‏VARCHAR(191) כברירת מחדל.

💡 רמז 2

migrations הן SQL — של איזה מסד?

✅ פתרון
  1. נשבר: VARCHAR(191) — כותרת של 300 נכשלת ("value too long"). ‏@db.VarChar(500) או @db.Text.
  2. נשבר — mode: "insensitive" לא נתמך ב־MySQL. ולא צריך: הקולציה כבר לא רגישה לרישיות. מורידים את mode.
  3. נשבר: || הוא OR, ו־ILIKE לא קיים. ‏CONCAT(title, ' ', description) LIKE ….
  4. לא שמיש — זה SQL של PostgreSQL. מתחילים היסטוריה חדשה (‏migrate dev על מסד MySQL ריק), ומעבירים נתונים בנפרד (שיעור 5).
  5. עובד אחרת: ב־REPEATABLE READ ה־findUnique (‏SELECT רגיל) יכול לראות ערך ישן — אותה בעיה כמו ב־PostgreSQL, ועוד יותר (E56). ההחלטה ב־updateMany עם תנאי (‏where: { id, stock: { gte: qty } }), ו־count.
⚠️ טעויות נפוצות
  • להחליף provider ולהריץ migrate deploy — Prisma מנסה להריץ SQL של PostgreSQL על MySQL, ונופל בקובץ הראשון.

P25.5-E82 · הזרקת SQL — גם ב־MySQL 🧠 הבנה רמה 2

💡 רמז 1

כל מקום שבו קלט נכנס לטקסט של ה־SQL — ולא כפרמטר.

💡 רמז 2

ב־ORDER BY אי אפשר לשים ? לשם עמודה.

✅ פתרון
  1. פגיע. q = "' OR 1=1 -- " מחזיר הכול; ‏q = "' UNION SELECT email, … FROM customers -- " מוציא לקוחות. תיקון: "… LIKE ?" עם [%${q}%] (ו־escape של % ו־_ בקלט, אם חשוב).
  2. פגיע. תת־שאילתה ב־sort שבוחרת עמודת מיון לפי תו של password_hash — מוציא מידע לפי סדר התוצאות. תיקון: רשימה סגורה — { name: "name", price: "price" }[sort] ?? "id".

P25.5-E83 · ‏repository של מוצרים מעל mysql2 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

פונקציה פרטית אחת #toProduct(row) — ‏DECIMAL ← אגורות, ‏0/1 ← boolean (‏P25.5-E10).

💡 רמז 2

‏adjustStock:

UPDATE … SET stock = stock + ? WHERE id = ? AND stock + ? >= 0

ואז SELECT של המלאי (או הבחנה בין NOT_FOUND ל־OUT_OF_STOCK).

✅ פתרון
// P25.5-E83: repository של מוצרים מעל mysql2
import type { Pool, ResultSetHeader, RowDataPacket } from "mysql2/promise";

export type Product = { id: number; name: string; category: string; priceCents: number; stock: number; isActive: boolean; attributes: Record<string, unknown> | null };

export class MysqlProductsRepository {
  #pool: Pool;
  constructor(pool: Pool) {
    this.#pool = pool;
  }

  #toProduct(r: RowDataPacket): Product {
    return {
      id: Number(r.id),
      name: String(r.name),
      category: String(r.category),
      priceCents: Math.round(Number(r.price) * 100),
      stock: Number(r.stock),
      isActive: Boolean(r.is_active),
      attributes: r.attributes ?? null,
    };
  }

  async findById(id: number): Promise<Product | null> {
    const [rows] = await this.#pool.execute<RowDataPacket[]>("SELECT * FROM products WHERE id = ?", [id]);
    return rows.length ? this.#toProduct(rows[0]) : null;
  }

  async list({ category, onlyActive = true, limit = 20 }: { category?: string; onlyActive?: boolean; limit?: number } = {}): Promise<Product[]> {
    const where: string[] = [];
    const params: unknown[] = [];
    if (category !== undefined) {
      where.push("category = ?");
      params.push(category);
    }
    if (onlyActive) where.push("is_active");
    const sql = `SELECT * FROM products ${where.length ? "WHERE " + where.join(" AND ") : ""} ORDER BY id LIMIT ?`;
    const [rows] = await this.#pool.query<RowDataPacket[]>(sql, [...params, limit]);
    return rows.map((r) => this.#toProduct(r));
  }

  async adjustStock(id: number, delta: number): Promise<number> {
    const [res] = await this.#pool.execute<ResultSetHeader>("UPDATE products SET stock = stock + ? WHERE id = ? AND stock + ? >= 0", [delta, id, delta]);
    if (res.affectedRows === 0) {
      const exists = await this.findById(id);
      throw new Error(exists ? "OUT_OF_STOCK" : "NOT_FOUND");
    }
    const p = await this.findById(id);
    return p!.stock;
  }
}

שאר האפליקציה מכירה רק את Product — לא "89.90", לא 1, לא is_active. ככה עוברים מסד (או מחליפים בכפיל בבדיקות, פרק 22) בלי לגעת בשאר הקוד.

⚠️ טעויות נפוצות
  • SELECT stock ואז UPDATE … SET stock = ? עם הערך החדש — lost update (E52).

P25.5-E84 · ‏GET /products עם cursor 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שלם חיובי מ־query string: /^\d+$/.test(v), ואז Number(v).

💡 רמז 2

‏"העמוד מלא" — ‏rows.length === limit. (כך יכול להיות עמוד ריק אחרון — מחיר קטן בשביל שאילתה אחת.)

✅ פתרון
// P25.5-E84: GET /products עם cursor
import { Router } from "express";
import type { Pool, RowDataPacket } from "mysql2/promise";

const intParam = (v: unknown, def: number | null, min: number, max: number) => {
  if (v === undefined) return def;
  if (typeof v !== "string" || !/^\d+$/.test(v)) return NaN;
  const n = Number(v);
  return n >= min && n <= max ? n : NaN;
};

export function productsRouter(pool: Pool) {
  const router = Router();
  router.get("/products", async (req, res, next) => {
    const limit = intParam(req.query.limit, 10, 1, 50) as number;
    const after = intParam(req.query.after, 0, 0, Number.MAX_SAFE_INTEGER) as number;
    const category = req.query.category;
    if (Number.isNaN(limit) || Number.isNaN(after) || (category !== undefined && typeof category !== "string")) {
      res.status(400).json({ error: { code: "VALIDATION_ERROR" } });
      return;
    }
    try {
      const [rows] = await pool.query<RowDataPacket[]>(
        `SELECT id, name, price FROM products
          WHERE is_active AND id > ? ${category !== undefined ? "AND category = ?" : ""}
          ORDER BY id LIMIT ?`,
        category !== undefined ? [after, category, limit] : [after, limit],
      );
      const items = rows.map((r) => ({ id: Number(r.id), name: String(r.name), priceCents: Math.round(Number(r.price) * 100) }));
      res.json({ items, nextAfter: items.length === limit ? items[items.length - 1].id : null });
    } catch (err) {
      next(err);
    }
  });
  return router;
}
⚠️ טעויות נפוצות
  • OFFSET (page - 1) * limit — עובד, אבל עם כל החסרונות של E53.

// P25.5-E85: database זמני לבדיקות
import { randomUUID } from "node:crypto";
import mysql, { type Pool } from "mysql2/promise";

export async function withTempDatabase<T>(url: string, seedSql: string, fn: (pool: Pool) => Promise<T>): Promise<T> {
  const name = `test_${randomUUID().replaceAll("-", "").slice(0, 12)}`;
  const admin = await mysql.createConnection({ uri: url, multipleStatements: true });
  let pool: Pool | undefined;
  try {
    await admin.query(`CREATE DATABASE \`${name}\` CHARACTER SET utf8mb4`);
    pool = mysql.createPool({ uri: url, database: name, multipleStatements: true, connectionLimit: 5 });
    if (seedSql.trim()) await pool.query(seedSql);
    return await fn(pool);
  } finally {
    await pool?.end();
    await admin.query(`DROP DATABASE IF EXISTS \`${name}\``);
    await admin.end();
  }
}

‏return await בתוך try — כדי שה־finally ירוץ אחרי ש־fn באמת הסתיימה (ולא מיד, כשה־Promise חוזר).

⚠️ טעויות נפוצות
  • return fn(pool) בלי await — ה־finally סוגר את ה־pool בזמן ש־fn עוד רצה, והבדיקה נכשלת על "Pool is closed".
