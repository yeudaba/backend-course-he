P25.5-E03 · REPEATABLE READ

🧠 הבנהרמה 1⏱ 15 דק׳ידע נדרש: שיעור 3

ב־MySQL ברירת המחדל היא REPEATABLE READ (ב־PostgreSQL: READ COMMITTED). מלאי = 10. טרנזקציה A: START TRANSACTION; SELECT stock … ← 10. עכשיו B (בחיבור אחר) מוריד ל־7 ועושה COMMIT. מה יראה A ב: (1) SELECT stock שוב? (2) SELECT stock … FOR UPDATE? (3) UPDATE products SET stock = stock - 1 ואז SELECT? ומה המסקנה לגבי "קרא ואז החלט"?

P25.5-E14 · תור עבודות: SKIP LOCKED 🤖

P25.5-E15 · deadlock, ואיך חיים איתו 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25.5-E15.ts: withDeadlockRetry(fn, { retries = 3, sleep, random }) — מריץ את fn(attempt); אם נזרקה שגיאה עם errno 1213 (deadlock) או 1205 (lock wait timeout) — מחכה קצת (אקראי, גדל) ומנסה שוב, עד retries פעמים. כל שגיאה אחרת — מיד. הבודק גם מייצר deadlock אמיתי: שתי טרנזקציות שנועלות שני מוצרים בסדר הפוך.

P25.5-E17 · idempotency ב־MySQL 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

טבלת idempotency (idem_key PK, status 'pending'/'done', result JSON). בקובץ P25.5-E17.ts: once(pool, key, fn) — הראשון עם המפתח מריץ את fn ושומר את התוצאה ({ result, replayed: false }); מי שבא אחריו מקבל את התוצאה השמורה (replayed: true), או InProgress אם הראשון עוד רץ. fn נכשל ← המפתח נמחק, ואפשר לנסות שוב.
