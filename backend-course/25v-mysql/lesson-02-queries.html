שיעור 2 — שאילתות: upsert, JSON, GROUP BY ו־FULLTEXT

⏱ ~40 דקות

🎯 בשיעור הזה
  • אין RETURNING: איך מקבלים את ה־id שנוצר.
  • upsert: ON DUPLICATE KEY UPDATE, ובמה הוא שונה מ־ON CONFLICT.
  • GROUP BY תחת ONLY_FULL_GROUP_BY.
  • window functions, JSON ו־FULLTEXT.

1. ה־id שנוצר

ב־PostgreSQL כתבנו INSERT … RETURNING id. ב־MySQL אין RETURNING. השרת מחזיר ל־driver את ה־id האחרון שנוצר בחיבור — ב־mysql2 זה insertId (שיעור 4), וב־SQL — LAST_INSERT_ID(), ששייך לחיבור, לא לטבלה: שני חיבורים שמכניסים במקביל מקבלים כל אחד את שלו.

INSERT INTO customers (name, email, city) VALUES ('Omer Biton', 'omer@example.com', 'Beer Sheva');
SELECT LAST_INSERT_ID() AS new_id;
INSERT INTO customers (name, email, city) VALUES ('Tamar', 'tamar@example.com', 'Eilat'), ('Eli', 'eli@example.com', 'Eilat');
SELECT LAST_INSERT_ID() AS first_of_batch;
+--------+
| new_id |
+--------+
|      6 |
+--------+
+----------------+
| first_of_batch |
+----------------+
|              7 |
+----------------+

שימו לב לשאילתה השנייה: ב־INSERT של כמה שורות, LAST_INSERT_ID() הוא ה־id של הראשונה.

2. upsert

INSERT INTO cart_items (customer_id, product_id, quantity) VALUES (1, 3, 2) AS new
  ON DUPLICATE KEY UPDATE quantity = cart_items.quantity + new.quantity;
SELECT ROW_COUNT() AS row_count;
SELECT customer_id, product_id, quantity FROM cart_items WHERE customer_id = 1 ORDER BY product_id;
+-----------+
| row_count |
+-----------+
|         2 |
+-----------+
+-------------+------------+----------+
| customer_id | product_id | quantity |
+-------------+------------+----------+
|           1 |          3 |        4 |
|           1 |          9 |        1 |
+-------------+------------+----------+

ROW_COUNT() אחרי upsert הוא 1 כשנוספה שורה, ו־2 כשעודכנה קיימת — כך יודעים מה קרה. וב־MySQL ישן ראית quantity = VALUES(quantity): עובד, אבל מיושן מ־8.0.20 ומייצר warning (E08 בודק שאין).

3. GROUP BY

ב־MySQL ישן אפשר היה לכתוב SELECT category, name, MAX(price) … GROUP BY category — והוא החזיר name "כלשהו" מהקבוצה, לא בהכרח של המוצר היקר. מ־5.7, ONLY_FULL_GROUP_BY מופעל כברירת מחדל ודוחה את זה:

SELECT category, name, MAX(price) FROM products GROUP BY category;
SELECT c.name, c.city, COUNT(*) AS orders FROM customers c JOIN orders o ON o.customer_id = c.id GROUP BY c.id ORDER BY orders DESC, c.id LIMIT 3;
ERROR 1055 (42000): Expression #2 of SELECT list is not in GROUP BY clause and contains nonaggregated column 'snippet.products.name' which is not functionally dependent on columns in GROUP BY clause; this is incompatible with sql_mode=only_full_group_by
+-------------+----------+--------+
| name        | city     | orders |
+-------------+----------+--------+
| Dana Levi   | Haifa    |      2 |
| Yossi Cohen | Tel Aviv |      2 |
| Noa Mizrahi | Tel Aviv |      1 |
+-------------+----------+--------+

השאילתה השנייה עוברת: c.name ו־c.city לא ב־GROUP BY, אבל הם תלויים פונקציונלית ב־c.id — המפתח הראשי. MySQL מבין את זה (וגם PostgreSQL). ל"המוצר היקר בכל קטגוריה" — window function (E07).

4. JSON ו־FULLTEXT

עמודת JSON (בינארית, מאומתת) עם אופרטורים קצרים: -> מחזיר JSON, ->> טקסט:

SELECT name, attributes->'$.material' AS as_json, attributes->>'$.material' AS as_text
FROM products WHERE category = 'brewing' AND attributes->>'$.material' = 'glass';
+-----------------+---------+---------+
| name            | as_json | as_text |
+-----------------+---------+---------+
| French Press 1L | "glass" | glass   |
+-----------------+---------+---------+

וחיפוש טקסט: LIKE '%grinder%' סורק את כל הטבלה. אינדקס FULLTEXT בונה אינדקס של מילים, ו־MATCH … AGAINST משתמש בו — במצב BOOLEAN עם + (חובה), - (אסור) ו־* (prefix) (E16). לחיפוש רציני באמת — דירוג, שגיאות כתיב, עברית עם תחיליות — מנוע חיפוש ייעודי.
