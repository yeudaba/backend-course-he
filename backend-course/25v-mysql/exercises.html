P25.5-E27 · INSERT מרובה שורות, עם upsert 🤖

🔁 חזרהרמה 2⏱ 20 דק׳ידע נדרש: שיעור 2

🔁 חזרה על Object.keys (פרק 7), ‏map/flatMap/join (פרק 6), ‏regex (‏P13-E26) ושאילתות עם פרמטרים (‏P16-E27). ‏ORM לא תמיד יודע לייצר INSERT אחד עם 500 שורות. לולאה של 500 INSERTים איטית פי כמה עשרות. כתוב וייצא:

buildBulkInsert(table, rows, { add?, set? } = {}): { sql, params }

  • INSERT INTO t (a, b) VALUES (?, ?), (?, ?). סדר העמודות לפי המפתחות של השורה הראשונה, ו־params לפי אותו סדר, שורה אחרי שורה, גם אם בשורה אחרת המפתחות כתובים בסדר אחר.
  • upsert, בתחביר של שיעור 2: אם יש add או set, מוסיפים AS new ON DUPLICATE KEY UPDATE , ואחריו קודם כל עמודה מ־add (c = t.c + new.c), ואחר כך כל עמודה מ־set (c = new.c), מופרדות ב־", ".
  • שם טבלה או עמודה (גם ב־add/set) חייב להתאים ל־^[a-z_][a-z0-9_]*$. אין שורות, או שורה עם עמודות אחרות מהראשונה ← Error.

הבודק מריץ את התוצאה על MySQL אמיתי.

P25.5-E28 · שאילתה מ־PostgreSQL ל־MySQL 🤖

🔁 חזרהרמה 2⏱ 20 דק׳ידע נדרש: שיעור 1

🔁 חזרה על replace עם regex ופונקציה (‏P13-E26, ‏P20-E27) ועל קבוצות לכידה. בהעברת קוד מ־PostgreSQL ל־MySQL (שיעור 1), שני הבדלים חוזרים בכל שאילתה: placeholders ($1 מול ?), ושמות במירכאות ("order" מול order). כתוב וייצא pgToMysql(sql, params): { sql, params }:

  • כל $n הופך ל־?. ‏params החדש לפי סדר ההופעה בשאילתה: $2 שמופיע פעמיים ← הפרמטר השני פעמיים. ‏$10 הוא פרמטר 10.
  • $n שאין לו פרמטר ($0, או יותר מהאורך) ← RangeError.
  • "שם" הופך ל־שם.
  • בתוך מחרוזת '...' לא נוגעים בכלום (גם לא ב־$1 או ב־"). בתוך מחרוזת, '' הוא גרש אחד, והמחרוזת ממשיכה.

P25.5-E01 · מילון PostgreSQL ← MySQL

רמה 1⏱ 15 דק׳ידע נדרש: שיעור 1

לכל דבר שעבד ב־PostgreSQL בקורס — המקבילה ב־MySQL 8, או "אין":

  1. id integer GENERATED ALWAYS AS IDENTITY
  2. INSERT … RETURNING id
  3. ON CONFLICT (…) DO UPDATE
  4. 'a' || 'b'
  5. ILIKE
  6. boolean, jsonb, timestamptz
  7. SELECT DISTINCT ON (…)
  8. FULL OUTER JOIN
  9. $1, $2 בשאילתה עם פרמטרים

P25.5-E03 · REPEATABLE READ

רמה 1⏱ 15 דק׳ידע נדרש: שיעור 3

ב־MySQL ברירת המחדל היא REPEATABLE READ (ב־PostgreSQL: READ COMMITTED). מלאי = 10. טרנזקציה A: START TRANSACTION; SELECT stock … ← 10. עכשיו B (בחיבור אחר) מוריד ל־7 ועושה COMMIT. מה יראה A ב: (1) SELECT stock שוב? (2) SELECT stock … FOR UPDATE? (3) UPDATE products SET stock = stock - 1 ואז SELECT? ומה המסקנה לגבי "קרא ואז החלט"?
