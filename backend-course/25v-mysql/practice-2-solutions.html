P25.5-E07 · היקר ביותר בכל קטגוריה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

אין DISTINCT ON. יש window functions.

💡 רמז 2

ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC, id) בתת־שאילתה, ו־WHERE rn = 1 בחוץ.

✅ פתרון
-- P25.5-E07
-- המוצר היקר ביותר בכל קטגוריה (פעיל ובמלאי); בתיקו — ה־id הקטן. window functions קיימות מ־MySQL 8.0
SELECT category, name, price
FROM (
  SELECT category, name, price,
         ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC, id) AS rn
  FROM products
  WHERE is_active AND stock > 0
) ranked
WHERE rn = 1
ORDER BY category;
+-------------+----------------------+--------+
| category    | name                 | price  |
+-------------+----------------------+--------+
| accessories | Paper Filters (100)  |  24.90 |
| beans       | Ethiopia Beans 1kg   |  89.90 |
| brewing     | Gooseneck Kettle     | 229.00 |
| grinders    | Electric Grinder Pro | 649.00 |
+-------------+----------------------+--------+
⚠️ טעויות נפוצות
  • SELECT category, name, MAX(price) … GROUP BY category — ב־MySQL ישן זה "עבד" ונתן name אקראי; ב־8 עם ONLY_FULL_GROUP_BY — שגיאה. וטוב שכך.

P25.5-E08 · upsert לעגלה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

INSERT … ON DUPLICATE KEY UPDATE.

💡 רמז 2

VALUES(quantity) בתוך ה־UPDATE מיושן מ־8.0.20 (warning). במקומו: VALUES (1, 3, 2) AS new … quantity = cart_items.quantity + new.quantity.

✅ פתרון
-- P25.5-E08
-- "הוסף 2 יחידות של מוצר 3 לעגלה של לקוח 1": אם השורה קיימת — מוסיפים לכמות. ב־PostgreSQL: ON CONFLICT … DO UPDATE.
-- ב־MySQL: ON DUPLICATE KEY UPDATE, עם alias לשורה החדשה (VALUES() בתוך UPDATE מיושן מ־8.0.20 ומחזיר warning)
INSERT INTO cart_items (customer_id, product_id, quantity)
VALUES (1, 3, 2) AS new
ON DUPLICATE KEY UPDATE quantity = cart_items.quantity + new.quantity;

שימו לב להבדל מ־PostgreSQL: ON CONFLICT (customer_id, product_id) בוחר מפתח; ON DUPLICATE KEY מופעל על כל מפתח ייחודי בטבלה. בטבלה עם שני מפתחות ייחודיים זה יכול לעדכן שורה שלא התכוונת אליה.

⚠️ טעויות נפוצות
  • REPLACE INTO — "upsert" שבעצם מוחק ומכניס מחדש: ה־id משתנה, וטריגרים ומפתחות זרים עם ON DELETE מופעלים.

P25.5-E11 · GROUP BY נכון 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כל עמודה ב־SELECT — או ב־GROUP BY, או בתוך פונקציה מצטברת, או תלויה פונקציונלית במה שב־GROUP BY.

💡 רמז 2

GROUP BY c.id מספיק ל־c.name ו־c.city — כי id הוא המפתח הראשי.

✅ פתרון
-- P25.5-E11
-- לכל לקוח עם הזמנות ששולמו: כמה, כמה כסף, ומתי האחרונה. ONLY_FULL_GROUP_BY מרשה name ו־city
-- כי הם תלויים פונקציונלית ב־c.id (המפתח הראשי) — לא צריך להוסיף אותם ל־GROUP BY
SELECT c.name, c.city,
       COUNT(*) AS paid_orders,
       SUM(o.total) AS paid_total,
       MAX(o.created_at) AS last_order
FROM customers c
JOIN orders o ON o.customer_id = c.id AND o.status IN ('paid', 'shipped')
GROUP BY c.id
ORDER BY paid_total DESC, c.id;

| name        | city      | paid_orders | paid_total | last_order              |

| Dana Levi   | Haifa     |           1 |     278.90 | 2026-03-01 09:00:00.000 |
| Noa Mizrahi | Tel Aviv  |           1 |     238.00 | 2026-03-04 16:45:00.000 |
| Avi Peretz  | Jerusalem |           1 |     119.00 | 2026-03-06 10:10:00.000 |
+-------------+-----------+-------------+------------+-------------------------+
⚠️ טעויות נפוצות
  • לכבות את ONLY_FULL_GROUP_BY ב־sql_mode כי "השאילתה הישנה נשברה". השאילתה הישנה החזירה ערכים שרירותיים — עכשיו פשוט יודעים.

P25.5-E12 · עמודת JSON 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

attributes->>'$.material' — טקסט; -> — JSON (עם מרכאות).

💡 רמז 2

CAST(attributes->>'$.cups' AS UNSIGNED), ו־ORDER BY cups IS NULL, cups DESC.

✅ פתרון
-- P25.5-E12
-- עמודת JSON: ->> מחזיר טקסט (בלי מרכאות), -> מחזיר JSON. מספר — CAST, כדי למיין ולהשוות כמספר
SELECT name,
       attributes->>'$.material' AS material,
       CAST(attributes->>'$.cups' AS UNSIGNED) AS cups
FROM products
WHERE category = 'brewing'
  AND attributes->>'$.material' IS NOT NULL
ORDER BY cups IS NULL, cups DESC, name;
+------------------+-----------+------+
| name             | material  | cups |
+------------------+-----------+------+
| French Press 1L  | glass     |    8 |
| Moka Pot 6 Cups  | aluminium |    6 |
| Gooseneck Kettle | steel     | NULL |
| V60 Ceramic      | ceramic   | NULL |
+------------------+-----------+------+

וכשמחפשים לפי שדה ב־JSON הרבה: עמודה מחושבת (GENERATED ALWAYS AS (attributes->>'$.material')) עם אינדקס, או functional index. אבל אם שדה מופיע בכל שורה ומחפשים לפיו — הוא כנראה צריך להיות עמודה רגילה.

⚠️ טעויות נפוצות
  • להשוות attributes->'$.material' = 'glass' — ה־-> מחזיר JSON ("glass" עם מרכאות), וההשוואה מתנהגת אחרת ממה שנראה.

P25.5-E20 · שאילתה מ־PostgreSQL — שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

שלושה דברים ש־MySQL לא מכיר, או מכיר אחרת.

💡 רמז 2

||, ILIKE, DISTINCT ON.

✅ פתרון
-- P25.5-E20
-- "השאילתה עבדה ב־PostgreSQL": שלוש בעיות ב־MySQL
-- תקלה 1: || ב־MySQL הוא OR לוגי (מחזיר 0/1), לא חיבור מחרוזות ← CONCAT
-- תקלה 2: אין ILIKE ← LIKE, שבקולציה של הטבלה (_ai_ci) כבר לא רגיש לרישיות
-- תקלה 3: DISTINCT ON לא קיים ← ROW_NUMBER() בתת־שאילתה
SELECT customer, city, last_total
FROM (
  SELECT CONCAT(c.name, ' (', c.email, ')') AS customer,
         c.city,
         o.total AS last_total,
         ROW_NUMBER() OVER (PARTITION BY c.id ORDER BY o.created_at DESC) AS rn
  FROM customers c
  JOIN orders o ON o.customer_id = c.id
  WHERE c.city LIKE '%aviv%'
) t
WHERE rn = 1
ORDER BY customer;
+---------------------------------+----------+------------+
| customer                        | city     | last_total |
+---------------------------------+----------+------------+
| Noa Mizrahi (noa@example.com)   | Tel Aviv |     238.00 |
| Yossi Cohen (yossi@example.com) | Tel Aviv |      89.90 |
+---------------------------------+----------+------------+
⚠️ טעויות נפוצות
  • להפעיל PIPES_AS_CONCAT ב־sql_mode כדי ש־|| יעבוד — עכשיו הקוד תלוי בהגדרת שרת, ושרת אחר יחזיר 0.

P25.5-E26 · דוח לקוחות ב־MySQL — מקובץ ריק 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שתי טבלאות "רבות" לכל לקוח (הזמנות ועגלה). ‏JOIN לשתיהן יחד מכפיל שורות: לדנה יש שני פריטים בעגלה, וההזמנה שלה נספרת פעמיים. לכן מסכמים כל אחת בנפרד ב־CTE (WITH spent AS (... GROUP BY customer_id), cart AS (...)), ואז LEFT JOIN ללקוחות.

💡 רמז 2

MySQL: ‏IFNULL(s.spent, 0) (או COALESCE), ‏DATE_FORMAT(s.last_at, '%d/%m/%Y'). ‏DATE_FORMAT של NULL הוא NULL. בחלון: RANK() OVER (PARTITION BY c.city ORDER BY IFNULL(s.spent, 0) DESC), ובסוף ORDER BY c.city, city_rank, c.name (מותר למיין לפי כינוי של עמודה).

✅ פתרון
WITH spent AS (
  SELECT customer_id, COUNT(*) AS orders, SUM(total) AS spent, MAX(created_at) AS last_at
  FROM orders
  WHERE status IN ('paid', 'shipped')
  GROUP BY customer_id
),
cart AS (
  SELECT customer_id, SUM(quantity) AS units
  FROM cart_items
  GROUP BY customer_id
)
SELECT
  c.name,
  c.city,
  IFNULL(s.orders, 0) AS orders,
  IFNULL(s.spent, 0) AS spent,
  DATE_FORMAT(s.last_at, '%d/%m/%Y') AS last_order,
  IFNULL(ct.units, 0) AS cart_units,
  RANK() OVER (PARTITION BY c.city ORDER BY IFNULL(s.spent, 0) DESC) AS city_rank
FROM customers c
LEFT JOIN spent s ON s.customer_id = c.id
LEFT JOIN cart ct ON ct.customer_id = c.id
ORDER BY c.city, city_rank, c.name;
+-------------+-----------+--------+--------+------------+------------+-----------+
| name        | city      | orders | spent  | last_order | cart_units | city_rank |
+-------------+-----------+--------+--------+------------+------------+-----------+
| Dana Levi   | Haifa     |      1 | 278.90 | 01/03/2026 |          3 |         1 |
| Maya Katz   | Haifa     |      0 |   0.00 | NULL       |          1 |         2 |
| Avi Peretz  | Jerusalem |      1 | 119.00 | 06/03/2026 |          0 |         1 |
| Yossi Cohen | Tel Aviv  |      1 | 649.00 | 02/03/2026 |          0 |         1 |
| Noa Mizrahi | Tel Aviv  |      1 | 238.00 | 04/03/2026 |          0 |         2 |
+-------------+-----------+--------+--------+------------+------------+-----------+

דנה: הזמנה אחת ששולמה (278.90). ההזמנה המבוטלת לא נספרת. בעגלה שלה 2 + 1 = 3 יחידות. מי שמצרף את orders ואת cart_items באותו FROM מקבל לה spent של 557.80, כי כל הזמנה מופיעה פעם לכל פריט בעגלה. זה ה־"fan-out" מפרק 17, והוא נראה בדיוק אותו דבר ב־MySQL.

מה כאן MySQL ומה לא? ‏CTE, ‏LEFT JOIN, ‏RANK ו־GROUP BY זהים ל־PostgreSQL (מגרסה 8). ההבדלים: ‏DATE_FORMAT עם %d/%m/%Y (ב־PostgreSQL: ‏to_char(..., 'DD/MM/YYYY')), ו־IFNULL, שקיים רק ב־MySQL. ‏COALESCE עובד בשניהם, ולכן הוא בחירה טובה כשכותבים SQL שצריך לרוץ בשני המסדים.

⚠️ טעויות נפוצות
  • JOIN במקום LEFT JOIN — מאיה, שעוד לא הזמינה, נעלמת מהדוח.
  • WHERE o.status IN (...) אחרי LEFT JOIN ל־orders — הופך אותו ל־JOIN רגיל, ומאיה שוב נעלמת. את הסינון שמים בתוך ה־CTE (או בתנאי ה־ON).
  • ROW_NUMBER במקום RANK — בתיקו אחד מקבל 1 והשני 2, לפי סדר מקרי.
  • '%d/%m/%y' — ‏y קטנה היא שנה בשתי ספרות (26).

P25.5-E27 · INSERT מרובה שורות, עם upsert 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שמות לא יכולים להיות פרמטרים (? הוא רק לערכים), ולכן בודקים אותם מול רשימה מותרת: פונקציה קטנה ident(name) שזורקת אם ה־regex לא מתאים, ומחזירה את השם עטוף ב־backticks. כל שם עובר דרכה.

💡 רמז 2

const columns = Object.keys(rows[0]). השוואת עמודות: Object.keys(row).sort().join(",") מול אותו דבר בשורה הראשונה. פרמטרים: rows.flatMap((row) => columns.map((c) => row[c])). ‏placeholders: ‏rows.map(() => "(?, ?, ?)").join(", ").

✅ פתרון
// P25.5-E27 — INSERT מרובה שורות, עם upsert
type Value = string | number | boolean | null;

const IDENT = /^[a-z_][a-z0-9_]*$/;

function ident(name: string): string {
  if (!IDENT.test(name)) throw new Error(`שם לא חוקי: ${name}`);
  return `\`${name}\``;
}

export function buildBulkInsert(
  table: string,
  rows: Record<string, Value>[],
  options: { add?: string[]; set?: string[] } = {},
): { sql: string; params: Value[] } {
  if (rows.length === 0) throw new Error("אין שורות");
  const columns = Object.keys(rows[0]);
  const key = [...columns].sort().join(",");
  for (const row of rows) {
    if (Object.keys(row).sort().join(",") !== key) throw new Error("לכל השורות צריכות להיות אותן עמודות");
  }

  const placeholders = `(${columns.map(() => "?").join(", ")})`;
  let sql = `INSERT INTO ${ident(table)} (${columns.map(ident).join(", ")}) VALUES ${rows.map(() => placeholders).join(", ")}`;
  const params = rows.flatMap((row) => columns.map((c) => row[c]));

  const updates = [
    ...(options.add ?? []).map((c) => `${ident(c)} = ${ident(table)}.${ident(c)} + new.${ident(c)}`),
    ...(options.set ?? []).map((c) => `${ident(c)} = new.${ident(c)}`),
  ];
  if (updates.length > 0) sql += ` AS new ON DUPLICATE KEY UPDATE ${updates.join(", ")}`;
  return { sql, params };
}

console.log(buildBulkInsert("cart_items", [
  { customer_id: 1, product_id: 3, quantity: 2 },
  { product_id: 4, customer_id: 1, quantity: 1 },
], { add: ["quantity"] }));
try {
  buildBulkInsert("products; DROP TABLE orders", [{ id: 1 }]);
} catch (err) {
  console.log((err as Error).message);
}

שם לא חוקי: products; DROP TABLE orders

שני חלקים, ולכל אחד הגנה משלו מ־injection. ערכים עוברים תמיד כ־?, ולכן "x'); DROP TABLE orders; --" נשמר כשם של לקוח. שמות אי אפשר להעביר כפרמטר, ולכן הם עוברים בדיקה מול regex קשוח. שם כמו products; DROP TABLE orders לא מגיע ל־SQL בכלל.

flatMap לפי columns, ולא Object.values(row): בשורה השנייה בדוגמה המפתחות כתובים בסדר אחר. ‏Object.values היה מכניס את מספר המוצר לעמודת הלקוח, בלי שום שגיאה.

‏MySQL מגביל את מספר ה־placeholders בשאילתה (65,535). לכן בטעינה גדולה מחלקים את השורות לקבוצות של כמה מאות, ומריצים כל קבוצה בנפרד.

⚠️ טעויות נפוצות
  • Object.values(row) — תלוי בסדר שבו המפתחות נכתבו בכל שורה.
  • לשרשר ערכים לתוך ה־SQL (VALUES ('${name}')) — ‏injection, וגם שבירה על כל שם עם גרש (O'Brien).
  • VALUES(quantity) במקום new.quantity — עובד, אבל deprecated מ־MySQL 8.0.20.
  • לבדוק רק שמספר העמודות שווה — ‏{a, b} ו־{a, c} עוברים.
