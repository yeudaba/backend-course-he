P30-E04 · מה לשאול את המראיין 🧠 הבנה רמה 1

💡 רמז 1

שאלות על העבודה עצמה: איך נראה שבוע, איך קוד עולה לפרודקשן, מי ילמד אותך.

💡 רמז 2

שכר ותנאים — עם הגיוס, לא עם המראיין הטכני (אלא אם הוא פותח).

✅ פתרון
  1. "How does code get from a pull request to production here?" — יש CI? code review? כמה פעמים בשבוע עולים? (תשובה טובה מזכירה בדיקות ו־review.)
  2. "What would a new junior work on in the first month?" — יש תוכנית קליטה, או "תסתדר".
  3. "Who would I learn from day to day?" — יש מנטור או בכיר בצוות, או שאתה המפתח היחיד.
  4. "What's a technical problem the team is dealing with now?" — מראה עניין, ונותן לך משהו לדבר עליו.
  5. "What does success look like for this role after six months?" — ציפיות ברורות.

דגלים אדומים: אין code review ואין בדיקות ("אנחנו זזים מהר"); "הג׳וניור יחזיק לבד את ה־Backend"; אף אחד בצוות לא יודע לענות מה תעשה בחודש הראשון. ודגלים ירוקים: תשובות קונקרטיות, ומראיין ששואל אותך שאלות המשך על הפרויקט שלך.

⚠️ טעויות נפוצות
  • "אין לי שאלות" — נשמע כמו חוסר עניין. ושאלה שהתשובה עליה בדף הבית של החברה — נשמעת כמו חוסר הכנה.

P30-E17 · מעקב אחרי מועמדויות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

ימים = הפרש במילישניות חלקי 86,400,000 — לא getDate().

💡 רמז 2

לחברה שנדחתה לא שולחים תזכורת.

✅ פתרון
// P30-E17
// מעקב אחרי מועמדויות: חיפוש עבודה הוא משפך — וכדאי לדעת איפה הוא נתקע.
// שיעור תגובה נמוך ← קורות החיים / ההתאמה; הרבה ראיונות ובלי הצעות ← הכנה לראיונות
export type Stage = "applied" | "screen" | "interview" | "offer" | "rejected";
export interface Application {
  company: string;
  stage: Stage;
  appliedAt: string; // ISO
  lastUpdate: string; // ISO
}

const DAY = 86_400_000;

export function pipelineStats(apps: readonly Application[], now: Date, { followUpDays = 7 }: { followUpDays?: number } = {}) {
  const byStage: Record<Stage, number> = { applied: 0, screen: 0, interview: 0, offer: 0, rejected: 0 };
  for (const a of apps) byStage[a.stage]++;
  const responded = apps.length - byStage.applied;
  const reachedInterview = byStage.interview + byStage.offer;
  const followUps = apps
    .filter((a) => a.stage === "applied" && now.getTime() - Date.parse(a.lastUpdate) >= followUpDays * DAY)
    .sort((a, b) => Date.parse(a.lastUpdate) - Date.parse(b.lastUpdate))
    .map((a) => a.company);
  const rate = (n: number) => (apps.length ? Math.round((n / apps.length) * 100) / 100 : 0);
  return { total: apps.length, byStage, responseRate: rate(responded), interviewRate: rate(reachedInterview), followUps };
}

איך משתמשים בזה: 30 מועמדויות, 5% תגובה ← הבעיה בקורות החיים או בהתאמה למשרות (E18). 50% תגובה, ואף ראיון לא עובר ← להתאמן על ראיונות (שיעור 4). המספרים אומרים איפה להשקיע.

⚠️ טעויות נפוצות
  • לא לעקוב בכלל, ולשלוח "עוד 20" כל שבוע. בלי מספרים — לא יודעים מה לא עובד.

P30-E18 · התאמה למודעת דרושים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

regex לכל כינוי: לפניו התחלה או תו שאינו אות/ספרה/+#., ואחריו — אותו דבר (lookahead).

💡 רמז 2

לפני שבונים regex מטקסט — escape לתווים מיוחדים (. ב־node.js, / ב־ci/cd).

✅ פתרון
// P30-E18
// מודעת דרושים ← אילו כישורים היא מבקשת, מה יש לך, ומה חסר. לא כדי "לעבור סינון" —
// כדי להחליט על מה להתכונן, ומה להבליט בקורות החיים לאותה משרה
export const SKILLS: Record<string, string[]> = {
  "Node.js": ["node.js", "nodejs", "node"],
  TypeScript: ["typescript", "ts"],
  JavaScript: ["javascript", "js"],
  NestJS: ["nestjs", "nest.js"],
  Express: ["express", "express.js"],
  PostgreSQL: ["postgresql", "postgres", "psql"],
  MySQL: ["mysql"],
  MongoDB: ["mongodb", "mongo"],
  Redis: ["redis"],
  Docker: ["docker"],
  Kubernetes: ["kubernetes", "k8s"],
  AWS: ["aws", "amazon web services"],
  "CI/CD": ["ci/cd", "ci", "github actions", "jenkins"],
  REST: ["restful", "rest api", "rest apis"],
  GraphQL: ["graphql"],
  Python: ["python"],
  Go: ["golang"],
  Kafka: ["kafka"],
  SQL: ["sql"],
  Testing: ["jest", "unit tests", "testing", "tdd"],
};

const escape = (s: string) => s.replace(/[.*+?^${}()|[\]\\/]/g, "\\$&");

export function extractSkills(text: string): string[] {
  const t = ` ${text.toLowerCase()} `;
  return Object.entries(SKILLS)
    .filter(([, aliases]) => aliases.some((a) => new RegExp(`(^|[^a-z0-9+#.])${escape(a)}(?![a-z0-9+#])`).test(t)))
    .map(([name]) => name);
}

export function matchJob(adText: string, mySkills: readonly string[]) {
  const required = extractSkills(adText);
  const mine = new Set(extractSkills(mySkills.join(", ")));
  const matched = required.filter((s) => mine.has(s));
  const missing = required.filter((s) => !mine.has(s));
  return { required, matched, missing, score: required.length ? Math.round((matched.length / required.length) * 100) / 100 : 0 };
}

מה עושים עם missing? אם זה Docker או SQL — יש לך, רק לא כתבת בקורות החיים. אם זה Kubernetes — שורה כנה במכתב: "לא עבדתי עם k8s; עבדתי עם Docker Compose ו־CI, ואשמח ללמוד". אם חסרים 70% — כנראה לא המשרה.

⚠️ טעויות נפוצות
  • להוסיף לקורות החיים כל מילה מהמודעה כדי "לעבור את ה־ATS". הסינון האוטומטי הוא רק הצעד הראשון — המראיין שואל.

P30-E19 · בדיקה לפני הגשת מטלת בית 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

כל בדיקה — if אחד על Object.keys(files).

💡 רמז 2

JSON.parse בתוך try.

✅ פתרון
// P30-E19
// לפני שמגישים מטלת בית: בדיקה של הדברים שמראיין רואה ב־30 השניות הראשונות
export function checkSubmission(files: Readonly<Record<string, string>>): string[] {
  const paths = Object.keys(files);
  const problems: string[] = [];
  const readme = paths.find((p) => /^readme\.md$/i.test(p));
  if (!readme) problems.push("אין README.md");
  else if (!/```(bash|sh|shell)?\n[\s\S]*?(npm|docker|node|pnpm|yarn)\b/.test(files[readme])) problems.push("ב־README אין הוראות הרצה (בלוק קוד עם הפקודות)");
  if (!paths.some((p) => /(\.spec|\.test)\.[jt]s$/.test(p) || /^tests?\//.test(p))) problems.push("אין בדיקות");
  if (paths.some((p) => /(^|\/)node_modules\//.test(p))) problems.push("node_modules בתוך ההגשה");
  if (paths.some((p) => /(^|\/)\.env$/.test(p))) problems.push(".env בתוך ההגשה — סודות");
  const usesEnv = paths.some((p) => /\.[jt]s$/.test(p) && /process\.env\.\w+/.test(files[p]));
  if (usesEnv && !paths.some((p) => /(^|\/)\.env\.example$/.test(p))) problems.push("הקוד קורא משתני סביבה, ואין .env.example");
  const pkg = files["package.json"];
  if (!pkg) problems.push("אין package.json");
  else {
    try {
      if (!JSON.parse(pkg).scripts?.test) problems.push('אין script בשם "test" ב־package.json');
    } catch {
      problems.push("package.json לא תקין");
    }
  }
  return problems;
}

ומעבר לבודק: מטלת בית נבדקת כמו קוד של עמית. README קצר עם "איך מריצים" ו"מה הייתי עושה עם עוד זמן", בדיקות לחלקים החשובים, commits הגיוניים (לא commit אחד ענק), ועמידה בזמן שביקשו — גם אם זה אומר לוותר על משהו ולכתוב שוויתרת.

⚠️ טעויות נפוצות
  • להשקיע 30 שעות במטלה של "3–4 שעות" — זה לא מרשים, זה אומר שלא עמדת בהערכה. כתוב מה היית מוסיף.

P30-E23 · תזכורות מעקב — שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

getDate() — יום בחודש, לא תאריך.

💡 רמז 2

appliedAt או lastUpdate?

✅ פתרון
// P30-E23
export interface Application {
  company: string;
  stage: "applied" | "screen" | "interview" | "offer" | "rejected";
  appliedAt: string;
  lastUpdate: string;
}

export function followUps(apps: readonly Application[], now: Date, days = 7): string[] {
  return apps
    // תקלה 1: לא סיננו לפי stage ← "תזכורת" לחברה שכבר דחתה, או שכבר בראיון
    .filter((a) => a.stage === "applied")
    // תקלה 2: היה appliedAt ← מועמדות שקיבלה תגובה אתמול "צריכה מעקב"; מה שקובע הוא העדכון האחרון
    // תקלה 3: היה new Date(a.lastUpdate).getDate() — יום בחודש. ב־1 לחודש, עדכון מ־28 לחודש הקודם "חדש"
    .filter((a) => now.getTime() - Date.parse(a.lastUpdate) >= days * 86_400_000)
    .sort((a, b) => Date.parse(a.lastUpdate) - Date.parse(b.lastUpdate))
    .map((a) => a.company);
}
⚠️ טעויות נפוצות
  • חישוב "ימים" עם שעון מקומי ושינוי שעון קיץ — במילישניות זה תמיד נכון (פרק 24).

P30-E24 · אתגר: מטלת בית — בודק זמינות 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

workers (כמו E19 בפרק 29) עם אינדקס משותף; התוצאה נכתבת למקום i.

💡 רמז 2

timeout: Promise.race מול הבטחה שנדחית אחרי timeoutMs, ו־clearTimeout ב־finally — אחרת התהליך נשאר פתוח.

✅ פתרון
// P30-E24
// מטלת בית טיפוסית: "בודק זמינות" לרשימת כתובות. מה בודקים במטלה כזו: מקביליות מוגבלת, timeout,
// retry רק כשזה הגיוני, תוצאות בסדר הקלט, ושגיאה של אחד לא מפילה את כולם
export type Check = (url: string, signal: AbortSignal) => Promise<{ status: number }>;
export interface UrlResult {
  url: string;
  ok: boolean;
  status?: number;
  error?: string;
  attempts: number;
  ms: number;
}

export async function checkUrls(
  urls: readonly string[],
  check: Check,
  { concurrency = 5, timeoutMs = 3000, retries = 1, now = () => Date.now() }: { concurrency?: number; timeoutMs?: number; retries?: number; now?: () => number } = {},
): Promise<{ results: UrlResult[]; up: number; down: number }> {
  const results: UrlResult[] = new Array(urls.length);

  async function once(url: string): Promise<{ status?: number; error?: string }> {
    const ac = new AbortController();
    let timer: ReturnType<typeof setTimeout> | undefined;
    const timeout = new Promise<never>((_, reject) => {
      timer = setTimeout(() => {
        ac.abort();
        reject(new Error("timeout"));
      }, timeoutMs);
    });
    try {
      const r = await Promise.race([check(url, ac.signal), timeout]);
      return { status: r.status };
    } catch (err) {
      return { error: (err as Error).message };
    } finally {
      clearTimeout(timer);
    }
  }

  async function run(i: number) {
    const url = urls[i];
    const start = now();
    let attempts = 0;
    let last: { status?: number; error?: string } = {};
    while (attempts <= retries) {
      attempts++;
      last = await once(url);
      const retryable = last.error !== undefined || (last.status ?? 0) >= 500;
      if (!retryable) break; // 2xx/3xx/4xx — תשובה סופית; 404 לא יהפוך ל־200 בניסיון שני
    }
    const ok = last.status !== undefined && last.status < 400;
    results[i] = { url, ok, ...(last.status !== undefined ? { status: last.status } : {}), ...(last.error ? { error: last.error } : {}), attempts, ms: now() - start };
  }

  let next = 0;
  await Promise.all(Array.from({ length: Math.min(concurrency, urls.length) }, async () => {
    while (next < urls.length) await run(next++);
  }));
  const up = results.filter((r) => r.ok).length;
  return { results, up, down: results.length - up };
}

ובהגשה אמיתית — README: איך מריצים, מה ההחלטות (למה 4xx בלי retry), מה לא עשית ולמה, ובדיקות כמו של הבודק הזה.

⚠️ טעויות נפוצות
  • Promise.all(urls.map(check)) — אלף בקשות בבת אחת; השירות הנבדק (או הרשת שלך) לא יאהב את זה.
