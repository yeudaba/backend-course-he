P30-E26 · מתי AI, ואיך לבקש? 🧠 הבנה רמה 1

💡 רמז 1

שלוש שאלות לכל מצב: האם אני לומד עכשיו את הדבר הזה? האם אני יכול לבדוק את התשובה? ומה אני מדביק לצ'אט?

💡 רמז 2

בקשה טובה: הקשר (סטאק, גרסאות, מה כבר יש), מה בדיוק צריך, אילוצים, דוגמה של קלט ופלט — ובקשה לשינוי קטן, לא "את כל הפיצ'ר".

✅ פתרון
  1. לא, עוד לא. 4 דקות זה לא "נתקעתי". המאבק הוא הלמידה. אחרי 10–15 דקות של ניסיון אמיתי: רמז 1 ← רמז 2 ← ורק אז AI, ובקשה "תסביר לי למה זה לא עובד", לא "תתקן".
  2. כן. עבודה מכנית שקל לבדוק בעין. לבדוק שהנתונים עומדים באילוצים (UNIQUE, CHECK) ושה־seed רץ.
  3. כן, אבל קודם לנקות. מוחקים את הסיסמה מהכתובת (E28). ובחברה — רק בכלי שהחברה אישרה; יש חברות שאוסרות להדביק קוד לכלים חיצוניים.
  4. "כן, אבל" — בזהירות מירבית. קוד אבטחה הוא בדיוק המקום שבו AI כותב משהו שנראה נכון ושוכח בדיקת בעלות (E30). אם משתמשים — כותבים קודם את הבדיקות (403/404 למשתמש אחר), ומבינים כל שורה.
  5. לא — אלא אם המראיין אמר במפורש שמותר. וגם אז: מסבירים כל שורה בקול.

חלק ב׳, לדוגמה: "פרויקט NestJS 12 (CommonJS) עם Prisma 7 ו־PostgreSQL. יש TasksService עם findAll(userId). תוסיף ל־TasksController את GET /tasks?status= — status אחד מ־todo/doing/done, אחרת 400 (יש לנו ZodValidationPipe). רק המשימות של המשתמש המחובר (@CurrentUser()). תראה רק את ה־diff, ותסביר מה שינית."

⚠️ טעויות נפוצות
  • לבקש "את כל הפרויקט" — מקבלים הרבה קוד שאף אחד לא בדק, בסגנון שלא שלך, עם גרסאות שאולי ישנות.
  • להדביק .env או לוג מלא "כדי שיבין את ההקשר".

P30-E27 · בדיקות לקוד שה־AI כתב 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

חשוב על מקרי גבול: עמוד ראשון, עמוד אחרון, מספר פריטים שמתחלק בדיוק ושלא, אפס פריטים, pageSize מעל התקרה — ומה קורה ל־offset כשיש תקרה.

💡 רמז 2

45 פריטים, 20 בעמוד: offset של עמוד 1 ושל עמוד 2? כמה עמודים? יש עמוד הבא בעמוד 2? ובעמוד 2 של 40 פריטים?

✅ פתרון
// P30-E27: בדיקות לקוד שה־AI כתב. כל בדיקה — מקרה גבול שקל לפספס
import { test } from "node:test";
import assert from "node:assert/strict";
import { paginate } from "./P30-E27.ts";

test("עמוד ראשון ושני: offset מתחיל מ־0", () => {
  assert.deepEqual(paginate(45, 1, 20), { offset: 0, limit: 20, totalPages: 3, hasNext: true });
  assert.equal(paginate(45, 2, 20).offset, 20);
});
test("totalPages מעגל למעלה, ו־hasNext בעמוד האחרון false", () => {
  assert.equal(paginate(41, 1, 20).totalPages, 3);
  assert.equal(paginate(40, 2, 20).hasNext, false, "40 פריטים, עמוד 2 מתוך 2");
  assert.equal(paginate(41, 2, 20).hasNext, true);
});
test("בלי פריטים בכלל", () => {
  assert.deepEqual(paginate(0), { offset: 0, limit: 20, totalPages: 0, hasNext: false });
});
test("pageSize מוגבל ל־100", () => {
  assert.equal(paginate(1000, 1, 500).limit, 100);
  assert.equal(paginate(1000, 3, 500).offset, 200);
});
test("קלט לא תקין ← RangeError", () => {
  for (const [p, s] of [[0, 20], [-1, 20], [1.5, 20], [1, 0], [1, 2.5]]) {
    assert.throws(() => paginate(10, p, s), RangeError, `page=${p} pageSize=${s}`);
  }
});

כל בדיקה מכוונת לטעות אחרת: offset של עמוד 1 (מתחיל מ־0, לא מ־20), עיגול למעלה, hasNext בעמוד האחרון בדיוק, אפס פריטים, התקרה — וגם ה־offset אחרי התקרה (200 ולא 1000), וקלט לא שלם. זה מה שעוזר AI הכי נוטה לפספס: הוא כותב את המקרה הרגיל, ואת הגבולות — לפעמים.

⚠️ טעויות נפוצות
  • לבדוק רק את המקרה "הרגיל" (עמוד 2 מתוך 5) — כל הגרסאות השבורות עוברות אותו.
  • לבקש מה־AI לכתוב גם את הבדיקות לקוד שהוא עצמו כתב — הוא יבדוק את מה שהקוד עושה, לא את מה שהוא צריך לעשות. את החוזה כותב אתה.

P30-E28 · לנקות סודות לפני שמדביקים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

רשימה של כללים { type, re } עם הדגל g, ו־text.replace(re, fn) לכל אחד. כשצריך להשאיר חלק (המשתמש בכתובת, המילה Bearer) — קבוצות בסוגריים, ו־fn בונה מחדש.

💡 רמז 2

שורות .env: /^(\s*[A-Z0-9_]*(?:SECRET|PASSWORD|TOKEN|API_KEY)[A-Z0-9_]*\s*=\s*)(\S.*)$/gm — הדגל m הופך את ^ ו־$ לתחילת וסוף שורה.

✅ פתרון
// P30-E28
// מנקה טקסט לפני שמדביקים אותו לצ'אט של AI (או ל־issue, או ל־Slack): סודות לא יוצאים מהמחשב שלך
const RULES: { type: string; re: RegExp; keep?: (m: string, ...g: string[]) => string }[] = [
  // בלוק מפתח פרטי — מהשורה BEGIN ועד END
  { type: "private-key", re: /-----BEGIN [A-Z ]*PRIVATE KEY-----[\s\S]*?-----END [A-Z ]*PRIVATE KEY-----/g },
  // כתובת חיבור עם סיסמה: משאירים את המשתמש והשרת, מסתירים רק את הסיסמה
  { type: "url-password", re: /\b([a-z][a-z0-9+.-]*:\/\/[^\s:@/]+:)([^\s@/]+)(@)/gi, keep: (_m, a, _p, c) => `${a}[REDACTED:url-password]${c}` },
  { type: "jwt", re: /\beyJ[A-Za-z0-9_-]{5,}\.[A-Za-z0-9_-]{5,}\.[A-Za-z0-9_-]{5,}/g },
  { type: "api-key", re: /\bsk-[A-Za-z0-9_-]{16,}/g },
  { type: "aws-key", re: /\bAKIA[0-9A-Z]{16}\b/g },
  { type: "github-token", re: /\bgh[pousr]_[A-Za-z0-9]{30,}/g },
  { type: "bearer", re: /(\bBearer\s+)([A-Za-z0-9._~+/-]{8,}=*)/g, keep: (_m, a) => `${a}[REDACTED:bearer]` },
  // שורות של .env: KEY=value, כשהשם נשמע כמו סוד
  { type: "env-secret", re: /^(\s*[A-Z0-9_]*(?:SECRET|PASSWORD|PASSWD|TOKEN|API_KEY|PRIVATE_KEY)[A-Z0-9_]*\s*=\s*)(\S.*)$/gm, keep: (_m, a) => `${a}[REDACTED:env-secret]` },
];

export function redactForPrompt(text: string): { text: string; found: string[] } {
  const found = new Set<string>();
  let out = text;
  for (const { type, re, keep } of RULES) {
    out = out.replace(re, (...args) => {
      // ערך שכבר הוסתר (מכלל קודם) — לא מסתירים שוב
      if (String(args[0]).includes("[REDACTED:")) return args[0];
      found.add(type);
      return keep ? keep(...(args as [string, ...string[]])) : `[REDACTED:${type}]`;
    });
  }
  return { text: out, found: [...found].sort() };
}

הכלי הזה הוא רשת ביטחון, לא היתר: מה שלא מתאים לאף כלל (סיסמה בתוך JSON, נתוני לקוחות) עובר כמו שהוא. הכלל הראשון נשאר "לא מדביקים מה שלא צריך".

⚠️ טעויות נפוצות
  • להסתיר את כל הכתובת במקום רק את הסיסמה — ה־AI לא יכול לעזור עם "connection refused" אם הוא לא רואה host ופורט.
  • regex של JWT בלי אורך מינימלי — כל מילה שמתחילה ב־eyJ ויש בה שתי נקודות נמחקת.

P30-E29 · סקירה של diff שה־AI הציע 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שורת @@ -10,6 +10,5 @@ אומרת: החלק מתחיל בשורה 10 בקובץ הישן ובשורה 10 בחדש. משם: שורה שמתחילה ב־+ מקדמת רק את המונה החדש, - רק את הישן, ורווח — את שניהם.

💡 רמז 2

שורות +++ ו־--- מתחילות גם הן ב־+ ו־−. לבדוק אותן לפני שבודקים שורות שנוספו או נמחקו.

✅ פתרון
// P30-E29
// עובר על diff (הפורמט של git diff) שעוזר AI הציע, ומסמן שינויים שחייבים עין אנושית
export interface Finding {
  file: string;
  line: number; // בשורה שנוספה — מספר השורה בקובץ החדש; בשורה שנמחקה — בקובץ הישן
  rule: "test-disabled" | "assertion-removed" | "new-dependency" | "dangerous-eval" | "type-escape";
}

export function reviewDiff(diff: string): Finding[] {
  const findings: Finding[] = [];
  let file = "";
  let oldLine = 0;
  let newLine = 0;
  for (const raw of diff.split("\n")) {
    if (raw.startsWith("diff --git")) continue;
    if (raw.startsWith("+++ ")) {
      file = raw.slice(4).replace(/^b\//, "");
      continue;
    }
    if (raw.startsWith("--- ")) continue;
    const hunk = /^@@ -(\d+)(?:,\d+)? \+(\d+)(?:,\d+)? @@/.exec(raw);
    if (hunk) {
      oldLine = +hunk[1];
      newLine = +hunk[2];
      continue;
    }
    if (!file) continue;
    const add = (rule: Finding["rule"], line: number) => findings.push({ file, line, rule });
    if (raw.startsWith("+")) {
      const code = raw.slice(1);
      // AI "מתקן" בדיקה שנכשלת בכך שהוא מכבה אותה
      if (/\b(?:test|it|describe)\.(?:skip|only)\s*\(/.test(code)) add("test-disabled", newLine);
      if (/\beval\s*\(|\bnew Function\s*\(/.test(code)) add("dangerous-eval", newLine);
      if (/@ts-ignore|@ts-expect-error|\bas any\b/.test(code)) add("type-escape", newLine);
      // חבילה חדשה: לבדוק שהיא קיימת, מי מתחזק אותה, ושבאמת צריך אותה
      if (/(^|\/)package\.json$/.test(file) && /^\s*"(?!version")[^"]+"\s*:\s*"[\^~>=<]*\d/.test(code)) add("new-dependency", newLine);
      newLine++;
    } else if (raw.startsWith("-")) {
      // בדיקה שאיבדה assertion — "עוברת" כי היא כבר לא בודקת כלום
      if (/\bassert\b|\bexpect\s*\(/.test(raw.slice(1))) add("assertion-removed", oldLine);
      oldLine++;
    } else {
      oldLine++;
      newLine++;
    }
  }
  return findings;
}
⚠️ טעויות נפוצות
  • לספור את שורות ה־+++/--- כשורות שנוספו/נמחקו.
  • לקדם את שני המונים בכל שורה — מספרי השורות "זזים" אחרי המחיקה הראשונה.
  • /skip/ בלי ההקשר — items.skip או משתנה בשם skipped מסומנים בטעות.

זה לא מחליף קריאה. אבל אלה בדיוק השינויים שקל לפספס ב־diff של 300 שורות: "הבדיקות עוברות" — כי ה־AI כיבה את זו שנכשלה.

P30-E30 · הקוד שה־AI הציע: שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

קרא את ה־SQL שנבנה כשמישהו שולח ?status=x' OR '1'='1. ומה אם ?sort=password_hash?

💡 רמז 2

בפרק 21 (OWASP API Top 10): הבעיה הראשונה ברשימה היא בדיוק מה שחסר כאן ב־WHERE.

✅ פתרון
// P30-E30
// GET /tasks?status=&sort=&order= — אחרי תיקון של הקוד שה־AI הציע
interface Db {
  query(text: string, params: unknown[]): Promise<{ rows: unknown[] }>;
}

// עמודות שמותר למיין לפיהן. שם עמודה לא יכול להיות פרמטר ($2) — לכן רשימה סגורה
const SORTS: Record<string, string> = { created: "created_at", due: "due_date", title: "title" };

export async function listTasks(
  db: Db,
  userId: number,
  { status, sort = "created", order = "asc" }: { status?: string; sort?: string; order?: string } = {}
) {
  const column = SORTS[sort];
  if (!column) throw new RangeError(`אי אפשר למיין לפי ${sort}`);
  if (order !== "asc" && order !== "desc") throw new RangeError("order: asc או desc");
  // תקלה 1: בלי user_id — כל משתמש ראה את המשימות של כולם
  const params: unknown[] = [userId];
  let sql = "SELECT id, title, status, due_date FROM tasks WHERE user_id = $1";
  if (status !== undefined) {
    params.push(status); // תקלה 2: ערך מהמשתמש — רק כפרמטר, אף פעם לא בתוך הטקסט
    sql += ` AND status = $${params.length}`;
  }
  sql += ` ORDER BY ${column} ${order.toUpperCase()}`; // תקלה 3: רק מהרשימה הסגורה
  const { rows } = await db.query(sql, params);
  return rows;
}
  1. אין WHERE user_id — כל משתמש מחובר רואה את המשימות של כולם (Broken Object Level Authorization, מקום 1 ב־OWASP API Top 10).
  2. status בתוך הטקסט — SQL injection. x' OR '1'='1 מחזיר הכול, ומשהו גרוע יותר מוחק. ערך מהמשתמש — רק כפרמטר ($2).
  3. sort ו־order בלי רשימה סגורה — columns[sort] ?? sort נראה כמו הגנה, אבל כל ערך לא מוכר עובר כמו שהוא. שם עמודה וכיוון מיון לא יכולים להיות פרמטרים, ולכן רק ערכים מרשימה שאתה כתבת.
⚠️ טעויות נפוצות
  • "לנקות" את status עם replace של גרשיים — תמיד יש עוד דרך. פרמטרים, לא ניקוי.
  • לתקן את ה־injection ולשכוח את ה־user_id: הקוד "מאובטח" ועדיין מחזיר משימות של אחרים. אוטומציה לא תתפוס את זה; רק מי שיודע מה ה־endpoint צריך לעשות.
