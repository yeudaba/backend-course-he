## עברית
בניתי API לחנות אונליין של ציוד קפה — הפרויקט המרכזי שלי. לקוחות נרשמים, מחפשים מוצרים, מוסיפים לעגלה ומזמינים; מנהל מנהל את הקטלוג ואת המלאי. זה NestJS עם PostgreSQL ו־Prisma, רץ ב־Docker, ועולה לאוויר אוטומטית מ־GitHub Actions אחרי שכל הבדיקות עוברות.

החלק שהכי מעניין אותי הוא הנכונות. נניח שנשארו 3 יחידות, ו־20 לקוחות לוחצים "הזמן" באותה שנייה. בגרסה הראשונה, שבדקה את המלאי ואז עדכנה, נמכרו 12 יחידות — מצאתי את זה בבדיקה שמריצה 20 הזמנות במקביל. תיקנתי עם UPDATE מותנה בתוך טרנזקציה, כי ככה המסד עצמו מסדר את הבקשות ורק שלוש מצליחות, ובנוסף שמתי CHECK על המלאי כרשת ביטחון. אותו רעיון בתשלום: Idempotency-Key, כך שלחיצה כפולה לא מחייבת פעמיים.

אחר כך הוספתי Redis: cache לקטלוג, שהוריד חיפוש מכ־80 מילישניות ל־3, ותור למייל אישור, כדי שהלקוח לא יחכה לשרת מיילים. ההזמנות שלא שולמו מתבטלות לבד אחרי חצי שעה, והמלאי חוזר.

עם עוד זמן הייתי מוסיף outbox, כדי שתשלום ומייל האישור יירשמו באותה טרנזקציה, ובדיקת עומס אמיתית לפני מבצעים. הקוד, ה־README עם ההחלטות, וקישור חי — בפרופיל שלי.

## English
My main project is an API for an online coffee-equipment store. Customers sign up, search products, fill a cart and place orders; an admin manages the catalog and the stock. It's NestJS with PostgreSQL and Prisma, it runs in Docker, and GitHub Actions deploys it only after all the tests pass.

The part I find most interesting is correctness. Say there are 3 units left and 20 customers click "order" in the same second. My first version checked the stock and then updated it, and it sold 12 units. I found that with a test that sends 20 orders in parallel. I fixed it with a conditional UPDATE inside a transaction, because that way the database itself orders the requests and exactly three succeed, plus a CHECK constraint on the stock as a safety net. Payments use the same idea: an Idempotency-Key, so a double click never charges twice.

Then I added Redis: a cache for the catalog, which took search from about 80 milliseconds to 3, and a queue for the confirmation email, so the customer doesn't wait for a mail server. Unpaid orders cancel themselves after thirty minutes and the stock comes back.

With more time, I would add an outbox, so the payment and the confirmation email are recorded in the same transaction, and a real load test before big sales. The code, a README with my technical decisions, and a live demo are all on my GitHub profile.
