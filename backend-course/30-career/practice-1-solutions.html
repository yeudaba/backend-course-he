💡 רמז 2

אחת הבעיות היא לא "נראות" — היא אבטחה.

✅ פתרון
  1. .env ב־repo ציבורי — קודם כול: לבטל את הסודות (סיסמת מסד, JWT_SECRET, מפתחות) ולייצר חדשים, ואז להוציא את הקובץ ולהוסיף ל־.gitignore. מחיקה ב־commit חדש לא מספיקה — הוא בהיסטוריה (E08).
  2. מה מוצמד — 2–4 repos בלבד: הפרויקטים שאתה רוצה שיראו. test ו־new-folder — להסתיר (archive או private).
  3. README של הפרויקט הגדול — הוא הדבר היחיד שרוב המראיינים יקראו: משפט מה המערכת עושה, קישור חי, הרצה ב־3 פקודות, החלטות טכניות (פרויקט 3, שלב 4).
  4. תיאור, topics וקישור ל־repo (E07) — מופיעים בכרטיס המוצמד, לפני שנכנסים.
  5. README לפרופיל — 5 שורות: מי אתה, מה בנית (עם קישורים), איך ליצור קשר (E06). והיסטוריה: "final final 2" לא נמחק, אבל מכאן — הודעות שאומרות מה השתנה (E09).
⚠️ טעויות נפוצות

// P30-E08
// לפני שה־repo הופך לציבורי (ומראיינים פותחים אותו): סריקה לסודות. סוד שעלה ל־GitHub — נחשב דלוף,
// גם אם מחקת אותו ב־commit הבא (הוא בהיסטוריה). מבטלים אותו ומייצרים חדש
export interface Finding {
  path: string;
  line: number;
  kind: "env-file" | "anthropic-key" | "aws-key" | "private-key" | "db-password" | "jwt-secret";
}

const PLACEHOLDER = /^(\$\{.*\}|<.*>|your[_-]?\w*|password|changeme|secret|xxx+|\*+|)$/i;

export function findSecrets(files: readonly { path: string; content: string }[]): Finding[] {
  const out: Finding[] = [];
  for (const f of files) {
    if (/(^|\/)node_modules\//.test(f.path)) continue;
    const base = f.path.split("/").pop()!;
    const isExample = /\.example$|\.sample$|\.template$/.test(base);
    if (/^\.env(\..+)?$/.test(base) && !isExample) out.push({ path: f.path, line: 0, kind: "env-file" });
    f.content.split("\n").forEach((text, i) => {
      const line = i + 1;
      if (/sk-ant-[A-Za-z0-9_-]{10,}/.test(text)) out.push({ path: f.path, line, kind: "anthropic-key" });
      if (/\bAKIA[0-9A-Z]{16}\b/.test(text)) out.push({ path: f.path, line, kind: "aws-key" });
      if (/-----BEGIN [A-Z ]*PRIVATE KEY-----/.test(text)) out.push({ path: f.path, line, kind: "private-key" });
      const db = /postgres(?:ql)?:\/\/[^:\s/@]+:([^@\s]+)@/.exec(text);
      if (db && !PLACEHOLDER.test(db[1])) out.push({ path: f.path, line, kind: "db-password" });
      const jwt = /^\s*JWT_SECRET\s*=\s*["']?([^"'\s#]*)/.exec(text);
      if (jwt && !isExample && !PLACEHOLDER.test(jwt[1])) out.push({ path: f.path, line, kind: "jwt-secret" });
    });
  }
  return out;
}

בפועל: gitleaks או trufflehog סורקים גם את ההיסטוריה, ו־GitHub עצמו מתריע על מפתחות מוכרים (secret scanning). אבל להבין מה הם מחפשים — זה מה שמונע את הטעות מלכתחילה.

⚠️ טעויות נפוצות

P30-E09 · הודעות commit 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

message.split("\n"); שורה 0 היא הנושא, שורה 1 חייבת להיות ריקה (אם יש עוד).

💡 רמז 2

"מילה אחת" — subject.split(/\s+/).length < 2.

✅ פתרון
// P30-E09
// היסטוריית commits היא חלק מתיק העבודות: מראיין שפותח את ה־repo רואה "fix", "wip", "asdf" — או סיפור.
// הכללים המקובלים: שורת נושא קצרה שאומרת מה השתנה, בלי נקודה בסוף; שורה ריקה; גוף שמסביר למה
const VAGUE = /^(wip|fix(es|ed)?|update[sd]?|changes?|stuff|misc|asdf+|test|tmp|temp|\.+|commit|final|done|more)$/i;

export function lintCommit(message: string): string[] {
  const problems: string[] = [];
  const lines = message.replace(/\r\n/g, "\n").replace(/\n+$/, "").split("\n");
  const subject = (lines[0] ?? "").trim();
  if (!subject) return ["שורת נושא ריקה"];
  if (subject.length > 72) problems.push(`שורת נושא ארוכה (${subject.length} תווים, עד 72)`);
  if (/[.。]$/.test(subject)) problems.push("נקודה בסוף שורת הנושא");
  if (VAGUE.test(subject) || subject.split(/\s+/).length < 2) problems.push("שורת נושא לא אומרת מה השתנה");
  if (lines.length > 1 && lines[1].trim() !== "") problems.push("חסרה שורה ריקה בין הנושא לגוף");
  lines.slice(2).forEach((l, i) => {
    if (l.length > 100) problems.push(`שורה ${i + 3} בגוף ארוכה מ־100 תווים`);
  });
  return problems;
}

אפשר להריץ את זה אוטומטית ב־hook של commit-msg (למשל עם husky ו־commitlint). ובקבוצות רבות נהוג Conventional Commits: feat: …, fix: ….

⚠️ טעויות נפוצות
  • להיתקע על "מושלם" — commits קטנים עם הודעות סבירות עדיפים על commit ענק אחד עם הודעה מושלמת.

💡 רמז 1

💡 רמז 2

✅ פתרון
// P30-E20
export interface Finding {
  path: string;
  line: number;
  kind: "env-file" | "anthropic-key" | "db-password";
}

export function findSecrets(files: readonly { path: string; content: string }[]): Finding[] {
  const out: Finding[] = [];
  for (const f of files) {
    const base = f.path.split("/").pop()!;
    // תקלה 1: היה base === ".env" ← .env.production ו־.env.local עברו בלי התראה
    if (/^\.env(\..+)?$/.test(base) && !base.endsWith(".example")) out.push({ path: f.path, line: 0, kind: "env-file" });
    f.content.split("\n").forEach((text, i) => {
      // תקלה 2: מספרי השורות התחילו מ־0 ← "שורה 0" בהודעה, והשורה הלא נכונה בעורך
      if (/sk-ant-[A-Za-z0-9_-]{10,}/.test(text)) out.push({ path: f.path, line: i + 1, kind: "anthropic-key" });
      const db = /postgres(?:ql)?:\/\/[^:\s/@]+:([^@\s]+)@/.exec(text);
      // תקלה 3: כל כתובת עם סיסמה דווחה — גם YOUR_PASSWORD ב־.env.example ← אלף התראות שווא, ואף אחד לא קורא אותן
      if (db && !/^(\$\{.*\}|<.*>|your[_-]?\w*|password|changeme)$/i.test(db[1])) out.push({ path: f.path, line: i + 1, kind: "db-password" });
    });
  }
  return out;
}

  • סורק עם הרבה התראות שווא — אנשים מפסיקים לקרוא אותו, ואז הוא לא שווה כלום גם כשהוא צודק.
