P30-E69 · שאלות ההמשך שיבואו 🧠 הבנה רמה 1

💡 רמז 1

"Why not…?", "What if…?", "How did you test…?".

💡 רמז 2

"לא עשיתי" + "ככה הייתי עושה" — זו תשובה טובה.

✅ פתרון
  • "Why not SELECT … FOR UPDATE?" — "It works too, it locks the row for the transaction. The conditional UPDATE is one statement, no explicit lock — simpler for this case."
  • "How did you test it?" — "A test with 20 parallel requests for 3 units; it failed on the old code (12 sold) and passes now."
  • "What if the payment fails after you decrement stock?" — "The decrement and the order are in one transaction; payment is a separate step with a reservation timeout — I'd release the stock if it expires."
  • "How would this work with 10 servers?" — "The same — the database enforces it, not the server. With a cache in front, stock must never be read from the cache for the decision." (אם לא בדקת — אמור.)
⚠️ טעויות נפוצות
  • לנחש תשובה בביטחון על משהו שלא בדקת — עדיף "I haven't tested that; I'd expect … and I'd verify by …".

## עברית
בניתי API לחנות אונליין של ציוד קפה — הפרויקט המרכזי שלי. לקוחות נרשמים, מחפשים מוצרים, מוסיפים לעגלה ומזמינים; מנהל מנהל את הקטלוג ואת המלאי. זה NestJS עם PostgreSQL ו־Prisma, רץ ב־Docker, ועולה לאוויר אוטומטית מ־GitHub Actions אחרי שכל הבדיקות עוברות.

החלק שהכי מעניין אותי הוא הנכונות. נניח שנשארו 3 יחידות, ו־20 לקוחות לוחצים "הזמן" באותה שנייה. בגרסה הראשונה, שבדקה את המלאי ואז עדכנה, נמכרו 12 יחידות — מצאתי את זה בבדיקה שמריצה 20 הזמנות במקביל. תיקנתי עם UPDATE מותנה בתוך טרנזקציה, כי ככה המסד עצמו מסדר את הבקשות ורק שלוש מצליחות, ובנוסף שמתי CHECK על המלאי כרשת ביטחון. אותו רעיון בתשלום: Idempotency-Key, כך שלחיצה כפולה לא מחייבת פעמיים.

אחר כך הוספתי Redis: cache לקטלוג, שהוריד חיפוש מכ־80 מילישניות ל־3, ותור למייל אישור, כדי שהלקוח לא יחכה לשרת מיילים. ההזמנות שלא שולמו מתבטלות לבד אחרי חצי שעה, והמלאי חוזר.

עם עוד זמן הייתי מוסיף outbox, כדי שתשלום ומייל האישור יירשמו באותה טרנזקציה, ובדיקת עומס אמיתית לפני מבצעים. הקוד, ה־README עם ההחלטות, וקישור חי — בפרופיל שלי.

## English
My main project is an API for an online coffee-equipment store. Customers sign up, search products, fill a cart and place orders; an admin manages the catalog and the stock. It's NestJS with PostgreSQL and Prisma, it runs in Docker, and GitHub Actions deploys it only after all the tests pass.

The part I find most interesting is correctness. Say there are 3 units left and 20 customers click "order" in the same second. My first version checked the stock and then updated it, and it sold 12 units. I found that with a test that sends 20 orders in parallel. I fixed it with a conditional UPDATE inside a transaction, because that way the database itself orders the requests and exactly three succeed, plus a CHECK constraint on the stock as a safety net. Payments use the same idea: an Idempotency-Key, so a double click never charges twice.

Then I added Redis: a cache for the catalog, which took search from about 80 milliseconds to 3, and a queue for the confirmation email, so the customer doesn't wait for a mail server. Unpaid orders cancel themselves after thirty minutes and the stock comes back.

With more time, I would add an outbox, so the payment and the confirmation email are recorded in the same transaction, and a real load test before big sales. The code, a README with my technical decisions, and a live demo are all on my GitHub profile.

// P30-E70: כמה זמן ייקח להגיד את זה
export function speakingTime(text: string, wpm = 130): { words: number; seconds: number; verdict: "short" | "ok" | "long" } {
  if (!(wpm > 0)) throw new RangeError("wpm חייב להיות חיובי");
  const words = text.split(/\s+/).filter((w) => /[\p{L}\p{N}]/u.test(w)).length;
  const seconds = Math.round((words / wpm) * 60);
  return { words, seconds, verdict: seconds < 90 ? "short" : seconds > 150 ? "long" : "ok" };
}

130 מילים בדקה — קצב דיבור רגוע. רוב האנשים בראיון מדברים מהר יותר; ההקלטה (שיעור 3) תגיד לך את הקצב שלך.

// P30-E71: בדיקת מבנה STAR
const LABEL = /^\s*(s|t|a|r|situation|task|action|result):\s*(.*)$/i;
const countWords = (s: string) => s.split(/\s+/).filter((w) => /[\p{L}\p{N}]/u.test(w)).length;

export function starCheck(answer: string) {
  const parts: { key: string; text: string }[] = [];
  for (const line of answer.split("\n")) {
    const m = LABEL.exec(line);
    if (m) parts.push({ key: m[1][0].toUpperCase(), text: m[2] });
    else if (parts.length) parts.at(-1)!.text += "\n" + line;
  }
  const order = "STAR";
  const keys = parts.map((p) => p.key);
  const missing = [...order].filter((k) => !keys.includes(k));
  const idx = keys.map((k) => order.indexOf(k));
  const outOfOrder = idx.some((v, i) => i > 0 && v <= idx[i - 1]);
  const total = parts.reduce((s, p) => s + countWords(p.text), 0);
  const action = parts.filter((p) => p.key === "A").reduce((s, p) => s + countWords(p.text), 0);
  return { missing, outOfOrder, actionShare: total ? Math.round((action / total) * 100) / 100 : 0 };
}

‏Action הוא "רוב התשובה" — מתחת ל־40% בדרך כלל אומר יותר מדי רקע ומעט מה אתה עשית.

⚠️ טעויות נפוצות
  • ‏/^A/ בלי נקודתיים — כל שורה שמתחילה ב־"After" או "And" נחשבת Action.

// P30-E72: "we" או "I"
const WE = new Set(["we", "we're", "we've", "our", "us", "אנחנו", "אנו", "שלנו"]);
const I = new Set(["i", "i'm", "i've", "my", "me", "אני", "שלי"]);

export function weVsI(text: string): { we: number; i: number; verdict: "say_i" | "more_we" | "ok" } {
  let we = 0;
  let i = 0;
  for (const w of text.toLowerCase().split(/[^\p{L}']+/u)) {
    if (WE.has(w)) we++;
    else if (I.has(w)) i++;
  }
  return { we, i, verdict: i === 0 && we > 0 ? "say_i" : we > i ? "more_we" : "ok" };
}

"we" בסיפור של צוות זה טבעי — אבל המראיין צריך לשמוע מה החלק שלך. בעברית, "בדקנו" ו"בדקתי" לא נתפסים כאן — זה דורש ניתוח פעלים.

// P30-E73: מילות מילוי בתמליל
const tokens = (s: string) => s.toLowerCase().match(/[\p{L}']+/gu) ?? [];

export function fillerStats(transcript: string, fillers: string[]) {
  const words = tokens(transcript);
  const counts = fillers.map((f) => {
    const t = tokens(f);
    let count = 0;
    if (t.length) {
      for (let i = 0; i + t.length <= words.length; i++) {
        if (t.every((w, j) => words[i + j] === w)) count++;
      }
    }
    return { filler: f, count };
  });
  const total = counts.reduce((s, c) => s + c.count, 0);
  const top = counts
    .filter((c) => c.count > 0)
    .sort((a, b) => b.count - a.count)
    .slice(0, 3);
  return { words: words.length, fillers: total, per100: words.length ? Math.round((total / words.length) * 1000) / 10 : 0, top };
}

// P30-E74: ציון עצמי לתשובה
export function scoreAnswer(answer: string, rubric: { id: string; any: string[] }[]) {
  const a = answer.toLowerCase();
  const missing = rubric.filter((r) => !r.any.some((k) => a.includes(k.toLowerCase()))).map((r) => r.id);
  return { score: rubric.length - missing.length, max: rubric.length, missing };
}

💡 רמז 2

מיינו את האינדקסים לפי שארית יורדת (‏sort יציב שומר את הסדר בתיקו).

✅ פתרון
// P30-E75: לחלק שתי דקות בין החלקים
export function allocateSeconds(weights: Record<string, number>, total: number): Record<string, number> {
  const entries = Object.entries(weights);
  if (!Number.isInteger(total) || total < 0) throw new RangeError("total חייב להיות שלם אי־שלילי");
  if (entries.some(([, w]) => !(typeof w === "number" && w >= 0))) throw new RangeError("משקל לא תקין");
  const sum = entries.reduce((s, [, w]) => s + w, 0);
  if (sum === 0) throw new RangeError("סכום המשקלים 0");
  const exact = entries.map(([, w]) => (w * total) / sum);
  const base = exact.map(Math.floor);
  let left = total - base.reduce((s, x) => s + x, 0);
  const byRemainder = exact.map((x, i) => i).sort((a, b) => exact[b] - base[b] - (exact[a] - base[a]));
  for (const i of byRemainder) {
    if (left === 0) break;
    base[i]++;
    left--;
  }
  return Object.fromEntries(entries.map(([k], i) => [k, base[i]]));
}
⚠️ טעויות נפוצות

// P30-E76: בנק סיפורים לשאלות התנהגותיות
type Item = { id: string; tags: string[] };

export function assignStories(questions: Item[], stories: Item[], maxUses = 2): Record<string, string | null> {
  const uses = new Map<string, number>(stories.map((s) => [s.id, 0]));
  const out: Record<string, string | null> = {};
  for (const q of questions) {
    let best: { s: Item; shared: number; used: number } | null = null;
    for (const s of stories) {
      const shared = s.tags.filter((t) => q.tags.includes(t)).length;
      const used = uses.get(s.id)!;
      if (shared === 0 || used >= maxUses) continue;
      if (!best || shared > best.shared || (shared === best.shared && used < best.used)) best = { s, shared, used };
    }
    out[q.id] = best ? best.s.id : null;
    if (best) uses.set(best.s.id, best.used + 1);
  }
  return out;
}

שימוש: לראות אילו שאלות נשארו null — שם צריך סיפור חדש, לפני הראיון ולא בזמנו.

ב־REPEATABLE READ, מה קורה כששתי טרנזקציות מעדכנות אותה שורה?

✅ פתרון

"PostgreSQL defaults to READ COMMITTED: each statement sees data committed before it started, so no dirty reads. It doesn't prevent two transactions from reading the same stock and both writing — that's a lost update, and that's exactly what happened. // P30-E80: "12 מתוך 3" — לשחזר בקוד
type Store = { read(): Promise<number>; write(v: number): Promise<void>; decrementIfAvailable(): Promise<boolean> };

export function createStore(stock: number, delayMs: number): Store {
  let current = stock;
  const wait = () => new Promise<void>((r) => setTimeout(r, delayMs));
  return {
    async read() {
      await wait();
      return current;
    },
    async write(v: number) {
      await wait();
      current = v;
    },
    async decrementIfAvailable() {
      await wait();
      if (current < 1) return false; // הבדיקה והכתיבה — באותו צעד, בלי await ביניהן
      current--;
      return true;
    },
  };
}

export async function naiveBuy(store: Store): Promise<boolean> {
  const stock = await store.read();
  if (stock < 1) return false;
  await store.write(stock - 1); // בין ה־read ל־write — כל הקונים האחרים כבר קראו
  return true;
}

export function safeBuy(store: Store): Promise<boolean> {
  return store.decrementIfAvailable();
}

export async function simulate(buy: (s: Store) => Promise<boolean>, stock: number, buyers: number, delayMs: number) {
  const store = createStore(stock, delayMs);
  const results = await Promise.all(Array.from({ length: buyers }, () => buy(store)));
  return { sold: results.filter(Boolean).length, finalStock: await store.read() };
}

הריצו simulate(naiveBuy, 3, 20, 5): כל 20 קוראים "3", כולם "קונים", והמלאי הסופי 2. זה בדיוק הסיפור — ועכשיו אתה יכול להראות אותו בשורה אחת.

⚠️ טעויות נפוצות

// P30-E81: המספרים של תקלה, מתוך הלוגים
type Incident = { errors: number; firstErrorAt: string | null; lastErrorAt: string | null; minutes: number; peakPerMinute: number; fixedBy: string | null };

export function incidentNumbers(lines: string[]): Incident {
  const errors: number[] = [];
  const deploys: { time: number; version: string }[] = [];
  for (const line of lines) {
    let o: any;
    try {
      o = JSON.parse(line);
    } catch {
      continue;
    }
    if (!o || typeof o.time !== "number") continue;
    if (o.level >= 50) errors.push(o.time);
    if (o.msg === "deploy") deploys.push({ time: o.time, version: String(o.version) });
  }
  if (errors.length === 0) return { errors: 0, firstErrorAt: null, lastErrorAt: null, minutes: 0, peakPerMinute: 0, fixedBy: null };
  const first = Math.min(...errors);
  const last = Math.max(...errors);
  const perMinute = new Map<number, number>();
  for (const t of errors) perMinute.set(Math.floor(t / 60000), (perMinute.get(Math.floor(t / 60000)) ?? 0) + 1);
  const fix = deploys.find((d) => d.time >= first && d.time <= last);
  return {
    errors: errors.length,
    firstErrorAt: new Date(first).toISOString(),
    lastErrorAt: new Date(last).toISOString(),
    minutes: Math.ceil((last - first) / 60000),
    peakPerMinute: Math.max(...perMinute.values()),
    fixedBy: fix ? fix.version : null,
  };
}

// P30-E82: O(?) מתוך מדידות
type Cls = "O(1)" | "O(log n)" | "O(n)" | "O(n log n)" | "O(n^2)";

const F: [Cls, (n: number) => number][] = [
  ["O(1)", () => 1],
  ["O(log n)", (n) => Math.log2(n)],
  ["O(n)", (n) => n],
  ["O(n log n)", (n) => n * Math.log2(n)],
  ["O(n^2)", (n) => n * n],
];

export function growthClass(ns: number[], ops: number[]): Cls {
  if (ns.length !== ops.length || ns.length < 2) throw new RangeError("צריך לפחות שתי מדידות, באותו אורך");
  if (ns.some((n) => !(n >= 2)) || ops.some((o) => !(o > 0))) throw new RangeError("n ≥ 2 ו־ops חיובי");
  let best: Cls = F[0][0];
  let bestSpread = Infinity;
  for (const [name, f] of F) {
    const ratios = ns.map((n, i) => ops[i] / f(n));
    const spread = Math.max(...ratios) / Math.min(...ratios);
    if (spread < bestSpread) {
      best = name;
      bestSpread = spread;
    }
  }
  return best;
}

⚠️ טעויות נפוצות
  • להסיק מתוך שתי נקודות קרובות (n=100, n=120) — כל המועמדים נראים דומים. צריך טווח רחב.
