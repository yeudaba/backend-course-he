מה שונה בפרק הזה: בחלק מהתרגילים אתה כותב מסמכים — README לפרופיל, קורות חיים, LinkedIn, הסבר הפרויקט — כקבצי Markdown ב־30-career/starter. הבודק לא שופט סגנון; הוא תופס את מה שמגייסים רואים מיד (placeholders, אורך, קישורים חסרים, מבנה). אחרי שעבר — מעתיקים לאתר עצמו. הפתרונות הם דוגמאות של דמות בדויה, לא תבנית להעתקה.

🎯 בסוף הפרק תדע
  • פרופיל GitHub שמגייס מבין ב־30 שניות: README אישי, שני פרויקטים מוצמדים, repos נקיים מסודות.
  • קורות חיים חד־עמודיים באנגלית ופרופיל LinkedIn — עם מה שבנית ומדדת בקורס.
  • להסביר את הפרויקט בשתי דקות, בעברית ובאנגלית, ולענות על שאלות התנהגותיות ב־STAR.
  • שלוש סימולציות ראיון: שאלות על הפרויקט, שאלת קוד, שאלת SQL.
  • לעבוד עם עוזר קוד AI כמו מקצוען: הקשר, שינוי קטן, בדיקות שאתה כתבת — ולדבר על זה בראיון.
  • חיפוש עבודה כתהליך: מתי מתחילים, איפה מחפשים, מעקב, מטלות בית — ומה עושים עם דחייה.

🤔 למה צריך את זה?

כתבת שלושה פרויקטים, מאות תרגילים, ומערכת שרצה באוויר. אבל מגייסת רואה קודם PDF של עמוד אחד ופרופיל GitHub — לפני ששורת קוד אחת שלך נקראת. ומראיין שואל "ספר לי על הפרויקט" — ושתי הדקות הבאות קובעות אם השיחה תמשיך לקוד. הפרק האחרון הוא על הדרך מ"אני יודע" ל"הם יודעים שאני יודע". ולפי האפיון: לא מחכים לסוף. ברגע שפרויקט הדגל באוויר עם README טוב — מתחילים להגיש. הפרקים 26, 28 ו־29 לא תנאי.
