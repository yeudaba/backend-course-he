3. המסד: Neon

  1. ב־neon.com — כניסה עם GitHub, ו־New Project: שם tasks-api, הגרסה העדכנית של PostgreSQL שמוצעת (18 אם יש; עם 17 הפרויקט עובד בדיוק אותו דבר), ואזור קרוב: Frankfurt (AWS eu-central-1).
  2. Connect ← העתק את ה־connection string. הוא נראה כך: postgresql://neondb_owner:…@ep-….eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require.
  3. migrations, פעם ראשונה, מה־Mac (בהמשך — ה־CI):
% DATABASE_URL='postgresql://neondb_owner:…@ep-….neon.tech/neondb?sslmode=require&channel_binding=require' npx prisma migrate deploy

(מרכאות בודדות — יש בכתובת &, שה־shell מבין כ"הרץ ברקע".)

4. השרת: Render

  1. ב־render.com — כניסה עם GitHub, ו־New ← Web Service ← בחר את ה־repo tasks-api.
  2. Render מזהה את ה־Dockerfile. אזור: Frankfurt (קרוב ל־Neon — כל שאילתה עוברת בין השניים). Instance type: Free.
  3. Environment Variables:
    • DATABASE_URL — מ־Neon.
    • JWT_SECRET — חדש, לא זה של הפיתוח: node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))".
    • CORS_ORIGINS — הכתובת של הדף (סעיף 6), למשל https://tasks-web.onrender.com. עד אז — אפשר https://example.com; השרת דורש ערך https תקין כדי לעלות.
    • TRUST_PROXY = 1.
    (NODE_ENV=production כבר ב־image; PORT ו־RENDER_GIT_COMMIT — Render מגדירה לבד.)
  4. Health Check Path: /ready. Auto-Deploy: כבוי — ה־CI מחליט מתי (אחרי בדיקות ו־migrations).
  5. Create. ה־deploy הראשון לוקח כמה דקות (build של ה־image). בסוף: https://tasks-api-….onrender.com/docs — Swagger, חי.

ואם ה־deploy נכשל — Logs בדף ה־service. הלוגים הם ה־JSON מפרק 24, וההודעה של loadServerConfig אומרת בדיוק איזה משתנה חסר.

5. לחבר: GitHub ← Render

  1. ב־Render, Settings של ה־service ← Deploy Hook ← העתק.
  2. ב־GitHub, Settings של ה־repo ← Secrets and variables ← Actions:
    • Secrets: DATABASE_URL (של Neon), RENDER_DEPLOY_HOOK_URL.
    • Variables: PRODUCTION_URL = https://tasks-api-….onrender.com.
  3. (רשות) Settings ← Environments ← production: אפשר להגביל ל־branch main, או לדרוש אישור לפני deploy.
  4. שינוי קטן, commit, push ל־main — ובלשונית Actions: test ✓ docker ✓ ← deploy: migrations, deploy hook, ובדיקת העשן מחכה ל־commit החדש. כמה דקות, ו־✓.

מעכשיו: כל merge ל־main מגיע לאוויר לבד — רק אם עבר בדיקות, ורק אחרי ה־migrations. curl https://tasks-api-….onrender.com/version מראה בדיוק איזה commit רץ.

6. (רשות) הדף

ב־web/index.html: <meta name="api-url" content="https://tasks-api-….onrender.com">. ב־Render: New ← Static Site ← אותו repo, Publish Directory: web, בלי build command. את הכתובת שלו — ל־CORS_ORIGINS של ה־API. עכשיו יש לך קישור שמראיין יכול ללחוץ עליו, להירשם וליצור משימה.

💼 בעולם העבודה

"איך הקוד שלכם מגיע לפרודקשן?" — שאלה בכמעט כל ראיון. עכשיו יש לך תשובה מהניסיון: pull request עם CI (בדיקות, typecheck, build של image), merge, migrations שתואמים לשתי הגרסאות, deploy, בדיקת עשן מול /version ו־/ready, ו־rollback אם צריך. ומהצד של המראיין: repo עם תג CI ירוק וקישור חי שעובד — זה ההבדל בין "עשיתי קורס" ל"הרצתי מערכת". בעבודה עצמה תפגוש את אותם רעיונות בקנה מידה אחר: GitHub Actions או GitLab CI, images ב־registry, Kubernetes או ECS במקום Render, ו־feature flags במקום "deploy ונראה" — אבל השאלות זהות.
