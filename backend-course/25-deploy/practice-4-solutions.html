P25-E05 · HTTPS ו־proxy 🧠 הבנה רמה 1

💡 רמז 1

ה־TLS "נגמר" (terminates) ב־load balancer. מה הקוד שלך רואה?

💡 רמז 2

X-Forwarded-For ו־X-Forwarded-Proto — מי כותב אותם?

✅ פתרון
  1. כן. ההצפנה בין הדפדפן ל־load balancer, שמחזיק את התעודה. משם — ברשת הפנימית של הפלטפורמה. זה המודל הרגיל, וכך נמנעים מניהול תעודות בקוד.
  2. הכתובת של ה־load balancer — אותה כתובת לכל המשתמשים. הגבלת הקצב תחסום את כולם יחד אחרי 10 ניסיונות כניסה בדקה. עם trust proxy: 1, Express לוקח את הכתובת שה־proxy הוסיף ל־X-Forwarded-For.
  3. http — כי זה החיבור שהשרת רואה. עם trust proxy — https, מ־X-Forwarded-Proto. (חשוב ל־req.secure, לקישורים שהשרת בונה, ול־cookies עם Secure.)
  4. true = לסמוך על כל השרשרת, כולל מה שהלקוח עצמו כתב ב־header. בדקנו בפרק (פלט אמיתי): עם TRUST_PROXY=1 מאחורי Caddy, 11 בקשות עם X-Forwarded-For מזויף שונה בכל פעם ← הבקשה ה־11 קיבלה 429. עם true — כל אחת נראית כמו לקוח חדש (E23).
  5. אומר לדפדפן: "לאתר הזה — רק HTTPS, גם אם מקלידים http, לתקופה X". שולחים אותו רק על HTTPS אמיתי: דפדפן שקיבל אותו מ־localhost יסרב אחר כך ל־http://localhost:3000 של כל פרויקט אחר שלך.
⚠️ טעויות נפוצות
  • להוסיף HTTPS לקוד ה־Node "כי ככה בטוח יותר" — מאחורי load balancer זה רק מסבך.

P25-E07 · security headers 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

res.setHeader, res.removeHeader("X-Powered-By").

💡 רמז 2

req.secure מאחורי proxy נכון רק עם trust proxy — אז הוא נקרא מ־X-Forwarded-Proto. בבדיקה בלי trust proxy, header כזה לא אמור להשפיע.

✅ פתרון
// P25-E07
import type { NextFunction, Request, Response } from "express";

export function securityHeaders({ hstsMaxAge = 15_552_000 }: { hstsMaxAge?: number } = {}) {
  return (req: Request, res: Response, next: NextFunction) => {
    res.removeHeader("X-Powered-By"); // לא לפרסם באיזו טכנולוגיה (וגרסה) השרת רץ
    res.setHeader("X-Content-Type-Options", "nosniff"); // הדפדפן לא "מנחש" סוג קובץ
    res.setHeader("X-Frame-Options", "DENY"); // אי אפשר להטמיע את הדפים ב־iframe (clickjacking)
    res.setHeader("Referrer-Policy", "no-referrer");
    res.setHeader("Cross-Origin-Resource-Policy", "same-site");
    // HSTS — רק על חיבור HTTPS. req.secure נכון גם מאחורי proxy, אם trust proxy מוגדר
    if (req.secure) res.setHeader("Strict-Transport-Security", `max-age=${hstsMaxAge}; includeSubDomains`);
    next();
  };
}

בעבודה משתמשים ב־helmet, שעושה את זה ועוד (כולל Content-Security-Policy). ל־API שמחזיר JSON בלבד, החשובים הם אלה שכאן.

⚠️ טעויות נפוצות
  • HSTS על כל תשובה — כולל http://localhost (E23).

P25-E12 · /ready עם כמה בדיקות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

Promise.race([check(), timeout]) — ו־Promise.all על כולן.

💡 רמז 2

בדיקה שזורקת סינכרונית (לא async): Promise.resolve().then(check) הופך את זה ל־Promise שנדחה.

✅ פתרון
// P25-E12
import type { Request, Response } from "express";

type Check = () => Promise<unknown>;

function withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
  let timer: NodeJS.Timeout;
  const timeout = new Promise<never>((_, reject) => {
    timer = setTimeout(() => reject(new Error("timeout")), ms);
  });
  return Promise.race([p, timeout]).finally(() => clearTimeout(timer));
}

export function readyHandler(checks: Record<string, Check>, { timeoutMs = 1000 }: { timeoutMs?: number } = {}) {
  return async (req: Request, res: Response) => {
    // במקביל: בדיקה איטית אחת לא מעכבת את האחרות, וכולן מוגבלות בזמן
    const results = await Promise.all(
      Object.entries(checks).map(async ([name, check]) => {
        try {
          await withTimeout(Promise.resolve().then(check), timeoutMs);
          return [name, "up"] as const;
        } catch (err) {
          return [name, (err as Error).message === "timeout" ? "timeout" : "down"] as const;
        }
      }),
    );
    const ok = results.every(([, s]) => s === "up");
    res.status(ok ? 200 : 503).set("Cache-Control", "no-store").json({ status: ok ? "ok" : "unavailable", checks: Object.fromEntries(results) });
  };
}
⚠️ טעויות נפוצות
  • בדיקות בטור — מסד איטי ו־cache איטי = שתי שניות לכל בקשת readiness, והפלטפורמה מחליטה שהשרת מת.
  • לבדוק את המסד ב־/health (liveness): המסד נופל לרגע ← הפלטפורמה מפעילה מחדש את כל השרתים, שלא היו בעיה.

P25-E18 · מי הלקוח? X-Forwarded-For 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

[remoteAddress, ...list.reverse()] ואז אינדקס hops.

💡 רמז 2

למה לא את הראשונה ברשימה? כי את הראשונה — הלקוח כתב בעצמו.

✅ פתרון
// P25-E18
// כמו "trust proxy" של Express עם מספר: hops = כמה proxies שלנו יש לפני השרת.
// X-Forwarded-For הוא רשימה: "<מה שהלקוח כתב>, …, <מה שה־proxy הראשון שלנו ראה>". כל proxy מוסיף בסוף.
// סומכים רק על hops הכתובות האחרונות — את מה שלפניהן כל אחד יכול לזייף.
export function clientIp(remoteAddress: string, forwardedFor: string | undefined, hops: number): string {
  const chain = [remoteAddress, ...(forwardedFor ?? "").split(",").map((s) => s.trim()).filter(Boolean).reverse()];
  // chain[0] = מי שהתחבר אלינו ישירות; chain[k] = מה ש־proxy מספר k כתב
  return chain[Math.min(hops, chain.length - 1)];
}
⚠️ טעויות נפוצות
  • trust proxy: true — Express לוקח את הכתובת הראשונה, שהלקוח כתב (E23).

P25-E23 · proxy ו־headers עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

trust proxy: true מול trust proxy: 1 — E18.

💡 רמז 2

מתי מותר לשלוח Strict-Transport-Security? (E07)

✅ פתרון
// P25-E23
import express from "express";

export function createApp({ limit = 5 }: { limit?: number } = {}) {
  const app = express();
  // תקלה 1: trust proxy = true — Express לוקח את הכתובת *הראשונה* ב־X-Forwarded-For, שהלקוח כותב בעצמו.
  // יש בדיוק proxy אחד לפנינו — סומכים על hop אחד
  app.set("trust proxy", 1);
  // תקלה 3: X-Powered-By: Express
  app.disable("x-powered-by");
  const hits = new Map<string, number>();
  app.use((req, res, next) => {
    // תקלה 2: HSTS על HTTP — דפדפן שקיבל אותו מ־localhost מסרב אחר כך ל־http://localhost. רק כשהחיבור מאובטח
    if (req.secure) res.setHeader("Strict-Transport-Security", "max-age=31536000");
    const n = (hits.get(req.ip ?? "") ?? 0) + 1;
    hits.set(req.ip ?? "", n);
    if (n > limit) return res.status(429).json({ error: "יותר מדי בקשות" });
    next();
  });
  app.post("/login", (req, res) => res.json({ ok: true }));
  return app;
}
⚠️ טעויות נפוצות
  • לתקן את 1 עם trust proxy: false — ואז כל המשתמשים "באים" מה־load balancer וחוסמים זה את זה.
