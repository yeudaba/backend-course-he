P25-E05 · HTTPS ו־proxy 🧠 הבנה רמה 1

💡 רמז 1

ה־TLS "נגמר" (terminates) ב־load balancer. מה הקוד שלך רואה?

💡 רמז 2

X-Forwarded-For ו־X-Forwarded-Proto — מי כותב אותם?

✅ פתרון
  1. כן. ההצפנה בין הדפדפן ל־load balancer, שמחזיק את התעודה. משם — ברשת הפנימית של הפלטפורמה. זה המודל הרגיל, וכך נמנעים מניהול תעודות בקוד.
  2. הכתובת של ה־load balancer — אותה כתובת לכל המשתמשים. הגבלת הקצב תחסום את כולם יחד אחרי 10 ניסיונות כניסה בדקה. עם trust proxy: 1, Express לוקח את הכתובת שה־proxy הוסיף ל־X-Forwarded-For.
  3. http — כי זה החיבור שהשרת רואה. עם trust proxy — https, מ־X-Forwarded-Proto. (חשוב ל־req.secure, לקישורים שהשרת בונה, ול־cookies עם Secure.)
  4. true = לסמוך על כל השרשרת, כולל מה שהלקוח עצמו כתב ב־header. בדקנו בפרק (פלט אמיתי): עם TRUST_PROXY=1 מאחורי Caddy, 11 בקשות עם X-Forwarded-For מזויף שונה בכל פעם ← הבקשה ה־11 קיבלה 429. עם true — כל אחת נראית כמו לקוח חדש (E23).
  5. אומר לדפדפן: "לאתר הזה — רק HTTPS, גם אם מקלידים http, לתקופה X". שולחים אותו רק על HTTPS אמיתי: דפדפן שקיבל אותו מ־localhost יסרב אחר כך ל־http://localhost:3000 של כל פרויקט אחר שלך.
⚠️ טעויות נפוצות
  • להוסיף HTTPS לקוד ה־Node "כי ככה בטוח יותר" — מאחורי load balancer זה רק מסבך.

P25-E68 · מה HTTPS נותן, ומה לא? 🧠 הבנה רמה 1

💡 רמז 1

TLS: הצפנה, שלמות, וזהות (של השרת). זה הכול.

💡 רמז 2

‏TLS "נגמר" ב־proxy (איור 1).

✅ פתרון
  1. נכון — הצפנה.
  2. לא לגמרי. התוכן והנתיב מוצפנים, אבל שם האתר נשלח בגלוי ב־TLS (‏SNI) וגם ב־DNS — רואים tasks-api.onrender.com, לא /tasks/7.
  3. לא. HTTPS מגן על הדרך, לא על מה שהשרת עושה עם הקלט. התוקף שולח את ה־injection בתוך חיבור מוצפן בדיוק כמו כל אחד.
  4. לא. תעודה אומרת "זה באמת הדומיין הזה". אתר פישינג עם דומיין משלו מקבל תעודה תקינה בחינם.
  5. נכון — שם TLS נגמר. לכן סומכים על הפלטפורמה, ולכן הקשר בין ה־proxy לאפליקציה צריך להיות ברשת פרטית.
  6. נכון — שלמות: שינוי בדרך נחשף, והחיבור נכשל.
⚠️ טעויות נפוצות
  • לחשוב שמנעול בדפדפן = אבטחה של כל האפליקציה.

P25-E69 · מה האפליקציה רואה מאחורי proxy? 🧠 הבנה רמה 2

💡 רמז 1

בלי trust proxy, Express לא מסתכל על אף X-Forwarded-*.

💡 רמז 2

מבחינת Express, מי פתח את החיבור אליו?

✅ פתרון
  1. http, ‏false, והכתובת של ה־proxy.
  2. https, ‏true, והכתובת של הלקוח (מה שה־proxy הוסיף).

בגרסה 1: (א) ‏Location: http://… — הלקוח עובר ל־HTTP (ושם ה־proxy אולי מפנה חזרה, ומתקבלת לולאה). (ב) HSTS לא נשלח אף פעם — הדפדפן לא "נועל" HTTPS. (ג) כל הלקוחות נראים כמו IP אחד, ונחסמים יחד.

⚠️ טעויות נפוצות
  • trust proxy: true "כדי שיעבוד" — ואז גם X-Forwarded-For שהלקוח כתב בעצמו מתקבל (P25-E23).

P25-E70 · ‏HSTS — מתי, ולכמה זמן? 🧠 הבנה רמה 2

💡 רמז 1

HSTS הוא הבטחה קדימה: "בתקופה הקרובה — רק HTTPS לדומיין הזה". הדפדפן זוכר.

💡 רמז 2

אי אפשר "לבטל" HSTS מהשרת אם הדפדפן כבר לא פונה ב־HTTP.

✅ פתרון
  1. לשנה הקרובה, כל כתובת http:// לדומיין הזה הופכת אצלו ל־https:// עוד לפני שהבקשה יוצאת, ושגיאת תעודה היא חסימה (בלי "המשך בכל זאת").
  2. על HTTP הדפדפן מתעלם ממנו לפי התקן — אבל אפליקציה שמאחורי proxy רואה HTTP תמיד, אז הבדיקה היא req.secure (עם trust proxy). ובפיתוח: אם בכל זאת ננעל — כל פרויקט על localhost "דורש" HTTPS בדפדפן, עד שמנקים את ההגדרה ידנית (P25-E23).
  3. כל תת־דומיין נכנס להבטחה — גם legacy.example.com ישן שעוד רץ ב־HTTP בלבד, ושנעלם אצל כל מי שביקר בדומיין הראשי.
  4. אם מתגלה בעיה ב־HTTPS (תעודה, proxy) — עם max-age של שנה, המשתמשים "תקועים" שנה. עם 300 שניות — חמש דקות.
⚠️ טעויות נפוצות
  • להוסיף HSTS ב־middleware בלי תנאי — ואז גם ה־localhost של כל מפתח בצוות "ננעל".

P25-E71 · ‏/health או /ready — מה ייכשל? 🧠 הבנה רמה 2

💡 רמז 1

‏/health לא בודק כלום — אבל כדי להחזיר משהו, התהליך צריך להיות מסוגל לענות.

💡 רמז 2

מה הפלטפורמה עושה כש־/health נכשל, וכש־/ready נכשל?

✅ פתרון
  1. /health — 200. ‏/ready — 503. הפלטפורמה מפסיקה לשלוח תנועה, ולא מפעילה מחדש. כשהמסד חוזר — חוזרת התנועה. (restart לא היה עוזר — רק מחמיר.)
  2. שניהם לא עונים (timeout). /health נכשל ← restart. זה בדיוק המקרה ש־liveness נועד לו.
  3. /health — 200, ‏/ready — 503 (פרק 24): מוציאים מהתנועה, לא הורגים באמצע.
  4. /ready — 503 עד שהמסד עונה. ב־deploy: התנועה לא עוברת לגרסה החדשה עד אז.
  5. שניהם 200 (איטי). אין כאן בדיקה שתתפוס את זה — מדדים (latency, זיכרון) והתראה (פרק 24, שיעור 6).
⚠️ טעויות נפוצות
  • לבדוק את המסד ב־/health — מקרה 1 הופך ל"כל השרתים מופעלים מחדש בלולאה".

P25-E72 · ‏301, ‏302, ‏307 או 308? 🧠 הבנה רמה 2

💡 רמז 1

‏307 ו־308 מבטיחים: אותה method, אותו body. ‏301 ו־302 — דפדפנים הופכים POST ל־GET.

💡 רמז 2

הבקשה הראשונה — עם הסיסמה — כבר עברה ברשת.

✅ פתרון
  1. 301/302: דפדפנים (מסיבות היסטוריות) שולחים את הבקשה החדשה כ־GET, בלי body — ה־POST "נעלם". 307/308: אותה method ואותו body. לכן Caddy מחזיר 308.
  2. הכתובת ב־HTTP לא תחזור להיות נכונה. "קבוע" מאפשר לדפדפן ולכלים לזכור ולפנות ישר ל־HTTPS.
  3. הסיסמה כבר נשלחה בטקסט גלוי בבקשה הראשונה — ההפניה לא מחזירה את זה. ב־API עדיף לסרב (‏403 / ‏400 "HTTPS required") על כל method שאינו GET/HEAD — כך המפתח של הלקוח מגלה את הטעות מיד, ולא "עובד" בשקט עם דליפה בכל קריאה (E73). ו־HSTS לדפדפנים.
⚠️ טעויות נפוצות
  • להפנות POST עם 301 — הלקוח מקבל 200 על GET שלא ביקש, וה־POST לא קרה.

P25-E07 · security headers 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

res.setHeader, res.removeHeader("X-Powered-By").

💡 רמז 2

req.secure מאחורי proxy נכון רק עם trust proxy — אז הוא נקרא מ־X-Forwarded-Proto. בבדיקה בלי trust proxy, header כזה לא אמור להשפיע.

✅ פתרון
// P25-E07
import type { NextFunction, Request, Response } from "express";

export function securityHeaders({ hstsMaxAge = 15_552_000 }: { hstsMaxAge?: number } = {}) {
  return (req: Request, res: Response, next: NextFunction) => {
    res.removeHeader("X-Powered-By"); // לא לפרסם באיזו טכנולוגיה (וגרסה) השרת רץ
    res.setHeader("X-Content-Type-Options", "nosniff"); // הדפדפן לא "מנחש" סוג קובץ
    res.setHeader("X-Frame-Options", "DENY"); // אי אפשר להטמיע את הדפים ב־iframe (clickjacking)
    res.setHeader("Referrer-Policy", "no-referrer");
    res.setHeader("Cross-Origin-Resource-Policy", "same-site");
    // HSTS — רק על חיבור HTTPS. req.secure נכון גם מאחורי proxy, אם trust proxy מוגדר
    if (req.secure) res.setHeader("Strict-Transport-Security", `max-age=${hstsMaxAge}; includeSubDomains`);
    next();
  };
}

בעבודה משתמשים ב־helmet, שעושה את זה ועוד (כולל Content-Security-Policy). ל־API שמחזיר JSON בלבד, החשובים הם אלה שכאן.

⚠️ טעויות נפוצות
  • HSTS על כל תשובה — כולל http://localhost (E23).

P25-E12 · /ready עם כמה בדיקות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

Promise.race([check(), timeout]) — ו־Promise.all על כולן.

💡 רמז 2

בדיקה שזורקת סינכרונית (לא async): Promise.resolve().then(check) הופך את זה ל־Promise שנדחה.

✅ פתרון
// P25-E12
import type { Request, Response } from "express";

type Check = () => Promise<unknown>;

function withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
  let timer: NodeJS.Timeout;
  const timeout = new Promise<never>((_, reject) => {
    timer = setTimeout(() => reject(new Error("timeout")), ms);
  });
  return Promise.race([p, timeout]).finally(() => clearTimeout(timer));
}

export function readyHandler(checks: Record<string, Check>, { timeoutMs = 1000 }: { timeoutMs?: number } = {}) {
  return async (req: Request, res: Response) => {
    // במקביל: בדיקה איטית אחת לא מעכבת את האחרות, וכולן מוגבלות בזמן
    const results = await Promise.all(
      Object.entries(checks).map(async ([name, check]) => {
        try {
          await withTimeout(Promise.resolve().then(check), timeoutMs);
          return [name, "up"] as const;
        } catch (err) {
          return [name, (err as Error).message === "timeout" ? "timeout" : "down"] as const;
        }
      }),
    );
    const ok = results.every(([, s]) => s === "up");
    res.status(ok ? 200 : 503).set("Cache-Control", "no-store").json({ status: ok ? "ok" : "unavailable", checks: Object.fromEntries(results) });
  };
}
⚠️ טעויות נפוצות
  • בדיקות בטור — מסד איטי ו־cache איטי = שתי שניות לכל בקשת readiness, והפלטפורמה מחליטה שהשרת מת.
  • לבדוק את המסד ב־/health (liveness): המסד נופל לרגע ← הפלטפורמה מפעילה מחדש את כל השרתים, שלא היו בעיה.

P25-E18 · מי הלקוח? X-Forwarded-For 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

[remoteAddress, ...list.reverse()] ואז אינדקס hops.

💡 רמז 2

למה לא את הראשונה ברשימה? כי את הראשונה — הלקוח כתב בעצמו.

✅ פתרון
// P25-E18
// כמו "trust proxy" של Express עם מספר: hops = כמה proxies שלנו יש לפני השרת.
// X-Forwarded-For הוא רשימה: "<מה שהלקוח כתב>, …, <מה שה־proxy הראשון שלנו ראה>". כל proxy מוסיף בסוף.
// סומכים רק על hops הכתובות האחרונות — את מה שלפניהן כל אחד יכול לזייף.
export function clientIp(remoteAddress: string, forwardedFor: string | undefined, hops: number): string {
  const chain = [remoteAddress, ...(forwardedFor ?? "").split(",").map((s) => s.trim()).filter(Boolean).reverse()];
  // chain[0] = מי שהתחבר אלינו ישירות; chain[k] = מה ש־proxy מספר k כתב
  return chain[Math.min(hops, chain.length - 1)];
}
⚠️ טעויות נפוצות
  • trust proxy: true — Express לוקח את הכתובת הראשונה, שהלקוח כתב (E23).

P25-E23 · proxy ו־headers עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

trust proxy: true מול trust proxy: 1 — E18.

💡 רמז 2

מתי מותר לשלוח Strict-Transport-Security? (E07)

✅ פתרון
// P25-E23
import express from "express";

export function createApp({ limit = 5 }: { limit?: number } = {}) {
  const app = express();
  // תקלה 1: trust proxy = true — Express לוקח את הכתובת *הראשונה* ב־X-Forwarded-For, שהלקוח כותב בעצמו.
  // יש בדיוק proxy אחד לפנינו — סומכים על hop אחד
  app.set("trust proxy", 1);
  // תקלה 3: X-Powered-By: Express
  app.disable("x-powered-by");
  const hits = new Map<string, number>();
  app.use((req, res, next) => {
    // תקלה 2: HSTS על HTTP — דפדפן שקיבל אותו מ־localhost מסרב אחר כך ל־http://localhost. רק כשהחיבור מאובטח
    if (req.secure) res.setHeader("Strict-Transport-Security", "max-age=31536000");
    const n = (hits.get(req.ip ?? "") ?? 0) + 1;
    hits.set(req.ip ?? "", n);
    if (n > limit) return res.status(429).json({ error: "יותר מדי בקשות" });
    next();
  });
  app.post("/login", (req, res) => res.json({ ok: true }));
  return app;
}
⚠️ טעויות נפוצות
  • לתקן את 1 עם trust proxy: false — ואז כל המשתמשים "באים" מה־load balancer וחוסמים זה את זה.

P25-E73 · הפניה ל־HTTPS — רק כשמותר 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

req.originalUrl.split("?")[0] בשביל הבדיקה מול exclude; ב־Location — originalUrl המלא, עם ה־query.

💡 רמז 2

res.redirect(308, url).

✅ פתרון
// P25-E73: הפניה ל־HTTPS — רק כשמותר
import type { NextFunction, Request, Response } from "express";

export function requireHttps({ exclude = ["/health", "/ready"] }: { exclude?: string[] } = {}) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (req.secure || exclude.includes(req.originalUrl.split("?")[0])) return next();
    if (req.method === "GET" || req.method === "HEAD") {
      res.redirect(308, `https://${req.host}${req.originalUrl}`);
      return;
    }
    res.status(403).json({ error: { code: "HTTPS_REQUIRED", message: "השתמש ב־HTTPS" } });
  };
}

מאחורי Render זה כמעט לא קורה — ה־proxy כבר מפנה. אבל ב־VPS עם nginx שהוגדר לא נכון, זו רשת הביטחון.

⚠️ טעויות נפוצות
  • לבדוק req.protocol === "https" בלי trust proxy — תמיד http, וכל בקשה מופנית ← לולאה אינסופית של הפניות.

P25-E74 · מאיזו כתובת הגיעה הבקשה? 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

const first = (v: string) => v.split(",")[0].trim().

💡 רמז 2

‏trusted הוא "האם ה־proxy שלפניי הוא שלי" — רק אז מקשיבים ל־X-Forwarded-*.

✅ פתרון
// P25-E74: מאיזו כתובת הגיעה הבקשה?
const first = (v: string) => v.split(",")[0].trim();

export function requestOrigin(h: { host?: string; forwardedHost?: string; forwardedProto?: string; encrypted?: boolean }, trusted: boolean): string {
  let protocol = h.encrypted ? "https" : "http";
  if (trusted && h.forwardedProto) protocol = first(h.forwardedProto);
  const host = trusted && h.forwardedHost ? first(h.forwardedHost) : h.host;
  if (!host) throw new Error("אין Host");
  return `${protocol}://${host}`;
}

שימו לב: ב־X-Forwarded-For לוקחים מימין (מה שה־proxy הוסיף), וכאן — את הראשון. ההבדל: לכתובת IP כל proxy מוסיף, ואילו את ה־proto וה־host ה־proxy הקרוב קובע (בדרך כלל מחליף). זה מה ש־Express עושה, ולכן הבודק משווה אליו.

⚠️ טעויות נפוצות
  • לסמוך על X-Forwarded-Host בלי trust — תוקף שולח X-Forwarded-Host: evil.com, ומייל "איפוס סיסמה" יוצא עם קישור לאתר שלו.

P25-E75 · תעודה שעומדת לפוג 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

/^notAfter=(.+)$/m — ‏m כדי ש־^ ו־$ יתאימו לכל שורה. ‏new Date("Feb 5 12:00:00 2027 GMT") עובד ב־Node.

💡 רמז 2

תאריך שלא נקרא: Number.isNaN(d.getTime()).

✅ פתרון
// P25-E75: תעודה שעומדת לפוג
const DAY = 86_400_000;

export function parseCertDates(text: string) {
  const read = (name: string) => {
    const m = new RegExp(`^${name}=(.+)$`, "m").exec(text);
    const d = m ? new Date(m[1].trim()) : new Date(NaN);
    if (Number.isNaN(d.getTime())) throw new Error("פלט לא תקין");
    return d;
  };
  return { notBefore: read("notBefore"), notAfter: read("notAfter") };
}

export function certStatus(notAfter: Date, now: Date, warnDays = 21) {

P25-E76 · ‏uptime monitor: מתי להעיר? 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P25-E76: uptime monitor — מתי להעיר?
export function uptimeEvents(checks: { at: string; ok: boolean }[], failuresToAlert = 3) {
  const events: { at: string; type: "DOWN" | "UP" }[] = [];
  let downMs = 0;
  let streak = 0;
  let streakStart = "";
  let down = false;
  for (const { at, ok } of checks) {
    if (ok) {
      if (down) {
        events.push({ at, type: "UP" });
        downMs += Date.parse(at) - Date.parse(streakStart);
      }
      streak = 0;
      down = false;
      continue;
    }
    if (streak === 0) streakStart = at;
    streak++;
    if (streak === failuresToAlert) {
      events.push({ at, type: "DOWN" });
      down = true;
    }
  }
  if (down) downMs += Date.parse(checks[checks.length - 1].at) - Date.parse(streakStart);
  return { events, downMs };
}

שלושה כישלונות ברצף בבדיקה כל דקה = התראה אחרי כ־2 דקות, ובלי "התראות שווא" על כל תקלת רשת. ה־downMs מתחיל מהכישלון הראשון — כי זה הרגע שבו המשתמשים התחילו להרגיש.

⚠️ טעויות נפוצות
  • לשלוח DOWN על כל כישלון — עשרים הודעות בתקלה אחת, ומשתיקים את הערוץ.

// P25-E80: /ready שיודע על כיבוי
import type { Request, Response } from "express";

export function createHealth({ checkDb, timeoutMs }: { checkDb: () => Promise<unknown>; timeoutMs: number }) {
  let draining = false;
  const withTimeout = async (p: Promise<unknown>) => {
    let timer: NodeJS.Timeout | undefined;
    try {
      await Promise.race([p, new Promise((_, reject) => { timer = setTimeout(() => reject(new Error("timeout")), timeoutMs); })]);
    } finally {
      clearTimeout(timer);
    }
  };
  return {
    health(req: Request, res: Response) {
      res.set("Cache-Control", "no-store").json({ status: "ok" });
    },
    async ready(req: Request, res: Response) {
      res.set("Cache-Control", "no-store");
      if (draining) {
        res.status(503).json({ status: "draining" });
        return;
      }
      try {
        await withTimeout(checkDb());
        res.json({ status: "ok" });
      } catch {
        res.status(503).json({ status: "unavailable" });
      }
    },
    startDraining() {
      draining = true;
    },
  };
}

// P25-E81: ביקורת על headers של תשובה
export function auditHeaders(headers: Record<string, string>, { https }: { https: boolean }): string[] {
  const h = Object.fromEntries(Object.entries(headers).map(([k, v]) => [k.toLowerCase(), String(v)]));
  const findings: string[] = [];
  if (h["x-content-type-options"]?.toLowerCase() !== "nosniff") findings.push("missing-nosniff");
  const xfo = /^(deny|sameorigin)$/i.test(h["x-frame-options"] ?? "");
  const csp = /frame-ancestors/i.test(h["content-security-policy"] ?? "");
  if (!xfo && !csp) findings.push("missing-frame-protection");
  if ("x-powered-by" in h) findings.push("x-powered-by");
  const hsts = h["strict-transport-security"];
  if (https && !hsts) findings.push("hsts-missing");
  if (!https && hsts) findings.push("hsts-on-http");
  if (hsts) {
    const m = /max-age=(\d+)/i.exec(hsts);
    if (!m || Number(m[1]) < 15_552_000) findings.push("hsts-too-short");
  }
  return findings;
}

// P25-E82: לעקוב אחרי הפניות
export async function redirectChain(fetchFn: typeof fetch, url: string, max = 5) {
  const chain: { url: string; status: number }[] = [];
  const seen = new Set<string>();
  let current = new URL(url).toString();
  for (;;) {
    if (seen.has(current)) throw new Error("REDIRECT_LOOP");
    seen.add(current);
    const res = await fetchFn(current, { redirect: "manual" });
    await res.body?.cancel();
    chain.push({ url: current, status: res.status });
    const location = res.headers.get("location");
    if (res.status < 300 || res.status > 399 || !location) return chain;
    if (chain.length > max) throw new Error("TOO_MANY_REDIRECTS");
    current = new URL(location, current).toString();
  }
}
⚠️ טעויות נפוצות
