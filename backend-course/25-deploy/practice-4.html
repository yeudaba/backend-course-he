P25-E68 · מה HTTPS נותן, ומה לא?

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 4

האתר שלך עובד ב־HTTPS. לכל טענה — נכונה או לא, ולמה?

  1. מי שיושב באותו Wi-Fi לא יכול לקרוא את הסיסמה שנשלחת ב־login.

  4. אם התעודה תקינה, האתר "בטוח".
  5. ה־proxy (Render) רואה את הבקשות בטקסט גלוי.
  6. אי אפשר לשנות את התשובה של השרת בדרך.

P25-E69 · מה האפליקציה רואה מאחורי proxy?

P25-E18 · מי הלקוח? X-Forwarded-For 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

בקובץ P25-E18.ts: clientIp(remoteAddress, forwardedFor, hops) — מה Express עושה עם trust proxy: hops.

  • forwardedFor — הערך של X-Forwarded-For: רשימה מופרדת בפסיקים. כל proxy מוסיף בסוף את הכתובת שהתחברה אליו.
  • hops — כמה proxies שלנו יש לפני השרת. 0 ← remoteAddress.
  • סופרים מהסוף: remoteAddress הוא hop 0, הכתובת האחרונה ברשימה — hop 1, וכן הלאה. רשימה קצרה מ־hops — הכתובת הכי רחוקה שיש.

הבודק משווה גם ל־req.ip של Express האמיתי.

P25-E73 · הפניה ל־HTTPS — רק כשמותר 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 20 דק׳ידע נדרש: שיעור 4

בקובץ 25-deploy/starter/P25-E73.ts (יש בו רק הערה) כתוב וייצא middleware של Express:

export function requireHttps(opts?: { exclude?: string[] }): (req: Request, res: Response, next: NextFunction) => void
  • req.secure ← next(). (האפליקציה של הבודק מגדירה trust proxy, ושולחת X-Forwarded-Proto.)
  • נתיב (בלי query) שנמצא ב־exclude (ברירת מחדל: ["/health", "/ready"]) ← next(), גם בלי HTTPS — הבדיקות של הפלטפורמה פונות ב־HTTP.
  • GET או HEAD ← 308, עם Location: https://<req.host><originalUrl>.
  • כל method אחר ← 403 { error: { code: "HTTPS_REQUIRED", message } } (E72).

P25-E74 · מאיזו כתובת הגיעה הבקשה? 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

מה ש־Express עושה בשביל req.protocol ו־req.host — ביד. בקובץ 25-deploy/starter/P25-E74.ts (יש בו רק הערה) כתוב וייצא:

export function requestOrigin(h: { host?: string; forwardedHost?: string; forwardedProto?: string; encrypted?: boolean }, trusted: boolean): string
  • מחזיר ${protocol}://${host}.
  • ‏protocol: אם encrypted — ‏https, אחרת http. אם trusted ויש forwardedProto — הערך הראשון בו (לפני פסיק), בלי רווחים.
  • ‏host: אם trusted ויש forwardedHost — הערך הראשון בו. אחרת — host.
  • בלי host בכלל ← Error("אין Host").

הבודק משווה ל־req.protocol ו־req.host של Express אמיתי, עם ובלי trust proxy.

P25-E76 · ‏uptime monitor: מתי להעיר? 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

שירות ה־uptime בודק /health כל דקה. בדיקה אחת שנכשלת היא לא תקלה (רשת, שרת שמתעורר). בקובץ 25-deploy/starter/P25-E76.ts (יש בו רק הערה) כתוב וייצא:

export function uptimeEvents(checks: { at: string; ok: boolean }[], failuresToAlert?: number): {
  events: { at: string; type: "DOWN" | "UP" }[];
  downMs: number;
}
  • checks ממוינות לפי זמן (ISO). ‏failuresToAlert — ברירת מחדל 3.
  • DOWN — בבדיקה שבה הגיעו ל־failuresToAlert כישלונות רצופים (‏at שלה). פעם אחת לכל תקלה — לא בכל כישלון אחריה.
  • UP — בבדיקה המוצלחת הראשונה אחרי DOWN. הצלחה בלי DOWN לפניה — אין אירוע.
  • downMs — סך הזמן של התקלות: מהכישלון הראשון ברצף (לא מה־DOWN) ועד ה־UP. תקלה שעוד לא נגמרה — עד הבדיקה האחרונה.
