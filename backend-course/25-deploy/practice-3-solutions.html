P25-E04 · deploy בלי downtime 🧠 הבנה רמה 1

💡 רמז 1

שאל: האם הקוד הישן — שלא יודע כלום על השינוי — ממשיך לעבוד?

💡 רמז 2

"expand / contract": קודם מרחיבים (מוסיפים, בלי לשבור), ורק אחרי שאף קוד לא משתמש בישן — מצמצמים.

✅ פתרון
  1. בטוח. הקוד הישן לא יודע על העמודה ולא נפגע.
  2. שובר: הקוד הישן עושה SELECT title — ונכשל. בבטחה, בשלושה deploys: (א) מוסיפים name, הקוד כותב לשתיהן; (ב) מעתיקים את הנתונים, והקוד קורא מ־name; (ג) מוחקים את title.
  3. שובר, אם זה באותו deploy: הגרסה הישנה עוד קוראת אותה. deploy אחד שמפסיק להשתמש, ורק בבא — DROP.
  4. שובר: ה־INSERT של הקוד הישן לא מכיל את העמודה ← null value violates not-null constraint. בבטחה: DEFAULT 'UTC' — בדיוק מה שעשינו בפרק 24.
  5. שובר בפועל: CREATE INDEX נועל כתיבות לכל זמן הבנייה (דקות). CREATE INDEX CONCURRENTLY — לא נועל. (ב־Prisma: עורכים את קובץ ה־migration ביד.)

ומה עם rollback? אם הגרסה החדשה נכשלה וחוזרים לישנה — ה־migration נשאר. לכן migration בטוח הוא כזה שגם הגרסה הקודמת עובדת איתו. אותו כלל, משני הכיוונים.

⚠️ טעויות נפוצות
  • להניח ש־deploy הוא רגע אחד. הוא חלון זמן, ושתי הגרסאות חיות בו יחד.

// P25-E08
import express from "express";

export function createApp({ env = process.env, now = () => new Date(), pkg }: { env?: Record<string, string | undefined>; now?: () => Date; pkg: { name: string; version: string } }) {
  const app = express();
  const startedAt = now(); // פעם אחת — כשהשרת עולה
  const commit = env.GIT_COMMIT ?? env.RENDER_GIT_COMMIT ?? "dev";
  app.get("/version", (req, res) => {
    res.set("Cache-Control", "no-store"); // אחרי deploy רוצים לראות מיד את החדש, לא עותק מ־cache
    res.json({
      name: pkg.name,
      version: pkg.version,
      commit,
      shortCommit: commit.slice(0, 7),
      startedAt: startedAt.toISOString(),
      uptimeSeconds: Math.floor((now().getTime() - startedAt.getTime()) / 1000),
    });
  });
  return app;
}

✅ פתרון
// P25-E10
export interface SmokeResult {
  ok: boolean;
  attempts: number;
  commit: string | null;
}

export async function smokeTest(
  baseUrl: string,
  { expectCommit, timeoutMs = 600_000, intervalMs = 5_000, now = () => Date.now() }: { expectCommit?: string; timeoutMs?: number; intervalMs?: number; now?: () => number } = {},
): Promise<SmokeResult> {
  const started = now();
  let attempts = 0;
  let commit: string | null = null;
  while (true) {
    attempts++;
    try {
      const v = await fetch(new URL("/version", baseUrl), { signal: AbortSignal.timeout(10_000) });
      if (v.status === 200) {
        commit = ((await v.json()) as { commit?: string }).commit ?? null;
        // אותו commit (מלא או מקוצר) — הגרסה החדשה רצה. ואז: מוכנה?
        if (!expectCommit || (commit !== null && (commit.startsWith(expectCommit) || expectCommit.startsWith(commit)) && commit.length >= 7)) {
          const r = await fetch(new URL("/ready", baseUrl), { signal: AbortSignal.timeout(10_000) });
          if (r.status === 200) return { ok: true, attempts, commit };
        }
      }
    } catch {
      // השרת עוד לא עונה (build, התעוררות) — זה צפוי, מנסים שוב
    }
    if (now() - started + intervalMs > timeoutMs) return { ok: false, attempts, commit };
    await new Promise((r) => setTimeout(r, intervalMs));
  }
}

P25-E15 · הגרסה הבאה מה־commits 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

regex עם named groups: /^(?<type>[a-z]+)(\((?<scope>[^)]+)\))?(?<bang>!)?: (?<subject>.+)$/.

💡 רמז 2

שמור את ה־bump ה"גבוה" ביותר: none < patch < minor < major.

✅ פתרון
// P25-E15
const TYPE = /^(?<type>[a-z]+)(\((?<scope>[^)]+)\))?(?<bang>!)?: (?<subject>.+)$/;

export function nextVersion(current: string, commits: string[]): { version: string; bump: "major" | "minor" | "patch" | "none"; notes: string } {
  const m = /^(\d+)\.(\d+)\.(\d+)$/.exec(current);
  if (!m) throw new Error(`גרסה לא תקינה: ${current}`);
  let [major, minor, patch] = m.slice(1).map(Number);
  const groups: Record<string, string[]> = { "⚠️ שינויים שוברים": [], "✨ חדש": [], "🐛 תיקונים": [] };
  let bump: "major" | "minor" | "patch" | "none" = "none";
  const rank = { none: 0, patch: 1, minor: 2, major: 3 };
  const raise = (b: typeof bump) => { if (rank[b] > rank[bump]) bump = b; };
  for (const message of commits) {
    const [title, ...body] = message.split("\n");
    const c = TYPE.exec(title)?.groups;
    if (!c) continue; // לא בפורמט — לא משפיע על הגרסה
    const breaking = Boolean(c.bang) || body.some((l) => l.startsWith("BREAKING CHANGE:"));
    const line = c.scope ? `${c.scope}: ${c.subject}` : c.subject;
    if (breaking) { raise("major"); groups["⚠️ שינויים שוברים"].push(line); }
    else if (c.type === "feat") { raise("minor"); groups["✨ חדש"].push(line); }
    else if (c.type === "fix") { raise("patch"); groups["🐛 תיקונים"].push(line); }
  }
  if (bump === "major") [major, minor, patch] = [major + 1, 0, 0];
  else if (bump === "minor") [minor, patch] = [minor + 1, 0];
  else if (bump === "patch") patch++;
  const version = `${major}.${minor}.${patch}`;
  const notes = Object.entries(groups)
    .filter(([, items]) => items.length)
    .map(([title, items]) => `### ${title}\n${items.map((i) => `- ${i}`).join("\n")}`)
    .join("\n\n");
  return { version, bump, notes };
}

כלים כמו release-please ו־semantic-release עושים בדיוק את זה ב־CI: קוראים את ה־commits מאז הגרסה האחרונה, קובעים גרסה, כותבים CHANGELOG ויוצרים tag.

⚠️ טעויות נפוצות
  • להשוות גרסאות כמחרוזות: "0.10.0" < "0.9.0" הוא true.

P25-E16 · migration שלא שובר את מה שרץ 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שורה אחרי שורה: sql.split("\n"), ומורידים הערות עם replace(/--.*$/, "").

💡 רמז 2

"בלי CONCURRENTLY": negative lookahead — /CREATE\s+(UNIQUE\s+)?INDEX\s+(?!CONCURRENTLY\b)/i.

✅ פתרון
// P25-E16
export interface Finding {
  line: number;
  rule: "drop-column" | "drop-table" | "rename" | "not-null-without-default" | "alter-type" | "index-without-concurrently";
  message: string;
}

// בזמן deploy, הגרסה הישנה של הקוד עדיין רצה כמה דקות מול המסד *החדש*.
// שינוי שהקוד הישן לא שורד אותו — שובר את הפרודקשן באמצע ה־deploy.
const RULES: { rule: Finding["rule"]; re: RegExp; message: string }[] = [
  { rule: "drop-column", re: /\bDROP\s+COLUMN\b/i, message: "הקוד הישן עוד קורא את העמודה. קודם deploy שמפסיק להשתמש בה, ורק בגרסה הבאה — DROP" },
  { rule: "drop-table", re: /\bDROP\s+TABLE\b/i, message: "הקוד הישן עוד משתמש בטבלה. מוחקים בשני שלבים" },
  { rule: "rename", re: /\bRENAME\s+(COLUMN\s+|TO\b)/i, message: "שינוי שם = הקוד הישן לא מוצא. מוסיפים חדש, מעתיקים, ומוחקים את הישן בהמשך" },
  { rule: "alter-type", re: /\bALTER\s+COLUMN\s+\S+\s+(SET\s+DATA\s+)?TYPE\b/i, message: "שינוי טיפוס כותב מחדש את כל הטבלה תחת נעילה" },
  { rule: "index-without-concurrently", re: /\bCREATE\s+(UNIQUE\s+)?INDEX\s+(?!CONCURRENTLY\b)/i, message: "CREATE INDEX נועל כתיבות לכל הטבלה. בטבלה גדולה — CONCURRENTLY" },
];

export function checkMigration(sql: string): Finding[] {
  const findings: Finding[] = [];
  const lines = sql.split("\n");
  lines.forEach((text, i) => {
    const code = text.replace(/--.*$/, ""); // הערות לא נחשבות
    for (const r of RULES) if (r.re.test(code)) findings.push({ line: i + 1, rule: r.rule, message: r.message });
    // NOT NULL על עמודה חדשה בלי DEFAULT: הקוד הישן מכניס שורות בלי העמודה ← נכשל
    if (/\bADD\s+COLUMN\b/i.test(code) && /\bNOT\s+NULL\b/i.test(code) && !/\bDEFAULT\b/i.test(code)) {
      findings.push({ line: i + 1, rule: "not-null-without-default", message: "עמודה חדשה NOT NULL בלי DEFAULT — ה־INSERT של הקוד הישן ייכשל" });
    }
  });
  return findings;
}

P25-E17 · pipeline עם rollback 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני בלוקים של try: אחד ל־migrate (בלי rollback — לא שינינו גרסה), ואחד ל־deploy+smoke.

💡 רמז 2

ה־migration לא "חוזר" ב־rollback. לכן הוא חייב להיות תואם גם לגרסה הקודמת (E04, E16).

✅ פתרון
// P25-E17
export interface Steps {
  migrate(): Promise<void>;
  deploy(version: string): Promise<void>;
  smoke(version: string): Promise<boolean>;
  currentVersion(): Promise<string>;
}

export async function runPipeline(version: string, steps: Steps, log: (line: string) => void = () => {}): Promise<{ ok: boolean; running: string }> {
  const previous = await steps.currentVersion(); // לפני הכול: לאן חוזרים אם משהו נכשל
  log(`deploy ${version} (עכשיו רץ: ${previous})`);
  try {
    await steps.migrate();
  } catch (err) {
    log(`migrate נכשל: ${(err as Error).message} — לא עושים deploy`);
    return { ok: false, running: previous };
  }
  try {
    await steps.deploy(version);
    if (await steps.smoke(version)) {
      log(`✔ ${version} רץ ותקין`);
      return { ok: true, running: version };
    }
    log(`smoke נכשל על ${version}`);
  } catch (err) {
    log(`deploy נכשל: ${(err as Error).message}`);
  }
  // rollback: חוזרים לגרסה הקודמת (ה־migration נשאר — לכן הוא חייב להיות תואם לשתי הגרסאות, E16)
  log(`rollback ל־${previous}`);
  await steps.deploy(previous);
  return { ok: false, running: previous };
}
⚠️ טעויות נפוצות
  • rollback ל"גרסה הקודמת" שמחושבת אחרי ה־deploy — וזו כבר החדשה.

P25-E19 · retry עם backoff 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

"full jitter": לא מחכים בדיוק 100, 200, 400 — אלא מספר אקראי עד התקרה.

💡 רמז 2

sleep מוזרק — כך הבדיקה לא מחכה באמת.

✅ פתרון
// P25-E19
export class HttpStatusError extends Error {
  status: number;
  constructor(status: number) {
    super(`HTTP ${status}`);
    this.status = status;
  }
}

// לנסות שוב — רק כשיש סיכוי שזה יעזור
export function isRetryable(err: unknown): boolean {
  if (err instanceof HttpStatusError) return err.status === 429 || err.status >= 500; // 4xx אחר — הבקשה עצמה שגויה
  return true; // שגיאת רשת: ECONNRESET, timeout
}

export function backoffDelays({ retries, baseMs, maxMs, random = Math.random }: { retries: number; baseMs: number; maxMs: number; random?: () => number }): number[] {
  // exponential backoff עם "full jitter": אקראי בין 0 לתקרה — כך אלף לקוחות לא חוזרים באותה שנייה
  return Array.from({ length: retries }, (_, i) => Math.floor(random() * Math.min(maxMs, baseMs * 2 ** i)));
}

export async function retry<T>(
  fn: (attempt: number) => Promise<T>,
  { retries = 3, baseMs = 200, maxMs = 5_000, random = Math.random, sleep = (ms: number) => new Promise((r) => setTimeout(r, ms)) }: { retries?: number; baseMs?: number; maxMs?: number; random?: () => number; sleep?: (ms: number) => Promise<unknown> } = {},
): Promise<T> {
  const delays = backoffDelays({ retries, baseMs, maxMs, random });
  for (let attempt = 1; ; attempt++) {
    try {
      return await fn(attempt);
    } catch (err) {
      if (attempt > retries || !isRetryable(err)) throw err;
      await sleep(delays[attempt - 1]);
    }
  }
}

למה jitter? 1,000 לקוחות שנכשלו באותה שנייה (השרת נפל) ומנסים שוב בדיוק אחרי 200ms — יפילו אותו שוב, בדיוק כשהוא עולה. עם jitter הם מתפזרים. ולמה לא לנסות שוב על 4xx? בקשה לא תקינה תישאר לא תקינה; ו־POST שנכשל באמצע — ננסה שוב רק עם Idempotency-Key (פרק 24).

⚠️ טעויות נפוצות
  • retry סביב POST בלי Idempotency-Key — כל ניסיון חוזר יכול ליצור עוד הזמנה.

💡 רמז 2

// P25-E22
export async function smokeCheck(base: string, expectCommit: string, { attempts = 30, intervalMs = 5000 } = {}): Promise<boolean> {
  // תקלה 1: ניסיון אחד. אחרי deploy השרת עוד בונה/מתעורר — "✖" על deploy תקין
  for (let i = 0; i < attempts; i++) {
    try {
      const res = await fetch(`${base}/version`);
      // תקלה 2: res.ok בלבד — הגרסה *הישנה* עונה 200 בזמן שהחדשה נבנית (או אחרי שנכשלה). בודקים את ה־commit
      if (res.ok && ((await res.json()) as { commit?: string }).commit === expectCommit) {
        // תקלה 3: גרסה שעלתה בלי מסד היא לא "תקינה" — /ready
        const ready = await fetch(`${base}/ready`);
        if (ready.ok) return true;
      }
    } catch {
      // עוד לא עונה
    }
    await new Promise((r) => setTimeout(r, intervalMs));
  }
  return false;
}

P25-E25 · אתגר: blue/green 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

שמור #live ו־#versions: { blue?, green? }. הצבע הפנוי: ההפך מ־#live.

💡 רמז 2

שדות פרטיים עם #, ו־constructor(platform) שמציב אותם — לא parameter properties.

✅ פתרון
// P25-E25
export type Color = "blue" | "green";

export interface Platform {
  start(color: Color, version: string): Promise<void>;
  healthy(color: Color): Promise<boolean>;
  stop(color: Color): Promise<void>;
}

// blue/green: שתי "סביבות". אחת מקבלת תנועה; את החדשה מעלים בשנייה, בודקים — ורק אז מעבירים תנועה.
// rollback = להעביר את התנועה בחזרה, מיד, כי הישנה עוד רצה
export class BlueGreen {
  #platform: Platform;
  #live: Color | null = null;
  #versions: Partial<Record<Color, string>> = {};
  #history: string[] = [];

  constructor(platform: Platform) {
    this.#platform = platform;
  }

  get live() {
    return this.#live === null ? null : { color: this.#live, version: this.#versions[this.#live]! };
  }

  get history() {
    return [...this.#history];
  }

  async deploy(version: string, { attempts = 5 } = {}): Promise<boolean> {
    const idle: Color = this.#live === "blue" ? "green" : "blue";
    await this.#platform.start(idle, version);
    this.#versions[idle] = version;
    for (let i = 0; i < attempts; i++) {
      if (await this.#platform.healthy(idle)) {
        this.#live = idle; // המעבר עצמו — אטומי. אף בקשה לא מגיעה לגרסה שלא עברה בדיקה
        this.#history.push(version);
        return true;
      }
    }
    await this.#platform.stop(idle); // לא עבר — עוצרים. התנועה בכלל לא זזה
    delete this.#versions[idle];
    return false;
  }

  async rollback(): Promise<boolean> {
    if (this.#live === null) return false;
    const other: Color = this.#live === "blue" ? "green" : "blue";
    if (!this.#versions[other] || !(await this.#platform.healthy(other))) return false;
    this.#live = other;
    this.#history.push(this.#versions[other]!);
    return true;
  }

  // אחרי שהחדשה יציבה — משחררים את הישנה (וגם את האפשרות ל־rollback מיידי)
  async retireIdle(): Promise<void> {
    if (this.#live === null) return;
    const other: Color = this.#live === "blue" ? "green" : "blue";
    if (this.#versions[other]) {
      await this.#platform.stop(other);
      delete this.#versions[other];
    }
  }
}

היתרון: rollback בשנייה, כי הישנה עדיין רצה. המחיר: פעמיים משאבים בזמן ה־deploy, ו־migrations שחייבים להתאים לשתי הגרסאות (E04). פלטפורמות כמו Render עושות גרסה של זה בשבילך: הגרסה החדשה מקבלת תנועה רק אחרי שה־health check שלה עובר.

⚠️ טעויות נפוצות
  • להעביר תנועה ואז לבדוק — אז המשתמשים הם הבדיקה.

P25-E26 · feature flags: לפתוח ל־10% מהמשתמשים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

💡 רמז 2

שלוש שורות ב־isEnabled: ‏const flag = flags[flagName]; if (!flag || !flag.enabled) return false; if (flag.allow?.includes(userId)) return true; ואז ההשוואה. ‏?. מטפל בדגל בלי allow.

✅ פתרון
// P25-E26 — feature flags עם פריסה הדרגתית
import { createHash } from "node:crypto";

export type Flag = { enabled: boolean; percent: number; allow?: string[] };

export function bucketOf(flagName: string, userId: string): number {
  const digest = createHash("sha256").update(`${flagName}:${userId}`).digest();
  return digest.readUInt32BE(0) % 100;
}

export function isEnabled(flags: Record<string, Flag>, flagName: string, userId: string): boolean {
  const flag = flags[flagName];
  if (!flag || !flag.enabled) return false;
  if (flag.allow?.includes(userId)) return true;
  return bucketOf(flagName, userId) < flag.percent;
}

  • hash של userId בלבד — אותם משתמשים בכל הדגלים.

P25-E27 · כמה זמן השרת למעלה 🤖 💻 כתיבת קוד 🤖 רמה 1

💡 רמז 1

טבלת יחידות: [["d", 86400], ["h", 3600], ["m", 60], ["s", 1]]. עוברים עליה עם map, ובכל יחידה: Math.floor(rest / size), ואז rest %= size.

💡 רמז 2

parts.findIndex((p) => p.value > 0) נותן את היחידה הראשונה. ‏-1 אומר שהכול אפס ← "0s". אחרת parts.slice(first, first + 2).filter(...).map(...).join(" ").

✅ פתרון
// P25-E27 — כמה זמן השרת למעלה
const UNITS: [string, number][] = [
  ["d", 86_400],
  ["h", 3_600],
  ["m", 60],
  ["s", 1],
];

export function formatUptime(totalSeconds: number): string {
  if (!Number.isInteger(totalSeconds) || totalSeconds < 0) throw new RangeError("totalSeconds חייב להיות מספר שלם לא שלילי");
  let rest = totalSeconds;
  const parts = UNITS.map(([unit, size]) => {
    const value = Math.floor(rest / size);
    rest %= size;
    return { unit, value };
  });
  const first = parts.findIndex((p) => p.value > 0);
  if (first === -1) return "0s";
  return parts
    .slice(first, first + 2)
    .filter((p) => p.value > 0)
    .map((p) => `${p.value}${p.unit}`)
    .join(" ");
}

map עם משתנה rest מבחוץ עובד, כי map עובר על המערך לפי הסדר. אבל זו פונקציה עם תופעת לוואי. אם זה מפריע לך, לולאת for...of שדוחפת למערך כתובה באותו אורך.

⚠️ טעויות נפוצות
  • totalSeconds / 3600 בלי Math.floor — ‏1.0169h.
  • להחזיר "" על 0 — שדה ריק ב־/version נראה כמו באג.
  • לסנן אפסים לפני slice — ‏3601 הופך ל־"1h 1s".
  • if (totalSeconds < 0) בלבד — ‏NaN ו־1.5 עוברים. ‏Number.isInteger תופס את שניהם (וגם Infinity).

P25-E28 · mapLimit: הרבה עבודות, מעט במקביל 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

הרעיון: limit "עובדים". כל עובד הוא פונקציה async עם לולאה: לוקח את האינדקס הבא (const i = next++), מחכה ל־fn, ושומר ב־results[i]. ‏next ו־results משותפים לכל העובדים (closure). ‏JavaScript רץ על thread אחד, ולכן next++ לא יכול "להתנגש".

💡 רמז 2

const workers = Array.from({ length: Math.min(limit, items.length) }, () => worker()); await Promise.all(workers);. כדי לעצור אחרי שגיאה: משתנה failed שהעובד מדליק ב־catch (ואז זורק שוב), ותנאי הלולאה בודק אותו.

✅ פתרון
// P25-E28 — mapLimit: הרבה עבודות, מעט במקביל
export async function mapLimit<T, R>(items: T[], limit: number, fn: (item: T, index: number) => Promise<R>): Promise<R[]> {
  if (!Number.isInteger(limit) || limit < 1) throw new RangeError("limit חייב להיות מספר שלם חיובי");
  const results: R[] = new Array(items.length);
  let next = 0;
  let failed = false;

  async function worker(): Promise<void> {
    while (next < items.length && !failed) {
      const index = next++;
      try {
        results[index] = await fn(items[index], index);
      } catch (err) {
        failed = true;
        throw err;
      }
    }
  }

  const workers = Array.from({ length: Math.min(limit, items.length) }, () => worker());
  await Promise.all(workers);
  return results;
}

async function demo() {
  const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));
  let running = 0;
  let peak = 0;
  const started = Date.now();
  const sizes = await mapLimit(["a.js", "b.js", "c.css", "d.png", "e.svg"], 2, async (file, i) => {
    running++;
    peak = Math.max(peak, running);
    await sleep(100);
    running--;
    return `${i}:${file}`;
  });
  console.log(sizes);
  console.log("peak:", peak, "· ~ms:", Math.round((Date.now() - started) / 100) * 100);
  try {
    await mapLimit([1, 2, 3], 2, async (n) => {
      if (n === 2) throw new Error(`upload ${n} failed`);
      return n;
    });
  } catch (err) {
    console.log("נכשל:", (err as Error).message);
  }
}

חמישה קבצים, שניים במקביל, 100ms כל אחד: שלושה "סבבים", כ־300ms. אחד־אחד היה לוקח 500ms, וכולם יחד 100ms עם חמישה חיבורים פתוחים. ‏peak: 2 מראה שהמגבלה נשמרה.

למה עובדים ולא "קבוצות של 2" (‏Promise.all על slice(0, 2), אחר כך slice(2, 4))? בקבוצות, כל קבוצה מחכה לאיטי שבה. עם עובדים, מי שסיים לוקח מיד את הבא. כשהזמנים שונים (קובץ של 2KB מול קובץ של 20MB) ההבדל גדול.

זה מה שחבילות כמו p-limit עושות, וזה גם הרעיון של connectionLimit ב־pool של מסד נתונים: מספר קבוע של "עובדים", ותור לכל השאר.

⚠️ טעויות נפוצות
  • results.push(...) במקום results[i] = ... — התוצאות בסדר הסיום, לא בסדר הקלט.
  • לחלק לקבוצות קבועות — נכון, אבל איטי כשהזמנים לא אחידים.
  • Array.from({ length: limit }) בלי Math.min — עם 2 פריטים ו־limit של 10 זה עובד, אבל יוצרים 8 עובדים מיותרים.
  • לבלוע את השגיאה ב־catch בלי לזרוק שוב — ‏mapLimit "מצליחה" עם חורים במערך.
