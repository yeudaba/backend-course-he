P25-E03 · איפה שמים כל דבר? 🧠 הבנה רמה 1

💡 רמז 1

שאלה לכל ערך: מה יקרה אם כל העולם יראה אותו? (ה־repo שלך ציבורי — זה תיק עבודות.)

💡 רמז 2

מי צריך את הערך: השרת בזמן ריצה, ה־CI, או שניהם?

✅ פתרון
  1. Render (השרת צריך אותו בזמן ריצה) וגם GitHub Secrets (ה־deploy job מריץ migrations). אף פעם לא בקוד.
  2. רק ב־Render. ה־CI לא צריך אותו. מי שמחזיק אותו יכול לחתום טוקן של admin.
  3. בקוד / ב־workflow — ערך מזויף, לבדיקות בלבד (כמו ci-only-secret-… שלנו). הוא לא שווה כלום מחוץ ל־CI. לא צריך "להגן" עליו.
  4. GitHub Secrets. מי שמחזיק את הכתובת יכול להפעיל deploy. (כן, URL יכול להיות סוד.)
  5. GitHub Variables (vars.PRODUCTION_URL) — לא סוד, אבל הגדרה ולא קוד. וגם ב־README — זה הקישור החי.
  6. בקוד, כברירת מחדל (zod .default(900)). לא סוד. env רק אם רוצים לשנות בלי deploy.
  7. בתוך ה־workflow, גלוי. המסד הזה חי שתי דקות, ב־runner מבודד, ואין בו כלום.
⚠️ טעויות נפוצות
  • "ה־repo פרטי, אז אפשר בקוד." היום פרטי — מחר תהפוך אותו לציבורי לתיק העבודות, וההיסטוריה של Git זוכרת הכול. סוד שנכנס ל־commit — מחליפים (rotate), לא רק מוחקים.

P25-E44 · סוד נכנס ל־Git — מה עושים, ובאיזה סדר? 🧠 הבנה רמה 2

💡 רמז 1

הסוד כבר "בחוץ" — בוטים סורקים את GitHub תוך דקות. מה מבטל את הערך שלו?

💡 רמז 2

access token נחתם ב־JWT_SECRET. מה קורה לטוקנים קיימים כשהוא מתחלף?

✅ פתרון
  1. ב ו־ג קודם, מיד — רק החלפה (rotate) הופכת את מה שדלף לחסר ערך. כל דקה שהסוד הישן עובד היא דקה שמישהו יכול להשתמש בו.
  2. ד — לדעת אם כבר נוצל (ואם כן — זו תקלת אבטחה עם נתונים, לא רק "סוד שדלף").
  3. א — כדי שלא יחזור.
  4. ה — רק אחר כך, ואופציונלי: ההיסטוריה כבר הועתקה (forks, ‏clones, ‏cache). ניקוי היסטוריה לא מחליף את ההחלפה.

המחיר של (ג): כל ה־access tokens הקיימים נפסלים (החתימה לא תואמת) — כולם יקבלו 401. ה־refresh tokens שלנו אטומים ונשמרים במסד (פרק 21), אז ה־frontend יבצע refresh ויקבל access token חדש — רוב המשתמשים לא ירגישו.

⚠️ טעויות נפוצות
  • להתחיל מ"למחוק מה־Git" — ולהשאיר את הסוד הישן פעיל, "כי מחקתי".

P25-E45 · מי רואה את הסוד? 🧠 הבנה רמה 2

💡 רמז 1

GitHub מחליף ב־*** כל הופעה של הערך המדויק של סוד בלוג.

💡 רמז 2

מה -v של curl מדפיס?

✅ פתרון
  1. *** — מוחלף.
  2. מופיע, מקודד ב־base64 — ש"מתפענח" בשנייה. GitHub מסווה רק את הערך המדויק.
  3. מופיע — חלק מהסוד הוא לא הסוד, אז אין מה להסוות. עשרה תווים מטוקן קצר הם רוב הדרך.
  4. כלום — PR מ־fork לא מקבל secrets בכלל (המשתנה ריק). בדיוק בשביל זה.
  5. *** בשורת ה־header (הערך המדויק מופיע שם). אבל -v מדפיס גם את התשובה — ואם השרת מחזיר טוקן אחר (למשל token קצר־מועד), הוא לא סוד שמור, ויופיע.

הכלל: לא להדפיס סודות, בשום צורה. ההסוואה היא רשת ביטחון, לא תוכנית (E56).

⚠️ טעויות נפוצות
  • "זה בסדר, GitHub מסתיר" — ואז set -x בסקריפט, או לוג של ספרייה שמקודדת את הערך.

P25-E46 · להיכשל, או ברירת מחדל? 🧠 הבנה רמה 2

💡 רמז 1

השאלה: האם יש ערך שנכון לכל פרודקשן? ואם השרת עולה עם ברירת המחדל — האם משהו מסוכן קורה בשקט?

💡 רמז 2

שרת שלא עולה ב־deploy = הגרסה הקודמת ממשיכה לרוץ (שיעור 2, סעיף 2).

✅ פתרון
  1. ברירת מחדל (3000) — והפלטפורמה ממילא קובעת.
  2. ברירת מחדל: info.
  3. להיכשל. ברירת מחדל = סוד שכתוב בקוד הציבורי — כל אחד יכול לחתום טוקנים.
  4. להיכשל. ברירת מחדל כמו localhost נכשלת רק בבקשה הראשונה, אחרי שה־deploy "הצליח".
  5. להיכשל. אין ערך נכון לכולם, ו־* פותח את ה־API לכל אתר.
  6. ברירת מחדל 0 — בטוחה (לא סומכים על headers). החיסרון — כל הבקשות "מאותו IP" — מתגלה מהר בהגבלת הקצב.
  7. ברירת מחדל (900) — ערך סביר שמופיע בקוד, לא סוד.

ו־verbose: להיכשל. טעות הקלדה בהגדרה עדיף לגלות ב־deploy (הגרסה הקודמת ממשיכה לרוץ) מאשר לגלות כשמחפשים לוגים של debug ואין (פרק 24, E95).

⚠️ טעויות נפוצות
  • ברירת מחדל ל־JWT_SECRET "רק בשביל הפיתוח" בלי לבדוק את NODE_ENV — והיא מגיעה לפרודקשן (P25-E21).

P25-E47 · ‏sslmode — מי מבין מה? 🧠 הבנה רמה 2

💡 רמז 1

‏"התחבר בלי TLS בלי אזהרה" — מה זה אומר על הסיסמה שנשלחת?

💡 רמז 2

pgConnectionOptions מוחק את sslmode מה־URL ומעביר ssl במפורש.

✅ פתרון
  1. pg: אזהרה (‏require מטופל כמו verify-full), ואז "The server does not support SSL connections" — נכשל. Prisma CLI: ‏P1011 — דורש TLS, נכשל. שניהם בטוחים.
  2. pg — דורש TLS עם בדיקת תעודה. Prisma CLI — לא מכיר את הערך, מתעלם, ומתחבר בלי TLS, בלי אזהרה.
  3. ה־migrations (ש־CI מריץ עם Prisma CLI) היו יכולים לשלוח את הסיסמה של המסד בטקסט גלוי, או להתחבר לשרת מתחזה — ואף אחד לא היה יודע. "verify-full" בכתובת נותן תחושה של ביטחון מקסימלי.
  4. הכתובת נשארת sslmode=require (מה שה־CLI מבין). בזמן ריצה, pgConnectionOptions מוריד את sslmode מהכתובת ומעביר ל־pg ‏ssl: { rejectUnauthorized: true } — TLS עם בדיקת תעודה, במפורש, בלי לנחש (E50).
⚠️ טעויות נפוצות
  • להעתיק את ההמלצה מה־warning בלי לבדוק את כל מי שקורא את אותה כתובת.

P25-E48 · ‏Secret או Variable? 🧠 הבנה רמה 1

💡 רמז 1

Variable — לא סוד, אבל משתנה בין סביבות או שלא רוצים לכתוב בקוד. Secret — מי שמחזיק בו יכול לעשות משהו.

💡 רמז 2

האם ה־CI בכלל צריך את JWT_SECRET?

✅ פתרון
  1. Variable — ציבורי בכל מקרה.
  2. Secret — עם environment של production.
  3. Secret — מי שמחזיק בו יכול להפעיל deploy.
  4. בקובץ — זה חלק מהקוד (וכדאי שיתאים ל־engines ול־Dockerfile).
  5. לא ב־GitHub בכלל — רק ב־Render. ה־CI לא חותם טוקנים של פרודקשן. (בבדיקות — ערך מזויף, ישירות ב־workflow.)
  6. Secret — מי שמחזיק בכתובת יכול לשלוח הודעות לערוץ.
  7. בקובץ, ישירות: המסד זמני, נוצר ונמחק בכל ריצה, והסיסמה שלו לא מגינה על שום דבר.
⚠️ טעויות נפוצות
  • "נשים הכול ב־Secrets, ליתר ביטחון" — ואז אי אפשר לראות מה הערך של PRODUCTION_URL כשבודקים תקלה (הוא מוסתר בלוג).

P25-E06 · הגדרות: נוח בפיתוח, קשוח בפרודקשן 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

z.object({...}).superRefine((e, ctx) => { if (e.NODE_ENV !== "production") return; ... ctx.addIssue({ code: "custom", path: ["JWT_SECRET"], message: "..." }) }).

💡 רמז 2

safeParse ו־result.error.issues — כל הבעיות, לא רק הראשונה.

✅ פתרון
// P25-E06
import { z } from "zod";

const schema = z
  .object({
    NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
    PORT: z.coerce.number().int().min(1).max(65535).default(3000),
    DATABASE_URL: z.string().optional(),
    JWT_SECRET: z.string().optional(),
    LOG_LEVEL: z.enum(["debug", "info", "warn", "error"]).default("info"),
  })
  .superRefine((e, ctx) => {
    if (e.NODE_ENV !== "production") return;
    if (!e.DATABASE_URL) ctx.addIssue({ code: "custom", path: ["DATABASE_URL"], message: "חובה בפרודקשן" });
    if (!e.JWT_SECRET || e.JWT_SECRET.length < 32) ctx.addIssue({ code: "custom", path: ["JWT_SECRET"], message: "בפרודקשן — לפחות 32 תווים" });
    if (e.LOG_LEVEL === "debug") ctx.addIssue({ code: "custom", path: ["LOG_LEVEL"], message: "debug בפרודקשן כותב יותר מדי (ולפעמים מידע רגיש)" });
  });

export interface Config {
  env: "development" | "test" | "production";
  port: number;
  databaseUrl: string;
  jwtSecret: string;
  logLevel: "debug" | "info" | "warn" | "error";
}

export function loadConfig(env: Record<string, string | undefined>): Config {
  const r = schema.safeParse(env);
  if (!r.success) {
    // כל הבעיות בהודעה אחת — לא "תקן אחת, deploy, גלה את הבאה"
    throw new Error(`הגדרות לא תקינות:\n${r.error.issues.map((i) => `- ${i.path.join(".")}: ${i.message}`).join("\n")}`);
  }
  const e = r.data;
  return {
    env: e.NODE_ENV,
    port: e.PORT,
    // בפיתוח בלבד: ברירות מחדל נוחות. בפרודקשן הן לא יגיעו לכאן — superRefine כבר נכשל
    databaseUrl: e.DATABASE_URL ?? "postgresql://postgres@localhost:5432/dev",
    jwtSecret: e.JWT_SECRET ?? "dev-only-secret-not-for-production!!",
    logLevel: e.LOG_LEVEL,
  };
}

למה "כל הבעיות בהודעה אחת"? כי deploy לוקח דקות. "תקן אחת, deploy, גלה את הבאה" × שלוש = חצי שעה. ולמה להיכשל בעלייה ולא מאוחר? כי בפלטפורמה, שרת שלא עולה = deploy שנכשל — והגרסה הקודמת ממשיכה לרוץ. שרת שעולה עם הגדרה שגויה נכשל מול משתמשים.

⚠️ טעויות נפוצות
  • env.JWT_SECRET ?? "dev-secret" בלי לבדוק סביבה — ובפרודקשן כל אחד יכול לחתום טוקנים (E21).

P25-E11 · DATABASE_URL בלי לחשוף 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

new URL(url) מבין postgresql://: .username, .password, .hostname, .port, .pathname, .searchParams. ואפשר לשנות u.password.

💡 רמז 2

new URL זורק TypeError שההודעה שלו כוללת את הכתובת המלאה. תופסים וזורקים שגיאה משלך.

✅ פתרון
// P25-E11
function parse(url: string): URL {
  try {
    const u = new URL(url);
    if (!/^postgres(ql)?:$/.test(u.protocol)) throw new Error();
    return u;
  } catch {
    // בלי הכתובת עצמה בהודעה: יש בה סיסמה, והודעות שגיאה מגיעות ללוגים
    throw new Error("DATABASE_URL לא תקין (צריך postgresql://user:password@host:port/db)");
  }
}

export function redactDatabaseUrl(url: string): string {
  const u = parse(url);
  if (u.password) u.password = "***";
  return u.toString();
}

export function describeDb(url: string) {
  const u = parse(url);
  const sslmode = u.searchParams.get("sslmode");
  return {
    host: u.hostname,
    port: Number(u.port || 5432),
    database: decodeURIComponent(u.pathname.slice(1)),
    user: decodeURIComponent(u.username),
    ssl: sslmode !== null && sslmode !== "disable",
  };
}

שימוש: בעלייה, logger.info("db", describeDb(process.env.DATABASE_URL)) — ויודעים לאיזה מסד השרת מחובר, בלי שהסיסמה מגיעה ללוגים.

⚠️ טעויות נפוצות
  • throw new Error(כתובת לא תקינה: ${url}) — הסיסמה בדיוק בלוג שרצית להגן עליו.

P25-E20 · workflow מסוכן 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

איזה DATABASE_URL רואה ה־job של הבדיקות? ומה עושה prisma migrate reset --force?

💡 רמז 2

מה מחבר בין deploy ל־test? ומתי בכלל deploy רץ?

✅ פתרון
# P25-E20
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    # תקלה 1: DATABASE_URL של הפרודקשן היה ב־env של כל ה־workflow — וה־test job הריץ עליו migrate reset.
    # לבדיקות: מסד משלהן, שירות postgres ב־CI
    services:
      postgres:
        image: postgres:18-alpine
        env:
          POSTGRES_PASSWORD: test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 2s
          --health-retries 30
    env:
      DATABASE_URL: postgresql://postgres:test@localhost:5432/postgres
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
        with:
          node-version: 24
          cache: npm
      - run: npm ci
      - run: npx prisma migrate reset --force
      - run: npm test

  deploy:
    # תקלה 2: בלי needs, deploy רץ במקביל לבדיקות — גם כשהן נכשלות
    needs: test
    # תקלה 3: on: [push, pull_request] בלי תנאי — deploy מכל branch ומכל pull request
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v5
      - run: npm ci
      # הסוד של הפרודקשן — רק בצעד שצריך אותו
      - run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
      - run: curl -fsS -X POST "$HOOK"
        env:
          HOOK: ${{ secrets.RENDER_DEPLOY_HOOK_URL }}
⚠️ טעויות נפוצות
  • "תיקון" של 1 ע"י מחיקת migrate reset — והבדיקות עדיין כותבות לפרודקשן.

P25-E21 · הגדרות עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

מה הטיפוס של כל ערך ב־process.env?

💡 רמז 2

"https://a.com, https://b.com".split(",") — הדפס את התוצאה עם JSON.stringify.

✅ פתרון
// P25-E21
export function loadConfig(env: Record<string, string | undefined>) {
  const production = env.NODE_ENV === "production";
  // תקלה 1: בפרודקשן בלי JWT_SECRET — השרת עלה עם "dev-secret", וכל אחד יכול לחתום טוקנים
  if (production && (!env.JWT_SECRET || env.JWT_SECRET.length < 32)) throw new Error("JWT_SECRET חובה בפרודקשן (32+ תווים)");
  return {
    production,
    jwtSecret: env.JWT_SECRET ?? "dev-secret",
    // תקלה 2: ב־env הכול מחרוזות. "true" === true הוא תמיד false
    debug: env.DEBUG === "true" || env.DEBUG === "1",
    // תקלה 3: "https://a.com, https://b.com" ← " https://b.com" עם רווח, שלא שווה ל־Origin של הדפדפן
    corsOrigins: (env.CORS_ORIGINS ?? "http://localhost:5500").split(",").map((o) => o.trim()).filter(Boolean),
  };
}
⚠️ טעויות נפוצות
  • Boolean(env.DEBUG) — Boolean("false") הוא true.

P25-E49 · ‏.env.example מול הקוד 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1
code.matchAll(/process\.env(?:\.([A-Z0-9_]+)|\[["']([A-Z0-9_]+)["']\])/g)

קבוצה 1 או קבוצה 2.

💡 רמז 2

שורה בדוגמה: /^(?:export\s+)?([A-Z0-9_]+)=/ אחרי trim.

✅ פתרון
// P25-E49: .env.example מול הקוד
export function envDrift(exampleText: string, code: string) {
  const used = new Set<string>();
  for (const m of code.matchAll(/process\.env(?:\.([A-Z0-9_]+)|\[["']([A-Z0-9_]+)["']\])/g)) used.add(m[1] ?? m[2]);
  const documented = new Set<string>();
  for (const raw of exampleText.split("\n")) {
    const line = raw.trim();
    if (!line || line.startsWith("#")) continue;
    const m = /^(?:export\s+)?([A-Z0-9_]+)=/.exec(line);
    if (m) documented.add(m[1]);
  }
  return {

const VERIFY: Record<string, boolean> = { require: true, "verify-ca": true, "verify-full": true, "no-verify": false };

export function pgConnectionOptions(url: string): { connectionString: string; ssl?: { rejectUnauthorized: boolean } } {
  if (!url) return { connectionString: url };
  const u = new URL(url);
  const mode = u.searchParams.get("sslmode");
  u.searchParams.delete("sslmode");
  u.searchParams.delete("channel_binding");
  const connectionString = u.toString();
  if (!mode || mode === "disable") return { connectionString };
  if (!Object.hasOwn(VERIFY, mode)) throw new Error(`sslmode לא מוכר: ${mode}`);
  return { connectionString, ssl: { rejectUnauthorized: VERIFY[mode] } };
}

// P25-E52: CORS_ORIGINS — מחמיר בפרודקשן
export function parseCorsOrigins(value: string | undefined, nodeEnv: "development" | "test" | "production"): string[] {
  const list = [...new Set((value ?? "").split(",").map((s) => s.trim()).filter(Boolean))];
  if (list.length === 0) {
    if (nodeEnv === "production") throw new Error("CORS_ORIGINS חובה בפרודקשן");
    return ["http://localhost:5500"];
  }
  const valid = nodeEnv === "production" ? /^https:\/\/[^/*\s]+$/ : /^https?:\/\/[^/*\s]+$/;
  const bad = list.filter((o) => !valid.test(o));
  if (bad.length) throw new Error(`CORS_ORIGINS לא תקין: ${bad.join(", ")}`);
  return list;
}

export function maskLog(text: string, secrets: string[]): string {
  const forms = new Set<string>();
  for (const s of secrets) {
    if (s.length < 4) continue;
    forms.add(s);
    forms.add(Buffer.from(s).toString("base64"));
    forms.add(Buffer.from(s).toString("base64url"));
    forms.add(encodeURIComponent(s));
  }
  let out = text;
  for (const f of [...forms].sort((a, b) => b.length - a.length)) out = out.split(f).join("***");
  return out;
}

// P25-E57: סודות מקבצים — NAME_FILE
export function resolveFileEnv(env: Record<string, string | undefined>, readFile: (path: string) => string) {
  const out: Record<string, string | undefined> = { ...env };
  for (const [key, path] of Object.entries(env)) {
    if (!key.endsWith("_FILE") || !path) continue;
    const name = key.slice(0, -"_FILE".length);
    if (env[name] !== undefined) throw new Error(`${name} ו־${name}_FILE מוגדרים שניהם`);
    let content: string;
    try {
      content = readFile(path);
    } catch {
      throw new Error(`לא ניתן לקרוא את ${name}_FILE`); // בלי הנתיב ובלי התוכן
    }
    out[name] = content.replace(/(\r?\n)+$/, "");
    delete out[key];
  }
  return out;
}

// P25-E58: אימות JWT עם שני מפתחות
import { JwtService } from "@nestjs/jwt";

export function createVerifier(secrets: string[]) {
  if (secrets.length === 0 || secrets.some((s) => s.length < 32)) throw new Error("מפתח לא תקין");
  const jwt = new JwtService();
  return async (token: string) => {
    for (const [keyIndex, secret] of secrets.entries()) {
      try {
        const payload = await jwt.verifyAsync<Record<string, unknown>>(token, { secret });
        return { payload, keyIndex };
      } catch (err) {
        // החתימה תואמת אבל פג תוקף — אין טעם לנסות מפתח אחר
        if ((err as Error).name === "TokenExpiredError") throw new Error("TOKEN_EXPIRED");
      }
    }
    throw new Error("INVALID_TOKEN");
  };
}

‏keyIndex שימושי למדד: כמה בקשות עוד מגיעות עם המפתח הישן. כשזה 0 — אפשר להוציא אותו.
