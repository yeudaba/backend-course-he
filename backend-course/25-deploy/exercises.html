P25-E02 · לקרוא workflow

רמה 1⏱ 10 דק׳ידע נדרש: שיעור 1

זה ה־workflow של הפרויקט (מקוצר). ענה:

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
permissions:
  contents: read
jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres: { image: postgres:18-alpine, ports: ["5432:5432"] }
    steps:
      - uses: actions/checkout@v5
      - run: npm ci
      - run: npm test
  docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - run: docker build -t tasks-api:${{ github.sha }} .
  deploy:
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    needs: [test, docker]
    environment: production
    steps:
      - run: curl -fsS -X POST "$RENDER_DEPLOY_HOOK_URL"
        env:
          RENDER_DEPLOY_HOOK_URL: ${{ secrets.RENDER_DEPLOY_HOOK_URL }}
  1. פתחת pull request מ־branch בשם feature/stats. אילו jobs רצים?
  2. עשית merge. אילו jobs רצים, ובאיזה סדר?
  3. push ל־branch experiment (בלי pull request). מה רץ?
  4. הבדיקות נכשלו ב־main. מה קורה עם deploy?
  5. מה זה actions/checkout@v5, ולמה צריך אותו?
  6. למה curl -fsS ולא סתם curl?

P25-E04 · deploy בלי downtime

רמה 1⏱ 15 דק׳ידע נדרש: שיעור 3

הגרסה הנוכחית רצה. ה־deploy: migration ← הגרסה החדשה עולה ← התנועה עוברת אליה. במשך דקה או שתיים הגרסה הישנה עדיין מקבלת בקשות מול המסד החדש. לכל migration — בטוח או שובר, ואם שובר — איך עושים אותו בבטחה:

  1. הוספת עמודה archived_at TIMESTAMPTZ (מותר NULL)
  2. שינוי שם title ל־name
  3. מחיקת העמודה priority, שהגרסה החדשה כבר לא משתמשת בה
  4. הוספת time_zone TEXT NOT NULL בלי DEFAULT
  5. אינדקס על טבלה של 50 מיליון שורות

P25-E15 · הגרסה הבאה מה־commits 🤖

P25-E17 · pipeline עם rollback 🤖

רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E17.ts: runPipeline(version, steps, log) ← { ok, running }, כש־steps הוא { currentVersion, migrate, deploy, smoke }:

  1. שומרים את הגרסה שרצה עכשיו.
  2. migrate(). נכשל ← עוצרים: לא עושים deploy בכלל.
  3. deploy(version) ו־smoke(version). הצליח ← { ok: true, running: version }.
  4. deploy זרק או smoke החזיר false ← rollback: deploy(הקודמת), ו־{ ok: false, running: הקודמת }.

וכתוב שורות ל־log לאורך הדרך.

P25-E18 · מי הלקוח? X-Forwarded-For 🤖

רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

בקובץ P25-E18.ts: clientIp(remoteAddress, forwardedFor, hops) — מה Express עושה עם trust proxy: hops.

  • forwardedFor — הערך של X-Forwarded-For: רשימה מופרדת בפסיקים. כל proxy מוסיף בסוף את הכתובת שהתחברה אליו.
  • hops — כמה proxies שלנו יש לפני השרת. 0 ← remoteAddress.
  • סופרים מהסוף: remoteAddress הוא hop 0, הכתובת האחרונה ברשימה — hop 1, וכן הלאה. רשימה קצרה מ־hops — הכתובת הכי רחוקה שיש.

הבודק משווה גם ל־req.ip של Express האמיתי.

P25-E19 · retry עם backoff 🤖

רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E19.ts:

  • isRetryable(err) — HttpStatusError עם 429 או 5xx ← כן; 4xx אחר ← לא; כל שגיאה אחרת (רשת) ← כן.
  • backoffDelays({ retries, baseMs, maxMs, random }) ← לכל ניסיון חוזר i (מ־0): Math.floor(random() × min(maxMs, baseMs × 2^i)).
  • retry(fn, { retries, baseMs, maxMs, random, sleep }) — קורא ל־fn(attempt) (מ־1). שגיאה שאפשר לנסות שוב ← sleep(delay) ושוב, עד retries פעמים. אחרת, או כשנגמרו — זורק את השגיאה האחרונה.

P25-E25 · אתגר: blue/green 🤖

רמה 5⏱ 60 דק׳ידע נדרש: שיעור 3

בקובץ P25-E25.ts: מחלקה BlueGreen מעל Platform (start(color, version), healthy(color), stop(color)):

  • live — { color, version } של מה שמקבל תנועה, או null. history — הגרסאות שקיבלו תנועה, לפי הסדר (עותק).
  • deploy(version, { attempts = 5 }): מעלה את הגרסה ב"צבע" הפנוי (בפעם הראשונה — blue), בודק healthy עד attempts פעמים. תקין ← התנועה עוברת אליו, true. לא ← stop על הפנוי, התנועה לא זזה, false.
  • rollback(): אם בצבע השני רצה גרסה תקינה — התנועה עוברת אליה, true. אחרת false.
  • retireIdle(): עוצר את הצבע שלא מקבל תנועה (ואז אין rollback מיידי).
