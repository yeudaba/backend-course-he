P25-E01 · CI, CD, deploy — מה זה מה?

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 1

לכל משפט — נכון או לא, ולמה:

  1. "יש לנו CI: כל מפתח מריץ npm test לפני push."
  2. "CI נכשל על ה־pull request שלי, אבל אצלי זה עובר — אז אפשר לעשות merge."
  3. "Continuous Delivery אומר שכל commit ל־main עולה אוטומטית לפרודקשן."
  4. "ה־CI צריך לבנות את ה־Docker image, גם אם לא מעלים אותו לשום מקום."
  5. "deploy שנכשל באמצע — הכי טוב לתקן מהר ולעשות deploy שוב."
  6. "ב־CI מריצים את הבדיקות מול המסד של הפרודקשן, כדי לבדוק על נתונים אמיתיים."

P25-E02 · לקרוא workflow

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 1

זה ה־workflow של הפרויקט (מקוצר). ענה:

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
permissions:
  contents: read
jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres: { image: postgres:18-alpine, ports: ["5432:5432"] }
    steps:
      - uses: actions/checkout@v5
      - run: npm ci
      - run: npm test
  docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - run: docker build -t tasks-api:${{ github.sha }} .
  deploy:
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    needs: [test, docker]
    environment: production
    steps:
      - run: curl -fsS -X POST "$RENDER_DEPLOY_HOOK_URL"
        env:
          RENDER_DEPLOY_HOOK_URL: ${{ secrets.RENDER_DEPLOY_HOOK_URL }}
  1. פתחת pull request מ־branch בשם feature/stats. אילו jobs רצים?
  2. עשית merge. אילו jobs רצים, ובאיזה סדר?
  3. push ל־branch experiment (בלי pull request). מה רץ?
  4. הבדיקות נכשלו ב־main. מה קורה עם deploy?
  5. מה זה actions/checkout@v5, ולמה צריך אותו?
  6. למה curl -fsS ולא סתם curl?

P25-E14 · strategy.matrix 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 1

ב־GitHub Actions, strategy.matrix מריץ את אותו job על כמה שילובים. בקובץ P25-E14.ts כתוב expandMatrix(matrix) שמחזיר את רשימת השילובים, לפי הכללים של GitHub:

  1. מכפלה של כל הצירים, לפי הסדר (הציר הראשון — הלולאה החיצונית).
  2. exclude: מוחק כל שילוב שמתאים לכל השדות שבפריט (גם פריט חלקי).
  3. include (אחרי exclude): אם הפריט מתאים לשילובים קיימים בצירים המקוריים, והשדות הנוספים לא דורסים ערכים קיימים — מוסיף לכל אחד מהם את השדות הנוספים. אחרת — שילוב חדש בסוף.
