P25-E02 · לקרוא workflow

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 1

זה ה־workflow של הפרויקט (מקוצר). ענה:

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
permissions:
  contents: read
jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres: { image: postgres:18-alpine, ports: ["5432:5432"] }
    steps:
      - uses: actions/checkout@v5
      - run: npm ci
      - run: npm test
  docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - run: docker build -t tasks-api:${{ github.sha }} .
  deploy:
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    needs: [test, docker]
    environment: production
    steps:
      - run: curl -fsS -X POST "$RENDER_DEPLOY_HOOK_URL"
        env:
          RENDER_DEPLOY_HOOK_URL: ${{ secrets.RENDER_DEPLOY_HOOK_URL }}
  1. פתחת pull request מ־branch בשם feature/stats. אילו jobs רצים?
  2. עשית merge. אילו jobs רצים, ובאיזה סדר?
  3. push ל־branch experiment (בלי pull request). מה רץ?
  4. הבדיקות נכשלו ב־main. מה קורה עם deploy?
  5. מה זה actions/checkout@v5, ולמה צריך אותו?
  6. למה curl -fsS ולא סתם curl?

P25-E14 · strategy.matrix 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 1

ב־GitHub Actions, strategy.matrix מריץ את אותו job על כמה שילובים. בקובץ P25-E14.ts כתוב expandMatrix(matrix) שמחזיר את רשימת השילובים, לפי הכללים של GitHub:

  1. מכפלה של כל הצירים, לפי הסדר (הציר הראשון — הלולאה החיצונית).
  2. exclude: מוחק כל שילוב שמתאים לכל השדות שבפריט (גם פריט חלקי).
  3. include (אחרי exclude): אם הפריט מתאים לשילובים קיימים בצירים המקוריים, והשדות הנוספים לא דורסים ערכים קיימים — מוסיף לכל אחד מהם את השדות הנוספים. אחרת — שילוב חדש בסוף.

P25-E35 · מה נכשל? סיכום של לוג 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 20 דק׳ידע נדרש: שיעור 1

בלוג של GitHub Actions כל צעד מתחיל ב־##[group]Run …, ושגיאות מסומנות ב־##[error] (סעיף 4). בקובץ 25-deploy/starter/P25-E35.ts (יש בו רק הערה) כתוב וייצא:

export function summarizeLog(text: string): { failedStep: string | null; firstError: string | null; errorCount: number; exitCode: number | null }
  • לשורות יכול להיות prefix של זמן (2026-11-07T15:40:01.1234567Z ) — מתעלמים ממנו.

  • errorCount — כמה שורות ##[error], בלי שורות ה־exit code. ‏exitCode — המספר מהשורה Process completed with exit code N. הראשונה, או null.

P25-E36 · האם ה־workflow ירוץ? 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 1

בקובץ 25-deploy/starter/P25-E36.ts (יש בו רק הערה) כתוב וייצא:

type Filter = { branches?: string[]; "branches-ignore"?: string[] } | null;
export type On = string | string[] | Record<string, Filter>;
export function shouldTrigger(on: On, event: { name: string; branch: string }): boolean
  • on הוא מה שיוצא מה־YAML: מחרוזת (on: push), מערך (on: [push, pull_request]), או אובייקט שהמפתחות שלו הם שמות אירועים.
  • מחרוזת או מערך ← רץ אם שם האירוע ברשימה, לכל branch.
  • אובייקט ← האירוע חייב להיות מפתח. ערך null או בלי מסננים ← כל branch. ‏branches ← ה־branch חייב להתאים לאחד הדפוסים. ‏branches-ignore ← ה־branch לא יכול להתאים לאף אחד.
  • דפוס: * ← כל רצף תווים בלי /; ‏** ← כל רצף, כולל /. כל תו אחר — כמו שהוא.
  • ב־pull_request, ‏branch הוא ה־branch שאליו ה־PR מכוון.

P25-E43 · ‏package.json מוכן ל־CI? 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: פרק 13, שיעור 1

לפני שמוסיפים CI, כדאי לוודא שיש מה להריץ. בקובץ 25-deploy/starter/P25-E43.ts (יש בו רק הערה) כתוב וייצא:

export function ciReadiness(pkg: { scripts?: Record<string, string>; engines?: Record<string, string>; devDependencies?: Record<string, string>; dependencies?: Record<string, string> }): string[]

מחזיר רשימת בעיות (מחרוזות), לפי הסדר הזה, רק את אלה שקיימות:

  1. "missing script: test", ‏"missing script: typecheck", ‏"missing script: build" — לכל אחד שחסר.
  2. "test runs in watch mode" — אם ב־test יש --watch (ב־CI הוא לא ייגמר לעולם).
  3. "typecheck should not emit" — אם ב־typecheck יש tsc בלי --noEmit.
  4. "typescript is not installed" — אם סקריפט כלשהו מריץ tsc, ו־typescript לא ב־dependencies ולא ב־devDependencies.
  5. "engines.node is missing" — אין engines.node.
