P25-E01 · CI, CD, deploy — מה זה מה? 🧠 הבנה רמה 1

💡 רמז 1

CI = שרת שמריץ את הבדיקות על כל שינוי, בסביבה נקייה. ההבדל מ"אצלי" הוא בדיוק העניין.

💡 רמז 2

Continuous Delivery מול Continuous Deployment — מילה אחת, הבדל גדול.

✅ פתרון
  1. לא. זו משמעת, לא CI. CI הוא שרת שמריץ את הבדיקות על כל push וכל pull request — גם כשמישהו שכח, ממהר, או בטוח ש"זה רק README".
  2. לא. "אצלי עובר" הוא בדיוק מה ש־CI נועד לבדוק: אצלך יש קובץ שלא עשית לו commit, node_modules ישן, מסד עם נתונים, אזור זמן אחר. הסביבה הנקייה של ה־CI היא האמת. (בפרק הזה ראינו את זה קורה: npm run typecheck עבר אצלנו ונכשל ב־CI.)
  3. לא — זה Continuous Deployment. Delivery: כל commit ב־main מוכן לעלות (נבדק, נבנה), ומישהו לוחץ. Deployment: עולה לבד. בפרויקט שלנו — Deployment, עם בדיקת עשן אחרי.
  4. נכון. Dockerfile שבור (קובץ שחסר ב־.dockerignore, שלב שנכשל) צריך להתגלות ב־pull request, לא ב־deploy.
  5. לא, בדרך כלל. קודם rollback — חוזרים לגרסה שעבדה, תוך דקה, והמשתמשים בסדר. ואז מתקנים בשקט, עם בדיקה שתופסת את הבאג.
  6. לא! בדיקות מוחקות, מאפסות ויוצרות נתונים (TRUNCATE, migrate reset). מסד בדיקות נפרד — שירות PostgreSQL בתוך ה־CI (E13). והסוד של מסד הפרודקשן לא מגיע בכלל ל־job של הבדיקות (E20).
⚠️ טעויות נפוצות
  • "CI ירוק = אין באגים". CI בודק רק מה שיש עליו בדיקות.

P25-E02 · לקרוא workflow 🧠 הבנה רמה 1

💡 רמז 1

on קובע מתי ה־workflow מתחיל. if — אם job מסוים רץ. needs — אחרי מי.

💡 רמז 2

runner מתחיל ריק: בלי הקוד שלך. ו־curl בלי -f מחזיר exit code 0 גם על 404.

✅ פתרון
  1. test ו־docker, במקביל. deploy מדולג: github.event_name הוא pull_request.
  2. merge ל־main = push ל־main: test ו־docker במקביל, ורק אם שניהם עברו — deploy.
  3. כלום. on.push.branches: [main]. (אם רוצים CI גם על branches בלי PR — מוחקים את ה־branches מ־push, ו־deploy עדיין מוגן ב־if.)
  4. deploy לא רץ (needs). הפרודקשן נשאר על הגרסה הקודמת — וזה כל הרעיון.
  5. action מוכן (קוד של GitHub) שמוריד את ה־repo ל־runner. בלעדיו ה־runner ריק, ו־npm ci נכשל: אין package.json. @v5 — גרסה ראשית קבועה: לא מתעדכן לגרסה שוברת לבד.
  6. -f: תשובת HTTP של שגיאה (404, 500) ← exit code שונה מ־0, וה־step נכשל. בלי זה, deploy hook שגוי "מצליח" ואף אחד לא יודע. -sS: בלי פס התקדמות, אבל כן הודעת שגיאה.
⚠️ טעויות נפוצות
  • לחשוב שה־jobs רצים לפי הסדר בקובץ. בלי needs — במקביל.

P25-E29 · מה ירוץ, ומתי? 🧠 הבנה רמה 2

💡 רמז 1

ב־pull_request, ה־branches מתייחס ל־branch שאליו ה־PR מכוון (main), לא לזה שממנו.

💡 רמז 2

job עם needs לא רץ אם אחד מה־jobs שהוא תלוי בהם נכשל.

✅ פתרון
  1. כלום. push רק ל־main מפעיל.
  2. test ו־docker (אירוע pull_request, מכוון ל־main). deploy — לא: ה־if דורש push.
  3. שוב test ו־docker — כל push ל־branch של PR פתוח מעדכן את ה־PR ומריץ מחדש.
  4. merge = push ל־main: ‏test ו־docker במקביל, ואם שניהם עברו — deploy.
  5. test אדום; docker רץ (במקביל, לא תלוי בו); deploy מדולג ("skipped") — לא עולה לאוויר קוד שהבדיקות שלו נכשלו.
⚠️ טעויות נפוצות
  • לשים deploy רק עם if ובלי needs — הוא רץ במקביל לבדיקות, ומעלה גם כשהן נכשלות.

P25-E30 · ‏npm ci ולא npm install 🧠 הבנה רמה 1

💡 רמז 1

npm ci לא משנה את ה־lock — הוא נכשל אם הוא לא תואם.

💡 רמז 2

מה בדיוק ה־CI בודק — את הקוד שלך, או את מה שבמקרה הותקן היום?

✅ פתרון
  1. npm ci נכשל מיד עם הודעה ברורה ("package.json and package-lock.json are not in sync"). ‏npm install "מתקן" את ה־lock בשקט, על ה־runner — וה־CI בודק משהו שאף אחד לא עשה לו commit.
  2. npm ci מתקין בדיוק את הגרסאות שב־lock. ‏npm install יכול להתקין את החדשה.
  3. גרסה חדשה של תלות (בתוך הטווח) הותקנה ב־CI ושברה משהו — בלי שינוי בקוד שלך. עם npm ci מה שנבדק = מה שבריפו, ושדרוג קורה רק כשמישהו מעדכן את ה־lock בכוונה (ב־PR, עם CI).
⚠️ טעויות נפוצות
  • למחוק את package-lock.json "כי יש בו קונפליקטים" — ואיתו את כל ההבטחה של "אותה התקנה בכל מקום".

P25-E31 · כמה זמן ייקח ה־workflow? 🧠 הבנה רמה 2

💡 רמז 1

jobs בלי needs מתחילים יחד. job עם needs מתחיל כשהאחרון מהם נגמר.

💡 רמז 2

deploy לא תלוי ב־lint בגרסה הראשונה.

✅ פתרון
  1. lint, ‏test ו־docker במקביל. deploy מתחיל אחרי test (3 דקות, הארוך מבין השניים שהוא צריך) ← סך הכול 4 דקות.
  2. docker מחכה ל־test (3) ← רץ 2 ← deploy מתחיל אחרי 5 ← סך הכול 6 דקות.
  3. בגרסה הראשונה: lint אדום, ‏test ו־docker רצים, ו־deploy כן רץ — כי הוא לא תלוי ב־lint! (תיקון: needs: [lint, test, docker].) בשנייה: docker מדולג, ולכן גם deploy.
  4. אם ה־build של ה־image לא צריך את התוצאה של הבדיקות — במקביל: משוב מהיר יותר. התלות האמיתית היא של deploy, בכל מה שחייב לעבור.
⚠️ טעויות נפוצות
  • לשרשר את כל ה־jobs ב־needs "כדי שיהיה בטוח" — ה־CI איטי פי כמה, ואנשים מפסיקים לחכות לו.

P25-E32 · לקרוא ריצה אדומה 🧠 הבנה רמה 2

💡 רמז 1

שם הבדיקה מדבר על "תאריך בעבר". מה ב־CI שונה מהמחשב שלך בעניין תאריכים?

💡 רמז 2

git status — מה יש אצלך שאין ב־Git?

✅ פתרון
  1. בדיקה אחת ב־tasks.service.spec.ts: ציפתה לשגיאה ("dueDate בעבר"), והפעולה הצליחה. אצלך: npm test -- tasks.service — אותה פקודה, לא "משהו דומה".
  2. (א) אזור זמן: ה־runner ב־UTC, אתה בישראל — ו"היום" שונה (פרק 24, שיעור 2). TZ=UTC npm test משחזר. (ב) שעון: הבדיקה משתמשת ב־new Date() ולא בשעון קבוע — עוברת או נכשלת לפי השעה. (ג) קובץ שלא ב־Git (‏git status), או תלות בגרסה אחרת (‏npm ci אצלך).
  3. להריץ שוב ב־CI "אולי יעבור", או לסמן את הבדיקה כ־skip. בדיקה שעוברת לפעמים היא בדיוק הבאג של שיעור 2 בפרק 24 — הוא יגיע למשתמשים.
⚠️ טעויות נפוצות
  • לקרוא רק את ##[error] האחרון ("exit code 1") — הוא תוצאה; הסיבה למעלה.

  push:
    branches: [main]
  pull_request:
    branches: [main]

P25-E14 · strategy.matrix 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

מכפלה: מתחילים מ־[{}], ולכל ציר — flatMap.

💡 רמז 2

matrix עם include בלבד (בלי צירים) — כל פריט הוא שילוב.

✅ פתרון
// P25-E14
type Value = string | number | boolean;
type Combo = Record<string, Value>;

export function expandMatrix(matrix: Record<string, Value[] | Combo[]>): Combo[] {
  const { include = [], exclude = [], ...axes } = matrix as { include?: Combo[]; exclude?: Combo[] } & Record<string, Value[]>;
  // 1. מכפלה קרטזית של כל הצירים, לפי הסדר
  let combos: Combo[] = [{}];
  for (const [key, values] of Object.entries(axes)) {
    combos = combos.flatMap((c) => values.map((v) => ({ ...c, [key]: v })));
  }
  if (Object.keys(axes).length === 0) combos = [];
  // 2. exclude: מוחק כל שילוב שמתאים לכל השדות שב־exclude
  const matches = (c: Combo, partial: Combo) => Object.entries(partial).every(([k, v]) => c[k] === v);
  combos = combos.filter((c) => !exclude.some((e) => matches(c, e)));
  // 3. include: מוסיף שדות לשילובים קיימים שמתאימים בצירים המקוריים — ואם אין כאלה, שילוב חדש
  const axisKeys = new Set(Object.keys(axes));
  for (const inc of include) {
    const original = Object.fromEntries(Object.entries(inc).filter(([k]) => axisKeys.has(k)));
    const targets = combos.filter((c) => matches(c, original) && Object.entries(inc).every(([k, v]) => axisKeys.has(k) || !(k in c) || c[k] === v));
    if (targets.length > 0 && Object.keys(original).length > 0) targets.forEach((c) => Object.assign(c, inc));
    else combos.push({ ...inc });
  }
  return combos;
}

מתי בפועל? ספרייה שצריכה לעבוד על Node 22 וגם 24, או בדיקות שמתחלקות ל־4 jobs במקביל כדי לרוץ מהר יותר. לפרויקט כמו שלנו (שרת אחד, Node 24 אחד) — לא צריך.

⚠️ טעויות נפוצות
  • matrix של 3×3×2 = 18 jobs על כל push. דקות CI הן משאב.

P25-E34 · מלכודות של YAML 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

/^\s*(?:-\s+)?([\w-]+):\s+(.*)$/ — קבוצה 1 המפתח, קבוצה 2 הערך.

💡 רמז 2

הערה: value.replace(/\s+#.*$/, "").trim(). ‏node-version: 24 הוא מספר, אבל String(24) === "24" — לא מלכודת.

✅ פתרון
// P25-E34: מלכודות של YAML
import { load } from "js-yaml";

export function yamlTraps(text: string) {
  const traps: { line: number; key: string; raw: string; parsed: unknown }[] = [];
  text.split("\n").forEach((line, i) => {
    const m = /^\s*(?:-\s+)?([\w-]+):\s+(.*)$/.exec(line);
    if (!m) return;
    const raw = m[2].replace(/\s+#.*$/, "").trim();
    if (raw === "" || /^["'[{|>&*$]/.test(raw)) return;
    const parsed = load(raw);
    if (typeof parsed !== "string" && String(parsed) !== raw) traps.push({ line: i + 1, key: m[1], raw, parsed });
  });
  return traps;
}

P25-E35 · מה נכשל? סיכום של לוג 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הסרת הזמן: line.replace(/^\d{4}-\d{2}-\d{2}T[\d:.]+Z\s/, "").

💡 רמז 2

משתנה currentStep שמתעדכן בכל ##[group]Run — וכשמגיעה השגיאה הראשונה, שומרים אותו.

✅ פתרון
// P25-E35: מה נכשל? סיכום של לוג
export function summarizeLog(text: string) {
  let currentStep: string | null = null;
  let failedStep: string | null = null;
  let firstError: string | null = null;
  let errorCount = 0;
  let exitCode: number | null = null;
  for (const raw of text.split("\n")) {
    const line = raw.replace(/^\d{4}-\d{2}-\d{2}T[\d:.]+Z\s/, "");
    if (line.startsWith("##[group]Run ")) currentStep = line.slice("##[group]Run ".length).trim();
    if (!line.startsWith("##[error]")) continue;
    const msg = line.slice("##[error]".length).trim();
    const exit = /^Process completed with exit code (\d+)\.$/.exec(msg);
    if (exit) {
      exitCode ??= Number(exit[1]);
      continue;
    }
    errorCount++;
    if (firstError === null) {
      firstError = msg;
      failedStep = currentStep;
    }
  }
  return { failedStep, firstError, errorCount, exitCode };
}

💡 רמז 1

💡 רמז 2

קודם ** ואחר כך * — אחרת ** הופך ל־[^/]*[^/]*. אפשר לפצל: pattern.split("**").

✅ פתרון
// P25-E36: האם ה־workflow ירוץ?
type Filter = { branches?: string[]; "branches-ignore"?: string[] } | null;
export type On = string | string[] | Record<string, Filter>;

const esc = (s: string) => s.replace(/[.+?^${}()|[\]\\]/g, "\\$&");
function toRegex(pattern: string): RegExp {
  const body = pattern
    .split("**")
    .map((part) => part.split("*").map(esc).join("[^/]*"))
    .join(".*");
  return new RegExp(`^${body}$`);
}
const matchesAny = (branch: string, patterns: string[]) => patterns.some((p) => toRegex(p).test(branch));

export function shouldTrigger(on: On, event: { name: string; branch: string }): boolean {
  if (typeof on === "string") return on === event.name;
  if (Array.isArray(on)) return on.includes(event.name);
  if (!Object.hasOwn(on, event.name)) return false;
  const filter = on[event.name];
  if (filter?.branches && !matchesAny(event.branch, filter.branches)) return false;
  if (filter?.["branches-ignore"] && matchesAny(event.branch, filter["branches-ignore"])) return false;
  return true;
}

‏esc — כדי ש־release/1.0 לא יתאים ל־release/1x0 (נקודה ב־regex היא "כל תו").

⚠️ טעויות נפוצות
  • branch.startsWith(pattern.replace("*", "")) — ‏feature/* תופס גם feature/a/b, ו־*-hotfix לא עובד בכלל.

// P25-E37: DATABASE_URL מתוך services
export function databaseUrlFromService(service: { env?: Record<string, string>; ports?: string[] }): string {
  const env = service.env ?? {};
  const user = env.POSTGRES_USER ?? "postgres";
  const password = env.POSTGRES_PASSWORD;
  if (!password) throw new Error("חסר POSTGRES_PASSWORD");
  const db = env.POSTGRES_DB ?? user;
  let hostPort: string | undefined;
  for (const p of service.ports ?? []) {
    const parts = String(p).split(":"); // "55432:5432" או "5432"
    if (parts.at(-1) === "5432") hostPort = parts[0];
  }
  if (!hostPort) throw new Error("השירות לא חושף את 5432");
  return `postgresql://${encodeURIComponent(user)}:${encodeURIComponent(password)}@localhost:${hostPort}/${db}`;
}

// P25-E41: סיכום של node --test ל־CI
export type TestSummary = { tests: number; pass: number; fail: number; skipped: number; durationMs: number; failed: string[] };

export function parseTestOutput(text: string): TestSummary {
  const s: TestSummary = { tests: 0, pass: 0, fail: 0, skipped: 0, durationMs: 0, failed: [] };
  const failed = new Set<string>();
  for (const raw of text.split("\n")) {
    const line = raw.trim();
    const m = /^ℹ (tests|pass|fail|skipped|duration_ms) ([\d.]+)$/.exec(line);
    if (m) {
      const n = Number(m[2]);
      if (m[1] === "duration_ms") s.durationMs = Math.round(n);
      else s[m[1] as "tests" | "pass" | "fail" | "skipped"] = n;
      continue;
    }
    const f = /^✖ (.+?) \([\d.]+ms\)$/.exec(line);
    if (f) failed.add(f[1]);
  }
  s.failed = [...failed];
  return s;
}

export function toMarkdown(s: TestSummary): string {
  const head = `## ${s.fail > 0 ? "❌" : "✅"} ${s.pass}/${s.tests} בדיקות עברו`;
  return [head, ...s.failed.map((name) => `- ✖ ${name}`)].join("\n");
}

// P25-E43: package.json מוכן ל־CI?
type Pkg = { scripts?: Record<string, string>; engines?: Record<string, string>; devDependencies?: Record<string, string>; dependencies?: Record<string, string> };

export function ciReadiness(pkg: Pkg): string[] {
  const problems: string[] = [];
  const scripts = pkg.scripts ?? {};
  for (const name of ["test", "typecheck", "build"]) {
    if (!scripts[name]) problems.push(`missing script: ${name}`);
  }
  if (scripts.test?.includes("--watch")) problems.push("test runs in watch mode");
  if (scripts.typecheck && /\btsc\b/.test(scripts.typecheck) && !scripts.typecheck.includes("--noEmit")) problems.push("typecheck should not emit");
  const usesTsc = Object.values(scripts).some((cmd) => /\btsc\b/.test(cmd));
  const hasTs = Boolean(pkg.dependencies?.typescript ?? pkg.devDependencies?.typescript);
  if (usesTsc && !hasTs) problems.push("typescript is not installed");
  if (!pkg.engines?.node) problems.push("engines.node is missing");
  return problems;
}
⚠️ טעויות נפוצות
