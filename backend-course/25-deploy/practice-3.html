P25-E04 · deploy בלי downtime

🧠 הבנהרמה 1⏱ 15 דק׳ידע נדרש: שיעור 3

הגרסה הנוכחית רצה. ה־deploy: migration ← הגרסה החדשה עולה ← התנועה עוברת אליה. במשך דקה או שתיים הגרסה הישנה עדיין מקבלת בקשות מול המסד החדש. לכל migration — בטוח או שובר, ואם שובר — איך עושים אותו בבטחה:

  1. הוספת עמודה archived_at TIMESTAMPTZ (מותר NULL)
  2. שינוי שם title ל־name
  3. מחיקת העמודה priority, שהגרסה החדשה כבר לא משתמשת בה
  4. הוספת time_zone TEXT NOT NULL בלי DEFAULT
  5. אינדקס על טבלה של 50 מיליון שורות

P25-E10 · בדיקת עשן 🤖

  • בכל ניסיון: GET /version. אם 200 ו־commit מתאים (מלא, או ש־expectCommit מקוצר והוא תחילת ה־commit) — GET /ready. 200 ← הצלחה.

P25-E15 · הגרסה הבאה מה־commits 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E15.ts: nextVersion(current, commits) ← { version, bump, notes }, לפי Conventional Commits ו־SemVer:

  • שורה ראשונה: type(scope)!: subject (scope ו־! — רשות). commit שלא בפורמט — מתעלמים.
  • !, או שורה בגוף שמתחילה ב־BREAKING CHANGE: ← major. feat ← minor. fix ← patch. השאר (docs, chore, ci…) — לא משנים גרסה.
  • major מאפס minor ו־patch; minor מאפס patch.
  • notes: קבוצות בסדר "⚠️ שינויים שוברים", "✨ חדש", "🐛 תיקונים" — רק קבוצות לא ריקות, כל אחת ### כותרת ואז - scope: subject (או - subject), עם שורה ריקה בין קבוצות.
  • גרסה שאינה X.Y.Z ← Error("גרסה לא תקינה: …").

P25-E16 · migration שלא שובר את מה שרץ 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E16.ts: checkMigration(sql) ← רשימת { line, rule, message } (מספרי שורות מ־1). כללים:

  • drop-column — DROP COLUMN. drop-table — DROP TABLE.
  • rename — RENAME COLUMN או RENAME TO.
  • alter-type — ALTER COLUMN x TYPE / SET DATA TYPE.
  • index-without-concurrently — CREATE [UNIQUE] INDEX בלי CONCURRENTLY.
  • not-null-without-default — שורה עם ADD COLUMN ו־NOT NULL בלי DEFAULT.

בלי תלות באותיות גדולות/קטנות, והערות (-- …) לא נחשבות. לכל ממצא — הסבר קצר ב־message.

P25-E17 · pipeline עם rollback 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E17.ts: runPipeline(version, steps, log) ← { ok, running }, כש־steps הוא { currentVersion, migrate, deploy, smoke }:

  1. שומרים את הגרסה שרצה עכשיו.
  2. migrate(). נכשל ← עוצרים: לא עושים deploy בכלל.
  3. deploy(version) ו־smoke(version). הצליח ← { ok: true, running: version }.
  4. deploy זרק או smoke החזיר false ← rollback: deploy(הקודמת), ו־{ ok: false, running: הקודמת }.

וכתוב שורות ל־log לאורך הדרך.

P25-E19 · retry עם backoff 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E19.ts:

  • isRetryable(err) — HttpStatusError עם 429 או 5xx ← כן; 4xx אחר ← לא; כל שגיאה אחרת (רשת) ← כן.
  • backoffDelays({ retries, baseMs, maxMs, random }) ← לכל ניסיון חוזר i (מ־0): Math.floor(random() × min(maxMs, baseMs × 2^i)).
  • retry(fn, { retries, baseMs, maxMs, random, sleep }) — קורא ל־fn(attempt) (מ־1). שגיאה שאפשר לנסות שוב ← sleep(delay) ושוב, עד retries פעמים. אחרת, או כשנגמרו — זורק את השגיאה האחרונה.

P25-E25 · אתגר: blue/green 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 60 דק׳ידע נדרש: שיעור 3

בקובץ P25-E25.ts: מחלקה BlueGreen מעל Platform (start(color, version), healthy(color), stop(color)):

  • live — { color, version } של מה שמקבל תנועה, או null. history — הגרסאות שקיבלו תנועה, לפי הסדר (עותק).
  • deploy(version, { attempts = 5 }): מעלה את הגרסה ב"צבע" הפנוי (בפעם הראשונה — blue), בודק healthy עד attempts פעמים. תקין ← התנועה עוברת אליו, true. לא ← stop על הפנוי, התנועה לא זזה, false.
  • rollback(): אם בצבע השני רצה גרסה תקינה — התנועה עוברת אליה, true. אחרת false.
  • retireIdle(): עוצר את הצבע שלא מקבל תנועה (ואז אין rollback מיידי).

P25-E26 · feature flags: לפתוח ל־10% מהמשתמשים 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 2⏱ 20 דק׳ידע נדרש: שיעור 3

deploy בלי downtime (שיעור 3) מבטיח שהשרת לא נופל. הוא לא מבטיח שהפיצ'ר החדש טוב. לכן פותחים אותו קודם ל־10% מהמשתמשים, ואם הכול בסדר מעלים ל־50% ול־100%. כתוב מקובץ ריק וייצא:

  • type Flag = { enabled: boolean; percent: number; allow?: string[] }.
  • bucketOf(flagName, userId): number — מספר בין 0 ל־99 שתמיד יוצא זהה לאותו משתמש ואותו דגל: ‏SHA-256 של ${flagName}:${userId} (‏createHash מ־node:crypto), ארבעת הבתים הראשונים של ה־digest כמספר (readUInt32BE(0)), מודולו 100.
  • isEnabled(flags, flagName, userId): boolean — דגל שלא קיים, או enabled: false ← false (גם למי שב־allow). משתמש ב־allow (צוות QA) ← true. אחרת bucketOf(...) < percent.

P25-E27 · כמה זמן השרת למעלה 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 1⏱ 15 דק׳ידע נדרש: שיעור 3

🔁 חזרה על Math.floor ו־% (פרק 2), ועל findIndex, ‏slice, ‏filter, ‏map ו־join (פרק 6). ‏GET /version (‏P25-E08) מחזיר גם כמה זמן השרת רץ. ‏process.uptime() נותן שניות, ובני אדם רוצים "14d 2h". כתוב וייצא formatUptime(totalSeconds): string:

  • מפרקים לימים, שעות, דקות ושניות (d, ‏h, ‏m, ‏s).
  • מתחילים מהיחידה הגדולה הראשונה שאינה 0, ולוקחים אותה ואת זו שאחריה (שתי יחידות לכל היותר). יחידה שערכה 0 לא מוצגת.
  • דוגמאות: 0 ← "0s", ‏61 ← "1m 1s", ‏3601 ← "1h" (‏1h 0m 1s: לוקחים h ו־m, וה־m הוא 0), ‏90061 ← "1d 1h".
  • מספר שאינו שלם, או שלילי ← RangeError.

P25-E28 · mapLimit: הרבה עבודות, מעט במקביל 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

🔁 חזרה על async/await ו־Promise.all (פרק 10), ‏closure (פרק 5), ‏while (פרק 4) ו־generics (פרק 11). אחרי build מעלים 400 קבצים ל־CDN. Promise.all על כולם פותח 400 חיבורים בבת אחת, וחלק נכשלים. לולאה עם await מעלה אחד־אחד, ולוקחת עשר דקות. הפתרון באמצע: כמה במקביל. כתוב וייצא:

mapLimit<T, R>(items: T[], limit: number, fn: (item: T, index: number) => Promise<R>): Promise<R[]>

  • לכל היותר limit קריאות ל־fn רצות בו־זמנית. כשאחת מסתיימת, מתחילה הבאה בתור.
  • התוצאות מוחזרות בסדר של items, גם אם פריט מאוחר הסתיים ראשון.
  • fn נכשלה ← mapLimit נדחית עם אותה שגיאה, ולא מתחילים פריטים חדשים.
  • limit שאינו שלם חיובי ← RangeError. ‏limit גדול מהרשימה, או רשימה ריקה — עובד.
