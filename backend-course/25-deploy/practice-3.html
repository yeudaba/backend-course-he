P25-E17 · pipeline עם rollback 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E17.ts: runPipeline(version, steps, log) ← { ok, running }, כש־steps הוא { currentVersion, migrate, deploy, smoke }:

  1. שומרים את הגרסה שרצה עכשיו.
  2. migrate(). נכשל ← עוצרים: לא עושים deploy בכלל.
  3. deploy(version) ו־smoke(version). הצליח ← { ok: true, running: version }.
  4. deploy זרק או smoke החזיר false ← rollback: deploy(הקודמת), ו־{ ok: false, running: הקודמת }.

וכתוב שורות ל־log לאורך הדרך.

P25-E19 · retry עם backoff 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ P25-E19.ts:

  • isRetryable(err) — HttpStatusError עם 429 או 5xx ← כן; 4xx אחר ← לא; כל שגיאה אחרת (רשת) ← כן.
  • backoffDelays({ retries, baseMs, maxMs, random }) ← לכל ניסיון חוזר i (מ־0): Math.floor(random() × min(maxMs, baseMs × 2^i)).
  • retry(fn, { retries, baseMs, maxMs, random, sleep }) — קורא ל־fn(attempt) (מ־1). שגיאה שאפשר לנסות שוב ← sleep(delay) ושוב, עד retries פעמים. אחרת, או כשנגמרו — זורק את השגיאה האחרונה.

P25-E25 · אתגר: blue/green 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 60 דק׳ידע נדרש: שיעור 3

בקובץ P25-E25.ts: מחלקה BlueGreen מעל Platform (start(color, version), healthy(color), stop(color)):

P25-E26 · feature flags: לפתוח ל־10% מהמשתמשים 🤖

💻 כתיבת קוד 🤖✍️ מאפסרמה 2⏱ 20 דק׳ידע נדרש: שיעור 3

deploy בלי downtime (שיעור 3) מבטיח שהשרת לא נופל. הוא לא מבטיח שהפיצ'ר החדש טוב. לכן פותחים אותו קודם ל־10% מהמשתמשים, ואם הכול בסדר מעלים ל־50% ול־100%. כתוב מקובץ ריק וייצא:

  • type Flag = { enabled: boolean; percent: number; allow?: string[] }.
  • bucketOf(flagName, userId): number — מספר בין 0 ל־99 שתמיד יוצא זהה לאותו משתמש ואותו דגל: ‏SHA-256 של ${flagName}:${userId} (‏createHash מ־node:crypto), ארבעת הבתים הראשונים של ה־digest כמספר (readUInt32BE(0)), מודולו 100.
  • isEnabled(flags, flagName, userId): boolean — דגל שלא קיים, או enabled: false ← false (גם למי שב־allow). משתמש ב־allow (צוות QA) ← true. אחרת bucketOf(...) < percent.

P25-E28 · mapLimit: הרבה עבודות, מעט במקביל 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

🔁 חזרה על async/await ו־Promise.all (פרק 10), ‏closure (פרק 5), ‏while (פרק 4) ו־generics (פרק 11). אחרי build מעלים 400 קבצים ל־CDN. Promise.all על כולם פותח 400 חיבורים בבת אחת, וחלק נכשלים. לולאה עם await מעלה אחד־אחד, ולוקחת עשר דקות. הפתרון באמצע: כמה במקביל. כתוב וייצא:

mapLimit<T, R>(items: T[], limit: number, fn: (item: T, index: number) => Promise<R>): Promise<R[]>

  • לכל היותר limit קריאות ל־fn רצות בו־זמנית. כשאחת מסתיימת, מתחילה הבאה בתור.
  • התוצאות מוחזרות בסדר של items, גם אם פריט מאוחר הסתיים ראשון.
  • fn נכשלה ← mapLimit נדחית עם אותה שגיאה, ולא מתחילים פריטים חדשים.
  • limit שאינו שלם חיובי ← RangeError. ‏limit גדול מהרשימה, או רשימה ריקה — עובד.

🔗 איך זה מתחבר: ‏Promises ו־async/await מפרק 10 ו־generics מפרק 11 — והשיעור: צעדי ה־pipeline שאחרי ה־build.

  • expand — בטרנזקציה אחת: מוסיף עמודה name text (אם היא עוד לא קיימת), וממלא name = title בשורות שבהן name ריק. מחזיר כמה שורות מולאו. מותר להריץ אותו פעמיים (בפעם השנייה — 0).
  • אחרי expand, ה־INSERT של "הקוד הישן" (INSERT INTO tasks (title) VALUES (...)) חייב להמשיך לעבוד.
  • contract — אם יש שורות שבהן name ריק ← Error("NOT_MIGRATED"), ולא נוגעים בכלום. אחרת — DROP COLUMN title, ו־name הופך ל־NOT NULL. בטרנזקציה אחת.
