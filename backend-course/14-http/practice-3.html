P14-E10 · מבקשה לפקודת curl 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 3

כלים כמו DevTools יודעים "Copy as cURL". בקובץ 14-http/starter/P14-E10.mjs השלם toCurl({ method, url, headers, body }):

  • method ברירת מחדל "GET"; רק אם אינו GET ← -X METHOD.
  • הכתובת, כל header (-H 'Name: value') והגוף (-d '...') — בתוך מירכאות בודדות.
  • גוף שהוא אובייקט ← JSON.stringify, ואם אין header בשם content-type (בלי תלות באותיות) ← מוסיפים Content-Type: application/json אחרי ה־headers הקיימים.
  • גרש בתוך ערך ← '\'' (סוגרים, גרש מוגן, פותחים).

סדר: curl [-X M] 'url' [-H ...] [-d ...], מופרד ברווח אחד.

P14-E15 · לקרוא קובץ .http 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ 14-http/starter/P14-E15.mjs השלם parseHttpFile(text) — "מנוע" מוקטן של REST Client. מחזירה מערך { name, method, url, headers, body }:

  • שורות @name = value (לפני ה־### הראשון) מגדירות משתנים.
  • כל שורה שמתחילה ב־### פותחת בקשה חדשה; מה שאחריה (בלי רווחים) הוא name.
  • בתוך בקשה: מדלגים על שורות ריקות ועל הערות (# או //) עד שורת METHOD URL; אחריה headers (אובייקט, שמות כמו שנכתבו) עד שורה ריקה; כל השאר — body (אחרי trim; ריק ← undefined).
  • {{name}} בכתובת, ב־headers ובגוף ← ערך המשתנה. משתנה לא מוגדר ← Error(משתנה לא מוגדר: ${name}).
  • בקשה בלי שורת METHOD URL — לא נכנסת לתוצאה.

P14-E63 · מפקודת curl לבקשה 🤖

💻 כתיבת קוד 🤖🔥 חימוםרמה 2⏱ 15 דק׳ידע נדרש: שיעור 3

ב־P14-E10 בנית פקודת curl מבקשה. עכשיו הכיוון ההפוך: כתוב וייצא parseCurlArgs(args) שמקבלת את מערך הארגומנטים (מה שאחרי המילה curl) ומחזירה { method, url, headers, body }:

  • -X/--request ← ה־method (באותיות גדולות). ‏-H/--header ← header (מפרקים לפי ה־: הראשון, ומורידים רווחים; השם נשאר כמו שנכתב). ‏-d/--data ← הגוף (מחרוזת).
  • בלי -X: יש גוף ← "POST", אין ← "GET" (בדיוק כמו curl, P14-E58).
  • -i, ‏-v, ‏-s — מתעלמים. ארגומנט שלא מתחיל ב־- הוא הכתובת.
  • דגל אחר ← throw new Error(דגל לא מוכר: ${flag}). אין כתובת ← throw new Error("חסרה כתובת"). בלי גוף ← body: undefined.
parseCurlArgs(["-i", "-d", '{"a":1}', "-H", "Content-Type: application/json", "http://localhost:4000/products"]);
// { method: "POST", url: "http://localhost:4000/products", headers: { "Content-Type": "application/json" }, body: '{"a":1}' }

% npm run check P14-E63

P14-E64 · לפרק שורת פקודה עם מירכאות 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

לפני ש־curl מקבל מערך, ה־shell מפרק את השורה (P14-E60). כתוב וייצא splitArgs(cmd) שעושה את זה בצורה מוקטנת:

  • רווחים (ותווי שורה חדשה) מפרידים בין ארגומנטים — רק מחוץ למירכאות. רצף רווחים = מפריד אחד.
  • '...' — הכול בפנים כמו שהוא. ‏"..." — הכול כמו שהוא, חוץ מ־\" שהופך ל־" ו־\\ שהופך ל־\.
  • מירכאות צמודות לטקסט מתחברות לאותו ארגומנט: -H"X: 1" ← -HX: 1, ו־'' לבד הוא ארגומנט ריק.
  • מחוץ למירכאות: \ ואחריו שורה חדשה ← כמו רווח (כך DevTools מעתיק פקודה ארוכה בכמה שורות).
  • מירכאה שלא נסגרה ← throw new Error("מירכאה לא נסגרה").
splitArgs(`curl -X POST 'http://x/a b' -H "Content-Type: application/json" -d '{"a":1}'`);
// ["curl", "-X", "POST", "http://x/a b", "-H", "Content-Type: application/json", "-d", '{"a":1}']

% npm run check P14-E64

P14-E65 · לפרק פלט של curl -v 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

כתוב וייצא parseVerbose(text) שמקבלת את הפלט של curl -v (כמו ב־P14-E59) ומחזירה:

{
  request: { method: "GET", path: "/products/1", headers: { host: "localhost:4000", ... } },
  response: { status: 200, headers: { "content-type": "application/json; charset=utf-8", ... } },
}
  • שורות > שייכות לבקשה ושורות < לתשובה. השורה הראשונה בכל צד היא שורת הבקשה / שורת ה־status; השאר — headers.
  • שמות headers באותיות קטנות; מפרידים לפי ה־: הראשון ומורידים רווחים. שורה ריקה (> לבד) — מדלגים.
  • כל שורה אחרת (*, הגוף, שורות התקדמות) — מתעלמים. שורות יכולות להסתיים ב־\r\n.
  • אין שורות של בקשה או של תשובה ← הצד הזה הוא null.

P14-E66 · מבקשות לקובץ .http 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

כתוב וייצא toHttpFile(requests) שמקבלת מערך { name, method, url, headers, body } (‏headers ו־body אופציונליים) ומחזירה את הטקסט של קובץ .http כמו בשיעור:

  • לכל בקשה: ### name, שורת METHOD url, שורה לכל header (Name: value). אם יש גוף: שורה ריקה ואז הגוף — אובייקט ← JSON.stringify(body, null, 2), מחרוזת ← כמו שהיא.

P14-E67 · סיכום של לשונית Network 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

בשיעור ביקשנו לבדוק "כמה בקשות טוען דף אחד? כמה מהן מחזירות JSON?". כתוב וייצא networkSummary(entries) שעונה על זה. כל רשומה: { url, method, status, contentType, size, ms } (‏status ‏0 — הבקשה נכשלה בלי תשובה, כמו "(failed)" ב־DevTools).

מחזירה:

  • count — כמה בקשות. ‏bytes — סכום ה־size.
  • failed — כמה עם status ‏0 או 400 ומעלה.
  • json — כמה עם contentType שמכיל json (בלי תלות באותיות; ‏contentType יכול להיות חסר).
  • slowest — ה־url של האיטית ביותר (בשוויון — הראשונה), או null לרשימה ריקה.
  • byHost — אובייקט: כמה בקשות לכל host (‏new URL(url).host).

P14-E68 · בודק לקובצי .http 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

כתוב וייצא lintHttpFile(text) שמחזירה מערך אזהרות (מחרוזות) על הבעיות מ־P14-E61. מספרי שורות מתחילים ב־1.

  • משתנים מוגדרים בשורות @name = value. שימוש ב־{{name}} שלא הוגדר (בכל מקום בקובץ, גם לפני ההגדרה זה בסדר) ← שורה N: המשתנה name לא הוגדר (פעם אחת לכל שימוש).
  • בקשה מתחילה בשורה הראשונה שאינה ריקה ואינה הערה (# או //, אבל לא ###) אחרי ###. אחריה — headers עד שורה ריקה, ואחריה הגוף.
  • שורת header שאינה בצורה Name: value (שם בלי רווחים, נקודתיים, ערך) ← שורה N: header לא תקין.
  • בקשה עם גוף (שורה לא ריקה אחרי השורה הריקה) בלי header בשם Content-Type (בלי תלות באותיות) ← שורה N: יש גוף בלי Content-Type, כש־N היא שורת הבקשה.
  • האזהרות לפי סדר השורות. קובץ תקין ← [].

P14-E69 · O'Brien בפקודת curl

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 2, שיעור 3

סקריפט בונה פקודת curl עם template literal. מה יודפס? והאם אפשר להדביק את הפקודה ב־Terminal?

const name = "O'Brien";
const body = JSON.stringify({ name });
console.log(body);

const quote = (s) => `'${s.replaceAll("'", `'\\''`)}'`;

ועשה git commit ו־git push. ענה:

P14-E71 · קוד יציאה של curl

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 13, שיעור 3

אלה שלוש הרצות אמיתיות מול שרת ההדגמה (מוצר 9 לא קיים; על פורט 4001 אף אחד לא מקשיב). $? הוא קוד היציאה של הפקודה הקודמת. לפני שאתה מסתכל על הפלט — נחש את שלושת הקודים.

% curl -s http://localhost:4000/products/9; echo " exit=$?"
{"error":"המוצר לא נמצא"} exit=0
% curl -sf http://localhost:4000/products/9; echo "exit=$?"
exit=22
% curl -s http://localhost:4001/; echo "exit=$?"
exit=7

ענה: (1) למה 404 נותן קוד יציאה 0? (2) מה עושה -f ("fail")? (3) בסקריפט פריסה כתוב curl -s http://localhost:4000/health && echo "השרת תקין". מתי הוא ידפיס "תקין" למרות שהשרת לא תקין, ואיך לתקן?

🔗 איך זה מתחבר: קודי יציאה ו־&& מפרק 13 (שיעור 2). השיעור: curl כחלק מסקריפט — ואותו רעיון כמו ב־P14-E05: "הגיעה תשובה" זה לא "הצליח".

P14-E72 · להסתיר סודות בפקודת curl 🤖

💻 כתיבת קודרמה 3⏱ 20 דק׳ידע נדרש: פרק 2, שיעור 1, שיעור 2, שיעור 3

לפני שמדביקים פקודת curl (מ־"Copy as cURL" של DevTools) בצ'אט או בבאג, מסתירים סודות. כתוב וייצא redactCurl(args) שמקבלת מערך ארגומנטים (כמו ב־P14-E63) ומחזירה מערך חדש:

  • header ‏Authorization (אחרי -H/--header, בלי תלות באותיות): אם הערך הוא Scheme token ← Authorization: Scheme ***; אם אין רווח ← Authorization: ***.
  • header ‏Cookie ← כל ערך של עוגייה הופך ל־***, והשמות נשארים: Cookie: sid=***; theme=***.
  • בכתובות (ארגומנט שמתחיל ב־http:// או https://): פרמטרים ב־query ששמם (בלי תלות באותיות) token, ‏key, ‏apikey, ‏password או secret ← *** (דרך searchParams.set). השאר נשאר.
  • שם ה־header נשמר כמו שנכתב. את המערך המקורי לא משנים.

P14-E73 · סיכום קובצי .http בתיקייה 🤖

💻 כתיבת קודרמה 3⏱ 20 דק׳ידע נדרש: פרק 10, פרק 13, שיעור 3

בפרויקט יש תיקיית requests/ עם קובצי .http. כתוב וייצא async function summarizeHttpDir(dir) (עם fs/promises ו־path):

  • קוראת את כל הקבצים שמסתיימים ב־.http ישירות בתיקייה (בלי תתי־תיקיות). שאר הקבצים — מתעלמים.
  • לכל קובץ מחזירה { file, requests, methods }: ‏file — שם הקובץ בלבד; ‏requests — מספר שורות הבקשה (שורה שמתחילה ב־GET , ‏POST , ‏PUT , ‏PATCH או DELETE ); ‏methods — אובייקט ספירה לפי method (רק methods שהופיעו).
  • התוצאה ממוינת לפי שם הקובץ. את הקבצים קוראים במקביל.
  • התיקייה לא קיימת ← throw new Error(התיקייה לא קיימת: ${dir}).

% npm run check P14-E73

P14-E74 · ממה שנכשל ב־Network — לפקודות curl 🤖

💻 כתיבת קודרמה 3⏱ 20 דק׳ידע נדרש: פרק 6, פרק 7, שיעור 3

DevTools יודע "Copy as cURL" לבקשה אחת. כתוב כלי שעושה את זה לכל הבקשות שנכשלו. כתוב וייצא failedAsCurl(entries). כל רשומה: { method, url, status, startedAt, headers } (‏headers — אובייקט, אופציונלי).

  • רק רשומות שנכשלו: status ‏0 או 400 ומעלה.
  • בלי כפילויות: אותו method ו־url — רק הרשומה המוקדמת ביותר (לפי startedAt).
  • ממוין לפי startedAt.
  • כל רשומה הופכת למחרוזת: curl, ‏-X METHOD רק אם אינו GET, הכתובת במירכאות בודדות, ו־-H 'Name: value' לכל header — חוץ מ־cookie (בלי תלות באותיות), שלא מעתיקים. רווח אחד בין החלקים.
failedAsCurl([{ method: "POST", url: "http://x/orders", status: 500, startedAt: 2, headers: { Accept: "application/json", Cookie: "sid=1" } }]);
// ["curl -X POST 'http://x/orders' -H 'Accept: application/json'"]

% npm run check P14-E74
