1. HTTP הוא טקסט

מתחת לכל הכלים, בקשה היא כמה שורות טקסט:

POST /products HTTP/1.1
Host: localhost:4000
Content-Type: application/json
Accept: application/json
Content-Length: 29

{"name":"מסך","price":899}

ותשובה:

HTTP/1.1 201 Created
Content-Type: application/json; charset=utf-8
Location: /products/3

{"id":3,"name":"מסך","price":899}
חלקבבקשהבתשובה
שורה ראשונהmethod, path, גרסהגרסה, status, טקסט
headersName: value, שורה לכל אחדכנ״ל
שורה ריקהמפרידה בין headers לגוף — חובה
גוףאופציונלי (ב־POST/PUT/PATCH)אופציונלי (אין ב־204)

(ב־HTTP/2 ו־3 העברת הנתונים בינארית ויעילה יותר, אבל המבנה הלוגי — method, headers, body, status — זהה. כלים כמו curl מציגים אותו כך.)

2. headers שתפגוש כל יום

Headerאיפהמה אומר
Content-Typeבקשה ותשובההפורמט של הגוף: application/json, text/html, multipart/form-data (קבצים)
Acceptבקשה"אילו פורמטים אני מבין"
Authorizationבקשההוכחת זהות: Bearer <token> (פרק 21)
Locationתשובה (201, 3xx)"המשאב החדש נמצא כאן"
Cache-Controlתשובההאם ולכמה זמן מותר לשמור (פרק 26)
Set-Cookie / Cookieתשובה / בקשההשרת שם עוגייה; הדפדפן שולח אותה בכל בקשה
X-Request-Idשניהםמזהה לעקוב אחרי בקשה ביומנים (פרק 24)

שמות headers לא רגישים לאותיות: content-type = Content-Type. ב־Node הם מגיעים באותיות קטנות (req.headers["content-type"]).

3. JSON — שפת ה־API

כמעט כל API מודרני מקבל ומחזיר JSON (פרק 7). מוסכמות שכדאי לאמץ מעכשיו:

  • שמות שדות ב־camelCase: {"createdAt": "2026-11-01T10:00:00Z"}.
  • תאריכים כמחרוזת ISO 8601 (עם אזור זמן — פרק 24).
  • כסף: מספר באגורות, או מחרוזת עשרונית — לא float "סתם".
  • שגיאות במבנה קבוע: {"error": {"code": "NOT_FOUND", "message": "..."}} — הלקוח יודע תמיד איפה לחפש.

4. Stateless

השרת לא "זוכר" אותך בין בקשה לבקשה. כל בקשה צריכה להכיל את כל מה שצריך כדי לטפל בה — כולל מי שלח אותה. לכן כל בקשה של משתמש מחובר נושאת הוכחה:

  • Token בכותרת Authorization: Bearer eyJ... — נפוץ ב־API ובאפליקציות.
  • Cookie — הדפדפן שולח אוטומטית; נפוץ באתרים.

למה stateless זה טוב? כי אז אפשר להריץ 10 עותקים של אותו שרת, וכל בקשה יכולה להגיע לכל אחד מהם (scaling — פרק 28). נעמיק בטוקנים ובעוגיות בפרק 21.
