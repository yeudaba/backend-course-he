PATCH /orders/17?notify=false HTTP/1.1
Host: api.shop.co.il
Authorization: Bearer eyJhbGciOi...
Content-Type: application/json

{"status":"shipped"}
  1. מה הבקשה רוצה לעשות, ולאיזה משאב?
  2. מה תפקיד notify=false, ולמה הוא ב־query ולא בגוף?
  3. איך השרת יודע מי שלח את הבקשה?
  4. מה יקרה אם נמחק את השורה Content-Type?
  5. התשובה היא HTTP/1.1 403 Forbidden. מה זה אומר — ומה היה אומר 401?
  6. החיבור נפל לפני שהגיעה תשובה. בטוח לשלוח שוב?

P14-E08 · פירוק headers 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 2

בקובץ 14-http/starter/P14-E08.mjs השלם parseHeaders(lines) — מקבלת מערך שורות "Name: value" ומחזירה אובייקט:

  • שמות באותיות קטנות (כמו ב־Node).
  • מפרידים לפי הנקודתיים הראשונות בלבד ("Authorization: Basic a:b"), ומורידים רווחים מסביב.
  • אותו header פעמיים ← הערכים מחוברים ב־", ".
  • שורה בלי : ← Error(header לא תקין: ${line}).

P14-E13 · לפרק בקשה גולמית 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 2

בקובץ 14-http/starter/P14-E13.mjs השלם parseRequest(raw), שמקבלת בקשת HTTP כטקסט (שורות מופרדות ב־\r\n או \n) ומחזירה:

  • method, path (בלי query), query (אובייקט), headers (שמות באותיות קטנות).
  • body: אחרי השורה הריקה הראשונה. ריק ← undefined. אם content-type מכיל json ← אובייקט (JSON.parse), אחרת — המחרוזת.
  • שורה ראשונה שאין בה בדיוק 3 חלקים ← Error("שורת בקשה לא תקינה").

P14-E14 · לבנות תשובה גולמית 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 2

בקובץ 14-http/starter/P14-E14.mjs השלם buildResponse(status, body, headers = {}) שמחזירה את התשובה כטקסט עם \r\n:

  • שורה ראשונה: HTTP/1.1 201 Created — לפי המפה STATUS_TEXT שבקובץ. status שלא במפה ← Error(status לא מוכר: ${status}).
  • אחריה ה־headers שקיבלת, לפי הסדר.
  • אם יש גוף: מחרוזת ← כמו שהיא; אחרת ← JSON.stringify ו־Content-Type: application/json; charset=utf-8 (אם לא נשלח content-type). ובכל מקרה — Content-Length בבתים.
  • שורה ריקה, ואז הגוף.
  • 204 עם גוף ← Error("204 לא יכול להכיל גוף").

P14-E20 · שרת עם שלושה באגים 🤖

💻 כתיבת קוד 🤖רמה 4⏱ 15 דק׳ידע נדרש: שיעור 2

בקובץ 14-http/starter/P14-E20.mjs השרת "עובד" בדפדפן, אבל: (1) לקוח שבודק את Content-Type של /health לא מזהה JSON; (2) בקשה ל־/old-users נתקעת ולא חוזרת; (3) כתובת שלא קיימת מחזירה 200, וכלי הניטור מדווח "הכול תקין". תקן את שלושתם. (ל־/old-users צריך לחזור 301 עם Location: /users.)

P14-E26 · פירוק header של Cookie 🤖

💻 כתיבת קוד 🤖🔥 חימוםרמה 2⏱ 10 דק׳ידע נדרש: שיעור 2

הדפדפן שולח את כל העוגיות (cookies) של האתר ב־header אחד:

Cookie: theme=dark; lang=he; cart=%D7%A1%D7%9C

כתוב וייצא parseCookies(header) שהופכת את הערך של ה־header (מה שאחרי Cookie: ) לאובייקט:

  • הזוגות מופרדים ב־;. רווחים מסביב לשם ולערך — מסירים.
  • הערכים מקודדים כמו ב־URL. מפענחים עם decodeURIComponent (‏%D7%A1%D7%9C ← "סל").
  • בערך עצמו יכול להופיע = (‏token=a=b=c ← { token: "a=b=c" }). רק ה־= הראשון מפריד.
  • חלק בלי =, או עם שם ריק — מדלגים עליו.
  • undefined או מחרוזת ריקה (אין header) ← {}.

📄 כותבים בקובץ 14-http/starter/P14-E26.mjs (יש בו רק הערה), מריצים ובודקים:

% node 14-http/starter/P14-E26.mjs
% npm run check P14-E26
