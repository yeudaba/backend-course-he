P14-E03 · לקרוא בקשה גולמית 🧠 הבנה רמה 1

💡 רמז 1

שורה ריקה מפרידה בין headers לגוף.

💡 רמז 2

idempotent: האם שליחה כפולה משנה את התוצאה?

✅ פתרון
  1. עדכון חלקי (PATCH) של הזמנה 17: הסטטוס יהיה "shipped".
  2. אפשרות שמשנה איך לבצע (בלי לשלוח הודעה ללקוח), לא מה לשנות. מוסכמה, לא חוק — אפשר היה גם בגוף.
  3. מהטוקן ב־Authorization — השרת stateless, אז כל בקשה מביאה את ההוכחה איתה.
  4. השרת לא יודע שהגוף הוא JSON; שרת זהיר יחזיר 415 (כמו שרת ההדגמה), שרת אחר אולי יתעלם מהגוף.
  5. הטוקן תקין והשרת יודע מי אתה — אבל אין לך הרשאה לעדכן את ההזמנה הזו. 401 היה אומר שהטוקן חסר, פג או לא תקין.
  6. כן — לקבוע סטטוס "shipped" פעמיים נותן אותה תוצאה. ({"addItem": 5} כבר לא היה בטוח.)
⚠️ טעויות נפוצות
  • לחשוב ש־PATCH תמיד idempotent — תלוי מה הוא עושה. "קבע ל־X" כן; "הוסף 1" לא.

P14-E08 · פירוק headers 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

line.indexOf(":"), ואז slice לשני הצדדים.

💡 רמז 2

result[name] = name in result ? ${result[name]}, ${value} : value

✅ פתרון
// P14-E08
export function parseHeaders(lines) {
  const result = {};
  for (const line of lines) {
    const i = line.indexOf(":");
    if (i <= 0) throw new Error(`header לא תקין: ${line}`);
    const name = line.slice(0, i).trim().toLowerCase();
    const value = line.slice(i + 1).trim();
    result[name] = name in result ? `${result[name]}, ${value}` : value;
  }
  return result;
}

console.log(JSON.stringify(parseHeaders(["Content-Type: application/json", "Accept: text/html", "accept: application/json", "Authorization: Basic a:b"])));
{"content-type":"application/json","accept":"text/html, application/json","authorization":"Basic a:b"}
⚠️ טעויות נפוצות
  • line.split(":") — חותך את "Basic a:b" ומאבד חלק מהערך. אותו דבר בכל header עם כתובת (http://).

P14-E13 · לפרק בקשה גולמית 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

קודם raw.replaceAll("\r\n", "\n"), ואז indexOf("\n\n") מפריד head מגוף.

💡 רמז 2

ה־path וה־query: new URL(target, "http://x").

✅ פתרון
// P14-E13
export function parseRequest(raw) {
  const text = raw.replaceAll("\r\n", "\n");
  const split = text.indexOf("\n\n");
  const head = split === -1 ? text : text.slice(0, split);
  const rawBody = split === -1 ? "" : text.slice(split + 2);
  const [requestLine, ...headerLines] = head.split("\n");

  const parts = requestLine.split(" ");
  if (parts.length !== 3) throw new Error("שורת בקשה לא תקינה");
  const [method, target] = parts;
  const url = new URL(target, "http://x");

  const headers = {};
  for (const line of headerLines) {
    const i = line.indexOf(":");
    headers[line.slice(0, i).trim().toLowerCase()] = line.slice(i + 1).trim();
  }

  let body;
  if (rawBody !== "") {
    body = headers["content-type"]?.includes("json") ? JSON.parse(rawBody) : rawBody;
  }
  return { method, path: url.pathname, query: Object.fromEntries(url.searchParams), headers, body };
}

const raw = "PATCH /orders/17?notify=false HTTP/1.1\r\nHost: api.shop.co.il\r\nContent-Type: application/json\r\n\r\n{\"status\":\"shipped\"}";
console.log(JSON.stringify(parseRequest(raw)));
{"method":"PATCH","path":"/orders/17","query":{"notify":"false"},"headers":{"host":"api.shop.co.il","content-type":"application/json"},"body":{"status":"shipped"}}

זה (בגרסה פשוטה מאוד) מה ש־node:http עושה לפני שהוא קורא ל־handler שלך — ומה ש־Express מוסיף מעליו (req.query, req.body).

⚠️ טעויות נפוצות
  • לפצל את כל הטקסט לפי \n ולחפש שורה ריקה — גוף JSON מרובה שורות יישבר.

P14-E14 · לבנות תשובה גולמית 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

Buffer.byteLength("שלום") הוא 8, לא 4 — כל אות עברית היא 2 בתים ב־UTF-8.

💡 רמז 2

בנה מערך שורות ו־join("\r\n").

✅ פתרון
// P14-E14
export const STATUS_TEXT = {
  200: "OK", 201: "Created", 204: "No Content", 400: "Bad Request", 401: "Unauthorized",
  403: "Forbidden", 404: "Not Found", 409: "Conflict", 500: "Internal Server Error",
};

export function buildResponse(status, body, headers = {}) {
  const text = STATUS_TEXT[status];
  if (!text) throw new Error(`status לא מוכר: ${status}`);
  if (status === 204 && body !== undefined) throw new Error("204 לא יכול להכיל גוף");

  const all = { ...headers };
  let payload = "";
  if (body !== undefined) {
    payload = typeof body === "string" ? body : JSON.stringify(body);
    const hasType = Object.keys(headers).some((h) => h.toLowerCase() === "content-type");
    if (typeof body !== "string" && !hasType) all["Content-Type"] = "application/json; charset=utf-8";
    all["Content-Length"] = Buffer.byteLength(payload);
  }
  const lines = [`HTTP/1.1 ${status} ${text}`, ...Object.entries(all).map(([k, v]) => `${k}: ${v}`)];
  return lines.join("\r\n") + "\r\n\r\n" + payload;
}

console.log(buildResponse(201, { id: 3, name: "מסך" }, { Location: "/products/3" }));
HTTP/1.1 201 Created
Location: /products/3
Content-Type: application/json; charset=utf-8
Content-Length: 24

{"id":3,"name":"מסך"}
⚠️ טעויות נפוצות
  • payload.length — סופר תווים, לא בתים. עם עברית הלקוח יחתוך את הגוף באמצע.

P14-E20 · שרת עם שלושה באגים 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

res.writeHead לא שולח את התשובה — רק res.end.

💡 רמז 2

בדוק כל ענף: מה ה־status, האם יש Content-Type, והאם יש end.

✅ פתרון
// P14-E20: מתוקן
import http from "node:http";

const JSON_TYPE = { "Content-Type": "application/json; charset=utf-8" };

export function createServer() {
  return http.createServer((req, res) => {
    if (req.url === "/health") {
      res.writeHead(200, JSON_TYPE);
      res.end(JSON.stringify({ ok: true }));
    } else if (req.url === "/users") {
      res.writeHead(200, JSON_TYPE);
      res.end(JSON.stringify([{ id: 1, name: "דנה" }]));
    } else if (req.url === "/old-users") {
      res.writeHead(301, { Location: "/users" });
      res.end();
    } else {
      res.writeHead(404, JSON_TYPE);
      res.end(JSON.stringify({ error: "לא נמצא" }));
    }
  });
}

באג 2 הוא הכי מסוכן: בקשות תקועות לא נראות בשום יומן שגיאות — רק החיבורים מצטברים עד שהשרת נחנק.

⚠️ טעויות נפוצות
  • לתקן את 3 על ידי בדיקה בצד הלקוח (if (data.error)) — ה־status הוא החוזה, ושאר הכלים (ניטור, cache, retry) מסתכלים רק עליו.

P14-E26 · פירוק header של Cookie 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

header.split(";"), ובכל חלק: const i = part.indexOf("="). אם i === -1 — continue. השם הוא part.slice(0, i).trim(), והערך part.slice(i + 1).trim().

💡 רמז 2

למה לא part.split("=")? כי "a=b=c".split("=") נותן שלושה חלקים, והערך נחתך. ואם בכל זאת רוצים split, צריך לחבר בחזרה: const [name, ...rest] = part.split("="); rest.join("=").

✅ פתרון
// P14-E26: פירוק header של Cookie
export function parseCookies(header) {
  const cookies = {};
  if (!header) {
    return cookies;
  }
  for (const part of header.split(";")) {
    const i = part.indexOf("=");
    if (i === -1) {
      continue;
    }
    const name = part.slice(0, i).trim();
    const value = part.slice(i + 1).trim();
    if (name) {
      cookies[name] = decodeURIComponent(value);
    }
  }
  return cookies;
}

console.log(parseCookies("theme=dark; lang=he; cart=%D7%A1%D7%9C"));
console.log(parseCookies("token=a=b=c;  broken ; =x"));
console.log(parseCookies(undefined));
{ theme: 'dark', lang: 'he', cart: 'סל' }
{ token: 'a=b=c' }
{}

זה אותו פירוק כמו של query string (P14-E06) ושל קובץ .env (P13-E10): מפרידים לזוגות, ובכל זוג חותכים ב־= הראשון. ‏indexOf ו־slice עושים את זה בלי להרוס ערכים שיש בהם =, כמו טוקנים ב־base64.

בפרק 21 תשמור טוקן בעוגייה עם HttpOnly. בפרויקט אמיתי ספרייה כמו cookie-parser מפרקת את ה־header בשבילך, ועכשיו אתה יודע מה היא עושה.

⚠️ טעויות נפוצות
  • const [name, value] = part.split("=") — ‏a=b=c נהיה "b".
  • לשכוח trim — אחרי split(";") לכל שם חוץ מהראשון יש רווח בהתחלה (" lang").
  • לא לבדוק undefined — ‏header.split קורס כשהדפדפן לא שלח עוגיות בכלל.
