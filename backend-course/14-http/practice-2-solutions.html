P14-E03 · לקרוא בקשה גולמית 🧠 הבנה רמה 1

💡 רמז 1

שורה ריקה מפרידה בין headers לגוף.

💡 רמז 2

idempotent: האם שליחה כפולה משנה את התוצאה?

✅ פתרון
  1. עדכון חלקי (PATCH) של הזמנה 17: הסטטוס יהיה "shipped".
  2. אפשרות שמשנה איך לבצע (בלי לשלוח הודעה ללקוח), לא מה לשנות. מוסכמה, לא חוק — אפשר היה גם בגוף.
  3. מהטוקן ב־Authorization — השרת stateless, אז כל בקשה מביאה את ההוכחה איתה.
  4. השרת לא יודע שהגוף הוא JSON; שרת זהיר יחזיר 415 (כמו שרת ההדגמה), שרת אחר אולי יתעלם מהגוף.
  5. הטוקן תקין והשרת יודע מי אתה — אבל אין לך הרשאה לעדכן את ההזמנה הזו. 401 היה אומר שהטוקן חסר, פג או לא תקין.
  6. כן — לקבוע סטטוס "shipped" פעמיים נותן אותה תוצאה. ({"addItem": 5} כבר לא היה בטוח.)
⚠️ טעויות נפוצות
  • לחשוב ש־PATCH תמיד idempotent — תלוי מה הוא עושה. "קבע ל־X" כן; "הוסף 1" לא.

P14-E44 · איזה header? 🧠 הבנה רמה 1

💡 רמז 1

כל התשובות בטבלה בסעיף 2 של השיעור. במצב 5 יש שני headers — אחד לכל כיוון.

💡 רמז 2

Content-Type מתאר את מה שנשלח; Accept מבקש את מה שיחזור.

✅ פתרון
  1. Location: /orders/42 — בתשובה (עם 201).
  2. Content-Type: application/json — בבקשה.
  3. Accept: application/json — בבקשה.
  4. Authorization: Bearer eyJ... — בבקשה.
  5. Set-Cookie: lang=he בתשובה, ואחר כך Cookie: lang=he בכל בקשה (הדפדפן מוסיף לבד).
  6. X-Request-Id: 7f3a... — בתשובה (ולפעמים הלקוח שולח אותו כבר בבקשה).
  7. Cache-Control: max-age=3600 — בתשובה (פרק 26).
⚠️ טעויות נפוצות
  • לשלוח Content-Type ב־GET בלי גוף "כדי לקבל JSON" — זה התפקיד של Accept.

P14-E45 · מה שבור בהודעה? 🧠 הבנה רמה 2

💡 רמז 1

חזור לטבלה "חלק / בבקשה / בתשובה" — מה חובה בין headers לגוף? ובאיזו תשובה אין גוף?

💡 רמז 2

בהודעה (ד) הבעיה לא במבנה — היא במה שהלקוח (או כלי ניטור) יסיק מהשורה הראשונה.

✅ פתרון
  1. אין שורה ריקה לפני הגוף. השרת יקרא את {"name":...} כעוד header (לא תקין) — ובדרך כלל יחזיר 400.
  2. Content-Type שגוי. הגוף הוא JSON, אבל ה־header אומר טקסט. שרת קפדן יחזיר 415, ו־Express (פרק 15) פשוט לא יפרש את הגוף — req.body יהיה undefined.
  3. 204 = "אין תוכן" — לתשובה הזו אסור גוף. הלקוח יתעלם ממנו (או יתבלבל בחיבור). אם רוצים להחזיר משהו ← 200.
  4. status שקרי. הגוף אומר "לא נמצא", ה־status אומר "הצליח". res.ok יהיה true, ניטור יראה "הכול תקין", ו־cache עלול לשמור את השגיאה. ← 404.
⚠️ טעויות נפוצות
  • לחשוב שהגוף "מספיק" כדי לדווח על שגיאה. כלים — fetch, ניטור, cache, retry — מסתכלים קודם על ה־status.

P14-E46 · השרת "זוכר" — ומה רע בזה? 🧠 הבנה רמה 2

💡 רמז 1

יש משתנה אחד לכל השרת — לא אחד לכל משתמש.

💡 רמז 2

stateless: "כל בקשה צריכה להכיל את כל מה שצריך כדי לטפל בה — כולל מי שלח אותה".

✅ פתרון
let currentUser = null;

function handle(req) {
  if (req.path === "/login") {
    currentUser = req.body.name;
    return `שלום ${currentUser}`;
  }
  if (req.path === "/me") return `אתה ${currentUser}`;
}

console.log(handle({ path: "/login", body: { name: "דנה" } }));
console.log(handle({ path: "/login", body: { name: "יוסי" } }));
console.log(handle({ path: "/me" })); // דנה שולחת
שלום דנה
שלום יוסי
אתה יוסי

דנה רואה את הפרטים של יוסי — דליפת מידע. (1) הבקשה צריכה לשאת הוכחה: Authorization: Bearer <token> או cookie, והשרת מזהה לפיה את המשתמש בכל בקשה מחדש. (2) Map בזיכרון של עותק א׳ לא קיים בעותק ב׳: דנה מתחברת מול א׳, הבקשה הבאה מגיעה ל־ב׳ — "לא מחוברת". לכן או שהטוקן עצמו נושא את הזהות (JWT, פרק 21), או שהמידע נשמר במקום משותף (מסד, Redis — פרק 26).

⚠️ טעויות נפוצות
  • "זה עובד אצלי" — בבדיקה עם משתמש אחד ושרת אחד הבאג לא נראה בכלל.

P14-E47 · ביקורת על תשובת JSON 🧠 הבנה רמה 1

💡 רמז 1

שמות שדות, תאריך, כסף, מבנה של רשימה, ומבנה של שגיאה. ואל תשכח את ה־status.

💡 רמז 2

"1/11/26" — זה 1 בנובמבר או 11 בינואר? ובאיזה אזור זמן?

✅ פתרון
  1. שמות לא אחידים (Order_ID, Total) ← camelCase: id, total.
  2. תאריך דו־משמעי ובלי אזור זמן ← ISO 8601: "createdAt": "2026-11-01T10:00:00Z".
  3. כסף כ־float עם שארית ← אגורות ("totalAgorot": 5970) או מחרוזת ("59.70").
  4. רשימה כמחרוזת ← מערך של אובייקטים: "items": [{"name":"מקלדת"}, ...] — הלקוח לא צריך לפרק טקסט.
  5. "status":"ok" מיותר ומבלבל — הסטטוס כבר ב־HTTP. (אם הכוונה היא מצב ההזמנה — שם ברור: "orderStatus": "paid".)
  6. שגיאה עם 200 ← 404.
  7. מבנה שגיאה לא קבוע ← {"error":{"code":"NOT_FOUND","message":"ההזמנה לא נמצאה"}} — הלקוח תמיד יודע איפה לחפש.
⚠️ טעויות נפוצות
  • לתקן רק את ה"נראות" (שמות) ולהשאיר את ה־200 — זו הבעיה שגורמת לבאגים אצל הלקוח.

P14-E48 · למה Content-Length הוא 29? 🧠 הבנה רמה 2

💡 רמז 1

Buffer.byteLength סופר בתים בקידוד UTF-8, ו־length סופר תווים.

💡 רמז 2

אות אנגלית — בית אחד. אות עברית — שניים.

✅ פתרון
const body = JSON.stringify({ name: "מסך", price: 899 });
console.log(body);
console.log(body.length, Buffer.byteLength(body));
console.log("abc".length, Buffer.byteLength("abc"));
console.log("שלום".length, Buffer.byteLength("שלום"));
{"name":"מסך","price":899}
26 29
3 3

Content-Length הוא מספר הבתים שעוברים ברשת: 26 תווים, מתוכם 3 אותיות עבריות ← 3 בתים נוספים ← 29. אם השרת יקבל 26, הוא יקרא רק 26 בתים — הגוף ייחתך באמצע ({"name":"מסך","price":8), ‏JSON.parse ייכשל, והבתים שנשארו ייקראו כ"התחלה" של הבקשה הבאה. לכן אף פעם לא מחשבים Content-Length עם .length (P14-E14).

⚠️ טעויות נפוצות
  • לבדוק רק עם טקסט באנגלית — שם תווים ובתים שווים, והבאג מופיע רק אצל משתמשים בעברית.

P14-E08 · פירוק headers 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

line.indexOf(":"), ואז slice לשני הצדדים.

💡 רמז 2

result[name] = name in result ? ${result[name]}, ${value} : value

✅ פתרון
// P14-E08
export function parseHeaders(lines) {
  const result = {};
  for (const line of lines) {
    const i = line.indexOf(":");
    if (i <= 0) throw new Error(`header לא תקין: ${line}`);
    const name = line.slice(0, i).trim().toLowerCase();
    const value = line.slice(i + 1).trim();
    result[name] = name in result ? `${result[name]}, ${value}` : value;
  }
  return result;
}

console.log(JSON.stringify(parseHeaders(["Content-Type: application/json", "Accept: text/html", "accept: application/json", "Authorization: Basic a:b"])));
{"content-type":"application/json","accept":"text/html, application/json","authorization":"Basic a:b"}
⚠️ טעויות נפוצות
  • line.split(":") — חותך את "Basic a:b" ומאבד חלק מהערך. אותו דבר בכל header עם כתובת (http://).

P14-E13 · לפרק בקשה גולמית 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

קודם raw.replaceAll("\r\n", "\n"), ואז indexOf("\n\n") מפריד head מגוף.

💡 רמז 2

ה־path וה־query: new URL(target, "http://x").

✅ פתרון
// P14-E13
export function parseRequest(raw) {
  const text = raw.replaceAll("\r\n", "\n");
  const split = text.indexOf("\n\n");
  const head = split === -1 ? text : text.slice(0, split);
  const rawBody = split === -1 ? "" : text.slice(split + 2);
  const [requestLine, ...headerLines] = head.split("\n");

  const parts = requestLine.split(" ");
  if (parts.length !== 3) throw new Error("שורת בקשה לא תקינה");
  const [method, target] = parts;
  const url = new URL(target, "http://x");

  const headers = {};
  for (const line of headerLines) {
    const i = line.indexOf(":");
    headers[line.slice(0, i).trim().toLowerCase()] = line.slice(i + 1).trim();
  }

  let body;
  if (rawBody !== "") {
    body = headers["content-type"]?.includes("json") ? JSON.parse(rawBody) : rawBody;
  }
  return { method, path: url.pathname, query: Object.fromEntries(url.searchParams), headers, body };
}

const raw = "PATCH /orders/17?notify=false HTTP/1.1\r\nHost: api.shop.co.il\r\nContent-Type: application/json\r\n\r\n{\"status\":\"shipped\"}";
console.log(JSON.stringify(parseRequest(raw)));
{"method":"PATCH","path":"/orders/17","query":{"notify":"false"},"headers":{"host":"api.shop.co.il","content-type":"application/json"},"body":{"status":"shipped"}}

זה (בגרסה פשוטה מאוד) מה ש־node:http עושה לפני שהוא קורא ל־handler שלך — ומה ש־Express מוסיף מעליו (req.query, req.body).

⚠️ טעויות נפוצות
  • לפצל את כל הטקסט לפי \n ולחפש שורה ריקה — גוף JSON מרובה שורות יישבר.

P14-E14 · לבנות תשובה גולמית 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

Buffer.byteLength("שלום") הוא 8, לא 4 — כל אות עברית היא 2 בתים ב־UTF-8.

💡 רמז 2

בנה מערך שורות ו־join("\r\n").

✅ פתרון
// P14-E14
export const STATUS_TEXT = {
  200: "OK", 201: "Created", 204: "No Content", 400: "Bad Request", 401: "Unauthorized",
  403: "Forbidden", 404: "Not Found", 409: "Conflict", 500: "Internal Server Error",
};

export function buildResponse(status, body, headers = {}) {
  const text = STATUS_TEXT[status];
  if (!text) throw new Error(`status לא מוכר: ${status}`);
  if (status === 204 && body !== undefined) throw new Error("204 לא יכול להכיל גוף");

  const all = { ...headers };
  let payload = "";
  if (body !== undefined) {
    payload = typeof body === "string" ? body : JSON.stringify(body);
    const hasType = Object.keys(headers).some((h) => h.toLowerCase() === "content-type");
    if (typeof body !== "string" && !hasType) all["Content-Type"] = "application/json; charset=utf-8";
    all["Content-Length"] = Buffer.byteLength(payload);
  }
  const lines = [`HTTP/1.1 ${status} ${text}`, ...Object.entries(all).map(([k, v]) => `${k}: ${v}`)];
  return lines.join("\r\n") + "\r\n\r\n" + payload;
}

HTTP/1.1 201 Created
Location: /products/3
Content-Type: application/json; charset=utf-8
Content-Length: 24

{"id":3,"name":"מסך"}
⚠️ טעויות נפוצות
  • payload.length — סופר תווים, לא בתים. עם עברית הלקוח יחתוך את הגוף באמצע.

P14-E20 · שרת עם שלושה באגים 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

res.writeHead לא שולח את התשובה — רק res.end.

💡 רמז 2

בדוק כל ענף: מה ה־status, האם יש Content-Type, והאם יש end.

✅ פתרון
// P14-E20: מתוקן
import http from "node:http";

const JSON_TYPE = { "Content-Type": "application/json; charset=utf-8" };

export function createServer() {
  return http.createServer((req, res) => {
    if (req.url === "/health") {
      res.writeHead(200, JSON_TYPE);
      res.end(JSON.stringify({ ok: true }));
    } else if (req.url === "/users") {
      res.writeHead(200, JSON_TYPE);
      res.end(JSON.stringify([{ id: 1, name: "דנה" }]));
    } else if (req.url === "/old-users") {
      res.writeHead(301, { Location: "/users" });
      res.end();
    } else {
      res.writeHead(404, JSON_TYPE);
      res.end(JSON.stringify({ error: "לא נמצא" }));
    }
  });
}

באג 2 הוא הכי מסוכן: בקשות תקועות לא נראות בשום יומן שגיאות — רק החיבורים מצטברים עד שהשרת נחנק.

⚠️ טעויות נפוצות
  • לתקן את 3 על ידי בדיקה בצד הלקוח (if (data.error)) — ה־status הוא החוזה, ושאר הכלים (ניטור, cache, retry) מסתכלים רק עליו.

P14-E26 · פירוק header של Cookie 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

header.split(";"), ובכל חלק: const i = part.indexOf("="). אם i === -1 — continue. השם הוא part.slice(0, i).trim(), והערך part.slice(i + 1).trim().

💡 רמז 2

למה לא part.split("=")? כי "a=b=c".split("=") נותן שלושה חלקים, והערך נחתך. ואם בכל זאת רוצים split, צריך לחבר בחזרה: const [name, ...rest] = part.split("="); rest.join("=").

✅ פתרון
// P14-E26: פירוק header של Cookie
export function parseCookies(header) {
  const cookies = {};
  if (!header) {
    return cookies;
  }
  for (const part of header.split(";")) {
    const i = part.indexOf("=");
    if (i === -1) {
      continue;
    }
    const name = part.slice(0, i).trim();
    const value = part.slice(i + 1).trim();
    if (name) {
      cookies[name] = decodeURIComponent(value);
    }
  }
  return cookies;
}

console.log(parseCookies("theme=dark; lang=he; cart=%D7%A1%D7%9C"));
console.log(parseCookies("token=a=b=c;  broken ; =x"));
console.log(parseCookies(undefined));
{ theme: 'dark', lang: 'he', cart: 'סל' }
{ token: 'a=b=c' }
{}

זה אותו פירוק כמו של query string (P14-E06) ושל קובץ .env (P13-E10): מפרידים לזוגות, ובכל זוג חותכים ב־= הראשון. ‏indexOf ו־slice עושים את זה בלי להרוס ערכים שיש בהם =, כמו טוקנים ב־base64.

בפרק 21 תשמור טוקן בעוגייה עם HttpOnly. בפרויקט אמיתי ספרייה כמו cookie-parser מפרקת את ה־header בשבילך, ועכשיו אתה יודע מה היא עושה.

⚠️ טעויות נפוצות
  • const [name, value] = part.split("=") — ‏a=b=c נהיה "b".
  • לשכוח trim — אחרי split(";") לכל שם חוץ מהראשון יש רווח בהתחלה (" lang").
  • לא לבדוק undefined — ‏header.split קורס כשהדפדפן לא שלח עוגיות בכלל.

P14-E49 · פירוק שורת status 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

const [first, code, ...rest] = line.split(" "); — ‏rest.join(" ") מחזיר את הטקסט, עם הרווחים.

💡 רמז 2

/^\d{3}$/.test(code) — בדיוק 3 ספרות. אחר כך Number(code) ובדיקת טווח.

✅ פתרון
// P14-E49: פירוק שורת status
export function parseStatusLine(line) {
  const [first, code = "", ...rest] = line.trim().split(" ");
  const status = Number(code);
  if (!first.startsWith("HTTP/") || first.length === 5 || !/^\d{3}$/.test(code) || status < 100 || status > 599) {
    throw new Error(`שורת status לא תקינה: ${line}`);
  }
  return { version: first.slice(5), status, text: rest.join(" ") };
}

console.log(parseStatusLine("HTTP/1.1 404 Not Found"));
console.log(parseStatusLine("HTTP/2 200"));
console.log(parseStatusLine("HTTP/1.1 503 Service Unavailable"));
for (const bad of ["404 Not Found", "HTTP/1.1 OK", "HTTP/1.1 99 Old", "HTTP/1.1 2000 Big"]) {
  try {
    parseStatusLine(bad);
  } catch (err) {
    console.log(err.message);
  }
}

// P14-E50: לקרוא Content-Type
export function parseContentType(value) {
  if (typeof value !== "string" || value.trim() === "") return null;
  const [type, ...params] = value.split(";");
  let charset = null;
  for (const param of params) {
    const i = param.indexOf("=");
    if (i === -1) continue;
    const name = param.slice(0, i).trim().toLowerCase();
    if (name === "charset") charset = param.slice(i + 1).trim().replace(/^"|"$/g, "").toLowerCase();
  }
  return { type: type.trim().toLowerCase(), charset };
}

export function isJson(value) {
  const parsed = parseContentType(value);
  if (!parsed) return false;
  return parsed.type === "application/json" || parsed.type.endsWith("+json");
}

P14-E51 · לבחור פורמט לפי Accept 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

✅ פתרון
// P14-E51: לבחור פורמט לפי Accept
function parseAccept(accept) {
  return accept.split(",").map((part) => {
    const [type, ...params] = part.split(";").map((s) => s.trim().toLowerCase());
    let q = 1;
    for (const p of params) if (p.startsWith("q=")) q = Number(p.slice(2));
    return { type, q };
  });
}

export function chooseFormat(accept, available) {
  if (!accept || accept.trim() === "") return available[0] ?? null;
  const list = parseAccept(accept);
  let best = null;
  let bestQ = 0;
  for (const format of available) {
    const f = format.toLowerCase();
    const rule =
      list.find((r) => r.type === f) ?? list.find((r) => r.type === f.split("/")[0] + "/*") ?? list.find((r) => r.type === "*/*");
    const q = rule?.q ?? 0;
    if (q > bestQ) {
      best = format;
      bestQ = q;
    }
  }
  return best;
}

export class NotFoundError extends Error {

  name = "ConflictError";
}

  constructor(message, details) {
    super(message);
    this.name = "ValidationError";
    this.details = details;
  }

const reply = (status, code, message, extra = {}) => ({ status, body: { error: { code, message, ...extra } } });

export function toApiError(err) {
  if (err instanceof ValidationError) return reply(400, "VALIDATION", err.message, { details: err.details });
  if (err instanceof NotFoundError) return reply(404, "NOT_FOUND", err.message);
  if (err instanceof ConflictError) return reply(409, "CONFLICT", err.message);
  if (err instanceof SyntaxError) return reply(400, "INVALID_JSON", "JSON לא תקין");
  return reply(500, "INTERNAL", "שגיאה פנימית");
}

const camel = (key) => key.replace(/_([a-z])/g, (all, ch) => ch.toUpperCase());

export function toApiJson(value) {
  if (value instanceof Date) return value.toISOString();
  if (Array.isArray(value)) return value.map(toApiJson);
  if (value !== null && typeof value === "object") {

      Object.entries(value)
        .filter(([, v]) => v !== undefined)
        .map(([k, v]) => [camel(k), toApiJson(v)]),
    );
  }
  return value;
}

// P14-E57: sessions בזיכרון
export class SessionStore {
  #sessions = new Map();

  login(user) {
    const token = crypto.randomUUID();
    this.#sessions.set(token, user);
    return token;
  }

  userFor(headers) {
    const [scheme, token, ...rest] = (headers.authorization ?? "").split(" ");
    if (scheme !== "Bearer" || !token || rest.length > 0) return null;
    return this.#sessions.get(token) ?? null;
  }

  logout(token) {
    return this.#sessions.delete(token);
  }

  get size() {
    return this.#sessions.size;
  }
}
