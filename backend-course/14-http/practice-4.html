P14-E79 · json() על תשובה בלי גוף

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: שיעור 4

לקוח קורא תמיד await res.json(). מה יודפס לכל אחת מהתשובות?

import http from "node:http";
import { once } from "node:events";

const server = http.createServer((req, res) => {
  if (req.url === "/deleted") return res.writeHead(204).end();
  if (req.url === "/html") return res.writeHead(502, { "Content-Type": "text/html" }).end("<h1>Bad Gateway</h1>");
  res.writeHead(200, { "Content-Type": "application/json" }).end('{"ok":true}');
});
server.listen(0);
await once(server, "listening");
const base = `http://localhost:${server.address().port}`;

for (const path of ["/ok", "/deleted", "/html"]) {
  const res = await fetch(base + path);
  try {
    console.log(path, res.status, await res.json());
  } catch (err) {
    console.log(path, res.status, err.name + ":", err.message);
  }
}
server.close();

P14-E11 · השרת הראשון שלך 🤖

בקובץ 14-http/starter/P14-E11.mjs השלם createHelloServer() שמחזירה http.Server (לא מפעילה listen — הבדיקות עושות זאת):

P14-E16 · router עם פרמטרים 🤖

  • add(method, pattern, handler) — pattern כמו "/products/:id/reviews".

P14-E17 · לקרוא גוף JSON בבטחה 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

בקובץ 14-http/starter/P14-E17.mjs (המחלקה HttpError כבר כתובה) השלם readJsonBody(req, { limit = 1_000_000 } = {}). req הוא stream עם req.headers. זרוק HttpError:

P14-E80 · בקשה אחת חוסמת את כולן

🧠 הבנהרמה 3⏱ 15 דק׳ידע נדרש: פרק 10, שיעור 4

לשרת יש route איטי /report שמחשב משהו בלולאה סינכרונית של 300ms, ו־route מהיר /ping. שולחים את שתי הבקשות במקביל — קודם /report. באיזה סדר יודפסו השורות?

import http from "node:http";
import { once } from "node:events";

const busy = (ms) => {
  const end = Date.now() + ms;
  while (Date.now() < end) {}
};
const log = [];
const server = http.createServer((req, res) => {
  log.push(`התחיל ${req.url}`);
  if (req.url === "/report") busy(300);
  log.push(`סיים ${req.url}`);
  res.end();
});
server.listen(0);
await once(server, "listening");
const base = `http://localhost:${server.address().port}`;

const report = fetch(base + "/report").then(() => log.push("לקוח: report חזר"));
await new Promise((r) => setTimeout(r, 50));
const ping = fetch(base + "/ping").then(() => log.push("לקוח: ping חזר"));
await Promise.all([report, ping]);
console.log(log.join("\n"));
server.close();

🔗 איך זה מתחבר: לולאת האירועים (event loop) מפרק 10 — Node מריץ JavaScript ב־thread אחד; ‏Promise.all ו־then מאותו פרק. השיעור: ה־handler של השרת הוא callback, והוא רץ באותו thread לכל הבקשות.

P14-E81 · מונה בתוך או מחוץ ל־handler

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 5, שיעור 4

שני שרתים סופרים בקשות. שולחים לכל אחד שלוש בקשות. מה יודפס?

import http from "node:http";
import { once } from "node:events";

let total = 0;
function createCounterServer() {
  let count = 0;
  return http.createServer((req, res) => {
    let perRequest = 0;
    count++;
    total++;
    perRequest++;
    res.end(`${count} ${total} ${perRequest}`);
  });
}

const a = createCounterServer();
const b = createCounterServer();
for (const s of [a, b]) {
  s.listen(0);
  await once(s, "listening");
}
const hit = async (s) => (await fetch(`http://localhost:${s.address().port}/`)).text();
console.log(await hit(a), "|", await hit(a), "|", await hit(b), "|", await hit(a), "|", await hit(b));
a.close();
b.close();

🔗 איך זה מתחבר: closures ו־scope מפרק 5 — ‏count "חי" בתוך הפונקציה שיצרה את השרת. השיעור: ה־handler נקרא מחדש בכל בקשה; ולכן יש הבדל עצום בין משתנה בתוכו למשתנה מעליו.

P14-E82 · async handler שזורק

🧠 הבנהרמה 3⏱ 15 דק׳ידע נדרש: פרק 8, פרק 10, שיעור 4

ה־handler הוא async, וזורק שגיאה אחרי await. מסביב ל־createServer יש try/catch. מה יודפס? (בשורה הראשונה "תופסים" שגיאות שאיש לא טיפל בהן, כדי שהדוגמה לא תקרוס.)

import http from "node:http";
import { once } from "node:events";

process.on("unhandledRejection", (err) => console.log("unhandledRejection:", err.message));

let server;
try {
  server = http.createServer(async (req, res) => {
    await new Promise((r) => setTimeout(r, 10));
    throw new Error("המסד לא זמין");
  });
} catch (err) {
  console.log("catch:", err.message);
}
server.listen(0);
await once(server, "listening");

try {
  await fetch(`http://localhost:${server.address().port}/`, { signal: AbortSignal.timeout(300) });
  console.log("הגיעה תשובה");
} catch (err) {
  console.log("לקוח:", err.name);
}
server.closeAllConnections();
server.close();

ובלי השורה של process.on — מה היה קורה לשרת?

🔗 איך זה מתחבר: try/catch תופס רק מה שנזרק בזמן שהוא רץ (פרק 8), ו־async הופך throw ל־Promise שנדחה (פרק 10). השיעור: ה־handler נקרא הרבה אחרי שה־try נגמר — ולכן ה־try/catch של שרת ההדגמה נמצא בתוך ה־handler.

P14-E24 · אתגר: Express משלך 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 50 דק׳ידע נדרש: כל הפרק

בקובץ 14-http/starter/P14-E24.mjs בנה createApp() — מסגרת זעירה בסגנון Express:

const app = createApp();
app.use((req, res, next) => { console.log(req.method, req.path); next(); });
app.get("/products/:id", (req, res) => res.json({ id: req.params.id, sort: req.query.sort }));
app.post("/products", (req, res) => res.status(201).json(req.body));
const server = app.listen(3000);
  • get, post, put, patch, delete (path עם :params), ו־use(fn) ל־middleware שרץ לפני כל route לפי הסדר; middleware ממשיך רק אם קרא next().
  • req.path, req.query (אובייקט), req.params, ו־req.body — JSON שנקרא אוטומטית כשה־Content-Type הוא JSON (אחרת undefined). JSON שבור ← 400.
  • res.status(code) (מחזיר את res לשרשור), res.json(obj) (ברירת מחדל 200). ב־res.status(204).json() אין גוף.
  • handler (רגיל או async) שזורק ← 500 { "error": "שגיאה פנימית" }; אבל אם לשגיאה יש status ← אותו status ו־{ "error": err.message }.
  • אין route ← 404 { "error": "לא נמצא" }. path קיים עם method אחר ← 405.
  • listen(port, cb) ← מחזיר את ה־http.Server.

🔗 איך זה מתחבר: כל הפרק ביחד — router עם פרמטרים (P14-E16), קריאת גוף JSON (P14-E17), status נכון (שיעור 1) — ועוד closures ומערך של פונקציות (פרק 5) ל־middleware עם next. זה בדיוק מה ש־Express עושה בפרק 15.

P14-E25 · אתגר: הגבלת קצב (rate limit) 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 35 דק׳ידע נדרש: כל הפרק

הגנה בסיסית מפני לקוח ששולח אלפי בקשות. בקובץ 14-http/starter/P14-E25.mjs השלם createLimitedServer({ limit, windowMs, now = Date.now }):

  • מזהה לקוח: ה־header X-Client-Id, או "anonymous".
  • "חלון קבוע": החלון של לקוח מתחיל בבקשה הראשונה שלו, ונמשך windowMs. אחריו — מתחיל חלון חדש מאפס.
  • בתוך החלון, עד limit בקשות ← 200 { "ok": true } עם X-RateLimit-Remaining (כמה נשארו).
  • מעבר לזה ← 429 { "error": "יותר מדי בקשות" }, עם Retry-After — שניות שלמות (עיגול למעלה) עד סוף החלון, ו־X-RateLimit-Remaining: 0.
  • הזמן נלקח מ־now() — כך הבדיקות "מזיזות שעון" בלי לחכות.

🔗 איך זה מתחבר: Map לכל לקוח (פרק 7), שעון מוזרק (now) כמו ב־P10 ו־P12, ו־Math.ceil לשניות (פרק 1). השיעורים: 429 ו־Retry-After (שיעור 1), headers (שיעור 2) ושרת node:http (שיעור 4).

P14-E27 · סטטיסטיקת בקשות כמחלקה 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

🔁 חזרה על class עם שדה פרטי (פרק 12), Map (פרק 7) ו־sort עם שני קריטריונים (פרק 6). שרת אמיתי מודד כל בקשה: איזה route, כמה זמן, והאם נכשלה. כתוב וייצא class RequestStats:

  • record(method, path, status, ms) — רושמת בקשה אחת. ה־route הוא ${method} ${path} (למשל "GET /users").
  • getter total — כמה בקשות נרשמו בסך הכול.
  • summary() — מערך של { route, count, avgMs, errors }, שורה לכל route. ‏avgMs — ממוצע הזמנים, מעוגל למספר שלם (Math.round). ‏errors — כמה בקשות הסתיימו ב־status ‏500 ומעלה.
  • מיון: לפי count מהגדול לקטן. כשיש תיקו — לפי route בסדר א״ב.
  • את הנתונים שומרים בשדה פרטי (#). מבחוץ אי אפשר לשנות אותם.

% npm run check P14-E27

🔗 איך זה מתחבר: class עם שדה פרטי (פרק 12), ‏Map (פרק 7) ו־sort עם שני קריטריונים (פרק 6) — על הנתונים ששרת node:http רואה בכל בקשה. מפתח route אחיד — P14-E42.

P14-E28 · לחכות שהשרת יעלה 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 15 דק׳ידע נדרש: שיעור 4

🔁 חזרה על while (פרק 4) ועל await עם השהיה (פרק 10), עם fetch. כשמפעילים שרת ומסד ב־Docker (פרק 23), השרת מוכן רק אחרי כמה שניות. סקריפט בדיקות שמתחיל מוקדם מדי נכשל. הפתרון הוא לבדוק שוב ושוב את /health עד שהשרת עונה. כתוב וייצא:

async function waitUntilReady(url, { tries = 10, delayMs = 100 } = {})

  • שולחת fetch(url). תשובה עם res.ok (status ‏200–299) ← מחזירה את מספר הניסיון שהצליח (1, 2, 3...).
  • status אחר (למשל 503), או fetch שנכשל (השרת עוד לא מקשיב) ← מחכים delayMs ומנסים שוב.
  • אחרי tries ניסיונות שנכשלו ← Error(השרת לא מוכן אחרי ${tries} ניסיונות). אחרי הניסיון האחרון לא מחכים.
  • הלולאה — עם while.

% npm run check P14-E28

🔗 איך זה מתחבר: while (פרק 4), ‏await עם השהיה (פרק 10) ו־try/catch (פרק 8), יחד עם fetch ו־res.ok מהשיעור.
