P14-E01 · לפרק כתובות 🧠 הבנה רמה 1

💡 רמז 1

port לא כתוב ← url.port הוא מחרוזת ריקה, והדפדפן משתמש ב־80 (http) או 443 (https).

💡 רמז 2

path תמיד מתחיל ב־/ — גם אם לא כתבו אותו.

✅ פתרון
for (const text of [
  "http://localhost:4000/products?maxPrice=100",
  "https://api.shop.co.il/v2/orders/17/items?page=2&sort=-date",
  "https://example.com",
]) {
  const u = new URL(text);
  console.log(u.protocol, u.hostname, u.port || "-", u.pathname, u.search || "-");
}
http: localhost 4000 /products ?maxPrice=100
https: api.shop.co.il - /v2/orders/17/items ?page=2&sort=-date

בשתיים האחרונות ה־port הוא 443 (ברירת המחדל של https). ב־2: המשאב הוא "הפריטים של הזמנה 17", בגרסה 2 של ה־API; sort=-date היא מוסכמה נפוצה ל"מיון יורד לפי תאריך".

⚠️ טעויות נפוצות
  • לחשוב שה־query הוא חלק מה־path. השרת מקבל אותם בנפרד — routing לפי path, סינון לפי query.

P14-E02 · method ו־status 🧠 הבנה רמה 1

💡 רמז 1

4xx — הלקוח צריך לשנות משהו. 5xx — הבעיה אצלנו.

💡 רמז 2

לא מחובר ← 401. מחובר אבל אסור ← 403.

✅ פתרון
  1. GET /orders ← 200
  2. POST /orders ← 201, עם header Location: /orders/42 והאובייקט החדש בגוף
  3. GET /orders/999 ← 404
  4. DELETE /orders/7 ← 204 (או 200 עם גוף)
  5. PATCH /orders/7 עם {"address": "..."} ← 200
  6. POST /users ← 409 Conflict
  7. GET /orders ← 401
  8. DELETE /orders/8 ← 403 (יש מערכות שמחזירות 404 כדי לא לחשוף שההזמנה קיימת — גם זה לגיטימי)
  9. POST /products ← 400 (או 422)
  10. כל בקשה ← 503 (או 500)
⚠️ טעויות נפוצות
  • להחזיר 200 עם {"error": ...} בגוף. הלקוח, הדפדפן, כלי הניטור ו־retry — כולם מסתכלים על ה־status.
  • 500 על קלט לא תקין — זו לא תקלה שלנו.

P14-E29 · המסע של בקשה — בסדר הנכון 🧠 הבנה רמה 1

💡 רמז 1

אי אפשר לשלוח בקשה לפני שיודעים לאן — כתובת IP.

💡 רמז 2

תקלה שבה הגיעה תשובה (404, ‏500) אומרת שכל השלבים עד השרת עבדו.

✅ פתרון

הסדר: c ← d ← a ← e ← b. (443 — כי https בלי פורט מפורש.)

  1. DNS — השם לא תורגם לכתובת. הבקשה לא יצאה בכלל, והשרת לא יודע שניסית.
  2. השרת — הבקשה הגיעה, השרת עבד ועבד נכון: אין מוצר כזה. התקלה (אם יש) בכתובת שהלקוח שלח.
  3. השרת — הבקשה הגיעה והשרת נכשל בעבודה (אולי מול המסד). באג או תקלה אצלנו.
  4. בדרך או בשרת — הכתובת נמצאה, אבל תשובה לא חזרה: השרת לא מקשיב, תקוע, או שהרשת חוסמת. לכן לקוח טוב שם timeout (שיעור 4).
⚠️ טעויות נפוצות
  • לחשוב ש־404 הוא "השרת לא נמצא". 404 היא תשובה — מהשרת. "השרת לא נמצא" הוא שגיאת DNS או חיבור, שבה אין status בכלל.

P14-E30 · מותר לנסות שוב? 🧠 הבנה רמה 1

💡 רמז 1

השאלה: אם השרת יבצע את הבקשה פעמיים — האם המצב בסוף זהה למצב אחרי פעם אחת?

💡 רמז 2

PATCH הוא "בדרך כלל" בטבלה. מה ההבדל בין "קבע ל־X" לבין "שנה ב־X"?

✅ פתרון
  1. בטוח. GET לא משנה כלום.
  2. לא בטוח. עלולות להיווצר שתי הזמנות, ושני חיובים. (הפתרון — מפתח idempotency, פרק 24.)
  3. בטוח. "הכתובת היא X" — פעמיים זה אותו דבר.
  4. בטוח. בפעם השנייה הפריט כבר מחוק. התשובה אולי שונה (404 במקום 204), אבל המצב זהה.
  5. בטוח. "הטלפון הוא X" — קביעת ערך.
  6. לא בטוח. "הורד אחד" פעמיים מוריד שניים. זה PATCH שאינו idempotent — ולכן בטבלה כתוב "בדרך כלל".

הכלל: קביעת ערך חוזרת בבטחה, שינוי יחסי (הוסף, הורד, צור) — לא.

⚠️ טעויות נפוצות
  • לבלבל בין "אותה תשובה" ל"אותו מצב". idempotent מדבר על המצב בשרת — ב־DELETE השני התשובה שונה, והמצב זהה.

P14-E31 · מה URL מחזיר? 🧠 הבנה רמה 2

💡 רמז 1

כל מה שיוצא מ־URL הוא מחרוזת — גם הפורט. פרמטר שלא קיים — null; פרמטר ריק — מחרוזת ריקה.

💡 רמז 2

ב־query, ‏+ הוא רווח. ופורט שהוא ברירת המחדל של הפרוטוקול — URL "שוכח" אותו.

✅ פתרון

console.log(u.searchParams.get("empty"), u.searchParams.get("missing"));

const h = new URL("https://example.com:443/a");
console.log(h.port === "", h.host);

const rel = new URL("/products/7?x=1", "http://localhost:3000");
console.log(rel.href);

red shoes
a [ 'a', 'b' ]

true example.com

שלוש מסקנות לשרת: (1) port ופרמטרים הם מחרוזות — ממירים במפורש; (2) get מחזיר רק את הערך הראשון — לפרמטר שחוזר (tag) צריך getAll; (3) "לא נשלח" (null) ו"נשלח ריק" ("") הם שני מצבים שונים. והשורה האחרונה היא בדיוק מה שהשרת עושה עם req.url (שיעור 4): נתיב יחסי + כתובת בסיס.

⚠️ טעויות נפוצות
  • לצפות ש־u.port יהיה 443 ב־https — הוא ריק, כי זו ברירת המחדל.
  • לצפות ל־red+shoes — ה־+ מפוענח לרווח.

P14-E32 · של מי האשמה — ומה הלקוח עושה? 🧠 הבנה רמה 1

💡 רמז 1

שאל: אם הלקוח ישלח בדיוק את אותה בקשה עוד דקה — האם יש סיכוי שתצליח?

💡 רמז 2

שירות אחר שלא ענה בזמן — יש לזה status משלו בשורת ה־5xx (טבלה בשיעור: "שירות לא זמין / timeout").

✅ פתרון
  1. 400 — הלקוח צריך לתקן את הקלט. ניסיון חוזר ייכשל שוב.
  2. 500 — באג אצלנו. ללקוח אין מה לתקן; מתקנים את השרת.
  3. 429 — 4xx, אבל מיוחד: הבקשה תקינה, צריך לחכות ואז לנסות שוב.
  4. 504 (או 502/503) — תקלה זמנית "מאחורינו". אפשר לנסות שוב אחר כך.
  5. 409 — התנגשות. ניסיון חוזר ייכשל; צריך שם אחר.
  6. 422 (או 400) — מבנה תקין, אבל לא עובר חוק. הלקוח מתקן.

זה בדיוק ההבדל ש־shouldRetry ב־P14-E07 מקודד: ניסיון חוזר עוזר רק לתקלה זמנית (429, ‏5xx של זמינות).

⚠️ טעויות נפוצות
  • להחזיר 500 על קלט לא תקין (כי "נזרקה שגיאה"). הלקוח יחשוב שהשרת שבור, ואולי ינסה שוב ושוב.

P14-E06 · פירוק URL 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

new URL(text) זורק על כתובת לא תקינה — תפוס וזרוק שגיאה משלך.

💡 רמז 2

Object.fromEntries(url.searchParams)

✅ פתרון
// P14-E06
const DEFAULT_PORTS = { "http:": 80, "https:": 443 };

export function parseUrl(text) {
  let url;
  try {
    url = new URL(text);
  } catch {
    throw new Error(`כתובת לא תקינה: ${text}`);
  }
  return {
    protocol: url.protocol.slice(0, -1),
    host: url.hostname,
    port: url.port ? Number(url.port) : (DEFAULT_PORTS[url.protocol] ?? null),
    path: url.pathname,
    query: Object.fromEntries(url.searchParams),
  };
}

console.log(JSON.stringify(parseUrl("http://localhost:4000/products?maxPrice=100&sort=price")));
console.log(JSON.stringify(parseUrl("https://shop.co.il")));
{"protocol":"http","host":"localhost","port":4000,"path":"/products","query":{"maxPrice":"100","sort":"price"}}
{"protocol":"https","host":"shop.co.il","port":443,"path":"/","query":{}}
⚠️ טעויות נפוצות
  • לפרק עם split(":") ו־split("/") — נשבר על פורטים, query, תווים מקודדים. יש URL מובנה.
  • Number(url.port) כש־port ריק ← 0, לא ברירת המחדל.

P14-E07 · קטגוריות status 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

Math.floor(code / 100) נותן את הספרה הראשונה.

💡 רמז 2

new Set([...]).has(code)

✅ פתרון
// P14-E07
const CATEGORIES = { 2: "success", 3: "redirect", 4: "client-error", 5: "server-error" };
const RETRYABLE = new Set([408, 429, 500, 502, 503, 504]);

export function statusCategory(code) {
  if (!Number.isInteger(code)) return "unknown";
  return CATEGORIES[Math.floor(code / 100)] ?? "unknown";
}

export function shouldRetry(code) {
  return RETRYABLE.has(code);
}

console.log([200, 204, 301, 404, 429, 503, 99].map(statusCategory).join(" "));
console.log([400, 404, 429, 500, 503].map(shouldRetry).join(" "));
success success redirect client-error client-error server-error unknown
false false true true true

למה לא לנסות שוב 400 או 404? כי אותה בקשה תקבל אותה תשובה. ניסיון חוזר עוזר רק כשהבעיה זמנית. (501 Not Implemented הוא 5xx שגם לא כדאי לנסות שוב.)

⚠️ טעויות נפוצות
  • code >= 500 בלבד — מפספס את 429 ו־408, ותופס את 501.

P14-E09 · בניית query string 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

new URLSearchParams() ו־append(key, value) מקודדים בשבילך.

💡 רמז 2

const s = sp.toString(); return s ? "?" + s : "";

✅ פתרון
// P14-E09
export function buildQuery(params) {
  const sp = new URLSearchParams();
  for (const [key, value] of Object.entries(params)) {
    if (value === undefined || value === null) continue;
    for (const v of Array.isArray(value) ? value : [value]) sp.append(key, String(v));
  }
  const s = sp.toString();
  return s ? `?${s}` : "";
}

console.log(buildQuery({ page: 2, tag: ["a", "b"], q: "red & blue", skip: undefined }));
console.log(JSON.stringify(buildQuery({ skip: null })));
?page=2&tag=a&tag=b&q=red+%26+blue
""

שים לב ל־%26: בלי קידוד, q=red & blue היה נקרא כפרמטר q=red ועוד פרמטר בשם blue.

⚠️ טעויות נפוצות
  • לחבר מחרוזות ידנית (?q=${q}) — שובר ערכים עם &, = או #.

P14-E33 · מה מותר לכל method 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

קודם מנרמלים: const m = method.trim().toUpperCase();

💡 רמז 2

switch (m) עם case לכל method, ו־default שזורק.

✅ פתרון
// P14-E33: מה מותר לכל method
export function methodInfo(method) {
  const m = String(method).trim().toUpperCase();
  switch (m) {
    case "GET":
    case "DELETE":
      return { hasBody: false, idempotent: true };
    case "PUT":
      return { hasBody: true, idempotent: true };
    case "POST":
    case "PATCH":
      return { hasBody: true, idempotent: false };
    default:
      throw new Error(`method לא מוכר: ${method}`);
  }
}

for (const m of ["GET", "post", " Put ", "PATCH", "delete"]) console.log(m.trim(), methodInfo(m));
try {
  methodInfo("FETCH");
} catch (err) {
  console.log(err.message);
}
GET { hasBody: false, idempotent: true }
post { hasBody: true, idempotent: false }
Put { hasBody: true, idempotent: true }
PATCH { hasBody: true, idempotent: false }
delete { hasBody: false, idempotent: true }
method לא מוכר: FETCH

שתי שאלות בלתי תלויות — "יש גוף?" ו"בטוח לחזור?" — ולכן ארבעה צירופים. PUT הוא היחיד עם גוף שגם בטוח לחזור: הוא שולח את המשאב המלא, ולא "שינוי".

⚠️ טעויות נפוצות
  • לסמן PATCH כ־idempotent. "בדרך כלל" לא מספיק לכלי שמחליט אם לשלוח שוב (P14-E30, סעיף 6).
  • להשוות בלי toUpperCase — "get" ייזרק כ"לא מוכר".

P14-E34 · חלקי הנתיב 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

new URL(input, "http://x") עובד גם על נתיב וגם על כתובת מלאה — כתובת הבסיס נדרשת רק כשהקלט יחסי. ‏pathname נותן את הנתיב בלי query.

💡 רמז 2

pathname.split("/").filter(Boolean).map(decodeURIComponent) — וב־pathname ה־%D7... עוד מקודד, ולכן הסדר נכון.

✅ פתרון
// P14-E34: חלקי הנתיב
export function pathSegments(input) {
  const { pathname } = new URL(input, "http://x");
  return pathname
    .split("/")
    .filter(Boolean)
    .map((part) => decodeURIComponent(part));
}

for (const s of ["https://shop.co.il/v2/orders/17?page=2", "/a//b/", "/%D7%A1%D7%9C/7", "/files/a%2Fb", "/"]) {
  console.log(s.padEnd(40), pathSegments(s));
}
https://shop.co.il/v2/orders/17?page=2   [ 'v2', 'orders', '17' ]
/a//b/                                   [ 'a', 'b' ]
/%D7%A1%D7%9C/7                          [ 'סל', '7' ]
/files/a%2Fb                             [ 'files', 'a/b' ]
/                                        []

הסדר "קודם split, אחר כך decode" הוא עניין של אבטחה ונכונות: אם מפענחים קודם, ‏%2F הופך ל־/ ו"שובר" חלק אחד לשניים — וכך שם קובץ יכול להפוך לנתיב אחר. Express (פרק 15) עושה בדיוק את זה ב־req.params.

⚠️ טעויות נפוצות
  • input.split("/") על הכתובת המלאה — https: ו־shop.co.il נכנסים לרשימה, וגם ה־query.
  • decodeURIComponent(pathname).split("/") — הסדר ההפוך, ו־a%2Fb נשבר.

P14-E35 · אותו origin? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

ראית ב־P14-E31: ‏new URL("https://example.com:443/a").port הוא "" — URL כבר "מנרמל" את פורט ברירת המחדל. גם האותיות ב־host מנורמלות.

💡 רמז 2

new URL(...) זורק על כתובת לא תקינה — עטוף ב־try/catch.

✅ פתרון
// P14-E35: אותו origin?
export function sameOrigin(a, b) {
  let x, y;
  try {
    x = new URL(a);
    y = new URL(b);
  } catch {
    return false;
  }
  return x.protocol === y.protocol && x.hostname === y.hostname && x.port === y.port;
}

const pairs = [
  ["http://localhost:3000/a", "http://localhost:3000/b?x=1"],
  ["http://example.com", "http://example.com:80/x"],
  ["https://EXAMPLE.com/", "https://example.com:443"],
  ["https://example.com", "http://example.com"],
  ["http://localhost:3000", "http://127.0.0.1:3000"],
  ["http://localhost:3000", "http://localhost:3001"],
  ["not a url", "http://x.com"],
];
for (const [a, b] of pairs) console.log(sameOrigin(a, b), a, b);
true http://localhost:3000/a http://localhost:3000/b?x=1
true http://example.com http://example.com:80/x
true https://EXAMPLE.com/ https://example.com:443
false https://example.com http://example.com
false http://localhost:3000 http://127.0.0.1:3000
false http://localhost:3000 http://localhost:3001
false not a url http://x.com

URL עושה את רוב העבודה: מוריד פורט שהוא ברירת מחדל, ומקטין אותיות ב־host. (יש גם מאפיין מוכן, new URL(a).origin, שמחזיר "https://example.com" — ואפשר להשוות אותו. כאן כתבנו את ההשוואה ביד כדי לראות ממה origin בנוי.)

⚠️ טעויות נפוצות
  • להשוות את המחרוזות כמו שהן — http://example.com מול http://example.com:80 ייצאו שונים.
  • לשכוח את הפרוטוקול: http ו־https של אותו host הם origins שונים.

P14-E36 · לשנות פרמטרים בכתובת 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

const u = new URL(url); ואז u.searchParams.set(key, String(value)) או u.searchParams.delete(key). בסוף — u.href.

💡 רמז 2

for (const [key, value] of Object.entries(changes)), ו־value == null תופס גם null וגם undefined.

✅ פתרון
// P14-E36: לשנות פרמטרים בכתובת
export function withQuery(url, changes) {
  const u = new URL(url);
  for (const [key, value] of Object.entries(changes)) {
    if (value === null || value === undefined) u.searchParams.delete(key);
    else u.searchParams.set(key, String(value));
  }
  return u.href;
}

console.log(withQuery("http://shop.test/p?page=1&sort=price", { page: 2 }));

P14-E37 · לבחור status לפי הסדר 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

💡 רמז 2

למה 401 לפני 404? כדי לא לגלות למי שלא מחובר אילו משאבים קיימים.

✅ פתרון
// P14-E37: לבחור status לפי הסדר
export function decideStatus({ method, loggedIn, allowed, exists, valid, duplicate }) {
  if (!loggedIn) return 401;
  if (!allowed) return 403;
  if (method !== "POST" && !exists) return 404;
  if (!valid) return 400;
  if (duplicate) return 409;
  if (method === "POST") return 201;
  if (method === "DELETE") return 204;
  return 200;
}

הסדר מבטא שאלה של "מה מותר לגלות": מי שלא מחובר מקבל 401 גם על משאב שלא קיים — אחרת, היה יכול לסרוק מספרים ולגלות לפי 404 מול 401 אילו הזמנות קיימות. ובקשת PATCH למשאב חסר עם קלט שבור מקבלת 404: אין טעם לבדוק קלט לשינוי של משהו שלא קיים.

P14-E41 · ספירת תשובות לפי טווח 🤖 💻 כתיבת קוד 🤖 רמה 3

// P14-E41: ספירת תשובות לפי טווח
export function countByCategory(lines) {
  const counts = { "2xx": 0, "3xx": 0, "4xx": 0, "5xx": 0, invalid: 0 };
  for (const line of lines) {
    if (line.trim() === "") continue;
    const parts = line.trim().split(/\s+/);
    const status = Number(parts[2]);
    if (parts.length !== 4 || !Number.isInteger(status) || status < 100 || status > 599) {
      counts.invalid++;
      continue;
    }
    const key = `${Math.floor(status / 100)}xx`;
    if (key in counts) counts[key]++;
  }
  return counts;
}

P14-E42 · מפתח route לסטטיסטיקה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

/^\d+$/ — "רק ספרות, מההתחלה ועד הסוף". ונתיב שמתחיל ב־//? נסה new URL("//orders/5", "http://x").host לפני שאתה סומך על URL.

💡 רמז 2

UUID: /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i — הדגל i מתעלם מאותיות גדולות.

✅ פתרון
// P14-E42: מפתח route לסטטיסטיקה
const UUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

export function routeKey(method, url) {
  // נתיב שמתחיל ב־// הוא בעיני URL "כתובת בלי פרוטוקול" (host בשם orders!) — ולכן נתיב מפרקים בלי URL
  const pathname = url.startsWith("/") ? url.split("?")[0] : new URL(url).pathname;
  const parts = pathname
    .split("/")
    .filter(Boolean)
    .map((part) => (/^\d+$/.test(part) ? ":id" : UUID.test(part) ? ":uuid" : part));
  return `${method.toUpperCase()} /${parts.join("/")}`;
}

שימו לב ל־v2 ול־7a: הם לא "כולם ספרות", ולכן נשארים. בכלי ניטור אמיתיים (פרק 24) זו בעיה מוכרת — אם כל מזהה נשאר בנתיב, נוצרות אלפי שורות שונות ("high cardinality"), והגרף הופך לחסר תועלת.

⚠️ טעויות נפוצות
  • /\d+/ בלי ^ ו־$ — ‏v2 הופך ל־:id.
  • new URL(url, "http://x") גם לנתיב — עובד על /orders/5, אבל //orders/5 נקרא כ"כתובת בלי פרוטוקול": ה־host הוא orders, והתוצאה POST /:id/items. (נתגלה בבדיקה של התרגיל הזה.)
  • להחזיר "GET " (בלי /) לשורש — join של מערך ריק הוא "", ולכן ה־/ נכתב מחוץ ל־join.

P14-E43 · קישורי עמודים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

פונקציית עזר: const positiveInt = (text, fallback) => { const n = Number(text); return Number.isInteger(n) && n > 0 ? n : fallback; }; — ושים לב ש־Number(null) הוא 0, שנופל לברירת המחדל.

💡 רמז 2

✅ פתרון
// P14-E43: קישורי עמודים
function positiveInt(text, fallback) {
  const n = Number(text);
  return Number.isInteger(n) && n > 0 ? n : fallback;
}

export function pageLinks(url, total) {
  const params = new URL(url).searchParams;
  const page = positiveInt(params.get("page"), 1);
  const limit = Math.min(positiveInt(params.get("limit"), 10), 100);
  const pages = Math.max(1, Math.ceil(total / limit));
  const link = (p) => {
    const u = new URL(url);
    u.searchParams.set("page", String(p));
    return u.href;
  };
  return {
    page,
    limit,
    pages,
    prev: page > 1 ? link(page - 1) : null,
    next: page < pages ? link(page + 1) : null,
  };
}
