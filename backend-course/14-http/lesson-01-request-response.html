2. חלקי URL

const url = new URL("https://shop.example.com/products/7?currency=ILS&lang=he");
console.log(url.hostname, url.pathname, url.searchParams.get("currency"), url.port || "(ברירת מחדל)");

URL ו־URLSearchParams: לקרוא כתובת

new URL(text) מפרק כתובת לחלקים. ‏url.searchParams הוא אובייקט מסוג URLSearchParams — "רשימת הפרמטרים" של ה־query, שכבר מפוענחת (%D7%A7… ← עברית, ‏+ ← רווח):

const url = new URL("https://shop.example.com:8443/search?q=%D7%A7%D7%A4%D7%94+%D7%A9%D7%97%D7%95%D7%A8&tag=new&tag=sale");
console.log(url.protocol, url.host, url.hostname, url.port);
console.log(url.pathname, url.search);
console.log(url.searchParams.get("q"), url.searchParams.get("missing"));
console.log(url.searchParams.get("tag"), url.searchParams.getAll("tag"));
for (const [key, value] of url.searchParams) {
  console.log(key, "=", value);
}
console.log(Object.fromEntries(url.searchParams));
https: shop.example.com:8443 shop.example.com 8443

שים לב: protocol כולל את הנקודתיים ("https:"); ‏host כולל את הפורט ו־hostname לא; ‏get של מפתח שחוזר נותן רק את הראשון, ו־getAll את כולם. ‏Object.fromEntries (פרק 7, שיעור 3) הופך את הפרמטרים לאובייקט רגיל — אבל ממפתח שחוזר נשאר רק ערך אחד (האחרון).

לשנות ולבנות כתובת

const url = new URL("https://shop.example.com/products?page=2&debug=1");
url.searchParams.set("page", "3");
url.searchParams.delete("debug");
url.searchParams.append("tag", "קפה & חלב");
console.log(url.href);

const params = new URLSearchParams();
params.append("q", "תה ירוק");
params.append("maxPrice", "50");
console.log(params.toString());
https://shop.example.com/products?page=3&tag=%D7%A7%D7%A4%D7%94+%26+%D7%97%D7%9C%D7%91
q=%D7%AA%D7%94+%D7%99%D7%A8%D7%95%D7%A7&maxPrice=50
מתודהמה היא עושה
get(key) / getAll(key)הערך הראשון (או null) / מערך של כל הערכים
has(key)האם הפרמטר קיים
set(key, value)קובע ערך אחד: מחליף את כל הקיימים, או מוסיף בסוף
append(key, value)מוסיף עוד ערך, גם אם המפתח כבר קיים (tag=a&tag=b)
delete(key)מוחק את כל הערכים של המפתח
toString()ה־query מקודד, בלי ?. ‏url.href — הכתובת המלאה אחרי השינויים

הערכים תמיד מחרוזות: set("page", 3) שומר "3". ‏new URLSearchParams() עובד גם בלי URL — כשרוצים רק לבנות query string. הקידוד נעשה לבד: רווח ← +, ‏& ← %26 (אחרת הוא היה נראה כמו תחילת פרמטר חדש).

כתובת יחסית: new URL(path, base)

לנתיב בלבד (/orders/5) אין פרוטוקול ו־host, ו־new URL("/orders/5") זורק Invalid URL. נותנים כתובת בסיס כפרמטר שני, ו־URL משלים ממנה את מה שחסר:

console.log(new URL("/orders/5?x=1", "http://localhost:3000").href);
console.log(new URL("https://api.test/a", "http://localhost:3000").href);
const tricky = new URL("//orders/5", "http://localhost:3000");
console.log(tricky.host, tricky.pathname);
http://localhost:3000/orders/5?x=1
https://api.test/a
orders /5
⚠️ נתיב שמתחיל ב־//

//orders/5 הוא בעיני URL "כתובת בלי פרוטוקול": ‏orders נהיה ה־host, והנתיב שנשאר הוא רק /5. כשהקלט הוא נתיב שעלול להכיל // (למשל req.url מלקוח רשלני), מפרקים אותו בעצמך: path.split("?")[0].

encodeURIComponent ו־decodeURIComponent

כשבונים חלק של כתובת בעצמך (למשל שם בתוך הנתיב), מקודדים אותו. ‏encodeURIComponent מקודד כל תו שיש לו משמעות בכתובת (/, ‏?, ‏&, רווח, עברית), ו־decodeURIComponent מחזיר:

const name = "קפה/תה & חלב";
console.log(`/products/${encodeURIComponent(name)}`);
console.log(decodeURIComponent("%D7%A1%D7%9C"));
console.log(new URL("http://x/files/a%2Fb").pathname.split("/"));
/products/%D7%A7%D7%A4%D7%94%2F%D7%AA%D7%94%20%26%20%D7%97%D7%9C%D7%91
סל
[ '', 'files', 'a%2Fb' ]

pathname לא מפוענח: ‏%2F נשאר כמו שהוא, ולכן קודם מפרקים לפי / ורק אחר כך מפענחים כל חלק. (‏searchParams, לעומת זאת, כבר מפוענח.)

3. Methods

Methodמשמעותדוגמהגוף?בטוח לחזור?
GETהבאGET /products/7לא✔ (לא משנה כלום)
POSTצור / פעולהPOST /productsכן✘ — שתי בקשות = שני מוצרים
PUTהחלף לגמריPUT /products/7כן✔ (אותה תוצאה)
PATCHעדכן חלקיתPATCH /products/7 עם {"price": 99}כןבדרך כלל
DELETEמחקDELETE /products/7לא✔ (מחוק נשאר מחוק)

"בטוח לחזור" = idempotent. זה חשוב כי רשתות נופלות: אם בקשה לא קיבלה תשובה, לקוח ינסה שוב. ב־GET, PUT ו־DELETE זה בסדר. ב־POST — עלולה להיווצר הזמנה כפולה; את זה נפתור ב"מפתח idempotency" (פרק 24 ופרויקט הדגל).

4. Status codes

טווחמשמעותהנפוצים
2xxהצליח200 OK · 201 Created (נוצר משהו) · 204 No Content (הצליח, אין גוף — למשל אחרי מחיקה)
3xxהפניה301 (עבר לצמיתות) · 304 Not Modified (cache)
4xxהלקוח טעה400 Bad Request (קלט לא תקין) · 401 Unauthorized (לא מחובר) · 403 Forbidden (מחובר, אבל אסור) · 404 Not Found · 409 Conflict (התנגשות — למשל אימייל תפוס) · 415 Unsupported Media Type (הגוף בפורמט שהשרת לא מקבל — למשל לא JSON) · 422 (תקין מבנית, לא עובר חוקים) · 429 Too Many Requests
5xxהשרת נכשל500 Internal Server Error (באג) · 502/503/504 (שירות לא זמין / timeout)
💡 401 מול 403

401 = "מי אתה? תתחבר" (אין זהות או שהיא לא תקפה). 403 = "אני יודע מי אתה — ואסור לך" (אין הרשאה). שאלת ראיון קלאסית; נממש את שניהם בפרק 21.

⚠️ 4xx או 5xx — חשוב

קלט לא תקין שגרם לקריסה ← השרת מחזיר 500 ← הלקוח חושב שהשרת שבור (ולפעמים ינסה שוב ושוב). בדיקת קלט (פרקים 11–12) הופכת את זה ל־400 עם הודעה ברורה. כלל: 5xx = באג או תקלה אצלנו, שצריך לטפל בה; 4xx = הלקוח צריך לשנות משהו.
