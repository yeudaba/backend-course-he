P14-E29 · המסע של בקשה — בסדר הנכון

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 1

הקלדת בדפדפן https://shop.example.com/products/7 ולחצת Enter. סדר את השלבים לפי איור 1 בשיעור:

  1. השרת שולף את מוצר 7 מהמסד.
  2. הדפדפן מציג את המוצר.
  3. DNS מתרגם את shop.example.com לכתובת IP.
  4. הדפדפן שולח GET /products/7 לכתובת ה־IP, לפורט 443.
  5. השרת מחזיר תשובה עם status ‏200 וגוף.

ואז: לכל אחת מהתקלות — באיזה שלב היא קרתה? (1) "This site can't be reached — DNS_PROBE_FINISHED_NXDOMAIN". (2) הגיעה תשובה 404. (3) הגיעה תשובה 500. (4) הדפדפן מחכה דקה ואז "timed out".

P14-E32 · של מי האשמה — ומה הלקוח עושה?

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 1

לכל מקרה בחר status מהטבלה בשיעור, וענה: האם זה 4xx או 5xx — והאם הלקוח צריך לשנות משהו בבקשה, או לנסות שוב אחר כך?

  1. הגוף שנשלח הוא {"price": "זול"} — מחיר שאינו מספר.
  2. בקוד של השרת יש undefined.length והוא קרס.
  3. הלקוח שלח 300 בקשות בדקה, והמגבלה היא 100.
  4. השרת מעביר את הבקשה לשירות תשלומים, וזה לא ענה בזמן.
  5. מנסים לשנות את שם המשתמש ל"dana", והשם תפוס.
  6. הבקשה תקינה מבנית — {"from":"2026-12-10","to":"2026-12-01"} — אבל תאריך הסיום לפני ההתחלה.

P14-E06 · פירוק URL 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 1

בקובץ 14-http/starter/P14-E06.mjs השלם parseUrl(text) שמחזירה:

  • protocol — בלי הנקודתיים: "https".
  • host, path.
  • port — מספר. לא כתוב ← 80 ל־http, 443 ל־https, null לאחרים.
  • query — אובייקט רגיל: { maxPrice: "100" }.

כתובת לא תקינה ← Error(כתובת לא תקינה: ${text}).

P14-E07 · קטגוריות status 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: שיעור 1

בקובץ 14-http/starter/P14-E07.mjs השלם:

  • statusCategory(code) ← "success" (2xx), "redirect" (3xx), "client-error" (4xx), "server-error" (5xx), אחרת "unknown" (גם למספר לא שלם).
  • shouldRetry(code) ← true רק לתקלות זמניות שכדאי לנסות שוב: 408, 429, 500, 502, 503, 504.

P14-E09 · בניית query string 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 15 דק׳ידע נדרש: שיעור 1

בקובץ 14-http/starter/P14-E09.mjs השלם buildQuery(params):

  • מחזירה "?a=1&b=2", או "" אם אין אף פרמטר.
  • מדלגת על undefined ו־null — אבל לא על 0, false או "".
  • מערך ← אותו מפתח כמה פעמים: { tag: ["a", "b"] } ← tag=a&tag=b.
  • קידוד נכון של רווחים, עברית ו־& — בלי לקודד ידנית.

P14-E33 · מה מותר לכל method 🤖

💻 כתיבת קוד 🤖🔥 חימוםרמה 2⏱ 10 דק׳ידע נדרש: שיעור 1

כתוב וייצא methodInfo(method) שמחזירה אובייקט לפי טבלת ה־methods בשיעור:

  • hasBody — האם לבקשה יש בדרך כלל גוף (POST, ‏PUT, ‏PATCH).
  • idempotent — האם בטוח לשלוח שוב (GET, ‏PUT, ‏DELETE). PATCH הוא "בדרך כלל" — כלומר לא מובטח, ולכן false.

האותיות לא משנות ("get", ‏"Get"), ורווחים מסביב מוסרים. method אחר ← throw new Error(method לא מוכר: ${method}).

methodInfo("GET");    // { hasBody: false, idempotent: true }
methodInfo("patch");  // { hasBody: true, idempotent: false }

P14-E34 · חלקי הנתיב 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: שיעור 1

כתוב וייצא pathSegments(input). ‏input הוא כתובת מלאה או נתיב בלבד. מחזירה את חלקי ה־path כמערך:

  • בלי ה־query ובלי חלקים ריקים ("/a//b/" ← ["a", "b"]).
  • כל חלק מפוענח עם decodeURIComponent: "/%D7%A1%D7%9C/7" ← ["סל", "7"].
  • מפרקים לפי / לפני שמפענחים: "/files/a%2Fb" ← ["files", "a/b"] — חלק אחד.
pathSegments("https://shop.co.il/v2/orders/17?page=2"); // ["v2", "orders", "17"]
pathSegments("/");                                      // []

P14-E35 · אותו origin? 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: שיעור 1

הדפדפן מתייחס לשתי כתובות כ"אותו אתר" (same origin) רק אם הפרוטוקול, ה־host והפורט זהים (נפגוש את זה ב־CORS, יחידה 15.5). כתוב וייצא sameOrigin(a, b):

  • פורט שלא נכתב = ברירת המחדל: http://example.com ו־http://example.com:80/x — אותו origin.
  • ה־path וה־query לא משנים.
  • localhost ו־127.0.0.1 — origins שונים (ההשוואה היא על הטקסט, לא על המחשב).
  • אחת הכתובות לא תקינה ← false.

P14-E36 · לשנות פרמטרים בכתובת 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 10 דק׳ידע נדרש: שיעור 1

כתוב וייצא withQuery(url, changes) שמחזירה מחרוזת של כתובת חדשה:

  • לכל מפתח ב־changes: ערך רגיל (גם 0 או false) ← קובע את הפרמטר (מחליף אם קיים, כמחרוזת). ‏null או undefined ← מוחק אותו.
  • שאר הפרמטרים נשארים, באותו סדר.
withQuery("http://shop.test/p?page=1&sort=price", { page: 2 });
// "http://shop.test/p?page=2&sort=price"
withQuery("http://shop.test/p?page=1", { page: null, q: "red shoes" });
// "http://shop.test/p?q=red+shoes"

P14-E37 · לבחור status לפי הסדר 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 15 דק׳ידע נדרש: שיעור 1

שרת מחליט על status לפי כמה בדיקות — והסדר שלהן חשוב. כתוב וייצא decideStatus(ctx). ‏ctx הוא { method, loggedIn, allowed, exists, valid, duplicate } (כולם boolean חוץ מ־method). בדוק לפי הסדר:

  1. לא מחובר ← 401.
  2. אין הרשאה ← 403.
  3. method אינו "POST" והמשאב לא קיים ← 404. (ב־POST יוצרים משאב חדש, אז אין מה לחפש.)
  4. קלט לא תקין ← 400.
  5. כפילות ← 409.
  6. הצלחה: POST ← 201, ‏DELETE ← 204, אחרת ← 200.

P14-E40 · switch על ספרת המאות

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 3, שיעור 1

בלי להריץ — מה יודפס?

function category(status) {
  switch (Math.floor(status / 100)) {
    case 2:
      return "success";
    case 4:
    case 5:
      return "error";
    default:
      return "other";
  }
}
console.log(category(204), category(404), category(503));
console.log(category("404"), category(99), category(299.9), category(600));

🔗 איך זה מתחבר: switch עם case שנופל לבא (fall-through) מפרק 3, והמרה אוטומטית של מחרוזת בחילוק מפרק 1. השיעור: טווחי ה־status לפי הספרה הראשונה.

P14-E42 · מפתח route לסטטיסטיקה 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 15 דק׳ידע נדרש: פרק 6, פרק 13, שיעור 1

כדי לספור בקשות לפי route, צריך ש־/products/7 ו־/products/8 ייספרו יחד. כתוב וייצא routeKey(method, url):

  • ה־method באותיות גדולות, רווח, ואחריו הנתיב.
  • url יכול להיות כתובת מלאה או נתיב. ה־query יורד.
  • חלק בנתיב שכולו ספרות ← :id. חלק שנראה כמו UUID (32 תווים הקסדצימליים ב־5 קבוצות, 8-4-4-4-12, אותיות קטנות או גדולות) ← :uuid.
  • / בסוף ו־// לא משנים; שורש ← "/".
routeKey("get", "/products/17?sort=price");                 // "GET /products/:id"
routeKey("DELETE", "https://api.test/users/3f2c9a1e-0b7d-4c1a-9f00-2a6b8c4d5e6f/"); // "DELETE /users/:uuid"
routeKey("GET", "/");                                       // "GET /"

P14-E43 · קישורי עמודים 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 1, פרק 3, שיעור 1

API שמחזיר רשימה ארוכה מחזיר אותה בעמודים, עם קישורים לעמוד הקודם והבא. כתוב וייצא pageLinks(url, total). ‏url — הכתובת המלאה של הבקשה הנוכחית; ‏total — כמה פריטים יש בסך הכול. מחזירה { page, limit, pages, prev, next }:

  • page ו־limit מה־query. ברירת מחדל: 1 ו־10. ערך שאינו מספר שלם חיובי ← ברירת המחדל. ‏limit מעל 100 ← 100.
  • pages — כמה עמודים יש (לפחות 1, גם כש־total הוא 0).
  • prev — הכתובת של העמוד הקודם, או null בעמוד 1. ‏next — של העמוד הבא, או null אם page >= pages.
  • בקישורים: כל שאר הפרמטרים נשמרים, ו־page מוחלף (כמו ב־P14-E36).
