1. משאבים, לא פעולות

ב־REST, הכתובת היא שם עצם (המשאב), וה־method הוא הפועל:

פעולה✘ לא כך✔ כךstatus
כל המשימותGET /getAllTasksGET /tasks200
משימה אחתGET /task?id=7GET /tasks/7200 / 404
יצירהPOST /createTaskPOST /tasks201
עדכון חלקיPOST /tasks/7/updatePATCH /tasks/7200
מחיקהGET /deleteTask/7DELETE /tasks/7204
תגובות של משימהGET /comments?taskId=7GET /tasks/7/comments200
  • רבים: /tasks, לא /task. אותיות קטנות ומקפים: /order-items.
  • קינון רק כשמשאב "שייך" לאחר, ולא יותר משתי רמות.
  • פעולה שהיא באמת לא CRUD — פועל בסוף זה בסדר: POST /orders/7/cancel.
  • GET /deleteTask/7 מסוכן במיוחד: דפדפנים, כלי תצוגה מקדימה וסורקים שולחים GET בלי לשאול.

2. רשימות: סינון, מיון, pagination

GET /tasks?status=open&q=חלב&sort=-createdAt&page=2&limit=20

  • סינון — שדה = ערך (status=open), חיפוש חופשי (q).
  • מיון — שם שדה, ומינוס לסדר יורד (-createdAt). רק מרשימה סגורה של שדות.
  • pagination — page ו־limit, עם ברירת מחדל ותקרה ל־limit. בלי תקרה, ?limit=10000000 יפיל את השרת.

ומה מחזירים? לא רק מערך — גם מידע על העמוד, כדי שהלקוח יידע אם יש עוד:

{
  "data": [{ "id": 21, "title": "..." }],
  "meta": { "page": 2, "limit": 20, "total": 57, "totalPages": 3 }
}
function paginate<T>(items: T[], page: number, limit: number) {
  const start = (page - 1) * limit;
  return {
    data: items.slice(start, start + limit),
    meta: { page, limit, total: items.length, totalPages: Math.ceil(items.length / limit) },
  };
}

const items = Array.from({ length: 57 }, (_, i) => i + 1);
const result = paginate(items, 3, 20);
console.log(result.data.length, result.data[0], JSON.stringify(result.meta));
17 41 {"page":3,"limit":20,"total":57,"totalPages":3}

(זו pagination לפי offset — פשוטה ומספיקה לרוב המקרים. ברשימות ענק משתמשים ב־cursor: "תן לי 20 אחרי id 1040". נכיר בפרק 18.)

3. מבנה שגיאה אחיד

כל שגיאה ב־API — אותו מבנה. הלקוח כותב קוד טיפול אחד:

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "קלט לא תקין",
    "details": [{ "path": "title", "message": "חובה" }]
  }
}

code — קבוע, באנגלית, בשביל קוד (if (err.code === "TASK_NOT_FOUND")). message — לבני אדם, ואפשר לשנות אותו בלי לשבור לקוחות. details — רק כשיש מה לפרט.

4. Router ושכבות

src/tasks/tasks.routes.ts 
import { Router } from "express";
import type { TasksService } from "./tasks.service.ts";

export function createTasksRouter(service: TasksService) {
  const router = Router();

  router.get("/", (req, res) => {
    res.json(service.list());
  });

  router.get("/:id", (req, res) => {
    res.json(service.get(Number(req.params.id))); // service זורק HttpError(404) אם אין
  });

  return router;
}
src/app.ts 
export function createApp(service = new TasksService(new InMemoryTasksRepository())) {
  const app = express();
  app.use(express.json());
  app.use("/tasks", createTasksRouter(service));
  app.use(notFound);
  app.use(errorHandler);
  return app;
}

בתוך ה־router, הכתובות יחסיות לקידומת: router.get("/:id") + app.use("/tasks", ...) = GET /tasks/:id. וה־service מוזרק מבחוץ (dependency injection — פרק 12): בבדיקות אפשר להעביר service עם נתונים מוכנים.
