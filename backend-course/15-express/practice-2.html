  next(new HttpError(403, "next"));

P15-E48 · X-Request-Id 🤖

💻 כתיבת קוד 🤖🔥 חימוםרמה 2⏱ 15 דק׳ידע נדרש: שיעור 2

P15-E51 · middleware שנוצר פעמיים

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 5, שיעור 2

counter() מחזירה middleware שסופר בקשות. פעם הוא נרשם עם app.use, ופעם בתוך routes. מה יודפס?

import express from "express";

function counter(name: string): express.RequestHandler {
  let n = 0;
  return (req, res, next) => {
    n++;
    res.append("X-Count", `${name}=${n}`);
    next();
  };
}

const app = express();
app.use(counter("global"));
app.get("/a", counter("a"), (req, res) => {
  res.end();
});
app.get("/b", counter("b"), (req, res) => {
  res.end();
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  for (const path of ["/a", "/a", "/b", "/a"]) {
    console.log(path, (await fetch(base + path)).headers.get("x-count"));
  }
  server.close();
});

🔗 איך זה מתחבר: closures מפרק 5 — כל קריאה ל־counter() יוצרת n חדש. השיעור: middleware גלובלי מול middleware בתוך route (app.get(path, mw, handler)).

P15-E52 · מה קורה אחרי next()?

🧠 הבנהרמה 3⏱ 10 דק׳ידע נדרש: פרק 10, שיעור 2

ה־middleware מדפיס לפני next(), אחרי next(), ובאירוע finish. באיזה סדר יודפסו השורות — לבקשה ל־route סינכרוני, ולבקשה ל־route אסינכרוני?

import express from "express";

const log: string[] = [];
const app = express();
app.use((req, res, next) => {
  log.push(`${req.path}: לפני next`);
  res.on("finish", () => log.push(`${req.path}: finish`));
  next();
  log.push(`${req.path}: אחרי next`);
});
app.get("/sync", (req, res) => {
  log.push("/sync: route");
  res.end();
});
app.get("/async", async (req, res) => {
  await new Promise((r) => setTimeout(r, 20));
  log.push("/async: route");
  res.end();
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  await fetch(`${base}/sync`);
  await fetch(`${base}/async`);
  await new Promise((r) => setTimeout(r, 20));
  console.log(log.join("\n"));
  server.close();
});

🔗 איך זה מתחבר: אירועים (on) ו־await מפרק 10 — ‏next() הוא קריאה רגילה לפונקציה, שלא מחכה ל־Promise. השיעור: למה ה־logger משתמש ב־finish ולא בשורה שאחרי next().

P15-E53 · מה נחשב HttpError?

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 8, פרק 12, שיעור 2

ה־error handler מהשיעור בודק err instanceof HttpError. מה יקבל הלקוח לכל אחד מהדברים שנזרקים?

import express from "express";

class HttpError extends Error {
  status: number;
  code: string;
  constructor(status: number, code: string, message: string) {
    super(message);
    this.status = status;
    this.code = code;
  }
}
class NotFoundError extends HttpError {
  constructor(what: string) {
    super(404, "NOT_FOUND", `${what} לא נמצא`);
  }
}

const thrown: Record<string, () => unknown> = {
  sub: () => new NotFoundError("המוצר"),
  plain: () => ({ status: 404, code: "NOT_FOUND", message: "אובייקט רגיל" }),
  text: () => "שגיאה כטקסט",
  type: () => new TypeError("x is undefined"),
};

const app = express();
app.get("/:kind", (req) => {
  throw thrown[req.params.kind]();
});
app.use((err: unknown, req: express.Request, res: express.Response, next: express.NextFunction) => {
  if (err instanceof HttpError) {
    res.status(err.status).json({ error: { code: err.code, message: err.message } });
    return;
  }
  res.status(500).json({ error: { code: "INTERNAL", message: "שגיאה פנימית" } });
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  for (const kind of Object.keys(thrown)) {
    const res = await fetch(`${base}/${kind}`);
    console.log(kind.padEnd(6), res.status, await res.text());
  }
  server.close();
});

🔗 איך זה מתחבר: instanceof ו־extends מפרקים 8 ו־12 — מחלקה יורשת היא גם מופע של מחלקת האב; ובפרק 8: אפשר לזרוק כל ערך, לא רק Error. השיעור: error handler אחד לכל האפליקציה.

P15-E54 · שגיאות של התחום ל־HTTP 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 12, שיעור 2

כתוב וייצא createMetrics(now = () => performance.now()) שמחזירה { middleware, snapshot }:

  • middleware — רושם כל בקשה כשהתשובה נשלחה (אירוע finish): המשך (now() בסוף פחות now() בהתחלה) וה־status.
  • snapshot() ← { total, byStatus, avgMs, maxMs, slowest }: ‏byStatus — ספירה לפי טווח ("2xx" וכו׳ — רק טווחים שהופיעו); ‏avgMs — ממוצע מעוגל למספר שלם (0 אם אין בקשות); ‏maxMs — המשך הארוך ביותר (0 אם אין); ‏slowest — ${method} ${originalUrl} של הבקשה האיטית ביותר (בשוויון — הראשונה), או null.
  • snapshot מחזיר אובייקט חדש בכל קריאה — שינוי שלו לא משפיע על המדדים.

הבדיקה מזריקה now משלה (שעון מזויף), כדי שהזמנים יהיו ידועים מראש.

P15-E56 · timeout ל־route אסינכרוני 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 10, שיעור 2

route שמחכה לשירות איטי לא צריך להשאיר את הלקוח מחכה לנצח. כתוב וייצא withTimeout(handler, ms) — מקבלת handler אסינכרוני (req, res) => Promise<unknown> ומחזירה handler חדש:

  • מריץ את handler. אם לא נשלחה תשובה תוך ms ← 503 { "error": { "code": "TIMEOUT", "message": "הבקשה לקחה יותר מדי זמן" } }.
  • כשה־handler המקורי מסיים מאוחר וכותב תשובה — אסור שזה יזרוק או יפיל משהו. בודקים res.headersSent לפני שעונים, והטיימר מבוטל (clearTimeout) כשה־handler סיים בזמן.
  • ה־handler זרק ← השגיאה עוברת ל־next(err) (אם עוד לא נשלחה תשובה).

שים לב: ה־handler המקורי צריך לבדוק res.headersSent בעצמו לפני שהוא עונה — אחרת Express יזרוק "Cannot set headers". בבדיקה, ה־handlers האיטיים עושים את זה.
