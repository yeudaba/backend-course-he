1. למה Zod

בפרק 12 כתבת ולידציה ביד: if (typeof body.title !== "string" || ...). זה עובד, אבל ארוך, קל לשכוח שדה, ו־TypeScript לא יודע שבדקת. Zod: מתארים פעם אחת איך נראה קלט תקין — ומקבלים גם בדיקה וגם טיפוס.

import { z } from "zod";

const createTaskSchema = z.object({
  title: z.string().trim().min(1, "חובה").max(100, "עד 100 תווים"),
  priority: z.enum(["low", "medium", "high"]).default("medium"),
  dueDate: z.iso.date().optional(),
});

type CreateTaskInput = z.infer<typeof createTaskSchema>;

const good = createTaskSchema.safeParse({ title: "  לקנות חלב ", dueDate: "2026-11-20" });
if (good.success) {
  const task: CreateTaskInput = good.data;
  console.log(JSON.stringify(task));
}

const bad = createTaskSchema.safeParse({ title: "", priority: "urgent" });
if (!bad.success) {
  for (const issue of bad.error.issues) console.log(issue.path.join("."), "—", issue.message);
}
{"title":"לקנות חלב","priority":"medium","dueDate":"2026-11-20"}
title — חובה
priority — Invalid option: expected one of "low"|"medium"|"high"
  • .trim() ו־.default() לא רק בודקים — הם משנים: התוצאה ב־data היא הגרסה הנקייה. תמיד ממשיכים עם data, לא עם הקלט המקורי.
  • שדות שלא בסכמה ({"isAdmin": true}) נמחקים מ־data. זו הגנה חשובה: לקוח לא יכול "להשחיל" שדה שלא ציפית לו. (z.strictObject — מחזיר שגיאה במקום למחוק.)
  • z.infer נותן את הטיפוס — בלי לכתוב interface נפרד שעלול לא להתאים לבדיקה.
  • parse זורק; safeParse מחזיר { success, data | error }. בשרת — safeParse, כדי להחליט בעצמנו מה להחזיר.

כללים משלך ושינוי צורה: refine, ‏transform, ‏pipe

לפעמים הכלל לא נמצא בטבלה: "מחיר מינימום לא גדול מהמקסימום", "לפחות שדה אחד ב־PATCH". ‏.refine(fn, { message, path }) מוסיף בדיקה משלך: ‏fn מקבלת את הערך (אחרי שאר הבדיקות) ומחזירה true אם הוא תקין. ‏.transform(fn) משנה את הערך, ו־.pipe(סכמה) מעביר את התוצאה לסכמה נוספת — "קודם נקה, אחר כך בדוק":

import { z } from "zod";

const range = z
  .object({ minPrice: z.number().min(0), maxPrice: z.number().min(0) })
  .refine((r) => r.minPrice <= r.maxPrice, { message: "minPrice גדול מ־maxPrice", path: ["minPrice"] });
const bad = range.safeParse({ minPrice: 50, maxPrice: 10 });
console.log(bad.error?.issues[0].path, bad.error?.issues[0].message);

const tags = z.string().transform((s) => s.split(",").map((t) => t.trim()).filter((t) => t !== ""));
console.log(tags.parse(" קפה, תה ,,שוקו"));

const sku = z
  .string()
  .transform((s) => s.replaceAll(" ", "").toUpperCase())
  .pipe(z.string().regex(/^[A-Z]{3}-\d{3}$/, "מק״ט לא תקין"));
console.log(sku.parse(" abc-123 "), sku.safeParse("abc").error?.issues[0].message);

const update = z
  .strictObject({ title: z.string().trim().min(1), done: z.boolean() })
  .partial()
  .refine((u) => Object.keys(u).length > 0, { message: "צריך לפחות שדה אחד" });
console.log(update.safeParse({}).error?.issues[0].message);
console.log(update.safeParse({ done: true }).success, update.safeParse({ isAdmin: true }).error?.issues[0].code);

  • refine רץ רק אם כל שאר הבדיקות עברו — לכן בתוך fn הערך כבר בטוח מהטיפוס הנכון. ‏path קובע ליד איזה שדה תופיע ההודעה.
  • transform משנה גם את הטיפוס: tags מקבלת מחרוזת ומחזירה מערך (z.infer יודע את זה). אחרי transform אי אפשר לשרשר .regex — לכן pipe לסכמה חדשה.
  • לניקוי פשוט יש קיצורים בלי transform: z.string().trim(), ‏.toLowerCase(), ‏.toUpperCase() — הם משנים את הערך ואחר כך אפשר להמשיך לשרשר בדיקות.
  • strictObject(...).partial() — סכמה טובה ל־PATCH: כל שדה לא חובה, ושדה לא מוכר נדחה. ה־refine שאחריה מוסיף "לפחות שדה אחד".

2. query: הכול מגיע כמחרוזת

ב־?page=2, הערך הוא "2". z.number() יכשיל אותו. z.coerce.number() ממיר קודם:

import { z } from "zod";

const listQuerySchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  limit: z.coerce.number().int().min(1).max(50).default(20),
  status: z.enum(["open", "done"]).optional(),
});

console.log(JSON.stringify(listQuerySchema.parse({ page: "2" })));
console.log(listQuerySchema.safeParse({ limit: "1000" }).success);
console.log(listQuerySchema.safeParse({ page: "" }).success);
console.log(z.coerce.number().parse(""));
{"page":2,"limit":20}
false
false
0

שורה 2: limit מעל התקרה ← נכשל, וטוב שכך. שורה 3: ?page= (ריק) נכשל — כי Number("") הוא 0, ו־0 קטן מ־1. ושורה 4 היא המלכודת: בשדה בלי min, ערך ריק הופך בשקט ל־0. ?maxPrice= יחזיר רק מוצרים בחינם. כשזה חשוב — הוסף .positive(), או בדוק ש־"" לא נשלח.

3. middleware בדיקה אחד לכל ה־routes

src/middleware/validate.ts 
import type { Request, Response, NextFunction } from "express";
import type { ZodType } from "zod";

export function validateBody(schema: ZodType) {
  return (req: Request, res: Response, next: NextFunction) => {
    const result = schema.safeParse(req.body);
    if (!result.success) {
      res.status(400).json({
        error: {
          code: "VALIDATION_ERROR",
          message: "קלט לא תקין",
          details: result.error.issues.map((i) => ({ path: i.path.join("."), message: i.message })),
        },
      });
      return;
    }
    req.body = result.data; // מעכשיו req.body נקי ובטוח
    next();
  };
}
router.post("/", validateBody(createTaskSchema), (req, res) => {
  const task = service.create(req.body);
  res.status(201).location(`/tasks/${task.id}`).json(task);
});

שים לב לרעיון: validateBody(schema) היא פונקציה שמחזירה middleware (closure — פרק 5). כך אותו קוד משרת כל סכמה.

⚠️ Express 5: אסור לדרוס את req.query

req.body = result.data עובד. אבל req.query = result.data זורק: Cannot set property query of #<IncomingMessage> which has only a getter (ב־Express 5 ה־query מחושב מחדש מהכתובת). המקום המקובל לשמור query שנבדק: res.locals.query = result.data — res.locals הוא אובייקט שמיועד בדיוק להעברת נתונים בין middleware ל־handler באותה בקשה.
