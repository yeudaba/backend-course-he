P15-E04 · סדר middleware 🧠 הבנה רמה 1

💡 רמז 1

app.use("/admin", fn) רץ על כל כתובת שמתחילה ב־/admin.

💡 רמז 2

ה־header לא נשלח בבקשה.

✅ פתרון

GET /admin/stats (בלי header): מודפס A, C; הלקוח מקבל 403 "אסור". D ו־E לא רצים. עם x-admin: yes: A C D, 200 "stats".

GET /public: A B; 200. ה־middleware של admin לא רץ — הוא רשום אחרי, וגם לא מתאים לכתובת.

⚠️ טעויות נפוצות
  • לחשוב ש־middleware שנרשם אחרי route "עוטף" אותו — לא; הוא רץ רק אם בקשה מגיעה אליו.

P15-E43 · middleware ששוכח את next 🧠 הבנה רמה 2

💡 רמז 1

middleware עושה אחד משניים: עונה, או קורא next(). מה קורה כשהוא לא עושה אף אחד מהם?

💡 רמז 2

Express לא "ממשיך לבד" — אין timeout בצד השרת.

✅ פתרון
import express from "express";

const app = express();
app.use((req, res, next) => {
  console.log("לוג:", req.method, req.path);
  if (req.path.startsWith("/admin")) next();
});
app.get("/health", (req, res) => {
  res.json({ ok: true });
});
app.get("/admin/stats", (req, res) => {
  res.json({ users: 42 });
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  for (const path of ["/admin/stats", "/health"]) {
    try {
      const res = await fetch(base + path, { signal: AbortSignal.timeout(300) });
      console.log(path, res.status, await res.text());
    } catch (err) {
      console.log(path, (err as Error).name);
    }
  }
  server.closeAllConnections();
  server.close();
});
לוג: GET /admin/stats
/admin/stats 200 {"users":42}
לוג: GET /health
/health TimeoutError

הבקשה ל־/health נתקעה: ה־middleware לא ענה ולא קרא next(), ו־Express מחכה לנצח. בלי timeout בלקוח (פרק 14) — גם הלקוח מחכה לנצח. וזה באג שקט: אין שגיאה ביומן, רק "השרת לא עונה". כלל: בכל ענף של middleware — או תשובה, או next().

⚠️ טעויות נפוצות
  • לחפש את הבאג ב־route של /health — הוא בכלל לא רץ.

P15-E44 · app.use עם קידומת 🧠 הבנה רמה 2

💡 רמז 1

הקידומת מתאימה לחלקים שלמים של הנתיב — /api ו־/api/..., לא כל מחרוזת שמתחילה ב־"api".

💡 רמז 2

בתוך middleware עם קידומת, Express "מוריד" את הקידומת מ־req.path. ‏originalUrl נשאר מלא — כולל query.

✅ פתרון
import express from "express";

const app = express();
const seen: string[] = [];
app.use("/api", (req, res, next) => {
  seen.push(`${req.originalUrl} → path=${req.path}`);
  next();
});
app.use((req, res) => {
  res.sendStatus(204);
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  for (const path of ["/api", "/api/users?x=1", "/API/users", "/apis", "/v2/api/users"]) await fetch(base + path);
  console.log(seen.join("\n"));
  server.close();
});
/api → path=/
/api/users?x=1 → path=/users
/API/users → path=/users

שלוש בקשות עברו: /api, ‏/api/users — ו־/API/users (Express לא רגיש לאותיות). ‏/apis ו־/v2/api/users לא. בתוך ה־middleware, ‏req.path הוא מה שאחרי הקידומת — ולכן middleware של לוג משתמש ב־originalUrl (P15-E09). זה גם מה שמאפשר ל־Router של שיעור 3 לכתוב router.get("/:id").

⚠️ טעויות נפוצות
  • לבדוק הרשאה ב־app.use("/admin", ...) ולסמוך על req.path.startsWith("/admin") בתוכו — שם req.path כבר בלי /admin.

P15-E45 · error handler עם שלושה פרמטרים 🧠 הבנה רמה 2

💡 רמז 1

Express מבדיל בין middleware רגיל ל־error handler לפי מספר הפרמטרים של הפונקציה.

💡 רמז 2

אם אין error handler משלך — Express עונה בעצמו, בדף HTML.

✅ פתרון
import express from "express";

const app = express();
app.get("/boom", () => {
  throw new Error("משהו נשבר");
});
// @ts-ignore — Express "מבין" רק לפי מספר הפרמטרים
app.use((err: Error, req: express.Request, res: express.Response) => {
  res.status(500).json({ error: { code: "INTERNAL", message: "שגיאה פנימית" } });
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  const res = await fetch(`${base}/boom`);
  const body = await res.text();
  console.log(res.status, res.headers.get("content-type"));
  console.log(body.includes("משהו נשבר") ? "ההודעה הפנימית נחשפה בגוף" : "ההודעה לא נחשפה");
  server.close();
});
500 text/html; charset=utf-8
ההודעה הפנימית נחשפה בגוף

עם שלושה פרמטרים, Express חושב שזה middleware רגיל (req, res, next) — ומדלג עליו כשיש שגיאה. השגיאה מגיעה ל־handler המובנה, שמחזיר דף HTML (ובמצב פיתוח — עם ה־stack וההודעה הפנימית; ב־NODE_ENV=production רק "Internal Server Error"). הלקוח מקבל HTML במקום מבנה השגיאה שלך. לכן בשיעור: "גם אם לא משתמשים ב־next, חובה לכתוב אותו". (ה־@ts-ignore כאן רק כדי שהדוגמה תעבור — TypeScript דווקא עזר לזהות את הבעיה.)

⚠️ טעויות נפוצות
  • "לנקות" פרמטר שלא בשימוש כי ESLint מתלונן — בפונקציה הזו הוא חלק מהחתימה. קוראים לו _next במקום למחוק.

P15-E46 · ארבע דרכים להגיע ל־error handler 🧠 הבנה רמה 2

💡 רמז 1

ב־Express 5, גם throw בפונקציה async מגיע ל־error handler (קופסת 💡 בשיעור).

💡 רמז 2

next() בלי ארגומנט = "תמשיך לתחנה הבאה". next(err) = "קפוץ ל־error handler".

✅ פתרון
import express from "express";

class HttpError extends Error {
  status: number;
  constructor(status: number, message: string) {
    super(message);
    this.status = status;
  }
}

const app = express();
app.get("/sync", () => {
  throw new HttpError(400, "sync");
});
app.get("/async", async () => {
  await new Promise((r) => setTimeout(r, 5));
  throw new HttpError(409, "async");
});
app.get("/next-err", (req, res, next) => {
  next(new HttpError(403, "next"));
});
app.get("/next-empty", (req, res, next) => {
  next();
});
app.use((req, res) => {
  res.status(404).json({ error: "לא נמצא" });
});
app.use((err: unknown, req: express.Request, res: express.Response, next: express.NextFunction) => {
  const status = err instanceof HttpError ? err.status : 500;
  res.status(status).json({ error: err instanceof Error ? err.message : "?" });
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  for (const path of ["/sync", "/async", "/next-err", "/next-empty"]) {
    const res = await fetch(base + path);
    console.log(path.padEnd(11), res.status, await res.text());
  }
  server.close();
});
/sync       400 {"error":"sync"}
/async      409 {"error":"async"}
/next-err   403 {"error":"next"}
/next-empty 404 {"error":"לא נמצא"}

שלוש הדרכים הראשונות שקולות: throw רגיל, throw אחרי await (Express 5), ו־next(err). ‏next() בלי שגיאה ממשיך הלאה — אין עוד route מתאים, ולכן ה־404.

⚠️ טעויות נפוצות
  • לכתוב next(err) ואחריו להמשיך את הפונקציה (בלי return) — אותה בעיה כמו תשובה כפולה.

P15-E47 · איפה לרשום את הלוג? 🧠 הבנה רמה 2

💡 רמז 1

route שענה — האם הבקשה ממשיכה לתחנות שאחריו?

💡 רמז 2

finish נורה אחרי שהתשובה נשלחה — ולכן statusCode הוא הסופי, גם אם נקבע מאוחר יותר בשרשרת.

✅ פתרון
import express from "express";

const lines: string[] = [];
function logger(tag: string): express.RequestHandler {
  return (req, res, next) => {
    res.on("finish", () => lines.push(`${tag}: ${req.method} ${req.originalUrl} ${res.statusCode}`));
    next();
  };
}

const app = express();
app.use(logger("לפני"));
app.get("/a", (req, res) => {
  res.json("A");
});
app.use(logger("אחרי"));
app.use((req, res) => {
  res.status(404).json("לא נמצא");
});

const server = app.listen(0, async () => {
  const base = `http://localhost:${(server.address() as { port: number }).port}`;
  await fetch(`${base}/a`);
  await fetch(`${base}/b?x=1`);
  await new Promise((r) => setTimeout(r, 20));
  console.log(lines.join("\n"));
  server.close();
});
לפני: GET /a 200
לפני: GET /b?x=1 404
אחרי: GET /b?x=1 404

ה־logger ש"אחרי" ה־routes ראה רק את הבקשה שאף route לא ענה לה. לוג שרשום מאוחר מדי "מפספס" בדיוק את הבקשות המוצלחות — ולכן בשיעור הוא נרשם מיד אחרי express.json(). וה־404 נרשם ב"לפני" עם status 404 — כי ה־finish רץ בסוף, אחרי שה־404 נקבע.

⚠️ טעויות נפוצות
  • להדפיס את res.statusCode מיד ב־middleware (בלי finish) — תמיד 200, כי התשובה עוד לא נקבעה.

P15-E09 · middleware לוג 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

res.on("finish", () => ...)

💡 רמז 2

Math.round(performance.now() - start)

✅ פתרון
// P15-E09
import type { Request, Response, NextFunction } from "express";

export function createLogger(write: (line: string) => void = console.log) {
  return (req: Request, res: Response, next: NextFunction) => {
    const start = performance.now();
    res.on("finish", () => {
      write(`${req.method} ${req.originalUrl} ${res.statusCode} ${Math.round(performance.now() - start)}ms`);
    });
    next();
  };
}
⚠️ טעויות נפוצות
  • לכתוב את השורה לפני next() — ה־status עוד 200 תמיד, והזמן תמיד 0.
  • req.path במקום req.originalUrl — בתוך router הוא רק החלק היחסי, ובלי query.

P15-E10 · שגיאות במקום אחד 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

error handler — חייב 4 פרמטרים.

💡 רמז 2

err instanceof HttpError

✅ פתרון
// P15-E10
import type { Request, Response, NextFunction } from "express";

export class HttpError extends Error {
  status: number;
  code: string;
  constructor(status: number, code: string, message: string) {
    super(message);
    this.status = status;
    this.code = code;
  }
}

export function notFound(req: Request, res: Response) {
  res.status(404).json({ error: { code: "NOT_FOUND", message: `אין כתובת ${req.method} ${req.path}` } });
}

export function errorHandler(err: unknown, req: Request, res: Response, next: NextFunction) {
  if (err instanceof HttpError) {
    res.status(err.status).json({ error: { code: err.code, message: err.message } });
    return;
  }
  if (typeof err === "object" && err !== null && "type" in err && err.type === "entity.parse.failed") {
    res.status(400).json({ error: { code: "INVALID_JSON", message: "JSON לא תקין" } });
    return;
  }
  console.error(err);
  res.status(500).json({ error: { code: "INTERNAL", message: "שגיאה פנימית" } });
}
⚠️ טעויות נפוצות
  • res.status(500).json({ error: err.message }) — חושף פרטים פנימיים ללקוח.

P15-E18 · מפתח API 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

app.use("/api", requireApiKey(keys)) לפני ה־routes של /api.

💡 רמז 2

req.get("x-api-key")

✅ פתרון
// P15-E18
import express, { type Request, type Response, type NextFunction } from "express";

export function requireApiKey(keys: Map<string, string>) {
  return (req: Request, res: Response, next: NextFunction) => {
    const key = req.get("x-api-key");
    if (!key) {
      res.status(401).set("WWW-Authenticate", "ApiKey").json({ error: { code: "MISSING_API_KEY", message: "חסר X-Api-Key" } });
      return;
    }
    const client = keys.get(key);
    if (!client) {
      res.status(403).json({ error: { code: "INVALID_API_KEY", message: "מפתח לא מוכר" } });
      return;
    }
    res.locals.client = client;
    next();
  };
}

export function createApp(keys: Map<string, string>) {
  const app = express();
  app.get("/public", (req, res) => {
    res.json({ ok: true });
  });
  app.use("/api", requireApiKey(keys));
  app.get("/api/me", (req, res) => {
    res.json({ client: res.locals.client });
  });
  return app;
}

מפתחות API מתאימים לשרת־מול־שרת. למשתמשים (שם וסיסמה, טוקנים) — פרק 21. ומפתחות אמיתיים נשמרים כ־hash ולא כטקסט — גם על זה בפרק 21.

⚠️ טעויות נפוצות
  • 403 גם כשאין מפתח בכלל — 401 אומר "תזדהה", 403 "הזדהית ואסור".

P15-E20 · הסדר הפוך 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

כתוב לעצמך את הסדר שהבקשה עוברת, תחנה אחר תחנה.

💡 רמז 2

json ← routes ← 404 ← error handler.

✅ פתרון
// P15-E20: מתוקן — רק הסדר השתנה
import express, { type Request, type Response, type NextFunction } from "express";

export function createApp() {
  const app = express();
  const tasks: { id: number; title: string }[] = [];

  app.use(express.json());

  app.get("/tasks", (req, res) => {
    res.json(tasks);
  });
  app.post("/tasks", (req, res) => {
    const task = { id: tasks.length + 1, title: String(req.body.title) };
    tasks.push(task);
    res.status(201).json(task);
  });
  app.get("/tasks/boom", () => {
    throw new Error("באג");
  });

  app.use((req: Request, res: Response) => {
    res.status(404).json({ error: { code: "NOT_FOUND", message: "לא נמצא" } });
  });

  app.use((err: unknown, req: Request, res: Response, next: NextFunction) => {
    console.error(err);
    res.status(500).json({ error: { code: "INTERNAL", message: "שגיאה פנימית" } });
  });

  return app;
}

(שים לב גם לבאג שלא ביקשנו לתקן: /tasks/boom רשום אחרי route שיכול היה לבלוע אותו? כאן לא — אין /tasks/:id. אבל אילו היה, הסדר היה חשוב גם שם.)

⚠️ טעויות נפוצות
  • error handler לפני ה־routes — הוא פשוט לא רץ: שגיאה "קופצת" רק קדימה בשרשרת.

P15-E21 · Cannot set headers 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

אחרי res.json הקוד ממשיך לרוץ. ומתי נשלחים ה־headers?

💡 רמז 2

header חייב להיקבע לפני שהתשובה נשלחת. אפשר לקבוע אותו מיד בהתחלה... או: res.on("finish") מאוחר מדי.

✅ פתרון
// P15-E21: מתוקן
import express from "express";

const products = [{ id: 1, name: "מקלדת" }];

export function createApp() {
  const app = express();

  app.use((req, res, next) => {
    const start = performance.now();
    const originalJson = res.json.bind(res);
    res.json = (body) => {
      res.set("X-Response-Time", `${Math.round(performance.now() - start)}ms`);
      return originalJson(body);
    };
    next();
  });

  app.get("/products/:id", (req, res) => {
    const id = Number(req.params.id);
    if (!Number.isInteger(id)) {
      res.status(400).json({ error: "id חייב להיות מספר" });
      return;
    }
    const product = products.find((p) => p.id === id);
    if (!product) {
      res.status(404).json({ error: "לא נמצא" });
      return;
    }
    res.json(product);
  });

  return app;
}

בעיה 3 קלאסית: header אחרי finish זורק, ו־header אחרי next() מגיע מאוחר אם ה־handler כבר ענה. הפתרון כאן עוטף את res.json, כך שה־header נקבע ברגע האחרון לפני השליחה. (ספריות כמו response-time משתמשות ב־on-headers לאותה מטרה.)

⚠️ טעויות נפוצות
  • להוסיף if (!res.headersSent) — משתיק את השגיאה, אבל ה־header עדיין חסר.

P15-E48 · X-Request-Id 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

req.get("x-request-id") — בלי תלות באותיות. בדיקה: /^[A-Za-z0-9-]{1,64}$/.

💡 רמז 2

החתימה: (req: Request, res: Response, next: NextFunction) => { ... }, ו־res.set("X-Request-Id", id).

✅ פתרון
// P15-E48: X-Request-Id
import express, { type Request, type Response, type NextFunction } from "express";

const VALID = /^[A-Za-z0-9-]{1,64}$/;

export function requestId() {
  return (req: Request, res: Response, next: NextFunction) => {
    const incoming = req.get("x-request-id");
    const id = incoming && VALID.test(incoming) ? incoming : crypto.randomUUID();
    res.locals.requestId = id;
    res.set("X-Request-Id", id);
    next();
  };
}

const app = express();
app.use(requestId());
app.get("/", (req, res) => {
  res.json({ id: res.locals.requestId });
});
const server = app.listen(0, async () => {
  const address = server.address();
  const base = `http://localhost:${typeof address === "object" && address ? address.port : 0}`;
  const a = await fetch(base, { headers: { "X-Request-Id": "abc-123" } });
  console.log(a.headers.get("x-request-id"), await a.text());
  const b = await fetch(base, { headers: { "X-Request-Id": "<script>" } });
  console.log(b.headers.get("x-request-id") === (await b.json()).id ? "UUID חדש, זהה ב־header ובגוף" : "?");
  server.close();
});

UUID חדש, זהה ב־header ובגוף

P15-E52 · מה קורה אחרי next()? 🧠 הבנה רמה 3

💡 רמז 1

next() קורא ל־route. route סינכרוני מסתיים לפני ש־next() חוזר.

💡 רמז 2

route אסינכרוני מגיע ל־await ו"חוזר" מיד (עם Promise) — ואז next() חוזר, עוד לפני שהתשובה נשלחה.

  log.push("/sync: route");

ב־/async, השורה "אחרי next" הודפסה לפני ה־route עצמו. מי שמודד זמן תגובה כך — start לפני next(), ‏end אחריו — יקבל כמעט 0ms לכל route אסינכרוני (כלומר לכולם, מול מסד). ‏finish נורה רק כשהתשובה באמת יצאה — ולכן ה־logger בשיעור מודד שם.

⚠️ טעויות נפוצות
  • await next() — ‏next לא מחזיר Promise של ה־route; זה לא עוזר ב־Express (ב־Koa, ספרייה אחרת, זה דווקא עובד).

✅ פתרון
// P15-E54: שגיאות של התחום ל־HTTP
import express, { type Request, type Response, type NextFunction } from "express";

export class InsufficientFundsError extends Error {
  constructor(balance: number, amount: number) {
    super(`אין מספיק כסף: יתרה ${balance}, ביקשת ${amount}`);
    this.name = "InsufficientFundsError";
  }
}
export class AccountNotFoundError extends Error {
  constructor(id: string) {
    super(`חשבון ${id} לא קיים`);
    this.name = "AccountNotFoundError";
  }
}

export class Bank {
  #balances: Map<string, number>;
  constructor(balances: Map<string, number>) {
    this.#balances = balances;
  }
  withdraw(id: string, amount: number): number {
    const balance = this.#balances.get(id);
    if (balance === undefined) throw new AccountNotFoundError(id);
    if (amount > balance) throw new InsufficientFundsError(balance, amount);
    this.#balances.set(id, balance - amount);
    return balance - amount;
  }
}

function errorHandler(err: unknown, req: Request, res: Response, next: NextFunction) {
  const send = (status: number, code: string, message: string) => res.status(status).json({ error: { code, message } });
  if (err instanceof AccountNotFoundError) return void send(404, "ACCOUNT_NOT_FOUND", err.message);
  if (err instanceof InsufficientFundsError) return void send(409, "INSUFFICIENT_FUNDS", err.message);
  console.error(err);
  send(500, "INTERNAL", "שגיאה פנימית");
}

export function createApp(bank: Bank) {
  const app = express();
  app.use(express.json());
  app.post("/accounts/:id/withdraw", (req, res) => {
    const amount = req.body?.amount;
    if (!Number.isInteger(amount) || amount <= 0) {
      res.status(400).json({ error: { code: "VALIDATION", message: "amount חייב להיות מספר שלם חיובי" } });
      return;
    }
    const balance = bank.withdraw(req.params.id, amount);
    res.json({ id: req.params.id, balance });
  });
  app.use(errorHandler);
  return app;
}

// P15-E55: מדדים לשרת
import express, { type Request, type Response, type NextFunction } from "express";

export function createMetrics(now = () => performance.now()) {
  let total = 0;
  let sumMs = 0;
  let maxMs = 0;
  let slowest: string | null = null;
  const byStatus: Record<string, number> = {};

  function middleware(req: Request, res: Response, next: NextFunction) {
    const start = now();
    res.on("finish", () => {
      const ms = now() - start;
      total++;
      sumMs += ms;
      const key = `${Math.floor(res.statusCode / 100)}xx`;
      byStatus[key] = (byStatus[key] ?? 0) + 1;
      if (slowest === null || ms > maxMs) {
        maxMs = ms;
        slowest = `${req.method} ${req.originalUrl}`;
      }
    });
    next();
  }

  const snapshot = () => ({
    total,
    byStatus: { ...byStatus },
    avgMs: total === 0 ? 0 : Math.round(sumMs / total),
    maxMs,
    slowest,
  });

  return { middleware, snapshot };
}

const metrics = createMetrics();
const app = express();
app.use(metrics.middleware);
app.get("/fast", (req, res) => {
  res.json("ok");
});
app.get("/slow", async (req, res) => {
  await new Promise((r) => setTimeout(r, 50));
  res.json("ok");
});
const server = app.listen(0, async () => {
  const address = server.address();
  const base = `http://localhost:${typeof address === "object" && address ? address.port : 0}`;
  await fetch(`${base}/fast`);
  await fetch(`${base}/slow?x=1`);
  await fetch(`${base}/nope`);
  await new Promise((r) => setTimeout(r, 10));
  const s = metrics.snapshot();
  console.log(s.total, JSON.stringify(s.byStatus), s.slowest, s.maxMs >= 50 ? "maxMs ≥ 50" : "?");
  server.close();
});

middleware ו־snapshot הן שתי פונקציות שנוצרו באותה קריאה, ולכן "רואות" את אותם משתנים — מצב פרטי בלי מחלקה. זה בסיס של כל ספריית ניטור (Prometheus, פרק 24): middleware שסופר, ו־endpoint שמציג את המונים.

⚠️ טעויות נפוצות
  • לחשב את המשך מיד אחרי next() — ל־route אסינכרוני יוצא כמעט 0 (P15-E52).
  • byStatus בלי העתקה ב־snapshot — הקוד שקרא יכול לאפס את המונים בטעות.

P15-E56 · timeout ל־route אסינכרוני 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

return async (req, res, next) => { const timer = setTimeout(() => { if (!res.headersSent) res.status(503).json(...); }, ms); try { await handler(req, res); } catch (err) { ... } finally { clearTimeout(timer); } };

💡 רמז 2

✅ פתרון
// P15-E56: timeout ל־route אסינכרוני
import express, { type Request, type Response, type NextFunction } from "express";

export function withTimeout(handler: (req: Request, res: Response) => Promise<unknown>, ms: number) {
  return async (req: Request, res: Response, next: NextFunction) => {
    const timer = setTimeout(() => {
      if (!res.headersSent) {
        res.status(503).json({ error: { code: "TIMEOUT", message: "הבקשה לקחה יותר מדי זמן" } });
      }
    }, ms);
    try {
      await handler(req, res);
    } catch (err) {
      if (!res.headersSent) next(err);
    } finally {
      clearTimeout(timer);
    }
  };
}

const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));
const app = express();
app.get(
  "/fast",
  withTimeout(async (req, res) => {
    await sleep(10);
    res.json({ ok: true });
  }, 100),
);
app.get(
  "/slow",
  withTimeout(async (req, res) => {
    await sleep(300);
    if (!res.headersSent) res.json({ ok: true });
  }, 100),
);
const server = app.listen(0, async () => {
  const address = server.address();
  const base = `http://localhost:${typeof address === "object" && address ? address.port : 0}`;
  for (const path of ["/fast", "/slow"]) {
    const start = Date.now();
    const res = await fetch(base + path);
    console.log(path, res.status, await res.text(), Date.now() - start < 250 ? "(מהר)" : "(איטי)");
  }
  await sleep(300);
  server.close();
});
/fast 200 {"ok":true} (מהר)
/slow 503 {"error":{"code":"TIMEOUT","message":"הבקשה לקחה יותר מדי זמן"}} (מהר)

ה־route האיטי עדיין רץ ברקע אחרי ה־503 — JavaScript לא יכול "להרוג" פונקציה באמצע. לכן ה־timeout רק מגן על הלקוח; כדי באמת לעצור את העבודה (למשל בקשה לשירות אחר) מעבירים AbortSignal הלאה (פרק 14). ‏clearTimeout ב־finally חשוב: בלעדיו כל בקשה מהירה משאירה טיימר פתוח.

⚠️ טעויות נפוצות
  • Promise.race בלי clearTimeout — עובד, אבל אלפי טיימרים "מתים" מצטברים.
  • לענות 503 בלי לבדוק headersSent — אם ה־handler ענה בדיוק באותו רגע, נזרק "Cannot set headers".
