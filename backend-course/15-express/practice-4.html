P15-E75 · parse שזורק בתוך route

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: שיעור 4

בשיעור כתוב: "בשרת — safeParse". מה קורה אם משתמשים ב־parse? בשרת a אין error handler משלך; ב־b יש אחד שמכיר את z.ZodError. מה יקבל הלקוח?

import express from "express";
import { z } from "zod";

const schema = z.object({ qty: z.number().int().min(1) });

function build(withHandler: boolean) {
  const app = express();
  app.use(express.json());
  app.post("/cart", (req, res) => {
    const { qty } = schema.parse(req.body);
    res.json({ qty });
  });
  if (withHandler) {
    app.use((err: unknown, req: express.Request, res: express.Response, next: express.NextFunction) => {
      if (err instanceof z.ZodError) {
        res.status(400).json({ error: { code: "VALIDATION_ERROR", details: err.issues.map((i) => i.path.join(".")) } });
        return;
      }
      res.status(500).json({ error: { code: "INTERNAL" } });
    });
  }
  return app;
}

const a = build(false).listen(0);
const b = build(true).listen(0);
const post = (s: typeof a, body: unknown) =>
  fetch(`http://localhost:${(s.address() as { port: number }).port}/cart`, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(body) });
setTimeout(async () => {
  for (const [name, server] of [["a", a], ["b", b]] as const) {
    const ok = await post(server, { qty: 2 });
    const bad = await post(server, { qty: 0 });
    const text = await bad.text();
    console.log(name, ok.status, bad.status, bad.headers.get("content-type"), text.startsWith("{") ? text : "(דף HTML)");
  }
  a.close();
  b.close();
}, 50);

P15-E78 · safeParse ו־narrowing

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 11, שיעור 4

התוצאה של safeParse היא union — "הצלחה עם data" או "כישלון עם error". הקוד משתמש בטיפוס שמחקה את זה של Zod (בקובץ אמיתי — schema.safeParse). אילו שורות TypeScript יפסול?

// כך (בקירוב) מוגדרת התוצאה של schema.safeParse ב־Zod:
type SafeParseResult<T> =
  | { success: true; data: T; error?: never }
  | { success: false; error: { issues: { path: string[]; message: string }[] }; data?: never };
declare function safeParse(body: unknown): SafeParseResult<{ qty: number }>;

function handle(body: unknown) {
  const r = safeParse(body);
  const a = r.data.qty;
  if (r.success) {
    const b = r.data.qty * 2;
    const c = r.error.issues;
  } else {
    const d = r.error.issues.length;
  }
  if (!r.success) return;
  const e: number = r.data.qty;
}

🔗 איך זה מתחבר: discriminated unions ו־narrowing מפרק 11 — success הוא השדה שמבחין. השיעור: safeParse במקום parse.

P15-E25 · אתגר: Idempotency-Key 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 40 דק׳ידע נדרש: כל הפרק

לקוח לחץ "הזמן", הרשת נפלה, והאפליקציה שלחה שוב. האם נוצרו שתי הזמנות? בקובץ 15-express/starter/P15-E25.ts בנה idempotency() — middleware לבקשות POST:

  • בלי header Idempotency-Key ← 400 MISSING_IDEMPOTENCY_KEY.
  • מפתח חדש ← הבקשה ממשיכה כרגיל, וה־status והגוף של התשובה נשמרים (יחד עם הגוף של הבקשה).
  • אותו מפתח ואותו גוף בקשה ← אותה תשובה בדיוק (status + גוף), בלי להריץ שוב את ה־handler, ועם header Idempotent-Replayed: true.
  • אותו מפתח, גוף אחר ← 422 IDEMPOTENCY_KEY_REUSED.
  • בקשה שנייה עם אותו מפתח בזמן שהראשונה עוד רצה ← 409 REQUEST_IN_PROGRESS.

והשלם createApp() עם POST /orders (מוגן, יוצר { id, ...body } ← 201, אחרי המתנה של 50ms שמדמה מסד נתונים) ו־GET /orders.

🔗 איך זה מתחבר: idempotency מפרק 14 (שיעור 1 — למה POST לא בטוח לחזור), ‏Map מפרק 7 ו־middleware מהשיעור 2 — יחד עם Zod מהשיעור הזה.

🔁 חזרה על ביטויים רגולריים (P13-E26) ועל replace (פרק 2), הפעם בתוך Zod. ‏z.string().regex(re, message) בודק שהמחרוזת מתאימה ל־regex. כתוב וייצא signupSchema ו־type Signup לטופס הרשמה:

  • username: קודם trim והמרה לאותיות קטנות. אחר כך: 3–16 תווים, רק אותיות באנגלית, ספרות ו־_, ומתחיל באות. הודעה: "שם משתמש: 3–16 תווים — אותיות באנגלית, ספרות ו־_, ומתחיל באות".
  • phone: טלפון נייד ישראלי. מסירים רווחים ומקפים, ואז מקבלים 05 ועוד 8 ספרות, או +9725 ועוד 8 ספרות. התוצאה תמיד בצורה 0501234567 (‏+972 הופך ל־0). הודעה: "טלפון נייד ישראלי: 05XXXXXXXX".
  • password: לפחות 8 תווים ("סיסמה: לפחות 8 תווים"), לפחות אות גדולה באנגלית ("סיסמה: לפחות אות גדולה אחת") ולפחות ספרה ("סיסמה: לפחות ספרה אחת").
signupSchema.parse({ username: " Dana_88 ", phone: "+972 50-123-4567", password: "Secret123" });
// { username: "dana_88", phone: "0501234567", password: "Secret123" }
