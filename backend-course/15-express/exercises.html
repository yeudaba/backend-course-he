P15-E25 · אתגר: Idempotency-Key 🤖

רמה 5⏱ 40 דק׳ידע נדרש: כל הפרק

לקוח לחץ "הזמן", הרשת נפלה, והאפליקציה שלחה שוב. האם נוצרו שתי הזמנות? בקובץ 15-express/starter/P15-E25.ts בנה idempotency() — middleware לבקשות POST:

  • בלי header Idempotency-Key ← 400 MISSING_IDEMPOTENCY_KEY.
  • מפתח חדש ← הבקשה ממשיכה כרגיל, וה־status והגוף של התשובה נשמרים (יחד עם הגוף של הבקשה).
  • אותו מפתח ואותו גוף בקשה ← אותה תשובה בדיוק (status + גוף), בלי להריץ שוב את ה־handler, ועם header Idempotent-Replayed: true.
  • אותו מפתח, גוף אחר ← 422 IDEMPOTENCY_KEY_REUSED.
  • בקשה שנייה עם אותו מפתח בזמן שהראשונה עוד רצה ← 409 REQUEST_IN_PROGRESS.

והשלם createApp() עם POST /orders (מוגן, יוצר { id, ...body } ← 201, אחרי המתנה של 50ms שמדמה מסד נתונים) ו־GET /orders.

🏁 מבחן מעבר

  • לבנות מאפס API של משאב אחד (CRUD) ב־Express, עם status נכון לכל מקרה.
  • להסביר מה קורה כשמחליפים סדר של שני app.use — ולתקן שרת שבו הסדר שגוי.
  • לכתוב error handler אחד שמטפל ב־JSON שבור, בשגיאת ולידציה, ב"לא נמצא" ובבאג.
  • לכתוב סכמת Zod ל־body ול־query (עם coerce), ולהחזיר 400 עם פירוט השדות.
  • להוסיף pagination וסינון לרשימה, עם meta בתשובה.
  • npm run check P15: 80% מ־E06–E19, ולפחות תרגיל תיקון אחד.
