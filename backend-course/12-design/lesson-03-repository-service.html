שיעור 3 — interface, repository, service והזרקת תלויות

⏱ ~45 דקות

🎯 בשיעור הזה
  • interface כחוזה, ו־implements.
  • Repository — "איך שומרים", Service — "מה החוקים".
  • הזרקת תלויות: לקבל את ה־repository מבחוץ.
  • generic repository.

1. חוזה

export type Product = { id: number; name: string; price: number; stock: number };

export interface ProductRepository {
  findById(id: number): Promise<Product | null>;
  findAll(): Promise<Product[]>;
  save(product: Product): Promise<void>;
}

ה־interface אומר מה אפשר לעשות, לא איך. כל מחלקה שמקיימת אותו — בזיכרון, בקובץ, ב־PostgreSQL — "מתאימה". שים לב שכל המתודות אסינכרוניות: מסד נתונים אמיתי יהיה אסינכרוני, אז כבר עכשיו מגדירים כך.

2. מימוש בזיכרון

export class InMemoryProductRepository implements ProductRepository {
  #items = new Map<number, Product>();

  async findById(id: number): Promise<Product | null> {
    const p = this.#items.get(id);
    return p ? { ...p } : null;
  }
  async findAll(): Promise<Product[]> {
    return [...this.#items.values()].map((p) => ({ ...p }));
  }
  async save(product: Product): Promise<void> {
    this.#items.set(product.id, { ...product });
  }
}

implements ProductRepository — TypeScript בודק שהמחלקה באמת מקיימת את החוזה (שכחת מתודה? שגיאה). ושים לב ל־{ ...p }: מחזירים עותקים — כדי שמי שקיבל מוצר לא ישנה את "המסד" בטעות (פרק 7, הפניות!). מסד אמיתי מתנהג כך מעצמו.

3. Service עם תלות מוזרקת

export class OrderService {
  #products: ProductRepository;

  constructor(products: ProductRepository) {
    this.#products = products;
  }

  async placeOrder(productId: number, qty: number): Promise<{ total: number }> {
    const product = await this.#products.findById(productId);
    if (product === null) {
      throw new NotFoundError("מוצר", productId);
    }
    if (product.stock < qty) {
      throw new ValidationError("qty", "אין מספיק במלאי");
    }
    await this.#products.save({ ...product, stock: product.stock - qty });
    return { total: product.price * qty };
  }
}

const service = new OrderService(new InMemoryProductRepository());

הזרקת תלויות (DI): ה־service לא כותב new InMemoryProductRepository() בעצמו — הוא מקבל repository ב־constructor. למה זה חשוב?

  • בדיקות: בבדיקה מעבירים repository מזויף עם בדיוק הנתונים שצריך — בלי מסד אמיתי (פרק 22).
  • החלפה: מעבר לזיכרון ← PostgreSQL הוא שורה אחת במקום אחד.
  • NestJS בנוי כולו על הרעיון הזה — שם המסגרת מזריקה את התלויות אוטומטית.

4. Repository גנרי

export class InMemoryRepository<T extends { id: number }> {
  #items = new Map<number, T>();
  async findById(id: number): Promise<T | null> { /* ... */ }
  async save(item: T): Promise<void> { /* ... */ }
}
const products = new InMemoryRepository<Product>();
const users = new InMemoryRepository<User>();

T extends { id: number } — "כל טיפוס, ובתנאי שיש לו id מספרי". כך כותבים את הלוגיקה פעם אחת לכל הישויות (תרגיל E15).
