שיעור 4 — גישור: טיפוסים מול בדיקה בזמן ריצה

⏱ ~25 דקות · יחידת גישור

🎯 יחידת גישור — TypeScript לא בודק בקשות

לפני שנבנה שרת (פרקים 14–15), חשוב לסגור בלבול נפוץ מאוד: אם יש לי טיפוסים בכל מקום — למה צריך עוד בדיקות קלט?

1. הניסוי

type CreateOrderDto = { productId: number; qty: number };

function createOrder(dto: CreateOrderDto): string {
  const total = dto.qty * 10;
  return `הזמנה: ${dto.qty} יחידות, סה״כ ${total}`;
}

const body: CreateOrderDto = JSON.parse('{"productId": "7", "qty": "-3abc"}');
console.log(createOrder(body));
הזמנה: -3abc יחידות, סה״כ NaN

TypeScript לא התלונן בכלל — כי JSON.parse מחזיר any, וההשמה ל־CreateOrderDto "האמינה" לו. ובזמן ריצה הטיפוסים כבר לא קיימים. כך בדיוק נראית בקשה מהרשת: טקסט שכל אחד יכול לשלוח.

2. הדפוס: parse, don't validate

במקום "לבדוק ואז להמשיך עם אותו any", כותבים פונקציה שמקבלת unknown ומחזירה אובייקט חדש מוקלד (או זורקת):

type CreateOrderDto = { productId: number; qty: number };

class ValidationError extends Error {}

function parseCreateOrder(input: unknown): CreateOrderDto {
  if (typeof input !== "object" || input === null) {
    throw new ValidationError("גוף הבקשה חייב להיות אובייקט");
  }
  const { productId, qty } = input as Record<string, unknown>;
  if (typeof productId !== "number" || !Number.isInteger(productId)) {
    throw new ValidationError("productId חייב להיות מספר שלם");
  }
  if (typeof qty !== "number" || !Number.isInteger(qty) || qty < 1) {
    throw new ValidationError("qty חייב להיות מספר שלם חיובי");
  }
  return { productId, qty };
}

try {
  parseCreateOrder(JSON.parse('{"productId": "7", "qty": "-3abc"}'));
} catch (err) {
  console.log((err as Error).message);
}
console.log(parseCreateOrder({ productId: 7, qty: 2, isAdmin: true }));
productId חייב להיות מספר שלם
{ productId: 7, qty: 2 }

שלושה דברים טובים: (1) הקלט הרע נעצר בגבול; (2) שדה מיותר (isAdmin: true) לא עובר פנימה — אחרת תוקף היה יכול להעביר שדות שלא תכננת (זו פרצה אמיתית בשם mass assignment); (3) מעכשיו כל הקוד עובד עם CreateOrderDto אמיתי.

(input as Record<string, unknown> — הצבה שמותר להשתמש בה כאן, כי בדקנו שזה אובייקט, וכל שדה עדיין unknown שנבדק.) את הקוד הזה תכתוב שוב ושוב — ולכן בפרק 15 נעבור ל־Zod, ובפרק 20 ל־class-validator של NestJS. אבל הרעיון — טיפוסים לא מחליפים validation — הוא מה שחשוב.
