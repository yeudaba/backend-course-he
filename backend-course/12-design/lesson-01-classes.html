1. מחלקה = תבנית

בפרק 8 כתבת פונקציות בנק שמקבלות חשבון ומחזירות חשבון חדש. מחלקה מחברת את הנתונים (יתרה) עם הפעולות המותרות עליהם (הפקדה, משיכה) ביחידה אחת:

class BankAccount {
  readonly owner: string;
  #balance = 0;

  constructor(owner: string, initial = 0) {
    this.owner = owner;
    this.deposit(initial);
  }

  get balance(): number {
    return this.#balance;
  }

  deposit(amount: number): void {
    if (amount < 0) {
      throw new Error("סכום שלילי");
    }
    this.#balance += amount;
  }

  withdraw(amount: number): void {
    if (amount > this.#balance) {
      throw new Error("אין מספיק יתרה");
    }
    this.#balance -= amount;
  }
}

const acc = new BankAccount("דנה", 100);
acc.withdraw(30);
console.log(acc.owner, acc.balance);
דנה 70

2. למה פרטי?

בלי #, כל קוד יכול לכתוב acc.balance = -1000000. עם #balance, הדרך היחידה לשנות יתרה היא דרך deposit/withdraw — שבודקות. זה נקרא encapsulation ("כימוס"): המחלקה מבטיחה שהאובייקט תמיד במצב חוקי.

class BankAccount {
  #balance = 0;
  get balance(): number {
    return this.#balance;
  }
}
const acc = new BankAccount();
acc.#balance = 1000000;
acc.balance = 5;

💡 # מול private

יש ב־TypeScript גם private balance = 0. ההבדל: private נבדק רק ב־TypeScript (בזמן ריצה השדה גלוי), # נאכף גם בזמן ריצה. ב־NestJS תראה הרבה private — ובמיוחד בכתיב מקוצר בתוך ה־constructor (constructor(private repo: Repo)). את הכתיב המקוצר הזה Node לא יודע להריץ ישירות מקובץ .ts — הוא דורש קומפילציה עם tsc, ולכן בקורס עד פרק 20 נכתוב את השדות במפורש.

3. static

class Money {
  static readonly CURRENCY = "₪";
  static fromAgorot(agorot: number): Money {
    return new Money(agorot / 100);
  }
  readonly amount: number;
  constructor(amount: number) {
    this.amount = Math.round(amount * 100) / 100;
  }
  toString(): string {
    return `${Money.CURRENCY}${this.amount.toFixed(2)}`;
  }
}
console.log(String(Money.fromAgorot(1990)));
₪19.90

static — שייך למחלקה, לא למופע: Money.CURRENCY, Money.fromAgorot(...). נוח לקבועים ול"מפעלים" (פונקציות שיוצרות מופעים בדרכים שונות). ו־toString() — JavaScript קוראת לה כשממירים את האובייקט למחרוזת.

4. מחלקה או אובייקט פשוט?

מחלקהtype + אובייקט פשוט + פונקציות
יש מצב פנימי שצריך להגן עליו (יתרה, מלאי)נתונים שעוברים בין שכבות (מה שמגיע מ־JSON, מהמסד)
שירות עם תלויות (service, repository)חישובים טהורים
סוגי שגיאותDTOs — אובייקטים שנשלחים ברשת

שים לב: JSON.stringify של מופע לא כולל שדות # ולא מתודות, ו־JSON.parse מחזיר אובייקט פשוט — לא מופע של המחלקה. לכן נתונים שעוברים ברשת או נשמרים — אובייקטים פשוטים. מחלקות — ללוגיקה.
