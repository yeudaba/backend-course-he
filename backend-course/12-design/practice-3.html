P12-E15 · UserService 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

בקובץ 12-design/starter/P12-E15.ts (יש בו User, UserRepository interface, InMemoryUserRepository, ומחלקות שגיאה) השלם UserService שמקבל repository ב־constructor:

  • register({ email, name }) — email מנורמל (trim+lowercase); אם כבר קיים ← ConflictError("האימייל כבר רשום"); id = מספר המשתמשים + 1; מחזיר את המשתמש.
  • getById(id) — או NotFoundError("משתמש", id).
  • rename(id, name) — שם ריק ← ValidationError("name", "שם חובה"); מחזיר את המשתמש המעודכן.

P12-E16 · OrderService עם צילום מחיר 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 3

בקובץ 12-design/starter/P12-E16.ts השלם OrderService, שמקבל ב־constructor { products, orders, now } (שני repositories ושעון). placeOrder(userId, items: { productId, qty }[]):

  • הזמנה ריקה ← ValidationError("items", "הזמנה ריקה").
  • מוצר לא קיים ← NotFoundError("מוצר", id); אין מספיק מלאי ← ConflictError(אין מספיק מלאי למוצר ${id}).
  • הכול או כלום: בדוק את כל הפריטים לפני שמשנים מלאי.
  • שמור הזמנה { id, userId, createdAt: now(), lines: [{ productId, qty, unitPrice }], total } — unitPrice הוא המחיר ברגע ההזמנה (אם המחיר ישתנה אחר כך — ההזמנה לא משתנה).

P12-E17 · repository עם cache (הרכבה) 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

בקובץ 12-design/starter/P12-E17.ts השלם CachedRepository<T> implements Repo<T> — עוטף repository אחר (מקבל אותו ב־constructor):

  • findById — מהזיכרון אם כבר נטען, אחרת מה־inner ושומר (גם תוצאה null נשמרת).
  • save — שומר ב־inner ומעדכן את ה־cache (אחרת יוחזר מידע ישן).
  • getters hits ו־misses.

ה־service שמשתמש בו לא יודע שיש cache בכלל — זה כל העניין.

P12-E28 · דוח הלקוחות הגדולים 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

🔁 חזרה על קיבוץ עם Map (פרק 7), על sort ו־slice (פרק 6) ועל async/await (פרק 10), בתוך service עם repositories מוזרקים (שיעור 3). כתוב וייצא:

export type Order = { id: number; userId: number; total: number; status: "paid" | "cancelled" };
export type User = { id: number; name: string };
export interface OrderRepository { findAll(): Promise<Order[]> }
export interface UserRepository { findByIds(ids: number[]): Promise<User[]> }

ומחלקה ReportService, שה־constructor שלה מקבל (orders: OrderRepository, users: UserRepository), עם מתודה אחת:

async topCustomers(n: number): Promise<{ name: string; total: number }[]>

  • רק הזמנות paid. סוכמים לפי userId.
  • ממיינים מהסכום הגבוה לנמוך. בסכום שווה — לפי userId מהקטן לגדול. לוקחים את ה־n הראשונים.
  • את השמות מביאים בקריאה אחת ל־findByIds, רק עם ה־ids של ה־n שנבחרו. משתמש שלא נמצא — השם "לא ידוע".

הבודק מזריק repositories מזויפים, וסופר כמה פעמים קראת להם.
