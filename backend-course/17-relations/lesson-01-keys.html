1. המבנה של החנות

יחסדוגמהאיך מממשים
אחד־לרביםלקוח ← הרבה הזמנותorders.customer_id מצביע על customers.id. ה־FK תמיד בצד ה"רבים"
רבים־לרביםהזמנה ↔ מוצריםטבלת קישור order_items עם שני FK. המפתח הראשי: הצירוף (order_id, product_id)
אחד־לאחדמשתמש ← פרופילFK עם UNIQUE (נדיר; לרוב פשוט עמודות באותה טבלה)

2. Foreign key

INSERT INTO orders (customer_id, status, created_at) VALUES (99, 'pending', now());
ERROR:  insert or update on table "orders" violates foreign key constraint "orders_customer_id_fkey"
DETAIL:  Key (customer_id)=(99) is not present in table "customers".

REFERENCES customers (id) אומר למסד: "אסור הזמנה של לקוח שלא קיים". בלי זה, באג אחד בקוד ייצור הזמנות "יתומות" שאף שאילתה לא תמצא את הלקוח שלהן.

3. נרמול: כל עובדה במקום אחד

למה products.category_id ולא products.category = 'beans' כמו בפרק 16? כי אם נרצה לשנות את השם ל־"coffee beans" — זו שורה אחת ב־categories, ולא עדכון של כל המוצרים (ואם שכחנו אחד — יש שתי קטגוריות "שונות"). וזה גם מה שמאפשר קטגוריה בלי מוצרים (gift cards).

💡 ומה עם unit_price? זה לא שכפול?

לא. order_items.unit_price הוא המחיר ברגע ההזמנה — עובדה אחרת מ"המחיר היום". בהזמנה 1 (ינואר) Ethiopia נקנה ב־84.90; היום המחיר 89.90. אם הקבלה הייתה מחשבת לפי products.price, כל שינוי מחיר היה משנה רטרואקטיבית הזמנות ישנות — וחשבוניות. זו דרישה מפורשת בפרויקט הדגל.

SELECT oi.order_id, p.name, oi.unit_price AS paid, p.price AS price_today
FROM order_items oi
JOIN products p ON p.id = oi.product_id
WHERE p.id = 1
ORDER BY oi.order_id;

4. ON DELETE

DELETE FROM customers WHERE id = 1;
ERROR:  update or delete on table "customers" violates foreign key constraint "orders_customer_id_fkey" on table "orders"
DETAIL:  Key (id)=(1) is still referenced from table "orders".

ברירת המחדל (RESTRICT/NO ACTION): אי אפשר למחוק לקוח שיש לו הזמנות. וזה טוב — אחרת אבדו נתוני מכירות. האפשרויות:

הגדרהכשמוחקים את ה"הורה"מתאים ל־
(ברירת מחדל)שגיאה, אם יש "ילדים"רוב המקרים: לקוח ← הזמנות
ON DELETE CASCADEהילדים נמחקים איתוחלקים שאין להם קיום בלי ההורה: הזמנה ← פריטי ההזמנה
ON DELETE SET NULLה־FK בילדים הופך ל־NULLקשר לא חובה: משימה ← "מוקצה ל" עובד שעזב
DELETE FROM orders WHERE id = 4;
SELECT COUNT(*) AS items_of_order_4 FROM order_items WHERE order_id = 4;
DELETE 1
 items_of_order_4
------------------
                0
(1 row)

order_items.order_id הוגדר עם ON DELETE CASCADE (ראה store.sql) — מחיקת הזמנה 4 מחקה גם את הפריט שלה. (בפועל, במערכת אמיתית לא מוחקים הזמנות — מסמנים cancelled. אבל העיקרון חשוב.)
