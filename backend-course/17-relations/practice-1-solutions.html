💡 רמז 2

האם מוחקים חבר שיש לו היסטוריית השאלות?

✅ פתרון
  • authors(id, full_name), books(id, title, isbn UNIQUE, published_year)
  • book_authors(book_id → books ON DELETE CASCADE, author_id → authors, PRIMARY KEY (book_id, author_id)) — טבלת קישור. מחיקת ספר מוחקת את הקישורים; מחיקת מחבר שיש לו ספרים — חסומה (ברירת מחדל).
  • members(id, full_name, email UNIQUE, joined_on)
  • loans(id, book_id → books, member_id → members, loaned_at, due_at, returned_at NULL) — שני ה־FK עם ברירת המחדל (RESTRICT): היסטוריית השאלות היא מידע שלא רוצים לאבד, אז אי אפשר למחוק ספר או חבר שיש להם השאלות. (במקום למחוק חבר — מסמנים is_active = false.)

(ואם יש כמה עותקים מאותו ספר? טבלה נוספת copies(id, book_id, barcode), וההשאלה מצביעה על עותק.)

⚠️ טעויות נפוצות
  • books.author_id — מאפשר רק מחבר אחד לספר.
  • ON DELETE CASCADE על loans — מחיקת חבר מוחקת בשקט את כל ההיסטוריה.

P17-E26 · הספרייה מ־P17-E01 — בקוד 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

הסדר חשוב: טבלה שמצביעים עליה נוצרת לפני הטבלה שמצביעה. ‏authors ו־books ← book_authors; ‏members ← loans. ‏FK: ‏book_id integer NOT NULL REFERENCES books (id) ON DELETE CASCADE. בלי ON DELETE, ברירת המחדל חוסמת מחיקה.

💡 רמז 2

מפתח ראשי של זוג נכתב בסוף הטבלה: PRIMARY KEY (book_id, author_id). גם אילוץ על שתי עמודות: CHECK (returned_on >= loaned_on). בשאילתה: שני JOIN (ספרים וחברים) ו־WHERE l.returned_on IS NULL.

✅ פתרון
CREATE TABLE authors (
  id         integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  full_name  text NOT NULL
);

CREATE TABLE books (
  id              integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title           text NOT NULL,
  isbn            text NOT NULL UNIQUE,
  published_year  integer
);

CREATE TABLE book_authors (
  book_id    integer NOT NULL REFERENCES books (id) ON DELETE CASCADE,
  author_id  integer NOT NULL REFERENCES authors (id),
  PRIMARY KEY (book_id, author_id)
);

CREATE TABLE members (
  id         integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  full_name  text NOT NULL,
  email      text NOT NULL UNIQUE
);

CREATE TABLE loans (
  id           integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  book_id      integer NOT NULL REFERENCES books (id),
  member_id    integer NOT NULL REFERENCES members (id),
  loaned_on    date NOT NULL DEFAULT CURRENT_DATE,
  returned_on  date,
  CHECK (returned_on >= loaned_on)
);

ההחלטות מ־P17-E01 נמצאות עכשיו במסד, ולא רק במסמך: ‏ON DELETE CASCADE רק בקישור ספר־מחבר (קישור בלי ספר הוא חסר משמעות), ובכל השאר ברירת המחדל שחוסמת. היסטוריית השאלות היא מידע שלא רוצים לאבד, אז המסד מסרב למחוק ספר או חבר שיש להם השאלות.

CHECK (returned_on >= loaned_on) עובר כש־returned_on הוא NULL, כמו ב־P16-E26: ‏"לא ידוע" אינו "נכשל". כך השאלה פתוחה היא חוקית.

"The Long Queue" מופיע פעמיים ב־book_authors ופעם אחת ב־books. זה כל הרעיון של טבלת קישור. אילו היה books.author_id, היה מקום רק לאחד מהם.

⚠️ טעויות נפוצות
  • ON DELETE CASCADE גם ב־loans — מחיקת חבר מוחקת בשקט את כל ההיסטוריה שלו.
  • id נוסף ב־book_authors בלי PRIMARY KEY (book_id, author_id) — אותו מחבר יכול להיות מקושר לאותו ספר פעמיים.
  • ליצור את loans לפני members — ‏relation "members" does not exist.
  • להכניס ids במפורש ב־INSERT INTO books (id, ...) — עם GENERATED ALWAYS המסד מסרב. סומכים על הסדר: 1, 2, 3.
