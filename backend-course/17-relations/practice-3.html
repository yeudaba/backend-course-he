P17-E04 · WHERE או HAVING?

🧠 הבנהרמה 1⏱ 10 דק׳ידע נדרש: שיעור 3

אילו שאילתות תקינות? לתקינות — מה הן מחזירות במילים.

SELECT status, COUNT(*) FROM orders WHERE COUNT(*) > 2 GROUP BY status;                    -- 1
SELECT status, COUNT(*) FROM orders GROUP BY status HAVING COUNT(*) > 2;                   -- 2
SELECT status, COUNT(*) FROM orders WHERE created_at >= '2026-03-01' GROUP BY status;      -- 3
SELECT status, customer_id, COUNT(*) FROM orders GROUP BY status;                          -- 4
SELECT customer_id, COUNT(*) FROM orders GROUP BY customer_id HAVING status = 'paid';      -- 5

P17-E59 · כינוי ב־WHERE, ב־HAVING וב־ORDER BY

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: שיעור 3

שלוש שאילתות שמשתמשות בכינוי revenue. אילו יעבדו? היעזר בסדר הביצוע מהשיעור.

SELECT o.id, SUM(oi.quantity * oi.unit_price) AS revenue
FROM orders o JOIN order_items oi ON oi.order_id = o.id
WHERE revenue > 300
GROUP BY o.id;

SELECT o.id, SUM(oi.quantity * oi.unit_price) AS revenue
FROM orders o JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.id
HAVING revenue > 300;

SELECT o.id, SUM(oi.quantity * oi.unit_price) AS revenue
FROM orders o JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.id
HAVING SUM(oi.quantity * oi.unit_price) > 300
ORDER BY revenue DESC;

P17-E62 · סכום של כלום אחרי LEFT JOIN

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: שיעור 3

"כמה כל לקוח הוציא" — כולל מי שלא הזמין. מה יופיע אצל אבי ועומר בכל עמודה? איזו עמודה מתאימה למסך באתר?

SELECT c.full_name,
       COUNT(oi.order_id) AS items,
       SUM(oi.quantity * oi.unit_price) AS spent,
       COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS spent_or_zero
FROM customers c
LEFT JOIN orders o       ON o.customer_id = c.id
LEFT JOIN order_items oi ON oi.order_id = o.id
GROUP BY c.id
ORDER BY c.id;

P17-E63 · באיזה חודש נכנסת ההזמנה?

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 13, שיעור 3

הזמנה בחצות וחצי, ב־1 בפברואר, שעון ישראל. ‏date_trunc('month', ...) — "עגל לתחילת החודש" — מחשב לפי אזור הזמן של החיבור. מה יחזיר כל SELECT? ומה זה אומר על "דוח חודשי" ששרת בענן (שרץ ב־UTC) מפיק?

SET timezone = 'Asia/Jerusalem';
SELECT date_trunc('month', timestamptz '2026-02-01 00:30:00+02')::date AS month;
SET timezone = 'UTC';
SELECT date_trunc('month', timestamptz '2026-02-01 00:30:00+02')::date AS month;

🔗 איך זה מתחבר: Date ו־UTC מפרק 13 (שעון אחד בשרת, שעון אחר אצל הלקוח) — והשיעור: GROUP BY לפי חודש (P17-E14).

P17-E64 · ‏?min=300 — מה יכול להשתבש?

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 15, פרק 16, שיעור 3

route לדוח "לקוחות שהוציאו לפחות X":

app.get("/reports/top-customers", async (req, res) => {
  const min = req.query.min;
  const { rows } = await pool.query(
    `SELECT c.full_name, SUM(oi.quantity * oi.unit_price) AS spent
     FROM customers c JOIN orders o ON o.customer_id = c.id JOIN order_items oi ON oi.order_id = o.id
     WHERE o.status <> 'cancelled'
     GROUP BY c.id HAVING SUM(oi.quantity * oi.unit_price) >= ${min}
     ORDER BY spent DESC`);
  res.json(rows);
});
  1. מה יקרה עם ?min=300? עם ?min=abc? בלי min בכלל?
  2. מה יקרה עם ?min=0 OR true? ועם ?min=0; DROP TABLE orders?
  3. תקן: Zod (פרק 15) ופרמטר (פרק 16). האם אפשר להשתמש ב־$1 בתוך HAVING?

🔗 איך זה מתחבר: query string ו־Zod מפרק 15, פרמטרים ו־SQL injection מפרק 16 — והשיעור: HAVING הוא עוד מקום בשאילתה שבו ערך מהמשתמש נכנס.

P17-E65 · ממוצע עם 16 ספרות

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 2, פרק 16, שיעור 3

מה יחזיר AVG על עמודת numeric(10,2)? ומה יקרה ב־Node, שבו pg מחזיר numeric כמחרוזת (פרק 16), לשורה row.avg_price.toFixed(2)? איפה הכי נכון לעגל?

SELECT cat.name AS category, AVG(p.price) AS avg_price, ROUND(AVG(p.price), 2) AS avg_rounded
FROM products p JOIN categories cat ON cat.id = p.category_id
GROUP BY cat.name
ORDER BY cat.name;

🔗 איך זה מתחבר: מספרים, toFixed ועיגול מפרק 2, ‏numeric כמחרוזת ב־pg מפרק 16 — והשיעור: צבירה לכל קבוצה.

P17-E66 · הכנסה לפי קטגוריה בטווח תאריכים 🤖

export type Db = { query(text: string, values?: unknown[]): Promise<{ rows: any[] }> };
export type CategoryRevenue = { category: string; units: number; revenue: number };

  • רק הזמנות שלא בוטלו, עם created_at >= from ו־created_at < to (‏from/to — מחרוזות "2026-03-01").

P17-E67 · דוח עם קיבוץ לבחירה 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: פרק 3, פרק 15, פרק 16, שיעור 3

GET /reports/orders?by=city&minOrders=2 — המשתמש בוחר לפי מה לקבץ. שם עמודה אי אפשר להעביר כפרמטר ($1 הוא ערך), אז בונים את השאילתה מרשימה סגורה. בקובץ 17-relations/starter/P17-E67.ts כתוב וייצא:

export const ReportQuery = z.object({ /* by, minOrders */ });
export function buildReport(query: unknown): { text: string; values: unknown[] }
  • ReportQuery (Zod): ‏by — אחד מ־"city", ‏"status", ‏"month". ‏minOrders — מספר שלם ≥ 1, מגיע כמחרוזת מה־URL (z.coerce), ברירת מחדל 1.
  • buildReport מפעילה ReportQuery.parse (קלט לא תקין ← ZodError נזרק), ומחזירה שאילתה שמחזירה שתי עמודות: key (טקסט) ו־orders (כמה הזמנות — כל ההזמנות, כולל מבוטלות), רק קבוצות עם orders >= minOrders, לפי orders מהגבוה ואז key.
  • ה־key: ‏city ← COALESCE(c.city, 'unknown'); ‏status ← o.status; ‏month ← date_trunc('month', o.created_at)::date::text. ‏minOrders — כפרמטר.
