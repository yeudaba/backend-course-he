P16-E04 · NULL בפועל 🧠 הבנה רמה 1

💡 רמז 1

כל השוואה עם NULL ← NULL. psql מציג NULL כתא ריק.

💡 רמז 2

יש 12 לקוחות: 3 בחיפה ו־2 בלי עיר.

✅ פתרון
SELECT NULL = NULL AS q1, NULL IS NULL AS q2, 10 + NULL AS q3, COALESCE(NULL, NULL, 'x', 'y') AS q4;
SELECT COUNT(city) AS q5_city, COUNT(*) AS q5_all FROM customers;
SELECT COUNT(*) AS q6 FROM customers WHERE city <> 'Haifa';
 q1 | q2 | q3 | q4
----+----+----+----
    | t  |    | x
(1 row)

 q5_city | q5_all
---------+--------
      10 |     12
(1 row)

 q6
----
  7
(1 row)

שאלה 6 היא המלכודת: 12 לקוחות, 3 בחיפה — אבל התשובה 7, לא 9. שני הלקוחות בלי עיר "נבלעו", כי NULL <> 'Haifa' הוא NULL.

⚠️ טעויות נפוצות
  • לחשוב ש־NULL "שונה מחיפה" — הוא לא ידוע.

P16-E58 · NOT IN עם NULL ברשימה 🧠 הבנה רמה 2

💡 רמז 1

x IN (a, b) = x = a OR x = b. ‏x NOT IN (a, b) = x <> a AND x <> b.

💡 רמז 2

x <> NULL הוא NULL — ו־true AND NULL הוא NULL (טבלה בשיעור).

✅ פתרון
SELECT COUNT(*) FROM customers WHERE city IN ('Haifa', NULL);
SELECT COUNT(*) FROM customers WHERE city NOT IN ('Haifa');
SELECT COUNT(*) FROM customers WHERE city NOT IN ('Haifa', NULL);
SELECT COUNT(*) FROM customers WHERE city IS DISTINCT FROM 'Haifa';
 count
-------
     3
(1 row)

 count
-------
     7
(1 row)

 count
-------
     0
(1 row)

 count
-------
     9
(1 row)

שאילתה 3 מחזירה אפס: לכל לקוח, ‏city <> NULL הוא NULL, וכל ה־AND הופך ל־NULL. NULL אחד ברשימה של NOT IN "מוחק" את כל התוצאה. זה קורה במציאות כשהרשימה מגיעה משאילתה אחרת (פרק 17) שיש בה NULL. ושאילתה 2 מפספסת את שני הלקוחות בלי עיר — 4 מכסה גם אותם.

⚠️ טעויות נפוצות
  • לבנות NOT IN (...) מרשימה שמגיעה מהמשתמש, בלי לסנן null ממנה.

P16-E59 · ממוצע שמתעלם מ־NULL 🧠 הבנה רמה 2

💡 רמז 1

כל הצבירות חוץ מ־COUNT(*) מתעלמות מ־NULL — כאילו השורה לא קיימת.

💡 רמז 2

COALESCE(x, 0) הופך את ה־NULL ל־0 — ועכשיו הוא "קיים". ו־30 / 3 של שלמים?

✅ פתרון
SELECT COUNT(*) AS all_rows, COUNT(x) AS with_x, SUM(x) AS sum_x,
       AVG(x) AS avg_x, AVG(COALESCE(x, 0)) AS avg_zero, SUM(x) / COUNT(*) AS sum_div_all
FROM (VALUES (10), (NULL), (20)) AS t(x);
 all_rows | with_x | sum_x |        avg_x        |      avg_zero       | sum_div_all
----------+--------+-------+---------------------+---------------------+-------------
        3 |      2 |    30 | 15.0000000000000000 | 10.0000000000000000 |          10
(1 row)

שני ממוצעים, שתי שאלות שונות: AVG(x) = "הממוצע של מי שדירג" (15); ‏AVG(COALESCE(x, 0)) = "הממוצע כשמי שלא דירג נחשב 0" (10). אין תשובה "נכונה" — צריך להחליט מה המשמעות של NULL בעמודה. ו־SUM / COUNT(*) הוא עוד דרך להגיע ל־10 (ושוב: חילוק שלמים).

⚠️ טעויות נפוצות
  • לשים COALESCE(..., 0) "ליתר ביטחון" על כל עמודה בממוצע — זה משנה את התשובה, לא רק "מגן" עליה.

P16-E60 · צבירה על אפס שורות 🧠 הבנה רמה 2

💡 רמז 1

צבירה מחזירה תמיד שורה אחת — גם כשאין שורות לצבור.

💡 רמז 2

"סכום של כלום" — 0 או NULL? ב־SQL: NULL. רק COUNT מחזיר 0.

✅ פתרון
SELECT COUNT(*) AS n, SUM(stock) AS units, MAX(price) AS max_price, AVG(price) AS avg_price,
       COALESCE(SUM(stock), 0) AS units_or_zero
FROM products
WHERE category = 'tea';
 n | units | max_price | avg_price | units_or_zero
---+-------+-----------+-----------+---------------
 0 |       |           |           |             0
(1 row)

COUNT הוא 0, וכל השאר NULL. ב־Node זה מגיע כ־null — ו־units.toFixed() קורס, או ש־total + units הופך ל־total + null. לכן לסכומים שמוצגים או מחושבים: COALESCE(SUM(...), 0).

⚠️ טעויות נפוצות
  • לבדוק rows.length === 0 כדי לדעת "אין נתונים" בשאילתת צבירה — תמיד יש שורה אחת.

P16-E61 · עמודה רגילה ליד צבירה 🧠 הבנה רמה 2

💡 רמז 1

MAX הופך 14 שורות לשורה אחת. מאיזו מהן המסד אמור לקחת את name?

💡 רמז 2

"היקר ביותר" = למיין לפי מחיר ולקחת את הראשון (שיעור 2).

✅ פתרון
SELECT name, MAX(price) FROM products;
ERROR:  column "products.name" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: SELECT name, MAX(price) FROM products;
               ^
SELECT name, price FROM products ORDER BY price DESC, id LIMIT 1;
SELECT MAX(price) AS max_price, MIN(price) AS min_price, COUNT(*) AS n FROM products;
         name         | price
----------------------+--------
 Electric Grinder Pro | 649.00
(1 row)

 max_price | min_price | n
-----------+-----------+----
    649.00 |     19.90 | 14
(1 row)

PostgreSQL מסרב: עמודה רגילה ליד צבירה חייבת להיות ב־GROUP BY (פרק 17), אחרת לא ברור מאיזו שורה לקחת אותה. ("היו צריכים לקחת את השם של המקסימום" — אבל מה אם יש שני מוצרים באותו מחיר? ומה עם MIN באותה שאילתה?) ל"השורה עם הערך הגבוה" — ORDER BY ... LIMIT 1. לצבירות "נקיות" — רק צבירות ב־SELECT.

⚠️ טעויות נפוצות
  • להניח שזה יעבוד כי "ב־MySQL זה עבד" — שם, במצב ישן, המסד בוחר שם אקראי. PostgreSQL מעדיף שגיאה על תשובה שגויה (נראה ביחידה 25.5).

P16-E62 · NULL במיון 🧠 הבנה רמה 2

💡 רמז 1

ב־PostgreSQL, NULL נחשב "גדול מכל ערך" במיון: בסוף ב־ASC, בהתחלה ב־DESC.

💡 רמז 2

NULLS FIRST / NULLS LAST קובעים במפורש. ו־ORDER BY 2 = "לפי העמודה השנייה ב־SELECT".

✅ פתרון
SELECT full_name, city FROM customers ORDER BY city, id LIMIT 3;
SELECT full_name, city FROM customers ORDER BY city DESC, id LIMIT 3;
SELECT full_name, city FROM customers ORDER BY city NULLS FIRST, id LIMIT 3;
SELECT full_name, COALESCE(city, 'zzz') AS city FROM customers ORDER BY 2, id LIMIT 3;
  full_name  |    city
-------------+------------
 Ron Avraham | Beer Sheva
 Yossi Cohen | Haifa
 Shira David | Haifa
(3 rows)

  full_name  |   city
-------------+----------
 Avi Peretz  |
 Omer Shalom |
 Dana Levi   | Tel Aviv
(3 rows)

  full_name  |    city
-------------+------------
 Avi Peretz  |
 Omer Shalom |
 Ron Avraham | Beer Sheva
(3 rows)

  full_name  |    city
-------------+------------
 Ron Avraham | Beer Sheva
 Yossi Cohen | Haifa
 Shira David | Haifa
(3 rows)

"מיון לפי עיר, יורד" שם את מי שאין לו עיר ראשון — כנראה לא מה שהמשתמש רצה לראות בראש הרשימה. כשמיון של עמודה שיכולה להיות NULL חשוב למשתמש — מחליטים במפורש (NULLS LAST). (ושים לב: מסדים אחרים — MySQL למשל — מסדרים NULL הפוך. עוד סיבה להיות מפורש.)

⚠️ טעויות נפוצות
  • "לפתור" עם COALESCE(city, 'zzz') — עובד, עד שתהיה עיר שמתחילה ב־zzz, או מיון בעברית.

 products | stock_value

P16-E15 · דוח קטגוריה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

"כמה עם מלאי 0" — COUNT סופר שורות שאינן NULL. איך הופכים תנאי לערך שהוא NULL כשהתנאי לא מתקיים?

💡 רמז 2

COUNT(*) FILTER (WHERE stock = 0) — תחביר של PostgreSQL בדיוק לזה.

✅ פתרון
SELECT
  COUNT(*) AS products,
  MIN(price) AS min_price,
  MAX(price) AS max_price,
  ROUND(AVG(price), 2) AS avg_price,
  COUNT(*) FILTER (WHERE stock = 0) AS out_of_stock
FROM products
WHERE category = 'brewing';
 products | min_price | max_price | avg_price | out_of_stock
----------+-----------+-----------+-----------+--------------
        4 |     99.00 |    229.00 |    149.00 |            1
(1 row)

FILTER הוא דרך נוחה לספור כמה תנאים בשאילתה אחת. (בלעדיו: SUM(CASE WHEN stock = 0 THEN 1 ELSE 0 END) — תראה את זה בקוד ישן.)

⚠️ טעויות נפוצות
  • להוסיף AND stock = 0 ל־WHERE — כל שאר הצבירות יחושבו רק על המוצרים שאזלו.

P16-E64 · פרופיל של טבלת הלקוחות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

COUNT(*) - COUNT(phone) — כל השורות פחות אלה שיש בהן טלפון.

💡 רמז 2

MIN ו־MAX עובדים גם על תאריכים. ‏COUNT(DISTINCT city) — בלי NULL.

✅ פתרון
SELECT
  COUNT(*)                AS customers,
  COUNT(phone)            AS with_phone,
  COUNT(*) - COUNT(phone) AS without_phone,
  COUNT(DISTINCT city)    AS cities,
  MIN(joined_on)          AS first_joined,
  MAX(joined_on)          AS last_joined
FROM customers;
 customers | with_phone | without_phone | cities | first_joined | last_joined
-----------+------------+---------------+--------+--------------+-------------
        12 |          8 |             4 |      5 | 2025-11-02   | 2026-09-14
(1 row)

שאילתת "פרופיל" כזו היא הדבר הראשון שכדאי להריץ על טבלה שלא מכירים: כמה שורות, כמה ריקות בכל עמודה, טווח תאריכים. היא מגלה מהר נתונים חסרים או מוזרים.

⚠️ טעויות נפוצות
  • COUNT(phone IS NULL) — סופר את כל השורות (הביטוי הוא true או false, אף פעם לא NULL).

P16-E65 · סיכום של פולי הקפה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

MAX(price) - MIN(price) — אפשר לחשב עם תוצאות של צבירות.

💡 רמז 2

SUM(price * stock) — הכפל קורה לכל שורה, ואז הסכום.

✅ פתרון
SELECT
  COUNT(*)                   AS products,
  SUM(stock)                 AS units,
  ROUND(AVG(price), 2)       AS avg_price,
  MAX(price) - MIN(price)    AS price_range,
  SUM(price * stock)         AS stock_value
FROM products
WHERE category = 'beans' AND is_active;
 products | units | avg_price | price_range | stock_value
----------+-------+-----------+-------------+-------------
        3 |   160 |     68.23 |       60.00 |     7184.00
(1 row)

SUM(price * stock) שונה מ־SUM(price) * SUM(stock) — הראשון "כמה שווה המלאי", השני מספר חסר משמעות. ה־Espresso Blend הלא פעיל לא נספר בשום עמודה, כי ה־WHERE רץ לפני הצבירה.

⚠️ טעויות נפוצות
  • AVG(price) * SUM(stock) כ"שווי מלאי" — מוצר זול עם מלאי גדול מעוות את התוצאה.

P16-E66 · כל מי שלא מחיפה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

שתי דרכים לתנאי: city IS DISTINCT FROM 'Haifa', או city <> 'Haifa' OR city IS NULL.

💡 רמז 2

אפשר לתת לעמודה המחושבת את השם city — ה־WHERE עדיין רואה את העמודה המקורית (שיעור 2, סדר הביצוע).

✅ פתרון
SELECT id, full_name, COALESCE(city, 'unknown') AS city
FROM customers
WHERE city IS DISTINCT FROM 'Haifa'
ORDER BY id;
 id |  full_name   |    city
----+--------------+------------
  1 | Dana Levi    | Tel Aviv
  3 | Noa Mizrahi  | Jerusalem
  4 | Avi Peretz   | unknown
  5 | Michal Biton | Tel Aviv
  6 | Ron Avraham  | Beer Sheva
  8 | Omer Shalom  | unknown
  9 | Tamar Gabay  | Jerusalem
 10 | Itay Hadad   | Tel Aviv
 11 | lior katz    | Ramat Gan
(9 rows)

9 לקוחות: 12 פחות 3 מחיפה. עם city <> 'Haifa' לבד היו יוצאים 7 — שני "unknown" נעלמים בשקט (P16-E04, שורה 6).

⚠️ טעויות נפוצות
  • לכתוב את ה־COALESCE בתוך ה־WHERE (COALESCE(city, '') <> 'Haifa') — עובד, אבל מסתיר את הכוונה, ומונע שימוש ב־index (פרק 18).

P16-E67 · null ב־JavaScript מול NULL ב־SQL 🧠 הבנה רמה 2

💡 רמז 1

ב־JavaScript, null בחשבון הופך ל־0; בשרשור מחרוזות — ל־"null".

💡 רמז 2

ב־SQL, ‏NULL "מדביק": כל חשבון והשוואה איתו נותנים NULL. ‏GREATEST הוא יוצא דופן — הוא מתעלם מ־NULL.

✅ פתרון
console.log(null === null, null == undefined, null + 5, null > 0, null >= 0);
console.log([null, 5].includes(null), "a" + null, Math.max(3, null));
true true 5 false true
true anull 3
SELECT NULL = NULL AS eq, NULL + 5 AS plus, NULL > 0 AS gt, 'a' || NULL AS concat, GREATEST(3, NULL) AS greatest;
 eq | plus | gt | concat | greatest
----+------+----+--------+----------
    |      |    |        |        3
(1 row)

ב־JavaScript, null הוא ערך שמומר בשקט (ל־0, ל־"null") — ולכן null >= 0 הוא true ו־null + 5 הוא 5. ב־SQL הוא "לא ידוע", והתוצאה נשארת לא ידועה (ריק בטבלה = NULL). כשנתונים עוברים בין העולמות (פרק 18), אותה עמודה יכולה להתנהג אחרת ב־WHERE וב־filter.

⚠️ טעויות נפוצות
  • "לתקן" ב־JavaScript חישוב שנתן NULL במסד — הבעיה היא שחסר ערך, לא שהחשבון שגוי.

P16-E68 · מה pg מחזיר מ־COUNT ו־SUM? 🧠 הבנה רמה 2

💡 רמז 1

COUNT ו־SUM של integer מחזירים bigint — מספר שלם עד ‎9×10¹⁸. כמה ספרות JavaScript שומר בדיוק?

💡 רמז 2

numeric יכול להכיל ספרות רבות אחרי הנקודה — יותר ממה ש־number מחזיק.

✅ פתרון
  1. COUNT/SUM מחזירים bigint, ו־number שומר בדיוק רק עד ‎2⁵³ (בערך 9×10¹⁵). כדי לא להחזיר מספר שגוי בשקט, pg מחזיר מחרוזת. 7 הוא integer רגיל — נכנס ב־number.
  2. אותה סיבה: numeric מדויק, ו־number לא (0.1 + 0.2). ‏float8 (f) כבר "לא מדויק" במסד, ולכן הוא מגיע כ־number.
  3. JSON: "n":"2" — הלקוח מקבל מחרוזת. ‏n + 1 ← "21".
  4. ממירים במפורש איפה שבטוח: Number(row.n), או בשאילתה COUNT(*)::int. לכסף — להשאיר מחרוזת או לעבור לאגורות (P16-E56, ‏P16-E70).
⚠️ טעויות נפוצות
  • להגדיר ל־pg "תמיד להמיר bigint ל־number" גלובלית — עובד, עד שמזהה גדול מ־2⁵³ מאבד ספרות בלי שגיאה.

P16-E69 · reduce מול SUM ו־AVG 🧠 הבנה רמה 2

💡 רמז 1

0 + 10 + null + 20 — ‏null הופך ל־0 בחשבון.

💡 רמז 2

על מערך ריק: Math.max() הוא -Infinity, ו־0 / 0 הוא NaN.

✅ פתרון

ה"ממוצע" הנאיבי ב־JavaScript הוא 10 — כמו AVG(COALESCE(x, 0)), לא כמו AVG(x). כדי לקבל את ההתנהגות של SQL צריך filter קודם. ועל אפס ערכים, SQL מחזיר NULL (ברור: "אין"), ו־JavaScript מחזיר 0, ‏-Infinity ו־NaN — שלושה ערכים שנראים כמו מספרים. ב־P16-E71 תכתוב צבירות ב־JavaScript שמתנהגות כמו במסד.

⚠️ טעויות נפוצות
  • לחשב ממוצע עם sum / arr.length על נתונים שיש בהם null — המכנה כולל את מי שלא דירג.

P16-E28 · אזור לכל לקוח (CASE כמו switch) 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

בצורה הקצרה כל WHEN הוא ערך אחד, כמו case ב־JavaScript. לשתי ערים של אותו אזור כותבים שני WHEN (ב־PostgreSQL אין WHEN 'a', 'b'). ‏contact: ‏COALESCE(phone, email).

ל־NULL אין WHEN: ‏CASE city WHEN NULL משווה עם =, ו־NULL = NULL אינו true. ה־ELSE תופס גם אותו.

💡 רמז 2

מיון בסדר משלך: CASE נוסף בתוך ORDER BY, שהופך כל אזור למספר: ORDER BY CASE region WHEN 'center' THEN 1 WHEN 'north' THEN 2 ... END, full_name. ב־ORDER BY מותר להשתמש בכינוי region, אבל רק כשהוא עומד לבד. בתוך ביטוי (כמו CASE) הכינוי לא מוכר, וצריך לחזור על הביטוי של העיר.

✅ פתרון
SELECT
  full_name,
  CASE city
    WHEN 'Tel Aviv' THEN 'center'
    WHEN 'Ramat Gan' THEN 'center'
    WHEN 'Haifa' THEN 'north'
    WHEN 'Jerusalem' THEN 'jerusalem'
    WHEN 'Beer Sheva' THEN 'south'
    ELSE 'unknown'
  END AS region,
  COALESCE(phone, email) AS contact
FROM customers
ORDER BY
  CASE city
    WHEN 'Tel Aviv' THEN 1
    WHEN 'Ramat Gan' THEN 1
    WHEN 'Haifa' THEN 2
    WHEN 'Jerusalem' THEN 3
    WHEN 'Beer Sheva' THEN 4
    ELSE 5
  END,
  full_name;

שני ה־CASE הם switch לכל דבר: ערך אחד מושווה לרשימת קבועים, ו־ELSE הוא ה־default. הראשון מתרגם עיר לשם אזור, והשני מתרגם עיר למקום בתור. ב־ORDER BY חוזרים על city ולא כותבים CASE region, כי כינוי מה־SELECT לא מוכר בתוך ביטוי.

Omer ו־Avi בלי עיר, והם בסוף, ב־unknown. ה־ELSE תפס אותם, כמו ב־P16-E21: השוואה ל־NULL אף פעם לא "נכונה".

סדר מיון "עסקי" (לא א״ב ולא מספרי) הוא מקום טבעי ל־CASE בתוך ORDER BY. בפרויקטים גדולים שומרים אותו בעמודה בטבלה (regions.sort_order), ואז ה־CASE נעלם — נראה טבלאות קשורות בפרק 17.

⚠️ טעויות נפוצות
  • ORDER BY region — מיון לפי א״ב: ‏center, jerusalem, north, south, unknown.
  • WHEN NULL THEN 'unknown' בלי ELSE — הלקוחות בלי עיר מקבלים NULL ולא 'unknown'.
  • ORDER BY CASE region WHEN ... — ‏column "region" does not exist: בתוך ביטוי ב־ORDER BY אי אפשר להשתמש בכינוי.
  • COALESCE(email, phone) — הסדר הפוך, וכולם מקבלים אימייל.

P16-E70 · דוח מלאי מ־Node 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

בשאילתה: COUNT(*)::int, ‏COALESCE(SUM(stock), 0)::int, ‏ROUND(AVG(price), 2).

💡 רמז 2

בקוד: const num = (v: string | null) => (v === null ? null : Number(v));

✅ פתרון
// P16-E70: דוח מלאי מ־Node
export type Db = { query(text: string, values?: unknown[]): Promise<{ rows: any[] }> };
export type Report = { products: number; units: number; cheapest: number | null; priciest: number | null; avgPrice: number | null };

const num = (v: string | number | null) => (v === null ? null : Number(v));

export async function inventoryReport(client: Db, category?: string): Promise<Report> {
  const values: unknown[] = [];
  let where = "is_active";
  if (category !== undefined) {
    values.push(category);
    where += " AND category = $1";
  }
  const { rows } = await client.query(
    `SELECT COUNT(*)::int AS products, COALESCE(SUM(stock), 0)::int AS units,
            MIN(price) AS cheapest, MAX(price) AS priciest, ROUND(AVG(price), 2) AS avg_price
     FROM products WHERE ${where}`,
    values,
  );
  const r = rows[0];
  return { products: r.products, units: r.units, cheapest: num(r.cheapest), priciest: num(r.priciest), avgPrice: num(r.avg_price) };
}

שני כלים לטיפוסים: ::int בתוך השאילתה (כשבטוח שהמספר קטן), ו־Number() בקוד עם טיפול ב־null. השאילתה עצמה כמעט זהה לזו שבשיעור — ההבדל הוא כל מה שקורה בדרך מהמסד ל־JavaScript.

⚠️ טעויות נפוצות
  • Number(r.cheapest) בלי לבדוק null — ‏Number(null) הוא 0, ו"המוצר הזול ביותר" בקטגוריה ריקה עולה 0.

P16-E71 · צבירות ב־JavaScript שמתנהגות כמו SQL 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

const values = rows.map((r) => r[column]).filter((v) => v !== null && v !== undefined); — והכול מחושב מ־values.

💡 רמז 2

min/max בלולאה עם < — עובד גם למספרים וגם למחרוזות (בניגוד ל־Math.min).

✅ פתרון
// P16-E71: צבירות ב־JavaScript שמתנהגות כמו SQL
type Row = Record<string, unknown>;
type Value = number | string;

export function aggregate(rows: Row[], column: string) {
  const values = rows.map((r) => r[column]).filter((v) => v !== null && v !== undefined) as Value[];
  if (values.length === 0) return { count: 0, countAll: rows.length, sum: null, avg: null, min: null, max: null };
  let min = values[0];
  let max = values[0];
  for (const v of values) {
    if (v < min) min = v;
    if (v > max) max = v;
  }
  const numbers = values as number[];
  const sum = typeof values[0] === "number" ? numbers.reduce((s, x) => s + x, 0) : null;
  return { count: values.length, countAll: rows.length, sum, avg: sum === null ? null : sum / values.length, min, max };
}

console.log(aggregate([], "x"));

בעמודת מחרוזות (תאריכים) sum ו־avg הם null — גם SQL לא יסכם טקסט (הוא יחזיר שגיאה). העיקר: הממוצע 15 (לא 10), ואפס ערכים נותן null — ולא אחד משלושת ה"מספרים" המטעים של P16-E69.

⚠️ טעויות נפוצות
  • Math.min(...values) על תאריכים — NaN; ועל מערך ריק — Infinity.
