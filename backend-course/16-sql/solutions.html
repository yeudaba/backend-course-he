P16-E01 · איזה טיפוס? רמה 1

💡 רמז 1

טלפון הוא מספר? האם עושים עליו חשבון?

💡 רמז 2

"מתי נוצרה" = רגע בזמן. "תאריך משלוח" = יום.

✅ פתרון
  1. integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY (או bigint אם מצפים למיליארדים)
  2. numeric(10, 2) NOT NULL CHECK (total >= 0) — לא float
  3. integer NOT NULL CHECK (quantity > 0)
  4. text — מספר טלפון הוא מחרוזת: אפס מוביל (050...), מקפים, +972. לא עושים עליו חשבון.
  5. text (nullable), אולי CHECK (length(notes) <= 1000)
  6. timestamptz NOT NULL DEFAULT now()
  7. date
  8. boolean NOT NULL DEFAULT false
  9. text NOT NULL DEFAULT 'new' CHECK (status IN ('new', 'shipped', 'cancelled')) (בהמשך נכיר גם enum)
⚠️ טעויות נפוצות
  • טלפון כ־integer — 050 הופך ל־50, ו־+972 בכלל לא נכנס.

P16-E03 · מה נכשל? רמה 1

💡 רמז 1

סדר הביצוע: FROM ← WHERE ← SELECT ← ORDER BY.

💡 רמז 2

מה ההבדל בין ' ל־" ב־SQL?

✅ פתרון
  1. ✔ — ORDER BY רץ אחרי SELECT, ומכיר את הכינוי.
  2. ✘ column "with_vat" does not exist — WHERE רץ לפני SELECT. צריך לחזור על הביטוי: WHERE price * 1.17 > 100.
  3. ✘ column "beans" does not exist — מירכאות כפולות הן שם עמודה. מחרוזת: 'beans'.
  4. ✔ — המוצרים במקומות 4–6 לפי מחיר (עמוד 2 של 3).
  5. ✔ — אבל כנראה לא מה שרצית: DISTINCT חל על כל העמודות יחד, וכל צירוף category+name הוא ייחודי — חוזרים כל 14 המוצרים.
⚠️ טעויות נפוצות
  • לחשוב ש־DISTINCT category, name הוא "DISTINCT על category ועוד name".

P16-E05 · מה הפקודה עושה? רמה 1

💡 רמז 1

חפש WHERE חסר, ו־WHERE שתופס יותר ממה שנראה.

💡 רמז 2

3 ו־4 נראים כמעט אותו דבר.

✅ פתרון
  1. ⚠️ מאפס את המלאי של כל המוצרים — אין WHERE.
  2. מאפס מלאי של מוצר 7 בלבד.
  3. לא מוחק כלום (= NULL אף פעם לא true). לא מסוכן — אבל באג: מי שכתב התכוון ל־4.
  4. מוחק את הלקוחות בלי עיר (Avi, Omer).
  5. ⚠️ הנחה ל־beans וגם לכל המוצרים הפעילים — OR רחב מדי. כנראה התכוון ל־AND.
  6. ⚠️⚠️ מוחק את הטבלה עם כל הנתונים. אין undo.

ההרגל: לפני UPDATE/DELETE — הרץ SELECT COUNT(*) עם אותו WHERE.

⚠️ טעויות נפוצות
  • להסתכל רק על הפקודה ולא לשאול "כמה שורות זה יתפוס?".

P16-E15 · דוח קטגוריה 🤖 רמה 3

💡 רמז 1

"כמה עם מלאי 0" — COUNT סופר שורות שאינן NULL. איך הופכים תנאי לערך שהוא NULL כשהתנאי לא מתקיים?

💡 רמז 2

COUNT(*) FILTER (WHERE stock = 0) — תחביר של PostgreSQL בדיוק לזה.

✅ פתרון
SELECT
  COUNT(*) AS products,
  MIN(price) AS min_price,
  MAX(price) AS max_price,
  ROUND(AVG(price), 2) AS avg_price,
  COUNT(*) FILTER (WHERE stock = 0) AS out_of_stock
FROM products
WHERE category = 'brewing';
 products | min_price | max_price | avg_price | out_of_stock
----------+-----------+-----------+-----------+--------------
        4 |     99.00 |    229.00 |    149.00 |            1
(1 row)

FILTER הוא דרך נוחה לספור כמה תנאים בשאילתה אחת. (בלעדיו: SUM(CASE WHEN stock = 0 THEN 1 ELSE 0 END) — תראה את זה בקוד ישן.)

⚠️ טעויות נפוצות
  • להוסיף AND stock = 0 ל־WHERE — כל שאר הצבירות יחושבו רק על המוצרים שאזלו.

P16-E16 · טבלת ביקורות 🤖 רמה 3

💡 רמז 1

אילוץ על שתי עמודות יחד: בסוף ההגדרה, UNIQUE (product_id, author_email).

💡 רמז 2

CHECK (rating BETWEEN 1 AND 5), CHECK (length(comment) <= 500) — ו־CHECK על NULL עובר (NULL לא "נכשל").

✅ פתרון
CREATE TABLE reviews (
  id            integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  product_id    integer NOT NULL,
  rating        smallint NOT NULL CHECK (rating BETWEEN 1 AND 5),
  comment       text CHECK (length(comment) <= 500),
  author_email  text NOT NULL,
  created_at    timestamptz NOT NULL DEFAULT now(),
  UNIQUE (product_id, author_email)
);

(product_id אמור להצביע על מוצר קיים — זה foreign key, הנושא הראשון של פרק 17.)

⚠️ טעויות נפוצות
  • product_id integer UNIQUE ו־author_email text UNIQUE בנפרד — אז מחבר יכול לכתוב רק ביקורת אחת בכלל, ולכל מוצר רק ביקורת אחת.

P16-E24 · אתגר: טבלת קופונים 🤖 רמה 5

💡 רמז 1

תבנית: CHECK (code ~ '^[A-Z0-9]{4,20}$') (~ = התאמה ל־regex).

💡 רמז 2

"בדיוק אחד": CHECK (num_nonnulls(percent_off, amount_off) = 1). ו־uses <= max_uses כשהוא NULL — CHECK עם NULL עובר.

✅ פתרון
CREATE TABLE coupons (
  id           integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  code         text NOT NULL UNIQUE CHECK (code ~ '^[A-Z0-9]{4,20}$'),
  percent_off  smallint CHECK (percent_off BETWEEN 1 AND 90),
  amount_off   numeric(10, 2) CHECK (amount_off > 0),
  valid_from   date NOT NULL,
  valid_until  date NOT NULL,
  max_uses     integer CHECK (max_uses > 0),
  uses         integer NOT NULL DEFAULT 0 CHECK (uses >= 0),
  CHECK (num_nonnulls(percent_off, amount_off) = 1),
  CHECK (valid_until > valid_from),
  CHECK (uses <= max_uses)
);
CREATE TABLE

שים לב לאילוצים בסוף הטבלה — אילוץ שמערב כמה עמודות כותבים כך. ומה יקרה כש־uses יגיע ל־max_uses ושני לקוחות ינסו לממש את הקופון האחרון באותו רגע? ה־CHECK יציל אחד מהם — נראה איך בפרק 18.

⚠️ טעויות נפוצות
  • CHECK (percent_off IS NOT NULL OR amount_off IS NOT NULL) — "לפחות אחד", לא "בדיוק אחד".

P16-E25 · אתגר: מחירון עם תוויות 🤖 רמה 5

💡 רמז 1

CASE WHEN price < 50 THEN 'basic' WHEN price <= 150 THEN 'standard' ELSE 'premium' END AS tier — התנאי הראשון שמתקיים מנצח.

💡 רמז 2

בגלל "הראשון מנצח", סדר ה־WHEN חשוב: stock = 0 לפני stock < 10.

✅ פתרון
SELECT
  name,
  price,
  ROUND(price * 1.18, 2) AS price_with_vat,
  CASE
    WHEN price < 50 THEN 'basic'
    WHEN price <= 150 THEN 'standard'
    ELSE 'premium'
  END AS tier,
  CASE
    WHEN stock = 0 THEN 'out of stock'
    WHEN stock < 10 THEN 'last units'
    ELSE 'in stock'
  END AS availability
FROM products
WHERE is_active
ORDER BY price, name;
