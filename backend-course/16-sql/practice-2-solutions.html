P16-E03 · מה נכשל? 🧠 הבנה רמה 1

💡 רמז 1

סדר הביצוע: FROM ← WHERE ← SELECT ← ORDER BY.

💡 רמז 2

מה ההבדל בין ' ל־" ב־SQL?

✅ פתרון
  1. ✔ — ORDER BY רץ אחרי SELECT, ומכיר את הכינוי.
  2. ✘ column "with_vat" does not exist — WHERE רץ לפני SELECT. צריך לחזור על הביטוי: WHERE price * 1.17 > 100.
  3. ✘ column "beans" does not exist — מירכאות כפולות הן שם עמודה. מחרוזת: 'beans'.
  4. ✔ — המוצרים במקומות 4–6 לפי מחיר (עמוד 2 של 3).
  5. ✔ — אבל כנראה לא מה שרצית: DISTINCT חל על כל העמודות יחד, וכל צירוף category+name הוא ייחודי — חוזרים כל 14 המוצרים.
⚠️ טעויות נפוצות
  • לחשוב ש־DISTINCT category, name הוא "DISTINCT על category ועוד name".

P16-E27 · בונה שאילתות עם פרמטרים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני מערכים: conditions = ["is_active"] ו־values = []. פונקציית עזר קטנה: const param = (value) => { values.push(value); return $${values.length}; }. כך המספר תמיד מתאים למקום של הערך.

💡 רמז 2

if (filters.category !== undefined) conditions.push(category = ${param(filters.category)});. ‏!== undefined ולא if (filters.minPrice) — אחרת minPrice: 0 נעלם. בסוף: conditions.join(" AND ").

✅ פתרון
// P16-E27: בונה שאילתות עם פרמטרים
export type ProductFilters = {
  category?: string;
  minPrice?: number;
  maxPrice?: number;
  search?: string;
  inStock?: boolean;
  sort?: "price" | "-price" | "name";
  limit?: number;
};

export function buildProductQuery(filters: ProductFilters): { text: string; values: unknown[] } {
  const conditions = ["is_active"];
  const values: unknown[] = [];
  const param = (value: unknown) => {
    values.push(value);
    return `$${values.length}`;
  };

  if (filters.category !== undefined) conditions.push(`category = ${param(filters.category)}`);
  if (filters.minPrice !== undefined) conditions.push(`price >= ${param(filters.minPrice)}`);
  if (filters.maxPrice !== undefined) conditions.push(`price <= ${param(filters.maxPrice)}`);
  if (filters.search !== undefined) conditions.push(`name ILIKE ${param(`%${filters.search}%`)}`);
  if (filters.inStock === true) conditions.push("stock > 0");
  if (filters.inStock === false) conditions.push("stock = 0");

  let orderBy: string;
  switch (filters.sort) {
    case "price":
      orderBy = "price, id";
      break;
    case "-price":
      orderBy = "price DESC, id";
      break;
    case "name":
      orderBy = "name";
      break;
    case undefined:
      orderBy = "id";
      break;
    default:
      throw new Error(`מיון לא מוכר: ${filters.sort}`);
  }

  let text = `SELECT id, name, price FROM products WHERE ${conditions.join(" AND ")} ORDER BY ${orderBy}`;
  if (filters.limit !== undefined) text += ` LIMIT ${param(filters.limit)}`;
  return { text, values };
}

console.log(buildProductQuery({}));
console.log(buildProductQuery({ category: "beans", maxPrice: 90, inStock: true, sort: "-price", limit: 2 }));
console.log(buildProductQuery({ search: "grinder", sort: "name" }));

הפונקציה param היא העיקר: היא שומרת את הערך ומחזירה את המספר שלו. כך אי אפשר לטעות ב־$3 כשחלק מהמסננים חסרים. המספור נבנה לפי מה שבאמת נשלח.

למה stock > 0 נכתב ישר בטקסט ו־category לא? כי stock > 0 הוא קוד שאנחנו כתבנו. ‏category מגיע מהמשתמש. כל מה שמגיע מבחוץ עובר כפרמטר, וכך '; DROP TABLE products; -- הוא סתם מחרוזת שלא נמצאת. גם המיון מגיע מהמשתמש, אבל הוא עובר דרך switch שמתרגם אותו לטקסט שלנו. ערך לא מוכר נזרק, ולא נכנס לשאילתה.

ה־case undefined: נראה מוזר, אבל הוא חוקי: switch משווה עם ===, ו־undefined הוא ערך כמו כל ערך אחר. בזכותו ה־default נשאר רק לערכים לא מוכרים.

⚠️ טעויות נפוצות
  • category = '${filters.category}' — ‏SQL injection. הבודק שולח search עם מירכאה ובודק שהטבלה שרדה.
  • if (filters.minPrice) — ‏minPrice: 0 ו־inStock: false נעלמים.
  • מספור קבוע (price >= $2) — כשאין category, ‏$2 מצביע על הערך הלא נכון.
  • ORDER BY price בלי id — בשני מוצרים באותו מחיר הסדר לא מובטח, ו־LIMIT מחזיר כל פעם משהו אחר.
