P16-E02 · מה יוחזר? 🧠 הבנה רמה 1

💡 רמז 1

AND לפני OR — כמו כפל לפני חיבור.

💡 רמז 2

א' = "כל ה־grinders" ועוד "brewing יקרים מ־200".

SELECT name FROM products WHERE category = 'grinders' OR category = 'brewing' AND price > 200 ORDER BY name;

(3 rows)

----------------------

(2 rows)

ב־א' ה־Hand Grinder (189) נכנס, למרות שהוא מתחת ל־200 — כי ה־AND חל רק על brewing.

⚠️ טעויות נפוצות
  • להניח שהמסד "מבין למה התכוונת". סוגריים — תמיד, כשמערבבים AND ו־OR.

P16-E03 · מה נכשל? 🧠 הבנה רמה 1

💡 רמז 1

סדר הביצוע: FROM ← WHERE ← SELECT ← ORDER BY.

💡 רמז 2

מה ההבדל בין ' ל־" ב־SQL?

✅ פתרון
  1. ✔ — ORDER BY רץ אחרי SELECT, ומכיר את הכינוי.
  2. ✘ column "with_vat" does not exist — WHERE רץ לפני SELECT. צריך לחזור על הביטוי: WHERE price * 1.17 > 100.
  3. ✘ column "beans" does not exist — מירכאות כפולות הן שם עמודה. מחרוזת: 'beans'.
  4. ✔ — המוצרים במקומות 4–6 לפי מחיר (עמוד 2 של 3).
  5. ✔ — אבל כנראה לא מה שרצית: DISTINCT חל על כל העמודות יחד, וכל צירוף category+name הוא ייחודי — חוזרים כל 14 המוצרים.
⚠️ טעויות נפוצות
  • לחשוב ש־DISTINCT category, name הוא "DISTINCT על category ועוד name".

P16-E49 · אילו שמות יתאימו ל־LIKE? 🧠 הבנה רמה 2

💡 רמז 1

LIKE רגיש לאותיות; ILIKE לא. ובלי % בהתחלה — השם חייב להתחיל בתבנית.

💡 רמז 2

'%1_' — "נגמר ב־1 ואחריו תו אחד בדיוק". חפש שמות שנגמרים ב־1L, ‏1kg...

✅ פתרון
SELECT COUNT(*) FROM products WHERE name LIKE '%Grinder%';
SELECT COUNT(*) FROM products WHERE name LIKE 'Grinder%';
SELECT COUNT(*) FROM products WHERE name LIKE '%grinder%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%grinder%';
SELECT COUNT(*) FROM products WHERE name LIKE '%1_';
SELECT COUNT(*) FROM products WHERE name LIKE '%(%)';

(1 row)

-------
     1
(1 row)

-------
     0
(1 row)

 count
-------
     3
(1 row)

 count
-------
     1
(1 row)

 count
-------
     1
(1 row)

שלושה דברים: 'Grinder%' מחפש התחלה ("Grinder Cleaning Brush" — כן, "Hand Grinder" — לא); LIKE '%grinder%' לא מוצא את "Grinder" עם G גדולה; ו־_ הוא בדיוק תו אחד — '%1_' תפס את 1L אבל לא את 1kg. בחיפוש של משתמשים — כמעט תמיד ILIKE.

⚠️ טעויות נפוצות
  • לשכוח את ה־% מאחת הצדדים — מקבלים "מתחיל ב" או "נגמר ב" במקום "מכיל".

P16-E50 · סדר שלא מובטח 🧠 הבנה רמה 2

💡 רמז 1

כמה מוצרים יש עם stock = 0? ואם יש יותר משלושה עם אותו ערך — מי "ראשון"?

💡 רמז 2

בלי עמודה שמכריעה בשוויון, המסד רשאי להחזיר את השורות השוות בכל סדר — ולשנות אותו בין הרצות.

✅ פתרון
SELECT id, name, stock FROM products ORDER BY stock, id LIMIT 3;
SELECT id, name, stock FROM products ORDER BY stock, id LIMIT 3 OFFSET 3;
 id |        name        | stock
----+--------------------+-------
  2 | Colombia Beans 1kg |     0
  8 | V60 Ceramic        |     0
 12 | Digital Scale      |     0
(3 rows)

 id |         name         | stock
----+----------------------+-------
  6 | Electric Grinder Pro |     3
 13 | Gooseneck Kettle     |     7
  5 | Hand Grinder         |     8
(3 rows)

(הרצנו רק את 2 ו־3.) יש שלושה מוצרים עם מלאי 0 ומוצר אחד עם 3 — בשאילתה 1, המסד לא מבטיח איזה סדר יקבלו השווים. כרגע הוא אולי מחזיר לפי סדר ההכנסה, אבל אחרי עדכונים, index או גרסה אחרת — זה יכול להשתנות, ואז "עמוד 2" (OFFSET) מדלג על מוצר או מציג אותו פעמיים. כלל: עם LIMIT/OFFSET — תמיד עמודה ייחודית בסוף ה־ORDER BY (בדרך כלל id).

⚠️ טעויות נפוצות
  • "זה עבד בבדיקה" — סדר לא מוגדר הוא בדיוק סוג הבאג שמופיע רק בייצור.

P16-E51 · BETWEEN ותאריכים 🧠 הבנה רמה 2

💡 רמז 1

BETWEEN a AND b = >= a AND <= b — כולל שני הקצוות.

💡 רמז 2

אם a > b — אין מספר שגדול מ־119 וגם קטן מ־89.90.

✅ פתרון
SELECT COUNT(*) FROM products WHERE price BETWEEN 89.90 AND 119;
SELECT COUNT(*) FROM products WHERE price > 89.90 AND price < 119;
SELECT COUNT(*) FROM products WHERE price BETWEEN 119 AND 89.90;
SELECT COUNT(*) FROM customers WHERE joined_on BETWEEN '2026-01-01' AND '2026-03-31';
SELECT COUNT(*) FROM customers WHERE joined_on >= '2026-01-01' AND joined_on < '2026-04-01';
 count
-------
     3
(1 row)

 count
-------
     1
(1 row)

 count
-------
     0
(1 row)

 count
-------
     5
(1 row)

 count
-------
     5
(1 row)

ההבדל בין 1 ל־2 הוא בדיוק שני הקצוות. שאילתה 3 לא נכשלת — היא פשוט מחזירה 0 (סדר הפוך). ושתי שאילתות התאריכים שוות כאן, אבל רק כי העמודה היא date. עם timestamptz (שעה), ‏BETWEEN ... AND '2026-03-31' עוצר בחצות של ה־31 ומפספס את כל היום; ‏< '2026-04-01' נכון תמיד. לכן לטווח זמן — עדיף >= התחלה AND < הבא.

⚠️ טעויות נפוצות
  • להעביר טווח "מ־עד" מהמשתמש בלי לוודא ש־from ≤ to — מקבלים 0 שורות, בלי שגיאה (P15-E14 בודק את זה ב־Zod).

P16-E52 · חשבון בתוך SELECT 🧠 הבנה רמה 2

💡 רמז 1

שלם חלקי שלם — שלם (החלק העשרוני נחתך). כמו ב־Java, לא כמו ב־JavaScript.

💡 רמז 2

numeric כפול integer — numeric, עם שתי הספרות אחרי הנקודה.

✅ פתרון
SELECT 7 / 2 AS a, 7.0 / 2 AS b, 7 % 2 AS c, ROUND(10 / 3.0, 2) AS d;
SELECT name, stock, stock / 4 AS boxes, price * stock AS stock_value
FROM products
WHERE id IN (1, 3, 5)
ORDER BY id;
 a |         b          | c |  d
---+--------------------+---+------
 3 | 3.5000000000000000 | 1 | 3.33
(1 row)

        name        | stock | boxes | stock_value
--------------------+-------+-------+-------------
 Ethiopia Beans 1kg |    40 |    10 |     3596.00
 Brazil Beans 250g  |   120 |    30 |     3588.00
 Hand Grinder       |     8 |     2 |     1512.00
(3 rows)

7 / 2 הוא 3 — לא 3.5. זה מקור לבאגים כשמחשבים ממוצע או אחוז מעמודות integer (stock / total ← 0). הפתרון: להפוך אחד הצדדים ל־numeric (stock * 1.0 / total, או ::numeric). ‏boxes כאן דווקא נכון — כמה קופסאות מלאות של 4.

⚠️ טעויות נפוצות
  • לחשב אחוז עם sold / total * 100 על שלמים — יוצא 0 כמעט תמיד. 100.0 * sold / total.

P16-E53 · SQL injection בעיניים 🧠 הבנה רמה 2

💡 רמז 1

המסד מקבל טקסט, ולא יודע אילו חלקים הגיעו מהמשתמש.

💡 רמז 2

בשורה השלישית: ... ILIKE '%x' OR 'a'='a%' — איך המסד קורא את זה?

✅ פתרון
const search = (q) => `SELECT name, price FROM products WHERE is_active AND name ILIKE '%${q}%'`;
console.log(search("grinder"));
console.log(search("O'Brien"));
console.log(search("x' OR 'a'='a"));
console.log(search("'; DROP TABLE products; --"));

const safe = { text: "SELECT name, price FROM products WHERE is_active AND name ILIKE $1", values: ["%x' OR 'a'='a%"] };
console.log(safe.text, "|", safe.values);
SELECT name, price FROM products WHERE is_active AND name ILIKE '%grinder%'
SELECT name, price FROM products WHERE is_active AND name ILIKE '%O'Brien%'
SELECT name, price FROM products WHERE is_active AND name ILIKE '%x' OR 'a'='a%'
SELECT name, price FROM products WHERE is_active AND name ILIKE '%'; DROP TABLE products; --%'
SELECT name, price FROM products WHERE is_active AND name ILIKE $1 | [ "%x' OR 'a'='a%" ]

1 תקין. 2 — שגיאת תחביר (משתמש תמים עם גרש מקבל 500). 3 — ... AND name ILIKE '%x' OR 'a'='a%': ה־OR "בורח" מה־AND, והשאילתה מחזירה גם מוצרים לא פעילים. 4 — שתי פקודות; מה שאחרי -- הוא הערה. זו SQL injection, מהפרצות הנפוצות בעולם. עם פרמטר ($1), הערך מגיע למסד בנפרד מהטקסט — והוא תמיד רק ערך, גם אם יש בו גרשיים.

⚠️ טעויות נפוצות
  • "לנקות" את הקלט ביד (replace("'", "")) — תמיד יש עוד דרך. פרמטרים — תמיד.

P16-E54 · LIMIT/OFFSET מול slice 🧠 הבנה רמה 2

💡 רמז 1

OFFSET 4 = "דלג על 4", בדיוק כמו התחלת ה־slice.

💡 רמז 2

עמוד שמעבר לסוף — מערך ריק בשני העולמות. אבל slice עם מספר שלילי סופר מהסוף (P15-E67) — ו־OFFSET שלילי?

✅ פתרון
SELECT id FROM products ORDER BY price DESC, id LIMIT 4 OFFSET 4;
 id
----
 12
  7
  8
  1
(4 rows)
const byPriceDesc = [6, 13, 5, 9, 12, 7, 8, 1, 2, 4, 11, 3, 10, 14]; // ids, ממוינים לפי price DESC, id
const page = 2;
const limit = 4;
console.log(byPriceDesc.slice((page - 1) * limit, page * limit));
console.log(byPriceDesc.slice(4 * limit, 5 * limit), byPriceDesc.slice(-1 * limit));
[ 12, 7, 8, 1 ]
[] [ 11, 3, 10, 14 ]

אותן ארבע מזהים — OFFSET הוא תחילת ה־slice ו־LIMIT הוא האורך. ההבדל המעשי: ב־SQL המסד מחזיר רק 4 שורות; ב־JavaScript צריך קודם להביא את כל הרשימה. ו־OFFSET -4 ב־PostgreSQL הוא שגיאה (OFFSET must not be negative), לא "מהסוף" כמו slice — עוד סיבה לבדוק page ≥ 1 לפני השאילתה.

⚠️ טעויות נפוצות
  • לטעון את כל הטבלה ולעשות slice ב־Node "כי זה פשוט יותר" — עובד עם 14 שורות, לא עם מיליון.

P16-E55 · % של המשתמש בתוך ILIKE 🧠 הבנה רמה 3

💡 רמז 1

_ = "תו אחד כלשהו", ו־% = "כל רצף". ‏'%_%' מתאים לכל שם שיש בו לפחות תו אחד.

💡 רמז 2

\ לפני תו מיוחד הופך אותו לתו רגיל — כמו ב־regex.

✅ פתרון
SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '_' || '%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '%' || '%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '\_' || '%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '(100)' || '%';
 count
-------
    14
(1 row)

 count
-------
    14
(1 row)

 count
-------
     0
(1 row)

 count
-------
     1
(1 row)

משתמש שחיפש _ קיבל את כל 14 המוצרים — לא פרצה, אבל תוצאה שגויה (ובטבלה גדולה — שאילתה כבדה). התיקון בקוד, לפני שבונים את הפרמטר: q.replace(/[\\%_]/g, "\\$&") — בורחים מ־\, ‏% ו־_. סוגריים, לעומת זאת, הם תווים רגילים ב־LIKE.

⚠️ טעויות נפוצות
  • לחשוב שפרמטרים "פותרים הכול" — הם מונעים injection, אבל התוכן של הערך עדיין מתפרש כתבנית LIKE.

P16-E27 · בונה שאילתות עם פרמטרים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני מערכים: conditions = ["is_active"] ו־values = []. פונקציית עזר קטנה: const param = (value) => { values.push(value); return $${values.length}; }. כך המספר תמיד מתאים למקום של הערך.

💡 רמז 2

if (filters.category !== undefined) conditions.push(category = ${param(filters.category)});. ‏!== undefined ולא if (filters.minPrice) — אחרת minPrice: 0 נעלם. בסוף: conditions.join(" AND ").

✅ פתרון
// P16-E27: בונה שאילתות עם פרמטרים
export type ProductFilters = {
  category?: string;
  minPrice?: number;
  maxPrice?: number;
  search?: string;
  inStock?: boolean;
  sort?: "price" | "-price" | "name";
  limit?: number;
};

export function buildProductQuery(filters: ProductFilters): { text: string; values: unknown[] } {
  const conditions = ["is_active"];
  const values: unknown[] = [];
  const param = (value: unknown) => {
    values.push(value);
    return `$${values.length}`;
  };

  if (filters.category !== undefined) conditions.push(`category = ${param(filters.category)}`);
  if (filters.minPrice !== undefined) conditions.push(`price >= ${param(filters.minPrice)}`);
  if (filters.maxPrice !== undefined) conditions.push(`price <= ${param(filters.maxPrice)}`);
  if (filters.search !== undefined) conditions.push(`name ILIKE ${param(`%${filters.search}%`)}`);
  if (filters.inStock === true) conditions.push("stock > 0");
  if (filters.inStock === false) conditions.push("stock = 0");

  let orderBy: string;
  switch (filters.sort) {
    case "price":
      orderBy = "price, id";
      break;
    case "-price":
      orderBy = "price DESC, id";
      break;
    case "name":
      orderBy = "name";
      break;
    case undefined:
      orderBy = "id";
      break;
    default:
      throw new Error(`מיון לא מוכר: ${filters.sort}`);
  }

  let text = `SELECT id, name, price FROM products WHERE ${conditions.join(" AND ")} ORDER BY ${orderBy}`;
  if (filters.limit !== undefined) text += ` LIMIT ${param(filters.limit)}`;
  return { text, values };
}

console.log(buildProductQuery({ category: "beans", maxPrice: 90, inStock: true, sort: "-price", limit: 2 }));

הפונקציה param היא העיקר: היא שומרת את הערך ומחזירה את המספר שלו. כך אי אפשר לטעות ב־$3 כשחלק מהמסננים חסרים. המספור נבנה לפי מה שבאמת נשלח.

למה stock > 0 נכתב ישר בטקסט ו־category לא? כי stock > 0 הוא קוד שאנחנו כתבנו. ‏category מגיע מהמשתמש. כל מה שמגיע מבחוץ עובר כפרמטר, וכך '; DROP TABLE products; -- הוא סתם מחרוזת שלא נמצאת. גם המיון מגיע מהמשתמש, אבל הוא עובר דרך switch שמתרגם אותו לטקסט שלנו. ערך לא מוכר נזרק, ולא נכנס לשאילתה.

ה־case undefined: נראה מוזר, אבל הוא חוקי: switch משווה עם ===, ו־undefined הוא ערך כמו כל ערך אחר. בזכותו ה־default נשאר רק לערכים לא מוכרים.

⚠️ טעויות נפוצות
  • category = '${filters.category}' — ‏SQL injection. הבודק שולח search עם מירכאה ובודק שהטבלה שרדה.
  • if (filters.minPrice) — ‏minPrice: 0 ו־inStock: false נעלמים.
  • מספור קבוע (price >= $2) — כשאין category, ‏$2 מצביע על הערך הלא נכון.
  • ORDER BY price בלי id — בשני מוצרים באותו מחיר הסדר לא מובטח, ו־LIMIT מחזיר כל פעם משהו אחר.

P16-E56 · חיפוש מוצרים מ־Node 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

הטיפוס של client: מספיק { query(text: string, values?: unknown[]): Promise<{ rows: any[] }> } — לא צריך לייבא את pg.

💡 רמז 2

מערך conditions ומערך values; לכל תנאי: values.push(v); conditions.push(name ILIKE $${values.length}).

✅ פתרון
// P16-E56: חיפוש מוצרים מ־Node
export type Db = { query(text: string, values?: unknown[]): Promise<{ rows: any[] }> };
export type Found = { id: number; name: string; price: number };

export async function searchProducts(client: Db, { q, category, limit = 10 }: { q?: string; category?: string; limit?: number }): Promise<Found[]> {
  if (!Number.isInteger(limit) || limit < 1 || limit > 50) throw new Error("limit חייב להיות 1–50");
  const conditions = ["is_active"];
  const values: unknown[] = [];
  if (q && q.trim()) {
    values.push(`%${q.trim().replace(/[\\%_]/g, "\\$&")}%`);
    conditions.push(`name ILIKE $${values.length}`);
  }
  if (category) {
    values.push(category);
    conditions.push(`category = $${values.length}`);
  }
  values.push(limit);
  const text = `SELECT id, name, price FROM products WHERE ${conditions.join(" AND ")} ORDER BY name, id LIMIT $${values.length}`;
  const { rows } = await client.query(text, values);
  return rows.map((r) => ({ id: r.id, name: r.name, price: Number(r.price) }));
}

הטקסט של השאילתה בנוי רק ממחרוזות שכתבת בקוד; כל מה שהגיע מבחוץ נמצא ב־values. ‏Number(r.price) — כי pg מחזיר numeric כמחרוזת ("189.00"), כדי לא לאבד דיוק; למחירים בטווח הזה Number מספיק, ולכסף בחישובים — אגורות (פרק 2).

⚠️ טעויות נפוצות
  • להחזיר את rows כמו שהן — הלקוח מקבל "price": "189.00" (מחרוזת), ו־a.price + b.price הופך לשרשור.
  • לשים את limit בתוך הטקסט (LIMIT ${limit}) — "רק מספר", עד שמישהו שולח "5; DROP...".

// P16-E57: ייצוא תוצאה ל־CSV
export type Db = { query(text: string, values?: unknown[]): Promise<{ rows: any[]; fields: { name: string }[] }> };

const cell = (v: unknown) => {
  if (v === null || v === undefined) return "";
  const s = String(v);
  return /[",\r\n]/.test(s) ? `"${s.replaceAll('"', '""')}"` : s;
};

export async function exportCsv(client: Db, text: string, values: unknown[] = []): Promise<string> {
  const { rows, fields } = await client.query(text, values);
  const names = fields.map((f) => f.name);
  const lines = [names.map(cell).join(","), ...rows.map((r) => names.map((n) => cell(r[n])).join(","))];
  return lines.join("\r\n") + "\r\n";
}

ה־\r\n והכפלת המירכאות הם מה שהתקן של CSV (ואקסל) מצפה לו. ‏fields חשוב כשאין שורות — "ייצוא ריק" עדיין צריך כותרת, וזה גם הסדר המדויק של ה־SELECT (בניגוד ל־Object.keys של שורה).

⚠️ טעויות נפוצות
  • Object.keys(rows[0]) לכותרת — קורס על תוצאה ריקה.
  • לעטוף כל ערך במירכאות בלי להכפיל " פנימיים — Moka Pot 6" שובר את השורה.
