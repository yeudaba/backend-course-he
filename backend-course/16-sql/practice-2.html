P16-E49 · אילו שמות יתאימו ל־LIKE?

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: שיעור 2

לפי הטבלה בשיעור (% = כל רצף, _ = תו אחד) — כמה מוצרים יחזיר כל אחד? בדוק בנתונים.

SELECT COUNT(*) FROM products WHERE name LIKE '%Grinder%';
SELECT COUNT(*) FROM products WHERE name LIKE 'Grinder%';
SELECT COUNT(*) FROM products WHERE name LIKE '%grinder%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%grinder%';
SELECT COUNT(*) FROM products WHERE name LIKE '%1_';
SELECT COUNT(*) FROM products WHERE name LIKE '%(%)';

P16-E53 · SQL injection בעיניים

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 2, שיעור 2

שרת בונה שאילתת חיפוש עם template literal. מה יודפס — מה באמת יישלח למסד בכל אחד מהמקרים?

const search = (q) => `SELECT name, price FROM products WHERE is_active AND name ILIKE '%${q}%'`;
console.log(search("grinder"));
console.log(search("O'Brien"));
console.log(search("x' OR 'a'='a"));
console.log(search("'; DROP TABLE products; --"));

const safe = { text: "SELECT name, price FROM products WHERE is_active AND name ILIKE $1", values: ["%x' OR 'a'='a%"] };
console.log(safe.text, "|", safe.values);

🔗 איך זה מתחבר: template literals מפרק 2, ואותה בעיה של O'Brien בפקודת curl (P14-E69). השיעור: WHERE ו־ILIKE — ו־P16-E27, שבו ערכים עוברים רק כפרמטרים.

P16-E54 · LIMIT/OFFSET מול slice

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 6, שיעור 2

אותה "עמוד 2, 4 בעמוד" — פעם ב־SQL ופעם ב־JavaScript על אותם נתונים. מה יחזיר כל אחד? האם התוצאות זהות?

SELECT id FROM products ORDER BY price DESC, id LIMIT 4 OFFSET 4;
const byPriceDesc = [6, 13, 5, 9, 12, 7, 8, 1, 2, 4, 11, 3, 10, 14]; // ids, ממוינים לפי price DESC, id
const page = 2;
const limit = 4;
console.log(byPriceDesc.slice((page - 1) * limit, page * limit));
console.log(byPriceDesc.slice(4 * limit, 5 * limit), byPriceDesc.slice(-1 * limit));

🔗 איך זה מתחבר: slice מפרק 6, ו־pagination ב־Express (P15-E13). השיעור: LIMIT ו־OFFSET — ואותו חשבון (page - 1) * limit.

P16-E55 · % של המשתמש בתוך ILIKE

🧠 הבנהרמה 3⏱ 10 דק׳ידע נדרש: פרק 13, שיעור 2

החיפוש עובר כפרמטר (בטוח מ־injection), ובקוד: values: [%${q}%]. אבל מה אם המשתמש מחפש תו שיש לו משמעות ב־LIKE? כמה שורות תחזיר כל שאילתה?

SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '_' || '%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '%' || '%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '\_' || '%';
SELECT COUNT(*) FROM products WHERE name ILIKE '%' || '(100)' || '%';

(|| מחבר מחרוזות ב־SQL — כמו + ב־JavaScript. כך נראה מה שהמסד מקבל מ־%${q}%.)

🔗 איך זה מתחבר: "תווים מיוחדים" ו־escape ב־regex מפרק 13 — אותו רעיון בדיוק. השיעור: ILIKE, ו־P16-E53 (פרמטרים מגינים מ־injection — לא מתווים מיוחדים של LIKE).

P16-E27 · בונה שאילתות עם פרמטרים 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 25 דק׳ידע נדרש: שיעור 2

🔁 חזרה על switch (פרק 4), ‏type עם שדות אופציונליים ו־union (פרק 11) ו־join (פרק 6), הפעם ב־TypeScript שמייצר SQL. מסך חיפוש מוצרים שולח לשרת מסננים, והשרת צריך לבנות מהם שאילתה. לעולם לא מדביקים ערכים מהמשתמש לתוך הטקסט של השאילתה. במקומם כותבים $1, ‏$2..., והערכים נשלחים בנפרד (זה יקרה בפרק 18 עם pg).

בקובץ 16-sql/starter/P16-E27.ts כתוב וייצא:

  • type ProductFilters — כל השדות לא חובה: category: string, ‏minPrice: number, ‏maxPrice: number, ‏search: string, ‏inStock: boolean, ‏sort: "price" | "-price" | "name", ‏limit: number.
  • buildProductQuery(filters: ProductFilters): { text: string; values: unknown[] }.

הטקסט: SELECT id, name, price FROM products WHERE is_active, ואחריו תנאים עם AND , ‏ ORDER BY ... ובסוף LIMIT $n (רק אם יש limit). התנאים, בסדר הזה, ורק למסננים שנשלחו:

  • category = $n, ‏price >= $n (‏minPrice), ‏price <= $n (‏maxPrice), ‏name ILIKE $n (הערך: %search%).
  • inStock: true ← stock > 0. ‏inStock: false ← stock = 0. (בלי פרמטר — אלה לא ערכים מהמשתמש.)
  • מיון, עם switch: ‏"price" ← price, id; ‏"-price" ← price DESC, id; ‏"name" ← name; בלי sort ← id. ערך אחר (מקוד JavaScript שלא עבר בדיקת טיפוסים) ← Error(מיון לא מוכר: ${sort}).
  • המספרים של הפרמטרים לפי הסדר שבו נוספו: $1, ‏$2... ‏values באותו סדר.
buildProductQuery({ category: "beans", maxPrice: 90, inStock: true, sort: "-price", limit: 2 });
// text:   "SELECT id, name, price FROM products WHERE is_active AND category = $1 AND price <= $2 AND stock > 0 ORDER BY price DESC, id LIMIT $3"
// values: ["beans", 90, 2]

📄 כותבים בקובץ 16-sql/starter/P16-E27.ts (יש בו רק הערה), מריצים ובודקים:

% node 16-sql/starter/P16-E27.ts
% npm run check P16-E27

הבודק בודק את הטקסט, ואז גם מריץ את השאילתה שלך על נתוני החנות, ומשווה את המוצרים שחזרו.

🔗 איך זה מתחבר: switch מפרק 3 ו־union types מפרק 11 — כדי לבנות WHERE ו־ORDER BY מהשיעור, עם פרמטרים במקום שרשור (P16-E53).

P16-E56 · חיפוש מוצרים מ־Node 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 10, פרק 11, שיעור 2

כתוב וייצא async function searchProducts(client, { q, category, limit = 10 }). ‏client הוא חיבור של pg (יש לו client.query(text, values); הבודק מעביר חיבור אמיתי למסד, עם נתוני shop.sql).

  • מחזירה מערך { id, name, price }, כש־price הוא מספר (הדרייבר מחזיר numeric כמחרוזת — P16-E68).

P16-E57 · ייצוא תוצאה ל־CSV 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: פרק 2, פרק 6, שיעור 2

"תן לי את הרשימה באקסל" — בקשה שתשמע הרבה. כתוב וייצא async function exportCsv(client, text, values = []) שמריצה שאילתה ומחזירה מחרוזת CSV:

  • שורה ראשונה — שמות העמודות, לפי הסדר של התוצאה (result.fields.map((f) => f.name) — כך גם שאילתה בלי שורות מחזירה כותרת).
  • שורה לכל שורת תוצאה. ‏null ← שדה ריק. כל ערך אחר ← String(value).
  • ערך שמכיל פסיק, מירכאה כפולה או שורה חדשה ← עטוף ב־"...", וכל " בפנים מוכפל (""). כך גם בכותרת.
  • שורות מופרדות ב־\r\n, ובסוף — \r\n אחד.
