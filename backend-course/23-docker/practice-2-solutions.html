P23-E04 · image, container, volume 🧠 הבנה רמה 1

💡 רמז 1

image — קבוע ולקריאה בלבד. container — מופע שרץ, עם שכבה שאפשר לכתוב אליה. volume — אחסון מחוץ לשניהם.

💡 רמז 2

מה נמחק עם הקונטיינר?

✅ פתרון

(א) image הוא כמו class (או קובץ התקנה): תבנית קבועה. container הוא מופע שלו שרץ — אפשר ליצור עשרה מאותו image. (ב) נעלמה. כל מה שנכתב בתוך הקונטיינר — בשכבה הכתיבה שלו — נמחק איתו. (ג) נשארה. הנתונים נכתבו ל־volume, שחי בנפרד; הקונטיינר החדש מחובר לאותו volume. (ד) לא. הבנייה יוצרת קונטיינר חדש מה־image, וה־image לא יודע על מה שעשית ידנית בקונטיינר הישן. מה שצריך — ב־Dockerfile. (ה) כי ה־volume הוא הנתונים — והם החלק היקר. מוחקים אותם רק במפורש: docker volume rm או docker compose down -v.

⚠️ טעויות נפוצות
  • docker compose down -v "כדי לנקות" — מוחק את המסד. down בלי -v משאיר את הנתונים.

P23-E38 · כמה קונטיינרים יש עכשיו? 🧠 הבנה רמה 1

💡 רמז 1

כל docker run יוצר קונטיינר חדש. קונטיינר שסיים — לא נמחק, הוא "Exited".

💡 רמז 2

שם של קונטיינר חייב להיות ייחודי.

✅ פתרון
  • (א) ‏docker ps: אחד (api-1). ‏docker ps -a: שלושה — שני קונטיינרי node ב־Exited, ו־api-1.
  • (ב) שגיאה: השם api-1 כבר בשימוש (‏Conflict. The container name "/api-1" is already in use). לא נוצר כלום.
  • (ג) אחד. ה־image הורד פעם אחת, ושני הקונטיינרים הם מופעים שלו.
  • (ד) ‏docker rm <id> לכל אחד, או docker container prune (כל מה שעצר). עם --rm, קונטיינרים חד־פעמיים נמחקים לבד כשהם מסיימים.
⚠️ טעויות נפוצות
  • לחשוב ש־docker run "מפעיל שוב" את הקונטיינר הקודם. זה docker start.

P23-E39 · ‏-p: מי מגיע לאן? 🧠 הבנה רמה 2

💡 רמז 1

הצורה המלאה: -p [כתובת במחשב:]port במחשב:port בקונטיינר.

💡 רמז 2

בלי כתובת — Docker מאזין על כל הכתובות (0.0.0.0) של המחשב.

✅ פתרון
  1. localhost:3000; כן — כל הכתובות.
  2. localhost:8080 (בפנים עדיין 3000); כן.
  3. localhost:55432; לא — רק מהמחשב עצמו. טוב למסד פיתוח.
  4. אין דרך מבחוץ. הקונטיינר רץ, אבל אף port לא מחובר. (‏EXPOSE ב־Dockerfile לא מספיק — זה תיעוד.)
  5. port אקראי במחשב ← 3000 בקונטיינר. ‏docker port מראה איזה.
⚠️ טעויות נפוצות
  • מסד פיתוח עם -p 5432:5432 ב־Wi-Fi ציבורי, עם סיסמה secret. ‏127.0.0.1: בהתחלה סוגר את זה.

P23-E47 · איפה הנתונים? 🧠 הבנה רמה 2

💡 רמז 1

‏stop ו־start — אותו קונטיינר. rm — הקונטיינר והשכבה הכתיבה שלו נמחקים.

💡 רמז 2

volume שלא מחובר לאף קונטיינר נחשב "לא בשימוש".

✅ פתרון
  1. נשארו — אותו קונטיינר, אותה שכבת כתיבה.
  2. נעלמו.
  3. נשארו — ה־volume לא נמחק עם הקונטיינר.
  4. "נעלמו" — נוצר volume חדש וריק. הישן עדיין קיים (docker volume ls), רק לא מחובר.
  5. נעלמו — prune מוחק volumes שאף קונטיינר לא משתמש בהם.
⚠️ טעויות נפוצות
  • לסמוך על "stop/start עובד" ולבנות על זה. ביום שמעדכנים image, הקונטיינר נמחק ונוצר מחדש.

P23-E48 · ‏volume או bind mount? 🧠 הבנה רמה 1

💡 רמז 1

bind mount — תיקייה אמיתית שלך. volume — Docker מנהל, ואתה לא עורך אותו ישירות.

💡 רמז 2

סעיף 5: חבילות מקומפלות ל־macOS לא רצות ב־Linux.

✅ פתרון
  1. volume — Docker מנהל, מהיר, ולא מתערבב עם הקבצים שלך.
  2. bind mount — כל שמירה מגיעה מיד לקונטיינר.
  3. volume (או אחסון חיצוני, כמו S3 — פרק 26). תיקייה במחשב השרת קשורה למחשב אחד.
  4. bind mount (עם :ro — לקריאה בלבד).
  5. volume נפרד על /app/node_modules — כדי שה־node_modules של Linux לא יידרס ע"י זה של ה־Mac.
⚠️ טעויות נפוצות
  • bind mount לנתוני מסד ב־Mac — איטי (דרך ה־VM), ובעיות הרשאות.

P23-E49 · ‏latest, ‏alpine ו־digest 🧠 הבנה רמה 2

💡 רמז 1

tag הוא שם שאפשר להזיז, כמו branch ב־Git. digest הוא כמו hash של commit.

💡 רמז 2

Alpine משתמש ב־musl ולא ב־glibc.

✅ פתרון
  • (א) latest. מחר latest הוא Node 26, וה־build נשבר (או גרוע: עובד אחרת).
  • (ב) Node 24 על Alpine. אבל ה־tag מתעדכן לגרסאות 24.x חדשות ולתיקוני אבטחה — זה בדרך כלל רצוי.
  • (ג) בדיוק אותו image, ביט אחרי ביט, לתמיד. ‏build שאפשר לשחזר. (המחיר: תיקוני אבטחה רק כשמעדכנים במפורש.)
  • (ד) חבילות npm עם קוד native מקומפל ל־glibc נכשלות, או צריכות גרסה מיוחדת. רוב החבילות בסדר; כשלא — node:24-slim (Debian).
⚠️ טעויות נפוצות
  • להצמיד ל־node:24.22.2 ולשכוח. הוא לא יקבל אף תיקון אבטחה.

P23-E11 · PostgreSQL לפיתוח בפקודה אחת 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

כל דרישה היא דגל של docker run: -d, --name, -e, -p, -v, --restart.

💡 רמז 2

"שוב ושוב": docker rm -f p23-e11-db 2>/dev/null || true לפני — || true כי בפעם הראשונה אין מה למחוק, ו־set -e היה עוצר.

✅ פתרון
#!/usr/bin/env bash
# P23-E11: מסד PostgreSQL לפיתוח, בפקודה אחת. אפשר להריץ שוב ושוב
set -euo pipefail

# אם כבר יש קונטיינר בשם הזה — מוחקים אותו (את ה־volume לא! שם הנתונים)
docker rm -f p23-e11-db >/dev/null 2>&1 || true

docker run -d \
  --name p23-e11-db \
  --restart unless-stopped \
  -e POSTGRES_PASSWORD=course \
  -e POSTGRES_DB=shop \
  -p 55432:5432 \
  -v p23-e11-data:/var/lib/postgresql \
  postgres:18-alpine

שים לב ל־docker rm -f: הוא מוחק את הקונטיינר, לא את ה־volume — אז הנתונים נשארים בין הרצות. זה הסקריפט ש"מחליף" את התקנת PostgreSQL במחשב: כל פרויקט — מסד משלו, בגרסה שלו, בפורט שלו.

⚠️ טעויות נפוצות
  • -p 5432:5432 — מתנגש ב־PostgreSQL שכבר מותקן במחשב (פרק 16).
  • -v לנתיב /var/lib/postgresql/data — ב־PostgreSQL 18 הקונטיינר לא עולה (שיעור 4).

P23-E40 · ‏Redis לפיתוח — run או start 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1
if docker ps -a --format '{{.Names}}' | grep -qx dev-redis; then

— ‏-x: כל השורה, לא "מכיל".

💡 רמז 2

שורה ארוכה — שבור עם \ בסוף שורה.

✅ פתרון
#!/usr/bin/env bash
# P23-E40: Redis לפיתוח — run בפעם הראשונה, start אחר כך
set -euo pipefail
if docker ps -a --format '{{.Names}}' | grep -qx dev-redis; then
  docker start dev-redis
else
  docker run -d --name dev-redis -p 127.0.0.1:56379:6379 \
    -v dev-redis-data:/data --restart unless-stopped redis:8-alpine
fi

‏grep -x חשוב: בלעדיו, קונטיינר בשם old-dev-redis "נמצא", והסקריפט מנסה start לשם שלא קיים.

⚠️ טעויות נפוצות
  • docker run תמיד — בפעם השנייה: "name already in use".
  • docker ps בלי -a — לא רואה קונטיינר שעצר, ומנסה ליצור חדש באותו שם.

P23-E41 · ‏psql בתוך קונטיינר — עם מרכאות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

"${DB:-postgres}" — ברירת מחדל ב־bash.

💡 רמז 2

"$2" במרכאות כפולות: ‏bash לא מפרק לפי רווחים ולא מרחיב *. וה־$1 שבתוך ה־SQL? הוא חלק מהערך, לא מתפרש שוב.

✅ פתרון
#!/usr/bin/env bash
# P23-E41: psql-in.sh <container> <sql>
set -euo pipefail
if [ $# -ne 2 ]; then
  echo "שימוש: psql-in.sh <container> <sql>" >&2
  exit 2
fi
docker exec "$1" psql -U postgres -d "${DB:-postgres}" -tAc "$2"

שורה אחת, ושלוש החלטות: מרכאות סביב כל משתנה, ברירת מחדל עם :-, ו־exit code שעובר הלאה (בזכות set -e, או פשוט כי זו הפקודה האחרונה).

⚠️ טעויות נפוצות
  • $2 בלי מרכאות — select * from tasks הופך לארבעה ארגומנטים, וה־* מתפרש כרשימת הקבצים בתיקייה.

P23-E42 · ניקוי קונטיינרים שעצרו 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

while IFS= read -r name; do ... done < <(docker ps -a ...)

💡 רמז 2

"מתחיל ב־": ‏[[ "$name" == "$1"* ]] — ה־* מחוץ למרכאות הוא wildcard, ה־prefix בתוך מרכאות הוא טקסט.

✅ פתרון
#!/usr/bin/env bash
# P23-E42: cleanup.sh <prefix> — מוחק קונטיינרים שעצרו ששמם מתחיל ב־prefix
set -euo pipefail
if [ $# -ne 1 ] || [ -z "$1" ]; then
  echo "שימוש: cleanup.sh <prefix>" >&2
  exit 2
fi
count=0
while IFS= read -r name; do
  if [[ "$name" == "$1"* ]]; then
    docker rm "$name" > /dev/null
    echo "$name"
    count=$((count + 1))
  fi
done < <(docker ps -a --filter status=exited --format '{{.Names}}')
echo "removed $count"

‏"$1"*: אם ה־prefix עצמו מכיל תו כמו * או ?, המרכאות מבטיחות שהוא מושווה כטקסט. וה־prefix הריק נחסם — בלעדיו "מתחיל במחרוזת ריקה" נכון לכל שם.

⚠️ טעויות נפוצות
  • grep "$1" — "מכיל", לא "מתחיל ב־": ‏old-demo-1 נמחק.
  • ((count++)) עם set -e — כשהערך היה 0, הביטוי "נכשל" והסקריפט עוצר.

P23-E43 · לפרק את עמודת PORTS 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

ביטוי רגולרי: /^(\[[^\]]+\]|[\d.]+):(\d+)->(\d+)\/(tcp|udp)$/.

💡 רמז 2

hostIp.replace(/^\[|\]$/g, "") מוריד סוגריים.

✅ פתרון
// P23-E43: לפרק את עמודת PORTS של docker ps
export type PortMap = { hostIp: string; hostPort: number; containerPort: number; protocol: "tcp" | "udp" };

const RE = /^(\[[^\]]+\]|[\d.]+):(\d+)->(\d+)\/(tcp|udp)$/;

export function parsePorts(text: string): PortMap[] {
  if (text.trim() === "") return [];
  const out: PortMap[] = [];
  for (const item of text.split(",").map((s) => s.trim())) {
    if (!item.includes("->")) {
      if (/^\d+\/(tcp|udp)$/.test(item)) continue;
      throw new Error(`לא מובן: ${item}`);
    }
    const m = RE.exec(item);
    if (!m) throw new Error(`לא מובן: ${item}`);
    out.push({ hostIp: m[1].replace(/^\[|\]$/g, ""), hostPort: Number(m[2]), containerPort: Number(m[3]), protocol: m[4] as "tcp" | "udp" });
  }
  return out;
}

שתי שורות לאותו port (‏0.0.0.0 ו־[::]) — IPv4 ו־IPv6. ו־127.0.0.1:55432->5432/tcp אומר "רק מהמחשב הזה" (E39).

⚠️ טעויות נפוצות
  • split(":") — ה־IPv6 ([::]) מלא נקודתיים.

P23-E44 · לפרק שם של image 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

קודם digest: const [rest, digest] = ref.split("@"). אחר כך tag: הנקודתיים האחרונות, אבל רק אם אחריהן אין / (כדי לא לבלבל עם port של registry).

💡 רמז 2

const parts = name.split("/"); אם parts.length > 1 ו־/[.:]/.test(parts[0]) || parts[0] === "localhost" ← registry. בלי / ב־repository של docker.io ← library/ לפני.

✅ פתרון
// P23-E44: registry/repository:tag@digest
export type ImageRef = { registry: string; repository: string; tag: string | null; digest: string | null };

export function parseImageRef(ref: string): ImageRef {
  const bad = () => new Error(`שם לא תקין: ${ref}`);
  if (ref === "" || /\s/.test(ref)) throw bad();
  const [rest, digest = null] = ref.split("@");
  let name = rest;
  let tag: string | null = null;
  const colon = rest.lastIndexOf(":");
  if (colon !== -1 && !rest.slice(colon).includes("/")) {
    name = rest.slice(0, colon);
    tag = rest.slice(colon + 1);
  }
  if (tag === null && digest === null) tag = "latest";
  const parts = name.split("/");
  let registry = "docker.io";
  if (parts.length > 1 && (/[.:]/.test(parts[0]) || parts[0] === "localhost")) registry = parts.shift()!;
  let repository = parts.join("/");
  if (!repository || /[A-Z]/.test(repository) || tag === "") throw bad();
  if (registry === "docker.io" && !repository.includes("/")) repository = `library/${repository}`;
  return { registry, repository, tag, digest };
}

"‏postgres" הוא בעצם docker.io/library/postgres:latest. כשרואים את זה, ברור למה FROM node מסוכן (E49), ולמה docker push ל־GitHub (פרק 25) צריך שם שמתחיל ב־ghcr.io/.

⚠️ טעויות נפוצות
  • לפצל לפי : הראשון — localhost:5000/app:dev נשבר.

P23-E45 · לבנות את פקודת docker run 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

מערך const args = ["run"]; ו־push לפי הסדר.

💡 רמז 2

tag: החלק האחרון אחרי / צריך להכיל :, או שיש @.

✅ פתרון
// P23-E45: RunSpec ← ארגומנטים של docker run
export type RunSpec = {
  image: string;
  name?: string;
  detach?: boolean;
  rm?: boolean;
  restart?: "no" | "always" | "unless-stopped";
  env?: Record<string, string>;
  ports?: string[];
  volumes?: string[];
  command?: string[];
};

export function runArgs(spec: RunSpec): string[] {
  const last = spec.image.split("/").at(-1)!;
  if (!last.includes(":") && !spec.image.includes("@")) throw new Error(`צריך tag מפורש: ${spec.image}`);
  if (spec.rm && spec.restart && spec.restart !== "no") throw new Error("--rm ו־--restart לא הולכים יחד");
  const args = ["run"];
  if (spec.detach) args.push("-d");
  if (spec.rm) args.push("--rm");
  if (spec.name) args.push("--name", spec.name);
  if (spec.restart) args.push("--restart", spec.restart);
  for (const [k, v] of Object.entries(spec.env ?? {})) args.push("-e", `${k}=${v}`);
  for (const p of spec.ports ?? []) args.push("-p", p);
  for (const v of spec.volumes ?? []) args.push("-v", v);
  args.push(spec.image, ...(spec.command ?? []));
  return args;
}

מערך של ארגומנטים (ולא מחרוזת אחת) הוא בדיוק מה ש־spawn("docker", args) צריך — בלי shell באמצע, ובלי בעיות של רווחים ומרכאות. כך עובדים כלים שמריצים Docker מקוד (גם הבודק של הפרק).

⚠️ טעויות נפוצות
  • -e ${k}=${v} כמחרוזת אחת — Docker מקבל ארגומנט אחד שמתחיל ב־"-e " (עם רווח), ונכשל.

P23-E46 · שגיאות מ־docker logs — משני הערוצים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

docker logs "$1" 2>&1 | grep -c ERROR — ומה קורה כש־grep לא מוצא כלום (exit 1) עם set -o pipefail?

💡 רמז 2

קודם לשמור את הלוגים במשתנה (כך כישלון של docker נתפס), ואז לספור: logs=$(docker logs "$1" 2>&1), ‏grep -c ERROR <<< "$logs" || true.

✅ פתרון
#!/usr/bin/env bash
# P23-E46: count-errors.sh <container>
set -euo pipefail
if [ $# -ne 1 ]; then
  echo "שימוש: count-errors.sh <container>" >&2
  exit 2
fi
if ! logs=$(docker logs "$1" 2>&1); then
  echo "$logs" >&2
  exit 1
fi
grep -c ERROR <<< "$logs" || true

‏grep -c מדפיס 0 כשאין התאמות, אבל יוצא עם 1. ‏|| true אומר "זה לא כישלון". ובלי 2>&1 — רוב השגיאות (שאפליקציות כותבות ל־stderr) פשוט לא נספרות.

// P23-E28 — גדלים של images
const UNITS = ["B", "kB", "MB", "GB", "TB"];

export function parseSize(text: string): number {
  const match = text.trim().match(/^(\d+(?:\.\d+)?)\s*([a-zA-Z]+)$/);
  if (!match) throw new Error(`גודל לא תקין: ${text}`);
  const value = Number(match[1]);
  switch (match[2]) {
    case "B":
      return value;
    case "kB":
    case "KB":
      return value * 1000;
    case "MB":
      return value * 1000 ** 2;
    case "GB":
      return value * 1000 ** 3;
    case "TB":
      return value * 1000 ** 4;
    default:
      throw new Error(`יחידה לא מוכרת: ${match[2]}`);
  }
}

export function formatSize(bytes: number): string {
  let unit = 0;
  let value = bytes;
  while (value >= 1000 && unit < UNITS.length - 1) {
    value /= 1000;
    unit++;
  }
  const text = unit === 0 ? String(Math.round(value)) : value.toFixed(1).replace(/\.0$/, "");
  return text + UNITS[unit];
}

export function totalSize(dockerImages: string): string {
  const [header, ...rows] = dockerImages.trim().split("\n");
  const sizeColumn = header.split(/\s{2,}/).indexOf("SIZE");
  if (sizeColumn === -1) throw new Error("אין עמודה SIZE");
  const bytes = rows
    .filter((row) => row.trim() !== "")
    .reduce((sum, row) => sum + parseSize(row.trim().split(/\s{2,}/)[sizeColumn]), 0);
  return formatSize(bytes);
}

למה לחפש את SIZE בכותרת? ‏docker images --format, וגרסאות חדשות של Docker, משנים את סדר העמודות. קוד שמניח "העמודה החמישית" נשבר בשקט ומחזיר מספר לא נכון. קוד שמחפש בכותרת נכשל עם הודעה ברורה.

P23-E50 · גיבוי של מסד בקונטיינר 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

כותבים קודם לקובץ זמני ("$file.tmp"), ורק אם הכול הצליח — mv לשם הסופי.

💡 רמז 2

בלי pipefail, ה־exit code של docker exec ... | gzip הוא של gzip — שתמיד מצליח. ‏trap 'rm -f "$tmp"' EXIT מנקה בכל יציאה.

✅ פתרון
#!/usr/bin/env bash
# P23-E50: backup-db.sh <container> <db> <dir>
set -euo pipefail
if [ $# -ne 3 ]; then
  echo "שימוש: backup-db.sh <container> <db> <dir>" >&2
  exit 2
fi
mkdir -p "$3"
file="$3/$2-$(date +%F).sql.gz"
tmp="$file.tmp"
trap 'rm -f "$tmp"' EXIT
docker exec "$1" pg_dump -U postgres "$2" | gzip > "$tmp"
mv "$tmp" "$file"
echo "$file"

שלושה דברים מגנים על הגיבוי: pipefail (כישלון של pg_dump לא "נבלע" ע"י gzip), קובץ זמני ו־mv (אף פעם אין קובץ גיבוי חצי־כתוב בשם האמיתי), ו־trap (הזמני נמחק גם בכישלון). גיבוי שנראה תקין ולא תקין הוא גרוע מאין גיבוי.

⚠️ טעויות נפוצות
  • לכתוב ישר לשם הסופי — כישלון משאיר קובץ .sql.gz ריק, שנראה כמו גיבוי.

// P23-E51: מה חשוב ב־docker inspect — בלי סודות
const SENSITIVE = /PASSWORD|SECRET|TOKEN|KEY/i;

export function summarize(inspect: any[]) {
  const c = inspect[0];
  if (!c) throw new Error("אין קונטיינר");
  const ports = Object.entries(c.HostConfig?.PortBindings ?? {})
    .flatMap(([port, binds]) => ((binds as any[]) ?? []).map((b) => `${b.HostIp || "0.0.0.0"}:${b.HostPort}->${port}`))
    .sort();
  const mounts = (c.Mounts ?? []).map((m: any) => (m.Type === "volume" ? `volume ${m.Name} → ${m.Destination}` : `bind ${m.Source} → ${m.Destination}`));
  const env: Record<string, string> = {};
  for (const s of c.Config?.Env ?? []) {
    const i = s.indexOf("=");
    const k = s.slice(0, i);
    env[k] = SENSITIVE.test(k) ? "***" : s.slice(i + 1);
  }
  return {
    name: String(c.Name).replace(/^\//, ""),
    image: c.Config.Image,
    running: c.State.Running,
    health: c.State.Health?.Status ?? null,
    ports,
    mounts,
    env,
  };
}

‏docker inspect מראה את כל משתני הסביבה של הקונטיינר — כולל POSTGRES_PASSWORD ו־JWT_SECRET. כל כלי שמציג אותו (דשבורד, לוג של CI) צריך הסתרה כזו.
