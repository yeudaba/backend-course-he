🎯 בשיעור הזה

  • image, container, volume ו־port.
  • הפקודות היומיומיות: run, ps, logs, exec, stop, rm.
  • PostgreSQL לפיתוח — בפקודה אחת, בלי התקנה.

1. "אצלי זה עובד"

אצלך — Node 24, PostgreSQL 18, Mac. אצל העמית — Node 20 ו־PostgreSQL 15. בשרת — Linux בלי Node בכלל. כל הבדל כזה הוא באג שמחכה לקרות. Docker אורז את האפליקציה יחד עם הסביבה שלה: מערכת קבצים של Linux מינימלי, Node בגרסה מדויקת, התלויות והקוד — וזה רץ אותו דבר בכל מחשב שיש בו Docker.

% docker run --rm node:24-alpine node -e "console.log(process.version, process.platform)"
v24.22.2 linux

(פלט אמיתי.) שורה אחת: Docker הוריד image של Node 24 על Alpine Linux, הריץ אותו, והדפיס linux — גם כשהפקודה רצה על Mac. (ב־Mac, Docker Desktop מריץ מכונה וירטואלית קטנה של Linux, והקונטיינרים רצים בתוכה.) --rm — למחוק את הקונטיינר כשהוא מסיים.

4. volumes — איפה הנתונים גרים

כל מה שהקונטיינר כותב — נכתב לשכבה שנמחקת איתו. מסד בלי volume מאבד הכול ב־docker rm. עם volume:

% docker run -d --name dev-db -e POSTGRES_PASSWORD=secret -p 55432:5432 \
    -v dev-db-data:/var/lib/postgresql postgres:18-alpine

ועכשיו אפשר למחוק ולהריץ מחדש (גם בגרסה חדשה של ה־image) — הנתונים ב־dev-db-data. docker volume ls מראה אותם, ו־docker volume rm מוחק — רק במפורש.

named volume (-v data:/path)bind mount (-v ./src:/path)
איפהDocker מנהל (בתוך ה־VM)תיקייה אמיתית במחשב שלך
בשבילנתונים: מסדים, uploadsפיתוח: הקוד שלך בתוך הקונטיינר, משתנה בזמן אמת
💡 tags

postgres:18-alpine = image בשם postgres, tag 18-alpine: גרסה 18, על Alpine Linux (קטן). בלי tag — latest, שמשתנה מתחת לרגליים. בעבודה: תמיד גרסה מפורשת. ו־-alpine מול בלי: 433MB מול 650MB ב־PostgreSQL (פלט אמיתי של docker image ls).
