P23-E02 · הרשאות 🧠 הבנה רמה 1

💡 רמז 1

💡 רמז 2

r=4, w=2, x=1. מחברים לכל שלשה.

✅ פתרון

(א) deploy.sh — הבעלים: הכול; כולם: קריאה והרצה. .env — הבעלים: קריאה וכתיבה; כולם: קריאה. id_ed25519 — רק הבעלים קורא וכותב. src — תיקייה (x בתיקייה = מותר להיכנס אליה).

(ד) 755 = rwxr-xr-x (סקריפטים ותיקיות), 644 = rw-r--r-- (קבצים רגילים), 600 = rw------- (סודות).

⚠️ טעויות נפוצות
  • chmod 777 "כדי שיעבוד" — כל אחד יכול לשנות את הקובץ. כמעט אף פעם לא התשובה.

P23-E30 · ‏2>&1 — הסדר קובע 🧠 הבנה רמה 2

💡 רמז 1

ההפניות מתבצעות משמאל לימין. 2>&1 אומר "stderr הולך לאן ש־stdout הולך עכשיו".

💡 רמז 2

> מוחק ומתחיל מחדש. ‏>> מוסיף.

✅ פתרון
ls /nope > out1.txt 2>&1; echo "1: $(wc -l < out1.txt)"
ls /nope 2>&1 > out2.txt | sed 's/^/pipe: /'; echo "2: $(wc -l < out2.txt)"
ls /nope 2> err.txt > out3.txt; echo "3: $(wc -l < err.txt)"
echo "a" > f.txt; echo "b" > f.txt; echo "c" >> f.txt; cat f.txt
?
  • 1 — קודם stdout לקובץ, ואז stderr "לאותו מקום" — שניהם בקובץ.
  • 2 — קודם stderr לאן ש־stdout הולך עכשיו (ה־pipe), ורק אחר כך stdout לקובץ. השגיאה הלכה ל־pipe, והקובץ ריק.
  • 3 — כל אחד לקובץ משלו.
  • 4 — > השני דרס את a, ‏>> הוסיף.

ב־cron: ‏backup.sh >> /var/log/backup.log 2>&1 — מוסיף, ושגיאות נכנסות לאותו לוג.

⚠️ טעויות נפוצות
  • 2>&1 > file ("זה אותו דבר") — השגיאות לא בקובץ.

P23-E31 · ‏kill או kill -9? 🧠 הבנה רמה 2

💡 רמז 1

SIGTERM — "בבקשה". SIGKILL — מערכת ההפעלה עוצרת את התהליך, הוא לא יודע כלום.

💡 רמז 2

טרנזקציה שלא עשו לה COMMIT — מה המסד עושה כשהחיבור נקטע?

✅ פתרון
  • (א) השרת מפסיק לקבל בקשות חדשות, מסיים את 40 הקיימות, סוגר חיבורים למסד, ויוצא. הלקוחות מקבלים תשובה.
  • (ב) התהליך נעצר מיד. 40 הלקוחות מקבלים חיבור שנקטע. הטרנזקציה לא הגיעה ל־COMMIT, אז PostgreSQL מבטל אותה כשהחיבור נופל — הנתונים עקביים (פרק 18), אבל הפעולה לא קרתה, והלקוח לא יודע.
  • (ג) שולח SIGTERM, מחכה 10 שניות, ואז SIGKILL. שרת שמתעלם — כל פריסה "תקועה" 10 שניות ונגמרת ב־SIGKILL.
  • (ד) כשתהליך תקוע לגמרי ולא מגיב ל־SIGTERM. מוצא אחרון.
⚠️ טעויות נפוצות
  • להתרגל ל־kill -9 "כי זה עובד תמיד". הוא עובד — ומשאיר בקשות באמצע.

P23-E06 · כמה שגיאות? 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הרץ grep -c ERROR על הקובץ — ותסתכל בשורה האחרונה שלו. למה התוצאה 4?

💡 רמז 2

awk '$2 == "ERROR"' מדפיס רק שורות שהעמודה השנייה שלהן ERROR. wc -l סופר. ב־Mac wc מוסיף רווחים — tr -d ' '.

✅ פתרון
#!/usr/bin/env bash
# P23-E06: כמה שורות ברמת ERROR יש בלוג
set -euo pipefail

if [ $# -ne 1 ]; then
  echo "שימוש: count-errors.sh <קובץ-לוג>" >&2
  exit 2
fi
if [ ! -f "$1" ]; then
  echo "לא נמצא הקובץ: $1" >&2
  exit 1
fi

# העמודה השנייה היא הרמה. grep -c ERROR היה סופר גם שורה שהמילה מופיעה בה בטקסט
awk '$2 == "ERROR"' "$1" | wc -l | tr -d ' '

set -euo pipefail בראש כל סקריפט: עוצר על שגיאה (-e), על משתנה לא מוגדר (-u), ועל כישלון באמצע pipeline (pipefail). והודעות שגיאה — ל־stderr (>&2), כדי שמי שמשתמש בפלט (count=$(bash count-errors.sh app.log)) יקבל רק את המספר.

⚠️ טעויות נפוצות
  • grep -c ERROR — סופר כל שורה שהמילה מופיעה בה, כולל בטקסט החופשי.

P23-E07 · הכתובות הכי פעילות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הדפוס הקלאסי: awk '{print $1}' | sort | uniq -c | sort -rn | head.

💡 רמז 2

מיון לפי שני מפתחות: sort -k1,1nr -k2,2 — עמודה 1 מספרית יורדת, ואז עמודה 2. ו־${2:-3} — הארגומנט השני או 3.

✅ פתרון
#!/usr/bin/env bash
# P23-E07: N כתובות ה־IP עם הכי הרבה בקשות (ברירת מחדל 3): "כמות כתובת"
set -euo pipefail

if [ $# -lt 1 ]; then
  echo "שימוש: top-ips.sh <access.log> [N]" >&2
  exit 2
fi

awk '{ print $1 }' "$1" \
  | sort \
  | uniq -c \
  | sort -k1,1nr -k2,2 \
  | head -n "${2:-3}" \
  | awk '{ print $1, $2 }'

האחרון (awk '{print $1, $2}') מנקה את הרווחים ש־uniq -c מוסיף — וזה גם מה שעושה את הפלט זהה ב־Mac וב־Linux, שם הריווח שונה. זה הדפוס שמשתמשים בו באמת כשיש עומס חשוד על השרת: "מי שולח לי הכי הרבה בקשות?".

⚠️ טעויות נפוצות
  • sort -rn בלי מפתח שני — בתיקו, הסדר תלוי במערכת.

P23-E08 · awk ו־CSV 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

tail -n +2 — מהשורה השנייה (בלי הכותרת). awk -F, — מפריד פסיק.

💡 רמז 2

מערך ב־awk: { total[$2] += $3 } END { for (c in total) printf "%s %.2f\n", c, total[c] }. הסדר של for in לא מוגדר — לכן sort אחריו.

✅ פתרון
#!/usr/bin/env bash
# P23-E08: סכום הזמנות לכל לקוח, מהגדול לקטן: "לקוח סכום" (2 ספרות אחרי הנקודה)
set -euo pipefail

if [ $# -ne 1 ]; then
  echo "שימוש: sum-by-customer.sh <orders.csv>" >&2
  exit 2
fi

tail -n +2 "$1" \
  | awk -F, '{ total[$2] += $3 } END { for (c in total) printf "%s %.2f\n", c, total[c] }' \
  | sort -k2,2nr -k1,1

awk הוא שפה קטנה שלמה — ו"סכום לפי מפתח" הוא 80% ממה שעושים איתו. כשהקובץ גדול מדי ל־Excel או שהוא בשרת — זה הכלי.

⚠️ טעויות נפוצות
  • לשכוח את הכותרת — יוצא לקוח בשם customer עם סכום 0.

P23-E09 · בדיקת env לפני עלייה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

[ -z "${VAR:-}" ] — ריק או לא מוגדר (ה־:- מונע שגיאה עם set -u). ${#VAR} — האורך.

💡 רמז 2

לולאה על שמות: for name in DATABASE_URL JWT_SECRET, ו־${!name} — הערך של המשתנה ששמו ב־name.

✅ פתרון
#!/usr/bin/env bash
# P23-E09: בודק שההגדרות קיימות לפני שהשרת עולה (למשל ב־entrypoint של קונטיינר)
set -uo pipefail

ok=1
for name in DATABASE_URL JWT_SECRET; do
  if [ -z "${!name:-}" ]; then
    echo "חסר: $name" >&2
    ok=0
  fi
done

if [ -n "${JWT_SECRET:-}" ] && [ "${#JWT_SECRET}" -lt 32 ]; then
  echo "JWT_SECRET קצר מדי (${#JWT_SECRET} תווים, צריך 32)" >&2
  ok=0
fi

if [ "$ok" -eq 1 ]; then
  echo "OK"
else
  exit 1
fi

כאן אין -e ב־set: רוצים לאסוף את כל הבעיות ולדווח בבת אחת, לא לעצור בראשונה. ואותו רעיון כמו loadConfig בפרויקט (פרק 21): שרת עם הגדרות שבורות לא אמור לעלות "בערך".

⚠️ טעויות נפוצות
  • לבדוק רק "מוגדר" — JWT_SECRET="" עובר.

P23-E22 · סקריפט שבור 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

(1) מרכאות סביב כל שימוש במשתנה: "$src"/*.json, cp "$f" "$dest/".

💡 רמז 2

(2)+(3) set -euo pipefail, ובדיקה של $#. ועל תיקייה בלי קבצים — [ -e "$f" ] || continue.

✅ פתרון
#!/usr/bin/env bash
# P23-E22 (מתוקן): מעתיק את כל קובצי ה־JSON מתיקייה אחת לאחרת
set -euo pipefail # ← היה חסר: שגיאה באמצע לא עצרה את הסקריפט, והוא דיווח הצלחה

if [ $# -ne 2 ]; then # ← היה חסר: בלי ארגומנטים — "הצלחה" על כלום
  echo "שימוש: backup.sh <מקור> <יעד>" >&2
  exit 2
fi

src="$1"
dest="$2"
mkdir -p "$dest"

count=0
for f in "$src"/*.json; do # ← היה $src/*.json בלי מרכאות: נשבר על תיקייה עם רווח
  [ -e "$f" ] || continue # אין קבצים בכלל — הדפוס נשאר כמו שהוא
  cp "$f" "$dest/" # ← היה cp $f $dest/
  count=$((count + 1))
done

echo "הועתקו $count קבצים"

שלוש הטעויות האלה אחראיות לרוב הבאגים בסקריפטים של shell. set -euo pipefail בשורה השנייה של כל סקריפט, ומרכאות סביב כל משתנה — וחצי מהבעיות לא קורות. (ו־ShellCheck תופס את השאר, גם כתוסף ל־VS Code.)

⚠️ טעויות נפוצות
  • "הועתקו 1 קבצים" כשאין קבצים — בלי בדיקה, הלולאה רצה פעם אחת על הדפוס *.json עצמו.

P23-E25 · אתגר: wait-for 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

curl -fs -o /dev/null --max-time 2 "$url" — מצליח רק על 2xx/3xx, בשקט, ולא נתקע.

💡 רמז 2

$SECONDS ב־bash — כמה שניות הסקריפט רץ. לולאת while עם sleep 1.

✅ פתרון
#!/usr/bin/env bash
# P23-E25: מחכה עד שכתובת עונה 2xx, או עד שנגמר הזמן
set -uo pipefail

if [ $# -ne 2 ]; then
  echo "שימוש: wait-for.sh <url> <שניות>" >&2
  exit 2
fi

url="$1"
timeout="$2"
echo "מחכה ל־$url..."
start=$SECONDS
while [ $((SECONDS - start)) -lt "$timeout" ]; do
  # -f: קוד 4xx/5xx ← כישלון.  -s: בלי פס התקדמות.  --max-time: לא להיתקע על חיבור תקוע
  if curl -fs -o /dev/null --max-time 2 "$url"; then
    echo "✔ $url עונה"
    exit 0
  fi
  sleep 1
done

echo "✖ $url לא ענה תוך $timeout שניות" >&2
exit 1

שים לב ל־--max-time: בלעדיו, שרת שמקבל חיבור ולא עונה תוקע את הסקריפט לנצח, והזמן שקבעת לא שווה כלום. ו־-f: בלעדיו curl מחשיב 503 כהצלחה (הוא קיבל תשובה, הרי).

⚠️ טעויות נפוצות
  • sleep 30 "וזה בטח יספיק" — איטי כשהשרת מהיר, ונכשל כשהוא איטי.

P23-E26 · סבב גיבויים: לשמור רק את האחרונים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

התאריך בפורמט YYYY-MM-DD ממוין נכון גם כטקסט, ולכן sort רגיל מסדר מהישן לחדש. את הקבצים מוצאים עם find "$dir" -maxdepth 1 -type f -name 'db-[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9].sql.gz'. ‏[0-9] ב־glob הוא ספרה אחת.

לבדיקת keep: ‏[[ $keep =~ ^[1-9][0-9]*$ ]].

💡 רמז 2

אם יש count גיבויים, מוחקים את count - keep הראשונים ברשימה הממוינת: head -n $((count - keep)), ואחריו while read -r name; do rm -- "$dir/$name"; echo "$name"; done. שים מירכאות סביב כל משתנה שהוא נתיב.

✅ פתרון
#!/usr/bin/env bash
# P23-E26 — rotate-backups.sh <dir> <keep>
set -euo pipefail

if [ $# -ne 2 ]; then
  echo "שימוש: rotate-backups.sh <dir> <keep>" >&2
  exit 2
fi
dir=$1
keep=$2

if ! [[ $keep =~ ^[1-9][0-9]*$ ]]; then
  echo "keep חייב להיות מספר שלם חיובי: $keep" >&2
  exit 2
fi
if [ ! -d "$dir" ]; then
  echo "התיקייה לא קיימת: $dir" >&2
  exit 1
fi

# רק גיבויים בשם הנכון; התאריך בפורמט YYYY-MM-DD ממוין נכון גם כטקסט
backups=$(find "$dir" -maxdepth 1 -type f -name 'db-[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9].sql.gz' -exec basename {} \; | sort)
count=$(printf '%s\n' "$backups" | grep -c . || true)

if [ "$count" -le "$keep" ]; then
  exit 0
fi

printf '%s\n' "$backups" | head -n $((count - keep)) | while read -r name; do
  rm -- "$dir/$name"
  echo "$name"
done

סקריפט שמוחק קבצים צריך להיות זהיר יותר מכל סקריפט אחר. לכן התבנית בשם מדויקת: ‏db-*.gz היה מוחק גם את db-latest.sql.gz. בגלל אותה זהירות keep חייב להיות לפחות 1: עם 0 הסקריפט היה מוחק את כל הגיבויים.

grep -c . || true: כשאין אף גיבוי, ‏grep -c מדפיס 0 ויוצא עם 1. בלי || true, ‏set -e היה עוצר את הסקריפט. ו־rm -- מבטיח ששם קובץ שמתחיל במקף לא ייקרא כאפשרות.

בשרת אמיתי מריצים את זה מ־cron מיד אחרי הגיבוי. גיבוי שלא בודקים אם אפשר לשחזר ממנו הוא לא גיבוי — מדי פעם מריצים gunzip -c ... | psql על מסד ריק.

⚠️ טעויות נפוצות
  • ls -t (לפי זמן שינוי) במקום מיון לפי השם — אחרי העתקה או שחזור כל הקבצים מקבלים אותו זמן, והסקריפט מוחק את הגיבויים הלא נכונים.
  • rm $dir/$name בלי מירכאות — תיקייה עם רווח בשם נשברת לשני נתיבים.
  • לשכוח -maxdepth 1 — גיבויים בתתי־תיקיות (‏backups/archive/) נמחקים גם הם.
  • head -n -3 ("הכול חוץ משלושה האחרונים") — עובד ב־Linux, אבל לא ב־head של macOS.

// P23-E36: הרשאות — אותיות ↔ מספרים
export function toOctal(perms: string): string {
  if (!/^[-dl]([r-][w-][x-]){3}$/.test(perms)) throw new Error(`הרשאות לא תקינות: ${perms}`);
  let out = "";
  for (let i = 0; i < 3; i++) {
    const t = perms.slice(1 + i * 3, 4 + i * 3);
    out += (t[0] === "r" ? 4 : 0) + (t[1] === "w" ? 2 : 0) + (t[2] === "x" ? 1 : 0);
  }
  return out;
}

export function fromOctal(octal: string): string {
  if (!/^[0-7]{3}$/.test(octal)) throw new Error(`מספר לא תקין: ${octal}`);
  return [...octal]
    .map(Number)
    .map((d) => (d & 4 ? "r" : "-") + (d & 2 ? "w" : "-") + (d & 1 ? "x" : "-"))
    .join("");
}

‏d & 4 הוא "and" על ביטים: האם הביט של 4 דולק. זה בדיוק למה r=4, ‏w=2, ‏x=1 — כל אחד ביט אחר, ואפשר לחבר בלי להתבלבל.

⚠️ טעויות נפוצות
  • out += a + b + c כשה־out מחרוזת — הסדר של חיבור מספרים ומחרוזות. כאן החיבור בתוך הסוגריים קורה קודם (מספרים), ורק התוצאה מצורפת.
