P23-E02 · הרשאות רמה 1

💡 רמז 1

עשרה תווים: הראשון — סוג (- קובץ, d תיקייה); אחר כך שלוש שלשות: בעלים, קבוצה, אחרים. r=קריאה, w=כתיבה, x=הרצה.

💡 רמז 2

r=4, w=2, x=1. מחברים לכל שלשה.

✅ פתרון

(א) deploy.sh — הבעלים: הכול; כולם: קריאה והרצה. .env — הבעלים: קריאה וכתיבה; כולם: קריאה. id_ed25519 — רק הבעלים קורא וכותב. src — תיקייה (x בתיקייה = מותר להיכנס אליה).

(ב) .env מכיל סודות, וכל משתמש במחשב (או בשרת) יכול לקרוא אותו. chmod 600 .env — רק אתה. (מפתח SSH פרטי כבר כזה — ו־ssh מסרב לעבוד אם הוא לא.)

(ג) לקובץ חדש אין הרשאת הרצה. chmod +x backup.sh ואז ./backup.sh; או בלי הרשאה: bash backup.sh (כמו שהבודק מריץ את הסקריפטים שלך).

(ד) 755 = rwxr-xr-x (סקריפטים ותיקיות), 644 = rw-r--r-- (קבצים רגילים), 600 = rw------- (סודות).

⚠️ טעויות נפוצות
  • chmod 777 "כדי שיעבוד" — כל אחד יכול לשנות את הקובץ. כמעט אף פעם לא התשובה.

P23-E04 · image, container, volume רמה 1

💡 רמז 1

image — קבוע ולקריאה בלבד. container — מופע שרץ, עם שכבה שאפשר לכתוב אליה. volume — אחסון מחוץ לשניהם.

💡 רמז 2

מה נמחק עם הקונטיינר?

✅ פתרון

(א) image הוא כמו class (או קובץ התקנה): תבנית קבועה. container הוא מופע שלו שרץ — אפשר ליצור עשרה מאותו image. (ב) נעלמה. כל מה שנכתב בתוך הקונטיינר — בשכבה הכתיבה שלו — נמחק איתו. (ג) נשארה. הנתונים נכתבו ל־volume, שחי בנפרד; הקונטיינר החדש מחובר לאותו volume. (ד) לא. הבנייה יוצרת קונטיינר חדש מה־image, וה־image לא יודע על מה שעשית ידנית בקונטיינר הישן. מה שצריך — ב־Dockerfile. (ה) כי ה־volume הוא הנתונים — והם החלק היקר. מוחקים אותם רק במפורש: docker volume rm או docker compose down -v.

⚠️ טעויות נפוצות
  • docker compose down -v "כדי לנקות" — מוחק את המסד. down בלי -v משאיר את הנתונים.

P23-E05 · סקירת Dockerfile רמה 1

💡 רמז 1

חשוב על: גרסה, cache, סודות, גודל, משתמש, ומה קורה ב־docker stop.

💡 רמז 2

ואיפה הקבצים מועתקים? (אין WORKDIR.)

✅ פתרון
  1. node:latest — משתנה מתחת לרגליים; בנייה מחר עלולה לקבל Node אחר. גרסה קבועה: node:24-alpine.
  2. בלי WORKDIR — הכול נשפך לשורש (/) של מערכת הקבצים.
  3. COPY . . לפני ההתקנה — כל שינוי בקוד מבטל את ה־cache של npm install, וכל build מתקין הכול מחדש. קודם package*.json, התקנה, ורק אז הקוד.
  4. npm install במקום npm ci — לא בהכרח לפי ה־lock; ואין --omit=dev או multi-stage, אז כל ה־devDependencies (TypeScript, Jest...) נכנסים ל־image.
  5. סיסמה בתוך ה־image — כל מי שיש לו את ה־image (registry, מחשב של עמית) רואה אותה ב־docker image inspect. סודות — רק בזמן ריצה (-e, compose, מנהל סודות).
  6. רץ כ־root — אין USER.
  7. CMD npm start בצורת shell — יש shell ו־npm בין Docker לבין Node, ו־SIGTERM של docker stop לא תמיד מגיע לאפליקציה. CMD ["node", "dist/main.js"].
  8. ואין .dockerignore — סביר ש־.env ו־node_modules מהמחשב נכנסו עם COPY . ..
⚠️ טעויות נפוצות
  • לחשוב שסוד ב־ENV "בסדר כי ה־image פרטי". images מועברים, נשמרים ב־cache ובגיבויים — וזה תמיד דולף בסוף.

P23-E06 · כמה שגיאות? 🤖 רמה 2

💡 רמז 1

הרץ grep -c ERROR על הקובץ — ותסתכל בשורה האחרונה שלו. למה התוצאה 4?

💡 רמז 2

awk '$2 == "ERROR"' מדפיס רק שורות שהעמודה השנייה שלהן ERROR. wc -l סופר. ב־Mac wc מוסיף רווחים — tr -d ' '.

✅ פתרון
#!/usr/bin/env bash
# P23-E06: כמה שורות ברמת ERROR יש בלוג
set -euo pipefail

if [ $# -ne 1 ]; then
  echo "שימוש: count-errors.sh <קובץ-לוג>" >&2
  exit 2
fi
if [ ! -f "$1" ]; then
  echo "לא נמצא הקובץ: $1" >&2
  exit 1
fi

# העמודה השנייה היא הרמה. grep -c ERROR היה סופר גם שורה שהמילה מופיעה בה בטקסט
awk '$2 == "ERROR"' "$1" | wc -l | tr -d ' '

set -euo pipefail בראש כל סקריפט: עוצר על שגיאה (-e), על משתנה לא מוגדר (-u), ועל כישלון באמצע pipeline (pipefail). והודעות שגיאה — ל־stderr (>&2), כדי שמי שמשתמש בפלט (count=$(bash count-errors.sh app.log)) יקבל רק את המספר.

⚠️ טעויות נפוצות
  • grep -c ERROR — סופר כל שורה שהמילה מופיעה בה, כולל בטקסט החופשי.

P23-E07 · הכתובות הכי פעילות 🤖 רמה 2

💡 רמז 1

הדפוס הקלאסי: awk '{print $1}' | sort | uniq -c | sort -rn | head.

💡 רמז 2

מיון לפי שני מפתחות: sort -k1,1nr -k2,2 — עמודה 1 מספרית יורדת, ואז עמודה 2. ו־${2:-3} — הארגומנט השני או 3.

✅ פתרון
#!/usr/bin/env bash
# P23-E07: N כתובות ה־IP עם הכי הרבה בקשות (ברירת מחדל 3): "כמות כתובת"
set -euo pipefail

if [ $# -lt 1 ]; then
  echo "שימוש: top-ips.sh <access.log> [N]" >&2
  exit 2
fi

awk '{ print $1 }' "$1" \
  | sort \
  | uniq -c \
  | sort -k1,1nr -k2,2 \
  | head -n "${2:-3}" \
  | awk '{ print $1, $2 }'

האחרון (awk '{print $1, $2}') מנקה את הרווחים ש־uniq -c מוסיף — וזה גם מה שעושה את הפלט זהה ב־Mac וב־Linux, שם הריווח שונה. זה הדפוס שמשתמשים בו באמת כשיש עומס חשוד על השרת: "מי שולח לי הכי הרבה בקשות?".

⚠️ טעויות נפוצות
  • sort -rn בלי מפתח שני — בתיקו, הסדר תלוי במערכת.

P23-E08 · awk ו־CSV 🤖 רמה 2

💡 רמז 1

tail -n +2 — מהשורה השנייה (בלי הכותרת). awk -F, — מפריד פסיק.

💡 רמז 2

מערך ב־awk: { total[$2] += $3 } END { for (c in total) printf "%s %.2f\n", c, total[c] }. הסדר של for in לא מוגדר — לכן sort אחריו.

✅ פתרון
#!/usr/bin/env bash
# P23-E08: סכום הזמנות לכל לקוח, מהגדול לקטן: "לקוח סכום" (2 ספרות אחרי הנקודה)
set -euo pipefail

if [ $# -ne 1 ]; then
  echo "שימוש: sum-by-customer.sh <orders.csv>" >&2
  exit 2
fi

tail -n +2 "$1" \
  | awk -F, '{ total[$2] += $3 } END { for (c in total) printf "%s %.2f\n", c, total[c] }' \
  | sort -k2,2nr -k1,1

awk הוא שפה קטנה שלמה — ו"סכום לפי מפתח" הוא 80% ממה שעושים איתו. כשהקובץ גדול מדי ל־Excel או שהוא בשרת — זה הכלי.

⚠️ טעויות נפוצות
  • לשכוח את הכותרת — יוצא לקוח בשם customer עם סכום 0.

P23-E09 · בדיקת env לפני עלייה 🤖 רמה 2

💡 רמז 1

[ -z "${VAR:-}" ] — ריק או לא מוגדר (ה־:- מונע שגיאה עם set -u). ${#VAR} — האורך.

💡 רמז 2

לולאה על שמות: for name in DATABASE_URL JWT_SECRET, ו־${!name} — הערך של המשתנה ששמו ב־name.

✅ פתרון
#!/usr/bin/env bash
# P23-E09: בודק שההגדרות קיימות לפני שהשרת עולה (למשל ב־entrypoint של קונטיינר)
set -uo pipefail

ok=1
for name in DATABASE_URL JWT_SECRET; do
  if [ -z "${!name:-}" ]; then
    echo "חסר: $name" >&2
    ok=0
  fi
done

if [ -n "${JWT_SECRET:-}" ] && [ "${#JWT_SECRET}" -lt 32 ]; then
  echo "JWT_SECRET קצר מדי (${#JWT_SECRET} תווים, צריך 32)" >&2
  ok=0
fi

if [ "$ok" -eq 1 ]; then
  echo "OK"
else
  exit 1
fi

כאן אין -e ב־set: רוצים לאסוף את כל הבעיות ולדווח בבת אחת, לא לעצור בראשונה. ואותו רעיון כמו loadConfig בפרויקט (פרק 21): שרת עם הגדרות שבורות לא אמור לעלות "בערך".

⚠️ טעויות נפוצות
  • לבדוק רק "מוגדר" — JWT_SECRET="" עובר.

P23-E11 · PostgreSQL לפיתוח בפקודה אחת 🤖 רמה 2

💡 רמז 1

כל דרישה היא דגל של docker run: -d, --name, -e, -p, -v, --restart.

💡 רמז 2

"שוב ושוב": docker rm -f p23-e11-db 2>/dev/null || true לפני — || true כי בפעם הראשונה אין מה למחוק, ו־set -e היה עוצר.

✅ פתרון
#!/usr/bin/env bash
# P23-E11: מסד PostgreSQL לפיתוח, בפקודה אחת. אפשר להריץ שוב ושוב
set -euo pipefail

# אם כבר יש קונטיינר בשם הזה — מוחקים אותו (את ה־volume לא! שם הנתונים)
docker rm -f p23-e11-db >/dev/null 2>&1 || true

docker run -d \
  --name p23-e11-db \
  --restart unless-stopped \
  -e POSTGRES_PASSWORD=course \
  -e POSTGRES_DB=shop \
  -p 55432:5432 \
  -v p23-e11-data:/var/lib/postgresql \
  postgres:18-alpine

שים לב ל־docker rm -f: הוא מוחק את הקונטיינר, לא את ה־volume — אז הנתונים נשארים בין הרצות. זה הסקריפט ש"מחליף" את התקנת PostgreSQL במחשב: כל פרויקט — מסד משלו, בגרסה שלו, בפורט שלו.

⚠️ טעויות נפוצות
  • -p 5432:5432 — מתנגש ב־PostgreSQL שכבר מותקן במחשב (פרק 16).
  • -v לנתיב /var/lib/postgresql/data — ב־PostgreSQL 18 הקונטיינר לא עולה (שיעור 4).

P23-E14 · cache של שכבות 🤖 רמה 3

💡 רמז 1

Docker משתמש ב־cache לשכבה כל עוד כל מה שלפניה, וכל הקבצים שהיא מעתיקה, לא השתנו.

💡 רמז 2

COPY package.json package-lock.json ./ ← RUN npm ci --omit=dev ← COPY server.mjs ./.

✅ פתרון
FROM node:24-alpine
WORKDIR /app
# קודם רק מה שקובע את התלויות — השכבה הזו נשארת ב־cache כל עוד הם לא השתנו
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
# הקוד משתנה כל הזמן — הוא אחרון
COPY server.mjs ./
USER node
EXPOSE 3000
CMD ["node", "server.mjs"]

ב־docker build --progress=plain תראה את זה בעיניים: [3/5] RUN npm ci --omit=dev ← CACHED. בפרויקט עם 300 חבילות, זה ההבדל בין build של 5 שניות ל־2 דקות — בכל שינוי.

⚠️ טעויות נפוצות
  • COPY . . לפני npm ci — כל שינוי בקוד "מלכלך" את השכבה, וכל ההתקנה רצה מחדש.

P23-E15 · multi-stage ל־TypeScript 🤖 רמה 3

💡 רמז 1

FROM node:24-alpine AS build, ובשלב השני COPY --from=build /app/dist ./dist.

💡 רמז 2

בשלב השני — שוב COPY package*.json ו־npm ci --omit=dev (כאן אין תלויות בכלל — אבל בפרויקט יש).

✅ פתרון
# שלב 1: קומפילציה — צריך typescript ו־@types (devDependencies)
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY tsconfig.json ./
COPY src ./src
RUN npm run build

# שלב 2: ריצה — רק JavaScript מקומפל ותלויות של production
FROM node:24-alpine
ENV NODE_ENV=production
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
USER node
EXPOSE 3000
CMD ["node", "dist/server.js"]

שלב ה־build נזרק אחרי הבנייה — רק מה שהועתק ממנו במפורש עובר. זה בדיוק ה־Dockerfile של פרויקט 2, בקטן.

P23-E16 · HEALTHCHECK ו־PORT 🤖 רמה 3

💡 רמז 2

P23-E22 · סקריפט שבור 🤖 רמה 4

💡 רמז 1

(1) מרכאות סביב כל שימוש במשתנה: "$src"/*.json, cp "$f" "$dest/".

💡 רמז 2

(2)+(3) set -euo pipefail, ובדיקה של $#. ועל תיקייה בלי קבצים — [ -e "$f" ] || continue.

✅ פתרון
#!/usr/bin/env bash
# P23-E22 (מתוקן): מעתיק את כל קובצי ה־JSON מתיקייה אחת לאחרת
set -euo pipefail # ← היה חסר: שגיאה באמצע לא עצרה את הסקריפט, והוא דיווח הצלחה

if [ $# -ne 2 ]; then # ← היה חסר: בלי ארגומנטים — "הצלחה" על כלום
  echo "שימוש: backup.sh <מקור> <יעד>" >&2
  exit 2
fi

src="$1"
dest="$2"
mkdir -p "$dest"

count=0
for f in "$src"/*.json; do # ← היה $src/*.json בלי מרכאות: נשבר על תיקייה עם רווח
  [ -e "$f" ] || continue # אין קבצים בכלל — הדפוס נשאר כמו שהוא
  cp "$f" "$dest/" # ← היה cp $f $dest/
  count=$((count + 1))
done

echo "הועתקו $count קבצים"

שלוש הטעויות האלה אחראיות לרוב הבאגים בסקריפטים של shell. set -euo pipefail בשורה השנייה של כל סקריפט, ומרכאות סביב כל משתנה — וחצי מהבעיות לא קורות. (ו־ShellCheck תופס את השאר, גם כתוסף ל־VS Code.)

⚠️ טעויות נפוצות
  • "הועתקו 1 קבצים" כשאין קבצים — בלי בדיקה, הלולאה רצה פעם אחת על הדפוס *.json עצמו.

P23-E23 · עובד אצלי, לא ב־Docker 🤖 רמה 4

💡 רמז 1

docker logs של הקונטיינר — על איזו כתובת ואיזה port הוא מאזין?

💡 רמז 2

127.0.0.1 בתוך קונטיינר = רק מתוך הקונטיינר. ו־-p 3000:3000 מעביר ל־3000 בתוכו.

✅ פתרון
// שרת קטן בלי תלויות. PORT ו־HOST מה־env
import http from "node:http";

const port = Number(process.env.PORT ?? 3000);
const host = process.env.HOST ?? "0.0.0.0"; // בתוך קונטיינר — חייב להאזין לכל הכתובות, לא רק ל־127.0.0.1

const server = http.createServer((req, res) => {
  if (req.url === "/health") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ ok: true, node: process.version }));
    return;
  }
  res.writeHead(404, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ error: "not found" }));
});

server.listen(port, host, () => console.log(`listening on ${host}:${port}`));

// docker stop שולח SIGTERM — סוגרים יפה, ולא מחכים 10 שניות ל־SIGKILL
process.on("SIGTERM", () => server.close(() => process.exit(0)));

הבאג הכי נפוץ במעבר ל־Docker: שרת שמאזין ל־127.0.0.1 מקבל חיבורים רק מתוך עצמו. Docker מעביר את התעבורה לכתובת של הקונטיינר ברשת שלו — אז צריך 0.0.0.0 ("כל הכתובות"). (Express ו־Nest מאזינים לכל הכתובות כברירת מחדל — לכן בפרויקט לא נתקלת בזה.)

⚠️ טעויות נפוצות
  • "לתקן" עם --network host — עובד רק ב־Linux, ומבטל את הבידוד.

P23-E25 · אתגר: wait-for 🤖 רמה 5

💡 רמז 1

curl -fs -o /dev/null --max-time 2 "$url" — מצליח רק על 2xx/3xx, בשקט, ולא נתקע.

💡 רמז 2

$SECONDS ב־bash — כמה שניות הסקריפט רץ. לולאת while עם sleep 1.

✅ פתרון
#!/usr/bin/env bash
# P23-E25: מחכה עד שכתובת עונה 2xx, או עד שנגמר הזמן
set -uo pipefail

if [ $# -ne 2 ]; then
  echo "שימוש: wait-for.sh <url> <שניות>" >&2
  exit 2
fi

url="$1"
timeout="$2"
echo "מחכה ל־$url..."
start=$SECONDS
while [ $((SECONDS - start)) -lt "$timeout" ]; do
  # -f: קוד 4xx/5xx ← כישלון.  -s: בלי פס התקדמות.  --max-time: לא להיתקע על חיבור תקוע
  if curl -fs -o /dev/null --max-time 2 "$url"; then
    echo "✔ $url עונה"
    exit 0
  fi
  sleep 1
done

echo "✖ $url לא ענה תוך $timeout שניות" >&2
exit 1

שים לב ל־--max-time: בלעדיו, שרת שמקבל חיבור ולא עונה תוקע את הסקריפט לנצח, והזמן שקבעת לא שווה כלום. ו־-f: בלעדיו curl מחשיב 503 כהצלחה (הוא קיבל תשובה, הרי).

⚠️ טעויות נפוצות
  • sleep 30 "וזה בטח יספיק" — איטי כשהשרת מהיר, ונכשל כשהוא איטי.
