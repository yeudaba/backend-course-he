2. Dockerfile

Dockerfile 
# ---------- שלב 1: build ----------
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npx prisma generate && npm run build

# ---------- שלב 2: runtime ----------
FROM node:24-alpine
ENV NODE_ENV=production
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev --omit=optional && npm cache clean --force
COPY --from=build /app/dist ./dist
USER node
EXPOSE 3000
HEALTHCHECK --interval=5s --timeout=3s --start-period=10s --retries=5 \
  CMD wget -qO- http://127.0.0.1:3000/health || exit 1
CMD ["node", "dist/main.js"]
  • ה־Prisma Client שנוצר (src/generated) מתקמפל לתוך dist — לכן מספיק להעתיק את dist.
  • --omit=optional — שיעור 3: בלעדיו ה־image 827MB, איתו 435MB.
  • שינוי אחד ב־package.json: dotenv עובר מ־devDependencies ל־dependencies. main.ts מתחיל ב־import "dotenv/config" — ובלי זה, השרת נופל בעלייה עם Cannot find module 'dotenv/config'.
  • ה־package-lock.json חייב להיות ב־Git: npm ci בלעדיו נכשל.
⚠️ TypeScript 6

בבנייה הזו npm ci מתקין בדיוק מה שב־lock. תבנית Nest 12 משתמשת ב־TypeScript 6 (@nestjs/schematics דורש אותו). אם ב־package.json שלך כתוב "typescript": "^5…" — npm install נכשל עם ERESOLVE ו־peer typescript@">=6.0.0". עדכן ל־"^6.0.2".

4. compose.yaml

compose.yaml 
services:
  db:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: tasks
      POSTGRES_PASSWORD: tasks
      POSTGRES_DB: tasks
    volumes:
      - db-data:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U tasks -d tasks"]
      interval: 2s
      timeout: 3s
      retries: 30

  migrate:
    build:
      context: .
      target: build
    command: ["npx", "prisma", "migrate", "deploy"]
    environment:
      DATABASE_URL: postgresql://tasks:tasks@db:5432/tasks
    depends_on:
      db:
        condition: service_healthy

  api:
    build: .
    environment:
      DATABASE_URL: postgresql://tasks:tasks@db:5432/tasks
      JWT_SECRET: ${JWT_SECRET:?הגדר JWT_SECRET בקובץ .env}
      CORS_ORIGINS: http://localhost:5500
    ports:
      - "${API_PORT:-3000}:3000"
    depends_on:
      migrate:
        condition: service_completed_successfully

  web:
    image: nginx:1.29-alpine
    volumes:
      - ./web:/usr/share/nginx/html:ro
    ports:
      - "${WEB_PORT:-5500}:80"
    depends_on:
      - api

volumes:
  db-data:
  • migrate — משתמש בשלב ה־build (target: build), שבו יש את ה־Prisma CLI. הוא רץ, מריץ migrations, ונגמר. ה־image של ה־api נשאר נקי מה־CLI.
  • הסיסמאות של המסד כתובות בקובץ — זה מסד מקומי לפיתוח, לא נגיש מבחוץ (אין לו ports). בפרודקשן (פרק 25) הן יבואו מההגדרות של הפלטפורמה.
  • JWT_SECRET — מקובץ .env שליד ה־compose (שכבר יש לך).
  • web — nginx מגיש את web/ כמו שהוא. אותו דף מיחידה 15.5 ופרק 21 — עובד בלי שינוי.

ו־scripts נוחים ב־package.json: "docker:up": "docker compose up --build" ו־"docker:down": "docker compose down".

PR2-DOCKER: (1) ה־Dockerfile — multi-stage, סדר שמנצל cache, לא root, בלי COPY . . בשלב האחרון; (2) .dockerignore עם node_modules ו־.env; (3) ב־compose: PostgreSQL עם healthcheck ו־volume בנתיב של גרסה 18, api עם "${API_PORT:-3000}:3000" ותלות עם condition; (4) בפועל: docker compose up --build --wait בפרויקט נפרד (שם אחר, port אחר — לא נוגע בשלך), הרשמה, כניסה, משימה; ה־api לא root; down ו־up — והמשימה עדיין שם. ובסוף down -v. בפעם הראשונה זה לוקח דקה־שתיים (הורדות ו־build); אחר כך — שניות.

💼 בעולם העבודה

"יש לך ניסיון עם Docker?" — שאלה כמעט בכל ראיון Backend. תשובה טובה מראה הבנה, לא רק פקודות: למה multi-stage, למה הסדר ב־Dockerfile, למה לא root, מה ההבדל בין volume ל־bind mount, ולמה localhost לא עובד בין קונטיינרים. ובמשימות בית — docker compose up שמעלה הכול, עם README של שלוש שורות, עושה רושם מיידי: המראיין לא צריך להתקין PostgreSQL כדי לבדוק אותך. בעבודה עצמה: סביבת פיתוח ב־compose, images שנבנים ב־CI (פרק 25), ולוגים של קונטיינרים כשמשהו נופל.
