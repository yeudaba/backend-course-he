P23-E05 · סקירת Dockerfile 🧠 הבנה רמה 1

💡 רמז 1

חשוב על: גרסה, cache, סודות, גודל, משתמש, ומה קורה ב־docker stop.

💡 רמז 2

ואיפה הקבצים מועתקים? (אין WORKDIR.)

✅ פתרון
  1. node:latest — משתנה מתחת לרגליים; בנייה מחר עלולה לקבל Node אחר. גרסה קבועה: node:24-alpine.
  2. בלי WORKDIR — הכול נשפך לשורש (/) של מערכת הקבצים.
  3. COPY . . לפני ההתקנה — כל שינוי בקוד מבטל את ה־cache של npm install, וכל build מתקין הכול מחדש. קודם package*.json, התקנה, ורק אז הקוד.
  4. npm install במקום npm ci — לא בהכרח לפי ה־lock; ואין --omit=dev או multi-stage, אז כל ה־devDependencies (TypeScript, Jest...) נכנסים ל־image.
  5. סיסמה בתוך ה־image — כל מי שיש לו את ה־image (registry, מחשב של עמית) רואה אותה ב־docker image inspect. סודות — רק בזמן ריצה (-e, compose, מנהל סודות).
  6. רץ כ־root — אין USER.
  7. CMD npm start בצורת shell — יש shell ו־npm בין Docker לבין Node, ו־SIGTERM של docker stop לא תמיד מגיע לאפליקציה. CMD ["node", "dist/main.js"].
  8. ואין .dockerignore — סביר ש־.env ו־node_modules מהמחשב נכנסו עם COPY . ..
⚠️ טעויות נפוצות
  • לחשוב שסוד ב־ENV "בסדר כי ה־image פרטי". images מועברים, נשמרים ב־cache ובגיבויים — וזה תמיד דולף בסוף.

P23-E55 · מה נבנה מחדש? 🧠 הבנה רמה 2

💡 רמז 1

שכבה נבנית מחדש אם ההוראה שלה, או הקבצים שהיא מעתיקה, או כל שכבה לפניה השתנו.

💡 רמז 2

‏npm install zod משנה את package.json ואת package-lock.json.

✅ פתרון
  1. COPY src, ‏COPY README.md, ‏CMD. ‏npm ci — מה־cache.
  2. מ־COPY package.json ... והלאה — כולל npm ci.
  3. רק COPY README.md ו־CMD.
  4. רק CMD (מטא־דאטה — מהיר).
  5. הכול: ה־FROM השתנה, וכל השכבות נבנות עליו מחדש.

עוד שיפור קטן: README.md לא צריך להיות ב־image בכלל.

⚠️ טעויות נפוצות
  • לחשוב ש־Docker "יודע" אילו קבצים בתוך src השתנו כדי לחסוך. הוא בודק את התוכן של כל מה שה־COPY מעתיק, וכל שינוי — השכבה (וכל מה שאחריה) מחדש.

P23-E56 · ‏RUN, CMD, ENV, COPY — מתי כל אחד רץ? 🧠 הבנה רמה 1

💡 רמז 1

‏build מייצר image. ‏run מפעיל קונטיינר ממנו.

💡 רמז 2

‏EXPOSE ו־CMD נשמרים כמטא־דאטה של ה־image.

✅ פתרון
  • build: ‏FROM, ‏WORKDIR, ‏COPY, ‏RUN npm ci.
  • נרשם ב־image ופועל ב־run: ‏ENV (משתנה בקונטיינר), ‏CMD (מה רץ בעלייה), ‏EXPOSE (תיעוד בלבד).
  • CMD npm ci: ההתקנה הייתה רצה בכל עליית קונטיינר — איטי, וצריך רשת בפרודקשן. ‏RUN node server.mjs: ה־build היה "נתקע" — השרת רץ לנצח בזמן הבנייה.
⚠️ טעויות נפוצות
  • לשים migrations ב־RUN — בזמן build אין מסד (ואין אותו מסד שבו ה־image ירוץ). זה שירות נפרד (שיעור 5).

P23-E57 · ‏CMD במחרוזת או במערך? 🧠 הבנה רמה 2

💡 רמז 1

צורת מחרוזת = ‏/bin/sh -c "npm start".

💡 רמז 2

האם sh מעביר SIGTERM לילדים שלו? ו־npm?

✅ פתרון
  • (א) א: ‏sh, שמריץ את npm, שמריץ את node. ב: ‏node עצמו.
  • (ב) א: ה־SIGTERM מגיע ל־sh, שלא תמיד מעביר אותו הלאה. node לא יודע שצריך לעצור, ואחרי 10 שניות — SIGKILL. בקשות נקטעות. ב: node מקבל את האות, מסיים ויוצא תוך שנייה.
  • (ג) 10 × 10 שניות של המתנה, ובכל אחת — בקשות שנחתכות באמצע, במקום סגירה נקייה.
⚠️ טעויות נפוצות
  • לחשוב ש־npm start הוא "אותו דבר" כמו node .... בתוך קונטיינר, תוספת התהליך משנה איך מקבלים אותות.

P23-E58 · סוד ב־ARG ו־ENV 🧠 הבנה רמה 2

docker image inspect ו־docker history.

💡 רמז 2

כל RUN נשמר עם הפקודה שלו בהיסטוריה של ה־image.

✅ פתרון

⚠️ טעויות נפוצות
  • "זה רק סוד של פיתוח". ‏images יוצאים מהמחשב שלך יותר ממה שנדמה, וסודות "זמניים" נשארים.

P23-E60 · איפה הלכו 400MB? 🧠 הבנה רמה 2

💡 רמז 1

prisma (ה־CLI) ו־typescript הם כלים של בנייה.

💡 רמז 2

npm מסמן אותם devOptional.

✅ פתרון
  • (א) ה־CLI של Prisma ו־TypeScript — כלים לבנייה ול־migrations — בתוך image שרק מריץ.
  • (ב) ‏@prisma/client מגדיר אותם כ־optional peer dependencies, ו־npm מתקין אותם כ־"devOptional". ‏--omit=dev לבד לא מוריד אותם.

⚠️ טעויות נפוצות
  • למחוק תיקיות ב־RUN rm -rf node_modules/prisma — שביר, ולא מקטין את השכבה הקודמת.

P23-E12 · Dockerfile ראשון 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

חמש שורות: FROM, WORKDIR, COPY, EXPOSE, CMD.

💡 רמז 2

CMD ["node", "server.mjs"] — לא CMD node server.mjs.

✅ פתרון
FROM node:24-alpine
WORKDIR /app
COPY package.json server.mjs ./
EXPOSE 3000
CMD ["node", "server.mjs"]

EXPOSE לא פותח כלום — הוא תיעוד ("האפליקציה מאזינה ב־3000"). מה שפותח הוא -p 3000:3000 ב־docker run. ו־/health מחזיר node: "v24…" — מה שהבודק בודק: הגרסה של ה־image, לא של ה־Mac שלך.

⚠️ טעויות נפוצות
  • FROM node (בלי tag) = latest.

P23-E13 · .dockerignore 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

אותו תחביר כמו .gitignore: שורה לכל דפוס.

💡 רמז 2

.env.* תופס את .env.production; ואם יש .env.example שצריך — !.env.example.

✅ פתרון
# סודות — לעולם לא בתוך image
.env
.env.*
# נבנה מחדש בתוך ה־image, ולא בהכרח לאותה מערכת הפעלה

שני הנימוקים החשובים: סודות — .env שנכנס ל־image נשאר בו לתמיד; ו־node_modules מה־Mac — חבילות עם קוד native מקומפלות ל־macOS, ולא ירוצו ב־Linux של הקונטיינר. ובונוס: הקשר הבנייה (build context) קטן, וה־build מהיר.

⚠️ טעויות נפוצות
  • להסתמך על .gitignore — Docker לא קורא אותו.

P23-E14 · cache של שכבות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

Docker משתמש ב־cache לשכבה כל עוד כל מה שלפניה, וכל הקבצים שהיא מעתיקה, לא השתנו.

💡 רמז 2

COPY package.json package-lock.json ./ ← RUN npm ci --omit=dev ← COPY server.mjs ./.

✅ פתרון
FROM node:24-alpine
WORKDIR /app
# קודם רק מה שקובע את התלויות — השכבה הזו נשארת ב־cache כל עוד הם לא השתנו
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
# הקוד משתנה כל הזמן — הוא אחרון
COPY server.mjs ./
USER node
EXPOSE 3000
CMD ["node", "server.mjs"]

ב־docker build --progress=plain תראה את זה בעיניים: [3/5] RUN npm ci --omit=dev ← CACHED. בפרויקט עם 300 חבילות, זה ההבדל בין build של 5 שניות ל־2 דקות — בכל שינוי.

⚠️ טעויות נפוצות
  • COPY . . לפני npm ci — כל שינוי בקוד "מלכלך" את השכבה, וכל ההתקנה רצה מחדש.

P23-E15 · multi-stage ל־TypeScript 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

FROM node:24-alpine AS build, ובשלב השני COPY --from=build /app/dist ./dist.

💡 רמז 2

בשלב השני — שוב COPY package*.json ו־npm ci --omit=dev (כאן אין תלויות בכלל — אבל בפרויקט יש).

✅ פתרון
# שלב 1: קומפילציה — צריך typescript ו־@types (devDependencies)
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY tsconfig.json ./
COPY src ./src
RUN npm run build

# שלב 2: ריצה — רק JavaScript מקומפל ותלויות של production
FROM node:24-alpine
ENV NODE_ENV=production
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
USER node
EXPOSE 3000
CMD ["node", "dist/server.js"]

שלב ה־build נזרק אחרי הבנייה — רק מה שהועתק ממנו במפורש עובר. זה בדיוק ה־Dockerfile של פרויקט 2, בקטן.

⚠️ טעויות נפוצות
  • COPY --from=build /app ./ — מעתיק את הכול, כולל devDependencies, וכל היתרון נעלם.

P23-E16 · HEALTHCHECK ו־PORT 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

ב־alpine יש wget: wget -qO- http://127.0.0.1:$PORT/health || exit 1.

💡 רמז 2

כדי ש־$PORT יתורגם, ה־CMD של ה־HEALTHCHECK צריך להיות בצורת shell (מחרוזת), לא מערך.

✅ פתרון
FROM node:24-alpine
WORKDIR /app
COPY package.json server.mjs ./
ENV PORT=8080
EXPOSE 8080
USER node
# צורת shell (לא מערך) — כדי ש־$PORT יתורגם. wget קיים ב־alpine
HEALTHCHECK --interval=2s --timeout=2s --start-period=3s --retries=3 \
  CMD wget -qO- "http://127.0.0.1:$PORT/health" || exit 1
CMD ["node", "server.mjs"]

מה עושים עם healthcheck? docker ps מראה (healthy); ב־compose — depends_on: condition: service_healthy; ובפלטפורמות פריסה (פרק 25) — לא שולחים תעבורה לקונטיינר עד שהוא healthy, ומחליפים אותו כשהוא נהיה unhealthy.

⚠️ טעויות נפוצות
  • HEALTHCHECK עם localhost:8080 קבוע — עם PORT=9000 הקונטיינר "unhealthy" למרות שהוא עובד.

P23-E23 · עובד אצלי, לא ב־Docker 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

docker logs של הקונטיינר — על איזו כתובת ואיזה port הוא מאזין?

💡 רמז 2

127.0.0.1 בתוך קונטיינר = רק מתוך הקונטיינר. ו־-p 3000:3000 מעביר ל־3000 בתוכו.

✅ פתרון
// שרת קטן בלי תלויות. PORT ו־HOST מה־env
import http from "node:http";

const port = Number(process.env.PORT ?? 3000);
const host = process.env.HOST ?? "0.0.0.0"; // בתוך קונטיינר — חייב להאזין לכל הכתובות, לא רק ל־127.0.0.1

const server = http.createServer((req, res) => {
  if (req.url === "/health") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ ok: true, node: process.version }));
    return;
  }
  res.writeHead(404, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ error: "not found" }));
});

server.listen(port, host, () => console.log(`listening on ${host}:${port}`));

// docker stop שולח SIGTERM — סוגרים יפה, ולא מחכים 10 שניות ל־SIGKILL
process.on("SIGTERM", () => server.close(() => process.exit(0)));

הבאג הכי נפוץ במעבר ל־Docker: שרת שמאזין ל־127.0.0.1 מקבל חיבורים רק מתוך עצמו. Docker מעביר את התעבורה לכתובת של הקונטיינר ברשת שלו — אז צריך 0.0.0.0 ("כל הכתובות"). (Express ו־Nest מאזינים לכל הכתובות כברירת מחדל — לכן בפרויקט לא נתקלת בזה.)

⚠️ טעויות נפוצות
  • "לתקן" עם --network host — עובד רק ב־Linux, ומבטל את הבידוד.

P23-E59 · ‏Dockerfile לשירות עם PORT ו־healthcheck 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

העתק את המבנה מסעיף 2 בשיעור, והוסף ENV ו־HEALTHCHECK מסעיף 5.

💡 רמז 2
HEALTHCHECK CMD wget -qO- http://127.0.0.1:8080/health || exit 1
✅ פתרון
FROM node:24-alpine
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=8080
# קודם התלויות — משתנות לעתים רחוקות
COPY package.json package-lock.json ./

⚠️ טעויות נפוצות
  • USER node לפני RUN npm ci — ל־node אין הרשאה לכתוב ל־/app שנוצר כ־root.

P23-E61 · ‏SIGTERM ב־Node — סגירה נקייה 🧠 הבנה רמה 2

💡 רמז 1

server.close(cb) — מפסיק לקבל חיבורים חדשים, ו־cb נקרא כשהקיימים נגמרו.

💡 רמז 2

תהליך עם PID 1 בלינוקס לא מקבל את התנהגות ברירת המחדל של אותות (שהיא "למות").

✅ פתרון
  • (א) מפסיק לקבל חיבורים חדשים, נותן לבקשות הקיימות להסתיים, ורק אז קורא ל־callback. (חיבורי keep-alive פתוחים יכולים לעכב — server.closeIdleConnections() עוזר.)
  • (ב) ל־PID 1 אין "התנהגות ברירת מחדל" לאותות. בלי handler, SIGTERM פשוט לא עושה כלום, ו־Docker מחכה 10 שניות ושולח SIGKILL. (Nest עושה את זה עם app.enableShutdownHooks().)
  • (ג) ה־pool של המסד (await pool.end() / prisma.$disconnect()), כדי שחיבורים לא יישארו פתוחים בצד של PostgreSQL.
⚠️ טעויות נפוצות
  • process.exit(0) ישר ב־handler — זה kill -9 בנימוס: בקשות באמצע נחתכות.

P23-E62 · ‏npm ci ו־package-lock.json 🧠 הבנה רמה 2

💡 רמז 1

^1.2.0 ב־package.json מתיר גרסאות חדשות יותר. ה־lock מקבע אחת.

💡 רמז 2

‏npm ci לא כותב ל־lock — הוא דורש אותו.

✅ פתרון
  • (א) npm install פותר גרסאות לפי package.json ויכול לעדכן את ה־lock. ‏npm ci מתקין בדיוק מה שב־lock, מוחק node_modules קודם, ונכשל אם יש סתירה.
  • (ב) בלי lock — ‏npm ci נכשל מיד. ‏lock לא מתאים — נכשל עם הודעה שהם לא מסונכרנים. שני הכישלונות טובים: עדיף מ־build ש"עובד" עם גרסאות אחרות ממה שנבדק.
  • (ג) כדי שהשכבה של npm ci תיבנה מחדש רק כשהתלויות השתנו (סעיף 2).
⚠️ טעויות נפוצות
  • להוסיף package-lock.json ל־.gitignore "כי הוא גדול ועושה קונפליקטים".

P23-E63 · ‏lint ל־Dockerfile משלך 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

קודם: text.replace(/\\\r?\n/g, " ").split(/\r?\n/), ואז לכל שורה { cmd, args, stage } — ‏stage עולה בכל FROM.

💡 רמז 2

שם המשתנה ב־ENV/ARG: ‏args.split(/[=\s]/)[0].

✅ פתרון
// P23-E63: lint ל־Dockerfile
type Step = { cmd: string; args: string; stage: number };

function parse(text: string): Step[] {
  const out: Step[] = [];
  let stage = -1;
  for (const raw of text.replace(/\\\r?\n/g, " ").split(/\r?\n/)) {
    const line = raw.trim();
    if (!line || line.startsWith("#")) continue;
    const m = /^(\w+)\s+(.*)$/.exec(line);
    if (!m) continue;
    const cmd = m[1].toUpperCase();
    if (cmd === "FROM") stage++;
    out.push({ cmd, args: m[2].trim(), stage });
  }
  return out;
}

export function lintDockerfile(text: string): string[] {
  const steps = parse(text);
  const out: string[] = [];
  const froms = steps.filter((s) => s.cmd === "FROM").map((s) => s.args.split(/\s+/)[0]);
  if (froms.some((img) => (!img.includes(":") && !img.includes("@")) || img.endsWith(":latest"))) out.push("FROM בלי tag");
  if (steps.some((s) => s.cmd === "RUN" && /npm install\b/.test(s.args))) out.push("npm install במקום npm ci");
  const lastStage = Math.max(...steps.map((s) => s.stage));
  for (let st = 0; st <= lastStage; st++) {
    const inStage = steps.filter((s) => s.stage === st);
    const copyAll = inStage.findIndex((s) => s.cmd === "COPY" && /^\.\s+\.\/?$/.test(s.args));
    const install = inStage.findIndex((s) => s.cmd === "RUN" && /npm (ci|install)\b/.test(s.args));
    if (copyAll !== -1 && install !== -1 && copyAll < install) {
      out.push("COPY . . לפני התקנת התלויות");
      break;
    }
  }
  for (const s of steps) {
    if (s.cmd !== "ENV" && s.cmd !== "ARG") continue;
    const name = s.args.split(/[=\s]/)[0];
    if (/SECRET|PASSWORD|TOKEN|KEY/i.test(name)) out.push(`סוד ב־ENV או ARG: ${name}`);
  }
  if (!steps.some((s) => s.cmd === "USER" && s.stage === lastStage)) out.push("אין USER — רץ כ־root");
  const cmd = steps.filter((s) => s.cmd === "CMD").at(-1);
  if (cmd && !cmd.args.startsWith("[")) out.push("CMD בצורת מחרוזת");
  return out;
}

כלים אמיתיים (‏hadolint) עושים את אותו דבר, עם עשרות כללים. הרעיון זהה: לפרק את הקובץ להוראות, ולשאול שאלות על הסדר ועל התוכן. כך גם PR2-DOCKER בודק את ה־Dockerfile שלך.

⚠️ טעויות נפוצות
  • לבדוק "יש USER" בכל הקובץ — USER בשלב ה־build לא עוזר לשלב שרץ.

P23-E64 · האם הקובץ ייכנס ל־image? 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

הפוך כל תבנית ל־RegExp: ‏**/ ← (?:.*/)?, ‏** ← .*, ‏* ← [^/]*, ‏? ← [^/], ושאר התווים — escape. ואז ^...(?:/.*)?$.

💡 רמז 2

רץ על כל התבניות, ושמור let ignored = false — כל התאמה מעדכנת (‏! ← false).

✅ פתרון
// P23-E64: האם קובץ נכנס ל־build context
function toRegExp(pattern: string): RegExp {
  let re = "";
  for (let i = 0; i < pattern.length; i++) {
    const c = pattern[i];
    if (c === "*" && pattern[i + 1] === "*") {
      if (pattern[i + 2] === "/") {
        re += "(?:.*/)?";
        i += 2;
      } else {
        re += ".*";
        i += 1;
      }
    } else if (c === "*") re += "[^/]*";
    else if (c === "?") re += "[^/]";
    else re += c.replace(/[.+^${}()|[\]\\]/g, "\\$&");
  }
  return new RegExp(`^${re}(?:/.*)?$`);
}

export function isIgnored(file: string, patterns: string[]): boolean {
  let ignored = false;
  for (const raw of patterns) {
    let p = raw.trim();
    if (!p || p.startsWith("#")) continue;
    const negate = p.startsWith("!");
    if (negate) p = p.slice(1);
    p = p.replace(/^\/+|\/+$/g, "");
    if (toRegExp(p).test(file)) ignored = !negate;
  }
  return ignored;
}

"האחרונה שמתאימה קובעת" — לכן .env.* ואחריה !.env.example (שיעור 5) עובד: הדוגמה נכנסת, כל השאר לא. בסדר הפוך — ה־! לא היה עוזר.

⚠️ טעויות נפוצות
  • להפסיק בהתאמה הראשונה — ‏! לא עובד אף פעם.
  • * ← .* — ‏*.log היה תופס גם logs/app.log (ב־Docker הוא לא).

P23-E65 · ‏Dockerfile שמריץ בדיקות לפני build 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

‏RUN npm test בשלב ה־build — שם יש devDependencies (‏jest, ‏typescript).

💡 רמז 2

אם הבדיקות נכשלות, ה־exit code של ה־RUN הוא לא 0, ו־docker build נעצר. אין image.

✅ פתרון
# ---------- build: תלויות מלאות, בדיקות, קומפילציה ----------
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
# בדיקות שנכשלות ← ה־build נעצר, ואין image
RUN npm test
RUN npm run build
# ---------- runtime ----------
FROM node:24-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
USER node
CMD ["node", "dist/main.js"]

זה לא מחליף CI (פרק 25) — בדיקות integration צריכות מסד, ובתוך build אין. אבל בדיקות unit כאן מבטיחות שאף image שנבנה (גם ידנית, גם בשרת) לא נבנה מקוד שבדיקות ה־unit שלו אדומות.

⚠️ טעויות נפוצות
  • RUN npm test לפני COPY . . — אין עדיין בדיקות להריץ.
  • RUN npm test || true — "שה־build לא ייכשל". בדיוק הפוך מהמטרה.
