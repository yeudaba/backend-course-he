P23-E17 · compose: app ו־PostgreSQL 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

בתוך compose, כל שירות נגיש לאחרים לפי השם שלו: @db:5432, לא localhost.

💡 רמז 2

depends_on: db: condition: service_healthy — רק עם healthcheck ב־db.

✅ פתרון
services:
  db:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: visits
    volumes:
      - db-data:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d visits"]
      interval: 2s
      timeout: 3s
      retries: 30

  app:
    build: .
    environment:
      DATABASE_URL: postgresql://app:app@db:5432/visits # db = שם השירות, לא localhost
    ports:
      - "${APP_PORT:-3000}:3000"
    depends_on:
      db:
        condition: service_healthy

volumes:
  db-data:

שלושה דברים שכל compose של "אפליקציה + מסד" צריך: שם שירות כ־host, volume בשם (שורד down), וhealthcheck + condition (בלעדיהם האפליקציה עולה לפני שהמסד מוכן, ונופלת — E21).

⚠️ טעויות נפוצות
  • volume בלי שם (- /var/lib/postgresql) — volume אנונימי שקל לאבד.

P23-E21 · compose עם שלוש תקלות 🤖 💻 כתיבת קוד 🤖 רמה 4

docker compose logs app ו־docker compose logs db — כל אחת מהתקלות כתובה שם.

💡 רמז 2

(1) מה זה localhost בתוך קונטיינר? (2) depends_on בלי condition מחכה רק שהקונטיינר יעלה. (3) שיעור 4.

✅ פתרון

services:

(1) localhost בתוך קונטיינר הוא הקונטיינר עצמו — אין שם PostgreSQL. (2) "הקונטיינר עלה" זה לא "המסד מקבל חיבורים" — PostgreSQL צריך כמה שניות. (3) מ־18, הנתונים ב־/var/lib/postgresql/18/docker, וה־image מסרב לעלות כשיש mount ל־/var/lib/postgresql/data.

⚠️ טעויות נפוצות
  • לתקן את (2) עם restart: always — ה־app "מתאושש" אחרי כמה נפילות. עובד, אבל מסתיר את הבעיה ומלכלך את הלוגים.

P23-E24 · אתגר: nginx, app ומסד 🤖 💻 כתיבת קוד 🤖 רמה 5

💡 רמז 1

ב־nginx: location /api/ { proxy_pass http://app:3000/; } — ה־/ בסוף ה־proxy_pass הוא מה שמוריד את /api.

💡 רמז 2

שני bind mounts ל־web: ./web ← /usr/share/nginx/html, ו־./nginx.conf ← /etc/nginx/conf.d/default.conf.

✅ פתרון
services:
  db:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: visits
    volumes:
      - db-data:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d visits"]
      interval: 2s
      timeout: 3s
      retries: 30

  app:
    build: .
    environment:
      DATABASE_URL: postgresql://app:app@db:5432/visits
    depends_on:
      db:
        condition: service_healthy
    # בלי ports: נגיש רק מתוך הרשת של compose (דרך nginx)

  web:
    image: nginx:1.29-alpine
    volumes:
      - ./web:/usr/share/nginx/html:ro
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    ports:
      - "${WEB_PORT:-8080}:80"
    depends_on:
      - app

volumes:
  db-data:
server {
  listen 80;

  # הדף
  location / {
    root /usr/share/nginx/html;
    index index.html;
  }

  # כל מה שמתחיל ב־/api/ ← השירות app (בלי ה־/api)
  location /api/ {
    proxy_pass http://app:3000/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}

זה המבנה של הרבה מערכות אמיתיות: reverse proxy אחד בחזית, וכל השאר ברשת פנימית. יתרונות: הדף וה־API באותו origin (אין CORS בכלל); רק פורט אחד פתוח לעולם; ובפרק 25 — HTTPS במקום אחד.

⚠️ טעויות נפוצות
  • proxy_pass http://app:3000; בלי / בסוף — nginx מעביר את /api/visits כמו שהוא, וה־app מחזיר 404.

P23-E27 · קורא קובץ .env 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

לולאת for (let i = 0; i < lines.length; i++) ולא for...of, כי צריך את מספר השורה להודעה. ‏const eq = line.indexOf("="), ואז line.slice(0, eq) ו־line.slice(eq + 1). ‏split("=") היה חותך את הערך בכל =.

💡 רמז 2

שלושה מקרים לערך, לפי הסדר: מתחיל ונגמר ב־" ← value.slice(1, -1).replaceAll("\\n", "\n"). מתחיל ונגמר ב־' ← slice(1, -1). אחרת ← חותכים ב־indexOf(" #") אם יש. בדוק value.length >= 2, אחרת הערך " לבדו "מתחיל ונגמר" במירכאות.

✅ פתרון
// P23-E27 — קורא קובץ .env
export function parseEnv(text: string): Record<string, string> {
  const result: Record<string, string> = {};
  const lines = text.split("\n");
  for (let i = 0; i < lines.length; i++) {
    let line = lines[i].trim();
    if (line === "" || line.startsWith("#")) continue;
    if (line.startsWith("export ")) line = line.slice("export ".length).trim();

    const eq = line.indexOf("=");
    if (eq === -1) throw new SyntaxError(`שורה ${i + 1}: חסר =`);
    const key = line.slice(0, eq).trim();
    if (!/^[A-Za-z_][A-Za-z0-9_]*$/.test(key)) throw new SyntaxError(`שורה ${i + 1}: שם לא חוקי: ${key}`);

    let value = line.slice(eq + 1).trim();
    if (value.length >= 2 && value.startsWith('"') && value.endsWith('"')) {
      value = value.slice(1, -1).replaceAll("\\n", "\n");
    } else if (value.length >= 2 && value.startsWith("'") && value.endsWith("'")) {
      value = value.slice(1, -1);
    } else {
      const hash = value.indexOf(" #");
      if (hash !== -1) value = value.slice(0, hash).trim();
    }
    result[key] = value;
  }
  return result;
}

const env = parseEnv(`
# מסד הנתונים
DATABASE_URL=postgres://app:secret@db:5432/app?sslmode=disable

PATTERN='a#b\\n'

SyntaxError שורה 2: שם לא חוקי: 2B

PORT מופיע פעמיים, וה־8080 המאוחר קובע. זו ההתנהגות של רוב הכלים, וכך אפשר לדרוס ערך בסוף הקובץ. בתוך מירכאות בודדות שום דבר לא מתפרש: ‏# נשאר, וגם \n נשאר שני תווים.

למה SyntaxError עם מספר שורה? קובץ .env שבור הוא תקלה שמגלים בעלייה של הקונטיינר. ההודעה "שורה 2: שם לא חוקי: 2B" מראה מיד איפה הבעיה. ‏undefined שקט היה מתגלה רק כשמשהו בשרת מתנהג מוזר.

בפרויקט לא כותבים את זה בעצמך: Node 24 קורא .env עם --env-file, ו־compose עם env_file. אבל עכשיו אתה יודע למה PASSWORD=a#b עובד, ו־PASSWORD=a #b מאבד חצי מהסיסמה.

⚠️ טעויות נפוצות
  • line.split("=") — ‏DATABASE_URL עם ?sslmode=disable נחתך באמצע.
  • לחתוך הערה בכל # — סיסמה כמו a#b נחתכת ל־a. הערה מתחילה רק ב־ #, ורק מחוץ למירכאות.
  • להחליף \n גם במירכאות בודדות — שם הערך מילולי.
  • לבדוק את השם לפני שמורידים export — ‏export PORT נראה כמו שם עם רווח.
