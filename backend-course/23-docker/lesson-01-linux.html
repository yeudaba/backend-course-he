1. למה Linux?

השרתים שלך — בענן, בחברה, בתוך קונטיינרים — רצים כמעט תמיד על Linux. כשמשהו לא עובד בפרודקשן, אתה מתחבר לשם (או לקונטיינר) ויש לך רק טרמינל: לקרוא לוגים, לבדוק מה רץ, לראות מה תופס את הדיסק. ה־Mac שלך הוא "בן דוד" של Linux (Unix): רוב הפקודות זהות. ההבדלים הקטנים — בהמשך.

מקוםמה יש שם
/השורש של הכול
~ (/home/dana; ב־Mac /Users/dana)תיקיית הבית שלך
/etcהגדרות (למשל /etc/nginx/)
/var/logלוגים של המערכת ושל שירותים
/tmpקבצים זמניים — נמחקים
/usr/bin, /usr/local/binתוכנות (which node — איפה בדיוק)

2. הרשאות

ls -l מראה לכל קובץ עשרה תווים: -rw-r--r--. התו הראשון — סוג (- קובץ, d תיקייה), ואז שלוש שלשות: בעלים, קבוצה, כל השאר; בכל אחת r (קריאה), w (כתיבה), x (הרצה). במספרים: r=4, w=2, x=1, ומחברים:

touch script.sh secrets.env
chmod 755 script.sh
chmod 600 secrets.env
ls -l script.sh secrets.env | cut -c1-10
-rwxr-xr-x
-rw-------

755 — סקריפטים ותיקיות (כולם קוראים ומריצים, רק אתה כותב). 644 — קבצים רגילים. 600 — סודות: .env, מפתח SSH. ו־chmod +x deploy.sh — "מותר להריץ" (אחרת ./deploy.sh נותן permission denied).

3. תהליכים, ports ואותות

% lsof -nP -iTCP:3000 -sTCP:LISTEN
COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
node    5310 root   21u  IPv4  14504      0t0  TCP *:3000 (LISTEN)
% kill 5310

(פלט אמיתי, משרת Linux.) "port 3000 already in use" — lsof מראה מי (-nP — מספרים במקום שמות, -sTCP:LISTEN — רק מי שמאזין), ו־kill <PID> שולח לו SIGTERM: "סגור בבקשה". אפליקציה טובה מסיימת בקשות, סוגרת חיבורים למסד ויוצאת. kill -9 שולח SIGKILL — התהליך נעצר מיד, באמצע מה שעשה. זה מוצא אחרון. (וזה בדיוק מה ש־docker stop עושה: SIGTERM, ואחרי 10 שניות — SIGKILL. בשיעור 3 נראה למה זה חשוב.)

4. משתני סביבה ו־exit codes

export GREETING="שלום"
echo "$GREETING, $USER_NAME_THAT_DOES_NOT_EXIST!"
GREETING="hi" bash -c 'echo "in a child: $GREETING"'
false
echo "exit code of false: $?"
true
echo "exit code of true: $?"
שלום, !
in a child: hi
exit code of false: 1
exit code of true: 0

משתנה שלא הוגדר הוא פשוט ריק — בלי שגיאה (בהמשך — set -u משנה את זה). VAR=x command מגדיר משתנה רק לפקודה אחת. ו־$? — ה־exit code של הפקודה הקודמת: 0 = הצלחה, כל דבר אחר = כישלון. כל כלי שמריץ פקודות — CI, Docker, && — מחליט לפי המספר הזה.

5. pipelines — ארגז הכלים לטקסט

לוגים, CSV, פלט של פקודות — הכול טקסט. כל פקודה עושה דבר אחד, ו־| מחבר אותן:

printf 'dana /tasks\nyossi /tasks\ndana /docs\nrona /tasks\ndana /tasks\nyossi /health\n' > visits.txt
echo "--- who, how many:"
cut -d' ' -f1 visits.txt | sort | uniq -c | sort -rn | awk '{print $1, $2}'
echo "--- only /tasks:"
grep -c ' /tasks$' visits.txt
echo "--- sum with awk:"
printf 'a,10\nb,5\na,2.5\n' | awk -F, '{ s[$1] += $2 } END { for (k in s) print k, s[k] }' | sort
--- who, how many:
3 dana
2 yossi
1 rona
--- only /tasks:
4
--- sum with awk:
a 12.5
b 5
פקודהמה
grep (-c, -v, -i, -r, -n)שורות שמתאימות (ספירה, הפוך, בלי אותיות, רקורסיבי, מספרי שורות)
cut -d, -f2עמודה לפי מפריד
awk '{print $1}'עמודות לפי רווח — וגם חישובים, תנאים ומערכים
sort (-n, -r, -k2,2)מיון (מספרי, הפוך, לפי עמודה)
uniq -cספירת כפילויות צמודות — לכן תמיד אחרי sort
head, tail (-n, -f)התחלה, סוף, ומעקב אחרי קובץ שגדל
wc -lכמה שורות
> · >> · 2> · 2>&1פלט לקובץ · הוספה · שגיאות לקובץ · שגיאות לאותו מקום כמו הפלט

6. סקריפט בטוח

backup.sh 
#!/usr/bin/env bash
set -euo pipefail                       # עוצר על שגיאה, משתנה לא מוגדר, וכישלון באמצע pipeline

if [ $# -ne 2 ]; then                   # $# — כמה ארגומנטים
  echo "שימוש: backup.sh <מקור> <יעד>" >&2   # שגיאות — ל־stderr
  exit 2
fi

src="$1"                                # תמיד במרכאות: "my data" הוא ארגומנט אחד
mkdir -p "$2"
cp "$src"/*.json "$2"/

מה המרכאות עושות? בלעדיהן, bash מפרק ערכים לפי רווחים:

name="my data"
mkdir -p "$name"
ls -d $name 2>&1 | sed 's/^ls: //'
ls -d "$name"
cannot access 'my': No such file or directory
cannot access 'data': No such file or directory
my data

בלי מרכאות, $name הפך לשני ארגומנטים — my ו־data — ואף אחד מהם לא קיים. בתוך סקריפט שעושה rm, זה ההבדל בין "מחקתי את התיקייה" ל"מחקתי משהו אחר".

⚠️ Mac מול Linux

ב־Mac הטרמינל הוא zsh, ו־bash שמגיע עם macOS ישן (3.2). כמה כלים שונים מעט: sed -i '' ב־Mac מול sed -i ב־Linux; wc -l ב־Mac מוסיף רווחים לפני המספר; date -d לא קיים ב־Mac. בסקריפטים שצריכים לרוץ בשני המקומות — כלים פשוטים (awk, sort, cut), ו־tr -d ' ' כשצריך מספר נקי. והבודק מריץ את הסקריפטים שלך עם bash.
