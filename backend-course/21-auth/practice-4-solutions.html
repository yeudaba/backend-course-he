P21-E03 · 401, 403 או 404? 🧠 הבנה רמה 1

💡 רמז 1

401 — "לא יודע מי אתה". 403 — "יודע, ואסור". 404 — "אין (בשבילך)".

💡 רמז 2

מה יוסי יכול ללמוד אם (3) יחזיר 403?

✅ פתרון
  1. 401 UNAUTHORIZED — אין זהות בכלל.
  2. 401 INVALID_TOKEN ("פג תוקף הטוקן") — הטוקן כבר לא מוכיח זהות. הלקוח צריך לעשות refresh ולנסות שוב.
  3. 404 TASK_NOT_FOUND — מבחינת יוסי המשימה לא קיימת. 403 היה מגלה לו ש־5 קיים (ומאפשר לסרוק אילו מספרים קיימים).
  4. 403 FORBIDDEN — דנה מזוהה, אבל הפעולה עצמה אסורה לתפקיד שלה. כאן אין מה להסתיר: כולם יודעים שיש /users.
  5. 404 — בדיוק כמו (3). וזה העיקר: יוסי לא יכול להבדיל בין "לא קיים" ל"לא שלך".
  6. 401 INVALID_CREDENTIALS.
⚠️ טעויות נפוצות
  • 403 על משאב של משתמש אחר — "נכון" מבחינת השם, ודולף מבחינת אבטחה.
  • 403 כשאין טוקן — הלקוח לא יבין שצריך להתחבר. 401 אומר "תתחבר"; 403 אומר "גם אם תתחבר — לא".

P21-E05 · מצא את הפרצות 🧠 הבנה רמה 1

💡 רמז 1

עבור שורה אחר שורה. בכל שורה שאל: מה אם הלקוח שולח משהו שלא ציפיתי? ומה אם מישהו קורא את זה?

💡 רמז 2

יש בעיות בסוד, ב־body, בלוג, בהודעות השגיאה, בהשוואה, בטוקן (שלוש!), וב־route האחרון.

✅ פתרון
  1. סוד קצר וקבוע בקוד — "secret" ננחש תוך שניות, ונמצא בכל עותק של הקוד ב־Git. ← סוד אקראי ארוך מ־env.
  2. סיסמה נשמרת כמו שהיא (password: body.password) ← bcrypt.hash, ועמודה בשם passwordHash.
  3. mass assignment — ...body מאפשר לשלוח "role":"admin". ← schema מחמיר (strict), ושדות מפורשים.
  4. מחזירים את כל המשתמש מההרשמה — כולל הסיסמה. ← toPublicUser.
  5. סיסמה בלוג ← לעולם לא. לכל היותר האימייל, ובזהירות.
  6. user enumeration — 404 "אין משתמש" מול 401 "סיסמה שגויה". ← אותה תשובה (401) לשניהם, ו־compare מול hash דמה.
  7. השוואה ישירה (!==) — נובעת מבעיה 2. ← bcrypt.compare.
  8. הסיסמה והאימייל בתוך ה־JWT — כל אחד קורא את ה־payload. ← רק sub ו־role.
  9. JWT בלי expiresIn — תקף לנצח. ← 15 דקות + refresh.
  10. IDOR ב־orders/:id — אין התחברות ואין בדיקת בעלות: כל אחד עובר על כל ההזמנות. ← guard, ו־where: { id, userId: user.id } עם 404.
⚠️ טעויות נפוצות
  • למצוא את הבעיות ה"גדולות" ולפספס את הלוג — בפועל, לוגים הם אחד המקומות הנפוצים לדליפת סיסמאות.

P21-E08 · הרשמה 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

אם תנרמל את האימייל רק ב־service — @IsEmail() ייכשל קודם על הרווחים. צריך לנרמל לפני הבדיקה.

💡 רמז 2

@Transform(({ value }) => ...) מ־class-transformer רץ (עם transform: true) לפני ה־decorators של class-validator.

✅ פתרון
// P21-E08
import { Body, ConflictException, Controller, Inject, Injectable, Module, Post } from "@nestjs/common";
import bcrypt from "bcryptjs";
import { Transform } from "class-transformer";
import { IsEmail, IsString, MaxLength, MinLength } from "class-validator";

export const BCRYPT_ROUNDS = "BCRYPT_ROUNDS";

export class RegisterDto {
  // רץ לפני הבדיקה (transform: true): "  Dana@Example.com " ← "dana@example.com"
  @Transform(({ value }) => (typeof value === "string" ? value.trim().toLowerCase() : value))
  @IsEmail()
  @MaxLength(254)
  email: string;

  @IsString()
  @MinLength(8)
  password: string;
}

export interface User {
  id: number;
  email: string;
  passwordHash: string;
  role: "user" | "admin";
}

@Injectable()
export class UsersService {
  private readonly users: User[] = [];

  constructor(@Inject(BCRYPT_ROUNDS) private readonly rounds: number) {}

  findByEmail(email: string) {
    return this.users.find((u) => u.email === email);
  }

  async register(dto: RegisterDto) {
    const email = dto.email;
    if (this.findByEmail(email)) throw new ConflictException("האימייל כבר רשום");
    const user: User = { id: this.users.length + 1, email, passwordHash: await bcrypt.hash(dto.password, this.rounds), role: "user" };
    this.users.push(user);
    const { passwordHash, ...publicUser } = user; // hash לא יוצא החוצה
    return publicUser;
  }
}

@Controller("auth")
export class AuthController {
  constructor(private readonly users: UsersService) {}

  @Post("register")
  register(@Body() dto: RegisterDto) {
    return this.users.register(dto);
  }
}

@Module({
  controllers: [AuthController],
  providers: [UsersService, { provide: BCRYPT_ROUNDS, useValue: 12 }],
})
export class AuthModule {}

ה־role נחסם פעמיים: forbidNonWhitelisted מחזיר {"message":["property role should not exist"],"error":"Bad Request","statusCode":400} (פלט אמיתי), וגם אם מישהו יכבה את זה מחר — ה־service קובע role: "user" בעצמו. שתי שכבות הגנה, כל אחת מספיקה לבד.

⚠️ טעויות נפוצות
  • { ...dto, passwordHash, role: "user" } — עובד כאן, אבל ה־password המקורי נשמר במשתמש! בונים את האובייקט משדות מפורשים.
  • return user — עם ה־hash.

P21-E13 · תפקידים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

אותו getAllAndOverride כמו ב־@Public(): מה שעל המתודה גובר על מה שעל ה־class.

💡 רמז 2

כמה APP_GUARD ב־providers — רצים לפי סדר הרישום.

✅ פתרון
// P21-E13
import {
  CanActivate, Controller, Delete, ExecutionContext, ForbiddenException, Get, HttpCode, Injectable, Module, Param,
  SetMetadata, UnauthorizedException,
} from "@nestjs/common";
import { APP_GUARD, Reflector } from "@nestjs/core";

export type Role = "user" | "manager" | "admin";

// מדמה התחברות בשביל התרגיל (במקום JWT): x-user-id ו־x-user-role ב־headers
@Injectable()
export class FakeAuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest();
    const id = Number(req.get("x-user-id"));
    if (!Number.isInteger(id) || id < 1) throw new UnauthorizedException("נדרשת התחברות");
    req.user = { id, role: req.get("x-user-role") ?? "user" };
    return true;
  }
}

export const ROLES = "roles";
export const Roles = (...roles: Role[]) => SetMetadata(ROLES, roles);

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const roles = this.reflector.getAllAndOverride<Role[] | undefined>(ROLES, [context.getHandler(), context.getClass()]);
    if (!roles || roles.length === 0) return true;
    const user = context.switchToHttp().getRequest().user;
    if (!user || !roles.includes(user.role)) throw new ForbiddenException("אין הרשאה");
    return true;
  }
}

@Controller("reports")
@Roles("manager", "admin")
export class ReportsController {
  @Get()
  list() {
    return [{ id: 1, title: "מכירות נובמבר" }];
  }

  @Delete(":id")
  @Roles("admin") // מחליף את מה שעל ה־class
  @HttpCode(204)
  remove(@Param("id") id: string) {}
}

@Controller("profile")
export class ProfileController {
  @Get()
  profile() {
    return { ok: true };
  }
}

@Module({
  controllers: [ReportsController, ProfileController],
  providers: [
    { provide: APP_GUARD, useClass: FakeAuthGuard }, // קודם "מי אתה"
    { provide: APP_GUARD, useClass: RolesGuard }, // אחר כך "מה מותר"
  ],
})
export class ReportsModule {}

"Override" ולא "merge": על DELETE, @Roles("admin") מחליף את ("manager", "admin") של ה־class — ולכן manager מקבל 403. אם היית רוצה איחוד, היית משתמש ב־getAllAndMerge.

⚠️ טעויות נפוצות
  • RolesGuard לפני FakeAuthGuard ← אין עדיין req.user, ומשתמש לא מחובר מקבל 403.
  • roles.includes(user.role) כש־roles הוא undefined ← קריסה (500). קודם בודקים שיש בכלל @Roles.

@Injectable()

    if (!Number.isInteger(id) || id < 1) throw new UnauthorizedException("נדרשת התחברות");

export interface Note {
  id: number;
  ownerId: number;
  text: string;
}

@Injectable()
export class NotesService {
  private readonly notes: Note[] = [
    { id: 1, ownerId: 1, text: "הפתק של דנה" },
    { id: 2, ownerId: 2, text: "הפתק של יוסי" },
    { id: 3, ownerId: 1, text: "עוד פתק של דנה" },
  ];

  list(user: AuthUser, all: boolean) {
    if (all && user.role !== "admin") throw new ForbiddenException("רק admin רואה הכול");
    return all ? this.notes : this.notes.filter((n) => n.ownerId === user.id);
  }

  // בעלות בכל פעולה. של מישהו אחר ← 404, כאילו לא קיים
  private findOwn(user: AuthUser, id: number) {
    const note = this.notes.find((n) => n.id === id && n.ownerId === user.id);
    if (!note) throw new NotFoundException(`פתק ${id} לא נמצא`);
    return note;
  }

  get(user: AuthUser, id: number) {
    return this.findOwn(user, id);
  }

  update(user: AuthUser, id: number, text: string) {
    const note = this.findOwn(user, id);
    note.text = text;
    return note;
  }

  remove(user: AuthUser, id: number) {
    const note = this.findOwn(user, id);
    this.notes.splice(this.notes.indexOf(note), 1);
  }
}

@Controller("notes")
export class NotesController {
  constructor(private readonly notes: NotesService) {}

  @Get()
  list(@Req() req: { user: AuthUser }, @Query("all") all?: string) {
    return this.notes.list(req.user, all === "true");
  }

  @Get(":id")
  get(@Req() req: { user: AuthUser }, @Param("id", ParseIntPipe) id: number) {
    return this.notes.get(req.user, id);
  }

  @Patch(":id")
  update(@Req() req: { user: AuthUser }, @Param("id", ParseIntPipe) id: number, @Body() body: { text: string }) {
    return this.notes.update(req.user, id, String(body.text));
  }

  @Delete(":id")
  @HttpCode(204)
  remove(@Req() req: { user: AuthUser }, @Param("id", ParseIntPipe) id: number) {
    this.notes.remove(req.user, id);
  }
}

@Module({
  controllers: [NotesController],
  providers: [NotesService, { provide: APP_GUARD, useClass: FakeAuthGuard }],
})
export class NotesModule {}

findOwn היא כל הסיפור: אין דרך להגיע לפתק בלי לעבור דרכה. במסד זה ה־WHERE id = ? AND owner_id = ? מהשיעור. ו־?all=true הוא דוגמה לפעולה שהיא עצמה אסורה (403), להבדיל מאובייקט של אחר (404).

⚠️ טעויות נפוצות
  • לבדוק בעלות ב־get ולשכוח ב־remove — בדיוק הבאג של E22.
  • throw new ForbiddenException() כשהפתק של מישהו אחר — מגלה שהוא קיים.

P21-E19 · נעילה אחרי ניסיונות כושלים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

לכל אימייל — מערך של זמני כישלון. בכל פעם מסננים את מה שישן מ־15 דקות.

💡 רמז 2

אם יש 5 ומעלה בחלון: נפתח ב־list[list.length - 5] + WINDOW_MS. ו־Math.ceil לשניות.

✅ פתרון
// P21-E19
import { Body, Controller, HttpCode, HttpException, HttpStatus, Inject, Injectable, Module, Post, Res, UnauthorizedException } from "@nestjs/common";
import type { Response } from "express";

export const CLOCK = "CLOCK";
export interface Clock {
  now(): Date;
}

export const MAX_FAILURES = 5;
export const WINDOW_MS = 15 * 60 * 1000;

@Injectable()
export class LoginAttemptsService {
  // לכל אימייל: מתי היו הכישלונות האחרונים
  private readonly failures = new Map<string, number[]>();

  constructor(@Inject(CLOCK) private readonly clock: Clock) {}

  private recent(email: string) {
    const now = this.clock.now().getTime();
    const list = (this.failures.get(email) ?? []).filter((t) => now - t < WINDOW_MS);
    this.failures.set(email, list);
    return list;
  }

  // כמה שניות לחכות, או 0 אם מותר לנסות
  retryAfterSeconds(email: string): number {
    const list = this.recent(email);
    if (list.length < MAX_FAILURES) return 0;
    const unlockAt = list[list.length - MAX_FAILURES] + WINDOW_MS;
    return Math.ceil((unlockAt - this.clock.now().getTime()) / 1000);
  }

  recordFailure(email: string) {
    this.failures.set(email, [...this.recent(email), this.clock.now().getTime()]);
  }

  reset(email: string) {
    this.failures.delete(email);
  }
}

@Controller("auth")
export class AuthController {
  constructor(private readonly attempts: LoginAttemptsService) {}

  @Post("login")
  @HttpCode(200)
  login(@Body() body: { email: string; password: string }, @Res({ passthrough: true }) res: Response) {
    const email = String(body.email).trim().toLowerCase(); // אחרת Dana@ ו־dana@ — שני מונים
    const wait = this.attempts.retryAfterSeconds(email);
    if (wait > 0) {
      res.setHeader("Retry-After", String(wait));
      throw new HttpException("יותר מדי ניסיונות. נסה שוב מאוחר יותר", HttpStatus.TOO_MANY_REQUESTS);
    }
    // בתרגיל: סיסמה "נכונה" היא correct-password (בפרויקט — bcrypt)
    if (body.password !== "correct-password") {
      this.attempts.recordFailure(email);
      throw new UnauthorizedException("אימייל או סיסמה שגויים");
    }
    this.attempts.reset(email);
    return { ok: true };
  }
}

@Module({
  controllers: [AuthController],
  providers: [LoginAttemptsService, { provide: CLOCK, useValue: { now: () => new Date() } }],
})
export class AuthModule {}

למה גם סיסמה נכונה נחסמת בזמן נעילה? אחרת התוקף פשוט ממשיך לנחש, ומחכה לתשובה שאינה 429 — כלומר הנעילה לא עוצרת כלום. החיסרון: תוקף יכול לנעול משתמש אמיתי בכוונה (לכן נעילה זמנית, ולכן בפרודקשן מוסיפים גם הגבלה לפי IP — פרק 24).

⚠️ טעויות נפוצות
  • לא לנרמל את האימייל — חמישה ניסיונות לכל גרסת אותיות.
  • לשמור את המונה בזיכרון השרת כשיש כמה שרתים — כל אחד סופר לבד. בפרק 26 — Redis.

// מדמה התחברות בשביל התרגיל (במקום JWT): x-user-id ב־header

export class UpdateNoteDto {
  @IsOptional()
  @IsString()
  @Length(1, 500)
  text?: string;
  // ← תקלה 3: היה כאן ownerId — הלקוח יכול היה "להעביר" פתק למשתמש אחר
}

interface Note {
  id: number;
  ownerId: number;
  text: string;
}

@Injectable()
export class NotesService {
  private readonly notes: Note[] = [
    { id: 1, ownerId: 1, text: "הפתק של דנה" },
    { id: 2, ownerId: 2, text: "הפתק של יוסי" },

  private findOwn(userId: number, id: number) {

    if (!note) throw new NotFoundException(`פתק ${id} לא נמצא`);

    if (dto.text !== undefined) note.text = dto.text;
    return note;

  }
}

  }

// P21-E25
import { createHash, randomBytes, timingSafeEqual } from "node:crypto";
import {
  Body, CanActivate, Controller, Delete, ExecutionContext, ForbiddenException, Get, HttpCode, Inject, Injectable, Module,
  NotFoundException, Param, ParseIntPipe, Post, Req, SetMetadata, UnauthorizedException, UseGuards,
} from "@nestjs/common";
import { Reflector } from "@nestjs/core";

export const CLOCK = "CLOCK";
export interface Clock {
  now(): Date;
}
export type Scope = "read" | "write";

// מדמה התחברות של משתמש (במקום JWT): x-user-id ב־header — לניהול המפתחות
@Injectable()
export class FakeAuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest();
    const id = Number(req.get("x-user-id"));
    if (!Number.isInteger(id) || id < 1) throw new UnauthorizedException("נדרשת התחברות");
    req.user = { id };
    return true;
  }
}

interface ApiKeyRecord {
  id: number;
  userId: number;
  name: string;
  prefix: string;
  hash: string;
  scopes: Scope[];
  createdAt: string;
  lastUsedAt: string | null;
  revokedAt: string | null;
}

const sha256 = (v: string) => createHash("sha256").update(v).digest();
const KEY_FORMAT = /^tk_([0-9a-f]{8})_[A-Za-z0-9_-]{32}$/;

@Injectable()
export class ApiKeysService {
  private readonly keys: ApiKeyRecord[] = [];

  constructor(@Inject(CLOCK) private readonly clock: Clock) {}

  // המפתח המלא מוחזר פעם אחת בלבד. נשמרים: prefix (לחיפוש ולתצוגה) ו־hash
  create(userId: number, name: string, scopes: Scope[]) {
    const prefix = randomBytes(4).toString("hex");
    const key = `tk_${prefix}_${randomBytes(24).toString("base64url")}`;
    const record: ApiKeyRecord = {
      id: this.keys.length + 1, userId, name, prefix, hash: sha256(key).toString("hex"), scopes,
      createdAt: this.clock.now().toISOString(), lastUsedAt: null, revokedAt: null,
    };
    this.keys.push(record);
    return { id: record.id, name, prefix, scopes, key };
  }

  list(userId: number) {
    return this.keys
      .filter((k) => k.userId === userId)
      .map(({ id, name, prefix, scopes, createdAt, lastUsedAt, revokedAt }) => ({ id, name, prefix, scopes, createdAt, lastUsedAt, revoked: revokedAt !== null }));
  }

  revoke(userId: number, id: number) {
    const record = this.keys.find((k) => k.id === id && k.userId === userId);
    if (!record) throw new NotFoundException(`מפתח ${id} לא נמצא`);
    record.revokedAt ??= this.clock.now().toISOString();
  }

  authenticate(key: string): { userId: number; scopes: Scope[] } | undefined {
    const prefix = KEY_FORMAT.exec(key)?.[1];
    if (!prefix) return undefined;
    const record = this.keys.find((k) => k.prefix === prefix && k.revokedAt === null);
    if (!record || !timingSafeEqual(sha256(key), Buffer.from(record.hash, "hex"))) return undefined;
    record.lastUsedAt = this.clock.now().toISOString();
    return { userId: record.userId, scopes: record.scopes };
  }
}

const SCOPE = "scope";
export const RequireScope = (scope: Scope) => SetMetadata(SCOPE, scope);

@Injectable()
export class ApiKeyGuard implements CanActivate {
  constructor(private readonly keys: ApiKeysService, private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest();
    const key = req.get("x-api-key");
    if (!key) throw new UnauthorizedException("חסר X-Api-Key");
    const auth = this.keys.authenticate(key);
    if (!auth) throw new UnauthorizedException("מפתח לא תקין");
    const scope = this.reflector.get<Scope | undefined>(SCOPE, context.getHandler());
    if (scope && !auth.scopes.includes(scope)) throw new ForbiddenException(`למפתח אין הרשאת ${scope}`);
    req.apiKey = auth;
    return true;
  }
}

@Controller("keys")
@UseGuards(FakeAuthGuard)
export class KeysController {
  constructor(private readonly keys: ApiKeysService) {}

  @Post()
  create(@Req() req: { user: { id: number } }, @Body() body: { name: string; scopes: Scope[] }) {
    const scopes = (Array.isArray(body.scopes) ? body.scopes : []).filter((s): s is Scope => s === "read" || s === "write");
    return this.keys.create(req.user.id, String(body.name), scopes.length ? scopes : ["read"]);
  }

  @Get()
  list(@Req() req: { user: { id: number } }) {
    return this.keys.list(req.user.id);
  }

  @Delete(":id")
  @HttpCode(204)
  revoke(@Req() req: { user: { id: number } }, @Param("id", ParseIntPipe) id: number) {
    this.keys.revoke(req.user.id, id);
  }
}

@Controller("data")
@UseGuards(ApiKeyGuard)
export class DataController {
  @Get()
  @RequireScope("read")
  read(@Req() req: { apiKey: { userId: number } }) {
    return { data: [1, 2, 3], owner: req.apiKey.userId };
  }

  @Post()
  @RequireScope("write")
  write(@Req() req: { apiKey: { userId: number } }) {
    return { saved: true, owner: req.apiKey.userId };
  }
}

@Module({
  controllers: [KeysController, DataController],
  providers: [ApiKeysService, FakeAuthGuard, ApiKeyGuard, { provide: CLOCK, useValue: { now: () => new Date() } }],
})
export class ApiKeysModule {}

זה המבנה של מפתחות אמיתיים (GitHub, Stripe ודומיהם): קידומת שמזהה את סוג המפתח (tk_) — כך כלים שסורקים קוד ב־Git מזהים מפתח שדלף; prefix גלוי שמאפשר להציג "tk_3f9a…" ברשימה ולמצוא את הרשומה בלי לסרוק הכול; ו־hash בלבד במסד. ו־scopes: מפתח של CI שרק קורא לא צריך הרשאת כתיבה — אם הוא ידלוף, הנזק מוגבל ("least privilege").
