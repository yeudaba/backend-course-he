P21-E15 · refresh token אטום 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

בקובץ 21-auth/starter/P21-E15.ts השלם את RefreshTokenService:

  • issue(userId) ← 32 בתים אקראיים ב־base64url (43 תווים). באחסון (records) המפתח הוא ה־SHA-256 (hex) של הטוקן — לא הטוקן. תוקף: 7 ימים לפי CLOCK.

P21-E65 · ‏UPDATE עם תנאי, או SELECT ואז UPDATE?

🧠 הבנהרמה 2⏱ 10 דק׳ידע נדרש: פרק 18, שיעור 3

שתי גרסאות של revoke. בשתיהן שתי בקשות refresh עם אותו טוקן מגיעות יחד:

-- גרסה א: שתי פקודות
SELECT revoked_at FROM refresh_tokens WHERE id = $1;
-- (בקוד: אם revoked_at הוא null ←)
UPDATE refresh_tokens SET revoked_at = now() WHERE id = $1;

-- גרסה ב: פקודה אחת, ובודקים rowCount
UPDATE refresh_tokens SET revoked_at = now() WHERE id = $1 AND revoked_at IS NULL;

(א) מה יכול לקרות בגרסה א, צעד אחר צעד? (ב) למה בגרסה ב רק אחת מקבלת rowCount = 1? (ג) איך עושים את גרסה ב ב־Prisma?

P21-E28 · רשימת חסימה לטוקנים 🤖

💻 כתיבת קוד 🤖🔁 חזרהרמה 3⏱ 20 דק׳ידע נדרש: שיעור 3

🔁 חזרה על class עם שדות פרטיים ו־getter (פרק 12), ‏Map ומחיקה תוך כדי מעבר (פרק 7), ושעון מוזרק (‏P21-E12). access token אי אפשר "לבטל": הוא תקף עד ה־exp שלו. כשחייבים לבטל אחד מיד (משתמש נחסם, טוקן דלף), שומרים את המזהה שלו (jti) ברשימת חסימה, עד שהוא פג ממילא. כתוב וייצא class TokenBlocklist:

  • constructor(now = () => Math.floor(Date.now() / 1000)) — שעון בשניות, שאפשר להחליף בבדיקות.
  • block(jti, exp) — חוסמת עד exp. טוקן שכבר פג (exp <= now()) — לא נשמר בכלל.
  • isBlocked(jti) — ‏true רק אם הוא ברשימה ועוד לא פג.
  • cleanup() — מוחקת את כל מה שפג, ומחזירה כמה נמחקו.
  • getter size. הנתונים בשדות פרטיים.

🔗 איך זה מתחבר: class עם שדות פרטיים מפרק 12 ו־Map מפרק 7 — והשיעור: מה עושים כשצריך לבטל access token לפני שפג.

P21-E69 · ‏fetch שמרענן לבד על 401 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 30 דק׳ידע נדרש: יחידה 15.5, שיעור 3

הדף של פרויקט 2 עושה "refresh אוטומטי על 401". בקובץ 21-auth/starter/P21-E69.ts כתוב וייצא:

export type Tokens = { accessToken: string; refreshToken: string };
export type TokenStore = { get(): Tokens | null; set(tokens: Tokens | null): void };
export function createAuthedFetch(baseUrl: string, store: TokenStore): (path: string, init?: RequestInit) => Promise<Response>
  • כל בקשה: fetch(baseUrl + path, init), ואם יש טוקנים, עם Authorization: Bearer <accessToken> (בנוסף ל־headers שב־init, כאובייקט פשוט).
  • תשובה 401 ויש refresh token ← POST baseUrl + "/auth/refresh" עם JSON ‏{ refreshToken }:
    • 200 ← store.set(הזוג החדש מהגוף), ושולחים את הבקשה המקורית פעם אחת נוספת עם הטוקן החדש. מחזירים את התשובה שלה (גם אם היא שוב 401).
    • אחרת ← store.set(null) ומחזירים את ה־401 המקורי.
  • כמה בקשות שמקבלות 401 יחד ← refresh אחד (E62).
  • 401 על /auth/refresh עצמו לא מפעיל refresh נוסף (אין לולאה).
