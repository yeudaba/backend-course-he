P21-E04 · שני טוקנים — למה? 🧠 הבנה רמה 1

💡 רמז 1

מה אפשר לבטל, ומה לא?

💡 רמז 2

(ג) — עקוב אחרי refresh() בשיעור 3: מה רואה השרת כשהדפדפן של דנה שולח טוקן שכבר הוחלף?

✅ פתרון

(א) JWT אי אפשר לבטל — הוא תקף עד exp. טוקן גנוב היה עובד שבוע, גם אחרי יציאה וגם אחרי החלפת סיסמה.

(ב) כל הערך של ה־refresh token הוא שאפשר לבטל אותו (יציאה, החלפת סיסמה, זיהוי גניבה) ולוודא שהוא חד־פעמי. לשם כך השרת צריך לזכור מה ניתן ומה כבר נוצל — כלומר מסד. ואם ממילא בודקים במסד, אין סיבה שהוא יהיה JWT: מחרוזת אקראית מספיקה.

(ג) 09:05: התוקף שולח את הטוקן ← השרת מבטל אותו ומחזיר לתוקף זוג חדש (A2, R2). 09:30: הדפדפן של דנה שולח את אותו טוקן ← השרת רואה טוקן שכבר בוטל ← מבטל את כל ה־refresh tokens של דנה (כולל R2 של התוקף) ← 401 לדנה, שמתחברת מחדש עם סיסמה. התוקף נשאר עם A2 בלבד — עד 15 דקות מ־09:05, כלומר כבר לא תקף. (במערכת אמיתית גם שולחים לדנה מייל: "זיהינו כניסה חשודה".)

(ד) הוא עובד עד שיפוג — לכל היותר 15 דקות. זה המחיר של JWT, ולכן התוקף קצר.

⚠️ טעויות נפוצות
  • לחשוב שיציאה "מבטלת" את ה־access token. היא מבטלת רק את ה־refresh.

P21-E56 · גנבו את טבלת refresh_tokens 🧠 הבנה רמה 1

💡 רמז 1

מה צריך לשלוח ל־POST /auth/refresh: את הטוקן, או את ה־hash שלו?

💡 רמז 2

כמה ניחושים צריך כדי למצוא מחרוזת אקראית של 256 ביט? ואיך מחפשים שורה לפי bcrypt?

✅ פתרון
  • (א) כמעט כלום. השרת מצפה לטוקן, ומחשב ממנו SHA-256. מה־hash אי אפשר לחזור לטוקן. הוא כן לומד מי משתמש פעיל ומתי.
  • (ב) הוא שולח כל טוקן פעיל ל־/auth/refresh ומקבל access token, כלומר נכנס לכל החשבונות שעוד לא פגו.
  • (ג) לסיסמאות יש "רשימה" לנחש ממנה (סיסמאות נפוצות). לטוקן אקראי של 32 בתים אין: ‏2256 אפשרויות, גם במיליארד ניחושים בשנייה.
  • (ד) bcrypt נותן hash שונה בכל פעם (salt), אז אי אפשר WHERE token_hash = ?. היינו צריכים לעבור על כל השורות ולהריץ compare על כל אחת. ובלי שום תועלת, כי אין מה לנחש.
⚠️ טעויות נפוצות
  • "hash זה hash". השאלה היא תמיד כמה קשה לנחש את המקור. סיסמה של אדם: קל. 256 ביט אקראיים: בלתי אפשרי.

P21-E57 · ‏rotation: מי נתקע? 🧠 הבנה רמה 2

💡 רמז 1

שורה 1 מבטלת את R1 ומנפיקה R2.

💡 רמז 2

טוקן שכבר בוטל וחוזר ← revokeAllForUser.

✅ פתרון
  1. 200, זוג חדש עם R2. ‏R1 מבוטל, R2 פעיל.
  2. 401. ‏R1 כבר מבוטל, אז זה "שימוש חוזר": השרת מבטל את כל הטוקנים של דנה, כולל R2.
  3. 401: גם R2 בוטל. דנה צריכה להתחבר.
  4. 200, ‏R3 חדש. התוקף לא מחזיק שום דבר שעובד (רק access token שיפוג תוך 15 דקות).

אם התוקף ראשון: הוא מקבל R2, והדפדפן של דנה שולח R1 ומפעיל את זיהוי השימוש החוזר. גם R2 של התוקף מבוטל. בשני הסדרים הגניבה נעצרת. המחיר: דנה מתחברת שוב.

⚠️ טעויות נפוצות
  • לחשוב שזיהוי שימוש חוזר "יודע" מי התוקף. הוא לא יודע. הוא רק יודע שיש שני עותקים, ומבטל את כולם.

P21-E58 · שתי לשוניות מרעננות יחד 🧠 הבנה רמה 2

💡 רמז 1

הבקשה השנייה מגיעה עם טוקן שהראשונה כבר ביטלה.

💡 רמז 2

בלקוח: רק לשונית אחת מרעננת, והאחרות מחכות לה (E62 עושה את זה בתוך לשונית אחת).

✅ פתרון
  • (א) הראשונה מצליחה ומבטלת את הטוקן. השנייה מגיעה עם טוקן מבוטל ← "שימוש חוזר" ← כל הטוקנים של דנה מבוטלים.
  • (ב) היא "מתנתקת" בלי סיבה. מבחינת השרת זה נראה בדיוק כמו גניבה.
  • (ג) לקוח: refresh אחד בכל פעם (single-flight). בתוך לשונית: Promise משותף (E62). בין לשוניות: נעילה (למשל Web Locks) או לשונית "מובילה". שרת: חלון חסד, כלומר טוקן שבוטל לפני פחות מ־10 שניות מחזיר שוב את אותו זוג חדש במקום להפעיל אזעקה. המחיר: מי שגנב טוקן ומשתמש בו בתוך החלון לא נתפס, והקוד מסובך יותר.
⚠️ טעויות נפוצות
  • לבטל את זיהוי השימוש החוזר "כי הוא מנתק משתמשים". זה מחזיר את הבעיה שבגללה הוא קיים.

P21-E59 · איפה לשמור את הטוקן? 🧠 הבנה רמה 1

💡 רמז 1

הטבלה בסעיף 5: מה XSS יכול לקרוא, ומה נשאר אחרי רענון ואחרי סגירה.

💡 רמז 2

ל־CLI אין דפדפן בכלל.

✅ פתרון

P21-E15 · refresh token אטום 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

randomBytes(32).toString("base64url") ו־createHash("sha256").update(token).digest("hex").

💡 רמז 2

"פג" — כש־expiresAt <= now. בדיוק 7 ימים אחרי — כבר לא.

✅ פתרון
// P21-E15
import { createHash, randomBytes } from "node:crypto";
import { Inject, Injectable, UnauthorizedException } from "@nestjs/common";

export const CLOCK = "CLOCK";
export interface Clock {
  now(): Date;
}

export const REFRESH_TTL_MS = 7 * 24 * 60 * 60 * 1000;
const sha256 = (value: string) => createHash("sha256").update(value).digest("hex");

interface Record {
  userId: number;
  expiresAt: number;
  usedAt: number | null;
}

@Injectable()
export class RefreshTokenService {
  // המפתח הוא ה־hash של הטוקן — הטוקן עצמו לא נשמר בשום מקום
  private readonly records = new Map<string, Record>();

  constructor(@Inject(CLOCK) private readonly clock: Clock) {}

  issue(userId: number): string {
    const token = randomBytes(32).toString("base64url");
    this.records.set(sha256(token), { userId, expiresAt: this.clock.now().getTime() + REFRESH_TTL_MS, usedAt: null });
    return token;
  }

  rotate(token: string): { userId: number; refreshToken: string } {
    const record = this.records.get(sha256(token));
    const now = this.clock.now().getTime();
    if (!record || record.usedAt !== null || record.expiresAt <= now) throw new UnauthorizedException("צריך להתחבר מחדש");
    record.usedAt = now; // פעם אחת בלבד
    return { userId: record.userId, refreshToken: this.issue(record.userId) };
  }

  storedKeys(): string[] {
    return [...this.records.keys()];
  }
}

שים לב ש־storedKeys() מחזיר רק hashes: אם מישהו ישפוך את ה־Map (או את הטבלה) — אין לו אף טוקן שעובד. ולמה SHA-256 ולא bcrypt? כי הטוקן אקראי לגמרי (אין מה לנחש), וכי צריך לחפש לפיו — bcrypt נותן hash שונה בכל פעם.

⚠️ טעויות נפוצות
  • Math.random().toString(36) — לא מספיק אקראי לאבטחה. תמיד crypto.randomBytes.
  • למחוק את הרשומה הישנה במקום לסמן אותה — עובד כאן, אבל אז אי אפשר לזהות שימוש חוזר (E16).

P21-E16 · משפחות של טוקנים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

לכל רשומה: { userId, familyId, expiresAt, revoked }. familyId — מחרוזת אקראית שנוצרת ב־login.

💡 רמז 2

ב־rotate, הסדר: לא קיים ← 401; מבוטל ← בטל משפחה, 401; פג ← 401; אחרת — בטל וצור חדש עם אותו familyId.

✅ פתרון
// P21-E16
import { createHash, randomBytes } from "node:crypto";
import { Inject, Injectable, UnauthorizedException } from "@nestjs/common";

export const CLOCK = "CLOCK";
export interface Clock {
  now(): Date;
}

const TTL_MS = 7 * 24 * 60 * 60 * 1000;
const sha256 = (value: string) => createHash("sha256").update(value).digest("hex");

interface Record {
  userId: number;
  familyId: string; // כל הטוקנים שנולדו מאותה כניסה (אותו מכשיר)
  expiresAt: number;
  revoked: boolean;
}

@Injectable()
export class RefreshTokenService {
  private readonly records = new Map<string, Record>();

  constructor(@Inject(CLOCK) private readonly clock: Clock) {}

  private store(userId: number, familyId: string) {
    const token = randomBytes(32).toString("base64url");
    this.records.set(sha256(token), { userId, familyId, expiresAt: this.clock.now().getTime() + TTL_MS, revoked: false });
    return token;
  }

  // כניסה חדשה = משפחה חדשה
  login(userId: number): string {
    return this.store(userId, randomBytes(8).toString("hex"));
  }

  rotate(token: string): { userId: number; refreshToken: string } {
    const record = this.records.get(sha256(token));
    if (!record) throw new UnauthorizedException("צריך להתחבר מחדש");
    if (record.revoked) {
      // שימוש חוזר: מישהו מחזיק עותק. מבטלים את כל המשפחה — רק המכשיר הזה, לא את כל המכשירים
      for (const r of this.records.values()) if (r.familyId === record.familyId) r.revoked = true;
      throw new UnauthorizedException("צריך להתחבר מחדש");
    }
    if (record.expiresAt <= this.clock.now().getTime()) throw new UnauthorizedException("צריך להתחבר מחדש");
    record.revoked = true;
    return { userId: record.userId, refreshToken: this.store(record.userId, record.familyId) };
  }

  activeCount(userId: number): number {
    return [...this.records.values()].filter((r) => r.userId === userId && !r.revoked).length;
  }
}

rotation עם זיהוי שימוש חוזר מופיע בהמלצות האבטחה של OAuth, ו"משפחה" (token family) הוא המונח שספקי זהות כמו Auth0 משתמשים בו. התוקף שגנב מהלפטופ נחסם, הלפטופ מתחבר מחדש — והטלפון לא מרגיש כלום.

⚠️ טעויות נפוצות
  • לבטל את המשפחה רק כשהטוקן המבוטל חוזר, אבל לשכוח שהחדש (שבידי התוקף או המשתמש) באותה משפחה — אז הוא ממשיך לעבוד.

P21-E17 · יציאה והחלפת סיסמה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

למה לדרוש את הסיסמה הישנה, אם המשתמש כבר מחובר?

💡 רמז 2

הבדיקות לפי הסדר: קודם הישנה (401), ורק אחר כך החדשה (400). כך ניסיון "לנחש" לא מקבל רמזים על מדיניות.

✅ פתרון
// P21-E17
import { createHash, randomBytes } from "node:crypto";
import { BadRequestException, Inject, Injectable, NotFoundException, UnauthorizedException } from "@nestjs/common";
import bcrypt from "bcryptjs";

export const BCRYPT_ROUNDS = "BCRYPT_ROUNDS";
const sha256 = (value: string) => createHash("sha256").update(value).digest("hex");

interface User {
  id: number;
  email: string;
  passwordHash: string;
}

@Injectable()
export class AccountService {
  private readonly users: User[] = [];
  private readonly refreshTokens = new Map<string, { userId: number; revoked: boolean }>();

  constructor(@Inject(BCRYPT_ROUNDS) private readonly rounds: number) {}

  async createUser(email: string, password: string) {
    const user = { id: this.users.length + 1, email, passwordHash: await bcrypt.hash(password, this.rounds) };
    this.users.push(user);
    return user.id;
  }

  async login(email: string, password: string): Promise<string> {
    const user = this.users.find((u) => u.email === email);
    if (!user || !(await bcrypt.compare(password, user.passwordHash))) throw new UnauthorizedException("אימייל או סיסמה שגויים");
    const token = randomBytes(32).toString("base64url");
    this.refreshTokens.set(sha256(token), { userId: user.id, revoked: false });
    return token;
  }

  isActive(token: string): boolean {
    const record = this.refreshTokens.get(sha256(token));
    return record !== undefined && !record.revoked;
  }

  logout(token: string): void {
    const record = this.refreshTokens.get(sha256(token));
    if (record) record.revoked = true; // טוקן לא מוכר — פשוט לא עושים כלום
  }

  async changePassword(userId: number, oldPassword: string, newPassword: string): Promise<void> {
    const user = this.users.find((u) => u.id === userId);
    if (!user) throw new NotFoundException("משתמש לא נמצא");
    // מי שמחזיק טוקן גנוב לא יכול להחליף סיסמה בלי לדעת את הישנה
    if (!(await bcrypt.compare(oldPassword, user.passwordHash))) throw new UnauthorizedException("הסיסמה הנוכחית שגויה");
    if (newPassword.length < 8) throw new BadRequestException("לפחות 8 תווים");
    if (newPassword === oldPassword) throw new BadRequestException("הסיסמה החדשה זהה לישנה");
    user.passwordHash = await bcrypt.hash(newPassword, this.rounds);
    // "צא מכל המכשירים": אם הסיסמה דלפה, גם הטוקנים שנוצרו איתה לא בטוחים
    for (const record of this.refreshTokens.values()) if (record.userId === userId) record.revoked = true;
  }
}

הסיסמה הישנה נדרשת כי "מחובר" לא אומר "זה באמת הוא": אולי מישהו גנב טוקן, או ישב ליד מחשב פתוח. בלי הישנה — הוא היה מחליף סיסמה ונועל את הבעלים בחוץ. וביטול כל הטוקנים — כי אם המשתמש מחליף סיסמה בגלל חשד, הוא מצפה שכל מי שהיה מחובר ייזרק החוצה.

⚠️ טעויות נפוצות
  • לבטל את הטוקנים לפני הבדיקות ← ניסיון כושל עם סיסמה שגויה מנתק את המשתמש מכל המכשירים (התקפת "ניתוק" פשוטה).

P21-E23 · refresh token שבור 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

(3): כמה מילישניות ביום?

💡 רמז 2

(1): המפתח של ה־Map צריך להיות sha256(token) — גם ב־set וגם ב־get.

✅ פתרון
// P21-E23: מתוקן
import { createHash, randomBytes } from "node:crypto";
import { Inject, Injectable, UnauthorizedException } from "@nestjs/common";

export const CLOCK = "CLOCK";
export interface Clock {
  now(): Date;
}

const DAY_MS = 24 * 60 * 60 * 1000; // ← תקלה 3: היה 24 * 60 * 60 — שניות, לא מילישניות
const sha256 = (value: string) => createHash("sha256").update(value).digest("hex");

@Injectable()
export class RefreshTokenService {
  // ← תקלה 1: היה Map לפי הטוקן עצמו. מי שקורא את האחסון — מקבל טוקנים עובדים
  private readonly records = new Map<string, { userId: number; expiresAt: number; used: boolean }>();

  constructor(@Inject(CLOCK) private readonly clock: Clock) {}

  issue(userId: number): string {
    const token = randomBytes(32).toString("base64url");
    this.records.set(sha256(token), { userId, expiresAt: this.clock.now().getTime() + 7 * DAY_MS, used: false });
    return token;
  }

  rotate(token: string) {
    const record = this.records.get(sha256(token));
    if (!record || record.used || record.expiresAt <= this.clock.now().getTime()) throw new UnauthorizedException("צריך להתחבר מחדש");
    record.used = true; // ← תקלה 2: הישן לא סומן — עבד שוב ושוב
    return { userId: record.userId, refreshToken: this.issue(record.userId) };
  }

  storedKeys(): string[] {
    return [...this.records.keys()];
  }
}

(3) הוא באג יחידות קלאסי: 24 * 60 * 60 הוא מספר השניות ביום, ו־Date.getTime() במילישניות. שבעה "ימים" כאלה הם 604,800 מילישניות — קצת יותר מ־10 דקות. בדיקה עם שעון מזויף תופסת את זה מיד; בדיקה ידנית "התחברתי וזה עבד" — לא.

⚠️ טעויות נפוצות

// P21-E28: רשימת חסימה לטוקנים (logout ל־access token)
export class TokenBlocklist {
  #blocked = new Map<string, number>();
  #now: () => number;

  constructor(now: () => number = () => Math.floor(Date.now() / 1000)) {
    this.#now = now;
  }

  block(jti: string, exp: number): void {
    if (exp <= this.#now()) return; // כבר פג תוקף — אין מה לחסום
    this.#blocked.set(jti, exp);
  }

  isBlocked(jti: string): boolean {
    const exp = this.#blocked.get(jti);
    return exp !== undefined && exp > this.#now();
  }

  cleanup(): number {
    const now = this.#now();
    let removed = 0;
    for (const [jti, exp] of this.#blocked) {
      if (exp <= now) {
        this.#blocked.delete(jti);
        removed++;
      }
    }
    return removed;
  }

  get size(): number {
    return this.#blocked.size;
  }
}

💡 רמז 1

💡 רמז 2

✅ פתרון
// P21-E69: fetch שמוסיף טוקן, ומרענן לבד (פעם אחת) על 401
export type Tokens = { accessToken: string; refreshToken: string };
export type TokenStore = { get(): Tokens | null; set(tokens: Tokens | null): void };

export function createAuthedFetch(baseUrl: string, store: TokenStore) {
  let inFlight: Promise<Tokens | null> | null = null;

  function send(path: string, init: RequestInit, tokens: Tokens | null): Promise<Response> {
    const headers: Record<string, string> = { ...(init.headers as Record<string, string> | undefined) };
    if (tokens) headers.authorization = `Bearer ${tokens.accessToken}`;
    return fetch(baseUrl + path, { ...init, headers });
  }

  function refreshOnce(refreshToken: string): Promise<Tokens | null> {
    inFlight ??= (async () => {
      const res = await fetch(baseUrl + "/auth/refresh", {
        method: "POST",
        headers: { "content-type": "application/json" },
        body: JSON.stringify({ refreshToken }),
      });
      const next: Tokens | null = res.status === 200 ? await res.json() : null;
      store.set(next);
      return next;
    })().finally(() => {
      inFlight = null;
    });
    return inFlight;
  }

  return async (path: string, init: RequestInit = {}): Promise<Response> => {
    const tokens = store.get();
    const res = await send(path, init, tokens);
    if (res.status !== 401 || !tokens || path === "/auth/refresh") return res;
    const next = await refreshOnce(tokens.refreshToken);
    if (!next) return res;
    return send(path, init, next);
  };
}

שלושה דברים שמונעים באגים קשים: ניסיון חוזר אחד (בלי לולאה אינסופית), refresh אחד לכל הבקשות (בלי להפעיל זיהוי שימוש חוזר על עצמך), ו־store.set(null) בכישלון (הדף עובר למסך הכניסה).

⚠️ טעויות נפוצות
  • לקרוא ל־refreshOnce(store.get().refreshToken) מחדש בכל בקשה שחיכתה. אחרי שהראשונה הצליחה, ב־store כבר יש טוקן חדש, והשנייה מרעננת שוב ושורפת אותו.
  • headers: init.headers בלי להעתיק — דורס את Authorization, או משנה את האובייקט של מי שקרא.
