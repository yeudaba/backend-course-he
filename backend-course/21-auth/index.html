פרק 21 — כניסה והרשאות

⏱ 5 מפגשים

🧰 לפני שמתחילים — פרק 21

מה צריך שכבר יהיה מותקן: Node.js 24+, VS Code, PostgreSQL, ופרויקט 2 בשלב ג׳ (NestJS).

מה מתקינים עכשיו: שתי חבילות — הן כבר רשומות ב־package.json של תיקיית הקורס (npm install), ובפרויקט מתקינים אותן בשיעור 5:

  • bcryptjs — hashing של סיסמאות. JavaScript טהור: אין קומפילציה של קוד C, אין תלות בגרסת Node.
  • @nestjs/jwt — יצירה ובדיקה של JWT בתוך Nest.

כדאי לשמור בסימניות: OWASP — אחסון סיסמאות · OWASP API Security Top 10 (2023).

📂 העתקת חומרי הפרק: ב־Finder, העתק את התיקייה 21-auth מתוך ~/Desktop/Backend/backend-course אל ~/dev/backend-course (גרירה עם ⌥ Option). אם התיקייה כבר שם מהעתקה קודמת ואתה רוצה לשמור את מה שכתבת — בחר Keep Both / Stop ולא Replace.

✔ בדיקה: ב־Terminal, בתיקיית הקורס: node -e "import('bcryptjs').then(b => b.default.hash('x', 4)).then(console.log)" ← שורה שמתחילה ב־$2b$04$.

🎯 בסוף הפרק תדע
  • לשמור סיסמאות נכון: hash איטי עם salt (bcrypt), ומה בדיוק נשמר במסד.
  • להבין JWT מבפנים: מה כתוב בו, מה החתימה מבטיחה, ומה היא לא מבטיחה.
  • access token קצר + refresh token ארוך, עם rotation וזיהוי שימוש חוזר.
  • הרשאות: תפקידים (roles) ובעלות על מידע — ולמה 404 ולא 403.
  • OWASP בסיסי: הפרצות הנפוצות ב־API, ואיך הקוד שלך נמנע מהן.
  • פרויקט 2, שלב ד׳: משתמשים — וכל משתמש רואה רק את המשימות שלו.

🤔 למה צריך את זה?

עד עכשיו ה־API של פרויקט 2 היה פתוח: כל מי שמכיר את הכתובת רואה, משנה ומוחק הכול. כמעט לכל מוצר אמיתי יש משתמשים, וברגע שיש משתמשים — יש שתי שאלות שהשרת שואל בכל בקשה: מי אתה? (authentication) ומה מותר לך? (authorization). זה גם הפרק שבו טעות קטנה הופכת לכותרת בעיתון: סיסמאות שנשמרו כמו שהן, או API שמחזיר את ההזמנות של לקוח אחר אם רק משנים מספר ב־URL. בראיונות שואלים על זה כמעט תמיד — ובסוף הפרק תוכל להסביר כל שורה בקוד שלך.
