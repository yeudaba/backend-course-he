P21-E05 · מצא את הפרצות

🧠 הבנהרמה 1⏱ 15 דק׳ידע נדרש: שיעור 4

קוד שנכתב בלחץ של דדליין. מצא לפחות שש בעיות אבטחה, וכתוב לכל אחת מה התוקף עושה ואיך מתקנים:

const JWT_SECRET = "secret";

@Post("register")
async register(@Body() body: any) {
  const user = await this.prisma.user.create({ data: { ...body, password: body.password } });
  return user;
}

@Post("login")
async login(@Body() { email, password }: any) {
  console.log("login attempt", email, password);
  const user = await this.prisma.user.findUnique({ where: { email } });
  if (!user) throw new NotFoundException("אין משתמש עם האימייל הזה");
  if (user.password !== password) throw new UnauthorizedException("סיסמה שגויה");
  return { token: jwt.sign({ sub: user.id, role: user.role, email, password }, JWT_SECRET) };
}

@Get("orders/:id")
async order(@Param("id") id: string) {
  return this.prisma.order.findUnique({ where: { id: Number(id) } });
}

P21-E08 · הרשמה 🤖

💻 כתיבת קוד 🤖רמה 2⏱ 20 דק׳ידע נדרש: שיעור 4

בקובץ 21-auth/starter/P21-E08.ts:

  • RegisterDto: email תקין (עד 254 תווים) — אחרי trim ו־toLowerCase; password מחרוזת, 8 תווים לפחות.
  • UsersService.register(dto): hash עם BCRYPT_ROUNDS (token), ids מ־1, role: "user" תמיד. אימייל קיים ← 409 "האימייל כבר רשום". מחזיר את המשתמש בלי passwordHash. ו־findByEmail(email).
  • POST /auth/register ← 201.

הבודק מפעיל את ה־ValidationPipe מפרק 20 (whitelist, forbidNonWhitelisted, transform), ושולח גם " Dana@Example.com " וגם "role": "admin".

P21-E13 · תפקידים 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 20 דק׳ידע נדרש: שיעור 4

בקובץ 21-auth/starter/P21-E13.ts יש FakeAuthGuard שמדמה התחברות (headers x-user-id ו־x-user-role). כתוב:

  • Roles(...roles) ו־RolesGuard: בלי @Roles — כל מחובר עובר; עם — רק התפקידים שברשימה, אחרת 403 "אין הרשאה".
  • /reports — manager או admin (על ה־class). DELETE /reports/:id — רק admin (על המתודה).
  • רשום את שני ה־guards גלובלית, בסדר הנכון: משתמש לא מחובר צריך לקבל 401, לא 403.

P21-E19 · נעילה אחרי ניסיונות כושלים 🤖

💻 כתיבת קוד 🤖רמה 3⏱ 25 דק׳ידע נדרש: שיעור 4

בקובץ 21-auth/starter/P21-E19.ts — הגנה מניחוש סיסמאות (OWASP API2):

  • LoginAttemptsService עם CLOCK: recordFailure(email), reset(email), ו־retryAfterSeconds(email) ← 0 אם מותר, אחרת כמה שניות לחכות.
  • הכלל: 5 כישלונות בתוך 15 דקות ← נעול, עד 15 דקות אחרי הכישלון הראשון מבין החמישה.
  • POST /auth/login: נעול ← 429 עם Retry-After (גם אם הסיסמה נכונה!). כישלון ← רושמים, 401. הצלחה ← מאפסים.
  • האימייל מנורמל (trim, toLowerCase) — אחרת DANA@ עוקף את המונה.

P21-E25 · אתגר: מפתחות API 🤖

💻 כתיבת קוד 🤖רמה 5⏱ 60 דק׳ידע נדרש: שיעור 4

לא כל לקוח הוא אדם עם סיסמה: סקריפט של CI או שירות אחר צריכים מפתח API. בקובץ 21-auth/starter/P21-E25.ts:

  • POST /keys { name, scopes } (משתמש מחובר, דרך FakeAuthGuard) ← 201 { id, name, prefix, scopes, key }. המפתח: tk_<8 hex>_<32 תווי base64url>, ו־prefix הם 8 ה־hex. scopes: "read" / "write" (ברירת מחדל ["read"]). המפתח המלא מוחזר רק כאן — נשמרים רק prefix ו־SHA-256.
  • GET /keys ← המפתחות של המשתמש: { id, name, prefix, scopes, createdAt, lastUsedAt, revoked }. DELETE /keys/:id ← 204; של אחר ← 404.
  • GET /data (scope read) ו־POST /data (scope write) — עם header X-Api-Key ו־ApiKeyGuard: חסר ← 401 "חסר X-Api-Key"; לא תקין/מבוטל ← 401 "מפתח לא תקין"; בלי scope ← 403 "למפתח אין הרשאת write". מחזירים { data: [1, 2, 3], owner } / { saved: true, owner }, ומעדכנים lastUsedAt לפי CLOCK.
