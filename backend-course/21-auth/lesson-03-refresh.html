1. הדילמה

JWT אי אפשר לבטל: אם הוא נגנב, הוא עובד עד ה־exp שלו. אז נקצר אותו — 15 דקות. אבל אז המשתמש צריך להקליד סיסמה כל רבע שעה. הפתרון המקובל — שני טוקנים:

2. refresh token אטום, ו־hash במסד

ה־refresh token לא צריך להכיל מידע — השרת ממילא בודק אותו במסד. לכן הוא פשוט 32 בתים אקראיים:

import { createHash, randomBytes } from "node:crypto";

const token = randomBytes(32).toString("base64url");
const hash = createHash("sha256").update(token).digest("hex");
console.log(token.length, hash.length);
console.log(createHash("sha256").update("abc").digest("hex"));

הלקוח מקבל את token (43 תווים). במסד, בעמודה token_hash, נשמר רק ה־SHA-256 שלו — מאותה סיבה שלא שומרים סיסמאות: מי שקורא את הטבלה לא יכול להשתמש במה שמצא. ולמה כאן SHA-256 המהיר מספיק, כשבסיסמאות אמרנו שהוא לא? כי לטוקן יש 256 ביט אקראיים — אין "רשימת טוקנים נפוצים" לנחש מתוכה. וצריך לחפש לפיו (WHERE token_hash = ?) — מה שאי אפשר עם bcrypt, שנותן hash שונה בכל פעם.

3. Rotation וזיהוי שימוש חוזר

כל refresh token עובד פעם אחת: POST /auth/refresh מבטל אותו ומחזיר זוג חדש. למה? כי אז אפשר לזהות גניבה:

src/auth/auth.service.ts 
async refresh(refreshToken: string) {
  const record = await this.refreshTokens.findByHash(sha256(refreshToken));
  if (!record) throw invalidRefresh();
  const now = this.clock.now().toISOString();
  if (record.revokedAt !== null) {
    // טוקן שכבר הוחלף — חוזר. אחד משניים (המשתמש או התוקף) מחזיק עותק ישן
    await this.refreshTokens.revokeAllForUser(record.userId, now);
    throw invalidRefresh();
  }
  if (record.expiresAt <= now) throw invalidRefresh();
  if (!(await this.refreshTokens.revoke(record.id, now))) throw invalidRefresh();
  const user = await this.users.findById(record.userId);
  if (!user) throw invalidRefresh();
  return this.issueTokens(user);
}

תרחיש: תוקף גנב את ה־refresh token של דנה. אם הוא משתמש בו ראשון — הוא מקבל זוג חדש, אבל כשהדפדפן של דנה ינסה את אותו טוקן, השרת יראה טוקן שכבר בוטל, ויבטל הכול — כולל מה שהתוקף קיבל. ואם דנה ראשונה — התוקף הוא זה שנתקע. בשני המקרים הגניבה מתגלה ונעצרת, ודנה רק צריכה להתחבר שוב.

💡 שתי בקשות באותו רגע

revoke הוא UPDATE ... WHERE id = ? AND revoked_at IS NULL, ובודקים כמה שורות השתנו. אם שתי בקשות עם אותו טוקן מגיעות יחד — רק אחת תקבל 1 (פרק 18: בדיקה ושינוי באותה פקודה, בלי חלון ביניהם). ב־Prisma: updateMany ו־count.

4. יציאה

POST /auth/logout עם ה־refresh token ← מבטלים אותו, ו־204. (גם על טוקן לא מוכר — 204: אין סיבה לספר.) ה־access token? ממשיך לעבוד עד שיפוג — זה המחיר של JWT, ולכן 15 דקות ולא יום. כשצריך יותר (למשל "צא מכל המכשירים" אחרי החלפת סיסמה): מבטלים את כל ה־refresh tokens של המשתמש, ואם חייבים גם מיידיות — שומרים tokenVersion במשתמש ובודקים אותו ב־guard (וזה כבר שאילתה למסד בכל בקשה).
