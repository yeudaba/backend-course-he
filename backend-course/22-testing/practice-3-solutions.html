P22-E50 · ‏TRUNCATE ... RESTART IDENTITY CASCADE 🧠 הבנה רמה 2

💡 רמז 1

‏serial משתמש ב־sequence, ו־TRUNCATE לבד לא מאפס אותו.

💡 רמז 2

ל־tasks.owner_id יש foreign key ל־users.

✅ פתרון
  • 1 — הטבלאות ריקות, אבל ה־ids ממשיכים מהבדיקה הקודמת. בדיקה שמצפה ל־{ id: 1 } עוברת לבד ונכשלת כשהיא רצה אחרי אחרת.
  • 2 — שגיאה של PostgreSQL ("cannot truncate a table referenced in a foreign key constraint"). ‏CASCADE מרוקן גם את הטבלאות שמפנות אליה. (אם כותבים את כולן ברשימה, כמו בשיעור, ‏CASCADE הוא רשת ביטחון לטבלה שתתווסף מחר.)
  • 3 — סדר חשוב: ‏DELETE FROM users קודם נכשל (FK), אלא אם יש ON DELETE CASCADE. וגם: ה־sequences לא מתאפסים, ו־DELETE איטי יותר על טבלאות גדולות (שורה אחר שורה).
⚠️ טעויות נפוצות
  • לכתוב בבדיקות id: 1 בלי לאפס, ואז "לתקן" עם id: expect.any(Number) בכל מקום. עדיף לאפס.

P22-E53 · ‏ROLLBACK בסוף כל בדיקה — מתי זה נשבר? 🧠 הבנה רמה 3

💡 רמז 1

ב־PostgreSQL אין טרנזקציות מקוננות. ‏BEGIN בתוך טרנזקציה מחזיר רק אזהרה.

💡 רמז 2

טרנזקציה שייכת לחיבור. חיבור אחר לא רואה שינויים שלא עברו commit.

✅ פתרון
  • (א) אין CREATE SCHEMA, אין migrations ואין TRUNCATE בין בדיקות. רק ROLLBACK, שהוא כמעט מיידי.
  • (ב) ה־BEGIN של הקוד מתעלם (אזהרה), אבל ה־COMMIT שלו מסיים את הטרנזקציה של הבדיקה. הנתונים נשמרים באמת, וה־ROLLBACK בסוף לא עושה כלום. הבדיקות הבאות רואות "זבל".
  • (ג) החיבור השני לא רואה את מה שהבדיקה הכינה (עוד לא commit), והקוד "לא מוצא" את הנתונים. או שהוא כותב בלי טרנזקציה, והכתיבה נשארת.
  • (ד) כשהקוד שבודקים מקבל חיבור (client) מבחוץ ולא פותח טרנזקציות בעצמו. למשל repositories פשוטים. בפרק 18 ובפרויקט, עם טרנזקציות בקוד, schema לכל קובץ + TRUNCATE בטוח יותר. (‏E62 כותב helper כזה.)
⚠️ טעויות נפוצות
  • לחשוב ש־SAVEPOINT פותר הכול. הוא עובד רק אם הקוד שבודקים יודע להשתמש בו במקום BEGIN/COMMIT.

P22-E14 · בדיקות HTTP 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

createApp().listen(0, ...) — 0 = "כל פורט פנוי". server.address().port אחר כך.

💡 רמז 2

אפליקציה חדשה לכל בדיקה, ו־t.after(() => server.close()).

✅ פתרון
// P22-E14 — הבדיקות
import { test, before, after } from "node:test";
import assert from "node:assert/strict";
import type { AddressInfo } from "node:net";
import type { Server } from "node:http";
import { createApp } from "./P22-E14.ts";

// שרת אמיתי על פורט פנוי (0), ו־fetch אמיתי. אפליקציה חדשה לכל בדיקה — בלי state משותף
async function start(t: { after: (fn: () => void) => void }) {
  const server: Server = await new Promise((resolve) => {
    const s = createApp().listen(0, () => resolve(s));
  });
  t.after(() => server.close());
  const base = `http://localhost:${(server.address() as AddressInfo).port}`;
  return (method: string, path: string, body?: unknown) =>
    fetch(base + path, { method, headers: { "Content-Type": "application/json" }, body: body === undefined ? undefined : JSON.stringify(body) });
}

test("POST ← 201 עם Location, ואז GET", async (t) => {
  const call = await start(t);
  const res = await call("POST", "/items", { name: "  Mug  " });
  assert.equal(res.status, 201);
  assert.equal(res.headers.get("location"), "/items/1");
  assert.deepEqual(await res.json(), { id: 1, name: "Mug" });
  assert.deepEqual(await (await call("GET", "/items/1")).json(), { id: 1, name: "Mug" });
  assert.deepEqual(await (await call("GET", "/items")).json(), [{ id: 1, name: "Mug" }]);
});

test("ולידציה ← 400", async (t) => {
  const call = await start(t);
  for (const body of [{ name: "" }, { name: "   " }, { name: "x".repeat(51) }, {}]) {
    assert.equal((await call("POST", "/items", body)).status, 400, JSON.stringify(body));
  }
  assert.equal((await call("POST", "/items", { name: "x".repeat(50) })).status, 201);
});

test("404 ו־DELETE", async (t) => {
  const call = await start(t);
  assert.equal((await call("GET", "/items/9")).status, 404);
  await call("POST", "/items", { name: "Mug" });
  assert.equal((await call("DELETE", "/items/1")).status, 204);
  assert.equal((await call("GET", "/items/1")).status, 404);
  assert.equal((await call("DELETE", "/items/1")).status, 404);
});

שים לב ל־start(t): פונקציה אחת שמעלה שרת חדש, רושמת סגירה, ומחזירה call קצר. כל בדיקה מתחילה מאפס — אין "ה־id הבא הוא 4 כי בדיקה אחרת יצרה 3".

⚠️ טעויות נפוצות
  • שרת אחד לכל הקובץ — נוח, עד שבדיקה אחת משאירה פריטים והשנייה סופרת אותם.

P22-E15 · מסד בדיקות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

before — יוצרים את ה־schema פעם אחת; beforeEach — reset(); after — close().

💡 רמז 2

כדי לבדוק מיון — צור את המוצרים בסדר אחר מהמחיר. ובשביל עמוד 2 — יותר מ־10 מוצרים.

✅ פתרון
// P22-E15 — הבדיקות
import { test, before, after, beforeEach } from "node:test";
import assert from "node:assert/strict";
import { createTestSchema } from "./db-helper.ts";
import { ProductsRepository } from "./P22-E15.ts";

let db: Awaited<ReturnType<typeof createTestSchema>>;
let repo: ProductsRepository;

before(async () => {
  db = await createTestSchema();
  repo = new ProductsRepository(db.pool);
});
after(() => db.close());
beforeEach(() => db.reset());

test("create מחזיר את המוצר, עם מחיר כמספר", async () => {
  assert.deepEqual(await repo.create("Mug", 19.9), { id: 1, name: "Mug", price: 19.9 });
});

test("חיפוש בלי תלות באותיות", async () => {
  await repo.create("Espresso Cup", 25);
  await repo.create("Milk jug", 60);
  assert.deepEqual(await repo.search({ q: "CUP" }), [{ id: 1, name: "Espresso Cup", price: 25 }], "גם המחיר — מספר, לא \"25.00\"");
});

test("טווח מחירים — כולל הגבולות", async () => {
  for (const [name, price] of [["a", 10], ["b", 20], ["c", 30]] as const) await repo.create(name, price);
  assert.deepEqual((await repo.search({ minPrice: 10, maxPrice: 20 })).map((p) => p.name), ["a", "b"]);
  assert.deepEqual((await repo.search({ minPrice: 20, maxPrice: 30 })).map((p) => p.name), ["b", "c"]);
});

test("מיון לפי מחיר, ועמודים של 10", async () => {
  for (let i = 1; i <= 12; i++) await repo.create(`p${i}`, 100 - i); // הזול ביותר נוצר אחרון
  const first = await repo.search();
  assert.equal(first.length, 10);
  assert.equal(first[0].name, "p12");
  assert.deepEqual((await repo.search({ page: 2 })).map((p) => p.name), ["p2", "p1"]);
});

למה schema זמני ולא המסד הרגיל? (1) הבדיקות לא נוגעות בנתוני הפיתוח שלך; (2) reset() מאפס גם ids, אז אפשר לכתוב id: 1; (3) שתי ריצות במקביל לא מפריעות זו לזו. ו־deepEqual על המוצר השלם תפס מוטנט שבדיקת שמות בלבד לא תופסת: מחיר שחוזר כמחרוזת "25.00" (כך pg מחזיר NUMERIC).

⚠️ טעויות נפוצות
  • לבדוק רק .length של התוצאות — מיון ועמודים לא נבדקים בכלל.

P22-E16 · builders לנתוני בדיקה 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

const id = overrides.id ?? nextUserId++ — ואז { ...defaults, ...overrides }.

💡 רמז 2

שים לב שאם הועבר id, המונה לא מתקדם — ?? מקצר.

✅ פתרון
// P22-E16 — builders: ערכי ברירת מחדל תקינים, ids ייחודיים, ורק מה שחשוב לבדיקה — כותבים במפורש
export interface User {
  id: number;
  email: string;
  role: "user" | "admin";
  createdAt: string;
}

export interface Task {
  id: number;
  ownerId: number;
  title: string;
  status: "todo" | "in_progress" | "done";
  priority: "low" | "medium" | "high";
  dueDate: string | null;
}

let nextUserId = 1;
let nextTaskId = 1;

export function aUser(overrides: Partial<User> = {}): User {
  const id = overrides.id ?? nextUserId++;
  return { id, email: `user${id}@example.com`, role: "user", createdAt: "2026-11-01T00:00:00.000Z", ...overrides };
}

export function aTask(overrides: Partial<Task> = {}): Task {
  const id = overrides.id ?? nextTaskId++;
  return { id, ownerId: 1, title: `משימה ${id}`, status: "todo", priority: "medium", dueDate: null, ...overrides };
}

export function resetBuilders(): void {
  nextUserId = 1;
  nextTaskId = 1;
}

למה builders? בדיקה שצריכה "משימה של admin שהסתיימה" כותבת aTask({ ownerId: admin.id, status: "done" }) — רק מה שחשוב לה. כשמוסיפים שדה חובה למשימה, משנים מקום אחד ולא מאה בדיקות.

⚠️ טעויות נפוצות
  • מונה שלא מתאפס בין בדיקות — ids תלויים בסדר הריצה.

P22-E18 · e2e: כניסה ובעלות 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

helper אחד: start(t) שמחזיר call(method, path, { body, token }), login(email, password) ושעון שאפשר לקדם.

💡 רמז 2

בעלות: דנה יוצרת, יוסי מנסה לראות ולמחוק — ואז בודקים שאצל דנה זה עדיין שם.

✅ פתרון
// P22-E18 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import type { AddressInfo } from "node:net";
import type { Server } from "node:http";
import { createApp } from "./P22-E18.ts";

async function start(t: { after: (fn: () => void) => void }) {
  const clock = { now: new Date("2026-11-04T10:00:00Z") };
  const server: Server = await new Promise((resolve) => {
    const s = createApp({ now: () => clock.now }).listen(0, () => resolve(s));
  });
  t.after(() => server.close());
  const base = `http://localhost:${(server.address() as AddressInfo).port}`;
  const call = async (method: string, path: string, { body, token }: { body?: unknown; token?: string } = {}) => {
    const res = await fetch(base + path, {
      method,
      headers: { "Content-Type": "application/json", ...(token ? { Authorization: `Bearer ${token}` } : {}) },
      body: body === undefined ? undefined : JSON.stringify(body),
    });
    return { status: res.status, body: res.status === 204 ? null : await res.json() };
  };
  const login = async (email: string, password: string) => (await call("POST", "/login", { body: { email, password } })).body.token as string;
  return { call, login, clock };
}

test("כניסה", async (t) => {
  const { call } = await start(t);
  assert.equal((await call("POST", "/login", { body: { email: "dana@example.com", password: "wrong" } })).status, 401);
  const ok = await call("POST", "/login", { body: { email: "dana@example.com", password: "dana-password-1" } });
  assert.equal(ok.status, 200);
  assert.equal(typeof ok.body.token, "string");
});

test("בלי טוקן ← 401", async (t) => {
  const { call } = await start(t);
  assert.equal((await call("GET", "/notes")).status, 401);
  assert.equal((await call("GET", "/notes", { token: "made-up" })).status, 401);
});

test("כל אחד רואה ומוחק רק את שלו", async (t) => {
  const { call, login } = await start(t);
  const dana = await login("dana@example.com", "dana-password-1");
  const yossi = await login("yossi@example.com", "yossi-password-1");
  await call("POST", "/notes", { token: dana, body: { text: "של דנה" } });
  await call("POST", "/notes", { token: yossi, body: { text: "של יוסי" } });
  assert.deepEqual((await call("GET", "/notes", { token: yossi })).body, [{ id: 2, text: "של יוסי" }]);
  assert.equal((await call("DELETE", "/notes/1", { token: yossi })).status, 404);
  assert.deepEqual((await call("GET", "/notes", { token: dana })).body, [{ id: 1, text: "של דנה" }]);
  assert.equal((await call("DELETE", "/notes/1", { token: dana })).status, 204);
});

test("ה־session פג אחרי 15 דקות", async (t) => {
  const { call, login, clock } = await start(t);
  const dana = await login("dana@example.com", "dana-password-1");
  clock.now = new Date("2026-11-04T10:14:59Z");
  assert.equal((await call("GET", "/notes", { token: dana })).status, 200);
  clock.now = new Date("2026-11-04T10:15:00Z");
  assert.equal((await call("GET", "/notes", { token: dana })).status, 401);
});

⚠️ טעויות נפוצות

// P22-E54: start — שרת אמיתי על פורט פנוי, ותשובה נוחה לבדיקה
import type { Express } from "express";
import type { Server } from "node:http";
import type { AddressInfo } from "node:net";

export type Reply = { status: number; headers: Headers; body: unknown };

export async function start(t: { after(fn: () => void | Promise<void>): void }, app: Express) {
  const server = await new Promise<Server>((resolve) => {
    const s = app.listen(0, () => resolve(s));
  });
  t.after(() => new Promise<void>((resolve) => server.close(() => resolve())));
  const base = `http://localhost:${(server.address() as AddressInfo).port}`;

  return async (method: string, path: string, body?: unknown): Promise<Reply> => {
    const res = await fetch(base + path, {
      method,
      headers: body === undefined ? {} : { "content-type": "application/json" },
      body: body === undefined ? undefined : JSON.stringify(body),
    });
    const text = await res.text();
    const parsed = text === "" ? null : (res.headers.get("content-type") ?? "").includes("json") ? JSON.parse(text) : text;
    return { status: res.status, headers: res.headers, body: parsed };
  };
}

  • t.after(() => server.close()) בלי לחכות — בדרך כלל עובד, אבל חיבורי keep-alive של fetch יכולים להשאיר את התהליך פתוח עוד כמה שניות.

// P22-E56: createTestDatabase — schema זמני לכל קובץ בדיקות
import { randomBytes } from "node:crypto";
import pg from "pg";

export async function createTestDatabase(url: string | undefined, migrations: string[]) {
  if (!url) throw new Error("חסר DATABASE_URL_TEST");
  const schema = `test_${randomBytes(4).toString("hex")}`;
  const client = new pg.Client({ connectionString: url });
  await client.connect();
  await client.query(`CREATE SCHEMA "${schema}"`);
  await client.query(`SET search_path TO "${schema}"`);
  for (const sql of migrations) await client.query(sql);
  return {
    schema,
    client,
    async reset(tables: string[]) {
      await client.query(`TRUNCATE ${tables.join(", ")} RESTART IDENTITY CASCADE`);
    },
    async close() {
      await client.query(`DROP SCHEMA "${schema}" CASCADE`);
      await client.end();
    },
  };
}

✅ פתרון
// P22-E62: withRollback — כל מה שהבדיקה כתבה נעלם בסוף
import type pg from "pg";

export async function withRollback<T>(pool: pg.Pool, fn: (client: pg.PoolClient) => Promise<T>): Promise<T> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    return await fn(client);
  } finally {
    await client.query("ROLLBACK");
    client.release();
  }
}

שים לב ל־return await: בלי ה־await, ה־finally היה רץ לפני ש־fn הסתיימה, וה־ROLLBACK היה נשלח באמצע הבדיקה.

⚠️ טעויות נפוצות
  • return fn(client) בלי await (ראה למעלה).
  • catch (err) { await ROLLBACK } בלי finally — בהצלחה אין ROLLBACK, והנתונים נשארים (בלי COMMIT הם בסוף נזרקים, אבל רק כשהחיבור נסגר — והוא חוזר ל־pool עם טרנזקציה פתוחה).

✅ פתרון
// P22-E63: waitFor — מנסים שוב עד שהתנאי מתקיים, או עד timeout
const sleep = (ms: number) => new Promise<void>((resolve) => setTimeout(resolve, ms));

export async function waitFor<T>(
  check: () => T | Promise<T>,
  { timeoutMs = 1000, intervalMs = 20 }: { timeoutMs?: number; intervalMs?: number } = {},
): Promise<T> {
  const start = Date.now();
  while (true) {
    try {
      return await check();
    } catch (err) {
      if (Date.now() - start >= timeoutMs) throw err;
    }
    await sleep(intervalMs);
  }
}

ההבדל מ־sleep(2000): כשהתנאי מתקיים אחרי 30ms, הבדיקה ממשיכה אחרי 30ms. וכשהוא לא מתקיים, ההודעה היא ה־assert האחרון ("1 !== 0"), לא "timeout". (ב־Testing Library של React יש פונקציה עם אותו שם ואותו רעיון.)

⚠️ טעויות נפוצות
  • לזרוק new Error("timeout") — מאבדים את המידע על מה לא התקיים.
  • לבדוק את ה־timeout לפני הניסיון הראשון — עם timeoutMs: 0 לא מנסים בכלל.
