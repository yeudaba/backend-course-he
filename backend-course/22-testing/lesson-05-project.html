2. הכנה

% cd ~/dev/tasks-api
% git switch -c tests
% npm install -D jest ts-jest @types/jest supertest @types/supertest

ב־package.json — ה־scripts (כמו בתבנית של Nest 12) והגדרות Jest:

package.json 
"scripts": {
  "test": "node --experimental-vm-modules node_modules/jest/bin/jest.js",
  "test:watch": "node --experimental-vm-modules node_modules/jest/bin/jest.js --watch",
  "test:cov": "node --experimental-vm-modules node_modules/jest/bin/jest.js --coverage",
  "test:int": "node --experimental-vm-modules node_modules/jest/bin/jest.js --config jest.int.json --runInBand"
},
"jest": {
  "moduleFileExtensions": ["js", "json", "ts"],
  "rootDir": ".",
  "testRegex": "(src/.*\\.spec|test/.*\\.e2e-spec)\\.ts$",
  "transform": { "^.+\\.ts$": "ts-jest" },
  "testEnvironment": "node",
  "collectCoverageFrom": ["src/**/*.ts", "!src/generated/**", "!src/main.ts"],
  "coverageDirectory": "coverage"
}

ו־jest.int.json — אותו דבר, עם "testRegex": "test/.*\\.int-spec\\.ts$". למה בנפרד? בדיקות integration צריכות מסד, ואיטיות יותר; npm test צריך לרוץ בשנייה־שתיים, בכל שמירה. --runInBand — קובץ אחרי קובץ, כי כולם מדברים עם אותו שרת מסד.

עוד שלושה דברים קטנים: ב־tsconfig.build.json הוסף ל־exclude את "test" ו־"**/*.spec.ts" (שלא ייכנסו ל־dist); ב־.gitignore — coverage/; וב־.env — DATABASE_URL_TEST שמצביע על מסד אחר מ־DATABASE_URL (למשל tasks_api_test — CREATE DATABASE tasks_api_test; ב־psql).

3. helpers

קובץמה
test/clock.tsTestClock: now(), ו־set(iso) שהבדיקה קוראת לו
test/helpers.tscreateTestApp() — Test.createTestingModule({ imports: [AppModule] }) עם overrideProvider ל־3 ה־repositories (בזיכרון), CLOCK, CONFIG (סוד של בדיקות, bcryptRounds: 4) ו־PrismaService; ואז configureApp ו־app.init(). מחזיר { app, clock, users, http }. ו־signUp(app, email) — נרשם, נכנס, מחזיר טוקנים
test/db.tscreateTestDatabase() משיעור 3: schema חדש, migrations, reset(), close()
💡 רמז: bcrypt בבדיקות

עם cost 12, כל הרשמה וכניסה לוקחות זמן מורגש — ובחבילה של עשרות בדיקות זה מצטבר. bcryptRounds: 4 ב־CONFIG של הבדיקות. האבטחה לא נפגעת: זה רק בבדיקות.

💡 רמז: PrismaService ב־e2e

ה־repositories הוחלפו, אבל PrismaService עדיין נוצר — ומנסה להתחבר. .overrideProvider(PrismaService).useValue({ $disconnect: async () => {} }) — ו־app.close() בסוף עדיין עובד.

💡 רמז: איך יודעים מה לבדוק?

עבור על הטבלה של שלב ד׳ (פרק 21, שיעור 5) ועל קודי השגיאה. לכל שורה — "מה היה קורה אם זה היה שבור? איזו בדיקה הייתה נכשלת?". ובמיוחד: גבולות (היום, 15 דקות, 7 ימים), ומה שאסור (משתמש אחר, תפקיד, hash בתשובה).
