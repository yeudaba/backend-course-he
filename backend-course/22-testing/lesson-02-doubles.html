1. מה הופך קוד ל"בלתי בדיק"

נסה לכתוב בדיקה לזה:

let counter = 0;
export function createInvoiceNumber() {
  counter++;
  const d = new Date();
  const rand = String(Math.floor(Math.random() * 1000)).padStart(3, "0");
  return `INV-${d.getFullYear()}${String(d.getMonth() + 1).padStart(2, "0")}-${String(counter).padStart(4, "0")}-${rand}`;
}

מה התוצאה הצפויה? תלוי בשעה, במזל, ובכמה פעמים קראו לפונקציה קודם — גם בבדיקות אחרות. הפתרון הוא אותו רעיון כמו CLOCK בפרויקט: כל מה שלא צפוי — מגיע מבחוץ.

export function createInvoiceNumberer({ now = () => new Date(), random = Math.random } = {}) {
  let counter = 0;                                   // של המופע, לא של הקובץ
  return () => { /* אותו חישוב, עם now() ו־random() */ };
}
// בבדיקה:
const next = createInvoiceNumberer({ now: () => new Date("2026-11-07T10:00:00Z"), random: () => 0.0421 });

שעה, אקראיות, רשת, מסד, מייל, קבצים — כל אחד מאלה הוא תלות. כשהיא מוזרקת, הבדיקה קובעת אותה. זה גם כל הסוד של DI ב־Nest (פרק 20): לא "ארכיטקטורה יפה" — בדיקות.

3. זמן ואזורי זמן

שתי טעויות קבועות. הראשונה: new Date() בבדיקה — עוברת היום, נכשלת ב־31 בחודש. השנייה: שעון מקומי. אותו רגע הוא יום אחר בישראל וב־UTC:

const moment = new Date("2026-11-04T23:30:00Z");
console.log(moment.toISOString().slice(0, 10));
console.log(moment.toLocaleDateString("sv-SE", { timeZone: "Asia/Jerusalem" }));
console.log(moment.toLocaleDateString("sv-SE", { timeZone: "America/New_York" }));
2026-11-04
2026-11-05
2026-11-04

(sv-SE — פורמט YYYY-MM-DD.) קוד שמשתמש ב־getDate() או toLocaleDateString() בלי timeZone נותן תוצאה שונה לפי המחשב שמריץ אותו. השרת בפרודקשן רץ בדרך כלל ב־UTC, ה־Mac שלך — בשעון ישראל. בדיקה טובה בוחרת בכוונה רגע כזה, שבו שני השעונים ביום שונה (E10, E22).

4. טיימרים מזויפים

debounce, retry עם המתנה, תפוגה — לא מחכים באמת. node:test יודע להחליף את setTimeout:

import { mock } from "node:test";

mock.timers.enable({ apis: ["setTimeout"] });
let fired = 0;
setTimeout(() => fired++, 1000);

mock.timers.tick(999);
console.log("אחרי 999ms:", fired);
mock.timers.tick(1);
console.log("אחרי 1000ms:", fired);
mock.timers.reset();
אחרי 999ms: 0
אחרי 1000ms: 1

בתוך בדיקה — t.mock.timers.enable(...) (ה־t של הבדיקה), והטיימרים חוזרים לאמיתיים לבד כשהיא נגמרת. אותו רעיון ב־Jest: jest.useFakeTimers() ו־jest.advanceTimersByTime(1000).

5. fake או mock?

בדיקה שבודקת "הפונקציה קראה ל־findByMonth פעם אחת עם [2026, 11]" נכשלת כשמישהו משפר את הקוד (מוסיף cache, מפצל לשתי שאילתות) — ועוברת כשהחישוב שגוי. היא שומרת על המימוש במקום על ההתנהגות. עם fake שמחזיר נתונים לפי חודש, הבדיקה פשוט בודקת את הדוח שיצא — וגם "חודש לא נכון" מתגלה, דרך התוצאה (E23).

כלל אצבע: spy רק כשהקריאה היא התוצאה (נשלח מייל? נרשם לוג?). לכל השאר — fake או stub, ובדיקה של מה שחזר.
