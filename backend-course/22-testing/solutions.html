P22-E26 · בדיקות ל־pagination — מקובץ ריק 🤖 ✍️ מאפס רמה 3

💡 רמז 1

לכל השוואה בקוד (<, ‏>, ‏>=) — בדיקה בדיוק על הגבול. ‏hasNext בעמוד האחרון, ‏hasPrev בעמוד הראשון, ‏pageSize של 100 ושל 101. ולספירת עמודים: מספר שורות שמתחלק בדיוק, ואחד שלא.

💡 רמז 2

טבלת מקרים (‏P22-E17) חוסכת הרבה שורות לקלט לא תקין: for (const [total, page, size] of bad) assert.throws(() => paginate(total, page, size), RangeError, ...). וקריאה בלי pageSize בודקת את ברירת המחדל.

✅ פתרון
// P22-E26 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { paginate } from "./P22-E26.ts";

test("עמוד ראשון, אמצעי ואחרון", () => {
  assert.deepEqual(paginate(23, 1), { pages: 3, offset: 0, hasPrev: false, hasNext: true });
  assert.deepEqual(paginate(23, 2), { pages: 3, offset: 10, hasPrev: true, hasNext: true });
  assert.deepEqual(paginate(23, 3), { pages: 3, offset: 20, hasPrev: true, hasNext: false });
});

test("מספר עמודים: מתחלק בדיוק, לא מתחלק, ואפס שורות", () => {
  assert.equal(paginate(20, 1).pages, 2);
  assert.equal(paginate(21, 1).pages, 3);
  assert.deepEqual(paginate(0, 1), { pages: 0, offset: 0, hasPrev: false, hasNext: false });
});

test("pageSize מפורש, וגבולות 1 ו־100", () => {
  assert.deepEqual(paginate(5, 2, 2), { pages: 3, offset: 2, hasPrev: true, hasNext: true });
  assert.equal(paginate(500, 1, 1).pages, 500);
  assert.equal(paginate(500, 1, 100).pages, 5);
});

test("קלט לא תקין ← RangeError", () => {
  const bad: [number, number, number?][] = [
    [-1, 1],
    [10.5, 1],
    [10, 0],
    [10, -1],
    [10, 1.5],
    [10, 1, 0],
    [10, 1, 101],
    [10, 1, 2.5],
  ];
  for (const [total, page, size] of bad) {
    assert.throws(() => paginate(total, page, size), RangeError, `paginate(${total}, ${page}, ${size})`);
  }
});

הבדיקה הראשונה עושה הרבה עבודה: ‏deepEqual על כל האובייקט בשלושה עמודים תופס את רוב הבאגים בבת אחת. ‏offset שגוי, ‏hasPrev בעמוד 1, ‏hasNext בעמוד האחרון, וברירת מחדל שגויה (עם 20 בעמוד יש רק 2 עמודים).

23 שורות נבחרו בכוונה: מספר שלא מתחלק ב־10 מבדיל בין ceil ל־floor. עם 20 או 30 שתי הגרסאות נותנות אותה תשובה, והבאג שורד.

assert.throws(..., RangeError) בודק גם את סוג השגיאה. בלי הארגומנט השני, באג שזורק Error רגיל היה עובר. וה־controller שמתרגם RangeError ל־400 היה מחזיר 500.

⚠️ טעויות נפוצות
  • לבדוק רק "עמוד 1 של 100 שורות" — ‏floor ו־ceil נותנים 10 בשניהם, ו־hasNext בעמוד האחרון לא נבדק.
  • לבדוק pageSize של 1000 במקום 101 — לא תופס > 101. הגבול הוא 100, ולכן בודקים 100 (עובר) ו־101 (נכשל).
  • לבדוק את המימוש (למשל שהקוד קורא ל־Math.ceil) — שני המימושים התקינים האחרים נכשלים, והבודק מתלונן ש"הבדיקות בודקות איך ולא מה".

P22-E27 · מטמון LRU עם Map 🤖 🔁 חזרה רמה 3

💡 רמז 1

שני שדות: #items = new Map<K, V>() ו־#capacity. ב־get: ‏if (!this.#items.has(key)) return undefined; (לא if (!value), בגלל 0), ואז delete ו־set מחדש.

💡 רמז 2

הישן ביותר: this.#items.keys().next().value — האיבר הראשון של ה־iterator. ‏TypeScript לא יודע שהוא קיים, ולכן as K. ב־set: קודם delete(key) (אם הוא קיים, כדי שיעבור לסוף), אחר כך set, ורק אז בודקים אם size > capacity.

✅ פתרון
// P22-E27: מטמון LRU עם Map
export class LruCache<K, V> {
  #items = new Map<K, V>();
  #capacity: number;

  constructor(capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 1) throw new RangeError("capacity חייב להיות מספר שלם חיובי");
    this.#capacity = capacity;
  }

  get(key: K): V | undefined {
    if (!this.#items.has(key)) return undefined;
    const value = this.#items.get(key) as V;
    // "נגיעה": מוציאים ומכניסים מחדש — עכשיו הוא האחרון בסדר של ה־Map
    this.#items.delete(key);
    this.#items.set(key, value);
    return value;
  }

  set(key: K, value: V): void {
    this.#items.delete(key);
    this.#items.set(key, value);
    if (this.#items.size > this.#capacity) {
      const oldest = this.#items.keys().next().value as K;
      this.#items.delete(oldest);
    }
  }

  get size(): number {
    return this.#items.size;
  }

  keys(): K[] {
    return [...this.#items.keys()];
  }
}

const cache = new LruCache<string, number>(2);
cache.set("a", 1);
cache.set("b", 2);
cache.get("a"); // a נהיה "האחרון שנגעו בו"
cache.set("c", 3); // אין מקום — b יוצא
console.log(cache.keys(), cache.get("b"), cache.size);
[ 'a', 'c' ] undefined 2

כל פעולה היא כמה פעולות על Map, וכל אחת מהן מהירה (O(1)). מימוש עם מערך של מפתחות (indexOf ו־splice בכל get) עובד, אבל לאט יותר ככל שהמטמון גדל.

ה־<K, V> אומר ש־new LruCache<string, number>(2) מקבל רק מספרים, ו־get מחזיר number | undefined. ה־undefined בטיפוס מכריח את מי שמשתמש במטמון לטפל במקרה של "לא נמצא".

למה זה בפרק הבדיקות? כי זו מחלקה שקל לבדוק: אין שעון, אין רשת, רק קלט ופלט. כדאי לכתוב לעצמך בדיקה לפני שמריצים את הבודק: מה ייצא כשמוסיפים פריט שלישי ל־capacity 2?

⚠️ טעויות נפוצות
  • set למפתח קיים בלי delete קודם — ‏Map.set משאיר אותו במקום הישן, והוא ייצא ראשון למרות שעדכנו אותו.
  • if (!value) return undefined — ‏0 ו־"" "לא נמצאים", ולא עוברים לסוף.
  • להוציא את הישן לפני ה־set גם כשהמפתח כבר קיים — מוציאים פריט בלי סיבה.

P22-E28 · memoizeAsync עם שעון מוזרק 🤖 🔁 חזרה רמה 3

💡 רמז 1

שומרים במטמון את ה־Promise, לא את התוצאה: ‏Map<A, { promise, expiresAt }>. כך מי שמגיע בזמן ההמתנה מקבל את אותו Promise. ה־Map חי בתוך memoizeAsync, והפונקציה המוחזרת סוגרת עליו (closure).

חתימה עם generics: memoizeAsync<A extends string | number, R>(fn: (arg: A) => Promise<R>, { ttlMs, now = Date.now }: { ttlMs: number; now?: () => number }): (arg: A) => Promise<R>.

💡 רמז 2

שגיאה: promise.catch(() => cache.delete(arg)) מיד אחרי השמירה. ה־catch הזה לא "בולע" את השגיאה למי שקרא: הוא יוצר Promise חדש, ומי שקרא קיבל את המקורי. בדיקה זהירה יותר: למחוק רק אם במטמון עדיין יושב אותו Promise.

✅ פתרון
// P22-E28: memoizeAsync — מטמון לפונקציה אסינכרונית, עם שעון מוזרק
export function memoizeAsync<A extends string | number, R>(
  fn: (arg: A) => Promise<R>,
  { ttlMs, now = Date.now }: { ttlMs: number; now?: () => number },
): (arg: A) => Promise<R> {
  const cache = new Map<A, { promise: Promise<R>; expiresAt: number }>();

  return (arg: A) => {
    const hit = cache.get(arg);
    if (hit && hit.expiresAt > now()) return hit.promise;

    const promise = fn(arg);
    cache.set(arg, { promise, expiresAt: now() + ttlMs });
    // שגיאה לא נשמרת: הקריאה הבאה תנסה שוב
    promise.catch(() => {
      if (cache.get(arg)?.promise === promise) cache.delete(arg);
    });
    return promise;
  };
}

let clock = 0;
let calls = 0;
const getRate = memoizeAsync(
  async (currency: string) => {
    calls++;
    return currency === "USD" ? 3.7 : 4;
  },
  { ttlMs: 60_000, now: () => clock },
);

Promise.all([getRate("USD"), getRate("USD")])
  .then(([a, b]) => {
    console.log(a, b, "קריאות:", calls);
    clock = 60_000;
    return getRate("USD");
  })
  .then(() => console.log("אחרי דקה — קריאות:", calls));
3.7 3.7 קריאות: 1
אחרי דקה — קריאות: 2

שמירת ה־Promise היא העיקר. אילו שמרנו את התוצאה (אחרי await), שתי הקריאות הראשונות היו מגיעות לפני שיש תוצאה, ושתיהן היו קוראות ל־fn. בשרת עמוס זה נקרא cache stampede: מאה בקשות בבת אחת מפעילות מאה שאילתות זהות, בדיוק כשהמטמון התרוקן.

השעון המוזרק הופך "אחרי דקה" לשורה אחת בבדיקה (clock = 60_000), בלי לחכות דקה ובלי טיימרים מזויפים. זה הדפוס של שיעור 2: כל מה שתלוי בזמן מקבל now מבחוץ.

בפרק 26 תראה את אותו רעיון עם Redis: ‏GET, ואם אין — מחשבים ושומרים עם EX.

⚠️ טעויות נפוצות
  • const value = await fn(arg); cache.set(arg, value) — קריאות במקביל קוראות כולן ל־fn.
  • לשמור גם שגיאות — תקלה רגעית ברשת "נתקעת" במטמון לכל ה־TTL.
  • Date.now() ישירות בתוך הפונקציה במקום now() — הבודק לא יכול "להזיז את השעון".
  • expiresAt >= now() — התשובה תקפה גם ברגע שהיא אמורה לפוג.

P22-E02 · מה רע בבדיקות האלה? רמה 1

💡 רמז 1

חמש בעיות שונות: תלות בסדר, תלות בזמן, תלות ברשת, בדיקה בלי assert, ו"חישוב מחדש" של התוצאה.

💡 רמז 2

מה יקרה אם מריצים רק את "מוחק משימה"? ומה אם מריצים את "תאריך יעד" מחר?

✅ פתרון
  1. "מוסיף" ו"מוחק" — תלויות זו בזו (state משותף ברמת הקובץ). "מוחק" לבד ← tasks.length הוא 0 מההתחלה, והוא עובר בלי לבדוק כלום; בסדר הפוך — נכשל. כל בדיקה יוצרת את הנתונים שלה (או beforeEach).
  2. "תאריך יעד" — תלויה בשעון: עוברת רק ב־4 בנובמבר 2026. מעבירים now קבוע (E22).
  3. "שולח מייל" — רשת אמיתית, ובלי assert: איטית, נכשלת כשאין אינטרנט, שולחת מיילים אמיתיים — ובכל זאת לא בודקת כלום (עוברת כל עוד לא נזרקה שגיאה). מזריקים mailer מזויף ובודקים מה נשלח (E11).
  4. "מחשב סכום" — מחשבת את התשובה באותה נוסחה כמו הקוד: אם הנוסחה שגויה, גם הציפייה שגויה. כותבים את התוצאה כמספר: 20.
⚠️ טעויות נפוצות
  • לחשוב שבדיקה ירוקה היא בדיקה טובה. השאלה היא אם היא יכולה להיכשל כשיש באג — זה כל הפרק.

P22-E03 · לקרוא בדיקה שנכשלה רמה 1

💡 רמז 1

+ = מה שקיבלנו (actual), - = מה שציפינו (expected). שורות בלי סימן — זהות.

💡 רמז 2

עם page=1 ו־limit=20 יצא offset=20. איזו נוסחה נותנת את זה?

✅ פתרון

(א) הקוד החזיר offset: 20; ציפינו ל־0. page ו־limit נכונים.

(ב) הנוסחה כנראה page * limit במקום (page - 1) * limit — off-by-one קלאסי. (זה אחד המוטנטים של E08.)

(ג) השוואה של כל האובייקט תופסת גם שדה שלא חשבת עליו (שדה מיותר, שדה חסר, שם שגוי), וההודעה מראה את כל ההבדל בבת אחת. שלוש בדיקות נפרדות עוצרות בראשונה שנכשלת.

⚠️ טעויות נפוצות
  • להפוך את הסדר: assert.equal(expected, actual) — אז ה־+ וה־- מתהפכים, וההודעה מטעה. הסדר תמיד: actual ואחר כך expected.

P22-E04 · stub, fake, spy או mock? רמה 1

💡 רמז 1

stub — מחזיר תשובה קבועה. fake — מימוש אמיתי ופשוט (בזיכרון). spy — מקליט קריאות. mock — spy עם ציפיות על הקריאות.

💡 רמז 2

מחליפים מה שאיטי, לא צפוי או חיצוני. לא מחליפים את הקוד של עצמך רק כי אפשר.

✅ פתרון
  1. fake — InMemoryTasksRepository: מתנהג כמו האמיתי, רק בזיכרון. בדיקות דרכו בודקות התנהגות, לא קריאות.
  2. spy (mock.fn) — כאן הקריאה היא התוצאה: מה נשלח, למי, כמה פעמים.
  3. stub — { now: () => new Date("2026-11-04T10:00:00Z") }.
  4. stub שזורק HttpStatusError(503) — כך בודקים מסלול שגיאה שקשה לייצר במציאות.
  5. לא מחליפים. היא מהירה, צפויה, ושלך. החלפה שלה רק תקשור את הבדיקה למימוש.
  6. לא מחליפים — בודקים מול PostgreSQL אמיתי (integration). mock של Prisma יבדוק שקראת ל־findMany עם אובייקט מסוים — לא שה־SQL מחזיר את השורות הנכונות.
⚠️ טעויות נפוצות
  • mock לכל דבר ← בדיקות שבודקות "קראת לפונקציה X עם Y" ונשברות בכל שינוי פנימי, בלי לתפוס באגים (E23).

P22-E05 · 100% כיסוי, ובכל זאת באג רמה 1

💡 רמז 1

coverage מודד אילו שורות רצו, לא אילו התנהגויות נבדקו.

💡 רמז 2

"מ־200" — כולל 200?

✅ פתרון

(א) 100% — שתי השורות רצות, שני הענפים נלקחים.

(ב) כן. "מ־200" כולל 200, אבל total > 200 מחזיר 25 על 200 בדיוק. הבדיקות לא נגעו בגבול, אז הכיסוי לא "ראה" את זה.

(ג) mutation testing משנה את הקוד בכוונה — למשל > ל־>= — ומריץ את הבדיקות. אם הן עדיין עוברות, ה"מוטנט" שרד: הבדיקות לא מבחינות בין שתי ההתנהגויות. כאן >= הוא דווקא התיקון — והבדיקות לא היו מרגישות בהבדל. זה בדיוק מה ש־npm run check עושה בפרק הזה: מריץ את הבדיקות שלך על הקוד התקין (חייבות לעבור) ועל כמה גרסאות עם באג (חייבות להיכשל). כלי אמיתי לזה ב־JavaScript: Stryker.

⚠️ טעויות נפוצות
  • לקבוע יעד של 100% כיסוי. אחרי 80% בערך, כל אחוז נוסף עולה הרבה ומוסיף מעט — עדיף לבדוק גבולות ומקרי שגיאה.

P22-E06 · בדיקות ראשונות 🤖 רמה 2

💡 רמז 1

לכל כלל בתיאור — לפחות בדיקה אחת שתיכשל אם הכלל לא מתקיים.

💡 רמז 2

// P22-E09 — הבדיקות

import assert from "node:assert/strict";

test("הצלחה מיד — קריאה אחת", async () => {
  const fn = mock.fn(async () => "ok");
  assert.equal(await withRetry(fn), "ok");
  assert.equal(fn.mock.callCount(), 1);
});

test("נכשל פעמיים עם 503, ואז מצליח", async () => {
  let calls = 0;
  const fn = mock.fn(async () => {
    calls++;
    if (calls < 3) throw new HttpStatusError(503);
    return "ok";
  });
  assert.equal(await withRetry(fn), "ok");
  assert.equal(fn.mock.callCount(), 3);
});

test("נכשל תמיד — 1 + retries ניסיונות, וזורק את השגיאה האחרונה", async () => {
  let calls = 0;
  const fn = mock.fn(async () => {
    calls++;
    throw new Error(`ניסיון ${calls}`);
  });
  await assert.rejects(withRetry(fn, 2), { message: "ניסיון 3" });
  assert.equal(fn.mock.callCount(), 3);
});

test("4xx — לא מנסים שוב", async () => {
  const fn = mock.fn(async () => {
    throw new HttpStatusError(404);
  });
  await assert.rejects(withRetry(fn), HttpStatusError);
  assert.equal(fn.mock.callCount(), 1);
});

test("retries=0 — ניסיון אחד", async () => {
  const fn = mock.fn(async () => {

  });
  await assert.rejects(withRetry(fn, 0));
  assert.equal(fn.mock.callCount(), 1);
});

// P22-E13 — אחרי השינוי: כל מה שלא צפוי (שעה, אקראיות) מוזרק, וה־counter שייך למופע
export interface InvoiceDeps {
  now?: () => Date;
  random?: () => number; // [0, 1)
}

export function createInvoiceNumberer({ now = () => new Date(), random = Math.random }: InvoiceDeps = {}) {
  let counter = 0;
  return function next(): string {
    counter++;
    const d = now();
    const month = String(d.getUTCMonth() + 1).padStart(2, "0"); // UTC: אותה תוצאה בכל אזור זמן
    const rand = String(Math.floor(random() * 1000)).padStart(3, "0");
    return `INV-${d.getUTCFullYear()}${month}-${String(counter).padStart(4, "0")}-${rand}`;
  };
}

  • getMonth() (מקומי) — בסוף חודש, בלילה, המספר קופץ לחודש הבא.

💡 רמז 2

✅ פתרון
// P22-E14 — הבדיקות
import { test, before, after } from "node:test";
import assert from "node:assert/strict";
import type { AddressInfo } from "node:net";
import type { Server } from "node:http";
import { createApp } from "./P22-E14.ts";

// שרת אמיתי על פורט פנוי (0), ו־fetch אמיתי. אפליקציה חדשה לכל בדיקה — בלי state משותף
async function start(t: { after: (fn: () => void) => void }) {
  const server: Server = await new Promise((resolve) => {
    const s = createApp().listen(0, () => resolve(s));
  });
  t.after(() => server.close());
  const base = `http://localhost:${(server.address() as AddressInfo).port}`;
  return (method: string, path: string, body?: unknown) =>
    fetch(base + path, { method, headers: { "Content-Type": "application/json" }, body: body === undefined ? undefined : JSON.stringify(body) });
}

test("POST ← 201 עם Location, ואז GET", async (t) => {
  const call = await start(t);
  const res = await call("POST", "/items", { name: "  Mug  " });
  assert.equal(res.status, 201);
  assert.equal(res.headers.get("location"), "/items/1");
  assert.deepEqual(await res.json(), { id: 1, name: "Mug" });
  assert.deepEqual(await (await call("GET", "/items/1")).json(), { id: 1, name: "Mug" });
  assert.deepEqual(await (await call("GET", "/items")).json(), [{ id: 1, name: "Mug" }]);
});

test("ולידציה ← 400", async (t) => {
  const call = await start(t);
  for (const body of [{ name: "" }, { name: "   " }, { name: "x".repeat(51) }, {}]) {
    assert.equal((await call("POST", "/items", body)).status, 400, JSON.stringify(body));
  }
  assert.equal((await call("POST", "/items", { name: "x".repeat(50) })).status, 201);
});

test("404 ו־DELETE", async (t) => {
  const call = await start(t);
  assert.equal((await call("GET", "/items/9")).status, 404);
  await call("POST", "/items", { name: "Mug" });
  assert.equal((await call("DELETE", "/items/1")).status, 204);
  assert.equal((await call("GET", "/items/1")).status, 404);
  assert.equal((await call("DELETE", "/items/1")).status, 404);
});

שים לב ל־start(t): פונקציה אחת שמעלה שרת חדש, רושמת סגירה, ומחזירה call קצר. כל בדיקה מתחילה מאפס — אין "ה־id הבא הוא 4 כי בדיקה אחרת יצרה 3".

⚠️ טעויות נפוצות
  • שרת אחד לכל הקובץ — נוח, עד שבדיקה אחת משאירה פריטים והשנייה סופרת אותם.

async function start(t: { after: (fn: () => void) => void }) {
  const clock = { now: new Date("2026-11-04T10:00:00Z") };
  const server: Server = await new Promise((resolve) => {
    const s = createApp({ now: () => clock.now }).listen(0, () => resolve(s));
  });
  t.after(() => server.close());
  const base = `http://localhost:${(server.address() as AddressInfo).port}`;
  const call = async (method: string, path: string, { body, token }: { body?: unknown; token?: string } = {}) => {

  };

}

  assert.deepEqual(await monthlyReport(repo, 2026, 11), { count: 4, total: 70, byCategory: { coffee: 55, tea: 15 } });

test("חודש בלי מכירות", async () => {

// P22-E24 — הבדיקות
import { test, mock } from "node:test";
import assert from "node:assert/strict";
import { InventoryService, OutOfStockError, type Notifier } from "./P22-E24.ts";

function setup(threshold = 3) {
  let now = new Date("2026-11-04T10:00:00Z");
  const clock = { now: () => now, advance: (minutes: number) => (now = new Date(now.getTime() + minutes * 60_000)) };
  const notifier = { lowStock: mock.fn<Notifier["lowStock"]>() };
  const inventory = new InventoryService(clock, notifier, threshold);
  return { inventory, clock, notifier };
}

test("restock מוסיף", () => {
  const { inventory } = setup();
  inventory.restock("mug", 5);
  inventory.restock("mug", 3);
  assert.equal(inventory.available("mug"), 8);
  assert.equal(inventory.available("unknown"), 0);
});

test("כמויות לא תקינות", () => {
  const { inventory } = setup();
  inventory.restock("mug", 5);
  for (const qty of [0, -1, 1.5]) {
    assert.throws(() => inventory.restock("mug", qty), RangeError);

  }
});

test("שמירה מורידה מהפנוי; release מחזיר", () => {
  const { inventory } = setup();
  inventory.restock("mug", 10);
  const id = inventory.reserve("mug", 4);
  assert.equal(inventory.available("mug"), 6);

  assert.equal(inventory.available("mug"), 10);

  const id = inventory.reserve("mug", 5);
  clock.advance(14);
  assert.equal(inventory.available("mug"), 0);
  clock.advance(1);
  assert.equal(inventory.available("mug"), 5);
  assert.throws(() => inventory.commit(id), /פג תוקפה/);
});

  const { inventory, clock } = setup();
  inventory.restock("mug", 5);
  const id = inventory.reserve("mug", 2);
  inventory.commit(id);
  clock.advance(60);
  assert.equal(inventory.available("mug"), 3, "גם אחרי שהשמירה הייתה פגה");

💡 רמז 1

💡 רמז 2

הגבול: ב־t + windowMs − 1 עדיין חסום, ב־t + windowMs כבר מותר.

✅ פתרון
// P22-E25 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { SlidingWindowLimiter } from "./P22-E25.ts";

function setup(limit = 3, windowMs = 10_000) {
  const clock = { t: 1_000_000, now() { return this.t; } };
  return { limiter: new SlidingWindowLimiter(limit, windowMs, clock), clock };
}

test("עד limit בקשות; remaining יורד", () => {
  const { limiter } = setup();
  assert.deepEqual([1, 2, 3].map(() => limiter.hit("a").remaining), [2, 1, 0]);
  assert.deepEqual(limiter.hit("a"), { allowed: false, remaining: 0, retryAfterMs: 10_000 });
});

test("החלון נע: בקשה ישנה יוצאת בדיוק אחרי windowMs", () => {
  const { limiter, clock } = setup();
  limiter.hit("a"); // t=0
  clock.t += 4_000;
  limiter.hit("a"); // t=4s
  limiter.hit("a");
  clock.t += 5_999; // t=9.999s
  assert.equal(limiter.hit("a").allowed, false);
  clock.t += 1; // t=10s — הראשונה יצאה
  assert.equal(limiter.hit("a").allowed, true);
});

test("retryAfterMs — עד שהבקשה הוותיקה יוצאת", () => {
  const { limiter, clock } = setup();
  limiter.hit("a");
  clock.t += 3_000;
  limiter.hit("a");
  limiter.hit("a");
  clock.t += 1_000;
  assert.equal(limiter.hit("a").retryAfterMs, 6_000);
});

test("בקשה שנדחתה לא נספרת", () => {
  const { limiter, clock } = setup(1, 1_000);
  limiter.hit("a");
  clock.t += 500;
  assert.equal(limiter.hit("a").allowed, false);
  clock.t += 500;
  assert.equal(limiter.hit("a").allowed, true, "הדחויה ב־500 לא מאריכה את החסימה");
});

test("כל מפתח — לבד", () => {
  const { limiter } = setup(1);
  assert.equal(limiter.hit("a").allowed, true);
  assert.equal(limiter.hit("b").allowed, true);
  assert.equal(limiter.hit("a").allowed, false);
});

זה ההבדל מה"חלון הקבוע" של P20-E25: אין "התחלה של חלון" — כל בקשה יוצאת בזמן משלה. לכן הבדיקות בודקות זמנים בין בקשות, ולא רק "אחרי 10 שניות הכול מתאפס".

⚠️ טעויות נפוצות
  • לקדם את השעון בקפיצות עגולות בלבד (10 שניות) — אף באג של ">" מול ">=" לא נתפס.
