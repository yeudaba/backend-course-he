2. node:test

Node כולל מריץ בדיקות מובנה — בלי התקנה. קובץ בדיקות הוא קובץ רגיל:

slugify.spec.ts 
import { test } from "node:test";
import assert from "node:assert/strict";
import { slugify } from "./slugify.ts";

test("אותיות קטנות, ורווח ← מקף", () => {
  assert.equal(slugify("Hello World"), "hello-world");
});

test("עברית נשארת", () => {
  assert.equal(slugify("פרק 22: בדיקות"), "פרק-22-בדיקות");
});
% node --test slugify.spec.ts
✔ אותיות קטנות, ורווח ← מקף (0.80097ms)
✔ עברית נשארת (0.227425ms)
ℹ tests 2
ℹ pass 2
ℹ fail 0

(פלט אמיתי, מקוצר.) ואם מישהו "מתקן" את slugify ומוחק בטעות את האותיות העבריות מהביטוי הרגולרי:

% node --test slugify.spec.ts
✔ אותיות קטנות, ורווח ← מקף (0.739684ms)
✖ עברית נשארת (0.969321ms)
AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:
+ actual - expected
..
+ '22'
- 'פרק-22-בדיקות'

איך קוראים: + — מה שקיבלנו, - — מה שציפינו. לכן הסדר ב־assert.equal(actual, expected) חשוב: קודם מה שהקוד החזיר, אחר כך מה שאתה מצפה.

💡 שלושה חלקים בכל בדיקה (AAA)

Arrange — הכנה (נתונים, כפילים). Act — פעולה אחת. Assert — בדיקת התוצאה. בדיקה שעושה שלוש פעולות ובודקת אחרי כל אחת — היא בעצם שלוש בדיקות. ושם הבדיקה אומר מה נבדק ("עברית נשארת"), כך שכישלון מסביר את עצמו.

3. assert — הכלים

import assert from "node:assert/strict";

const checks: [string, () => void][] = [
  ["equal", () => assert.equal(0.1 + 0.2, 0.3)],
  ["deepEqual", () => assert.deepEqual({ page: 1, offset: 20 }, { page: 1, offset: 20 })],
  ["throws + סוג", () => assert.throws(() => JSON.parse("{oops"), SyntaxError)],
  ["throws על קוד שלא זורק", () => assert.throws(() => JSON.parse("{}"))],
  ["match", () => assert.match("INV-202611-0001", /^INV-\d{6}-\d{4}$/)],
];
for (const [name, check] of checks) {
  try {
    check();
    console.log(`✔ ${name}`);
  } catch (err) {
    console.log(`✖ ${name}: ${(err as Error).message.split("\n")[0]}`);
  }
}
✖ equal: Expected values to be strictly equal:
✔ deepEqual
✔ throws + סוג
✖ throws על קוד שלא זורק: Missing expected exception.
✔ match

השורה הראשונה היא תזכורת שימושית: 0.1 + 0.2 הוא לא 0.3 ב־JavaScript (שבר בינארי) — לכן בכסף מעגלים, ובבדיקות של כסף בודקים את העיגול (E07). והרביעית: assert.throws על קוד שלא זורק — נכשל, וזה בדיוק מה שאנחנו רוצים.

equal לערכים פשוטים, deepEqual לאובייקטים ומערכים (משווה תוכן), throws (ובקוד async — await assert.rejects), ו־match לביטוי רגולרי. ו־node:assert/strict — כדי ש־equal יהיה ===, לא ==.

4. מה לבדוק: גבולות

באגים גרים בקצוות. לכל > או >= בקוד — בדיקה על הגבול ולידו. לכל רשימה — ריקה, אחת, הרבה. לכל מספר — 0, שלילי, שבר. וכשיש הרבה מקרים דומים — טבלה:

const cases: [string, number, string][] = [
  ["?page=1", 0, "עמוד ראשון"],
  ["?page=3&limit=10", 20, "עמוד שלישי"],
];
for (const [query, offset, why] of cases) {
  test(`${query} ← offset ${offset} (${why})`, () => { /* ... */ });
}

5. בדיקה שלא יכולה להיכשל

הבדיקה הכי מסוכנת היא ירוקה שלא בודקת כלום. שלושה דפוסים נפוצים:

// 1. משווה אובייקט לעצמו — תמיד שווה
const before = accounts;
await transfer(accounts, "a", "b", 30);
assert.deepEqual(accounts, before);

// 2. try/catch — אם לא נזרקה שגיאה, הבדיקה פשוט עוברת
try { await transfer(accounts, "a", "b", 9999); } catch (err) { assert.ok(err instanceof InsufficientFundsError); }

// 3. לולאה על התוצאה — על רשימה ריקה היא לא בודקת כלום
for (const name of lowBalance(accounts, 10)) assert.ok(accounts.get(name)! < 10);

והחלשות — assert.ok(result) במקום הערך המדויק. הדרך לתפוס את כולן: שבור את הקוד בכוונה, וודא שהבדיקה נהיית אדומה. זה מה שהבודק של הפרק עושה אוטומטית, ולכן בתרגילים שלו המסר הוא "הבדיקות שלך עוברות גם על קוד עם הבאגים האלה".
