P22-E04 · stub, fake, spy או mock? 🧠 הבנה רמה 1

💡 רמז 1

stub — מחזיר תשובה קבועה. fake — מימוש אמיתי ופשוט (בזיכרון). spy — מקליט קריאות. mock — spy עם ציפיות על הקריאות.

💡 רמז 2

מחליפים מה שאיטי, לא צפוי או חיצוני. לא מחליפים את הקוד של עצמך רק כי אפשר.

✅ פתרון
  1. fake — InMemoryTasksRepository: מתנהג כמו האמיתי, רק בזיכרון. בדיקות דרכו בודקות התנהגות, לא קריאות.
  2. spy (mock.fn) — כאן הקריאה היא התוצאה: מה נשלח, למי, כמה פעמים.
  3. stub — { now: () => new Date("2026-11-04T10:00:00Z") }.
  4. stub שזורק HttpStatusError(503) — כך בודקים מסלול שגיאה שקשה לייצר במציאות.
  5. לא מחליפים. היא מהירה, צפויה, ושלך. החלפה שלה רק תקשור את הבדיקה למימוש.
  6. לא מחליפים — בודקים מול PostgreSQL אמיתי (integration). mock של Prisma יבדוק שקראת ל־findMany עם אובייקט מסוים — לא שה־SQL מחזיר את השורות הנכונות.
⚠️ טעויות נפוצות
  • mock לכל דבר ← בדיקות שבודקות "קראת לפונקציה X עם Y" ונשברות בכל שינוי פנימי, בלי לתפוס באגים (E23).

P22-E40 · איזה יום זה? 🧠 הבנה רמה 2

💡 רמז 1

בחורף ישראל ב־UTC+2. ב־27 במרץ 2026 כבר שעון קיץ (UTC+3).

💡 רמז 2

בדיקה טובה בוחרת רגע שבו שני השעונים לא מסכימים.

✅ פתרון
for (const iso of ["2026-11-30T22:30:00Z", "2026-12-31T21:59:00Z", "2026-12-31T22:00:00Z", "2026-03-27T00:30:00Z"]) {

}

2026-12-31T22:00:00Z 2026-12-31 2027-01-01

לדוח של נובמבר: 2026-11-30T22:30:00Z. ב־UTC זה עדיין נובמבר, אבל בישראל כבר 1 בדצמבר. קוד שעובד לפי UTC יכניס את ההזמנה לנובמבר בטעות, ובדיקה עם הרגע הזה תתפוס. ‏21:59 ו־22:00 ב־31 בדצמבר הם זוג של "הגבול ולידו": אותו יום ובשנה אחרת. הרגע האחרון: אותו תאריך בשניהם, כלומר הוא לא בודק כלום על אזורי זמן.

⚠️ טעויות נפוצות
  • לבחור רגע בצהריים ("2026-11-15T12:00:00Z"). בכל אזור זמן זה אותו יום, ובאג של אזור זמן עובר.

P22-E41 · מה ה־spy רשם? 🧠 הבנה רמה 2

💡 רמז 1

"Once" — רק לקריאה הבאה. אחר כך חוזרים למימוש הרגיל.

💡 רמז 2

mock.calls שומר לכל קריאה את הארגומנטים ואת התוצאה.

✅ פתרון
import { mock } from "node:test";
const random = mock.fn(() => 0.5);
random.mock.mockImplementationOnce(() => 0.01);
console.log(random(), random(), random());
console.log(random.mock.callCount());
const add = mock.fn((a: number, b: number) => a + b);
add(2, 3);
try { add(1, Number("x")); } catch {}
console.log(add.mock.calls.map((c) => [c.arguments, c.result]));
0.01 0.5 0.5
3
[ [ [ 2, 3 ], 5 ], [ [ 1, NaN ], NaN ] ]

הקריאה הראשונה מקבלת את המימוש "של פעם אחת", והשאר את הרגיל. שימוש אמיתי: "השרת החיצוני נכשל בניסיון הראשון ומצליח בשני" (stub שמחזיר שגיאה פעם אחת), כדי לבדוק retry (E47). ושים לב לשורה האחרונה: ה־spy לא "מתקן" כלום. NaN נרשם בדיוק כמו שהיה.

⚠️ טעויות נפוצות
  • לחשוב ש־mock.fn() בלי מימוש מחזיר משהו שימושי. הוא מחזיר undefined.

P22-E42 · טיימרים מזויפים — מה זז, ומה לא 🧠 הבנה רמה 2

💡 רמז 1

ב־3500ms ה־interval רץ ב־1000, ‏2000, ‏3000.

💡 רמז 2

רק מה שמופיע ב־apis מזויף.

✅ פתרון
import { mock } from "node:test";
mock.timers.enable({ apis: ["setInterval", "setTimeout"] });
let ticks = 0;
const id = setInterval(() => ticks++, 1000);
setTimeout(() => clearInterval(id), 3500);
mock.timers.tick(3500);
console.log("ticks:", ticks);
mock.timers.tick(5000);
console.log("ticks:", ticks);
console.log("Date.now() מזויף?", Date.now() < 100000);
mock.timers.reset();
mock.timers.enable({ apis: ["Date"], now: new Date("2026-11-30T22:30:00Z") });
console.log(new Date().toISOString());
mock.timers.tick(60 * 60 * 1000);
console.log(new Date().toISOString());
mock.timers.reset();
ticks: 3
ticks: 3
Date.now() מזויף? false
2026-11-30T22:30:00.000Z
2026-11-30T23:30:00.000Z

שלוש פעימות, וה־clearInterval עצר אותן, ולכן ה־tick השני לא מוסיף. אבל Date.now() נשאר אמיתי כל עוד Date לא ברשימת ה־apis. קוד שמחשב "עברו 15 דקות?" לפי Date.now() לא יראה את ה־tick. לכן או שמזייפים את שניהם (apis: ["setTimeout", "Date"]), או, עדיף, שעון מוזרק (‏now()), כמו ה־CLOCK בפרויקט.

⚠️ טעויות נפוצות
  • לשכוח reset (מחוץ ל־t.mock). הבדיקות הבאות רצות עם זמן מזויף, ונתקעות.

P22-E43 · עובר לבד, נכשל עם כולם 🧠 הבנה רמה 2

💡 רמז 1

counter חי ברמת הקובץ. כמה פעמים הקובץ נטען בריצה אחת?

💡 רמז 2

createInvoiceNumberer() בשיעור: המונה "של המופע, לא של הקובץ".

✅ פתרון
  • (א) הראשונה עוברת, השנייה נכשלת: היא מקבלת INV-0002 ו־INV-0003.
  • (ב) עוברת. הבדיקה "תלויה" במה שרץ לפניה.
  • (ג) עכשיו הבדיקה הראשונה בקובץ היא זו שעוברת, והאחרת נכשלת. כישלון שתלוי בסדר הוא מהבאגים הכי מבלבלים בבדיקות.
  • (ד) מונה לכל מופע:
export function createInvoiceNumberer() {
  let counter = 0;
  return () => `INV-${String(++counter).padStart(4, "0")}`;
}
// בבדיקה: const next = createInvoiceNumberer(); — חדש בכל בדיקה
⚠️ טעויות נפוצות
  • "לתקן" את הבדיקה לצפות ל־INV-0002. עכשיו היא תלויה בסדר, ונשברת ברגע שמוסיפים בדיקה לפניה.

P22-E09 · async ו־spy 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

const fn = mock.fn(async () => ...), ואז fn.mock.callCount().

💡 רמז 2

await assert.rejects(promise, { message: "..." }) — עם await!

✅ פתרון
// P22-E09 — הבדיקות
import { test, mock } from "node:test";
import assert from "node:assert/strict";
import { HttpStatusError, withRetry } from "./P22-E09.ts";

test("הצלחה מיד — קריאה אחת", async () => {
  const fn = mock.fn(async () => "ok");
  assert.equal(await withRetry(fn), "ok");
  assert.equal(fn.mock.callCount(), 1);
});

test("נכשל פעמיים עם 503, ואז מצליח", async () => {
  let calls = 0;
  const fn = mock.fn(async () => {
    calls++;
    if (calls < 3) throw new HttpStatusError(503);
    return "ok";
  });
  assert.equal(await withRetry(fn), "ok");
  assert.equal(fn.mock.callCount(), 3);
});

test("נכשל תמיד — 1 + retries ניסיונות, וזורק את השגיאה האחרונה", async () => {
  let calls = 0;
  const fn = mock.fn(async () => {
    calls++;
    throw new Error(`ניסיון ${calls}`);
  });
  await assert.rejects(withRetry(fn, 2), { message: "ניסיון 3" });
  assert.equal(fn.mock.callCount(), 3);
});

test("4xx — לא מנסים שוב", async () => {
  const fn = mock.fn(async () => {
    throw new HttpStatusError(404);
  });
  await assert.rejects(withRetry(fn), HttpStatusError);
  assert.equal(fn.mock.callCount(), 1);
});

test("retries=0 — ניסיון אחד", async () => {
  const fn = mock.fn(async () => {
    throw new HttpStatusError(500);
  });
  await assert.rejects(withRetry(fn, 0));
  assert.equal(fn.mock.callCount(), 1);
});

כאן callCount הוא באמת חלק מההתנהגות (כמה ניסיונות), אז spy הוא הכלי הנכון. ובשביל "השגיאה האחרונה" — fn שזורקת הודעה שונה בכל ניסיון.

⚠️ טעויות נפוצות
  • assert.rejects(...) בלי await: הבדיקה מסתיימת לפני הבדיקה עצמה. ב־node:test הקובץ ייכשל עם "generated asynchronous activity after the test ended" — הודעה מבלבלת שכדאי להכיר.

P22-E10 · זמן ואזורי זמן 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הפונקציה מקבלת now — זה כל הטריק. לכל בדיקה — שעה קבועה.

💡 רמז 2

איזו שעה ב־UTC היא כבר "מחר" בישראל?

✅ פתרון
// P22-E10 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { dueStatus } from "./P22-E10.ts";

const now = new Date("2026-11-04T10:00:00Z");

test("כל המצבים, והגבולות", () => {
  assert.equal(dueStatus(null, now), "none");
  assert.equal(dueStatus("2026-11-03", now), "overdue");
  assert.equal(dueStatus("2026-11-04", now), "today");
  assert.equal(dueStatus("2026-11-05", now), "soon");
  assert.equal(dueStatus("2026-11-07", now), "soon"); // בדיוק 3 ימים
  assert.equal(dueStatus("2026-11-08", now), "later");
});

test("\"היום\" לפי UTC — גם כשבישראל כבר מחר", () => {
  const lateNight = new Date("2026-11-04T23:30:00Z"); // 01:30 ב־5 בנובמבר בישראל
  assert.equal(dueStatus("2026-11-04", lateNight), "today");
});

הבדיקה השנייה היא החשובה: 23:30 UTC הוא 01:30 של היום הבא בישראל. קוד שמשתמש בשעון המקומי יחשוב שהמשימה "באיחור". בלי בדיקה כזו — הבאג מופיע רק אצל משתמשים בלילה, ורק בפרודקשן.

⚠️ טעויות נפוצות
  • new Date() בתוך הבדיקה — עוברת היום, נכשלת מחר (E22).

P22-E11 · fake mailer 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

const send = mock.fn<Mailer["send"]>(async () => {}) — ו־{ send } הוא mailer שלם.

💡 רמז 2

send.mock.calls[0].arguments — כל הארגומנטים של הקריאה הראשונה, במערך.

✅ פתרון
// P22-E11 — הבדיקות
import { test, mock } from "node:test";
import assert from "node:assert/strict";
import { notifyOverdue, type Mailer } from "./P22-E11.ts";

// fake שמקליט — במקום שרת מיילים אמיתי
function fakeMailer() {
  const send = mock.fn<Mailer["send"]>(async () => {});
  return { send };
}

const users = [
  { id: 1, email: "dana@example.com", wantsEmails: true },
  { id: 2, email: "yossi@example.com", wantsEmails: false },
  { id: 3, email: "rona@example.com", wantsEmails: true },
];

test("שולח רק למי שרוצה ויש לו משימות באיחור", async () => {
  const mailer = fakeMailer();
  const overdue = new Map([
    [1, ["לשלם חשבון", "להתקשר לבנק"]],
    [2, ["משהו"]],
  ]);
  const sent = await notifyOverdue(users, overdue, mailer);
  assert.equal(sent, 1);
  assert.equal(mailer.send.mock.callCount(), 1);
  assert.deepEqual(mailer.send.mock.calls[0].arguments, ["dana@example.com", "יש לך 2 משימות באיחור", "לשלם חשבון\nלהתקשר לבנק"]);
});

test("אין משימות באיחור — לא שולחים כלום", async () => {
  const mailer = fakeMailer();
  assert.equal(await notifyOverdue(users, new Map(), mailer), 0);
  assert.equal(mailer.send.mock.callCount(), 0);
});

test("רשימה ריקה לא נחשבת", async () => {
  const mailer = fakeMailer();
  assert.equal(await notifyOverdue(users, new Map([[3, []]]), mailer), 0);
});

שים לב שבודקים גם מה לא קרה: משתמש שלא רוצה מיילים, ורשימה ריקה. מוטנטים רבים נתפסים רק ככה.

⚠️ טעויות נפוצות
  • לבדוק רק את ערך ההחזרה (1) — אז מייל לכתובת הלא נכונה עובר.

P22-E12 · טיימרים מזויפים 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

t.mock.timers.enable({ apis: ["setTimeout"] }) בתוך הבדיקה, ואז t.mock.timers.tick(299).

💡 רמז 2

בדוק את הרגע לפני (299) ואת הרגע עצמו (300).

✅ פתרון
// P22-E12 — הבדיקות
import { test, mock } from "node:test";
import assert from "node:assert/strict";
import { debounce } from "./P22-E12.ts";

test("רץ פעם אחת, אחרי ההמתנה, עם הארגומנטים האחרונים", (t) => {
  t.mock.timers.enable({ apis: ["setTimeout"] });
  const fn = mock.fn();
  const save = debounce(fn, 300);
  save("a");
  t.mock.timers.tick(200);
  save("ab");
  t.mock.timers.tick(299);
  assert.equal(fn.mock.callCount(), 0, "עוד לא עברו 300ms מהקריאה האחרונה");
  t.mock.timers.tick(1);
  assert.equal(fn.mock.callCount(), 1);
  assert.deepEqual(fn.mock.calls[0].arguments, ["ab"]);
});

test("cancel מבטל", (t) => {
  t.mock.timers.enable({ apis: ["setTimeout"] });
  const fn = mock.fn();
  const save = debounce(fn, 300);
  save("x");
  save.cancel();
  t.mock.timers.tick(1000);
  assert.equal(fn.mock.callCount(), 0);
});

test("שתי סדרות נפרדות ← שתי קריאות", (t) => {
  t.mock.timers.enable({ apis: ["setTimeout"] });
  const fn = mock.fn();
  const save = debounce(fn, 100);
  save(1);
  t.mock.timers.tick(100);
  save(2);
  t.mock.timers.tick(100);
  assert.equal(fn.mock.callCount(), 2);
});

שלוש הבדיקות רצות במילישניות, למרות שהן "מחכות" שניות. ו־t.mock (של הבדיקה) מחזיר את הטיימרים האמיתיים לבד בסוף — בלי afterEach.

⚠️ טעויות נפוצות
  • await new Promise(r => setTimeout(r, 300)) — בדיקה איטית ושבירה (במחשב עמוס 300ms הם לפעמים 350).

P22-E13 · לשנות קוד כדי שיהיה בדיק 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

closure: let counter = 0 בתוך createInvoiceNumberer, לא ברמת הקובץ.

💡 רמז 2

ברירות מחדל בפרמטר שהוא אובייקט: ({ now = () => new Date(), random = Math.random } = {}).

✅ פתרון
// P22-E13 — אחרי השינוי: כל מה שלא צפוי (שעה, אקראיות) מוזרק, וה־counter שייך למופע
export interface InvoiceDeps {
  now?: () => Date;
  random?: () => number; // [0, 1)
}

export function createInvoiceNumberer({ now = () => new Date(), random = Math.random }: InvoiceDeps = {}) {
  let counter = 0;
  return function next(): string {
    counter++;
    const d = now();
    const month = String(d.getUTCMonth() + 1).padStart(2, "0"); // UTC: אותה תוצאה בכל אזור זמן
    const rand = String(Math.floor(random() * 1000)).padStart(3, "0");
    return `INV-${d.getUTCFullYear()}${month}-${String(counter).padStart(4, "0")}-${rand}`;
  };
}

זה הרעיון המרכזי של השיעור: קוד בדיק הוא קוד שמקבל את התלויות שלו, במקום לקחת אותן מהעולם. אותו דבר עשינו עם CLOCK בפרויקט — רק בלי Nest.

⚠️ טעויות נפוצות
  • להשאיר את counter גלובלי — הבדיקות תלויות בסדר שלהן.

P22-E27 · מטמון LRU עם Map 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שני שדות: #items = new Map<K, V>() ו־#capacity. ב־get: ‏if (!this.#items.has(key)) return undefined; (לא if (!value), בגלל 0), ואז delete ו־set מחדש.

💡 רמז 2

הישן ביותר: this.#items.keys().next().value — האיבר הראשון של ה־iterator. ‏TypeScript לא יודע שהוא קיים, ולכן as K. ב־set: קודם delete(key) (אם הוא קיים, כדי שיעבור לסוף), אחר כך set, ורק אז בודקים אם size > capacity.

✅ פתרון
// P22-E27: מטמון LRU עם Map
export class LruCache<K, V> {
  #items = new Map<K, V>();
  #capacity: number;

  constructor(capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 1) throw new RangeError("capacity חייב להיות מספר שלם חיובי");
    this.#capacity = capacity;
  }

  get(key: K): V | undefined {
    if (!this.#items.has(key)) return undefined;
    const value = this.#items.get(key) as V;
    // "נגיעה": מוציאים ומכניסים מחדש — עכשיו הוא האחרון בסדר של ה־Map
    this.#items.delete(key);
    this.#items.set(key, value);
    return value;
  }

  set(key: K, value: V): void {
    this.#items.delete(key);
    this.#items.set(key, value);
    if (this.#items.size > this.#capacity) {
      const oldest = this.#items.keys().next().value as K;
      this.#items.delete(oldest);
    }
  }

  get size(): number {
    return this.#items.size;
  }

  keys(): K[] {
    return [...this.#items.keys()];
  }
}

const cache = new LruCache<string, number>(2);
cache.set("a", 1);
cache.set("b", 2);
cache.get("a"); // a נהיה "האחרון שנגעו בו"
cache.set("c", 3); // אין מקום — b יוצא
console.log(cache.keys(), cache.get("b"), cache.size);
[ 'a', 'c' ] undefined 2

כל פעולה היא כמה פעולות על Map, וכל אחת מהן מהירה (O(1)). מימוש עם מערך של מפתחות (indexOf ו־splice בכל get) עובד, אבל לאט יותר ככל שהמטמון גדל.

ה־<K, V> אומר ש־new LruCache<string, number>(2) מקבל רק מספרים, ו־get מחזיר number | undefined. ה־undefined בטיפוס מכריח את מי שמשתמש במטמון לטפל במקרה של "לא נמצא".

למה זה בפרק הבדיקות? כי זו מחלקה שקל לבדוק: אין שעון, אין רשת, רק קלט ופלט. כדאי לכתוב לעצמך בדיקה לפני שמריצים את הבודק: מה ייצא כשמוסיפים פריט שלישי ל־capacity 2?

⚠️ טעויות נפוצות
  • set למפתח קיים בלי delete קודם — ‏Map.set משאיר אותו במקום הישן, והוא ייצא ראשון למרות שעדכנו אותו.
  • if (!value) return undefined — ‏0 ו־"" "לא נמצאים", ולא עוברים לסוף.
  • להוציא את הישן לפני ה־set גם כשהמפתח כבר קיים — מוציאים פריט בלי סיבה.

P22-E28 · memoizeAsync עם שעון מוזרק 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

שומרים במטמון את ה־Promise, לא את התוצאה: ‏Map<A, { promise, expiresAt }>. כך מי שמגיע בזמן ההמתנה מקבל את אותו Promise. ה־Map חי בתוך memoizeAsync, והפונקציה המוחזרת סוגרת עליו (closure).

חתימה עם generics: memoizeAsync<A extends string | number, R>(fn: (arg: A) => Promise<R>, { ttlMs, now = Date.now }: { ttlMs: number; now?: () => number }): (arg: A) => Promise<R>.

💡 רמז 2

שגיאה: promise.catch(() => cache.delete(arg)) מיד אחרי השמירה. ה־catch הזה לא "בולע" את השגיאה למי שקרא: הוא יוצר Promise חדש, ומי שקרא קיבל את המקורי. בדיקה זהירה יותר: למחוק רק אם במטמון עדיין יושב אותו Promise.

✅ פתרון
// P22-E28: memoizeAsync — מטמון לפונקציה אסינכרונית, עם שעון מוזרק
export function memoizeAsync<A extends string | number, R>(
  fn: (arg: A) => Promise<R>,
  { ttlMs, now = Date.now }: { ttlMs: number; now?: () => number },
): (arg: A) => Promise<R> {
  const cache = new Map<A, { promise: Promise<R>; expiresAt: number }>();

  return (arg: A) => {
    const hit = cache.get(arg);
    if (hit && hit.expiresAt > now()) return hit.promise;

    const promise = fn(arg);
    cache.set(arg, { promise, expiresAt: now() + ttlMs });
    // שגיאה לא נשמרת: הקריאה הבאה תנסה שוב
    promise.catch(() => {
      if (cache.get(arg)?.promise === promise) cache.delete(arg);
    });
    return promise;
  };
}

let clock = 0;
let calls = 0;
const getRate = memoizeAsync(
  async (currency: string) => {
    calls++;
    return currency === "USD" ? 3.7 : 4;
  },
  { ttlMs: 60_000, now: () => clock },
);

Promise.all([getRate("USD"), getRate("USD")])
  .then(([a, b]) => {
    console.log(a, b, "קריאות:", calls);
    clock = 60_000;
    return getRate("USD");
  })
  .then(() => console.log("אחרי דקה — קריאות:", calls));

אחרי דקה — קריאות: 2

שמירת ה־Promise היא העיקר. אילו שמרנו את התוצאה (אחרי await), שתי הקריאות הראשונות היו מגיעות לפני שיש תוצאה, ושתיהן היו קוראות ל־fn. בשרת עמוס זה נקרא cache stampede: מאה בקשות בבת אחת מפעילות מאה שאילתות זהות, בדיוק כשהמטמון התרוקן.

השעון המוזרק הופך "אחרי דקה" לשורה אחת בבדיקה (clock = 60_000), בלי לחכות דקה ובלי טיימרים מזויפים. זה הדפוס של שיעור 2: כל מה שתלוי בזמן מקבל now מבחוץ.

בפרק 26 תראה את אותו רעיון עם Redis: ‏GET, ואם אין — מחשבים ושומרים עם EX.

⚠️ טעויות נפוצות
  • const value = await fn(arg); cache.set(arg, value) — קריאות במקביל קוראות כולן ל־fn.
  • לשמור גם שגיאות — תקלה רגעית ברשת "נתקעת" במטמון לכל ה־TTL.
  • Date.now() ישירות בתוך הפונקציה במקום now() — הבודק לא יכול "להזיז את השעון".
  • expiresAt >= now() — התשובה תקפה גם ברגע שהיא אמורה לפוג.

// P22-E47 — הבדיקות
import { test, mock } from "node:test";
import assert from "node:assert/strict";
import { retry } from "./P22-E47.ts";

const failing = (...messages: string[]) => {
  const fn = mock.fn(async () => "ok");
  // הארגומנט השני: באיזו קריאה (0, 1, 2...). בלעדיו, שתי קריאות לפני הפעלה דורסות זו את זו
  messages.forEach((m, i) => fn.mock.mockImplementationOnce(async () => { throw new Error(m); }, i));
  return fn;
};

test("מצליח בפעם הראשונה — בלי המתנה", async () => {
  const fn = failing();
  const sleep = mock.fn(async (_ms: number) => {});
  assert.equal(await retry(fn, { sleep }), "ok");
  assert.equal(fn.mock.callCount(), 1);
  assert.equal(sleep.mock.callCount(), 0);
});

test("נכשל פעמיים ואז מצליח — המתנות מוכפלות", async () => {
  const fn = failing("1", "2");
  const sleep = mock.fn(async (_ms: number) => {});
  assert.equal(await retry(fn, { sleep }), "ok");
  assert.equal(fn.mock.callCount(), 3);
  assert.deepEqual(sleep.mock.calls.map((c) => c.arguments[0]), [100, 200]);
});

test("כולם נכשלים — השגיאה האחרונה, בלי המתנה אחרי האחרון", async () => {
  const fn = failing("1", "2", "3", "4");
  const sleep = mock.fn(async (_ms: number) => {});
  await assert.rejects(retry(fn, { attempts: 3, delayMs: 10, sleep }), { message: "3" });
  assert.equal(fn.mock.callCount(), 3);
  assert.deepEqual(sleep.mock.calls.map((c) => c.arguments[0]), [10, 20]);
});

test("attempts: 1 — ניסיון אחד", async () => {
  const fn = failing("only");
  const sleep = mock.fn(async (_ms: number) => {});
  await assert.rejects(retry(fn, { attempts: 1, sleep }), { message: "only" });
  assert.equal(fn.mock.callCount(), 1);
  assert.equal(sleep.mock.callCount(), 0);
});

test("attempts לא תקין ← RangeError", async () => {
  for (const attempts of [0, -1, 1.5]) {
    await assert.rejects(retry(async () => "x", { attempts, sleep: async () => {} }), RangeError, `attempts ${attempts}`);
  }
});
