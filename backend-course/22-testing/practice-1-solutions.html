P22-E01 · unit, integration או e2e? 🧠 הבנה רמה 1

💡 רמז 1

השאלה היא כמה חלקים אמיתיים משתתפים: פונקציה אחת? מסד? כל השרת? דפדפן?

💡 רמז 2

פירמידה: הרבה בדיקות מהירות בבסיס, מעט איטיות בקצה.

✅ פתרון
  1. unit — פונקציה טהורה, בלי שום תלות. מילישניות.
  2. unit — ה־service לבד, עם fake במקום המסד.
  3. integration — הקוד שלך מול מערכת אמיתית (PostgreSQL). זה מה שבדיקה בזיכרון לא יכולה לתפוס: SQL, NULLs, אזורי זמן.
  4. e2e (של ה־API) — כל השרשרת דרך HTTP. בפרויקט: supertest מול האפליקציה עם repositories בזיכרון — עדיין e2e של השרת, בלי מסד.
  5. e2e של המערכת (UI) — הכי קרוב למשתמש, הכי איטי והכי שביר (Playwright, Cypress). מעט מאוד כאלה.
  6. unit — מחלקה אחת.

שלוש ראשונות: (4) — היא מכסה הכי הרבה ומוכיחה שהדברים מחוברים; (2) — הלוגיקה העסקית והגבולות; (3) — מה שרק המסד יגלה. ההיגיון: לא "הכי הרבה בדיקות", אלא "הכי הרבה ביטחון לשעה".

⚠️ טעויות נפוצות
  • לקרוא לכל בדיקה עם Jest "unit". הסוג נקבע לפי מה שאמיתי בה, לא לפי הכלי.

P22-E02 · מה רע בבדיקות האלה? 🧠 הבנה רמה 1

💡 רמז 1

חמש בעיות שונות: תלות בסדר, תלות בזמן, תלות ברשת, בדיקה בלי assert, ו"חישוב מחדש" של התוצאה.

💡 רמז 2

מה יקרה אם מריצים רק את "מוחק משימה"? ומה אם מריצים את "תאריך יעד" מחר?

✅ פתרון
  1. "מוסיף" ו"מוחק" — תלויות זו בזו (state משותף ברמת הקובץ). "מוחק" לבד ← tasks.length הוא 0 מההתחלה, והוא עובר בלי לבדוק כלום; בסדר הפוך — נכשל. כל בדיקה יוצרת את הנתונים שלה (או beforeEach).
  2. "תאריך יעד" — תלויה בשעון: עוברת רק ב־4 בנובמבר 2026. מעבירים now קבוע (E22).
  3. "שולח מייל" — רשת אמיתית, ובלי assert: איטית, נכשלת כשאין אינטרנט, שולחת מיילים אמיתיים — ובכל זאת לא בודקת כלום (עוברת כל עוד לא נזרקה שגיאה). מזריקים mailer מזויף ובודקים מה נשלח (E11).
  4. "מחשב סכום" — מחשבת את התשובה באותה נוסחה כמו הקוד: אם הנוסחה שגויה, גם הציפייה שגויה. כותבים את התוצאה כמספר: 20.
⚠️ טעויות נפוצות
  • לחשוב שבדיקה ירוקה היא בדיקה טובה. השאלה היא אם היא יכולה להיכשל כשיש באג — זה כל הפרק.

P22-E03 · לקרוא בדיקה שנכשלה 🧠 הבנה רמה 1

💡 רמז 1

+ = מה שקיבלנו (actual), - = מה שציפינו (expected). שורות בלי סימן — זהות.

💡 רמז 2

עם page=1 ו־limit=20 יצא offset=20. איזו נוסחה נותנת את זה?

✅ פתרון

(א) הקוד החזיר offset: 20; ציפינו ל־0. page ו־limit נכונים.

(ב) הנוסחה כנראה page * limit במקום (page - 1) * limit — off-by-one קלאסי. (זה אחד המוטנטים של E08.)

(ג) השוואה של כל האובייקט תופסת גם שדה שלא חשבת עליו (שדה מיותר, שדה חסר, שם שגוי), וההודעה מראה את כל ההבדל בבת אחת. שלוש בדיקות נפרדות עוצרות בראשונה שנכשלת.

⚠️ טעויות נפוצות
  • להפוך את הסדר: assert.equal(expected, actual) — אז ה־+ וה־- מתהפכים, וההודעה מטעה. הסדר תמיד: actual ואחר כך expected.

P22-E29 · ‏actual ו־expected הפוכים 🧠 הבנה רמה 1

💡 רמז 1

הפרמטר הראשון של assert.equal הוא תמיד "מה שקיבלנו".

💡 רמז 2

+ הוא actual — כלומר מה שכתבת ראשון.

✅ פתרון
  • (א) לפי הפלט: הקוד החזיר 11800, וציפינו ל־11700.
  • (ב) הפוך: הקוד החזיר 11700, והציפייה הנכונה היא 11800. הפלט "משקר" כי הסדר הפוך.
  • (ג) מי שקורא את הכישלון מחפש באג שמחזיר 11800, ואולי "מתקן" את הבדיקה ל־11700 — והבאג נשאר, עם בדיקה ירוקה.
  • (ד) assert.equal(withVat(10000), 11800);
⚠️ טעויות נפוצות
  • לחשוב שהסדר "לא משנה כי זה שוויון". לתוצאה לא, אבל להודעה כן, וההודעה היא מה שאנשים קוראים.

P22-E30 · ‏equal, deepEqual — מה עובר? 🧠 הבנה רמה 2

💡 רמז 1

equal ב־strict הוא Object.is: שני אובייקטים שונים אף פעם לא "שווים", גם עם אותו תוכן.

💡 רמז 2

deepEqual ב־strict בודק גם שאותם מפתחות קיימים, גם סדר במערך, וגם מבדיל בין -0 ל־0.

✅ פתרון
import assert from "node:assert/strict";
const checks: [string, () => void][] = [
  ["equal על אובייקטים", () => assert.equal({ a: 1 }, { a: 1 })],
  ["deepEqual על מערכים בסדר אחר", () => assert.deepEqual([1, 2], [2, 1])],
  ["equal(NaN, NaN)", () => assert.equal(NaN, NaN)],
  ["deepEqual עם undefined", () => assert.deepEqual({ a: 1, b: undefined }, { a: 1 })],
  ["equal(\"1\", 1)", () => assert.equal("1", 1)],
  ["deepEqual על תאריכים", () => assert.deepEqual(new Date("2026-11-05"), new Date("2026-11-05T00:00:00Z"))],
  ["deepEqual(-0, 0)", () => assert.deepEqual(-0, 0)],
];
for (const [name, check] of checks) {
  try { check(); console.log(`✔ ${name}`); } catch { console.log(`✖ ${name}`); }
}
✖ equal על אובייקטים
✖ deepEqual על מערכים בסדר אחר
✔ equal(NaN, NaN)
✖ deepEqual עם undefined
✖ equal("1", 1)
✔ deepEqual על תאריכים
✖ deepEqual(-0, 0)
  • אובייקטים: equal נכשל (שני אובייקטים שונים), צריך deepEqual.
  • מערכים: סדר הוא חלק מהערך. אם הסדר לא אמור לשנות, ממיינים לפני ההשוואה.
  • NaN: ב־strict ‏(Object.is) — שווה. (עם === היה לא שווה.)
  • b: undefined מול בלי b: ב־strict, שונה. זה חשוב: תשובת JSON בלי שדה ותשובה עם null הן לא אותו דבר.
  • "1" מול 1: נכשל, וטוב שכך (בלי strict זה היה עובר).
  • תאריכים: אותו רגע ← שווים.
⚠️ טעויות נפוצות
  • לייבא node:assert בלי /strict. אז equal("1", 1) עובר, ובאגים של מחרוזת במקום מספר (query string!) נעלמים.

P22-E31 · בדיקה אחת שעושה הכול 🧠 הבנה רמה 2

💡 רמז 1

כמה פעולות (Act) יש כאן? כל אחת היא בדיקה.

💡 רמז 2

מה תגיד ההודעה אם השורה החמישית נכשלת? ומה עם השורות שאחריה — הן ירוצו?

✅ פתרון

ארבע פעולות, וכל אחת תלויה במצב שהקודמות השאירו. כשמשהו נכשל, השם "עגלה" לא אומר מה, ושאר הבדיקות לא רצות. וגם assert.throws בלי סוג שגיאה תופס כל שגיאה, גם TypeError של באג.

test("מוצר אחד ← הסכום הוא המחיר", () => {
  const cart = new Cart();
  cart.add("mug", 4990);
  assert.equal(cart.totalAgorot(), 4990);
});
test("אותו מוצר פעמיים ← הכמויות מצטברות", () => {
  const cart = new Cart();
  cart.add("mug", 4990);
  cart.add("mug", 4990, 2);
  assert.equal(cart.count, 3);
});
test("יותר מ־10 מאותו מוצר ← RangeError", () => {
  const cart = new Cart();
  cart.add("mug", 4990, 3);
  assert.throws(() => cart.add("mug", 4990, 8), RangeError);
});
test("הסרה ← העגלה ריקה", () => {
  const cart = new Cart();
  cart.add("mug", 4990, 3);
  cart.remove("mug");
  assert.equal(cart.count, 0);
});

כל בדיקה מתחילה מעגלה חדשה (Arrange משלה), עושה דבר אחד, ובודקת אותו. כשאחת נכשלת, השם שלה הוא כבר חצי מהאבחנה.

⚠️ טעויות נפוצות
  • "זה יותר שורות". כן, אבל כל שורה פשוטה, וכישלון אחד לא מסתיר את האחרים.

P22-E06 · בדיקות ראשונות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

לכל כלל בתיאור — לפחות בדיקה אחת שתיכשל אם הכלל לא מתקיים.

💡 רמז 2

אל תשכח את מה ש"נשאר": עברית וספרות. ומה עם קלט שכולו סימנים?

✅ פתרון
// P22-E06 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { slugify } from "./P22-E06.ts";

test("אותיות קטנות, ורווח ← מקף", () => {
  assert.equal(slugify("Hello World"), "hello-world");
});

test("רצף של סימנים ← מקף אחד", () => {
  assert.equal(slugify("Node.js -- 24!!"), "node-js-24");
});

test("בלי מקפים בהתחלה ובסוף", () => {
  assert.equal(slugify("  ...Learn Express!  "), "learn-express");
});

test("עברית וספרות נשארות", () => {
  assert.equal(slugify("פרק 22: בדיקות"), "פרק-22-בדיקות");
});

test("רק סימנים ← מחרוזת ריקה", () => {
  assert.equal(slugify("!!!"), "");
  assert.equal(slugify(""), "");
});

שים לב לשמות הבדיקות: כל אחת אומרת איזה כלל היא בודקת. כשמשהו נשבר, שם הבדיקה כבר מסביר מה.

⚠️ טעויות נפוצות
  • בדיקה אחת ענקית עם עשרה assert — היא עוצרת בראשון שנכשל, ואתה לא יודע מה עוד שבור.

P22-E07 · גבולות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

הבאגים גרים בגבולות: בדיוק minTotal, קופון גדול מהסכום, עגלה ריקה.

💡 רמז 2

עיגול: 0.1 * 3 ב־JavaScript הוא 0.30000000000000004.

✅ פתרון
// P22-E07 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { cartTotal } from "./P22-E07.ts";

const mug = { price: 40, qty: 2 }; // 80
const jug = { price: 20, qty: 1 }; // 20

test("עגלה ריקה ← 0", () => {
  assert.equal(cartTotal([]), 0);
});

test("מחיר × כמות", () => {
  assert.equal(cartTotal([mug, jug]), 100);
});

test("קופון אחוזים וקופון קבוע", () => {
  assert.equal(cartTotal([mug, jug], { type: "percent", value: 10 }), 90);
  assert.equal(cartTotal([mug, jug], { type: "fixed", value: 15 }), 85);
});

test("minTotal: בדיוק בגבול — חל; מתחת — לא", () => {
  assert.equal(cartTotal([mug, jug], { type: "fixed", value: 10, minTotal: 100 }), 90);
  assert.equal(cartTotal([mug], { type: "fixed", value: 10, minTotal: 100 }), 80);
});

test("לא יורד מתחת ל־0", () => {
  assert.equal(cartTotal([jug], { type: "fixed", value: 50 }), 0);
});

test("עיגול לאגורות", () => {
  assert.equal(cartTotal([{ price: 0.1, qty: 3 }]), 0.3);
  assert.equal(cartTotal([{ price: 9.99, qty: 1 }], { type: "percent", value: 15 }), 8.49);
});

כל בדיקה כאן היא גבול: בדיוק בסף, מתחת לסף, מתחת לאפס, ושבר עשרוני. כלל אצבע: לכל > או >= בקוד — בדיקה על הערך עצמו ועל אחד לידו.

⚠️ טעויות נפוצות
  • להשתמש רק במספרים "עגולים" (100, 50) — אז אף באג של עיגול לא יתגלה.

P22-E08 · בדיקות של שגיאות 🤖 💻 כתיבת קוד 🤖 רמה 2

💡 רמז 1

assert.throws(() => fn(), RangeError) — בודק גם שנזרק וגם את הסוג. עם { message: "..." } — גם את ההודעה.

💡 רמז 2

לולאה על רשימת קלטים לא תקינים חוסכת הרבה שורות — רק תן לכל אחד הודעה (הפרמטר השלישי).

✅ פתרון
// P22-E08 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { parsePagination } from "./P22-E08.ts";

test("ברירות מחדל", () => {
  assert.deepEqual(parsePagination({}), { page: 1, limit: 20, offset: 0 });
  assert.deepEqual(parsePagination({}, { defaultLimit: 5 }), { page: 1, limit: 5, offset: 0 });
});

test("offset", () => {
  assert.deepEqual(parsePagination({ page: "3", limit: "10" }), { page: 3, limit: 10, offset: 20 });
});

test("הגבולות עצמם תקינים", () => {
  assert.equal(parsePagination({ limit: "50" }).limit, 50);
  assert.equal(parsePagination({ limit: "1" }).limit, 1);
});

test("ערכים לא תקינים ← RangeError", () => {
  for (const query of [{ page: "0" }, { page: "-1" }, { page: "abc" }, { page: "" }, { limit: "51" }, { limit: "0" }, { limit: "2.5" }]) {
    assert.throws(() => parsePagination(query), RangeError, JSON.stringify(query));
  }
});

test("ההודעה מציינת את הערך", () => {
  assert.throws(() => parsePagination({ limit: "99" }), { message: "limit לא תקין: 99" });
});

שים לב ש־assert.throws מקבל פונקציה (() => parsePagination(...)), לא את התוצאה. אחרת השגיאה נזרקת עוד לפני ש־assert רץ, והבדיקה נכשלת עם השגיאה עצמה.

⚠️ טעויות נפוצות
  • assert.throws(() => fn()) בלי סוג — עובר גם על TypeError מבאג אחר לגמרי.

P22-E17 · טבלת מקרים 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

לכל כלל בתיאור — שורה שתיכשל בלעדיו. "מעל 9 מחסירים 9" — מספר עם ספרות גדולות במקומות הזוגיים.

💡 רמז 2

"ספרות בלבד" — נסה תו ש־Number() הופך ל־0: רווח באמצע.

✅ פתרון
// P22-E17 — הבדיקות
import { test } from "node:test";
import assert from "node:assert/strict";
import { isValidIsraeliId } from "./P22-E17.ts";

// "טבלה" של מקרים — ובדיקה אחת שעוברת עליה. מקרה חדש = שורה חדשה
const cases: [string, boolean, string][] = [
  ["123456782", true, "תקין"],
  ["039337423", true, "תקין, מתחיל ב־0"],
  ["000000018", true, "צריך \"מעל 9 ← מחסירים 9\"? לא, אבל משקל 2"],
  ["18", true, "קצר — משלימים אפסים"],
  ["999999998", true, "הרבה ספרות מעל 9 אחרי הכפלה"],
  [" 123456782 ", true, "רווחים מסביב"],
  ["123456789", false, "ספרת ביקורת שגויה"],
  ["300000004", false, "שגוי"],
  ["1234567820", false, "10 ספרות"],
  ["12345678a", false, "לא ספרה"],
  ["1234 0004", false, "רווח באמצע (123400004 תקין) — Number(\" \") הוא 0, אז בלי בדיקת ספרות זה היה \"עובר\""],
  ["", false, "ריק"],
];

for (const [id, expected, why] of cases) {
  test(`${JSON.stringify(id)} ← ${expected} (${why})`, () => {
    assert.equal(isValidIsraeliId(id), expected);
  });
}

המקרה המעניין הוא "1234 0004": Number(" ") הוא 0, ו־123400004 תקין — כך שקוד בלי בדיקת "ספרות בלבד" היה מקבל אותו. ("12345678a" לא מספיק: Number("a") הוא NaN, והסכום נכשל ממילא.) בדיקה טובה בוחרת קלט שבו הבאג משנה את התוצאה.

⚠️ טעויות נפוצות
  • טבלה רק של מקרים תקינים — אף כלל לא נבדק בכיוון ה"נדחה".

P22-E20 · בדיקות שלא יכולות להיכשל 🤖 💻 כתיבת קוד 🤖 רמה 4

💡 רמז 1

שלושה דפוסים: השוואה של אובייקט לעצמו; try/catch בלי כישלון כשלא נזרק כלום; לולאה על תוצאה שיכולה להיות ריקה.

💡 רמז 2

await assert.rejects(promise, ErrorClass) במקום try/catch. ו־deepEqual עם הערך הצפוי, כתוב במפורש.

✅ פתרון
// P22-E20 — מתוקן
import { test } from "node:test";
import assert from "node:assert/strict";
import { InsufficientFundsError, lowBalance, transfer } from "./P22-E20.ts";

test("העברה מעדכנת את שני החשבונות", async () => {
  const accounts = new Map([["a", 100], ["b", 0]]);

P22-E26 · בדיקות ל־pagination — מקובץ ריק 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1

לכל השוואה בקוד (<, ‏>, ‏>=) — בדיקה בדיוק על הגבול. ‏hasNext בעמוד האחרון, ‏hasPrev בעמוד הראשון, ‏pageSize של 100 ושל 101. ולספירת עמודים: מספר שורות שמתחלק בדיוק, ואחד שלא.

💡 רמז 2

טבלת מקרים (‏P22-E17) חוסכת הרבה שורות לקלט לא תקין: for (const [total, page, size] of bad) assert.throws(() => paginate(total, page, size), RangeError, ...). וקריאה בלי pageSize בודקת את ברירת המחדל.

  const bad: [number, number, number?][] = [

    [10.5, 1],

    [10, -1],
    [10, 1.5],
    [10, 1, 0],
    [10, 1, 101],
    [10, 1, 2.5],

  • לבדוק רק "עמוד 1 של 100 שורות" — ‏floor ו־ceil נותנים 10 בשניהם, ו־hasNext בעמוד האחרון לא נבדק.

P22-E38 · מריץ בדיקות משלך 🤖 💻 כתיבת קוד 🤖 רמה 3

💡 רמז 1
for (const t of tests) { try { await ...; passed.push(t.name); } catch (err) { failed.push(...) } }

await t.fn() עובד גם על פונקציה סינכרונית.

💡 רמז 2

timeout:

Promise.race([Promise.resolve().then(t.fn), new Promise((_, reject) => timer = setTimeout(...))])

ובסוף clearTimeout(timer) כדי שהטיימר לא ישאיר את התהליך ער.

✅ פתרון
// P22-E38: מריץ בדיקות קטן
export type TestCase = { name: string; fn: () => void | Promise<void> };
export type Report = { passed: string[]; failed: { name: string; message: string }[] };

export async function runTests(tests: TestCase[], { timeoutMs = 1000 }: { timeoutMs?: number } = {}): Promise<Report> {
  const report: Report = { passed: [], failed: [] };
  for (const t of tests) {
    let timer: ReturnType<typeof setTimeout> | undefined;
    const timeout = new Promise<never>((_, reject) => {
      timer = setTimeout(() => reject(new Error(`timeout אחרי ${timeoutMs}ms`)), timeoutMs);
    });
    try {
      await Promise.race([Promise.resolve().then(t.fn), timeout]);
      report.passed.push(t.name);
    } catch (err) {
      report.failed.push({ name: t.name, message: err instanceof Error ? err.message : String(err) });
    } finally {
      clearTimeout(timer);
    }
  }
  return report;
}

Promise.resolve().then(t.fn) ולא t.fn() ישירות: אם fn סינכרונית וזורקת, t.fn() היה זורק לפני ש־Promise.race קיבל משהו. בתוך then הזריקה הופכת ל־Promise שנדחה, ומטופלת כמו כל כישלון. בבדיקה ש"נתקעה" אין דרך באמת לעצור אותה (אין "ביטול" ב־JavaScript). המריץ רק מפסיק לחכות לה. גם node --test עובד כך.

⚠️ טעויות נפוצות
  • Promise.all(tests.map(...)) — מריץ במקביל. בדיקות שחולקות מצב (מסד, קובץ) מפריעות זו לזו.
  • לשכוח clearTimeout — התהליך מחכה עוד שנייה בסוף כל בדיקה.
