שיעור 3 — המרות, NaN ומלכודות

⏱ ~25 דקות

🎯 בשיעור הזה
  • להמיר טקסט למספר (Number) ומספר לטקסט (String, toFixed).
  • לזהות NaN — "לא מספר".
  • להכיר את ההמרות האוטומטיות של JavaScript, ולמה הן מסוכנות.

1. הבעיה

בשרת, כמעט כל קלט מגיע כטקסט: כתובת URL כמו /products?page=2, שדה בטופס, קובץ. גם כשהמשתמש הקליד 2, השרת מקבל "2". ואז:

const quantityFromForm = "2";
const price = 50;
console.log(quantityFromForm + price);
console.log(quantityFromForm * price);
250
100

שורה ראשונה: "2" + 50 הפך לשרשור — "250". שורה שנייה עבדה "במקרה". שני המקרים מבלבלים — והפתרון הוא להמיר במפורש.

2. Number(...) — טקסט למספר

console.log(Number("42"));
console.log(Number("49.90"));
console.log(Number("  7  "));
console.log(Number(""));
console.log(Number("12abc"));
console.log(Number("שלוש"));
42
49.9
7
0
NaN
NaN

רוב התוצאות צפויות. שתיים מסוכנות: Number("") נותן 0 (שדה ריק הופך לאפס!), ו־"12abc" נותן NaN.

NaN — "Not a Number"

NaN הוא הערך שמקבלים כשחישוב או המרה נכשלים. הוא "מדבק": כל חישוב איתו נותן שוב NaN. ובאופן מוזר — typeof NaN הוא "number".

const bad = Number("abc");
console.log(bad + 10);
console.log(typeof bad);
console.log(Number.isNaN(bad));
console.log(Number.isNaN(42));
NaN
number
true
false

הדרך הנכונה לבדוק: Number.isNaN(x). בפרק 3 נשתמש בזה כדי לדחות קלט לא תקין ("נא להזין מספר").

💡 ומה עם parseInt / parseFloat?

הן "סלחניות": קוראות מספר מתחילת הטקסט ועוצרות בתו הראשון שאינו ספרה. parseFloat("3.5kg") ← 3.5, parseInt("12abc") ← 12. שימושי לפעמים, אבל ב־Backend עדיף בדרך כלל להיות קפדן: אם הגיע "12abc" — זה כנראה קלט שגוי, ועדיף NaN ושגיאה ברורה. בקורס נשתמש ב־Number.

3. מספר לטקסט: String ו־toFixed

const price = 19.9;
console.log(String(price) + "!");
console.log(price.toFixed(2));
console.log(typeof price.toFixed(2));
console.log((1234.5).toFixed(0));
19.9!
19.90
string
1235

toFixed(2) מחזיר טקסט עם בדיוק 2 ספרות אחרי הנקודה (ומעגל). מושלם להצגה — אבל זה טקסט, אז לא ממשיכים לחשב איתו. כלל: מחשבים עם מספרים, ומעגלים עם toFixed רק ברגע ההדפסה.

⚠️ גם toFixed לא מושלם 
console.log((1.005).toFixed(2));
1.00

ציפית ל־1.01? 1.005 נשמר בזיכרון כ־1.00499999... (אותה בעיה של 0.1 + 0.2). עוד סיבה לשמור כסף באגורות שלמות.

4. ⚡ ההמרות האוטומטיות

⚡ חשוב גם במסלול המהיר — Type coercion

JavaScript מנסה "לעזור" ומבצעת המרות לבד כשסוגים מתערבבים. הכלל שצריך לזכור:

  • + עם מחרוזת באחד הצדדים ← שרשור.
  • -, *, /, % ← הכול מומר למספר.
console.log("5" + 3);
console.log("5" - 3);
console.log("5" * "2");
console.log("abc" * 2);
console.log(1 + 2 + "3");
console.log("1" + 2 + 3);
53
2
10
NaN
33
123

שתי השורות האחרונות מראות שזה עובד משמאל לימין: 1 + 2 = 3 (מספרים), ואז 3 + "3" = "33". אבל "1" + 2 = "12", ואז "12" + 3 = "123". המסקנה: לעולם אל תסמוך על המרה אוטומטית. המר במפורש עם Number().

👣 דוגמה מודרכת: מחיר עם מע״מ מטופס

const priceInput = "49.90";
const quantityInput = "3";
const vatRate = 0.18;

const unitPrice = Number(priceInput);
const quantity = Number(quantityInput);
const subtotal = unitPrice * quantity;
const vat = subtotal * vatRate;
const total = subtotal + vat;

console.log(`ביניים: ${subtotal.toFixed(2)}`);
console.log(`מע״מ: ${vat.toFixed(2)}`);
console.log(`לתשלום: ${total.toFixed(2)}`);
ביניים: 149.70
מע״מ: 26.95
לתשלום: 176.65

המרה בהתחלה, חישוב עם מספרים באמצע, toFixed רק בהצגה. זה הדפוס.
