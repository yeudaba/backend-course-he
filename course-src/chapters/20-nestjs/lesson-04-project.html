  • Swagger: תיעוד API אוטומטי וממשק לניסוי.
  • בדיקות ב־Nest: `Test.createTestingModule` ו־`overrideProvider`.
  • פרויקט 2 עובר ל־Nest — עם אותו API בדיוק. בסוף: PR2-NEST עובר.

1. Swagger

```ts file=src/app.setup.ts import { DocumentBuilder, SwaggerModule } from "@nestjs/swagger"; const config = new DocumentBuilder().setTitle("tasks-api").setVersion("1.0").build(); SwaggerModule.setup("docs", app, () => SwaggerModule.createDocument(app, config)); ```

פתח `http://localhost:3000/docs`: כל ה־endpoints, עם כפתור "Try it out" ששולח בקשה אמיתית. ה־JSON הגולמי (מפרט OpenAPI) — ב־`/docs-json`; ממנו אפשר לייצר לקוחות אוטומטית (גם ה־Frontend יכול). Nest יודע לתאר את הגוף מתוך DTO של class־validator, עם `@ApiProperty()` על השדות (או ה־plugin של ה־CLI שמוסיף אותם לבד). בפרויקט שלנו הסכמות הן Zod — ו־Zod 4 יודע לייצר JSON Schema: `@ApiBody({ schema: z.toJSONSchema(createTaskSchema, { io: "input" }) })`.

💡 למה זה חשוב בראיון

קישור ל־`/docs` של פרויקט שרץ — המראיין לוחץ, רואה את כל ה־API, ושולח בקשה. זה שווה יותר מעמוד README שלם. בפרויקט הדגל זו דרישה.

2. בדיקה של אפליקציית Nest

```ts const moduleRef = await Test.createTestingModule({ imports: [AppModule] }) .overrideProvider(TASKS_REPOSITORY).useValue(new InMemoryTasksRepository()) .overrideProvider(CLOCK).useValue({ now: () => new Date("2026-11-04T10:00:00Z") }) .compile(); const app = moduleRef.createNestApplication(); configureApp(app); // אותן הגדרות גלובליות כמו ב־main.ts await app.init(); await app.listen(0); // או: supertest מול app.getHttpServer() ```

זה מה שהבודק עושה לפרויקט שלך (ופרק 22 יעמיק). שים לב לשני דברים שמאפשרים את זה: (1) `configureApp` — פונקציה אחת עם כל ההגדרות הגלובליות, ש־main.ts וגם הבדיקות קוראות לה; (2) tokens לתלויות שמחליפים.

3. פרויקט 2 עובר ל־Nest

הכי נקי: ענף חדש ב־Git (`git switch -c nest`), פרויקט Nest חדש בתיקייה זמנית, והעברת הקוד אליו. בסוף — מיזוג לענף הראשי. ההיסטוריה ב־GitHub תספר את הסיפור.

```term % cd ~/dev && npx @nestjs/cli@12 new tasks-nest --package-manager npm --strict --skip-git --no-observe ```

לשאלה על מערכת המודולים בוחרים שוב CJS (CommonJS) עם Jest, כמו בשיעור 1.

העבר מ־`tasks-nest` לתוך `tasks-api`: `nest-cli.json`, `tsconfig.json`, `tsconfig.build.json`, ואת ה־scripts וה־dependencies מ־`package.json` (ו־`npm install`). מ־`tasks-api` הקיים נשארים: `prisma/` (כמעט בלי שינוי), `src/tasks/tasks.schema.ts`, `tasks.repository.ts`, `tasks.prisma-repository.ts`, `tasks.service.ts`, `src/errors.ts`, `web/`, `requests.http`.

קובץמה עושים
כל ה־importsבלי `.ts` בסוף (בתבנית CJS הפרויקט מתקמפל ל־CommonJS)
`prisma/schema.prisma`בגנרטור: `moduleFormat = "cjs"` ו־`importFileExtension = ""` — ואז `npx prisma generate`. (אין migration חדש: המבנה לא השתנה)
`src/prisma/prisma.service.ts` + `prisma.module.ts`חדש: `PrismaService extends PrismaClient`, עם ה־adapter ו־`timezone=UTC`; module עם `@Global()`
`src/tasks/tasks.tokens.ts`חדש: `TASKS_REPOSITORY`, `CLOCK` ו־`interface Clock`
`tasks.service.ts``@Injectable()`, ו־constructor עם `@Inject(TASKS_REPOSITORY)` ו־`@Inject(CLOCK)`
`tasks.prisma-repository.ts``@Injectable()`, ו־`constructor(private readonly prisma: PrismaService)`
`src/common/zod-validation.pipe.ts`חדש: pipe שמקבל סכמת Zod וזורק `HttpError(400, "VALIDATION_ERROR", ...)` עם paths כמו `body.title`
`tasks.controller.ts`במקום `tasks.routes.ts`: `@Get()`, `@Get("stats")` (לפני `:id`!), `@Post()` עם `Location`, `@Delete()` עם `@HttpCode(204)`
`src/common/http-error.filter.ts`במקום `errorHandler`: `@Catch()` שמחזיר `{ error: { code, message, details? } }` — גם ל־`HttpError`, גם ל־404 של Nest, גם ל־JSON שבור, ו־500 לכל השאר
`src/app.setup.ts``configureApp(app, { corsOrigins })`: filter, CORS, Swagger
`src/main.ts`, `app.module.ts`, `health.controller.ts`bootstrap, module ראשי (`PrismaModule`, `TasksModule`), ו־`GET /health`
💡 רמז: ה־Location ב־POST

`@Res({ passthrough: true }) res: Response` בפרמטרים, ואז `res.location(...)` — וממשיכים להחזיר את האובייקט כרגיל (passthrough אומר ל־Nest "אני רק נוגע ב־res, אתה עדיין שולח").

💡 רמז: ZodValidationPipe ו־params

`transform(value, metadata)` — `metadata.type` הוא `"body"`, `"query"` או `"param"`, ו־`metadata.data` הוא שם הפרמטר (`"id"`). כך בונים את ה־path: `params.id`. ל־`@Param("id", pipe)` מעבירים סכמה של ערך בודד: `idParamsSchema.shape.id`.

💡 רמז: לזהות JSON שבור ב־filter

Nest עוטף את השגיאה של body-parser כ־`BadRequestException` שההודעה שלה מזכירה JSON. `/JSON/i.test(message)` ← `INVALID_JSON`.

4. להריץ ולבדוק

```term % npm run start:dev .. tasks-api רץ: http://localhost:3000 (תיעוד: /docs) % npm run build % cd ~/dev/backend-course && npm run check PR2-NEST -- --dir ~/dev/tasks-api ```

PR2-NEST טוען את ה־`dist/` שלך (לכן `npm run build` לפני), מחליף את ה־repository ואת השעון, ומריץ את בדיקות ה־API — כולל שמבנה השגיאות זהה לגרסת Express, ושהתיעוד ב־`/docs-json`. (PR2-SCHEMA/SERVICE/API/LIST/DB נכתבו לגרסת Express ולא ירוצו על פרויקט Nest — זה צפוי.) ובדיקה ידנית: הדף של יחידה 15.5 (`npm run web`) עובד מול השרת החדש בלי שום שינוי. זה כל הרעיון.
