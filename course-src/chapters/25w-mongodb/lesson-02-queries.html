🎯 בשיעור הזה
  • אופרטורים בשאילתה: $gt, $in, $ne, $or, $regex.
  • שאילתות על מערכים: "מכיל", $all, $elemMatch.
  • מיון, דילוג והגבלה — ועימוד.
  • עדכונים: $set, $inc, $push, $addToSet, $pull, upsert.
  • עדכון אטומי עם תנאי — איך Mongo מונע את המרוץ מפרק 18.

1. אופרטורים

במקום ערך, אפשר לתת לשדה אובייקט של אופרטורים. התרגום מ־SQL כמעט מילולי:

SQLMongoDB
price <= 50{ price: { $lte: 50 } }
price BETWEEN 40 AND 60{ price: { $gte: 40, $lte: 60 } }
status IN ('paid', 'delivered'){ status: { $in: ["paid", "delivered"] } }
status <> 'cancelled'{ status: { $ne: "cancelled" } }
a = 1 AND b = 2{ a: 1, b: 2 }
a = 1 OR b = 2{ $or: [{ a: 1 }, { b: 2 }] }
name ILIKE '%mug%'{ name: { $regex: "mug", $options: "i" } }
specs IS NOT NULL{ specs: { $exists: true } }
⚠️ $regex מקלט של משתמש

הטקסט שהמשתמש הקליד הוא טקסט, לא regex. "(1" שובר את השאילתה, ו־".*" מחזיר הכול. לפני שמכניסים ל־$regex — escaping של התווים המיוחדים (E20). ו־$regex עם i לא משתמש באינדקס רגיל: על קטלוג גדול — אינדקס טקסט או Atlas Search.

2. מערכים

ב־Mongo מערך הוא אזרח מלא, והשאילתות "מבינות" אותו:

```ts run import { MongoClient } from "mongodb"; const client = new MongoClient(process.env.MONGO_URL ?? "mongodb://localhost:27017/?directConnection=true"); const db = client.db("lesson2"); const products = db.collection("products"); await products.insertMany([ { _id: "p1", name: "Ethiopia Yirgacheffe", tags: ["light", "single-origin"], reviews: [{ by: "c1", rating: 5 }, { by: "c3", rating: 4 }] }, { _id: "p5", name: "V60 Dripper", tags: ["pour-over"], reviews: [{ by: "c3", rating: 5 }] }, { _id: "p7", name: "Gooseneck Kettle", tags: ["pour-over", "kettle"], reviews: [{ by: "c1", rating: 2 }, { by: "c2", rating: 5 }] }, ]); const ids = async (filter: object) => (await products.find(filter).toArray()).map((p) => p._id); console.log(await ids({ tags: "pour-over" })); // המערך מכיל את הערך console.log(await ids({ tags: { $all: ["pour-over", "kettle"] } })); // מכיל את כולם console.log(await ids({ "reviews.by": "c1", "reviews.rating": 5 })); // ⚠️ כל תנאי — על פריט אחר? console.log(await ids({ reviews: { $elemMatch: { by: "c1", rating: 5 } } })); // שני התנאים על אותו פריט await db.dropDatabase(); await client.close(); ``` ```out [ 'p5', 'p7' ] [ 'p7' ] [ 'p1', 'p7' ] [ 'p1' ] ```

השורה השלישית היא המלכודת של השיעור: "reviews.by": "c1" ו־"reviews.rating": 5 מתקיימים כל אחד בנפרד — אולי על פריטים שונים במערך. ב־p7, c1 נתן 2 ו־c2 נתן 5, ובכל זאת p7 חזר. כשכמה תנאים צריכים להתקיים על אותו פריט — $elemMatch.

3. מיון ועימוד

sort, skip, limit — על ה־cursor, בכל סדר שתכתוב (השרת מבצע תמיד sort ← skip ← limit). שני כללים מפרק 18 עובדים גם כאן: מיון חייב להיות יציב ({ name: 1, _id: 1 } — אחרת מסמכים "קופצים" בין עמודים), ו־skip גדול איטי. בעמודים עמוקים — keyset: { _id: { $gt: lastId } }. הספירה לעמוד: countDocuments(filter) עם אותו filter (E10).

4. עדכונים

updateOne(filter, update): המסמך הראשון שמתאים ל־filter, עם אופרטורי עדכון:

```ts run import { MongoClient } from "mongodb"; const client = new MongoClient(process.env.MONGO_URL ?? "mongodb://localhost:27017/?directConnection=true"); const db = client.db("lesson2b"); const products = db.collection("products"); await products.insertOne({ _id: "p1", name: "Ethiopia Yirgacheffe", price: 62, stock: 40, tags: ["light"] }); const show = async () => console.log(JSON.stringify(await products.findOne({ _id: "p1" }, { projection: { _id: 0, name: 0 } }))); await products.updateOne({ _id: "p1" }, { $set: { price: 65 }, $inc: { stock: -2 } }); await show(); await products.updateOne({ _id: "p1" }, { $push: { tags: "organic" } }); await products.updateOne({ _id: "p1" }, { $addToSet: { tags: "organic" } }); // כבר קיים — לא מוסיף await products.updateOne({ _id: "p1" }, { $pull: { tags: "light" } }); await show(); const r = await products.updateOne({ _id: "p1" }, { $set: { price: 65 } }); console.log(r.matchedCount, r.modifiedCount); // התאים — אבל לא השתנה כלום const up = await products.updateOne({ _id: "p9" }, { $set: { name: "Filter Papers", price: 15 } }, { upsert: true }); console.log(up.matchedCount, up.upsertedId); await db.dropDatabase(); await client.close(); ``` ```out {"price":65,"stock":38,"tags":["light"]} {"price":65,"stock":38,"tags":["organic"]} 1 0 0 p9 ```
  • $set משנה רק את השדות שכתבת. בלי אופרטור (replaceOne) — כל המסמך מוחלף, וכל שדה שלא כתבת נמחק (E21).
  • matchedCount מול modifiedCount — כמו affectedRows מול changedRows ב־MySQL. "לא נמצא" זה matchedCount: 0.
  • upsert — "עדכן, ואם אין — צור". ה־_id מה־filter נכנס למסמך החדש.
  • findOneAndUpdate — אותו דבר, ומחזיר את המסמך (returnDocument: "after" — אחרי העדכון). שימושי כשצריך את הערך החדש (E08).

5. עדכון אטומי עם תנאי

זוכר את המרוץ מפרק 18? שני לקוחות קונים את המטחנה האחרונה: שניהם קוראים "1 במלאי", שניהם מורידים. ב־Postgres פתרנו עם UPDATE … WHERE stock >= 1. ב־Mongo — בדיוק אותו רעיון: התנאי בתוך ה־filter, והשינוי ב־$inc, באותה פקודה. השרת מבצע את שניהם אטומית על המסמך:

```ts run import { MongoClient } from "mongodb"; const client = new MongoClient(process.env.MONGO_URL ?? "mongodb://localhost:27017/?directConnection=true"); const db = client.db("lesson2c"); const products = db.collection<{ _id: string; stock: number }>("products"); // הדרך השבורה: קודם קוראים, אחר כך כותבים await products.insertOne({ _id: "naive", stock: 5 }); let sold = 0; await Promise.all(Array.from({ length: 20 }, async () => { const p = await products.findOne({ _id: "naive" }); if (p && p.stock >= 1) { await products.updateOne({ _id: "naive" }, { $set: { stock: p.stock - 1 } }); sold++; } })); console.log("naive: sold more than 5?", sold > 5); // המספר המדויק משתנה מהרצה להרצה // הדרך הנכונה: תנאי + $inc בפקודה אחת await products.insertOne({ _id: "atomic", stock: 5 }); const results = await Promise.all(Array.from({ length: 20 }, async () => (await products.updateOne({ _id: "atomic", stock: { $gte: 1 } }, { $inc: { stock: -1 } })).modifiedCount === 1)); console.log("atomic:", (await products.findOne({ _id: "atomic" }))!.stock, "sold:", results.filter(Boolean).length); await db.dropDatabase(); await client.close(); ``` ```out naive: sold more than 5? true atomic: 0 sold: 5 ```

הגרסה הנאיבית מכרה יותר מ־5: הבקשות קראו 5 בערך באותו זמן, וכל אחת כתבה "4" מעל השנייה. האטומית מכרה בדיוק 5. זה הכלל החשוב ביותר בעבודה עם Mongo: כל עוד השינוי הוא במסמך אחד, פקודה אחת עם תנאי היא כל מה שצריך — בלי טרנזקציה ובלי נעילה (E13, E16).
