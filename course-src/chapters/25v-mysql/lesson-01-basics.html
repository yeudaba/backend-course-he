2. טבלה ראשונה

הטבלה products מנתוני היחידה (files/shop.sql), ומה שבה שונה מהגרסה של פרק 16:

```sql CREATE TABLE products ( id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY, -- ב־PostgreSQL: integer GENERATED ALWAYS AS IDENTITY name VARCHAR(200) NOT NULL, -- VARCHAR חייב אורך; TEXT לא נכנס לאינדקס רגיל במלואו price DECIMAL(10, 2) NOT NULL, -- כמו numeric(10,2) — מדויק. לא FLOAT לכסף stock INT NOT NULL DEFAULT 0, is_active BOOLEAN NOT NULL DEFAULT TRUE, -- בעצם TINYINT(1): נשמר וחוזר כ־0/1 attributes JSON NULL, -- בינארי, כמו jsonb CONSTRAINT chk_products_stock CHECK (stock >= 0) -- נאכף רק מ־MySQL 8.0.16 (לפני — התעלם בשקט!) ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci; ```

UNSIGNED — בלי מספרים שליליים, וטווח כפול. רק זכור: מפתח זר חייב להיות בדיוק אותו טיפוס, כולל UNSIGNED, אחרת MySQL מסרב ליצור אותו (E06).

ותאריכים — במקום timestamptz יש שתי אפשרויות, ואף אחת לא זהה:

DATETIME(3)TIMESTAMP(3)
מה נשמר"שעון על הקיר", בלי אזור זמןUTC; מומר לפי time_zone של החיבור בכתיבה ובקריאה
טווח1000–99991970–2038
מתירוב המקרים — כשהאפליקציה כותבת תמיד UTC, ומתעדת את זהכשרוצים המרה אוטומטית — ונזהרים מחיבורים עם הגדרה שונה

ובשאלת "רגע" מול "תאריך" מפרק 24 — DATE לתאריך בלי שעה (יום לידה, יום אספקה).

3. utf8 שאינו UTF-8

הבאג הכי מפורסם של MySQL: CHARSET=utf8 הוא בעצם utf8mb3 — עד 3 בתים לתו. רוב העברית והאנגלית נכנסות, וגם ☕ (3 בתים). אבל 🔥 (4 בתים) נדחה:

```sql run mysql stderr continue CREATE TABLE notes_old (body TEXT) DEFAULT CHARSET=utf8; CREATE TABLE notes_new (body TEXT) DEFAULT CHARSET=utf8mb4; INSERT INTO notes_old VALUES ('קפה ☕'); INSERT INTO notes_old VALUES ('חם 🔥'); INSERT INTO notes_new VALUES ('חם 🔥'); SELECT body, LENGTH(body) AS bytes, CHAR_LENGTH(body) AS chars FROM notes_new; ``` ```out ERROR 1366 (HY000): Incorrect string value: '\xF0\x9F\x94\xA5' for column 'body' at row 1 +-----------+-------+-------+ | body | bytes | chars | +-----------+-------+-------+ | חם 🔥 | 9 | 4 | +-----------+-------+-------+ ```

הכלל: utf8mb4 תמיד — לטבלאות, ל־database, ולחיבור. (ב־MySQL 8 זו כבר ברירת המחדל; טבלאות ישנות ממיגרציה — לבדוק.)

4. קולציה: מה שווה למה

קולציה קובעת איך משווים וממיינים טקסט. ברירת המחדל של MySQL 8, utf8mb4_0900_ai_ci: ai = accent-insensitive, ci = case-insensitive. ב־PostgreSQL ההשוואה רגישה לשניהם:

```sql run mysql db=25v-mysql/files/shop.sql SELECT name, email FROM customers WHERE email = 'DANA@EXAMPLE.COM'; SELECT 'Café' = 'cafe' COLLATE utf8mb4_0900_ai_ci AS accent_insensitive; SELECT 'Dana' = 'dana' COLLATE utf8mb4_bin AS case_sensitive; ``` ```out +-----------+------------------+ | name | email | +-----------+------------------+ | Dana Levi | dana@example.com | +-----------+------------------+ +--------------------+ | accent_insensitive | +--------------------+ | 1 | +--------------------+ +----------------+ | case_sensitive | +----------------+ | 0 | +----------------+ ```

שלוש השלכות: חיפוש "לא רגיש לרישיות" מגיע בחינם (בלי ILIKE ובלי lower()); UNIQUE (email) כבר לא מרשה Dana@ ו־dana@ יחד (E02); ומזהים שחייבים להיות מדויקים — טוקנים, מפתחות API, hashes — צריכים utf8mb4_bin או VARBINARY.

5. שלוש מלכודות שקטות

```sql run mysql SELECT 'a' || 'b' AS pipes, CONCAT('a', 'b') AS concat_fn; SELECT 10 / 4 AS division, 10 DIV 4 AS int_division; SELECT '5 apples' + 1 AS sum_text; ``` ```out +-------+-----------+ | pipes | concat_fn | +-------+-----------+ | 0 | ab | +-------+-----------+ +----------+--------------+ | division | int_division | +----------+--------------+ | 2.5000 | 2 | +----------+--------------+ +----------+ | sum_text | +----------+ | 6 | +----------+ ```
  • || הוא OR. ב־PostgreSQL זה חיבור מחרוזות; ב־MySQL — OR לוגי. 'a' || 'b' מחזיר 0 — בלי שגיאה.
  • חילוק מחזיר עשרוני (ב־PostgreSQL, 10 / 4 של שלמים הוא 2). חילוק שלם: DIV.
  • המרות מרומזות. '5 apples' + 1 הוא 6, עם warning. במצב STRICT (ברירת המחדל) הכנסה של ערך כזה לעמודה מספרית נכשלת — אל תכבה את STRICT.
