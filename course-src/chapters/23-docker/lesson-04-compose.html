🎯 בשיעור הזה
  • compose.yaml: כמה שירותים בקובץ אחד.
  • רשת: איך שירות מוצא שירות אחר (לא localhost).
  • סדר עלייה: healthcheck ו־depends_on.
  • משתנים, סודות, ו"פיתוח מול פרודקשן".

1. מ־docker run ל־compose

אפליקציה + מסד עם docker run הם שתי פקודות ארוכות, רשת, volume, וסדר נכון. compose מתאר את כל זה בקובץ אחד:

```yaml file=compose.yaml services: db: image: postgres:18-alpine environment: POSTGRES_USER: app POSTGRES_PASSWORD: app POSTGRES_DB: visits volumes: - db-data:/var/lib/postgresql healthcheck: test: ["CMD-SHELL", "pg_isready -U app -d visits"] interval: 2s timeout: 3s retries: 30 app: build: . environment: DATABASE_URL: postgresql://app:app@db:5432/visits ports: - "${APP_PORT:-3000}:3000" depends_on: db: condition: service_healthy volumes: db-data: ```
פקודהמה
docker compose up --buildבונה ומעלה הכול (ומראה את כל הלוגים; Ctrl+C עוצר)
docker compose up -d --waitברקע, ומחכה שהכול healthy
docker compose ps · logs -f appמה רץ · לוגים של שירות
docker compose exec db psql -U app visitsפקודה בתוך שירות
docker compose downעוצר ומוחק קונטיינרים ורשת — volumes נשארים
docker compose down -v…וגם את ה־volumes. המסד נמחק.

2. רשת: לפי שם השירות

compose יוצר רשת לכל פרויקט, ושם כל שירות הוא שם מחשב בתוכה. לכן DATABASE_URL מצביע על @db:5432. ההודעה שתקבל אם תכתוב localhost (פלט אמיתי): connect ECONNREFUSED 127.0.0.1:5432 (E21). ו־ports — רק למה שצריך להיות נגיש מבחוץ. המסד לא.

3. סדר עלייה

depends_on: [db] מחכה רק שהקונטיינר של המסד יתחיל — לא שהמסד מוכן לקבל חיבורים. PostgreSQL צריך כמה שניות, והאפליקציה שמתחברת מיד בעלייה נופלת. הפתרון: healthcheck ב־db (pg_isready), ו־condition: service_healthy ב־app. ולמשימה שרצה פעם אחת ונגמרת (migrations) — condition: service_completed_successfully (בפרויקט, בשיעור הבא).

4. PostgreSQL 18 ו־volume

הרבה מדריכים כותבים - data:/var/lib/postgresql/data. מ־PostgreSQL 18, ה־image שומר את הנתונים ב־/var/lib/postgresql/18/docker, וה־volume צריך להיות על /var/lib/postgresql. עם הנתיב הישן, הקונטיינר מסרב לעלות (פלט אמיתי, מקוצר):

```term !! Error: in 18+, these Docker images are configured to store database data in a .. format which is compatible with "pg_ctlcluster" (specifically, using .. major-version-specific directory names). .. ... .. Counter to that, there appears to be PostgreSQL data in: .. /var/lib/postgresql/data (unused mount/volume) ```

שווה לזכור: כשמדריך ישן לא עובד עם גרסה חדשה, הפתרון כמעט תמיד בהודעת השגיאה — או בתיעוד של ה־image (docker image inspect postgres:18-alpine מראה גם את PGDATA).

5. משתנים וסודות

```yaml environment: JWT_SECRET: ${JWT_SECRET:?הגדר JWT_SECRET בקובץ .env} # חובה — אחרת compose נכשל מיד LOG_LEVEL: ${LOG_LEVEL:-info} # ברירת מחדל ports: - "${API_PORT:-3000}:3000" ```

compose קורא משתנים מה־Terminal ומקובץ .env שליד compose.yaml (שלא נכנס ל־Git). :? — חובה, עם הודעה; :- — ברירת מחדל. כך הסוד לא כתוב בקובץ, ו־port אפשר לשנות בלי לגעת בו (הבודק מריץ על port אחר).

6. פיתוח מול פרודקשן

compose.override.yaml נטען אוטומטית יחד עם compose.yaml — רק כשלא מציינים -f. מקום טבעי למה שרק אתה צריך במחשב: bind mount של הקוד, node --watch, לוגים מפורטים. בשרת: docker compose -f compose.yaml up -d — בלי כל זה (E19).
