1. Dockerfile ראשון

```dockerfile file=Dockerfile # בסיס: Linux קטן + Node 24 FROM node:24-alpine # תיקיית העבודה (נוצרת אם לא קיימת) WORKDIR /app COPY package.json server.mjs ./ # תיעוד: האפליקציה מאזינה ב־3000 EXPOSE 3000 # מה רץ כשהקונטיינר עולה CMD ["node", "server.mjs"] ``` ```term % docker build -t hello-api . % docker run --rm -p 3000:3000 hello-api % curl localhost:3000/health ```

(הערות ב־Dockerfile — רק בשורה משלהן, שמתחילה ב־#. WORKDIR /app # הערה לא עובד.) RUN — פקודה שרצה בזמן הבנייה (התקנות). CMD — פקודה שרצה כשהקונטיינר עולה. ENV — משתנה סביבה קבוע. COPY — מהתיקייה שלך (ה־build context) לתוך ה־image.

⚠️ 127.0.0.1 בתוך קונטיינר

שרת שמאזין ל־127.0.0.1 מקבל חיבורים רק מתוך הקונטיינר עצמו — curl מה־Mac יקבל Connection reset by peer. בתוך Docker מאזינים ל־0.0.0.0 (Express ו־Nest עושים את זה כברירת מחדל). E23.

2. שכבות ו־cache

כל הוראה היא שכבה. Docker שומר כל שכבה ב־cache, ומשתמש בה שוב אם ההוראה וכל מה שלפניה — וכל הקבצים שהיא מעתיקה — לא השתנו. ברגע ששכבה אחת משתנה, כל מה שאחריה נבנה מחדש. לכן הסדר:

```dockerfile file=Dockerfile FROM node:24-alpine WORKDIR /app # משתנה לעיתים רחוקות COPY package.json package-lock.json ./ # האיטי — רץ רק כשהתלויות השתנו RUN npm ci --omit=dev # משתנה כל הזמן — אחרון COPY server.mjs ./ USER node CMD ["node", "server.mjs"] ``` ```term % echo "// change" >> server.mjs % docker build --progress=plain -t zod-api . .. #7 [3/5] COPY package.json package-lock.json ./ .. #7 CACHED .. #8 [4/5] RUN npm ci --omit=dev .. #8 CACHED .. #9 [5/5] COPY server.mjs ./ ```

(פלט אמיתי, מקוצר.) שינית קוד — npm ci לא רץ שוב. עם COPY . . לפני npm ci, כל שינוי בקוד היה "מלכלך" את השכבה, וכל ההתקנה הייתה רצה מחדש — בכל build.

ו־npm ci ולא npm install: מתקין בדיוק מה שב־package-lock.json, ונכשל אם הוא לא תואם ל־package.json. ב־build רוצים בדיוק את מה שנבדק.

3. .dockerignore

```text file=.dockerignore node_modules dist coverage .env .env.* .git *.log ```

מה שלא נשלח ל־Docker בכלל. שתי סיבות קריטיות: סודות (.env שנכנס ל־image נשאר בו לתמיד — כל מי שיש לו את ה־image יכול לקרוא אותו), ו־node_modules מה־Mac (חבילות עם קוד native מקומפלות ל־macOS ולא ירוצו בלינוקס של הקונטיינר). Docker לא קורא את .gitignore.

4. multi-stage — לבנות בשלב אחד, לשלוח את השני

המספרים, מהפרויקט שלך (פלט אמיתי של docker image ls):

גרסהגודל
FROM node:24, COPY . ., npm install, build — הכול בשלב אחד2.54GB
multi-stage על node:24-alpine, npm ci --omit=dev827MB
…ועוד --omit=optional435MB

השורה האחרונה היא גילוי מעניין: @prisma/client מגדיר את prisma (ה־CLI, עם כל הכלים שלו) ואת typescript כ־optional peer dependencies. npm מסמן אותם devOptional — ו־--omit=dev לבד לא מסיר אותם. כמעט 400MB שהשרת לא צריך. ככה מוצאים דברים כאלה: docker compose exec api du -sh node_modules/* | sort -rh | head.

5. לא root, signals, healthcheck

```dockerfile # המשתמש node כבר קיים ב־image של Node USER node HEALTHCHECK --interval=5s --timeout=3s --start-period=10s --retries=5 \ CMD wget -qO- http://127.0.0.1:3000/health || exit 1 # מערך — לא "node dist/main.js" CMD ["node", "dist/main.js"] ```
  • USER — בלי זה הכול רץ כ־root. אם מישהו מוצא חולשה באפליקציה, הוא root בתוך הקונטיינר.
  • CMD כמערך (exec form) — Node הוא התהליך הראשי, ומקבל את ה־SIGTERM של docker stop. בצורת מחרוזת (CMD npm start) יש shell ו־npm באמצע, והאות לא תמיד מגיע — Docker מחכה 10 שניות והורג.
  • HEALTHCHECK — docker ps מראה (healthy), ו־compose (השיעור הבא) יכול לחכות לו.
  • סודות — רק בזמן ריצה: לא ENV JWT_SECRET=... ולא ARG. docker image inspect ו־docker history מראים אותם לכל אחד (E20).
