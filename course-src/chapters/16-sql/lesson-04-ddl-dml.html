🎯 בשיעור הזה
  • `CREATE TABLE`: טיפוסים, מפתח ראשי ואילוצים.
  • `INSERT` (עם `RETURNING`), `UPDATE`, `DELETE`.
  • `ALTER TABLE` ו־`DROP TABLE`.

1. CREATE TABLE

```sql run CREATE TABLE tasks ( id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY, title text NOT NULL CHECK (length(title) BETWEEN 1 AND 120), status text NOT NULL DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')), priority smallint NOT NULL DEFAULT 2, due_date date, created_at timestamptz NOT NULL DEFAULT now() ); ``` ```out CREATE TABLE ```
טיפוסלְמה
`integer` / `bigint`מספרים שלמים (bigint — לטבלאות ענק)
`numeric(10, 2)`כסף וכל מה שחייב דיוק
`text`מחרוזת. ב־PostgreSQL אין סיבה ל־`varchar(n)` — את האורך בודקים עם CHECK
`boolean`true / false
`date`תאריך בלי שעה: `'2026-11-04'`
`timestamptz`רגע בזמן (נשמר ב־UTC). תמיד tz, לא `timestamp` "ערום" — פרק 24
`uuid` · `jsonb`מזהה אקראי · מסמך JSON (נכיר בהמשך)
אילוץאומר
`PRIMARY KEY`מזהה ייחודי, לא NULL. `GENERATED ALWAYS AS IDENTITY` — המסד ממספר בעצמו (1, 2, 3...)
`NOT NULL`חובה
`DEFAULT x`ערך כשלא נשלח
`UNIQUE`אין שתי שורות עם אותו ערך (אימייל)
`CHECK (...)`כל תנאי: `price > 0`

זו "שכבת ההגנה האחרונה": גם אם יש באג בקוד, או מישהו מריץ SQL ידנית — המסד לא יסכים לנתונים לא תקינים. Zod בגבול ה־API + אילוצים במסד = שתי שכבות.

2. INSERT

```sql run CREATE TABLE tasks ( id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY, title text NOT NULL, status text NOT NULL DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')), due_date date ); INSERT INTO tasks (title, due_date) VALUES ('Learn SQL', '2026-12-01'); INSERT INTO tasks (title, status) VALUES ('Buy coffee beans', 'done'), ('Connect project 2 to the DB', 'todo') RETURNING id, title, status; ``` ```out CREATE TABLE INSERT 0 1 id | title | status ----+-----------------------------+-------- 2 | Buy coffee beans | done 3 | Connect project 2 to the DB | todo (2 rows) INSERT 0 2 ```
  • מציינים עמודות במפורש (`(title, due_date)`). מה שלא צוין — DEFAULT או NULL.
  • `INSERT 0 1` — psql מדווח כמה שורות נוספו.
  • `RETURNING` מחזיר את השורות שנוצרו — כולל ה־id שהמסד בחר. בדיוק מה שצריך ל־`POST /tasks` שמחזיר 201 עם האובייקט.
```sql run stderr CREATE TABLE tasks ( id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY, title text NOT NULL, status text NOT NULL DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')) ); INSERT INTO tasks (title, status) VALUES ('Test', 'urgent'); ``` ```out CREATE TABLE ERROR: new row for relation "tasks" violates check constraint "tasks_status_check" DETAIL: Failing row contains (1, Test, urgent). ```

המסד מסרב, ושום שורה לא נוספה. בפרק 19 נראה איך שגיאה כזו מגיעה לקוד ומתורגמת ל־400/409.

3. UPDATE ו־DELETE

```sql run db=16-sql/files/shop.sql UPDATE products SET price = price * 1.10, stock = stock + 10 WHERE category = 'grinders' RETURNING name, price, stock; ``` ```out name | price | stock ----------------------+--------+------- Hand Grinder | 207.90 | 18 Electric Grinder Pro | 713.90 | 13 (2 rows) UPDATE 2 ``` ```sql run db=16-sql/files/shop.sql DELETE FROM customers WHERE email = 'omer@example.com'; SELECT COUNT(*) FROM customers; ``` ```out DELETE 1 count ------- 11 (1 row) ```
⚠️ UPDATE / DELETE בלי WHERE

`DELETE FROM customers;` מוחק את כל הלקוחות. בלי אישור, בלי "פח מחזור". `UPDATE products SET price = 0;` — כל המוצרים בחינם. זה קורה גם לאנשים מנוסים. הרגל שמציל: קודם מריצים `SELECT` עם אותו WHERE ובודקים כמה שורות חוזרות — ורק אז מחליפים ל־UPDATE/DELETE. (ובפרק 18: לעטוף ב־transaction, ולבטל אם טעית.)

4. ALTER ו־DROP

```sql run db=16-sql/files/shop.sql ALTER TABLE customers ADD COLUMN newsletter boolean NOT NULL DEFAULT false; ALTER TABLE customers RENAME COLUMN phone TO phone_number; SELECT full_name, phone_number, newsletter FROM customers ORDER BY id LIMIT 2; ``` ```out ALTER TABLE ALTER TABLE full_name | phone_number | newsletter -------------+--------------+------------ Dana Levi | 050-1111111 | f Yossi Cohen | | f (2 rows) ```

`DROP TABLE tasks;` — מוחק טבלה עם כל הנתונים. `DROP TABLE IF EXISTS` — בלי שגיאה אם לא קיימת (כמו בקובץ `shop.sql`).
