🎯 בשיעור הזה
  • `Set` — אוסף בלי כפילויות.
  • `Map` — מילון מפתח ← ערך עם חיפוש מהיר.
  • יחידת גישור: תוכנית קטנה מקצה לקצה עם נתונים מקושרים (הזמנות ולקוחות).

1. `Set`

```js run const visitors = new Set(); visitors.add("dana"); visitors.add("omer"); visitors.add("dana"); console.log(visitors.size, visitors.has("dana"), visitors.has("noa")); const tags = ["node", "api", "node", "sql", "api"]; console.log([...new Set(tags)]); ``` ```out 2 true false [ 'node', 'api', 'sql' ] ```

`Set` שומר כל ערך פעם אחת. `has` מהיר מאוד גם עם מיליון ערכים — בניגוד ל־`includes` על מערך, שעובר על כל האיברים. `[...new Set(arr)]` הוא הקיצור ל־`unique` שכתבת ב־P06-E13.

2. `Map`

```js run const stock = new Map(); stock.set("KB-101", 4); stock.set("MS-201", 0); console.log(stock.get("KB-101")); console.log(stock.get("XX")); console.log(stock.has("MS-201"), stock.size); stock.set("KB-101", stock.get("KB-101") - 1); for (const [code, qty] of stock) { console.log(code, qty); } ``` ```out 4 undefined true 2 KB-101 3 MS-201 0 ```
אובייקט רגיל `{}``Map`
מתי"כרטיס" עם שדות ידועים: `user.name`, `user.age`מילון של הרבה רשומות שהמפתחות שלהן דינמיים: מזהה ← משתמש
מפתחותרק מחרוזותכל סוג (גם מספרים, גם אובייקטים)
גודל`Object.keys(o).length``map.size`

3. 👣 גישור: חיבור נתונים מקושרים

במערכת אמיתית הנתונים מפוצלים: הזמנה לא מכילה את כל פרטי הלקוח — רק את המזהה שלו (`customerId`). כדי להציג "הזמנה 7 של עומר מאילת", צריך לחבר שני מקורות. זה בדיוק מה ש־SQL עושה עם `JOIN` (פרק 17) — ועכשיו נעשה את זה בקוד.

```js run const customers = [ { id: 1, name: "דנה", city: "חיפה" }, { id: 2, name: "עומר", city: "אילת" }, ]; const orders = [ { id: 7, customerId: 2, total: 320 }, { id: 8, customerId: 1, total: 150 }, { id: 9, customerId: 2, total: 80 }, { id: 10, customerId: 3, total: 40 }, ]; const customersById = new Map(customers.map((c) => [c.id, c])); const report = orders.map((o) => { const customer = customersById.get(o.customerId); return `הזמנה ${o.id}: ${customer?.name ?? "לקוח לא ידוע"} (${customer?.city ?? "-"}) — ₪${o.total}`; }); console.log(report.join("\n")); const totals = new Map(); for (const o of orders) { totals.set(o.customerId, (totals.get(o.customerId) ?? 0) + o.total); } console.log(totals); ``` ```out הזמנה 7: עומר (אילת) — ₪320 הזמנה 8: דנה (חיפה) — ₪150 הזמנה 9: עומר (אילת) — ₪80 הזמנה 10: לקוח לא ידוע (-) — ₪40 Map(3) { 2 => 400, 1 => 150, 3 => 40 } ```

למה Map ולא `find`?

הגרסה ה"נאיבית" — `customers.find((c) => c.id === o.customerId)` בתוך ה־`map` — היא לולאה בתוך לולאה: על כל הזמנה עוברים על כל הלקוחות. עם 10,000 הזמנות ו־10,000 לקוחות — 100 מיליון השוואות. עם `Map` — בונים פעם אחת (10,000 צעדים), ואז כל `get` הוא צעד אחד: ~20,000 צעדים בסך הכול.

💡 הדפוס: "בנה אינדקס, ואז חפש"

`new Map(list.map((x) => [x.id, x]))` — שורה שתכתוב שוב ושוב. היא הופכת מערך למילון לפי מזהה. וזה בדיוק מה ש"אינדקס" עושה במסד נתונים (פרק 18).

ושים לב להזמנה 10: לקוח 3 לא קיים. בנתונים אמיתיים זה יקרה (לקוח נמחק, באג בייבוא). קוד טוב לא קורס — `?.` ו־`??` מציגים "לקוח לא ידוע". במסד נתונים נמנע את זה מראש עם foreign key (פרק 17).
