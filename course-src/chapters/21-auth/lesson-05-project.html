```ts file=prisma/schema.prisma enum Role { user admin } model User { id Int @id @default(autoincrement()) email String @unique passwordHash String @map("password_hash") role Role @default(user) createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3) tasks Task[] refreshTokens RefreshToken[] @@map("users") } model RefreshToken { id Int @id @default(autoincrement()) userId Int @map("user_id") user User @relation(fields: [userId], references: [id], onDelete: Cascade) tokenHash String @unique @map("token_hash") expiresAt DateTime @map("expires_at") @db.Timestamptz(3) revokedAt DateTime? @map("revoked_at") @db.Timestamptz(3) createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3) @@index([userId]) @@map("refresh_tokens") } model Task { id Int @id @default(autoincrement()) ownerId Int @map("owner_id") owner User @relation(fields: [ownerId], references: [id], onDelete: Cascade) // ... שאר השדות כמו קודם @@index([ownerId, status, createdAt]) @@map("tasks") } ```

וה־migration — הפעם קודם יוצרים, קוראים, ורק אז מריצים:

```term % npx prisma migrate dev --create-only --name add_users .. Prisma Migrate created the following migration without applying it 20261107055700_add_users ```

בראש הקובץ שנוצר Prisma משאיר אזהרה: Added the required column `owner_id` to the `tasks` table without a default value. This is not possible if the table is not empty. — והוא צודק: ל־owner_id יש NOT NULL, ולמשימות שכבר בטבלה אין בעלים. בפיתוח הפתרון פשוט: מוסיפים בראש הקובץ DELETE FROM "tasks"; (ה־seed ייצור נתונים חדשים), ואז npx prisma migrate dev ו־npx prisma generate.

💡 ובפרודקשן?

אצל משתמשים אמיתיים לא מוחקים נתונים. עושים את זה בשלושה migrations: (1) expand — מוסיפים owner_id כ־nullable; (2) backfill — ממלאים (למשל: כל המשימות הישנות שייכות למשתמש "ראשי"); (3) contract — SET NOT NULL. כך אף שלב לא נכשל, והאפליקציה עובדת לאורך כל הדרך. שאלה שאוהבים בראיונות.

💡 רמז: ה־repository בזיכרון שומר ownerId, אבל לא מחזיר אותו

type StoredTask = Task & { ownerId: number } בפנים, ו־strip שמסיר אותו בכל החזרה — ה־API נשאר זהה לשלבים הקודמים.

💡 רמז: למה ה־CLOCK והקונפיג "גלובליים"?

גם TasksService וגם AuthService צריכים שעון, ו־JwtModule צריך את הסוד. @Global() על ConfigModule חוסך לייבא אותו בכל מקום — ובבדיקות overrideProvider(CONFIG) מחליף אותו לכולם, כולל את הסוד של JwtModule.

💡 רמז: update בלי חלון בין "בדקתי" ל"שיניתי"

prisma.task.updateMany({ where: { id, ownerId }, data }) מחזיר { count }. 0 ← לא קיים או לא שלך (ובשני המקרים: 404). ואז findFirst כדי להחזיר את המשימה המעודכנת.

5. להריץ ולבדוק

פתח את requests.http — יש בו את כל הזרימה: כניסה (התשובה נשמרת במשתנה login), בקשות עם הטוקן, ניסיון לגשת למשימה של משתמש אחר, refresh, ו־register עם role. ו־/docs: לחץ Authorize, הדבק את ה־accessToken, ו־"Try it out". ואז הדף: npm run web, היכנס כ־dana@example.com / dana-password-1, רענן את הדף (נשארת מחובר — בזכות ה־refresh token), ונסה את yossi@example.com: רשימה אחרת לגמרי.

```term % npm run build % cd ~/dev/backend-course % npm run check PR2-AUTH -- --dir ~/dev/tasks-api % npm run check PR2-AUTH-DB -- --dir ~/dev/tasks-api ```

PR2-AUTH מריץ את הקוד המקומפל עם repositories בזיכרון ושעון מזויף: הרשמה, כניסה (כולל שאותה תשובה חוזרת לאימייל לא רשום), טוקן מזויף, תוקף אחרי 15 דקות, משימות של אחר (GET/PATCH/DELETE ← 404), rotation ושימוש חוזר, ו־/users. PR2-AUTH-DB עושה את אותו הדבר מול PostgreSQL אמיתי, ובודק מה נשמר בטבלאות: hash ולא סיסמה, SHA-256 ולא טוקן, owner_id, ו־ON DELETE CASCADE. (PR2-NEST של פרק 20 כבר לא יעבור — הוא שולח בקשות בלי טוקן. זה צפוי.)
