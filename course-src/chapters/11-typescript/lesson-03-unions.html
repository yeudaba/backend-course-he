🎯 בשיעור הזה
  • union — "אחד מכמה טיפוסים".
  • literal types — רשימה סגורה של ערכים מותרים.
  • narrowing — איך TypeScript "מבין" את הטיפוס אחרי בדיקה.
  • discriminated unions ו־`never` — לא לשכוח אף מקרה.
  • `keyof` ו־`T[K]` — שמות השדות של טיפוס כ־union, והטיפוס של שדה אחד.

1. Union: `A | B`

```ts tsc function format(id: string | number): string { return id.toUpperCase(); } ``` ```out snippet.ts(2,13): error TS2339: Property 'toUpperCase' does not exist on type 'string | number'. Property 'toUpperCase' does not exist on type 'number'. ```

`id` יכול להיות מספר — ולמספר אין `toUpperCase`. TypeScript מרשה רק מה שבטוח לכל האפשרויות. כדי להשתמש במשהו ספציפי — בודקים קודם:

2. Narrowing — צמצום בבדיקה

```ts run function format(id: string | number): string { if (typeof id === "number") { return `#${id.toFixed(0)}`; } return id.toUpperCase(); } console.log(format(42), format("ab-7")); ``` ```out #42 AB-7 ```

בתוך ה־`if`, TypeScript יודע ש־`id` הוא `number`; אחרי ה־`return`, מה שנשאר הוא רק `string`. אותן בדיקות שכתבת בפרק 3 — עכשיו הן גם מלמדות את הבודק.

בדיקהמצמצמת
`typeof x === "string"`טיפוסים בסיסיים
`x === null`, `x !== undefined`, `if (x)`מוציא את `null`/`undefined`
`Array.isArray(x)`מערך
`"email" in x`אובייקט שיש לו את השדה
`x.kind === "card"`discriminated union (סעיף 4)

3. Literal types — רשימה סגורה

```ts tsc type OrderStatus = "pending" | "paid" | "shipped" | "cancelled"; let orderStatus: OrderStatus = "pending"; orderStatus = "paid"; orderStatus = "deliverd"; ``` ```out snippet.ts(5,1): error TS2322: Type '"deliverd"' is not assignable to type 'OrderStatus'. ```

שגיאת כתיב בסטטוס — באג שיכול לחיות שנים בקוד JavaScript — נתפסת מיד. ובעורך, הקלדת `orderStatus = "` מציעה את ארבעת הערכים. (ב־SQL נראה את המקבילה: `CHECK` או `enum` בעמודה, פרק 17.)

4. Discriminated unions

אמצעי תשלום: לכרטיס יש 4 ספרות אחרונות, ל־PayPal — אימייל, להעברה — מספר אסמכתא. אובייקט אחד עם כל השדות האופציונליים היה מבולגן. במקום:

```ts run type Payment = | { method: "card"; last4: string } | { method: "paypal"; email: string } | { method: "transfer"; reference: string }; function describe(p: Payment): string { switch (p.method) { case "card": return `כרטיס שמסתיים ב־${p.last4}`; case "paypal": return `PayPal (${p.email})`; case "transfer": return `העברה ${p.reference}`; } } console.log(describe({ method: "card", last4: "4242" })); ``` ```out כרטיס שמסתיים ב־4242 ```

השדה המשותף `method` "מבחין" בין האפשרויות. בתוך `case "card"`, TypeScript יודע שיש `last4` ואין `email`.

`never` — לוודא שלא שכחנו מקרה

```ts tsc type Payment = | { method: "card"; last4: string } | { method: "paypal"; email: string } | { method: "bit"; phone: string }; function fee(p: Payment): number { switch (p.method) { case "card": return 1.5; case "paypal": return 2.9; default: { const unhandled: never = p; throw new Error(`אמצעי תשלום לא נתמך: ${JSON.stringify(unhandled)}`); } } } ``` ```out snippet.ts(13,13): error TS2322: Type '{ method: "bit"; phone: string; }' is not assignable to type 'never'. ```

מישהו הוסיף "bit" לטיפוס — ו־TypeScript מראה בדיוק איפה הקוד לא מטפל בו. `never` = "טיפוס שאין לו אף ערך"; אם הגענו לשם עם ערך — שכחנו מקרה. דפוס חזק מאוד בקוד עסקי.

5. `keyof` ו־`T[K]`: טיפוסים מתוך טיפוסים

בפרק 7 קראת שדה ששמו במשתנה: `product[key]`. ב־TypeScript זה נתקע:

```ts tsc type Product = { id: number; name: string; price: number }; function getField(p: Product, key: string) { return p[key]; } ``` ```out snippet.ts(4,10): error TS7053: Element implicitly has an 'any' type because expression of type 'string' can't be used to index type 'Product'. No index signature with a parameter of type 'string' was found on type 'Product'. ```

`key` הוא "כל מחרוזת", ו־TypeScript לא יכול לדעת מה יחזור עבור `"color"`. מה שחסר הוא טיפוס שאומר "אחד משמות השדות של `Product`". הוא כבר קיים, ושמו `keyof Product`:

```ts tsc type Product = { id: number; name: string; price: number }; type ProductKey = keyof Product; const ok: ProductKey = "price"; const typo: ProductKey = "prise"; type Price = Product["price"]; const p: Price = "200"; ``` ```out snippet.ts(5,7): error TS2820: Type '"prise"' is not assignable to type 'keyof Product'. Did you mean '"price"'? snippet.ts(8,7): error TS2322: Type 'string' is not assignable to type 'number'. ```
  • `keyof Product` הוא union של literal types (סעיף 3): `"id" | "name" | "price"`. הוא נבנה מהטיפוס, ולכן שדה חדש ב־`Product` נכנס אליו לבד.
  • `Product["price"]` (indexed access) הוא הטיפוס של השדה: `number`.

יחד עם generics (שיעור 2) מקבלים פונקציה שיודעת בדיוק מה היא מחזירה:

```ts tsc type Product = { id: number; name: string; price: number }; function getField(p: Product, key: K): Product[K] { return p[key]; } const keyboard: Product = { id: 1, name: "מקלדת", price: 200 }; const price: number = getField(keyboard, "price"); const title: string = getField(keyboard, "name"); const wrong: string = getField(keyboard, "price"); getField(keyboard, "color"); ``` ```out snippet.ts(10,7): error TS2322: Type 'number' is not assignable to type 'string'. snippet.ts(11,20): error TS2345: Argument of type '"color"' is not assignable to parameter of type 'keyof Product'. ```

שתי שגיאות, בדיוק איפה שצריך: ב־`wrong` (המחיר הוא `number`, לא `string`), וב־`"color"`. ‏`K extends keyof Product` = "`K` הוא אחד משמות השדות". בקריאה עם `"price"`, ‏`K` הוא `"price"`, והתוצאה `Product["price"]`, כלומר `number`. ואפשר להחליף גם את `Product` בפרמטר, ואז הפונקציה עובדת על כל אובייקט:

```ts run function pluck(items: T[], key: K): T[K][] { return items.map((item) => item[key]); } const products = [ { id: 1, name: "מקלדת", price: 200 }, { id: 2, name: "עכבר", price: 90 }, ]; const prices = pluck(products, "price"); console.log(prices, prices.reduce((s, n) => s + n, 0)); console.log(pluck(products, "name")); ``` ```out [ 200, 90 ] 290 [ 'מקלדת', 'עכבר' ] ```

`keyof typeof`: שמות מתוך אובייקט קיים

לפעמים אין `type`, יש אובייקט רגיל, למשל טבלת המרה. `typeof` (בתוך טיפוס) לוקח את הטיפוס של משתנה, ו־`keyof` את שמות השדות שלו:

```ts tsc const UNIT_MS = { s: 1000, m: 60_000, h: 3_600_000 }; type Unit = keyof typeof UNIT_MS; function toMs(amount: number, unit: Unit): number { return amount * UNIT_MS[unit]; } toMs(2, "h"); toMs(2, "d"); ``` ```out snippet.ts(9,9): error TS2345: Argument of type '"d"' is not assignable to parameter of type '"s" | "m" | "h"'. ```

הוספת `d: 86_400_000` לאובייקט מוסיפה את `"d"` לטיפוס לבד. רשימה אחת, בלי להעתיק את השמות ל־union נפרד.

הצצה: לבנות טיפוס חדש מכל השדות

`[K in keyof T]` עובר על כל השדות של טיפוס ובונה טיפוס חדש עם אותם שמות. כך בנויים `Partial` ו־`Record` שתכיר ב־P11-E26:

```ts tsc type Product = { id: number; name: string; price: number }; type Flags = { [K in keyof T]: boolean }; const changed: Flags = { id: false, name: true, price: true }; const missing: Flags = { id: false, name: true }; ``` ```out snippet.ts(5,7): error TS2741: Property 'price' is missing in type '{ id: false; name: true; }' but required in type 'Flags'. ```
⚠️ טעויות נפוצות עם keyof
  • `Object.keys` מחזיר `string[]`, לא `(keyof T)[]`. לולאה `for (const k of Object.keys(p)) p[k]` נותנת את אותה שגיאה `TS7053` כמו בתחילת הסעיף. TypeScript לא מניח שאין באובייקט שדות נוספים. כשאפשר, עוברים על רשימה מפורשת של שדות עם טיפוס `(keyof Product)[]`.
  • `keyof` על משתנה: `keyof UNIT_MS` (בלי `typeof`) הוא שגיאה (`TS2749: 'UNIT_MS' refers to a value`), כי `keyof` עובד על טיפוסים ו־`UNIT_MS` הוא ערך. ההודעה אפילו מציעה את התיקון: `Did you mean 'typeof UNIT_MS'?`
  • `keyof` הוא רק בזמן כתיבה. כמו כל טיפוס, הוא נמחק לפני ההרצה. מחרוזת שמגיעה מהמשתמש (`?sort=price`) צריך עדיין לבדוק בזמן ריצה, למשל עם `key in UNIT_MS` (סעיף 2), לפני שמשתמשים בה כשם שדה. ואיך "מספרים" ל־TypeScript שהבדיקה עברה? עם type guard, בשיעור 4.
