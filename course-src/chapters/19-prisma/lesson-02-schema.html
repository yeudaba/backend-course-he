בלי `@db.Timestamptz(3)`, Prisma יוצר `timestamp(3)` — "ערום", בלי אזור זמן. בפרק 16 ראינו למה זה רע. הוסף `@db.Timestamptz(3)` לכל שדה זמן.

2. קשרים

```text model Order { id Int @id @default(autoincrement()) customerId Int @map("customer_id") customer Customer @relation(fields: [customerId], references: [id]) items OrderItem[] ... } ```
  • אחד־לרבים: בצד ה"רבים" — עמודת FK (`customerId`) ושדה קשר (`customer`) עם `@relation(fields, references)`. בצד ה"אחד" — מערך (`orders Order[]`). שדות הקשר לא קיימים במסד; הם בשביל ה־client (`include: { customer: true }`).
  • רבים־לרבים: מודל קישור מפורש (`ProductTag` עם `@@id([productId, tagId])`), כמו בפרק 17. (ל־Prisma יש גם קשר "מובלע", אבל המפורש גמיש יותר — אפשר להוסיף לו שדות כמו "מתי נוסף".)
  • `onDelete`: ברירת המחדל — מחיקה חסומה כשיש "ילדים". `onDelete: Cascade` על `OrderItem.order` — מחיקת הזמנה מוחקת את פריטיה. (`SetNull` — לקשר אופציונלי.)

3. Migrations

נניח שמוסיפים לקוח VIP: בסכמה, ב־`Customer`: `isVip Boolean @default(false) @map("is_vip")`. ואז:

```term % npx prisma migrate dev --name add_customer_is_vip Applying migration `20261105093000_add_customer_is_vip` % npx prisma generate ``` ```sql file=prisma/migrations/20261105093000_add_customer_is_vip/migration.sql -- AlterTable ALTER TABLE "customers" ADD COLUMN "is_vip" BOOLEAN NOT NULL DEFAULT false; ```

Prisma השווה את הסכמה למצב האחרון של ה־migrations, וכתב את ה־SQL שמגשר. זה הקובץ שנכנס ל־Git, ורץ — בדיוק כך — אצל חבר הצוות, בבדיקות ובייצור.

פקודהמתימה עושה
`migrate dev`פיתוחיוצר migration חדש מהשינויים בסכמה ומריץ. אם המסד "התפזר" — מציע לאפס (ומוחק נתונים!)
`migrate deploy`ייצור, CIמריץ רק migrations שעוד לא רצו. לא יוצר, לא מאפס, לא שואל
`migrate reset`פיתוחמוחק הכול ומריץ את כל ה־migrations מהתחלה
`migrate status`תמידאילו migrations רצו ואילו לא
`db seed`פיתוחמריץ את פקודת ה־seed מ־`prisma.config.ts`
⚠️ חוקי הברזל
  • לא עורכים migration שכבר רץ אצל מישהו אחר (או בייצור) — יוצרים חדש.
  • לא מריצים `migrate dev` או `reset` מול ייצור — רק `deploy`.
  • שינוי "הורס" (מחיקת עמודה, שינוי טיפוס) — קרא את ה־SQL שנוצר לפני שמריצים. Prisma מזהיר, אבל אתה אחראי.
  • עמודה חובה חדשה בטבלה עם נתונים? `@default(...)`, או שלושה שלבים כמו ב־P16-E19 (Prisma ייתן לערוך את ה־SQL עם `--create-only`).

ו־`npx prisma studio` — ממשק בדפדפן לראות ולערוך נתונים. נוח לבדיקות מהירות (בפיתוח בלבד).
