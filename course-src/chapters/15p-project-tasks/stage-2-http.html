🎯 בשלב הזה

לחבר את הלב ל־HTTP: `errors.ts`, `validate.ts`, `tasks.routes.ts` ו־`app.ts`. בסוף: `npm run check PR2-API -- --dir ~/dev/tasks-api` עובר, והשרת עונה ל־`requests.http`.

1. `errors.ts`

כמו P15-E10, עם תוספת אחת: אם ל־`HttpError` יש `details` — הם נכנסים לתשובה: `{ error: { code, message, details } }`. בלי details — בלי השדה (לא `details: undefined`).

2. `middleware/validate.ts`

כמו P15-E15, בהבדל אחד: בכישלון לא עונים ישירות אלא זורקים `new HttpError(400, "VALIDATION_ERROR", "קלט לא תקין", details)`. כך יש מקום אחד בלבד (errorHandler) שבונה תשובות שגיאה. ה־paths: `"body.title"`, `"query.limit"`, `"params.id"`.

3. `tasks.routes.ts`

```ts router.get("/:id", validate({ params: idParamsSchema }), async (req, res) => { res.json(await service.get(res.locals.params.id)); }); ```

כל route ככה: validate ← קריאה ל־service ← status. בלי try/catch (Express 5 מעביר שגיאות async ל־errorHandler). ממש את כל ששת ה־routes מהטבלה בשלב 0; ל־`GET /` ול־`/stats` — חיבור ל־`service.list` / `service.stats` (את המימוש שלהם תכתוב בשלב 3; עד אז הם יחזירו 500, וזה בסדר).

⚠️ סדר

`router.get("/stats")` חייב להיות לפני `router.get("/:id")`. אחרת "stats" ייתפס כ־id, ו־idParamsSchema יחזיר 400. (זוכר את P15-E01?)

4. `app.ts`

הסדר: `express.json()` ← `logger(log)` (רק אם קיבלת `log`) ← `GET /health` ← `app.use("/tasks", createTasksRouter(new TasksService(repository, now)))` ← `notFound` ← `errorHandler`.

ה־repository וה־now מגיעים מבחוץ, עם ברירות מחדל. הבדיקות מעבירות שעון קבוע; `server.ts` מעביר `log: console.log`; ובפרק 19 תעביר repository של PostgreSQL.
