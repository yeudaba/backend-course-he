1. הדרישות

משימה נראית כך:

```json { "id": 1, "title": "ללמוד Express", "description": null, "status": "todo", "priority": "high", "dueDate": "2026-12-31", "createdAt": "2026-11-04T19:09:09.056Z", "updatedAt": "2026-11-04T19:09:09.056Z" } ```
בקשהמה עושההצלחה
`GET /health`"אני חי" — לניטור ולפריסה (פרק 25)200 `{ "ok": true }`
`POST /tasks`יצירה201 + `Location`
`GET /tasks`רשימה: `status`, `priority`, `q`, `sort`, `page`, `limit`200 `{ data, meta }`
`GET /tasks/stats`כמה בכל סטטוס, וכמה באיחור200
`GET /tasks/:id`משימה אחת200
`PATCH /tasks/:id`עדכון חלקי200
`DELETE /tasks/:id`מחיקה204

שגיאות — תמיד `{ "error": { "code", "message", "details"? } }`:

statuscodeמתי
400`VALIDATION_ERROR`body / query / params לא עוברים את הסכמה (עם `details`)
400`INVALID_JSON`גוף שאינו JSON תקין
404`TASK_NOT_FOUND`אין משימה עם ה־id
404`NOT_FOUND`אין כתובת כזו
422`DUE_DATE_IN_PAST`יצירת משימה עם תאריך יעד שכבר עבר
500`INTERNAL`באג — פרטים רק ביומן
💡 400 מול 422

`{"dueDate": "31/12"}` — המבנה שגוי ← 400, הסכמה תופסת. `{"dueDate": "2020-01-01"}` — מבנה תקין, אבל חוק עסקי ("לא יוצרים משימה לעבר") נכשל ← 422, וה־service תופס. ההבחנה הזו קובעת גם איפה כל בדיקה גרה.

2. המבנה

```text tasks-api/ ├── package.json ├── tsconfig.json ├── requests.http ← בקשות לדוגמה ל־REST Client ├── README.md ← שלב 4 └── src/ ├── server.ts ← מפעיל על פורט (מוכן) ├── app.ts ← createApp(): מחבר הכול (שלב 2) ├── errors.ts ← HttpError, notFound, errorHandler (שלב 2) ├── middleware/ │ ├── logger.ts ← (מוכן — כמו P15-E09) │ └── validate.ts ← (שלב 2) └── tasks/ ├── tasks.schema.ts ← Zod + טיפוסים (שלב 1) ├── tasks.repository.ts ← אחסון בזיכרון (שלב 1) ├── tasks.service.ts ← חוקים (שלבים 1, 3) └── tasks.routes.ts ← HTTP (שלב 2) ```

מבנה "לפי תחום" (`tasks/`) ולא "לפי סוג" (`routes/`, `services/`): כשיתווספו `users/` ו־`auth/` בפרק 21, כל תחום יהיה בתיקייה אחת. כך בנוי גם NestJS (פרק 20).

3. הקמה

  1. ב־Finder: העתק את `15p-project-tasks/starter/tasks-api` אל `~/dev/tasks-api` (לצד `backend-course`, לא בתוכו).
  2. ב־Terminal:
```term % cd ~/dev/tasks-api % npm install .. added 78 packages, and audited 79 packages in 6s % code . ```
  1. צור `.gitignore` עם השורה `node_modules/` — לפני ה־commit הראשון.
  2. Git ו־GitHub (כמו בפרק 9, שיעור 4):
```term % git init % git add . % git commit -m "Initial skeleton for tasks API" % git remote add origin https://github.com/YOUR-USER/tasks-api.git % git push -u origin main ```
  1. הפעל: `npm run dev`. השרת עולה (`tasks-api רץ: http://localhost:3000`) — אבל כל בקשה תחזיר 404 של Express, כי `createApp` עוד ריקה.
  2. הרץ את הבודק (בחלון Terminal שני, מתיקיית הקורס): `npm run check PR2 -- --dir ~/dev/tasks-api`. הכול נכשל — מצוין, זו נקודת ההתחלה.

4. איך עובדים

  • commit לכל צעד שעובד: "Add task schemas", "Implement in-memory repository"... מראיין שפותח את ה־repo רואה איך אתה עובד, לא רק את התוצאה.
  • `npm run typecheck` (בתיקיית הפרויקט) מדי פעם — הבודק לא בודק טיפוסים, אבל TypeScript ימצא באגים לפני שהם קורים.
  • אפשר (ומומלץ) להעתיק מהפתרונות שלך לתרגילי פרק 15: E10 (שגיאות), E13 (pagination), E15 (validate), E16 (שכבות). זה לא רמאות — זו הסיבה שתרגלת אותם.
  • תקוע? רמזים בכל שלב. הפתרון המלא — רק בסוף (`reference.html`).
