🎯 בשיעור הזה
  • ההבדל בין סינכרוני לאסינכרוני — באנלוגיה ובקוד.
  • `setTimeout` — הפעולה האסינכרונית הפשוטה ביותר.
  • ה־event loop: למה הסדר של ההדפסות "מוזר".

1. מלצר אחד, הרבה שולחנות

דמיין מסעדה עם מלצר אחד. מלצר סינכרוני לוקח הזמנה משולחן 1, הולך למטבח, עומד ומחכה 20 דקות עד שהמנה מוכנה, מגיש — ורק אז ניגש לשולחן 2. מלצר אסינכרוני לוקח הזמנה, מוסר למטבח, וממשיך לשולחן 2, 3, 4. כשהמטבח מצלצל "מנה מוכנה" — הוא מגיש.

Node הוא המלצר האסינכרוני: יש לו תהליכון אחד שמריץ את הקוד שלך, אבל פעולות איטיות (רשת, קבצים, מסד נתונים) נמסרות "למטבח" — מערכת ההפעלה — והוא ממשיך הלאה. כך שרת אחד מטפל באלפי בקשות.

2. `setTimeout`

```js run console.log("מזמין קפה"); setTimeout(() => { console.log("☕ הקפה מוכן"); }, 1000); console.log("קורא עיתון בינתיים"); ``` ```out מזמין קפה קורא עיתון בינתיים ☕ הקפה מוכן ```

`setTimeout(fn, ms)` אומר: "תריץ את `fn` בעוד `ms` מילישניות (לפחות)". השורה האחרונה לא חיכתה — היא רצה מיד, והקפה הגיע שנייה אחר כך. (1000 מילישניות = שנייה.)

3. ⚡ ה־event loop

⚡ הנושא הזה הוא שאלת ראיון קבועה ```js run console.log("1"); setTimeout(() => console.log("timeout"), 0); Promise.resolve().then(() => console.log("promise")); console.log("2"); ``` ```out 1 2 promise timeout ```

גם `setTimeout` של 0 מילישניות רץ אחרי "2". ו־Promise רץ לפני ה־timeout. למה?

  1. Node מריץ את הקובץ מלמעלה למטה: מדפיס "1", רושם טיימר, רושם Promise, מדפיס "2".
  2. הקוד הנוכחי הסתיים. עכשיו — תור ה־Promises: "promise".
  3. ואז תור המשימות: הטיימר כבר הבשיל ← "timeout".

שתי מסקנות חשובות לעבודה:

  • callback לעולם לא קוטע קוד שרץ. אין "שני דברים באמת באותו רגע" ב־JavaScript שלך — לכן אין צורך בנעילות כמו בשפות אחרות (בתוך תהליך אחד).
  • קוד כבד וסינכרוני חוסם הכול. לולאה של 5 שניות בשרת = 5 שניות שבהן אף בקשה אחרת לא מקבלת תשובה, וגם טיימרים מתעכבים.
```js run const start = Date.now(); setTimeout(() => console.log(`הטיימר רץ אחרי ~${Math.round((Date.now() - start) / 100) * 100}ms`), 100); while (Date.now() - start < 500) { // לולאה "עסוקה" של חצי שנייה } console.log("הלולאה הסתיימה"); ``` ```out הלולאה הסתיימה הטיימר רץ אחרי ~500ms ```

ביקשנו 100ms — קיבלנו 500. הטיימר "הבשיל" בזמן, אבל המלצר היה עסוק.
