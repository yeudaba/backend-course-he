1. `.env`

להקליד `DATABASE_URL=... node app.js` בכל הרצה — לא נוח. במקום, קובץ `.env` בתיקיית הפרויקט:

```text file=.env PORT=8080 DATABASE_URL=postgres://dana:secret@localhost:5432/shop JWT_SECRET=change-me-to-something-long # הערה APP_NAME="Dana Shop" ``` ```term % node --env-file=.env src/app.mjs ```

Node (20.6 ומעלה) קורא את הקובץ ומכניס את הערכים ל־`process.env` לפני שהקוד מתחיל. בקוד ישן תראה את החבילה `dotenv` (`import "dotenv/config"`) — אותו רעיון.

2. מה נכנס ל־Git

קובץב־Git?מה בו
`.env`✘ לעולם לא (ב־`.gitignore`)הערכים האמיתיים שלך
`.env.example`✔אותם שמות, עם ערכים לדוגמה/ריקים. מי שעושה clone מעתיק ל־`.env` וממלא

ובשרת? אין `.env` בכלל — משתני הסביבה מוגדרים בממשק של שירות הפריסה או של "מנהל סודות" (פרק 25).

3. 👣 מודול config

במקום לפזר `process.env.X` בכל הקוד — מקום אחד שקורא, ממיר, בודק ומייצא אובייקט מוקלד. זה P08-E18, עכשיו כמודול אמיתי:

```js file=src/config.mjs function required(name) { const value = process.env[name]; if (value === undefined || value.trim() === "") { throw new Error(`חסר משתנה סביבה: ${name}`); } return value; } function intFromEnv(name, fallback) { const raw = process.env[name]; if (raw === undefined) return fallback; const n = Number(raw); if (!Number.isInteger(n)) { throw new Error(`${name} חייב להיות מספר שלם`); } return n; } export const config = Object.freeze({ port: intFromEnv("PORT", 3000), databaseUrl: required("DATABASE_URL"), jwtSecret: required("JWT_SECRET"), isProduction: process.env.NODE_ENV === "production", }); ```

ייבוא המודול רץ פעם אחת בעליית השרת — אם חסרה הגדרה, השרת לא יעלה בכלל, עם הודעה ברורה (fail fast). `Object.freeze` — אף אחד לא ישנה את ההגדרות בזמן ריצה בטעות. ובכל שאר הקוד: `import { config } from "./config.mjs"`.

⚠️ לא להדפיס סודות

`console.log(config)` בעליית השרת "כדי לבדוק" — ישלח את הסיסמה ליומני המערכת, שאנשים רבים רואים. אם צריך — הדפס רק את השמות, או החלף ערכים סודיים ב־`"***"` (תרגיל E15).
