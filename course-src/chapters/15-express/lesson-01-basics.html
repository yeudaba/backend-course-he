1. לפני ואחרי

זוכר את שרת ההדגמה של פרק 14? ככה נראה החלק של המוצרים ב־Express:

```ts file=playground/express-demo.ts import express from "express"; const app = express(); app.use(express.json()); const products = [ { id: 1, name: "מקלדת", price: 249 }, { id: 2, name: "עכבר", price: 89 }, ]; let nextId = 3; app.get("/products", (req, res) => { res.json(products); }); app.get("/products/:id", (req, res) => { const product = products.find((p) => p.id === Number(req.params.id)); if (!product) { res.status(404).json({ error: "המוצר לא נמצא" }); return; } res.json(product); }); app.post("/products", (req, res) => { const product = { id: nextId++, name: req.body.name, price: req.body.price }; products.push(product); res.status(201).location(`/products/${product.id}`).json(product); }); app.listen(4000, () => console.log("http://localhost:4000")); ```

הרץ: `node --watch playground/express-demo.ts` (ה־`--watch` מפעיל מחדש בכל שמירה) ובדוק עם curl או REST Client. מה נעלם לעומת פרק 14?

2. מה יש ב־req

לבקשה `GET /products/7?sort=price&page=2` מול route `"/products/:id"`:

ביטויערךשים לב
`req.params``{ id: "7" }`תמיד מחרוזות
`req.query``{ sort: "price", page: "2" }`מחרוזות; קריאה בלבד ב־Express 5
`req.body``undefined`יש ערך רק אם נשלח JSON וגם `express.json()` רץ
`req.method`, `req.path``"GET"`, `"/products/7"`path בלי query
`req.get("authorization")`ערך ה־headerבלי תלות באותיות
```ts run import express from "express"; const app = express(); app.get("/products/:id", (req, res) => { res.json({ params: req.params, query: req.query, path: req.path }); }); const server = app.listen(0, async () => { const port = (server.address() as { port: number }).port; const res = await fetch(`http://localhost:${port}/products/7?sort=price&page=2`); console.log(JSON.stringify(await res.json())); server.close(); }); ``` ```out {"params":{"id":"7"},"query":{"sort":"price","page":"2"},"path":"/products/7"} ```

(הדוגמה מפעילה שרת על פורט פנוי (`0`), שולחת אליו בקשה וסוגרת אותו — כך גם הבדיקות האוטומטיות של הפרק עובדות.)

3. תשובות

קודמה נשלח
`res.json(obj)`200 + `Content-Type: application/json` + הגוף
`res.status(201).json(obj)`status אחר. `status` מחזיר את `res`, ולכן אפשר לשרשר
`res.sendStatus(204)`status בלבד, בלי גוף — למחיקה
`res.location("/products/3")`header `Location`
`res.set("X-Total-Count", "42")`כל header
⚠️ `return` אחרי תשובה

`res.status(404).json(...)` לא עוצר את הפונקציה. בלי `return` הקוד ממשיך, מגיע ל־`res.json(product)` — ו־Express זורק `Cannot set headers after they are sent`. לכן אחרי כל תשובה מוקדמת: `return`. (בדוגמה למעלה — `return;` בשורה נפרדת, כי TypeScript מעדיף שה־handler לא יחזיר ערך.)

4. `app.ts` ו־`server.ts` — למה לפצל

```ts file=src/app.ts import express from "express"; export function createApp() { const app = express(); app.use(express.json()); app.get("/health", (req, res) => { res.json({ ok: true }); }); return app; } ``` ```ts file=src/server.ts import { createApp } from "./app.ts"; const port = Number(process.env.PORT ?? 3000); createApp().listen(port, () => console.log(`http://localhost:${port}`)); ```

`app.ts` רק בונה את האפליקציה; `server.ts` מפעיל אותה על פורט. היתרון: בדיקות (שלך ושל הבודק) קוראות ל־`createApp()`, מפעילות על פורט פנוי, וכל בדיקה מקבלת אפליקציה נקייה. ככה בנויים כל התרגילים בפרק — וכל הפרויקטים מכאן והלאה.

וטיפוסים? `@types/express` מותקן, ולכן `req` ו־`res` מוקלדים אוטומטית בתוך `app.get(...)`. נסה לכתוב `req.` ב־VS Code ותראה את ההשלמות. כשכותבים handler כפונקציה נפרדת — מייבאים את הטיפוסים: `import express, { type Request, type Response } from "express"`.
