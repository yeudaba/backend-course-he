1. בקשה עוברת בצינור

middleware הוא פונקציה `(req, res, next)`. היא יכולה (1) לעשות משהו ולקרוא `next()` כדי להמשיך, או (2) לענות ולעצור. route הוא בעצם middleware שרץ רק כש־method ו־path מתאימים.

```ts run import express from "express"; const app = express(); const log: string[] = []; app.use((req, res, next) => { log.push(`1: ${req.method} ${req.path}`); next(); }); app.get("/a", (req, res) => { log.push("2: route /a"); res.json("A"); }); app.use((req, res) => { log.push("3: אף route לא התאים"); res.status(404).json({ error: "לא נמצא" }); }); const server = app.listen(0, async () => { const base = `http://localhost:${(server.address() as { port: number }).port}`; await fetch(`${base}/a`); await fetch(`${base}/b`); console.log(log.join("\n")); server.close(); }); ``` ```out 1: GET /a 2: route /a 1: GET /b 3: אף route לא התאים ```

שים לב: ה־404 עובד רק כי הוא נרשם אחרי ה־routes. אילו היה ראשון — כל בקשה הייתה מקבלת 404.

2. middleware לוג עם זמן תגובה

```ts file=src/middleware/logger.ts import type { Request, Response, NextFunction } from "express"; export function logger(req: Request, res: Response, next: NextFunction) { const start = performance.now(); res.on("finish", () => { const ms = Math.round(performance.now() - start); console.log(`${req.method} ${req.originalUrl} ${res.statusCode} ${ms}ms`); }); next(); } ```

הטריק: כשה־middleware רץ, התשובה עוד לא קיימת. לכן נרשמים לאירוע `finish` של `res` (פרק 10 — אירועים) ומדפיסים כשהתשובה נשלחה. כך נראים יומנים בכל שרת אמיתי: `GET /tasks?page=2 200 4ms`.

3. שגיאות: מקום אחד לכולן

middleware עם ארבעה פרמטרים הוא error handler. Express מזהה אותו לפי מספר הפרמטרים — גם אם לא משתמשים ב־`next`, חובה לכתוב אותו.

```ts file=src/errors.ts import type { Request, Response, NextFunction } from "express"; export class HttpError extends Error { status: number; code: string; constructor(status: number, code: string, message: string) { super(message); this.status = status; this.code = code; } } export function notFound(req: Request, res: Response) { res.status(404).json({ error: { code: "NOT_FOUND", message: `אין כתובת ${req.method} ${req.path}` } }); } export function errorHandler(err: unknown, req: Request, res: Response, next: NextFunction) { if (err instanceof HttpError) { res.status(err.status).json({ error: { code: err.code, message: err.message } }); return; } // JSON שבור בגוף הבקשה — express.json() זורק שגיאה עם type כזה if (typeof err === "object" && err !== null && "type" in err && err.type === "entity.parse.failed") { res.status(400).json({ error: { code: "INVALID_JSON", message: "JSON לא תקין" } }); return; } console.error(err); res.status(500).json({ error: { code: "INTERNAL", message: "שגיאה פנימית" } }); } ``` ```ts file=src/app.ts app.use(express.json()); app.use(logger); app.use("/tasks", tasksRouter); // כל ה־routes app.use(notFound); // אחרי כל ה־routes app.use(errorHandler); // אחרון ```

מעכשיו, בתוך route, כדי להחזיר שגיאה פשוט זורקים: `throw new HttpError(404, "TASK_NOT_FOUND", "המשימה לא נמצאה")`. אין צורך ב־try/catch בכל route.

💡 Express 5 ו־async

ב־Express 5, route שהוא `async` וזורק (או מחזיר Promise שנדחה) — השגיאה מגיעה אוטומטית ל־error handler. ב־Express 4 זה לא היה כך, והשרת היה קורס או הבקשה נתקעת; בקוד ישן תראה עוטפים כמו `asyncHandler(...)` או `express-async-errors` — זו הסיבה.

⚠️ לא לחשוף פרטים

500 מחזיר "שגיאה פנימית" — לא את `err.message` ולא stack. הפרטים הולכים ליומן (`console.error`), שרק אתה רואה. הודעת שגיאה פנימית יכולה לחשוף שמות טבלאות, נתיבים או מידע של משתמשים אחרים.
