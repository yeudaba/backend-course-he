1. למה Zod

בפרק 12 כתבת ולידציה ביד: `if (typeof body.title !== "string" || ...)`. זה עובד, אבל ארוך, קל לשכוח שדה, ו־TypeScript לא יודע שבדקת. Zod: מתארים פעם אחת איך נראה קלט תקין — ומקבלים גם בדיקה וגם טיפוס.

```ts run import { z } from "zod"; const createTaskSchema = z.object({ title: z.string().trim().min(1, "חובה").max(100, "עד 100 תווים"), priority: z.enum(["low", "medium", "high"]).default("medium"), dueDate: z.iso.date().optional(), }); type CreateTaskInput = z.infer; const good = createTaskSchema.safeParse({ title: " לקנות חלב ", dueDate: "2026-11-20" }); if (good.success) { const task: CreateTaskInput = good.data; console.log(JSON.stringify(task)); } const bad = createTaskSchema.safeParse({ title: "", priority: "urgent" }); if (!bad.success) { for (const issue of bad.error.issues) console.log(issue.path.join("."), "—", issue.message); } ``` ```out {"title":"לקנות חלב","priority":"medium","dueDate":"2026-11-20"} title — חובה priority — Invalid option: expected one of "low"|"medium"|"high" ```
  • `.trim()` ו־`.default()` לא רק בודקים — הם משנים: התוצאה ב־`data` היא הגרסה הנקייה. תמיד ממשיכים עם `data`, לא עם הקלט המקורי.
  • שדות שלא בסכמה (`{"isAdmin": true}`) נמחקים מ־`data`. זו הגנה חשובה: לקוח לא יכול "להשחיל" שדה שלא ציפית לו. (`z.strictObject` — מחזיר שגיאה במקום למחוק.)
  • `z.infer` נותן את הטיפוס — בלי לכתוב `interface` נפרד שעלול לא להתאים לבדיקה.
  • `parse` זורק; `safeParse` מחזיר `{ success, data | error }`. בשרת — `safeParse`, כדי להחליט בעצמנו מה להחזיר.
Zodמה בודק
`z.string().min(1).max(100)`מחרוזת באורך
`z.email()` · `z.url()` · `z.uuid()` · `z.iso.date()`פורמטים נפוצים
`z.number().int().positive()`מספר שלם חיובי
`z.boolean()` · `z.enum([...])`ערכים סגורים
`z.array(z.string()).max(5)`מערך
`.optional()` · `.nullable()` · `.default(x)`שדה לא חובה / יכול להיות null / ערך אם חסר
`schema.partial()`אותה סכמה, כל השדות לא חובה — מושלם ל־PATCH

2. query: הכול מגיע כמחרוזת

ב־`?page=2`, הערך הוא `"2"`. `z.number()` יכשיל אותו. `z.coerce.number()` ממיר קודם:

```ts run import { z } from "zod"; const listQuerySchema = z.object({ page: z.coerce.number().int().min(1).default(1), limit: z.coerce.number().int().min(1).max(50).default(20), status: z.enum(["open", "done"]).optional(), }); console.log(JSON.stringify(listQuerySchema.parse({ page: "2" }))); console.log(listQuerySchema.safeParse({ limit: "1000" }).success); console.log(listQuerySchema.safeParse({ page: "" }).success); console.log(z.coerce.number().parse("")); ``` ```out {"page":2,"limit":20} false false 0 ```

שורה 2: limit מעל התקרה ← נכשל, וטוב שכך. שורה 3: `?page=` (ריק) נכשל — כי `Number("")` הוא `0`, ו־0 קטן מ־1. ושורה 4 היא המלכודת: בשדה בלי `min`, ערך ריק הופך בשקט ל־0. `?maxPrice=` יחזיר רק מוצרים בחינם. כשזה חשוב — הוסף `.positive()`, או בדוק ש־`""` לא נשלח.

3. middleware בדיקה אחד לכל ה־routes

```ts file=src/middleware/validate.ts import type { Request, Response, NextFunction } from "express"; import type { ZodType } from "zod"; export function validateBody(schema: ZodType) { return (req: Request, res: Response, next: NextFunction) => { const result = schema.safeParse(req.body); if (!result.success) { res.status(400).json({ error: { code: "VALIDATION_ERROR", message: "קלט לא תקין", details: result.error.issues.map((i) => ({ path: i.path.join("."), message: i.message })), }, }); return; } req.body = result.data; // מעכשיו req.body נקי ובטוח next(); }; } ``` ```ts router.post("/", validateBody(createTaskSchema), (req, res) => { const task = service.create(req.body); res.status(201).location(`/tasks/${task.id}`).json(task); }); ```

שים לב לרעיון: `validateBody(schema)` היא פונקציה שמחזירה middleware (closure — פרק 5). כך אותו קוד משרת כל סכמה.

⚠️ Express 5: אסור לדרוס את req.query

`req.body = result.data` עובד. אבל `req.query = result.data` זורק: `Cannot set property query of # which has only a getter` (ב־Express 5 ה־query מחושב מחדש מהכתובת). המקום המקובל לשמור query שנבדק: `res.locals.query = result.data` — `res.locals` הוא אובייקט שמיועד בדיוק להעברת נתונים בין middleware ל־handler באותה בקשה.
