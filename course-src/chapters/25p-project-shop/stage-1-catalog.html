🎯 בשלב הזה
  • משתמשים: הרשמה, כניסה, /auth/me, ומנהל ראשון מההגדרות.
  • guard אחד: כל נתיב דורש התחברות, אלא אם סומן ציבורי; ותפקידים.
  • מוצרים: CRUD למנהל, ו־GET /products עם חיפוש, סינון, מיון ו־pagination.

1. משתמשים

  • הרשמה: { email, password, name }. אימייל — קטנות, בלי רווחים. סיסמה — 8 תווים לפחות ועד 72 בתים (bcrypt, פרק 21). role — תמיד customer; אם הוא מגיע בגוף הבקשה: 400, או להתעלם — אבל אף פעם לא admin.
  • כניסה: אימייל שלא קיים וסיסמה שגויה — בדיוק אותה תשובה (401 INVALID_CREDENTIALS). הבודק משווה את שתי התשובות.
  • מנהל ראשון: אין טופס "הרשמה כמנהל" — ומי ייתן לראשון הרשאות? בעלייה, אם מוגדרים ADMIN_EMAIL ו־ADMIN_PASSWORD, השרת יוצר את המשתמש (או מעדכן אותו ל־admin). ב־Nest: OnApplicationBootstrap ו־upsert.
  • התפקיד — מהמסד, לא מהטוקן. אם התפקיד בתוך ה־JWT, מנהל שהורד מתפקידו נשאר מנהל עד שהטוקן פג. שאילתה אחת לבקשה, ובתמורה — אמת.

guard גלובלי (APP_GUARD) עם @Public() ו־@Roles("admin") — כמו בפרק 21. 401 = "מי אתה?"; 403 = "אני יודע מי אתה, ולא".

2. מוצרים

מוצר: { id, name, description, priceCents, stock, category, createdAt, updatedAt }. ולידציה: priceCents שלם וחיובי (9.99 ← 400 — זה הסימן שמישהו שלח שקלים במקום אגורות), stock שלם ולא שלילי.

פרמטר ב־GET /productsמה
qחיפוש בשם ובתיאור, בלי תלות באותיות גדולות/קטנות (ב־Prisma: contains עם mode: "insensitive")
categoryהתאמה מדויקת
minPrice · maxPriceבאגורות, כולל הגבולות
inStock=trueרק מה שיש במלאי
sortprice, -price, name, -name, newest (ברירת מחדל). ערך אחר ← 400
page · limitברירת מחדל 1 ו־20; limit עד 100 (אחרת 400) — אחרת מישהו מבקש מיליון שורות

מחיקה — רכה: מוצר שכבר הוזמן חייב להישאר, כי order_items מצביעות עליו. מסמנים active = false: הוא נעלם מהרשימה, GET /products/:id מחזיר 404, והוא יוצא מהעגלות. ובמיון, תמיד עוד שדה ייחודי בסוף (id) — אחרת שני מוצרים באותו מחיר יכולים "לקפוץ" בין עמודים.

3. לבדוק

```term % cd ~/dev/coffee-shop && npx prisma generate && npm run build % cd ~/dev/backend-course % npm run check PR3-AUTH -- --dir ~/dev/coffee-shop % npm run check PR3-PRODUCTS -- --dir ~/dev/coffee-shop ```

PR3-AUTH: הרשמה (אימייל מנורמל, בלי hash בתשובה), 409 על אימייל קיים, אותה תשובה לסיסמה שגויה ולמשתמש שלא קיים, /auth/me עם ובלי טוקן, ולידציה, role בגוף, ומנהל מ־ADMIN_EMAIL. PR3-PRODUCTS: יצירה, עדכון ומחיקה רכה; 401/403 ללקוח ולאורח; ולידציה; וחיפוש עם כל הפרמטרים, כולל meta של pagination. כל בדיקה מעלה את השרת שלך מחדש, מול מסד ריק — לכן היא לוקחת כמה שניות.
