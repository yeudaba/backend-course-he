<p>כשבאג נכנס "מתישהו" ויש מאות commits, <code>git bisect</code> מוצא את ה־commit האשם בחיפוש בינארי. בנה בעצמך מאגר <code>playground/bisect-lab</code> עם 12 commits, שבכל אחד שינוי קטן ב־<code>calc.js</code> (פונקציה <code>total(items)</code>), ובאחד מהם (נגיד השביעי) — באג. אחר כך כתוב סקריפט בדיקה קטן <code>check.js</code> שיוצא עם קוד 0 כשהתוצאה נכונה ו־1 כשלא, והרץ:</p>
```term
% git bisect start
% git bisect bad HEAD
% git bisect good <hash-of-first-commit>
% git bisect run node check.js
```
<p>כמה צעדים לקח ל־Git? כמה היו לוקחים עם 1,000 commits?</p>
@hint1
<p>check.js: <code>const { total } = require("./calc"); process.exit(total([{ price: 10, qty: 2 }]) === 20 ? 0 : 1);</code></p>
@hint2
<p>אחרי שנמצא: <code>git bisect reset</code> מחזיר אותך ל־HEAD.</p>
@solution

<p>עם 12 commits — כ־4 צעדים (log₂12 ≈ 3.6). עם 1,000 — כ־10. זו אותה חשיבה כמו חיפוש בינארי במערך ממוין (פרק 27): כל בדיקה חותכת את מרחב החיפוש בחצי. ושים לב ש־<code>check.js</code> הוא בעצם בדיקה אוטומטית — עוד הוכחה כמה הן שוות (פרק 22).</p>
