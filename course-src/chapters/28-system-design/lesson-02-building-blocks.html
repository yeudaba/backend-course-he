1. עוד שרתים: stateless

שרת אחד הגיע ל־100% CPU. שתי דרכים: שרת חזק יותר (vertical — פשוט, ויש לו תקרה), או עוד שרתים (horizontal). בשביל horizontal, השרת חייב להיות stateless: אף מידע שחשוב לבקשה הבאה לא נשמר בזיכרון שלו. בקשה של אותו משתמש יכולה להגיע לכל עותק.

בדוק את הפרויקטים שלך: JWT — בלי session בזיכרון ✔. idempotency keys — במסד ✔. הגבלת קצב מפרק 24 — ב־Map בזיכרון ✘ — בדיוק לכן העברנו אותה ל־Redis בפרק 26. ה־cache בזיכרון של E19 בפרק 26 — מותר, כי הוא רק אופטימיזציה, עם pub/sub לביטול.

לפני השרתים יושב load balancer: מקבל את כל הבקשות ומפזר — round robin, או למי שהכי פנוי (least connections, E08). ושואל כל כמה שניות את /ready (פרק 25): שרת שלא עונה, או עונה 503, יוצא מהסבב (E09). ב־Render ובכל ענן זה רכיב מוכן; מקומית — nginx או Caddy (פרק 25).

2. המסד: replicas

השרתים הוכפלו — עכשיו כולם מכים במסד אחד. ברוב המערכות יש הרבה יותר קריאות מכתיבות, ולכן הצעד הראשון: read replicas — עותקים שמקבלים כל שינוי מה־primary ומשרתים קריאות. כתיבות — רק ל־primary.

המחיר: replication lag. ה־replica מקבלת את השינויים באיחור — מילישניות בדרך כלל, שניות בעומס. לקוח ששילם ומרענן את הדף מ־replica עלול לראות "ממתין לתשלום". הפתרון הנפוץ (E14): מי שכתב עכשיו — קורא מה־primary לכמה שניות. ומה שמחליט על כסף ומלאי — תמיד מה־primary, בתוך טרנזקציה (E04).

4. כשלים

במערכת עם כמה רכיבים, משהו תמיד קצת שבור. שלושה כלים, שתמיד באים יחד:

timeout. כל קריאה לשירות אחר — עם גבול זמן. בלי timeout, ספק שנתקע תוקע אותך: כל בקשה מחזיקה חיבור, החיבורים נגמרים, ונופלות גם בקשות שלא קשורות אליו. ב־fetch: signal: AbortSignal.timeout(3000).

retry עם backoff ו־jitter (E12). נכשל? לחכות ולנסות שוב, בהמתנה שגדלה. ו־jitter — רעש אקראי — כי אחרת כל הלקוחות שנכשלו יחד חוזרים יחד:

```ts run // 1,000 לקוחות נכשלו באותו רגע. מתי כל אחד מנסה שוב (ניסיון שלישי, תקרה 400ms)? let seed = 7; const random = () => ((seed = (seed * 1664525 + 1013904223) >>> 0) / 2 ** 32); const peakPerMs = (delays: number[]) => Math.max(...[...delays.reduce((m, d) => m.set(d, (m.get(d) ?? 0) + 1), new Map()).values()]); const plain = Array.from({ length: 1000 }, () => 100 * 2 ** 2); const jittered = Array.from({ length: 1000 }, () => Math.floor(random() * 100 * 2 ** 2)); console.log("בלי jitter — באותה מילישנייה:", peakPerMs(plain)); console.log("עם jitter — באותה מילישנייה, לכל היותר:", peakPerMs(jittered)); ``` ```out בלי jitter — באותה מילישנייה: 1000 עם jitter — באותה מילישנייה, לכל היותר: 6 ```

ועוד שני כללים: מנסים שוב רק מה שבטוח לחזור עליו (GET, PUT, או POST עם Idempotency-Key — פרק 24), ולא מנסים שוב 4xx — הבקשה שגויה, ותיכשל באותה דרך.

circuit breaker (E15). כשהשירות למטה, גם retry חכם הוא בזבוז — ולפעמים מה שמונע ממנו לקום. ה"מפסק": אחרי N כישלונות — open: נכשלים מיד, בלי לפנות. אחרי זמן — half-open: בקשת ניסיון אחת. הצליחה — closed; נכשלה — שוב open. בינתיים — fallback: "המשלוח יחושב בהמשך", המלצות כלליות במקום אישיות, תשובה מה־cache.
