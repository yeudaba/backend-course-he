```sql run db=17-relations/files/store.sql
  (SELECT COUNT(*) FROM customers c LEFT JOIN orders o ON o.customer_id = c.id) AS q2,
  (SELECT COUNT(*) FROM orders o LEFT JOIN customers c ON c.id = o.customer_id) AS q3,
  (SELECT COUNT(*) FROM customers c JOIN orders o ON true) AS q4;
```

```out
 q1 | q2 | q3 | q4
----+----+----+----

(1 row)
```

@@ P17-E03 | 1 | למה הסכום כפול? | 10 | שיעור 2
@task
<p>נניח שיש גם טבלת <code>payments(order_id, amount)</code>, ולהזמנה אחת יכולים להיות כמה תשלומים (חלוקה לכרטיסים). מישהו כתב:</p>
```sql
SELECT o.id, SUM(oi.quantity * oi.unit_price) AS total, SUM(p.amount) AS paid
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
JOIN payments p     ON p.order_id = o.id
GROUP BY o.id;
```
<p>להזמנה עם 3 פריטים ו־2 תשלומים — מה יקרה ל־total ול־paid? למה? ואיך מתקנים?</p>
@hint1
<p>כמה שורות יש להזמנה הזו אחרי שני ה־JOIN־ים?</p>
@hint2
<p>לסכם כל צד בנפרד, ורק אז לחבר.</p>
@solution
<p>אחרי שני ה־JOIN־ים יש 3 × 2 = 6 שורות להזמנה (כל פריט עם כל תשלום). total יוצא פי 2 (כל פריט נספר פעמיים), ו־paid פי 3. זה ה־"fan-out" — אחד הבאגים הנפוצים בדוחות.</p>
```sql
WITH items AS (SELECT order_id, SUM(quantity * unit_price) AS total FROM order_items GROUP BY order_id),
     pays  AS (SELECT order_id, SUM(amount) AS paid FROM payments GROUP BY order_id)
SELECT o.id, i.total, COALESCE(p.paid, 0) AS paid
FROM orders o
JOIN items i     ON i.order_id = o.id
LEFT JOIN pays p ON p.order_id = o.id;
```
@mistakes
<ul><li>"לתקן" עם <code>SUM(DISTINCT ...)</code> — שני פריטים באותו מחיר ייספרו כאחד.</li></ul>

```sql
SELECT status, COUNT(*) FROM orders GROUP BY status HAVING COUNT(*) > 2;                   -- 2

```

```out
-------------

(2 rows)

 full_name
-----------
(0 rows)

    name
------------
 gift cards
(1 row)
```
<p>1: בלי Avi ו־Omer (עיר NULL). 2: <strong>כלום</strong> — בגלל ה־NULL ברשימה. 3: עובד כאן, כי <code>category_id</code> הוא NOT NULL. אבל אם יום אחד העמודה תהיה nullable ומוצר אחד יהיה בלי קטגוריה — השאילתה תחזיר כלום בשקט. לכן: <code>NOT EXISTS</code>.</p>

```sql run db=17-relations/files/store.sql save=solutions/P17-E27.sql
WITH order_totals AS (
  SELECT o.id, o.customer_id, o.created_at, SUM(oi.quantity * oi.unit_price) AS total
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  WHERE o.status <> 'cancelled'
  GROUP BY o.id
)

  c.full_name,
  t.id AS order_id,
  ROW_NUMBER() OVER (PARTITION BY c.id ORDER BY t.created_at) AS order_no,
  t.total,
  SUM(t.total) OVER (PARTITION BY c.id ORDER BY t.created_at) AS running_total
FROM order_totals t
JOIN customers c ON c.id = t.customer_id
ORDER BY c.full_name, order_no;
```

```ts run save=solutions/P17-E28.ts
// P17-E28: JOIN ו־GROUP BY בקוד
export type Customer = { id: number; full_name: string; city: string | null };
export type Order = { id: number; customer_id: number; status: string };
export type OrderItem = { order_id: number; quantity: number; unit_price: number };
export type CityRevenue = { city: string; revenue: number };

export function revenueByCity(customers: Customer[], orders: Order[], items: OrderItem[]): CityRevenue[] {
  // "אינדקס" לפי id — כמו JOIN ... ON c.id = o.customer_id, בלי לחפש במערך כל פעם
  const customerById = new Map(customers.map((c) => [c.id, c]));
  const orderById = new Map(orders.map((o) => [o.id, o]));

  const agorotByCity = new Map<string, number>();
  for (const item of items) {
    const order = orderById.get(item.order_id);
    if (!order || order.status === "cancelled") continue;
    const city = customerById.get(order.customer_id)?.city ?? "unknown";
    const agorot = Math.round(item.quantity * item.unit_price * 100);
    agorotByCity.set(city, (agorotByCity.get(city) ?? 0) + agorot);
  }

  return [...agorotByCity]
    .map(([city, agorot]) => ({ city, revenue: agorot / 100 }))
    .sort((a, b) => b.revenue - a.revenue || a.city.localeCompare(b.city));
}

const customers = [
  { id: 1, full_name: "Dana", city: "Haifa" },
  { id: 2, full_name: "Avi", city: null },
];
const orders = [
  { id: 10, customer_id: 1, status: "paid" },
  { id: 11, customer_id: 2, status: "pending" },
  { id: 12, customer_id: 1, status: "cancelled" },
];
const items = [
  { order_id: 10, quantity: 3, unit_price: 19.9 },
  { order_id: 11, quantity: 1, unit_price: 89.9 },
  { order_id: 12, quantity: 5, unit_price: 100 },
];
console.log(revenueByCity(customers, orders, items));
```
```out

  { city: 'Haifa', revenue: 59.7 }
]
```
<p>כל חלק בשאילתה של P17-E12 קיבל מקבילה בקוד. ‏<code>JOIN ... ON</code> הוא <code>Map.get</code> לפי id. ‏<code>WHERE status &lt;&gt; 'cancelled'</code> הוא <code>continue</code>. ‏<code>GROUP BY</code> עם <code>SUM</code> הוא <code>Map</code> של צוברים. ‏<code>ORDER BY</code> הוא <code>sort</code>. גם PostgreSQL עושה בדיוק את זה (נקרא <em>hash join</em>): בונה טבלת גיבוב מצד אחד, ועובר על הצד השני.</p>
<p>ההבדל: SQL עושה את זה ליד הנתונים, ומחזיר 4 שורות. בקוד היית צריך קודם להעביר את כל ההזמנות והפריטים מהמסד. לכן ברוב המקרים עדיף SQL, וזה תרגיל כדי לראות מה קורה "מתחת למכסה".</p>
<p><code>numeric</code> ב־PostgreSQL מדויק, ו־<code>number</code> ב־JavaScript לא. לכן הסכום עובר באגורות שלמות (פרק 2), והחילוק ב־100 נעשה רק בסוף.</p>
