🎯 בשיעור הזה
  • מה זה ביטוי רגולרי (regex), ולמה הוא חוסך לולאות שלמות.
  • אבני הבניין: תווים, קבוצות תווים, כמויות, ו־`^`/`$`.
  • `test` לבדיקה, `match` ו־groups לפירוק, `replace` ו־`split` לשינוי.
  • הדגלים `g`, `i`, `u`, ‏regex מתוך משתנה, ו"מתי לא להשתמש ב־regex".

1. למה צריך את זה

ב־P03-E27 (פרק 3) בדקת שמספר טלפון "נראה תקין". בדקת אורך, ובדקת שהוא מתחיל ב־`05`. אבל "שכל התווים הם ספרות" נשאר בחוץ. עם מה שאתה יודע עכשיו, זו לולאה:

```js run function allDigits(text) { if (text.length === 0) { return false; } for (const ch of text) { if (ch < "0" || ch > "9") { return false; } } return true; } console.log(allDigits("0521234567"), allDigits("052-123")); console.log(/^\d+$/.test("0521234567"), /^\d+$/.test("052-123")); ``` ```out true false true false ```

השורה האחרונה עושה את אותה בדיקה. `/^\d+$/` הוא ביטוי רגולרי (regular expression, ובקיצור regex): תבנית שמתארת איך טקסט צריך להיראות. `test` שואל "האם הטקסט מתאים לתבנית?" ומחזיר `true` או `false`.

בשרת תפגוש regex כל הזמן: בדיקת קלט (טלפון, מיקוד, שם משתמש), פירוק שורות לוג, ניקוי טקסט, ובספריות כמו Zod (פרק 15), שבהן כותבים `.regex(/.../)`. הקורס משתמש בו מכאן והלאה, אז כדאי להכיר אותו טוב.

2. אבני הבניין

regex כותבים בין שני לוכסנים: `/.../`. אותיות וספרות רגילות מתאימות לעצמן. `/cat/` מחפש את הרצף "cat" בכל מקום בטקסט. התווים המיוחדים הם אלה:

כתיבמתאים ל־דוגמה
`\d`ספרה אחת (0–9)`/\d\d/` ← "07" ✔
`\w`אות לטינית, ספרה או `_``/\w/` ← "a" ✔, "א" ✘
`\s`רווח, טאב או ירידת שורה
`\D` / `\W` / `\S`ההפך (אות גדולה = "כל תו שאינו..."): לא ספרה / לא `\w` / לא רווח`/\S+/` ← "abc" מתוך " abc "
`.`כל תו (חוץ מירידת שורה)`/1.5/` ← "1.5" ✔, אבל גם "105" ✔
`[abc]`אחד מהתווים שבסוגריים`/[-.]/` ← מקף או נקודה
`[a-z]`, `[0-9]`טווח`/[a-z0-9_]/`
`[^0-9]`כל תו חוץ מאלה
`+` / `*` / `?`מה שלפני: פעם או יותר / אפס או יותר / אופציונלי`/\d+/`, `/-?/`
`{7}` / `{2,4}`בדיוק 7 פעמים / בין 2 ל־4`/\d{7}/`
`^` / `$`תחילת הטקסט / סוף הטקסט`/^\d+$/` ← רק ספרות, מההתחלה עד הסוף
`a|b`או זה או זה`/^(GET|POST)$/`
`\.` `\(` `\$` ...התו עצמו, בלי המשמעות המיוחדת`/\d+\.\d\d/` ← "12.50"

הנה טלפון נייד ישראלי, עם או בלי מקף אחרי הקידומת:

```js run const mobile = /^05\d-?\d{7}$/; for (const phone of ["052-1234567", "0521234567", "052-12345", "x0521234567", "052--1234567"]) { console.log(phone, mobile.test(phone)); } console.log(/\d{7}/.test("abc12345678xyz")); console.log(/^GET|POST$/.test("GETTER"), /^(GET|POST)$/.test("GETTER")); console.log(/hello/i.test("Hello World")); ``` ```out 052-1234567 true 0521234567 true 052-12345 false x0521234567 false 052--1234567 false true true false true ```

שלוש השורות האחרונות הן שלושה שיעורים:

  • בלי `^` ו־`$`, `/\d{7}/` מסתפק ב־7 ספרות איפשהו, גם בתוך זבל. כשבודקים קלט, כמעט תמיד צריך את שניהם.
  • `|` מחלק את כל הביטוי: `/^GET|POST$/` הוא "מתחיל ב־GET" או "נגמר ב־POST". סוגריים תוחמים אותו: `/^(GET|POST)$/`.
  • `i` אחרי הלוכסן הסוגר הוא דגל (flag): בלי הבדל בין אותיות גדולות לקטנות. נכיר עוד שניים בהמשך.

3. `match` ו־groups: לפרק טקסט לחלקים

`test` עונה רק כן או לא. `match` מחזיר מה נמצא. סוגריים בתבנית יוצרים group, וכל group נכנס למקום משלו במערך:

```js run const m = "2026-11-19".match(/^(\d{4})-(\d{2})-(\d{2})$/); console.log(m[0], m[1], m[2], m[3]); const [, year, month, day] = m; console.log(Number(day), Number(month), Number(year)); console.log("19/11/2026".match(/^(\d{4})-(\d{2})-(\d{2})$/)); const line = "GET /tasks/42 200"; const named = line.match(/^(?[A-Z]+) (?\S+) (?\d{3})$/); console.log(named.groups.method, named.groups.path, Number(named.groups.status)); ``` ```out 2026-11-19 2026 11 19 19 11 2026 null GET /tasks/42 200 ```
  • `m[0]` הוא כל מה שהתאים. `m[1]`, `m[2]`... הם ה־groups, לפי סדר הסוגריים הפותחים. ה־destructuring משיעור 3 של פרק 7 מדלג על `m[0]` עם הפסיק הראשון.
  • כשאין התאמה, `match` מחזיר `null`, לא מערך ריק. תמיד בודקים לפני שניגשים ל־`m[1]`.
  • `(?...)` נותן ל־group שם, והוא מופיע ב־`m.groups.name`. עם יותר משלושה חלקים, שמות קריאים יותר ממספרים.
  • group תמיד מחזיר מחרוזת. מספר צריך להמיר עם `Number(...)`.
  • סוגריים רק כדי לקבץ, בלי לשמור (כמו ב־`(GET|POST)`), כותבים `(?:GET|POST)`. כך המספור של שאר ה־groups לא זז.

וזה הדפוס שתכתוב הכי הרבה: פונקציה שמפרקת קלט, וזורקת שגיאה ברורה אם הוא לא בפורמט (בדיוק כמו `parseQuantity` משיעור 2):

```js run function parseDate(text) { const m = text.match(/^(\d{4})-(\d{2})-(\d{2})$/); if (m === null) { throw new Error(`תאריך לא בפורמט YYYY-MM-DD: "${text}"`); } return { year: Number(m[1]), month: Number(m[2]), day: Number(m[3]) }; } for (const input of ["2026-11-19", "19/11/2026", "2026-1-5"]) { try { console.log(parseDate(input)); } catch (err) { console.log(`✘ ${err.message}`); } } ``` ```out { year: 2026, month: 11, day: 19 } ✘ תאריך לא בפורמט YYYY-MM-DD: "19/11/2026" ✘ תאריך לא בפורמט YYYY-MM-DD: "2026-1-5" ```

4. הדגל `g`: כל ההתאמות

בלי דגל, `match` עוצר בהתאמה הראשונה. עם `g` (global) הוא מחזיר מערך של כל ההתאמות, אבל בלי ה־groups. כשצריך גם את כל ההתאמות וגם את ה־groups, משתמשים ב־`matchAll`:

```js run const text = "קפה 12 ₪, עוגה 18 ₪, מים 6 ₪"; console.log(text.match(/\d+/)); console.log(text.match(/\d+/g)); console.log("אין כאן מספרים".match(/\d+/g)); const items = [...text.matchAll(/(\S+) (\d+) ₪/g)].map((m) => ({ name: m[1], price: Number(m[2]) })); console.log(items); ``` ```out [ '12', index: 4, input: 'קפה 12 ₪, עוגה 18 ₪, מים 6 ₪', groups: undefined ] [ '12', '18', '6' ] null [ { name: 'קפה', price: 12 }, { name: 'עוגה', price: 18 }, { name: 'מים', price: 6 } ] ```

`matchAll` מחזיר משהו שעוברים עליו (כמו `Map` או `Set`), ולכן מפזרים אותו למערך עם `[...]` ואז ממשיכים עם `map`. ושים לב: גם `match` עם `g` מחזיר `null` כשאין אף התאמה, לא `[]`.

5. `replace` ו־`split`: לשנות ולחתוך

```js run console.log("052-123-4567".replace(/-/g, "")); console.log("052-123-4567".replace(/-/, "")); console.log("052-123-4567".replace("-", "")); console.log("ת.ז. 012-345-678".replace(/\D/g, "")); console.log(" כמה רווחים כפולים ".trim().replace(/\s+/g, " ")); console.log("19/11/2026".replace(/^(\d{2})\/(\d{2})\/(\d{4})$/, "$3-$2-$1")); console.log("created_at_utc".replace(/_([a-z])/g, (all, letter) => letter.toUpperCase())); console.log("a, b,c , d".split(/\s*,\s*/)); console.log("שורה 1\r\nשורה 2\nשורה 3".split(/\r?\n/)); ``` ```out 0521234567 052123-4567 052123-4567 012345678 כמה רווחים כפולים 2026-11-19 createdAtUtc [ 'a', 'b', 'c', 'd' ] [ 'שורה 1', 'שורה 2', 'שורה 3' ] ```
  • בלי `g`, ‏`replace` מחליף רק את ההתאמה הראשונה. השורה השנייה בפלט מראה את זה. גם עם מחרוזת רגילה במקום regex (השורה השלישית) מוחלפת רק ההופעה הראשונה. לכל ההופעות: regex עם `g`, או `replaceAll` מפרק 2.
  • `\D` הוא "כל תו שאינו ספרה" — ולכן `replace(/\D/g, "")` משאיר רק ספרות.
  • בטקסט ההחלפה, `$1`, `$2`... הם ה־groups. כך הפכנו תאריך ישראלי לפורמט ISO בשורה אחת.
  • במקום טקסט אפשר לתת פונקציה. היא נקראת לכל התאמה, עם ההתאמה המלאה ואחריה ה־groups, ומה שהיא מחזירה נכנס במקום. כך `created_at_utc` הפך ל־`createdAtUtc`.
  • `split` עם regex חותך לפי תבנית, ולא רק לפי תו קבוע. `/\r?\n/` מתאים לירידת שורה גם של Windows (`\r\n`) וגם של Mac ולינוקס (`\n`). תראה אותו בכל קוד שקורא קבצים.

6. regex מתוך משתנה, ועברית

לפעמים התבנית לא ידועה מראש, למשל מילה שהמשתמש חיפש. `new RegExp(טקסט, דגלים)` בונה regex ממחרוזת:

```js run const word = "קפה"; const re = new RegExp(word, "g"); console.log("קפה הפוך וקפה שחור".match(re).length); function escapeRegex(text) { return text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&"); } const search = "1.5"; console.log(new RegExp(search).test("105"), new RegExp(escapeRegex(search)).test("105")); console.log("שלום, world 123".match(/\p{L}+/gu)); console.log(/\bcat\b/.test("a cat here"), /\bשלום\b/u.test("אמר שלום לכולם")); ``` ```out 2 true false [ 'שלום', 'world' ] true false ```
  • טקסט של משתמש הוא טקסט, לא תבנית. בלי escaping, הנקודה ב־`"1.5"` מתאימה לכל תו, ו־`"("` מפיל את התוכנית (בתיבה למטה). `escapeRegex` מוסיף `\` לפני כל תו מיוחד (`$&` בטקסט ההחלפה = מה שהתאים).
  • `\w` מכיר רק אותיות לטיניות. אותיות בכל שפה, כולל עברית: `\p{L}`. הוא עובד רק עם הדגל `u` (unicode).
  • `\b` הוא "גבול מילה", והוא נשען על `\w`. לכן סביב מילה בעברית הוא לא עובד, גם עם `u`. בעברית כותבים את הגבול בעצמך, למשל `(^|[^\u0590-\u05FF])`: ‏`\u0590-\u05FF` הוא הטווח של התווים העבריים בטבלת התווים (Unicode), ולכן `[^\u0590-\u05FF]` הוא "תו שאינו עברי".
⚠️ טעויות נפוצות
  • שכחת `^` ו־`$` בבדיקת קלט: `/\d{7}/` מקבל גם `"abc12345678xyz"`.
  • `match` החזיר `null` וניגשת ל־`m[1]`: `TypeError: Cannot read properties of null (reading '1')`. בודקים `m === null` קודם.
  • נקודה בלי `\`: `/1.5/` מתאים גם ל־"105". נקודה אמיתית: `\.`.
  • טקסט של משתמש ב־`new RegExp` בלי escaping: `new RegExp("(1")` זורק `SyntaxError: Invalid regular expression: /(1/: Unterminated group`.
  • `g` עם `test`: regex עם `g` זוכר איפה עצר (בשדה `lastIndex`), ולכן אותה בדיקה מחזירה פעם `true` ופעם `false`. ל־`test` לא שמים `g`.
```js run const hasDigit = /\d/g; console.log(hasDigit.test("a1"), hasDigit.test("a1"), hasDigit.test("a1")); console.log(/\d/.test("a1"), /\d/.test("a1"), /\d/.test("a1")); ``` ```out true false true true true true ```

7. מתי לא להשתמש ב־regex

  • כשיש פונקציה פשוטה יותר: `startsWith`, `endsWith`, `includes` ו־`split(",")` קריאים יותר, ולא צריך regex בשבילם.
  • לפורמטים מקוננים כמו JSON או HTML: `JSON.parse` ולא regex. regex לא יודע לספור סוגריים מקוננים.
  • כשהתבנית נהיית ארוכה מדי לקריאה: מפרקים לכמה בדיקות קטנות עם הודעת שגיאה לכל אחת. "סיסמה חייבת ספרה" עדיף על "סיסמה לא תקינה".
  • אימייל: regex פשוט כמו `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` תופס טעויות הקלדה. הבדיקה האמיתית היא לשלוח מייל עם קישור.

ועוד דבר לעתיד: regex מסוים על קלט ארוך של משתמש יכול לתקוע שרת שלם. זה נקרא ReDoS, ונגיע אליו ביחידה 28.5.
